## Кеш запитів

`getRouter` створює новий `QueryClient` для кожного HTTP-запиту, тож на сервері дані не просочуються між користувачами. Типові значення:

| Параметр                   | Значення               |
| -------------------------- | ---------------------- |
| `staleTime` запитів        | 1 хвилина              |
| `gcTime` запитів           | 5 хвилин               |
| `defaultStaleTime` роутера | 1 хвилина              |
| Попереднє завантаження     | За наміром користувача |

Loader-функції заповнюють кеш через `queryClient.query({ ...options, staleTime: "static" })`, а компоненти читають ті самі ключі через `useSuspenseQuery`. Виняток — сторінки курсів і редактор курсів в адмінпанелі: їхні запити мають `staleTime: COURSE_STALE_MS` (одна хвилина), бо `invalidateQueries` ніколи не перезавантажує `static`-запит, а завершення уроку чи збереження зміни в редакторі має оновити програму. `setupRouterSsrQueryIntegration` серіалізує серверний кеш у HTML і гідратує його в браузері.

- **Повідомлення перекладів** кешуються для кожної локалі та простору імен із нескінченними `staleTime` і `gcTime`.
- **Запит сесії** (`getCurrentSessionQuery`) має `staleTime` в одну хвилину. Guard-функції маршрутів повторно отримують його під час справжніх переходів і очищають увесь кеш, коли змінюється користувач, що увійшов.
- **Мутації** після успішного виконання інвалідують ключі запитів свого модуля, наприклад `USER_QUERY_KEYS.ALL`.

## Пререндеринг

`bun run build` попередньо рендерить публічні сторінки, обходячи посилання: лендинг, юридичні сторінки, блог і документацію в усіх дев'яти локалях. Шляхи в `/admin`, `/app`, `/auth`, `/courses`, `/newsletter` і `/api` (з префіксом локалі або без нього), а також посилання з рядком запиту чи хешем виключено. Сторінки курсів виключено, бо вони показують блокування й прогрес кожного глядача. Блок курсів на головній сторінці браузер заповнює даними з `getCourseShowcase`, коли той наближається до видимої області, тому пререндерена головна сторінка однакова для всіх (див. [Курси](/docs/features/courses)).

Worker віддає попередньо відрендерений HTML із прив'язки `ASSETS` ще до завантаження застосунку. Попередньо відрендерена сторінка не містить даних користувача, тож її безпечно віддавати всім. Коли відвідувач має право на регіональні ціни, Worker переписує HTML і позначає відповідь `Cache-Control: private, no-cache`.

Попередній рендеринг виконується на збірці Worker, яка містить усі сторінки. Після цього Worker для розгортання збирається заново без відрендереного MDX документації та блогу і без перекладів, які використовують лише лендинг і юридичні сторінки. Серверні функції документації та блогу і `/api/search` і далі читають frontmatter, заголовки й текст для пошуку кожної сторінки, тож навігація на клієнті та пошук працюють як раніше. Див. [Cloudflare Workers](/docs/integrations/cloudflare-workers).

## KV і D1

- **KV (`CACHE`)** зберігає кількість зірок на GitHub для `src/lib/github.ts` і регіональні знижки під час оплати для `src/modules/license/license.ppp.ts`. Кількість зірок, старша за одну годину, повертається одразу й оновлюється у фоні через `waitUntil`; знижки, старші за п’ять хвилин, повторно отримуються з Polar.
- **D1 (`DB`)** зберігає сесії та лічильники обмеження частоти запитів. Перевірки сесії для серверних функцій оминають кеш cookie у Better Auth і мемоізуються до кінця запиту.
- **Кеш Workers** зберігає відеофайли, які `serveMedia` читає з R2, під `/media/_/<videoId>/<file>`, без підпису, тож глядачі на одному периферійному вузлі спільно використовують одну кешовану копію. Див. [Cloudflare R2](/docs/integrations/cloudflare-r2).
- Серверні функції ніколи не ухвалюють рішень щодо дозволів на основі кешованих даних.
