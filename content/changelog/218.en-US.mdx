- Fixed: every option of the CLI configurator on the landing page answers the first press. A press near an option's edge no longer misses, because no control shrinks when pressed, the copy buttons included, and an answer no longer moves the options around it: a selected option changes colour instead of weight, every question keeps all its options on screen, and the configurator fades in without rising. Each question is a radio group and the extras a toggle group, both the shadcn `ToggleGroup`, so the arrow keys move within a question, Space or Enter answers it and Tab moves to the next. An option that an earlier answer rules out stays in place, disabled, and the note under its question gives the reason to keyboard, touch and screen reader users alike, where a tooltip showed it only to a mouse. See [CLI configurator](/docs/features/landing-page#cli-configurator) and [Accessibility](/docs/conventions/accessibility).
- Changed: the CLI configurator hydrates in a `Suspense` boundary of its own, so its forty React Aria buttons leave desktop Total Blocking Time where it was. Keeping TanStack Start's preload hints, now all at low priority, was measured again: the page hydrates sooner but First Contentful Paint comes later, so they stay stripped. See [Performance](/docs/conventions/performance).
