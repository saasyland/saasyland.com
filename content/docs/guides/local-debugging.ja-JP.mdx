## 環境を選ぶ

| 環境           | コマンド                                    | データ                                                                    | プロバイダー                                  |
| -------------- | ------------------------------------------- | ------------------------------------------------------------------------- | --------------------------------------------- |
| 分離プレビュー | `db:reset:test`、`build:test`、`start:test` | `.wrangler/test` にあるローカルの D1、KV、R2、シード済みのアカウント      | インターセプトされるため、アカウントは不要    |
| 開発           | `db:reset:local`、`db:seed:local`、`dev`    | `.wrangler/state` にあるローカルの D1、KV、R2、シード済みの管理者とコース | 実際のプロバイダー（`.env.development` から） |

```sh
bun run db:reset:test
bun run build:test
bun run start:test
```

分離プレビューは、ビルドを <RepositoryFact name="localServerOrigin" /> で配信します。ソースの変更を反映するには再ビルドしてください。[初回起動](/docs/getting-started/first-run)に一覧があるシード済みのアカウントのいずれかで、`e2e/data/accounts.ts` にあるパスワードを使ってサインインします。メールは送信されずにキャプチャされます。認証リンクを含むメールを読むには、`/__test/emails?to=<address>` を開きます。

```sh
cp .env.example .env.development
bun run db:reset:local
bun run db:seed:local
bun run dev
```

開発サーバーは `http://localhost:3000` でホットリロード付きで動作します。その `DB`、`CACHE`、`MEDIA`、`BUNDLES` のバインディングはローカルのものであるため、何をしてもプレビューや本番のデータには届きません。[ローカルのシード](/docs/tooling/database#the-local-seed)にあるシード済みの管理者でサインインします。`POLAR_SERVER=sandbox` を使ってください。

## サーバーエラーを読む

- 失敗したサーバー関数は、元のエラーとともに `Server function failed` をログに出力します。出力先は、`bun run dev` を実行しているターミナル、またはデプロイ済みの環境では Workers Logs です。ブラウザが受け取るのはエラーコードだけです。
- `Rate-limit storage unavailable` は、レート制限のチェック中に D1 に到達できなかったことを意味します。そのリクエストは拒否されています。
- `[license] <method> <path> failed` は、CLI ライセンス API へのリクエストが、たとえば D1 や Polar の失敗によってサーバー側で失敗し、CLI が `serviceUnavailable` を受け取ったことを意味します。このエントリーには、エラーとその原因、スタックが含まれ、呼び出し元のキーは `[licence key]` に置き換わっています。
- `No messages/<locale>/<namespace>.json` は、そのロケールのファイルが存在しない名前空間を、ルートが宣言していることを意味します。

## データを確認する

- Drizzle Studio：ローカルのデータベースには `bun run db:studio:local`。`:preview` と `:production` には、対応する環境ファイルに `CLOUDFLARE_*` 変数が必要です。
- ローカルのテスト用データベース：`bunx wrangler d1 execute DB --env test --local --persist-to .wrangler/test --command "SELECT email, role FROM user"`。

## 生成されたファイルを修正する

- Worker のバインディング、クラス名のテーブル、ドキュメントコンテンツの型が古くなっている場合：`bun run typegen`。
- 翻訳が解決されない場合：`bun run check:i18n` が、ロケールごとの不足しているキーと、`useTranslations` のスコープで解決されないキーを一覧表示します。
- `bun run clean` は、ローカルのテスト用データベースを含め、ビルド出力、キャッシュ、`.wrangler` を削除します。その後、`db:reset:test` を実行してください。

## テストをデバッグする

- 1 つのプロジェクトだけ、または影響を受けたテストだけを実行するには：`bun run test:unit`、`bun run test:component`、`bun run test:changed`、`bun run test:watch`。
- Playwright：`bun run test:e2e:headed` はブラウザを表示し、`bun run test:e2e:ui` は UI モードを開きます。ローカルでの実行では、失敗したテストのトレースが保存され、失敗時には HTML レポートが開きます。
- 別のサーバーが <RepositoryFact name="localServerOrigin" /> を使っているときや、別のワークツリーがスイートを実行しているときは、テストビルドの範囲内の空いているポートでブラウザーテストを実行します: `PLAYWRIGHT_BASE_URL=http://127.0.0.1:3027 bun run test:e2e:pr`。ポートの選び方は [Playwright](/docs/tooling/playwright#running-beside-other-worktrees) で説明しています。
