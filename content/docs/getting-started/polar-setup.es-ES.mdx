<LegalNotice />

Polar vende los tres niveles a los precios que envía el pago, emite sus claves de licencia y cobra los impuestos. El código espera una configuración precisa en Polar, y Polar no avisa cuando ambos dejan de coincidir: un producto sin un beneficio de clave de licencia sigue aceptando el pago, pero no emite ninguna clave. `bun run polar:verify:<environment>` compara Polar con el código, y los scripts de despliegue lo ejecutan antes de cada despliegue manual.

## Producción y sandbox

Polar mantiene dos servicios independientes. Producción (`polar.sh`, API `api.polar.sh`) hace cargos en tarjetas reales; el sandbox (`sandbox.polar.sh`, API `sandbox-api.polar.sh`) solo acepta tarjetas de prueba. No comparten nada: una cuenta, una organización, un token, un producto, un descuento o un webhook existe en un solo servicio, así que regístrate por separado en `sandbox.polar.sh` y configura cada servicio por su cuenta.

| Archivo de entorno | `POLAR_SERVER` | Organización de Polar |
| ------------------ | -------------- | --------------------- |
| `.env.development` | `sandbox`      | Sandbox               |
| `.env.preview`     | `sandbox`      | Sandbox               |
| `.env.production`  | `production`   | Producción            |

Desarrollo y preview pueden compartir una organización del sandbox, pero su webhook solo llega a preview: envía los eventos al host de preview, que escribe en la base de datos D1 de preview, mientras que `bun run dev` usa una base de datos local propia. Por eso, una compra de prueba hecha en desarrollo no concede ninguna licencia en local; prueba las compras de principio a fin en preview.

No pongas nunca un token, un ID de organización o un ID de producto de producción en `.env.development` ni en `.env.preview`. La API del sandbox rechaza un token de producción, y con `POLAR_SERVER=production` un pago de prueba haría un cargo en una tarjeta real y concedería la licencia en la base de datos local o de preview. `polar:verify` rechaza `POLAR_SERVER=production` para desarrollo y preview, y `POLAR_SERVER=sandbox` para producción.

## Organización y token

En el sandbox y, después, en producción:

1. Crea una organización y copia su ID, que figura en los ajustes de la organización, en `POLAR_ORGANIZATION_ID`. Da a las dos organizaciones el slug de `POLAR_ORGANIZATION_SLUG` (`src/integrations/polar/polar.constants.ts`), o cambia la constante por su slug: el [aviso y la lista de administración de los pedidos que no corresponden a ninguna cuenta](/docs/features/licences#orders-that-match-no-account) enlazan cada pedido al panel de Polar con ese slug.
2. En los ajustes de la organización, crea un token de acceso de organización con estos ámbitos, y ningún otro, y cópialo en `POLAR_ACCESS_TOKEN`.

| Ámbito                    | Lo necesita                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `checkouts:write`         | `createCheckout`, que crea todos los pagos con el SDK de Polar (`polar.checkouts.create`)                                                                                                                                                                                                                                                                                                                  |
| `customer_sessions:write` | El enlace al portal de cliente, `/api/auth/customer/portal`                                                                                                                                                                                                                                                                                                                                                |
| `license_keys:write`      | Leer una clave y sus activaciones, activar un dispositivo y eliminar una activación (`deactivateLicense` y la [API de licencias de la CLI](/docs/features/cli-licence-api)) y, en una mejora, elevar el límite de activaciones de la clave y desactivar la clave que Polar emite para el pedido de mejora                                                                                                  |
| `orders:read`             | Los handlers de los webhooks, que leen el pedido que hay detrás de una licencia y el cliente actual de un pedido cuyo evento no corresponde a ninguna cuenta, el precio de la mejora, que suma lo que el cliente ha pagado por licencias, la página de un pedido en la administración, que lee el pedido y su factura, y `orders:backfill`, que copia el descuento y el país de facturación de cada pedido |
| `organizations:read`      | `polar:verify`, que lee si la localización del pago está activada, el comportamiento fiscal predeterminado y los hosts que pueden incrustar el pago                                                                                                                                                                                                                                                        |
| `products:read`           | `getPolarProducts`, que lista los productos en `/admin/products` y los cuenta en el panel ([Productos](/docs/features/products)), y `polar:verify`                                                                                                                                                                                                                                                         |
| `webhooks:read`           | `polar:verify`                                                                                                                                                                                                                                                                                                                                                                                             |

Un ámbito de escritura incluye la lectura, así que `license_keys:write` también cubre la lectura de claves. Un token de organización ya actúa en nombre de su propia organización. Aun así, `polar:verify` envía `POLAR_ORGANIZATION_ID` como parámetro de consulta `organization_id`, igual que el listado de pedidos para una mejora y `getPolarProducts`, así que un ID de otra organización se manifiesta como productos que faltan. El Worker desplegado conserva el token que subió el último `deploy:preview` o `deploy:production`, así que un token nuevo solo llega al sitio con el siguiente despliegue manual.

## Productos

Crea un producto por nivel: una compra única, no una suscripción, con un precio fijo en `DEFAULT_CURRENCY_CODE` (dólares estadounidenses) igual a `TIER_PRICES` de `src/data/license.ts`. Copia el ID de cada producto en su clave.

| Nivel    | Clave                       | Precio                        | Activaciones por clave              |
| -------- | --------------------------- | ----------------------------- | ----------------------------------- |
| Core     | `POLAR_PRODUCT_ID_CORE`     | <TierPrice tier="core" />     | <ActivationLimit tier="core" />     |
| Complete | `POLAR_PRODUCT_ID_COMPLETE` | <TierPrice tier="complete" /> | <ActivationLimit tier="complete" /> |
| Agency   | `POLAR_PRODUCT_ID_AGENCY`   | <TierPrice tier="agency" />   | <ActivationLimit tier="agency" />   |

Polar guarda los precios en la unidad menor de la moneda, centavos en el caso del dólar estadounidense, y `polar:verify` convierte `TIER_PRICES` de la misma forma antes de compararlos. Ignora los precios archivados.

## Claves de licencia

Crea un beneficio de tipo **License Keys** (claves de licencia) por nivel y vincúlalo solo al producto de ese nivel:

- **Activaciones**: limitadas al número de la tabla anterior, `LICENSE_ACTIVATION_LIMITS` en `src/modules/license/license.constants.ts`. Permitir que los clientes gestionen sus activaciones en Polar es opcional, porque `/app/license` ya las enumera y las elimina por su cuenta.
- **Caducidad**: ninguna. Las claves no caducan nunca, ya que la compra es un pago único.
- **Límite de uso**: ninguno.
- **Prefijo**: el que prefieras; `polar:verify` no lo comprueba.

Cada producto necesita exactamente un beneficio de clave de licencia; puede tener otros beneficios además de ese. Cuando Polar concede el beneficio, el webhook `benefit_grant.created` guarda la clave en la licencia del comprador.

## Casilla de consentimiento [#consent-checkbox]

El comprador da el consentimiento al suministro inmediato en el pago de Polar, y este campo es el único lugar donde se pide (consulta [Licencias](/docs/features/licences#consent-to-immediate-supply)); Polar lo registra en el pedido. Crea un campo personalizado en la organización y vincúlalo a los tres productos:

- **Tipo**: casilla de verificación.
- **Identificador (slug)**: <RepositoryFact name="licenseWithdrawalConsentField" />, `LICENSE_CHECKOUT_FIELD.WITHDRAWAL_CONSENT` en `src/modules/license/license.constants.ts`. El pedido guarda la casilla marcada con esta clave en `custom_field_data`.
- **Etiqueta**: exactamente `WITHDRAWAL_CONSENT_FIELD.label` de `src/lib/polar.ts`, la frase en inglés construida a partir de `REFUND_TERMS.WITHDRAWAL_DAYS` que termina con un enlace en Markdown a la Política de Reembolsos de producción.
- **Nombre**: el que prefieras; `WITHDRAWAL_CONSENT_FIELD.name` es el que sugiere el código, y `polar:verify` no lo comprueba.
- **Obligatorio** en cada uno de los tres productos. Los demás campos que pidan los productos pueden quedarse.

`startCheckout` no envía ningún valor para el campo, así que la casilla empieza vacía y la marca el comprador; Polar no acepta el pago mientras una casilla obligatoria esté vacía. Polar solo conserva los valores de los campos que pide el producto: antes de vincular el campo, el pago sigue funcionando, pero el pedido no registra ningún consentimiento, y la [confirmación de compra](/docs/features/licences#purchase-confirmation) indica en su lugar el derecho de desistimiento legal.

Crear el campo y vincularlo a un producto requiere los ámbitos `custom_fields:write` y `products:write`, que el token anterior no tiene. Créalo y vincúlalo en el panel de Polar, o mediante la API con otro token que sí los tenga. `polar:verify` lee los campos vinculados en el listado de productos, así que no necesita ningún otro ámbito.

## Idioma del pago [#checkout-language]

Polar muestra su pago en el idioma que pide `createCheckout` solo mientras la localización del pago esté activada en la organización; si no, todos los pagos se abren en inglés. Actívala en los ajustes de la organización. La [guía de localización del pago](https://polar.sh/docs/features/checkout/localization) de Polar la llama feature flag, y la API la devuelve como `feature_settings.checkout_localization_enabled` en la organización. `POLAR_CHECKOUT_LANGUAGES` en `src/integrations/polar/polar.constants.ts` enumera los idiomas que pide el código, y `polar:verify` falla mientras la localización esté desactivada.

## Comportamiento fiscal [#tax-behaviour]

Las tarjetas de precios indican que los precios están en dólares estadounidenses, que el IVA está incluido en la UE y que el impuesto sobre ventas se añade en el pago en Estados Unidos, Canadá e India. Polar cobra los impuestos así cuando el comportamiento fiscal predeterminado de la organización se basa en la ubicación, así que configúralo de esa forma en los ajustes de la organización. La API lo devuelve como `default_tax_behavior` en la organización, y `polar:verify` falla mientras no sea `location` (`POLAR_TAX_BEHAVIOR.LOCATION` en `src/lib/polar.ts`).

## Incrustación [#embedding]

Los botones de compra abren el pago de Polar superpuesto al sitio en un iframe ([Licencias](/docs/features/licences#the-checkout-over-the-page)), y Polar solo permite mostrar su pago en un marco a los hosts que su organización incluye en la lista. En **Settings > Embedding**, añade los hosts que `appHostsForMode` sirve en cada entorno, sin esquema y con el puerto cuando lo hay:

| Entorno       | Organización | Hosts                              |
| ------------- | ------------ | ---------------------------------- |
| `development` | Sandbox      | `localhost:3000`, `127.0.0.1:3000` |
| `preview`     | Sandbox      | `preview.saasyland.com`            |
| `production`  | Producción   | `saasyland.com`                    |

Una entrada `*.saasyland.com` cubre `preview.saasyland.com`, pero no `saasyland.com`. Polar añade por sí mismo a la lista los dominios verificados de la organización. La API devuelve la lista como `embed_hosts` en la organización, y `polar:verify` falla mientras falte un host del entorno. Hasta que esté en la lista, el marco de Polar se queda en blanco en ese host y, tras <RepositoryFact name="checkoutOverlayGraceSeconds" unit="second" />, el botón lleva en su lugar al comprador a la página de pago de Polar, así que los compradores pueden pagar igualmente, un poco más tarde.

## Precios regionales [#regional-prices]

Los precios regionales no necesitan nada en Polar. Para un comprador de un país de `PPP_TIERS` (`src/modules/license/license.pricing.ts`), cuyos tramos descuentan <RegionalDiscounts />, `startCheckout` envía el propio precio: `regionalPrice` redondea a la baja el precio del nivel a dólares enteros, el importe que muestran las tarjetas de niveles, y el pago lo lleva en `prices` como precio fijo del producto del nivel que solo vale para ese pago, de modo que el producto conserva su precio de `TIER_PRICES`. Una [mejora](/docs/features/licences#upgrades) envía su precio de la misma forma. Los descuentos que creó una configuración anterior ya no se usan, y puedes eliminarlos.

## Webhook

Crea un endpoint de webhook para cada entorno desplegado, en la organización que usa ese entorno.

| Entorno      | Organización | URL                                                     |
| ------------ | ------------ | ------------------------------------------------------- |
| `preview`    | Sandbox      | `https://preview.saasyland.com/api/auth/polar/webhooks` |
| `production` | Producción   | `https://saasyland.com/api/auth/polar/webhooks`         |

El host sale de `DEPLOYED_HOSTS` y la ruta, de `ROUTES`. Elige el formato raw, mantén el endpoint activado y suscríbelo exactamente a los eventos de `POLAR_EVENTS` (`src/integrations/polar/polar.webhooks.ts`), que reúne los eventos de cada handler de `POLAR_EVENT_HANDLERS` (consulta [Pagos](/docs/features/payments#webhooks)). Hoy la licencia gestiona los eventos de `LICENSE_WEBHOOK_EVENTS` (`src/modules/license/license.constants.ts`), y las copias de los pedidos y de las suscripciones, los de `ORDER_WEBHOOK_EVENTS` y `SUBSCRIPTION_WEBHOOK_EVENTS`:

| Evento                  | Área de licencias                                                                  | Área de facturación                  |
| ----------------------- | ---------------------------------------------------------------------------------- | ------------------------------------ |
| `benefit_grant.created` | Guarda la clave de licencia                                                        |                                      |
| `benefit_grant.revoked` | Revoca la licencia                                                                 |                                      |
| `order.created`         |                                                                                    | Copia el pedido en D1                |
| `order.paid`            | Concede la licencia                                                                | Actualiza la copia del pedido        |
| `order.refunded`        | Marca la licencia como reembolsada cuando el pedido se ha reembolsado por completo | Actualiza la copia del pedido        |
| `order.updated`         |                                                                                    | Actualiza la copia del pedido        |
| `subscription.created`  |                                                                                    | Copia la suscripción en D1           |
| `subscription.updated`  |                                                                                    | Actualiza la copia de la suscripción |

Cuando un área empiece a gestionar un evento, añade el evento a cada endpoint antes de desplegar ese código. El código desplegado hasta entonces responde 200 a un evento que ninguna área gestiona y no hace nada con él, así que añadir el evento primero no causa ningún daño, y `polar:verify` hace fallar el despliegue mientras un endpoint no envíe todos los eventos de `POLAR_EVENTS`.

Copia el secreto de firma del endpoint en `POLAR_WEBHOOK_SECRET`, en el mismo archivo de entorno. Desarrollo no necesita ningún endpoint, porque Polar no puede acceder a `localhost`.

No añadas nunca un endpoint de preview a la organización de producción ni un endpoint de producción al sandbox: los pagos reales llegarían a preview, o las compras de prueba concederían licencias en producción.

## Comprobar la configuración

```sh
bun run polar:verify:development
bun run polar:verify:preview
bun run polar:verify:production
```

Cada script lee las claves de Polar de `.env.<environment>` y solo envía peticiones GET a la API que indica `POLAR_SERVER`: lee la organización y enumera sus productos y endpoints de webhook, y no modifica nada. Comprueba que:

- el archivo de entorno define todas las claves de Polar, con `POLAR_SERVER=sandbox` para desarrollo y preview y `POLAR_SERVER=production` para producción;
- la localización del pago está activada en la organización, su comportamiento fiscal predeterminado se basa en la ubicación y la organización permite que todos los hosts del entorno incrusten su pago;
- cada `POLAR_PRODUCT_ID_*` corresponde a un producto de la organización que no está archivado ni es una suscripción, y cuyos precios son fijos, están en `DEFAULT_CURRENCY_CODE` y son iguales a `TIER_PRICES`;
- cada producto tiene exactamente un beneficio de clave de licencia con el límite del nivel según `LICENSE_ACTIVATION_LIMITS`, sin caducidad y sin límite de uso;
- cada producto exige el campo de casilla <RepositoryFact name="licenseWithdrawalConsentField" /> con la etiqueta de `WITHDRAWAL_CONSENT_FIELD`;
- preview y producción tienen un endpoint raw activado en su URL de webhook, firmado con `POLAR_WEBHOOK_SECRET` y suscrito exactamente a `POLAR_EVENTS`;
- ningún endpoint envía eventos al host de un entorno que usa el otro servicio de Polar.

`polar:verify` es la comprobación de despliegue del área de Polar, porque sus scripts se llaman `polar:verify:<environment>`. Por eso `deploy:preview` y `deploy:production` lo ejecutan a través de `scripts/run-deploy-checks.ts`, después de `scripts/verify-bindings.ts` y `scripts/prepare-deploy-secrets.ts` y antes de la compilación. Los despliegues de la CI no ejecutan ninguna comprobación de despliegue, tampoco `polar:verify`: `deploy-reusable.yml` no tiene ningún paso para `scripts/run-deploy-checks.ts`, los entornos de GitHub no guardan ningún token de Polar, y el Worker conserva los secretos de Polar ya configurados en Cloudflare. Ejecuta tú mismo `polar:verify` después de cada cambio en Polar.

## Cuando falla

El script termina con un error que enumera todos los problemas que ha encontrado, uno por línea:

```text
Polar production does not match the code for production:
The core product (POLAR_PRODUCT_ID_CORE) has 0 licence-key benefits; it needs exactly one.
A webhook endpoint posts to https://preview.saasyland.com/api/auth/polar/webhooks, the preview host, from this Polar production organisation; remove it.
```

Un fallo detiene el despliegue antes de que se compile, se migre o se suba nada. El script nunca modifica Polar: corrige Polar y vuelve a ejecutarlo. Cada mensaje indica la clave, la constante o el ajuste que hay que corregir:

- **`Set … in .env.<environment>`**: falta una clave de Polar o está vacía, o `POLAR_SERVER` indica el servicio equivocado.
- **`rejects POLAR_ACCESS_TOKEN`**: el token no es válido, se ha revocado o es del otro servicio, como un token de producción en `.env.preview`.
- **`lacks the … scope`**: crea un token con los ámbitos indicados más arriba. Si es `products:read`, el mensaje añade que el sitio desplegado también necesita ese ámbito: sin él, `/admin/products` y el recuento de productos del panel no reciben productos de Polar.
- **`names no product of the organisation`**: el ID de producto o `POLAR_ORGANIZATION_ID` es incorrecto, o pertenece al otro servicio.
- **Un precio o una clave de licencia**: cámbialo en Polar para que coincida con el código. Cuando un valor de negocio cambie a propósito, cambia primero `TIER_PRICES` o `LICENSE_ACTIVATION_LIMITS` y después Polar.
- **`does not ask for the … checkout field`, `without requiring it`, `instead of a checkbox` o `label differs`**: crea, vincula o corrige la [casilla de consentimiento](#consent-checkbox). Cuando la redacción cambie a propósito, cambia primero `WITHDRAWAL_CONSENT_FIELD.label` y después la etiqueta en Polar.
- **`Checkout localization is off`**: activa la [localización del pago](#checkout-language) en la organización.
- **`default tax behaviour is not location`**: configura el [comportamiento fiscal](#tax-behaviour) de la organización para que se base en la ubicación.
- **`does not let … embed its checkout`**: añade el host que indica el mensaje en [Settings > Embedding](#embedding).
- **Un endpoint de webhook**: corrige el endpoint que indica el mensaje o elimina un endpoint que envíe eventos al host de otro entorno.
