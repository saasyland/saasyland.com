O Cloudflare D1 (SQLite) é o banco de dados da aplicação. Os schemas dos módulos usam `drizzle-orm/sqlite-core`, `src/integrations/drizzle-orm/drizzle.schemas.ts` os reúne e o drizzle-kit grava as migrações em `src/integrations/drizzle-orm/migrations/` com um prefixo de data e hora.

## Fluxo de trabalho

1. Altere `<table>.schema.ts`. Para uma tabela nova, exporte-a também em `drizzle.schemas.ts`.
2. Gere o SQL:

```sh
bun run db:generate
```

3. Revise o arquivo gerado e faça o commit junto com a mudança do schema.
4. Aplique-o no banco com que você trabalha. `deploy:preview`, `deploy:production` e a CI o aplicam no banco da prévia ou de produção antes do deploy.

## Comandos

| Comando                         | Banco de dados                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------------- |
| `bun run db:migrate:local`      | Banco de desenvolvimento local em `.wrangler/state`, usado por `bun run dev`          |
| `bun run db:reset:local`        | Apaga o banco de desenvolvimento local e depois refaz as migrações dele               |
| `bun run db:migrate:test`       | Banco de teste local em `.wrangler/test`, usado pelo Playwright e pela prévia isolada |
| `bun run db:reset:test`         | Apaga `.wrangler/test` e depois refaz as migrações e o seed do banco de teste local   |
| `bun run db:migrate:preview`    | Banco remoto da prévia                                                                |
| `bun run db:migrate:production` | Banco remoto de produção                                                              |

`bun run db:migrations:local`, `db:migrations:preview` e `db:migrations:production` listam as migrações que um banco ainda não aplicou. `bun run db:studio:local` abre o Drizzle Studio no arquivo do banco local. `db:studio:preview` e `db:studio:production` o abrem em um banco remoto, e os scripts `db:introspect:*` fazem a introspecção dele, ambos pela API HTTP do D1 com `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID` e `CLOUDFLARE_ACCESS_TOKEN` do arquivo de ambiente correspondente. Veja [Banco de dados](/docs/tooling/database).

## Convenções do schema

- Datas são `integer(..., { mode: "timestamp_ms" })` com o padrão `(unixepoch() * 1000)`. As tabelas recebem `createdAt` e `updatedAt` de `...timestamps()` em `src/integrations/drizzle-orm/drizzle.columns.ts`.
- Booleanos são `integer(..., { mode: "boolean" })`.
- Índices, restrições de unicidade, chaves estrangeiras e relações ficam no arquivo do schema.
- O D1 não tem transações interativas. Mantenha uma operação atômica com uma única instrução SQL ou com `db.batch([...])`, como fazem `getUsers` e o limitador de requisições.

## Testes

O binding D1 de teste aplica cada arquivo SQL da pasta de migrações a um banco SQLite em memória, então os testes que usam o D1 rodam sobre o schema migrado. `src/integrations/drizzle-orm/__test__/` verifica se o schema, seus índices e suas chaves estrangeiras são criados corretamente. O `migrations.test.ts` dessa pasta restringe a migração que adiciona as tabelas `order` e `subscription` a instruções `CREATE` para essas tabelas e seus índices e verifica, em um banco migrado até a migração anterior a ela, que toda tabela e todo índice anteriores continuam como estavam. Ele restringe a migração que adiciona os registros da licença a três instruções `ALTER TABLE … ADD` de colunas anuláveis e verifica que todas as outras tabelas, todos os índices e uma licença existente continuam como estavam, com as novas colunas vazias. Ele restringe a migração que adiciona o conteúdo dos cursos a um `CREATE TABLE` e um `CREATE INDEX` para `lesson_attachment`, seguidos apenas de instruções `ALTER TABLE … ADD` de colunas com valor padrão, e verifica que todas as outras tabelas e todos os outros índices e um curso, um capítulo, uma aula e um vídeo existentes continuam como estavam, com as novas colunas nos valores padrão, e que excluir uma aula exclui os materiais dela. Veja [Escrever testes](/docs/guides/writing-tests).

## Dados existentes do PostgreSQL

Estas migrações criam apenas o schema SQLite. Mover dados de uma instalação anterior em PostgreSQL exige uma exportação e uma importação separadas e revisadas.
