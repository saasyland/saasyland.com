## 注文

ページ `/admin/orders` (`src/routes/admin.orders.index.tsx`) は、D1 に保存した Polar の注文のコピー ([決済](/docs/features/payments#orders-and-subscriptions-in-d1)) を、`DataGrid` ([データグリッド](/docs/ui/data-grid)) と `useOrderColumns` (`src/presentation/components/custom/admin/payments/order-columns.tsx`) で一覧にします。決済のエリアは、サイドバーの販売グループへの追加と、ダッシュボードからこのページと顧客へのリンクを次のファイルで行います: `src/data/payments.navigation.ts`。

- `getOrdersPageQuery` は `getOrders` (`src/modules/order/use-cases/get-orders.ts`, `order: ["read"]`) を呼び出します。ページ送り、日時・合計・返金・ステータスでの並べ替え、検索、絞り込みはすべてサーバーで行い、書き出しもサーバーにすべてのページを要求します。
- 検索は注文 ID、Polar の顧客 ID、商品、一致したアカウントの名前とメールアドレスを対象にし、入力が止まった時点で送信されます。
- 絞り込みは、注文した日、顧客（アカウントの名前とメールアドレス、Polar の顧客 ID に一致）、商品、合計の範囲（各注文の通貨で比較）、割引（割引あり、割引なし、または特定の割引）、請求先の国、そして `ORDER_STATUSES` によるステータスです。`getOrderFilters` (`get-order-filters.ts`, `order: ["read"]`) は、コピーに含まれる商品、割引、請求先の国を一覧にし、各商品と各割引には最新の注文での名前を使います。
- 各行には、注文日時と ID、アカウント（一致しない場合はアカウントなしと Polar の顧客 ID）、商品、注文の通貨での合計と返金額、割引とそのコードと金額、請求先の国、ステータスが表示されます。「注文日時」の列は左に固定されています。「返金額」の列は、管理者が「列」メニューから表示するまで非表示です。金額は `fromMinorUnits` で変換され、税を含みます。
- CSV には、日付が ISO 形式の時刻として、顧客が名前とメールアドレスまたは Polar の顧客 ID として、金額が通貨コード付きで、割引の名前、国コード、ステータスが入ります。
- 絞り込みを設定しておらず、まだ注文が 1 件もコピーされていない場合、グリッドには注文がまだないことが表示されます。何にも一致しない検索や絞り込みでは、そのことが表示され、解除するよう提案されます。

## 注文ページ

`/admin/orders/<orderId>` (`admin.orders.$orderId.tsx`) は次の `getOrderQuery` (`get-order.ts`, `order: ["read"]`):

| 部分       | 取得元                                                                                                                                                                                                                                                  |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `order`    | D1 のコピー: 注文日時と最終更新、商品、合計、返金、割引とその金額、請求先の国、請求書番号、サブスクリプション、Polar の顧客、一致したアカウント。割引と請求先の国を保存するようになる前にコピーされた注文では、どちらも「未コピー」と表示されます       |
| `polar`    | `polar.orders.get` （ページの読み込み時）: 小計、割引、割引後の金額、税金、合計、返金額と返金された税金、ステータス、割引の名前とコード、請求先の名前と国、顧客の名前とメールアドレス、そして `polar.orders.invoice` （Polar が請求書を作成済みの場合） |
| `polarUrl` | Polar のダッシュボードでの注文                                                                                                                                                                                                                          |

Polar が応答しない場合、 `polar` は `{ read: "unavailable" }` (`POLAR_READ`, `order.constants.ts`) になり、ページはコピーを表示したまま Polar に接続できなかったことを伝えます。コピーにない注文は見つからないページになります。アカウントカードはプロフィールにリンクし、そこにアカウントのライセンスとすべての注文があります。

## 顧客 [#customers]

決済のエリアは、ユーザー管理に顧客タブを (`src/data/payments.user-tabs.ts`, `/admin/users/customers`) 、アカウントのプロフィールにその注文を追加します (`src/data/payments.user-profile.ts`).

- `getCustomersPageQuery` は `getCustomers` (`get-customers.ts`, `order: ["read"]`) を呼び出し、コピーを Polar の顧客ごとにまとめ、注文が一致したアカウントを結び付けます。ページはそれらを `useCustomerColumns` (`customer-columns.tsx`) を使って `DataGrid` に表示します。登録日時を含むアカウント、注文数、通貨ごとの返金後の支払額（ステータスが <RepositoryFact name="revenueOrderStatuses" />の注文を数えます）、最新の注文です。アカウントのメールが確認済みかどうかは「列」メニューに控えています。通貨を合算することはありません。
- 検索は名前、メールアドレス、Polar の顧客 ID を対象にします。絞り込みは、顧客をテキストで、メール確認をはい・いいえで、注文数を範囲で、登録と最新の注文を日の範囲で指定します。絞り込み、ページネーション、顧客・登録・注文数・最新の注文による並べ替えはサーバーで行い、`orderZodSchemas.getCustomers` で検証します。
- ほかのエリアは `src/data/<area>.customer-columns.ts` でテーブルに列を追加し、 `src/data/customer-columns.entries.ts` がそれらを `CUSTOMER_COLUMNS` (`src/data/customer-columns.ts`) にまとめます。各列はセル、キー、ヘッダーのメッセージキーを指定します。決済のエリアは何も追加しません。ライセンスのエリアは **端末** (`license-machines.tsx`) を追加します。アカウントのある顧客ごとに、ライセンスが有効化した端末の数を上限とあわせて「5台中2台を使用中」のように表示し、ラベル、システム、有効化日時を含む端末の一覧を開きます。1 ページのセルは、そのページのアカウントに対する 1 つの `userActivationsQuery` を共有します（[ユーザー（管理）](/docs/features/users-admin#profile)を参照）。
- `UserOrders` (`user-orders.tsx`) は、プロフィールにアカウントの注文をそれぞれのページへのリンク付きで一覧にし、通貨ごとの返金後の支払額を表示します。

## 以前の注文の割引と請求先の国 [#discounts-and-billing-countries-of-older-orders]

`recordOrder` は注文のイベントのたびに割引と請求先の国をコピーするので、Polar が再び変更した注文には次の Webhook でそれらが入ります。 `20261122143452_familiar_tusk.sql` より前にコピーされた注文は、それまで `discount_amount` が空のままです。 `bun run orders:backfill:<local|preview|production>` は、それらを Polar の API からまとめてコピーします。[データベース](/docs/tooling/database#discounts-and-billing-countries-of-older-orders)を参照してください。

## まだ作られていないもの

- 返金は Polar のダッシュボードで行います。注文ページからそこへリンクしています。
