## 隔離されたテストプレビュー

テストプレビューは、アプリケーションを `test` 環境向けにビルドします。`.wrangler/test` 内のローカル D1 と KV、`.env.test` のダミー認証情報、シードされたアカウントを使い、Resend と Polar へのリクエストは横取りされます。アカウントは必要ありません。

```sh
bun run db:migrate:test
bun run db:seed:test
bun run build:test
bun run start:test
```

http://127.0.0.1:3000 を開き、シードされたアカウントのいずれかでサインインします。どちらのアカウントも、`e2e/data/accounts.ts` にあるパスワード `WorkerTestPassword123!` を使います。

| ロール | メールアドレス                    | ワークスペース |
| ------ | --------------------------------- | -------------- |
| 管理者 | `admin@saasyland.example.test`    | `/admin`       |
| 顧客   | `customer@saasyland.example.test` | `/app`         |

プレビューはビルド済みの成果物を配信するため、ソースの変更を反映するには再ビルドしてください。

## Cloudflare を使った開発

`bun run dev` は、ホットリロード付きの開発サーバーを http://localhost:3000 で起動します。`DB` と `CACHE` のバインディングはリモートのプレビュー用リソースに接続するため、開発中の書き込みはプレビュー用データベースに反映されます。

```sh
bunx wrangler login
cp .env.example .env.development
bun run db:migrate:development
bun run dev
```

1. Wrangler で Cloudflare にサインインします。
2. [環境変数](/docs/getting-started/environment-variables)の説明に従って `.env.development` に値を記入し、`POLAR_SERVER=sandbox` を設定します。
3. 自分の Cloudflare アカウントで D1 データベースと KV 名前空間を作成し、`wrangler.jsonc` の `development` と `preview` の ID を置き換えます。コミットされている ID は既存のデプロイのものです。[プレビューをデプロイする](/docs/getting-started/deploy-preview)を参照してください。
4. マイグレーションを適用し、サーバーを起動します。

アカウントはサインインする前にメールアドレスを認証する必要があるため、メールによるサインアップには動作する Resend の設定が必要です。開発用の管理者シードはありません。サインアップしてアドレスを認証し、`bun run db:studio:development` で自分のユーザーの `role` を `admin` に設定してください。
