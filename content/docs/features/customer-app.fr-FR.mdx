## Layout

`src/routes/app.tsx` valide les paramètres de recherche de chaque page de l’espace, le protège avec `requireSignedIn` et précharge ses espaces de noms :

```tsx
const NAMESPACES = ["auth.errors", "pages.app.sidebar", "pages.license", "timezones"] as const

export const Route = createFileRoute("/app")({
  validateSearch: appSearchSchema,
  beforeLoad: requireSignedIn,
  component: AppLayout,
  loader: ({ context }) => preloadNamespaces({ locale: getCurrentLocale(), namespaces: NAMESPACES, queryClient: context.queryClient }),
  pendingComponent: AppPending,
  staticData: { namespaces: NAMESPACES },
})
```

`AppLayout` affiche `AppSidebar` et `AppHeader` de `src/presentation/components/custom/app` dans le `SidebarProvider` de shadcn. La barre latérale construit ses liens à partir de `APP_NAVIGATION` dans `src/data/navigation.ts` (Vue d’ensemble et Paramètres de `core.navigation.ts`, Licence de `license.navigation.ts`, avec les libellés de `navigation.core.json` et `navigation.license.json`), lit l’utilisateur dans le contexte de route (`getRouteApi("/app")`) et se termine par `SignOutButton`. L’en-tête affiche la page courante et un lien de retour vers le site. Après la connexion, les administrateurs arrivent sur `/admin` et tous les autres sur `/app`.

## Pages

| Route           | Contenu                                                                                                                                                                                             |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/app`          | `LicenseOffer` sans licence active, sinon `LicenseStatusCard` (offre, statut et lien vers la page de licence) ; liens vers la documentation et vers l’assistance par e-mail.                        |
| `/app/license`  | `LicenseOffer` sans licence active, sinon `LicenseCard` (clé, commandes de la CLI, lien vers le portail client, comment changer d’offre) et, une fois la clé émise par Polar, `LicenseActivations`. |
| `/app/settings` | `PreferencesCard` : le fuseau horaire de toutes les dates de l’espace de travail, avec une recherche et **Détecter depuis ce navigateur**. Voir [Paramètres](/docs/features/settings).              |

`LicenseOffer` (`src/presentation/components/custom/app/license-offer.tsx`) réutilise les `PricingTiers` de la page d’accueil avec un `CheckoutButton` pour chaque offre, ajoute les conditions d’achat (`CheckoutAgreement`) et se termine par les sections que d’autres zones y ajoutent (`LICENSE_OFFER_SECTIONS` dans `src/data/license-offer.ts`), chacune avec son squelette et les données que ses pages chargent. La zone des cours ajoute `CourseUnlocks` (`src/data/courses.license-offer.ts`) : les cours publiés qui ont des leçons payantes, avec le nombre de leçons verrouillées de chacun, compté dans D1 par `getCatalogue`. Ce bloc est omis tant qu’aucun cours n’a de leçon payante. Une licence remboursée garde sa carte, et l’offre d’achat s’affiche à côté.

`appSearchSchema` (`src/data/app.ts`) accepte deux paramètres facultatifs, tous deux ignorés s’ils sont invalides :

| Paramètre    | Valeur                       | Effet                                                                                                                                                                  |
| ------------ | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tier`       | une valeur de `LICENSE_TIER` | `ChosenTier` au-dessus de l’offre d’achat : l’offre choisie, son prix et un bouton **Passer au paiement**.                                                             |
| `checkoutId` | un UUID fourni par Polar     | `CheckoutActivation` à la place de l’offre d’achat jusqu’à ce que la licence soit active, puis un remerciement. Voir [Paiements et licences](/docs/features/payments). |

Les loaders de la vue d’ensemble et de la licence préchargent `currentLicenseQuery` et le catalogue des cours ; `/app/license` précharge aussi `licenseActivationsQuery`. `/app/settings` ne charge que l’espace de noms de sa page, et les `NAMESPACES` du layout incluent `timezones` pour les noms des fuseaux horaires. Le paiement, les webhooks et les états de licence sont décrits dans [Paiements et licences](/docs/features/payments).

## Instructions de la CLI [#cli-instructions]

`LicenseCard` liste les commandes qui utilisent la clé sur un appareil, <RepositoryFact name="cliLicenseCommands" />, chacune avec ce qu’elle fait, et indique que la CI lit la clé dans <RepositoryFact name="cliLicenseKeyVariable" />. Leur seule source est `src/data/cli.ts`, qui construit aussi la commande <RepositoryFact name="scaffoldTarget" /> de la page d’accueil. `CLI_RELEASE_CHANNEL` nomme le tag npm depuis lequel la CLI s’exécute. La CLI et `@saasyland/stack` sont publiés ensemble sous une même version : `cli.test.ts` échoue donc si ce tag n’est pas celui sous lequel le `@saasyland/stack` installé a été publié, soit `beta` pour une préversion `x.y.z-beta.n` et le tag par défaut de npm pour une version stable. Mettre à jour `@saasyland/stack` vers une version stable fait donc échouer les tests jusqu’à ce que `CLI_RELEASE_CHANNEL` nomme le tag par défaut, et la page de licence, la page d’accueil, la documentation et la [suite de parcours client](/docs/tooling/playwright#journey-suite) le suivent. C’est une constante plutôt qu’un import de `@saasyland/stack/package.json`, qui mettrait le fichier entier dans le Worker et dans le bundle de chaque page.

## Squelettes

`AppSettingsPending` (`app/core-pending.tsx`) dessine l’en-tête de la page et `PreferencesCardPending`. `AppOverviewPending` et `AppLicensePending` (`app/license-pending.tsx`, déclarés par la zone de la licence dans `src/data/license.skeletons.ts`) reflètent l’état que la page va afficher : ils lisent les paramètres de recherche avec `appSearchSchema` ainsi que la licence et le catalogue mis en cache dans le client de requêtes, et dessinent le panneau d’activation, l’offre choisie, la grille des offres avec une ligne par cours ayant des leçons payantes, ou les cartes de licence.

Il n’y a dans `/app` ni historique de facturation, ni écrans de cours, et `/app/settings` n’a pas encore de formulaires pour le profil, l’adresse e-mail ou le mot de passe.
