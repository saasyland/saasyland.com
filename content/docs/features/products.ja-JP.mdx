このページは saasyland.com 自身の課金を説明します。生成したプロジェクトの課金は `src/data/marketing.ts` の `BILLING_GENERATION` で決まり、現在は <RepositoryFact name="billingGeneration" /> です。

## Polar のカタログ

商品は Polar が管理しています。Core、Complete、Agency の各プランと、組織にあるそれ以外の商品です。`/admin/products` は、アクセスのたびに `src/lib/polar-catalogue.ts` の `getPolarProducts` で商品を読み込みます。これは `authorized({ product: ["read"] })` で保護されたサーバー関数です。SDK の商品サービス（`src/integrations/polar/polar.config.ts` の `polar.products`）で組織の商品をページごとに名前順で取得し、`POLAR_ACCESS_TOKEN` に `products:read` スコープが必要です（[Polar の設定](/docs/getting-started/polar-setup)を参照）。

商品ごとに、次の内容を返します。

- 名前と説明
- アーカイブされていない価格。固定価格は `fromMinorUnits` で通貨の主単位に換算した金額、任意の金額の価格はその最低額、シート単位・数量単位・従量制の価格は料金モデルと通貨
- サブスクリプションの請求期間。商品の `recurring_interval` と `recurring_interval_count` から求めます
- 各ライセンスキーの特典のアクティベーション上限、または上限なし
- `src/integrations/polar/polar.constants.ts` の `POLAR_PRODUCT_STATUSES` にあるステータス。アーカイブされた商品はアーカイブ済み、それ以外は公開範囲である公開、非公開、下書きのいずれか
- Polar のダッシュボードにある商品へのリンク。`polarDashboardUrl` が `POLAR_SERVER` に対応する `POLAR_DASHBOARD_HOSTS` と `POLAR_ORGANIZATION_SLUG` から組み立てます

Polar がリクエストを拒否するか失敗すると、`getPolarProducts` はエラーをログに記録し、商品なしで `POLAR_READ.UNAVAILABLE` を返します。このときページは Polar から商品が届かなかったことを伝えて確認すべきスコープを示し、ダッシュボードの商品数にも商品は数えられません。

## 販売数と売上

`src/modules/order/use-cases/get-product-sales.ts` の `getProductSales`（`order: ["read"]`）は、D1 にある注文のコピーを読み込みます（[決済](/docs/features/payments#orders-and-subscriptions-in-d1)を参照）。商品ごとに、ステータスが <RepositoryFact name="revenueOrderStatuses" /> のいずれかである注文を返金されたものも含めて数え、返金後の支払額を通貨ごとに合計します。異なる通貨を合算することはありません。下書き、保留中、無効の注文は販売に含めません。そうした注文がない商品は販売なしとなり、商品がもう Polar にない注文はどの行にも表示されません。

## 管理画面

`src/routes/admin.products.index.tsx` は `polarProductsQuery` と `productSalesQuery` を事前に読み込み、`PolarProductGrid`（`custom/admin/products/polar-product-grid.tsx`）を表示します。これは両者を商品 ID で結び付け、その行を `usePolarProductColumns`（`polar-product-columns.tsx`）を使った `DataGrid` に渡します。

```tsx
<DataGrid
  columns={columns}
  data={rows}
  empty={t("table.empty")}
  emptyDescription={t("table.emptyDescription")}
  id={POLAR_PRODUCT_GRID_ID}
  label={t("title")}
  search={t("table.search")}
  selectable
/>
```

列は、説明付きの商品、請求期間付きの価格、ライセンスキーで有効化できる端末の台数、ステータス、販売数、通貨ごとの返金後の支払額、そして Polar のダッシュボードにある商品ページへのリンク付きの Polar ID です。カタログ全体がブラウザーにあるため、名前での検索、ステータスでの絞り込み、販売数の範囲指定、名前・ステータス・販売数での並べ替えはブラウザー側で行います。チェックボックスで商品を選択して CSV に書き出せます。

一覧は読み取り専用です。商品の作成、編集、アーカイブは Polar のダッシュボードで行い、各行からそこへリンクしています。

## D1 の商品テーブル

`src/modules/product` には今も `product` テーブルとそのユースケースが、`src/modules/category` には `category` テーブルがあります（[カテゴリー](/docs/features/categories)を参照）。ただし、どの画面もこれらを読み書きせず、購入処理も一度も使っていません。購入者が買うのは Polar の商品です（[ライセンス](/docs/features/licences)を参照）。
