Todo ambiente vincula um namespace KV como `CACHE`. Ele guarda uma entrada.

## Contagem de estrelas do GitHub

A contagem de estrelas exibida no site, implementada em `src/lib/github.ts`:

- `getStarCount` lê a entrada `github:<owner>/<repo>:stars`.
- Sem uma entrada, ele busca o repositório na API do GitHub com um timeout de <RepositoryFact name="starCountFetchTimeoutSeconds" unit="second" />, retorna a contagem e grava `count` e `fetchedAt` no KV com `waitUntil`.
- Quando a entrada tem mais de <RepositoryFact name="starCountRefreshHours" unit="hour" /> (`STAR_COUNT_REFRESH_AFTER_MS`), ele retorna a contagem em cache e a atualiza em segundo plano.
- `starCountQuery` mantém o resultado no cache de queries pelo mesmo tempo: `STAR_COUNT_REFRESH_AFTER_MS` também é o seu `gcTime` e, em todo build exceto o de teste, o seu `staleTime`. O Worker de teste responde à API do GitHub com uma contagem fixa, então ali `starCountStaleTime` nunca a deixa ficar desatualizada, e uma página que o `build:test` pré-renderizou não pede a contagem de estrelas, por mais antigo que seja o build.

As entradas não têm expiração no KV; é `fetchedAt` que decide quando atualizar. A requisição ao GitHub se autentica com as credenciais do app OAuth do GitHub, `AUTH_GITHUB_CLIENT_ID` e `AUTH_GITHUB_CLIENT_SECRET`.

## Consistência e testes

O KV tem consistência eventual. Sessões, rate limits e tudo o que é usado para autorização ficam no D1.

No Vitest, `cloudflare:workers` é resolvido para `src/platform/testing/mocks/cloudflare.ts`, que fornece um `CACHE` em memória. O ambiente `test` do Wrangler usa um namespace local em `.wrangler/test`.
