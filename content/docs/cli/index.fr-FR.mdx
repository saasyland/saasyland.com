Une licence SaaSy Land est une licence pour la ligne de commande `saasyland`. Cette page décrit la version publiée sur le tag <RepositoryFact name="cliReleaseChannel" /> de npm, <RepositoryFact name="cliPackageSpec" />, et les [notes de version](/docs/cli/releases) indiquent ce que chaque version a changé.

## Ce qui fonctionne aujourd’hui

- `activate`, `whoami` et `deactivate` gèrent votre clé de licence sur un appareil.
- `--help` et `--version` fonctionnent entièrement, et chaque commande accepte `--json` et `--locale`.
- La génération de projets arrive dans une version ultérieure. D’ici là, <RepositoryFact name="cliInit" /> vérifie ses options et se termine avec le code <RepositoryFact name="cliExitNotAvailable" />, tout comme `change`, `update` et `status`. Le [configurateur](/#cli) de la page d’accueil signale la stack par défaut, celle qu’écrit la première version capable de générer des projets, et la [feuille de route](/docs/project/roadmap) indique ce qui suit.

## La lancer

Lancez la CLI depuis le tag <RepositoryFact name="cliReleaseChannel" /> avec votre gestionnaire de paquets. Rien n’est à installer globalement :

<RepositoryTable columns={["Gestionnaire de paquets", "Commande"]} name="cliRunners" />

Sans le tag, votre gestionnaire de paquets lance le tag `latest` de npm, qui contient encore la version provisoire ayant réservé le nom, et aucune de ses commandes ne fonctionne. La CLI nécessite Node.js <RepositoryFact name="cliNodeEngine" /> ou Bun.

## Activer votre clé

1. Connectez-vous et copiez votre clé depuis [votre page de licence](/app/license).
2. Lancez <RepositoryFact name="cliActivate" />. Dans un terminal, la CLI demande la clé et la masque pendant la saisie.
3. Au lieu de la saisir, vous pouvez passer la clé en argument, qui reste dans l’historique de votre shell, ou définir <RepositoryFact name="cliLicenseKeyVariable" />, qui n’y reste pas. Sans clé, `activate` utilise la clé déjà activée sur cet appareil.

`--label` nomme l’appareil sur votre page de licence ; par défaut, le nom est celui de l’hôte. Activer à nouveau un appareil conserve l’activation qu’il occupe déjà.

## Appareils

Chaque appareil que vous activez occupe une des activations de votre licence : <ActivationLimit tier="core" /> avec Core, <ActivationLimit tier="complete" /> avec Complete et <ActivationLimit tier="agency" /> avec Agency.

- <RepositoryFact name="cliWhoami" /> affiche votre offre, les activations utilisées et le nom de cet appareil.
- <RepositoryFact name="cliDeactivate" /> libère l’activation de cet appareil et en supprime la licence.
- Pour libérer l’activation d’un appareil que vous n’utilisez plus, supprimez-le sous **Appareils** sur [votre page de licence](/app/license). Le prochain `whoami` ou `deactivate` sur cet appareil s’en aperçoit.

Lorsque toutes les activations sont occupées, `activate` liste les appareils qui les occupent et vous envoie sur votre page de licence pour en libérer une.

## CI

Enregistrez la clé comme secret dans <RepositoryFact name="cliLicenseKeyVariable" />. Sur <RepositoryFact name="cliCiProviders" />, chaque exécution d’un même dépôt dérive le même identifiant d’appareil : le dépôt occupe donc une seule activation, quel que soit le nombre d’exécutions, nommée d’après le fournisseur et le nom du dépôt. Sur tout autre système de CI, ou dans un conteneur sans identifiant d’appareil, définissez <RepositoryFact name="cliCiRepositoryVariable" /> avec le nom du dépôt.

## Où la licence est conservée

La CLI conserve la licence dans <RepositoryFact name="cliCredentialsFile" />, que seul votre utilisateur peut lire (mode <RepositoryFact name="cliCredentialsFileMode" />), dans votre répertoire de configuration :

<RepositoryTable columns={["Système", "Répertoire"]} name="cliCredentialDirectories" />

Lorsque `XDG_CONFIG_HOME` n’est pas défini, Linux utilise <RepositoryFact name="cliCredentialsLinuxFallback" />. La CLI envoie à saasyland.com un hachage à clé de l’identifiant de cet appareil, jamais l’identifiant lui-même. Lorsque saasyland.com signale la licence comme remboursée ou révoquée, la CLI la supprime de l’appareil et vous renvoie vers votre page de licence et vers l’assistance.

## Variables d’environnement

| Variable                                          | Ce qu’elle définit                                                                                                        |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| <RepositoryFact name="cliLicenseKeyVariable" />   | La clé de licence, pour la CI et pour les sessions qui ne peuvent pas la demander                                         |
| <RepositoryFact name="cliCiRepositoryVariable" /> | Le nom du dépôt sur un système de CI que la CLI ne reconnaît pas                                                          |
| <RepositoryFact name="cliLocaleVariable" />       | La langue de la sortie : `--locale` d’abord, puis cette variable, puis la langue de votre système                         |
| <RepositoryFact name="cliApiUrlVariable" />       | Un autre déploiement de saasyland.com, comme une préversion : une URL `https`, ou une URL `http` sur votre propre machine |

## Scripts et agents de code

`--json` affiche le résultat ou l’erreur sous la forme d’un seul document JSON. En CI, dans un agent de code ou sans terminal, la CLI n’attend jamais de saisie : `activate` sans clé s’arrête avec le code de sortie <RepositoryFact name="cliExitUsage" /> et indique comment en passer une.

| Code de sortie                                    | Quand                                                                                                                                                              |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| <RepositoryFact name="cliExitSuccess" />          | La commande a fait ce qu’elle annonce                                                                                                                              |
| <RepositoryFact name="cliExitFailure" />          | Une erreur s’est produite dans la CLI                                                                                                                              |
| <RepositoryFact name="cliExitUsage" />            | Une option ou <RepositoryFact name="cliApiUrlVariable" /> n’est pas valide, ou la clé manque dans une session qui ne peut pas la demander                          |
| <RepositoryFact name="cliExitNotAvailable" />     | La commande n’est pas encore disponible, l’identifiant de cet appareil est illisible, ou le système n’est ni Linux, ni macOS, ni Windows                           |
| <RepositoryFact name="cliExitTemporaryFailure" /> | saasyland.com est injoignable, ou demande de réessayer plus tard                                                                                                   |
| <RepositoryFact name="cliExitProtocol" />         | saasyland.com et cette version de la CLI ne se comprennent pas ; mettez la CLI à jour                                                                              |
| <RepositoryFact name="cliExitNoPermission" />     | Aucune licence n’est activée ici, l’activation de cet appareil a été libérée, la clé est invalide, révoquée ou remboursée, ou toutes les activations sont occupées |
| <RepositoryFact name="cliExitCancelled" />        | Vous avez annulé la question avec Ctrl+C                                                                                                                           |
