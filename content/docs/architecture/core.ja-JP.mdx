title: "Core 共有カーネル"
description: "すべてのモジュールの土台となる、src/modules/_core のエラーコード、HTTP 定数、Zod フィールド、ユースケースの入力。"
---

`src/modules/_core` は、テーブルを所有しない唯一のモジュールフォルダーです。ここには、モジュールのスキーマ、Zod スキーマ、ユースケースが土台とするものだけを置き、各モジュールで再定義しないようにしています。エラーコード、HTTP と環境の定数、共有の Zod フィールドとローカライズされたテキスト、ページネーション・並び順・検索の入力です。

## 定数

| ファイル                | 内容                                                                                                                 |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `constants/errors.ts`   | `ERROR_CODES`、`ErrorCode` 型、`AppError` クラス                                                                     |
| `constants/api.ts`      | `HTTP_STATUS`、`cf-ipcountry` と `cf-connecting-ip` のヘッダー名、セキュリティヘッダー、ビルドモードごとの許可ホスト |
| `constants/ordering.ts` | 順序付きの一覧で先頭の項目が置かれる位置 `FIRST_POSITION`                                                            |

モジュールが使っても土台にはしないデータとヘルパーは `_core` の外にあります。国、通貨、ロケール、タイムゾーンのカタログは `src/data/countries.ts`、`src/data/currencies.ts`、`src/data/locales.ts`、`src/data/timezones.ts`、ストアの通貨と価格の形式は `src/data/pricing.ts`、管理画面のグラフの期間と区切りは `src/lib/time-series.ts` です。ロケールカタログには既知のすべてのロケールが含まれ、アプリケーションが提供するロケールは `src/integrations/use-intl/i18n.config.ts` の `I18N.SUPPORTED_LOCALES` です。`_core` のファイルがこのページで説明されていないと `src/__test__/module-tables.test.ts` のテストが失敗するため、新しいファイルを置くことは意識的な判断になります。

## ユーティリティ

- `utils/localized-text.ts`：JSON として保存するロケールごとのテキスト `LocalizedText`、`en-US` を必須とし各テキストを最大 <RepositoryFact name="localizedTextMaxLength" /> 文字に制限する `localizedTextSchema`、`en-US` にフォールバックする `localize`
- `utils/ordering.ts`：最大の `position` に 1 を足した値を返す `nextPosition` と、項目を同じ階層の項目の中の指定した位置へ移動する `reorder`。`reorder` は両端より外の位置をその端として扱い、一覧を `FIRST_POSITION` から番号付けし直し、`position` が変わる項目だけを返します。コース、チャプター、レッスン、資料のユースケースはこれらで `position` を詰めた状態に保ちます
- `utils/pagination.ts`：`paginationSchema`（`pageIndex`、`pageSize`）、`DEFAULT_PAGE_SIZE`
- `utils/search.ts`：`searchSchema` と `localizedSearchSchema`。管理画面の検索ユースケースの入力、その長さの上限、返す `SearchHit`
- `utils/zod-fields.ts`：`idField`、`localeField`、`positionField`（`FIRST_POSITION` 以上の整数）、`slugField` などの再利用可能な Zod フィールド

## エラー

エラークラスは 1 つ、エラーコードの一覧も 1 つだけです。

```ts
export const ERROR_CODES = {
  AUTH_API_ERROR: "AUTH_API_ERROR",
  CONFLICT: "CONFLICT",
  FORBIDDEN: "FORBIDDEN",
  INTERNAL_ERROR: "INTERNAL_ERROR",
  NOT_FOUND: "NOT_FOUND",
  TOO_MANY_REQUESTS: "TOO_MANY_REQUESTS",
  UNAUTHORIZED: "UNAUTHORIZED",
  VALIDATION: "VALIDATION",
} as const

export type ErrorCode = (typeof ERROR_CODES)[keyof typeof ERROR_CODES]

export class AppError extends Error {
  readonly code: ErrorCode

  constructor(code: ErrorCode, message: string = code) {
    super(message)
    this.name = "AppError"
    this.code = code
  }
}
```

サーバー関数は `AppError` をスローします。それ以外のエラーは `withRequest` ミドルウェアが正規化します。Better Auth の API エラーは、Better Auth のエラーキーをメッセージとする `AUTH_API_ERROR` に、Zod のエラーは `VALIDATION` になり、未知のエラーはログに記録されたうえで `INTERNAL_ERROR` になります。ブラウザでは、`src/hooks/use-error-message.ts` の `useErrorMessage()` がメッセージを `auth.errors.*` または `errors.codes.*` の翻訳に対応付けます。
