- API ліцензій для CLI: Worker віддає бандл шаблонів кожного випуску, потрібний `saasyland init`, щоб згенерувати проєкт. `POST /api/cli/v1/activations/:activationId/bundles` перевіряє ліцензію й те, що активація належить пристрою, який надсилає запит, а потім повертає HTTPS-адресу архіву випуску в новому бакеті R2 `BUNDLES` розділу ліцензій, SHA-256 JSON-вмісту архіву (дайджест, який CLI закріплює для кожного випуску), розмір архіву й час, коли спливає термін дії URL-адреси, — через `API_LIMIT.BUNDLE_URL_TTL_SECONDS` після її видачі. На випуск без архіву API відповідає `versionNotFound`, а коли бакет не вдається прочитати, — `serviceUnavailable`. Обробник Worker розділу ліцензій віддає `/bundles/<expiry>.<signature>/<version>.json.gz` з R2, щойно термін дії та HMAC пройшли перевірку, з ключем, який HKDF виводить з `AUTH_SECRET` лише для бандлів, тож облікові дані S3 не потрібні; виведення ключа, яке використовувало відтворення відео, перенесено в `src/lib/hmac.ts`, спільний для обох. Репозиторій CLI під час випуску завантажує кожен архів у бакет preview і в продакшн-бакет, а [Публікація бандлів](/docs/features/cli-licence-api#publishing-bundles) наводить ключ, тип вмісту й бакети. Політика конфіденційності зазначає, що запит бандла надсилає випуск і відповіді щодо стеку, які API не зберігає.
