## 結論から

**Next.js を選ぶ**のは、公開ページがアプリと同じくらい重要な場合です。マーケティング、ドキュメント、コンテンツをサーバーでレンダリングし、キャッシュして再検証し、画像も最適化したいなら、そのすべてが組み込まれています。チームがすでに Next.js を知っている場合、React で最大のエコシステムと採用できる人材の層が欲しい場合、Vercel でホストする予定の場合も、Next.js を選んでください。

**TanStack Start を選ぶ**のは、プロダクトの大部分がサインインの後ろにあり、ダッシュボード、テーブル、フォーム、フィルターでできている場合です。そこでは、型付きのルートと型付きの検索パラメーターが、リリース前にミスを捕まえてくれます。Server Components をコンポーネントモデルにせずにサーバー関数を使いたい場合や、TanStack が公式ホスティングパートナーとして挙げる Cloudflare Workers にデプロイする場合も、TanStack Start を選んでください。

どちらも、現在すでに本番の SaaS を動かせます。この記事の残りは、この 2 つの段落の背景にある詳細です。

## 2026年11月時点での両フレームワークの現状

**TanStack Start は安定版です。** TanStack は 2026年10月13日に「TanStack Start 1.0 がついに安定版になった」と発表しました。安定版は 1.0.0 ではなく `@tanstack/react-start` のバージョン 1.169 として公開され、TanStack の移行ガイドは 1.169 を「最初の安定版リリース」と呼んでいます。そのため、それより前のバージョン番号はリリース候補です。10月より前に書かれた比較記事は、まだ安定版ではなかったフレームワークを説明しています。

**Next.js はバージョン 16 です。** Next.js 16 は Turbopack をデフォルトのバンドラーにし、`middleware.ts` を Node.js ランタイムで動く `proxy.ts` に置き換え、React Compiler との統合を安定版にし、`"use cache"` ディレクティブを使う Cache Components を導入しました。Next.js 16.2 は 2026年3月に Adapter API を安定版にしました。16.4 では、`create-next-app` で作成した新しいアプリで Cache Components がデフォルトで有効になり、Next.js はこのモデルが「Next.js 17 でデフォルトになる」としています。2026年11月20日時点で、npm 上の最新リリースは 16.4.6 でした。

**公式の比較は異例なほど公平です。** 2026年9月11日に Next.js 16.3 を対象に確認された TanStack 自身の比較ページは、Next.js のセルフホスティングには「画像最適化と ISR の設定が含まれており、これらの機能を Vercel 専用と表示すべきではない」こと、そしてこのページが「パフォーマンスの勝者を決めるものではない」ことを述べています。TanStack Start のほうが速い、あるいは Next.js は Vercel でしか動かない、と伝える記事は、TanStack 自身よりも踏み込んだことを言っています。

## ほかのすべてを左右する違い：サーバー上で何が動くか

**Next.js はサーバーから始まります。** App Router では、デフォルトで「レイアウトとページは Server Components」です。コンポーネントはレンダリングする場所でデータを取得し、自身のための JavaScript を送らず、インタラクティブな部分には `"use client"` で印を付けます。データの変更は Server Functions で行い、クライアントコンポーネントはそれをローカルの関数のように呼び出します。コンテンツの多いページでは、これは実際の利点です。ブラウザに届く JavaScript が減り、データ取得がそれを使うマークアップの隣に置かれます。

**TanStack Start は普通の React から始まります。** ページはクライアントコンポーネントで、TanStack Start が最初のリクエストに対してサーバーでレンダリングし、ブラウザでハイドレーションします。データはルートローダーを通じて届き、サーバー専用のコードは `createServerFn` で作るサーバー関数に置きます。サーバー関数は「サーバーで実行されるが、クライアントのコードからシームレスに呼び出せる」ものです。選択的 SSR を使えばルートごとにサーバーレンダリングを無効にでき、サーバー関数を呼び出すシングルページアプリとして配信することもできます。Server Components もありますが、実験的な扱いです。ドキュメントには「デフォルトでは有効になっていない」とあり、Tanner Linsley は 1.0 の発表で「tanstack.com ではそれを使うのをやめることにした」と書いています。

**SaaS にとっての意味。** SaaS の大部分はサインインの後ろにある部分です。テーブル、フィルター、フォーム、設定といった、ページがもともとインタラクティブで、状態の大半をすでにブラウザが持っている部分です。TanStack Start のモデルのコストが最も小さくなるのはそこです。マーケティングサイト、ドキュメント、ブログはその逆で、大部分が静的で、検索エンジンに読まれ、Next.js のサーバーファーストのモデルのほうがうまく扱えます。プロダクトのどちらの半分が大きいかが、最初に答えるべき問いです。

## ルーティングと型安全性

**TanStack Router はすべてのルートに型を付けます。** TanStack Router は「与えられた型を完全に推論し、ルーティングの体験全体を通して粘り強く受け渡す」ので、存在しないルートへのリンク、足りないパスパラメーター、誤った検索パラメーターは型チェックで失敗します。検索パラメーターはルートごとに `validateSearch` で検証され、型が付きます。これは SaaS では重要です。フィルター、並べ替え、ページネーション、タブは、ビューを共有したり再読み込みしたりできるよう URL に置くべきものだからです。

**Next.js にも型付きルートがありますが、範囲が異なります。** Next.js はオプトインの `typedRoutes` オプションによって「`next/link` を使う際のタイプミスやその他のエラーを防ぐために、リンクに静的に型を付けられる」ようになり、TanStack 自身の比較ページも「IDE のヒントにすぎないと説明するのは不正確」だと注意を促しています。ただし、検索パラメーターは文字列としてページに届き、自分で、またはライブラリを使って解析し検証することになります。

これは TanStack Start を選ぶ理由として私たちが最もよく耳にするもので、私たちが選んだ理由でもあります。フィルターできるテーブルが何十もあるアプリでは URL が状態であり、それをコンパイラにチェックさせることは十分に元が取れます。

## サーバー関数とセキュリティの境界

どちらのフレームワークでも、クライアントコンポーネントからサーバーで動く関数を呼び出せます。そしてどちらでも、それは誰でも呼び出せる HTTP エンドポイントです。Next.js のドキュメントは「Server Functions には、アプリケーションの UI からだけでなく、直接の POST リクエストでも到達できます。すべての Server Function の中で、必ず認証と認可を検証してください」と明言しています。TanStack Start の `createServerFn` にも同じことが当てはまり、そのチェックを置くべき場所はミドルウェアです。

チェックをアプリの入り口ではなく各関数の中に置くべき理由は、3 つのインシデントが示しています。

- **CVE-2025-29927、2025年3月。** Next.js に、「認可チェックがミドルウェアで行われている場合、Next.js アプリケーション内の認可チェックを回避できる」という脆弱性がありました。深刻度は Critical と評価され、11.1.4 以降のリリースが影響を受け、12.3.5、13.5.9、14.2.25、15.2.3 で修正されました。Vercel のポストモーテムによれば、`next start` と `output: 'standalone'` を使うセルフホストのアプリは影響を受け、Vercel、Netlify、Cloudflare Workers 上のアプリは影響を受けませんでした。
- **CVE-2025-55182、2025年12月。** React は「React Server Components における、認証不要のリモートコード実行の脆弱性」を公表し、CVSS 10.0 と評価されました。影響は Server Components をサポートするすべてのフレームワークとバンドラーに及び、その中には `next`、`react-router`、`@vitejs/plugin-rsc` も含まれていました。Next.js では 15.x と 16.x の App Router のアプリが影響を受け、Pages Router のアプリは影響を受けませんでした。TanStack Start はリストに含まれていませんでした。Server Components がオプトインだからですが、その実験的なセットアップは `@vitejs/plugin-rsc` を使っています。
- **CVE-2026-102989、2026年9月。** TanStack は「TanStack Start のサーバー関数のレスポンス処理における、重大な反射型クロスサイトスクリプティング（XSS）の脆弱性」を公表しました。影響を受けたのは 1.143.12 以降の `@tanstack/react-start` で、1.168.60 で修正されました。

どちらのフレームワークも脆弱性と無縁ではなく、新しいフレームワークほど攻撃にさらされてきた期間は短くなります。SaaS を守るのは、すべてのサーバー関数での認可チェックと、数日以内にアップデートする習慣です。saasyland.com では、すべてのサーバー関数が `auth.middleware.ts` のミドルウェアのうちその関数に合うもの、たとえばサインイン済みのユーザーや権限には `authorized(...)` を実行しており、[サーバー関数の規約](/docs/conventions/server-functions)では、ルートガードを決して認可として扱わない理由を説明しています。

## ホスティング：Vercel、Node サーバー、Cloudflare Workers

### Next.js

**Next.js は Node.js が動く場所ならどこでも動きます。** デプロイガイドには、プラットフォームに「Node.js サーバーが必要です。それだけです。`next start` のプロセス 1 つで、Next.js のすべての機能が正しく処理されます」とあります。Next.js 16.2 以降、Adapter API は安定版で、OpenNext、Netlify、Cloudflare、AWS Amplify、Google Cloud とともに作られました。ドキュメントには Vercel 向けと Bun 向けの 2 つの検証済みアダプターが記載されており、Cloudflare と Netlify もそれぞれのアダプターに取り組んでいます。

**複数のインスタンスをセルフホストするには設定が必要です。** ISR と Cache Components が使うキャッシュは「各 Next.js サーバーインスタンスのローカルファイルシステム（ディスク）上」に保存され、「あるインスタンスで `revalidateTag()` を呼び出しても、無効化されるのはそのインスタンスのキャッシュだけ」なので、複数のインスタンスには共有のキャッシュハンドラーが必要です。また、すべてのインスタンスに同じ `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` も必要で、そうしないとデプロイ後にユーザーに「Failed to find Server Action」エラーが表示されます。

**Vercel は最もスムーズな道で、SaaS には Pro が必要です。** Vercel の規約には「Hobby プランのサービスは、個人的または非商用の利用にのみ使用するものとする」とあるので、料金を取るプロダクトは Pro に置くべきです。Pro は月額 $20 のプラットフォーム料金で、デプロイできるシート 1 つと $20 分の利用クレジットが含まれます。有料シートの追加は 1 つにつき月額 $20 で、閲覧者のシートは無料、クレジットを超えた利用分は従量課金です。

**Cloudflare Workers では、Next.js は再実装かアダプターを通じて動きます。** Cloudflare は「Cloudflare Workers で Next.js アプリケーションを動かすデフォルトの方法として vinext を推奨」しています。vinext は Next.js の API を再実装した Vite プラグインで、Cloudflare のドキュメントには「vinext はベータ版」とあります。vinext 自身の README は、本番環境で使うべきかという問いに「使えますが、注意が必要です」と答え、Vercel の外で Next.js を動かす成熟した方法が必要なら「OpenNext のほうが安全な選択」だと付け加えています。OpenNext の Cloudflare アダプターは、Next.js 16 のすべてのマイナーバージョンとパッチバージョンに対応しています。

### TanStack Start

**TanStack Start は Vite アプリケーションであり、そのとおりにデプロイできます。** ホスティングガイドは、Cloudflare、Netlify、Railway の 3 つを公式ホスティングパートナーとして推奨し、Nitro を通じて Vercel、Node サーバー、Bun などを挙げています。Cloudflare では Cloudflare 自身の Vite プラグインでビルドするので、アプリはそのまま Worker になり、D1、KV、R2 は、別のフレームワークのランタイムを変換するアダプターを介さず、通常のバインディングとして使えます。

**その代わりに手放すのは、組み込みのキャッシュです。** TanStack Start の ISR は「どの CDN でも機能する標準の HTTP キャッシュヘッダーを活用」します。ヘッダーを設定すれば、あとは CDN が処理します。そのほうが仕組みを理解しやすい一方で、Next.js なら代わりにやってくれる作業でもあります。

saasyland.com は、Drizzle 経由の D1、KV、R2 を使う Cloudflare Worker 上で動いており、その方法は [Cloudflare Workers のドキュメント](/docs/integrations/cloudflare-workers)で説明しています。

## どちらのフレームワークにも含まれていない、SaaS に必要なもの

フレームワークは SaaS の中で最も小さな部分です。TanStack Start も Next.js も、サインイン、課金、トランザクションメール、管理画面、そしてそれらが動き続けるよう守るテストを備えておらず、残る隙間も少しずつ異なります。

- **対応言語。** Next.js の App Router には国際化されたルーティングが組み込まれていません。ガイドでは、すべてのページを `app/[lang]` フォルダーの下に置き、`proxy.js` でロケールに応じてリダイレクトし、next-intl などのライブラリを紹介しています。TanStack Router は、オプションのパスパラメーターやルートの書き換えといったプリミティブを提供し、Paraglide を使ったサンプルがあります。いずれにしても、ライブラリを選んで組み込むのは自分です。
- **画像。** Next.js には `next/image` と `next/font` があります。TanStack Start は画像を CSS、画像サービス、ホスティング先に任せています。
- **認証。** どちらも Better Auth、Clerk などのライブラリが対応しています。これらは [Better Auth、Clerk、Auth.js の比較](/blog/better-auth-vs-clerk-vs-authjs)で比較しています。
- **課金。** どちらのフレームワークも決済を受け付けません。Polar、Stripe、Lemon Squeezy は [Polar、Stripe、Lemon Squeezy の比較](/blog/polar-vs-stripe-vs-lemon-squeezy)で比較しています。

このリストに、管理コンソール、メール、テストスイート、ドキュメントを加えたものが、スターターキットの役割です。そしてその作業は、下にどちらのフレームワークがあっても変わりません。

## エコシステム、採用、AI コーディングエージェント

**Next.js のほうがはるかに大規模です。** 2026年11月12日から18日までの週に、npm のダウンロード統計では `next` が 99,343,684 回、`@tanstack/react-start` が 14,088,042 回ダウンロードされました。Next.js を知っている開発者のほうが多く、真っ先に Next.js 向けのドキュメントを用意するベンダーも、Next.js で作られたスターターキットも多くあります。これは採用、エラーメッセージの検索、サービスの統合のどれにおいても、実際の利点です。

**TanStack Start は TanStack の恩恵を受けています。** TanStack Query、Router、Table、Form はそれぞれ単体で広く使われているので、TanStack Start のアプリの大部分は、それらを使ったことがある人にはなじみのあるものです。また、SaaS に必要なサービスも TanStack Start のドキュメントを用意するようになってきており、Better Auth と Clerk にはどちらも TanStack Start のガイドがあります。

**コーディングエージェントにとっては、どちらのフレームワークも新しいものです。** Next.js 16 は middleware の名前を変え、キャッシュを変更しました。TanStack Start の安定版は `.inputValidator()` を `.validator()` に改名し、Vite 8 を必要とします。どちらを選ぶにしても、エージェントが学習で覚えた内容に頼るのではなく、最新のドキュメントを渡してください。これについては [AI コーディングエージェントのための SaaS スタックの選び方](/blog/choosing-a-saas-stack-for-ai-coding-agents)で書きました。

## Next.js のほうが良い選択になる場合

- **公開ページがビジネスを支えている。** コンテンツサイト、インデックスされるページが何千もあるマーケットプレイス、サインアップにつながるドキュメントは、Server Components、ISR、Cache Components、画像最適化を、自分で組み立てることなく活用できます。
- **Server Components をモデルにしたい。** Server Components は App Router の中核ですが、TanStack Start では実験的な機能です。
- **チームがすでに Next.js を知っている。** TanStack 自身の比較ページは「ルーティングモデルが違うことは、それだけでは健全なアプリケーションを書き直す理由にならない」としており、同じ理屈はチームの経験にも当てはまります。
- **Vercel でホストする。** プレビューデプロイ、キャッシュ、画像最適化が設定なしで動き、Pro は月額 $20 から始められます。
- **最も幅広いエコシステムが必要。** インテグレーション、サンプル、スターターキット、採用できる開発者がより多くあります。

## TanStack Start のほうが良い選択になる場合

- **プロダクトの大部分がサインインの後ろにある。** ダッシュボード、テーブル、フォームにとっては、Server Components よりも、型付きのルート、検証される検索パラメーター、明示的なローダーのほうが得るものが大きくなります。
- **クライアントファーストのメンタルモデルが欲しい。** サーバー関数とミドルウェアがあれば、サーバーとクライアントの境界をすべてのコンポーネントの一部にすることなく、サーバーのコードを書けます。
- **Cloudflare Workers にデプロイする、またはホスティング先を選べるようにしたい。** Cloudflare は公式ホスティングパートナーで、ビルドは Vite のものです。
- **フレームワークにキャッシュへ口を出させたくない。** インスタンスごとに設定するフレームワークのキャッシュではなく、HTTP キャッシュヘッダーと CDN で済みます。

## SaaSy Land が TanStack Start で作られている理由

saasyland.com は、まさに上で最初に挙げた種類の SaaS です。顧客ワークスペース、データテーブルを備えた管理コンソール、ライセンス API、チェックアウト、そして <RepositoryFact name="languages" /> 言語のブログとドキュメントがあります。2026年9月までは Vercel 上の Next.js 16 で動いていました。Cloudflare Workers 上の TanStack Start への移行は、公開されている履歴で確認できます。私たちは React <RepositoryFact name="reactMajor" />、Vite+、Cloudflare Workers とともに TanStack Start を選びました。理由は 4 つあり、どれも公開されているソースで確認できます。

1. **型付きの URL。** 検索パラメーターを読み取るルートは、`validateSearch` で Zod を使ってそれを検証するので、URL にあるフィルター、ページ番号、タブは、解析の時点でチェックされ、読み取られるすべての場所で型が付きます。[ルートファイルの規約](/docs/conventions/routes)では、すべてのルートファイルに共通する 1 つの形を示しています。
2. **明示的なミドルウェアを備えたサーバー関数。** すべてのサーバー関数は、モジュールの Zod スキーマで入力を検証し、その関数に合う認可ミドルウェアを実行します。これは、上で挙げたインシデントが求めているチェックです。
3. **ターゲットではなくプラットフォームとしての Workers。** Worker、D1、KV、R2 がアプリケーションのランタイムであり、フレームワークとプラットフォームの間にアダプターはありません。
4. **1 つのツールチェーン。** Vite+ が 1 つの `vite.config.ts` から開発サーバー、ビルド、Vitest、リンターを実行し、ステートメント、分岐、関数、行のカバレッジが <RepositoryFact name="coverageThreshold" />% を下回るとマージが失敗します。

コストも確かにあります。Server Components がないため、マーケティングページのすべてのコンポーネントが、決して変わらない部分も含めてブラウザでハイドレーションされます。その代わりに何を計測して削っているかは、[パフォーマンスの規約](/docs/conventions/performance)に記録しています。`next/image` がないため、画像と動画のポスターは自分たちで用意しています。そして、より若いフレームワークを間近で追いかけています。その安定版のリリースでは私たちが使っている API が変わりましたが、私たちは常に最新のリリースを使っています。

SaaSy Land の CLI はベータ版です。現在はライセンスを有効化します。プロジェクト生成は今後のリリースで提供予定で、Cloudflare Workers 上の TanStack Start から始まり、[コンフィギュレーター](/#cli)では Next.js を提供予定としています。それまでは saasyland.com の全体が MIT ライセンスで公開されているので、ジェネレーターがプロジェクトを書き出す元になる TanStack Start のアプリを読めます。
