## Requête de page

1. **Canonicalisation de la locale.** `src/server.ts` appelle `resolveLocale` pour les requêtes de document `GET` et `HEAD` en dehors de `/api` et `/_serverFn`. Un préfixe limité à la langue ou correspondant à la locale par défaut (`/pl/docs`, `/en-US/docs`) est redirigé en `308` vers sa forme canonique (`/pl-PL/docs`, `/docs`). Quand la locale de l'URL diffère de celle du cookie de locale, le cookie est mis à jour dans la réponse.
2. **Ressources statiques d'abord.** Le Worker demande le chemin au binding `ASSETS`. Les fichiers statiques sont renvoyés tels quels, et une page prérendue passe en flux par `withNonce`, qui pose sur ses scripts un nonce créé pour cette réponse. Ce n'est qu'en cas de `404` qu'il charge le handler TanStack Start avec un `import()` dynamique.
3. **Routage.** `getRouter` crée un nouveau routeur et un nouveau `QueryClient`. Le `rewrite` du routeur retire le préfixe de locale, si bien que `/pl-PL/docs` correspond aux routes `/docs`.
4. **Le `beforeLoad` racine** précharge les namespaces de traduction racine (`common`, `components.*`, `errors*`).
5. **Guards.** Les fonctions `beforeLoad` des layouts, comme `requireAdmin`, chargent la query de session et redirigent lorsque l'accès n'est pas autorisé.
6. **Les loaders** s'exécutent en parallèle. Chacun précharge ses namespaces, les métadonnées de la page et ses queries dans le `QueryClient` de la requête.
7. **Rendu.** Le shell racine rend `<html lang dir>` et enveloppe le body dans `TranslationsProvider`. Le cache de queries est sérialisé dans le HTML afin que le navigateur ne récupère pas à nouveau les mêmes données.
8. **En-têtes de réponse.** Pour les réponses HTML, le Worker ajoute un en-tête `Link` de préchargement pour les polices de la locale, définit le cookie de locale si nécessaire et applique les attributs de tarification régionale lorsque l'en-tête `cf-ipcountry` donne droit à une réduction. Chaque réponse renvoyée par le Worker reçoit ensuite les en-têtes de sécurité (`SECURITY_HEADERS`, plus `HTTPS_SECURITY_HEADERS` en HTTPS, issus de `src/modules/_core/constants/api.ts`), qui remplacent toute valeur déjà définie. Une réponse HTML reçoit à la place `documentPolicy` comme Content Security Policy, avec le nonce que `src/server.ts` a créé pour elle, et elle est `private, no-cache` sans `ETag` ni `Last-Modified`, si bien qu'un navigateur ne la réutilise jamais avec le nonce d'une autre réponse.
9. **Hydratation.** Le navigateur hydrate la page avec le cache sérialisé. Les navigations suivantes exécutent les guards et les loaders dans le navigateur et récupèrent les données via des fonctions serveur.

## Appel de fonction serveur

1. Le navigateur appelle la fonction serveur, que le build a remplacée par une requête RPC vers `/_serverFn/…`. Le Worker ignore la gestion des locales pour ce chemin. L'URL n'a pas de préfixe de locale, donc `getCurrentLocale()` renvoie `en-US` côté serveur ; une fonction serveur qui a besoin de la locale la reçoit en entrée.
2. Les middlewares s'exécutent dans l'ordre déclaré. `withRequest` capture les en-têtes de la requête et normalise les erreurs, `withRateLimit` comptabilise la tentative dans D1, et `authorized` charge la session et vérifie la permission.
3. Le validateur analyse l'entrée avec le schéma Zod du module.
4. Le handler interroge D1 ou appelle un fournisseur, puis renvoie des données simples.
5. Le composant reçoit les données ou un code `AppError`. En cas de succès, il invalide les clés de query du module ; en cas d'échec, il affiche `useErrorMessage()(error)`.

```text
GET /pl-PL/admin/users/all
  src/server.ts        resolveLocale, ASSETS lookup, TanStack Start handler
  router rewrite       /admin/users/all
  __root beforeLoad    root namespaces
  /admin beforeLoad    requireAdmin
  loaders              metadata, namespaces, queries
  SSR                  HTML with serialized query cache
  src/server.ts        Link header, locale cookie, regional pricing, security headers

POST /_serverFn/…
  withRequest → withRateLimit → authorized → validator → handler → data or AppError
```

## Requête de média

`src/server.ts` vérifie le chemin avant toute autre chose : un chemin que revendique le handler de requêtes d'une zone est confié à ce handler et échappe à la gestion de la locale, à la recherche dans `ASSETS` et à TanStack Start. La zone des cours revendique `/media/`, et son handler charge `serveMedia` (`src/modules/video/video.delivery.ts`) avec un `import()` dynamique. `serveMedia` vérifie la signature et l'expiration présentes dans le chemin, puis répond depuis le cache des Workers ou depuis R2, requêtes `Range` comprises. La zone des licences revendique `/bundles/` de la même manière, et son handler charge `serveBundle` (`src/modules/license/license.delivery.ts`), qui vérifie la signature et l'expiration puis diffuse en flux le bundle de modèles de la CLI depuis R2. La réponse reçoit les mêmes en-têtes de sécurité que toutes les autres. Voir [Cloudflare R2](/docs/integrations/cloudflare-r2).
