---
title: "Conventional Commits"
description: "Format komunikatów commitów i hook, który dodaje emoji."
---

Temat commita ma postać `<type>(<scope>): <description>`. Zakres jest opcjonalny, a `!` oznacza zmianę, która łamie zgodność. Temat pisz bez emoji:

```sh
git commit -m "fix(auth): keep the locale in verification links"
```

Hook `prepare-commit-msg` w `.vite-hooks/` uruchamia `bun scripts/commit-msg.ts`, który sprawdza temat i dopisuje na jego początku emoji przypisane do typu, więc powyższy commit dostaje temat `🐛 fix(auth): keep the locale in verification links`.

<RepositoryTable name="commitTypes" columns={["Typ", "Emoji"]} />

Inny typ albo temat w innym formacie przerywa commit i wyświetla listę dozwolonych typów. Hook nie zmienia tematu, który zaczyna się już od emoji, tematu wygenerowanego przez Gita (`Merge`, `Revert "`, `fixup!`, `squash!`) ani komunikatów scalenia, squasha i komunikatów z szablonu.

Przed hookiem komunikatu hook `pre-commit` uruchamia `bun run check:pre-commit`. Gdy komunikat jest gotowy, hook `commit-msg` uruchamia `bun scripts/verify-commit-msg.ts` na komunikacie, który Git ma zapisać, i przerywa commit przypisujący autorstwo narzędziu AI: stopkę `Co-Authored-By`, `Signed-off-by` albo inną stopkę `-by:`, która wymienia jedno z narzędzi z `AI_TOOLS`, albo wiersz zaczynający się od „Generated with”. Pomija wiersze, które Git i tak usuwa, czyli komentarze i diff pod linią z nożyczkami w `git commit -v`, i wskazuje każdy wiersz do usunięcia. Nie omijaj hooków.
