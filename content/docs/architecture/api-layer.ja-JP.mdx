アプリケーション自身の処理はサーバー関数で実装します。HTTP ハンドラーを置くのは、アプリケーションの RPC クライアント以外のものが URL を呼び出す場合だけです。具体的には、Better Auth のブラウザクライアント、OAuth プロバイダー、Polar の Webhook、ドキュメントの検索ボックス、`saasyland` CLI です。

| ファイル                     | パス                                         | メソッド          | 処理内容                                                                                                                                              |
| ---------------------------- | -------------------------------------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/routes/api/index.ts`    | `/api`                                       | GET               | JSON のステータスレスポンス `{ runtime: "cloudflare-workers" }`                                                                                       |
| `src/routes/api/auth.$.ts`   | `/api/auth/*`                                | GET, POST         | OAuth コールバック、メール認証、Polar のカスタマーポータル、`/api/auth/polar/webhooks` を含む Better Auth のすべてのエンドポイント                    |
| `src/routes/api/search.ts`   | `/api/search`                                | GET               | ドキュメントを対象とした Fumadocs の検索                                                                                                              |
| `src/routes/api/cli.v1.*.ts` | <RepositoryFact name="cliApiBasePath" />`/*` | GET, POST, DELETE | [CLI ライセンス API](/docs/features/cli-licence-api)。`licenseApiHandlers` を通じて、ライセンス、その端末、各リリースのテンプレートバンドルを扱います |

Worker は `/media/<expiry>.<signature>/<videoId>/<file>` にも自分で応答します。これはルートではありません。`src/server.ts` がこれらのリクエストをロケールミドルウェアと TanStack Start より前に `serveMedia`（`src/modules/video/video.delivery.ts`）へ渡し、`serveMedia` が署名を確認して、動画ファイルを Workers のキャッシュまたは `MEDIA` バケットから配信します。[Cloudflare R2](/docs/integrations/cloudflare-r2) を参照してください。<RepositoryFact name="cliBundleUrlPath" /> にも同じように応答します。ライセンスのエリアのハンドラーがこれを `serveBundle`（`src/modules/license/license.delivery.ts`）へ渡し、`serveBundle` が署名を確認して、CLI のテンプレートバンドルを `BUNDLES` バケットからストリーミングします。[CLI ライセンス API](/docs/features/cli-licence-api#template-bundles) を参照してください。

ハンドラーは `createFileRoute` の `server.handlers` で宣言します。Web API の `Request` を受け取り、`Response` を返します。

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## ルール

- このアプリケーションからしか呼ばれない処理のために REST エンドポイントを追加しないでください。代わりに `createServerFn` でユースケースを書きます。そうすれば、型付きの入力、ミドルウェア、クエリオプションを利用できます。
- ハンドラーは入力の検証と権限のチェックを自分で行います。サーバー関数のミドルウェア（`authorized`、`withRateLimit`）はハンドラーでは実行されません。CLI ライセンス API は、すべてのリクエストをコントラクトの `readApiRequest` で読み取り、`src/lib/rate-limit.ts` の `countRequest` でカウントし、D1 や Polar の失敗など自身のあらゆる失敗には、コントラクトの `serviceUnavailable` を返します。
- ベンダー固有の検証はインテグレーション内に置きます。Polar の Webhook 署名は、独自のハンドラーではなく、Better Auth 内の Polar プラグインが検証します。
- `/api` と `/media` のパスはローカライズもプリレンダリングもされず、Worker のロケール処理もスキップします。
