## Layout

`src/routes/app.tsx` protege el área con `requireSignedIn` y precarga sus espacios de nombres:

```tsx
const NAMESPACES = ["auth.errors", "pages.app", "pages.license"] as const

export const Route = createFileRoute("/app")({
  beforeLoad: requireSignedIn,
  component: AppLayout,
  loader: ({ context }) => preloadNamespaces({ locale: getCurrentLocale(), namespaces: NAMESPACES, queryClient: context.queryClient }),
  staticData: { namespaces: NAMESPACES },
})
```

`AppLayout` muestra `AppSidebar` y `AppHeader` de `src/presentation/components/custom/app` dentro del `SidebarProvider` de shadcn. La barra lateral construye sus enlaces a partir de `APP_NAVIGATION` en `src/data/app.ts`, lee el usuario del contexto de la ruta (`getRouteApi("/app")`) y termina con `SignOutButton`. La cabecera muestra la página actual y un enlace de vuelta al sitio web. Tras iniciar sesión, los administradores llegan a `/admin` y el resto a `/app`.

## Páginas

| Ruta           | Contenido                                                                                                                                                                    |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/app`         | `CheckoutOptions` sin licencia; si no, `LicenseStatusCard` (nivel, estado y un enlace a la página de licencia); enlaces a la documentación y al soporte por correo.          |
| `/app/license` | `CheckoutOptions` sin licencia; si no, `LicenseCard` (clave, comando de instalación, enlace al portal de cliente) y, cuando Polar ha emitido la clave, `LicenseActivations`. |

Ambos loaders precargan `currentLicenseQuery`; `/app/license` también precarga `licenseActivationsQuery`. El pago, los webhooks y los estados de la licencia se describen en [Pagos y licencias](/docs/features/payments).

En `/app` no hay historial de facturación, ajustes de cuenta ni pantallas de cursos.
