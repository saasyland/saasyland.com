Сесії зберігаються в таблиці `session` у D1 (`src/modules/session/session.schema.ts`). `auth.session.ts` читає їх через `getRequestSession`, що кешується в межах запиту, і надає `getCurrentSessionQuery` маршрутам і компонентам. Клієнтська копія ніколи не містить токена сесії.

## Сценарії використання

| Сценарій                                  | Middleware                  | Використовує       |
| ----------------------------------------- | --------------------------- | ------------------ |
| `getActiveSessions`                       | з сесією                    | `SettingsSessions` |
| `revokeSession`                           | з сесією; лише власні сесії | `SessionRow`       |
| `revokeOtherSessions`                     | з сесією                    | `SettingsSessions` |
| `listUserSessions`                        | `session: ["list"]`         | жоден екран        |
| `revokeUserSession`, `revokeUserSessions` | `session: ["revoke"]`       | жоден екран        |

`getActiveSessions` повертає непрострочені сесії поточного користувача, від найновішої, і пропускає сесії входу від імені іншого користувача.

## Інтерфейс

**Налаштування → Безпека** в `/admin/settings` показує `SettingsSessions` (`src/presentation/components/custom/admin/settings/sessions.tsx`). Кожен `SessionRow` показує пристрій (user agent або IP-адресу), останню активність і позначку поточної сесії та дає змогу відкликати цю сесію. Кнопка в заголовку відкликає всі інші сесії. Зміна пароля також оновлює список сесій.

Адміністративні варіанти для сесій інших користувачів існують лише як серверні функції.
