- I test seguono le aree. Un file di test copre un'area o un file sorgente, così escludere un'area ne toglie anche i test e tutti gli altri restano validi: i test delle pagine di amministrazione e dei loro loader sono divisi in `admin-<area>-routes.component.test.tsx` e `admin-<area>-loaders.test.ts`, quelli degli handler dell'API, degli scheletri e dei componenti condivisi in un file per ogni file sorgente. Gli elenchi che attraversano le aree sono dichiarati per area e riuniti da barrel: i dati delle query dell'amministrazione (`<area>.fixtures.ts`), le etichette delle enumerazioni (`<area>.labels.ts`), le righe di D1 (`<area>.rows.ts`), le pagine visitate dalle spec di accessibilità e delle aree di lavoro (`e2e/data/<area>.pages.ts`) e il seed del database di test (`e2e/data/<area>.seed.ts`). Le regressioni di navigazione sono passate nelle spec delle loro aree, i controlli della tabella utenti in `admin-users.spec.ts` e la navigazione della licenza in `license.spec.ts`; la spec delle aree di lavoro ora si sposta tra la panoramica e le impostazioni. Vedi [I test seguono le aree](/docs/conventions/testing#tests-follow-the-areas).
