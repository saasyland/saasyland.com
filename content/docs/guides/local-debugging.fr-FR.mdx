## Choisir un environnement

| Environnement | Commandes                                   | Données                                                                         | Fournisseurs                      |
| ------------- | ------------------------------------------- | ------------------------------------------------------------------------------- | --------------------------------- |
| Aperçu isolé  | `db:reset:test`, `build:test`, `start:test` | D1, KV et R2 locaux dans `.wrangler/test`, comptes initialisés                  | Interceptés ; aucun compte requis |
| Développement | `db:reset:local`, `db:seed:local`, `dev`    | D1, KV et R2 locaux dans `.wrangler/state`, administrateur et cours initialisés | Réels, depuis `.env.development`  |

```sh
bun run db:reset:test
bun run build:test
bun run start:test
```

L'aperçu isolé sert un build sur `http://127.0.0.1:3000` ; recompilez-le pour voir les changements du code. Connectez-vous avec l'un des comptes créés par le seed qu'énumère [Premier lancement](/docs/getting-started/first-run) et le mot de passe de `e2e/data/accounts.ts`. Les e-mails sont capturés au lieu d'être envoyés : ouvrez `/__test/emails?to=<address>` pour les lire, liens de vérification compris.

```sh
cp .env.example .env.development
bun run db:reset:local
bun run db:seed:local
bun run dev
```

Le serveur de développement tourne sur `http://localhost:3000` avec rechargement à chaud. Ses bindings `DB`, `CACHE`, `MEDIA` et `BUNDLES` sont locaux : rien de ce que vous faites n'atteint donc les données de l'aperçu ou de production. Connectez-vous avec l'administrateur initialisé décrit dans [Le seed local](/docs/tooling/database#the-local-seed). Utilisez `POLAR_SERVER=sandbox`.

## Lire les erreurs serveur

- Une fonction serveur en échec journalise `Server function failed` avec l'erreur d'origine dans le terminal qui exécute `bun run dev`, ou dans Workers Logs pour les environnements déployés. Le navigateur ne reçoit que le code d'erreur.
- `Rate-limit storage unavailable` signifie que D1 était injoignable lors d'une vérification de limite de débit ; la requête a été rejetée.
- `[license] <method> <path> failed` signifie qu'une requête à l'API de licence de la CLI a échoué sur le serveur, par exemple parce que D1 ou Polar a échoué, et que la CLI a reçu `serviceUnavailable`. L'entrée contient l'erreur avec sa cause et sa pile d'appels, et `[licence key]` à la place de la clé de l'appelant.
- `No messages/<locale>/<namespace>.json` signifie qu'une route déclare un espace de noms sans fichier pour cette langue.

## Inspecter les données

- Drizzle Studio : `bun run db:studio:local` pour la base locale ; `:preview` et `:production` exigent les variables `CLOUDFLARE_*` dans le fichier d'environnement correspondant.
- Base de test locale : `bunx wrangler d1 execute DB --env test --local --persist-to .wrangler/test --command "SELECT email, role FROM user"`.

## Réparer les fichiers générés

- Types des bindings du Worker, tables de noms de classes ou contenu de la documentation obsolètes : `bun run typegen`.
- Les traductions ne se résolvent pas : `bun run check:i18n` liste les clés manquantes par langue et les clés qui ne se résolvent pas dans leur portée `useTranslations`.
- `bun run clean` supprime la sortie de build, les caches et `.wrangler`, y compris la base de test locale ; exécutez ensuite `db:reset:test`.

## Déboguer les tests

- Lancez un seul projet ou seulement les tests concernés : `bun run test:unit`, `bun run test:component`, `bun run test:changed`, `bun run test:watch`.
- Playwright : `bun run test:e2e:headed` affiche le navigateur et `bun run test:e2e:ui` ouvre le mode UI. Les exécutions locales conservent les traces des tests en échec et ouvrent le rapport HTML en cas d'échec.
- Lancez la suite du navigateur sur un port libre de la plage du build de test quand un autre serveur occupe `127.0.0.1:3000` ou qu'un autre worktree lance sa suite : `PLAYWRIGHT_BASE_URL=http://127.0.0.1:3027 bun run test:e2e:pr`. [Playwright](/docs/tooling/playwright#running-beside-other-worktrees) explique comment choisir le port.
