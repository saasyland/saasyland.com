Vite+ (`vite-plus`, command `vp`) bundles Vite, Vitest, oxlint and oxfmt behind one CLI, and `vite.config.ts` configures all of them. `package.json` overrides `vite` with `@voidzero-dev/vite-plus-core` and pins `vitest` to 5.1.0. `vite-plus` is pinned to an exact version too; upgrade all three together with `vp migrate`, not `bun update`. The package scripts call `vp`; outside them use the global Vite+ CLI or `bunx vp`.

| Command           | Used by                                           |
| ----------------- | ------------------------------------------------- |
| `vp dev`          | `dev`                                             |
| `vp build --mode` | `build:preview`, `build:production`, `build:test` |
| `vp preview`      | `start`, `start:test`                             |
| `vp test`         | `test` and the `test:*` Vitest scripts            |
| `vp lint`         | `lint`                                            |
| `vp fmt`          | `format`, `format:check`                          |
| `vp check`        | `check`, `check:fix`                              |
| `vp staged`       | `check:pre-commit`                                |
| `vp config`       | `prepare`, which installs the Git hooks           |

## Configuration

`vite.config.ts` loads its plugins lazily. Under Vitest only `repositoryFacts()` and `@vitejs/plugin-react` load; otherwise the stack is:

- `@cloudflare/vite-plugin`: runs the Worker in the SSR environment, persists local state (in `.wrangler/test` for the `test` mode) and uses remote bindings for `development`.
- `fumadocs-mdx`: compiles the docs and blog collections.
- `repositoryFacts` (`scripts/repository-facts.ts`): serves the `virtual:repository-facts` module, the counts and versions measured from the repository at build time; see [Landing page](/docs/features/landing-page).
- `@tailwindcss/vite`: Tailwind CSS 4.
- `tanstackStart`: routing, code splitting and prerendering of public pages.
- `@vitejs/plugin-react`.
- `deployedWorker` (`scripts/deployed-worker.ts`): rebuilds the Worker after prerendering without rendered MDX and without the landing and legal page translations; see [Cloudflare Workers](/docs/integrations/cloudflare-workers).

The dev server uses port 3000 and fails if it is taken. `resolve.tsconfigPaths` provides the `~/` import alias. The same file holds the `fmt`, `lint`, `staged` and `test` sections; see [Lint and format](/docs/tooling/lint-format) and [Testing](/docs/tooling/testing).

`build.rolldownOptions.external` lists the optional peer dependencies of `@polar-sh/sdk` (OpenTelemetry and `ioredis`). They are not installed, and the module that imports them is tree-shaken out of the Worker.

## Git hooks

`bun install` runs `prepare`, which calls `vp config --no-agent` to install the hook dispatcher for `.vite-hooks/`. `pre-commit` runs `bun run check:pre-commit`, and `prepare-commit-msg` runs `scripts/commit-msg.ts` (see [Conventional commits](/docs/tooling/conventional-commits)). `vp hooks status` shows whether the hooks are active in a clone.

Prefer the package scripts; call `vp` directly for targeted runs, such as formatting or linting specific paths.
