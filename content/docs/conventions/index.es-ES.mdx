Estas páginas son el estándar de código de este repositorio. Describen cómo se escribe el código aquí, no cómo podría escribirse, y cada regla nombra los archivos que la siguen. La mayoría de las reglas las hace cumplir un comando: `bun run check` (formato, lint, tipos, traducciones y estructura de la documentación), `bun run test:coverage` (el umbral del 100 %) o la suite end-to-end. El resto se vigila en la revisión, y cada página indica cuáles.

Cuando no tengas claro cómo escribir algo, busca el ejemplo existente más parecido del mismo tipo, léelo y copia su forma. La coherencia vale más que una idea mejor a nivel local: una segunda manera de hacer lo mismo obliga a cada lector posterior, humano o agente, a aprender las dos.

## Implementación de referencia

La funcionalidad de cursos es el código más reciente del repositorio y la forma que hay que copiar. Abarca un módulo de tabla, rutas públicas y de administración, formularios, diálogos, una tabla de datos, esqueletos de carga y pruebas.

## Reglas sin excepciones

Incumplir una de ellas hace que se rechace un cambio, por bien que haga todo lo demás.

1. Sin comentarios en el código, las pruebas, los scripts, la configuración ni el CSS. Consulta [Estilo de código](/docs/conventions/code-style).
2. Sin `oxlint-disable`, `eslint-disable`, `@ts-expect-error`, `@ts-ignore`, `@ts-nocheck`, casts con `as` ni `any` para saltarse una regla. Corrige la causa.
3. Sin ternarios de varias líneas y sin `?? undefined`. Fuera de las pruebas y de `src/platform/testing`, `null` solo se escribe donde lo impone una API: al comparar con un valor que puede ser `null` y en una ref del DOM de React (`useRef<HTMLElement>(null)`). Consulta [Estilo de código](/docs/conventions/code-style).
4. Los estados, tipos, niveles, roles y demás valores del dominio son constantes con nombre, nunca literales de cadena repetidos, también en las pruebas. Las pruebas de esquema son el único lugar donde se escribe un valor almacenado. Consulta [Pruebas](/docs/conventions/testing).
5. Una carpeta en `src/modules` existe solo para una tabla de la base de datos. Consulta [Módulos](/docs/conventions/modules).
6. Cada texto visible para el usuario existe en los nueve idiomas, y lo mismo cada página de la documentación. Las cifras que muestra el sitio se miden, nunca se escriben a mano. Consulta [Traducciones y contenido](/docs/conventions/translations).
7. La cobertura se mantiene al 100 % en líneas, sentencias, funciones y ramas. Consulta [Pruebas](/docs/conventions/testing).
8. Un cambio actualiza el README, la documentación y los textos del sitio que deja inexactos, en la misma pull request.
9. Los commits y las pull requests no llevan atribución a una IA ni el trailer `Co-Authored-By`. Consulta [Git y pull requests](/docs/conventions/git-workflow).

## Definición de terminado

Un cambio está terminado cuando estos comandos pasan, en este orden, en la rama que vas a subir:

```sh
bun run check
bun run test:coverage
bun run build:test
bun run test:e2e:pr
```

`check` y las pruebas no ejercitan el build de Cloudflare: una actualización de dependencias pasó una vez ambos mientras el build de producción estaba roto. Ejecuta `build:test` en cada cambio, y la suite del navegador en todo lo que no sea documentación. Antes de hacer commit, lee tu propio diff en busca de comentarios, literales de cadena que deberían ser constantes y textos o documentación que el cambio haya vuelto incorrectos.
