## コンテンツ

- ページは、すべての言語について `content/docs/<section>/<page>.<locale>.mdx` として置きます。
- 各フォルダーの `meta.<locale>.json` がセクションのタイトル、アイコン、ページの順序を決めます。
- `src/integrations/fumadocs/fumadocs.i18n.ts` は `dot` パーサー、既定言語かつフォールバックとしての `en-US`、`hideLocale: "always"` を使います。言語プレフィックスはアプリ自身が処理するためです。
- `bun run content` は `fumadocs.config.ts` から `.source` を生成します。

## ルート

- `/docs` レイアウト（`src/routes/_site.docs.tsx`）: サーバー関数が現在の言語のページツリーを返し、レイアウトは Fumadocs の `DocsLayout` を `_site` レイアウトの中、サイトヘッダーの下、`BackToTop` の上に表示します。Fumadocs の目次は見出しへ移動するだけなので、ドキュメントには `BackToTop` が必要です。Fumadocs の `--fd-banner-height` をヘッダーの高さに設定してサイドバーと目次がヘッダーの下に固定されるようにし、サイドバーに `/docs` へのリンク付きの **ドキュメント** というタイトルを付け、GitHub へのリンクと、サイドバー下部に同じスタイルのセレクトフィールドとして並ぶ `LocaleSelect`・`ThemeSwitch` を表示します。`docs.css` を読み込み、読み込み中は `DocsPending` を表示します。ローダーはページツリーと一緒に `fumadocs` 名前空間を事前に読み込みます。ほかのすべての公開ページと同じく、ドキュメントの後にはサイトの `Footer` が続くため、法的情報のページ、連絡先のアドレス、ニュースレター、言語のリンクにはどのドキュメントページからもスクロールひとつで届きます。
- 小さい画面では、サイトヘッダーは自分のメニューをそのまま持ち、その下にドキュメントのバーが 1 本だけ並びます。レイアウトの `header` スロットである `DocsToolbar`（`custom/docs-toolbar.tsx`）には、ドキュメントのナビゲーションを開く唯一のボタン、現在のページのタイトル、検索ボタンが入ります。ナビゲーションはボタンと同じ側、つまり広い画面でサイドバーがある側から滑り込みます（`docs.css` の `#nd-sidebar-mobile`）。このバーは **ドキュメント** という名前のナビゲーションランドマークなので、ページのバナーはサイトヘッダーだけのままです。Fumadocs は自分のバーにしか高さ `--fd-header-height` を設定しないため、小さい画面ではドキュメントのレイアウトが自分で設定します。目次の列が隠れる `xl` 未満では、`docs-content.tsx` が Fumadocs の目次バーを無効にし、ブログ記事と同じく、ページの見出しを説明の下の折りたたまれた `InlineTOC` に並べるため、3 本目のバーが画面に残ることはありません。
- Fumadocs は自分のコントロールの文言を自分で書きます。検索、サイドバーのボタン、**このページの内容**、コードブロック・見出しのアンカー・アコーディオンの項目のコピーボタン、前後のページへのリンクです。`useFumadocsI18n`（`src/hooks/use-fumadocs-i18n.ts`）はこれらの文言をそれぞれ `fumadocs` 名前空間のメッセージに対応付け、ページの言語と一緒に `RootProvider` に渡すため、ほかのすべての文言と同じく `messages/<locale>/fumadocs.json` から表示されます。ポーランド語またはドイツ語のドキュメントページやブログ記事に Fumadocs の文言が英語のまま残ると、`e2e/specs/content-chrome.spec.ts` が失敗します。
- サイトヘッダーの **本文へスキップ** リンクがページで唯一のスキップリンクです。このリンクはドキュメントの記事へ移動し、その id は `docs-content.tsx` が `SITE_CONTENT_ID` に設定します。Fumadocs のドキュメントレイアウトは、記事がもう持たない id である `#nd-page` への見えない 2 本目のリンクを常に追加していました。`patches/@fumadocs%2Fbase-ui@16.19.3.patch` がレイアウトに `skipToContent` スロットを加え、`_site.docs.tsx` がそれを `false` にしています（[依存関係](/docs/conventions/dependencies)を参照）。
- `/docs/` と `/docs/$` は `loadDocsPage`（`fumadocs.docs.ts`）を呼び出し、ページを解決してからレンダリング前にコンパイル済み MDX（`docsContent`）をプリロードします。
- `/api/search` はすべての言語を対象とした Fumadocs の検索を提供します（`fumadocs.search.ts`）。

MDX ページでは `src/presentation/components/custom/mdx.tsx` の `mdxComponents` を使えます。Fumadocs の既定コンポーネント、Fumadocs の `Accordions`・`Steps`・`Tabs`、shadcn の `Alert`・`Badge`・`Button`・カードの各パーツ・`Separator`・テーブルの各パーツ、そして値を手入力する代わりにコードから表示する `RepositoryFact`・`RepositoryTable`・`TierPrice`・`ActivationLimit`・`RegionalDiscounts`（[翻訳とコンテンツ](/docs/conventions/translations)）が含まれます。リンクは自動的にローカライズされます。

## アクセシビリティ

ドキュメントページは両方のテーマで WCAG 2.2 AA を満たします。コードブロックは Shiki の GitHub Light と GitHub Dark のテーマを使い、2 つのトークンの色を置き換えて（`fumadocs.config.ts` の `colorReplacements`）すべてのトークンが 4.5:1 を満たすようにしています。コードブロックのスクロール領域はフォーカスできますが、ランドマークにはなりません。タスクリストのチェックボックスには項目のテキストで名前が付きます。`e2e/specs/accessibility.spec.ts` はドキュメントのトップページ、規約のすべてのページ、それ以外の各セクションから 1 ページずつをスキャンします。[アクセシビリティ](/docs/conventions/accessibility)を参照してください。

## ページの追加

1. `title` と `description` を付けて `<page>.en-US.mdx` を書きます。
2. スラッグを `meta.en-US.json` と、ほかのすべての `meta.<locale>.json` に同じ順序で追加します。
3. コードブロックをバイト単位で同一に保ったまま、ほかのすべての言語の翻訳を追加します。
4. `bun scripts/check-content.ts`（`bun run check:i18n` にも含まれます）と `bun run content` を実行します。

`bun run build` はすべてのドキュメントページを全言語でプリレンダリングします。
