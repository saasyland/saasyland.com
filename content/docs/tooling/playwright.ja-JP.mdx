---

Playwright は、ビルドしたアプリケーションを実際のブラウザーでテストします。スイートは Wrangler の `test` 環境に対して実行されます。この環境では、`.wrangler/test` 内のローカル D1、KV、R2、`.env.test` のダミー認証情報、そして Resend と Polar へのリクエストを横取りするテスト用エントリー `src/platform/testing/worker.ts` を使います。

```sh
bun run test:e2e:install
bun run test:e2e
bun run test:e2e:smoke
bun run test:e2e:pr
bun run test:e2e:headed
bun run test:e2e:ui
bun run test:journey
```

| スクリプト         | 実行内容                                                               |
| ------------------ | ---------------------------------------------------------------------- |
| `test:e2e:install` | Chromium と WebKit をシステムの依存関係とともにインストールします      |
| `test:e2e`         | すべてのスペックを Chromium と WebKit で実行します                     |
| `test:e2e:smoke`   | `e2e/specs/smoke.spec.ts` を Chromium で実行します                     |
| `test:e2e:pr`      | プルリクエストの CI と同じく、すべてのスペックを Chromium で実行します |
| `test:e2e:headed`  | すべてのスペックを表示されるブラウザーで実行します                     |
| `test:e2e:ui`      | Playwright の UI モード                                                |
| `test:journey`     | プレビューに対する[ジャーニースイート](#journey-suite)                 |

## 設定

`playwright.config.ts` は `e2e/specs/` のスペックを実行し、`chromium`（Desktop Chrome）と `webkit`（Desktop Safari）のプロジェクトを定義し、`PLAYWRIGHT_BASE_URL` または `http://127.0.0.1:3000`（`src/data/local-server.ts` の `LOCAL_SERVER_ORIGIN`） を使います。ローカルでは、Web サーバーのコマンドが `db:reset:test`、`build:test`、`start:test` を実行します。その URL ですでに応答しているサーバーがあれば再利用するため、先に `127.0.0.1:3000` で動いている他のサーバーを停止してください。CI ではワークフローがビルドを準備し、Playwright はサーバーを起動するだけです。

| 設定       | ローカル                                         | CI                                            |
| ---------- | ------------------------------------------------ | --------------------------------------------- |
| リトライ   | <RepositoryFact name="playwrightLocalRetries" /> | <RepositoryFact name="playwrightCiRetries" /> |
| ワーカー   | <RepositoryFact name="playwrightLocalWorkers" /> | <RepositoryFact name="playwrightCiWorkers" /> |
| トレース   | 失敗時に保持                                     | 最初のリトライ時                              |
| ビデオ     | オフ                                             | 失敗時に保持                                  |
| レポーター | List と HTML                                     | GitHub と HTML                                |

## 構成

- `e2e/specs/`: スモークチェック、ランディングページとその操作、ナビゲーション、ロケール、テーマ、SEO、認証とそのリダイレクトおよびルーティング、ワークスペース、ユーザー管理、ニュースレター、コンテンツ、法務ページ、地域別価格、購入ファネル、ライセンスページ、CLI ライセンス API、アフィリエイト、動画、コース、コースへのアクセス、コース管理、フッター、フォーカスリング、スクロールバー、アクセシビリティのスペック（<RepositoryFact name="e2eSpecs" /> ファイル）。
- `e2e/pages/`: ページオブジェクト。
- `e2e/fixtures/`: 拡張した `test` フィクスチャ、キャプチャしたメール用のヘルパー、署名付きの `order.paid` Webhook を送信してライセンスを付与する `license.ts` の `deliverPaidOrder`、`accessibility.ts` の `accessibilityViolations` とライトとダークの `COLOR_SCHEMES`。
- `e2e/data/accounts.ts`: シードされるアカウント（管理者と顧客）とそのパスワード。ライセンスを持つ顧客とそのライセンス、および CLI ライセンス API のスペックが端末をアクティベートする、並列ワーカーごとのライセンスは `e2e/data/licenses.ts` にあります。
- `e2e/data/videos.ts` と `e2e/data/courses.ts`: シードされるテスト動画（ファイルは `e2e/fixtures/video/`）と、シードされるコース。コースは 1 つのチャプターに、無料プレビュー、アカウント用レッスン、有料レッスン 2 つ（うち 1 つは動画なし）を持ちます。
- `e2e/data/<area>.pages.ts` と `e2e/data/<area>.seed.ts`: 各エリアのページ（`accessibility.spec.ts` と `workspaces.spec.ts` が訪れます）と、テスト用データベースに入るそのエリアの行とメディア。`pages.entries.ts` と `seed.entries.ts` がまとめます。
- `e2e/journey/`: 独自の設定を持つ[ジャーニースイート](#journey-suite)。

テスト用 Worker は、各エリアが `e2e/data/<area>.worker.ts` で宣言し、`worker.entries.ts` がまとめたものを実行します。ライセンスのエリアは Polar のモックにテスト用のライセンスキーを登録し、Resend はキャプチャしたメールを読み取る `/__test/emails` を、ニュースレターのエリアは購読者の状態を読み取る `/__test/newsletter` を公開します。

## アクセシビリティ

`e2e/specs/accessibility.spec.ts` は `@axe-core/playwright` を通じて [axe-core](https://github.com/dequelabs/axe-core) を実行し、公開ページ、コースのページ、ドキュメントのトップページ、規約のすべてのページと、それ以外の各ドキュメントセクションから 1 ページずつ、ブログ記事、管理者とカスタマーのワークスペースをライトテーマとダークテーマで検査します。管理画面のページには `/admin/courses`、`/admin/courses/create`、シード済みのコースのエディターが含まれ、これらは `e2e/specs/workspaces.spec.ts` でも巡回します。WCAG 2.0、2.1、2.2 の A と AA のルールに加えて axe のベストプラクティスを適用し、ページが成功ステータスで読み込まれなければ失敗とし、スクロールで表示されるセクションも検査できるようページ全体をスクロールし、有限のアニメーションが終わるのを待ってから検査します。違反が 1 件でもあれば、ルール、影響度、該当するセレクターを示して失敗します。

axe はキーボードの操作の流れもレイアウトも確認できないため、サイトのヘッダーとフッターについては 3 つのスペックがそれを確認します。`e2e/specs/navigation.spec.ts` はスマートフォンのメニューがフォーカスを自身に移し、Tab を中にとどめ、背後のページを `inert` にし、フォーカスをボタンに戻すことを、`e2e/specs/footer.spec.ts` はどのロケールでも 320、390、430 px でフッターのリンク同士が接したりフッターからはみ出したりしないこと、およびホームページのセクションへのリンクが自身のセクションでだけ現在のリンクになることを、`e2e/specs/focus-rings.spec.ts` はフッターの言語切り替えと管理画面のコマンドパレットのトリガーがキーボードに対してリングを描くことを確認します。

## スクロールバー [#scrollbars]

`e2e/specs/scrollbars.spec.ts` は、`launchOptions` の `ignoreDefaultArgs` で Playwright の `--hide-scrollbars` スイッチを外して Chromium を起動します。そのため Chromium は、Windows や Linux、スクロールバーを常に表示する設定の Mac と同じく、場所を取るクラシックなスクロールバーを描画します。このスペックは、ドキュメントのページ、認証ページ、管理画面のページが、ページがスクロールしなくなるまでウィンドウを広げても見出しの位置を保つこと、ドキュメントの検索、言語の選択、ダイアログ、メニューを開いても何も動かないこと、`/admin` がウィンドウいっぱいに広がること、ライトテーマでもダークなページの背後のウィンドウがダークであることを確認します。macOS の WebKit は場所を取らないオーバーレイのスクロールバーしか描画せず、起動オプションでは変えられないため、確保した場所の確認は Chromium でのみ実行します。ヘッダーのリンクを `lg` 未満で置き換えるサイトのメニューは 768 px で確認し、開閉しても何も動かないことを確かめます。

## ジャーニースイート [#journey-suite]

`bun run test:journey` は、顧客と同じ手順でライセンスを購入し、CLI を使います。対象は `https://preview.saasyland.com` のプレビューデプロイで、支払いは Polar のサンドボックスで処理されます。`e2e/journey/playwright.config.ts` は専用の Chromium プロジェクトを持ち、Web サーバーを起動しない独立した設定なので、`test:e2e` やプルリクエストのチェックでは実行されません。プランごとに独立したテストがあり、テストは並行して実行されます。

1. **アカウント。** Resend のテスト用受信箱の新しいアドレス `delivered+journey-<run>-<tier>@resend.dev` で登録し、Resend API で認証メールを見つけて、そのリンクを開きます。
2. **価格。** `/app/license` は、`/cdn-cgi/trace` が示す、Cloudflare がランナーの所在地とみなす国の価格でプランを提示しなければなりません。`PPP_TIERS` に含まれる国では地域価格、それ以外の国では通常価格です。
3. **チェックアウト。** Polar サンドボックスのチェックアウトは、アカウントのメールアドレスが入力済みの状態で開かなければなりません。テストは [Stripe のテストカード](https://docs.stripe.com/testing)を使って支払います。請求先はポーランドで、請求先住所は国だけで済みます。
4. **注文とキー。** Polar には、プランの商品に対する支払い済みの注文が 1 件だけあり、その金額は通常価格から地域割引を引いたものでなければなりません。また `/app/license` には、Webhook が発行したキー、CLI コマンド、使用中の端末がないことが表示されなければなりません。
5. **CLI。** 公開済みの CLI は、`/app/license` のコマンドと同じく <RepositoryFact name="cliExec" /> として実行され、`SAASYLAND_API_URL` を通じてプレビューと通信します。`activate` は認証情報ファイルをモード `0600` で書き込み、もう一度アクティベートしても同じ枠のままで、`whoami` は端末を表示します。`SAASYLAND_CI_REPOSITORY` で区別される CI 端末が残りの枠（Core は最大 <ActivationLimit tier="core" /> 台、Complete は <ActivationLimit tier="complete" /> 台、Agency は <ActivationLimit tier="agency" /> 台）を埋め、次の端末は `activationLimitReached` で拒否されます。`/app/license` で枠を解放すると、拒否された端末がその枠を得て、解放された端末には `activationNotFound` が返ります。`deactivate` は最初の端末を解放し、その認証情報を削除します。
6. **返金。** Polar サンドボックスの API で注文を返金し、`/app/license` にライセンスが返金済みと表示されるまで待ちます。その後、`whoami` は `licenseRefunded` を返し、認証情報を削除しなければなりません。

CLI の各端末はテストの出力フォルダー内のディレクトリで、CLI はそれをホームディレクトリとして使います。CLI の環境には `PATH`、そのホームディレクトリ、npm のキャッシュ、`SAASYLAND_*` 変数しかないため、スイートの認証情報が CLI に渡ることはありません。失敗したテストが支払い済みのまま残した注文は、テストの終了時に返金されます。アカウントはそれぞれ返金済みのライセンスとともにプレビューに残ります。

スイートはこれらの値を環境変数から、またはファイルがあれば `.env.preview` から読み込み、値がなければ最初のテストの前に停止します。

| 変数                                                                            | 用途                                                                                         |
| ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `POLAR_ACCESS_TOKEN`                                                            | サンドボックスでの注文の読み取りと返金。スコープ `orders:read` と `refunds:write` が必要です |
| `POLAR_SERVER`                                                                  | `sandbox` でなければなりません                                                               |
| `POLAR_PRODUCT_ID_CORE`, `POLAR_PRODUCT_ID_COMPLETE`, `POLAR_PRODUCT_ID_AGENCY` | 注文の対象となるべきサンドボックスの商品                                                     |
| `RESEND_API_KEY`                                                                | プレビューが送信した認証メールの読み取り。フルアクセスのキーが必要です                       |

プレビューでは [CLI ライセンス API](/docs/features/cli-licence-api) を含むビルドが動いている必要があります。プルリクエストは **Deploy preview** ジョブでそのブランチをプレビューにデプロイします。サンドボックスはコードと一致している必要があり、`bun run polar:verify:preview` がそれを確認します。そのうえで次を実行します。

```sh
bun run test:e2e:install
bun run polar:verify:preview
bun run test:journey
```

レポートは `playwright-report/journey/` に、失敗したテストのトレース、動画、端末ディレクトリは `test-results/journey/` に書き出されます。
