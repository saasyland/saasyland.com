---
title: "Dodawanie modułu"
description: "Dodaj tabelę bazy danych ze schematem Drizzle, schematami Zod, stałymi, typami i przypadkami użycia."
---

Moduł to jedna tabela bazy danych. `src/modules/<table>/` istnieje wyłącznie dla prawdziwych tabel; funkcje serwerowe, które nie należą do żadnej tabeli, trafiają do `src/lib` albo do trasy, która ich używa. Najmniejszym kompletnym przykładem jest `src/modules/category`.

## Pliki

| Plik                       | Zawartość                                                                                                  |
| -------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `<table>.schema.ts`        | Tabela Drizzle, indeksy, relacje i krotki wartości wyliczeniowych zbudowane ze stałych                     |
| `<table>.zod.ts`           | Po jednym schemacie wejścia na operację oraz schematy `drizzle-zod`, eksportowane jako `<table>ZodSchemas` |
| `<table>.constants.ts`     | Nazwane wartości domenowe, takie jak `CATEGORY_KIND`, limity kolumn oraz krotki kluczy zapytań i mutacji   |
| `<table>.types.ts`         | Jeden interfejs z typami wierszy i typem wejścia każdej operacji                                           |
| `<table>.utils.ts`         | Opcjonalne czyste funkcje pomocnicze                                                                       |
| `use-cases/<operation>.ts` | Jedna funkcja serwerowa na plik wraz z opcjami zapytania lub mutacji                                       |
| `__test__/`                | Testy nazwane od pliku źródłowego, np. `category.schema.test.ts` i `category.zod.test.ts`                  |

## 1. Zdefiniuj tabelę

Nazwij wartości tabeli raz, w `category.constants.ts`. Schemat, schematy Zod, przypadki użycia, komponenty, testy i dane e2e importują je stamtąd, zamiast powtarzać napis taki jak `"collection"`:

```ts
export const CATEGORY_NAME_MAX_LENGTH = 255

export const CATEGORY_KIND = {
  CATEGORY: "category",
  COLLECTION: "collection",
} as const
```

Zbuduj tabelę z tych nazw:

```ts
import { index, sqliteTable, text } from "drizzle-orm/sqlite-core"

import { timestamps } from "~/src/integrations/drizzle-orm/drizzle.columns"

import { CATEGORY_KIND, CATEGORY_NAME_MAX_LENGTH } from "~/src/modules/category/category.constants"

export const CATEGORY_KINDS = [CATEGORY_KIND.CATEGORY, CATEGORY_KIND.COLLECTION] as const

export const category = sqliteTable(
  "category",
  {
    id: text("id").primaryKey(),
    kind: text("kind", { enum: CATEGORY_KINDS }).notNull().default(CATEGORY_KIND.CATEGORY),
    name: text("name", { length: CATEGORY_NAME_MAX_LENGTH }).notNull(),
    ...timestamps(),
  },
  (table) => [index("category_createdAt_idx").on(table.createdAt)],
)
```

- Nazwy kolumn zapisujemy w snake_case, a właściwości w camelCase.
- Identyfikatory to klucze główne typu `text`, wypełniane przez `v7()` z pakietu `uuid` w przypadku użycia, który wstawia wiersz.
- `...timestamps()` z `src/integrations/drizzle-orm/drizzle.columns.ts` dodaje `createdAt` i `updatedAt`: znaczniki czasu w milisekundach, domyślnie ustawiane na chwilę wstawienia; `updatedAt` jest odświeżany przy każdej aktualizacji. Pozostałe daty to `integer(..., { mode: "timestamp_ms" })`, a wartości logiczne to `integer(..., { mode: "boolean" })`.
- Kolumna wyliczeniowa dostaje krotkę zbudowaną z obiektu stałych, a jej wartością domyślną jest stała, np. `CATEGORY_KIND.CATEGORY`, nigdy literał tekstowy.
- Klucze obce używają `.references(() => user.id, { onDelete: "cascade" })`, a `relations(...)` deklaruje złączenia (zobacz `session.schema.ts`).

## 2. Zarejestruj schemat

Wyeksportuj tabelę, a także jej relacje, jeśli je ma, z `src/integrations/drizzle-orm/drizzle.schemas.ts`:

```ts
export { category } from "~/src/modules/category/category.schema"
```

Z tego pliku korzystają klient D1 (`drizzle(env.DB, { schema })`), adapter Drizzle w Better Auth oraz drizzle-kit. Tabela, której tu brakuje, nie dostanie migracji.

## 3. Wygeneruj migrację

```sh
bun run db:generate
bun run db:migrate:local
```

Przejrzyj wygenerowany SQL w `src/integrations/drizzle-orm/migrations/` i zatwierdź go razem ze schematem. Środowiska zdalne opisuje poradnik [Migracje bazy danych](/docs/guides/database-migrations).

## 4. Dodaj schematy Zod

Każda operacja ma własny schemat wejścia. Komunikaty walidacji są kluczami tłumaczeń; formularz wyświetla je przez `ValidationFieldError` w przestrzeni nazw, którą wskazuje.

```ts
import { createSchemaFactory } from "drizzle-zod"
import zod from "zod/v4"

import { MIN_FIELD_LENGTH, idField } from "~/src/modules/_core/utils/zod-fields"
import { CATEGORY_NAME_MAX_LENGTH } from "~/src/modules/category/category.constants"
import { CATEGORY_KINDS, category } from "~/src/modules/category/category.schema"

const { createInsertSchema, createSelectSchema, createUpdateSchema } = createSchemaFactory({ zodInstance: zod })

const createCategory = zod.object({
  kind: zod.enum(CATEGORY_KINDS),
  name: zod.string().min(MIN_FIELD_LENGTH, { message: "nameRequired" }).max(CATEGORY_NAME_MAX_LENGTH, { message: "nameMaxLength" }),
})

const deleteCategory = zod.object({ categoryId: idField })

export const categoryZodSchemas = {
  createCategory,
  deleteCategory,
  insert: createInsertSchema(category),
  select: createSelectSchema(category),
  update: createUpdateSchema(category),
}
```

Dodaj `messages/<locale>/<table>.validations.json` we wszystkich dziewięciu językach, ze wszystkimi kluczami używanymi przez schematy. Formularz wyświetla te klucze tylko wtedy, gdy jego trasa wstępnie ładuje tę przestrzeń nazw i przekazuje ją do `ValidationFieldError`; formularze kursów w administracji używają `course.validations`, a pozostałe formularze `auth.validations`.

## 5. Dodaj stałe i typy

```ts
export const CATEGORY_QUERY_KEYS = {
  ALL: ["category"],
  LIST: ["category", "getCategories"],
} as const

export const CATEGORY_MUTATION_KEYS = {
  CREATE: ["category", "createCategory"],
  DELETE: ["category", "deleteCategory"],
  UPDATE: ["category", "updateCategory"],
} as const
```

```ts
import type * as zod from "zod"

import type { category } from "~/src/modules/category/category.schema"
import type { categoryZodSchemas } from "~/src/modules/category/category.zod"

export interface Category {
  select: typeof category.$inferSelect
  insert: typeof category.$inferInsert
  createCategory: zod.input<typeof categoryZodSchemas.createCategory>
  deleteCategory: zod.input<typeof categoryZodSchemas.deleteCategory>
}
```

Każdy klucz zaczyna się od nazwy modułu, więc unieważnienie `ALL` odświeża wszystkie zapytania modułu.

`Category` ma jeden klucz na każdy schemat operacji; pełny moduł `category` ma też `getCategories`, `getCategory` i `updateCategory`. Funkcja serwerowa typuje wejście walidatora jako `Category["createCategory"]`, a jej opcje mutation lub query używają tego samego typu. Dodając schemat, dodaj też klucz.

## 6. Dodaj uprawnienia i przypadki użycia

- Dodaj akcje tabeli do `APP_STATEMENTS` w `src/integrations/better-auth/auth.access.ts`, jeśli operacje wymagają uprawnień. Zobacz [Role i uprawnienia](/docs/guides/roles-and-permissions).
- Dodaj po jednym pliku na operację w `use-cases/`. Zobacz [Dodawanie przypadku użycia](/docs/guides/add-a-use-case).

## 7. Przetestuj

Dodaj `__test__/<table>.schema.test.ts`, `<table>.zod.test.ts` i `<table>.types.test.ts` obok modułu oraz `use-cases/__test__/<operation>.test.ts` dla każdej operacji. Wymagane pokrycie wynosi 100%; zobacz [Pisanie testów](/docs/guides/writing-tests).
