Cette politique couvre saasyland.com, y compris l'espace client et la console d'administration, le code de ce dépôt et la CLI payante avec ses paquets : `saasyland`, `create-saasyland` et `@saasyland/stack`. `SECURITY.md`, à la racine du dépôt, dit la même chose.

## Signaler une vulnérabilité [#report]

Ne signalez jamais une vulnérabilité dans une issue, une pull request ou un commentaire publics. Signalez-la en privé, de l'une de ces deux façons :

- avec le [signalement privé de vulnérabilités](https://github.com/saasyland/saasyland.com/security/advisories/new) de GitHub ;
- par e-mail à hello@saasyland.com.

Indiquez ce qui est touché (une URL, une route, une fonction serveur, un fichier ou une commande de la CLI), les étapes pour reproduire le problème ou une preuve de concept, l'impact (ce qu'un attaquant peut lire, modifier ou faire) et le commit ou la version que vous avez testés. Écrivez en anglais ou en polonais.

Le site publie le même contact à l'adresse <RepositoryFact name="securityTxtPath" />, au format de la RFC 9116, avec les langues <RepositoryFact name="securityTxtLanguages" /> et un lien vers cette page. Le build écrit le fichier à partir de `src/lib/security-txt.ts`, et `security-txt.test.ts` échoue dès que sa date `Expires` est passée ou se situe à plus d'un an, si bien qu'il est renouvelé avant de devenir obsolète.

## Après votre signalement [#after-you-report]

Ce sont des objectifs, pas des garanties :

1. **Accusé de réception.** Vous recevez une réponse sous <RepositoryFact name="securityAcknowledgeWorkingDays" /> jours ouvrés.
2. **Évaluation.** Sous <RepositoryFact name="securityAssessWorkingDays" /> jours ouvrés, nous confirmons ou écartons le problème, évaluons sa gravité et, s'il est confirmé, planifions le correctif.
3. **Correctif.** Le correctif est appliqué à chaque version prise en charge ci-dessous, et nous vous tenons informé jusqu'à sa publication.
4. **Divulgation.** Une fois le correctif disponible, nous publions un avis de sécurité GitHub qui indique les versions corrigées et vous crédite, sauf si vous préférez ne pas être cité.

Merci de nous laisser un délai raisonnable pour corriger un problème confirmé avant de le divulguer.

## Versions prises en charge [#supported-versions]

| Version                                                                                                                                       | Prise en charge |
| --------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| saasyland.com et `main`                                                                                                                       | Oui             |
| La dernière version datée du site                                                                                                             | Oui             |
| La dernière version de `saasyland`, `create-saasyland` et `@saasyland/stack` sous l'étiquette npm <RepositoryFact name="cliReleaseChannel" /> | Oui             |
| Les versions et commits antérieurs                                                                                                            | Non             |

Ce qui est fusionné dans `main` est déployé sur saasyland.com dès que la CI passe, donc un correctif arrive d'abord sur le site ([CI/CD](/docs/tooling/ci-cd)). La CLI et ses paquets sont publiés ensemble sous une même version, et un correctif sort dans une nouvelle version sur npm, que citent les [notes de version](/docs/cli/releases). Sur une version antérieure, passez à la plus récente pour obtenir le correctif.

## Périmètre [#scope]

Dans le périmètre : saasyland.com, y compris l'espace client et la console d'administration, le code de ce dépôt, la CLI payante, les clés de licence et les activations, et le code que génère la CLI.

Hors périmètre : les vulnérabilités des services tiers comme Cloudflare, Polar et Resend, sauf si notre configuration en est la cause, et les résultats de scanners sans impact démontré.

## Règlement européen sur la cyberrésilience [#cyber-resilience-act]

SaaSy Land notifie les vulnérabilités activement exploitées et les incidents graves qui touchent ses produits via la plateforme unique de déclaration de l'UE (Single Reporting Platform), comme l'exige le règlement sur la cyberrésilience (règlement (UE) 2024/2847).
