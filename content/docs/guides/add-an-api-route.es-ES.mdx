---
title: "Añadir una ruta de API"
description: "Añade un handler HTTP bajo /api para webhooks y otros clientes externos."
---

Las rutas de API son handlers de servidor de TanStack Start en `src/routes/api/`. Las pantallas de la aplicación nunca las necesitan: llaman a funciones de servidor. Añade una ruta de API solo para clientes ajenos a la aplicación, como webhooks, clientes de terceros o rastreadores.

## Rutas existentes

| Archivo                      | Ruta                                         | Propósito                                                                                                    |
| ---------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `src/routes/api/auth.$.ts`   | `/api/auth/*`                                | Better Auth: inicio de sesión, callbacks de OAuth, verificación de correo, el portal y los webhooks de Polar |
| `src/routes/api/index.ts`    | `/api`                                       | Comprobación del entorno de ejecución que devuelve `{ "runtime": "cloudflare-workers" }`                     |
| `src/routes/api/cli.v1.*.ts` | <RepositoryFact name="cliApiBasePath" />`/*` | La [API de licencias de la CLI](/docs/features/cli-licence-api) a la que llama la CLI `saasyland`            |

El plugin de Polar no añade ningún endpoint de checkout; el checkout se inicia en las funciones de servidor `startCheckout` de los módulos de pedidos y de licencias, y ambas lo crean con `createCheckout`. Los webhooks de Polar llegan a `/api/auth/polar/webhooks`; el plugin de Polar para Better Auth verifica su firma con `POLAR_WEBHOOK_SECRET` antes de que `handlePolarEvent` (`src/integrations/polar/polar.webhooks.ts`) entregue cada evento a los manejadores de pedidos, suscripciones y licencias que enumera `POLAR_EVENT_HANDLERS`.

## Escribe un handler

Declara los métodos en `server.handlers`. Cada handler recibe la `Request` web y devuelve una `Response` web:

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: {
    handlers: {
      GET: ({ request }) => auth.handler(request),
      POST: ({ request }) => auth.handler(request),
    },
  },
})
```

Dentro de un handler:

- Valida la query o el cuerpo con un esquema Zod y devuelve `HTTP_STATUS.BAD_REQUEST` (de `src/modules/_core/constants/api.ts`) cuando falle. Si el handler necesita un estado nuevo, añádelo ahí.
- Lee la sesión con `getRequestSession(request)` y compruébala con `hasPermission`. El middleware de función, como `authorized`, se aplica a las funciones de servidor, no a los handlers.
- Limita las peticiones a los endpoints públicos con `withinRateLimit({ key, limit, windowSeconds })` de `src/lib/rate-limit.ts` y `clientAddress(request.headers)` de `src/integrations/better-auth/auth.middleware.ts`.
- Verifica las firmas antes de confiar en el contenido de un webhook.
- Devuelve cuerpos de error seguros y registra los detalles con `console.error`.

## Reglas de enrutamiento

- Las rutas `/api` nunca llevan prefijo de idioma, y el Worker omite para ellas la búsqueda de recursos estáticos y las redirecciones de idioma.
- Las URL de `/api` no llevan idioma, así que `getCurrentLocale()` devuelve ahí el idioma por defecto. Una respuesta localizada toma el idioma de la petición, por ejemplo de un parámetro de query `locale`.
- `/api` queda fuera del prerenderizado.

## Test

Llama al handler a través de las opciones de la ruta, como hace `src/routes/api/__test__/auth.test.ts` con `Route.options.server.handlers`, y simula el proveedor al que reenvía la petición.
