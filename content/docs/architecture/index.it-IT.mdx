SaaSy Land è un'unica applicazione TanStack Start eseguita come Cloudflare Worker. Il codice è suddiviso per responsabilità:

- Le **route** (`src/routes`) compongono le pagine. Un file di route dichiara i propri namespace di traduzione, la guard, il loader e i tag head, poi renderizza i componenti.
- I **moduli** (`src/modules/<table>`) esistono solo per tabelle reali del database. Un modulo possiede lo schema Drizzle della tabella, gli schemi Zod, le costanti, i tipi e i casi d'uso che la leggono o la modificano.
- Le **integrazioni** (`src/integrations/<vendor>`) configurano librerie e servizi di terze parti.
- La **presentazione** (`src/presentation`) contiene le primitive shadcn, i componenti dell'applicazione, i template React Email, gli stili, il tema e il branding.
- Il **codice condiviso** si trova in `src/data` (dati usati da più file), `src/lib` (piccole utility), `src/hooks` e `src/providers`.

```text
src/
├── routes/          Flat file routes that compose pages
├── modules/         One folder per database table, plus _core
├── integrations/    One folder per vendor
├── presentation/    Components, emails, styles, theme, branding
├── data/            Data shared by several files
├── lib/             Small shared utilities
├── hooks/           Shared React hooks
├── providers/       Application providers
├── platform/        Test runtime wiring
├── types/           Global type declarations
├── router.tsx       Router and per-request QueryClient
├── routes.ts        ROUTES path constants
└── server.ts        Cloudflare Worker entry
```

## Regole che danno forma al codice

- I file di route si limitano a comporre. Widget, dialog, form e colonne delle tabelle si trovano in `src/presentation/components/custom`, uno per file.
- I componenti leggono le proprie traduzioni e i propri dati con `useTranslations`, `useSuspenseQuery` o i dati del loader della route. Le route non passano etichette o dati come props.
- Una server function che lavora su una tabella è un caso d'uso nel modulo di quella tabella. Una server function usata da una sola route può essere definita nel file di quella route. Tutto il resto va in `src/lib`.
- Non esistono container di dependency injection né livelli di wrapper. Importa la funzione concreta dalla cartella che la possiede.
- Una costante usata da un solo file resta in quel file. Solo i dati condivisi da più file vanno in `src/data`.
