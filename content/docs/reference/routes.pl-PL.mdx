---

Każda ścieżka ma stałą w `ROUTES`, zadeklarowaną w `src/routes.ts`, który niczego nie importuje (zobacz [Ścieżki i nawigacja](/docs/conventions/routes#paths-and-navigation)). Linki używają tej stałej, na przykład `<Link to={ROUTES.SIGN_IN}>`, a router dodaje prefiks języka. Każda z poniższych stron jest też serwowana pod prefiksem każdego języka innego niż domyślny, na przykład `/pl-PL/terms`.

## Strony publiczne

Te strony znajdują się w layoucie `_site`, który renderuje nagłówek witryny. Wszystkie poza dokumentacją znajdują się też w layoucie `_marketing` (ramka strony i stopka), layout dokumentacji sam renderuje tę samą stopkę, a blog i dokumentacja mają wewnątrz nich własne layouty. Wszystkie poza stronami newslettera są prerenderowane.

## Kursy

Layout `/courses` (`_site._marketing.courses.tsx`) znajduje się, tak jak blog, w layoutach `_site` i `_marketing` i nie ma guarda: poziom dostępu każdej lekcji sprawdza serwer (zobacz [Kursy](/docs/features/courses)). Te strony czytają D1 przy każdym żądaniu i nie są prerenderowane. `/sitemap-courses.xml` nie ma pliku trasy: odpowiada na nie z D1 handler żądań w `src/server.ts` (zobacz [Mapa witryny kursów](/docs/features/seo#course-sitemap)).

## API

Ścieżki API nigdy nie są lokalizowane.

| Ścieżka                                      | Stała           | Plik trasy                                                                                                                                         |
| -------------------------------------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/api`                                       | `API`           | `api/index.ts`                                                                                                                                     |
| `/api/auth/*`                                | `API_AUTH_BASE` | `api/auth.$.ts`                                                                                                                                    |
| <RepositoryFact name="cliApiBasePath" />`/*` | brak            | `api/cli.v1.license.ts`, `api/cli.v1.activations.ts`, `api/cli.v1.activations.$activationId.ts`, `api/cli.v1.activations.$activationId.bundles.ts` |

Ścieżki API licencji CLI pochodzą z jego kontraktu, czyli z `API_BASE_PATH` i `API_ROUTE` w `@saasyland/stack/api`, a `src/routes/api/__test__/cli.v1.test.ts` sprawdza, czy router kieruje każdą z nich do jej pliku trasy (zobacz [API licencji CLI](/docs/features/cli-licence-api)).

`ROUTES.API_AUTH` zawiera ścieżki własnych endpointów Better Auth oraz endpointów jego wtyczek admin i dwuskładnikowej, względem `/api/auth`; `auth.server.ts` używa ich, aby wyłączyć endpointy z limitów żądań, a `INPUT_POLICY` w `auth.hooks.ts`, aby walidować endpointy przyjmujące hasło, imię, adres e-mail lub obraz. `ROUTES.API_AUTH_POLAR` zawiera webhooki wtyczki Polara, które `auth.server.ts` wyłącza z limitów żądań, i znika razem z obszarem polar, tak jak `API_AUTH_CUSTOMER_PORTAL`. `API_AUTH_CUSTOMER_PORTAL` i `API_AUTH_VERIFY_EMAIL` to pełne ścieżki do endpointów Better Auth, zbudowane z `API_AUTH_BASE`. `AUTH` i `NEWSLETTER` nie mają własnych stron; razem z `ADMIN`, `APP`, `API` i `COURSES` oznaczają obszary, które nigdy nie są prerenderowane (`REQUEST_RENDERED_ROUTES` w `src/routes.ts`, które odczytuje `isRequestRenderedRoute`), a `verify-build.ts` przerywa build, który prerenderował stronę pod którymkolwiek z nich.

## Media

`/media/<expiry>.<signature>/<videoId>/<file>` serwuje podpisane pliki wideo. Ta ścieżka nie ma stałej w `ROUTES` ani pliku trasy: `src/server.ts` przekazuje ją do `serveMedia` przed middleware języka, więc nigdy nie jest lokalizowana. Zobacz [Cloudflare R2](/docs/integrations/cloudflare-r2).

`/media/covers/<courseId>/<file>` serwuje publiczne okładki kursów przez `serveCover`, a `/media/downloads/<expiry>.<signature>/<attachmentId>/<fileName>` podpisane materiały lekcji przez `serveAttachment`. Kieruje je tam handler `/media/` obszaru kursów, więc one też nigdy nie są lokalizowane. Zobacz [Okładki kursów](/docs/features/courses#course-covers).

<RepositoryFact name="cliBundleUrlPath" /> w ten sam sposób serwuje podpisane paczki szablonów CLI, przez `serveBundle`, a swój prefiks
bierze z `BUNDLE_PATH_PREFIX` w `license.constants.ts`. Zobacz [API licencji CLI](/docs/features/cli-licence-api#template-bundles).
