- D1 は、Polar の注文とサブスクリプションのコピーを、Polar のエリアの 2 つの新しいテーブル `order` と `subscription`（`src/modules/order/` と `src/modules/subscription/`）に保持します。これらを読むことになる注文一覧、検索、アクセスチェックのためのもので、書き込むコードはまだありません。各行は Polar の ID と Polar のフィールド名を使った Polar のレコードで、`changed_at` は Polar のレコードのバージョンを、`placed_at` は Polar が注文を作成した時刻を保持します。アカウントを削除しても、その注文とサブスクリプションは残り、`user_id` が空になるだけです。マイグレーションは 2 つのテーブルとそのインデックスを作成するだけで、ほかの文を含んだり、それ以前からあるテーブルやインデックスを変更したりすると `migrations.test.ts` が失敗します。`polar.constants.ts` は Polar の SDK にある注文のステータス、サブスクリプションのステータス、課金間隔をすべて定義し、SDK が値を追加すると型テストが失敗します。`POLAR_ID_MAX_LENGTH` は `license.constants.ts` からそこへ移り、通貨の列は長さを `CURRENCY_CODE_LENGTH` から取ります。[決済](/docs/features/payments)を参照してください。
