## MakerKit が優れている点

MakerKit を候補に挙げているなら、このカテゴリで最も本格的な製品の 1 つを検討していることになります。何かと比べる前に、きちんと説明しておくべき製品です。

**リリースを続けており、それが何年も続いています。** Giancarlo Buomprisco は 2022年から MakerKit をフルタイムでメンテナンスしており、ホームページによれば 2024年5月以降の変更履歴のリリースは 66 回です。TanStack Start キットは 2026年7月9日に Drizzle 版、Prisma 版、Supabase 版で登場し、どれも今すぐクローンできます。

**最初のリリースからチームとシート課金。** 個人アカウントとチームアカウント、招待、ロールベースのアクセス制御がデータベースでモデル化されています。課金は定額、シート課金、従量課金のプランに対応し、Drizzle 版と Prisma 版では Stripe または Polar、Supabase 版では Stripe を使います。スーパー管理者はユーザー、組織、サブスクリプションを確認でき、ユーザーになりすましたり、アカウントを停止したりできます。最初の顧客が 10 シートの企業であっても、そのすべてがすでに書かれています。

**1 つのライセンスで選べる。** ライセンスは Supabase、Drizzle、Prisma 7 というデータレイヤーごとに販売され、そのキットの Next.js 版と TanStack Start 版の両方が含まれます。Supabase のライセンスには React Router 版も加わります。Supabase 版は Postgres の行レベルセキュリティでテナントの分離を強制し、それを pgTAP でテストしています。

**コーディングエージェント向けのツール。** キットには `AGENTS.md`、`CLAUDE.md`、`/reviewer` や `/bug-hunt` などの Claude Code スキル、MCP サーバーが含まれます。Supabase キットにはさらに `/rls-review` があり、テナントをまたぐ攻撃を pgTAP のテストとして書いて実行します。

**ドキュメント。** MakerKit のホームページには、Next.js Supabase キットについて「alone has more than 170 pages」（それだけで 170 ページを超える）とあり、TanStack Start の各版にもそれぞれ一式のドキュメントがあります。

MakerKit を値札の付いたテンプレートにすぎないと言う人は、それを読んでいません。この記事の残りでは、信頼できる 2 つの選択肢を比較します。

## 支払う前に読めるもの

これがタイトルで言っている違いであり、程度の違いではなく種類の違いです。

MakerKit の有料キットはプライベートな GitHub リポジトリにあります。購入手続きの後に招待され、ライセンスは、コードをオープンソースライセンスで公開することや、「publicly available in any form」（いかなる形でも一般に公開）することを禁じています。購入前には、ドキュメントを読み、デモを試し、**MakerKit Lite** をクローンできます。MakerKit Lite は無料で MIT ライセンスであり、「the same Turborepo structure and conventions as the paid kits, without billing, teams, or the admin panel」（有料キットと同じ Turborepo の構成と規約を持ち、課金、チーム、管理パネルはない）とされています。規約を知るためのサンプルとしては妥当です。ただし、それはお金を払う対象のコードではなく、MakerKit はソースコードの購入に返金を提供していないので、判断の材料はそのサンプルになります。

SaaSy Land の CLI とそのテンプレートもプロプライエタリです。公開されているのはそれ以外のすべてです。saasyland.com のソースは MIT ライセンスで公開されており、縮小版ではなくアプリケーション全体です。Cloudflare Worker 上の TanStack Start、Drizzle 経由の D1、二要素認証付きの Better Auth、管理画面、顧客ワークスペース、Polar のチェックアウトと Webhook、ライセンス API、Resend 経由の React Email、<RepositoryFact name="languages" /> 言語のドキュメント、そしてカバレッジゲートを支えるテストです。CLI は同じコードからプロジェクトを生成します。現在生成するのは、プラットフォーム、サインイン、管理画面のダッシュボード・ユーザー・設定、顧客ワークスペースの概要と設定、メール、そしてドキュメントとブログです。Polar のチェックアウト、Webhook、ワークスペースのライセンスページは、CLI に課金が加わるときに提供されます。そのすべてを読み、動かし、その中で作業したいかどうかを判断できます。購入後にライセンスを使っていなければ、<RepositoryFact name="refundWithdrawalDays" unit="day" />以内に全額返金を受けられます。

依存関係を採用する前にソースを読むタイプのエンジニアにとって、これはスターターキットの別の買い方です。

## 開発者、端末、クライアント

2 つのライセンスは数えるものが違い、どちらが合うかはチームの働き方によります。

**MakerKit は人を数えます。** ライセンスには 2 種類あります。「grants permission to one individual」（1 人の個人に許諾する）Developer ライセンスと、「Employees and Contractors of the Licensee, up to the number of Seats purchased」（購入したシート数までの、ライセンシーの従業員と契約者）を対象とする Team ライセンスで、後者は最大 5 シートで販売されています。どちらも自社製品は無制限に作れます。Developer ライセンスは「does not permit building End Products for Clients under any circumstances」（いかなる場合もクライアント向けの最終製品の構築を認めない）としていますが、Team ライセンスは、ソースコードを受け取るすべてのクライアントが自分の MakerKit ライセンスを持っていることを条件に、それを認めています。ライセンスはまた、競合するスターターキット、オープンソースとしての公開、コードを使った AI の学習を禁じる一方で、AI コーディングアシスタントの利用は明示的に認めています。

**SaaSy Land は端末を数えます。** ライセンスの対象は購入した個人または法人と、そのために働く人々で、各キーで同時に CLI を実行できる端末は、Core で <ActivationLimit tier="core" /> 台、Complete で <ActivationLimit tier="complete" /> 台、Agency で <ActivationLimit tier="agency" /> 台です。ライセンスページで解放した端末の枠は空きます。Core と Complete は自社製品が対象です。Agency はクライアント向けに作るアプリケーションも対象とし、生成したアプリケーションとそのソースを、クライアントが何も購入することなく、制作対象のクライアントに納品できます。どちらの製品も、コードをスターターキットとして再販することは認めていません。全文は[ライセンス](/licence)のページにあります。

ソロの開発者にとって、この違いが問題になることはほとんどありません。フリーランスで働くチームやクライアント向けに開発するチームにとっては、クライアントにライセンスを求める条件こそ費用に織り込むべき項目です。コードを受け取るすべてのクライアントに適用されるからです。

## テスト：Playwright のスイートか、すべての分岐にかかるゲートか

MakerKit の TanStack Start キットは「Playwright for E2E tests in apps/e2e; Vitest for package-level unit tests」（apps/e2e の E2E テストに Playwright、パッケージ単位のユニットテストに Vitest）を使っており、FAQ によれば「auth, billing, members, roles, admin impersonation」（認証、課金、メンバー、ロール、管理者によるなりすまし）という主要なフローが Playwright のスイートでカバーされています。Supabase 版には、データベース内で実行される pgTAP のテストが加わります。これはこのカテゴリのほとんどの製品よりも多く、特に pgTAP のテストは、B2B ソフトウェアで最も重要なテナント分離のバグを捕まえます。

一方でドキュメントには、「there is no repo-wide (root) test:unit:coverage script」（リポジトリ全体で使うルートの test:unit:coverage スクリプトはない）とも書かれています。ドキュメントにあるセットアップには、テストされていない分岐のマージを止めるものはありません。

ここが違いです。このリポジトリの `vite.config.ts` には 4 つの数値があります。

```ts title="vite.config.ts"
      thresholds: {
        branches: 100,
        functions: 100,
        lines: 100,
        statements: 100,
      },
```

4 つすべてが強制されており、現在は <RepositoryFact name="testFiles" /> 個のテストファイルに適用され、Chromium と WebKit で実行される <RepositoryFact name="e2eSpecs" /> 個の Playwright スペックがそれに加わります。E2E のスイートは、テストを書いたパスが動くことを証明します。分岐カバレッジのゲートは、不正な署名の Webhook、期限切れの招待、false を返す権限チェックのように、誰もテストしなかったエラーパスをマージできなくします。これがコーディングエージェントにとってなぜ重要なのかは、[AI コーディングエージェントに向けたリポジトリの準備](/blog/ai-coding-agents-repository-readiness)で詳しく書きました。

## 実行環境：Node ホストか Cloudflare Worker か

MakerKit の TanStack Start キットは「builds a server bundle (via Vite + Nitro) that you run with Node」（Vite と Nitro でサーバーバンドルをビルドし、それを Node で実行する）もので、Drizzle 版と Prisma 版には Railway と Docker のガイド、Supabase 版には Vercel、Cloudflare、VPS のガイドがあります。MakerKit はさらに、Void、React、Vite+、Better Auth、Postgres 上の Drizzle による Cloudflare キットを発表しており、Drizzle キットとは別に販売され、確認した日には「Coming soon」（近日公開）と表示されていました。

SaaSy Land は現在、Cloudflare Workers 向けに作られています。このサイトは、データベースに D1、その隣に KV と R2 を使う Worker 上で動いており、CLI が生成するプロジェクトも同じプラットフォームを対象にしています。用意したりパッチを当てたりするサーバーはなく、データモデルは最初のマイグレーションから D1 上の SQLite 向けに書かれています。ホスティングがすでに決まっていて、それが Node ホストなら、MakerKit のほうが合っています。Cloudflare なら、SaaSy Land は後から適応させたものではなく、そのために作られています。このサイトでの使い方は [Cloudflare Workers のドキュメント](/docs/integrations/cloudflare-workers)で説明しています。

## 対応言語

MakerKit の TanStack Start キットは、SaaSy Land と同じライブラリである use-intl を使っており、デフォルトで有効なのは英語だけです。

SaaSy Land は現在、インターフェースもドキュメントも <RepositoryFact name="languages" /> 言語で動いており、いずれかの言語でキーが欠けていたり、翻訳がプレースホルダーを落としていたりすると、チェックが CI を失敗させます。英語圏以外でも販売するなら、それはゼロから始めずに済む作業です。

## アップデート：git の upstream か、再生成した差分か

MakerKit のアップデートは git を通じて届きます。プライベートリポジトリを upstream リモートとして追加して `git pull upstream main` を実行し、ドキュメントは「opt for merging instead of rebasing」（リベースではなくマージを選ぶ）よう勧めています。MakerKit の CLI と MCP サーバーは、upstream のアップデートを取り込み、マージのコンフリクトの解決を手助けできます。ほとんどの有料キットが使うモデルの中でもよくサポートされた形ですが、限界はモデルそのものの限界です。カスタマイズすればするほど、マージのたびの規模が大きくなります。

SaaSy Land の CLI は、別のモデルのために `update` コマンドを用意しています。同じ回答で再生成できるベースラインを基準にした、生成したモジュールの差分です。これはまだ利用できません。また、ファイルを編集した後でも手間のかからないアップデートを実現できるスターターキットはありません。現在は、`saasyland.json` にある回答でクリーンなプロジェクトを再生成し、自分のプロジェクトとの差分を取ることができます。基本コードの無期限アップデートはすべてのプランに含まれています。

## MakerKit を買うべき人

最初のリリースにチーム、ロール、シート課金が必要なら、MakerKit を買ってください。MakerKit には現在それがあり、SaaSy Land にはありません。行レベルセキュリティと pgTAP のテスト付きの Supabase、あるいは 1 つのライセンスで Next.js と TanStack Start を使いたい場合も、買ってください。Node ホストにデプロイする場合、このカテゴリで最も充実したドキュメントが欲しい場合、Discord で作者に直接連絡できることにお金を払う価値がある場合も同様です。そして、今週始める必要があるなら買ってください。そのキットは今日から使えます。

フルタイムで取り組む人がメンテナンスしている良い製品であり、選んで恥ずかしい思いをすることはありません。

## 代わりに SaaSy Land を検討すべき人

決める前に本番アプリの完全なソースを読み、使う前に気が変わったら返金を受けたいなら、SaaSy Land を検討してください。D1 を使う Cloudflare Workers がターゲットである場合。<RepositoryFact name="coverageThreshold" />% のカバレッジゲートと <RepositoryFact name="languages" /> 言語を、プロジェクトの出発点にしたい場合。開発者数ではなく端末数で数えるライセンスのほうがチームに合っている場合、あるいはクライアント向けに開発していて、クライアントがそれぞれ自分のライセンスを必要としないほうがよい場合。

そして、現在の姿を理解したうえで検討してください。コンフィギュレーターで選択できるオプションを生成するベータ版 CLI のライセンスと、今すぐ読める MIT のコードベースです。現在動作するものは [CLI のドキュメント](/docs/cli)に、その後に続くものは[ロードマップ](/docs/project/roadmap)に記載しています。
