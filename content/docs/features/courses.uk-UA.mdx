Курси, туторіали й проєкти зберігаються в D1, а дивляться їх у `/courses`. Кожен урок відтворює відео з бібліотеки функції [Відео](/docs/features/videos), а його рівень доступу визначає, хто може його дивитися.

## Модель даних

Кожна таблиця має власний модуль у `src/modules` і створюється міграцією `20261113004409_salty_slipstream.sql`:

| Таблиця           | Стовпці                                                                                                                                                     |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `course`          | `slug` (унікальний), `kind` (`course`, `tutorial`, `project`), `status` (`draft`, `published`), `position`, `title`, `summary`                              |
| `chapter`         | `course_id`, `position`, `title`                                                                                                                            |
| `lesson`          | `course_id`, `chapter_id`, `slug` (унікальний у межах курсу), `access` (`preview`, `account`, `paid`), `status`, `position`, `title`, `summary`, `video_id` |
| `lesson_progress` | `user_id` і `lesson_id` (первинний ключ), `position_ms`, `completed_at`                                                                                     |

- `title` і `summary` зберігають JSON із локалями як ключами, наприклад `{"en-US": "Billing", "pl-PL": "Płatności"}` (`LocalizedText` у `src/modules/_core/utils/localized-text.ts`). `localize()` повертає текст локалі відвідувача, а якщо його немає, — `en-US`, тож завжди заповнюйте `en-US`.
- Нові рядки мають статус `draft`, а нові уроки — доступ `paid`. Показуються й віддаються лише курси та уроки зі статусом `published`; будь-який інший slug відкриває сторінку «не знайдено».
- Курси впорядковано за `position`, розділи — за `position` у межах курсу, а уроки — за `position` у межах розділу. Уроки нумеруються наскрізно в усьому курсі.
- `video_id` посилається на таблицю `video` і стає `NULL`, коли відео видаляють. Видалення курсу або розділу видаляє його уроки, а видалення уроку чи користувача — пов’язаний із ними прогрес.

## Рівні доступу

| `access`  | Хто може дивитися                                                                      |
| --------- | -------------------------------------------------------------------------------------- |
| `preview` | Усі, з входом чи без нього                                                             |
| `account` | Будь-який користувач, який увійшов                                                     |
| `paid`    | Користувач з ліцензією `active` рівня `complete` або `agency` (`COURSE_LICENCE_TIERS`) |

Ролі з дозволом `course: ["read"]`, який мають адміністратори, можуть дивитися кожен урок. Рішення ухвалює `hasLessonAccess` (`src/modules/lesson/lesson.access.ts`) для глядача, якого `resolveViewer` (`lesson.viewer.ts`) будує із сесії, ролі та `getLicense`. Цю перевірку застосовує кожна серверна функція, що віддає вміст курсів, а не лише сторінки:

- `getCatalogue` (публічна) повертає опубліковані курси з кількістю уроків, загальною тривалістю відео та кількістю безкоштовних переглядів.
- `getCourse` (публічна) повертає опублікований курс із розділами й опублікованими уроками мовою відвідувача, кожен із `locked`, `completed` і `positionMs` для глядача.
- `getLessonPlayback` (публічна) повертає підписані шляхи відтворення з `createPlayback`. Гостю без доступу вона відповідає `UNAUTHORIZED`, користувачу, який увійшов, але не має доступу, — `FORBIDDEN`, а для неопублікованого уроку чи уроку без відео — `NOT_FOUND`.
- `saveLessonProgress` вимагає сесію і перед записом перевіряє той самий доступ.

## Сторінки

Макет `/courses` (`courses.tsx`) має власну навігацію, а його тексти лежать у просторі імен `pages.courses`. Сторінки читають D1 для кожного глядача, тому не проходять пререндеринг: `ROUTES.COURSES` є в `UNLISTED_ROUTES` у `vite.config.ts`.

- `/courses`: по одній картці на кожен опублікований курс із його типом, кількістю уроків, хвилинами й безкоштовними уроками.
- `/courses/<course>`: опис, смуга прогресу для глядачів, які увійшли, посилання **Почати курс** або **Продовжити: …** на наступний урок для перегляду та програма за розділами з позначками **Безкоштовний перегляд**, тривалістю й іконками замка та завершення. Коли якийсь урок заблоковано, панель **Кожен урок входить до Complete** веде до розділу цін, а глядача, який увійшов, — до `/app/license`.
- `/courses/<course>/<lesson>`: плеєр або панель блокування з кнопкою **Увійти й дивитися**, яка після входу повертає до уроку через `redirect`, або **Отримати Complete**. Урок без відео повідомляє, що запис з’явиться незабаром. Нижче показано рівень доступу, **Позначити як завершений** для глядачів, які увійшли, і посилання на попередній та наступний уроки; на широких екранах зміст курсу залишається поруч.

## Прогрес

Для глядача, який увійшов, плеєр починає із збереженої `position_ms`, а `useLessonProgress` (`src/hooks/use-lesson-progress.ts`) зберігає позицію під час відтворення не частіше ніж раз на 15 секунд через пропси `startAt` і `onProgress` компонента `VideoPlayer`. Коли відео закінчується (`onEnded`) або глядач натискає **Позначити як завершений**, встановлюється `completed_at`, збережена позиція повертається на початок, а сторінка курсу оновлює прогрес. Встановлене `completed_at` зберігається. Гості можуть дивитися безкоштовні перегляди, але нічого не зберігається.

## Уроки та відео

Урок не зберігає власних відеофайлів. Опублікуйте запис командою `bun run video:publish:<environment>` (див. [Відео](/docs/features/videos)); скрипт виводить id відео, який потрібно записати в стовпець `video_id` уроку. Кілька уроків можуть використовувати те саме відео. Тривалість у каталозі та програмі береться з `video.duration_ms`.

## Створення курсів

Створення курсів в адмінпанелі ще немає. `/admin/courses/create` досі демонстраційний екран, де **Зберегти** та **Скасувати** нічого не роблять, `/admin/products?tab=courses` показує порожній стан, і жоден екран адмінпанелі не показує курси. Доти додавайте рядки в D1 самостійно, наприклад у Drizzle Studio через `bun run db:studio:<environment>` або через `bunx wrangler d1 execute DB --env <environment> --remote --file <file>`. Ідентифікатори не мають значення за замовчуванням; підійде будь-який унікальний рядок.

```sql
INSERT INTO course (id, slug, kind, status, title, summary)
VALUES ('course-1', 'the-walkthrough', 'course', 'published', '{"en-US":"The walkthrough"}', '{"en-US":"How the code works, subsystem by subsystem."}');

INSERT INTO chapter (id, course_id, position, title)
VALUES ('chapter-1', 'course-1', 0, '{"en-US":"Foundations"}');

INSERT INTO lesson (id, course_id, chapter_id, slug, access, status, position, title, summary, video_id)
VALUES ('lesson-1', 'course-1', 'chapter-1', 'module-boundaries', 'preview', 'published', 0, '{"en-US":"Module boundaries"}', '{"en-US":"Why every feature starts at the module boundary."}', '<videoId>');
```

`scripts/seed-test.ts` створює такий курс з одним розділом і чотирма уроками для браузерних тестів у `e2e/specs/courses.spec.ts`.
