---
title: "Como contribuir"
description: "Como propor alterações ao SaaSy Land."
---

1. Discuta alterações grandes primeiro em uma issue.
2. Crie uma branch a partir de `main`.
3. Siga a [arquitetura](/docs/architecture) e as [convenções](/docs/reference/conventions), e leia a [skill para agentes](/docs/tooling/agent-skills) correspondente antes de alterar a integração com um fornecedor.
4. Mantenha os testes ao lado do código a que pertencem e preserve a exigência de 100% de cobertura.
5. Execute as verificações abaixo.
6. Faça o commit com uma mensagem no formato de [conventional commit](/docs/tooling/conventional-commits) e abra um pull request com um título no formato convencional.

```sh
bun run check
bun run test:coverage
bun run test:e2e:install
bun run test:e2e:smoke
```

Execute a suíte completa de testes no navegador (`bun run test:e2e`) para alterações que afetam várias rotas, a autenticação ou o comportamento no navegador. Valide separadamente as integrações reais com provedores quando alterar a configuração delas.

Quando o comportamento mudar, atualize `content/docs` nos nove locales; `bun run check:i18n` rejeita traduções ausentes, blocos de código divergentes e navegação divergente. No pull request, descreva o comportamento resultante, como você o verificou e qualquer demonstração ou fluxo inacabado que ele deixe.
