---
title: "Mitwirken"
description: "Wie du Änderungen an SaaSy Land vorschlägst."
---

1. Besprich größere Änderungen zuerst in einem Issue, das du über das Formular für Fehlerberichte oder Feature-Wünsche eröffnest.
2. Erstelle einen Branch von `main`.
3. Halte dich an die [Konventionen](/docs/conventions) und die [Architektur](/docs/architecture), und lies den passenden [Agent-Skill](/docs/tooling/agent-skills), bevor du eine Anbieter-Integration änderst. Coding-Agenten beginnen mit `AGENTS.md` im Stammverzeichnis des Repositorys.
4. Lege Tests neben ihren Besitzer und halte die Testabdeckung bei <RepositoryFact name="coverageThreshold" unit="percent" />.
5. Führe die folgenden Prüfungen aus.
6. Committe mit einer Nachricht im Format der [Conventional Commits](/docs/tooling/conventional-commits), öffne einen Pull Request mit einem konventionellen Titel und fülle dessen Vorlage aus.
7. Halte den Branch aktuell, indem du ihn auf `main` rebasest, nie indem du `main` hineinmergst, wie [Git und Pull Requests](/docs/conventions/git-workflow#linear-history) beschreibt.

```sh
bun run check
bun run test:coverage
bun run build:test
bun run test:e2e:install
bun run test:e2e:pr
```

`build:test` führt den vollständigen Cloudflare-Build aus, den `check` und die Unit-Tests nicht abdecken. `test:e2e:pr` baut und startet den Test-Worker, wenn kein Server läuft, und führt jede Spec in Chromium aus, so wie die CI bei Pull Requests. Führe zusätzlich die vollständige Browser-Suite (`bun run test:e2e`) für Änderungen aus, die sich in WebKit anders verhalten könnten. Prüfe echte Anbieter-Integrationen separat, wenn du deren Konfiguration änderst.

Wenn sich Verhalten ändert, aktualisiere `content/docs` in jeder Sprache; `bun run check:i18n` weist fehlende Übersetzungen, abweichende Codeblöcke und abweichende Navigation zurück. Die Pull-Request-Vorlage enthält eine Zusammenfassung, einen Testplan mit den obigen Prüfungen und eine Liste der aktualisierten Dokumentation; beschreibe darin das resultierende Verhalten, wie du es geprüft hast und welche Abläufe die Änderung unfertig zurücklässt. Eine Admin-Ansicht wird nur mit einer echten Quelle für ihre Daten ausgeliefert (siehe [Admin-Dashboard](/docs/features/admin-dashboard#real-data-only)).

`CONTRIBUTING.md` im Stammverzeichnis des Repositorys ist die Kurzfassung dieser Seite, und `SUPPORT.md` nennt die Wege zu Hilfe. Alle Beteiligten halten sich an `CODE_OF_CONDUCT.md`, den Contributor Covenant 2.1. Melde Sicherheitslücken vertraulich, wie in `SECURITY.md` beschrieben, und niemals in einem öffentlichen Issue.
