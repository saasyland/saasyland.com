## Open SaaS が優れている点

Open SaaS は、ほとんどの開発者がすでに名前を聞いたことのある無料の SaaS スターターであり、その評判に見合う中身があります。

**無料で、人気があります。** MIT ライセンスで、2026年11月25日時点でリポジトリには GitHub で **16,427 個のスター** が付いていました。大きなコミュニティが使ってきたので、出てくる疑問のほとんどは、すでに Issue や Wasp の Discord で答えが見つかります。

**現時点で提供している機能が多いです。** 確認付きのメールサインインに加え、Google、GitHub、Discord もすぐに有効にできます。Wasp の PgBoss ベースのジョブによるバックグラウンドジョブと cron ジョブ。AWS S3 へのファイルアップロード。Plausible または Google Analytics のアナリティクスを表示する管理ダッシュボード。OpenAI のデモアプリ。Astro Starlight によるドキュメントサイトとブログ。Stripe、Lemon Squeezy、Polar、Paddle から 1 つのファイルで選べる決済。

**1 つのコマンドでデプロイできます。** `wasp deploy` はデータベース、サーバー、クライアントを Fly.io または Railway に配置します。ワンクリックの Railway テンプレートもあり、ほかのホスティング先にも手動でデプロイできます。

**コーディングエージェントに語りかけます。** テンプレートには `AGENTS.md` と `CLAUDE.md`、`.agents` と `.claude` のエージェントスキル、`llms.txt` による LLM 向けのドキュメントがあり、リポジトリでは Claude Code プラグインも紹介されています。

**Wasp が多くの作業を代わりに引き受けます。** README では Wasp を、「認証、バックグラウンドジョブ、RPC、メール送信、エンドツーエンドの型安全性、単一コマンドでのデプロイなど、複雑なフルスタックの機能を抽象化する」フレームワークと説明しています。そうした判断を誰かに下してもらい、保守してもらいたいなら、まさにそれが手に入ります。

「決済、ジョブ、アップロードを備えた動く SaaS に、無料で最も早くたどり着く方法は何か」という問いであれば、Open SaaS はとても良い答えであり、ほかに何かが必要だと感じる必要はありません。

## 本当の違い：下にフレームワークがあるか、ないか

どちらの製品も、読んで変更できる React のコードを提供します。違いは、そのコードが何の上に立っているかです。

**Open SaaS は Wasp の上に立っています。** アプリは `main.wasp.ts` で宣言します。ルート、認証方式、ジョブ、メールの送信元、オペレーションです。Wasp CLI はその宣言を読み取り、ブラウザーでは React、サーバーでは Node.js と Prisma を使ってアプリをビルドし、実行します。Open SaaS がこれほど少ない行数で認証、ジョブ、ワンコマンドのデプロイを実現しているのはこのためです。同時に、アプリが Wasp に依存することも意味します。そのリリースのペース、バージョン間のアップグレード、そしてその CLI にです。Open SaaS 自身のテストガイドは、CI の `WASP_VERSION` をプロジェクトが使うバージョンに合わせて設定するよう求めています。Wasp の README には、「ほとんどの機能が完成し、問題なく動作している」ベータ版だと書かれています。

これはどれも欠点ではありません。トレードオフであり、多くのプロジェクトにとっては良いトレードオフです。配管部分の制御を一部手放す代わりに、多くの配管を無料で手に入れられます。

**SaaSy Land は、自社製のものの上には何も立っていません。** CLI は、選んだスタックの普通のコードを書き出します。現在は TanStack Start、React と Vite+、Better Auth、Cloudflare D1 を使う Drizzle、Resend、use-intl です。SaaSy Land のランタイムも、アプリがインポートする SaaSy Land のパッケージも、覚える必要のある独自の設定言語もありません。生成した翌日に CLI を削除しても、プロジェクトはそのままインストール、ビルド、テスト、デプロイできます。すべての行があなたのものだからです。

この選択のコストも現実のものです。Wasp なら代わりに書いてくれた部分を、CLI はあなたが所有するコードとしてプロジェクトに書き込まなければなりません。現在それは認証、メール、管理画面、ドキュメントとブログ、テストと CI ワークフローで、課金、ジョブ、アップロードはまだです。そして「選んだスタック」は、現時点では 1 つのスタックです。[ロードマップ](/docs/project/roadmap)は残りを提供順に並べています。Polar と Stripe による課金、Plunk、Postgres と Prisma、Vercel と Docker による自前のサーバー、分割 API、リアルタイム、そして Next.js、React Router、Solid、Nuxt による Vue、SvelteKit による Svelte、Analog または Angular SSR による Angular です。各オプションは、それで生成したプロジェクトが CI でインストール、型チェック、テストの合格、ビルド、起動まで通ったときにだけ有効になります。

## それぞれがコーディングエージェントに与えるもの

いまの SaaS の新しいコードのほとんどはエージェントが書いています。そのため、これが最も多くの時間を左右する問いです。

Open SaaS はエージェントに**コンテキスト**を与えます。その `AGENTS.md` は、作業を始める前に `llms.txt` のインデックスから Open SaaS と Wasp のドキュメントを読むようエージェントに指示し、テンプレートにはガイド付きツアーのようなエージェントスキルがあり、Wasp の単一の設定ファイルはアプリ全体の概要を 1 か所でエージェントに示します。これにより、エージェントは正しく見える Wasp のコードをより速く書けるようになります。

SaaSy Land はエージェントに**結果**を突きつけます。生成されたプロジェクトには、選んだスタックを説明する `AGENTS.md` と README、そしてプルリクエストごとにチェックとカバレッジ付きのテスト、続いてブラウザーテストを実行する CI ワークフローがあります。テンプレートの切り出し元であるリファレンスのこのサイトは、<RepositoryFact name="testFiles" /> 個のテストファイル全体で、ステートメント、分岐、関数、行のカバレッジが <RepositoryFact name="coverageThreshold" />% を下回るとマージを失敗させ、<RepositoryFact name="e2eTests" /> 件のブラウザーテストを実行し、`any` や無効化したリントルールを拒否し、<RepositoryFact name="languages" /> 言語のどれかで翻訳が欠けていれば CI を失敗させます。

指示とチェックは対立するものではなく、どちらのリポジトリにも指示があります。違いが表れるのは、エージェントが指示を無視した日です。エージェントが飛ばした指示は、レビュアーか顧客が見つけます。エージェントが壊したチェックは、何かがマージされる前にプルリクエストが見つけます。この違いについては、[プロンプトではなくガードレール](/blog/ai-coding-agent-guardrails)で書きました。

## テスト

Open SaaS には `e2e-tests` ディレクトリに Playwright の E2E テストがあり、2026年11月25日時点では 4 つのスペックファイルで、ランディングページ、料金ページ、認証のリダイレクト、デモアプリを扱っています。リポジトリはプルリクエストごとにそれを実行しており、テストガイドではそのワークフローを自分のプロジェクトにコピーする方法を説明しています。テンプレートには付属していないからです。

これは妥当な出発点であり、多くの有料スターターが提供しているものより充実しています。ただし、カバレッジゲートとは別の主張です。E2E テストは、誰かがテストを書いた経路が今日動くことを証明します。カバレッジゲートは、どのテストも通らない分岐を含むブランチのマージを拒否します。エラー処理、Webhook の署名、権限チェックが潜んでいるのは、まさにそこです。リリースのたびに手作業でテストする人間にとって、その差は小さなものです。1 日に 10 件のプルリクエストを開くエージェントにとっては、それが差のほとんどです。

## 決済と Lemon Squeezy の問題

Open SaaS は Stripe、Lemon Squeezy、Polar、Paddle の 4 つの決済プロバイダーに対応しています。決済ガイドにあるとおり、`src/payment/paymentProcessor.ts` とクライアント側の対応ファイルで 1 つを選び、ほかのプロバイダーのフォルダー、環境変数、パッケージを削除します。4 つのうち 3 つは Merchant of Record で、売上税を代わりに処理してくれます。

そのうちの 1 つはサービスを終了します。Lemon Squeezy は 2026年11月16日に新規ストアの登録を締め切り、2027年3月31日に決済処理を停止します。その告知では、対応国の事業者に Stripe の Managed Payments を勧めています。2026年11月25日時点で、Open SaaS は README と決済ガイドにまだ Lemon Squeezy を記載しています。いま Open SaaS で始めるなら、Stripe、Polar、Paddle のいずれかを選んでください。

2026年11月25日時点で、SaaSy Land が生成するプロジェクトには課金がありません。このサイトは自身のライセンスを Polar で販売しており、Polar による課金、続いて Stripe による課金がロードマップの最初にあります。最初の 1 週間で決済が必要で、それを自分で書きたくないなら、それだけで今日 Open SaaS を選ぶ理由になります。

## アップデート

Open SaaS はアップデートについて率直です。ドキュメントは、すでに作り始めたアプリに後からテンプレートの変更をマージすることを勧めていません。コードが分岐しているはずだからです。そして、必要な修正だけを手作業でコピーするよう提案しています。これは誠実な説明であり、実際ほとんどの無料テンプレートはそのように運用されています。

SaaSy Land は、生成するすべてのプロジェクトの `saasyland.json` にリリースと回答を記録しているので、新しいリリースから同じプロジェクトを再生成できます。それをプロジェクトにマージする `update` コマンドはロードマップにあり、まだ使えません。現時点では、どちらの製品もプロジェクトを代わりに更新してはくれません。

## それぞれの費用

Open SaaS は無料で、接続するサービスはそれぞれ直接請求します。

SaaSy Land にも無料の入り口があります。認証、顧客ワークスペース、管理画面、Polar のチェックアウト、カバレッジゲートを含む saasyland.com のソース全体が、MIT ライセンスで公開されています。お金を払わずに、すべてを読み、実行し、その上に構築できます。お金を払う対象はジェネレーターです。Core は <TierPrice tier="core" />、Complete は <TierPrice tier="complete" />、Agency は <TierPrice tier="agency" /> で、いずれもコアの生涯アップデート付きの一回払いです。Core と Complete は自社の製品が対象で、Agency は顧客案件の無制限化とホワイトラベル対応、<RepositoryFact name="callMinutes" /> 分のアーキテクチャ相談を加えます。各キーは同時に <ActivationLimit tier="core" />、<ActivationLimit tier="complete" />、<ActivationLimit tier="agency" /> 台の端末で使えます。

## Open SaaS を選ぶべきとき

- お金をかけたくなく、MIT ライセンスで十分なとき。
- 自分で書かずに、最初の 1 週間でバックグラウンドジョブ、ファイルアップロード、決済が必要なとき。
- Wasp の上に構築し、そのリリースに追従することに抵抗がなく、アプリを 1 つの設定ファイルで宣言するのが好きなとき。
- PostgreSQL を使い、1 つのコマンドで Fly.io や Railway にデプロイしたいとき。
- 製品が 1 つの言語だけで提供されるか、翻訳は自分で加えるとき。

## SaaSy Land を選ぶべきとき

- 自社製のフレームワークを下に挟まない素のコードがほしく、プロジェクトとそのスタック自身のリリースとの間に何も立たせたくないとき。
- コードのほとんどをコーディングエージェントが書き、エージェントが飛ばすかもしれない指示だけでなく、何かを壊せばプルリクエストを失敗させるチェックがほしいとき。
- 複数の言語で販売し、すべての文字列、日付、価格を初日から翻訳し、キーが欠ければ CI を失敗させたいとき。
- 現在 D1 を使う Cloudflare Workers にデプロイするか、望むスタックがロードマップに沿って提供されるのを待てるとき。
- 顧客案件を手がけ、それを明記したライセンスがほしいとき。Agency は顧客案件を無制限にカバーします。

まだ決めかねているなら、無料の部分から始めてください。このサイトのソースを読み、テストを実行し、それがエージェントに作業させたいコードベースかどうかを確かめてください。
