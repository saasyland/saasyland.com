## Caché de consultas

`getRouter` crea un `QueryClient` nuevo en cada petición, así que en el servidor no se filtran datos entre usuarios. Valores por defecto:

| Ajuste                        | Valor         |
| ----------------------------- | ------------- |
| `staleTime` de las consultas  | 1 minuto      |
| `gcTime` de las consultas     | 5 minutos     |
| `defaultStaleTime` del router | 1 minuto      |
| Precarga                      | Por intención |

Los loaders llenan la caché con `queryClient.query({ ...options, staleTime: "static" })` y los componentes leen las mismas claves con `useSuspenseQuery`. Las páginas de cursos y el editor de cursos de la administración son la excepción: sus queries usan `staleTime: COURSE_STALE_MS` (un minuto), porque `invalidateQueries` nunca vuelve a pedir una query `static`, y al terminar una lección o guardar un cambio en el editor hay que refrescar el temario. `setupRouterSsrQueryIntegration` serializa la caché del servidor en el HTML y la hidrata en el navegador.

- **Los mensajes de traducción** se cachean por locale y namespace con `staleTime` y `gcTime` infinitos.
- **La consulta de sesión** (`getCurrentSessionQuery`) tiene un `staleTime` de un minuto. Los guards de ruta la vuelven a pedir en las navegaciones reales y vacían toda la caché cuando cambia el usuario con sesión iniciada.
- **Las mutaciones** invalidan las claves de consulta de su módulo, por ejemplo `USER_QUERY_KEYS.ALL`, cuando terminan con éxito.

## Prerenderizado

`bun run build` prerenderiza las páginas públicas rastreando los enlaces: la landing, las páginas legales, el blog y la documentación en los nueve locales. Se excluyen las rutas bajo `/admin`, `/app`, `/auth`, `/courses`, `/newsletter` y `/api` (con o sin prefijo de locale), así como los enlaces con query string o hash. Las páginas de cursos se excluyen porque muestran los bloqueos y el progreso de cada espectador.

El Worker sirve el HTML prerenderizado desde el binding `ASSETS` antes de cargar la aplicación. Una página prerenderizada no contiene datos de usuario, así que se puede servir a cualquiera sin riesgo. Cuando un visitante tiene derecho a precios regionales, el Worker reescribe el HTML y marca la respuesta con `Cache-Control: private, no-cache`.

## KV y D1

- **KV (`CACHE`)** guarda el número de estrellas de GitHub para `src/lib/github.ts` y los descuentos regionales del checkout para `src/modules/license/license.ppp.ts`. Un número de estrellas con más de una hora de antigüedad se devuelve al instante y se actualiza en segundo plano con `waitUntil`; los descuentos con más de cinco minutos se vuelven a consultar en Polar.
- **D1 (`DB`)** guarda las sesiones y los contadores de límite de peticiones. Las comprobaciones de sesión de las funciones de servidor se saltan la caché de cookies de Better Auth y se memoizan durante el resto de la petición.
- **La caché de Workers** guarda los archivos de vídeo que `serveMedia` lee de R2 bajo `/media/_/<videoId>/<file>`, sin la firma, para que los espectadores de una misma ubicación del edge compartan una única copia en caché. Consulta [Cloudflare R2](/docs/integrations/cloudflare-r2).
- Las funciones de servidor nunca toman una decisión de permisos a partir de datos cacheados.
