---
title: "フォームとバリデーション"
description: "TanStack Form、shadcn のフィールド、そしてサーバーでも適用されるモジュールの Zod スキーマでフォームを構築します。"
---

フォームは shadcn の TanStack Form パターンに従います。モジュールの Zod スキーマを使う `useForm`、`form.Field` の render props、shadcn の `Field` コンポーネント、そして送信用のミューテーションです。サーバー関数が同じスキーマで再度検証するため、クライアント側のチェックはフィードバックのためだけのものです。

## 例

`src/presentation/components/custom/newsletter-form.tsx` から抜粋したものです（スタイルは省略しています）。

```tsx
const emailSchema = newsletterSubscriberZodSchemas.subscribeToNewsletter.pick({ email: true })

export const NewsletterForm = (): JSX.Element => {
  const t = useTranslations("components.custom.newsletter-form")
  const inputId = useId()
  const errorMessage = useErrorMessage()
  const queryClient = useQueryClient()

  const subscribe = useMutation({
    ...subscribeToNewsletterMutation,
    onError: (error) => {
      toast.error(errorMessage(error))
    },
    onSuccess: ({ status }) => {
      toast.success(t(status))
      return queryClient.invalidateQueries({ queryKey: NEWSLETTER_SUBSCRIBER_QUERY_KEYS.ALL })
    },
  })

  const form = useForm({
    defaultValues: { email: "" },
    listeners: { onBlur: validateOnBlur },
    onSubmit: ({ value, formApi }) => {
      subscribe.mutate(
        { email: value.email, locale: getCurrentLocale() },
        {
          onSuccess: () => {
            formApi.reset()
          },
        },
      )
    },
    validators: { onChange: emailSchema },
  })

  return (
    <form
      noValidate
      onSubmit={(event) => {
        void submitForm(event, form)
      }}
    >
      <form.Field name="email">
        {(field) => {
          const isInvalid = isFieldInvalid(field)

          return (
            <Field data-invalid={isInvalid}>
              <FieldLabel htmlFor={inputId}>{t("label")}</FieldLabel>
              <Input
                aria-describedby={`${inputId}-error`}
                aria-invalid={isInvalid}
                autoComplete="email"
                id={inputId}
                name={field.name}
                onBlur={field.handleBlur}
                onChange={(event) => {
                  field.handleChange(event.target.value)
                }}
                placeholder={t("placeholder")}
                type="email"
                value={field.state.value}
              />
              <Button isPending={subscribe.isPending} type="submit">
                {subscribe.isPending ? t("submitting") : t("button")}
              </Button>
              <div id={`${inputId}-error`}>
                {isInvalid && (
                  <ValidationFieldError
                    message={fieldErrorMessage(field.state.meta.errors)}
                    namespace="auth.validations"
                    params={AUTH_VALIDATION_PARAMS}
                  />
                )}
              </div>
            </Field>
          )
        }}
      </form.Field>
    </form>
  )
}
```

## スキーマ

- モジュールの `<table>.zod.ts` にあるスキーマを使います。認証フォームでは `src/integrations/better-auth/auth.zod.ts` のスキーマを使います。`.pick(...)` でフォームに表示するフィールドを選びます。ロケールのように、ユーザーが入力しない値は `onSubmit` で追加します。
- バリデーターは `validators: { onChange: emailSchema }` の 1 つだけです。TanStack Form は変更のたびに、そして送信時にもう一度これを実行します。別に `onSubmit` の複製を置くと、`passwordsMustMatch` のような送信時のエラーが、そのフィールド自身が変更されるまで赤いまま残ってしまいます。
- `listeners: { onBlur: validateOnBlur }` は、フィールドがフォーカスを失ったときに同じバリデーターを実行します。そのため、訪問者が Tab キーで通過したフィールドには、そこを離れた時点ですぐにエラーが表示されます。
- `noValidate` はブラウザのバリデーションを無効にし、Zod のメッセージだけがエラーとして表示されるようにします。

## エラー

- フィールドは、訪問者がそこを離れるか送信しようとした時点でエラーを表示し、まだ入力している間は表示しません。判定は `src/integrations/tanstack-form/form.fields.ts` の `isFieldInvalid(field)` で、その中身は `field.state.meta.isBlurred && !field.state.meta.isValid` です。この値が `Field` の `data-invalid`、入力要素の `aria-invalid`、そしてエラーを描画するかどうかを決めるため、3 つは常に一緒に変わります。
- エラーが表示された後は、変更のたびにフィールドが再検証されるため、値を直したキー入力でエラーが消えます。`isTouched` は使いません。TanStack Form は最初のキー入力でこれを設定します。
- `PasswordRequirements` のように進捗に報いるライブのフィードバックは、値を直接読み取り、最初のキー入力から更新されます。
- 入力は常に `aria-describedby` に自身のエラーの id（`<input id>-error`）を設定し、`ValidationFieldError` はフィールドが無効な間だけその id を持つ要素を描画します。ブラウザーは存在しない要素への参照を無視するため、有効なフィールドには説明がありません。
- Zod のメッセージは、`emailInvalid` のような翻訳キーです。`fieldErrorMessage` は最初のキーを取り出し、`ValidationFieldError` は `<namespace>.<key>` を `params` の対応するエントリとともにレンダリングします。例えば `emailMaxLength` には `{ max: 254 }` を使います。存在しないキーは `errors.codes.VALIDATION` にフォールバックします。
- フォームは `auth.validations` を渡します。これは `auth` と `admin` の各レイアウトがプリロードし、ニュースレターのエリアが自分のフォームのために `_marketing` レイアウトに追加します。例外は管理画面のコースのフォームで、`admin.courses.tsx` レイアウトが読み込む `course.validations` を渡します。ルートはフォームが使う名前空間を読み込む必要があります。`messages/` にはほかのモジュールにも `user.validations` のような `<table>.validations` 名前空間がありますが、それらを読み込むフォームやルートはありません。
- サーバーのエラーは、ミューテーションの `onError` で `useErrorMessage()` を通して処理します。

## 送信

- フォームの `onSubmit` は `src/integrations/tanstack-form/form.submit.ts` の `submitForm(event, form)` を呼び出します。これはブラウザーによる送信を防いで `form.handleSubmit()` を呼び出します。フォームが無効な場合は、すべてのフィールドを離れた状態としてマークしてすべてのエラーを表示し、`aria-invalid="true"` を持つ最初のコントロールにフォーカスを移します。
- ユースケースのミューテーションオプションを `useMutation` に展開し、それを通して送信します。例外は `SignInForm` で、独自の `useMutation` の中で Better Auth クライアントの `signIn.email` を呼び出し、`twoFactorRedirect` はクライアントの二要素認証プラグインが処理します。
- `<Button isPending={mutation.isPending} type="submit">` は、リクエストの実行中にボタンを無効化し、処理中であることを支援技術に伝えます。
- フォームが未完成の間も送信ボタンは有効なままで、無効化するのは `isPending` だけです。誤りがあるまま押すと、すべてのエラーを表示して最初の無効なフィールドにフォーカスを移します。
- 既知のデータ漏洩に含まれるパスワードに対する `passwordCompromised` のように、1 つのフィールドに属するサーバーのエラーは、トーストではなく `form.submit.ts` の `showFieldError(formApi, { controlId, field, message })` でそのフィールドの下に表示します。このエラーはフィールドが変更されると消えます。
- ミューテーションの `onSuccess` でフォームをリセットするかページを遷移し、ミューテーションが変更したモジュールのクエリを無効化します。

その他の例は、`src/presentation/components/custom/auth/` の `sign-in-form.tsx`、`sign-up-form.tsx`、`reset-password-form.tsx`、`two-factor-form.tsx` です。
