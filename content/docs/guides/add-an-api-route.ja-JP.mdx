---
title: "API ルートを追加する"
description: "Webhook やその他の外部の呼び出し元のために、/api 配下に HTTP ハンドラーを追加します。"
---

API ルートは、`src/routes/api/` にある TanStack Start のサーバーハンドラーです。アプリケーション自身の画面はサーバー関数を呼び出すため、API ルートを必要としません。API ルートは、Webhook、サードパーティのクライアント、クローラーなど、アプリ外部の呼び出し元のためだけに追加します。

## 既存のルート

| ファイル                     | パス                                         | 用途                                                                                 |
| ---------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------ |
| `src/routes/api/auth.$.ts`   | `/api/auth/*`                                | Better Auth：サインイン、OAuth のコールバック、メール認証、Polar のポータル、Webhook |
| `src/routes/api/index.ts`    | `/api`                                       | `{ "runtime": "cloudflare-workers" }` を返すランタイムチェック                       |
| `src/routes/api/cli.v1.*.ts` | <RepositoryFact name="cliApiBasePath" />`/*` | `saasyland` CLI が呼び出す [CLI ライセンス API](/docs/features/cli-licence-api)      |

Polar プラグインはチェックアウトのエンドポイントを追加しません。チェックアウトは注文モジュールとライセンスモジュールの `startCheckout` サーバー関数で開始し、どちらも `createCheckout` でチェックアウトを作成します。Polar の Webhook は `/api/auth/polar/webhooks` に届きます。Better Auth の Polar プラグインが `POLAR_WEBHOOK_SECRET` で署名を検証してから、`license.webhooks.ts` が処理します。

## ハンドラーを書く

`server.handlers` にメソッドを宣言します。各ハンドラーは Web の `Request` を受け取り、Web の `Response` を返します。

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: {
    handlers: {
      GET: ({ request }) => auth.handler(request),
      POST: ({ request }) => auth.handler(request),
    },
  },
})
```

ハンドラー内では、次の点を守ります。

- クエリやボディを Zod スキーマで検証し、失敗した場合は `HTTP_STATUS.BAD_REQUEST`（`src/modules/_core/constants/api.ts` から）を返します。ハンドラーに新しいステータスが必要な場合は、そこに追加します。
- `getRequestSession(request)` でセッションを読み取り、`hasPermission` でチェックします。`authorized` のような関数ミドルウェアはサーバー関数に適用されるもので、ハンドラーには適用されません。
- 公開エンドポイントには、`src/lib/rate-limit.ts` の `withinRateLimit({ key, limit, windowSeconds })` と `src/integrations/better-auth/auth.middleware.ts` の `clientAddress(request.headers)` でレート制限をかけます。
- Webhook のペイロードを信頼する前に、署名を検証します。
- 安全なエラーボディを返し、詳細は `console.error` でログに記録します。

## ルーティングのルール

- `/api` のパスにはロケールのプレフィックスが付きません。また、Worker はこれらのパスについて、静的アセットの検索とロケールのリダイレクトをスキップします。
- `/api` の URL にはロケールが含まれないため、`getCurrentLocale()` はそこでデフォルトのロケールを返します。ローカライズされたレスポンスは、クエリパラメーター `locale` などを使って、リクエストからロケールを取得します。
- `/api` はプリレンダリングの対象外です。

## テスト

`src/routes/api/__test__/auth.test.ts` が `Route.options.server.handlers` で行っているように、ルートのオプションを通じてハンドラーを呼び出し、転送先のプロバイダーをモックします。
