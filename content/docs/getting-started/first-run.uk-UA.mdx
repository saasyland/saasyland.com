## Ізольований тестовий preview

Тестовий preview збирає застосунок для середовища `test`: локальні D1 і KV у `.wrangler/test`, фіктивні облікові дані з `.env.test`, засіяні облікові записи та перехоплені запити до Resend і Polar. Він не потребує облікових записів у сервісах.

```sh
bun run db:migrate:test
bun run db:seed:test
bun run build:test
bun run start:test
```

Відкрийте http://127.0.0.1:3000 і ввійдіть з одним із засіяних облікових записів. Обидва використовують пароль `WorkerTestPassword123!` з `e2e/data/accounts.ts`.

| Роль          | Електронна пошта                  | Робочий простір |
| ------------- | --------------------------------- | --------------- |
| Адміністратор | `admin@saasyland.example.test`    | `/admin`        |
| Клієнт        | `customer@saasyland.example.test` | `/app`          |

Preview обслуговує збірку, тож щоб побачити зміни у вихідному коді, перезберіть його.

## Розробка з Cloudflare

`bun run dev` запускає dev-сервер із гарячим перезавантаженням за адресою http://localhost:3000. Його прив'язки `DB` і `CACHE` підключаються до віддалених ресурсів preview, тож записи під час розробки потрапляють у базу даних preview.

```sh
bunx wrangler login
cp .env.example .env.development
bun run db:migrate:development
bun run dev
```

1. Увійдіть у Cloudflare через Wrangler.
2. Заповніть `.env.development`, як описано в розділі [Змінні середовища](/docs/getting-started/environment-variables), з `POLAR_SERVER=sandbox`.
3. Якщо у вас власний обліковий запис Cloudflare, створіть базу даних D1 і простір імен KV та замініть ідентифікатори `development` і `preview` у `wrangler.jsonc`; закомічені ідентифікатори належать наявному розгортанню. Див. [Розгортання preview](/docs/getting-started/deploy-preview).
4. Застосуйте міграції та запустіть сервер.

Реєстрація за електронною поштою потребує робочої конфігурації Resend, бо облікові записи мають підтвердити адресу електронної пошти перед входом. Початкового адміністратора для розробки немає: зареєструйтеся, підтвердьте адресу, а потім задайте своєму користувачеві `role` зі значенням `admin` через `bun run db:studio:development`.
