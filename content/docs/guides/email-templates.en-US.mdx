An email has three parts: a template in `src/presentation/emails/`, a message namespace in `messages/<locale>/emails.<name>.json`, and the use case that loads the messages, renders the template and sends it. Templates: `verify-email`, `reset-password-email`, `change-email-confirmation-email`, `newsletter-confirmation-email` and `newsletter-notification-email`.

## Template

A template contains markup only and exports its namespace. It translates with `createTranslator` from `use-intl` because it renders outside React context. `src/presentation/emails/verify-email.tsx`:

```tsx
import type { JSX } from "react"

import { Body, Button, Container, Head, Heading, Html, Preview, Section, Tailwind, Text, pixelBasedPreset } from "react-email"
import { createTranslator } from "use-intl"

import type { SupportedLocale } from "~/src/integrations/use-intl/i18n.config"

import type emailMessages from "~/messages/en-US/emails.verify-email.json"

export const VERIFY_EMAIL_NAMESPACE = "emails.verify-email"

const TAILWIND_CONFIG = { presets: [pixelBasedPreset] }

interface VerifyEmailProps {
  readonly locale: SupportedLocale
  readonly messages: typeof emailMessages
  readonly name: string
  readonly verifyUrl: string
}

export const VerifyEmail = ({ messages, locale, name, verifyUrl }: Readonly<VerifyEmailProps>): JSX.Element => {
  const t = createTranslator({ locale, messages: { emails: { "verify-email": messages } }, namespace: "emails.verify-email" })

  return (
    <Html lang={locale}>
      <Tailwind config={TAILWIND_CONFIG}>
        <Head />
        <Body className="font-sans">
          <Preview>{t("preview")}</Preview>
          <Container className="mx-auto px-5 py-10">
            <Section>
              <Heading className="m-0 mb-4 text-2xl font-bold">{t("heading")}</Heading>
              <Text className="m-0 mb-6 text-base text-neutral-600">{t("body", { name })}</Text>
              <Button
                href={verifyUrl}
                className="box-border rounded-md bg-neutral-900 px-5 py-3 text-center text-base text-white no-underline"
              >
                {t("button")}
              </Button>
              <Text className="mt-6 text-sm text-neutral-500">{t("footer")}</Text>
            </Section>
          </Container>
        </Body>
      </Tailwind>
    </Html>
  )
}
```

## Messages

Create `messages/<locale>/emails.<name>.json` in all nine locales. Include a `subject` key; the use case translates it separately from the body.

```json
{
  "subject": "Verify your email address",
  "preview": "Verify your email for SaaSy Land",
  "heading": "Verify your email",
  "body": "Hi {name}, thanks for signing up. Confirm your email address to finish setting up your account.",
  "button": "Verify email",
  "footer": "If you did not create an account, you can safely ignore this email."
}
```

Email namespaces are never preloaded by routes; the sending use case loads them on the server.

## Sending

The use case receives the locale, loads the messages, builds absolute links with `localizePathname` and calls `sendEmail`. `src/modules/verification/use-cases/send-verify-email.ts`:

```ts
export const sendVerifyEmail = async ({
  locale,
  token,
  user,
}: {
  locale: SupportedLocale
  token: string
  user: { email: string; name: string }
}): Promise<void> => {
  const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
  const verifyUrl = new URL(localizePathname({ locale, pathname: ROUTES.VERIFY_EMAIL }), getRequest().url)
  verifyUrl.searchParams.set("token", token)

  await sendEmail({
    idempotencyKey: `verify-email/${token}`,
    react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
    subject: createTranslator({ locale, messages })("subject"),
    to: user.email,
  })
}
```

`sendEmail` (`src/integrations/resend/resend.utils.ts`) sends through Resend from `RESEND_EMAIL_FROM` unless `from` is given, passes the idempotency key so a retry never sends twice, and throws when Resend returns an error.

## Who sends what

- Better Auth hooks in `src/integrations/better-auth/auth.server.ts` call the use cases: `sendVerifyEmail` for `emailVerification.sendVerificationEmail` and repeated sign-ups of unverified accounts, `sendResetPasswordEmail` for `emailAndPassword.sendResetPassword` and `sendChangeEmailConfirmationEmail` for `user.changeEmail`.
- Better Auth requests arrive at `/api/auth` without a locale prefix, so the hooks take the email locale from the flow's `callbackURL`, a localized page path, with `extractLocaleFromCallbackURL` or `extractLocaleFromPath` from `src/integrations/use-intl/i18n.paths.ts`. English is the fallback.
- The newsletter use cases send the newsletter confirmation and notification emails themselves, for example `subscribeToNewsletter`.

## Add an email

1. Add the template to `src/presentation/emails/<name>.tsx` with its exported `<NAME>_NAMESPACE`.
2. Add `messages/<locale>/emails.<name>.json` in all nine locales.
3. Send it from the use case that owns the action, with an idempotency key derived from the triggering token or record.
4. Test the template in `src/presentation/emails/__test__/` and the use case with `sendEmail` mocked.

Resend credentials: `RESEND_API_KEY` and `RESEND_EMAIL_FROM`. Tests never contact Resend.
