Every environment binds a KV namespace as `CACHE`. It holds one entry.

## GitHub star count

The star count shown on the site, implemented in `src/lib/github.ts`:

- `getStarCount` reads the `github:<owner>/<repo>:stars` entry.
- Without an entry, it fetches the repository from the GitHub API with a timeout of <RepositoryFact name="starCountFetchTimeoutSeconds" unit="second" />, returns the count and writes `count` and `fetchedAt` to KV with `waitUntil`.
- When the entry is older than <RepositoryFact name="starCountRefreshHours" unit="hour" /> (`STAR_COUNT_REFRESH_AFTER_MS`), it returns the cached count and refreshes it in the background.
- `starCountQuery` keeps the result in the query cache for as long: `STAR_COUNT_REFRESH_AFTER_MS` is also its `gcTime` and, in every build but the test build, its `staleTime`. The test Worker answers the GitHub API with one fixed count, so there `starCountStaleTime` never lets the count go stale, and a page that `build:test` prerendered asks for no star count, however long ago it was built.

Entries have no KV expiration; `fetchedAt` decides when to refresh. The GitHub request authenticates with the GitHub OAuth app credentials `AUTH_GITHUB_CLIENT_ID` and `AUTH_GITHUB_CLIENT_SECRET`.

## Consistency and tests

KV is eventually consistent. Sessions, rate limits and everything used for authorization live in D1.

In Vitest, `cloudflare:workers` resolves to `src/platform/testing/mocks/cloudflare.ts`, which provides an in-memory `CACHE`. The `test` Wrangler environment uses a local namespace under `.wrangler/test`.
