Die Primitive in `src/presentation/components/shadcn/` sind shadcn/ui-Komponenten auf Basis von React Aria Components. `input-otp`, `carousel`, `resizable`, `chart`, `message-scroller` und `sonner` kapseln andere Bibliotheken, `drawer` nutzt Base UI, und alle übrigen folgen React Aria. `components.json` lässt den Alias `ui` auf diesen Ordner und `utils` auf `~/src/lib/cn` zeigen. Ansichten importieren Primitive direkt; es gibt keine Wrapper-Komponenten um sie herum.

## React-Aria-Props

| Gewohnheit aus DOM oder Radix    | Hier verwenden                          |
| -------------------------------- | --------------------------------------- |
| `onClick`                        | `onPress`                               |
| `disabled`                       | `isDisabled`                            |
| `open` bei einem Dialog          | `isOpen` mit `onOpenChange`             |
| `checked`                        | `isSelected`                            |
| `value` bei Tabs                 | `selectedKey` oder `defaultSelectedKey` |
| `onSelect` bei einem Menüeintrag | `onAction`                              |

`Input` behält das native `onChange`-Ereignis. `Select` akzeptiert ein `fieldLabel`, das sein Label rendert.

## Konventionen

- **Schaltflächen im Ladezustand**: Übergib den Mutationszustand an `Button`: `<Button isPending={mutation.isPending} type="submit">`.
- **Links**: `LinkButton`, `TabsTrigger` und `SidebarMenuButton` nehmen ein `href` entgegen. `AriaProvider` leitet diese über TanStack Router und ergänzt das Locale-Präfix. Andere Elemente werden mit `buttonVariants` als Schaltflächen gestaltet.
- **Formulare**: `Field`, `FieldGroup`, `FieldLabel`, `Input` und `ValidationFieldError` mit TanStack Form, wie in diesem Feld aus `ResetPasswordDialog`:

```tsx
<Field data-invalid={isInvalid}>
  <FieldLabel htmlFor={passwordId}>{t("resetPasswordDialog.password")}</FieldLabel>
  <Input
    aria-invalid={isInvalid}
    autoComplete="new-password"
    id={passwordId}
    name={field.name}
    onBlur={field.handleBlur}
    onChange={(event) => {
      field.handleChange(event.target.value)
    }}
    type="password"
    value={field.state.value}
  />
  {isInvalid && (
    <ValidationFieldError
      message={fieldErrorMessage(field.state.meta.errors)}
      namespace="auth.validations"
      params={AUTH_VALIDATION_PARAMS}
    />
  )}
</Field>
```

- **Dialoge**: `Dialog` und `AlertDialog` werden mit `isOpen` und `onOpenChange` gesteuert; jeder Dialog hat eine eigene Datei, zum Beispiel `admin/users/delete-user-dialog.tsx`.
- **Menüs**: `DropdownMenuTrigger` umschließt den auslösenden `Button` und das `DropdownMenu`; Einträge führen `onAction` aus und erhalten für gefährliche Aktionen `variant="destructive"`.
- **Toasts**: Rufe `toast.success` oder `toast.error` aus `sonner` auf; die Root-Route rendert den `Toaster` innerhalb von `ThemeProvider`. Der Bereich der Benachrichtigungen trägt den Namen aus `components.shadcn.sonner`, gefolgt vom Tastenkürzel von Sonner.
- **Fokusringe**: Gestalte React-Aria-Trigger mit `data-focus-visible:`-Varianten, wie es `checkbox`, `select`, `switch` und `radio-group` tun.
- **Klassennamen**: Verwende `cn` aus `~/src/lib/cn` mit der Objektsyntax für bedingte Klassen.

## CSS-Größe

`globals.css` enthält keine Liste von Primitiven. Das Vite-Plugin `unused-primitives` in `scripts/unused-primitives.ts` läuft vor Tailwind: Es schreibt für jedes Primitiv, das kein Quelltext der Anwendung importiert, weder direkt noch über ein anderes Primitiv (Tests und `src/platform/testing` zählen nicht), eine `@source not`-Zeile in `.source/unused-primitives.css` und importiert diese Datei in das Stylesheet, das es Tailwind übergibt. So enthält das CSS eines Projekts die Klassen der Primitive, die seine eigenen Bereiche verwenden, und keine anderen. Tailwind verfolgt die importierte Datei, und das Plugin schreibt sie nur neu, wenn sich die Liste ändert. Beginnt eine Ansicht, ein Primitiv zu importieren, baut der Dev-Server das CSS deshalb ohne Neustart mit dessen Klassen neu.
