These pages are the coding standard of this repository. They describe how code is written here, not how it could be written, and every rule names the files that follow it. Most rules are enforced by a command: `bun run check` (formatting, lint, types, translations and docs structure), `bun run test:coverage` (the 100% gate) or the end-to-end suite. The rest are held in review, and each page says which.

When you are unsure how to write something, find the closest existing example of the same kind, read it, and copy its shape. Consistency is worth more than a locally better idea: a second way of doing the same thing makes every later reader, human or agent, learn both.

## Rules without exceptions

Breaking one of these gets a change rejected, whatever else it does well.

1. No comments in code, tests, scripts, configuration or CSS. See [Code style](/docs/conventions/code-style).
2. No `oxlint-disable`, `eslint-disable`, `@ts-expect-error`, `@ts-ignore`, `as` casts or `any` to get past a rule. Fix the cause.
3. No multi-line ternaries, no `?? undefined` and no `null` literals.
4. Statuses, kinds, tiers, roles and other domain values are named constants, never repeated string literals, in tests too.
5. A folder in `src/modules` exists only for a database table. See [Modules](/docs/conventions/modules).
6. Every user-facing string exists in all nine locales, and so does every docs page. Numbers shown on the site are measured, never typed. See [Translations and content](/docs/conventions/translations).
7. Coverage stays at 100% for lines, statements, functions and branches. See [Testing](/docs/conventions/testing).
8. A change updates the README, the docs and the site copy it makes inaccurate, in the same pull request.
9. Commits and pull requests carry no AI attribution and no `Co-Authored-By` trailer. See [Git and pull requests](/docs/conventions/git-workflow).

## Definition of done

A change is done when these commands pass, in this order, in the branch you are about to push:

```sh
bun run check
bun run test:coverage
bun run build:test
bun run test:e2e:pr
```

`check` and the tests do not exercise the Cloudflare build: a dependency upgrade once passed both while the production build was broken. Run `build:test` for every change, and the browser suite for anything that is not documentation. Before you commit, read your own diff for comments, string literals that should be constants, and copy or docs that the change made wrong.
