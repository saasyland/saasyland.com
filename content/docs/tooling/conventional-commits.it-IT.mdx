---
title: "Conventional commits"
description: "Formato dei messaggi di commit e hook delle emoji."
---

L'oggetto dei commit segue il formato `<type>(<scope>): <description>`. Lo scope è facoltativo e `!` indica una modifica incompatibile. Scrivi l'oggetto senza emoji:

```sh
git commit -m "fix(auth): keep the locale in verification links"
```

L'hook `prepare-commit-msg` in `.vite-hooks/` esegue `bun scripts/commit-msg.ts`, che valida l'oggetto e antepone l'emoji corrispondente al tipo, quindi il commit qui sopra diventa `🐛 fix(auth): keep the locale in verification links`.

| Tipo       | Emoji |
| ---------- | ----- |
| `build`    | 🛠️    |
| `chore`    | ♻️    |
| `ci`       | ⚙️    |
| `docs`     | 📚    |
| `feat`     | ✨    |
| `fix`      | 🐛    |
| `perf`     | 🚀    |
| `refactor` | 📦    |
| `revert`   | 🗑️    |
| `style`    | 💎    |
| `test`     | 🚨    |

Qualsiasi altro tipo, o un oggetto che non rispetta il formato convenzionale, interrompe il commit mostrando l'elenco dei tipi consentiti. L'hook non modifica gli oggetti che iniziano già con un'emoji o che sono stati generati da Git (`Merge`, `Revert "`, `fixup!`, `squash!`), né i messaggi di merge, di squash e dei template.

Prima dell'hook del messaggio, l'hook `pre-commit` esegue `bun run check:pre-commit`. Non aggirare gli hook.
