## 結論から

**Clerk を選ぶ**のは、既製のコンポーネント、ボット対策、SOC 2 と HIPAA のレポートを他社に任せつつ、サインイン、ユーザー管理、組織を今日の午後には動かしたい場合で、しばらくは月間継続ユーザーが 50,000 人未満にとどまる見込みか、それを超えてもユーザー単位で支払えるだけの利益率がある場合です。

**Better Auth を選ぶ**のは、ユーザーを自分のデータベースに置きたい場合、どんな規模でもユーザー単位の料金を払いたくない場合、そして二要素認証、パスキー、組織、SSO などの機能を、コードで設定するプラグインとして使いたい場合です。私たちが使っているのはこれです。

**Auth.js を使い続ける**のは、すでに導入していて問題なく動いている場合です。新しいプロジェクトには、Auth.js 自身のメンテナーが Better Auth を推奨しています。

## 認証税：成長に応じたそれぞれのコスト

### Clerk の料金（料金ページより）

Clerk は**月間継続ユーザー**（MRU、monthly retained users）で料金を決めています。MRU とは「サインアップから少なくとも 1 日経ってから、ある月にアプリを訪れたユーザー」です。サインアップしたきり戻ってこない人は数えられません。これは寛大な仕組みで、ほかのサービスが数える月間アクティブユーザーとは同じではありません。

- **Hobby** は無料で、「アプリごとに 50,000 MRU の上限」があり、ダッシュボードのシートは最大 3 つ、セッションの有効期間は 7 日間で固定です。多要素認証とパスキーは含まれません。
- **Pro** は月額 $25、年払いなら月額 $20 で、「アプリごとに 50,000 MRU を含む」プランです。それを超えると、継続ユーザー 1 人あたりの月額は、50,001 人目から 100,000 人目までが $0.02、1,000,000 人までが $0.018、10,000,000 人までが $0.015、それを超えると $0.012 です。
- **Business** は月額 $300、年払いなら月額 $250 で、ユーザー単位の料金は同じ、ダッシュボードのシートは 10 個で、SOC 2 レポートを閲覧できます。

Clerk は 2026年2月5日に無料枠を引き上げ、「すべてのアプリケーションで、月間継続ユーザー 50,000 人が無料になりました。以前は 10,000 人でした」と発表しました。無料枠を 10,000 人とする比較記事は、古いプランを説明しています。

### 大規模になったときの Clerk の請求額

上の料金表から私が計算した、1 つのアプリケーションを Pro の月払いの定価で使い、アドオンを含めない場合の金額です。

| 月間継続ユーザー | Clerk Pro（月額） | Better Auth（月額） | Auth.js（月額） |
| ---------------- | ----------------- | ------------------- | --------------- |
| 10,000           | $25               | ライセンス料 $0     | ライセンス料 $0 |
| 50,000           | $25               | ライセンス料 $0     | ライセンス料 $0 |
| 100,000          | $1,025            | ライセンス料 $0     | ライセンス料 $0 |
| 1,000,000        | $17,225           | ライセンス料 $0     | ライセンス料 $0 |

100,000 人では、ユーザー単位の部分は 50,000 × $0.02 です。1,000,000 人では、その $1,000 に 900,000 × $0.018 の $16,200 が加わるので、年間ではおよそ $206,700 になります。Hobby プランなら最初の 2 行は無料でまかなえますが、多要素認証とパスキーは使えません。

アドオンは別途請求されます。組織は月間継続組織 100 個まで無料で、それを超えると、Clerk の FAQ によれば「B2B Authentication アドオンへのアップグレードが必要になります」。このアドオンは月額 $100 で、1,000 個までは追加の組織 1 つにつき $1 かかり、100,000 個を超えると $0.60 まで下がります。Pro と Business にはエンタープライズ SSO 接続が 1 つ含まれ、その次の 14 個はそれぞれ月額 $75 です。SMS コードは米国とカナダでは 1 通 $0.01、それ以外の地域では市場価格です。継続組織が 500 個あり、10 社の顧客が SAML を使う B2B プロダクトなら、上の金額に月額 $500 と $675 が加わります。

これが**認証税**です。あなたがまさに増やそうとしている数字とともに増えていく請求です。そしてそれは、ホスト型のサービスが最初にこれほど多くを無料で提供できる理由でもあります。

### ライブラリの場合のコスト

**Better Auth** は MIT ライセンスで、その比較ページが要点をまとめています。「ユーザーはサードパーティのサービスではなく、あなたのデータベースにとどまります」、そして「ユーザー単位のコストはありません」。費用がかかるのは、書き込み先のデータベース、コードやリンクを送るメールと SMS のプロバイダー、そして動かすためのホスティングで、いずれもアプリケーションにはどのみち必要なものです。

Better Auth は **Better Auth Infrastructure** も販売しています。セルフホストした Better Auth のための、マネージドなダッシュボード、監査ログ、セキュリティのサービスです。無料の Starter プラン、監査ログイベント 20,000 件とセキュリティ検知 10,000 件を含む月額 $20 の Pro、接続 1 つを含み追加の接続 1 つにつき月額 $50 のセルフサービス SSO とディレクトリ同期、そして 1 通あたり $0.001 のメールと $0.09 の SMS があります。料金ページは「Better Auth フレームワークは無料でオープンソース」であることを明記しており、この記事で取り上げるプラグインはどれも Infrastructure を必要としません。例外は、顧客がオンボーディングリンクから自分の SSO 接続を設定できるようにする機能で、これは Infrastructure の機能です。

**Auth.js** は ISC ライセンスで、同じように無料です。

**どの表にも表れないのは、あなたの時間です。** ライブラリを使うなら、サインイン画面を作り、メールを送り、依存関係を最新に保ち、何かが壊れたときのインシデントを引き受けるのはあなたです。Clerk なら、既製のコンポーネントと運用チームがそれを代わりに担います。チームが小さくユーザーも少ないなら、そのほうが認証税よりも価値がある場合があります。

## ユーザーテーブルを持つのは誰か

**Clerk では、Clerk が持ちます。** ユーザー、セッション、認証情報は Clerk のサービスに置かれ、セキュリティページによれば、Clerk は「リージョン単位のデータレジデンシーやリージョンの選択を提供していません。データは米国のインフラでホストされています」。すべてのプランに「完全なデータエクスポート」が含まれていますが、ロックインが表れるのはそのエクスポートです。Clerk のドキュメントによれば、「パスワードダイジェストと時間ベースのワンタイムパスワード（TOTP）のシークレットを含むのは、Clerk Dashboard からのエクスポートだけ」で、CLI と Backend API によるエクスポートにはパスワードダイジェストを含められず、「バックアップコードはどのエクスポートにも含まれません」。Dashboard からのエクスポートを使えば Clerk から移行できますが、バックアップコードに頼っているユーザーには新しいコードが必要になります。

Clerk はパスワードを bcrypt でハッシュ化しています。Better Auth の Clerk 移行ガイドによれば、Better Auth はデフォルトで scrypt を使うため、移行したユーザーが以前のパスワードでサインインできるのは、bcrypt のハッシュを検証するよう Better Auth を設定してからです。

**Better Auth や Auth.js では、あなたが持ちます。** ユーザー、セッション、アカウント、検証のテーブルは、Drizzle、Prisma、Kysely、MongoDB などのアダプターを通じて自分のデータベースに置かれ、ほかのデータと同じように、バックアップし、クエリし、自分のテーブルと結合できます。ロックインの相手はベンダーからライブラリに移ります。そのスキーマと API に依存することにはなりますが、ソースを読んでフォークでき、Better Auth は Auth.js からの移行ガイドを公開しています。

## セルフホスティングと実行環境

**Clerk** はマネージドサービスなので、ホストする必要のあるものも、ホストできるものもありません。主要なフレームワーク向けの SDK があり、その中には `@clerk/tanstack-react-start` による TanStack Start も含まれます。公開のステータスページもあります。

**Better Auth** はアプリケーションの中で動くので、アプリケーションが動くどのランタイムでも動きます。Next.js、TanStack Start、React Router、Nuxt、SvelteKit、SolidStart、Astro、Hono、Express などとのインテグレーションがドキュメントに記載されており、Cloudflare ガイドでは Workers について、クライアントの IP を `CF-Connecting-IP` から読み取ること、HTTP でクエリするデータベースドライバーを使うこと、そして Workers KV を `secondaryStorage` として使わないことを挙げています。KV は「`secondaryStorage` の契約を満たせない」ためです。

**Auth.js** もアプリケーションの中で動き、Cloudflare D1 を含むほとんどのデータベース向けに公式アダプターがあります。

## 組織とマルチテナンシー

企業に販売するなら、サインインフォームよりも組織のモデルのほうが重要です。

**Clerk** はすべてのプランに組織機能を含めており、メンバー 20 人までの月間継続組織 100 個までは無料で、管理者とメンバーのロール、カスタム権限、招待を備えています。組織が継続組織として数えられるのは、「メンバーが 2 人以上いて、そのうち少なくとも 1 人がその月の月間継続ユーザーであるとき」です。カスタムロール、メンバー数無制限、検証済みドメインは B2B アドオンに含まれます。`<OrganizationSwitcher />` コンポーネントは「組織に関連するすべてのフローを処理」し、エンタープライズ SSO は SAML、OIDC、EASIE に対応しています。

**Better Auth** には、メンバー、招待、ロールを備えた組織プラグインがあります。さらに、「組織内でメンバーをグループ化できる」チームと、「組織のロールを実行時に作成できる」動的アクセス制御もあります。SSO プラグインは「各組織を、それぞれの OIDC または SAML 2.0 のアイデンティティプロバイダーに」接続し、別の SCIM プラグインはディレクトリからユーザーをプロビジョニングします。そのすべてが自分のデータベースに置かれ、組織単位の料金はかかりません。

**Auth.js** には組織機能がありません。ロールベースのアクセス制御のガイドでは、セッションにロールを自分で追加する方法を示しています。

| 管理とアカウント停止 | Pro でアカウント停止。全プランで月 5 回までのなりすまし    | 管理プラグイン：ロール、アカウント停止、なりすまし               | 組み込みなし                                         |
| 既製の UI            | `<SignIn />`、`<UserProfile />` など                       | なし：画面は自分で作る                                           | デフォルトのサインインページ                         |

これらの行のうち 2 つは今年変わりました。Clerk は 2026年2月に Enhanced Authentication アドオンを廃止して多要素認証を Pro に移したので、Pro では二要素認証にアドオンが不要になりましたが、無料プランにはいまも含まれていません。そして Better Auth は、パスキー、SSO、API キーなどのいくつかのプラグインを独立したパッケージに移したため、古いチュートリアルは誤った場所からそれらをインポートしています。

Auth.js は自らの限界を率直に書いています。WebAuthn のページには「WebAuthn / パスキーのプロバイダーは実験的なもので、本番環境での使用は推奨されません」とあり、Credentials のページは「より現代的で安全な認証の仕組み」を勧めたうえで、「パスワードの暗号化、レート制限の追加、パスワードリセット機能の追加など、必要なロジックを用意」しなければならないと念を押しています。

## 2026年の Auth.js：Better Auth のチームがメンテナンス

2025年9月22日、Better Auth は「以前は NextAuth.js として知られていた Auth.js は、今後 Better Auth のチームがメンテナンスと監督を行う」と発表しました。この発表は「セキュリティパッチと緊急の問題への対応を続ける」と約束し、さらに「非常に特殊な機能の不足（特に、データベースを使わないステートレスなセッション管理）がない限り、新しいプロジェクトは Better Auth から始めることを強く推奨します」と付け加えています。Auth.js チーム自身の GitHub のディスカッションも同じことを述べており、Auth.js の 2 つのウェブサイトのどちらにも、このプロジェクトが Better Auth の一部になったことを示すバナーが表示されています。

その唯一の例外も、その後なくなりました。Better Auth のセッションのドキュメントには、Better Auth は「データベースをまったく使わないステートレスなセッション管理をサポート」しているとあります。

Auth.js v5 はいまもベータ版です。2026年11月20日時点で、npm 上の最新リリースは `next-auth` 4.24.15 と 5.0.0-beta.32 で、どちらも 2026年7月20日に公開されたものです。既存の Auth.js のアプリが危険にさらされているわけではなく、問題なく動いているアプリを書き直す理由はありません。新しいアプリは、将来性のあるところから始めるべきです。

## Clerk のほうが良い選択になる場合

Clerk は良い製品であり、多くのチームにとって正しい選択です。

- **今日から動かしたい。** `<SignIn />` は「ユーザーがサインインまたはサインアップできる UI をレンダリング」し、`<UserProfile />` はユーザーに「美しく、機能の揃ったアカウント管理 UI」を提供します。ライブラリを使うなら、そうした画面を作り、翻訳し、テストするのは自分です。
- **コンプライアンスの書類が必要。** Clerk は「2022年5月から SOC 2 Type 2 と HIPAA の認証を受けている」としており、SOC 2 レポートは Business 以上で、HIPAA の事業提携契約は Enterprise で提供されます。
- **不正利用への対処を任せたい。** ブルートフォース攻撃の防止と基本的なボット対策はすべてのプランにあり、より高度な保護は Business で利用できます。
- **ユーザー数がそれほど増えない見込み。** アプリケーションごとに月間継続ユーザー 50,000 人までなら、Clerk は Hobby で無料、Pro で月額 $25 で、一度サインアップして去ったユーザーは決して数えられません。
- **近いうちに企業へ販売する。** SAML、OIDC、EASIE の接続、ディレクトリ同期、組織が、そのための管理画面を作らなくても動きます。

その利点を、成功とともに大きくなる 2 つのものと比べて検討してください。ユーザー単位と組織単位の請求額、そして、ユーザー、セッション、2 つ目の認証要素が他社のサービスに置かれるようになってから離れるコストです。

## saasyland.com が Better Auth を使っている理由

saasyland.com は買い切りのライセンスを販売し、Cloudflare Worker 上で動き、<RepositoryFact name="languages" /> 言語に対応しています。その認証はすべて MIT ライセンスで公開されており、D1 上の Better Auth です。

- **ユーザー、セッション、レート制限は D1 の行です。** Drizzle アダプターを通じて保存されるので、管理コンソールはほかのテーブルと同じようにそれらを注文やライセンスと結合でき、管理者はユーザーのプロフィールからそのユーザーのセッションを取り消せます。
- **メールアドレスの確認を必須とするメールとパスワード。** パスワードは <RepositoryFact name="passwordMinLength" /> 文字から <RepositoryFact name="passwordMaxLength" /> 文字で、パスワードをリセットするとセッションが取り消されます。GitHub と Google のサインインは、アカウントの連携と暗号化された OAuth トークンに対応しています。
- **バックアップコード付きの二要素認証。** Better Auth の `twoFactor` プラグインを使っています。
- **ロール、アカウント停止、なりすまし。** `admin` プラグインを使い、権限ステートメントはコードの中にあります。
- **Polar の Better Auth プラグイン**が、各ユーザーをそのカスタマーポータルに結び付け、Polar の検証済み Webhook を受け取ります。Polar を選んだ理由は[決済サービスの比較](/blog/polar-vs-stripe-vs-lemon-squeezy)で説明しています。

[認証](/docs/features/authentication)、[二要素認証](/docs/features/two-factor)、[セッション](/docs/features/sessions)のページで、そのすべての部分を説明しています。

ここでもコストは確かにあります。Better Auth は画面を一切提供しないので、サインイン、サインアップ、確認、二要素認証の画面はすべて自分たちで作り、翻訳しました。サイトには現在パスキーがなく、組織もありません。[組織](/docs/features/organizations)のページには Better Auth の組織プラグインがインストールされていないとあり、コンフィギュレーターではマルチテナンシーを提供予定としています。そして Better Auth がリリースを公開したとき、サインインを正しく保つのはベンダーではなく私たちの仕事です。

SaaSy Land の CLI はベータ版です。ライセンスを有効化し、[コンフィギュレーター](/#cli)で選べるとおり、Better Auth 付きか認証なしでプロジェクトを生成します。
