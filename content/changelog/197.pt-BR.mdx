- Cada página carrega cerca de 21 KiB a menos de JavaScript com gzip. O script de entrada levava o mapa de cada arquivo de mensagens para o seu chunk, todos os namespaces de todos os locales, duas vezes, porque `loadPageMetadata` tinha um mapa próprio, embora a primeira página leia as suas mensagens do cache de queries que o servidor envia e nunca precisasse dele. O mapa agora fica em `i18n.loaders.ts`, que `loadNamespace` importa na primeira vez que carrega um namespace, e `loadPageMetadata` lê `metadata` do namespace da página; a página inicial foi de 462,9 KiB para 442,3 KiB. O `scripts/verify-build.ts` faz o build falhar quando os imports estáticos do script de entrada contêm o loader de um namespace de página. Veja [Carregue as mensagens quando uma página precisar delas](/docs/conventions/performance#load-messages-when-a-page-needs-them).
