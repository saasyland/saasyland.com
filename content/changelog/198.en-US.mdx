- Fixed: a user's profile in the admin could fail to hydrate, with React error #418. Each session's last activity is a relative time, and `UserSessions` counted it from `new Date()`, which the Worker reads when it renders the page and the browser reads again on its own clock when it hydrates it, so the server printed “active 9 seconds ago” and the browser “active 10 seconds ago” whenever the two fell in different seconds, as they did in CI. The profile, and `SessionRow` in `/admin/settings`, now count from the `dataUpdatedAt` of the sessions query, the moment the sessions were read, which the server sends to the browser with the query, so both print the same text whatever the hour, the time zone or the visitor's clock. A browser test signs in with the browser's clock set just after midnight UTC in Los Angeles, where it is still the previous day, and checks that `/admin` and the admin's own profile hydrate without an error and show the activity the server printed. See [Internationalization and locales](/docs/features/internationalization).
