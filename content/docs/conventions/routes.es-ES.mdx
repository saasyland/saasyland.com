title: "Archivos de ruta"
description: "La única forma de una ruta de página y de una ruta de layout: NAMESPACE o NAMESPACES, un loader con un solo Promise.all, un esqueleto que reproduce la página, esquemas de búsqueda y enlaces."
---

Todos los archivos de `src/routes` tienen la misma forma, así que quien conoce uno los conoce todos. Un archivo de ruta compone: declara lo que necesita la página y coloca componentes. Los widgets, formularios, diálogos y columnas de tabla viven en `src/presentation/components/custom`.

## Rutas de página

`src/routes/admin.courses.index.tsx`:

```tsx
const CoursesPage = (): JSX.Element => {
  const t = useTranslations("pages.admin.courses")

  return (
    <div className="flex w-full animate-in flex-col space-y-8 duration-500 fade-in-50">
      <div className="flex flex-col gap-4 sm:flex-row sm:items-end sm:justify-between">
        <div>
          <h1 className="text-statement font-semibold text-foreground">{t("title")}</h1>
          <p className="text-sm text-muted-foreground">{t("description")}</p>
        </div>
        <LinkButton className="h-9 gap-2" href={ROUTES.ADMIN_COURSES_CREATE} size="sm">
          <PlusCircle aria-hidden className="size-4" />
          {t("actions.create")}
        </LinkButton>
      </div>

      <DataTable columns={courseColumns} options={{ query: ({ pageIndex, pageSize }) => getCoursesPageQuery({ pageIndex, pageSize }) }} />
    </div>
  )
}

const NAMESPACE = "pages.admin.courses"

export const Route = createFileRoute("/admin/courses/")({
  component: CoursesPage,
  head: pageHead(ROUTES.ADMIN_COURSES),
  loader: async ({ context }) => {
    const locale = getCurrentLocale()
    const [metadata] = await Promise.all([
      loadPageMetadata({ locale, namespace: NAMESPACE }),
      preloadNamespaces({ locale, namespaces: [NAMESPACE], queryClient: context.queryClient }),
      context.queryClient.query({ ...getCoursesQuery, staleTime: "static" }),
    ])
    return { locale, metadata }
  },
  pendingComponent: AdminCoursesPending,
  staticData: { namespaces: [NAMESPACE] },
})
```

- **El componente** es una `const` local llamada `<Name>Page`, definida en primer lugar. El marcado pequeño que solo usa esta página puede ir encima como componentes locales, como hacen `CourseProgress` y `StartLink` en `courses.$course.index.tsx`; cualquier cosa con sus propios datos, mutación o estado va a un archivo de componente.
- **Un espacio de nombres.** `const NAMESPACE = "pages.<area>.<page>"` va justo encima de `export const Route` y se usa en `loadPageMetadata`, `preloadNamespaces` y `staticData`. Todo lo demás que necesite la página lo declara su layout.
- **Un solo `Promise.all`.** El loader inicia todo el trabajo a la vez: los metadatos de la página, el espacio de nombres y cada consulta que leen los componentes. Devuelve `{ locale, metadata }` para `head`. Nunca esperes a que termine una de estas tareas antes de iniciar la siguiente.
- **`head: pageHead(ROUTES.X)`** construye el título, la descripción, la URL canónica y las URL alternativas a partir de los metadatos del archivo del espacio de nombres.
- **Las rutas de URL salen de `ROUTES`**, en `src/routes.ts`; nunca escribas una ruta como literal.

Una página cuyo título sale de un registro espera ese registro y construye su head a partir de los datos del loader, como hace `admin.courses.$courseId.tsx`:

```tsx
export const Route = createFileRoute("/admin/courses/$courseId")({
  component: CourseEditorPage,
  head: ({ loaderData }: { loaderData?: { locale: SupportedLocale; pathname: string; title: string } | undefined }) =>
    buildPageHead({ locale: loaderData?.locale, pathname: loaderData?.pathname ?? ROUTES.ADMIN_COURSES, title: loaderData?.title }),
  loader: async ({ context, params }) => {
    const locale = getCurrentLocale()
    const data = await context.queryClient.query(courseEditorQuery({ courseId: params.courseId })).catch(rethrowAsNotFound)
    return { locale, pathname: `${ROUTES.ADMIN_COURSES}/${data.course.id}`, title: localize(data.course.title, locale) }
  },
  pendingComponent: AdminCourseEditorPending,
})
```

## Rutas de layout

`src/routes/admin.courses.tsx`:

```tsx
const NAMESPACES = ["course.validations", "pages.admin.courses"] as const

export const Route = createFileRoute("/admin/courses")({
  loader: ({ context }) => preloadNamespaces({ locale: getCurrentLocale(), namespaces: NAMESPACES, queryClient: context.queryClient }),
  pendingComponent: AdminCourseSectionPending,
  staticData: { namespaces: NAMESPACES },
})
```

- Un layout declara `const NAMESPACES = [...] as const` encima de `export const Route` y lo precarga. Cuando no tiene ninguno, omite la opción; no existe `namespaces: []`.
- El componente, cuando el layout renderiza uno, se llama `<Name>Layout` y coloca un `<Outlet />`.
- Una guarda va en el `beforeLoad` del layout que es dueño del área: `beforeLoad: requireAdmin` en `admin.tsx`, `requireSignedIn` en `app.tsx`. Las guardas solo deciden la navegación; cada función de servidor sigue comprobando su propio permiso.

## Orden de las opciones

`sort-keys` está desactivada en `src/routes` porque TanStack Router infiere los tipos en el orden de declaración. Las opciones van en orden alfabético, salvo `validateSearch`, que va primero, antes de todo lo que lee los parámetros de búsqueda:

```tsx
export const Route = createFileRoute("/auth/reset-password")({
  validateSearch: zod.object({
    error: searchText(),
    token: searchText(),
  }),
  component: ResetPasswordPage,
```

Nunca escribas en línea un array o un objeto de datos dentro de `createFileRoute`; decláralo encima como una constante.

## Parámetros de búsqueda

`validateSearch` es un `zod.object` construido con los helpers de `src/lib/search-params.ts`:

| Helper                            | Valor cuando el parámetro falta o está mal formado | Uso                                            |
| --------------------------------- | -------------------------------------------------- | ---------------------------------------------- |
| `searchText()`                    | `undefined`                                        | Tokens, correos electrónicos, códigos de error |
| `searchFlag()`                    | `undefined`                                        | Booleanos                                      |
| `searchParam(schema)`             | `undefined`                                        | Cualquier otro esquema, como una ruta          |
| `searchChoice(choices, fallback)` | `fallback`                                         | Una pestaña o una vista                        |

Un texto ausente se queda en `undefined`, así que un valor por defecto nunca se cuela en una URL que construye el router. Un parámetro `searchChoice` va acompañado de `search: { middlewares: [stripSearchParams({ tab: DEFAULT_TAB })] }`, que elimina el valor por defecto de la URL. Nunca escribas a mano comprobaciones `typeof search["x"] === "string"`; añade un helper cuando haga falta un nuevo tipo de campo. Cuando un hijo necesita un parámetro que la página ha validado como presente, la página estrecha su tipo y se lo pasa, como `auth.reset-password.tsx` pasa `token` a `ResetPasswordForm`.

## Esqueletos

La navegación debe sentirse instantánea, así que cada ruta que renderiza una página tiene un `pendingComponent` que la reproduce: la misma disposición, las mismas tarjetas y el mismo número de filas.

- Los esqueletos viven en el archivo pending del área (`content-pending.tsx`, `courses-pending.tsx`) y usan `Skeleton` de shadcn.
- Un marcador de texto lleva el token tipográfico real más `h-lh scale-y-70`, para que tenga la altura de la línea que sustituye: `<Skeleton className="h-lh w-28 scale-y-70 font-mono text-label" />`.
- La longitud de las listas sale de las constantes que usa la página: `PAGE_ROWS` en `admin/pending-blocks.tsx` tiene `DEFAULT_PAGE_SIZE` filas, el tamaño de página de todas las tablas de administración.
- El esqueleto de un layout elige de un mapa el esqueleto de página que corresponde a la ruta actual, como hacen `ADMIN_PAGES` en `admin-pending.tsx` y `COURSE_PAGES` en `content-pending.tsx`. Cada página nueva se añade a ese mapa.
- No hay un `defaultPendingComponent` para todo el router, y `pendingMs` mantiene el valor por defecto de TanStack. Las rutas de la documentación son la única excepción: `pendingMs: Number.POSITIVE_INFINITY` y `wrapInSuspense: false`, para que un clic que llega antes de que la página de documentación se haya hidratado se convierta en una carga de página normal.

## Enlaces

- Los enlaces del router reciben una constante: `<Link to={ROUTES.COURSES}>`, `<Link hash={MARKETING_SECTION_IDS.PRICING} to={ROUTES.HOME}>`, o un patrón de ruta con `params` para las rutas dinámicas. `LinkButton` de shadcn recibe un `href`.
- Nunca añadas el prefijo de idioma a un enlace del router; lo añade la reescritura del router. Una URL completa en el idioma actual, para un valor que sale del router como cadena, se obtiene de `router.buildLocation({ ... }).publicHref`, que es como `use-auth-redirect.ts` construye sus enlaces de inicio de sesión. `localizePathname` es para las URL que se construyen fuera de un contexto de router o para otro idioma: correos, destinos de redirección de Better Auth, enlaces dentro de MDX y el selector de idioma.
