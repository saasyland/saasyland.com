---

## Inhalte

- Seiten liegen unter `content/docs/<section>/<page>.<locale>.mdx`, für alle neun Locales.
- `meta.<locale>.json` legt in jedem Ordner den Abschnittstitel, das Icon und die Seitenreihenfolge fest.
- `src/integrations/fumadocs/fumadocs.i18n.ts` verwendet den Parser `dot`, `en-US` als Standard und Fallback sowie `hideLocale: "always"`, weil die App das Locale-Präfix selbst verwaltet.
- `bun run content` erzeugt `.source` aus `fumadocs.config.ts`.

## Routen

- Layout `/docs` (`src/routes/docs.tsx`): Eine Serverfunktion liefert den Seitenbaum für die aktuelle Locale; das Layout rendert das Fumadocs-`DocsLayout` mit dem GitHub-Link sowie `LocaleSelect` und `ThemeSwitch` als einheitlich gestaltete Auswahlfelder im Fußbereich der Seitenleiste, lädt `docs.css` und zeigt während des Ladens `DocsPending`.
- `/docs/` und `/docs/$` rufen `loadDocsPage` (`fumadocs.docs.ts`) auf, das die Seite auflöst und ihr kompiliertes MDX (`docsContent`) vor dem Rendern vorab lädt.
- `/api/search` stellt die Fumadocs-Suche über alle Locales bereit (`fumadocs.search.ts`).

MDX-Seiten können `mdxComponents` aus `src/presentation/components/custom/mdx.tsx` verwenden: die Fumadocs-Standardkomponenten, Fumadocs `Accordions`, `Steps` und `Tabs` sowie die shadcn-Komponenten `Alert`, `Badge`, `Button`, die Card-Bausteine, `Separator` und die Tabellen-Bausteine. Links werden automatisch lokalisiert.

## Eine Seite hinzufügen

1. Schreiben Sie `<page>.en-US.mdx` mit `title` und `description`.
2. Fügen Sie den Slug in `meta.en-US.json` und in jeder anderen `meta.<locale>.json` in derselben Reihenfolge hinzu.
3. Fügen Sie die acht Übersetzungen mit byte-identischen Codeblöcken hinzu.
4. Führen Sie `bun scripts/check-content.ts` (auch Teil von `bun run check:i18n`) und `bun run content` aus.

`bun run build` rendert jede Dokumentationsseite in jeder Locale vorab.
