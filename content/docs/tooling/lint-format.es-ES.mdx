---
title: "Lint y formato"
description: "oxlint y oxfmt a través de Vite+, y los scripts de comprobación."
---

Vite+ ejecuta oxfmt para el formateo y oxlint para el linting, ambos configurados en las secciones `fmt` y `lint` de `vite.config.ts`. `bun run check` es el control que ejecuta CI:

```sh
bun run check
```

Ejecuta `generate:cn`, `check:i18n` y `vp check`, que comprueba el formato, aplica las reglas de lint y comprueba los tipos del proyecto. Use `bun run lint`, `bun run format` y `bun run format:check` para ejecutar las herramientas de una en una.

## Formato

- Sin punto y coma, comillas dobles, comas finales, sangría de dos espacios, un ancho de línea de 140 y finales de línea LF.
- Las importaciones se ordenan en grupos fijos: solo servidor, `cloudflare:workers`, React, paquetes externos, después las áreas de `~/src` (platform, providers, integrations, modules, routes, hooks, datos y tema, types, lib, branding, componentes de shadcn, componentes personalizados, estilos) y, por último, las importaciones relativas.
- Las clases de Tailwind se ordenan en `className` y dentro de las llamadas a `cn`, `cva`, `clsx` y `tw`.

## Linting

- Las categorías `correctness`, `nursery`, `pedantic`, `perf`, `style` y `suspicious` son errores.
- Las reglas con información de tipos y la comprobación de tipos están activadas (`typeAware` y `typeCheck`).
- Límites destacados: 800 líneas por archivo, 150 líneas por función, 20 sentencias por función, ningún número mágico aparte de `0` e identificadores de al menos dos caracteres, salvo `_`, `m` y `t`.
- Las sobrescrituras relajan algunas reglas para las pruebas, el código de presentación y los hooks, los mocks de prueba y los archivos de ruta.

Ambas herramientas ignoran los archivos generados y externos: archivos de declaración, `src/routeTree.gen.ts`, migraciones, `.source`, `dist`, `coverage`, `e2e`, `remotion`, las carpetas de agentes y la salida de Playwright. `scripts/` se formatea y se analiza igual que `src/`.

Corrija la causa de un error de lint. No añada comentarios de desactivación, `@ts-expect-error` ni conversiones `as` para satisfacer una regla.

## Correcciones

El hook de pre-commit ejecuta `bun run check:pre-commit`; su paso `vp staged` ejecuta `vp check --fix` solo en los archivos preparados para el commit. `bun run check:fix` aplica correcciones en todo el repositorio y puede reescribir archivos que usted no ha modificado, así que revise su diff antes de hacer commit. Para corregir solo sus propios cambios, pase sus rutas a `vp` (la CLI global de Vite+ o `bunx vp`):

```sh
vp fmt src/routes/admin.users.all.tsx
vp lint --fix src/routes/admin.users.all.tsx
```
