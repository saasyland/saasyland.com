## Rotas

`src/routes/admin.users.tsx` é um layout com quatro abas em forma de link; `/admin/users` redireciona para `/admin/users/all`. Todas as abas usam o namespace `pages.admin.users`.

| Rota                       | Conteúdo                                                              |
| -------------------------- | --------------------------------------------------------------------- |
| `/admin/users/all`         | Tabela de usuários real                                               |
| `/admin/users/invitations` | Linhas de demonstração (`ADMIN_INVITATION_ROWS`) com busca por e-mail |
| `/admin/users/roles`       | Linhas de demonstração (`ADMIN_ROLE_ROWS`)                            |
| `/admin/users/security`    | Estado vazio                                                          |

## Todos os usuários

```tsx
<DataTable columns={userColumns} options={{ query: getUsersPageQuery, selectable: true }} />
```

- `getUsersPageQuery` chama a função de servidor `getUsers` (`src/modules/user/use-cases/get-users.ts`, permissão `user: ["list"]`). Paginação e ordenação acontecem no servidor por nome, papel, status, verificação de e-mail, 2FA, fuso horário e datas de criação e atualização.
- O status não é uma coluna. `getUserStatus` (`user.utils.ts`) deriva `banned`, `pending` ou `active` de `banned` e `emailVerified`, e o servidor ordena pela mesma expressão SQL `case`.
- `userColumns` fica em `src/presentation/components/custom/admin/users/user-columns.tsx`; as datas aparecem no fuso horário de cada usuário.

## Ações por linha

`UserRowActions` (`row-actions.tsx`) é o menu da última coluna:

- **Redefinir senha** abre `ResetPasswordDialog`, que chama `setUserPassword`.
- **Banir** ou **Remover banimento** chama `banUser` ou `unbanUser`.
- **Excluir** abre `DeleteUserDialog`, que chama `deleteUser`.

Cada sucesso invalida `USER_QUERY_KEYS.ALL` e mostra uma notificação; os erros passam por `useErrorMessage`. Os itens **Editar** e **Ver perfil** e o botão **Adicionar usuário** ainda não têm ação.

## Não conectados

`createUser`, `getUser`, `updateUser`, `setUserRole`, `impersonateUser` e `stopImpersonatingUser` existem em `src/modules/user/use-cases` com middleware de permissão, mas nenhuma tela os chama. Não há tabela de convites; os papéis reais são `admin` e `customer` em `auth.access.ts`.
