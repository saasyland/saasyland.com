---
title: "Deploy a preview"
description: "Provision Cloudflare resources and deploy the preview Worker."
---

The `preview` environment deploys the Worker `saasyland-preview` to `preview.saasyland.com`. By default `development` and `preview` share one D1 database, one KV namespace and one R2 bucket.

## Provision resources

```sh
bunx wrangler login
bunx wrangler d1 create saasyland_com_preview
bunx wrangler kv namespace create CACHE --env preview
bunx wrangler r2 bucket create saasyland-preview
```

In `wrangler.jsonc`, replace `database_id`, `database_name`, the KV `id` and the `MEDIA` `bucket_name` under both `development` and `preview`. Keep the binding names `DB`, `CACHE` and `MEDIA` and the `migrations_dir`, and update the Worker names and custom domain routes for your account. For production, create separate resources, including the `saasyland` bucket, and update the `production` block. Set `APP_DOMAIN` in `src/presentation/branding/index.ts`. `appHostsForMode` in `src/modules/_core/constants/api.ts` derives the allowed hosts from it: `APP_DOMAIN` in production, `preview.<APP_DOMAIN>` in preview, `localhost:3000` or `127.0.0.1:3000` in development, and those plus `localhost:3020` and `127.0.0.1:3020` in test. Edit `HOSTS_BY_MODE` there only if your preview host has a different name.

## Deploy

Fill in `.env.preview`, then migrate and deploy:

```sh
bun run db:migrate:preview
bun run deploy:preview
```

`deploy:preview` runs `scripts/verify-bindings.ts preview`, which rejects placeholder IDs, then `build:preview`, which prerenders the public pages and verifies the output, and finally `wrangler deploy --secrets-file .env.preview`, which also uploads the secrets. Building and deploying never apply migrations; run `db:migrate:preview` before deploying code that needs a new schema. `verify-bindings.ts` does not check the R2 bucket, which is bound by name: the deploy fails until it exists.

Register the OAuth callbacks and the Polar webhook for the preview host as listed in [Environment variables](/docs/getting-started/environment-variables).

## Automatic deployments

CI deploys every pull request from a branch in this repository to the shared preview, and every push to `main` to production, after checks and browser tests pass. See [CI/CD](/docs/tooling/ci-cd) for the required GitHub secrets.
