## Progetti Vitest

`vp test` esegue Vitest tramite Vite+ con tre progetti definiti in `vite.config.ts`. I test si trovano in una cartella `__test__` accanto al codice che coprono e importano le API di test da `vite-plus/test`.

| Progetto      | Ambiente | Pattern dei file        |
| ------------- | -------- | ----------------------- |
| `node`        | Node     | `*.test.ts`             |
| `integration` | Node     | `*.integration.test.ts` |
| `component`   | jsdom    | `*.component.test.tsx`  |

Nessun test contatta un account Cloudflare o un provider reale:

- D1 è un database SQLite in memoria che esegue le migrazioni versionate, e KV è una mappa in memoria. KV e i contatori del rate limit vengono azzerati prima di ogni test.
- `createServerFn` viene sostituita, così una server function viene eseguita nello stesso processo passando per il suo middleware e il suo validator reali.
- I test dei componenti eseguono il rendering con un `QueryClient` e un router reali.
- Le richieste di email, OAuth e pagamento sono sostituite da mock.

## Copertura

`bun run test:coverage` impone il 100% per righe, istruzioni, funzioni e branch in tutto `src`. Sono esclusi le primitive shadcn, `src/platform/testing`, i file generati e le dichiarazioni di tipo. Copri il comportamento reale ed elimina i branch che non possono mai essere eseguiti, invece di sostituire variabili globali con stub per raggiungerli.

## Test browser

Le spec Playwright si trovano in `e2e/specs`, con i page object in `e2e/pages` e le fixture in `e2e/fixtures`. Vengono eseguite su una build simile a quella di produzione che usa l'ambiente Wrangler `test`: D1 e KV locali in `.wrangler/test`, secret fittizi da `.env.test` e un Worker di test che cattura le email in uscita, così una spec può seguire un vero link di verifica. In locale Playwright esegue da sé migrazioni, seed, build e avvio dell'app. La suite viene eseguita in Chromium e WebKit.

## Script

```sh
bun run test
bun run test:unit
bun run test:integration
bun run test:component
bun run test:watch
bun run test:changed
bun run test:coverage
bun run test:e2e
bun run test:e2e:smoke
bun run test:e2e:pr
```

## CI

`.github/workflows/ci.yml` viene eseguito sulle pull request e sui push su `main`:

1. `bun run check`: formattazione, lint, controllo dei tipi e `check:i18n`
2. `bun run test:coverage`
3. Una build di test e la suite Playwright in Chromium
4. Un deploy di preview per le pull request, oppure un deploy di produzione per `main`
