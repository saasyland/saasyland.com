## まずは批判ではない部分から

Supastarter を候補に挙げているなら、あなたの目は確かです。このカテゴリで最も本格的な有料の競合製品であり、検索結果を占める週末仕立てのテンプレートとはまったくの別物です。**1,460 人の開発者**が購入しています。何年にもわたってきちんとメンテナンスされてきました。作者はマーケターではなくエンジニアであり、それはコードにもドキュメントにも表れています。

このカテゴリのほとんどの製品がまったく行っていないことを、4 つ行っています。

**本物のモノレポを 4 つに分割。** `apps/marketing`、`apps/saas`、`apps/docs`、`apps/mail-preview` があり、それぞれに独自の `package.json`、`next.config.ts`、`tsconfig.json`、レイアウト、Playwright の設定があります。マーケティングサイトをアプリとは独立してデプロイしたいなら、それはすでに実現されています。いずれマーケティングチームを持つ会社にとって、本当に良いデフォルトです。

**ほかの誰も手を付けない決済の選択肢。** Stripe、Lemon Squeezy、Polar、Creem、Dodo Payments に対応しています。特に Creem と Dodo は、ヨーロッパの創業者が VAT の理由からあえて選びたいかもしれないマーチャント・オブ・レコードのプロバイダーで、これらが最初からサポートされているのは珍しいことです。

**本当に完成している認証。** パスワード、パスキー、マジックリンク、二要素認証、OAuth、パスワード忘れとリセットのフロー、ロールと権限、スーパー管理者となりすまし。このリストはマーケティングではありません。特になりすましは、どのサポートチームも 40 日目に求めるのに、誰も 1 日目には作らない機能です。

**ORM を選べる。** Prisma か Drizzle か、決めるのはあなたです。多くの購入者はここに強いこだわりを持っており、どちらを使うか指定されるのは本当にストレスになります。

Supastarter を肥大化した週末仕立てのコードだと言う人は、そのコードを読んでいません。この記事の残りは、信頼できる 2 つの選択肢の比較であり、こき下ろしではありません。

## コマンドを入力する前に下される決定

どのスターターキットも、ほかのどの質問よりも先に 1 つの質問に答えます。**購入者は何を受け取るのか？**

答えはちょうど 2 つあり、それぞれがまったく異なる 2 年間をもたらします。

**答え 1：すべてを受け取り、自分で削除する。** 製品がサポートするすべての機能を含むリポジトリをクローンします。組織、5 つすべての決済プロバイダー、ドキュメントアプリ、メールプレビューアプリ、AI モジュール。そのうえで、不要なものを削除します。Supastarter のドキュメントに記載された始め方は `npx supastarter new my-awesome-project` で、ドキュメントではクローン、設定、インストールを行うコマンドとして説明されています。

**答え 2：回答した内容だけを受け取る。** いくつかの質問に答えます。ジェネレーターは回答に対応するモジュールだけを書き出し、それ以外は何も書きません。シングルテナントのプロジェクトには、組織のコードがどこにも存在しません。課金のないプロジェクトには、読み飛ばさなければならない Stripe の webhook ハンドラーがありません。ホームページの [CLI コンフィギュレーター](/#cli) は、まさにこれを目の前でライブに行います。<RepositoryCount fact="cliQuestions" /> 個の質問、4 つの任意機能、そして回答に応じて変わるコマンドです。

どちらも正当な方法です。答え 1 は学習に使える完全なリファレンス実装を提供し、不要なコードが手元にあるほうがないよりも良い日もあります。答え 2 はより小さなリポジトリを提供し、それは思っている以上に重要です。

なぜ思っている以上に重要なのかを説明します。

**使われないコードはタダではありません。** 参加するすべての開発者がそれを読みます。すべての grep がそれを検索します。すべての「使用箇所の検索」に現れます。バンドラーはそれをたどります。リポジトリに向けるすべてのコーディングエージェントのコンテキストウィンドウに読み込まれ、それは今や比喩ではなく本物の予算です。そして何より、**それはあなたが責任を負うのに自分では書いていないコード**であり、ソフトウェアにおいて最悪の組み合わせです。

この議論を最もはっきり示すとこうなります。シングルテナントでスキャフォールドした場合、組織スコープのクエリがどこかでまだ実行されていないと、どれだけ確信できるでしょうか。答え 2 なら、この問い自体が意味をなしません。そのコードは存在しないからです。

## upstream のマージが楽になるどころか難しくなる理由

これは、何かを買う前に私自身が説明してほしいと思う比較のポイントであり、めったに議論されません。

Supastarter のドキュメントはこの仕組みを明確に、そして評価すべきことに正直に説明しています。「将来アップデートを取り込めるように、supastarter のリポジトリをプロジェクトの upstream origin として設定する」もので、コマンドは `git remote add upstream https://github.com/supastarter/supastarter-nextjs.git` です。フェッチし、マージし、解決します。

初日はこれが見事に機能します。ほとんど何も変更していないので、マージは fast-forward になります。

18 か月目を考えてみてください。ダッシュボードを書き直し、課金の UI を再構成し、ユーザーのスキーマを変更し、使わなかった 2 つのアプリを削除しました。そこに新しいバージョンが届きます。

この時点で 3 つのことが成り立っており、それは誰かの落ち度ではなく構造的なものです。

**コンフリクトが起こりうる範囲は、相手の変更とあなたの変更が重なる部分であり、それは広がる一方です。** 触ったファイルはすべて、コンフリクトしうるファイルです。開発者としての生産性の高さこそがアップグレードを難しくするわけで、これは誰も望まないインセンティブです。

**削除は記憶されません。** ホスティング型のドキュメント製品を使っているので、`apps/docs` を削除しました。upstream にはまだそれがあります。今後のマージのたびに再び提案されます。同じ判断を際限なくやり直すことになり、ある日、大きなマージの最中にうっかり受け入れてしまい、本番環境にドキュメントアプリがあることに気づきます。

**マージはコミット単位で全か無かです。** アップデートには、認証のセキュリティ修正と、あなたがすでに作り直した設定ページのリデザインが含まれています。前者は欲しいが後者は要らない。git はそれを切り分ける手助けをしてくれません。

代替案は魔法ではなく、その点は正確に述べておきたいと思います。ジェネレーターはアップグレード作業をなくしません。変わるのは作業の形です。ツールがどのモジュールを生成したかを記録しているので、アップデートはまさにそのモジュールに対する差分として、実際に取り込んだものと一致するベースラインを基準に表現できます。同じ回答でクリーンなプロジェクトを再生成し、自分のプロジェクトとの差分を取ることもできます。これは見通しの良い作業です。18 か月前にフォークした 4 アプリ構成のモノレポをマージする作業は、そうではありません。

<Callout type="info" title="正直な注意点">

アップデートを完全に解決するスターターキットはありません。ファイルを編集した時点で、誰かがその 2 つのバージョンを調整しなければなりません。ここでの主張はもっと限定的で、擁護できるものだと考えています。選んだモジュールを再生成できるベースラインと照らし合わせて調整する作業は、削除したものがすべてまだ残っている upstream をマージするよりも小さく、範囲のはっきりした作業です。

</Callout>

## E2E テストとカバレッジゲートは別の主張です

Supastarter のドキュメントには Playwright による E2E テストが記載されています。これは本物で、ほとんどの競合製品が提供している以上のものであり、そうではないふりをするつもりはありません。

同時に、これはこのコードベースが掲げる主張とは別のものです。どちらも「テストあり」に分類されるので、その違いを理解しておく価値があります。

**E2E スイートは、テストを書いたパスが今日動くことを証明します。** ブラウザでサインアップ、チェックアウト、いくつかのフローを実行します。致命的な問題を見つけるのは得意ですが、具体的な問題を見つけるのには役に立ちません。

**カバレッジゲートは、テストされていない分岐がマージされることそのものを防ぎます。** このリポジトリの `vite.config.ts` にある実際の設定です。

```ts
coverage: {
  thresholds: {
    branches: 100,
    functions: 100,
    lines: 100,
    statements: 100,
  },
}
```

4 つの数値はすべて 100 で、すべて強制されています。現在、このゲートは **<RepositoryCount fact="testFiles" /> 個のテストファイル**に適用されています。生成されたファイル、テストインフラ、shadcn のプリミティブは除外されており、そのことは隠されずに設定ファイルに記載されています。ルート自体はカバーされています。

実際の違いが現れるのは、特定の場所、つまりエラー分岐です。webhook ハンドラーには、検証に失敗する署名のためのパスがあります。招待フローには、期限切れのトークンのためのパスがあります。権限チェックには、false を返すパスがあります。**E2E スイートがそれらを実行することはほとんどありません**。ブラウザテストで失敗する署名を用意するのは面倒で、誰もが省略するからです。100 に設定された分岐カバレッジのゲートは、それらをテストなしでマージさせません。

そして、まさにそうした分岐でこそ SaaS 製品は失敗します。リリース前に誰も手動で実行しない分岐だからです。

## 必要ないかもしれない 4 つのアプリ

4 アプリ構成のモノレポは上で Supastarter の利点として挙げましたし、適した購入者にとっては実際に利点です。ただ、そのコストも明示しておく価値があります。「モノレポ」は、無条件に良いものとして受け入れられがちな言葉だからです。

4 つのアプリとは、4 つの `package.json` ファイル、4 つの `tsconfig.json` ファイル、4 つの Next の設定、4 つのビルドパイプライン、4 組の依存関係のアップグレードを意味します。1 人で 1 つの製品を作っているなら、ソロ創業者の時間でプラットフォームチームの構造を運用することになります。

代替案は「モノレポにしない」ことではありません。**継承するのではなく、決めること**です。[CLI コンフィギュレーター](/#cli) は構成についての質問を直接尋ねます。モノリス、API 分離、マイクロサービスのどれにするか。モノリスを選べば、デプロイ単位も依存関係ツリーも 1 つです。分離を選べば、フロントエンドと独立した API が手に入ります。アーキテクチャは、購入した製品の性質ではなく、質問に対するあなたの答えになります。

## 読みやすさが保たれる責任範囲

どちらの製品にもアーキテクチャがあります。比較すべきは、ある処理がどこに属するのか、そしてそれがそこにとどまっていることをレビュアーがどう確認できるかです。

公開リファレンスアプリケーションは、フラットな機能単位の責任範囲と、型付きの Vite+ チェックを使っています。

```ts
// vite.config.ts, abridged
lint: {
  options: { typeAware: true, typeCheck: true },
}
```

`src/routes` はリクエストとナビゲーションを調整します。`src/modules` は機能のユースケースとバリデーションを、`src/integrations` はベンダーのセットアップを、`src/presentation` はコンポーネントとその周辺のパーツを担当します。`src/platform` ディレクトリにはローカルテストの支援コードが含まれます。これらの責任範囲はドキュメント化され、コードと一緒にレビューされます。

コンパイラーは型をチェックし、サーバー専用のインポートが Worker のコードをクライアントバンドルから守ります。ただし、すべての機能境界を強制するわけではありません。処理を追加するときは責任範囲をレビューし、テストは退行しうる振る舞いに集中させてください。

これは月を追うごとに重要になります。その理由は人間の開発者とはまったく関係ありません。コーディングエージェントは、コードベースのルールを README からではなく、失敗したものから学びます。ビルドを失敗させる境界は、エージェントが 2 回目の試行で尊重する境界です。規約にすぎない境界は、エージェントが丁寧に、繰り返し破る境界です。これについては [AI コーディングエージェントに向けたリポジトリの準備](/blog/ai-coding-agents-repository-readiness) で書きました。

## それぞれの製品の実際のコスト

Supastarter のプランは、開発者 1 シートで **$299** の Solo、最大 5 シートでコンサルティング通話と優先サポートが付く **$799** の Startup、最大 10 シートでホワイトラベル対応、プライベートな Discord チャンネル付きの **$1,499** の Agency です。

SaaSy Land は Core が **$249**、Complete が **$399**、Agency が **$899** です。いずれも買い切りの商用 CLI ライセンスで、編集可能な生成済みアプリケーションのソースが付きます。Core と Complete は購入者自身の製品をカバーし、Agency はクライアントプロジェクトもカバーします。アクティベーションやシート数の制限がある場合は、購入前に開示されます。

| 購入者                       | Supastarter      | SaaSy Land                 | 差額             |
| ---------------------------- | ---------------- | -------------------------- | ---------------- |
| ソロ創業者                   | $299             | $249                       | $50              |
| 3 人のチーム                 | $799             | $249                       | $550             |
| 5 人のチーム                 | $799             | $249                       | $550             |
| 8 人のチーム                 | $1,499           | $899                       | $600             |
| エージェンシー、開発者 10 人 | $1,499           | $899                       | $600             |
| それ以上の開発者             | 最新の条件を確認 | 開示されたライセンスの制限 | パッケージによる |

公平を期して言えば、Startup と Agency のプランにはシート以外にも実質的なものが含まれています。作者との 60 分のコンサルティング通話には価値があります。優先サポートにも価値があります。プライベートな Discord で創業者に直接連絡できることにも価値があります。それらが欲しいのであれば、価格は妥当であり、欲しいものを買うべきです。

しかし、欲しいのがソースコードであれば、シート数は製品の判断ではなくライセンスの判断です。そしてそれは、まさに会社が順調なときに煩わしくなる種類の判断です。

## Supastarter を買うべき人

4 アプリ構成のモノレポを最初から使いたい、どのみち自分でもそう作るという人は Supastarter を買ってください。Creem や Dodo Payments が特に必要な場合も同様です。ほかにサポートしているところはほとんどありません。代わりに決めてくれるジェネレーターよりも、自分で読んで削れる完全なリファレンス実装を重視する場合。作者との 60 分の通話に数百ドルの価値がある場合。購入者によっては明らかにそうです。Prisma を使っていて、今後も使い続けるつもりの場合。

実際の顧客を持つ良い製品であり、選んで恥ずかしい思いをすることはありません。

## 代わりにこちらを買うべき人

求めたコードだけを含むリポジトリが欲しいなら、こちらを買ってください。100% のカバレッジゲートを実際に維持するつもりがある場合。2 週目に無効化してしまう人にとっては無価値だからです。明確な機能の責任範囲、型付きのチェック、焦点を絞った振る舞いのテストが重要な場合。チームが 2 人以上で、シート数を数えたくない場合。Next.js を使いたくないかもしれない場合。ここでは TanStack Start と React Router も選べます。サンプル製品付きのストア、サブスクリプションコース、ページビルダー、ビジュアル投稿エディターが欲しい場合。これらはここでは任意の追加機能として用意されていますが、あちらでは提供されていません。

そして、1 日の大部分をコーディングエージェントとの作業に費やしているなら、こちらを買ってください。強制される境界とより小さなリポジトリについて上で述べたことはすべて、あなたにとってよりもエージェントにとって価値があるからです。

## よくある質問

<Accordions>

<Accordion title="Supastarter の代替として最適なものは何ですか？">

Supastarter を検討しているほとんどの人にとって、正直な答えは Supastarter です。1,460 人の開発者に支持されている、本格的でしっかりとメンテナンスされた製品です。次の 3 点が重要な場合は、ほかの選択肢を検討してください。不要な部分を削る完全なクローンではなく、選んだモジュールだけを書き出すジェネレーター。E2E テストだけではなく、強制されるカバレッジゲート。そして、シート単位のライセンスではなく、チーム全体をカバーする 1 つの価格です。

</Accordion>

<Accordion title="Supastarter はどのように提供され、インストールされますか？">

リポジトリをクローンする CLI を通じて提供されます。ドキュメントには `npx supastarter new my-awesome-project` が記載されており、このコマンドがクローン、設定、インストールを行います。代替手段として手動の `git clone` も用意されています。セットアップでは続いて Supastarter のリポジトリを git の upstream リモートとして追加するため、今後のバージョンはプロジェクトへのマージとして届きます。

</Accordion>

<Accordion title="git の upstream によるアップデートモデルの何が問題なのですか？">

カスタマイズするまでは何も問題ありません。マージでコンフリクトが起こりうる範囲は、相手の変更とあなたの変更が重なる部分であり、それは広がる一方です。さらに悪いことに、削除は記憶されません。不要だったので削除したコードは upstream にはまだ残っているため、今後のマージのたびに再び提案され、同じ判断を永遠にやり直すことになります。

</Accordion>

<Accordion title="Supastarter の価格は SaaSy Land と比べてどうですか？">

Supastarter は開発者 1 シートで $299、最大 5 シートで $799、最大 10 シートで $1,499 としています。SaaSy Land の Core は購入者自身の製品向けで $249、Agency は $899 でクライアントプロジェクトもカバーします。商用ライセンスと、購入前に表示されるアクティベーションやシート数の制限が適用されます。ここで引用した競合の価格では、1 人向けのエントリー価格の差は $50、クライアントワーク向けパッケージの価格差は $600 です。

</Accordion>

<Accordion title="Supastarter にはテストがありますか？">

ドキュメントには Playwright による E2E テストが記載されており、これは実際に存在し、有用なものです。公開ドキュメントに記載されていないのは、カバレッジのしきい値が強制されるユニットテストや統合テストのスイートです。重要なのはこの違いです。E2E テストはハッピーパスが今日動くことを証明し、カバレッジゲートはテストされていない分岐がマージされることそのものを防ぎます。

</Accordion>

<Accordion title="4 つのアプリを含むモノレポは良いものですか？">

マーケティングサイト、アプリ、ドキュメント、メールプレビューを初日から別々にデプロイしたいなら、本当の利点です。デプロイ単位を 1 つにしたかったのであればコストになります。1 人で書いている製品のために、4 つの package.json ファイル、4 つの tsconfig、4 つのビルドパイプラインを保守することになるからです。

</Accordion>

<Accordion title="Supastarter をクライアントプロジェクトに使えますか？">

はい。最大 10 シートで $1,499 の Agency プランで使え、ホワイトラベル対応が明記されています。SaaSy Land の Agency パッケージはクライアントプロジェクト向けで $899 です。ライセンスの対象は購入した個人または法人とその許可された従業員で、購入前に開示されるアクティベーションやシート数の制限が適用されます。クライアントには CLI を実行するライセンスは付与されません。

</Accordion>

<Accordion title="AI コーディングエージェントにはどちらが適していますか？">

明確な責任範囲、厳格な型、読みやすい例、エージェントが実行できるチェックがあるかを確認してください。この公開リファレンスアプリには、型付きの Vite+ チェック、振る舞いのテスト、サーバー専用の境界があります。機能フォルダーの責任範囲はドキュメント化されていますが、引き続きレビューが必要で、すべてがインポートルールで強制されているわけではありません。

</Accordion>

<Accordion title="どちらの製品も無期限のアップデートを提供していますか？">

どちらもサブスクリプションなしの無期限アクセスをうたっています。違いは受けられる権利ではなく、届け方です。カスタマイズしたプロジェクトに upstream のモノレポをマージすることと、実際に生成したモジュールの差分を取り込むことは別の作業であり、その違いは作業を続ける毎月積み重なっていきます。

</Accordion>

<Accordion title="すでに Supastarter を購入した場合、乗り換えるべきですか？">

うまく動いていて、それで製品をリリースしているなら、おそらく乗り換える必要はありません。乗り換えのコストは現実のものであり、より良いアーキテクチャというだけで書き直しに見合うことはまれです。どのみち次のプロジェクトを始めるときに乗り換えてください。比較にコストがかからないのはそのときだけです。

</Accordion>
