title: "Rutas"
description: "Todas las rutas de páginas y de la API, con su constante de ROUTES, su archivo de ruta y su guard."
---

Cada ruta tiene una constante en `ROUTES` (`src/routes.ts`), declarada en el `src/data/<area>.routes.ts` de su área (consulta [Rutas y navegación](/docs/conventions/routes#paths-and-navigation)). Los enlaces usan la constante, por ejemplo `<Link to={ROUTES.SIGN_IN}>`, y el router añade el prefijo de locale. Cada una de las páginas siguientes se sirve también bajo todos los prefijos de locale distintos del predeterminado, por ejemplo `/pl-PL/terms`.

## Páginas públicas

Estas páginas están dentro del layout `_site`, que muestra la cabecera del sitio. Todas excepto la documentación están además dentro del layout `_marketing` (marco de página y pie de página), el layout de la documentación muestra ese mismo pie de página por su cuenta, y el blog y la documentación tienen sus propios layouts dentro de ellos. Todas se prerenderizan salvo las páginas de la newsletter.

| Ruta                          | Constante                | Archivo de ruta                                                |
| ----------------------------- | ------------------------ | -------------------------------------------------------------- |
| `/`                           | `HOME`                   | `_site._marketing.index.tsx`                                   |
| `/licence`                    | `LICENCE`                | `_site._marketing.licence.tsx`                                 |
| `/privacy`                    | `PRIVACY`                | `_site._marketing.privacy.tsx`                                 |
| `/terms`                      | `TERMS`                  | `_site._marketing.terms.tsx`                                   |
| `/refunds`                    | `REFUNDS`                | `_site._marketing.refunds.tsx`                                 |
| `/affiliates`                 | `AFFILIATES`             | `_site._marketing.affiliates.tsx`                              |
| `/newsletter/confirm`         | `NEWSLETTER_CONFIRM`     | `_site._marketing.newsletter.confirm.tsx`                      |
| `/newsletter/unsubscribe`     | `NEWSLETTER_UNSUBSCRIBE` | `_site._marketing.newsletter.unsubscribe.tsx`                  |
| `/blog`                       | `BLOG`                   | `_site._marketing.blog.tsx`, `_site._marketing.blog.index.tsx` |
| `/blog/page/*`                | ninguna                  | `_site._marketing.blog.page.$page.tsx`                         |
| `/blog/*`                     | ninguna                  | `_site._marketing.blog.$.tsx`                                  |
| `/docs`                       | `DOCS`                   | `_site.docs.tsx`, `_site.docs.index.tsx`                       |
| `/docs/cli`                   | `DOCS_CLI`               | `_site.docs.$.tsx`                                             |
| `/docs/tooling/test-coverage` | `DOCS_TEST_COVERAGE`     | `_site.docs.$.tsx`                                             |
| `/docs/*`                     | ninguna                  | `_site.docs.$.tsx`                                             |
| `/*`                          | ninguna                  | `_site._marketing.$.tsx`                                       |

`/*` es cualquier dirección que ninguna otra ruta reconoce: `_site._marketing.$.tsx` lanza `notFound()`, así que el servidor responde 404 con la página de no encontrado, que se renderiza en cada petición (consulta [Página no encontrada](/docs/features/landing-page#not-found-page)).

## Cursos

El layout de `/courses` (`_site._marketing.courses.tsx`) está dentro de los layouts `_site` y `_marketing`, como el blog, y no tiene guard: el servidor comprueba el nivel de acceso de cada lección (consulta [Cursos](/docs/features/courses)). Estas páginas leen D1 en cada solicitud y no se prerenderizan.

| Ruta                         | Constante | Archivo de ruta                                                      |
| ---------------------------- | --------- | -------------------------------------------------------------------- |
| `/courses`                   | `COURSES` | `_site._marketing.courses.tsx`, `_site._marketing.courses.index.tsx` |
| `/courses/<course>`          | ninguna   | `_site._marketing.courses.$course.index.tsx`                         |
| `/courses/<course>/<lesson>` | ninguna   | `_site._marketing.courses.$course.$lesson.tsx`                       |

## API

Las rutas de la API nunca se localizan.

| Ruta                                         | Constante       | Archivo de ruta                                                                                                                                    |
| -------------------------------------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/api`                                       | `API`           | `api/index.ts`                                                                                                                                     |
| `/api/auth/*`                                | `API_AUTH_BASE` | `api/auth.$.ts`                                                                                                                                    |
| <RepositoryFact name="cliApiBasePath" />`/*` | ninguna         | `api/cli.v1.license.ts`, `api/cli.v1.activations.ts`, `api/cli.v1.activations.$activationId.ts`, `api/cli.v1.activations.$activationId.bundles.ts` |

Las rutas de la API de licencias de la CLI salen de su contrato, `API_BASE_PATH` y `API_ROUTE` en `@saasyland/stack/api`, y `src/routes/api/__test__/cli.v1.test.ts` comprueba que el router envía cada una de ellas a su archivo de ruta (consulta [API de licencias de la CLI](/docs/features/cli-licence-api)).

`ROUTES.API_AUTH` enumera las rutas de los endpoints propios de Better Auth y de los de sus plugins de administración y de dos factores, relativas a `/api/auth`; `auth.server.ts` las usa para eximir endpoints de la limitación de peticiones, y `INPUT_POLICY` en `auth.hooks.ts`, para validar los endpoints que aceptan una contraseña, un nombre, un correo o una imagen. `ROUTES.API_AUTH_POLAR` enumera los webhooks del plugin de Polar, que el área de Polar exime de la limitación de peticiones; esta ruta y `API_AUTH_CUSTOMER_PORTAL` están en `src/data/polar.routes.ts`. `API_AUTH_CUSTOMER_PORTAL` y `API_AUTH_VERIFY_EMAIL` son rutas completas a endpoints de Better Auth, construidas a partir de `API_AUTH_BASE`. `AUTH` y `NEWSLETTER` no tienen página propia; junto con `ADMIN`, `APP`, `API` y `COURSES`, marcan las áreas que nunca se prerenderizan (`UNLISTED_ROUTES` en `src/data/unlisted.ts`), y `verify-build.ts` hace fallar una compilación que haya prerenderizado una página bajo cualquiera de ellas.

## Medios

`/media/<expiry>.<signature>/<videoId>/<file>` sirve archivos de vídeo firmados. No tiene constante en `ROUTES` ni archivo de ruta: `src/server.ts` la envía a `serveMedia` antes del middleware de locale, así que nunca se localiza. Consulta [Cloudflare R2](/docs/integrations/cloudflare-r2).

<RepositoryFact name="cliBundleUrlPath" /> sirve del mismo modo los bundles de plantillas firmados de la CLI, mediante `serveBundle`, y toma
su prefijo de `BUNDLE_PATH_PREFIX` en `license.constants.ts`. Consulta [API de licencias de la
CLI](/docs/features/cli-licence-api#template-bundles).
