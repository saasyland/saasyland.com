---
title: "Añadir un caso de uso"
description: "Añade una operación: una función de servidor con sus opciones de query o mutation, la invalidación de caché y el manejo de errores."
---

Un caso de uso es una operación sobre una tabla. Vive en `src/modules/<table>/use-cases/<operation>.ts` y exporta la función de servidor junto con las opciones que usan los componentes. [Funciones de servidor](/docs/guides/server-functions) explica las piezas.

## Escribe una mutation

`src/modules/category/use-cases/create-category.ts`:

```ts
import { mutationOptions } from "@tanstack/react-query"
import { createServerFn } from "@tanstack/react-start"
import { v7 } from "uuid"
import type * as zod from "zod"

import { authorized } from "~/src/integrations/better-auth/auth.middleware"
import { db } from "~/src/integrations/drizzle-orm/drizzle.database"

import { CATEGORY_MUTATION_KEYS } from "~/src/modules/category/category.constants"
import { category } from "~/src/modules/category/category.schema"
import { categoryZodSchemas } from "~/src/modules/category/category.zod"

export const createCategory = createServerFn({ method: "POST" })
  .middleware([authorized({ category: ["create"] })])
  .validator((input: zod.input<typeof categoryZodSchemas.createCategory>) => categoryZodSchemas.createCategory.parse(input))
  .handler(({ data }) =>
    db
      .insert(category)
      .values({
        description: data.description ?? "",
        icon: data.icon ?? "FolderOpen",
        id: v7(),
        kind: data.kind,
        name: data.name,
        visibility: data.visibility ?? "public",
      })
      .returning()
      .get(),
  )

export const createCategoryMutation = mutationOptions({
  mutationFn: (data: Parameters<typeof createCategory>[0]["data"]) => createCategory({ data }),
  mutationKey: CATEGORY_MUTATION_KEYS.CREATE,
})
```

- Las escrituras usan `method: "POST"` y las lecturas `method: "GET"`.
- El middleware protege la llamada: `authorized(permission)` para usuarios con sesión y un permiso, `authorized()` para cualquier usuario con sesión y `withRateLimit(kind, RATE_LIMITS.SENSITIVE)` para operaciones públicas.
- El validador analiza el esquema del módulo; el handler recibe `data` ya validado.
- El handler devuelve el resultado directamente. Las operaciones sobre los datos del propio usuario leen el usuario de `context.auth.user.id`, nunca de la entrada.

## Escribe una query

Las queries exportan opciones cuya clave contiene la entrada validada, de modo que cada página o filtro tiene su propia entrada en la caché (`src/modules/category/use-cases/get-categories.ts`):

```ts
export const getCategoriesPageQuery = (input: zod.input<typeof listCategoriesSchema> = {}) =>
  queryOptions<Awaited<ReturnType<typeof getCategories>>>({
    queryFn: () => getCategories({ data: input }),
    queryKey: [...CATEGORY_QUERY_KEYS.LIST, listCategoriesSchema.parse(input)],
  })

export const getCategoriesQuery = getCategoriesPageQuery()
```

Precarga la query en el `Promise.all` del loader de la ruta con `context.queryClient.query({ ...getCategoriesQuery, staleTime: "static" })` y léela en el componente con `useSuspenseQuery(getCategoriesQuery)`.

## Gestiona los errores

Para los fallos esperados, lanza `AppError` con un código de `src/modules/_core/constants/errors.ts`:

```ts
if (row === undefined) {
  throw new AppError(ERROR_CODES.NOT_FOUND)
}
```

Los códigos son `AUTH_API_ERROR`, `CONFLICT`, `FORBIDDEN`, `INTERNAL_ERROR`, `NOT_FOUND`, `TOO_MANY_REQUESTS`, `UNAUTHORIZED` y `VALIDATION`. El middleware `withRequest`, que incluyen `authorized` y `withRateLimit`, reenvía solo el código de un `AppError`, convierte los errores de la API de Better Auth en `AUTH_API_ERROR` con la clave de error de autenticación, convierte los errores de Zod en `VALIDATION` y registra cualquier otro error antes de sustituirlo por `INTERNAL_ERROR`.

## Úsalo en un componente

Expande las opciones exportadas en `useMutation`, traduce los errores con `useErrorMessage` e invalida las queries del módulo al terminar con éxito (`src/presentation/components/custom/admin/users/delete-user-dialog.tsx`):

```tsx
const queryClient = useQueryClient()
const errorMessage = useErrorMessage()

const deleteUser = useMutation({
  ...deleteUserMutation,
  onError: (error) => {
    toast.error(errorMessage(error))
  },
  onSuccess: async () => {
    await queryClient.invalidateQueries({ queryKey: USER_QUERY_KEYS.ALL })
    toast.success(t("feedback.deleteSuccess"))
  },
})
```

`useErrorMessage` asigna las claves de error de autenticación a `auth.errors.<key>`, los códigos de error a `errors.codes.<CODE>` y todo lo desconocido a `errors.codes.INTERNAL_ERROR`. Invalida solo los módulos cuyos datos cambia la mutation.

## Pruébalo

Añade `use-cases/__test__/<operation>.test.ts`. `executeMutation` y `executeQuery` de `~/src/platform/testing/lib/query` ejecutan las opciones con un `QueryClient` real, y la configuración de tests pasa la función de servidor por su middleware y su validador reales. Cubre el éxito, cada código lanzado y la comprobación de permisos. Consulta [Escribir tests](/docs/guides/writing-tests).
