## レイアウト

`src/routes/app.tsx` はこの領域にあるすべてのページの検索パラメーターを検証し、`requireSignedIn` で領域を保護して、名前空間をプリロードします。

```tsx
const NAMESPACES = ["auth.errors", "pages.app.sidebar", "pages.license", "timezones"] as const

export const Route = createFileRoute("/app")({
  validateSearch: appSearchSchema,
  beforeLoad: requireSignedIn,
  component: AppLayout,
  loader: ({ context }) => preloadNamespaces({ locale: getCurrentLocale(), namespaces: NAMESPACES, queryClient: context.queryClient }),
  pendingComponent: AppPending,
  staticData: { namespaces: NAMESPACES },
})
```

`AppLayout` は shadcn の `SidebarProvider` の中に、`src/presentation/components/custom/app` の `AppSidebar` と `AppHeader` を表示します。サイドバーは `src/data/navigation.ts` の `APP_NAVIGATION`（概要と設定は `core.navigation.ts`、ライセンスは `license.navigation.ts` から、ラベルは `pages.app.sidebar` から）でリンクを作り、ルートコンテキスト（`getRouteApi("/app")`）からユーザーを読み取り、最後に `SignOutButton` を置きます。ヘッダーは現在のページとサイトへ戻るリンクを表示します。サインイン後、管理者は `/admin` に、それ以外のユーザーは `/app` に移動します。

## ページ

| ルート          | 内容                                                                                                                                                                                               |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/app`          | 有効なライセンスがなければ `LicenseOffer`、あれば `LicenseStatusCard`（プラン、ステータス、ライセンスページへのリンク）。ドキュメントとメールサポートへのリンク。                                  |
| `/app/license`  | 有効なライセンスがなければ `LicenseOffer`、あれば `LicenseCard`（キー、インストールコマンド、カスタマーポータルへのリンク、プランの変更方法）と、Polar がキーを発行した後は `LicenseActivations`。 |
| `/app/settings` | `PreferencesCard`: ワークスペース内のすべての日付に使うタイムゾーン。検索と **このブラウザから検出** を備えます。[設定](/docs/features/settings)を参照してください。                               |

`LicenseOffer`（`src/presentation/components/custom/app/license-offer.tsx`）は、ランディングページの `PricingTiers` を再利用してプランごとに `CheckoutButton` を置き、購入条件（`CheckoutAgreement`）を加え、最後に `CourseUnlocks` を表示します。`CourseUnlocks` は有料レッスンのある公開済みコースを、それぞれのロックされたレッスン数とともに示します。この数は `getCatalogue` が D1 から数えます。有料レッスンのあるコースが 1 つもない間、このブロックは表示されません。返金されたライセンスはカードがそのまま残り、その横に購入案内が表示されます。

`appSearchSchema`（`src/data/app.ts`）は省略可能なパラメーターを 2 つ受け付け、どちらも無効な値は無視します。

| パラメーター | 値                  | 効果                                                                                                                                                                      |
| ------------ | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tier`       | `LICENSE_TIER` の値 | 購入案内の上に `ChosenTier` を表示します。プラン、その価格、**決済に進む** ボタンが含まれます。                                                                           |
| `checkoutId` | Polar の UUID       | ライセンスが有効になるまで購入案内の代わりに `CheckoutActivation` を表示し、有効になるとお礼を表示します。[決済とライセンス](/docs/features/payments)を参照してください。 |

概要ページとライセンスページのローダーは `currentLicenseQuery` とコースのカタログをプリロードし、`/app/license` は `licenseActivationsQuery` もプリロードします。`/app/settings` は自身のページの名前空間だけを読み込み、レイアウトの `NAMESPACES` にはタイムゾーン名のための `timezones` が含まれます。購入、Webhook、ライセンスの状態は[決済とライセンス](/docs/features/payments)で説明しています。

## スケルトン

`AppSettingsPending`（`app-pending.tsx`）は、ページのヘッダーと `PreferencesCardPending` を描画します。`AppOverviewPending` と `AppLicensePending` は、ページが表示することになる状態をそのまま再現します。`appSearchSchema` で検索パラメーターを読み取り、クエリクライアントからキャッシュ済みのライセンスとカタログを読み取って、有効化のパネル、選択されたプラン、プランのグリッド（有料レッスンのあるコースごとに 1 行付き）、ライセンスのカードのいずれかを描画します。

`/app` には請求履歴とコースの画面はありません。また、`/app/settings` にはまだプロフィール、メールアドレス、パスワードのフォームはありません。
