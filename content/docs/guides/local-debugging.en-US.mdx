## Pick an environment

| Environment      | Commands                                    | Data                                                               | Providers                       |
| ---------------- | ------------------------------------------- | ------------------------------------------------------------------ | ------------------------------- |
| Isolated preview | `db:reset:test`, `build:test`, `start:test` | Local D1, KV and R2 in `.wrangler/test`, seeded accounts           | Intercepted; no accounts needed |
| Development      | `db:reset:local`, `db:seed:local`, `dev`    | Local D1, KV and R2 in `.wrangler/state`, seeded admin and courses | Real, from `.env.development`   |

```sh
bun run db:reset:test
bun run build:test
bun run start:test
```

The isolated preview serves a build at `http://127.0.0.1:3000`; rebuild it to see source changes. Sign in with one of the seeded accounts listed in [First run](/docs/getting-started/first-run) and the password from `e2e/data/accounts.ts`. Emails are captured instead of sent: open `/__test/emails?to=<address>` to read them, including verification links.

```sh
cp .env.example .env.development
bun run db:reset:local
bun run db:seed:local
bun run dev
```

The development server runs at `http://localhost:3000` with hot reload. Its `DB`, `CACHE`, `MEDIA` and `BUNDLES` bindings are local, so nothing you do reaches the preview or production data. Sign in as the seeded admin from [The local seed](/docs/tooling/database#the-local-seed). Use `POLAR_SERVER=sandbox`.

## Read server errors

- A failing server function logs `Server function failed` with the original error in the terminal running `bun run dev`, or in Workers Logs for deployed environments. The browser only receives the error code.
- `Rate-limit storage unavailable` means D1 was unreachable during a rate-limit check; the request was rejected.
- `[license] <method> <path> failed` means that a CLI licence API request failed on the server, for example because D1 or Polar did, and the CLI got `serviceUnavailable`. The entry holds the error with its cause and its stack, and `[licence key]` in place of the caller's key.
- `No messages/<locale>/<namespace>.json` means a route declares a namespace that has no file for that locale.

## Inspect data

- Drizzle Studio: `bun run db:studio:local` for the local database; `:preview` and `:production` need the `CLOUDFLARE_*` variables in the matching environment file.
- Local test database: `bunx wrangler d1 execute DB --env test --local --persist-to .wrangler/test --command "SELECT email, role FROM user"`.

## Fix generated files

- Types for Worker bindings, class-name tables or docs content are stale: `bun run typegen`.
- Translations do not resolve: `bun run check:i18n` lists missing keys per locale and keys that do not resolve in their `useTranslations` scope.
- `bun run clean` removes build output, caches and `.wrangler`, including the local test database; run `db:reset:test` afterwards.

## Debug tests

- Run one project or only affected tests: `bun run test:unit`, `bun run test:component`, `bun run test:changed`, `bun run test:watch`.
- Playwright: `bun run test:e2e:headed` shows the browser and `bun run test:e2e:ui` opens the UI mode. Local runs keep traces of failed tests and open the HTML report on failure.
- Run the browser suite on a free port of the test build's range when another server holds `127.0.0.1:3000` or another worktree runs its suite: `PLAYWRIGHT_BASE_URL=http://127.0.0.1:3027 bun run test:e2e:pr`. [Playwright](/docs/tooling/playwright#running-beside-other-worktrees) explains how to choose the port.
