## Préversion de test isolée

La préversion de test construit l'application pour l'environnement `test` : D1 et KV locaux dans `.wrangler/test`, identifiants factices issus de `.env.test`, comptes créés par le seed et requêtes vers Resend et Polar interceptées. Elle ne nécessite aucun compte.

```sh
bun run db:migrate:test
bun run db:seed:test
bun run build:test
bun run start:test
```

Ouvrez http://127.0.0.1:3000 et connectez-vous avec l'un des comptes créés par le seed. Les deux utilisent le mot de passe `WorkerTestPassword123!` défini dans `e2e/data/accounts.ts`.

| Rôle           | E-mail                            | Espace de travail |
| -------------- | --------------------------------- | ----------------- |
| Administrateur | `admin@saasyland.example.test`    | `/admin`          |
| Client         | `customer@saasyland.example.test` | `/app`            |

La préversion sert un build : reconstruisez-la pour voir les modifications du code source.

## Développement avec Cloudflare

`bun run dev` démarre le serveur de développement avec rechargement à chaud sur http://localhost:3000. Ses bindings `DB` et `CACHE` se connectent aux ressources de préversion distantes : les écritures faites en développement vont donc dans la base de données de préversion.

```sh
bunx wrangler login
cp .env.example .env.development
bun run db:migrate:development
bun run dev
```

1. Connectez-vous à Cloudflare avec Wrangler.
2. Remplissez `.env.development` comme décrit dans [Variables d'environnement](/docs/getting-started/environment-variables), avec `POLAR_SERVER=sandbox`.
3. Avec votre propre compte Cloudflare, créez la base de données D1 et l'espace de noms KV, puis remplacez les identifiants de `development` et `preview` dans `wrangler.jsonc` ; les identifiants versionnés appartiennent au déploiement existant. Voir [Déployer une préversion](/docs/getting-started/deploy-preview).
4. Appliquez les migrations et démarrez le serveur.

L'inscription par e-mail nécessite une configuration Resend fonctionnelle, car les comptes doivent vérifier leur adresse e-mail avant de se connecter. Il n'existe pas de seed administrateur pour le développement : inscrivez-vous, vérifiez l'adresse, puis définissez le `role` de votre utilisateur sur `admin` avec `bun run db:studio:development`.
