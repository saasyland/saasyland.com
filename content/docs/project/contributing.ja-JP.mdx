---
title: "コントリビューション"
description: "SaaSy Land への変更を提案する方法です。"
---

1. 大きな変更は、まずバグ報告または機能リクエストのフォームから Issue を作成して議論してください。
2. `main` からブランチを作成します。
3. [規約](/docs/conventions)と[アーキテクチャ](/docs/architecture)に従い、ベンダーとの連携を変更する前には対応する[エージェントスキル](/docs/tooling/agent-skills)を読んでください。コーディングエージェントは、リポジトリのルートにある `AGENTS.md` から始めます。
4. テストは対象のコードのそばに置き、100% のカバレッジのゲートを維持します。
5. 以下のチェックを実行します。
6. [Conventional Commits](/docs/tooling/conventional-commits) 形式のメッセージでコミットし、規約に沿ったタイトルでプルリクエストを作成して、そのテンプレートを記入します。

```sh
bun run check
bun run test:coverage
bun run build:test
bun run test:e2e:install
bun run test:e2e:pr
```

`build:test` は、`check` とユニットテストでは検証されない Cloudflare の完全なビルドを実行します。`test:e2e:pr` は、サーバーが起動していなければテスト用 Worker をビルドして起動し、プルリクエストの CI と同じく、すべてのスペックを Chromium で実行します。WebKit で挙動が異なる可能性がある変更では、ブラウザーテストのフルスイート（`bun run test:e2e`）も実行してください。実際のプロバイダーとの連携の設定を変更した場合は、それを別途検証してください。

挙動が変わる場合は、9 つのロケールすべてで `content/docs` を更新してください。`bun run check:i18n` は、翻訳の欠落、コードブロックやナビゲーションの差異を検出して失敗します。プルリクエストのテンプレートには、概要、上記のチェックを並べたテスト計画、更新したドキュメントの一覧があります。そこに、変更後の挙動、その検証方法、残っているデモや未完成のワークフローを記載してください。

リポジトリのルートにある `CONTRIBUTING.md` はこのページの要約版で、`SUPPORT.md` にはサポートの窓口をまとめています。参加するすべての人は、Contributor Covenant 2.1 である `CODE_OF_CONDUCT.md` に従います。セキュリティの脆弱性は、公開の Issue ではなく、`SECURITY.md` に記載された方法で非公開で報告してください。
