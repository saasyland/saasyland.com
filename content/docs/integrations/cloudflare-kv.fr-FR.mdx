Chaque environnement lie un espace de noms KV sous le nom `CACHE`. Il contient deux entrées.

## Nombre d'étoiles GitHub

Le nombre d'étoiles affiché sur le site, implémenté dans `src/lib/github.ts` :

- `getStarCount` lit l'entrée `github:<owner>/<repo>:stars`.
- En l'absence d'entrée, elle récupère le dépôt via l'API GitHub avec un délai d'expiration de trois secondes, renvoie le nombre et écrit `count` et `fetchedAt` dans KV avec `waitUntil`.
- Lorsque l'entrée date de plus d'une heure, elle renvoie le nombre en cache et l'actualise en arrière-plan.
- `starCountQuery` conserve le résultat dans le cache de requêtes pendant une heure.

Les entrées n'ont pas d'expiration KV ; c'est `fetchedAt` qui décide du moment de l'actualisation. La requête GitHub s'authentifie avec les identifiants de l'application OAuth GitHub `AUTH_GITHUB_CLIENT_ID` et `AUTH_GITHUB_CLIENT_SECRET`.

## Remises régionales du paiement

`pppDiscountId` (`src/modules/license/license.ppp.ts`) lit l’entrée `polar:regional-discounts` : les remises automatiques en pourcentage de Polar, réduites aux champs utiles au paiement, avec `fetchedAt`. Une entrée de moins de cinq minutes est utilisée telle quelle. Sinon, ou si l’entrée est mal formée, les remises sont de nouveau listées depuis Polar et une liste complète est écrite avec `waitUntil`. Un listage qui échoue est journalisé et non stocké ; ce paiement continue avec les remises trouvées jusque-là et le suivant liste à nouveau. Rien n’est gardé dans la mémoire du Worker entre les requêtes.

## Cohérence et tests

KV offre une cohérence à terme. Les sessions, les limites de débit et tout ce qui sert à l'autorisation résident dans D1.

Dans Vitest, `cloudflare:workers` est résolu vers `src/platform/testing/mocks/cloudflare.ts`, qui fournit un `CACHE` en mémoire. L'environnement Wrangler `test` utilise un espace de noms local sous `.wrangler/test`.
