- API licencji CLI: Worker obsługuje CLI `saasyland`. Odczyt licencji oraz aktywacja, sprawdzenie i zwolnienie maszyny działają według kontraktu z `@saasyland/stack/api`, który importuje też CLI: `readApiRequest` odczytuje każde żądanie, a `apiResponse` i `apiErrorResponse` zapisują każdą odpowiedź. Klucz jest wyszukiwany w D1, a maszyny to aktywacje klucza w Polar, rozpoznawane po identyfikatorze maszyny, który CLI wyprowadza za pomocą HMAC, więc surowy identyfikator maszyny nigdy jej nie opuszcza. Ponowna aktywacja z tej samej maszyny korzysta z jej dotychczasowego miejsca, licencja bez wolnych miejsc odpowiada kodem `activationLimitReached` wraz z używanymi maszynami, żądania mają limity na adres IP i na klucz licencyjny, a przy awarii Polar API odpowiada kodem `serviceUnavailable` z nagłówkiem `retry-after`. Zobacz [API licencji CLI](/docs/features/cli-licence-api).
- Licencje mają trzeci status, `refunded`, który ustawia `order.refunded`. `benefit_grant.revoked` nadal ustawia `revoked`, ale nigdy nie zastępuje `refunded`, ponieważ Polar cofa też benefit zwróconego zamówienia, a oba zdarzenia mogą przyjść w dowolnej kolejności. `/app` i `/app/license` informują, że za licencję zwrócono pieniądze. D1 przechowuje status jako tekst, więc migracja nie była potrzebna.
- Jedno źródło planów i długości klucza: `LICENSE_TIER` i `LICENSE_ACTIVATION_LIMITS` są sprawdzane względem planów z kontraktu podczas kompilacji i w teście, a kolumna `license.key` bierze swoją długość z kontraktu. Dokumentacja wyświetla ścieżkę, nagłówek, limity, endpointy i kody błędów API z kontraktu podczas budowania witryny, a `<RepositoryTable>` przyjmuje dowolną liczbę kolumn.
- Naprawiono: zwolnienie maszyny, której Polar już nie przechowuje, kończyło się odpowiedzią `INTERNAL_ERROR`; `deactivateLicense` odpowiada teraz `NOT_FOUND`.
- Polityka prywatności opisuje, co CLI wysyła przy aktywacji maszyny, co Polar przechowuje wraz z aktywacją i jak działają limity żądań API licencji.
