## Regole di posizionamento

- **File e cartelle usano il kebab-case.** I test si trovano in una cartella `__test__` adiacente.
- **Le route si limitano a comporre.** Un file di route definisce il componente di pagina o di layout, `NAMESPACE` o `NAMESPACES`, il loader e `head`. Non contiene widget, dialog né definizioni di colonne.
- **I moduli sono tabelle del database.** Crea `src/modules/<name>` solo per una tabella reale. Una server function che non lavora su una tabella va in `src/lib` (ad esempio `src/lib/github.ts`) oppure, se la usa una sola route, nel file di quella route.
- **I componenti condivisi sono piatti.** Un componente usato in più aree è un singolo file direttamente in `presentation/components/custom`.
- **Cartelle di area e di pagina.** I componenti usati da una sola area si trovano in `admin/`, `app/`, `auth/`, `blog/` o `landing-page/`. Le pagine admin hanno una propria cartella, come `admin/users/` o `admin/settings/`. La landing page è suddivisa in `sections/` (un file per ogni sezione della pagina) e `components/` (le parti condivise dalle sezioni).
- **Un widget, dialog, form o set di colonne per file.** Non dividere un componente in un wrapper e in un file `-content`.
- **Nessuna cartella di helper annidata.** Le cartelle dei componenti non contengono mai sottocartelle `components/`, `constants/`, `hooks/`, `lib/` o `types/`, e nessun file helper `.ts` sta accanto a un componente. Una costante usata da un solo componente resta nel file di quel componente.
- **I dati condivisi vanno in `src/data`.** Esempi: i gruppi della sidebar admin, `MARKETING_SECTION_IDS`, la navigazione dell'app, le opzioni della CLI e le righe demo.
- **I file generati non si modificano a mano.** Il plugin del router scrive `src/routeTree.gen.ts`, `bun run cf-typegen` scrive `src/types/worker-configuration.d.ts`, mentre `bun run content` e `bun run generate:cn` scrivono `.source/`.
