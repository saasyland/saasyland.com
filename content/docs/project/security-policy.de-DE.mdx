Diese Richtlinie gilt für saasyland.com einschließlich des Kunden- und des Adminbereichs, für den Code in diesem Repository und für die kostenpflichtige CLI mit ihren Paketen `saasyland`, `create-saasyland` und `@saasyland/stack`. `SECURITY.md` im Stammverzeichnis des Repositorys sagt dasselbe.

## Eine Sicherheitslücke melden [#report]

Melde eine Sicherheitslücke nie in einem öffentlichen Issue, Pull-Request oder Kommentar, sondern vertraulich auf einem dieser beiden Wege:

- über GitHubs [private Meldung von Sicherheitslücken](https://github.com/saasyland/saasyland.com/security/advisories/new);
- per E-Mail an hello@saasyland.com.

Nenne, was betroffen ist (eine URL, Route, Serverfunktion, Datei oder ein CLI-Befehl), die Schritte zum Nachstellen oder einen Proof of Concept, die Auswirkung (was ein Angreifer lesen, ändern oder tun kann) und den Commit oder das Release, das du getestet hast. Schreib auf Englisch oder Polnisch.

Die Website veröffentlicht denselben Kontakt unter <RepositoryFact name="securityTxtPath" /> im Format von RFC 9116, mit den Sprachen <RepositoryFact name="securityTxtLanguages" /> und einem Link auf diese Seite. Der Build schreibt die Datei aus `src/lib/security-txt.ts`, und `security-txt.test.ts` schlägt fehl, sobald ihr `Expires`-Datum vorbei ist oder mehr als ein Jahr in der Zukunft liegt, sodass sie erneuert wird, bevor sie veraltet.

## Was nach deiner Meldung geschieht [#after-you-report]

Das sind Ziele, keine Garantien:

1. **Bestätigen.** Du erhältst innerhalb von <RepositoryFact name="securityAcknowledgeWorkingDays" /> Werktagen eine Antwort.
2. **Bewerten.** Innerhalb von <RepositoryFact name="securityAssessWorkingDays" /> Werktagen bestätigen oder verwerfen wir das Problem, bewerten seinen Schweregrad und planen, wenn es sich bestätigt, die Korrektur.
3. **Beheben.** Die Korrektur geht in jede unten unterstützte Version, und wir halten dich auf dem Laufenden, bis sie ausgeliefert ist.
4. **Offenlegen.** Sobald die Korrektur verfügbar ist, veröffentlichen wir ein GitHub Security Advisory, das die korrigierten Versionen nennt und dich als meldende Person aufführt, außer du möchtest nicht genannt werden.

Gib uns bitte angemessen Zeit, ein bestätigtes Problem zu beheben, bevor du es offenlegst.

## Unterstützte Versionen [#supported-versions]

| Version                                                                                                                                      | Unterstützt |
| -------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| saasyland.com und `main`                                                                                                                     | Ja          |
| Das neueste datierte Release der Website                                                                                                     | Ja          |
| Das neueste Release von `saasyland`, `create-saasyland` und `@saasyland/stack` unter dem npm-Tag <RepositoryFact name="cliReleaseChannel" /> | Ja          |
| Frühere Releases und Commits                                                                                                                 | Nein        |

Merges in `main` werden auf saasyland.com bereitgestellt, sobald die CI durchläuft, daher erreicht eine Korrektur zuerst die Website ([CI/CD](/docs/tooling/ci-cd)). Die CLI und ihre Pakete erscheinen gemeinsam unter einer Version, und eine Korrektur erscheint als neues Release auf npm, das die [Release-Notes](/docs/cli/releases) nennen. Wer ein früheres Release nutzt, aktualisiert auf das neueste, um die Korrektur zu erhalten.

## Geltungsbereich [#scope]

Im Geltungsbereich: saasyland.com einschließlich des Kunden- und des Adminbereichs, der Code in diesem Repository, die kostenpflichtige CLI, Lizenzschlüssel und Aktivierungen sowie der Code, den die CLI erzeugt.

Außerhalb: Sicherheitslücken in Diensten Dritter wie Cloudflare, Polar und Resend, sofern nicht unsere Konfiguration sie verursacht, und Scanner-Ausgaben ohne nachgewiesene Auswirkung.

## EU Cyber Resilience Act [#cyber-resilience-act]

SaaSy Land meldet aktiv ausgenutzte Schwachstellen und schwerwiegende Sicherheitsvorfälle, die seine Produkte betreffen, über die einheitliche Meldeplattform der EU (Single Reporting Platform), wie es die Cyberresilienz-Verordnung (Verordnung (EU) 2024/2847) verlangt.
