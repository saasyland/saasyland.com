---
title: "Modul hinzufügen"
description: "Eine Datenbanktabelle mit Drizzle-Schema, Zod-Schemas, Konstanten, Typen und Use Cases hinzufügen."
---

Ein Modul entspricht genau einer Datenbanktabelle. `src/modules/<table>/` existiert nur für echte Tabellen; Server-Funktionen, die keine eigene Tabelle besitzen, liegen in `src/lib` oder in der Route, die sie verwendet. `src/modules/category` ist das kleinste vollständige Beispiel.

## Dateien

| Datei                      | Inhalt                                                                                                                                           |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `<table>.schema.ts`        | Drizzle-Tabelle, Indizes, Relationen und die aus den Konstanten gebildeten Enum-Tupel                                                            |
| `<table>.zod.ts`           | Ein Eingabeschema pro Operation sowie `drizzle-zod`-Schemas, exportiert als `<table>ZodSchemas`                                                  |
| `<table>.constants.ts`     | Benannte Domänenwerte wie `CATEGORY_KIND`, Spaltengrenzen und die Tupel der Query- und Mutation-Keys                                             |
| `<table>.types.ts`         | Ein Interface mit den Zeilentypen und dem Eingabetyp jeder Operation                                                                             |
| `<table>.utils.ts`         | Optionale Hilfsfunktionen; `license.utils.ts` liest die Worker-Umgebung und ist deshalb server-only                                              |
| `<table>.<concern>.ts`     | Optionaler Code, der keine einzelne Operation ist, etwa `license.webhooks.ts` oder `video.playback.ts` ([Modulkatalog](/docs/reference/modules)) |
| `use-cases/<operation>.ts` | Eine Server-Funktion pro Datei mit ihren Query- oder Mutation-Optionen                                                                           |
| `__test__/`                | Tests, benannt nach der Quelldatei, etwa `category.schema.test.ts` und `category.zod.test.ts`                                                    |

## 1. Tabelle definieren

Benennen Sie die Werte der Tabelle einmal in `category.constants.ts`. Schema, Zod-Schemas, Use Cases, Komponenten, Tests und E2E-Daten importieren sie von dort, statt einen String wie `"collection"` zu wiederholen:

```ts
export const CATEGORY_NAME_MAX_LENGTH = 255

export const CATEGORY_KIND = {
  CATEGORY: "category",
  COLLECTION: "collection",
} as const
```

Bauen Sie die Tabelle aus diesen Namen auf:

```ts
import { index, sqliteTable, text } from "drizzle-orm/sqlite-core"

import { timestamps } from "~/src/integrations/drizzle-orm/drizzle.columns"

import { CATEGORY_KIND, CATEGORY_NAME_MAX_LENGTH } from "~/src/modules/category/category.constants"

export const CATEGORY_KINDS = [CATEGORY_KIND.CATEGORY, CATEGORY_KIND.COLLECTION] as const

export const category = sqliteTable(
  "category",
  {
    id: text("id").primaryKey(),
    kind: text("kind", { enum: CATEGORY_KINDS }).notNull().default(CATEGORY_KIND.CATEGORY),
    name: text("name", { length: CATEGORY_NAME_MAX_LENGTH }).notNull(),
    ...timestamps(),
  },
  (table) => [index("category_createdAt_idx").on(table.createdAt)],
)
```

- Spaltennamen sind snake_case, Eigenschaften camelCase.
- IDs sind `text`-Primärschlüssel, die im Insert-Use-Case mit `v7()` aus `uuid` befüllt werden.
- `...timestamps()` aus `src/integrations/drizzle-orm/drizzle.columns.ts` fügt `createdAt` und `updatedAt` hinzu: Millisekunden-Zeitstempel mit dem Einfügezeitpunkt als Standardwert; `updatedAt` wird bei jedem Update neu gesetzt. Andere Datumswerte sind `integer(..., { mode: "timestamp_ms" })`, boolesche Werte `integer(..., { mode: "boolean" })`.
- Eine Enum-Spalte erhält das aus dem Konstantenobjekt gebildete Tupel, und ihr Standardwert ist eine Konstante wie `CATEGORY_KIND.CATEGORY`, nie ein String-Literal.
- Fremdschlüssel verwenden `.references(() => user.id, { onDelete: "cascade" })`, und `relations(...)` deklariert Joins (siehe `session.schema.ts`).

## 2. Schema registrieren

Die Tabelle und, falls vorhanden, ihre Relationen aus `src/integrations/drizzle-orm/drizzle.schemas.ts` exportieren:

```ts
export { category } from "~/src/modules/category/category.schema"
```

Diese Datei speist den D1-Client (`drizzle(env.DB, { schema })`), den Drizzle-Adapter von Better Auth und drizzle-kit. Eine Tabelle, die hier fehlt, erhält keine Migration.

## 3. Migration generieren

```sh
bun run db:generate
bun run db:migrate:local
```

Das generierte SQL in `src/integrations/drizzle-orm/migrations/` prüfen und zusammen mit dem Schema committen. [Datenbankmigrationen](/docs/guides/database-migrations) behandelt die Remote-Umgebungen.

## 4. Zod-Schemas hinzufügen

Jede Operation erhält ein eigenes Eingabeschema. Validierungsmeldungen sind Übersetzungsschlüssel; ein Formular zeigt sie mit `ValidationFieldError` in dem Namespace an, den es angibt.

```ts
import { createSchemaFactory } from "drizzle-zod"
import zod from "zod/v4"

import { MIN_FIELD_LENGTH, idField } from "~/src/modules/_core/utils/zod-fields"
import { CATEGORY_NAME_MAX_LENGTH } from "~/src/modules/category/category.constants"
import { CATEGORY_KINDS, category } from "~/src/modules/category/category.schema"

const { createInsertSchema, createSelectSchema, createUpdateSchema } = createSchemaFactory({ zodInstance: zod })

const createCategory = zod.object({
  kind: zod.enum(CATEGORY_KINDS),
  name: zod.string().min(MIN_FIELD_LENGTH, { message: "nameRequired" }).max(CATEGORY_NAME_MAX_LENGTH, { message: "nameMaxLength" }),
})

const deleteCategory = zod.object({ categoryId: idField })

export const categoryZodSchemas = {
  createCategory,
  deleteCategory,
  insert: createInsertSchema(category),
  select: createSelectSchema(category),
  update: createUpdateSchema(category),
}
```

`messages/<locale>/<table>.validations.json` für jede Locale mit jedem Schlüssel anlegen, den die Schemas verwenden. Ein Formular zeigt diese Schlüssel nur an, wenn seine Route den Namespace vorlädt und ihn an `ValidationFieldError` übergibt; die Kursformulare im Admin verwenden `course.validations`, die übrigen Formulare `auth.validations`.

## 5. Konstanten und Typen hinzufügen

```ts
export const CATEGORY_QUERY_KEYS = {
  ALL: ["category"],
  LIST: ["category", "getCategories"],
} as const

export const CATEGORY_MUTATION_KEYS = {
  CREATE: ["category", "createCategory"],
  DELETE: ["category", "deleteCategory"],
  UPDATE: ["category", "updateCategory"],
} as const
```

```ts
import type * as zod from "zod"

import type { category } from "~/src/modules/category/category.schema"
import type { categoryZodSchemas } from "~/src/modules/category/category.zod"

export interface Category {
  select: typeof category.$inferSelect
  insert: typeof category.$inferInsert
  createCategory: zod.input<typeof categoryZodSchemas.createCategory>
  deleteCategory: zod.input<typeof categoryZodSchemas.deleteCategory>
}
```

Jeder Key beginnt mit dem Modulnamen, sodass das Invalidieren von `ALL` jede Query des Moduls aktualisiert.

`Category` hat einen Schlüssel pro Operationsschema; das vollständige Modul `category` hat außerdem `getCategories`, `getCategory` und `updateCategory`. Eine Serverfunktion typisiert die Eingabe ihres Validators als `Category["createCategory"]`, und ihre Mutation- oder Query-Optionen verwenden denselben Typ. Fügen Sie den Schlüssel hinzu, sobald Sie ein Schema hinzufügen.

## 6. Berechtigungen und Use Cases hinzufügen

- Die Aktionen der Tabelle zu `APP_STATEMENTS` in `src/integrations/better-auth/auth.access.ts` hinzufügen, wenn die Operationen Berechtigungen benötigen. Siehe [Rollen und Berechtigungen](/docs/guides/roles-and-permissions).
- Eine Datei pro Operation unter `use-cases/` anlegen. Siehe [Use Case hinzufügen](/docs/guides/add-a-use-case).

## 7. Testen

`__test__/<table>.schema.test.ts`, `<table>.zod.test.ts` und `<table>.types.test.ts` neben dem Modul sowie `use-cases/__test__/<operation>.test.ts` für jede Operation anlegen. Das Coverage-Gate liegt bei <RepositoryFact name="coverageThreshold" unit="percent" />; siehe [Tests schreiben](/docs/guides/writing-tests).
