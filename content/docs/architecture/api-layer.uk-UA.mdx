Власні операції застосунку — це серверні функції. HTTP-обробники існують лише там, де URL викликає щось поза RPC-клієнтом застосунку: браузерний клієнт Better Auth, OAuth-провайдери, вебхуки Polar і поле пошуку документації.

| Файл                       | Шлях          | Методи    | Що обробляє                                                                                                                              |
| -------------------------- | ------------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `src/routes/api/index.ts`  | `/api`        | GET       | JSON-відповідь зі статусом `{ runtime: "cloudflare-workers" }`                                                                           |
| `src/routes/api/auth.$.ts` | `/api/auth/*` | GET, POST | Усі ендпоінти Better Auth, зокрема OAuth-колбеки, підтвердження електронної пошти, клієнтський портал Polar і `/api/auth/polar/webhooks` |
| `src/routes/api/search.ts` | `/api/search` | GET       | Пошук Fumadocs по документації                                                                                                           |

Обробник оголошується через `server.handlers` у `createFileRoute`. Він отримує Web `Request` і повертає `Response`:

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Правила

- Не додавайте REST-ендпоінт для операції, яку викликає лише цей застосунок. Натомість напишіть сценарій використання з `createServerFn`: він отримує типізовані вхідні дані, middleware та опції запиту.
- Обробник сам валідує вхідні дані й перевіряє дозволи. Middleware серверних функцій (`authorized`, `withRateLimit`) для обробників не виконуються.
- Перевірку, специфічну для вендора, тримайте в інтеграції. Підписи вебхуків Polar перевіряє плагін Polar усередині Better Auth, а не власний обробник.
- Шляхи `/api` ніколи не локалізуються, ніколи не проходять пререндеринг і оминають обробку локалі у Worker.
