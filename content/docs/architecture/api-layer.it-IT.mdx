---
title: "Handler HTTP di TanStack Start"
description: "Gli endpoint HTTP sotto /api e quando aggiungerne uno al posto di una server function."
---

Le operazioni proprie dell'applicazione sono server function. Gli handler HTTP esistono solo dove qualcosa al di fuori del client RPC dell'applicazione chiama un URL: il client browser di Better Auth, i provider OAuth, i webhook di Polar e la casella di ricerca della documentazione.

| File                       | Percorso      | Metodi    | Gestisce                                                                                                                                       |
| -------------------------- | ------------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/routes/api/index.ts`  | `/api`        | GET       | Una risposta JSON di stato `{ runtime: "cloudflare-workers" }`                                                                                 |
| `src/routes/api/auth.$.ts` | `/api/auth/*` | GET, POST | Tutti gli endpoint di Better Auth, compresi i callback OAuth, la verifica dell'email, il portale clienti di Polar e `/api/auth/polar/webhooks` |
| `src/routes/api/search.ts` | `/api/search` | GET       | La ricerca Fumadocs nella documentazione                                                                                                       |

Un handler si dichiara con `server.handlers` in `createFileRoute`. Riceve la `Request` Web e restituisce una `Response`:

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Regole

- Non aggiungere un endpoint REST per un'operazione che chiama solo questa applicazione. Scrivi invece un caso d'uso con `createServerFn`, che dispone di input tipizzato, middleware e opzioni di query.
- Un handler valida da sé il proprio input e controlla da sé i permessi. Il middleware delle server function (`authorized`, `withRateLimit`) non viene eseguito per gli handler.
- Mantieni nell'integrazione la verifica specifica del fornitore. Le firme dei webhook di Polar vengono verificate dal plugin Polar all'interno di Better Auth, non da un handler personalizzato.
- I percorsi `/api` non vengono mai localizzati né prerenderizzati e saltano la gestione del locale nel Worker.
