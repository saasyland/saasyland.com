---
title: "Aggiungere una funzionalità"
description: "Percorso completo dalla tabella del database a una pagina testata, con i collegamenti alle guide di dettaglio."
---

Una funzionalità di solito tocca ogni livello: un modulo di tabella, i suoi casi d'uso, una route, i componenti di presentazione, i messaggi e i test. Le categorie di prodotto mostrano il percorso completo: `src/modules/category`, la scheda delle categorie in `src/routes/admin.products.index.tsx` e `src/presentation/components/custom/admin/products/category-columns.tsx`.

## 1. Modella i dati

Se la funzionalità salva nuovi dati, aggiungi un modulo per la sua tabella e genera la migrazione.

- [Aggiungere un modulo](/docs/guides/add-a-module)
- [Migrazioni del database](/docs/guides/database-migrations)

## 2. Stabilisci chi può fare cosa

Aggiungi le nuove azioni a `APP_STATEMENTS` in `src/integrations/better-auth/auth.access.ts` e assegnale ai ruoli.

- [Ruoli e permessi](/docs/guides/roles-and-permissions)

## 3. Scrivi le operazioni

Aggiungi un caso d'uso per ogni operazione, con middleware, validatore, handler e opzioni di query o mutation.

- [Aggiungere un caso d'uso](/docs/guides/add-a-use-case)
- [Funzioni server](/docs/guides/server-functions)

## 4. Aggiungi la route

1. Aggiungi il percorso a `ROUTES` in `src/routes.ts`.
2. Crea un file di route piatto per l'area: `src/routes/admin.<feature>.tsx` sotto il layout di amministrazione, `src/routes/app.<feature>.tsx` sotto il layout del cliente autenticato oppure `src/routes/_landing.<page>.tsx` per una pagina pubblica.
3. Segui la convenzione delle route: `const NAMESPACE`, `staticData: { namespaces: [NAMESPACE] }`, `head: pageHead(ROUTES.X)`, un loader che carica metadati, messaggi e dati in un unico `Promise.all` e lo scheletro proprio della pagina come `pendingComponent`, registrato nella mappa dello scheletro del suo layout (vedi [Scheletri di caricamento](/docs/architecture/delivery-layer#scheletri-di-caricamento)).
4. La guardia `beforeLoad` del layout (`requireAdmin` per `/admin`, `requireSignedIn` per `/app`) protegge la pagina. Le funzioni server autorizzano comunque ogni chiamata da sole.

- [Aggiungere una pagina di amministrazione](/docs/guides/add-an-admin-page)
- [Stato nell'URL](/docs/guides/url-state)

## 5. Costruisci l'interfaccia

Metti widget, finestre di dialogo, moduli e colonne di tabella in `src/presentation/components/custom/<area>/<feature>/`, uno per file. Ogni componente legge da sé traduzioni e dati; la route si limita a comporli.

- [Aggiungere una tabella dati](/docs/guides/add-a-data-table)
- [Moduli e validazione](/docs/guides/forms-and-validation)

## 6. Aggiungi i messaggi

Crea il namespace della pagina, ed eventualmente un namespace di validazione, in tutte e nove le lingue. I namespace di pagina richiedono `metadata.title` e `metadata.description`.

- [Internazionalizzazione e lingue](/docs/guides/i18n-messages)
- [Modelli di email](/docs/guides/email-templates), se la funzionalità invia email

## 7. Testa e verifica

Copri con i test i casi d'uso, i componenti e la route, poi esegui tutti i controlli:

```sh
bun run check
bun run test:coverage
bun run build
bun run test:e2e:smoke
```

- [Scrivere i test](/docs/guides/writing-tests)
- [Checklist di sicurezza](/docs/guides/security-checklist)
