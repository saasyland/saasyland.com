## Modules

A module under `src/modules/<table>` exists only for a real database table. It contains:

- `<table>.schema.ts`: the Drizzle table, re-exported by `src/integrations/drizzle-orm/drizzle.schemas.ts`
- `<table>.zod.ts`: input schemas, used by both forms and server functions
- `<table>.constants.ts`: query and mutation keys, enums
- `<table>.types.ts` and `<table>.utils.ts`: when the table needs them
- `use-cases/<operation>.ts`: one operation per file

Current modules: account, category, license, newsletter-subscriber, product, rate-limit, session, two-factor, user and verification. Shared constants and helpers live in [`_core`](/docs/architecture/core). A server function that does not work on a table belongs in `src/lib` or in the one route that uses it.

## Use cases

Most use cases are server functions called from the browser. Each file exports the `createServerFn` and its query or mutation options:

```ts
import { mutationOptions } from "@tanstack/react-query"
import { createServerFn } from "@tanstack/react-start"
import { v7 } from "uuid"
import type * as zod from "zod"

import { authorized } from "~/src/integrations/better-auth/auth.middleware"
import { db } from "~/src/integrations/drizzle-orm/drizzle.database"

import { CATEGORY_MUTATION_KEYS } from "~/src/modules/category/category.constants"
import { category } from "~/src/modules/category/category.schema"
import { categoryZodSchemas } from "~/src/modules/category/category.zod"

export const createCategory = createServerFn({ method: "POST" })
  .middleware([authorized({ category: ["create"] })])
  .validator((input: zod.input<typeof categoryZodSchemas.createCategory>) => categoryZodSchemas.createCategory.parse(input))
  .handler(({ data }) =>
    db
      .insert(category)
      .values({
        description: data.description ?? "",
        icon: data.icon ?? "FolderOpen",
        id: v7(),
        kind: data.kind,
        name: data.name,
        visibility: data.visibility ?? "public",
      })
      .returning()
      .get(),
  )

export const createCategoryMutation = mutationOptions({
  mutationFn: (data: Parameters<typeof createCategory>[0]["data"]) => createCategory({ data }),
  mutationKey: CATEGORY_MUTATION_KEYS.CREATE,
})
```

- **Middleware** comes from `src/integrations/better-auth/auth.middleware.ts`. `authorized()` requires a session, `authorized({ category: ["create"] })` also checks a permission, and `withRateLimit(kind, RATE_LIMITS.SENSITIVE)` limits public operations.
- **Validation** parses the input with the module's Zod schema before the handler runs.
- **Ownership** comes from the session. Operations on the caller's own data filter by `context.auth.user.id` and never trust a user ID from the input.
- **Errors** are thrown as `new AppError(ERROR_CODES.X)`. Any other error is logged and reaches the client as `INTERNAL_ERROR`.
- **Reads** export `queryOptions` instead, for example `getCategoriesPageQuery(input)`, which resolves `{ rows, total }` for the data table.

Some use cases are plain async functions that run only on the server and have no RPC endpoint, such as `send-verify-email.ts` or `grant-license.ts`. Better Auth hooks and Polar webhook handlers call them.

## Calling a use case from a component

Components spread the exported options into `useMutation`, translate errors with `useErrorMessage()` and invalidate the module's query keys on success:

```tsx
const t = useTranslations("pages.admin.users.actions")
const queryClient = useQueryClient()
const errorMessage = useErrorMessage()

const deleteUser = useMutation({
  ...deleteUserMutation,
  onError: (error) => {
    toast.error(errorMessage(error))
  },
  onSuccess: async () => {
    await queryClient.invalidateQueries({ queryKey: USER_QUERY_KEYS.ALL })
    toast.success(t("feedback.deleteSuccess"))
  },
})
```
