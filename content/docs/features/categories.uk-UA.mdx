## Дані

`src/modules/category/category.schema.ts` визначає таблицю `category`: `name`, `description`, `kind` (`category` або `collection`), `visibility` (`public` або `hidden`), `icon` (`Archive`, `FolderOpen` або `Puzzle`) і позначки часу.

Сценарії використання в `src/modules/category/use-cases`, кожен захищений відповідним дозволом `category`: `getCategories` (посторінковий, необов’язковий `kind`), `getCategory`, `createCategory`, `updateCategory` і `deleteCategory`. `createCategory` — еталонна структура сценарію зі зміною даних:

```ts
export const createCategory = createServerFn({ method: "POST" })
  .middleware([authorized({ category: ["create"] })])
  .validator((input: Category["createCategory"]) => categoryZodSchemas.createCategory.parse(input))
  .handler(({ data }) =>
    db
      .insert(category)
      .values({
        description: data.description ?? "",
        icon: data.icon ?? CATEGORY_ICON.FOLDER_OPEN,
        id: v7(),
        kind: data.kind,
        name: data.name,
        visibility: data.visibility ?? CATEGORY_VISIBILITY.PUBLIC,
      })
      .returning()
      .get(),
  )

export const createCategoryMutation = mutationOptions({
  mutationFn: (data: Category["createCategory"]) => createCategory({ data }),
  mutationKey: CATEGORY_MUTATION_KEYS.CREATE,
})
```

Повідомлення про помилки розташовані в просторі імен `category.errors`. Жодна форма ще не редагує категорії, тож їхні повідомлення Zod отримають простір імен `category.validations` разом із першою формою, яка їх показуватиме.

## Екран адмінпанелі

Жоден екран не показує, не створює, не редагує й не видаляє категорій, а продукти не мають зв'язку з категоріями. `/admin/products` показує каталог із Polar (див. [Продукти](/docs/features/products)).
