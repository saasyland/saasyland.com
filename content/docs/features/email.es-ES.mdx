## Plantillas

Las plantillas están en `src/presentation/emails`. Cada archivo contiene solo marcado y exporta su constante de espacio de nombres:

| Plantilla                      | Espacio de nombres                       | La envía                                                 |
| ------------------------------ | ---------------------------------------- | -------------------------------------------------------- |
| `VerifyEmail`                  | `emails.verify-email`                    | `sendVerifyEmail` (hook de Better Auth)                  |
| `ResetPasswordEmail`           | `emails.reset-password-email`            | `sendResetPasswordEmail` (hook de Better Auth)           |
| `ChangeEmailConfirmationEmail` | `emails.change-email-confirmation-email` | `sendChangeEmailConfirmationEmail` (hook de Better Auth) |
| `NewsletterConfirmationEmail`  | `emails.newsletter-confirmation-email`   | `subscribeToNewsletter`                                  |
| `NewsletterNotificationEmail`  | `emails.newsletter-notification-email`   | `confirmNewsletterSubscription`, a `CONTACT_EMAIL`       |

Una plantilla recibe `locale` y `messages` y traduce con `createTranslator` de use-intl:

```tsx
const t = createTranslator({ locale, messages: { emails: { "verify-email": messages } }, namespace: "emails.verify-email" })
```

## Envío

El caso de uso toma el idioma y el `redirect` de la URL de callback que le pasa Better Auth, comprueba el límite por destinatario, carga los mensajes, renderiza la plantilla y la envía (`src/modules/verification/use-cases/send-verify-email.ts`):

```ts
if (!(await withinRecipientRateLimit({ kind: "verify-email", recipient: user.email }))) {
  console.warn("[email] verification email not sent: the recipient reached the hourly limit")
  return
}
const callback = new URL(callbackURL, getRequest().url)
const locale = extractLocaleFromPath(callback.pathname) ?? I18N.DEFAULT_LOCALE
const verifyUrl = new URL(localizePathname({ locale, pathname: ROUTES.VERIFY_EMAIL }), getRequest().url)
verifyUrl.search = callback.search
verifyUrl.searchParams.set("token", token)

const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotency: { purpose: "verify-email", token },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```

`sendEmail` (`src/integrations/resend/resend.utils.ts`) envía a través de Resend desde `RESEND_EMAIL_FROM`, salvo que se indique un `from` (la notificación al propietario usa `NOTIFICATIONS_EMAIL`), pasa la clave de idempotencia y lanza un error si el envío falla.

Los correos de cuenta usan el idioma de la página donde empezó el flujo, que se lee del `callbackURL` del enlace del correo; en un registro repetido sale del `callbackURL` de la petición de registro. Los correos del boletín usan el idioma enviado con el formulario; la notificación al propietario siempre está en `en-US`.

`withinRecipientRateLimit` (`src/lib/rate-limit.ts`) permite como máximo tres correos de verificación, tres de restablecimiento de contraseña y tres de confirmación del boletín por dirección y hora, contados en la tabla `rate_limit` con un hash SHA-256 de la dirección. Por encima del límite el correo se omite y la petición sigue recibiendo su respuesta normal. La confirmación del cambio de correo y la notificación al propietario no tienen límite.
