---
title: "Aggiungere una griglia dati"
description: "Scrivi un hook delle colonne con filtri, colonne nascoste e fissate e valori CSV, poi mostralo con DataGrid a partire da righe lato client o da una query sul server."
---

Ogni nuova tabella viene resa da `DataGrid` in `src/presentation/components/custom/data-grid.tsx` ([Griglia dati](/docs/ui/data-grid)). Porta con sé la ricerca, i filtri, l'ordinamento, il layout che ogni amministratore può riorganizzare e conservare, la selezione, l'esportazione CSV, le righe scheletro e gli stati vuoti. Una tabella ha bisogno di un hook delle colonne e di un `<DataGrid />`. `/admin/orders` è l'esempio completo: `src/presentation/components/custom/admin/payments/order-columns.tsx` e `src/routes/admin.orders.index.tsx`.

## 1. Scrivi l'hook delle colonne

Crea `<entity>-columns.tsx` accanto agli altri widget della pagina. Esporta un hook che legge le traduzioni e i dati che offrono i filtri, e restituisce le colonne memoizzate. Le celle sono piccoli componenti nello stesso file che leggono da sé le proprie traduzioni. Versione ridotta di `order-columns.tsx`:

```tsx
const columnHelper = createColumnHelper<DataGridFeatures, OrderRow>()

export const useOrderColumns = (): DataGridColumn<OrderRow>[] => {
  const t = useTranslations()

  const { products } = useSuspenseQuery(orderFiltersQuery).data

  return useMemo(
    () =>
      columnHelper.columns([
        columnHelper.accessor("placedAt", {
          cell: PlacedCell,
          header: t("pages.admin.orders.table.headers.placedAt"),
          meta: { filter: { kind: DATA_GRID_FILTER.DATE_RANGE }, pinned: DATA_GRID_PIN.START },
          size: ORDER_COLUMN_SIZES.placedAt,
        }),
        columnHelper.accessor("description", {
          cell: ProductCell,
          enableSorting: false,
          header: t("pages.admin.orders.table.headers.product"),
          id: "product",
          meta: { filter: { kind: DATA_GRID_FILTER.MULTI_SELECT, options: products.map(({ id, name }) => ({ label: name, value: id })) } },
          size: ORDER_COLUMN_SIZES.product,
        }),
        columnHelper.accessor("refunded", {
          cell: RefundedCell,
          header: t("pages.admin.orders.table.headers.refundedAmount"),
          id: "refundedAmount",
          meta: { export: ({ refunded }) => exportedMoney(refunded), hidden: true },
          size: ORDER_COLUMN_SIZES.refundedAmount,
        }),
      ]),
    [products, t],
  )
}
```

- Le righe devono avere un `id` di tipo stringa, che diventa l'identificatore della riga per la selezione.
- `header` è l'etichetta tradotta come stringa. La griglia la usa nell'intestazione, nei menu, nei chip dei filtri, nei suoi annunci e nel CSV.
- `meta.filter` dà alla colonna un filtro di un tipo: <RepositoryFact name="dataGridFilterKinds" />. Una scelta elenca le sue `options` come `{ label, value }`.
- `meta.hidden` nasconde la colonna finché l'amministratore non la mostra, `meta.pinned` la fissa a `start` o a `end`, e `meta.export` scrive il testo CSV della colonna per una riga.
- `size` è la larghezza iniziale in pixel. Tieni le dimensioni in una costante in `src/data/<area>.ts`, come `ORDER_COLUMN_SIZES` in `payments.ts`, così anche lo scheletro della route può usarle.
- Una colonna per cui il server non può ordinare imposta `enableSorting: false`.

## 2. Mostrala

Passa le colonne, un `id` univoco, il `label` della tabella e `data` oppure `query`:

```tsx
const OrdersPage = (): JSX.Element => {
  const t = useTranslations("pages.admin.orders")
  const columns = useOrderColumns()

  return (
    <DataGrid
      columns={columns}
      empty={t("empty")}
      id={ORDER_GRID_ID}
      label={t("title")}
      query={(request) => getOrdersPageQuery(orderZodSchemas.getOrders.parse(request))}
      search={t("filters.search")}
      selectable
    />
  )
}
```

Con `data`, la griglia cerca, filtra, ordina e pagina le righe nel browser. Con `query`, invia `{ filters, pageIndex, pageSize, search, sorting }` e il server fa tutto.

## 3. Leggi la richiesta sul server

Lo schema Zod del modulo prende la richiesta così com'è. `filters` contiene le colonne filtrate per id con i valori descritti in [Griglia dati](/docs/ui/data-grid#filters), quindi lo schema riusa i campi condivisi, da `src/modules/order/order.zod.ts`:

```ts
const orderFilters = zod.object({
  country: zod.array(countryCodeField).max(COUNTRY_CODES.length).optional(),
  customer: searchField.optional(),
  discount: idField.optional(),
  placedAt: dateRangeField.optional(),
  product: zod.array(idField).max(MAX_FILTER_VALUES).optional(),
  status: zod.array(choiceOf(ORDER_STATUSES)).max(ORDER_STATUSES.length).optional(),
  totalAmount: numberRangeField.optional(),
})

const getOrders = paginationSchema.extend({
  filters: orderFilters.default({}),
  search: searchField.default(""),
  sorting: sortingOf(ORDER_SORT_COLUMNS),
})
```

`numberRangeField`, `dateRangeField` e i limiti `SEARCH_MAX_LENGTH`, `MAX_SORTED_COLUMNS` e `MAX_FILTER_VALUES` vengono da `src/modules/_core/utils/`, gli stessi valori che usa la griglia, così la casella di ricerca accetta <RepositoryFact name="dataGridSearchMaxLength" /> caratteri e la griglia ordina per al massimo <RepositoryFact name="dataGridMaxSortedColumns" /> colonne. `getOrders` trasforma ogni filtro in SQL; un intervallo di importi confronta ogni ordine nella sua valuta con `inMinorUnits`.

Precarica la prima pagina nel loader della route con `context.queryClient.query({ ...getOrdersQuery, staleTime: "static" })`; la prima richiesta della griglia si traduce nella stessa chiave di query.

## 4. Riproducila nello scheletro

Il `pendingComponent` della route mostra `DataGridPending` da `data-grid-pending.tsx` con uno scheletro di cella e una larghezza per ogni colonna visibile, come fa `AdminOrdersPending` in `payments-pending.tsx`.

## 5. Messaggi

Barra degli strumenti, filtri, menu, paginazione, selezione e stati vuoti della griglia provengono da `components.custom.data-grid`, caricato da ogni pagina. Etichette delle colonne, opzioni dei filtri e messaggio vuoto appartengono al namespace della pagina, come `pages.admin.orders`.

Quando una mutation modifica le righe, invalida le chiavi di query del modulo; la griglia ricarica la pagina corrente. Vedi [Aggiungere un caso d'uso](/docs/guides/add-a-use-case).
