Each third-party library or service that needs setup owns one folder under `src/integrations`. Files are named `<prefix>.<concern>.ts`, where the prefix is the vendor's short name.

| Folder           | Files                                                                                                                                                                                      | Responsibility                                                                                                                             |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `affonso`        | `affonso.constants`, `affonso.program`, `affonso.referral`                                                                                                                                 | Referral parameters, the pixel URL, the program ID and the referral passed to Polar as checkout metadata                                   |
| `better-auth`    | `auth.server`, `auth.client`, `auth.access`, `auth.roles`, `auth.middleware`, `auth.routes`, `auth.session`, `auth.errors`, `auth.hooks`, `auth.zod`, `auth.constraints`, `auth.constants` | Auth configuration, roles, server function middleware, route guards, session query, provider IDs                                           |
| `drizzle-orm`    | `drizzle.config`, `drizzle.database`, `drizzle.schemas`, `drizzle.errors`, `drizzle.columns`, `migrations/`                                                                                | The D1 client, the schema registry, SQL migrations, `rethrowAsConflict` for unique-constraint errors and the shared `timestamps()` columns |
| `fumadocs`       | `fumadocs.config`, `fumadocs.schema`, `fumadocs.indexes`, `fumadocs.docs`, `fumadocs.blog`, `fumadocs.i18n`                                                                                | MDX collections for docs and blog, the build-time docs, blog and search indexes, and page loading                                          |
| `motion`         | `motion.features`, `motion.tokens`                                                                                                                                                         | The lazily loaded Motion feature bundle and shared transitions                                                                             |
| `polar`          | `polar.config`, `polar.constants`, `polar.discounts`, `polar.customers`                                                                                                                    | The Polar SDK client, Polar's own values checked against the SDK, the regional discount rule and the account of a Polar customer           |
| `resend`         | `resend.config`, `resend.utils`, `resend.constants`                                                                                                                                        | The Resend client, `sendEmail` and the `EMAIL_PURPOSE` names                                                                               |
| `tanstack-form`  | `form.fields`                                                                                                                                                                              | Field types and `fieldErrorMessage` for TanStack Form                                                                                      |
| `tanstack-query` | `query.cache`                                                                                                                                                                              | The default cache times of the `QueryClient` that `src/router.tsx` creates for every request                                               |

## What is not an integration

- The GitHub star count is a server function in `src/lib/github.ts`, cached in KV.
- Rate limiting is `src/lib/rate-limit.ts`, backed by the `rate_limit` table.
- Cloudflare bindings need no adapter. Server code reads them from `env` in `cloudflare:workers`.

## Business logic stays in modules

An integration configures a vendor. Decisions about application data belong to the module that owns the table:

- The Polar plugin, which the polar area adds to Better Auth in `src/data/polar.auth-plugins.ts`, verifies webhook signatures with `POLAR_WEBHOOK_SECRET` and hands each event to `handlePolarEvent` in `src/data/polar-events.ts`. That passes it to every area that lists the event in its `<area>.polar-events.ts`; the licence area's `src/data/license.polar-events.ts` calls `licenseWebhookHandlers` in `src/modules/license/license.webhooks.ts`, which call the licence use cases. The product IDs of the licence tiers, `POLAR_PRODUCT_IDS`, belong to the licence area too, in `src/modules/license/license.utils.ts`.
- Better Auth email hooks call `sendVerifyEmail`, `sendResetPasswordEmail` and `sendChangeEmailConfirmationEmail` from the verification and account modules, which Resend adds in `src/data/resend.auth-emails.ts`.
- A use case sends email in the locale its caller passes in (the verification email reads it from the callback URL): it loads the template's namespace, renders the template and calls `sendEmail`:

```ts
const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotency: { purpose: EMAIL_PURPOSE.VERIFY_EMAIL, token },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```
