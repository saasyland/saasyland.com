Jede Drittanbieter-Bibliothek und jeder Dienst, der eingerichtet werden muss, besitzt einen eigenen Ordner unter `src/integrations`. Die Dateien heißen `<prefix>.<concern>.ts`, wobei das Präfix der Kurzname des Anbieters ist.

| Ordner           | Dateien                                                                                                                                                                                    | Zuständigkeit                                                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `affonso`        | `affonso.constants`, `affonso.program`, `affonso.referral`                                                                                                                                 | Empfehlungsparameter, die Pixel-URL, die Programm-ID und die Empfehlung, die als Checkout-Metadaten an Polar geht                                    |
| `better-auth`    | `auth.server`, `auth.client`, `auth.access`, `auth.roles`, `auth.middleware`, `auth.routes`, `auth.session`, `auth.errors`, `auth.hooks`, `auth.zod`, `auth.constraints`, `auth.constants` | Auth-Konfiguration, Rollen, Middleware für Server Functions, Route-Guards, Session-Query, Provider-IDs                                               |
| `drizzle-orm`    | `drizzle.config`, `drizzle.database`, `drizzle.schemas`, `drizzle.errors`, `drizzle.columns`, `migrations/`                                                                                | Der D1-Client, die Schema-Registry, die SQL-Migrationen, `rethrowAsConflict` für Unique-Constraint-Fehler und die gemeinsamen `timestamps()`-Spalten |
| `fumadocs`       | `fumadocs.config`, `fumadocs.schema`, `fumadocs.indexes`, `fumadocs.docs`, `fumadocs.blog`, `fumadocs.i18n`                                                                                | MDX-Collections für Doku und Blog, die beim Build erzeugten Doku-, Blog- und Suchindizes und das Laden der Seiten                                    |

| `resend`         | `resend.config`, `resend.utils`, `resend.constants`                                                                                                                                        | Der Resend-Client, `sendEmail` und die Namen in `EMAIL_PURPOSE`                                                                                      |
| `tanstack-form`  | `form.fields`                                                                                                                                                                              | Feldtypen und `fieldErrorMessage` für TanStack Form                                                                                                  |

## Was keine Integration ist

- Die Anzahl der GitHub-Sterne ist eine Server Function in `src/lib/github.ts`, gecacht in KV.
- Rate Limiting ist `src/lib/rate-limit.ts` und basiert auf der Tabelle `rate_limit`.
- Cloudflare-Bindings brauchen keinen Adapter. Servercode liest sie aus `env` in `cloudflare:workers`.

## Geschäftslogik bleibt in Modulen

Eine Integration konfiguriert einen Anbieter. Entscheidungen über Anwendungsdaten gehören in das Modul, dem die Tabelle gehört:

- Das Polar-Plugin, das der Polar-Bereich in `src/data/polar.auth-plugins.ts` zu Better Auth hinzufügt, prüft Webhook-Signaturen mit `POLAR_WEBHOOK_SECRET` und übergibt jedes Ereignis an `handlePolarEvent` in `src/data/polar-events.ts`. Diese Funktion reicht es an jeden Bereich weiter, der das Ereignis in seiner `<area>.polar-events.ts` aufführt; im Lizenzbereich ruft `src/data/license.polar-events.ts` die `licenseWebhookHandlers` in `src/modules/license/license.webhooks.ts` auf, die wiederum die Lizenz-Use-Cases aufrufen. Auch die Produkt-IDs der Lizenzstufen, `POLAR_PRODUCT_IDS`, gehören zum Lizenzbereich; sie liegen in `src/modules/license/license.utils.ts`.
- Die E-Mail-Hooks von Better Auth rufen `sendVerifyEmail`, `sendResetPasswordEmail` und `sendChangeEmailConfirmationEmail` aus den Modulen verification und account auf, die Resend in `src/data/resend.auth-emails.ts` hinzufügt.
- Ein Use Case versendet eine E-Mail in der Locale, die sein Aufrufer übergibt (die Bestätigungs-E-Mail liest sie aus der Callback-URL): Er lädt den Namespace des Templates, rendert das Template und ruft `sendEmail` auf:

```ts
const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotency: { purpose: EMAIL_PURPOSE.VERIFY_EMAIL, token: crypto.randomUUID() },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```
