## База даних

**`no such table` у `bun run dev`.** Середовище `development` використовує віддалену базу даних D1 середовища preview. Застосуйте там міграції командою `bun run db:migrate:development`. `bun run db:migrate:local` лише застосовує міграції до локальної бази даних, яку `bun run dev` не використовує.

**`no such table` у Playwright.** Браузерні тести використовують власну локальну базу даних. Виконайте `bun run db:reset:test` або дайте Playwright самому запустити застосунок: він виконає цю команду.

**Таблиці у Vitest застаріли.** Мок D1 під час запуску застосовує кожен SQL-файл із `src/integrations/drizzle-orm/migrations`. Після зміни схеми згенеруйте міграцію командою `bun run db:generate`.

## Сервер розробки

**Сервер розробки не запускається.** Він слухає `localhost:3000` зі `strictPort`, тож завершується помилкою, коли порт зайнятий. Зупиніть інший процес.

**Не працює вхід або OAuth.** Перевірте `AUTH_SECRET` та облікові дані OAuth-клієнта у файлі середовища, а також те, що URL зворотного виклику провайдера вказує на <RepositoryFact name="oauthCallbackPath" /> на хості, який ви використовуєте. Better Auth приймає лише хости, налаштовані для режиму збірки: у режимі розробки це `localhost:3000` і `127.0.0.1:3000`.

**У типах Worker бракує прив'язки або секрету.** Після зміни `wrangler.jsonc` запустіть `bun run cf-typegen`: він типізує кожну прив'язку й кожен секрет із `secrets.required`. Значення, яке Wrangler не може вивести, як-от змінну, що її задає лише `test`, оголошують у `src/types/<area>.d.ts` відповідного розділу.

**Власні класи `text-*` зникають після об'єднання.** `cn` залежить від таблиць, згенерованих із `src/lib/cn.config.ts`. `bun run dev`, `bun run check` і збірки генерують їх заново; якщо `.source/cn-tables.ts` відсутній, запустіть `bun run generate:cn`.

## Переклади

**`No messages/<locale>/<namespace>.json`.** Маршрут оголошує простір імен, для якого в цій локалі немає файлу. Створіть файл у кожній локалі.

**Ключ відображається як його шлях, або `check:i18n` повідомляє про відсутній ключ.** Ключа немає в одній із локалей, або компонент читає його поза областю свого виклику `useTranslations`. Використовуйте один `useTranslations` на компонент і запустіть `bun run check:i18n`.

## Документація

**Сторінка документації повертає 404.** Файл має називатися `<page>.<locale>.mdx` і бути вказаним у `pages` файлу `meta.<locale>.json` відповідної папки. Запустіть `bun run content`, щоб заново згенерувати `.source`.

**`check-content.ts` завершується помилкою.** Скрипт порівнює кожну локаль з en-US. `Changed code examples` означає, що блок коду відрізняється від англійського; блоки коду мають бути ідентичними. `Untranslated English paragraph` означає, що абзац скопійовано без перекладу. `Missing <file>` означає, що файлу локалі не існує. `leaves out … from the English page` і `adds …, which the English page does not have` означають, що переклад загубив або додав вбудований код, компонент чи один з його props або посилання на іншу сторінку; перенесіть його так, як він є на англійській сторінці. `has … table rows where the English page has …` означає, що таблиця втратила або отримала зайвий рядок. `links to … instead of …` означає внутрішнє посилання, яке сайт перенаправив би або яке містить локаль; напишіть шлях, який пропонує повідомлення.

**`check-message-formats.ts` завершується помилкою.** `changed the path or command …` означає, що переклад змінив шлях до файлу чи команду з англійського повідомлення; залиште їх без змін або передайте як аргумент ICU з `REPOSITORY_FACTS`. `unexpected Markdown code` означає, що переклад додав зворотні апострофи, які повідомлення виводить як є. `uses “Sie” where de-DE addresses the reader as “du”` означає, що переклад звертається до читача у формі, якої його мова не використовує; перепишіть речення у [формі звертання](/docs/conventions/translations#one-form-of-address), прийнятій для мови. `check-content.ts` повідомляє те саме для сторінки документації, допису в блозі чи запису в журналі змін.

## Тести й розгортання

**`test:coverage` не проходить.** Покриття рядків, інструкцій, функцій і гілок має становити <RepositoryFact name="coverageThreshold" unit="percent" />. Звіт у `coverage/` показує непокриті рядки.

**Розгортання зупиняється на `verify-bindings.ts`.** Цільовому середовищу у `wrangler.jsonc` бракує прив'язки, яку оголошує середовище `development` (`DB`, `CACHE`, `MEDIA` або `BUNDLES`), воно досі має заглушкові ідентифікатори D1 або KV або, якщо це production, використовує спільний ресурс із preview. Створіть ресурси в Cloudflare і замініть ідентифікатори.

**Розгортання зупиняється на `prepare-deploy-secrets.ts`.** Ключ, зазначений у `secrets.required` середовища, відсутній, порожній або є заповнювачем у `.env.<environment>`. `Set …` називає ключі, які відсутні або порожні, а `Replace the placeholders …` — ключі зі значенням у дужках, як-от `[UPDATE]`, або зі словом на зразок `TODO` чи `changeme`; жодне з повідомлень не виводить значення. [Скрипти проєкту](/docs/tooling/scripts) перелічують усі заповнювачі, які скрипт відхиляє. Запишіть у файл справжні значення й запустіть розгортання ще раз.

**Розгортання зупиняється на `auth:verify`.** Ідентифікатор клієнта OAuth у `.env.<environment>` не має формату свого провайдера, тож провайдер відхилив би вхід. Помилка називає змінну, файл і провайдера, не виводячи значення, наприклад `AUTH_GOOGLE_CLIENT_ID in .env.production is not a Google OAuth client ID.` Скопіюйте ідентифікатор клієнта з консолі провайдера (для Google див. пункт про `invalid_client` нижче) і запустіть `bun run auth:verify:<environment>`, щоб перевірити його ще раз.

**Розгортання зупиняється на `polar:verify`.** Polar не відповідає коду: ключ у `.env.<environment>` відсутній або вказує не на той сервіс Polar, токен відхилено або йому бракує області доступу, чи продукт, ціна, ліцензійний ключ, регіональна знижка або вебхук відрізняються від того, що очікує код. Помилка перелічує кожну проблему; [Налаштування Polar](/docs/getting-started/polar-setup) пояснює кожне повідомлення. `bun run polar:verify:<environment>` запускає перевірку ще раз.

**Розгортання зупиняється на `verify-deployment.ts`.** Worker розгорнуто, але один із перевірених шляхів не відповів `200` з очікуваним типом вмісту або вхід не дійшов до свого провайдера так, як мав. Помилка перелічує кожен запит і проблему; відкрийте цю URL-адресу та перегляньте журнали Worker у Cloudflare. Рядок, що закінчується на `client_id is not a Google OAuth client ID.`, означає, що Worker не має справжнього ідентифікатора клієнта для цього провайдера; див. наступний пункт. `bun scripts/verify-deployment.ts <preview|production>` запускає перевірку ще раз.

**Google відповідає `Error 401: invalid_client` і `The OAuth client was not found.`** Worker надіслав Google ідентифікатор клієнта, якого Google не знає. `bun run deploy:<environment>` ще до збірки відхиляє заповнювач або значення в іншому форматі в `AUTH_GOOGLE_CLIENT_ID` (див. `prepare-deploy-secrets.ts` і `auth:verify` вище), тож секрет Worker із таким значенням задано в інший спосіб, наприклад через `wrangler secret put`. Ідентифікатор клієнта у форматі Google, якого Google не знає, належить клієнтові, який видалено або який розташований в іншому проєкті Google Cloud. Щоб це виправити:

1. У консолі Google Cloud відкрийте **Google Auth Platform → Clients** і створіть клієнт типу **Web application** або відкрийте той, який хочете використовувати. Його ідентифікатор клієнта закінчується на `.apps.googleusercontent.com`.
2. Для кожного хоста, на який ви розгортаєте, додайте `https://<host>` до **Authorized JavaScript origins** і <RepositoryFact name="googleCallbackUrl" /> до **Authorized redirect URIs**; Google може застосовувати їх кілька хвилин.
3. У **Google Auth Platform → Audience** виберіть **Publish app**, щоб увійти міг будь-який обліковий запис Google, а не лише тестові користувачі.
4. Запишіть ідентифікатор і секрет клієнта в `AUTH_GOOGLE_CLIENT_ID` і `AUTH_GOOGLE_CLIENT_SECRET` у `.env.<environment>` і запустіть `bun run deploy:<environment>`: він перевірить ідентифікатор клієнта ще до збірки, завантажить обидва секрети Worker і знову перевірить вхід.

**Збірка з пререндерингом завершується помилкою.** Вивід збірки називає першу URL-адресу, на якій стався збій. Відкрийте цю сторінку через `bun run dev`, щоб побачити помилку.
