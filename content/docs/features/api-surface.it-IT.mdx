L’app espone queste rotte HTTP, dichiarate con `server.handlers` su `createFileRoute` in `src/routes/api`:

| Rotta                                        | Metodi            | Handler                                                                                                                                                                                               |
| -------------------------------------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/api`                                       | GET               | Restituisce `{ "runtime": "cloudflare-workers" }`.                                                                                                                                                    |
| `/api/auth/$`                                | GET, POST         | Better Auth: accesso, callback OAuth, `/api/auth/verify-email`, oltre agli endpoint del plugin Polar `/api/auth/polar/webhooks` e `/api/auth/customer/portal`.                                        |
| `/api/search`                                | GET               | Ricerca di Fumadocs (`fumadocs.search.ts`).                                                                                                                                                           |
| <RepositoryFact name="cliApiBasePath" />`/*` | GET, POST, DELETE | L’[API delle licenze della CLI](/docs/features/cli-licence-api): `licenseApiHandlers` (`license.api.ts`) leggono la licenza e attivano, verificano e rilasciano i dispositivi per la CLI `saasyland`. |

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Funzioni server invece di REST

Le operazioni dell’app sono funzioni `createServerFn` in `src/modules/<table>/use-cases`. Le altre si trovano in `src/lib` (`getStarCount` in `github.ts`), in un’integrazione (`getCurrentSession` in `auth.session.ts`, `getDocsPage` in `fumadocs.docs.ts`) oppure direttamente nell’unica rotta che le usa (`getBlogPosts` in `_site._marketing.blog.index.tsx`). TanStack Start le chiama via RPC sotto `/_serverFn`, con middleware per sessioni, permessi e limiti di richieste. Non aggiungere un endpoint REST per un’operazione che solo questa app chiama; aggiungi una rotta HTTP solo per chiamanti esterni come i webhook e la CLI, e verifica le firme dei webhook nell’integrazione del provider.

## Comportamento

- Il Worker non applica i reindirizzamenti della lingua a `/api` e `/_serverFn`. I loro URL non contengono la lingua, quindi sul server `getCurrentLocale()` restituisce `en-US` per queste richieste; il codice che ha bisogno di una lingua la riceve come input o la legge da un `callbackURL`.
- La build non prerenderizza `/api`.
- `/media/*` non è una rotta di TanStack Start: il Worker la passa a `serveMedia` prima della gestione della lingua. Vedi [Cloudflare R2](/docs/integrations/cloudflare-r2). Non lo è nemmeno `/bundles/*`, che il Worker passa a `serveBundle`; vedi [API delle licenze della CLI](/docs/features/cli-licence-api#template-bundles).
- I test degli handler si trovano in `src/routes/api/__test__/`, un file per handler: `auth.test.ts`, `search.test.ts` e `index.test.ts`. `cli.v1.test.ts` copre i file di route dell’API delle licenze della CLI, il cui comportamento è testato in `src/modules/license/__test__/license.api.integration.test.ts` e, per i bundle, in `license.bundles.integration.test.ts`.
