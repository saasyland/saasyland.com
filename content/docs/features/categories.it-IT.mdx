## Dati

`src/modules/category/category.schema.ts` definisce la tabella `category`: `name`, `description`, `kind` (`category` o `collection`), `visibility` (`public` o `hidden`), `icon` (`Archive`, `FolderOpen` o `Puzzle`) e i timestamp.

Casi d’uso in `src/modules/category/use-cases`, ognuno protetto dal permesso `category` corrispondente: `getCategories` (paginato, `kind` opzionale), `getCategory`, `createCategory`, `updateCategory` e `deleteCategory`. `createCategory` è la struttura di riferimento per un caso d’uso di mutazione:

```ts
export const createCategory = createServerFn({ method: "POST" })
  .middleware([authorized({ category: ["create"] })])
  .validator((input: Category["createCategory"]) => categoryZodSchemas.createCategory.parse(input))
  .handler(({ data }) =>
    db
      .insert(category)
      .values({
        description: data.description ?? "",
        icon: data.icon ?? CATEGORY_ICON.FOLDER_OPEN,
        id: v7(),
        kind: data.kind,
        name: data.name,
        visibility: data.visibility ?? CATEGORY_VISIBILITY.PUBLIC,
      })
      .returning()
      .get(),
  )

export const createCategoryMutation = mutationOptions({
  mutationFn: (data: Category["createCategory"]) => createCategory({ data }),
  mutationKey: CATEGORY_MUTATION_KEYS.CREATE,
})
```

I messaggi di errore si trovano nel namespace `category.errors`. Nessun modulo modifica ancora le categorie, quindi i loro messaggi Zod avranno un namespace `category.validations` con il primo modulo che li mostra.

## Schermata di amministrazione

Le schede **Categorie** e **Collezioni** di `/admin/products` mostrano `categoryColumns` con `getCategoriesPageQuery({ kind, pageIndex, pageSize })`. È collegato solo l’elenco: nessuna schermata crea, modifica o elimina categorie. I prodotti non hanno ancora una relazione con le categorie, quindi la tabella non mostra il numero di elementi.
