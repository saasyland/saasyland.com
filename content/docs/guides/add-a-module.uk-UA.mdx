Модуль — це одна таблиця бази даних. `src/modules/<table>/` існує лише для справжніх таблиць; серверні функції, що не належать жодній таблиці, розміщуються в `src/lib` або в маршруті, який їх використовує. Найменший повний приклад — `src/modules/category`.

## Файли

| Файл                       | Вміст                                                                                                                                            |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `<table>.schema.ts`        | Таблиця Drizzle, індекси, зв'язки та кортежі значень перелічень, зібрані з констант                                                              |
| `<table>.zod.ts`           | Одна схема вхідних даних на операцію та схеми `drizzle-zod`, експортовані як `<table>ZodSchemas`                                                 |
| `<table>.constants.ts`     | Іменовані доменні значення, як-от `CATEGORY_KIND`, ліміти колонок і кортежі ключів запитів і мутацій                                             |
| `<table>.types.ts`         | Один інтерфейс із типами рядків і типом вхідних даних кожної операції                                                                            |
| `<table>.utils.ts`         | Необов'язкові допоміжні функції; `license.utils.ts` читає середовище Worker, тому виконується лише на сервері                                    |
| `<table>.<concern>.ts`     | Необов'язковий код, який не є однією операцією, як-от `license.webhooks.ts` або `video.playback.ts` ([Каталог модулів](/docs/reference/modules)) |
| `use-cases/<operation>.ts` | Одна серверна функція на файл разом із параметрами запиту чи мутації                                                                             |
| `__test__/`                | Тести, названі за вихідним файлом, наприклад `category.schema.test.ts` і `category.zod.test.ts`                                                  |

## 1. Визначте таблицю

Назвіть значення таблиці один раз у `category.constants.ts`. Схема, схеми Zod, сценарії використання, компоненти, тести й дані e2e імпортують їх звідти, а не повторюють рядок на кшталт `"collection"`:

```ts
export const CATEGORY_NAME_MAX_LENGTH = 255

export const CATEGORY_KIND = {
  CATEGORY: "category",
  COLLECTION: "collection",
} as const
```

Побудуйте таблицю з цих назв:

```ts
import { index, sqliteTable, text } from "drizzle-orm/sqlite-core"

import { timestamps } from "~/src/integrations/drizzle-orm/drizzle.columns"

import { CATEGORY_KIND, CATEGORY_NAME_MAX_LENGTH } from "~/src/modules/category/category.constants"

export const CATEGORY_KINDS = [CATEGORY_KIND.CATEGORY, CATEGORY_KIND.COLLECTION] as const

export const category = sqliteTable(
  "category",
  {
    id: text("id").primaryKey(),
    kind: text("kind", { enum: CATEGORY_KINDS }).notNull().default(CATEGORY_KIND.CATEGORY),
    name: text("name", { length: CATEGORY_NAME_MAX_LENGTH }).notNull(),
    ...timestamps(),
  },
  (table) => [index("category_createdAt_idx").on(table.createdAt)],
)
```

- Назви колонок пишуться в snake_case, властивості — у camelCase.
- Ідентифікатори — це первинні ключі типу `text`, які сценарій вставлення заповнює через `v7()` з `uuid`.
- `...timestamps()` з `src/integrations/drizzle-orm/drizzle.columns.ts` додає `createdAt` і `updatedAt`: мітки часу в мілісекундах, які за замовчуванням дорівнюють моменту вставлення; `updatedAt` оновлюється під час кожного оновлення. Інші дати — це `integer(..., { mode: "timestamp_ms" })`, булеві значення — `integer(..., { mode: "boolean" })`.
- Колонка-перелічення отримує кортеж, зібраний з об'єкта констант, а її значенням за замовчуванням є константа на кшталт `CATEGORY_KIND.CATEGORY`, ніколи не рядковий літерал.
- Зовнішні ключі використовують `.references(() => user.id, { onDelete: "cascade" })`, а `relations(...)` оголошує з'єднання (див. `session.schema.ts`).

## 2. Зареєструйте схему

Експортуйте таблицю, а також її зв'язки, якщо вони є, з `src/integrations/drizzle-orm/drizzle.schemas.ts`:

```ts
export { category } from "~/src/modules/category/category.schema"
```

Цей файл використовують клієнт D1 (`drizzle(env.DB, { schema })`), адаптер Drizzle у Better Auth і drizzle-kit. Таблиця, якої тут немає, не отримає міграції.

## 3. Згенеруйте міграцію

```sh
bun run db:generate
bun run db:migrate:local
```

Перегляньте згенерований SQL у `src/integrations/drizzle-orm/migrations/` і закомітьте його разом зі схемою. Віддалені середовища описано в посібнику [Міграції бази даних](/docs/guides/database-migrations).

## 4. Додайте схеми Zod

Кожна операція має власну схему вхідних даних. Повідомлення валідації — це ключі перекладу; форма показує їх через `ValidationFieldError` у просторі імен, який вона вказує.

```ts
import { createSchemaFactory } from "drizzle-zod"
import zod from "zod/v4"

import { MIN_FIELD_LENGTH, idField } from "~/src/modules/_core/utils/zod-fields"
import { CATEGORY_NAME_MAX_LENGTH } from "~/src/modules/category/category.constants"
import { CATEGORY_KINDS, category } from "~/src/modules/category/category.schema"

const { createInsertSchema, createSelectSchema, createUpdateSchema } = createSchemaFactory({ zodInstance: zod })

const createCategory = zod.object({
  kind: zod.enum(CATEGORY_KINDS),
  name: zod.string().min(MIN_FIELD_LENGTH, { message: "nameRequired" }).max(CATEGORY_NAME_MAX_LENGTH, { message: "nameMaxLength" }),
})

const deleteCategory = zod.object({ categoryId: idField })

export const categoryZodSchemas = {
  createCategory,
  deleteCategory,
  insert: createInsertSchema(category),
  select: createSelectSchema(category),
  update: createUpdateSchema(category),
}
```

Додайте `messages/<locale>/<table>.validations.json` для кожної мови з усіма ключами, які використовують схеми. Форма показує ці ключі, лише коли її маршрут попередньо завантажує простір імен і передає його в `ValidationFieldError`; форми курсів в адмінпанелі використовують `course.validations`, а інші форми — `auth.validations`.

## 5. Додайте константи й типи

```ts
export const CATEGORY_QUERY_KEYS = {
  ALL: ["category"],
  LIST: ["category", "getCategories"],
} as const

export const CATEGORY_MUTATION_KEYS = {
  CREATE: ["category", "createCategory"],
  DELETE: ["category", "deleteCategory"],
  UPDATE: ["category", "updateCategory"],
} as const
```

```ts
import type * as zod from "zod"

import type { category } from "~/src/modules/category/category.schema"
import type { categoryZodSchemas } from "~/src/modules/category/category.zod"

export interface Category {
  select: typeof category.$inferSelect
  insert: typeof category.$inferInsert
  createCategory: zod.input<typeof categoryZodSchemas.createCategory>
  deleteCategory: zod.input<typeof categoryZodSchemas.deleteCategory>
}
```

Кожен ключ починається з назви модуля, тож інвалідація `ALL` оновлює всі запити модуля.

`Category` має один ключ на кожну схему операції; повний модуль `category` також має `getCategories`, `getCategory` і `updateCategory`. Серверна функція типізує вхідні дані валідатора як `Category["createCategory"]`, а її опції mutation або query використовують той самий тип. Додаючи схему, додайте й ключ.

## 6. Додайте дозволи та сценарії використання

- Додайте дії таблиці до `APP_STATEMENTS` у `src/integrations/better-auth/auth.access.ts`, якщо операціям потрібні дозволи. Див. [Ролі та дозволи](/docs/guides/roles-and-permissions).
- Додайте по одному файлу на операцію в `use-cases/`. Див. [Додавання сценарію використання](/docs/guides/add-a-use-case).

## 7. Протестуйте

Додайте `__test__/<table>.schema.test.ts`, `<table>.zod.test.ts` і `<table>.types.test.ts` поруч із модулем та `use-cases/__test__/<operation>.test.ts` для кожної операції. Обов'язкове покриття — <RepositoryFact name="coverageThreshold" unit="percent" />; див. [Написання тестів](/docs/guides/writing-tests).
