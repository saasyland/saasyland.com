title: "Risoluzione dei problemi"
description: "Errori comuni durante sviluppo, test e deploy, e come risolverli."
---

## Database

**`no such table` in `bun run dev`.** Il database di sviluppo locale non è stato migrato. Esegui `bun run db:migrate:local`, oppure `bun run db:reset:local` e `bun run db:seed:local` per averne uno nuovo e popolato.

**`no such table` in Playwright.** I test browser usano un proprio database locale. Esegui `bun run db:reset:test`, oppure lascia che sia Playwright ad avviare l'app, perché esegue questo comando.

**Le tabelle di Vitest non sono aggiornate.** Il mock di D1 applica all'avvio ogni file SQL in `src/integrations/drizzle-orm/migrations`. Dopo una modifica allo schema, genera una migrazione con `bun run db:generate`.

## Server di sviluppo

**Il server di sviluppo non si avvia.** Resta in ascolto su `localhost:3000` con `strictPort`, quindi fallisce se la porta è occupata. Termina l'altro processo.

**L'accesso o OAuth non funziona.** Controlla `AUTH_SECRET` e le credenziali del client OAuth nel file di ambiente, e verifica che l'URL di callback del provider punti a <RepositoryFact name="oauthCallbackPath" /> sull'host che stai usando. Better Auth accetta solo gli host configurati per la modalità di build: `localhost:3000` e `127.0.0.1:3000` in sviluppo.

**Nei tipi del Worker manca un binding o un secret.** Esegui `bun run cf-typegen` dopo aver modificato `wrangler.jsonc`: tipizza ogni binding e ogni secret di `secrets.required`. Un valore che Wrangler non può ricavare, come una variabile impostata solo da `test`, va nel `src/types/<feature>.d.ts` della funzionalità.

**Le classi `text-*` personalizzate scompaiono durante l'unione.** `cn` dipende da tabelle generate da `src/lib/cn.config.ts`. `bun run dev`, `bun run check` e le build le rigenerano; esegui `bun run generate:cn` se manca `.source/cn-tables.ts`.

## Traduzioni

**`No messages/<locale>/<namespace>.json`.** Una route dichiara un namespace che non ha un file per quel locale. Crea il file in ogni locale.

**Una chiave viene mostrata come il suo percorso, oppure `check:i18n` segnala una chiave mancante.** La chiave manca in un locale, oppure il componente la legge fuori dallo scope della sua chiamata a `useTranslations`. Usa un solo `useTranslations` per componente ed esegui `bun run check:i18n`.

## Documentazione

**Una pagina della documentazione restituisce 404.** Il file deve chiamarsi `<page>.<locale>.mdx` ed essere elencato in `pages` nel `meta.<locale>.json` della cartella. Esegui `bun run content` per rigenerare `.source`.

**`check-content.ts` fallisce.** Lo script confronta ogni locale con en-US. `Changed code examples` significa che un blocco di codice differisce da quello inglese; i blocchi di codice devono essere identici. `Untranslated English paragraph` significa che un paragrafo è stato copiato senza tradurlo. `Missing <file>` significa che il file di un locale non esiste. `leaves out … from the English page` e `adds …, which the English page does not have` significano che una traduzione ha perso o aggiunto codice inline, un componente o una delle sue prop, o un link a un'altra pagina; riportalo come lo ha la pagina inglese. `has … table rows where the English page has …` significa che una tabella ha perso o guadagnato una riga. `links to … instead of …` significa che un link interno verrebbe reindirizzato o nomina un locale; scrivi il percorso che il messaggio suggerisce.

**`check-message-formats.ts` fallisce.** `changed the path or command …` significa che una traduzione ha modificato un percorso di file o un comando del messaggio inglese; lascialo com'è o passalo come argomento ICU da `REPOSITORY_FACTS`. `unexpected Markdown code` significa che una traduzione ha aggiunto dei backtick, che un messaggio stampa così come sono. `uses “Sie” where de-DE addresses the reader as “du”` significa che una traduzione si rivolge al lettore in una forma che la sua lingua non usa; riscrivi la frase nella [forma di cortesia](/docs/conventions/translations#one-form-of-address) della lingua. `check-content.ts` segnala lo stesso per una pagina della documentazione, un articolo del blog o una voce del changelog.

## Test e deploy

**`test:coverage` fallisce.** La copertura deve essere pari a <RepositoryFact name="coverageThreshold" unit="percent" /> per righe, istruzioni, funzioni e branch. Il report in `coverage/` elenca le righe non coperte.

**Il deploy si ferma a `verify-bindings.ts`.** L'ambiente di destinazione in `wrangler.jsonc` non ha un binding che l'ambiente `development` dichiara (`DB`, `CACHE`, `MEDIA` o `BUNDLES`), ha ancora ID D1 o KV segnaposto oppure, per la produzione, condivide una risorsa con la preview. Crea le risorse in Cloudflare e sostituisci gli ID.

**Il deploy si ferma a `prepare-deploy-secrets.ts`.** Una chiave elencata in `secrets.required` dell'ambiente manca, è vuota o è un segnaposto in `.env.<environment>`. `Set …` indica le chiavi mancanti o vuote, e `Replace the placeholders …` quelle che contengono un valore tra parentesi, come `[UPDATE]`, o una parola come `TODO` o `changeme`; nessuno dei due stampa un valore. [Script del progetto](/docs/tooling/scripts) elenca tutti i segnaposto che rifiuta. Inserisci i valori reali nel file ed esegui di nuovo il deploy.

**Il deploy si ferma a `auth:verify`.** Un ID client OAuth in `.env.<environment>` non ha il formato del suo provider, che quindi rifiuterebbe l'accesso. L'errore indica la variabile, il file e il provider senza stampare il valore, per esempio `AUTH_GOOGLE_CLIENT_ID in .env.production is not a Google OAuth client ID.` Copia l'ID client dalla console del provider (per Google, vedi la voce `invalid_client` più sotto) ed esegui `bun run auth:verify:<environment>` per controllarlo di nuovo.

**Il deploy si ferma a `polar:verify`.** Polar non corrisponde al codice: una chiave in `.env.<environment>` manca o indica il servizio Polar sbagliato, il token viene rifiutato o non ha uno scope, oppure la localizzazione del checkout o il comportamento fiscale dell'organizzazione, un prodotto, un prezzo, una chiave di licenza o un webhook è diverso da ciò che il codice si aspetta. L'errore elenca ogni problema; [Configurazione di Polar](/docs/getting-started/polar-setup) spiega ogni messaggio. `bun run polar:verify:<environment>` ripete il controllo.

**Il deploy si ferma a `verify-deployment.ts`.** Il Worker è stato distribuito, ma un percorso controllato non ha risposto `200` con il tipo di contenuto previsto, oppure un accesso non ha raggiunto il suo provider come dovrebbe. L'errore elenca ogni richiesta e il problema; apri l'URL e leggi i log del Worker in Cloudflare. Una riga che termina con `client_id is not a Google OAuth client ID.` significa che il Worker non ha un vero ID client per quel provider; vedi la voce successiva. `bun scripts/verify-deployment.ts <preview|production>` ripete il controllo.

**Google risponde `Error 401: invalid_client` e `The OAuth client was not found.`** Il Worker ha inviato a Google un ID client che Google non conosce. `bun run deploy:<environment>` rifiuta prima della build un segnaposto o un valore in un altro formato in `AUTH_GOOGLE_CLIENT_ID` (vedi `prepare-deploy-secrets.ts` e `auth:verify` più sopra), quindi un secret del Worker che ne contiene uno è stato impostato in un altro modo, per esempio con `wrangler secret put`. Un ID client nel formato di Google che Google non conosce appartiene a un client eliminato o a un client di un altro progetto Google Cloud. Per risolvere:

1. Nella console di Google Cloud apri **Google Auth Platform → Clients** e crea un client di tipo **Web application**, oppure apri quello che vuoi usare. Il suo ID client termina con `.apps.googleusercontent.com`.
2. Aggiungi `https://<host>` a **Authorized JavaScript origins** e <RepositoryFact name="googleCallbackUrl" /> a **Authorized redirect URIs** per ogni host su cui fai il deploy; Google può impiegare qualche minuto ad applicarli.
3. In **Google Auth Platform → Audience** seleziona **Publish app**, così può accedere qualsiasi account Google e non solo gli utenti di test.
4. Inserisci ID e secret del client in `AUTH_GOOGLE_CLIENT_ID` e `AUTH_GOOGLE_CLIENT_SECRET` in `.env.<environment>` ed esegui `bun run deploy:<environment>`, che controlla l'ID client prima della build, carica entrambi i secret del Worker e controlla di nuovo l'accesso.

**Una build con prerendering fallisce.** L'output della build indica il primo URL che ha fallito. Apri quella pagina con `bun run dev` per vedere l'errore.
