## 管理画面の骨格 [#admin-shell]

`src/routes/admin.tsx` はすべての管理ページを `requireAdmin` で保護し、共通の名前空間をプリロードします。レイアウトは次を表示します。

- `AdminSidebar`。`src/data/navigation.ts` の `ADMIN_NAVIGATION` から構築されます。これは各エリアが追加した項目をアイコンとともにグループにまとめたもので、概要（ダッシュボード）、商品・サービス（商品）、販売（注文）、コンテンツ（コース）、管理（ユーザー管理、設定）のグループがあります。どの項目も動作する画面を開きます。実際のデータの取得元がない画面には、ルートも、メニュー項目も、コマンドパレットの項目もありません（[実データのみ](#real-data-only)を参照）。表示中のページの項目には `aria-current="page"` とアクセントの線が付きます。パンくずリストの横のボタンでサイドバーをアイコンだけに折りたたみ、各アイコンの名前はツールチップに表示されます。スマートフォンでは同じボタンでシートとして開きます。
- 上部バーの `AdminBreadcrumbs` と `AdminCommandPalette` の検索ボタン。
- 各管理ページの上部にある `AdminPageHeader`（`custom/admin/admin-page-header.tsx`）。タイトル、説明、右側のページのアクション、タイトルの上の任意の戻るリンク、その下の任意のタブを表示し、罫線で区切ります。`AdminPageHeaderPending` は各ページの `pendingComponent` で同じ形を描きます。
- サイドバー下部のユーザーウィジェット。設定へのリンクと `SignOutButton` を含みます。
- サイドバー上部のワードマーク。ホームページへのリンクです。

### コマンドパレット [#command-palette]

⌘K または Ctrl+K、あるいは訪問者のプラットフォームのショートカットを表示する上部バーの検索ボタンで `AdminCommandPalette` が開きます。リストはダイアログの中でスクロールし、見つかったものをグループに分け、各行にアイコン、名前、詳細の行を表示します。

- **最近使った項目**: パレットから最後に開いたページとレコード。最大 `RECENT_LIMIT` 件で、検索が空のあいだ表示されます。ブラウザーの `localStorage` にだけ保存されます。
- **クイックアクション**: `src/data/navigation.ts` の `ADMIN_COMMAND_ACTIONS` の項目。**新しいコース** と **サイトを開く** です。
- **ページ**: `ADMIN_NAVIGATION` のすべての項目を、サイドバーのグループとともにブラウザーで絞り込みます。
- レコード: `src/data/command-search.ts` の `COMMAND_SEARCHES` の検索で、各エリアが `src/data/<area>.command-search.ts` で追加します。検索が `SEARCH_TEXT_MIN_LENGTH` 文字に達して入力が止まると、パレットはサインイン中のロールが実行できる検索をすべて並行して実行し、それぞれ最大 `SEARCH_HITS_LIMIT` 件を返します。

| グループ | エリア     | サーバー関数    | 権限           | 一致の対象                                                           |
| -------- | ---------- | --------------- | -------------- | -------------------------------------------------------------------- |
| ユーザー | `auth`     | `searchUsers`   | `user: list`   | 名前またはメールアドレス                                             |
| 注文     | `payments` | `searchOrders`  | `order: read`  | 注文 ID、Polar の顧客 ID、顧客の名前またはメールアドレス             |
| コース   | `courses`  | `searchCourses` | `course: read` | 任意の言語のタイトル、またはスラッグ                                 |
| レッスン | `courses`  | `searchLessons` | `course: read` | 任意の言語のタイトル、またはスラッグ。詳細にはコース名が表示されます |

どの検索も `authorized(...)` で保護されたサーバー関数で、パレットはロールの権限で許可されない検索を省くため、アカウントが読めないレコードを要求することはありません。矢印キーで結果を移動し、Enter で開き、Escape で検索を消してからパレットを閉じます。ライブリージョンが、パレットが検索中であることと見つかった件数をスクリーンリーダーに伝えます。

## ダッシュボード [#dashboard]

`/admin`（`src/routes/admin.index.tsx`）は `getUsersQuery` をプリロードし、ダッシュボードの各統計と各パネルのクエリを、それぞれの `prefetch` を通じてプリロードします。そして `src/presentation/components/custom/admin/dashboard` のウィジェットと各エリアが追加するパネルを組み合わせます。

- `DashboardActions`: `src/data/navigation.ts` の `ADMIN_DASHBOARD_ACTIONS` の各項目を、リストの順に並べたリンクで、ラベルはその `label` が指すメッセージから付きます。決済のエリアのページである **注文** と **顧客** です（[注文と顧客](/docs/features/orders)を参照）。
- `DashboardStats`: `ADMIN_DASHBOARD_STATS` の統計、つまり `src/data/<area>.dashboard.ts` のうち `DASHBOARD_PLACEMENT.STAT` に配置された項目を `order` の順に表示します。それぞれのラベルはそのエリアの `dashboard.<area>.json` から付き、値はページのロケールで書式設定されます。各カードには統計の `icon` が表示され、`to` を持つ統計は、カード全体がその統計の数える対象を一覧するページへのリンクになります。
- `ADMIN_DASHBOARD_PANELS` のパネル、つまり `DASHBOARD_PLACEMENT.PANEL` に配置された項目を `order` の順に表示します。それぞれ `AdminDashboardPending` が表示するスケルトンを持ちます。各項目は `lazyRouteComponent` でパネルを指定するため、パネルのコードはグラフや表とともに専用のチャンクで読み込まれ、ダッシュボードのローダーがパネルのデータと一緒にプリロードします。スケルトンはパネルの `-pending.tsx` ファイルから取ります。
- ユーザーカード: 最新のアカウントを 1 ページ <RepositoryFact name="adminPreviewPageSize" /> 行で表示し、検索とステータスのフィルターを備えます。各ユーザーの名前はそのユーザーのプロフィールへリンクし、アクションはそこにあります。

| 統計                     | エリア       | 取得元                                                                                        |
| ------------------------ | ------------ | --------------------------------------------------------------------------------------------- |
| 登録ユーザー             | `auth`       | `getUsersQuery` の `total`: `user` のすべての行                                               |
| カタログ掲載商品         | `products`   | `getProductsQuery` の `total`: `product` のすべての行                                         |
| メールアドレスの確認待ち | `auth`       | `getUsersQuery` の `pendingVerification`: 確認済みでも利用停止中でもないアカウント            |
| 受講者                   | `courses`    | `courseProgressQuery` の `learners`: 公開済みのレッスンに進捗を保存したアカウント             |
| 動画                     | `courses`    | `getVideosQuery` の `total`: `video` のすべての行。各レッスンが動画を持つコースにリンクします |
| ニュースレター購読者     | `newsletter` | `newsletterSubscribersQuery`: `newsletter_subscriber` のうちステータスが `subscribed` の行    |

| パネル                         | エリア     | 取得元                                                                                                                               |
| ------------------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| ライセンスのない支払い済み注文 | `license`  | `unlicensedOrdersQuery`（[ライセンス](/docs/features/licences#orders-that-match-no-account)を参照）                                  |
| パッケージ別のライセンス       | `license`  | `src/modules/license/use-cases/get-license-counts.ts` の `licenseCountsQuery`（[パッケージ別のライセンス](#licences-by-tier)を参照） |
| 売上                           | `payments` | `src/modules/order/use-cases/get-revenue.ts` の `revenueQuery`。[売上](#revenue)を参照                                               |
| 新規ユーザー                   | `auth`     | `src/modules/user/use-cases/get-user-signups.ts` の `userSignupsQuery`。[新規ユーザー](#new-users)を参照                             |
| コースの進捗                   | `courses`  | `src/modules/lesson-progress/use-cases/get-course-progress.ts` の `courseProgressQuery`。[コースの進捗](#course-progress)を参照      |

どのクエリも、各エリアがすでに宣言している権限を指定した `authorized(...)` の背後でサーバー関数を実行します。そのため、その権限を持たないサインイン中のアカウントには、数値ではなくエラーが返ります。

### 期間 [#periods]

売上と新規ユーザーのパネルでは、`src/lib/time-series.ts` の `TIME_RANGES` にある期間 <RepositoryFact name="dashboardRanges" /> を選べ、最初は <RepositoryFact name="defaultDashboardRange" /> で開きます。`timeSeries(range, now)` は期間をバケットに分けます。バケットは今日を含む直近の日々、または今月を含む直近の月々で、いずれも UTC です。サーバー関数が時計を読み、すべてのバケットを返すため、ブラウザーはサーバーが数えたとおりに描画します。`src/integrations/drizzle-orm/drizzle.time-series.ts` の `bucketOf` は SQLite の `strftime` で行を UTC でグループ化し、`pointsOf` は各合計をそのバケットに入れ、行のないバケットを 0 で埋めます。

各パネルは期間をコンポーネントの状態に保持します。`RangePicker` はトランジションの中で期間を変更するため、パネルは次の期間を読み込み終えるまで、現在の数値を色を落とし `aria-busy` を付けた状態で表示し続けます。`TimeSeriesChart`（`src/presentation/components/custom/admin/dashboard/time-series-chart.tsx`）は `ChartContainer` を通じて Recharts で系列を棒グラフとして描画します。グラフは支援技術からは隠され、視覚的に隠したテーブルがすべての日または月とその値を一覧にします。

### 売上 [#revenue]

`getRevenue`（`order: ["read"]`）は、D1 に保持する Polar の注文のコピーを読み取ります（[決済](/docs/features/payments#orders-and-subscriptions-in-d1)を参照）。

- ステータスが <RepositoryFact name="revenueOrderStatuses" />（`src/modules/order/order.constants.ts` の `REVENUE_ORDER_STATUSES`）のいずれかで、期間内に行われた注文を数えます。下書き、保留中、無効の注文は売上ではありません。
- 通貨ごとに、注文数、`gross`（`total_amount` の合計）、`refunded`（`refunded_amount` の合計）、`net`（gross から refunded を引いた額）、そして各バケットの純額である `points` を返します。金額は `fromMinorUnits` で変換した通貨の主単位で、Polar が課金したとおりの税を含みます。
- 返金は、返金対象の注文から、その注文が行われた日のバケットで差し引かれます。コピーには返金額はあっても、返金の時点がないためです。
- 通貨どうしを合算することはありません。パネルは通貨ごとにタブを表示し、注文の最も多い通貨を先頭にして、グラフの上に返金後の金額、注文数、返金額を示します。
- 期間内に支払い済みの注文がない場合、パネルはその旨を表示し、グラフを描画しません。

### 新規ユーザー [#new-users]

`getUserSignups`（`user: ["list"]`）は `user` の行を `created_at` のバケットごとに数え、系列とその合計を返します。パネルは合計とグラフを表示するか、期間内に作成されたアカウントがないことを表示します。

### コースの進捗 [#course-progress]

`getCourseProgress`（`course: ["read"]`）は、すべてのコースを管理画面での順序（`position`）で一覧にし、それぞれの公開済みのレッスン、そのいずれかに進捗を保存したアカウント、そのすべてを修了したアカウント、修了したレッスンの合計を示します。下書きのレッスンの進捗は数えず、管理者を含むすべてのアカウントを数えます。いずれかのコースに進捗を保存したアカウントの数である `learners` が、**受講者** の統計です。パネルはコースを `DataGrid`（`course-progress-columns.tsx` の `useCourseProgressColumns`）で一覧にし、コースと各件数で絞り込めます。まだコースがない場合は、そのことを表示します。

### パッケージ別のライセンス [#licences-by-tier]

`getLicenseCounts`（`admin: ["access"]`）は、`license` を `tier` と `status` でグループ化した1回のクエリで読み取り、何も書き込みません。`LICENSE_TIERS` の各パッケージについてその順序で1行を返し、`LICENSE_STATUSES` の各ステータスにあるライセンスの数を示します。あるステータスにライセンスがないパッケージは0です。パネルはパッケージを `DataGrid`（`license-count-columns.tsx` の `useLicenseCountColumns`）で一覧にし、それぞれを `components.custom.pricing.json` の名前で表示して、件数を右揃えにします。有効なライセンスはCLIで使えますが、返金済みまたは取り消し済みのライセンスは使えなくなります（[ライセンス](/docs/features/licences)を参照）。

### ニュースレター購読者 [#newsletter-subscribers]

`getNewsletterSubscribers`（`admin: ["access"]`）は、メールアドレスを確認し、購読を解除していない購読者を数えます。確認待ちの登録と購読を解除したアドレスは数えません。

### ユーザーカード [#users-card]

```tsx
<DataGrid
  columns={columns}
  data={users.rows.slice(0, ADMIN_DASHBOARD_PREVIEW_PAGINATION.pageSize)}
  id={DASHBOARD_USER_GRID_ID}
  label={t("users.title")}
  search={t("users.search")}
  selectable
/>
```

このグリッドはブラウザー上で、`getUsersQuery` の最初のページ（<RepositoryFact name="defaultPageSize" /> 人、新しい順）のうち最新のユーザーを扱い、サーバーに再度問い合わせることなく、検索、ユーザー・ステータス・登録日での絞り込み、並べ替えを行います。**登録日** の列はアカウントの `created_at` です。**すべて表示** は `/admin/users` へリンクします。

## 実データのみ [#real-data-only]

管理画面が表示する数値と行はすべて、`authorized(...)` の背後にあるモジュールのユースケースが D1 から読み取ります。`scripts/admin-data-lint-plugin.ts` の lint ルール `admin-data/no-literal-data` がこれを守らせます。`src/routes/admin*.tsx`、`src/presentation/components/custom/admin/`、`src/data/admin*.ts`、`src/data/*.dashboard.ts` のファイルが次のいずれかを宣言すると、`bun run check` は失敗します。

- 2 つ以上の数値のリスト。これはハードコードされた系列です。
- 並び順（`order`）以外の数値を持つ、2 つ以上のレコードのリスト。
- メールアドレス、ISO 形式の日付、数値から描いた SVG のパス。
- デモ、ダミー、フェイク、lorem、モック、サンプルのデータにちなんだ名前の定数、またはプレースホルダーを表す大文字の定数。
- `useValue` が `useSuspenseQuery` や `useQuery` でクエリを読まないダッシュボードの統計。

テストは独自の行を組み立てるため、テストではこのルールを無効にしています。`src/__test__/admin-data-lint-plugin.test.ts` に、このルールが受け入れるものと拒否するものが並んでいます。データの取得元がまだない画面は、取得元ができるまで作りません。
