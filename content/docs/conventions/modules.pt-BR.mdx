title: "Módulos"
description: "Um módulo é uma tabela do banco de dados: seu schema, suas constantes, seus schemas Zod, sua interface de tipos, seus casos de uso e os poucos arquivos de aspecto de que uma tabela pode precisar."
---

`src/modules/<table>/` existe apenas para uma tabela real do banco de dados. A pasta espelha o schema do Drizzle, então criar uma pasta afirma que uma tabela existe. O código que atende a um recurso sem tabela própria vai para outro lugar: uma server function que lê o GitHub ou a coleção da documentação fica em `src/lib/<topic>.ts` ou na única rota que a usa, e a configuração de fornecedores fica em `src/integrations/<vendor>`.

Os módulos são <RepositoryFact name="modules" />. `license` é dono de duas tabelas, `license` e `revoked_license_order`. `_core` não é um módulo: ele contém só a base sobre a qual todo módulo é construído, os códigos de erro, as constantes HTTP, os campos Zod e as entradas de paginação, ordenação e busca. Os catálogos ficam em `src/data` e os helpers genéricos em `src/lib`.

## Anatomia

`src/modules/course` é a referência. Um módulo contém estes arquivos, todos com o nome da tabela:

| Arquivo                      | Contém                                                                                                      |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `<table>.schema.ts`          | A tabela Drizzle, seus índices e relações                                                                   |
| `<table>.constants.ts`       | Objetos de valores de domínio, suas tuplas de enum, chaves de query, chaves de mutation e limites do módulo |
| `<table>.zod.ts`             | Um schema de entrada por operação, exportados juntos em um único objeto `<table>ZodSchemas`                 |
| `<table>.types.ts`           | Uma interface com o nome do módulo                                                                          |
| `<table>.utils.ts`           | Helpers da tabela, puros e seguros no navegador, a menos que leiam o ambiente do Worker                     |
| `<table>.<concern>.ts`       | Mais um aspecto da tabela, como `lesson.access.ts` ou `video.delivery.ts`                                   |
| `use-cases/<verb>-<noun>.ts` | Uma operação, com o nome da sua server function                                                             |
| `__test__/`                  | Testes e fixtures dos arquivos acima                                                                        |

## Schema

```ts title="src/modules/course/course.schema.ts"
export const course = sqliteTable(
  "course",
  {
    cover: text("cover"),
    icon: text("icon", { enum: COURSE_ICONS }).notNull().default(COURSE_ICON.BOOK_OPEN),
    id: text("id").primaryKey(),
    kind: text("kind", { enum: COURSE_KINDS }).notNull().default(COURSE_KIND.COURSE),
    level: text("level", { enum: COURSE_LEVELS }).notNull().default(COURSE_LEVEL.BEGINNER),
    outcomes: text("outcomes", { mode: "json" })
      .$type<LocalizedList>()
      .notNull()
      .default(sql`'{}'`),
    position: integer("position").notNull().default(0),
    prerequisites: text("prerequisites", { mode: "json" })
      .$type<LocalizedList>()
      .notNull()
      .default(sql`'{}'`),
    slug: text("slug", { length: SLUG_MAX_LENGTH }).notNull().unique(),
    status: text("status", { enum: COURSE_STATUSES }).notNull().default(COURSE_STATUS.DRAFT),
    summary: text("summary", { mode: "json" }).$type<LocalizedText>().notNull(),
    title: text("title", { mode: "json" }).$type<LocalizedText>().notNull(),
    ...timestamps(),
  },
  (table) => [index("course_status_position_idx").on(table.status, table.position)],
)
```

- As colunas usam camelCase no TypeScript e snake_case no SQL. As chaves ficam ordenadas, como o linter exige, com `...timestamps()` como a última entrada.
- `createdAt` e `updatedAt` vêm de `timestamps()` em `src/integrations/drizzle-orm/drizzle.columns.ts`: em milissegundos, preenchidos pelo SQLite na inserção, com `updatedAt` renovado a cada atualização. Nunca os escreva à mão. `lesson_progress` precisa apenas do segundo, então recebe `updatedAt: timestamps().updatedAt`. Duas tabelas não têm timestamps: `rate_limit` guarda contadores de vida curta que têm seu próprio `expiresAt` e mudam a cada requisição, e `revoked_license_order` registra uma única vez cada pedido da Polar reembolsado, pelo seu ID.
- As chaves primárias são texto. Um caso de uso que insere uma linha preenche a chave com um UUID v7 (`v7()` de `uuid`); uma [tabela que espelha um provedor](#tables-that-mirror-a-provider) usa o ID do provedor no lugar.
- Colunas de enum recebem uma tupla montada a partir do objeto de constantes do módulo, nunca uma lista de literais. A tupla fica ao lado do objeto em `<table>.constants.ts`, porque os schemas Zod e o navegador também a leem, e esse arquivo não importa nada do Drizzle.
- Um texto que os visitantes leem em vários idiomas é uma coluna JSON `LocalizedText`, validada por `localizedTextSchema` e lida com `localize(text, locale)` de `src/modules/_core/utils/localized-text.ts`.
- Uma tabela nova é reexportada em `src/integrations/drizzle-orm/drizzle.schemas.ts`, e a sua migração é gerada com `bun run db:generate`. Veja [Migrações de banco de dados](/docs/guides/database-migrations).

## Tabelas que espelham um provedor [#tables-that-mirror-a-provider]

`order` e `subscription` guardam cópias dos pedidos e das assinaturas da Polar, gravadas apenas a partir dos dados da Polar e nunca editadas à mão. Uma tabela espelho segue o provedor onde as regras acima diriam outra coisa:

- A chave primária é o ID do provedor, uma coluna de texto com `POLAR_ID_MAX_LENGTH`, e as colunas usam os nomes de campo do provedor, como `customer_id`, `product_id` e `subscription_id`. Uma tabela nossa que aponta para o provedor prefixa o nome, como faz `license.polar_order_id`.
- Os horários do próprio provedor ficam ao lado de `...timestamps()`. `placedAt` é quando a Polar criou o pedido, e `changedAt` é a versão do registro da Polar que a linha guarda: o seu `modified_at` ou, enquanto ele nunca mudou, o seu `created_at`. `createdAt` e `updatedAt` continuam registrando quando o D1 gravou a linha.
- Colunas de enum recebem tuplas com os valores do provedor: `ORDER_STATUSES` em `order.constants.ts` lista `POLAR_ORDER_STATUS` de `src/integrations/polar/polar.constants.ts`, e um teste de tipos falha quando o SDK nomeia um valor que falta na tupla.
- Nenhuma coluna tem valor padrão além de `createdAt` e `updatedAt`, porque todo valor vem do provedor.
- `user_id` é `ON DELETE SET NULL`: excluir uma conta mantém os seus pedidos e assinaturas e remove apenas o vínculo.

`order` é uma palavra reservada do SQL. O Drizzle coloca aspas em todo identificador, então as suas consultas não precisam de nada; SQL bruto nomeia a tabela pelo objeto do schema, como `${order}` dentro de um template `sql`, nunca como `order` solto.

## Constantes

```ts title="src/modules/course/course.constants.ts"
export const COURSE_STATUSES = [COURSE_STATUS.DRAFT, COURSE_STATUS.PUBLISHED] as const

export const COURSE_STALE_MS = 60_000

export const COURSE_SHOWCASE = {
  COURSES: 5,
  LESSONS: 5,
} as const

export const COURSE_QUERY_KEYS = {
  ALL: ["course"],
  CATALOGUE: ["course", "catalogue"],
  DETAIL: ["course", "detail"],
  EDITOR: ["course", "getCourseEditor"],
  LIST: ["course", "getCourses"],
  SEARCH: ["course", "searchCourses"],
  SHOWCASE: ["course", "showcase"],
} as const

export const COURSE_MUTATION_KEYS = {
  CREATE: ["course", "createCourse"],
  DELETE: ["course", "deleteCourses"],
  EXPORT: ["course", "exportCourses"],
  IMPORT: ["course", "importCourses"],
  MOVE: ["course", "moveCourse"],
  REMOVE_COVER: ["course", "removeCourseCover"],
  REORDER_CURRICULUM: ["course", "reorderCurriculum"],
  UPDATE: ["course", "updateCourse"],
  UPLOAD_COVER: ["course", "uploadCourseCover"],
} as const
```

- Toda chave de query começa com o prefixo `ALL` do módulo, então um único `invalidateQueries({ queryKey: COURSE_QUERY_KEYS.ALL })` atualiza tudo o que o módulo serve. Veja [Busca de dados e cache](/docs/conventions/data-fetching).
- As chaves de mutation são o nome do módulo e o nome da server function.
- Os comprimentos de colunas e de entradas são nomeados aqui e compartilhados pelo schema e pelo schema Zod, como `PRODUCT_NAME_MAX_LENGTH` em `product.constants.ts`.
- `<MODULE>_VALIDATION_PARAMS` contém os números que as mensagens de validação interpolam, como `{ slugTooLong: { max: SLUG_MAX_LENGTH } }`.
- `scripts/repository-facts.ts` lê alguns arquivos de constantes, como `license.constants.ts`, enquanto o Vite carrega a própria configuração, quando o alias `~` ainda não é resolvido. Um arquivo assim importa outros arquivos do código-fonte por caminho relativo, como `license.constants.ts` importa `POLAR_WEBHOOK_EVENT` de `../../integrations/polar/polar.constants.ts`; as importações só de tipos são apagadas e podem manter o alias.

## Schemas Zod

```ts title="src/modules/chapter/chapter.zod.ts"
import * as zod from "zod"

import { localizedTextSchema, optionalLocalizedTextSchema } from "~/src/modules/_core/utils/localized-text"
import { idField } from "~/src/modules/_core/utils/zod-fields"

const chapterIdInput = zod.object({
  chapterId: idField,
})

const chapterFields = zod.object({
  summary: optionalLocalizedTextSchema,
  title: localizedTextSchema,
})

const createChapter = chapterFields.extend({ courseId: idField })

const deleteChapter = chapterIdInput

const updateChapter = chapterFields.extend(chapterIdInput.shape)

export const chapterZodSchemas = {
  createChapter,
  deleteChapter,
  updateChapter,
}
```

- `<table>.zod.ts` importa `* as zod from "zod"` e exporta um único objeto cujas chaves são os nomes das operações.
- Os formulários validam com os mesmos schemas no navegador, então `<table>.zod.ts` não importa nada do Drizzle nem de um `.schema.ts`. As tuplas de enum e os comprimentos vêm de `<table>.constants.ts`, que a tabela também importa, de modo que a coluna e o schema compartilham uma única definição. O build do cliente falha quando `drizzle-orm` chega ao navegador; veja [Mantenha o ORM fora do navegador](/docs/conventions/performance#keep-the-orm-out-of-the-browser).
- Nenhum schema Zod é derivado da tabela: nada valida uma linha inteira em tempo de execução, e os tipos de linha da interface do módulo vêm de `$inferSelect` e `$inferInsert`.
- Os campos vêm de `src/modules/_core/utils/zod-fields.ts` (`idField`, `localeField`, `slugField`) e de fragmentos compartilhados no mesmo arquivo, nunca declarados de novo em cada schema.
- As listas paginadas reutilizam `paginationSchema`; as operações sobre um único registro recebem um objeto como `{ courseId }`, nunca uma string solta.
- As mensagens de erro são chaves de tradução (`{ message: "slugInvalid" }`), renderizadas a partir do namespace `<table>.validations` do módulo. Veja [Formulários e tabelas](/docs/conventions/forms-and-tables).

## A interface do módulo

`<table>.types.ts` exporta exatamente uma interface, com o nome do módulo, cujas chaves espelham o objeto Zod:

```ts title="src/modules/lesson/lesson.types.ts"
export interface Lesson {
  select: typeof lesson.$inferSelect
  insert: typeof lesson.$inferInsert
  page: LessonPage
  detail: LessonPage["lesson"]
  attachment: LessonPage["lesson"]["attachments"][number]
  createLesson: zod.input<typeof lessonZodSchemas.createLesson>
  deleteLesson: zod.input<typeof lessonZodSchemas.deleteLesson>
  getLesson: zod.input<typeof lessonZodSchemas.getLesson>
  getLessonPlayback: zod.input<typeof lessonZodSchemas.getLessonPlayback>
  getLessonTitle: zod.input<typeof lessonZodSchemas.getLessonTitle>
  removeLessonVideo: zod.input<typeof lessonZodSchemas.removeLessonVideo>
  replaceLessonVideo: zod.input<typeof lessonZodSchemas.replaceLessonVideo>
  searchLessons: zod.input<typeof lessonZodSchemas.searchLessons>
  setLessonFormat: zod.input<typeof lessonZodSchemas.setLessonFormat>
  updateLesson: zod.input<typeof lessonZodSchemas.updateLesson>
}
```

As server functions, as mutation options e os formulários tipam a entrada como `Lesson["createLesson"]`. Ao adicionar um schema a `<table>.zod.ts`, adicione a chave dele aqui na mesma alteração. Nunca derive um tipo de entrada com `Parameters<typeof fn>[0]`, e nunca declare um alias local ou uma segunda interface `LessonInput`. Quando os componentes precisam da forma que uma leitura retorna, a interface também dá nome a ela, derivada da server function: `Course["listRow"]` é `Awaited<ReturnType<typeof getCourses>>["rows"][number]`.

## Casos de uso

Cada arquivo em `use-cases/` contém uma operação, com o nome da sua server function em kebab-case: `get-course-editor.ts` exporta `getCourseEditor` e `courseEditorQuery`, `update-course.ts` exporta `updateCourse` e `updateCourseMutation`. O padrão, o seu middleware e os seus erros estão em [Server functions e erros](/docs/conventions/server-functions). O [catálogo de módulos](/docs/reference/modules) e a [matriz de permissões](/docs/reference/permissions) mostram as tabelas de cada módulo, seus casos de uso e a chamada `authorized` de cada um, que `collectModuleTables` em `scripts/repository-facts.ts` lê do código no build, então um caso de uso novo aparece ali sem edição, e `src/__test__/module-tables.test.ts` falha quando o catálogo deixa de fora um arquivo de módulo fora do conjunto padrão.

Um caso de uso que roda apenas no servidor, chamado por um hook do Better Auth ou por um webhook da Polar, e não pelo navegador, é uma função `async` comum em um arquivo que começa com `import "@tanstack/react-start/server-only"`, como `license/use-cases/grant-license.ts` e os remetentes de e-mail `send-verify-email.ts`, `send-reset-password-email.ts` e `send-change-email-confirmation-email.ts`.

## Arquivos de aspecto

Quando uma tabela precisa de uma lógica que não é nem um caso de uso nem um helper puro, ela ganha um arquivo por aspecto, chamado `<table>.<concern>.ts`:

| Arquivo                                           | Aspecto                                                                                                             |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `course/course.outline.ts`                        | A estrutura de um curso publicado para um espectador, para `getCourse` e `getLesson`                                |
| `course/course.cover.ts`                          | Tamanhos, larguras, tipos aceitos e chaves de objeto da capa de um curso; puro                                      |
| `course/course.delivery.ts`                       | O handler do Worker `serveCover`, que serve as capas dos cursos                                                     |
| `course/course.objects.ts`                        | Remoção dos objetos da capa de um curso do R2                                                                       |
| `course/course.transfer.ts`                       | Exportação e importação de cursos como um único documento JSON                                                      |
| `lesson/lesson.access.ts`                         | Quem pode assistir a uma aula; puro, usado no servidor e nos testes                                                 |
| `lesson/lesson.playable.ts`                       | O join com o vídeo de uma aula que deixa de fora os vídeos provisórios                                              |
| `lesson-attachment/lesson-attachment.download.ts` | Assinatura das URLs de download dos materiais das aulas                                                             |
| `lesson-attachment/lesson-attachment.delivery.ts` | O handler do Worker para as requisições `/media/downloads/` assinadas                                               |
| `lesson-attachment/lesson-attachment.files.ts`    | Tipos de conteúdo, nomes de arquivo, chaves de objeto e campos de upload dos materiais das aulas                    |
| `lesson-attachment/lesson-attachment.objects.ts`  | Listagem e remoção dos objetos do R2 dos materiais das aulas                                                        |
| `lesson/lesson.viewer.ts`                         | Resolve no servidor o espectador autenticado e o acesso dele aos cursos, e registra uma aula paga que ele abre      |
| `order/order.polar.ts`                            | O desconto e o país de cobrança de um pedido da Polar, para `recordOrder` e `scripts/backfill-order-terms.ts`; puro |
| `license/license.webhooks.ts`                     | Handlers de webhooks da Polar, chamados por `license.polar-events.ts`                                               |
| `license/license.api.ts`                          | Os handlers da API de licenças da CLI, servidos por `src/routes/api/cli.v1.*.ts`                                    |
| `license/license.bundles.ts`                      | Assinatura das URLs dos pacotes de templates da CLI; as chaves de objeto deles                                      |
| `license/license.delivery.ts`                     | O handler do Worker para as requisições `/bundles/` assinadas                                                       |
| `license/license.ppp.ts`                          | O preço de um plano para o comprador no checkout, com o preço regional incluído                                     |
| `license/license.pricing.ts`                      | Faixas de preços regionais e o cookie de recusa; puro                                                               |
| `license/license.upgrade-price.ts`                | O preço de um upgrade, a partir dos pedidos de licença do cliente na Polar                                          |
| `license/license.upgrades.ts`                     | Quais planos são um upgrade e o upgrade que os metadados de um pedido registram; puro                               |
| `license/license.refunds.ts`                      | Se uma compra pode ser reembolsada, a partir dos registros dela; puro                                               |
| `withdrawal/withdrawal.contracts.ts`              | A licença ativa indicada por uma declaração de desistência e as condições de reembolso dela                         |
| `video/video.delivery.ts`                         | O handler do Worker para as requisições `/media/` assinadas                                                         |
| `video/video.playback.ts`, `video/video.files.ts` | Assinatura das URLs de reprodução; chaves de objeto e tipos de conteúdo                                             |
| `video/video.encoding.ts`                         | Renditions, duração dos segmentos e ajustes de qualidade da codificação de vídeo                                    |
| `account/account.links.ts`                        | Os links dos e-mails da conta, montados a partir da URL de callback                                                 |

Um arquivo que nunca pode chegar ao bundle do navegador começa com `import "@tanstack/react-start/server-only"`, como fazem `course.outline.ts`, `course.delivery.ts`, `course.objects.ts`, `course.transfer.ts`, `lesson.viewer.ts`, `lesson-attachment.delivery.ts`, `lesson-attachment.objects.ts`, `license.webhooks.ts`, `license.api.ts`, `license.delivery.ts`, `license.ppp.ts`, `license.upgrade-price.ts`, `order.utils.ts`, `withdrawal.contracts.ts`, `account.links.ts`, `video.delivery.ts` e `license.utils.ts` (que lê os IDs de produto da Polar, `POLAR_PRODUCT_IDS`, do ambiente do Worker). Arquivos puros como `lesson.access.ts` e `course.utils.ts` não importam nada do lado do servidor, então os componentes e os testes podem usá-los.
