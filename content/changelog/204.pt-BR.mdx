- Cada pull request adiciona a sua própria entrada do changelog, `content/changelog/<number>.<locale>.mdx`, em vez de editar esta página, então pull requests abertos ao mesmo tempo não colidem mais nos nove arquivos do changelog. Nenhuma entrada tem data: a página e as notas de versão tiram o dia de cada entrada, em UTC, do commit squash cujo assunto termina com `(#<number>)` e listam em **Não lançado** as que ainda não chegaram à `main`. As entradas existentes foram para arquivos próprios com os dias que o Git registra: #160 passa para 2026-11-14, #104, #111 e #115 para 2026-11-12, e doze entradas de 2026-11-15 para 2026-11-16; os antigos itens de **Anteriormente** ficam com a data 2026-09-24. Em um pull request, `bun run check` falha enquanto a sua entrada não existir. Veja [Entradas do changelog](/docs/conventions/git-workflow#changelog-entries).
