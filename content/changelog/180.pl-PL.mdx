- API licencji CLI: Worker serwuje paczkę szablonów każdego wydania, której `saasyland init` potrzebuje do wygenerowania projektu. `POST /api/cli/v1/activations/:activationId/bundles` sprawdza licencję oraz to, czy aktywacja należy do wywołującego urządzenia, a następnie odpowiada adresem URL HTTPS archiwum wydania w nowym buckecie R2 `BUNDLES` obszaru licencji, skrótem SHA-256 zawartości JSON archiwum (skrótem, który CLI przypina dla każdego wydania), rozmiarem archiwum i czasem wygaśnięcia adresu URL, przypadającym `API_LIMIT.BUNDLE_URL_TTL_SECONDS` po jego wydaniu. Na wydanie bez archiwum API odpowiada `versionNotFound`, a gdy bucketu nie da się odczytać, `serviceUnavailable`. Handler Workera obszaru licencji serwuje `/bundles/<expiry>.<signature>/<version>.json.gz` z R2, gdy termin ważności i HMAC okażą się poprawne, z kluczem, który HKDF wyprowadza z `AUTH_SECRET` wyłącznie dla paczek, więc poświadczenia S3 nie są potrzebne; wyprowadzanie klucza, którego używało odtwarzanie wideo, przeniesiono do `src/lib/hmac.ts`, z którego korzystają oba. Wydanie w repozytorium CLI przesyła każde archiwum do bucketu środowiska podglądowego i do bucketu produkcyjnego, a [Publikowanie paczek](/docs/features/cli-licence-api#publishing-bundles) podaje klucz, typ zawartości i buckety. Polityka prywatności mówi, że żądanie paczki wysyła wydanie i odpowiedzi opisujące stack, których API nie przechowuje.
