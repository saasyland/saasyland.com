## コンテンツ

記事は言語ごとに 1 ファイルずつ `content/blog/<slug>.<locale>.mdx` に置きます。`src/integrations/fumadocs/fumadocs.config.ts` のフロントマタースキーマでは `title`、`authorName`、`date` が必須で、`description`、`authorImage`、`excerpt`、`faq`、`featured`、`image`、`published`（既定値 `true`）、`tags`、`updated` を指定できます。タグは `src/data/blog.ts` の `BLOG_TAGS` のいずれかで、スキーマはそれ以外の値を拒否します。`PostRow` と `PostMeta` は各タグを `pages.blog` の `tags` にあるラベルで表示するため、タグはページの言語で読めます。

## コードから取る値

記事はコードが定義する値を手で書かずに表示します。件数、カバレッジのしきい値（`coverageThreshold`）、React のメジャーバージョン（`reactMajor`）、例示用の時給（`illustrativeHourlyRate`、`unit="currency"` 付き）、Core の価格に相当する時間（`corePriceInHours`、`unit="hour"` 付き）には `<RepositoryFact>` を、価格、端末数の上限、先行時間には `<TierPrice>`、`<ActivationLimit>`、`<HeadStartTable />` を使います。`title` と `faq` の質問と回答は ICU メッセージで、`src/lib/post-text.ts` の `formatPostText` が `REPOSITORY_FACTS` と各プランの `<tier>Price`、`<tier>Machines` で整形します。`formatPostText` は `src/data/cli.ts` の `CLI_GENERATION_VALUES` も渡すため、プロジェクト生成の提供開始で変わる文は `{generation, select, available {…} other {…}}` として一度だけ書き、`post-faq.test.ts` が両方の状態で表示を確認します。`billingGeneration`（`src/data/marketing.ts` の `BILLING_GENERATION`）、`src/data/affiliates.ts` の `affiliateProgram` と `affiliateHoldDays`、`refundWithdrawalDays`（`REFUND_TERMS.WITHDRAWAL_DAYS`）も渡し、同じテストが `billingGeneration` と `affiliateProgram` による分岐を両方のステータスで表示します。`toBlogPostSummary` がタイトルを整形し、`<PostFaq entries={frontmatter.faq} />` が FAQ を表示します。記事の FAQPage JSON-LD も同じ FAQ を読みます。`post-faq.test.ts` は各記事のタイトル、質問、回答をその言語で整形します。

## ソース

`fumadocs.source.ts` の `blogSource` は、ドキュメントと同じ i18n 設定でコレクションを `/blog` 配下に読み込みます。コレクションは `async` なので、Worker は各記事のフロントマターを保持し、コンパイル済みの MDX はリクエストが表示する記事の分だけ読み込みます。`getPublishedBlogPages(locale)` は、ある言語の公開済みの記事を、フロントマターをもとに新しい順に一覧にします。`toBlogPostSummary` は記事を読み込み、その言語向けに `Intl.Segmenter` で読了時間を計算します。`getPublishedBlogPosts(locale)` は、公開済みのすべての記事の概要を作ります。

## ルート

- `/blog` レイアウト（`_site._marketing.blog.tsx`）は `_site` と `_marketing` のレイアウトの中にあり、この 2 つがサイトヘッダー、`PageFrame`、`Footer`、`BackToTop` でその周囲を囲みます（[ランディングページ](/docs/features/landing-page#navigation-and-back-to-top)を参照）。記事のタイポグラフィ用に `docs.css` を読み込みます。ヘッダーは、一覧とすべての記事で **ブログ** を現在のセクションとして示します。ローダーは `fumadocs` と `pages.blog` を事前に読み込みます。
- `/blog`（`_site._marketing.blog.index.tsx`）は `PostRow` で記事を一覧表示します。一覧はルートファイル内で定義したサーバー関数から取得します。
- `/blog/$`（`_site._marketing.blog.$.tsx`）は記事を 1 件読み込み（未公開なら 404）、`blogContent` でコンパイル済みの MDX をプリロードし、`src/presentation/components/custom/blog` の `PostMeta`、`PostToc`（小さい画面では同じ見出しの `InlineTOC`）、`PostCta`、`PostShare` を組み合わせます。`buildBlogPostStructuredDataHtml` の JSON-LD と `buildPageHead` の記事メタデータを追加します。`article:section` には `pages.blog` のブログのタイトルが入り、記事ごとに専用のソーシャルカードが付きます。[検索エンジンとソーシャルプレビュー](/docs/features/seo)を参照してください。記事は MDX を Fumadocs の `RootProvider` で包み、検索とテーマの切り替えは無効、文言は `useFumadocsI18n` のものです。そのため、コードブロックと見出しのアンカーのコピーボタン、FAQ のアコーディオンの項目には記事の言語で名前が付きます。

ランディングページの Notes セクションには、おすすめ記事を優先して最新の 3 記事が表示され、概要が作られるのもその 3 記事だけです。

## 管理画面のブログ（デモ）

`/admin/blog` と `/admin/blog/create` は、`src/data/admin-blog.ts` のデモ記事と統計、および静的なエディターを表示します。`content/blog` の読み書きは行いません。

## チェック

記事を追加したら `bun run content` を実行します。`bun scripts/check-content.ts` は、すべての言語のファイルがあること、タイトル・説明・抜粋が翻訳されていること、コードブロックが同一であることを確認します。
