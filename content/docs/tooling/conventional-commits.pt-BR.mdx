---
title: "Conventional commits"
description: "Formato das mensagens de commit e o hook de emojis."
---

Os assuntos dos commits seguem `<type>(<scope>): <description>`. O escopo é opcional e `!` indica uma breaking change. Escreva o assunto sem emoji:

```sh
git commit -m "fix(auth): keep the locale in verification links"
```

O hook `prepare-commit-msg` em `.vite-hooks/` executa `bun scripts/commit-msg.ts`, que valida o assunto e adiciona como prefixo o emoji do seu tipo, de modo que o commit acima se torna `🐛 fix(auth): keep the locale in verification links`.

| Tipo       | Emoji |
| ---------- | ----- |
| `build`    | 🛠️    |
| `chore`    | ♻️    |
| `ci`       | ⚙️    |
| `docs`     | 📚    |
| `feat`     | ✨    |
| `fix`      | 🐛    |
| `perf`     | 🚀    |
| `refactor` | 📦    |
| `revert`   | 🗑️    |
| `style`    | 💎    |
| `test`     | 🚨    |

Qualquer outro tipo, ou um assunto fora do formato convencional, interrompe o commit e exibe a lista de tipos permitidos. O hook não altera assuntos que já começam com um emoji, que foram gerados pelo Git (`Merge`, `Revert "`, `fixup!`, `squash!`) nem mensagens de merge, squash e template.

Antes do hook de mensagem, o hook `pre-commit` executa `bun run check:pre-commit`. Não contorne os hooks.
