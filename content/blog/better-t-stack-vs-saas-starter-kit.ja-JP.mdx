## スタックは製品ではありません

Better-T-Stack の README は 4 つのラインの哲学を述べ、第 2 つは全体比較です:

> 自分のスタックをロール: 必要な部分だけをピックアップします。, 何も余分な.
> **最小限のテンプレート: ベアボーンは、ゼロブラットで足場を足場します。**
> 最新の依存関係: デフォルトでは、常に現在の安定したバージョンを使用します。
> 無料およびオープンソース:永久に。

隠されているのは制限ではありません。 それは設計であり、明白に述べ、そしてプロジェクトはそれが約束するものを丁度提供します。 証拠は上記の表の最後の行にあります: 出荷された例は **トード** そして、 **社会招聘**. . トードリストとチャット。 これらは、配線が動作する正式なデモンストレーションであり、その作業が配線であるツールの正しい例です。

なので、正直なフラミングは「無料ツールが欠けている機能」ではありません。それは:

**Better-T-Stack スタックを足場します。 A SaaSスターターキットは製品を足場します。**

どちらも足場です。 彼らは異なる行で停止します。Better-T-Stackは、フロントエンドがバックエンドを呼び出すことができ、バックエンドは、9つのフロントエンドと6つのバックエンドの選択で、データベース、タイプ安全に到達することができるときに停止します。 つまり、止まるのが望ましい場所であり、ほとんどの足場が止まるべき場所です。

SaaS 始動機は他の場所を止めます: 人がサインアップしたり、組織に参加したり、ロールを割り当てたり、毎月請求したり、メールを受信したり、混乱した時に管理者パネルで閲覧したりできます。 これらの2つの線のすべては、法案です。

## 時間がない部分

そのテーブルの4列を見てください。 **多テナントの分離、役割および権限、webhook idempotency、およびセッションの取消。**

他の行のどれも持っているプロパティを共有します。 **間違った実装は、レビューを通過し、開発で動作し、正しくデモを行います。**

クエリレイヤーの代わりにビューレイヤーに適用されるテナントフィルタは、1つのテナントと完全に機能します。 あなたの備品は1つのテナントを持っているので、それはあなたのテストで完全に動作します。 2番目の顧客のデータが最初の顧客のダッシュボードに表示され、バグレポートではなく、電話電話です。

あなたが同じイベントを2回送らないので、あなたがそれをテストするたびに、出没鍵なしでWebhookハンドラが機能します。 Stripeは、再試行で、そして誰かが2回、または2回計画を与えられた。

データベースから再読み込みするのではなく、セッションからロールを読み込む権限チェックは、誰かがデモされ、古いセッションを保持するまで行われます。

これらは難しい問題ではありません。 彼らは問題です。 **それが高価であるまで間違っていることは見えない**「これは40時間かかります」から完全に異なるリスクプロファイルである。 あなたはあなたが時間を必要としていないので、あなたはより多くの時間でそれらのうち、あなたの方法を購入することはできません。 誰かがすでに間違いを犯し、それを修正した基礎から始めて、それが戻ってくると失敗するテストが現在存在するところからそれらを避けます。

つまり、時間数ではなく、有料のスターターキットが実際にあることです。

## 有料の側面がコンクリートのように見えるもの

抽象的ではなく、具体的には、このコードベースで「すでに解決された」手段であり、数値はマーケティングファイルではなく、テストの実行から読み出します。

**カバレッジバッジではなくカバレッジゲート。** 141 のテストファイル、472 のテスト、および 4 つの閾値の設定:

```ts
coverage: {
  thresholds: { branches: 100, functions: 100, lines: 100, statements: 100 },
}
```

前のセクションのエラーブランチは、テストする100つの力でブランチ・カバレッジ・ゲートが正確に何であるかです。 つまり、数ではなく、機構です。

**コンパイラのアーキテクチャは同意します。** 3つのlintルールにより、モジュールの境界が実行可能になります。

```ts
// vite.config.ts, abridged
lint: {
  options: { typeAware: true, typeCheck: true },
}
```

データベースクエリを React コンポーネントに入れることができません。 ビルドが失敗し、理由を伝えます。

**エスケープハッチなしの厳密さ。** `strict`、プラス `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, `noPropertyAccessFromIndexSignature` そして、 `verbatimModuleSyntax`. `typescript/no-explicit-any` エラーで、linter が実行されます。 `denyWarnings: true`ですから、無視できる警告はありません。

**オプション機能、固定テンプレートではありません。** ザ・オブ・ザ・ザ・ [コンフィギュレータ](/#cli) 12個の質問を聞き、サンプル製品、サブスクリプションコース、ビジュアルページビルダー、ビジュアルポストエディタ付きの4つのエキストラを提供しています。 モジュールを追加して 1 つをオンにします。 削除すると、コードがリポジトリに存在しないことを意味します。

どれもBetter-T-Stackの批判です。 2つの製品が止まる場所の説明です。

## Better-T-Stackが正しい答えであるとき

常に有料オプションをお勧めする比較は、比較ではなく広告であるため、適切に述べられます。

- あなたはプロトタイピングであり、物事は月に存在しないかもしれません。

## よくある質問

<Accordions>

<Accordion title={"Better-T-Stack無料ですか?"}>

はい。 MIT がライセンスされ、その README は "free and open source: forever" にコミットします。 書き込み時に 5,636 GitHub 星とおよそ 2,476 npm が週ダウンロードされます。 あなたがそれを使用してはならないこの記事の論争には何もありません、そして読者の大きなシェアのためにそれは正しい選択です。

</Accordion>

<Accordion title={"Better-T-Stackは実際に足場ですか?"}>

スタック。 React、Next.js、Nuxt、Svelte、Solid、Astro、React Native からのフロントエンド。 Hono、Express、Fastify、Elysia、Convex からのバックエンド。 tRPC または oRPC; Bun、Node または Cloudflare Workers; SQLite、 Postgres、MySQL または MongoDB; Drizzle、 Prisma または Mondoose; 必要に応じて Better Auth または Clerk。 これらは、真面目で困難な仕事である、正しく、タイプ安全に繋がる。

</Accordion>

<Accordion title={"Better-T-Stack は含まれていませんか?"}>

請求、トランザクションメール、管理者パネル、ロールおよび権限、マルチテナント、国際化、コンポーネントライブラリ、テストスイート。 これは、プロジェクトが述べた哲学は「最小限のテンプレート:ゼロの膨らみを持つベアボーンの足場」であり、その唯一の出荷例はTodoアプリとAIチャットです。

</Accordion>

<Accordion title={"有料のSaaSボイラープレートは、無料 CLIが存在するときに価値がありますか?"}>

削除する作業が、そうしないと動作している場合だけ。 auth フローの構築、または製品が請求を必要としない、またはすでに内部ライブラリがすべてある場合は、無料 CLI は厳密に優れています。 組織を再構築する場合, 役割, webhooks と 3 回目の管理者, 200 以上の時間に対する数百ドルは、近い呼び出しではありません.

</Accordion>

<Accordion title={"足場プロジェクトに請求を追加するにはどれくらいの時間がかかりますか?"}>

チェックアウトは午後に行われます。 請求は25〜40時間かかります。チェックアウトは簡単な10秒です。残りの部分は、プロレーション、アップグレード、ダウングレード、ダニング、請求書履歴、不法なWebhook処理、およびあなたが受け取らないWebhookをキャッチする調整ジョブです。 初回の支払いは、確実に請求できるものと同じではありません。

</Accordion>

<Accordion title={"Better-T-Stackと有料のスターターキットを一緒に使うことはできますか?"}>

同じプロジェクトでは、基礎を生成し、一つの基盤だけを得るので、有用ではありません。 彼らは異なるプロジェクトに適合しています。 多くの開発者は、プロトタイプや内部ツール用の無料の足場と、お金を稼ぐ必要がある製品のための有料の基礎を使用しています。これは矛盾ではなく、賢明な配分です。

</Accordion>

<Accordion title={"Better-T-Stack には認証が含まれていますか?"}>

オプションで、配線ステップとして: Better Auth または Clerk を設定できます。 サインインして、正しく設定されているサインインします。 組織、招待状、席数、ロールゲーテッドアクション、強化された2要素、サポートやセッションの取消に対する偽装、ライブラリの上部にある個別の機能がすべて取得しません。

</Accordion>

<Accordion title={"AI のコーディングの代理店にとっては、どれが良いですか?"}>

両方とも良い出発点であり、異なる理由で。 最小限の足場は、エージェントに小さなコンテキストを与え、混乱させるものはありません。 強化された境界を持つ大きな基盤は、その作業例と、それが漂流したときに失敗するビルドを与えます。 最悪のオプションは、readme にのみ存在する大きなコードベースです。

</Accordion>

<Accordion title={"有料スターターキットは何時間保存されますか?"}>

請求、役割、管理者とマルチテナント SaaS の場合、この記事の項目化された範囲は、有能な作業の 280 から 465 時間です。 1つのStripeのチェックアウトでシングルユーザーツールの場合、それは20に近いです。 正直な番号は、あなたが構築しているものに完全に依存します。つまり、テーブルがあなたのために合計されるのではなく、アイテム化される理由です。

</Accordion>

<Accordion title={"自分で構築すれば良いですか?"}>

配管があなたが学びたいと思うものであるとき、あなたの製品はスターターの前提があなたを戦うか、またはあなたの時間が本当に機会の費用がないとき、あなたの製品が十分に奇妙なとき、自分で構築してください。 既に一度にビルドして3四半期の退屈期間を正確に覚えているときに購入します。

</Accordion>

</Accordions>
