title: "Arquivos de rota"
description: "A forma única de uma rota de página e de uma rota de layout: NAMESPACE ou NAMESPACES, um loader com um único Promise.all, um esqueleto que reproduz a página, schemas de busca e links."
---

Todo arquivo em `src/routes` tem a mesma forma, então quem conhece um conhece todos. Um arquivo de rota compõe: ele declara do que a página precisa e posiciona os componentes. Widgets, formulários, diálogos e colunas de tabela ficam em `src/presentation/components/custom`.

## Rotas de página

`src/routes/admin.courses.index.tsx`:

```tsx title="src/routes/admin.courses.index.tsx"
const CoursesPage = (): JSX.Element => {
  const t = useTranslations("pages.admin.courses")
  const queryClient = useQueryClient()
  const errorMessage = useErrorMessage()
  const columns = useCourseColumns()

  const move = useMutation({
    ...moveCourseMutation,
    onError: (error) => {
      toast.error(errorMessage(error))
    },
    onSettled: () => queryClient.invalidateQueries({ queryKey: COURSE_QUERY_KEYS.ALL }),
    scope: COURSE_ORDER_SCOPE,
  })

  return (
    <div className="flex w-full animate-in flex-col space-y-8 duration-500 fade-in-50">
      <AdminPageHeader
        actions={
          <>
            <ImportCoursesDialog />
            <ExportCoursesButton />
            <LinkButton className="h-9 gap-2" to={ROUTES.ADMIN_COURSES_CREATE} size="sm">
              <PlusCircle aria-hidden className="size-4" />
              {t("actions.create")}
            </LinkButton>
          </>
        }
        description={t("description")}
        title={t("title")}
      />

      <DataGrid
        bulkActions={(rows) => <DeleteCoursesButton courses={rows} />}
        columns={columns}
        empty={t("table.empty")}
        emptyDescription={t("table.emptyDescription")}
        id={COURSE_GRID_ID}
        label={t("title")}
        onReorder={({ offset, row }) => move.mutateAsync({ courseId: row.id, offset })}
        query={(request) => getCoursesPageQuery(courseZodSchemas.getCourses.parse(request))}
        rowActions={CourseActions}
        search={t("table.search")}
        selectable
      />
    </div>
  )
}

const NAMESPACE = "pages.admin.courses"

export const Route = createFileRoute("/admin/courses/")({
  component: CoursesPage,
  head: pageHead(ROUTES.ADMIN_COURSES),
  loader: async ({ context }) => {
    const locale = getCurrentLocale()
    const [metadata] = await Promise.all([
      loadPageMetadata({ locale, namespace: NAMESPACE }),
      preloadNamespaces({ locale, namespaces: [NAMESPACE], queryClient: context.queryClient }),
      context.queryClient.query({ ...getCoursesQuery, staleTime: "static" }),
    ])
    return { locale, metadata }
  },
  pendingComponent: AdminCoursesPending,
  staticData: { namespaces: [NAMESPACE] },
})
```

- **O componente** é uma `const` local chamada `<Name>Page`, definida primeiro. Uma marcação pequena usada apenas por esta página pode ficar acima dele como componentes locais, como `CourseProgress` e `StartLink` em `_site._marketing.courses.$course.index.tsx`; tudo o que tem dados, mutation ou estado próprios vai para um arquivo de componente.
- **Um namespace.** `const NAMESPACE = "pages.<area>.<page>"` fica logo acima de `export const Route` e é usado em `loadPageMetadata`, `preloadNamespaces` e `staticData`. Todo o resto de que a página precisa é declarado pelo seu layout.
- **Um `Promise.all`.** O loader inicia todo o trabalho de uma vez: os metadados da página, o namespace e todas as queries que os componentes leem. Ele retorna `{ locale, metadata }` para `head`. Nunca aguarde um deles antes de iniciar o próximo.
- **`head: pageHead(ROUTES.X)`** monta o título, a descrição, a URL canônica e os links alternativos a partir dos metadados do arquivo de namespace.
- **Os caminhos vêm de `ROUTES`**, em `src/routes.ts`, que reúne os caminhos de todas as áreas (veja [Caminhos e navegação](#paths-and-navigation)); nunca escreva um literal de caminho.

Uma página cujo título vem de um registro aguarda esse registro e monta o seu head a partir dos dados do loader, como faz `admin.courses.$courseId.tsx`:

```tsx title="src/routes/admin.courses.$courseId.tsx"
export const Route = createFileRoute("/admin/courses/$courseId")({
  component: CourseEditorPage,
  head: ({ loaderData }: { loaderData?: { locale: SupportedLocale; pathname: string; title: string } | undefined }) =>
    buildPageHead({ locale: loaderData?.locale, pathname: loaderData?.pathname ?? ROUTES.ADMIN_COURSES, title: loaderData?.title }),
  loader: async ({ context, params }) => {
    const locale = getCurrentLocale()
    const data = await context.queryClient.query(courseEditorQuery({ courseId: params.courseId })).catch(rethrowAsNotFound)
    return { locale, pathname: `${ROUTES.ADMIN_COURSES}/${data.course.id}`, title: localize(data.course.title, locale) }
  },
  pendingComponent: AdminCourseEditorPending,
})
```

## Rotas de layout

`src/routes/admin.courses.tsx`:

```tsx title="src/routes/admin.courses.tsx"
const NAMESPACES = ["course.validations", "pages.admin.courses"] as const

export const Route = createFileRoute("/admin/courses")({
  loader: ({ context }) => preloadNamespaces({ locale: getCurrentLocale(), namespaces: NAMESPACES, queryClient: context.queryClient }),
  pendingComponent: AdminCourseSectionPending,
  staticData: { namespaces: NAMESPACES },
})
```

- Um layout declara `const NAMESPACES = [...] as const` acima de `export const Route` e os pré-carrega. Quando não tem nenhum, ele omite a opção; não existe `namespaces: []`.
- Um layout nomeia todos os namespaces de que as suas páginas e os componentes delas precisam, inclusive os de outras funcionalidades, como strings simples nos seus `NAMESPACES`. `/app` lista `pages.license`, `pages.withdrawal` e `withdrawal.validations`, porque a sua visão geral mostra o card da licença e a oferta e a sua página de licença mostra o card de desistência; `/admin/users` lista `pages.admin.customers`, `pages.admin.orders` e `pages.admin.users.license`; e `/_site/_marketing` e `/_site/docs` listam `auth.validations`, porque os seus rodapés mostram o formulário da newsletter, e o layout de marketing lista também `withdrawal.validations`. Deixar uma funcionalidade de fora apaga os seus arquivos de mensagens, e a regra de poda apaga cada string que nomeia um deles ([Testes](/docs/conventions/testing#tests-follow-the-areas)).
- O componente, quando o layout renderiza um, se chama `<Name>Layout` e posiciona um `<Outlet />`.
- Um guard vai em `beforeLoad`, no layout que é dono da área: `beforeLoad: requireAdmin` em `admin.tsx`, `requireSignedIn` em `app.tsx`, ambos layouts da área de autenticação. Os guards decidem apenas a navegação; toda server function continua verificando a sua própria permissão.

## Ordem das opções

`sort-keys` fica desativado em `src/routes` porque o TanStack Router infere os tipos na ordem de declaração. As opções ficam em ordem alfabética, exceto `validateSearch`, que vem primeiro, antes de tudo o que lê os search params:

```tsx title="src/routes/auth.reset-password.tsx"
export const Route = createFileRoute("/auth/reset-password")({
  validateSearch: authSearchSchema.extend({
    error: searchText(),
    token: searchText(),
  }),
  component: ResetPasswordPage,
```

Nunca escreva um array ou um objeto de dados diretamente dentro de `createFileRoute`; declare-o como uma constante acima.

## Search params

`validateSearch` é um `zod.object` montado com os helpers de `src/lib/search-params.ts`:

| Helper                            | Valor quando o parâmetro está ausente ou malformado | Uso                                    |
| --------------------------------- | --------------------------------------------------- | -------------------------------------- |
| `searchText()`                    | `undefined`                                         | Tokens, e-mails, códigos de erro       |
| `searchFlag()`                    | `undefined`                                         | Booleanos                              |
| `searchParam(schema)`             | `undefined`                                         | Qualquer outro schema, como um caminho |
| `searchChoice(choices, fallback)` | `fallback`                                          | Uma aba ou uma visualização            |

Um texto ausente continua `undefined`, então um valor padrão nunca vaza para uma URL que o router monta. Um parâmetro `searchChoice` vem acompanhado de `search: { middlewares: [stripSearchParams({ tab: DEFAULT_TAB })] }`, que remove o valor padrão da URL. Uma página para a qual outro site devolve os visitantes declara também `search: { middlewares: [onlyDeclaredSearch(schema)] }` com o próprio schema, como `/app` e `/app/license` fazem para o checkout da Polar: o router passa a montar o endereço só com os parâmetros declarados, e o servidor redireciona um endereço com qualquer outro parâmetro para o mesmo endereço sem ele, antes que uma verificação ou a página o leiam. Nunca escreva à mão verificações como `typeof search["x"] === "string"`; adicione um helper quando for necessário um novo tipo de campo. Quando um filho precisa de um parâmetro que a página validou como presente, a página o restringe e o repassa, como `auth.reset-password.tsx` repassa `token` para `ResetPasswordForm`. Páginas que leem os mesmos parâmetros compartilham um schema em `src/data`, que os seus esqueletos também analisam, como fazem `/app/license` e a parte da visão geral que a área de licenças adiciona com `licenseSearchSchema` (`src/data/license.ts`).

## Esqueletos

A navegação precisa parecer instantânea, então toda rota que renderiza uma página tem um `pendingComponent` que a reproduz: o mesmo layout, os mesmos cards e o mesmo número de linhas.

- Os esqueletos ficam no arquivo de esqueletos da área (`admin/products-pending.tsx`, `courses/courses-pending.tsx`) e usam o `Skeleton` do shadcn.
- Os esqueletos ficam no script de entrada de toda página, então um esqueleto importa `Skeleton`, as primitivas do shadcn, outros esqueletos e as constantes que definem os seus comprimentos, nunca um formulário nem o arquivo que contém um; `pending-imports.test.ts` falha quando algum chega a `@tanstack/react-form` (veja [Desempenho](/docs/conventions/performance#skeletons-stay-in-the-entry-script)).
- Um placeholder de texto recebe o token tipográfico real mais `h-lh scale-y-70`, para ter a altura da linha que substitui: `<Skeleton className="h-lh w-28 scale-y-70 text-label" />`.
- O comprimento das listas vem das constantes que a página usa: `DataGridPending` em `data-grid-pending.tsx` desenha por padrão `DEFAULT_PAGE_SIZE` linhas, o tamanho de página de todas as tabelas da administração.
- Um esqueleto de layout renderiza o `pendingComponent` da primeira rota abaixo do layout que corresponde ao caminho atual e define um, que `usePagePending(layout)` em `src/hooks/use-page-pending.ts` lê da árvore de rotas: `AdminPending`, `AppPending`, `AuthPending` e `MarketingPending` para os seus layouts, e `AdminUsersPending` e `AdminCourseSectionPending` um nível abaixo. Por isso, a rota de uma página é o único lugar que nomeia o seu esqueleto, seja qual for o layout que o mostre; `/admin/users`, que redireciona para `/admin/users/all`, define o esqueleto dessa página.
- Não existe um `defaultPendingComponent` para todo o router. `src/router.tsx` define `defaultPendingMs` como <RepositoryFact name="navigationPendingMs" unit="millisecond" /> e `defaultPendingMinMs` como <RepositoryFact name="navigationPendingMinMs" unit="millisecond" />, ambos de `src/data/navigation.constants.ts`: uma navegação que não terminou até lá mostra o esqueleto da rota, e o esqueleto some assim que a página fica pronta, sem ficar na tela nem um instante a mais. As rotas mantêm esses valores; veja [Desempenho](/docs/conventions/performance#a-slow-navigation-shows-its-skeleton-at-once) para as medições por trás deles.
- As páginas da documentação desenham os seus esqueletos dentro do layout da documentação: `DocsIndexPending` e `DocsPagePending` preenchem as áreas da grade do artigo e do sumário do Fumadocs, então uma navegação entre páginas da documentação mantém a barra lateral na tela. O componente da página renderiza o MDX no próprio `<Suspense key={path}>`, então a barra lateral funciona antes de o chunk MDX da página carregar, e uma navegação substitui o HTML do servidor da página anterior em vez de hidratá-lo com os dados da próxima.

## Links

- Os links do router recebem uma constante: `<Link to={ROUTES.COURSES}>`, `<Link hash={MARKETING_SECTION_IDS.PRICING} to={ROUTES.HOME}>`, ou um padrão de rota com `params` para caminhos dinâmicos. O `LinkButton` e o `SidebarMenuLink` do shadcn recebem `to` da mesma forma, e o `AnchorButton` recebe um `href` para um endereço fora da árvore de rotas.
- Nunca adicione o prefixo de locale a um link do router; o rewrite do router o adiciona. Uma URL completa no locale atual, para um valor que sai do router como string, vem de `router.buildLocation({ ... }).publicHref`, como `use-auth-redirect.ts` monta os seus links de login. `localizePathname` é para URLs montadas fora de um contexto de router ou para outro locale: e-mails, destinos de redirecionamento do Better Auth, links dentro de MDX e o seletor de idioma.

## Caminhos e navegação [#paths-and-navigation]

Cada caminho e cada item de menu é escrito uma única vez, em uma única lista, e uma funcionalidade que pode ficar de fora, como os cursos, os produtos ou as páginas legais, entra nessa lista como um elemento que nomeia o próprio caminho. Deixar a funcionalidade de fora apaga os seus arquivos e os seus nomes e, com eles, cada elemento que nomeia um deles, então as listas não precisam de um arquivo por funcionalidade nem de barrel. É assim que a CLI `saasyland` monta um projeto a partir de camadas de templates. Só `scripts/areas.ts`, que a aplicação nunca carrega, lista as áreas opcionais com os seus arquivos e os caminhos que lhes pertencem, para que `bun run check:areas` possa checar os tipos do site sem cada uma delas ([Testes](/docs/conventions/testing#tests-follow-the-areas)).

| O quê                                             | Declarado em                                                                                                                                                                                                         | Lido de                                                                                          |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Caminhos                                          | `src/routes.ts`: um `export const` por caminho                                                                                                                                                                       | `import * as ROUTES from "~/src/routes"`                                                         |
| Caminhos não listados                             | `UNLISTED_ROUTES` em `src/routes.ts`                                                                                                                                                                                 | `isUnlistedRoute` em `src/routes.ts`                                                             |
| Itens de menu                                     | `ADMIN_NAVIGATION`, `ADMIN_COMMAND_ACTIONS`, `ADMIN_DASHBOARD_ACTIONS`, `APP_NAVIGATION`, `APP_RESOURCE_NAVIGATION`, `HEADER_NAVIGATION` e `FOOTER_NAVIGATION` em `src/data/navigation.ts`, na ordem em que aparecem | As barras laterais, o cabeçalho, o rodapé, a paleta de comandos e o painel                       |
| Namespaces de layout                              | `NAMESPACES` na rota de layout                                                                                                                                                                                       | O loader e o `staticData` do layout                                                              |
| Listas do console de administração e do workspace | `DASHBOARD_STATS`, `DASHBOARD_PANELS`, `COMMAND_SEARCHES`, `USER_TABS`, `USER_PROFILE_SECTIONS` e `ACCOUNT_DELETION_NOTICES`, cada uma no componente que a renderiza                                                 | Esse componente, o seu esqueleto e a rota que carrega os seus dados                              |
| Verificações do site no ar                        | `LIVE_SITE_CHECKS` em `src/lib/deployment.ts`                                                                                                                                                                        | `verifyDeployment` ([Plataforma e testes](/docs/architecture/platform-layer#what-the-areas-add)) |

`src/routes.ts` declara todos os caminhos e não importa nada, porque todo ambiente de execução o carrega: o navegador, o Worker a cada cold start, os scripts do Bun, o Playwright, o `vite.config.ts` e o projeto do Remotion. Cada arquivo o importa como um único namespace, `import * as ROUTES from "~/src/routes"`, então cada caminho mantém o seu tipo literal e `<Link to={ROUTES.COURSES}>` continua sendo verificado contra a árvore de rotas. Um caminho construído a partir de outro, como `BLOG_FEED` a partir de `BLOG`, vem logo depois daquele de que é construído.

As listas às quais uma área ainda adiciona itens em um arquivo próprio, os handlers do Worker e os plugins do Vite, mantêm os seus barrels por enquanto. Um barrel contém só linhas `export { … } from`, uma por arquivo de área, ordenadas por módulo, como `src/integrations/drizzle-orm/drizzle.schemas.ts`.

`src/data/navigation.ts` contém os sete menus como listas literais, cada item com a sua página em `to`, a chave completa da sua mensagem em `label` e, no console de administração e no workspace, o seu ícone do `lucide-react`. O menu do admin agrupa os seus itens sob um grupo da barra lateral, com `key` de `ADMIN_NAVIGATION_GROUP`, e o rodapé agrupa os seus links sob uma coluna, com `key` de `FOOTER_COLUMN`. O arquivo importa apenas `lucide-react`, `~/src/routes` e `~/src/data/navigation.constants`, porque o projeto do Remotion lê o menu do admin e o seu job de CI só instala os pacotes do próprio Remotion; `src/__test__/source-layout.test.ts` falha quando ele importa qualquer outra coisa. O console de administração e o workspace do cliente só existem com login, então os seus itens nomeiam os caminhos da área de autenticação e saem junto com ela, assim como **Entrar** no cabeçalho e no rodapé:

```ts title="src/data/navigation.ts"
export const HEADER_NAVIGATION: readonly SiteEntry[] = [
  { hash: MARKETING_SECTION_IDS.PRICING, label: "navigation.core.header.pricing", to: ROUTES.HOME },
  { label: "navigation.courses.header.courses", to: ROUTES.COURSES },
  { label: "navigation.content.header.blog", to: ROUTES.BLOG },
  { label: "navigation.content.header.docs", to: ROUTES.DOCS },
  { label: "navigation.auth.header.signIn", signedIn: { label: "navigation.auth.header.account" }, to: ROUTES.SIGN_IN },
]
```

Um projeto sem os cursos não tem `ROUTES.COURSES`, então a regra de poda apaga o item **Cursos** do cabeçalho, e um grupo ou uma coluna que fique vazio sai junto, como acontece com a coluna jurídica do rodapé em um projeto sem as páginas legais.

Uma entrada do cabeçalho ou do rodapé pode indicar um rótulo `signedIn` que substitui o seu para um visitante logado, e o seu link passa a levar ao espaço de trabalho desse visitante: `/admin` para uma conta com acesso de administrador, `/app` para todas as outras. `Navigation`, `MobileMenu` e `Footer` leem os dois menus de `useSiteNavigation` (`src/hooks/use-site-navigation.ts`), que coloca as entradas `signedIn` assim que conhece o espaço de trabalho do visitante e, senão, devolve as listas sem alterações. Ele recebe o espaço de trabalho do único hook do seu `WORKSPACE_HOOKS`, `useVisitorWorkspace` (`src/hooks/use-visitor-workspace.ts`), que decide pelo papel da sessão, com `hasPermission` e a permissão `admin: ["access"]` que `requireAdmin` verifica; um projeto sem login não tem nenhum hook, então os seus menus ficam sem alterações. As páginas públicas são pré-renderizadas, então o HTML delas mostra **Entrar**; depois da hidratação, um navegador que tem o cookie do Better Auth com o último método de login pede a sua sessão, e o cabeçalho, o menu móvel e o rodapé mostram **Sua conta** no lugar, já com o link para o espaço certo. Um navegador que nunca fez login não pede nada. Até que uma parte da página tenha sido hidratada, `useVisitorWorkspace` não retorna nada, mesmo quando o navegador já tem a sessão, porque `useHydrated` responde com o valor do servidor enquanto o React hidrata: um rodapé que hidrata depois de a sessão chegar mostra o mesmo **Entrar** do HTML e muda depois, em vez de quebrar a hidratação.

Toda entrada do admin abre uma tela que funciona com dados reais, e a landing page conta todas elas. Uma tela cujos dados ainda não têm fonte não recebe entrada (veja [Painel administrativo](/docs/features/admin-dashboard#real-data-only)).

A barra lateral do app do cliente traz o item **Licença**, da área de licenças, e os seus recursos trazem **Documentação**, da área de conteúdo, acima do endereço de suporte. A base só precisa de `/` e `/api`, e do item **Preços** do cabeçalho, o único com `hash`, que leva à seção de preços de `/`.

Uma estatística do painel em `DASHBOARD_STATS` tem um `prefetch`, que o loader de `/admin` executa, e um hook `useValue`, que `DashboardStats` chama para ler o número.

`APP_STATEMENTS`, em `auth.access.ts`, define as declarações de permissão, uma por recurso, e `scripts/areas.ts` nomeia as declarações de uma funcionalidade que pode ficar de fora, como `APP_STATEMENTS.course`, para que deixá-la de fora as apague (veja [Papéis e permissões](/docs/guides/roles-and-permissions)).

As listas de `src/data/navigation.ts` têm um tipo declarado em `src/data/navigation.constants.ts`, como `IconEntry` ou `SiteEntry`, então uma lista cujos itens um projeto deixa de fora, como as ações do painel sem a área de pagamentos, é uma lista vazia que continua passando na verificação de tipos. `navigation.test.ts` verifica que o `to` de cada item é um caminho da árvore de rotas e que nenhum menu nomeia uma página ou um rótulo duas vezes.

O `label` de um item é a chave completa da sua mensagem, como `navigation.courses.admin.courses`, e a mensagem fica no arquivo da funcionalidade dona da página, `messages/<locale>/navigation.<area>.json`, então deixar a funcionalidade de fora apaga os seus rótulos junto. Um componente o renderiza com `t(entry.label)` de `useTranslations()`. Uma seção do admin rotula as suas subpáginas para a trilha de navegação no `breadcrumbs` do seu item, do segmento do caminho para a chave, como `create` para `navigation.courses.breadcrumbs.create`. Uma aba da gestão de usuários, uma busca da paleta de comandos e uma estatística do dashboard também indicam a chave completa do seu rótulo, como `navigation.team.userTabs.invitations`, `navigation.auth.search.users` e `dashboard.courses.learners`, e um painel do dashboard lê os seus textos sob a sua `key` em `dashboard.<area>.json`. Os dois tipos de arquivo são namespaces raiz, então qualquer menu pode rotular qualquer item. O que pertence ao próprio menu fica no namespace dele: `groups.<group>` em `pages.admin.sidebar`, `columns.<column>` em `components.custom.footer` e, do cabeçalho, a chamada para ação, o botão do menu e o link de pular para o conteúdo em `components.custom.navigation`. `navigation.test.ts` falha quando falta em algum locale a mensagem de um item, de uma variante para quem está logado, de um item da trilha de navegação, de uma aba da gestão de usuários ou de uma busca da paleta de comandos, e `admin-dashboard.component.test.tsx` quando falta a de uma estatística.

As páginas renderizadas no Worker a cada requisição, como `/admin`, `/auth` ou `/courses`, ficam listadas em `UNLISTED_ROUTES`, em `src/routes.ts`. O plugin do TanStack Start em `src/data/tanstack.vite.ts` as deixa fora da pré-renderização com `isUnlistedRoute`, e `buildPageHead` lhes dá o card do site em vez de um card de página (veja [Busca e prévias em redes sociais](/docs/features/seo)). O Vite não resolve o alias `~` enquanto carrega a própria configuração, por isso `tanstack.vite.ts` importa `src/routes.ts` por caminho relativo.
