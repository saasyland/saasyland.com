title: "Migracje bazy danych"
description: "Zmień schemat Drizzle, wygeneruj migrację SQL i zastosuj ją w każdej bazie D1."
---

Bazą danych aplikacji jest Cloudflare D1 (SQLite). Schematy modułów używają `drizzle-orm/sqlite-core`, `src/integrations/drizzle-orm/drizzle.schemas.ts` je zbiera, a drizzle-kit zapisuje migracje w `src/integrations/drizzle-orm/migrations/` z prefiksem znacznika czasu.

## Przebieg

1. Zmień `<table>.schema.ts`. Nową tabelę wyeksportuj także z `drizzle.schemas.ts`.
2. Wygeneruj SQL:

```sh
bun run db:generate
```

3. Przejrzyj wygenerowany plik i zatwierdź go razem ze zmianą schematu.
4. Zastosuj go w bazie, z którą pracujesz. `deploy:preview`, `deploy:production` i CI stosują go w bazie preview lub produkcyjnej przed wdrożeniem.

## Polecenia

| Polecenie                       | Baza danych                                                                           |
| ------------------------------- | ------------------------------------------------------------------------------------- |
| `bun run db:migrate:local`      | Lokalna baza deweloperska w `.wrangler/state`, używana przez `bun run dev`            |
| `bun run db:reset:local`        | Usuwa lokalną bazę deweloperską, a potem ponownie ją migruje                          |
| `bun run db:migrate:test`       | Lokalna baza testowa w `.wrangler/test`, używana przez Playwright i izolowany podgląd |
| `bun run db:reset:test`         | Usuwa `.wrangler/test`, a potem ponownie migruje i zasila danymi lokalną bazę testową |
| `bun run db:migrate:preview`    | Zdalna baza podglądu                                                                  |
| `bun run db:migrate:production` | Zdalna baza produkcyjna                                                               |

`bun run db:migrations:local`, `db:migrations:preview` i `db:migrations:production` wyświetlają migracje, których baza danych jeszcze nie zastosowała. `bun run db:studio:local` otwiera Drizzle Studio na pliku lokalnej bazy danych. `db:studio:preview` i `db:studio:production` otwierają je na zdalnej bazie danych, a skrypty `db:introspect:*` ją analizują, w obu przypadkach przez API HTTP D1 z `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID` i `CLOUDFLARE_ACCESS_TOKEN` z odpowiedniego pliku środowiskowego. Zobacz [Baza danych](/docs/tooling/database).

## Konwencje schematu

- Daty to `integer(..., { mode: "timestamp_ms" })` z wartością domyślną `(unixepoch() * 1000)`. Tabele dostają `createdAt` i `updatedAt` z `...timestamps()` w `src/integrations/drizzle-orm/drizzle.columns.ts`.
- Wartości logiczne to `integer(..., { mode: "boolean" })`.
- Indeksy, ograniczenia unikalności, klucze obce i relacje pozostają w pliku schematu.
- D1 nie obsługuje interaktywnych transakcji. Operację utrzymasz atomową dzięki jednej instrukcji SQL albo `db.batch([...])`, jak robią to `getUsers` i limiter żądań.

## Testy

Testowy binding D1 stosuje każdy plik SQL z folderu migracji w bazie SQLite w pamięci, więc testy korzystające z D1 działają na zmigrowanym schemacie. `src/integrations/drizzle-orm/__test__/` sprawdza, czy schemat, jego indeksy i klucze obce powstają poprawnie. Zawarty w nim `migrations.test.ts` ogranicza migrację, która dodaje tabele `order` i `subscription`, do instrukcji `CREATE` dla tych tabel i ich indeksów, a na bazie zmigrowanej do poprzedzającej ją migracji sprawdza, czy każda wcześniejsza tabela i każdy indeks pozostają bez zmian. Migrację, która dodaje zapisy licencji, ogranicza do trzech instrukcji `ALTER TABLE … ADD` dodających kolumny dopuszczające wartość NULL i sprawdza, czy każda inna tabela, każdy indeks i istniejąca licencja pozostają bez zmian, a nowe kolumny są puste. Migrację, która dodaje treści kursów, ogranicza do jednej instrukcji `CREATE TABLE` i jednej `CREATE INDEX` dla `lesson_attachment`, po których następują wyłącznie instrukcje `ALTER TABLE … ADD` dodające kolumny z wartościami domyślnymi, i sprawdza, czy każda inna tabela i każdy indeks oraz istniejący kurs, rozdział, lekcja i film pozostają bez zmian, a nowe kolumny mają wartości domyślne, oraz czy usunięcie lekcji usuwa jej materiały. Migrację, która zapisuje pierwszą płatną lekcję, ogranicza do dwóch instrukcji `ALTER TABLE … ADD` dodających do `license` kolumny dopuszczające wartość NULL i sprawdza, czy każda inna tabela, każdy indeks i istniejąca licencja pozostają bez zmian, a nowe kolumny są puste. Zobacz [Pisanie testów](/docs/guides/writing-tests).

## Istniejące dane z PostgreSQL

Te migracje tworzą wyłącznie schemat SQLite. Przeniesienie danych z wcześniejszej instalacji PostgreSQL wymaga osobnego, przejrzanego eksportu i importu.
