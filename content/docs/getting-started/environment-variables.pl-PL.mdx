Skopiuj szablon dla środowiska, w którym pracujesz. `.env.development`, `.env.preview` i `.env.production` są ignorowane przez Git; `.env.test` jest zapisany w repozytorium z fikcyjnymi wartościami dla testów i izolowanego podglądu.

```sh
cp .env.example .env.development
openssl rand -base64 48
```

Użyj wygenerowanej wartości jako `AUTH_SECRET`, z osobnym sekretem dla każdego wdrożonego środowiska.

| Zmienne                                                                         | Przeznaczenie                                                                          |
| ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `AUTH_SECRET`                                                                   | Sekret Better Auth do podpisywania i szyfrowania                                       |
| `AUTH_GITHUB_CLIENT_ID`, `AUTH_GITHUB_CLIENT_SECRET`                            | Aplikacja GitHub OAuth; uwierzytelnia też żądanie liczby gwiazdek na GitHubie          |
| `AUTH_GOOGLE_CLIENT_ID`, `AUTH_GOOGLE_CLIENT_SECRET`                            | Aplikacja Google OAuth                                                                 |
| `RESEND_API_KEY`, `RESEND_EMAIL_FROM`                                           | Klucz API Resend i domyślny adres nadawcy                                              |
| `POLAR_SERVER`                                                                  | `sandbox` dla trybu deweloperskiego i preview, `production` dla produkcji              |
| `POLAR_ACCESS_TOKEN`, `POLAR_ORGANIZATION_ID`                                   | Dostęp do API Polar oraz organizacja dla kluczy licencyjnych i zamówień                |
| `POLAR_WEBHOOK_SECRET`                                                          | Weryfikuje webhooki Polar pod `/api/auth/polar/webhooks`                               |
| `POLAR_PRODUCT_ID_CORE`, `POLAR_PRODUCT_ID_COMPLETE`, `POLAR_PRODUCT_ID_AGENCY` | Produkty Polar dla trzech planów dostępnych przy zakupie                               |
| `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID`, `CLOUDFLARE_ACCESS_TOKEN`    | Dostęp do API HTTP D1 dla Drizzle Studio i introspekcji; aplikacja używa bindingu `DB` |

Środowiska `development`, `preview` i `production` w `wrangler.jsonc` wymagają wszystkich powyższych kluczy jako sekretów (`secrets.required`). Kod serwerowy odczytuje je przez `import { env } from "cloudflare:workers"`. Żaden z nich nie ma prefiksu `VITE_`, ponieważ Vite udostępnia takie wartości przeglądarce. `.env.example` wymienia klucze w blokach, po jednym na moduł, w tej samej kolejności co `secrets.required`, a `src/__test__/wrangler.test.ts` kończy się błędem, gdy oba pliki się różnią.

`.env.development` może też ustawiać `LOCAL_ADMIN_PASSWORD`, hasło, które `bun run db:seed:local` nadaje lokalnemu administratorowi; nie jest sekretem Workera i nigdy nie opuszcza Twojego komputera. Zobacz [Lokalne dane początkowe](/docs/tooling/database#the-local-seed).

`AFFONSO_PROGRAM_ID` nie jest sekretem i nie występuje w `.env.example`. To publiczne ID programu Affonso, którego potrzebuje śledzenie poleceń partnerskich, więc jest zmienną Workera w `vars` w `wrangler.jsonc`, ustawianą tylko w środowisku, które przyjmuje prawdziwe płatności; `production` ustawia ID programu SaaSy Land, a `test` fikcyjne ID dla testów przeglądarkowych. Śledzenie działa tylko wtedy, gdy Worker ma to ID i program jest otwarty: dziś `AFFILIATE_PROGRAM` ma wartość <RepositoryFact name="affiliateProgram" />. Zobacz [Otwarcie programu](/docs/features/affiliates#opening-the-programme).

## Wartości w kodzie

Niektóre ustawienia są częścią kodu, a nie zmiennymi środowiskowymi:

- `src/presentation/branding/index.ts`: nazwa aplikacji, `APP_DOMAIN` (kanoniczny URL to `https://` z dołączoną tą domeną), host preview `APP_PREVIEW_DOMAIN`, adresy kontaktowe i repozytorium GitHub.
- `src/modules/_core/constants/api.ts`: hosty preview i produkcji (`DEPLOYED_HOSTS`, odczytywane z `APP_PREVIEW_DOMAIN` i `APP_DOMAIN`), które akceptują Better Auth i linki newslettera (`appHostsForMode`) i które skrypty wdrożeniowe sprawdzają po wdrożeniu.
- `wrangler.jsonc`: nazwy Workerów, domeny niestandardowe, które `src/__test__/wrangler.test.ts` utrzymuje zgodne z `DEPLOYED_HOSTS`, identyfikatory D1 i KV oraz nazwy bucketów R2.

## Adresy zwrotne dostawców

- GitHub i Google: <RepositoryFact name="oauthCallbackUrls" />.
- Webhooki Polar: `https://<host>/api/auth/polar/webhooks`, podpisywane za pomocą `POLAR_WEBHOOK_SECRET`. [Konfiguracja Polar](/docs/getting-started/polar-setup) wymienia zdarzenia, produkty, pole wyboru zgody i zakresy uprawnień tokenu, a `bun run polar:verify:<environment>` je sprawdza.
