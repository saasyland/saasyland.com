- Fixed: a change of the signed-in user no longer empties the whole query cache. The route guards, `useSignOut` and `finishSignIn` called `queryClient.clear()` so that one user's data never reached the next, which also threw away the translations, the star count and the course catalogue. On a prerendered page, which knows no session, the first guard to find a signed-in visitor did it, and a page body that had not hydrated yet rendered a skeleton where the server had printed data. They now call `removeUserData` (`auth.session.ts`), which removes every mutation and every query except those marked `meta: { public: true }`: the translations, the star count, the course catalogue and the course showcase. The landing loader no longer returns the star count for `ProofSection` to use as `placeholderData`. `auth.session.test.ts` runs every public query and fails if one reads the session, and `auth-routing.spec.ts` switches accounts, and signs out and in as another account, and checks that the licence page never shows the previous account's licence. See [Data fetching and caching](/docs/conventions/data-fetching#public-queries).
