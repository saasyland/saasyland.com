## Idiomas

`I18N` em `src/integrations/use-intl/i18n.config.ts` define `en-US` (padrão), `de-DE`, `es-ES`, `fr-FR`, `it-IT`, `ja-JP`, `pl-PL`, `pt-BR` e `uk-UA`, o cookie `saasyland.com_locale`, o fuso horário padrão `UTC` e os formatos de data nomeados `FORMATS`.

## URLs

O idioma padrão não tem prefixo; qualquer outro idioma é um prefixo de caminho, por exemplo `/docs` e `/pl-PL/docs`. Para requisições de documento, o Worker (`resolveLocale` em `i18n.middleware.ts`) redireciona caminhos não canônicos com um 308: `/en-US/docs` vira `/docs` e `/pl/docs` vira `/pl-PL/docs`. Os caminhos `/api` e `/_serverFn` nunca têm prefixo.

O `rewrite` do roteador em `src/router.tsx` remove o prefixo das URLs de entrada e o adiciona às de saída, então rotas e links usam caminhos simples: `<Link to={ROUTES.SIGN_IN}>`. URLs brutas no idioma atual, como `callbackURL` e `errorCallbackURL` do Better Auth, vêm de `router.buildLocation(...).publicHref`; `localizePathname({ locale, pathname })` monta uma URL para um idioma específico, como os links do seletor de idioma e os links em e-mails. `AriaProvider` localiza o `href` dos componentes do React Aria.

## Cookie de idioma

Quando o idioma da URL de um documento difere do cookie, o Worker define o cookie na resposta; nenhum código escolhe um idioma a partir dele. `getCurrentLocale()` funciona nos dois lados e lê o caminho da URL, recorrendo a `en-US`. As URLs de `/api` e de funções de servidor não têm prefixo, então no servidor ela retorna `en-US` para elas. Os e-mails recebem o idioma do fluxo: os e-mails de autenticação, do `callbackURL` dele; a confirmação da newsletter, do `locale` que o formulário envia.

## Mensagens

As mensagens são arquivos `messages/<locale>/<namespace>.json`; o nome do arquivo é o namespace, por exemplo `pages.admin.users`, `components.custom.footer`, `emails.verify-email`, `auth.validations` ou `common`. Todo namespace de página tem `metadata.title` e `metadata.description`.

- Os namespaces raiz (`common`, `components.*`, `errors*`) são pré-carregados no `beforeLoad` raiz.
- Um layout declara `NAMESPACES` e uma página declara `NAMESPACE`. Ambos vão para `staticData.namespaces` e são pré-carregados pelo loader:

```ts
loader: async ({ context }) => {
  const locale = getCurrentLocale()
  const [metadata] = await Promise.all([
    loadPageMetadata({ locale, namespace: NAMESPACE }),
    preloadNamespaces({ locale, namespaces: [NAMESPACE], queryClient: context.queryClient }),
  ])
  return { locale, metadata }
},
```

- `TranslationsProvider` envolve o corpo do documento e junta os namespaces raiz com os das rotas correspondentes em um único `IntlProvider`, então as telas de erro também são traduzidas.
- Os e-mails carregam o próprio namespace no servidor com `loadNamespace`.

## Componentes

Cada componente chama `useTranslations` uma única vez e chama o tradutor de `t`. Um componente que precisa de dois namespaces usa o pai comum deles ou `useTranslations()` com chaves completas.

## Datas, números e fusos horários

Datas e números são formatados com o `useFormatter` do use-intl (`format.dateTime`, `format.number`, `format.relativeTime`, `format.list`). O locale decide as convenções: a ordem do dia e do mês, o relógio de 12 ou 24 horas e os separadores. O fuso horário é a única preferência de exibição que o usuário armazena.

`TranslationsProvider` passa mais dois valores ao `IntlProvider`:

- `timeZone`: o `timezone` do usuário logado, vindo da query da sessão atual, ou `I18N.DEFAULT_TIMEZONE` (`UTC`) quando não há sessão. O provider lê a sessão que os guards de rota de `/app`, de `/admin` e da autenticação carregam e nunca a busca por conta própria, então as páginas públicas pré-renderizadas são iguais para todos os visitantes e se hidratam sem mudanças. Quando a query da sessão muda, por exemplo depois que o usuário salva um novo fuso em [Configurações](/docs/features/settings), todas as datas são renderizadas de novo.
- `formats`: `I18N.FORMATS`, os formatos de data nomeados. `src/types/use-intl.d.ts` registra os nomes deles no use-intl, então um nome desconhecido não passa na verificação de tipos.

| Nome            | Exemplo (inglês)          | Uso                                                                                                        |
| --------------- | ------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `date`          | Nov 14, 2026              | O dia de um instante no fuso do leitor, em tabelas                                                         |
| `dateTime`      | Nov 14, 2026, 3:04 PM UTC | Um instante com o horário e a sigla do fuso: ativações de licença e datas de contas no admin               |
| `calendarDate`  | Nov 14, 2026              | Uma data sem horário, como a data de um post do blog. É formatada em UTC, então nunca passa para outro dia |
| `calendarDay`   | November 14               | Rótulos de dia do gráfico de analytics do admin                                                            |
| `calendarMonth` | Nov                       | Rótulos de mês do gráfico do painel do admin                                                               |

Uma chamada pode substituir uma opção de um formato nomeado: `format.dateTime(new Date(post.date), "calendarDate", { month: "long" })`. As tabelas do admin mostram as datas de outros usuários no fuso horário de quem as visualiza, com a sigla, para que uma coluna seja lida e ordenada em um único fuso; o fuso do usuário tem uma coluna própria.

## Trocar de idioma

`locale-switcher.tsx` tem dois controles de idioma. `LocaleSwitcher`, no rodapé das páginas de marketing, é um menu `<details>` com um link simples por idioma para o caminho atual naquele idioma, então funciona antes da hidratação. `LocaleSelect`, nas barras laterais da documentação e do aplicativo do cliente, é um campo de seleção no mesmo estilo de `ThemeSwitch` que abre a mesma URL. Nos dois casos, escolher um idioma carrega um novo documento, e a query string e o fragmento não são mantidos. As páginas em polonês e ucraniano também pré-carregam os subconjuntos de fontes latino estendido e cirílico ([Fontes e marca](/docs/ui/fonts-and-branding)).

## Verificações

`bun run check:i18n` verifica a paridade de chaves entre os idiomas, resolve as chaves estáticas no escopo do respectivo `useTranslations`, valida a sintaxe das mensagens ICU e verifica a paridade do conteúdo da documentação e do blog.
