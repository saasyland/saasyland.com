---
title: "Commits convencionales"
description: "Formato de los mensajes de commit y el hook de emojis."
---

Los asuntos de los commits siguen el formato `<type>(<scope>): <description>`. El ámbito es opcional y `!` indica un cambio incompatible. Escriba el asunto sin emoji:

```sh
git commit -m "fix(auth): keep the locale in verification links"
```

El hook `prepare-commit-msg` de `.vite-hooks/` ejecuta `bun scripts/commit-msg.ts`, que valida el asunto y le antepone el emoji correspondiente a su tipo, de modo que el commit anterior pasa a ser `🐛 fix(auth): keep the locale in verification links`.

| Tipo       | Emoji |
| ---------- | ----- |
| `build`    | 🛠️    |
| `chore`    | ♻️    |
| `ci`       | ⚙️    |
| `docs`     | 📚    |
| `feat`     | ✨    |
| `fix`      | 🐛    |
| `perf`     | 🚀    |
| `refactor` | 📦    |
| `revert`   | 🗑️    |
| `style`    | 💎    |
| `test`     | 🚨    |

Cualquier otro tipo, o un asunto que no siga el formato convencional, cancela el commit y muestra la lista de tipos permitidos. El hook no modifica los asuntos que ya empiezan por un emoji ni los que ha generado Git (`Merge`, `Revert "`, `fixup!`, `squash!`), y tampoco los mensajes de merge, de squash ni de plantilla.

Antes del hook del mensaje, el hook `pre-commit` ejecuta `bun run check:pre-commit`. No omita los hooks.
