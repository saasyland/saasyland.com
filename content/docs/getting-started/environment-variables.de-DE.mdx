Kopieren Sie die Vorlage für die Umgebung, in der Sie arbeiten. `.env.development`, `.env.preview` und `.env.production` werden von Git ignoriert; `.env.test` ist mit Platzhalterwerten für Tests und die isolierte Preview eingecheckt.

```sh
cp .env.example .env.development
openssl rand -base64 48
```

Verwenden Sie den erzeugten Wert als `AUTH_SECRET`, mit einem eigenen Secret für jede deployte Umgebung.

| Variablen                                                                       | Zweck                                                                                                      |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `AUTH_SECRET`                                                                   | Secret von Better Auth für Signierung und Verschlüsselung                                                  |
| `AUTH_GITHUB_CLIENT_ID`, `AUTH_GITHUB_CLIENT_SECRET`                            | GitHub-OAuth-App; authentifiziert auch die Anfrage für die Anzahl der GitHub-Sterne                        |
| `AUTH_GOOGLE_CLIENT_ID`, `AUTH_GOOGLE_CLIENT_SECRET`                            | Google-OAuth-App                                                                                           |
| `RESEND_API_KEY`, `RESEND_EMAIL_FROM`                                           | Resend-API-Schlüssel und die Standard-Absenderadresse                                                      |
| `POLAR_SERVER`                                                                  | `sandbox` für Entwicklung und Preview, `production` für die Produktion                                     |
| `POLAR_ACCESS_TOKEN`, `POLAR_ORGANIZATION_ID`                                   | Zugriff auf die Polar-API und die Organisation für Rabatte und Lizenzschlüssel                             |
| `POLAR_WEBHOOK_SECRET`                                                          | Verifiziert Polar-Webhooks unter `/api/auth/polar/webhooks`                                                |
| `POLAR_PRODUCT_ID_CORE`, `POLAR_PRODUCT_ID_COMPLETE`, `POLAR_PRODUCT_ID_AGENCY` | Polar-Produkte für die drei Checkout-Stufen                                                                |
| `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID`, `CLOUDFLARE_ACCESS_TOKEN`    | Zugriff auf die D1-HTTP-API für Drizzle Studio und Introspektion; die Anwendung verwendet das `DB`-Binding |

Die Umgebungen `development`, `preview` und `production` in `wrangler.jsonc` verlangen jeden der obigen Schlüssel als Secret (`secrets.required`). Servercode liest sie mit `import { env } from "cloudflare:workers"`. Keiner hat ein `VITE_`-Präfix, weil Vite solche Werte im Browser verfügbar macht.

`AFFONSO_PROGRAM_ID` ist kein Secret und steht nicht in `.env.example`. Es ist die öffentliche Programm-ID von Affonso, die das Tracking von Partnerempfehlungen einschaltet, und deshalb eine Worker-Variable unter `vars` in `wrangler.jsonc`, die nur für die Umgebung gesetzt wird, die echte Zahlungen annimmt; derzeit setzt nur `test` eine, eine Dummy-ID für die Browsertests. Siehe [Partnerprogramm](/docs/features/affiliates).

## Werte im Code

Einige Einstellungen sind Code und keine Umgebungsvariablen:

- `src/presentation/branding/index.ts`: der Name der Anwendung, `APP_DOMAIN` (die kanonische URL ist `https://` plus diese Domain), Kontaktadressen und das GitHub-Repository.
- `src/modules/_core/constants/api.ts`: die Preview- und Produktions-Hosts (`DEPLOYED_HOSTS`, abgeleitet aus `APP_DOMAIN`), die Better Auth und Newsletter-Links akzeptieren (`appHostsForMode`) und die die Deploy-Skripte nach einem Deployment prüfen.
- `wrangler.jsonc`: Worker-Namen, eigene Domains, die IDs für D1 und KV sowie die Namen der R2-Buckets.

## Callbacks der Anbieter

- GitHub und Google: `https://<host>/api/auth/callback/github` und `https://<host>/api/auth/callback/google`.
- Polar-Webhooks: `https://<host>/api/auth/polar/webhooks`, signiert mit `POLAR_WEBHOOK_SECRET`. [Polar-Einrichtung](/docs/getting-started/polar-setup) listet die Ereignisse, Produkte, Rabatte und Token-Scopes auf, und `bun run polar:verify:<environment>` prüft sie.
