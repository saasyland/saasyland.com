## Was ist SaaSy Land?

SaaSy Land ist ein kommerzielles React-SaaS-Starter-Kit. Eine CLI stellt Konfigurationsfragen und schreibt nur die Module, für die Sie sich entschieden haben: Authentifizierung in Ihrer eigenen Datenbank, Abrechnung, Transaktions-E-Mails, eine Admin-Konsole, Internationalisierung und einen visuellen Seitendesigner. Es wird mit <RepositoryCount fact="testFiles" /> Testdateien und einem Coverage-Gate ausgeliefert, das sie bereits durchsetzt. Der Code, den Sie erhalten, ist also geprüft und nicht bloß vorhanden.

Der Quellcode der öffentlichen Website steht unter der MIT-Lizenz; die separate CLI und die privaten Vorlagen sind proprietär. Kaufen Sie eine Lizenz, melden Sie sich auf saasyland.com an und erhalten Sie den Schlüssel, den Sie zum Installieren und Nutzen der CLI benötigen. Die Online-Lizenzprüfung gilt für die CLI. Generierte Anwendungen dürfen unter der kommerziellen Lizenz bearbeitet und bereitgestellt werden und benötigen keinen Laufzeitschlüssel. Markenrechte an SaaSy Land werden durch die Lizenz der Website nicht eingeräumt.

## Stack wählen, einen Befehl ausführen

Die CLI ist keine Vorlage, die Sie herunterladen und gegen die Sie dann ankämpfen. Sie fragt, was Sie bauen, und schreibt genau das. Dasselbe Werkzeug erzeugt deshalb ein Single-Tenant-Nebenprojekt ebenso wie ein Multi-Tenant-Produkt mit einem Merchant of Record.

```bash
bunx saasyland@latest init my-app \
  --framework tanstack \
  --tenancy multi \
  --billing polar \
  --content mdx \
  --email resend
```

Einige der Optionen, mit bewusst langweiligen Flags, damit der Befehl es übersteht, in ein Skript statt in einen Prompt eingefügt zu werden:

| Frage              | Optionen                                          | Warum es eine Frage ist                                                                                                                                                                |
| ------------------ | ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Framework          | `next`, `tanstack`                                | Beide werden unterstützt; wählen Sie das, das Ihr Team bereits kennt                                                                                                                   |
| Mandantenfähigkeit | `multi`, `single`                                 | Organisationen später nachzurüsten berührt jede Abfrage, die Sie geschrieben haben                                                                                                     |
| Abrechnung         | `stripe`, `polar`, `lemonsqueezy`, `--no-billing` | Polar und Lemon Squeezy sind Merchants of Record und übernehmen für Sie die EU-Mehrwertsteuer und die US-Sales-Tax. Stripe tut das nicht. Diese Entscheidung trifft ein Gründer einmal |
| Inhalte            | `mdx`, `--no-content`                             | Ein Blog und eine Dokumentation, oder keins von beiden                                                                                                                                 |
| E-Mail             | `resend`, `--no-email`                            | Transaktions-E-Mails, eingebunden in die Auth-Abläufe, oder keine                                                                                                                      |

Ändern Sie eine Antwort, und der Befehl ändert sich mit. Führen Sie ihn für das nächste Projekt erneut aus: Die Antworten ändern sich, die CLI und die lebenslangen Updates nicht.

### Warum das Coverage-Gate heute wichtiger ist als zum Launch

Als 2.0 erschien, war die Coverage-Zahl ein Qualitätsargument. Inzwischen ist sie ein Durchsatzargument, denn ein großer Teil des Codes, der in SaaS-Codebasen hinzukommt, wird heute von einem Agenten geschrieben.

Im [2025 Stack Overflow Developer Survey](https://survey.stackoverflow.co/2025/ai) gaben 84 % der Entwickler an, KI-Tools zu nutzen oder dies zu planen, während das meistgenannte Ärgernis, angeführt von 45 %, KI-Ausgaben waren, die „fast richtig, aber eben nicht ganz“ sind. Eine Schwelle, die den Merge blockiert, ist die günstigste verfügbare Antwort darauf: Ein Agent kann kein Verhalten hinzufügen, ohne einen Test hinzuzufügen, und alles, was er kaputt macht, fällt im Pull Request auf statt beim Kunden.

Ausführlich haben wir das in [warum Ihr Repository über die Qualität der Agentenausgabe entscheidet](/blog/ai-coding-agents-repository-readiness) und in [wie Sie einen Stack für KI-Coding-Agenten auswählen](/blog/choosing-a-saas-stack-for-ai-coding-agents) beschrieben. Kurz gesagt: Dieses Repository erreicht auf unserer eigenen Readiness-Scorecard 18 von 20 Punkten, und zwar durch seine Konstruktion und nicht durch besondere Anstrengung.

## Für wen das nicht gedacht ist

Wenn Sie etwas Kostenloses zum Lernen suchen, klonen Sie eine Vorlage und haben Sie Freude daran. Wenn Ihnen lieber ist, dass ein gehosteter Anbieter Ihre Authentifizierung betreibt und Ihnen dieses Privileg pro monatlich aktivem Nutzer berechnet, kaufen Sie stattdessen das.

Kaufen Sie eine Lizenz, melden Sie sich auf saasyland.com an und erhalten Sie den Schlüssel, den Sie zum Installieren und Nutzen der CLI benötigen. Die Online-Lizenzprüfung gilt für die CLI. Generierte Anwendungen dürfen unter der kommerziellen Lizenz bearbeitet und bereitgestellt werden und benötigen keinen Laufzeitschlüssel. Markenrechte an SaaSy Land werden durch die Lizenz der Website nicht eingeräumt.

</Accordion>

<Accordion title="Woher weiß ich, dass es das ist, was diese Seite behauptet?">

Prüfen Sie es, bevor Sie bezahlen. Die Dokumentation ist öffentlich, der Coverage-Bericht wird vom Repository selbst erzeugt statt als Screenshot gezeigt, und der CI-Workflow, der das Gate durchsetzt, ist eine Datei in diesem Repository. Die Prüftabelle oben ordnet jede Aussage einem Befehl oder einem Pfad zu.

</Accordion>

<Accordion title="Warum lässt man das nicht einfach von einem KI-Agenten bauen?">

Er wird es tun, und das Ergebnis wird richtig aussehen. Was er Ihnen nicht sagt, ist, welche Auth-Randfälle er übersprungen hat, welcher Webhook nicht idempotent ist oder dass die Paritätsprüfung für Übersetzungen, die er nie geschrieben hat, die fehlenden Schlüssel gefunden hätte. Die Ausgabe eines Agenten ist nur so vertrauenswürdig wie die Prüfungen, die sie kontrolliert haben, und in einem leeren Repository gibt es keine.

</Accordion>
