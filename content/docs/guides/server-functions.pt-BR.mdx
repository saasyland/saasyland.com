Toda operação chamada pela interface é uma função de servidor do TanStack Start. As telas da aplicação não têm endpoints REST separados.

## Anatomia

```ts
export const deleteCategory = createServerFn({ method: "POST" })
  .middleware([authorized({ category: ["delete"] })])
  .validator((input: zod.input<typeof categoryZodSchemas.deleteCategory>) => categoryZodSchemas.deleteCategory.parse(input))
  .handler(async ({ data }) => {
    const [row] = await db.delete(category).where(eq(category.id, data.categoryId)).returning({ id: category.id })

    if (row === undefined) {
      throw new AppError(ERROR_CODES.NOT_FOUND, "category.errors.notFound")
    }

    return row
  })
```

1. `createServerFn({ method })`: `GET` para leituras, `POST` para escritas.
2. `.middleware([...])`: middleware de função executado no servidor antes da validação, que pode ampliar `context`.
3. `.validator(fn)`: recebe a entrada de quem chama e retorna o valor validado. O tipo do parâmetro é o tipo de entrada que quem chama precisa passar. Também é possível passar um schema diretamente, como `localeField`.
4. `.handler(({ context, data }) => ...)`: roda no servidor com o contexto do middleware e os dados validados. O valor retornado é serializado e devolvido a quem chamou.

## O caminho de uma chamada

- No servidor (loaders de rota durante o SSR e outro código de servidor), chamar `deleteCategory({ data })` executa a função diretamente.
- No navegador, o build substitui o handler por um stub RPC. A chamada vira uma requisição HTTP para o endpoint de funções de servidor em `/_serverFn`, e o resultado ou erro é desserializado no retorno.
- O Worker em `src/server.ts` pula a busca de arquivos estáticos e os redirecionamentos de idioma para os caminhos `/_serverFn` e `/api`.
- O middleware roda primeiro, depois o validador e por fim o handler, então uma sessão ausente é rejeitada antes de a entrada ser analisada.
- `getCurrentLocale()` lê o idioma da URL da requisição, e a URL de uma função de servidor não o contém, então ali ele retorna o idioma padrão. Funções que retornam conteúdo localizado recebem o idioma como entrada, como `getBlogPosts` em `src/routes/blog.index.tsx`.

## Middleware

`src/integrations/better-auth/auth.middleware.ts` oferece:

| Middleware                    | Efeito                                                                                                                                                                       |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `withRequest`                 | Adiciona `context.requestHeaders` e converte qualquer falha em um `AppError` seguro                                                                                          |
| `authorized(permission?)`     | Carrega a sessão, lança `UNAUTHORIZED` sem sessão e `FORBIDDEN` sem a permissão e depois adiciona `context.auth`                                                             |
| `withRateLimit(kind, limits)` | Conta as chamadas por `kind` e IP do cliente no D1 e lança `TOO_MANY_REQUESTS` acima do limite; `RATE_LIMITS.SENSITIVE` permite 3 e `RATE_LIMITS.TOKEN` 5 a cada 60 segundos |

`authorized` e `withRateLimit` incluem `withRequest` e podem ser combinados, como em `enable-two-factor.ts`:

```ts
.middleware([withRateLimit("enable-two-factor", RATE_LIMITS.SENSITIVE), authorized()])
```

`authorized` lê a sessão com `getRequestSession`, que ignora o cache de cookies do Better Auth e reutiliza uma única consulta por requisição.

## Código exclusivo do servidor

- Módulos que nunca podem chegar ao navegador começam com `import "@tanstack/react-start/server-only"`: o cliente do D1, o servidor do Better Auth, o cliente do Resend e o limitador de requisições. Funções de servidor podem importá-los porque seus handlers são removidos do bundle do cliente.
- `createServerOnlyFn`, `createClientOnlyFn` e `createIsomorphicFn` marcam funções auxiliares que rodam só de um lado, ou de forma diferente em cada lado (`getRequestSession`, as chamadas ao cliente do Better Auth no formulário de login, `getCurrentLocale`).
- Os segredos vêm de `env` em `cloudflare:workers` e são lidos apenas em código exclusivo do servidor.

## Onde fica uma função de servidor

- Uma operação sobre uma tabela: um caso de uso em `src/modules/<table>/use-cases/`. Veja [Adicionar um caso de uso](/docs/guides/add-a-use-case).
- Usada por uma única rota: no próprio arquivo da rota, com `createServerFn`, como `getBlogPosts`.
- Compartilhada, mas não ligada a uma tabela: `src/lib`, como `getStarCount` em `src/lib/github.ts`.

## Chamar uma função de servidor

- Componentes usam as opções de query ou mutation exportadas com o TanStack Query.
- Loaders pré-carregam com `context.queryClient.query(...)` para que a página seja renderizada a partir do cache.
- Testes chamam as opções com `executeMutation` ou `executeQuery`; a configuração de testes mantém o middleware e o validador reais na chamada. Veja [Escrever testes](/docs/guides/writing-tests).
