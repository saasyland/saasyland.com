すべてのパスには `ROUTES` に定数があり、その定数は何もインポートしない `src/routes.ts` で宣言します（[パスとナビゲーション](/docs/conventions/routes#paths-and-navigation)を参照）。リンクには定数を使い（例：`<Link to={ROUTES.SIGN_IN}>`）、ロケールプレフィックスはルーターが付けます。以下の各ページは、デフォルト以外のすべてのロケールプレフィックスの下でも提供されます（例：`/pl-PL/terms`）。

## 公開ページ

これらのページは、サイトヘッダーを表示する `_site` レイアウトの中にあります。ドキュメント以外は `_marketing` レイアウト（ページフレームとフッター）の中にもあり、ドキュメントのレイアウトは同じフッターを自分で表示します。ブログとドキュメントはその内側に独自のレイアウトを持ちます。ニュースレターのページを除き、すべてプリレンダリングされます。

| パス                          | 定数                     | ルートファイル                                                 |
| ----------------------------- | ------------------------ | -------------------------------------------------------------- |
| `/`                           | `HOME`                   | `_site._marketing.index.tsx`                                   |
| `/licence`                    | `LICENCE`                | `_site._marketing.licence.tsx`                                 |
| `/privacy`                    | `PRIVACY`                | `_site._marketing.privacy.tsx`                                 |
| `/terms`                      | `TERMS`                  | `_site._marketing.terms.tsx`                                   |
| `/refunds`                    | `REFUNDS`                | `_site._marketing.refunds.tsx`                                 |
| `/withdrawal`                 | `WITHDRAWAL`             | `_site._marketing.withdrawal.tsx`                              |
| `/affiliates`                 | `AFFILIATES`             | `_site._marketing.affiliates.tsx`                              |
| `/newsletter/confirm`         | `NEWSLETTER_CONFIRM`     | `_site._marketing.newsletter.confirm.tsx`                      |
| `/newsletter/unsubscribe`     | `NEWSLETTER_UNSUBSCRIBE` | `_site._marketing.newsletter.unsubscribe.tsx`                  |
| `/blog`                       | `BLOG`                   | `_site._marketing.blog.tsx`、`_site._marketing.blog.index.tsx` |
| `/blog/rss.xml`               | `BLOG_FEED`              | なし                                                           |
| `/blog/page/*`                | なし                     | `_site._marketing.blog.page.$page.tsx`                         |
| `/blog/*`                     | なし                     | `_site._marketing.blog.$.tsx`                                  |
| `/authors/*`                  | `AUTHORS`                | `_site._marketing.authors.$author.tsx`                         |
| `/docs`                       | `DOCS`                   | `_site.docs.tsx`、`_site.docs.index.tsx`                       |
| `/docs/cli`                   | `DOCS_CLI`               | `_site.docs.$.tsx`                                             |
| `/docs/tooling/test-coverage` | `DOCS_TEST_COVERAGE`     | `_site.docs.$.tsx`                                             |
| `/docs/*`                     | なし                     | `_site.docs.$.tsx`                                             |
| `/*`                          | なし                     | `_site._marketing.$.tsx`                                       |

`/*` はほかのどのルートにも一致しないパスです。`_site._marketing.$.tsx` が `notFound()` を投げるため、サーバーはリクエストごとにレンダリングする「ページが見つからない場合」のページを 404 で返します（[ページが見つからない場合](/docs/features/landing-page#not-found-page)を参照）。

`/blog/rss.xml` にはルートファイルがありません。`scripts/generate-seo-files.ts` がビルドの後に各言語のフィードを書き出します（[フィード](/docs/features/blog#feed)を参照）。

## コース

`/courses` レイアウト（`_site._marketing.courses.tsx`）はブログと同じく `_site` と `_marketing` のレイアウトの中にあり、ガードはありません。各レッスンのアクセスレベルはサーバーが確認します（[コース](/docs/features/courses)を参照）。これらのページはリクエストごとに D1 を読むため、プリレンダリングされません。`/sitemap-courses.xml` にはルートファイルがなく、`src/server.ts` のリクエストハンドラーが D1 から応答します（[コースのサイトマップ](/docs/features/seo#course-sitemap)を参照）。

| パス                         | 定数              | ルートファイル                                                       |
| ---------------------------- | ----------------- | -------------------------------------------------------------------- |
| `/courses`                   | `COURSES`         | `_site._marketing.courses.tsx`, `_site._marketing.courses.index.tsx` |
| `/courses/<course>`          | なし              | `_site._marketing.courses.$course.index.tsx`                         |
| `/courses/<course>/<lesson>` | なし              | `_site._marketing.courses.$course.$lesson.tsx`                       |
| `/sitemap-courses.xml`       | `COURSES_SITEMAP` | なし                                                                 |

## API

API のパスがローカライズされることはありません。

| パス                                         | 定数            | ルートファイル                                                                                                                                     |
| -------------------------------------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/api`                                       | `API`           | `api/index.ts`                                                                                                                                     |
| `/api/auth/*`                                | `API_AUTH_BASE` | `api/auth.$.ts`                                                                                                                                    |
| <RepositoryFact name="cliApiBasePath" />`/*` | なし            | `api/cli.v1.license.ts`、`api/cli.v1.activations.ts`、`api/cli.v1.activations.$activationId.ts`、`api/cli.v1.activations.$activationId.bundles.ts` |

CLI ライセンス API のパスは、そのコントラクトである `@saasyland/stack/api` の `API_BASE_PATH` と `API_ROUTE` から取得されます。`src/routes/api/__test__/cli.v1.test.ts` は、ルーターがそれぞれのパスを対応するルートファイルに渡すことを確認します（[CLI ライセンス API](/docs/features/cli-licence-api) を参照）。

`ROUTES.API_AUTH` は、Better Auth 自身のエンドポイントと、その admin プラグインおよび二要素認証プラグインのエンドポイントのパスを、`/api/auth` からの相対パスで列挙します。`auth.server.ts` はこれを使って、エンドポイントをレート制限の対象から除外します。また、`auth.hooks.ts` の `INPUT_POLICY` はこれを使って、パスワード、名前、メールアドレス、画像を受け付けるエンドポイントを検証します。`ROUTES.API_AUTH_POLAR` は Polar プラグインの Webhook を列挙し、`auth.server.ts` がこれをレート制限の対象から除外します。`ROUTES.API_AUTH_POLAR` と `API_AUTH_CUSTOMER_PORTAL` は、Polar のエリアと一緒に消えます。`API_AUTH_CUSTOMER_PORTAL` と `API_AUTH_VERIFY_EMAIL` は、`API_AUTH_BASE` から組み立てた、Better Auth のエンドポイントへのフルパスです。`AUTH` と `NEWSLETTER` には独自のページがありません。これらは `ADMIN`、`APP`、`API`、`COURSES` とともに、プリレンダリングされないエリアを示します（`src/routes.ts` の `REQUEST_RENDERED_ROUTES`。`isRequestRenderedRoute` がこれを読みます）。`verify-build.ts` は、そのいずれかの配下のページをプリレンダリングしたビルドを失敗させます。

## メディア

`/media/<expiry>.<signature>/<videoId>/<file>` は署名済みの動画ファイルを配信します。`ROUTES` の定数もルートファイルもありません。`src/server.ts` がロケールミドルウェアより前に `serveMedia` へ渡すため、ローカライズされることはありません。[Cloudflare R2](/docs/integrations/cloudflare-r2) を参照してください。

`/media/covers/<courseId>/<file>` は公開されているコースのカバー画像を `serveCover` で、`/media/downloads/<expiry>.<signature>/<attachmentId>/<fileName>` は署名済みのレッスンの資料を `serveAttachment` で配信します。コースのエリアの `/media/` ハンドラーがそこへ渡すため、これらもローカライズされることはありません。[コースのカバー画像](/docs/features/courses#course-covers)を参照してください。

<RepositoryFact name="cliBundleUrlPath" /> は、同じように `serveBundle` を通じて CLI
の署名済みのテンプレートバンドルを配信し、そのプレフィックスは `license.constants.ts` の `BUNDLE_PATH_PREFIX` から取得します。[CLI
ライセンス API](/docs/features/cli-licence-api#template-bundles) を参照してください。
