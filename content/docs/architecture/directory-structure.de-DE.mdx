## Ablageregeln

- **Dateien und Ordner verwenden kebab-case.** Tests liegen in einem benachbarten `__test__`-Ordner.
- **Routen setzen nur zusammen.** Eine Routendatei definiert die Seiten- oder Layout-Komponente, `NAMESPACE` oder `NAMESPACES`, den Loader und `head`. Sie enthält keine Widgets, Dialoge oder Spaltendefinitionen.
- **Module sind Datenbanktabellen.** Lege `src/modules/<name>` nur für eine echte Tabelle an. Eine Server Function, die nicht mit einer Tabelle arbeitet, gehört nach `src/lib` (zum Beispiel `src/lib/github.ts`) oder, wenn nur eine Route sie nutzt, in diese Routendatei.
- **Gemeinsame Komponenten liegen flach.** Eine Komponente, die in mehreren Bereichen genutzt wird, ist eine einzelne Datei direkt in `presentation/components/custom`.
- **Bereichs- und Seitenordner.** Komponenten, die nur ein Bereich nutzt, liegen in `admin/`, `app/`, `auth/`, `blog/`, `courses/`, `landing-page/` oder `settings/`, das die Kontokarten enthält, die sich `/app/settings` und `/admin/settings` teilen. Admin-Seiten bekommen einen eigenen Ordner, etwa `admin/users/`. Die Landingpage ist aufgeteilt in `sections/` (eine Datei pro Seitenabschnitt) und `components/` (Bausteine, die sich die Abschnitte teilen).
- **Ein Widget, Dialog, Formular oder Spaltensatz pro Datei.** Teile eine Komponente nicht in einen Wrapper und eine `-content`-Datei auf.
- **Keine verschachtelten Hilfsordner.** Komponentenordner enthalten nie Unterordner wie `components/`, `constants/`, `hooks/`, `lib/` oder `types/`, und neben einer Komponente liegt keine `.ts`-Hilfsdatei. Eine Konstante, die nur eine Komponente nutzt, bleibt in deren Datei.
- **Gemeinsame Daten gehören nach `src/data`.** Beispiele: `MARKETING_SECTION_IDS` und die CLI-Auswahloptionen. Dort deklariert auch jeder Bereich seine Dashboard-Statistiken, in `<area>.dashboard.ts`, die die Barrels `*.entries.ts` zusammenführen (siehe [Pfade und Navigation](/docs/conventions/routes#paths-and-navigation)). Dort deklarieren die Bereiche auch, was sie zur Plattform beitragen: Worker-Handler und Vite-Plugins (siehe [Was die Bereiche beitragen](/docs/architecture/platform-layer#what-the-areas-add)).
- **Jeder Pfad gehört nach `src/routes.ts`.** Diese Datei lädt jede Laufzeit: der Browser, der Worker, Bun-Skripte, Playwright, `vite.config.ts` und das Remotion-Projekt. Sie deklariert deshalb die Pfade und importiert nichts (siehe [Pfade und Navigation](/docs/conventions/routes#paths-and-navigation)).
- **Jedes Menü gehört nach `src/data/navigation.ts`.** Die sieben Menüs stehen dort als ausgeschriebene Listen, und die Datei importiert nur `lucide-react`, `~/src/routes` und `~/src/data/navigation.constants`, weil das Remotion-Projekt das Admin-Menü liest, wenn nur die eigenen Pakete von Remotion installiert sind.
- **Live-Checks gehören nach `src/lib/deployment.ts`**, als `LIVE_SITE_CHECKS` neben `verifyDeployment`, das sie abruft.
- **Die Berechtigungs-Statements jedes Bereichs gehören nach `src/areas/<area>.access.ts`**, in eine eigene Datei, damit ein Mensch jede Änderung daran prüft.
- **Generierte Dateien werden nicht von Hand bearbeitet.** Das Router-Plugin schreibt `src/routeTree.gen.ts`, `bun run cf-typegen` schreibt `src/types/worker-configuration.d.ts`, und `bun run content` sowie `bun run generate:cn` schreiben `.source/`.
