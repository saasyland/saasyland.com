## What MakerKit does better

If MakerKit is on your shortlist, you are looking at one of the most serious products in this category, and it deserves to be described properly before anything is compared with it.

**It ships, and it has for years.** Giancarlo Buomprisco has maintained MakerKit full-time since 2022; its homepage counts 66 changelog releases since May 2024. The TanStack Start kit arrived on 9 July 2026, in Drizzle, Prisma and Supabase variants, and you can clone any of them today.

**Teams and per-seat billing in the first release.** Personal and team accounts, invitations and role-based access control are modelled in the database. Billing covers flat, per-seat and metered plans with Stripe or Polar on the Drizzle and Prisma variants, and Stripe on Supabase. The super admin can see users, organizations and subscriptions, impersonate a user and ban an account. If your first customer is a company with ten seats, all of that is written already.

**Choice, under one licence.** A licence is sold per data layer, Supabase, Drizzle or Prisma 7, and includes that kit for both Next.js and TanStack Start; the Supabase licence adds React Router. The Supabase variant enforces tenant isolation with Postgres row-level security and tests it with pgTAP.

**Tooling for coding agents.** The kits ship `AGENTS.md`, `CLAUDE.md`, Claude Code skills such as `/reviewer` and `/bug-hunt`, and an MCP server; the Supabase kit adds `/rls-review`, which writes cross-tenant attacks as pgTAP tests and runs them.

**Documentation.** MakerKit’s homepage says the Next.js Supabase kit "alone has more than 170 pages", and each TanStack Start variant has its own full set.

Anyone telling you MakerKit is a template with a price tag has not read it. The rest of this article compares two credible options.

## What you can read before you pay

This is the difference the title is about, and it is a difference in kind rather than in degree.

MakerKit’s paid kits live in private GitHub repositories. You are invited after checkout, and the licence forbids publishing the code under an open-source licence or making it "publicly available in any form". Before you buy, you can read the documentation, try the demo and clone **MakerKit Lite**, which is free, MIT licensed and has "the same Turborepo structure and conventions as the paid kits, without billing, teams, or the admin panel". That is a fair sample of the conventions. It is not the code you will be paying for, and MakerKit does not offer refunds for source-code purchases, so the sample is what you decide on.

SaaSy Land’s CLI and its templates are proprietary too. What is public is everything else: the source of saasyland.com is under the MIT licence, and it is the whole application rather than a reduced edition. TanStack Start on a Cloudflare Worker, D1 through Drizzle, Better Auth with two-factor, the admin console, the customer workspace, Polar checkout and webhooks, the licence API, React Email through Resend, the documentation in <RepositoryFact name="languages" /> languages and the tests behind the coverage gate. Project generation, when it arrives, writes projects from the same code. You can read all of it, run it and decide whether you would want to work in it, and if you buy and have not used your licence, you can have a full refund within <RepositoryFact name="refundWithdrawalDays" unit="day" />.

If you are the kind of engineer who reads the source before adopting a dependency, that is a different way to buy a starter kit.

## Developers, machines and clients

The two licences count different things, and which one suits you depends on how your team works.

**MakerKit counts people.** Its licence names two kinds: a Developer licence, which "grants permission to one individual", and a Team licence for "Employees and Contractors of the Licensee, up to the number of Seats purchased", sold with up to five. Both allow unlimited products of your own. The Developer licence "does not permit building End Products for Clients under any circumstances"; the Team licence does, provided that every client who receives the source code holds their own MakerKit licence. The licence also forbids competing starter kits, open-source publication and AI training on the code, while explicitly allowing AI coding assistants.

**SaaSy Land counts machines.** A licence covers the purchasing person or company and the people working for it, and each key runs the CLI on <ActivationLimit tier="core" /> machines at a time on Core, <ActivationLimit tier="complete" /> on Complete and <ActivationLimit tier="agency" /> on Agency; a machine released on the licence page frees its slot. Core and Complete cover your own products. Agency also covers applications built for clients and lets you deliver a generated application and its source to the client it was built for, without the client buying anything. Neither side lets you resell the code as a starter kit. The full terms are on the [licence](/licence) page.

For a solo developer the difference rarely matters. For a team that freelances or builds for clients, the client-licence requirement is the line to price in, because it applies to every client who receives the code.

## Tests: a Playwright suite, or a gate on every branch

MakerKit’s TanStack Start kit uses "Playwright for E2E tests in apps/e2e; Vitest for package-level unit tests", and its FAQ says the core flows, "auth, billing, members, roles, admin impersonation", are covered by the Playwright suite. The Supabase variant adds pgTAP tests that run inside the database. That is more than most of the category has, and the pgTAP tests in particular catch the tenant-isolation bugs that matter most in B2B software.

What the documentation also says is that "there is no repo-wide (root) test:unit:coverage script". Nothing in the documented setup stops an untested branch from being merged.

That is the difference here. This repository’s `vite.config.ts` holds four numbers:

```ts
coverage: {
  thresholds: {
    branches: 100,
    functions: 100,
    lines: 100,
    statements: 100,
  },
}
```

All four are enforced, across <RepositoryFact name="testFiles" /> test files today, alongside <RepositoryFact name="e2eSpecs" /> Playwright specs that run in Chromium and WebKit. An end-to-end suite proves that the paths you wrote tests for work; a branch-coverage gate makes it impossible to merge the error path nobody tested, such as the webhook with a bad signature, the expired invitation or the permission check that returns false. We wrote more about why that matters for coding agents in [repository readiness for AI coding agents](/blog/ai-coding-agents-repository-readiness).

## Where it runs: a Node host or a Cloudflare Worker

MakerKit’s TanStack Start kit "builds a server bundle (via Vite + Nitro) that you run with Node", with Railway and Docker guides for the Drizzle and Prisma variants and Vercel, Cloudflare and VPS guides for Supabase. MakerKit has also announced a Cloudflare kit on Void, React, Vite+, Better Auth and Drizzle on Postgres, sold separately from the Drizzle kit and marked "Coming soon" on the day of checking.

SaaSy Land is built for Cloudflare Workers today. This site runs on a Worker with D1 as its database and KV and R2 beside it, and the first release of project generation targets the same platform. There is no server to provision or patch, and the data model is written for SQLite on D1 from the first migration. If your hosting is already decided and it is a Node host, MakerKit fits it better; if it is Cloudflare, SaaSy Land is built for it rather than adapted to it. The [Cloudflare Workers documentation](/docs/integrations/cloudflare-workers) shows how this site uses it.

## Languages

MakerKit’s TanStack Start kit uses use-intl, the same library as SaaSy Land, with only English enabled by default.

SaaSy Land runs in <RepositoryFact name="languages" /> languages today, interface and documentation alike, and a check fails CI when a key is missing in any of them or a translation drops one of its placeholders. If you sell outside the English-speaking world, that is work you do not start from zero.

## Updates: a git upstream, or a regenerated diff

MakerKit’s updates arrive through git. You add the private repository as an upstream remote and run `git pull upstream main`, and the documentation advises you to "opt for merging instead of rebasing". MakerKit’s CLI and its MCP server can pull upstream updates and help resolve merge conflicts. It is a well-supported version of the model most paid kits use, and its limit is the model’s: the more you have customised, the larger each merge.

SaaSy Land’s CLI reserves an `update` command for a different model: a diff for the modules you generated, against a baseline you can regenerate with the same answers. Like project generation, it is not available yet, and no starter kit makes updates free once you have edited the files. Lifetime core updates are part of every tier.

## Who should buy MakerKit

Buy MakerKit if your first release needs teams, roles and per-seat billing, because it has them today and SaaSy Land does not. Buy it if you want Supabase with row-level security and pgTAP tests, or Next.js and TanStack Start under one licence. Buy it if you deploy to a Node host, if you want the most complete documentation in the category, or if a direct line to the author on Discord is worth paying for. And buy it if you need to start this week, because its kits ship today.

It is a good product, maintained by someone who works on it full-time, and it will not embarrass you.

## Who should look at SaaSy Land instead

Look at SaaSy Land if you want to read the complete source of a production app before you decide, and to get your money back if you change your mind before using it. If Cloudflare Workers with D1 is your target. If you want a <RepositoryFact name="coverageThreshold" />% coverage gate and <RepositoryFact name="languages" /> languages to be where your project starts. If a licence counted in machines suits your team better than one counted in developers, or you build for clients and would rather they did not each need a licence of their own.

And look at it knowing what it is today: a licence for a CLI in beta, whose project generation is arriving, beside an MIT codebase you can read now. The [CLI documentation](/docs/cli) says what works today, and the [roadmap](/docs/project/roadmap) says what follows.
