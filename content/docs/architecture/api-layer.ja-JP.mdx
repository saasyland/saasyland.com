---

アプリケーション自身の処理はサーバー関数で実装します。HTTP ハンドラーを置くのは、アプリケーションの RPC クライアント以外のものが URL を呼び出す場合だけです。具体的には、Better Auth のブラウザクライアント、OAuth プロバイダー、Polar の Webhook、ドキュメントの検索ボックスです。

| ファイル                   | パス          | メソッド  | 処理内容                                                                                                                           |
| -------------------------- | ------------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `src/routes/api/index.ts`  | `/api`        | GET       | JSON のステータスレスポンス `{ runtime: "cloudflare-workers" }`                                                                    |
| `src/routes/api/auth.$.ts` | `/api/auth/*` | GET, POST | OAuth コールバック、メール認証、Polar のカスタマーポータル、`/api/auth/polar/webhooks` を含む Better Auth のすべてのエンドポイント |
| `src/routes/api/search.ts` | `/api/search` | GET       | ドキュメントを対象とした Fumadocs の検索                                                                                           |

ハンドラーは `createFileRoute` の `server.handlers` で宣言します。Web API の `Request` を受け取り、`Response` を返します。

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## ルール

- このアプリケーションからしか呼ばれない処理のために REST エンドポイントを追加しないでください。代わりに `createServerFn` でユースケースを書きます。そうすれば、型付きの入力、ミドルウェア、クエリオプションを利用できます。
- ハンドラーは入力の検証と権限のチェックを自分で行います。サーバー関数のミドルウェア（`authorized`、`withRateLimit`）はハンドラーでは実行されません。
- ベンダー固有の検証はインテグレーション内に置きます。Polar の Webhook 署名は、独自のハンドラーではなく、Better Auth 内の Polar プラグインが検証します。
- `/api` のパスはローカライズもプリレンダリングもされず、Worker のロケール処理もスキップします。
