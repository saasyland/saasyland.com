---
title: "Matrice dei permessi"
description: "Ruoli, statement dei permessi e server function che li controllano."
---

Ruoli e permessi sono definiti in `src/integrations/better-auth/auth.access.ts` con il controllo degli accessi di Better Auth. Le stesse definizioni vengono usate dal server (`authorized`, guard delle route) e dal client di Better Auth.

## Ruoli

| Ruolo   | Codice     | Permessi                                                                                                            |
| ------- | ---------- | ------------------------------------------------------------------------------------------------------------------- |
| Admin   | `admin`    | Tutti gli statement dell'applicazione elencati sotto, più gli statement admin di Better Auth per `user` e `session` |
| Cliente | `customer` | Nessuno. I clienti possono chiamare le server function che richiedono solo una sessione.                            |

I nuovi utenti ricevono il ruolo `customer` (`DEFAULT_ROLE_CODE`).

## Statement

Statement dell'applicazione (`APP_STATEMENTS`):

| Risorsa    | Azioni                                          |
| ---------- | ----------------------------------------------- |
| `admin`    | `access`                                        |
| `category` | `create`, `read`, `update`, `delete`            |
| `course`   | `create`, `read`, `update`, `delete`            |
| `order`    | `read`, `update`, `refund`                      |
| `product`  | `create`, `read`, `update`, `delete`, `publish` |
| `settings` | `manage`                                        |
| `video`    | `read`, `delete`                                |

Statement di Better Auth concessi agli admin:

| Risorsa   | Azioni                                                                                                                  |
| --------- | ----------------------------------------------------------------------------------------------------------------------- |
| `user`    | `create`, `list`, `set-role`, `ban`, `impersonate`, `delete`, `set-password`, `set-email`, `set-phone`, `get`, `update` |
| `session` | `list`, `revoke`, `delete`                                                                                              |

## Dove vengono controllati i permessi

| Permesso                      | Controllato da                                                                                                                                                             |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `admin: ["access"]`           | `requireAdmin` sul layout `/admin` e il reindirizzamento dopo l'accesso                                                                                                    |
| Azioni di `category`          | I casi d'uso delle categorie: `read`, `create`, `update`, `delete`                                                                                                         |
| `course: ["read"]`            | `resolveViewer` (`lesson.viewer.ts`): chi lo ha vede ogni lezione in `get-course`, `get-lesson-playback` e `save-lesson-progress`, qualunque sia il suo livello di accesso |
| Azioni di `product`           | I casi d'uso dei prodotti: `read`, `create`, `update`, `delete`                                                                                                            |
| Azioni di `video`             | `get-videos` e `get-video-playback` (`read`), `delete-video` (`delete`)                                                                                                    |
| Azioni di `user`              | I casi d'uso degli utenti, un'azione ciascuno; `ban` copre sia `ban-user` sia `unban-user`                                                                                 |
| Azioni di `session`           | `list-user-sessions` (`list`), `revoke-user-session` e `revoke-user-sessions` (`revoke`)                                                                                   |
| Una sessione, nessun permesso | I casi d'uso di account, licenza, autenticazione a due fattori, preferenze della newsletter e sessioni proprie, oltre a `stop-impersonating-user` e `save-lesson-progress` |

`order`, `product: ["publish"]`, `settings` e `course: ["create", "update", "delete"]` sono dichiarati ma non ancora controllati da alcuna server function.

## Controllare un permesso

Le server function usano il middleware, ad esempio `authorized({ category: ["read"] })`. Il resto del codice chiama `hasPermission`, come fanno le guard delle route:

```ts
const isAdmin = (role: string | null | undefined): boolean => hasPermission({ permission: { admin: ["access"] }, role })

export const requireAdmin = async (context: ProtectedRouteContext) => {
  const result = await requireSignedIn(context)
  if (!isAdmin(result.session.user.role)) {
    throw redirect({ replace: true, to: ROUTES.APP })
  }
  return result
}
```
