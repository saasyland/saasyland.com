## Estrutura administrativa

`src/routes/admin.tsx` protege todas as páginas administrativas com `requireAdmin` e pré-carrega os namespaces compartilhados. O layout mostra:

- `AdminSidebar`, `AdminBreadcrumbs` e `AdminCommandPalette` (aberta com ⌘K), todos montados a partir de `ADMIN_NAVIGATION` em `src/data/navigation.ts`, que agrupa os itens que as áreas fornecem, cada um com o seu ícone: Visão geral (Painel, Análise de dados), Ofertas (Produtos, Modelos de preço), Conteúdo (Blog, Cursos, Vídeos, Landing page) e Administração (Gestão de usuários, Pagamentos, Configurações).
- O widget do usuário no rodapé da barra lateral, com um link para as configurações e `SignOutButton`.

## Painel

`/admin` (`src/routes/admin.index.tsx`) pré-carrega no loader `getUsersQuery` e, pelo `prefetch` de cada uma, a query de cada estatística do painel e de cada painel que lê dados, e compõe os widgets de `src/presentation/components/custom/admin/dashboard` com os painéis que as áreas adicionam:

- `DashboardActions`: um link para cada item de `ADMIN_DASHBOARD_ACTIONS` na ordem do seu `order`, como **Adicionar produto**, de `src/data/products.navigation.ts`, com o rótulo de `navigation.products.json`.
- `DashboardStats` (real): as estatísticas de `ADMIN_DASHBOARD_STATS`, os itens de `src/data/<area>.dashboard.ts` posicionados como `DASHBOARD_PLACEMENT.STAT`, na ordem do seu `order`: o número de usuários e os usuários aguardando verificação de e-mail, de `src/data/auth.dashboard.ts`, e o número de produtos, de `src/data/products.dashboard.ts`, cada uma com o rótulo do `dashboard.<area>.json` da sua área.
- Os painéis de `ADMIN_DASHBOARD_PANELS`, os itens posicionados como `DASHBOARD_PLACEMENT.PANEL`, na ordem do seu `order`, cada um com o esqueleto que `AdminDashboardPending` mostra para ele:
  - a área de licenças adiciona `UnlicensedOrders` (real) em `src/data/license.dashboard.ts`: os pedidos de licença pagos que não têm licença, cada um com um link para o pedido no Polar, ou uma linha dizendo que não há nenhum, com os rótulos de `dashboard.license.json` (veja [Licenças](/docs/features/licences#orders-that-match-no-account));
  - a área de pagamentos adiciona `RevenueChart` (demonstração) em `src/data/payments.dashboard.ts`, um SVG estático com eixos fixos e rótulos de `dashboard.payments.json`; os botões de período não fazem nada.
- Um card de usuários (real): os usuários mais recentes com filtros de busca e de status, <RepositoryFact name="adminPreviewPageSize" /> linhas por página. Cada nome leva ao perfil do usuário, onde ficam as ações.

```tsx
<DataTable
  columns={dashboardUserColumns}
  data={users.rows}
  filters={[
    { columnId: "user", placeholder: t("users.search"), type: "search" },
    {
      columnId: "status",
      label: t("users.filters.status"),
      options: USER_STATUSES.map((status) => ({ label: t(`users.table.status.${status}`), value: status })),
      type: "select",
    },
  ]}
  options={{ initialState: { pagination: ADMIN_DASHBOARD_PREVIEW_PAGINATION }, selectable: true }}
/>
```

A tabela trabalha no navegador com a primeira página de `getUsersQuery` (<RepositoryFact name="defaultPageSize" /> usuários). **Ver todos** leva a `/admin/users`. **Adicionar produto**, o item da área de produtos em `ADMIN_DASHBOARD_ACTIONS`, leva a `/admin/products/create`.
