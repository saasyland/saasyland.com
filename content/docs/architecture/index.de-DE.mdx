SaaSy Land ist eine einzige TanStack-Start-Anwendung, die als Cloudflare Worker läuft. Der Code ist nach Zuständigkeiten aufgeteilt:

- **Routen** (`src/routes`) setzen Seiten zusammen. Eine Routendatei deklariert ihre Übersetzungs-Namespaces, ihren Guard, ihren Loader und ihre Head-Tags und rendert anschließend Komponenten.
- **Module** (`src/modules/<table>`) gibt es nur für echte Datenbanktabellen. Ein Modul besitzt das Drizzle-Schema der Tabelle, ihre Zod-Schemas, Konstanten und Typen sowie die Use Cases, die die Tabelle lesen oder ändern.
- **Integrationen** (`src/integrations/<vendor>`) konfigurieren Bibliotheken und Dienste von Drittanbietern.
- **Präsentation** (`src/presentation`) enthält die shadcn-Primitives, Anwendungskomponenten, React-Email-Templates, Styles, Theme und Branding.
- **Gemeinsamer Code** liegt in `src/data` (Daten, die mehrere Dateien nutzen), `src/lib` (kleine Hilfsfunktionen), `src/hooks` und `src/providers`.

```text
src/
├── routes/          Flat file routes that compose pages
├── modules/         One folder per database table, plus _core
├── integrations/    One folder per vendor
├── presentation/    Components, emails, styles, theme, branding
├── data/            Data shared by several files
├── lib/             Small shared utilities
├── hooks/           Shared React hooks
├── providers/       Application providers
├── platform/        Test runtime wiring
├── types/           Global type declarations
├── router.tsx       Router and per-request QueryClient
├── routes.ts        ROUTES path constants
└── server.ts        Cloudflare Worker entry
```

## Regeln, die den Code prägen

- Routendateien setzen nur zusammen. Widgets, Dialoge, Formulare und Tabellenspalten liegen in `src/presentation/components/custom`, jeweils eines pro Datei.
- Komponenten lesen ihre Übersetzungen und Daten selbst, mit `useTranslations`, `useSuspenseQuery` oder den Loader-Daten der Route. Routen reichen weder Beschriftungen noch Daten als Props nach unten durch.
- Eine Server Function, die mit einer Tabelle arbeitet, ist ein Use Case im Modul dieser Tabelle. Eine Server Function, die nur eine einzige Route nutzt, darf in der Routendatei definiert werden. Alles andere gehört nach `src/lib`.
- Es gibt keinen Dependency-Injection-Container und keine Wrapper-Schicht. Importiere die konkrete Funktion aus dem Ordner, dem sie gehört.
- Eine Konstante, die nur eine Datei nutzt, bleibt in dieser Datei. Nur Daten, die mehrere Dateien teilen, wandern nach `src/data`.
