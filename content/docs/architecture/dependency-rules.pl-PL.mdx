## Kierunki importów

| Folder                    | Może importować                                                                                                  | Nie może importować                                       |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| `src/routes`              | warstwę prezentacji, opcje zapytań i mutacji modułów, integracje (guardy, i18n, Fumadocs), `src/data`, `src/lib` | klientów bazy danych ani dostawców poza funkcją serwerową |
| `src/presentation`        | opcje modułów, schematy Zod, stałe i typy, hooki, `src/data`, `src/lib`, integracje bezpieczne dla przeglądarki  | `db`, `auth` z `auth.server.ts`, Polar, Resend            |
| `src/modules/*/use-cases` | integracje (`db`, `auth`, `sendEmail`, `polar`), `_core`, schematy modułów, szablony e-maili                     | komponentów                                               |
| `src/integrations`        | `_core`, schematy modułów i przypadki użycia, które dostawca wywołuje zwrotnie                                   | komponentów                                               |
| `src/server.ts`           | helpery locale, cookies, stałe `_core`, `MEDIA_PATH_PREFIX`, zasoby dokumentu                                    | bazy danych, Better Auth ani Polar SDK                    |

Do integracji bezpiecznych dla przeglądarki należą `i18n.paths.ts`, `i18n.utils.ts`, `auth.client.ts`, `auth.access.ts` i `form.fields.ts`.

## Granice kodu serwerowego

- **Funkcje serwerowe.** TanStack Start usuwa z bundla przeglądarki każdy handler `createServerFn` i zastępuje wywołanie żądaniem RPC. Dlatego komponent może zaimportować `createCategoryMutation` z tego samego pliku, który importuje `db`.
- **Moduły wyłącznie serwerowe.** Pliki, które odczytują sekrety lub bindingi, zaczynają się od `import "@tanstack/react-start/server-only"`, co wyklucza je z builda klienta. Przykłady: `drizzle.database.ts`, `auth.server.ts`, `polar.config.ts`, `resend.utils.ts`, `src/lib/rate-limit.ts` i `i18n.middleware.ts`. Wyjątkiem są pliki eksportujące funkcję serwerową, takie jak `src/lib/github.ts` i `deactivate-license.ts`: komponenty importują je dla wywołania RPC, więc odczytują one `env` tylko w handlerze i w helperach, które on wywołuje, a te build pomija w bundlu klienta.
- **Funkcje zależne od środowiska.** `createServerOnlyFn` opakowuje kod, który działa tylko na serwerze (`getRequestSession`). `createIsomorphicFn` dostarcza osobne implementacje dla serwera i przeglądarki (`getCurrentLocale`, `getCookie`).
- **Bindingi i sekrety** pochodzą z `env` w `cloudflare:workers` i odczytuje je wyłącznie kod serwerowy: moduły wyłącznie serwerowe, handlery funkcji serwerowych i helpery importowane tylko przez nie. `scripts/verify-build.ts` przerywa build, gdy zasób klienta importuje `cloudflare:workers`.
- **Punkt wejścia Workera.** `src/server.ts` działa przy każdym żądaniu z wyjątkiem `/assets/*`, `/fonts/*`, `/robots.txt` i `/llms.txt`, które `run_worker_first` w `wrangler.jsonc` serwuje bezpośrednio z zasobów statycznych. Ma niewiele statycznych importów: `serveMedia` ładuje dynamicznym `import()` tylko dla ścieżek `/media/`, a handler TanStack Start dopiero wtedy, gdy nie pasuje żaden zasób statyczny.

```ts
import "@tanstack/react-start/server-only"

import { env } from "cloudflare:workers"

import { drizzle } from "drizzle-orm/d1"

import * as schema from "~/src/integrations/drizzle-orm/drizzle.schemas"

export const db = drizzle(env.DB, { schema })
```
