Środowisko `preview` wdraża Workera `saasyland-preview` pod adresem `preview.saasyland.com`. Domyślnie `development` i `preview` współdzielą jedną bazę D1, jedną przestrzeń nazw KV i jeden bucket R2.

## Przygotowanie zasobów

```sh
bunx wrangler login
bunx wrangler d1 create saasyland_com_preview
bunx wrangler kv namespace create CACHE --env preview
bunx wrangler r2 bucket create saasyland-preview
```

W `wrangler.jsonc` zastąp `database_id`, `database_name`, `id` przestrzeni KV i `bucket_name` bindingu `MEDIA` zarówno w bloku `development`, jak i `preview`. Zachowaj nazwy bindingów `DB`, `CACHE` i `MEDIA` oraz `migrations_dir`, a nazwy Workerów i trasy domen niestandardowych dostosuj do swojego konta. Dla produkcji utwórz osobne zasoby, w tym bucket `saasyland`, i zaktualizuj blok `production`. Ustaw `APP_DOMAIN` w `src/presentation/branding/index.ts`. `DEPLOYED_HOSTS` w `src/modules/_core/constants/api.ts` wyprowadza z tej stałej wdrożone hosty, `APP_DOMAIN` dla produkcji i `preview.<APP_DOMAIN>` dla preview, i jest jedynym miejscem, w którym kod je nazywa: `appHostsForMode` odczytuje z niego hosty akceptowane przez Better Auth i linki newslettera, a `scripts/verify-deployment.ts` wysyła do nich żądanie po wdrożeniu. Lokalnie `appHostsForMode` akceptuje `localhost:3000` lub `127.0.0.1:3000` w trybie deweloperskim, a w testowym te hosty oraz `localhost:3020` i `127.0.0.1:3020`. `DEPLOYED_HOSTS` edytuj tylko wtedy, gdy Twój host preview ma inną nazwę. Trasy domen niestandardowych (`routes`) w `wrangler.jsonc` i adresy URL środowisk w `.github/workflows/deploy-reusable.yml` wskazują te same hosty, więc zmieniaj je razem.

## Wdrożenie

Uzupełnij `.env.preview`, a następnie wdróż aplikację:

```sh
bun run deploy:preview
```

`deploy:preview` uruchamia `scripts/verify-bindings.ts preview`, który odrzuca brakujące bindingi i zastępcze identyfikatory, następnie `build:preview`, który prerenderuje strony publiczne i weryfikuje wynik. Potem `scripts/prepare-deploy-secrets.ts preview` zapisuje sekrety, które `wrangler.jsonc` deklaruje dla `preview`, z `.env.preview` do `.wrangler/secrets.preview.json` i kończy się błędem, jeśli któryś z nich jest pusty. `db:migrate:preview` stosuje nowe migracje, zanim `wrangler deploy` prześle `dist/server/wrangler.json` z tymi sekretami, a na końcu `scripts/verify-deployment.ts preview` sprawdza, czy host preview z `DEPLOYED_HOSTS` (https://preview.saasyland.com) odpowiada. `verify-bindings.ts` nie sprawdza, czy bucket R2 istnieje, ponieważ jest wiązany po nazwie: wdrożenie kończy się błędem, dopóki ten bucket nie istnieje. `bun run db:migrations:preview` wyświetla migracje, których baza danych preview jeszcze nie zastosowała.

Zarejestruj adresy zwrotne OAuth i webhook Polar dla hosta preview zgodnie z listą w [Zmiennych środowiskowych](/docs/getting-started/environment-variables).

## Automatyczne wdrożenia

Po pomyślnym przejściu kontroli i testów przeglądarkowych CI wdraża każdy pull request z gałęzi w tym repozytorium do współdzielonego środowiska preview, a każdy push do `main` na produkcję. Wymagane sekrety GitHub opisuje strona [CI/CD](/docs/tooling/ci-cd).
