Playwright тестує зібраний застосунок у справжніх браузерах. Набір тестів працює із середовищем Wrangler `test`: локальні D1 і KV у `.wrangler/test`, фіктивні облікові дані з `.env.test` і тестова точка входу `src/platform/testing/worker.ts`, яка перехоплює запити до Resend і Polar.

```sh
bun run test:e2e:install
bun run test:e2e
bun run test:e2e:smoke
bun run test:e2e:pr
bun run test:e2e:headed
bun run test:e2e:ui
```

| Скрипт             | Що запускає                                                   |
| ------------------ | ------------------------------------------------------------- |
| `test:e2e:install` | Встановлює Chromium і WebKit разом із системними залежностями |
| `test:e2e`         | Усі специфікації в Chromium і WebKit                          |
| `test:e2e:smoke`   | `e2e/specs/smoke.spec.ts` у Chromium                          |
| `test:e2e:pr`      | Усі специфікації в Chromium, як у CI для pull request         |
| `test:e2e:headed`  | Усі специфікації у видимих браузерах                          |
| `test:e2e:ui`      | Режим UI Playwright                                           |

## Конфігурація

`playwright.config.ts` визначає проєкти `chromium` (Desktop Chrome) і `webkit` (Desktop Safari) та використовує `PLAYWRIGHT_BASE_URL` або `http://127.0.0.1:3000`. Локально команда вебсервера запускає `db:migrate:test`, `db:seed:test`, `build:test` і `start:test` та повторно використовує сервер, який уже відповідає за цією адресою, тож спершу зупиніть інші сервери на порту 3000. У CI збірку готує workflow, а Playwright лише запускає сервер.

| Параметр   | Локально              | CI                      |
| ---------- | --------------------- | ----------------------- |
| Повтори    | 0                     | 2                       |
| Воркери    | 1                     | 2                       |
| Трасування | Зберігаються при збої | Під час першого повтору |
| Відео      | Вимкнено              | Зберігаються при збої   |
| Звіт       | List і HTML           | GitHub і HTML           |

## Структура

- `e2e/specs/`: специфікації для smoke-перевірок, лендингу, навігації, локалей, автентифікації, робочих просторів, розсилки, контенту, теми та регіональних цін.
- `e2e/pages/`: об'єкти сторінок (page objects).
- `e2e/fixtures/`: розширена фікстура `test` і помічники для перехоплених листів.
- `e2e/data/accounts.ts`: засіяні облікові записи адміністратора й клієнта та їхній пароль.

Тестовий Worker відкриває `/__test/emails` для читання листів, перехоплених моком Resend, і `/__test/newsletter` для читання стану підписника.
