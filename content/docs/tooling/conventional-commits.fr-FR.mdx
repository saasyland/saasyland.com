---
title: "Commits conventionnels"
description: "Format des messages de commit et hook d'emoji."
---

Les sujets de commit suivent le format `<type>(<scope>): <description>`. La portée est facultative et `!` signale un changement incompatible. Écrivez le sujet sans emoji :

```sh
git commit -m "fix(auth): keep the locale in verification links"
```

Le hook `prepare-commit-msg` de `.vite-hooks/` exécute `bun scripts/commit-msg.ts`, qui valide le sujet et le préfixe de l'emoji correspondant à son type ; le commit ci-dessus devient ainsi `🐛 fix(auth): keep the locale in verification links`.

| Type       | Emoji |
| ---------- | ----- |
| `build`    | 🛠️    |
| `chore`    | ♻️    |
| `ci`       | ⚙️    |
| `docs`     | 📚    |
| `feat`     | ✨    |
| `fix`      | 🐛    |
| `perf`     | 🚀    |
| `refactor` | 📦    |
| `revert`   | 🗑️    |
| `style`    | 💎    |
| `test`     | 🚨    |

Tout autre type, ou un sujet qui ne respecte pas le format conventionnel, interrompt le commit en affichant la liste des types autorisés. Le hook ne modifie pas les sujets qui commencent déjà par un emoji, ceux générés par Git (`Merge`, `Revert "`, `fixup!`, `squash!`), ni les messages de merge, de squash et de modèle.

Avant le hook de message, le hook `pre-commit` exécute `bun run check:pre-commit`. Ne contournez pas les hooks.
