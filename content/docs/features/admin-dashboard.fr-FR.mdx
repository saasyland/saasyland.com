## Structure d’administration

`src/routes/admin.tsx` protège toutes les pages d’administration avec `requireAdmin` et précharge les espaces de noms communs. Le layout affiche :

- `AdminSidebar`, `AdminBreadcrumbs` et `AdminCommandPalette` (ouverte avec ⌘K), tous construits à partir de `ADMIN_NAVIGATION` dans `src/data/navigation.ts`, qui regroupe les entrées apportées par les zones, chacune avec son icône : Vue d’ensemble (Tableau de bord, Analytique), Offres (Produits, Modèles de tarification), Contenu (Blog, Cours, Vidéos, Page d’accueil) et Administration (Gestion des utilisateurs, Paiements, Paramètres).
- Le widget utilisateur en bas de la barre latérale, avec un lien vers les paramètres et `SignOutButton`.

## Tableau de bord

`/admin` (`src/routes/admin.index.tsx`) précharge dans son loader `getUsersQuery` et, par leur `prefetch`, la requête de chaque statistique du tableau de bord et de chaque panneau qui lit des données, et compose les widgets de `src/presentation/components/custom/admin/dashboard` avec les panneaux qu’ajoutent les zones :

- `DashboardActions` : un lien pour chaque entrée de `ADMIN_DASHBOARD_ACTIONS` dans l’ordre de leur `order`, comme **Ajouter un produit**, issu de `src/data/products.navigation.ts`, avec le libellé de `navigation.products.json`.
- `DashboardStats` (réel) : les statistiques de `ADMIN_DASHBOARD_STATS`, les entrées de `src/data/<area>.dashboard.ts` placées en `DASHBOARD_PLACEMENT.STAT`, dans l’ordre de leur `order` : le nombre d’utilisateurs et les utilisateurs en attente de vérification de leur e-mail, issus de `src/data/auth.dashboard.ts`, et le nombre de produits, issu de `src/data/products.dashboard.ts`, chacune avec le libellé du `dashboard.<area>.json` de sa zone.
- Les panneaux de `ADMIN_DASHBOARD_PANELS`, les entrées placées en `DASHBOARD_PLACEMENT.PANEL`, dans l’ordre de leur `order`, chacun avec le squelette qu’affiche `AdminDashboardPending` pour lui :
  - la zone des licences ajoute `UnlicensedOrders` (réel) dans `src/data/license.dashboard.ts` : les commandes de licence payées qui n’ont pas de licence, chacune avec un lien vers la commande dans Polar, ou une ligne indiquant qu’il n’y en a aucune, avec les libellés de `dashboard.license.json` (voir [Licences](/docs/features/licences#orders-that-match-no-account)) ;
  - la zone des paiements ajoute `RevenueChart` (démo) dans `src/data/payments.dashboard.ts`, un SVG statique aux axes fixes dont les libellés viennent de `dashboard.payments.json` ; les boutons de période ne font rien.
- Une carte des utilisateurs (réelle) : les utilisateurs les plus récents avec filtres de recherche et de statut, <RepositoryFact name="adminPreviewPageSize" /> lignes par page. Chaque nom renvoie vers le profil de l’utilisateur, où se trouvent les actions.

```tsx
<DataTable
  columns={dashboardUserColumns}
  data={users.rows}
  filters={[
    { columnId: "user", placeholder: t("users.search"), type: "search" },
    {
      columnId: "status",
      label: t("users.filters.status"),
      options: USER_STATUSES.map((status) => ({ label: t(`users.table.status.${status}`), value: status })),
      type: "select",
    },
  ]}
  options={{ initialState: { pagination: ADMIN_DASHBOARD_PREVIEW_PAGINATION }, selectable: true }}
/>
```

Le tableau travaille dans le navigateur sur la première page de `getUsersQuery` (<RepositoryFact name="defaultPageSize" /> utilisateurs). **Tout voir** renvoie vers `/admin/users`. **Ajouter un produit**, l’entrée de la zone des produits dans `ADMIN_DASHBOARD_ACTIONS`, renvoie vers `/admin/products/create`.
