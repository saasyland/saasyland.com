`wrangler.jsonc` definiert vier Umgebungen. `CLOUDFLARE_ENV` wählt eine davon für den Dev-Server und die Builds aus, und jede liest ihre Secrets aus ihrer eigenen Umgebungsdatei:

| Umgebung      | Ausgewählt durch                              | Bindings                             | Secrets aus        |
| ------------- | --------------------------------------------- | ------------------------------------ | ------------------ |
| `development` | `bun run dev`                                 | Entfernte Preview-D1 und -KV         | `.env.development` |
| `preview`     | `build:preview`, `deploy:preview`             | Preview-D1 und -KV                   | `.env.preview`     |
| `production`  | `build:production`, `deploy:production`       | Produktions-D1 und -KV               | `.env.production`  |
| `test`        | `build:test`, `start:test`, `db:migrate:test` | Lokale D1 und KV in `.wrangler/test` | `.env.test`        |

`.env.development`, `.env.preview` und `.env.production` werden von Git ignoriert; `.env.example` listet ihre Schlüssel auf. `.env.test` ist eingecheckt und enthält nur Platzhalterwerte. Die Deploy-Skripte laden die passende Datei mit `wrangler deploy --secrets-file` hoch.

## Secrets

Jede Umgebung führt ihre Secrets in `secrets.required` auf: die Schlüssel für Better Auth, OAuth, Resend und Polar sowie `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID` und `CLOUDFLARE_ACCESS_TOKEN` für die Drizzle-Werkzeuge (die Umgebung `test` lässt diese drei weg). Die einzelnen Schlüssel sind unter [Umgebungsvariablen](/docs/getting-started/environment-variables) beschrieben.

Servercode liest Secrets mit `import { env } from "cloudflare:workers"`. Keine Stelle verwendet eine `VITE_`-Variable, und keine darf ein Secret enthalten, weil Vite solche Variablen im Browser verfügbar macht. `scripts/verify-build.ts` lässt den Build fehlschlagen, wenn ein Client-Asset `cloudflare:workers` importiert. Die kanonische Domain stammt aus `APP_DOMAIN` in `src/presentation/branding/index.ts`, nicht aus einer Umgebungsvariablen.

## Bindings

| Binding  | Typ              | Verwendung                                                 |
| -------- | ---------------- | ---------------------------------------------------------- |
| `DB`     | D1               | Datenbank der Anwendung, Sitzungen und Ratenbegrenzung     |
| `CACHE`  | KV               | Anzahl der GitHub-Sterne                                   |
| `ASSETS` | Statische Assets | Vorab gerenderte Seiten, Schriften und öffentliche Dateien |

Die Entwicklung verwendet Remote-Bindings von Cloudflare, daher liest und schreibt `bun run dev` die Preview-Datenbank. Führen Sie nach einer Änderung der Bindings `bun run cf-typegen` aus, um `src/types/worker-configuration.d.ts` neu zu erzeugen.

## Tests

Vitest lädt `.env.test` über `test.env` und löst `cloudflare:workers` zu `src/platform/testing/mocks/cloudflare.ts` auf, das D1 und KV im Arbeitsspeicher bereitstellt. Playwright verwendet die Umgebung `test` und deren Einstiegspunkt `src/platform/testing/worker.ts`. Keines von beiden benötigt echte Zugangsdaten.
