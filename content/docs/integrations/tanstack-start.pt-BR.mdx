A aplicação é um app TanStack Start. `src/router.tsx` cria o roteador com um QueryClient por requisição, a integração de queries com SSR, componentes padrão de erro e de página não encontrada, pré-carregamento por intenção e o `rewrite` de locale. Não há componente de carregamento padrão: cada rota define o seu próprio esqueleto (veja [Esqueletos de carregamento](/docs/architecture/delivery-layer#esqueletos-de-carregamento)). `src/routes.ts` exporta `ROUTES`, as constantes de caminho usadas por links, guards e tags do head.

## Rotas

`src/routes/` contém rotas de arquivo planas: `admin.users.all.tsx` serve `/admin/users/all`, `_landing.tsx` é um layout sem caminho e `docs.$.tsx` é uma rota splat. O ID em `createFileRoute("…")` é uma string literal mantida pelo gerador de rotas em `src/routeTree.gen.ts`; pastas `__test__` são ignoradas como rotas.

Um arquivo de rota apenas compõe sua página. Ele define o componente `<Name>Page` ou `<Name>Layout`, `NAMESPACE` ou `NAMESPACES`, um loader que executa o carregamento de metadados, mensagens e dados em um único `Promise.all`, `head: pageHead(ROUTES.X)` e, nas áreas protegidas, um guard em `beforeLoad`. Widgets, diálogos, formulários e colunas de tabela ficam em `src/presentation/components/custom/` e leem as próprias traduções e dados. Veja [use-intl](/docs/integrations/use-intl) para o loader e [Better Auth](/docs/integrations/better-auth) para os guards.

## Server functions

As operações são funções `createServerFn` nativas exportadas pelos casos de uso dos módulos, portanto a aplicação não expõe um endpoint REST para elas. Veja [Server functions e casos de uso](/docs/integrations/server-functions).

## Handlers HTTP

Apenas três rotas declaram `server.handlers` em `src/routes/api/`:

| Rota          | Handler                                                                                     |
| ------------- | ------------------------------------------------------------------------------------------- |
| `/api`        | Retorna o runtime como JSON                                                                 |
| `/api/auth/$` | Better Auth, incluindo callbacks de OAuth e webhooks da Polar em `/api/auth/polar/webhooks` |
| `/api/search` | Busca da documentação do Fumadocs                                                           |

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Pré-renderização

`vite.config.ts` habilita a pré-renderização com rastreamento de links. `build:preview`, `build:production` e `build:test` pré-renderizam as páginas públicas (landing page, páginas legais, blog e documentação) nos nove locales. O filtro ignora `/admin`, `/api`, `/app`, `/auth` e `/newsletter`, com ou sem prefixo de locale, bem como links que contêm `?` ou `#`. As páginas ignoradas são renderizadas no Worker a cada requisição.
