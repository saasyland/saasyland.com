---
title: "Contribuir"
description: "Cómo proponer cambios en SaaSy Land."
---

1. Comente primero los cambios importantes en un issue.
2. Cree una rama a partir de `main`.
3. Siga la [arquitectura](/docs/architecture) y las [convenciones](/docs/reference/conventions), y lea la [skill para agentes](/docs/tooling/agent-skills) correspondiente antes de modificar una integración con un proveedor.
4. Mantenga las pruebas junto a su propietario y respete el umbral de cobertura del 100 %.
5. Ejecute las comprobaciones siguientes.
6. Haga commit con un mensaje de [commit convencional](/docs/tooling/conventional-commits) y abra una pull request con un título convencional.

```sh
bun run check
bun run test:coverage
bun run test:e2e:install
bun run test:e2e:smoke
```

Ejecute la suite completa de pruebas en el navegador (`bun run test:e2e`) para los cambios que afecten a varias rutas, a la autenticación o al comportamiento del navegador. Valide por separado las integraciones con proveedores reales cuando cambie su configuración.

Cuando cambie el comportamiento, actualice `content/docs` en los nueve idiomas; `bun run check:i18n` rechaza las traducciones que faltan y los bloques de código y la navegación que difieren. En la pull request, describa el comportamiento resultante, cómo lo ha verificado y cualquier flujo de demostración o sin terminar que quede.
