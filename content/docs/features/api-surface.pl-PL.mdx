Aplikacja udostępnia trzy trasy HTTP zadeklarowane przez `server.handlers` w `createFileRoute` w `src/routes/api`:

| Trasa         | Metody    | Handler                                                                                                                                                |
| ------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `/api`        | GET       | Zwraca `{ "runtime": "cloudflare-workers" }`.                                                                                                          |
| `/api/auth/$` | GET, POST | Better Auth: logowanie, powroty OAuth, `/api/auth/verify-email` oraz endpointy wtyczki Polar `/api/auth/polar/webhooks` i `/api/auth/customer/portal`. |
| `/api/search` | GET       | Wyszukiwarka Fumadocs (`fumadocs.search.ts`).                                                                                                          |

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Funkcje serwerowe zamiast REST

Operacje aplikacji to funkcje `createServerFn` w `src/modules/<table>/use-cases` (albo w jedynej trasie, która ich używa). TanStack Start wywołuje je przez RPC pod `/_serverFn`, z middleware dla sesji, uprawnień i limitów żądań. Nie dodawaj endpointu REST dla operacji, którą wywołuje tylko ta aplikacja; trasę HTTP dodawaj wyłącznie dla zewnętrznych wywołujących, takich jak webhooki, i weryfikuj ich podpisy w integracji dostawcy.

## Zachowanie

- Worker nie stosuje przekierowań językowych dla `/api` i `/_serverFn`; te żądania biorą język z ciasteczka.
- Build nie prerenderuje `/api`.
- Testy handlerów znajdują się w `src/routes/api/__test__/handlers.test.ts`.
