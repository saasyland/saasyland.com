## Query cache

`getRouter` creates a new `QueryClient` for every request, so no data leaks between users on the server. Defaults:

| Setting                          | Value                                                                                                                        |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Query `staleTime`                | <RepositoryFact name="queryStaleTimeMinutes" unit="minute" />                                                                |
| Query `gcTime`                   | <RepositoryFact name="queryGcTimeMinutes" unit="minute" />                                                                   |
| Router `defaultStaleTime`        | <RepositoryFact name="routerStaleTimeMinutes" unit="minute" />                                                               |
| Router `defaultPreloadStaleTime` | <RepositoryFact name="routerStaleTimeMinutes" unit="minute" />                                                               |
| Preloading                       | On intent, and the [header's pages](/docs/conventions/performance#the-headers-pages-load-before-a-click) once a page is idle |

Loaders fill the cache with `queryClient.query({ ...options, staleTime: "static" })` and components read the same keys with `useSuspenseQuery`. Course pages and the admin course editor are the exception: their queries keep `staleTime: COURSE_STALE_MS` (<RepositoryFact name="courseStaleMinutes" unit="minute" />), because `invalidateQueries` never refetches a `static` query, and finishing a lesson or saving a change in the editor has to refresh the curriculum. `setupRouterSsrQueryIntegration` serializes the server cache into the HTML and hydrates it in the browser.

- **Translation messages** are cached per locale and namespace with an infinite `staleTime` and `gcTime`.
- **The session query** (`getCurrentSessionQuery`) has a `staleTime` of <RepositoryFact name="sessionStaleTimeMinutes" unit="minute" />. Route guards let a navigation through on the cached session while it is fresh and fetch it again once it is stale. A server function that answers `UNAUTHORIZED` or `FORBIDDEN` makes `recheckRefusedSession` in `auth.routes.ts` check the session again, and the guards run again when it changed. When the signed-in user changes, the guards remove every query that is not marked `meta: { public: true }`. Public queries, such as the translations and the star count a prerendered page was rendered with, stay cached. See [Public queries](/docs/conventions/data-fetching#public-queries).
- **Mutations** invalidate their module's query keys, for example `USER_QUERY_KEYS.ALL`, after they succeed.

## Prerendering

`bun run build` prerenders the public pages by crawling links: landing, legal, blog and docs pages in every locale. Paths under `/admin`, `/app`, `/auth`, `/courses`, `/newsletter` and `/api` (with or without a locale prefix) and links with a query string or hash are excluded. The course pages are excluded because they show each viewer's locks and progress. The browser fills the landing page's course block from `getCourseShowcase` when it scrolls near, so the prerendered landing page stays the same for everyone (see [Courses](/docs/features/courses)).

The Worker serves prerendered HTML from the `ASSETS` binding before it loads the application. A prerendered page contains no user data, so it is safe to serve to everyone. When a visitor qualifies for regional pricing, the Worker rewrites the HTML and marks the response `Cache-Control: private, no-cache`.

Prerendering runs on a Worker build that contains every page. The deployed Worker is rebuilt afterwards without the compiled docs and blog pages and without the translations that only the landing and legal pages use. It needs neither: the docs, the blog and the landing page read their content from indexes the build writes to `/assets/`, in the browser on a client navigation, and the docs search searches a static index in the browser, so client navigations and search never reach the Worker (see [Performance](/docs/conventions/performance#the-worker-holds-no-docs-or-blog-content)). See [Cloudflare Workers](/docs/integrations/cloudflare-workers).

## KV and D1

- **KV (`CACHE`)** stores the GitHub star count for `src/lib/github.ts`. A star count older than <RepositoryFact name="starCountRefreshHours" unit="hour" /> is returned immediately and refreshed in the background with `waitUntil`.
- **D1 (`DB`)** stores sessions and rate-limit counters. Session checks for server functions bypass Better Auth's cookie cache and are memoized for the rest of the request.
- **The Workers cache** keeps the video files that `serveMedia` reads from R2 under `/media/_/<videoId>/<file>`, without the signature, so the viewers at one edge location share a single cached copy. See [Cloudflare R2](/docs/integrations/cloudflare-r2). `serveCover` keeps the course covers in a Workers cache of its own, `covers`, under their public path, and sends them with `public, max-age=31536000, immutable`, since every new cover gets a new id.
- Server functions never make a permission decision from cached data.
