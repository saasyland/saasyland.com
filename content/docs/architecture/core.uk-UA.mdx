`src/modules/_core` — єдина папка модуля, яка не володіє таблицею. Вона містить значення та допоміжні функції, потрібні кільком модулям, щоб жоден модуль не визначав їх повторно.

## Константи

| Файл                    | Вміст                                                                                                          |
| ----------------------- | -------------------------------------------------------------------------------------------------------------- |
| `constants/errors.ts`   | `ERROR_CODES`, тип `ErrorCode` і клас `AppError`                                                               |
| `constants/api.ts`      | `HTTP_STATUS`, назви заголовків `cf-ipcountry` і `cf-connecting-ip`, дозволені хости для кожного режиму збірки |
| `constants/locale.ts`   | Каталог `LOCALES`, `LocaleCode`, `getLocaleName` і `getLocaleDirection`                                        |
| `constants/country.ts`  | Каталог `COUNTRIES` і `CountryCode`                                                                            |
| `constants/currency.ts` | Каталог `CURRENCIES`, `CurrencyCode` і `DEFAULT_CURRENCY_CODE`                                                 |
| `constants/timezone.ts` | Каталог `TIMEZONES` і `TimezoneCode`                                                                           |
| `constants/pricing.ts`  | Множники регіональних цін, cookie регіональних цін і форматування валют                                        |

Каталог локалей містить усі відомі локалі. Дев'ять локалей, які застосунок справді обслуговує, задає `I18N.SUPPORTED_LOCALES` у `src/integrations/use-intl/i18n.config.ts`.

## Утиліти

- `utils/pagination.ts`: `paginationSchema` (`pageIndex`, `pageSize`), `DEFAULT_PAGINATION` і `DEFAULT_PAGE_SIZE`
- `utils/zod-fields.ts`: повторно використовувані поля Zod, як-от `idField` і `localeField`

## Помилки

Є один клас помилок і один список кодів:

```ts
export const ERROR_CODES = {
  AUTH_API_ERROR: "AUTH_API_ERROR",
  CONFLICT: "CONFLICT",
  FORBIDDEN: "FORBIDDEN",
  INTERNAL_ERROR: "INTERNAL_ERROR",
  NOT_FOUND: "NOT_FOUND",
  TOO_MANY_REQUESTS: "TOO_MANY_REQUESTS",
  UNAUTHORIZED: "UNAUTHORIZED",
  VALIDATION: "VALIDATION",
} as const

export type ErrorCode = (typeof ERROR_CODES)[keyof typeof ERROR_CODES]

export class AppError extends Error {
  readonly code: ErrorCode

  constructor(code: ErrorCode, message: string = code) {
    super(message)
    this.name = "AppError"
    this.code = code
  }
}
```

Серверні функції викидають `AppError`. Middleware `withRequest` нормалізує все інше: помилки API Better Auth стають `AUTH_API_ERROR` із ключем помилки Better Auth як повідомленням, помилки Zod стають `VALIDATION`, а невідомі помилки логуються й стають `INTERNAL_ERROR`. У браузері `useErrorMessage()` із `src/hooks/use-error-message.ts` зіставляє повідомлення з перекладами `auth.errors.*` або `errors.codes.*`.
