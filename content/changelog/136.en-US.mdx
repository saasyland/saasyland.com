- Polar: `bun run polar:verify:<environment>` compares the environment's Polar organisation with the code, with GET requests only, and `deploy:preview` and `deploy:production` run it after `verify-bindings.ts`. It fails when a tier product is missing, archived or a subscription, when a price is not the fixed `TIER_PRICES` amount in `DEFAULT_CURRENCY_CODE`, when a product lacks exactly one licence-key benefit with the tier's activation limit, no expiry and no usage limit, when a `PPP_TIERS` band has no automatic discount that checkout would apply to every tier, and when the webhook for the environment's host is missing, disabled, signed with another secret or subscribed to other events than the handlers handle, or an endpoint posts to another environment's host. CI deployments do not run it, because they hold no Polar token.
- The activation limit of each tier is code now, `LICENSE_ACTIVATION_LIMITS` in `license.constants.ts`, next to `LICENSE_WEBHOOK_EVENTS`, the events `licenseWebhookHandlers` must handle. Checkout and `polar:verify` share one regional discount rule, `findRegionalDiscount` in `polar.discounts.ts`.
- [Polar setup](/docs/getting-started/polar-setup) documents production and sandbox, the token scopes, the products, licence keys, regional discounts and webhook, how to run `polar:verify` and what each failure means. The MDX components `ActivationLimit` and `RegionalDiscounts` print the limits and discounts from the code.
