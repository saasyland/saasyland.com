## Dane

`src/modules/category/category.schema.ts` definiuje tabelę `category`: `name`, `description`, `kind` (`category` lub `collection`), `visibility` (`public` lub `hidden`), `icon` (`Archive`, `FolderOpen` lub `Puzzle`) i znaczniki czasu.

Przypadki użycia w `src/modules/category/use-cases`, każdy chroniony odpowiednim uprawnieniem `category`: `getCategories` (stronicowany, opcjonalny `kind`), `getCategory`, `createCategory`, `updateCategory` i `deleteCategory`. `createCategory` to wzorcowa struktura przypadku użycia z mutacją:

```ts
export const createCategory = createServerFn({ method: "POST" })
  .middleware([authorized({ category: ["create"] })])
  .validator((input: Category["createCategory"]) => categoryZodSchemas.createCategory.parse(input))
  .handler(({ data }) =>
    db
      .insert(category)
      .values({
        description: data.description ?? "",
        icon: data.icon ?? CATEGORY_ICON.FOLDER_OPEN,
        id: v7(),
        kind: data.kind,
        name: data.name,
        visibility: data.visibility ?? CATEGORY_VISIBILITY.PUBLIC,
      })
      .returning()
      .get(),
  )

export const createCategoryMutation = mutationOptions({
  mutationFn: (data: Category["createCategory"]) => createCategory({ data }),
  mutationKey: CATEGORY_MUTATION_KEYS.CREATE,
})
```

Komunikaty walidacji i błędów znajdują się w przestrzeniach nazw `category.validations` i `category.errors`.

## Ekran administracyjny

Karty **Kategorie** i **Kolekcje** w `/admin/products` wyświetlają `categoryColumns` z `getCategoriesPageQuery({ kind, pageIndex, pageSize })`. Podłączona jest tylko lista: żaden ekran nie tworzy, nie edytuje ani nie usuwa kategorii. Produkty nie mają jeszcze powiązania z kategoriami, dlatego kolumna liczby elementów pokazuje wartość zastępczą.
