Die App stellt diese HTTP-Routen bereit, deklariert mit `server.handlers` auf `createFileRoute` in `src/routes/api`:

| Route                                        | Methoden          | Handler                                                                                                                                                                                                                                         |
| -------------------------------------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/api`                                       | GET               | Gibt `{ "runtime": "cloudflare-workers" }` zurück.                                                                                                                                                                                              |
| `/api/auth/$`                                | GET, POST         | Better Auth: Anmeldung, OAuth-Callbacks, `/api/auth/verify-email` sowie die Endpunkte des Polar-Plugins `/api/auth/polar/webhooks` und `/api/auth/customer/portal`.                                                                             |
| <RepositoryFact name="cliApiBasePath" />`/*` | GET, POST, DELETE | Die [CLI-Lizenz-API](/docs/features/cli-licence-api): `licenseApiHandlers` (`license.api.ts`) lesen die Lizenz, aktivieren, prüfen und geben Geräte frei und signieren den Download des Template-Bundles einer Version für die CLI `saasyland`. |

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Serverfunktionen statt REST

Anwendungsoperationen sind `createServerFn`-Funktionen in `src/modules/<table>/use-cases`. Die übrigen liegen in `src/lib` (`getStarCount` in `github.ts`), in einer Integration (`getCurrentSession` in `auth.session.ts`) oder inline in der einzigen Route, die sie verwendet. TanStack Start ruft sie per RPC unter `/_serverFn` auf, mit Middleware für Sitzungen, Berechtigungen und Rate-Limits. Füge keinen REST-Endpunkt für eine Operation hinzu, die nur diese App aufruft; lege HTTP-Routen nur für externe Aufrufer wie Webhooks und die CLI an und prüfe Webhook-Signaturen in der Anbieter-Integration.

## Verhalten

- Der Worker überspringt Locale-Weiterleitungen für `/api` und `/_serverFn`. Ihre URLs enthalten keine Locale, daher gibt `getCurrentLocale()` für sie auf dem Server `en-US` zurück; Code, der eine Locale braucht, erhält sie als Eingabe oder liest sie aus einer `callbackURL`.
- Der Build rendert `/api` nicht vorab.
- `/media/*` ist keine TanStack-Start-Route: Der Worker leitet sie vor der Locale-Verarbeitung an `serveMedia` weiter. Siehe [Cloudflare R2](/docs/integrations/cloudflare-r2). Ebenso wenig ist es `/bundles/*`, das der Worker an `serveBundle` weiterleitet; siehe [CLI-Lizenz-API](/docs/features/cli-licence-api#template-bundles).
- Die Handler-Tests liegen in `src/routes/api/__test__/`, eine Datei pro Handler: `auth.test.ts` und `index.test.ts`. `cli.v1.test.ts` deckt die Routendateien der CLI-Lizenz-API ab; ihr Verhalten wird in `src/modules/license/__test__/license.api.integration.test.ts` und, für Bundles, in `license.bundles.integration.test.ts` getestet.
