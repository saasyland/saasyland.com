title: "Adicionar uma rota de API"
description: "Adicione um handler HTTP em /api para webhooks e outros chamadores externos."
---

Rotas de API são handlers de servidor do TanStack Start em `src/routes/api/`. As telas da aplicação nunca precisam delas: elas chamam funções de servidor. Adicione uma rota de API apenas para chamadores fora da aplicação, como webhooks, clientes de terceiros ou crawlers.

## Rotas existentes

| Arquivo                      | Caminho                                      | Finalidade                                                                                     |
| ---------------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `src/routes/api/auth.$.ts`   | `/api/auth/*`                                | Better Auth: login, callbacks de OAuth, verificação de e-mail, o portal e os webhooks da Polar |
| `src/routes/api/index.ts`    | `/api`                                       | Verificação do runtime que retorna `{ "runtime": "cloudflare-workers" }`                       |
| `src/routes/api/cli.v1.*.ts` | <RepositoryFact name="cliApiBasePath" />`/*` | A [API de licenças da CLI](/docs/features/cli-licence-api) que a CLI `saasyland` chama         |

O plugin da Polar não adiciona endpoint de checkout; os checkouts começam nas funções de servidor `startCheckout` dos módulos de pedidos e de licenças, e ambas os criam com `createCheckout`. Os webhooks da Polar chegam em `/api/auth/polar/webhooks`; o plugin da Polar para o Better Auth verifica a assinatura deles com `POLAR_WEBHOOK_SECRET` antes que `handlePolarEvent` (`src/integrations/polar/polar.webhooks.ts`) entregue cada evento aos handlers de pedidos, assinaturas e licenças listados em `POLAR_EVENT_HANDLERS`.

## Escreva um handler

Declare os métodos em `server.handlers`. Cada handler recebe a `Request` web e retorna uma `Response` web:

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: {
    handlers: {
      GET: ({ request }) => auth.handler(request),
      POST: ({ request }) => auth.handler(request),
    },
  },
})
```

Dentro de um handler:

- Valide a query ou o corpo com um schema Zod e retorne `HTTP_STATUS.BAD_REQUEST` (de `src/modules/_core/constants/api.ts`) quando a validação falhar. Se o handler precisar de um status novo, adicione-o ali.
- Leia a sessão com `getRequestSession(request)` e verifique-a com `hasPermission`. Middlewares de função, como `authorized`, valem para funções de servidor, não para handlers.
- Limite as requisições dos endpoints públicos com `withinRateLimit({ key, limit, windowSeconds })` de `src/lib/rate-limit.ts` e `clientAddress(request.headers)` de `src/integrations/better-auth/auth.middleware.ts`.
- Verifique assinaturas antes de confiar no conteúdo de um webhook.
- Retorne corpos de erro seguros e registre os detalhes com `console.error`.

## Regras de roteamento

- Caminhos `/api` nunca recebem prefixo de idioma, e o Worker pula para eles a busca de arquivos estáticos e os redirecionamentos de idioma.
- URLs de `/api` não trazem idioma, então `getCurrentLocale()` retorna ali o idioma padrão. Uma resposta localizada pega o idioma da requisição, por exemplo de um parâmetro de query `locale`.
- `/api` fica fora da pré-renderização.

## Teste

Chame o handler pelas opções da rota, como `src/routes/api/__test__/auth.test.ts` faz com `Route.options.server.handlers`, e simule o provedor para o qual ele encaminha a requisição.
