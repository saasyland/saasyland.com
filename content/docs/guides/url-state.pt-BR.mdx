---
title: "Estado na URL"
description: "Guarde abas, visualizações e tokens de uso único em parâmetros de busca validados."
---

Os parâmetros de busca guardam o estado que precisa sobreviver a um recarregamento ou a um link compartilhado: a aba ou visualização selecionada, um endereço de e-mail passado entre páginas de autenticação, um token de verificação. Todo o resto fica no estado do React. O `DataTable` mantém paginação, ordenação, seleção e filtros no estado do componente.

## Declare os parâmetros

`validateSearch` recebe um objeto do zod, então os parâmetros de busca da rota são tipados e validados em um só lugar. Os campos vêm de `src/lib/search-params.ts`: `searchText()` e `searchFlag()` são `undefined` quando o valor está ausente, vazio ou malformado, então valores ausentes nunca aparecem na URL; `searchChoice(choices, fallback)` volta a uma das opções. `searchParam(schema)` aplica a mesma regra a qualquer schema do zod; as rotas da newsletter leem `token` com o schema de token do próprio módulo. Um valor malformado nunca leva a uma página de erro. De `src/routes/admin.blog.index.tsx`:

```tsx
validateSearch: zod.object({
  view: searchChoice([ADMIN_BLOG_VIEW.GRID, ADMIN_BLOG_VIEW.TABLE], ADMIN_BLOG_VIEW.GRID),
}),
search: { middlewares: [stripSearchParams({ view: ADMIN_BLOG_VIEW.GRID })] },
```

`stripSearchParams` remove o valor padrão da URL, então `/admin/blog` continua sendo o endereço canônico da visualização em grade.

## Leia os parâmetros

- No componente da rota: `const { view } = Route.useSearch()`.
- Com um seletor, o componente só renderiza de novo quando o valor selecionado muda: `Route.useSearch({ select: (search) => search.error !== undefined })`.
- Em um componente fora do arquivo da rota: `getRouteApi("/auth/verify-email").useSearch()`, como em `verify-email-form.tsx`. Uma rota também pode passar como prop um valor que ela validou, como `auth.reset-password.tsx` passa `token` para `ResetPasswordForm`.

## Altere os parâmetros

- Links: `<Link search={{ view: id }} to={ROUTES.ADMIN_BLOG}>`.
- Componentes React Aria com `href`, como `TabsTrigger` em `src/routes/admin.products.index.tsx`, navegam pelo router porque o `AriaProvider` conecta o React Aria ao TanStack Router.
- Código: `router.navigate({ search: { email }, to: ROUTES.VERIFY_EMAIL })`.
- Guards e loaders: `throw redirect({ replace: true, to: ROUTES.AUTH_CALLBACK })`.

## Carregue dados a partir deles

Um componente lê parâmetros de busca com `Route.useSearch()`; um loader que depende de um deles o declara em `loaderDeps` e o lê de `deps`. Nunca gaste um token da URL em um loader, porque o pré-carregamento, os rastreadores e os scanners de e-mail executam loaders. As páginas de confirmação e de cancelamento da newsletter leem o token e só agem quando o visitante pressiona o botão:

```tsx
const { status, token } = Route.useSearch()
```

## Idiomas e URLs

- Links do router (`<Link to={ROUTES.X}>`) recebem o prefixo de idioma do `rewrite` do router. O inglês não tem prefixo (`/docs`); os outros idiomas têm (`/pl-PL/docs`).
- Monte URLs brutas com `localizePathname({ locale, pathname })`: `callbackURL` e `errorCallbackURL` do Better Auth, links em e-mails e `<a href>` montados à mão. Caminhos `/api` e URLs externas não mudam.
- O seletor de idioma leva ao mesmo caminho no outro idioma com um carregamento completo da página; a query e o fragmento não são mantidos.
