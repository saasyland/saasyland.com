`src/integrations/resend/resend.config.ts` は `resendClient` をエクスポートし、メールを送るたびに `RESEND_API_KEY` から Resend クライアントを作成します。Resend SDK はキーがないと例外をスローしますが、こうすることで、ビルドやプリレンダリングされたページ、メールを送らないリクエストはキーなしで動きます。`resend.utils.ts` は、メールを送信する唯一の関数である `sendEmail` をエクスポートします。`from` のデフォルトは `RESEND_EMAIL_FROM` です。必須の `idempotency` オプションでメールの目的ときっかけとなったトークンを渡すと、`sendEmail` がそれをキー `${purpose}/${sha256Hex(token)}` に変換します。このキーにより、再試行されたリクエストを Resend が二重に送信することはなく、Resend の 256 文字の上限にも収まります。Resend のエラーは例外としてスローされます。どちらのファイルもサーバー専用です。メールを送る各エリアは `src/data/<area>.email-purposes.ts` で目的に名前を付け、`resend.constants.ts` が `src/data/email-purposes.entries.ts` からそれらを `EMAIL_PURPOSE` にまとめます。重複がないことは `resend.constants.test.ts` が確認します。ユースケースは同じ名前を受信者ごとの上限の `kind` にも渡します。

## テンプレートとユースケース

`src/presentation/emails/` にあるテンプレートは、マークアップだけを持つ React Email コンポーネントです。各テンプレートは `*_NAMESPACE` 定数をエクスポートし、`locale` と `messages` をプロパティとして受け取り、use-intl の `createTranslator` で翻訳します。メールを送信するユースケースは呼び出し元からロケールを受け取り（確認メールはコールバック URL からロケールを読み取ります）、メッセージを読み込み、テンプレートを描画して `sendEmail` を呼び出します。

```ts
const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotency: { purpose: EMAIL_PURPOSE.VERIFY_EMAIL, token },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```

| テンプレート                          | 名前空間                                 | 送信元                                                                       |
| ------------------------------------- | ---------------------------------------- | ---------------------------------------------------------------------------- |
| `verify-email.tsx`                    | `emails.verify-email`                    | `modules/verification/use-cases/send-verify-email.ts`                        |
| `reset-password-email.tsx`            | `emails.reset-password-email`            | `modules/verification/use-cases/send-reset-password-email.ts`                |
| `change-email-confirmation-email.tsx` | `emails.change-email-confirmation-email` | `modules/account/use-cases/send-change-email-confirmation-email.ts`          |
| `newsletter-confirmation-email.tsx`   | `emails.newsletter-confirmation-email`   | `modules/newsletter-subscriber/use-cases/subscribe-to-newsletter.ts`         |
| `newsletter-notification-email.tsx`   | `emails.newsletter-notification-email`   | `modules/newsletter-subscriber/use-cases/confirm-newsletter-subscription.ts` |
| `purchase-confirmation-email.tsx`     | `emails.purchase-confirmation-email`     | `modules/license/use-cases/send-purchase-confirmation-email.ts`              |

最初の 3 つのユースケースは、Better Auth が `auth.server.ts` のフックから呼び出します。Resend はこれらを `src/data/resend.auth-emails.ts` の `RESEND_AUTH_EMAILS` を通じてフックに組み込みます。ニュースレターの通知は、購読が確認された後にサイトのオーナーへ英語で送信されます。購入確認メールは、ライセンスのエリアの `order.paid` ハンドラーが、注文に保存された言語で送信します。メール内のリンクは `localizePathname` で組み立てられるため、メールのロケールで開きます。

確認メール、パスワードリセット、ニュースレターの確認の各ユースケースは、最初に `src/lib/rate-limit.ts` の `withinRecipientRateLimit` を呼び出します。アドレスの SHA-256 ハッシュをキーとして、各種類のメールはアドレスごとに 1 時間あたり最大 <RepositoryFact name="recipientEmailsPerHour" /> 通までです。上限を超えると、エラーを出さずにメールをスキップします。

## テスト

Vitest はプロバイダーの呼び出しをモックします。Playwright のテスト用 Worker では、Resend API へのリクエストは送信されずにキャプチャされ、`/__test/emails?to=<address>` でキャプチャされたメールを取得できます。
