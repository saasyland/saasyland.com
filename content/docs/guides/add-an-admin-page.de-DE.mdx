---
title: "Admin-Seite hinzufügen"
description: "Route, Sidebar-Eintrag, Messages und Widgets einer neuen Admin-Seite registrieren."
---

Admin-Seiten sind flache Route-Dateien unter dem `/admin`-Layout (`src/routes/admin.tsx`), das in `beforeLoad` `requireAdmin` ausführt und Sidebar, Breadcrumbs und Befehlspalette rendert. Die folgenden Schritte fügen eine Seite unter `/admin/reports` hinzu; `src/routes/admin.payments.tsx` ist ein vollständiges reales Beispiel.

## 1. Pfad hinzufügen

Die Konstante zu `ROUTES` in `src/routes.ts` hinzufügen:

```ts
ADMIN_REPORTS: "/admin/reports",
```

## 2. Route-Datei anlegen

`src/routes/admin.reports.tsx` anlegen. Die Route definiert nur die Seitenkomponente, `NAMESPACE`, den Loader, `head` und `pendingComponent`; der Router-Generator registriert die Datei in `src/routeTree.gen.ts`.

```tsx
import type { JSX } from "react"

import { createFileRoute } from "@tanstack/react-router"
import { useTranslations } from "use-intl/react"

import { loadPageMetadata, preloadNamespaces } from "~/src/integrations/use-intl/i18n.messages"
import { getCurrentLocale } from "~/src/integrations/use-intl/i18n.utils"

import { pageHead } from "~/src/lib/seo"

import { AdminReportsPending } from "~/src/presentation/components/custom/admin/overview-pending"
import { ReportStats } from "~/src/presentation/components/custom/admin/reports/report-stats"

import { ROUTES } from "~/src/routes"

const ReportsPage = (): JSX.Element => {
  const t = useTranslations("pages.admin.reports")

  return (
    <div className="flex w-full flex-col space-y-8">
      <div>
        <h1 className="text-statement font-semibold text-foreground">{t("metadata.title")}</h1>
        <p className="text-sm text-muted-foreground">{t("metadata.description")}</p>
      </div>

      <ReportStats />
    </div>
  )
}

const NAMESPACE = "pages.admin.reports"

export const Route = createFileRoute("/admin/reports")({
  component: ReportsPage,
  head: pageHead(ROUTES.ADMIN_REPORTS),
  loader: async ({ context }) => {
    const locale = getCurrentLocale()
    const [metadata] = await Promise.all([
      loadPageMetadata({ locale, namespace: NAMESPACE }),
      preloadNamespaces({ locale, namespaces: [NAMESPACE], queryClient: context.queryClient }),
    ])
    return { locale, metadata }
  },
  pendingComponent: AdminReportsPending,
  staticData: { namespaces: [NAMESPACE] },
})
```

Queries, die die Seite benötigt, kommen in dasselbe `Promise.all`, zum Beispiel `context.queryClient.query({ ...getUsersQuery, staleTime: "static" })` in `src/routes/admin.users.all.tsx`. `pageHead` erzeugt Titel, Beschreibung, kanonische URL und Links zu den anderen Locales aus den `metadata` des Loaders. `AdminReportsPending` ist das eigene Skeleton der Seite und erscheint nur, wenn eine Navigation länger als eine Sekunde dauert. Das Skeleton in der Datei der Sidebar-Gruppe der Seite (`overview-pending.tsx`, `offerings-pending.tsx`, `content-pending.tsx` oder `administration-pending.tsx` in `custom/admin/`) aus den Bausteinen in `pending-blocks.tsx` aufbauen, sodass es das Layout der Seite nachbildet. Anschließend in `admin-pending.tsx` zu `ADMIN_PAGES` hinzufügen, damit das Skeleton des Admin-Layouts es anzeigt, wenn jemand `/admin/reports` von außerhalb des Admin-Bereichs aufruft. Siehe [Lade-Skeletons](/docs/architecture/delivery-layer#lade-skeletons).

## 3. Sidebar-Eintrag hinzufügen

Einer Gruppe in `ADMIN_SIDEBAR_GROUPS` (`src/data/admin.ts`) einen Eintrag mit einem `lucide-react`-Icon hinzufügen:

```ts
{ icon: FileText, titleKey: "reports", url: ROUTES.ADMIN_REPORTS },
```

`links.reports` in allen neun Locales zu `messages/<locale>/pages.admin.sidebar.json` hinzufügen. Eine neue Gruppe benötigt zusätzlich `groups.<titleKey>`. Sidebar, Breadcrumbs und die ⌘K-Befehlspalette lesen alle `ADMIN_SIDEBAR_GROUPS`, sodass die Seite an allen drei Stellen erscheint. Ein drittes URL-Segment wie `/admin/reports/create` zeigt die Breadcrumb-Beschriftung `components.breadcrumbs.actions.create` aus `pages.admin.json`.

## 4. Seiten-Messages hinzufügen

`messages/<locale>/pages.admin.reports.json` in allen neun Locales anlegen. `metadata` ist erforderlich, weil der Loader es für den Dokument-Head liest:

```json
{
  "metadata": {
    "title": "Reports",
    "description": "Revenue and usage reports."
  }
}
```

## 5. Widgets hinzufügen

Jedes Widget, jeden Dialog, jedes Formular und jeden Satz Tabellenspalten in eine eigene Datei unter `src/presentation/components/custom/admin/reports/` legen, zum Beispiel `report-stats.tsx` oder `report-columns.tsx`. Widgets rufen `useTranslations("pages.admin.reports")` auf und lesen ihre eigenen Daten mit `useSuspenseQuery`; die Seite übergibt ihnen weder Beschriftungen noch Daten. Tabellen verwenden die generische `DataTable`; siehe [Datentabelle hinzufügen](/docs/guides/add-a-data-table).

## 6. Schützen und testen

- Der Layout-Guard regelt den Seitenzugriff. Jede Server-Funktion, die die Seite aufruft, benötigt trotzdem `authorized(permission)`; siehe [Rollen und Berechtigungen](/docs/guides/roles-and-permissions).
- `/admin` ist vom Prerendering ausgeschlossen.
- Route-Tests neben den bestehenden in `src/routes/__test__/` und Widget-Tests in `src/presentation/components/custom/admin/__test__/` hinzufügen, danach `bun run check:i18n` und `bun run test:coverage` ausführen.
