## Кеш запитів

`getRouter` створює новий `QueryClient` для кожного HTTP-запиту, тож на сервері дані не просочуються між користувачами. Типові значення:

| Параметр                   | Значення               |
| -------------------------- | ---------------------- |
| `staleTime` запитів        | 1 хвилина              |
| `gcTime` запитів           | 5 хвилин               |
| `defaultStaleTime` роутера | 1 хвилина              |
| Попереднє завантаження     | За наміром користувача |

Loader-функції заповнюють кеш через `queryClient.query({ ...options, staleTime: "static" })`, а компоненти читають ті самі ключі через `useSuspenseQuery`. `setupRouterSsrQueryIntegration` серіалізує серверний кеш у HTML і гідратує його в браузері.

- **Повідомлення перекладів** кешуються для кожної локалі та простору імен із нескінченними `staleTime` і `gcTime`.
- **Запит сесії** (`getCurrentSessionQuery`) має `staleTime` в одну хвилину. Guard-функції маршрутів повторно отримують його під час справжніх переходів і очищають увесь кеш, коли змінюється користувач, що увійшов.
- **Мутації** після успішного виконання інвалідують ключі запитів свого модуля, наприклад `USER_QUERY_KEYS.ALL`.

## Пререндеринг

`bun run build` попередньо рендерить публічні сторінки, обходячи посилання: лендинг, юридичні сторінки, блог і документацію в усіх дев'яти локалях. Шляхи в `/admin`, `/app`, `/auth`, `/newsletter` і `/api` (з префіксом локалі або без нього), а також посилання з рядком запиту чи хешем виключено.

Worker віддає попередньо відрендерений HTML із прив'язки `ASSETS` ще до завантаження застосунку. Попередньо відрендерена сторінка не містить даних користувача, тож її безпечно віддавати всім. Коли відвідувач має право на регіональні ціни, Worker переписує HTML і позначає відповідь `Cache-Control: private, no-cache`.

## KV і D1

- **KV (`CACHE`)** зберігає лише кількість зірок на GitHub для `src/lib/github.ts`. Кешоване значення, старше за одну годину, повертається одразу й оновлюється у фоні через `waitUntil`.
- **D1 (`DB`)** зберігає сесії та лічильники обмеження частоти запитів. Перевірки сесії для серверних функцій оминають кеш cookie у Better Auth і мемоізуються до кінця запиту.
- Серверні функції ніколи не ухвалюють рішень щодо дозволів на основі кешованих даних.
