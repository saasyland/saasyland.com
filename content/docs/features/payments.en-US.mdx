Payments run through Polar with the `@polar-sh/better-auth` plugin in `auth.server.ts`:

```ts
polarPlugin({
  client: polarCore,
  use: [
    checkout({
      authenticatedUsersOnly: true,
      products: POLAR_CHECKOUT_PRODUCTS,
      successUrl: ROUTES.APP,
    }),
    portal(),
    webhooks({ ...licenseWebhookHandlers, secret: env.POLAR_WEBHOOK_SECRET }),
  ],
}),
```

`src/integrations/polar/polar.config.ts` creates `polarCore` from `POLAR_ACCESS_TOKEN` and `POLAR_SERVER`, which the plugin uses, and `polar`, the discounts, licence keys and orders services built on it. `POLAR_ORGANIZATION_ID` scopes the discount lookup and licence key deactivation. `POLAR_CHECKOUT_PRODUCTS` maps the tier slugs `core`, `complete` and `agency` to `POLAR_PRODUCT_ID_CORE`, `POLAR_PRODUCT_ID_COMPLETE` and `POLAR_PRODUCT_ID_AGENCY`.

## Checkout

A signed-in user without a licence sees `CheckoutOptions` on `/app` and `/app/license`. It calls `startCheckout` (`src/modules/license/use-cases/start-checkout.ts`), which:

1. looks up a regional discount with `pppDiscountId` (`license.ppp.ts`): the percentage for the `cf-ipcountry` country, matched against active automatic percentage discounts in Polar, skipped when the `regional_pricing` cookie is `off`;
2. creates a Polar checkout for the tier with discount codes disabled, carrying the affiliate referral in `metadata` when the visitor came through an affiliate link (see [Affiliate programme](/docs/features/affiliates));
3. returns the checkout URL, which the browser opens.

A paid checkout returns to `/app`.

## Webhooks and licences

Polar posts to `/api/auth/polar/webhooks`, verified with `POLAR_WEBHOOK_SECRET`. `licenseWebhookHandlers` (`src/modules/license/license.webhooks.ts`) match the user through the Polar customer `external_id`. An event for a customer with no account here is logged when it needed one and acknowledged, so Polar does not retry it:

- `onOrderPaid` → `grantLicense`: upserts the user's single licence with the tier of the purchased product; a newer purchase replaces an older one.
- `onBenefitGrantCreated` → `attachLicenseKey`: stores the Polar licence key on the licence. While the paid order is not recorded yet it fails, so Polar retries it; a key for a refunded order or for a product that is not a licence is acknowledged.
- `onOrderRefunded` (only once the order is fully refunded; a partial refund keeps the licence) and `onBenefitGrantRevoked` → `revokeLicense`: sets the status to `revoked` and records the order in `revoked_license_order`, so a late webhook cannot grant it again.

## Customer screens

`/app/license` shows `LicenseCard` (tier, key, install command and a link to the Polar customer portal at `/api/auth/customer/portal`) and `LicenseActivations`, which lists key activations from Polar and removes one with `deactivateLicense`. See [Customer app](/docs/features/customer-app).

## Admin screen (demo)

`/admin/payments` renders `RefundStats` and a refunds `DataTable` over `ADMIN_PAYMENT_ROWS` from `src/data/admin.ts`; its buttons are not wired. The `order` permission statements (`read`, `update`, `refund`) exist in `auth.access.ts`, but no use case reads orders or refunds.
