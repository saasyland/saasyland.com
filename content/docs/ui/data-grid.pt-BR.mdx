`DataGrid` (`src/presentation/components/custom/data-grid.tsx`) é o componente de tabela. Ele monta uma instância do TanStack Table v9 a partir dos recursos de `src/integrations/tanstack-table/table.features.ts` e a renderiza com as primitivas de tabela do shadcn e controles do React Aria. Uma página entrega a ele as suas colunas e, ou as suas linhas, ou uma query; todo o resto, da barra de ferramentas à barra de paginação, fica dentro dele.

```tsx
<DataGrid
  columns={columns}
  empty={t("empty")}
  id={ORDER_GRID_ID}
  label={t("title")}
  query={(request) => getOrdersPageQuery(orderZodSchemas.getOrders.parse(request))}
  search={t("filters.search")}
  selectable
/>
```

## Props

| Prop               | Finalidade                                                                                                                       |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| `columns`          | O conjunto de colunas do `<entity>-columns.tsx` da página. Toda linha precisa de um `id` do tipo string, usado como ID da linha  |
| `id`               | Dá nome à grade: a chave do seu layout salvo no navegador e o começo do nome do seu arquivo CSV                                  |
| `label`            | O nome acessível da tabela, geralmente o título da página                                                                        |
| `data`             | Linhas em memória, para uma grade que busca, filtra, ordena e pagina no cliente                                                  |
| `query`            | Modo servidor: uma função da requisição da grade que retorna query options resolvidas em `{ rows, total }`                       |
| `search`           | O rótulo e o placeholder da caixa de busca; sem ele, a grade não tem busca                                                       |
| `empty`            | O que a grade diz enquanto não tem linhas e nenhuma busca ou filtro está definido                                                |
| `emptyDescription` | Uma frase abaixo desse título que diz como a primeira linha chega                                                                |
| `selectable`       | Adiciona uma coluna de caixas de seleção e a barra de seleção                                                                    |
| `bulkActions`      | Uma função das linhas selecionadas que renderiza mais botões na barra de seleção                                                 |
| `rowActions`       | Um componente que recebe cada `row` e a encerra com o seu menu ⋯, em uma coluna fixada à direita                                 |
| `onReorder`        | Adiciona uma alça a cada linha; é chamada com a linha movida e quantos lugares ela andou, como em [Ordem das linhas](#row-order) |

## Colunas

Um conjunto de colunas é um hook em `custom/<feature>/<entity>-columns.tsx`, como `useOrderColumns`. Uma coluna que outra funcionalidade adiciona é um elemento das colunas do hook que nomeia a célula dessa funcionalidade, como a coluna **Máquinas** da licença em `useCustomerColumns`, e a lista de colunas do esqueleto nomeia do mesmo jeito a célula de esqueleto dessa funcionalidade, então deixar a funcionalidade de fora remove as duas. O hook lê as suas traduções e os dados que os seus filtros oferecem e retorna as colunas memoizadas, de modo que cada rótulo é uma string simples que a grade pode usar nos seus menus, nos seus anúncios e no cabeçalho do CSV. Cada célula é um componente pequeno no mesmo arquivo, que lê as suas próprias traduções.

```tsx
columnHelper.accessor("status", {
  cell: StatusCell,
  header: t("pages.admin.orders.table.headers.status"),
  meta: {
    export: ({ status }) => t(`pages.admin.orders.status.${status}`),
    filter: {
      kind: DATA_GRID_FILTER.MULTI_SELECT,
      options: ORDER_STATUSES.map((value) => ({ label: t(`pages.admin.orders.status.${value}`), value })),
    },
  },
  size: ORDER_COLUMN_SIZES.status,
})
```

`meta` é o que a grade lê de uma coluna:

| Chave    | Efeito                                                                                                                                              |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `filter` | O filtro da coluna: o seu `kind` e, para uma escolha, as `options` como `{ label, value }`                                                          |
| `hidden` | Oculta até o administrador mostrá-la pelo menu Colunas                                                                                              |
| `pinned` | Fixada no `start` ou no `end` até o administrador desafixá-la                                                                                       |
| `export` | O texto que o CSV recebe para uma linha. Sem ele, o CSV pega strings e números como estão, datas como instantes ISO, e deixa todo o resto em branco |
| `align`  | `end` alinha o cabeçalho e as células à direita com algarismos tabulares, para valores e contagens                                                  |

`size` é a largura inicial da coluna em pixels. Uma coluna é ordenável a menos que defina `enableSorting: false`; no modo servidor, só as colunas pelas quais o schema Zod do módulo consegue ordenar devem ser ordenáveis.

## Filtros [#filters]

Os tipos de filtro são <RepositoryFact name="dataGridFilterKinds" />. Cada um tem o seu próprio editor, aberto pelo botão Filtrar da barra de ferramentas ou pelo chip do filtro:

| Tipo          | Editor                                                                                                      | Valor                          |
| ------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------ |
| `text`        | Um campo de texto, aplicado quando a digitação pausa por <RepositoryFact name="dataGridTypingDelayMs" /> ms | O texto sem espaços nas pontas |
| `select`      | Uma lista de opções; escolher de novo a opção escolhida a remove                                            | Um `value`                     |
| `multiSelect` | Uma lista de opções, várias de uma vez; uma lista longa ganha um campo de busca                             | Um array de `value`            |
| `numberRange` | Dois campos numéricos, no mínimo e no máximo, qualquer um deles vazio                                       | `{ min?, max? }`               |
| `dateRange`   | Quaisquer dias em um calendário ou um atalho: <RepositoryFact name="dataGridDatePresets" />                 | `{ from?, to? }` em ms         |

Os dias são convertidos em instantes no fuso horário do administrador, do início do primeiro dia ao último milissegundo do último, de modo que o servidor compara instantes simples. Cada filtro ativo aparece como um chip na barra de ferramentas, ao lado do botão Filtrar, assim que é definido, de modo que os chips e os resultados mudam enquanto o filtro continua aberto. Um chip traz um resumo curto, como no mínimo 40, Pago ou Reembolsado, ou 3 selecionadas; o seu × o remove e Remover filtros remove todos. Mudar a busca, um filtro ou a ordenação volta para a primeira página e limpa a seleção.

## Modo servidor

Com `query`, a grade pagina, ordena, busca e filtra no servidor. Ela chama `query` com:

```ts
interface DataGridRequest {
  readonly filters: Readonly<Record<string, unknown>>
  readonly pageIndex: number
  readonly pageSize: number
  readonly search: string
  readonly sorting: SortingState
}
```

`filters` guarda o id de cada coluna filtrada com o seu valor. A rota valida a requisição com o schema Zod do módulo antes que ela chegue à função de servidor, como `/admin/orders` faz com `orderZodSchemas.getOrders.parse(request)`. Até a primeira página chegar, a grade mostra linhas de esqueleto; enquanto uma página seguinte carrega, ela mantém as linhas anteriores esmaecidas, marca a tabela como ocupada e desativa a paginação. Erros da query chegam ao error boundary da rota.

## Layout

O administrador reorganiza a grade, e o navegador guarda isso sob o `id` da grade em `localStorage` (`src/hooks/use-data-grid-preferences.ts`): quais colunas aparecem, a ordem delas, quais estão fixadas, as larguras, a densidade das linhas e o tamanho da página. Busca, filtros, ordenação e seleção não são guardados. Restaurar layout traz de volta os padrões. Quando o navegador recusa o armazenamento, o layout dura só a visita.

- **Menu Colunas.** Mostra e oculta cada coluna que pode ser ocultada.
- **Menu da coluna.** O botão ⋮ de cada cabeçalho ordena de forma crescente ou decrescente, limpa a ordenação, fixa a coluna à esquerda ou à direita, desafixa, move a coluna uma posição para a esquerda ou para a direita dentro do seu lado e a oculta.
- **Arrastar.** Um cabeçalho arrastado sobre outro cabeçalho do mesmo lado toma o lugar dele.
- **Redimensionar.** A borda de um cabeçalho pode ser arrastada para redimensionar; ela também é um separador que as setas do teclado alargam ou estreitam, e um clique duplo restaura a largura inicial.
- **Ordenação.** Pressionar um cabeçalho ordena por ele; com Shift, adiciona a coluna à ordenação, até <RepositoryFact name="dataGridMaxSortedColumns" /> colunas, numeradas no cabeçalho.
- **Densidade.** Linhas espaçosas ou compactas.
- **Tamanho da página.** <RepositoryFact name="dataGridPageSizes" /> linhas por página. Uma grade começa em `defaultPageSize`, <RepositoryFact name="defaultPageSize" />, a menos que passe outro valor, como os usuários mais recentes do dashboard, até o administrador escolher um tamanho, que a grade guarda.

A grade é um único cartão: a barra de ferramentas em cima, a tabela e a paginação embaixo, divididas por linhas finas. A barra de ferramentas tem duas linhas: na primeira, a busca e os controles de exibição; na segunda, abaixo, o botão Filtrar e os chips dos filtros ativos. Todos os controles da barra de ferramentas e chips de filtro têm a mesma altura; os cabeçalhos ficam só com a inicial maiúscula, no tamanho spec sobre uma faixa atenuada, as células no tamanho body, e a última coluna de dados ocupa toda a largura que sobra enquanto a coluna de ações mantém a sua. Em cada lista da grade, a opção sob o ponteiro é destacada como aquela em que o teclado está. O campo de pesquisa ocupa a largura livre da barra de ferramentas, então o texto de exemplo nunca é cortado. Um cabeçalho fica em uma única linha e nunca quebra no meio de uma palavra: a largura inicial de cada coluna comporta o cabeçalho, com as setas de ordenação e o menu da coluna, em todos os locales, e `e2e/specs/text-layout.spec.ts` falha quando o rótulo de um cabeçalho transborda da célula em qualquer grade do admin. Em uma grade mais estreita que 64rem, Colunas, Exportar CSV e Restaurar layout mostram só o ícone, e a pesquisa mantém seu espaço.

A linha de cabeçalho continua visível enquanto as linhas rolam dentro da grade, e as colunas fixadas continuam visíveis enquanto a grade rola para os lados, que é como um celular mostra uma tabela larga. Uma sombra no lado que tem mais colunas fora de vista, e na borda das colunas fixadas assim que outras passam por baixo delas, mostra que a grade rola (`.grid-scroller` em `globals.css`).

A coluna de ações da linha tem <RepositoryFact name="dataGridActionsSize" /> pixels de largura e contém um único botão ⋯, `RowMenu` (`src/presentation/components/custom/row-menu.tsx`), que abre as ações da linha como um menu: primeiro as do dia a dia e, depois de um separador, as destrutivas, que pedem confirmação em um diálogo de alerta. Toda grade do admin e toda lista reordenável, como o conteúdo programático, termina as linhas com ele, nunca com uma fileira de ícones. A coluna não tem menu da coluna: ela não ordena, não se oculta, não se move, não se redimensiona nem aparece no CSV, e fica por último à direita.

## Ordem das linhas [#row-order]

Com `onReorder`, a grade começa com uma coluna estreita de alças, depois das caixas de seleção quando a grade as tem. A alça é um ícone discreto de arrastar:

- **Arrastar.** Uma linha arrastada pela alça se desloca entre as outras conforme o ponteiro passa sobre elas, e soltá-la salva o novo lugar. Escape, ou soltá-la fora das linhas, a devolve ao lugar de antes.
- **Teclado.** Com a alça em foco, as setas para cima e para baixo movem a linha uma posição. Passar da primeira ou da última linha da página abre a página para onde a linha vai e coloca o foco na alça dela ali.
- **Salvamento.** `onReorder` recebe a linha e quantos lugares ela andou, negativo para cima, para que o servidor a mova a partir do lugar que ela tiver na ordem salva naquele momento, também entre páginas, e uma linha que outro administrador adicionou ou excluiu em outro ponto nesse meio-tempo não mude onde ela vai parar. A nova ordem aparece na hora e se mantém enquanto as movimentações são salvas, uma após a outra, até as linhas atualizadas chegarem; quando a Promise que `onReorder` retorna é rejeitada, as linhas voltam ao lugar. `/admin/courses` passa `moveCourse` em uma mutação com `scope`, então as movimentações são salvas na ordem em que foram feitas.
- **Quando fica desativada.** Enquanto as linhas estão ordenadas, filtradas ou com uma busca, o lugar de uma linha na tela não é o lugar dela na ordem salva, então as alças ficam desativadas.

Cada movimentação é anunciada na live region, por exemplo “Linha movida para a posição 3 de 12.”

## Seleção e exportação

Com `selectable`, uma caixa de seleção seleciona uma linha e a caixa do cabeçalho seleciona a página. Então uma barra flutua na parte de baixo da janela com a contagem, Exportar seleção, as `bulkActions` da página e Limpar seleção. Toda grade do admin que lista registros é selecionável: cursos, produtos da Polar, pedidos, clientes, usuários, convites, assinantes da newsletter e os pedidos sem licença; só as tabelas de contagens do painel e as edições da newsletter não são. `/admin/courses` adiciona **Excluir** para os cursos selecionados; as outras grades exportam a seleção, porque os registros delas não têm nenhuma ação que se aplique a vários de uma vez.

Exportar CSV baixa todas as linhas que a busca e os filtros encontram, não só a página na tela: no servidor, ele pede páginas de <RepositoryFact name="dataGridExportPageSize" /> linhas até ter todas. O arquivo tem as colunas visíveis na ordem delas, começa com uma marca de ordem de bytes para que as planilhas o leiam como UTF-8 e coloca um `'` antes de qualquer célula que começaria uma fórmula. Quem o escreve é `src/lib/csv.ts`.

## Acessibilidade

- A tabela leva `label` como nome e `aria-rowcount`; cada linha, o seu `aria-rowindex`, contado ao longo das páginas.
- Cabeçalhos ordenáveis são botões e levam `aria-sort`.
- Todo controle funciona pelo teclado: os menus e as listas seguem as setas e a busca por digitação do React Aria, Escape os fecha, o redimensionamento usa as setas no separador do cabeçalho e uma linha se move com as setas para cima e para baixo na alça dela, que se chama “Arraste ou use as setas para reordenar”.
- Mover uma coluna ou uma linha, fixar, ocultar, ordenar por um menu e restaurar o layout são anunciados em uma live region educada; a contagem de resultados e a contagem da seleção também são live.

## Traduções

Os textos próprios da grade ficam em `messages/<locale>/components.custom.data-grid.json`. Uma página entrega a ela só os rótulos das colunas, as opções dos filtros, o rótulo da busca e a mensagem de vazio.
