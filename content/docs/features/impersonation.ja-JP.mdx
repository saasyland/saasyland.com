---
title: "なりすまし"
description: "Better Auth の管理者によるなりすまし: 管理者がユーザー画面から顧客としてサインインし、ワークスペースのバナーから終了します。"
---

Better Auth の `admin` プラグインがなりすまし機能を提供し、`src/modules/user/use-cases` がそれをラップしています。

```ts
export const impersonateUser = createServerFn({ method: "POST" })
  .middleware([authorized({ user: ["impersonate"] })])
  .validator((input: User["impersonateUser"]) => userZodSchemas.impersonateUser.parse(input))
  .handler(({ context, data }) => auth.api.impersonateUser({ body: data, headers: context.requestHeaders }))
```

`stopImpersonatingUser` はサインイン済みのセッションだけを必要とします。両ファイルはミューテーションのオプション（`impersonateUserMutation`、`stopImpersonatingUserMutation`）をエクスポートします。

## 開始

ユーザーのアクションメニュー（[ユーザー（管理）](/docs/features/users-admin)）にある **このユーザーとしてログイン** は、`/admin/users/all` でもユーザーのプロフィールでも `impersonateUser` を呼び出します。Better Auth は `impersonatedBy` を記録したそのユーザーのセッションを作成し、管理者のセッショントークンを署名付きの `admin_session` Cookie に保存して、セッション Cookie を新しいセッションに切り替えます。`tanstackStartCookies()` が両方の Cookie をサーバー関数のレスポンスに載せます。その後、メニューは `removeUserData` で管理者のデータをクエリキャッシュから削除し、ルーターキャッシュをクリアして `/app` を開きます。

この項目は、管理者でも利用停止中でもないユーザーにだけ表示されます。Better Auth は、呼び出し元が `user: ["impersonate-admins"]` を持たない限り、管理者ロールを持つユーザーへのなりすましを拒否します。この権限は `auth.access.ts` のどのロールにも付与されていません。また、Better Auth のセッションフックは利用停止中のユーザーにセッションを与えません。`auth.server.ts` は `impersonationSessionDuration` を設定していないため、セッションは Better Auth のデフォルトが許す限り続きます。

## バナーと終了

`ImpersonationBanner`（`src/presentation/components/custom/app/impersonation-banner.tsx`）は `/app` レイアウトのヘッダーの上に表示されます。`getCurrentSessionQuery` を読み取り、セッションに `impersonatedBy` がある場合にだけ描画されます。内容は `components.custom.impersonation-banner.json` でラベルを付けたリージョンで、なりすましているユーザーとそのメールアドレスを示し、**なりすましを終了** ボタンを備えます。ボタンは `stopImpersonatingUser` を呼び出し、なりすましセッションを削除して `admin_session` Cookie から管理者のセッションを復元します。その後、バナーはユーザーのデータをキャッシュから削除し、`/admin/users` でそのユーザーのプロフィールを開きます。

どちらのミューテーションも、まず `settleQueries`（`src/lib/settle-queries.ts`）を待ちます。これは取得中のクエリがなくなった時点で解決し、そのあとで初めてサーバーを呼び出します。まだ処理中の読み取りは、離れようとしているセッションの Cookie を送っています。それが `stopImpersonatingUser` によるなりすましセッションの削除後にサーバーへ届くと、Better Auth はセッション Cookie を失効させる応答を返し、その応答が停止の応答より後に届くと、復元された管理者の Cookie が消えて管理者はサインアウトされます。なりすまし中の顧客がメールアドレスを確認していない間に繰り返されるメール確認のチェックが、こうした読み取りにあたります。

## セッション

- `getActiveSessions` は設定のセッション一覧からなりすましセッションを除外し、Better Auth 自身の `list-sessions` エンドポイントも同様に除外します。
- ユーザーのプロフィールにあるセッションカードにはそれらも表示されるため、管理者は別の管理者が開いたままにしたなりすましセッションを失効できます。
- ルートガードはセッションのユーザーが変わると前のユーザーのデータをクエリキャッシュから削除するため、開始後や終了後のどの画面遷移でも正しいユーザーのデータが読み込まれます。

なりすましの監査ログはありません。
