Ogni libreria o servizio di terze parti che richiede una configurazione possiede una cartella in `src/integrations`. I file si chiamano `<prefix>.<concern>.ts`, dove il prefisso è il nome breve del fornitore.

| Cartella        | File                                                                                                                                                                         | Responsabilità                                                                                                                                               |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `affonso`       | `affonso.constants`, `affonso.program`, `affonso.referral`                                                                                                                   | I parametri di referral, l'URL del pixel, l'ID del programma e il referral passato a Polar come metadati del checkout                                        |
| `better-auth`   | `auth.server`, `auth.client`, `auth.access`, `auth.middleware`, `auth.routes`, `auth.session`, `auth.errors`, `auth.hooks`, `auth.zod`, `auth.constraints`, `auth.constants` | Configurazione dell'autenticazione, ruoli, middleware delle server function, guard delle route, query della sessione, ID dei provider                        |
| `drizzle-orm`   | `drizzle.config`, `drizzle.database`, `drizzle.schemas`, `drizzle.errors`, `drizzle.columns`, `migrations/`                                                                  | Il client D1, il registro degli schemi, le migrazioni SQL, `rethrowAsConflict` per gli errori di vincolo di unicità e le colonne condivise di `timestamps()` |
| `fumadocs`      | `fumadocs.config`, `fumadocs.source`, `fumadocs.docs`, `fumadocs.search`, `fumadocs.i18n`                                                                                    | Le collezioni MDX per documentazione e blog, il caricamento delle pagine e la ricerca                                                                        |
| `motion`        | `motion.features`, `motion.tokens`                                                                                                                                           | Il bundle di funzionalità Motion caricato in modo lazy e le transizioni condivise                                                                            |
| `polar`         | `polar.config`, `polar.constants`, `polar.discounts`                                                                                                                         | Il client dell'SDK di Polar, gli ID dei prodotti offerti al checkout e la regola degli sconti regionali condivisa da checkout e `polar:verify`               |
| `resend`        | `resend.config`, `resend.utils`, `resend.constants`                                                                                                                          | Il client Resend, `sendEmail` e i nomi di `EMAIL_PURPOSE`                                                                                                    |
| `tanstack-form` | `form.fields`                                                                                                                                                                | I tipi di campo e `fieldErrorMessage` per TanStack Form                                                                                                      |
| `use-intl`      | `i18n.config`, `i18n.messages`, `i18n.middleware`, `i18n.paths`, `i18n.utils`                                                                                                | Locale, caricamento dei messaggi, URL localizzati e cookie                                                                                                   |

## Cosa non è un'integrazione

- Il numero di stelle GitHub è una server function in `src/lib/github.ts`, messa in cache in KV.
- Il rate limiting è `src/lib/rate-limit.ts`, basato sulla tabella `rate_limit`.
- I binding di Cloudflare non richiedono un adapter. Il codice server li legge da `env` in `cloudflare:workers`.

## La logica di business resta nei moduli

Un'integrazione configura un fornitore. Le decisioni sui dati dell'applicazione spettano al modulo che possiede la tabella:

- Il plugin Polar in `auth.server.ts` verifica le firme dei webhook con `POLAR_WEBHOOK_SECRET` e passa gli eventi a `licenseWebhookHandlers` in `src/modules/license/license.webhooks.ts`, che chiamano i casi d'uso delle licenze.
- Gli hook email di Better Auth chiamano `sendVerifyEmail`, `sendResetPasswordEmail` e `sendChangeEmailConfirmationEmail` dai moduli verification e account.
- Un caso d'uso invia un'email nel locale che gli passa il chiamante (l'email di verifica lo legge dall'URL di callback): carica il namespace del template, renderizza il template e chiama `sendEmail`:

```ts
const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotency: { purpose: EMAIL_PURPOSE.VERIFY_EMAIL, token },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```
