---
title: "Współtworzenie"
description: "Jak proponować zmiany w SaaSy Land."
---

1. Większe zmiany najpierw omów w zgłoszeniu (issue).
2. Utwórz gałąź od `main`.
3. Stosuj się do [architektury](/docs/architecture) i [konwencji](/docs/reference/conventions), a przed zmianą integracji z dostawcą przeczytaj odpowiednią [umiejętność agenta](/docs/tooling/agent-skills).
4. Trzymaj testy obok testowanego kodu i utrzymuj wymóg 100% pokrycia.
5. Uruchom poniższe kontrole.
6. Utwórz commit z komunikatem w formacie [konwencjonalnego commita](/docs/tooling/conventional-commits) i otwórz pull request z tytułem w tym samym formacie.

```sh
bun run check
bun run test:coverage
bun run test:e2e:install
bun run test:e2e:smoke
```

Przy zmianach, które wpływają na wiele tras, uwierzytelnianie lub zachowanie przeglądarki, uruchom pełny zestaw testów przeglądarkowych (`bun run test:e2e`). Gdy zmieniasz konfigurację prawdziwych integracji z dostawcami, zweryfikuj je osobno.

Gdy zmienia się zachowanie aplikacji, zaktualizuj `content/docs` we wszystkich dziewięciu językach; `bun run check:i18n` odrzuca brakujące tłumaczenia oraz różnice w blokach kodu i nawigacji. W pull requeście opisz wynikowe zachowanie, sposób weryfikacji oraz wszelkie pozostawione dane demonstracyjne lub niedokończone przepływy.
