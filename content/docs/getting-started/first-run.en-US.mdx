## Isolated test preview

The test preview builds the application for the `test` environment: local D1, KV and R2 in `.wrangler/test`, dummy credentials from `.env.test`, seeded accounts and intercepted Resend and Polar requests. It needs no accounts.

```sh
bun run db:reset:test
bun run build:test
bun run start:test
```

Open <RepositoryFact name="localServerOrigin" /> and sign in with one of the accounts that `e2e/data/accounts.ts` seeds. Each uses the password <RepositoryFact name="testPassword" />. Admins land on `/admin` and customers on `/app`, and the licensed accounts and their licences come from `e2e/data/licenses.ts`. The Complete licence opens every paid lesson of the sample course.

<RepositoryTable columns={["Email", "Role", "Licence"]} name="seededAccounts" />

The preview serves a build, so rebuild it to see source changes.

## Development with Cloudflare

`bun run dev` starts the dev server with hot reload at http://localhost:3000. Its `DB`, `CACHE`, `MEDIA` and `BUNDLES` bindings are local, in `.wrangler/state`, so development never reads or writes the preview or production data, and it needs no Cloudflare login.

```sh
cp .env.example .env.development
bun run db:reset:local
bun run db:seed:local
bun run dev
```

1. Fill in `.env.development` as described in [Environment variables](/docs/getting-started/environment-variables), with `POLAR_SERVER=sandbox`.
2. Create the local database and apply the migrations with `db:reset:local`.
3. Seed it with `db:seed:local`: an admin, the course curriculum, licences and an order.
4. Start the server and sign in as <RepositoryFact name="localAdminEmail" /> with `LOCAL_ADMIN_PASSWORD` from `.env.development`, or <RepositoryFact name="localAdminPassword" /> when it is not set.

`bun run db:studio:local` opens the local data in Drizzle Studio. Email sign-up needs a working Resend configuration: a new account is signed in at once, but its licence key and paid lessons wait for the confirmation link, and signing in again requires a confirmed address. [Database](/docs/tooling/database) describes the three databases, the seed and how to create the first admin on preview and production.
