ライセンスのエリアは、Polar のエリアのプラグインと Webhook（[決済](/docs/features/payments)）を土台に、プラン `core`、`complete`、`agency` を Polar の商品として販売します。`src/modules/license/license.utils.ts` の `POLAR_PRODUCT_IDS` はプランを `POLAR_PRODUCT_ID_CORE`、`POLAR_PRODUCT_ID_COMPLETE`、`POLAR_PRODUCT_ID_AGENCY` に対応付け、`licenseTierForProduct` は同じ対応付けから商品のプランを読み取ります。[Polar の設定](/docs/getting-started/polar-setup)では、各プランが Polar で必要とする商品、ライセンスキー、割引を説明しています。

## 購入

有効なライセンスを持たないサインイン済みユーザーには、`/app` と `/app/license` に `LicenseOffer` が表示されます。ランディングページのプランのカード（`PricingTiers`。[ランディングページ](/docs/features/landing-page)を参照）にプランごとの `CheckoutButton` を付けたもので、地域価格のチェックボックスと、購入で視聴できるようになるコースのレッスンも表示されます。

### 即時提供への同意 [#consent-to-immediate-supply]

`CheckoutButton`（`src/presentation/components/custom/app/checkout.tsx`）は、自分では購入を開始しません。代わりにダイアログを開き、そのプランがデジタルコンテンツで、購入者が支払うとすぐに提供されることを伝え、必須のチェックボックスを 1 つ求めます。このチェックボックスで、購入者は即時提供を求め、ライセンスキーの発行によって提供が始まった時点で <RepositoryFact name="refundWithdrawalDays" unit="day" />間の撤回権を失うことを了承します。ボックスの下には、プロジェクトを生成していなければ同じ期間内は全額返金を受けられることが示され、返金ポリシー、利用規約、商用ライセンスへのリンクがあります。これらは、EU でデジタルコンテンツの撤回権を消滅させる条件です。つまり、購入者の事前の明示的な同意、撤回権を失うことの了承、そして永続的な媒体での確認で、この確認が[購入確認](#purchase-confirmation)メールです。

フォームは `CheckoutConsent`（`checkout-consent.tsx`）で、`licenseZodSchemas.startCheckout.pick({ withdrawalConsent: true })` で検証する TanStack Form です。ボックスが空のまま **支払いに進む** を押しても何も始まりません。ボックスは無効としてマークされ、`aria-describedby` で `license.validations` の `withdrawalConsentRequired` を指し、このメッセージはアラートとして読み上げられます。ラベルを押してもボックスにチェックが入り、フォーカスはダイアログ内から始まります。Escape キーまたは **キャンセル** でダイアログを閉じられますが、購入の開始中は閉じられません。概要ページのセクションはすべてのページのスケルトンとともに読み込まれるため、`checkout.tsx` はダイアログが開いたときにフォームを `lazy` で読み込み、TanStack Form をエントリースクリプトに含めません（[パフォーマンス](/docs/conventions/performance#skeletons-stay-in-the-entry-script)を参照）。

### 購入の開始

`startCheckout`（`src/modules/license/use-cases/start-checkout.ts`）は `{ locale, tier, withdrawalConsent }` を受け取ります。そのスキーマは `withdrawalConsent` が `true` の場合にしか受け付けないため、サーバーは同意のない購入を拒否します。`startCheckout` は次の処理を行います。

1. アカウントにすでに `active` なライセンスがある場合は、チェックアウトの代わりに `{ alreadyActive: true }` を返します。ボタンは `pages.license` の `buy.alreadyActive` を表示してライセンスを再取得するため、購入後も開いたままだったページはライセンスの表示に切り替わります。
2. `pppDiscountId`（`license.ppp.ts`）で地域割引を探します。`cf-ipcountry` の国に対応する割引率を、`findRegionalDiscount`（`src/integrations/polar/polar.discounts.ts`）が Polar で現在利用できる自動のパーセント割引と照合します。`regional_pricing` Cookie が `off` の場合は適用しません。
3. `polar.checkouts.create` で、そのプランの Polar 購入セッションを作成します。セッションはアカウントに結び付けられ（`external_customer_id`）、アカウントのメールアドレスと名前が入力済みになる（`customer_email`、`customer_name`）ため、購入フォームはそれらが入った状態で開きます。さらに、`cf-connecting-ip` から得た購入者の IP アドレス（`customer_ip_address`、Better Auth の `getIP` で取得）を渡し、割引コードを無効にし、同意を `custom_field_data` に入れて、Polar 自身の必須チェックボックスに購入者に代わってチェックを入れます。購入者の言語は `metadata` の `locale`（`LICENSE_CHECKOUT_METADATA`）に入れ、訪問者がアフィリエイトリンク経由で来た場合は、その隣にアフィリエイトの紹介情報も含めます（[アフィリエイトプログラム](/docs/features/affiliates)を参照）。成功 URL は購入者の言語の `/app?checkoutId={CHECKOUT_ID}`（`localizePathname`）にします。Polar はメタデータとカスタムフィールドのデータを注文にコピーし、`{CHECKOUT_ID}`（`POLAR_CHECKOUT_ID_PLACEHOLDER`）を購入セッションの ID に置き換えます。
4. 購入 URL を返し、ブラウザーがそれを開きます。

返金済み（`refunded`）または取り消し済み（`revoked`）のライセンスがあっても、新しい購入はできます。

### アップグレード

アカウントが持つライセンスは 1 つだけで、新しい支払い済みの注文は古い注文のプランを置き換えます（`grantLicense`）。Polar の商品にはアップグレード用の価格がないため、セルフサービスでアップグレードすると最初の購入に加えて上位プランの全額が請求され、下位プランを購入するとライセンスがダウングレードされてしまいます。そのため、ライセンスが有効な間は購入を拒否し、`LicenseCard` ではプランを変更したい場合はサポートにメールするよう所有者に案内します。2 回目の購入を許可する前に、Polar でアップグレード用の商品か割引を作成してください。

### サインアップ前に選んだプラン

ランディングページの各プランのボタンは `/auth/sign-up?redirect=/app?tier=<tier>` にリンクします。戻り先のパスはサインアップ、メール認証、サインインを経ても保持され（`useAuthRedirect`）、すでにサインインしている訪問者はそのまま戻り先に移動します。`licenseSearchSchema`（`src/data/license.ts`。`searchParam` で構築）は、`/app/license` で、またライセンスのエリアが概要ページに追加するパラメーターとして `/app` で、`tier` を `LICENSE_TIER` と照合します。`/app` と `/app/license` はどちらもプランのカードの上に `ChosenTier` を表示します。プラン、地域割引を適用した価格、**決済に進む** ボタンが含まれ、このボタンも同じ同意のダイアログを開きます。ロックされた有料レッスンは、サインイン済みの視聴者を `/app/license?tier=complete` に、ゲストをランディングページの料金セクションにリンクします。アカウントが必要なレッスンはサインインにリンクします（[コース](/docs/features/courses)）。

サインアップページの時点でプランが示されます。ライセンスのエリアは `src/data/license.sign-up-intros.ts` で `SignUpOrderSummary`（`custom/app/sign-up-order-summary.tsx`）を `SIGN_UP_INTROS` に追加し、`redirectTierSchema`（`src/data/license.ts`）がロケールの接頭辞の有無にかかわらず `/app` または `/app/license` への `redirect` から `LICENSE_TIER` を読み取ると、ページは説明文の代わりにこれを表示します。概要には、プラン名と `TIER_PRICES` の金額、訪問者がいま `PURCHASE_STEP` のどのステップにいるか（アカウント作成の次に Polar での支払い）、そして未使用の購入なら `REFUND_TERMS.WITHDRAWAL_DAYS` 日以内に全額返金されることが、返金ポリシーへのリンク付きで表示されます。サインアップページには地域別価格の選択肢がないため、概要には定価が表示され、訪問者が辞退していなければ決済時に地域別の割引が適用されます。`SignUpPending` は同じリダイレクトに対して `SignUpOrderSummaryPending` を描画し、それ以外の `redirect` では説明文がそのまま表示されます。

### 支払い後

Polar は購入者を `/app?checkoutId=<id>` に戻します。通常、これは `order.paid` Webhook がライセンスを付与するより前です。`checkoutId` があり、ライセンスがまだ有効でない間、ページはプランのカードを隠して `CheckoutActivation` を表示します。このコンポーネントは <RepositoryFact name="activationPollSeconds" unit="second" />ごと（`ACTIVATION_POLL_MS`）に `currentLicenseQuery` を再取得します。

- ライセンスが有効になると購入者にお礼を表示し、その下にライセンスが表示されます。
- <RepositoryFact name="activationTimeoutSeconds" unit="second" />
  （`ACTIVATION_TIMEOUT_MS`）たってもライセンスがない場合は再取得を止め、Polar
  がまだ支払いを確認していないことを伝えます。あわせて、サポートのメールアドレス、問い合わせ用の番号としての購入セッション
  ID、**もう一度確認** ボタンを表示します。

UUID ではない `checkoutId` は無視されます。

## Webhook とライセンス [#webhooks-and-licences]

`src/data/license.polar-events.ts` は、`LICENSE_WEBHOOK_EVENTS`（`license.constants.ts`）に列挙されたイベントでライセンスのエリアを Polar のイベントに追加し（[決済](/docs/features/payments#webhooks)を参照）、そのうち注文のイベントには `POLAR_WEBHOOK_EVENT` の値を使います。このファイルの `handle` は、各イベントを `licenseWebhookHandlers` の同じ名前のハンドラーに渡します。`licenseWebhookHandlers` は `Record<keyof typeof LICENSE_WEBHOOK_EVENTS, unknown>` を満たすため、イベントのないハンドラーや、ハンドラーのないイベントがあるとコンパイルが通りません。`licenseWebhookHandlers`（`src/modules/license/license.webhooks.ts`）は Polar の顧客の `external_id` でユーザーを特定します。イベントには Polar がイベントを作成した時点で記録していた顧客が含まれ、再配信でも同じ内容が送られます。そのため、その `external_id` がどのアカウントも指していない場合、`onOrderPaid` と `onBenefitGrantCreated` は `polar.orders.get` で注文を読み直し、注文の現在の顧客で照合します。このアプリにアカウントがない顧客のイベントは、アカウントが必要な場合はログに記録したうえで受領し、Polar が再送しないようにします。

- `onOrderPaid` → `grantLicense`: 購入した商品のプランと、即時提供への購入者の同意（[記録と返金](#records-and-refunds)を参照）で、ユーザーの唯一のライセンスを作成または更新します。新しい購入が古い購入を置き換えます。続いて `sendPurchaseConfirmationEmail` が購入を確認します（[購入確認](#purchase-confirmation)を参照）。送信に失敗するとハンドラーも失敗するため、Polar がイベントを再送します。ライセンスではない商品の注文はログに記録するだけです。顧客がどのアカウントにも対応しないライセンスの注文は、ログに記録したうえで通知します（[アカウントに対応しない注文](#orders-that-match-no-account)を参照）。
- `onBenefitGrantCreated` → `attachLicenseKey`: Polar のライセンスキーをライセンスに保存します。支払い済みの注文がまだ記録されていない間は失敗させ、Polar に再送させます。返金済みの注文やライセンスではない商品のキーは受領します。
- `onOrderRefunded` → ステータス `refunded` で `revokeLicense`。注文が全額返金された場合のみで、一部返金ではライセンスを維持します。
- `onBenefitGrantRevoked` → ステータス `revoked` で `revokeLicense`。

`revokeLicense` は、その注文で購入したライセンスのステータスを設定し、注文を `revoked_license_order` に記録して、遅れて届いた Webhook が再び付与できないようにします。`refunded` を置き換えることはありません。Polar は返金された注文の特典も取り消し、2 つのイベントはどちらの順序でも届く可能性があるためです。[CLI ライセンス API](/docs/features/cli-licence-api) は、このステータスに応じて `licenseRefunded` または `licenseRevoked` を返します。

## 記録と返金 [#records-and-refunds]

`license` 行は、現在の購入について 3 つの記録を保持します。いずれも、そのできごとが起こるまでは空のままです。

| 列                      | 記録する内容                                                                                             | 書き込み元                                                          |
| ----------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| `withdrawal_consent_at` | 購入者がチェックアウトで即時提供に同意し、撤回権を失うことを了承した日時。注文が作成された時刻を使います | `order.paid` を受けた `grantLicense`                                |
| `activated_at`          | いずれかの端末でのキーの最初のアクティベーション                                                         | [CLI ライセンス API](/docs/features/cli-licence-api#records-of-use) |
| `delivered_at`          | CLI がそのキーで初めてテンプレートをダウンロードした日時                                                 | [CLI ライセンス API](/docs/features/cli-licence-api#records-of-use) |

購入者は[購入ダイアログ](#consent-to-immediate-supply)で同意します。Polar のチェックアウトは、すべてのライセンスの商品でこの同意を必須のチェックボックスとして改めて求め、`startCheckout` は直前に与えられた同意でそのボックスにチェックを入れます。同意は注文に `custom_field_data.<slug>` として保存されます。スラッグは <RepositoryFact name="licenseWithdrawalConsentField" />（`license.constants.ts` の `LICENSE_CHECKOUT_FIELD`）です。`src/lib/polar.ts` の `WITHDRAWAL_CONSENT_FIELD` はフィールドの名前、タイプ、英語のラベルを保持し、このフィールドを必須にしていない商品がある間は `polar:verify` が失敗します（[Polar の設定](/docs/getting-started/polar-setup#consent-checkbox)を参照）。`onOrderPaid` は Zod でこのフィールドを検証し、値が `true` の場合にだけ同意を記録します。返金後の購入など、同じアカウントの新しい注文は、同意をその注文自身の同意で置き換え、`activated_at` と `delivered_at` を空にします。そのため、記録は常に現在の購入を表します。これらの記録が導入される前に購入されたライセンスには、その当時の記録はありません。

`refundEligibility`（`src/modules/license/license.refunds.ts`）は、購入時刻、同意、最初のダウンロード、現在時刻だけから結果を求める純粋関数です。期間は購入から <RepositoryFact name="refundWithdrawalDays" unit="day" />で、この数値を宣言する唯一の場所である `src/data/refunds.ts` の `REFUND_TERMS.WITHDRAWAL_DAYS` で定められています。戻り値は `REFUND_ELIGIBILITY` のいずれか 1 つの種類です。

| 種類                  | 条件                                                                                     | 含む値        |
| --------------------- | ---------------------------------------------------------------------------------------- | ------------- |
| `refundable`          | 期間内で、購入者が同意しており、CLI がまだテンプレートをダウンロードしていない場合       | `until`       |
| `statutoryWithdrawal` | 期間内で、同意が記録されていないため、使用の有無にかかわらず法定の撤回権が適用される場合 | `until`       |
| `used`                | 期間内で、購入者が同意しており、CLI がすでにテンプレートをダウンロードした場合           | `deliveredAt` |
| `expired`             | 期間が終了した場合                                                                       | `endedAt`     |

管理者は、ユーザーのプロフィールで記録と、その結果を説明する文を確認できます。[ユーザー（管理）](/docs/features/users-admin#profile)を参照してください。

## 購入確認 [#purchase-confirmation]

`grantLicense` の後、`onOrderPaid` は、同意に必要な永続的な媒体での確認を購入者に送ります。`sendPurchaseConfirmationEmail`（`src/modules/license/use-cases/send-purchase-confirmation-email.ts`）は `PurchaseConfirmationEmail`（`src/presentation/emails/purchase-confirmation-email.tsx`、名前空間 `emails.purchase-confirmation-email`）をレンダリングし、購入したアカウントのアドレスに送信します。

- **言語**: 注文の `metadata.locale` を `localeField` で検証して使います。サイトが対応する言語を持たない注文には英語を使います。
- **注文**: 請求書番号（注文にまだ請求書番号がない場合は Polar の注文 ID）、注文日、その言語の料金カードと同じ名前で示すプラン、そして注文の通貨での `total_amount` です。`total_amount` は `fromMinorUnits` で補助単位から変換します。
- **撤回権**: `custom_field_data` に同意が含まれている場合、メールは、購入者が即時提供を求め、撤回権を失うことを了承したことを改めて示し、そのためこの注文には撤回権が適用されないことを伝えます。同意がない場合、メールは、購入者が注文日から <RepositoryFact name="refundWithdrawalDays" unit="day" />以内に撤回できることを伝えます。
- **返金**: 初回使用前の全額返金の期限 `refundDeadline`（`license.refunds.ts`）です。購入時刻に `REFUND_TERMS.WITHDRAWAL_DAYS` を加えた日付で、`refundEligibility` が使うのと同じ日付です。
- **リンク**: メールの言語のライセンスページ、利用規約、商用ライセンス、返金ポリシーです。リンク先は Webhook を受け取ったホストです。

日付は UTC で表示します。冪等性キーは `PURCHASE_CONFIRMATION`（`src/data/license.email-purposes.ts`）と Polar の注文 ID の組み合わせなので、Polar が `order.paid` を何度配信しても、Resend が送るメールは注文ごとに 1 通です。また、メールは注文だけから組み立てるため、再配信でも同じリクエストが送られます。アカウントやプランに対応しない注文には、確認メールを送りません。アカウントのないライセンスの注文については、代わりにサイト宛てにアラートを送ります（[アカウントに対応しない注文](#orders-that-match-no-account)を参照）。[トランザクションメール](/docs/features/email)を参照してください。

## アカウントに対応しない注文 [#orders-that-match-no-account]

`startCheckout` はすべての購入セッションをサインイン中のアカウントに結び付けます。そのため、注文がどのアカウントにも対応しないのは、Polar のダッシュボードで作成した購入リンクなど、`startCheckout` が作成していない購入セッションで支払われた場合か、購入セッションの開始から支払いまでの間にアカウントが削除された場合だけです。購入者は支払いを済ませているのにライセンスを持っていないため、サイトはその注文を通知し、ライセンスが付与されるまで一覧に表示します。

### アラート

`onOrderPaid` はこのような注文をログに記録し、`sendUnmatchedOrderAlert`（`src/modules/license/use-cases/send-unmatched-order-alert.ts`）に渡します。この関数は `UnmatchedOrderAlertEmail`（`src/presentation/emails/unmatched-order-alert-email.tsx`、名前空間 `emails.unmatched-order-alert-email`）を `I18N.DEFAULT_LOCALE` で、`NOTIFICATIONS_EMAIL` から `CONTACT_EMAIL` に送信します。メールには次の内容が記載されます。

- Polar の注文 ID と注文日（UTC）
- プランと、注文の通貨での `total_amount`
- イベントに含まれる顧客のメールアドレスと名前。含まれていない場合はその旨
- Polar のダッシュボードで注文を開くリンク。`polarOrderUrl`（`src/modules/license/license.utils.ts`）が、`POLAR_DASHBOARD_HOSTS` のうち `POLAR_SERVER` に対応するホスト、`POLAR_ORGANIZATION_SLUG`（どちらも `src/data/polar.ts`）、注文 ID から組み立てます
- [注文を復旧する](#recovering-an-order)手順

冪等性キーは `UNMATCHED_ORDER_ALERT`（`src/data/license.email-purposes.ts`）と Polar の注文 ID の組み合わせです。Resend はキーを 24 時間保持するため、その間に同じ注文が何度配信されても、アラートは 1 通だけ送られます。それ以降の再配信では、注文がまだどのアカウントにも対応していなければ、改めてアラートを送ります。アラートを送信できない場合はハンドラーが失敗するため、Polar がイベントを再送します。

### 管理画面の一覧

ライセンスのエリアは、`src/data/license.dashboard.ts` で `UnlicensedOrders`（`src/presentation/components/custom/admin/license/unlicensed-orders.tsx`）を[管理ダッシュボード](/docs/features/admin-dashboard)のパネルに追加し、ダッシュボードのローダーがそのクエリをプリフェッチします。`unlicensedOrdersQuery`（`src/modules/license/use-cases/get-unlicensed-orders.ts`）は `order: ["read"]` をチェックし、[Polar の注文のコピー](/docs/features/payments#orders-and-subscriptions-in-d1)のうち、次の条件をすべて満たすものを新しい順に一覧表示します。

- ステータスが `paid` であること
- `product_id` が `POLAR_PRODUCT_IDS` に含まれること
- どのライセンスの `polar_order_id` でもないこと
- `revoked_license_order` に含まれないこと

各行（`unlicensed-order-columns.tsx`）には、Polar の注文を新しいタブで開く注文 ID、日時、Polar の顧客 ID、補助単位から変換した金額が表示されます。該当する注文がない場合、パネルには、支払い済みのライセンス注文にはすべてライセンスがあることが表示されます。一覧には、`order.paid` の配信がまだ成功していない注文や、削除されたアカウントの注文（ライセンスもアカウントとともに削除されたもの）も含まれます。

### 注文の復旧 [#recovering-an-order]

1. 管理画面のユーザー管理で購入者のアカウントを探すか、**ユーザーを追加する** を使い、アラートに記載されたメールアドレスでアカウントを作成します（[ユーザー（管理）](/docs/features/users-admin)を参照）。アカウントの ID は、プロフィールのアドレス `/admin/users/<ID>` の最後の部分です。
2. アラートまたは管理画面の一覧から Polar で注文を開き、続いてその顧客を開きます。顧客のメニューで **Edit Customer** を選び、**External ID** にアカウントの ID を設定して **Save Customer** を選びます。API を使う場合は、`customers:write` を持つトークンで `PATCH /v1/customers/{id}` に `external_id` を送ります。Polar は外部 ID を一度設定すると保持し続け、組織内で一意であることを求めます。そのため、この方法が使えるのは、顧客に外部 ID がまだなく、アカウントに別の Polar の顧客がない場合だけです。それ以外の場合は、Polar で注文を返金し、サインインした状態でもう一度購入するよう購入者に依頼します。
3. Polar の Webhook の設定でエンドポイントの配信履歴を開き、その注文の `order.paid` イベントを見つけて **Redeliver** を選びます。続いて、`benefit_grant.created` イベントでも同じ操作をします。`onOrderPaid` がライセンスを付与してアカウントのアドレスに購入確認メールを送り、`onBenefitGrantCreated` がライセンスキーを保存します。`benefit_grant.created` が先に届いた場合は、ライセンスができるまで失敗し、Polar が再試行します。その後、注文は管理画面の一覧から消えます。

Polar がイベントを再配信できるのは、そのイベントのペイロードを保持している間だけです。Polar のサーバーはペイロードを 90 日後にアーカイブします。

## 顧客向け画面

`/app/license` は `LicenseCard`（プラン、キー、CLI コマンド、`/api/auth/customer/portal` の Polar カスタマーポータルへのリンク、プラン変更の連絡先となるサポートのメールアドレス。キーとポータルはアドレスが確認されるまで表示されません。[メール確認](/docs/features/email-verification#what-waits-for-the-confirmed-address)を参照）と `LicenseActivations` を表示します。`LicenseActivations` は Polar 上のキーのアクティベーションを一覧表示し、`deactivateLicense` で個別に解除します。Polar がそのアクティベーションをもう保持していない場合、`deactivateLicense` は `NOT_FOUND` を返します。CLI は [CLI ライセンス API](/docs/features/cli-licence-api) を通じてアクティベーションを追加、削除します。Polar は各プランのライセンスキーの特典に設定されたアクティベーション数の上限を強制します。この上限は `LICENSE_ACTIVATION_LIMITS` と一致している必要があり、Core は <ActivationLimit tier="core" />、Complete は <ActivationLimit tier="complete" />、Agency は <ActivationLimit tier="agency" /> です。[顧客アプリ](/docs/features/customer-app)を参照してください。
