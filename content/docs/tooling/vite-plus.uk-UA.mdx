Vite+ (`vite-plus`, команда `vp`) об'єднує Vite, Vitest, oxlint і oxfmt за одним CLI, а `vite.config.ts` налаштовує їх усі. `package.json` перевизначає `vite` на `@voidzero-dev/vite-plus-core` і фіксує `vitest` на версії 5.0.1. Скрипти пакета викликають `vp`; поза ними використовуйте глобальний Vite+ CLI або `bunx vp`.

| Команда           | Використовується в                                |
| ----------------- | ------------------------------------------------- |
| `vp dev`          | `dev`                                             |
| `vp build --mode` | `build:preview`, `build:production`, `build:test` |
| `vp preview`      | `start`, `start:test`                             |
| `vp test`         | `test` і скриптах Vitest `test:*`                 |
| `vp lint`         | `lint`                                            |
| `vp fmt`          | `format`, `format:check`                          |
| `vp check`        | `check`, `check:fix`                              |
| `vp staged`       | `check:pre-commit`                                |
| `vp config`       | `prepare`, який встановлює Git-хуки               |

## Конфігурація

`vite.config.ts` завантажує свої плагіни ліниво. Під Vitest завантажується лише `@vitejs/plugin-react`; в інших випадках набір такий:

- `@cloudflare/vite-plugin`: запускає Worker у середовищі SSR, зберігає локальний стан (у `.wrangler/test` для режиму `test`) і використовує віддалені прив'язки для `development`.
- `fumadocs-mdx`: компілює колекції документації та блогу.
- `@tailwindcss/vite`: Tailwind CSS 4.
- `tanstackStart`: маршрутизація, розділення коду та попередній рендеринг публічних сторінок.
- `@vitejs/plugin-react`.

Dev-сервер використовує порт 3000 і завершується з помилкою, якщо порт зайнятий. `resolve.tsconfigPaths` надає псевдонім імпорту `~/`. Той самий файл містить секції `fmt`, `lint`, `staged` і `test`; див. [Лінтинг і форматування](/docs/tooling/lint-format) і [Тестування](/docs/tooling/testing).

## Git-хуки

`bun install` запускає `prepare`, який викликає `vp config --no-agent`, щоб встановити диспетчер хуків для `.vite-hooks/`. `pre-commit` запускає `bun run check:pre-commit`, а `prepare-commit-msg` запускає `scripts/commit-msg.ts` (див. [Conventional commits](/docs/tooling/conventional-commits)). `vp hooks status` показує, чи активні хуки в клоні.

Надавайте перевагу скриптам пакета; викликайте `vp` напряму для цільових запусків, наприклад для форматування чи лінтингу конкретних шляхів.
