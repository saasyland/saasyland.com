## Preview de pruebas aislada

La preview de pruebas compila la aplicación para el entorno `test`: D1, KV y R2 locales en `.wrangler/test`, credenciales ficticias de `.env.test`, cuentas precargadas y solicitudes a Resend y a Polar interceptadas. No necesita cuentas.

```sh
bun run db:reset:test
bun run build:test
bun run start:test
```

Abre http://127.0.0.1:3000 e inicia sesión con una de las cuentas que precarga `e2e/data/accounts.ts`. Todas usan la contraseña <RepositoryFact name="testPassword" />. Los administradores llegan a `/admin` y los clientes a `/app`, y las cuentas con licencia y sus licencias vienen de `e2e/data/licenses.ts`. La licencia Complete abre todas las lecciones de pago del curso de ejemplo.

La preview sirve una compilación, así que vuelve a compilarla para ver los cambios en el código fuente.

## Desarrollo con Cloudflare

`bun run dev` inicia el servidor de desarrollo con recarga en caliente en http://localhost:3000. Sus bindings `DB`, `CACHE`, `MEDIA` y `BUNDLES` se conectan a los recursos remotos de preview, por lo que las escrituras durante el desarrollo van a la base de datos de preview.

```sh
bunx wrangler login
cp .env.example .env.development
bun run db:migrate:development
bun run dev
```

1. Inicia sesión en Cloudflare con Wrangler.
2. Rellena `.env.development` como se describe en [Variables de entorno](/docs/getting-started/environment-variables), con `POLAR_SERVER=sandbox`.
3. Con tu propia cuenta de Cloudflare, crea la base de datos D1, el espacio de nombres de KV y los buckets de R2, y después sustituye los ID y los nombres de bucket de `development` y `preview` en `wrangler.jsonc`; los valores incluidos en el repositorio pertenecen al despliegue existente. Consulta [Desplegar una preview](/docs/getting-started/deploy-preview).
4. Aplica las migraciones e inicia el servidor.

El registro por correo electrónico necesita una configuración de Resend que funcione, porque las cuentas deben verificar su dirección de correo antes de iniciar sesión. No hay ningún seed de administrador para desarrollo: regístrate, verifica la dirección y, a continuación, establece el `role` de tu usuario en `admin` con `bun run db:studio:development`.
