`src/integrations/better-auth/auth.access.ts` は、権限ステートメントを `APP_STATEMENTS` で宣言してロールに付与し、そこから Better Auth のアクセス制御を組み立てます（[ロールと権限](/docs/guides/roles-and-permissions)を参照）。同じ定義が、サーバー（`authorized`、ルートガード）と Better Auth のクライアントの両方で使われます。

## ロール

| ロール | コード     | 権限                                                                                                                |
| ------ | ---------- | ------------------------------------------------------------------------------------------------------------------- |
| 管理者 | `admin`    | 以下のすべてのアプリケーションステートメントに加え、`user` と `session` に対する Better Auth の管理者ステートメント |
| 顧客   | `customer` | なし。顧客は、セッションだけを必要とするサーバー関数を呼び出せます。                                                |

新規ユーザーには `customer`（`auth.roles.ts` の `DEFAULT_ROLE_CODE`）が割り当てられます。

## 権限がチェックされる場所

`src/modules/*/use-cases/` のすべてのユースケースを、実行する `authorized` 呼び出しごとに示します。`authorized()` はセッションだけを求め、権限は求めません。

<RepositoryTable name="permissionChecks" columns={["ミドルウェア", "ユースケース"]} />

`authorized` を使わないサーバー関数は `withRequest` または `withRateLimit` を実行し、セッションを必要としません: <RepositoryFact name="publicUseCases" />。ユースケースの外では、`/admin` レイアウトの `requireAdmin` とサインイン後のリダイレクトが `hasPermission` で `admin: ["access"]` を確認し、`resolveViewer`（`lesson.viewer.ts`）は `course: ["read"]` を持つユーザーに、レッスンのアクセスレベルにかかわらずすべてのレッスンの視聴と教材のダウンロードを許可します。

<RepositoryFact name="uncheckedStatements" /> は宣言されていますが、まだどのサーバー関数でもチェックされていません。

## 権限をチェックする

サーバー関数では、`authorized({ category: ["read"] })` のようにミドルウェアを使います。それ以外のコードでは、ルートガードと同じように `hasPermission` を呼び出します。

```ts
const isAdmin = (role: string | null | undefined): boolean => hasPermission({ permission: { admin: ["access"] }, role })

export const requireAdmin = async (context: ProtectedRouteContext) => {
  const result = await requireSignedIn(context)
  if (!isAdmin(result.session.user.role)) {
    throw redirect({ replace: true, to: ROUTES.APP.INDEX })
  }
  return result
}
```
