## Preview de pruebas aislada

La preview de pruebas compila la aplicación para el entorno `test`: D1 y KV locales en `.wrangler/test`, credenciales ficticias de `.env.test`, cuentas precargadas y solicitudes a Resend y a Polar interceptadas. No necesita cuentas.

```sh
bun run db:migrate:test
bun run db:seed:test
bun run build:test
bun run start:test
```

Abra http://127.0.0.1:3000 e inicie sesión con una de las cuentas precargadas. Ambas usan la contraseña `WorkerTestPassword123!` de `e2e/data/accounts.ts`.

| Rol           | Correo electrónico                | Espacio de trabajo |
| ------------- | --------------------------------- | ------------------ |
| Administrador | `admin@saasyland.example.test`    | `/admin`           |
| Cliente       | `customer@saasyland.example.test` | `/app`             |

La preview sirve una compilación, así que vuelva a compilarla para ver los cambios en el código fuente.

## Desarrollo con Cloudflare

`bun run dev` inicia el servidor de desarrollo con recarga en caliente en http://localhost:3000. Sus bindings `DB` y `CACHE` se conectan a los recursos remotos de preview, por lo que las escrituras durante el desarrollo van a la base de datos de preview.

```sh
bunx wrangler login
cp .env.example .env.development
bun run db:migrate:development
bun run dev
```

1. Inicie sesión en Cloudflare con Wrangler.
2. Rellene `.env.development` como se describe en [Variables de entorno](/docs/getting-started/environment-variables), con `POLAR_SERVER=sandbox`.
3. Con su propia cuenta de Cloudflare, cree la base de datos D1 y el espacio de nombres de KV y sustituya los ID de `development` y `preview` en `wrangler.jsonc`; los ID incluidos en el repositorio pertenecen al despliegue existente. Consulte [Desplegar una preview](/docs/getting-started/deploy-preview).
4. Aplique las migraciones e inicie el servidor.

El registro por correo electrónico necesita una configuración de Resend que funcione, porque las cuentas deben verificar su dirección de correo antes de iniciar sesión. No hay ningún seed de administrador para desarrollo: regístrese, verifique la dirección y, a continuación, establezca el `role` de su usuario en `admin` con `bun run db:studio:development`.
