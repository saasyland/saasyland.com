このリポジトリは、すべての依存関係の最新リリースで動作しています。アップグレードで何かが壊れた場合は、元に戻すのではなく、コードかアップストリームで前に進む形で修正します。

## ツールチェーンのバージョン

- Bun はパッケージマネージャー兼スクリプトランナーです。そのバージョンを設定する場所は `package.json` の `packageManager`（Bun <RepositoryFact name="bunVersion" />）だけで、CI もそこから読み取ります。`bun.lock` はコミットします。
- Node のバージョンは `.nvmrc`（<RepositoryFact name="nodeVersion" />）で決まり、`engines.node` はそれ以上のバージョンを要求します。
- 唯一の例外は `remotion/` で、独自の npm ツールチェーンを持ち、ランディングページの動画を編集するときにだけインストールします。

## アップグレード

1. 新しいバージョンの変更履歴と移行ガイドを読みます。できれば `node_modules/<package>` に同梱されているものを読んでください。
2. 新しいバージョンのドキュメントに記載された使い方に合わせてコードを変更します。
3. 次の順序で検証します。最後のステップが成功するまでは、何も完了したと報告しないでください。

```sh
bun run check
bun run test:coverage
bun run build:test
bun run test:e2e:pr
```

`check` とテストは Cloudflare と TanStack Start のビルドを行わずに実行されるため、ビルドが壊れていても成功することがあります。実際、1 回のアップグレードでそれが 2 度起きました。新しい `@polar-sh/sdk` がバンドルできなかったことと、TanStack Start のリリースで、`optimize-prerendered-html.ts` が書き換える `modulepreload` のマークアップが変わったことです。どちらも `build:test` でしか表面化しませんでした。ビルドの後、`find dist/server -name '*.map'` は何も出力してはいけません。`wrangler.jsonc` に `upload_source_maps: false` があるのは、ソースマップを含めた Worker が、Cloudflare がアップロードで受け付けるサイズを超えてしまうためです（[Cloudflare Workers](/docs/integrations/cloudflare-workers) を参照）。

破壊的変更を避けるためにパッケージを古いリリースに固定してはいけません。また、ライブラリのバグを回避するコードをアプリケーションに追加してはいけません。

## バグがアップストリームにある場合

アプリケーションがすでにドキュメントどおりの使い方をしていて、新しいバージョンのほうが誤っている場合は、新しいバージョンのまま修正を保持します。

1. このリポジトリの外で、最小限の再現例を作ってバグを証明します。
2. アップストリームに提案する修正と同じ内容で、パッケージ内のバグを直す最小限の変更を書き、`bun patch` で保存します。パッチは `patches/<package>@<version>.patch` と `patchedDependencies` に記録され、パッチが適用され続けるよう、パッケージはその正確なバージョンに固定されます。
3. そのプロジェクトのコントリビューションのルールに従って、アップストリームにバグを報告し、修正を含むプルリクエストを作成します。
4. 修正を含むリリースが出たら、すぐにパッチを削除します。パッチを維持したりドキュメントに記載したりする前に、`npm view <package> version` でそのリリースがすでに出ていないかを確認してください。

現在のパッチは 3 つです。`patches/@videojs%2Futils@10.3.0.patch` は動画プレーヤーのストーリーボードのサムネイル URL を修正し、これに合わせて `@videojs/react` は 10.3.0 に固定されています。`patches/@fumadocs%2Fbase-ui@16.19.0.patch` はタイトルのないコードブロックが名前のない region ランドマークになるのを防ぎ、`@fumadocs/base-ui` は 16.19.0 に固定されています。`patches/fumadocs-core@16.19.0.patch` は、次のページを読み込んでいる間も TanStack アダプターの `usePathname` がルーターの表示中のページを返すようにし、`fumadocs-core` は 16.19.0 に固定されています。`fumadocs-mdx` 15.6.0 へのパッチも同じ方法で保持し、15.6.1 でアップストリームの修正がリリースされた時点で削除しました。

## セキュリティアドバイザリー

Dependabot のアラートは `remotion/package-lock.json` を対象にしますが、GitHub は `bun.lock` を読みません。そのため、アプリケーションは `bun audit` で、動画プロジェクトは `remotion/` 内の `npm audit` で確認します。アドバイザリーは、脆弱なパッケージを取り込んでいるパッケージの最新リリースで解消します。そのパッケージのバージョン範囲がすでに修正済みのリリースを許容している場合は、ロックファイルを更新するだけで十分です（`bun update`、または `remotion/` での `npm update`）。

親パッケージのどのリリースもまだ修正を許容していない場合は、`overrides` のエントリーで脆弱なパッケージのバージョンを引き上げ、親パッケージのリリースが対応した時点でそのエントリーを削除します。現在のエントリーは次のとおりです。

- `package.json`: `"minimatch": "^11.0.1"`。`shadcn` は `ts-morph` 26 と `@ts-morph/common` を経由して `minimatch` ^10 を使っており、GHSA-g3hv-75wg-m249 を修正するのは `minimatch` 11.0.1 だけです。[dsherret/ts-morph#1697](https://github.com/dsherret/ts-morph/pull/1697) を含む `ts-morph` のリリースに `shadcn` が依存するようになったら削除します。
- `remotion/package.json`: `@typescript-eslint/typescript-estree` 配下の `minimatch` ^11.0.1 で、同じアドバイザリーへの対応です。`@remotion/eslint-config-flat` は `typescript-eslint` を 8.71.2 に固定しており、そのパーサーが `minimatch` ^10 を要求します。[typescript-eslint/typescript-eslint#13145](https://github.com/typescript-eslint/typescript-eslint/pull/13145) を含む `typescript-eslint` のリリースに `@remotion/eslint-config-flat` が依存するようになったら削除します。

`bun audit` は、適用できる修正のないアドバイザリーを 2 件まだ報告します。

- `deepmerge` 4.3.1（GHSA-gcqx-w48m-w2h4、重大度は低）: `shadcn` と `@shadcn/registry` 経由です。修正済みのリリースは存在せず、その CVE は脆弱性を記述していないとして却下されており、[github/advisory-database#10910](https://github.com/github/advisory-database/issues/10910) で GitHub にアドバイザリーの取り下げが求められています。
- `esbuild` 0.18.20（GHSA-67mh-4wv8-2f99、重大度は中）: `drizzle-kit` と `@esbuild-kit/esm-loader` 経由です。`drizzle-kit` 0.31.11 はこのローダーを依存関係として宣言していますが一度も import しておらず、アドバイザリーの対象は esbuild の開発サーバーで、このリポジトリでそれを起動するものはありません。[drizzle-team/drizzle-orm#5304](https://github.com/drizzle-team/drizzle-orm/issues/5304) で削除が追跡されており、`drizzle-kit` 1.0 のリリース候補はすでにこれに依存していません。

## package.json の Vite+ のエントリー

```json
"vite": "npm:@voidzero-dev/vite-plus-core@1.6.0",
"vite-plus": "1.6.0",
"vitest": "5.1.0"
```

これらの行と、`overrides` 配下の同じ `vite` エイリアスと `vitest` のバージョンは、Vite+ 自身の移行ツールが書き出すものとまったく同じです。`vite-plus` は正確なバージョンに固定され、Bun はコアを直接の `vite` 依存関係として必要とし、`vitest` は `@vitest/coverage-v8` とテストの型が必要とするため記載されています。これらは `bun update` ではなく、`vp migrate` でまとめてアップグレードします。どれかを削除できるかどうかを知りたい場合は、プロジェクトをコピーし、コピーに対して `vp migrate` を実行して結果の差分を取ってください。推論で判断してはいけません。`overrides` 配下の `minimatch` エントリーは上で説明したセキュリティ対応で、`vp migrate` はそれを変更しません。

`vite.config.ts` の `build.rolldownOptions.external` には、`@polar-sh/sdk` の省略可能なピア依存関係のうち、インストールされておらず Worker からツリーシェイキングで除かれるものを列挙しています。[Vite+](/docs/tooling/vite-plus) を参照してください。Polar がパッケージングを修正したら、このリストを削除します。

## 依存関係を追加する

1 つの関心事に使うライブラリを 1 つに保つため、まず `package.json` にすでにあるパッケージでその役割を果たせないかを確認します。ランタイムの依存関係は `bun add` で、ツールは `bun add --dev` で追加し、ベンダーのエージェントスキルが `skills-lock.json` にあればそれを使います（[エージェントスキル](/docs/tooling/agent-skills)を参照）。
