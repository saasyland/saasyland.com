The application is a TanStack Start app. `src/router.tsx` creates the router with a QueryClient per request, the SSR query integration, default error and not-found components, intent preloading, a preload stale time of <RepositoryFact name="routerPreloadStaleTimeMs" unit="millisecond" />, so TanStack Query alone decides what is fresh, and the locale `rewrite`. There is no default pending component: every route sets its own skeleton (see [Loading skeletons](/docs/architecture/delivery-layer#loading-skeletons)). `src/routes.ts` exports `ROUTES`, the path constants used by links, guards and head tags.

The repository carries Bun patches to `@tanstack/router-core` 1.171.39 and `@tanstack/react-router` 1.170.46, and pins `@tanstack/router-core`, `@tanstack/react-router` and `@tanstack/react-start` so the patched versions stay installed. The router's first render after hydration reset the window's scroll position, which the browser and the router's inline restoration script had already set, so a visitor who scrolled while the page hydrated was sent back to the top; with the patch, hydration leaves the scroll position alone. `lazyRouteComponent` reloads the page when a route chunk fails to load, to pick up a new deployment, and Safari and Firefox fail the chunks of a page the visitor is leaving the same way, so the reload replaced the visitor's navigation with the page they were leaving; with the patch, a chunk that fails after `beforeunload` waits instead and loads again if the visitor stays. A route's loader chunk gets no such reload; after a deploy, the router's default error component loads the page again instead (see [Routes and delivery](/docs/architecture/delivery-layer#after-a-deploy)). See [Dependencies](/docs/conventions/dependencies).

## Routes

`src/routes/` contains flat file routes: `admin.users.all.tsx` serves `/admin/users/all`, `_site.tsx` is a pathless layout and `_site.docs.$.tsx` is a splat route. The ID in `createFileRoute("…")` is a string literal maintained by the router generator in `src/routeTree.gen.ts`; `__test__` folders are ignored as routes.

A route file only composes its page. It defines the `<Name>Page` or `<Name>Layout` component, `NAMESPACE` or `NAMESPACES`, a loader that awaits metadata, messages and the data of its first flush in one `Promise.all` and streams the rest into the page's skeletons, `head: pageHead(ROUTES.X)` and, for protected areas, a guard in `beforeLoad`. Widgets, dialogs, forms and table columns live in `src/presentation/components/custom/` and read their own translations and data. See [use-intl](/docs/integrations/use-intl) for the loader and [Better Auth](/docs/integrations/better-auth) for the guards.

## Server functions

Operations are native `createServerFn` functions exported from module use cases, so the application does not expose a REST endpoint for them. See [Server functions and use cases](/docs/integrations/server-functions).

## HTTP handlers

These routes declare `server.handlers` in `src/routes/api/`:

| Route                                        | Handler                                                                                 |
| -------------------------------------------- | --------------------------------------------------------------------------------------- |
| `/api`                                       | Returns the runtime as JSON                                                             |
| `/api/auth/$`                                | Better Auth, including OAuth callbacks and Polar webhooks at `/api/auth/polar/webhooks` |
| <RepositoryFact name="cliApiBasePath" />`/*` | The CLI licence API, `licenseApiHandlers` in `src/modules/license/license.api.ts`       |

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Prerendering

The TanStack Start plugin in `vite.config.ts` enables prerendering with link crawling, and `shouldPrerender` (`src/lib/prerender.ts`) filters the crawled paths. `build:preview`, `build:production` and `build:test` prerender public pages (landing, legal pages, blog and docs) in every locale. The filter skips `/admin`, `/api`, `/app`, `/auth`, `/courses` and `/newsletter`, with or without a locale prefix, as well as links containing `?` or `#`. Skipped pages render on the Worker for each request.
