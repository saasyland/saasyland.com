## アプリケーションはどのランタイムで動作しますか？

Cloudflare Workers です。パッケージのインストールとスクリプトの実行には Bun を使い、アプリケーションのビルド、フォーマット、lint、テストには Vite+（`vp`）を使います。

## ローカルでテストを実行するのに Cloudflare アカウントは必要ですか？

いいえ。Vitest はインメモリの SQLite データベースとインメモリの KV を使います。Playwright は `test` Wrangler 環境を使い、`.wrangler/test` 内のローカル D1 と KV、`.env.test` のダミーシークレットで動作します。ただし、`bun run dev` には Cloudflare へのアクセスが必要です。`development` 環境はリモートのプレビュー用バインディングを使うためです。

## 新しい操作はどこに置きますか？

データベーステーブルを扱う操作であれば、そのテーブルのモジュール内のユースケース `src/modules/<table>/use-cases/<verb>-<noun>.ts` にします。1 つのルートだけが使い、どのテーブルにも触れない場合は、そのルートファイル内で `createServerFn` を使って定義します。それ以外は `src/lib` に置きます。

## 新しいモジュールはいつ作成しますか？

新しいデータベーステーブルを追加するときだけです。テーブルを持たないモジュールは認められていません。

## 新しいコンポーネントはどこに置きますか？

複数のエリアで共有するコンポーネントは、`src/presentation/components/custom` 内のフラットなファイルにします。1 つのエリアで使うコンポーネントは、そのエリアのフォルダー（例：`custom/admin/users/`）に置きます。1 ファイルにつき、ウィジェット、ダイアログ、フォームは 1 つだけです。

## 言語はどのように構成されていますか？

en-US はプレフィックスのない URL を使い、他の 8 つのロケールは完全なタグをプレフィックスとして使います（例：`/de-DE`、`/pl-PL`）。すべてのロケールが `messages/<locale>` に同じ名前空間ファイルを持ち、すべてのドキュメントページが `<page>.<locale>.mdx` として存在します。

## コンポーネントにテキストを渡すにはどうすればよいですか？

渡しません。コンポーネントが自分の名前空間に対して `useTranslations` を呼び出し、テキストを自分で読み取ります。
