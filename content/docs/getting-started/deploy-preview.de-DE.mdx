---
title: "Eine Preview deployen"
description: "Cloudflare-Ressourcen bereitstellen und den Preview-Worker deployen."
---

Die Umgebung `preview` deployt den Worker `saasyland-preview` nach `preview.saasyland.com`. Standardmäßig teilen sich `development` und `preview` eine D1-Datenbank, einen KV-Namespace und einen R2-Bucket.

## Ressourcen bereitstellen

```sh
bunx wrangler login
bunx wrangler d1 create saasyland_com_preview
bunx wrangler kv namespace create CACHE --env preview
bunx wrangler r2 bucket create saasyland-preview
```

Ersetzen Sie in `wrangler.jsonc` sowohl unter `development` als auch unter `preview` die Werte `database_id`, `database_name`, die KV-`id` und den `bucket_name` von `MEDIA`. Behalten Sie die Binding-Namen `DB`, `CACHE` und `MEDIA` sowie `migrations_dir` bei und passen Sie die Worker-Namen und die Routen der eigenen Domains an Ihr Konto an. Legen Sie für die Produktion separate Ressourcen an, einschließlich des Buckets `saasyland`, und aktualisieren Sie den Block `production`. Setzen Sie `APP_DOMAIN` in `src/presentation/branding/index.ts`. `appHostsForMode` in `src/modules/_core/constants/api.ts` leitet daraus die erlaubten Hosts ab: `APP_DOMAIN` in Produktion, `preview.<APP_DOMAIN>` in Preview, `localhost:3000` oder `127.0.0.1:3000` in Entwicklung sowie im Test diese und zusätzlich `localhost:3020` und `127.0.0.1:3020`. Bearbeiten Sie dort `HOSTS_BY_MODE` nur, wenn Ihr Preview-Host anders heißt.

## Deployen

Füllen Sie `.env.preview` aus und deployen Sie dann:

```sh
bun run deploy:preview
```

`deploy:preview` führt `scripts/verify-bindings.ts preview` aus, das fehlende Bindings und Platzhalter-IDs ablehnt, dann `build:preview`, das die öffentlichen Seiten vorab rendert und die Ausgabe prüft. Anschließend schreibt `scripts/prepare-deploy-secrets.ts preview` die Secrets, die `wrangler.jsonc` für `preview` deklariert, aus `.env.preview` nach `.wrangler/secrets.preview.json` und schlägt fehl, wenn eines davon leer ist. `db:migrate:preview` wendet die neuen Migrationen an, bevor `wrangler deploy` die Datei `dist/server/wrangler.json` mit diesen Secrets hochlädt, und `scripts/verify-deployment.ts preview` prüft zum Schluss, ob https://preview.saasyland.com antwortet. `verify-bindings.ts` prüft nicht, ob der R2-Bucket existiert, weil er über seinen Namen gebunden ist: Das Deployment schlägt fehl, solange er nicht existiert. `bun run db:migrations:preview` listet die Migrationen auf, die die Preview-Datenbank noch nicht angewendet hat.

Registrieren Sie die OAuth-Callbacks und den Polar-Webhook für den Preview-Host, wie unter [Umgebungsvariablen](/docs/getting-started/environment-variables) aufgeführt.

## Automatische Deployments

Die CI deployt jeden Pull Request von einem Branch in diesem Repository in die gemeinsame Preview und jeden Push auf `main` in die Produktion, sobald Prüfungen und Browsertests erfolgreich sind. Die erforderlichen GitHub-Secrets finden Sie unter [CI/CD](/docs/tooling/ci-cd).
