## 実装済み

- **セッション**: D1 に保存される Better Auth のセッション、Cookie プレフィックス `saasyland`、ローカル以外のモードでのセキュア Cookie、モード別の許可ホスト、クライアントアドレスとしての `cf-connecting-ip`。クライアント側のセッションにトークンは含まれません。
- **アカウント**: 必須のメール確認、パスワードリセット時のセッション失効、バックアップコード付きの任意の TOTP、ハッシュ化して保存される確認用識別子、暗号化された OAuth トークン。
- **認可**: ルートでは `requireSignedIn` と `requireAdmin`、サーバー関数では、`auth.access.ts` がエリアのアクセスファイルから組み立てるロールを使う `authorized(permission)`。
- **レート制限**: Better Auth のリミッターと `withRateLimit` ミドルウェアが D1 の `rate_limit` テーブルを共有します。`RATE_LIMITS.SENSITIVE` は <RepositoryFact name="sensitiveRateLimit" /> 回、`RATE_LIMITS.TOKEN` は <RepositoryFact name="tokenRateLimit" /> 回の呼び出しを、クライアントとアクションごとに <RepositoryFact name="rateLimitWindowSeconds" unit="second" />あたり許可します。確認メール、パスワードリセットメール、ニュースレターの確認メールも、種類ごとにアドレスあたり 1 時間に <RepositoryFact name="recipientEmailsPerHour" /> 通までに制限されます（`withinRecipientRateLimit`、アドレスの SHA-256 ハッシュがキー）。上限を超えるとメールは黙ってスキップされます。[CLI ライセンス API](/docs/features/cli-licence-api) は、そのリクエストをアドレスごととライセンスキーごとに同じテーブルでカウントします。
- **エラー**: リクエストミドルウェアが失敗を `AppError` のコード（`src/modules/_core/constants/errors.ts`）に変換するため、クライアントがサーバーの生のメッセージを受け取ることはありません。コンポーネントは `useErrorMessage` で表示します。
- **Webhook とフォーム**: Polar の Webhook は `POLAR_WEBHOOK_SECRET` で検証されます。ニュースレターの購読（`subscribeToNewsletter`）は、`appHostsForMode` が返すビルドモードのホスト上で、HTTPS 経由、または development と test では HTTP 経由で送られたものだけを受け付けます（`newsletterRequestOrigin`）。
- **Better Auth の入力**: `auth.hooks.ts` の `enforceInputPolicy` が、パスワード、名前、メールアドレス、画像を受け付けるすべての Better Auth エンドポイントにフォームのスキーマを適用します。そのため、`/api/auth` へ直接送られたリクエストにも同じルールが適用されます。ルールに反するリクエストには `VALIDATION_ERROR` を付けた `400` が返ります。
- **メディア**: 動画ファイルは非公開の R2 バケットに置かれます。Worker は、`AUTH_SECRET` から導出した HMAC 鍵で署名され、少なくとも <RepositoryFact name="signedMediaHours" unit="hour" />有効な `/media/` パスでのみ動画ファイルを配信します。`getVideoPlayback` は `video: ["read"]` を持つ呼び出し元にこのパスを発行します。`getLessonPlayback` は、公開済みのレッスンについて `hasLessonAccess` が視聴者を許可した時点で発行します。そのため、ゲストは無料プレビュー、サインイン済みのユーザーはアカウントが必要なレッスン、Complete または Agency のライセンスを持つユーザーは有料レッスン、管理者はすべてのレッスンについてこのパスを受け取ります。署名が不正または期限切れの場合は `403` が返ります。
- **CLI のテンプレートバンドル**: 各リリースのバンドルは非公開の `BUNDLES` バケットに置かれます。CLI ライセンス API は、有効なライセンスと呼び出し元の端末のアクティベーションに対してだけ、<RepositoryFact name="cliApiBundleUrlTtlSeconds" unit="second" />有効な `/bundles/` URL に署名します。鍵は、HKDF が `AUTH_SECRET` からバンドル専用に導出した HMAC 鍵です。署名が不正または期限切れの場合は `403` が返ります。[CLI ライセンス API](/docs/features/cli-licence-api#template-bundles) を参照してください。
- **ヘッダー**: Worker からのすべてのレスポンスに `X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`、`X-Frame-Options: DENY`、`Cross-Origin-Opener-Policy: same-origin`、カメラ・マイク・位置情報・topics を無効にする `Permissions-Policy`、フレームへの埋め込み・`<base>` の変更・プラグインを禁止する Content Security Policy（`base-uri 'none'`、`frame-ancestors 'none'`、`object-src 'none'`）を付けます。HTTPS のレスポンスには `Strict-Transport-Security` も加えます。これらは `src/modules/_core/constants/api.ts` の `SECURITY_HEADERS` と `HTTPS_SECURITY_HEADERS` として一度だけ定義され、`src/server.ts` が Worker のすべてのレスポンスに設定します。レスポンスや `public/_headers` のルールがすでに設定した値は置き換えます。Worker を経由せずに配信されるファイル（`/assets/*`、`/fonts/*`、`/robots.txt`、`/llms.txt`）には、`public/_headers` の `/*` ルールから同じヘッダーが付きます。`public/_headers` は、コードが実行される前にプラットフォームが読み取る静的ファイルです。そのルールと定数が異なると、`src/__test__/server.test.ts` が失敗します。
- **スクリプト**: ページは、配信時に含まれていたスクリプトだけを実行します。ページの Content Security Policy は Google の strict CSP に従います。nonce またはハッシュを指定した `script-src`、それらのスクリプトがルートのチャンクや Affonso のピクセルなどの残りを読み込めるようにする `'strict-dynamic'`、そして nonce とハッシュに対応したブラウザーでは無視されるフォールバックとしての `'unsafe-inline' https:` です。Worker がレンダリングするページは、ヘッダーでポリシーを受け取ります。`src/server.ts` はレスポンスごとに nonce を作成し、`renderedPagePolicy(nonce)`（`src/lib/content-security-policy.ts`）を送信して、その nonce をリクエストコンテキストの `nonce` として TanStack Start に渡します。`getRouter` がそれをルーターに渡すため、ルーター、React、`ThemeScript` がレンダリングするすべてのスクリプトに nonce が付きます。プリレンダリングされたページはどの訪問者にも同じファイルなので、nonce を持てません。そのため、すべてのビルドで `scripts/secure-prerendered-html.ts` が `optimize-prerendered-html.ts` の後に実行されます。`securePrerenderedPage`（`src/lib/prerendered-policy.ts`）は、エントリーモジュールを `<script src>` の代わりに小さなインラインスクリプトから読み込み、すべてのインラインスクリプトのハッシュを計算して、charset の直後の `<meta http-equiv="Content-Security-Policy">` タグにポリシーを書き込みます。ブラウザーは meta タグ内の `frame-ancestors` を無視するため、フレームへの埋め込みの制限はヘッダーに残ります。ブラウザーでは zod を `jitless` で実行するため（`src/integrations/zod/zod.config.ts`、zod 専用のチャンクに置かれます）、zod が `eval` を使えるかどうかを調べることはありません。開発サーバーはヘッダーのポリシーだけを送ります。Vite のインラインスクリプトには nonce が付かないためです。ブラウザーテストのスイートは本番ビルドに対して実行され、ページが違反を報告したスペックはすべて失敗します。

## 未実装

- スタイル、画像、メディア、フォント、接続に対する Content Security Policy のディレクティブ、Trusted Types、違反のレポート。ポリシーが制限するのは、スクリプト、プラグイン、ベース URL、フレームへの埋め込みです。
- 利用停止、削除、なりすましを含む監査ログ。
- 公開フォームのボット対策や CAPTCHA。
