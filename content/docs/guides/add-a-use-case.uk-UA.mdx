Сценарій використання — це одна операція над однією таблицею. Він розміщується в `src/modules/<table>/use-cases/<operation>.ts` і експортує серверну функцію разом із параметрами, які використовують компоненти. Будівельні блоки описано в посібнику [Серверні функції](/docs/guides/server-functions).

## Напишіть мутацію

`src/modules/category/use-cases/create-category.ts`:

```ts
import { mutationOptions } from "@tanstack/react-query"
import { createServerFn } from "@tanstack/react-start"
import { v7 } from "uuid"
import type * as zod from "zod"

import { authorized } from "~/src/integrations/better-auth/auth.middleware"
import { db } from "~/src/integrations/drizzle-orm/drizzle.database"

import { CATEGORY_MUTATION_KEYS } from "~/src/modules/category/category.constants"
import { category } from "~/src/modules/category/category.schema"
import { categoryZodSchemas } from "~/src/modules/category/category.zod"

export const createCategory = createServerFn({ method: "POST" })
  .middleware([authorized({ category: ["create"] })])
  .validator((input: zod.input<typeof categoryZodSchemas.createCategory>) => categoryZodSchemas.createCategory.parse(input))
  .handler(({ data }) =>
    db
      .insert(category)
      .values({
        description: data.description ?? "",
        icon: data.icon ?? "FolderOpen",
        id: v7(),
        kind: data.kind,
        name: data.name,
        visibility: data.visibility ?? "public",
      })
      .returning()
      .get(),
  )

export const createCategoryMutation = mutationOptions({
  mutationFn: (data: Parameters<typeof createCategory>[0]["data"]) => createCategory({ data }),
  mutationKey: CATEGORY_MUTATION_KEYS.CREATE,
})
```

- Записи використовують `method: "POST"`, читання — `method: "GET"`.
- Middleware захищає виклик: `authorized(permission)` для користувачів, що увійшли й мають дозвіл, `authorized()` для будь-якого користувача, що увійшов, `withRateLimit(kind, RATE_LIMITS.SENSITIVE)` для публічних операцій.
- Валідатор розбирає схему модуля, а handler отримує вже провалідовані `data`.
- Handler повертає результат напряму. Операції з власними даними того, хто викликає, беруть користувача з `context.auth.user.id`, а не з вхідних даних.

## Напишіть запит

Запити експортують параметри, ключ яких містить провалідовані вхідні дані, тож кожна сторінка чи фільтр має власний запис у кеші (`src/modules/category/use-cases/get-categories.ts`):

```ts
export const getCategoriesPageQuery = (input: zod.input<typeof listCategoriesSchema> = {}) =>
  queryOptions<Awaited<ReturnType<typeof getCategories>>>({
    queryFn: () => getCategories({ data: input }),
    queryKey: [...CATEGORY_QUERY_KEYS.LIST, listCategoriesSchema.parse(input)],
  })

export const getCategoriesQuery = getCategoriesPageQuery()
```

Попередньо завантажте запит у `Promise.all` loader маршруту через `context.queryClient.query({ ...getCategoriesQuery, staleTime: "static" })` і прочитайте його в компоненті через `useSuspenseQuery(getCategoriesQuery)`.

## Обробляйте збої

Для очікуваних збоїв кидайте `AppError` з кодом із `src/modules/_core/constants/errors.ts`:

```ts
if (row === undefined) {
  throw new AppError(ERROR_CODES.NOT_FOUND)
}
```

Коди: `AUTH_API_ERROR`, `CONFLICT`, `FORBIDDEN`, `INTERNAL_ERROR`, `NOT_FOUND`, `TOO_MANY_REQUESTS`, `UNAUTHORIZED` і `VALIDATION`. Middleware `withRequest`, який входить до `authorized` і `withRateLimit`, передає далі лише код `AppError`, перетворює помилки API Better Auth на `AUTH_API_ERROR` із ключем помилки автентифікації, помилки Zod — на `VALIDATION`, а будь-яку іншу помилку записує в лог і замінює на `INTERNAL_ERROR`.

## Використайте його в компоненті

Розгорніть експортовані параметри в `useMutation`, перекладайте помилки через `useErrorMessage` і після успіху інвалідуйте запити модуля (`src/presentation/components/custom/admin/users/delete-user-dialog.tsx`):

```tsx
const queryClient = useQueryClient()
const errorMessage = useErrorMessage()

const deleteUser = useMutation({
  ...deleteUserMutation,
  onError: (error) => {
    toast.error(errorMessage(error))
  },
  onSuccess: async () => {
    await queryClient.invalidateQueries({ queryKey: USER_QUERY_KEYS.ALL })
    toast.success(t("feedback.deleteSuccess"))
  },
})
```

`useErrorMessage` зіставляє ключі помилок автентифікації з `auth.errors.<key>`, коди помилок — з `errors.codes.<CODE>`, а все невідоме — з `errors.codes.INTERNAL_ERROR`. Інвалідуйте лише ті модулі, чиї дані змінює мутація.

## Протестуйте його

Додайте `use-cases/__test__/<operation>.test.ts`. `executeMutation` і `executeQuery` з `~/src/platform/testing/lib/query` виконують параметри через справжній `QueryClient`, а налаштування тестів проводить серверну функцію через її справжні middleware і валідатор. Покрийте успіх, кожен код, який кидається, і перевірку дозволу. Див. [Написання тестів](/docs/guides/writing-tests).
