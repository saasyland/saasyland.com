## コンテンツ

- ページは、すべての言語について `content/docs/<section>/<page>.<locale>.mdx` として置きます。
- 各フォルダーの `meta.<locale>.json` がセクションのタイトル、アイコン、ページの順序を決めます。アイコンは `fumadocs.icons.ts` の `DOCS_ICONS` のいずれかです。
- `src/integrations/fumadocs/fumadocs.i18n.ts` は `dot` パーサー、既定言語かつフォールバックとしての `en-US`、`hideLocale: "always"` を使います。言語プレフィックスはアプリ自身が処理するためです。
- `bun run content` は `fumadocs.config.ts` から `.source` を生成します。

## ルート

- `/docs` レイアウト（`src/routes/_site.docs.tsx`）: ローダーが現在の言語のページツリーをドキュメントのインデックスから読み（[Fumadocs](/docs/integrations/fumadocs#content-indexes) を参照）、レイアウトは Fumadocs の `DocsLayout` を `_site` レイアウトの中、サイトヘッダーの下、`BackToTop` の上に表示します。Fumadocs の目次は見出しへ移動するだけなので、ドキュメントには `BackToTop` が必要です。Fumadocs の `--fd-banner-height` をヘッダーの高さに設定してサイドバーと目次がヘッダーの下に固定されるようにし、サイドバーに `/docs` へのリンク付きの **ドキュメント** というタイトルを付け、GitHub へのリンクと、サイドバー下部に同じスタイルのセレクトフィールドとして並ぶ `LocaleSelect`・`ThemeSwitch` を表示します。`docs.css` を読み込み、読み込み中は `DocsPending`、つまりサイドバーと現在のパスのページを表示します。ローダーはページツリーと一緒に、`fumadocs` 名前空間と、ロードマップとテストカバレッジのページの表が表示する `stack` と `flow-features` のラベルを事前に読み込みます。ほかのすべての公開ページと同じく、ドキュメントの後にはサイトの `Footer` が続くため、法的情報のページ、連絡先のアドレス、ニュースレター、言語のリンクにはどのドキュメントページからもスクロールひとつで届きます。
- `md` 以上では、ドキュメントもほかの公開ページと同じくサイトの枠に収まります。レイアウトが Fumadocs のコンテナにヘッダーと同じ幅と余白（`mx-auto max-w-site md:px-10`）を与えるため、サイドバーはロゴの真下から始まり、`xl` 以上では目次が **開発を始める** の真下で終わり、ドキュメントとサイトのほかのページを行き来してもヘッダーの幅と位置は変わりません。サイドバーの幅は `--container-docs-sidebar`、目次の幅は `--container-docs-toc`（[テーマ](/docs/ui/theme)を参照）で、どちらも Fumadocs の既定より狭いため、記事はその間の列を読みやすい行の長さで埋めます。どちらかで 1 行に収まらないタイトルは、行の長さがそろうように折り返されます（`docs.css` の `text-wrap: balance`）。サイドバーは折りたためない（`collapsible: false`）ので、ヘッダーの下に表示されたまま独立してスクロールし、左右の線がヘッダーの線につながります。`e2e/specs/content-chrome.spec.ts` は、両端の位置、ヘッダーに対する枠の幅、記事の行の長さと記事がサイドバーと目次の間の列を埋めていること、スクロール前後のサイドバーの位置を確認し、`e2e/specs/navigation.spec.ts` は、ランディングページ、ブログ、コース、ドキュメントでヘッダーとフッターの幅と位置が同じであること、そしてそれらの間のクライアントナビゲーション中にヘッダーがどのフレームでも動かないことを確認します。
- `xl` 以上では、`docs-content.tsx` が `DocsPage` の `slots.toc.main` を通じて Fumadocs の目次を `DocsToc`（`custom/docs-toc.tsx`）に置き換えます。`#nd-toc` の列と **このページの内容** の見出しはそのままに、見出しの一覧にはブログと同じ `TableOfContents` を使うので、ドキュメントのページとブログの記事は、読んでいるセクションの示し方も線の動きも同じです（[ブログ](/docs/features/blog) を参照）。
- 小さい画面では、サイトヘッダーは自分のメニューをそのまま持ち、その下にドキュメントのバーが 1 本だけ並びます。レイアウトの `header` スロットである `DocsToolbar`（`custom/docs-toolbar.tsx`）には、ドキュメントのナビゲーションを開く唯一のボタン、現在のページのタイトル、検索ボタンが入ります。ナビゲーションはボタンと同じ側、つまり広い画面でサイドバーがある側から滑り込みます（`docs.css` の `#nd-sidebar-mobile`）。このバーは **ドキュメント** という名前のナビゲーションランドマークなので、ページのバナーはサイトヘッダーだけのままです。Fumadocs は自分のバーにしか高さ `--fd-header-height` を設定しないため、小さい画面ではドキュメントのレイアウトが自分で設定します。目次の列が隠れる `xl` 未満では、`docs-content.tsx` が Fumadocs の目次バーを無効にし、ブログ記事と同じく、ページの見出しを説明の下の折りたたまれた `InlineTOC` に並べるため、3 本目のバーが画面に残ることはありません。
- Fumadocs は自分のコントロールの文言を自分で書きます。検索、サイドバーのボタン、**このページの内容**、コードブロック・見出しのアンカー・アコーディオンの項目のコピーボタン、前後のページへのリンクです。`useFumadocsI18n`（`src/hooks/use-fumadocs-i18n.ts`）はこれらの文言をそれぞれ `fumadocs` 名前空間のメッセージに対応付け、ページの言語と一緒に `RootProvider` に渡すため、ほかのすべての文言と同じく `messages/<locale>/fumadocs.json` から表示されます。ポーランド語またはドイツ語のドキュメントページやブログ記事に Fumadocs の文言が英語のまま残ると、`e2e/specs/content-chrome.spec.ts` が失敗します。
- サイトヘッダーの **本文へスキップ** リンクがページで唯一のスキップリンクです。ドキュメントのページでは記事へ移動し、記事の id は Fumadocs の `nd-page` のままです。ドキュメントのレイアウトが `staticData` の `contentId` を `DOCS_CONTENT_ID`（`src/data/navigation.constants.ts`）に設定し、`Navigation` は一致したルートのうち `contentId` を設定している最も深いルートの値、なければ `SITE_CONTENT_ID` へリンクします。Fumadocs の `DocsLayout` は常に `#nd-page` への見えない 2 本目のリンクを自分で表示し、Fumadocs はそれを外すスロットを採用しませんでした（[fuma-nama/fumadocs#3866](https://github.com/fuma-nama/fumadocs/issues/3866)、[fuma-nama/fumadocs#3867](https://github.com/fuma-nama/fumadocs/pull/3867)）。サイトのリンクがすでに同じ記事へ移動するので、`globals.css` が `display: none` でそのリンクを隠し、Tab の順序とアクセシビリティツリーから外します。このルールは Tailwind のレイヤーの外に置いているため、16.19.5 以降に Fumadocs がリンクに付けるボタンのクラス（`inline-flex` など）でリンクが再び表示されることはありません。`e2e/specs/content-chrome.spec.ts` は、ドキュメント、ブログ、トップページのそれぞれにスキップリンクが 1 本あり、最初の Tab で届き、フォーカスを本文へ移すことを確認し、`e2e/specs/navigation.spec.ts` は、トップページからドキュメントへ移動して戻っても、ヘッダーが同じ要素のままであることを確認します。
- `/docs/` と `/docs/$` は `loadDocsPage`（`fumadocs.docs.ts`）を呼び出します。`loadDocsPage` は現在の言語のドキュメントのインデックスからスラッグでページを探してそのタイトル、説明、セクション、MDX ファイルを得て、レンダリング前にコンパイル済み MDX（`docsContent`）をプリロードします。読み込み中は `DocsIndexPending` と `DocsPagePending` が記事とその目次の代わりに表示され、サイドバーは画面に表示されたままです。
- どちらのローダーもクライアント側のナビゲーションではブラウザーで実行され、ドキュメントのインデックスとコンパイル済み MDX は `/assets/` 配下のファイルです。そのため、ドキュメント内を移動しても Worker には届きません（[パフォーマンス](/docs/conventions/performance#the-worker-holds-no-docs-or-blog-content)を参照）。

MDX ページでは `src/presentation/components/custom/mdx.tsx` の `mdxComponents` を使えます。Fumadocs の既定コンポーネント、Fumadocs の `Accordions`・`Steps`・`Tabs`、shadcn の `Alert`・`Badge`・`Button`・カードの各パーツ・`Separator`・テーブルの各パーツ、そして値を手入力する代わりにコードから表示する `RepositoryFact`・`RepositoryTable`・`TierPrice`・`ActivationLimit`・`RegionalDiscounts`（[翻訳とコンテンツ](/docs/conventions/translations)）が含まれます。リンクは自動的にローカライズされます。`localizeHref` は内部リンクのパスにページのロケールを付け、クエリとフラグメントはそのまま残します。そのため、ポーランド語のページでは `/#pricing` が `/pl-PL#pricing` を開きます。

## 検索 [#search]

検索ボタンと <kbd>Ctrl</kbd> または <kbd>⌘</kbd> + <kbd>K</kbd> で `DocsSearchDialog`（`custom/docs-search-dialog.tsx`）が開きます。ドキュメントのレイアウトはこれを Fumadocs の `RootProvider` に渡し、`lazy` で読み込みます。検索は Fumadocs の静的クライアントである `useStaticSearch` を使ってブラウザーで行います。訪問中の最初のクエリでページの言語の検索インデックス `/assets/search-index-<locale>-<hash>.json` をダウンロードし、それ以降の結果はすべてメモリから返します。このインデックスは、ビルドのたびに、その言語の各ドキュメントページの見出しと本文から書き出されます。ファイル名はコンテンツに応じて変わるため、ブラウザーはインデックスを 1 年間保持します。検索用のエンドポイントはありません。[Fumadocs](/docs/integrations/fumadocs#content-indexes) を参照してください。

## アクセシビリティ

ドキュメントページは両方のテーマで WCAG 2.2 AA を満たします。コードブロックは Shiki の GitHub Light と GitHub Dark のテーマを使い、2 つのトークンの色を置き換えて（`fumadocs.config.ts` の `colorReplacements`）すべてのトークンが 4.5:1 を満たすようにしています。コードブロックのスクロール領域はフォーカスできますが、ランドマークにはなりません。タスクリストのチェックボックスには項目のテキストで名前が付きます。`e2e/specs/accessibility.spec.ts` はドキュメントのトップページ、規約のすべてのページ、それ以外の各セクションから 1 ページずつをスキャンします。[アクセシビリティ](/docs/conventions/accessibility)を参照してください。

## ページの追加

1. `title` と `description` を付けて `<page>.en-US.mdx` を書きます。
2. スラッグを `meta.en-US.json` と、ほかのすべての `meta.<locale>.json` に同じ順序で追加します。
3. コードブロックをバイト単位で同一に保ったまま、ほかのすべての言語の翻訳を追加します。
4. `bun run check:content`（`bun run check` にも含まれます）と `bun run content` を実行します。

`bun run build` はすべてのドキュメントページを全言語でプリレンダリングします。
