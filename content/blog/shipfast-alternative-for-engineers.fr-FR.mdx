## Le nombre ShipFast publie, et celui qu'il ne publie pas

ShipFast fait quelque chose que la plupart des plaques de chaudière évitent: il montre son arithmétique. Sa page d'accueil itemise le travail qu'il supprime et le totalise. Ce chiffre est honnête, et le marché est d'accord avec lui. **8 393 fabricants** ont payé pour le produit. Un témoignage sur la page met la figure personnelle à "15 heures et plus." Je n'ai aucun argument avec tout cela. Si votre objectif est d'avoir une page d'atterrissage, une connexion et une caisse de travail en direct avant lundi, ShipFast est le bon achat et cet article ne vous en dissuadera pas.

Le deuxième numéro est celui qu'aucun kit de démarrage ne publie, parce qu'il est plus difficile d'énumérer et beaucoup plus grand:

**Combien d'heures y a-t-il entre votre lancement et votre deuxième cohorte?**

Pas entre un dossier vide et un déploiement. Entre un déploiement et une entreprise. C'est là que la première équipe demande des sièges, où le service financier du premier client demande une facture avec son nom d'entreprise, où vous découvrez que "delete account"doit passer par neuf tables, et où quelqu'un demande si l'application peut être utilisée en allemand.

L'heure 22 est une question de plaque de chaudière. **L'heure 300 est une question d'architecture**, et les deux n'ont presque rien à voir avec l'autre.

## Quatre décisions, et ce que chacun coûte à l'heure 300

Le reste est pour l'autre lecteur: celui qui construit quelque chose qu'une entreprise va payer, avec plus d'un siège, et qui a l'intention de le maintenir quand il a des clients.

### Le présent règlement est obligatoire dans tous ses éléments et directement applicable dans tout État membre. Un magasin de documents sous un produit relationnel

La ligne de pile de ShipFast est indiquée sur sa page d'accueil comme **"Mongo + Mailgun + Stripe + NextJS + Tailwind + NextAuth = ShipFast"**, avec Supabase disponible comme alternative.

Les objets sur lesquels les factures SaaS sont relationnelles, et pas d'ailleurs. Un utilisateur appartient à une organisation. Une organisation détient un abonnement. Un abonnement produit des factures. Une facture comporte des éléments de ligne qui renvoient à un prix qui fait référence à un produit. Chaque flèche de cette phrase est une clé étrangère.

Dans Postgres, ces flèches sont des contraintes. La base de données refuse d'orpheliner une facture. Une cascade sur la suppression de compte est une propriété schématique plutôt qu'un chemin de code que vous souhaitez que quelqu'un se souvienne. Un rapport joignant les abonnements aux organisations aux sièges est une question.

Dans un magasin de documents, chacune de ces flèches devient le code d'application. La jointure est un deuxième aller-retour. La garantie d'intégrité est une convention. Rien de tout cela n'est un problème à l'heure 22, quand vous avez quatre documents et un utilisateur. C'est le genre de problème qui arrive tranquillement à l'heure 300, quand un billet d'appui dit qu'une organisation annulée est toujours facturée et qu'il faut deux jours pour savoir pourquoi.

Il y a une autre ride spécifique à cette décennie. Les agents de codage écrivent beaucoup mieux le code relationnel que le code document, car le schéma est le type : un constructeur de requêtes tapé sur un schéma déclaré Postgres fait d'une colonne incorrecte une erreur de compilation. Nous avons écrit sur le mécanisme en [choisir une pile SaaS pour les agents de codage AI](/blog/choosing-a-saas-stack-for-ai-coding-agents), et il s'applique avec force ici. La mauvaise forme dans un magasin de documents compile, déploie et démos correctement.

### 2. NextAuth, et ce qui se passe au siège trois

NextAuth résout "let a person log in with Google" et il le résout bien. Les caractéristiques d'un produit d'affaires sont celles qui sont juste derrière : les organisations avec des invitations, les rôles qui permettent des actions spécifiques, deux facteurs appliqués par la politique plutôt que offert comme une option, l'imitation du soutien, la révocation de session quand quelqu'un quitte l'entreprise, et les pistes de vérification pour tout cela.

Rien de tout ça n'est exotique. Chacun d'eux est sur le premier questionnaire de sécurité que votre premier client d'affaires vous envoie. Et chacun, ajouté tard, touche le modèle de session, ce qui signifie qu'il touche tout ce qui lit la session.

L'alternative n'est pas tant une bibliothèque différente qu'une hypothèse de départ différente: que le code auth vit dans votre dépôt, dans une source lisible, avec l'organisation et le modèle de rôle déjà présents dans le schéma, que vous l'allumez ou non. C'est ce que signifie « Better Auth dans votre dépôt » dans le tableau ci-dessus. C'est aussi la raison pour laquelle il n'y a pas de ligne par mois-active-utilisateur dans votre modèle de coût au cours de la deuxième année.

### 3. Le Comité des droits de l'homme Deux dépôts, et un système de type qui est une préférence

ShipFast envoie une version JavaScript et une version TypeScript. C'est une décision de produit défendable. Il s'agit également d'une déclaration structurelle, et la déclaration est que **le système type est une option de distribution plutôt qu'une contrainte.**

Comparez avec ce à quoi ressemble la rigueur quand ce n'est pas facultatif. La configuration de cette base de code TypeScript n'est pas "strict: true" et rien d'autre. C'est :

```jsonc
{
  "strict": true,
  "exactOptionalPropertyTypes": true,
  "noUncheckedIndexedAccess": true,
  "noPropertyAccessFromIndexSignature": true,
  "noImplicitReturns": true,
  "noFallthroughCasesInSwitch": true,
  "noUnusedLocals": true,
  "noUnusedParameters": true,
  "verbatimModuleSyntax": true,
}
```

`noUncheckedIndexedAccess` seul change le caractère d'une base de code: `array[0]` est `T | undefined`, donc le bogue "il est évidemment là"devient une erreur de compilation plutôt qu'une page 3am. `exactOptionalPropertyTypes` signifie qu'il est explicite `undefined` n'est pas la même qu'une clé absente, ce qui est exactement la distinction qui produit la perte silencieuse de données dans un gestionnaire de mise à jour.

En plus de ça, `typescript/no-explicit-any` est une erreur plutôt qu'un avertissement, et le linter court avec `denyWarnings: true`C'est vrai. Il n'y a pas de `any` écoutille d'évacuation, et il n'y a aucun avertissement vous pouvez apprendre à ignorer, parce qu'un avertissement échoue la construction.

Le point n'est pas que les utilisateurs ShipFast écrivent un mauvais code. C'est qu'une base de code où la rigueur est un choix par projet contiendra, avec suffisamment de temps et suffisamment de contributeurs, le choix le plus faible quelque part. Et tu ne sauras pas où ça compte jusqu'à ce que ça compte.

## La différence qui n'est pas une caractéristique

Les tableaux de caractéristiques sont la forme la plus faible de comparaison, car n'importe qui peut ajouter une ligne. Voici la différence qui ne peut pas être ajoutée à une table par un concurrent la semaine prochaine, parce que c'est une propriété de la façon dont le code est tenu ensemble.

**Dans cette base de codes, l'architecture est exécutable.** Non documenté. Exécuté, par le linter, sur chaque commit.

```ts
// vite.config.ts, abridged
lint: {
  options: { typeAware: true, typeCheck: true },
}
```

Il y a trois de ces règles. Le code de domaine ne peut pas importer React, Ensuite, le code ORM, infrastructure ou application. Le code d'application ne peut pas importer d'infrastructure. Le code de présentation ne peut pas importer Drizzle ou entrer dans l'infrastructure d'un module, et doit appeler un cas d'utilisation d'application à la place.

La conséquence mérite d'être exprimée clairement. **Vous ne pouvez pas accidentellement mettre une requête de base de données dans un composant React.** Pas "vous ne devriez pas". Vous ne pouvez pas: la construction échoue avec un message qui dit pourquoi. Un nouveau contributeur apprend l'architecture dans le temps qu'il faut pour lire une erreur. Ainsi qu'un agent de codage, qui est de plus en plus le même énoncé.

Chaque kit de démarrage a un diagramme d'architecture dans sa lecture. Très peu en ont un avec lequel le compilateur est d'accord. Six mois en, c'est la différence entre une base de code qui a encore la forme que vous avez conçu et une qui est discrètement devenu un dossier de fichiers.

## Foire aux questions

<Accordions>

<Accordion title={"Quelle est la meilleure alternative ShipFast en 2026?"}>

Ça dépend de ce que vous construisez. Si vous voulez valider une idée ce week-end et passer à autre chose, ShipFast est déjà le bon outil et aucune alternative ne le bat à temps pour le premier déploiement. Si vous avez l'intention de charger des équipes, d'ajouter des sièges, de passer un examen de sécurité ou encore de maintenir la base de codes dans deux ans, vous voulez une fondation avec un modèle de données relationnelles, une porte de test et des limites architecturales imposées. C'est le métier à travers lequel cet article fonctionne.

</Accordion>

<Accordion title={"Est-ce que ShipFast est écrit dans TypeScript?"}>

Les deux. ShipFast envoie un dépôt JavaScript et un dépôt TypeScript comme options distinctes, et la documentation couvre les deux. C'est une vraie différence par rapport à une base de code où strict TypeScript est la seule chose qui existe : quand le système de type est un choix de distribution, ce n'est pas une contrainte que votre futur code doit satisfaire, et rien n'empêche un contributeur ultérieur d'atteindre le chemin non tapé.

</Accordion>

<Accordion title={"Est-ce que ShipFast inclut des tests automatisés?"}>

La documentation publique n'a pas de page pour les tests. Ses sections sont Tutoriels, Caractéristiques, Composants, Sécurité, Déploiement et Extras. Ceci est conforme à l'objectif déclaré du produit, qui est la vitesse à déployer d'abord plutôt que la maintenance à long terme, mais cela signifie que le filet de sécurité de régression est quelque chose que vous construisez vous-même avant votre deuxième fonction.

</Accordion>

<Accordion title={"Est-ce que ShipFast soutient des organisations ou des locataires multiples?"}>

La documentation n'a pas de page pour les locataires multiples, les organisations, les équipes ou le contrôle d'accès basé sur le rôle. Pour un produit mono-opérateur qui est parfait. Pour tout ce qui est vendu à une entreprise, il s'agit de l'élément le plus important du travail restant, parce que l'isolement des locataires doit être appliqué à la couche de requête plutôt que ajouté à la couche d'interface utilisateur une fois que les clients existent.

</Accordion>

<Accordion title={"Pourquoi l'utilisation de MongoDB est-elle importante pour une plaque de chaudière SaaS ?"}>

Parce que les objets des factures SaaS sont relationnels. Les utilisateurs appartiennent à des organisations, les organisations détiennent des abonnements, les abonnements produisent des factures, des postes de référence de factures. Un modèle de magasin de documents qui avec le niveau d'application rejoint et aucune clé étrangère, donc l'intégrité référente devient le code que vous devez écrire et garder correcte plutôt qu'une propriété garantie par la base de données.

</Accordion>

<Accordion title={"Est-ce qu'un kit de démarrage de 249 $ vaut quand ShipFast coûte 199 $?"}>

Les cinquante dollars ne sont pas la décision. Les deux prix sont une erreur d'arrondi par rapport au travail. La décision est quel ensemble de problèmes vous préférez posséder: à 199 $ vous possédez la location, les rôles, l'administrateur, la suite de test et le modèle de données réécrire; à 249 $ ceux qui arrivent écrits et couverts. Prix la différence dans vos propres heures et la comparaison cesse d'être sur le prix.

</Accordion>

<Accordion title={"Puis-je migrer un projet ShipFast existant ?"}>

Oui, et la voie honnête n'est pas une migration. Échafaudez un nouveau projet, transférez votre logique d'affaires dans les limites du module, et déplacez vos données avec un script unique. Les parties qui méritent d'être conservées sont votre code de domaine et votre copie. Les pièces que vous remplacez, le câblage auth, la plomberie de facturation et le modèle de données, sont les pièces qu'un kit de démarrage était censé vous donner de toute façon.

</Accordion>

<Accordion title={"Combien de clients ShipFast ont ?"}>

Sa page d'accueil indique 8 393 fabricants au moment de l'écriture, ainsi qu'un rabais qui compte à la baisse par rapport aux 8 400 premiers clients. C'est une véritable validation de l'offre et elle doit être prise au sérieux. Il mesure combien de personnes souhaitent un démarrage rapide, ce qui est une question différente de combien de ces projets étaient encore maintenus un an plus tard.

</Accordion>

<Accordion title={"Qu'est-ce que l'architecture mise en œuvre par linter signifie réellement ?"}>

Que les limites sont exécutables plutôt que décrites. Dans cette base de codes, le code de domaine ne peut pas importer React, Next, Drizzle ou infrastructure; le code d'application ne peut pas importer l'infrastructure; le code de présentation ne peut pas importer l'ORM. Ce sont des règles en peluche qui échouent à la construction, donc une violation architecturale est un contrôle rouge plutôt qu'un paragraphe dans une lecture que personne ne lit.

</Accordion>

<Accordion title={"Dois-je acheter une plaque de chaudière du tout, ou commencer par create-next-app?"}>

Commencez à partir de zéro quand la plomberie est la chose que vous voulez apprendre, ou quand votre produit est assez étrange que les hypothèses d'un démarreur vous combattre. Achetez lorsque le travail entre un dossier vide et votre première ligne vraiment nouvelle est le travail que vous avez fait avant et que vous préférez ne pas faire à nouveau. Presque personne n'a jamais été payé pour sa mise en œuvre auth.

</Accordion>
