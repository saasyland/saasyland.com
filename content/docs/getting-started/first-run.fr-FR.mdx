## Préversion de test isolée

La préversion de test construit l'application pour l'environnement `test` : D1, KV et R2 locaux dans `.wrangler/test`, identifiants factices issus de `.env.test`, comptes créés par le seed et requêtes vers Resend et Polar interceptées. Elle ne nécessite aucun compte.

```sh
bun run db:reset:test
bun run build:test
bun run start:test
```

Ouvrez http://127.0.0.1:3000 et connectez-vous avec l'un des comptes que crée le seed à partir de `e2e/data/accounts.ts`. Tous utilisent le mot de passe <RepositoryFact name="testPassword" />. Les administrateurs arrivent sur `/admin` et les clients sur `/app`, et les comptes licenciés et leurs licences viennent de `e2e/data/licenses.ts`. La licence Complete ouvre toutes les leçons payantes du cours d'exemple.

<RepositoryTable columns={["E-mail", "Rôle", "Licence"]} name="seededAccounts" />

La préversion sert un build : reconstruisez-la pour voir les modifications du code source.

## Développement avec Cloudflare

`bun run dev` démarre le serveur de développement avec rechargement à chaud sur http://localhost:3000. Ses bindings `DB`, `CACHE`, `MEDIA` et `BUNDLES` sont locaux, dans `.wrangler/state` : le développement ne lit ni n'écrit donc jamais les données de préversion ou de production, et il ne demande aucune connexion à Cloudflare.

```sh
cp .env.example .env.development
bun run db:reset:local
bun run db:seed:local
bun run dev
```

1. Remplissez `.env.development` comme décrit dans [Variables d'environnement](/docs/getting-started/environment-variables), avec `POLAR_SERVER=sandbox`.
2. Créez la base de données locale et appliquez les migrations avec `db:reset:local`.
3. Alimentez-la avec `db:seed:local` : un administrateur, le programme des cours, des licences et une commande.
4. Démarrez le serveur et connectez-vous en tant que <RepositoryFact name="localAdminEmail" /> avec `LOCAL_ADMIN_PASSWORD` de `.env.development`, ou <RepositoryFact name="localAdminPassword" /> lorsqu'il n'est pas défini.

`bun run db:studio:local` ouvre les données locales dans Drizzle Studio. L'inscription par e-mail nécessite une configuration Resend fonctionnelle, car les comptes doivent vérifier leur adresse e-mail avant de se connecter. [Base de données](/docs/tooling/database) décrit les trois bases de données, le seed et la création du premier administrateur en préversion et en production.
