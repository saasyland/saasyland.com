description: "Better Auth admin impersonation: the server functions exist, no screen uses them yet."
---

The Better Auth `admin` plugin provides impersonation, and `src/modules/user/use-cases` wraps it:

```ts
export const impersonateUser = createServerFn({ method: "POST" })
  .middleware([authorized({ user: ["impersonate"] })])
  .validator((input: zod.input<typeof userZodSchemas.impersonateUser>) => userZodSchemas.impersonateUser.parse(input))
  .handler(({ context, data }) => auth.api.impersonateUser({ body: data, headers: context.requestHeaders }))
```

`stopImpersonatingUser` needs only a signed-in session. Both files export mutation options (`impersonateUserMutation`, `stopImpersonatingUserMutation`).

## Current state

- No screen calls these functions: the users row actions menu has no impersonate item and there is no banner to stop impersonating.
- Better Auth marks impersonation sessions with `impersonatedBy`; `getActiveSessions` leaves them out of the settings session list.
- The route guards clear the query cache when the session user changes, so the next navigation after impersonating loads the other user's data.
- There is no audit log of impersonation.

To add it, put a menu item in `UserRowActions` (`src/presentation/components/custom/admin/users/row-actions.tsx`) and a visible way to stop impersonating in the layouts.
