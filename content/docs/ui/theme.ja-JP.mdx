## テーマの選択

`src/presentation/theme/index.ts` の `THEME` は、テーマ `light`、`dark`、`system`（既定）と Cookie `saasyland.com_theme` を定義します。アプリは `@wrksz/themes` を使います。

- ルートドキュメントの `head`（`src/routes/__root.tsx`）にある `ThemeScript` が Cookie を読み取り、最初の描画の前にテーマのクラスを設定するため、ちらつきは起きません。
- `ThemeProvider`（`src/providers/theme-provider.tsx`）は Cookie の値（`getStoredTheme`）から始まり、変更を Cookie に保存し、同じドキュメント内のすべての `ThemeProvider` を同期させます（`enableSameDocumentSync`）。他のタブとは同期しません。
- `ThemeProvider` が包むのは、テーマを読み取るか変更するウィジェットだけです。ルートの `Toaster` と、ドキュメントのサイドバーにある `ThemeSwitch` です。ハイドレーション後に更新されるプロバイダーはページ全体を再描画させるため、ルートの `Outlet` を包むことはありません。

```tsx
const RootComponent = () => (
  <AriaProvider>
    <OfflineBanner />
    {ROOT_COMPONENTS.map(({ component: Component, key }) => (
      <Component key={key} />
    ))}
    <Outlet />
    <ThemeProvider>
      <Toaster />
    </ThemeProvider>
  </AriaProvider>
)
```

`/admin`、`/app`、`/docs` は保存されたテーマに従います。テーマの切り替えはドキュメントのサイドバーにしかありません。`_site` レイアウトは、一致したルートが `staticData` に `dark: true` を設定している間、コンテナーに `dark` クラスを付けます。ランディングページ、法務ページ、ブログ、コースの `_marketing` レイアウトがこれを設定し、認証のレイアウトは自身のコンテナーに `dark` クラスを付けるため、これらのページは常にダークで表示されます。これらのコンテナーが `body` の直接の子である間は、`globals.css` が `html` にもダークのトークンを与えます（`:root:has(> body > .dark)`）。そのため、ページの周りのウィンドウはスクロールバーの背後も含め、ライトテーマでもダークになります。

## トークン

`src/presentation/styles/globals.css` は、shadcn のトークンを `:root`（ライト）と `.dark` の OKLCH 変数として定義します。`background`、`foreground`、`card`、`popover`、`primary`、`secondary`、`muted`、`accent`、`destructive`、`border`、`input`、`ring`、`chart-1` から `chart-5`、`sidebar-*` の一式、`radius` です。ブランドのアクセントは `ring` で、フォーカスリング、アクティブ状態、ハイライトに使われ、`chart-1` と同じ色です。`dark:` ユーティリティはクラスに従います。

```css
@custom-variant dark (&:is(.dark *));
```

`@theme inline` は変数を Tailwind の色に対応付け、フォントファミリーとタイプスケールを定義します。`globals.css` は Fumadocs UI のスタイルもインポートしているため、ドキュメントも同じトークンを使います。

`@theme` はレイアウト用のトークンを追加します。サイトヘッダーの高さ `--spacing-header`（`h-header`）、公開ページの幅 `--container-site`（`max-w-site`）、ドキュメントのサイドバーと目次の幅 `--container-docs-sidebar` と `--container-docs-toc`（`w-docs-sidebar`、`w-docs-toc`）です。`Navigation`、`MobileMenu`、`Footer`、`PageFrame`、ランディングページの各セクション、`ContentPage`、ブログ記事、コースのページ、ドキュメントのレイアウトはすべて `max-w-site` を使い、`md` 以上では同じ左右の余白を取るため、ヘッダーはページを移っても、クライアントナビゲーションでページが入れ替わる間も幅と位置が変わらず、内容はその下にそろいます。Fumadocs の `--fd-layout-width`（ドキュメントの最大幅）にも同じトークンを設定し、`globals.css` の末尾にある 2 つのルールが、`md` 以上で Fumadocs の `--fd-sidebar-width` にサイドバーのトークンを、`xl` 以上で `--fd-toc-width` に目次のトークンを設定します。ドキュメントの読み込み中のスケルトンも同じトークンを使います。

## スクロールバー [#scrollbars]

ウィンドウはどのページでもスクロールバーの場所を確保します。そのため、ページが短くてスクロールしないときも、ページが伸びたときも、ダイアログ、ポップオーバー、メニューがページのスクロールを止めたときも、コンテンツは動きません。`globals.css` は細いページのスクロールバーとあわせて `html` に `scrollbar-gutter: stable` を設定します。ブラウザーはウィンドウのスクロールバーに `html` の `scrollbar-color` と `scrollbar-width` を使い、`body` の値は使いません。

```css
html {
  scroll-behavior: smooth;
  scroll-padding-top: var(--spacing-header);
  scrollbar-color: color-mix(in oklab, var(--foreground) 20%, transparent) transparent;
  scrollbar-gutter: stable;
  scrollbar-width: thin;
}
html:has([data-page-scroller]) {
  scrollbar-gutter: auto;
}
[data-page-scroller] {
  scrollbar-gutter: stable;
}
```

`/app` と `/admin` はウィンドウいっぱいに広がり、代わりにコンテンツ領域をスクロールします。そのため、レイアウトでも読み込み中のスケルトンでも、その要素に `data-page-scroller` を付けます。確保する場所はその要素に移り、ワークスペースはウィンドウの幅いっぱいに広がります。React Aria の `usePreventScroll` と、ドキュメントの検索を動かす Base UI も、パディングではなく `scrollbar-gutter: stable` でページを止めるため、場所が二重に補われることはありません。ヘッダー、ページの枠、トップへ戻るボタンなどの固定レイヤーは、その場所を除いたウィンドウ内に配置され、コンテンツと揃います。スクロールバーのトラックは透明なので、確保した場所にはページ自身の背景が見えます。

## タイプスケール

生のサイズ指定ではなく、名前付きのテキストユーティリティを使います。`text-display-hero`、`text-display-gate`、`text-display-blast`、`text-headline-peak`、`text-headline-support`、`text-price`、`text-title-lg`、`text-title`、`text-statement`、`text-lead`、`text-body`、`text-body-sm`、`text-spec`、`text-label` です。それぞれサイズ、行の高さ、字間、見出しではウェイトを設定します。`src/lib/cn.config.ts` がこれらを登録しているため、`cn` はクラスを結合するときにこれらを保持します。`bun run generate:cn` はルックアップテーブルを再生成します。

## 角丸 [#corner-radius]

すべての角は 1 つのスケールから角丸を取ります。`:root` の `--radius` が基準で、`globals.css` の `@theme static` がそこから 3 つの段階を導くため、この 1 つの値を変えるとサイト全体の角丸が変わります。要素の種類ごとに段階は 1 つです。

| クラス         | 角丸                                        | 用途                                                                                                                                                                    |
| -------------- | ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `rounded-lg`   | <RepositoryFact name="radiusLgPixels" /> px | 面: カード、パネル、ダイアログ、シート、ポップオーバー、メニュー、トースト、コールアウト、表、コードブロック、動画と画像の枠、コースと料金のカード                      |
| `rounded-md`   | <RepositoryFact name="radiusMdPixels" /> px | コントロール: ボタン、行動喚起、入力欄、セレクト、タブのリスト、トグル、バッジ、チップ、ツールチップ、アイコンのタイル、サイドバーのメニュー行、1 行のコマンド          |
| `rounded-sm`   | <RepositoryFact name="radiusSmPixels" /> px | 余白のある面やコントロールの内側の要素: メニュー、セレクト、コマンドの項目、タブのトリガー、`kbd`、インラインコード、チェックボックス、テキストリンクのフォーカスリング |
| `rounded-full` | 円またはピル形                              | アバター、状態と目印のドット、スイッチ、スライダー、ラジオボタン、プログレスバー、ステップ番号、再生ボタン、円形のアイコンバッジ                                        |
| `rounded-none` | 0                                           | 角丸の親の中で角を立てておく要素。入力グループの中の入力欄など                                                                                                          |

余白のある角丸のコンテナの内側の要素が、コンテナより大きな角丸を持つことはありません。メニューの項目は `rounded-lg` のパネルの中で `rounded-sm` になり、カードの中のボタンは `rounded-md` です。親の角丸をそのまま繰り返す `rounded-[inherit]` が、唯一許される任意の値です。

`globals.css` は `--radius-*: initial` で Tailwind 自身の角丸の段階を取り除くため、`rounded-xs`、`rounded-3xl`、`rounded-4xl`、段階のない `rounded` は CSS を生成しません。`rounded-xl` と `rounded-2xl` は Fumadocs のコンポーネントが使うためだけに定義が残り、`--radius-lg` になるので、ドキュメントの検索ダイアログ、カード、コールアウト、タブ、コードブロックはサイトのほかの部分とそろいます。Fumadocs は自身のコントロールを `rounded-lg` で丸めるため、`_site.docs.tsx` のドキュメントのサイドバーはその行と検索ボタンに `rounded-md`、`kbd` のキーに `rounded-sm` を与え、`docs-search-dialog.tsx` は検索結果に `rounded-sm` を、`globals.css` は Fumadocs の本文のインラインコードに `--radius-sm` を与えます。`typeset.css` の本文スタイルも同じ変数を読みます。インラインコード、`kbd`、ハイライトしたテキストは `--radius-sm`、コードブロック、画像、動画は `--radius-lg` です。メールは React Email の Tailwind を使い、その既定の `rounded-sm`、`rounded-md`、`rounded-lg` は同じ値です。

`scripts/radius-lint-plugin.ts` の lint ルール `radius/no-off-scale` は、`src/` 以下のコードがほかの角丸を使うと `bun run check` を失敗させます。対象は、取り除いた段階、段階のない `rounded` や `rounded-l` のような段階のない辺、`rounded-[4px]` や `rounded-(--cell-radius)` のような任意の値、角かっこ内の `border-radius` プロパティ、`var(--radius)`、`var(--radius-sm)`、`var(--radius-md)`、`var(--radius-lg)` 以外に設定したコンポーネントの角丸の変数、スタイルオブジェクト内の `borderRadius` です。`src/presentation/styles/__test__/radius.test.ts` は `globals.css` のスケールを固定し、スタイルシートのすべての `border-radius` がそれを読むことを確かめます。

## ページタイトルと行動喚起 [#page-titles-and-calls-to-action]

コンテンツページ（ブログの一覧、講座カタログ、ニュースレターのページ、法務ページ、ページが見つからない場合のページ）は `ContentPage`（`src/presentation/components/custom/content-page.tsx`）で始まります。`h1` は `text-headline-peak`、リードは `text-lead` で、どのページでもサイトヘッダーから同じ距離に置かれます。スケルトンでは `ContentPagePending` が同じブロックを描きます。ブログ記事は記事タイトルに、より大きな `text-display-gate` を使います。公開ページの行動喚起は `src/data/cta.ts` の `CTA_CLASSES.PRIMARY` または `CTA_CLASSES.SECONDARY` を使うため、高さ（`h-11`）、余白、文字はすべて同じです。`BackHomeLink` は `/` へ戻る主要な行動喚起で、ラベルは `common.backHome` から取り、ページが見つからない場合のページとニュースレターのページに表示されます。

## ルートごとのスタイルシート

`docs.css` には、ドキュメントとブログ記事用の本文スタイル `typeset` が入っています。これは素の CSS で、`/docs` と `/blog` のレイアウトが `?url` のスタイルシートリンクとして読み込みます。ルートのスタイルシートで Tailwind のビルドを重ねて実行してはいけません。
