Кожна публічна сторінка, один допис блогу й кожна сторінка адмінки та робочого простору клієнта відповідають WCAG 2.2 рівня AA у світлій і темній темах. Це вимога до релізу, а не мета: `e2e/specs/accessibility.spec.ts` сканує їх у кожному pull request і завершується помилкою на будь-якому порушенні.

## Сканування

Специфікація запускає axe-core через `@axe-core/playwright` з правилами A та AA з WCAG 2.0, 2.1 і 2.2 та найкращими практиками axe, використовуючи допоміжні функції з `e2e/fixtures/accessibility.ts`, які також використовує `checkout-funnel.spec.ts`:

```ts
const WCAG_TAGS = ["wcag2a", "wcag2aa", "wcag21a", "wcag21aa", "wcag22aa", "best-practice"]

export const COLOR_SCHEMES = ["light", "dark"] as const
```

Перед скануванням `accessibilityViolations` прокручує всю сторінку, щоб розділи, які з’являються під час прокручування, стали видимими, і чекає завершення скінченних анімацій, щоб контраст вимірювався на сторінці в усталеному стані. Нову сторінку додають до `PUBLIC_PAGES` або `WORKSPACE_PAGES` в `accessibility.spec.ts` у тій самій зміні, що додає маршрут. Запускайте цю специфікацію разом з рештою набору:

```sh
bun run test:e2e:pr
```

## Чого axe не може перевірити

axe перевіряє розмітку, а не зміст чи порядок роботи з клавіатури. Ці правила покривають решту й перевіряються під час рев’ю:

- **Орієнтири й назви.** Кожен робочий простір має підписану навігацію (`<nav aria-label={t("navigationLabel")}>` в `admin-sidebar.tsx`), а бічні панелі, бокова панель екранів автентифікації та зміст документації є орієнтирами (landmarks).
- **Справжня семантика.** Вкладки мають панелі вкладок; набір варіантів, який не перемикає панелі, — це група перемикачів, а не список вкладок. Посилання, що виглядає як кнопка, — це `LinkButton`, а не посилання, обгорнуте навколо кнопки.
- **Мітки на кожному елементі керування.** Поля введення мають `FieldLabel`; візуально прихована мітка використовує `className="sr-only"`, як поле розсилки. Кнопки лише з іконкою мають `aria-label`, що називає їхню ціль, як-от `t("actions.delete", { title })`, а видимий текст елемента керування входить до його доступної назви.
- **Помилки оголошуються разом із полем.** Кожне поле введення встановлює `aria-describedby` на ідентифікатор своєї помилки та `aria-invalid`, поки воно некоректне; елемент помилки існує лише тоді, коли є помилка. Див. [Форми та таблиці](/docs/conventions/forms-and-tables).
- **Декоративний вміст приховано.** Іконки поруч із текстом отримують `aria-hidden`, як і суто візуальні крапки, роздільники та зациклені відео без підпису.
- **Заголовки по порядку.** Кожна сторінка має один `h1`; заголовок картки, що починає розділ, рендерить `h2` всередині `CardTitle`, як це робить `course-form.tsx`.
- **Насамперед клавіатура.** Усе, до чого можна дістатися мишею, доступне з клавіатури, зокрема дії, що з’являються під час наведення: вони з’являються й під час фокусу. Кільця фокусу використовують `data-focus-visible:` на компонентах React Aria; див. [Компоненти та стилізація](/docs/conventions/components).
- **Стани зайнятості.** Скелетони встановлюють `aria-busy="true"` на своєму кореневому елементі, а кнопки в стані очікування використовують стан `isPending` компонента `Button` із shadcn.
- **Стовпці мають назви.** Стовпець дій таблиці використовує `DataTableActionsHeader` — заголовок лише для екранних зчитувачів.
- **Мову оголошено.** `<html lang>` відповідає локалі маршруту, а поле для тексту іншою мовою встановлює `lang={locale}`, як локалізовані поля курсу.

## Контраст і рух

- Текст використовує колірні токени теми. `text-muted-foreground` забезпечує 4,5:1 в обох темах; світліші варіанти, як-от `text-muted-foreground/60`, призначені лише для неактивних чипів, декоративних іконок і роздільників.
- Анімація враховує налаштування читача: `MotionConfig reducedMotion="user"` у `MotionProvider`, варіанти `motion-reduce:` для переходів, `scroll-behavior: auto` при `prefers-reduced-motion`, а відео лендингу не відтворюються автоматично для читачів, які просять зменшити рух (`concept-loop.tsx`).
