Vite+ uruchamia Vitest z konfiguracją z `vite.config.ts`. Testy znajdują się w folderze `__test__` obok kodu, który testują, i importują swoje API z `vite-plus/test`.

| Projekt       | Pliki                                                            | Środowisko                   |
| ------------- | ---------------------------------------------------------------- | ---------------------------- |
| `node`        | `*.test.ts` i `*.test.tsx` z wyjątkiem dwóch poniższych rodzajów | Node                         |
| `integration` | `*.integration.test.ts`                                          | Node, limity czasu 20 sekund |
| `component`   | `*.component.test.tsx`                                           | jsdom                        |

```sh
bun run test
bun run test:unit
bun run test:integration
bun run test:component
bun run test:watch
bun run test:changed
bun run test:coverage
```

Używaj `bun run test`, a nie `bun test`: wbudowany runner testów Buna ignoruje projekty, środowiska i plik konfiguracyjny Vitest.

## Platforma testowa

`src/platform/testing/` zawiera wspólną infrastrukturę testową; wszystko inne znajduje się obok swojego właściciela.

- `setup.ts` rejestruje matchery jest-dom i wspólne hooki.
- `mocks/cloudflare.ts` zastępuje `cloudflare:workers`: D1 to baza `node:sqlite` w pamięci, która stosuje każdą migrację z repozytorium, a KV to mapa w pamięci.
- `lib/server-function.ts` wywołuje funkcje serwerowe przez prawdziwy potok middleware i walidacji TanStack.
- `lib/render.tsx` renderuje komponenty z prawdziwym QueryClient i routerem.
- `mocks/providers.ts` przechwytuje żądania do Resend i Polar. Instaluje go tylko testowy Worker Playwright (`worker.ts`).

Zewnętrzne wywołania związane z e-mailami, OAuth i płatnościami nigdy nie opuszczają procesu testowego.

## Pokrycie

`bun run test:coverage` wymusza 100% pokrycia linii, instrukcji, funkcji i gałęzi dla `src/**/*.{ts,tsx}`. Wykluczone są testy, foldery `__test__`, pliki deklaracji, `src/routeTree.gen.ts`, prymitywy shadcn i `src/platform/testing/`. Raporty trafiają do `coverage/` w formie tekstowej, HTML i `coverage-summary.json`. Testuj rzeczywiste zachowanie i usuwaj gałęzie, które nigdy nie mogą się wykonać, zamiast podmieniać obiekty globalne, żeby do nich dotrzeć. CI sprawdza wymóg pokrycia przy każdym pull requeście.
