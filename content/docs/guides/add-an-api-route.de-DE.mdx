---
title: "API-Route hinzufügen"
description: "Einen HTTP-Handler unter /api für Webhooks und andere externe Aufrufer hinzufügen."
---

API-Routen sind Server-Handler von TanStack Start in `src/routes/api/`. Die eigenen Bildschirme der Anwendung benötigen nie eine, denn sie rufen Server-Funktionen auf. Eine API-Route nur für Aufrufer außerhalb der App hinzufügen, etwa Webhooks, Clients von Drittanbietern oder Crawler.

## Bestehende Routen

| Datei                      | Pfad          | Zweck                                                                                                    |
| -------------------------- | ------------- | -------------------------------------------------------------------------------------------------------- |
| `src/routes/api/auth.$.ts` | `/api/auth/*` | Better Auth: Anmeldung, OAuth-Callbacks, E-Mail-Verifizierung, Polar-Checkout, Kundenportal und Webhooks |
| `src/routes/api/search.ts` | `/api/search` | Fumadocs-Suche für die Dokumentation                                                                     |
| `src/routes/api/index.ts`  | `/api`        | Laufzeitprüfung, die `{ "runtime": "cloudflare-workers" }` zurückgibt                                    |

Polar-Webhooks kommen unter `/api/auth/polar/webhooks` an; das Polar-Plugin von Better Auth prüft ihre Signatur mit `POLAR_WEBHOOK_SECRET`, bevor `license.webhooks.ts` sie verarbeitet.

## Handler schreiben

Die Methoden in `server.handlers` deklarieren. Jeder Handler erhält den Web-`Request` und gibt eine Web-`Response` zurück:

```ts
import { createFileRoute } from "@tanstack/react-router"

import { search } from "~/src/integrations/fumadocs/fumadocs.search"

export const Route = createFileRoute("/api/search")({
  server: {
    handlers: {
      GET: ({ request }) => search.GET(request),
    },
  },
})
```

Innerhalb eines Handlers:

- Query-Parameter oder Body mit einem Zod-Schema validieren und bei einem Fehlschlag `HTTP_STATUS.BAD_REQUEST` (aus `src/modules/_core/constants/api.ts`) zurückgeben. Dort einen Status ergänzen, wenn der Handler einen neuen benötigt.
- Die Session mit `getRequestSession(request)` lesen und mit `hasPermission` prüfen. Funktions-Middleware wie `authorized` gilt für Server-Funktionen, nicht für Handler.
- Öffentliche Endpunkte mit `withinRateLimit({ key, limit, windowSeconds })` und `clientAddress(request.headers)` aus `src/lib/rate-limit.ts` begrenzen.
- Signaturen prüfen, bevor einem Webhook-Payload vertraut wird.
- Sichere Fehler-Bodys zurückgeben; Details mit `console.error` protokollieren.

## Routing-Regeln

- `/api`-Pfade erhalten nie ein Locale-Präfix, und der Worker überspringt für sie die Suche nach statischen Assets und die Locale-Weiterleitungen.
- `/api`-URLs enthalten keine Locale, daher liefert `getCurrentLocale()` dort die Standard-Locale. Eine lokalisierte Antwort entnimmt die Locale dem Request, so wie `/api/search` über seinen Query-Parameter `locale`.
- `/api` ist vom Prerendering ausgeschlossen.

## Testen

Den Handler über die Route-Optionen aufrufen, wie es `src/routes/api/__test__/handlers.test.ts` mit `Route.options.server.handlers` tut, und den Provider mocken, an den er weiterleitet.
