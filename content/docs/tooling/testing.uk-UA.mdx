Vite+ запускає Vitest з конфігурацією з `vite.config.ts`. Тести розміщено в папці `__test__` поруч із кодом, який вони покривають, і вони імпортують свій API з `vite-plus/test`.

| Проєкт        | Файли                                                       | Середовище                |
| ------------- | ----------------------------------------------------------- | ------------------------- |
| `node`        | `*.test.ts` і `*.test.tsx`, крім двох наведених нижче видів | Node                      |
| `integration` | `*.integration.test.ts`                                     | Node, тайм-аути 20 секунд |
| `component`   | `*.component.test.tsx`                                      | jsdom                     |

```sh
bun run test
bun run test:unit
bun run test:integration
bun run test:component
bun run test:watch
bun run test:changed
bun run test:coverage
```

Використовуйте `bun run test`, а не `bun test`: власний тестовий раннер Bun ігнорує проєкти, середовища та файл налаштування Vitest.

## Тестова платформа

`src/platform/testing/` містить спільну обв'язку; усе інше розміщено поруч зі своїм власником.

- `setup.ts` реєструє матчери jest-dom і спільні хуки.
- `mocks/cloudflare.ts` замінює `cloudflare:workers`: D1 — це база даних `node:sqlite` у пам'яті, до якої застосовано кожну закомічену міграцію, KV — це мапа в пам'яті, а бакет R2 `MEDIA` — сховище в пам'яті з підтримкою діапазонів і посторінкового переліку.
- `mocks/cache.ts` експортує `createEdgeCache`, який підміняє кеш Workers для тестів доставки медіафайлів.
- `lib/server-function.ts` викликає серверні функції через справжній конвеєр middleware і валідації TanStack. Це стосується проєктів `node` та `integration`. У проєкті `component` серверна функція завершується помилкою, бо jsdom є браузером.
- `lib/render.tsx` рендерить компоненти зі справжніми QueryClient і роутером.
- `mocks/resend.ts` і `mocks/polar.ts` — це строгі дублери API Resend і Polar, а `mocks/providers.ts` спрямовує до них `fetch`. `setup.ts` встановлює їх для кожного тесту й провалює тест, який надіслав запит, що його відхилив би провайдер; тестовий Worker для Playwright (`worker.ts`) теж їх встановлює.
- `lib/polar.ts` створює моделі Polar і підписує вебхуки для інтеграційних наборів і браузерного набору.

Зовнішні виклики для листів, OAuth і платежів ніколи не виходять за межі тестового процесу.

## Покриття

`bun run test:coverage` вимагає 100% покриття рядків, інструкцій, функцій і гілок для `src/**/*.{ts,tsx}`. Тести, папки `__test__`, файли оголошень, `src/routeTree.gen.ts`, примітиви shadcn і `src/platform/testing/` виключено. Звіти записуються в `coverage/` у форматах тексту, HTML і `coverage-summary.json`. Покривайте реальну поведінку й видаляйте гілки, які ніколи не можуть виконатися, замість того щоб підміняти глобальні об'єкти, аби до них дістатися. CI запускає перевірку покриття для кожного pull request.
