SaaSy Land のライセンスは、コマンドライン `saasyland` のライセンスです。このページでは npm の <RepositoryFact name="cliReleaseChannel" /> タグのリリース <RepositoryFact name="cliPackageSpec" /> を説明します。各リリースの変更点は[リリースノート](/docs/cli/releases)にあります。

## 現在使える機能

- <RepositoryFact name="cliInit" /> はプロジェクトを作成します。Cloudflare Worker 上の React と TanStack Start で、Drizzle 経由の Cloudflare
  D1 を使い、Better Auth のサインイン付きかサインインなしです。書き出す内容は[プロジェクトを作成する](#create-a-project)で説明します。
- `activate`、`whoami`、`deactivate` で端末上のライセンスキーを管理します。
- `--help` と `--version` はすべて動作し、どのコマンドも `--json` と `--locale` を受け付けます。
- `change`、`update`、`status` はまだ利用できません。フラグを検証したうえでコード <RepositoryFact name="cliExitNotAvailable" /> で終了します。ランディングページの[構成ツール](/#cli)では、`init` が現在書き出すものだけを選択でき、それ以外のオプションは無効として表示されます。`init` はそれらのオプションを同じコードで拒否します。その後に続く内容は[ロードマップ](/docs/project/roadmap)にあります。

## 実行する

パッケージマネージャーで <RepositoryFact name="cliReleaseChannel" /> タグから CLI を実行します。グローバルにインストールする必要はありません。

<RepositoryTable columns={["パッケージマネージャー", "コマンド"]} name="cliRunners" />

タグを付けないと、パッケージマネージャーは npm の `latest` タグを実行します。そこにはまだ名前を確保するためのプレースホルダーのリリースがあり、どのコマンドも動きません。CLI には Node.js <RepositoryFact name="cliNodeEngine" /> または Bun が必要です。

## キーを有効化する

1. サインインし、[ライセンスページ](/app/license)からキーをコピーします。
2. <RepositoryFact name="cliActivate" /> を実行します。ターミナルでは CLI がキーの入力を求め、入力中は表示しません。
3. 入力する代わりに、キーを引数として渡すこともできます（シェルの履歴に残ります）。<RepositoryFact name="cliLicenseKeyVariable" /> を設定すれば履歴には残りません。キーを指定しない場合、`activate` はこの端末ですでに有効化されているキーを使います。

`--label` はライセンスページ上の端末の名前を付けます。既定ではホスト名です。同じ端末を再度有効化しても、その端末がすでに使っている枠はそのままです。

## プロジェクトを作成する [#create-a-project]

[構成ツール](/#cli)が回答から組み立てるフラグを付けて、または下の既定値を使う `--yes` を付けて、<RepositoryFact name="cliInitCommand" /> を実行します。

`init` は指定したディレクトリにプロジェクトを書き出します。そのディレクトリはまだ存在しないか、空でなければなりません。ディレクトリを指定しない場合は現在のディレクトリに書き出します。`--cwd` を付けると、別のディレクトリで起動したかのように実行します。回答はフラグで指定します。`--yes` は、どのフラグも指定していない回答すべてに既定値を使います。今後のリリースで質問が提供されるまでは、ターミナルのセッションも同じです。CI、コーディングエージェント、ターミナルのない環境では、`--yes` なしの `init` は足りないフラグを示し、すべての回答を含むコピー用のコマンドを出力します。

既定値は、リリースにテンプレートがある範囲で、このサイト自身のスタックです。React と TanStack Start、Cloudflare Worker 上のシングルテナントのモノリス、Drizzle 経由の Cloudflare D1 上の SQLite、Better Auth、Resend、Fumadocs のドキュメント、MDX のブログで、課金はありません（`--no-billing`）。`--no-auth` は、同じプロジェクトをサインインなしで書き出します。それ以外の回答は、`--billing polar` も含め、ライセンスが確認される前にコード <RepositoryFact name="cliExitNotAvailable" /> で終了し、このリリースでは利用できないことを伝え、利用できる回答を示します。

実行するたびに、ライセンスをオンラインで確認し、そのリリース自身のテンプレートを saasyland.com からダウンロードします。オフラインモードはありません。この端末で有効化されているライセンスを使います。ライセンスがない場合や、<RepositoryFact name="cliLicenseKeyVariable" /> に別のキーが設定されている場合は、まずその変数のキーを有効化するか、ターミナルではキーの入力を求めて有効化します。テンプレートを使う前に、そのサイズと SHA-256 を、saasyland.com が送ってきた値と、このリリースの CLI が固定したダイジェストに照らして確認し、少しでも違えば拒否します。プロジェクトはまず対象の隣にある一時ディレクトリに書き出してから所定の場所に移動するので、Ctrl+C や書き込みの失敗があっても何も残りません。`--dry-run` はテンプレートをダウンロードして確認し、`init` が書き出すすべてのファイルを一覧表示しますが、何も書き出しません。

プロジェクト内の `saasyland.json` には、リリース、回答、`init` が書き出したすべてのファイルの SHA-256 が記録され、ライセンスキーが含まれることはありません。そこに記録された回答で `init` を再度実行すると、自分のプロジェクトと比較するためのクリーンなプロジェクトが得られます。

プロジェクトの README が最初のインストールを案内します。`bun install` がロックファイルを書き出し、最初のコミットの前に 3 つのスクリプトが Worker の型、ルートツリー、データベースのマイグレーションを生成します。プロジェクトの `/docs` にあるドキュメントサイトは、そのインストールから最初のデプロイまでを説明します。

プロジェクトは、このサイトと同じように、そのスタックに必要な依存関係のパッチを持ちます。TanStack Router のパッチと `framer-motion` のパッチで、どれも `patches/` と `patchedDependencies` にあり、パッケージはパッチ対象のバージョンに固定され、`bun install` が当てます。それぞれが何を直し、このサイトのものとどう違い、いつ外れるかは[依存関係](/docs/conventions/dependencies#when-the-bug-is-upstream)にあります。

## 端末

有効化した端末はそれぞれライセンスの有効化枠を 1 つ使います。Core は <ActivationLimit tier="core" />、Complete は <ActivationLimit tier="complete" />、Agency は <ActivationLimit tier="agency" /> です。

- <RepositoryFact name="cliWhoami" /> は、プラン、使用中の枠、この端末の名前を表示します。
- <RepositoryFact name="cliDeactivate" /> は、この端末の枠を解放し、端末からライセンスを削除します。
- 使わなくなった端末の枠を解放するには、[ライセンスページ](/app/license)の **端末** からその端末を削除します。その端末で次に `whoami` か `deactivate` を実行したときに反映されます。

すべての枠が使用中の場合、`activate` は枠を使っている端末を一覧表示し、枠を解放できるようライセンスページへ案内します。

## CI

キーをシークレットとして <RepositoryFact name="cliLicenseKeyVariable" /> に保存します。<RepositoryFact name="cliCiProviders" /> では、1 つのリポジトリのすべての実行が同じ端末 ID を導き出すため、何回実行してもそのリポジトリが使う枠は 1 つで、プロバイダー名とリポジトリ名がラベルになります。それ以外の CI システムや端末 ID のないコンテナでは、<RepositoryFact name="cliCiRepositoryVariable" /> にリポジトリ名を設定してください。

## ライセンスの保存場所

CLI はライセンスを <RepositoryFact name="cliCredentialsFile" /> に保存します。このファイルはあなたのユーザーだけが読め（モード <RepositoryFact name="cliCredentialsFileMode" />）、設定ディレクトリに置かれます。

<RepositoryTable columns={["システム", "ディレクトリ"]} name="cliCredentialDirectories" />

`XDG_CONFIG_HOME` が設定されていない場合、Linux では <RepositoryFact name="cliCredentialsLinuxFallback" /> を使います。CLI が saasyland.com に送るのは、この端末の ID から鍵付きで計算したハッシュだけで、ID そのものは送りません。saasyland.com がライセンスの返金または取り消しを伝えると、CLI は端末からライセンスを削除し、ライセンスページとサポートを案内します。

## 環境変数

| 変数                                              | 設定する内容                                                                                    |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| <RepositoryFact name="cliLicenseKeyVariable" />   | ライセンスキー。CI や、キーの入力を求められないセッションで使います                             |
| <RepositoryFact name="cliCiRepositoryVariable" /> | CLI が認識しない CI システムでのリポジトリ名                                                    |
| <RepositoryFact name="cliLocaleVariable" />       | 出力の言語。`--locale` が最優先で、次にこの変数、その次にシステムの言語です                     |
| <RepositoryFact name="cliApiUrlVariable" />       | プレビューなど、saasyland.com の別のデプロイ。`https` の URL か、自分のマシン上の `http` の URL |

## スクリプトとコーディングエージェント

`--json` は結果またはエラーを 1 つの JSON ドキュメントとして出力します。CI、コーディングエージェント、ターミナルのない環境では、CLI は入力を待ちません。キーなしの `activate` と、必要な回答がない `init` は、終了コード <RepositoryFact name="cliExitUsage" /> で停止し、その渡し方を表示します。

| 終了コード                                        | 状況                                                                                                                                                                          |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <RepositoryFact name="cliExitSuccess" />          | コマンドが説明どおりに完了した                                                                                                                                                |
| <RepositoryFact name="cliExitFailure" />          | CLI の内部で問題が起きた                                                                                                                                                      |
| <RepositoryFact name="cliExitUsage" />            | フラグまたは <RepositoryFact name="cliApiUrlVariable" /> が無効、入力を求められないセッションでキーまたは回答がない、またはプロジェクトのディレクトリが空でないか書き込めない |
| <RepositoryFact name="cliExitNotAvailable" />     | コマンドまたは回答のいずれかがこのリリースでは提供されていない、この端末の ID を読み取れない、またはシステムが Linux、macOS、Windows 以外                                     |
| <RepositoryFact name="cliExitTemporaryFailure" /> | saasyland.com に接続できない、後で再試行するよう求められた、またはテンプレートをダウンロードできなかった                                                                      |
| <RepositoryFact name="cliExitProtocol" />         | saasyland.com とこのバージョンの CLI が互いを理解できない、またはテンプレートがダイジェストと一致しない。CLI を更新してください                                               |
| <RepositoryFact name="cliExitNoPermission" />     | この端末でライセンスが有効化されていない、この端末の枠が解放された、キーが無効・取り消し済み・返金済み、またはすべての枠が使用中                                              |
| <RepositoryFact name="cliExitCancelled" />        | Ctrl+C で質問をキャンセルした、または `init` を停止した。何も書き出されていない                                                                                               |
