SaaSy Land は <RepositoryFact name="languages" /> 個のロケール（<RepositoryFact name="supportedLocales" />）で提供され、それらは `src/integrations/use-intl/i18n.config.ts` の `I18N.SUPPORTED_LOCALES` に一度だけ列挙されています。英語が信頼できる唯一の情報源です。テキストを追加または編集する変更は、同じコミットですべてのロケールに対して追加または編集を行います。そうなっていない場合は `bun run check:i18n` が失敗します。

## 名前空間

メッセージは `messages/<locale>/<namespace>.json` に置きます。名前空間ごとに 1 ファイルで、ファイル名がそのまま名前空間になります。

| 名前空間                                                      | 内容                                                                            | 読み込み                                          |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------- |
| `common`、`errors`、`errors.global`                           | `errors.codes.<CODE>` を含め、どの画面でも必要になりうるテキスト                | すべてのルートで                                  |
| `components.custom.<file>`、`components.shadcn.<file>`        | `components.custom.newsletter-form` のような、1 つの共有コンポーネントの文言    | すべてのルートで                                  |
| `pages.<area>`、`pages.<area>.<page>`                         | `metadata.title` と `metadata.description` を持つ、1 つのレイアウトまたはページ | ルートが `NAMESPACE` または `NAMESPACES` を通して |
| `<table>.validations`                                         | `course.validations` のような、1 つのモジュールの Zod メッセージ                | それを使うフォームを持つレイアウトが              |
| `auth.errors`、`auth.validations`、その他の `auth.*` ファイル | Better Auth のエラー、バリデーション、認証画面                                  | それを必要とするレイアウトが                      |
| `emails.<template>`                                           | 1 つのメールテンプレート                                                        | サーバー上で、それを送信するユースケースが        |
| `countries`、`currencies`、`locales`、`timezones`             | カタログ                                                                        | それを必要とするレイアウトが                      |

root 名前空間は、`src/integrations/use-intl/i18n.messages.ts` でファイル名（`common.json`、`components.*.json`、`errors*.json`）によって検出されます。共有コンポーネントの文言はページの名前空間の中ではなく、専用の `components.custom.<file>` 名前空間に置きます。そうすれば、どこに表示されても同じテキストが描画されます。ルートが宣言するすべての名前空間は、すべてのロケールにファイルとして存在しなければなりません。存在しない名前空間に対しては `loadNamespace` がエラーをスローします。

## 1 コンポーネントに 1 つの翻訳関数

コンポーネントは自分の名前空間を指定して `useTranslations` を 1 回だけ呼び出し、その結果を `t` と名付けます。

```tsx
const t = useTranslations("pages.admin.courses.form")
```

`scripts/check-i18n.ts` は、`src` の `.tsx` ファイルにあるすべての静的な `t("key")` を、その上にある `useTranslations` 呼び出しの名前空間に照らして解決し、英語に存在しないキーがあれば失敗します。また、どのソースファイルもレンダリングしない英語のキーがあっても失敗するため、削除した文言がメッセージファイルに残り続けることはありません。キーがレンダリングされているとみなされるのは、`t()` 呼び出しがそのキーを指定している場合、`kinds.${kind}` のようにテンプレートから組み立てたキーが一致する場合、または変数を受け取る `t()` 呼び出しの下にあるキーについては、そのパスが `src` 内に文字列として現れる場合です。`countries`、`currencies`、`locales`、`timezones` のカタログは対象外で、代わりに `catalogues.test.ts` がそれらのキーが定数と一致することを確認します。値がユーザーに表示される定数は、`enum-labels.test.ts` がすべてのロケールでそのラベルを確認します。このテストには、そうした定数がそれぞれ、ラベルとなるメッセージとともに列挙されています。同じコンポーネントで `useTranslations` を 2 回呼び出すと、それ以降のすべての `t()` のスコープが気づかないうちに変わってしまいます。呼び出しが 1 回だけなのはそのためです。2 つの名前空間のキーが必要なコンポーネントは、名前空間を指定せずに `useTranslations()` を呼び出し、`sign-in-form.tsx` の `t("errors.codes.INTERNAL_ERROR")` のように完全なキーを使います。

## メッセージ

- キーはキャメルケースの名前を持つ入れ子の JSON オブジェクトで、画面の構成に合わせてグループ化します（`table.headers.course`、`delete.confirm`）。
- 複数形、数値、日付には、コード内での文字列連結ではなく、メッセージ内の ICU 構文を使います（`"{e2eSpecs, plural, one {# Playwright suite} other {# Playwright suites}}"`）。
- `scripts/check-message-formats.ts` は、すべてのロケールで同じ ICU 引数とタグを要求し、ほかのロケールに残った英語のテキストを拒否します。
- 数値、日付、通貨は、use-intl の `useFormatter` を使って読者のロケールに合わせてフォーマットし、手作業でフォーマットしてはいけません。日付には `I18N.FORMATS` の名前付きフォーマット（`date`、`dateTime`、`calendarDate`）を使うため、タイムゾーンとその表記が一貫します。`useCurrencyFormatter` は、指定した通貨で金額をフォーマットします。
- モジュールのスキーマにある Zod のメッセージは、そのモジュールの `<table>.validations` 名前空間のキー（`"slugInvalid"`）で、メッセージに含まれる数値は `<MODULE>_VALIDATION_PARAMS` から取ります。[フォームとテーブル](/docs/conventions/forms-and-tables)を参照してください。
- データベースに保存し、訪問者が複数の言語で読むテキストは `LocalizedText` カラムにします。英語は必須で、翻訳がない場合に `localize(text, locale)` が返すフォールバックになります。

## 数値は手入力せず計測する

テストファイル、Playwright のスイート、UI コンポーネント、国、通貨など、リポジトリ内の何かの数を文言に手入力することはありません。`scripts/repository-facts.ts` がビルド時にそれらを計測して `virtual:repository-facts` モジュールとして提供し、`src/data/repository-facts.ts` がそれらを `REPOSITORY_FACTS` としてエクスポートします。カタログの件数は、それを翻訳するメッセージファイルからではなく、必ずその定数（`COUNTRIES`、`CURRENCY_CODES`、`TIMEZONES`、`ADMIN_NAVIGATION`）から取得します。ランディングページの文言は、メッセージに `"{testFiles, number} test files"` を含めた `t("body", REPOSITORY_FACTS)` のようにそれらを埋め込み、MDX では `<RepositoryFact name="testFiles" />` で数値を 1 つ描画します。新しい数値に言及する場合は、まずそのプラグインで計測してください。アフィリエイトの報酬率のように、計測するのではなくビジネスとして決める数値は、`src/data` で一度だけ宣言し（`src/data/affiliates.ts` の `AFFILIATE_TERMS`）、同じ方法で埋め込みます。価格も同じルールに従います。`src/data/marketing.ts` の `TIER_PRICES` と `CONSULTING_HOURLY_RATE` は、メッセージには `{price}`、MDX には `<TierPrice tier="core" />` として渡り、連絡先のアドレスは `CONTACT_EMAIL` から `{email}` としてメッセージに渡ります。コンポーネントは `REPOSITORY_FACTS` を直接読みます。品質セクションのテスト実行の表示は、`REPOSITORY_FACTS.testFiles` を使って `Test Files` を出力します。これは Vitest の `include` パターンに一致するファイルの数です。個々のテストの件数のように、スイートを実行しなければ得られない数値は表示しません。

ドキュメントのページでも、コードが定義する値は手入力しません。`src/presentation/components/custom/repository-fact.tsx` の `<RepositoryFact name="…" />` は、計測した数、`repositoryFacts` が `vite.config.ts`、`playwright.config.ts`、`.nvmrc`、`package.json`、またはワークフローから読み取る設定、あるいは `RATE_LIMITS` や `PLAYBACK_TTL_SECONDS` のようにコードからインポートした定数を表示します。数値はページのロケールに合わせて書式設定され、値に単位がある場合は `unit="second"`、`"minute"`、`"hour"`、`"percent"` を指定します。テキストはコードとして、リストはコードのリストとして表示されます。`<RepositoryTable name="…" columns={["…", "…"]} />` は、権限のステートメント、コミットのタイプ、地域別価格の倍率など、コードから組み立てた表を、ページで翻訳した列名を付けて表示します。ルーターのキャッシュ時間と受信者ごとのメールの上限は、ドキュメントからインポートできないモジュール（`src/router.tsx` と、サーバー専用の `src/lib/rate-limit.ts`）にあるため、コンポーネントはそれらの値のコピーを持ち、そのテストがコピーをルーターとリミッターの値と比較します。コードブロックやフロントマターに残す必要がある値は、代わりに `scripts/check-content.ts` がチェックします。

## ドキュメントとブログ

`content/docs` 配下のすべてのページと `content/blog` 配下のすべての記事は、すべてのロケールに `<slug>.<locale>.mdx` として存在し、各フォルダーのナビゲーションは `meta.<locale>.json` として存在します。`bun run check:i18n` が実行する `scripts/check-content.ts` は、次の場合に失敗します。

- ロケールのファイルが欠けている。
- コードブロックが英語のものと異なる（コードブロックはバイト単位でそのままコピーします）。
- `meta.<locale>.json` が英語と異なるスラッグを列挙している。
- タイトル、説明、段落が英語のまま残っている。
- 機械翻訳のマーカーがテキストに残っている。
- リポジトリのパスをタイトルに付けたコードブロック（`title="src/integrations/better-auth/auth.access.ts"` など）が、そのファイルの抜粋になっていない。
- ドキュメントのページが、どのビルドモードでも `appHostsForMode` が許可しないローカルホストや `APP_DOMAIN` のサブドメインに言及している。
- ルートのリファレンス、スクリプトのページ、環境変数の表が、`ROUTES` の定数、`package.json` のスクリプト、`wrangler.jsonc` のシークレットのいずれかを載せていない、または誤った値で載せている。

翻訳は、そのロケールが `messages/<locale>/` ですでに使っている用語を使い、ネイティブスピーカーが書くように書いてください（たとえばポーランド語では、ティアを Komplet と Agencja と呼びます）。コードの識別子、ファイルパス、コマンド、製品名はそのままにし、リンクはロケールプレフィックスなしの `/docs/...` のパスのままにします。プレフィックスはサイトが描画時に付けます。
