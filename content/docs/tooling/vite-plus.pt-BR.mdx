O Vite+ (`vite-plus`, comando `vp`) reúne Vite, Vitest, oxlint e oxfmt em uma única CLI, e `vite.config.ts` configura todos eles. O `package.json` substitui `vite` por `@voidzero-dev/vite-plus-core` e fixa `vitest` na versão 5.1.0. `vite-plus` também está fixado em uma versão exata; atualize os três juntos com `vp migrate`, e não com `bun update`. Os scripts do pacote chamam `vp`; fora deles, use a CLI global do Vite+ ou `bunx vp`.

| Comando           | Usado por                                         |
| ----------------- | ------------------------------------------------- |
| `vp dev`          | `dev`                                             |
| `vp build --mode` | `build:preview`, `build:production`, `build:test` |
| `vp preview`      | `start`, `start:test`                             |
| `vp test`         | `test` e os scripts `test:*` do Vitest            |
| `vp lint`         | `lint`                                            |
| `vp fmt`          | `format`, `format:check`                          |
| `vp check`        | `check`, `check:fix`                              |
| `vp staged`       | `check:pre-commit`                                |
| `vp config`       | `prepare`, que instala os hooks do Git            |

## Configuração

`vite.config.ts` carrega seus plugins sob demanda. No Vitest, apenas `repositoryFacts()` e `@vitejs/plugin-react` são carregados; nos demais casos, a stack é:

- `@cloudflare/vite-plugin`: executa o Worker no ambiente de SSR, persiste o estado local (em `.wrangler/test` no modo `test`) e usa bindings remotos em `development`.
- `fumadocs-mdx`: compila as coleções da documentação e do blog.
- `repositoryFacts` (`scripts/repository-facts.ts`): serve o módulo `virtual:repository-facts`: as contagens, as versões e as configurações de ferramentas que a landing page e a documentação mostram, lidas do repositório durante o build; veja [Traduções e conteúdo](/docs/conventions/translations).
- `@tailwindcss/vite`: Tailwind CSS 4.
- `tanstackStart`: roteamento, code splitting e pré-renderização das páginas públicas.
- `@vitejs/plugin-react`.
- `deployedWorker` (`scripts/deployed-worker.ts`): depois da pré-renderização, recompila o Worker sem o MDX renderizado e sem as traduções da landing e das páginas legais; veja [Cloudflare Workers](/docs/integrations/cloudflare-workers).

O servidor de desenvolvimento escuta em `localhost:3000` e falha se a porta estiver ocupada. `resolve.tsconfigPaths` fornece o alias de import `~/`. O mesmo arquivo contém as seções `fmt`, `lint`, `staged` e `test`; veja [Lint e formatação](/docs/tooling/lint-format) e [Testes](/docs/tooling/testing).

`build.rolldownOptions.external` lista as dependências peer opcionais de `@polar-sh/sdk` (OpenTelemetry e `ioredis`). Elas não estão instaladas, e o módulo que as importa é removido do Worker por tree-shaking.

## Hooks do Git

`bun install` executa `prepare`, que chama `vp config --no-agent` para instalar o dispatcher de hooks de `.vite-hooks/`. `pre-commit` executa `bun run check:pre-commit`, e `prepare-commit-msg` executa `scripts/commit-msg.ts` (veja [Conventional commits](/docs/tooling/conventional-commits)). `vp hooks status` mostra se os hooks estão ativos em um clone.

Prefira os scripts do pacote; chame `vp` diretamente para execuções pontuais, como formatar ou aplicar o lint em caminhos específicos.
