L'application est une app TanStack Start. `src/router.tsx` crée le routeur avec un QueryClient par requête, l'intégration SSR des requêtes, des composants par défaut pour les erreurs et les pages introuvables, le préchargement à l'intention, un délai d'obsolescence des préchargements égal à son délai d'obsolescence et le `rewrite` de langue. Il n'y a pas de composant d'attente par défaut : chaque route définit son propre squelette (voir [Squelettes de chargement](/docs/architecture/delivery-layer#squelettes-de-chargement)). `src/routes.ts` exporte `ROUTES`, les constantes de chemin utilisées par les liens, les gardes et les balises d'en-tête.

Le dépôt embarque des patchs Bun pour `@tanstack/router-core` 1.171.39 et `@tanstack/react-router` 1.170.46 et fige `@tanstack/router-core`, `@tanstack/react-router` et `@tanstack/react-start` pour que les versions patchées restent installées. Le premier rendu du routeur après l'hydratation réinitialisait la position de défilement de la fenêtre, que le navigateur et le script de restauration en ligne du routeur avaient déjà fixée, si bien qu'un visiteur qui faisait défiler la page pendant son hydratation revenait en haut ; avec le patch, l'hydratation ne touche pas à la position de défilement. `lazyRouteComponent` recharge la page lorsqu'un chunk de route ne se charge pas, pour récupérer un nouveau déploiement, et Safari et Firefox font échouer de la même façon les chunks d'une page que le visiteur quitte, si bien que le rechargement remplaçait la navigation du visiteur par la page qu'il quittait ; avec le patch, un chunk qui échoue après `beforeunload` attend à la place et se recharge si le visiteur reste. Le chunk du loader d'une route n'a pas ce rechargement ; après un déploiement, c'est le composant d'erreur par défaut du routeur qui recharge la page (voir [Routes et livraison](/docs/architecture/delivery-layer#after-a-deploy)). Voir [Dépendances](/docs/conventions/dependencies).

## Routes

`src/routes/` contient des routes de fichiers à plat : `admin.users.all.tsx` sert `/admin/users/all`, `_site.tsx` est un layout sans chemin et `_site.docs.$.tsx` est une route splat. L'identifiant dans `createFileRoute("…")` est une chaîne littérale maintenue par le générateur du routeur dans `src/routeTree.gen.ts` ; les dossiers `__test__` sont ignorés en tant que routes.

Un fichier de route ne fait que composer sa page. Il définit le composant `<Name>Page` ou `<Name>Layout`, `NAMESPACE` ou `NAMESPACES`, un loader qui exécute le chargement des métadonnées, des messages et des données dans un seul `Promise.all`, `head: pageHead(ROUTES.X)` et, pour les zones protégées, une garde dans `beforeLoad`. Les widgets, boîtes de dialogue, formulaires et colonnes de tableau se trouvent dans `src/presentation/components/custom/` et lisent leurs propres traductions et données. Voir [use-intl](/docs/integrations/use-intl) pour le loader et [Better Auth](/docs/integrations/better-auth) pour les gardes.

## Fonctions serveur

Les opérations sont des fonctions `createServerFn` natives exportées par les cas d'usage des modules ; l'application n'expose donc pas de point de terminaison REST pour elles. Voir [Fonctions serveur et cas d'usage](/docs/integrations/server-functions).

## Handlers HTTP

Ces routes déclarent `server.handlers` dans `src/routes/api/` :

| Route                                        | Handler                                                                                         |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `/api`                                       | Renvoie le runtime au format JSON                                                               |
| `/api/auth/$`                                | Better Auth, y compris les callbacks OAuth et les webhooks Polar sur `/api/auth/polar/webhooks` |
| `/api/search`                                | Recherche dans la documentation Fumadocs                                                        |
| <RepositoryFact name="cliApiBasePath" />`/*` | L'API de licence de la CLI, `licenseApiHandlers` dans `src/modules/license/license.api.ts`      |

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Prérendu

`src/data/tanstack.vite.ts` active le prérendu avec exploration des liens. `build:preview`, `build:production` et `build:test` prérendent les pages publiques (page d'accueil, pages légales, blog et documentation) dans toutes les langues. Le filtre ignore `/admin`, `/api`, `/app`, `/auth`, `/courses` et `/newsletter`, avec ou sans préfixe de langue, ainsi que les liens contenant `?` ou `#`. Les pages ignorées sont rendues par le Worker à chaque requête.
