---
title: "Участь у розробці"
description: "Як запропонувати зміни до SaaSy Land."
---

1. Спершу обговоріть великі зміни в issue, відкритому через форму звіту про помилку або запиту на функцію.
2. Створіть гілку від `main`.
3. Дотримуйтеся [конвенцій](/docs/conventions) та [архітектури](/docs/architecture), а перед зміною інтеграції з постачальником прочитайте відповідну [навичку агента](/docs/tooling/agent-skills). Агенти програмування починають з `AGENTS.md` у корені репозиторію.
4. Розміщуйте тести поруч із їхнім власником і підтримуйте поріг покриття <RepositoryFact name="coverageThreshold" unit="percent" />.
5. Запустіть наведені нижче перевірки.
6. Зробіть коміт із повідомленням у форматі [conventional commits](/docs/tooling/conventional-commits), відкрийте pull request із заголовком у тому самому форматі та заповніть його шаблон.
7. Робіть rebase гілки на `main`, коли вона конфліктує, і ніколи не зливайте в неї `main`, як описує сторінка [Git і pull request](/docs/conventions/git-workflow#linear-history). Зелений pull request супровідник ставить у [чергу злиття](/docs/conventions/git-workflow#merging), яка ще раз тестує його поверх `main` і зливає.

```sh
bun run check
bun run test:coverage
bun run build:test
bun run test:e2e:install
bunx playwright test e2e/specs/<spec>.spec.ts --project=chromium
```

`build:test` запускає повну збірку Cloudflare, яку не перевіряють ні `check`, ні модульні тести. Остання команда збирає й запускає тестовий Worker, якщо сервер ще не працює, і виконує в Chromium названі вами специфікації: запускайте ті, що покривають змінене. CI запускає всі специфікації в Chromium і у WebKit на pull request і ще раз у черзі злиття, а pull request зливається лише тоді, коли обидва браузери зелені; `bun run test:e2e:pr` запускає весь набір локально в Chromium. Для змін, які можуть поводитися інакше у WebKit, запускайте його і там (`bun run test:e2e`). Коли змінюєте конфігурацію реальних інтеграцій із провайдерами, перевіряйте їх окремо.

Коли змінюється поведінка, оновіть `content/docs` у кожній локалі; `bun run check:content` відхиляє відсутні переклади, а також відмінності в блоках коду та навігації. Шаблон pull request містить підсумок, план тестування з наведеними вище перевірками та список оновленої документації; опишіть у ньому підсумкову поведінку, як ви її перевірили, а також сценарії, які зміна залишає незавершеними. Екран адмінпанелі випускають лише разом зі справжнім джерелом його даних (див. [Панель адміністратора](/docs/features/admin-dashboard#real-data-only)).

`CONTRIBUTING.md` у корені репозиторію — це стисла версія цієї сторінки, а `SUPPORT.md` пояснює, де отримати допомогу. Усі учасники дотримуються `CODE_OF_CONDUCT.md`, тобто Contributor Covenant 2.1. Повідомляйте про вразливості безпеки конфіденційно, як описано в `SECURITY.md`, а не в публічному issue.
