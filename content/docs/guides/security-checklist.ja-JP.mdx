認証は2回実施されます: ルート `beforeLoad` ガードは管理者および顧客のレイアウトを保護し、各保護されたサーバー機能は発信者を独自に点検します。 利用条件 `requireAdmin` または `requireSession` レイアウトのためおよび `withAuth(permission)` 業務用。 セッションから顧客操作の派手な所有権。

Better Auth は D1 でセッションを保存し、資格情報、OAuth、認証、パスワードリセット、2 要素認証、偽装および再発を処理します。 保護されたサーバー機能をチェックするとき、クッキーキャッシュはバイパスされます。 最終的なauthプラグインは `tanstackStartCookies`認証クッキーをサーバー機能の応答で転送する。

D1 レート制限は、原子書き込みと Cloudflare クライアント IP ヘッダを使用します。 敏感な公共操作は別の限界のキーを備えています。 モジュールZodスキーマで入力を検証し、予期しない失敗をマスクし、支払いのWebhookシグネチャを検証して、サーバーのみの境界の背後にあるすべての資格情報を保持します。 プライベートなルートとトークンのミューテーションは、プレンダーから除外されます。
