## Vorlagen

Die Vorlagen liegen in `src/presentation/emails`. Jede Datei enthält nur Markup und exportiert ihre Namespace-Konstante:

| Vorlage                        | Namespace                                | Gesendet von                                          |
| ------------------------------ | ---------------------------------------- | ----------------------------------------------------- |
| `VerifyEmail`                  | `emails.verify-email`                    | `sendVerifyEmail` (Better-Auth-Hook)                  |
| `ResetPasswordEmail`           | `emails.reset-password-email`            | `sendResetPasswordEmail` (Better-Auth-Hook)           |
| `ChangeEmailConfirmationEmail` | `emails.change-email-confirmation-email` | `sendChangeEmailConfirmationEmail` (Better-Auth-Hook) |
| `NewsletterConfirmationEmail`  | `emails.newsletter-confirmation-email`   | `subscribeToNewsletter`                               |
| `NewsletterNotificationEmail`  | `emails.newsletter-notification-email`   | `confirmNewsletterSubscription`, an `CONTACT_EMAIL`   |

Eine Vorlage erhält `locale` und `messages` und übersetzt mit `createTranslator` von use-intl:

```tsx
const t = createTranslator({ locale, messages: { emails: { "verify-email": messages } }, namespace: "emails.verify-email" })
```

## Versand

Der Anwendungsfall übernimmt die Locale und den `redirect` aus der Callback-URL, die Better Auth weiterreicht, prüft das Limit pro Empfänger, lädt die Meldungen, rendert die Vorlage und versendet sie (`src/modules/verification/use-cases/send-verify-email.ts`):

```ts
if (!(await withinRecipientRateLimit({ kind: EMAIL_PURPOSE.VERIFY_EMAIL, recipient: user.email }))) {
  console.warn("[email] verification email not sent: the recipient reached the hourly limit")
  return
}
const callback = new URL(callbackURL, getRequest().url)
const locale = extractLocaleFromPath(callback.pathname) ?? I18N.DEFAULT_LOCALE
const verifyUrl = new URL(localizePathname({ locale, pathname: ROUTES.VERIFY_EMAIL }), getRequest().url)
verifyUrl.search = callback.search
verifyUrl.searchParams.set("token", token)

const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotency: { purpose: EMAIL_PURPOSE.VERIFY_EMAIL, token },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```

`sendEmail` (`src/integrations/resend/resend.utils.ts`) versendet über Resend von `RESEND_EMAIL_FROM`, sofern kein `from` angegeben ist (die Benachrichtigung an den Betreiber verwendet `NOTIFICATIONS_EMAIL`), übergibt den Idempotenzschlüssel und wirft bei einem Fehler eine Ausnahme.

Konto-E-Mails verwenden die Locale der Seite, auf der der Ablauf begonnen hat, gelesen aus der `callbackURL` im E-Mail-Link; bei einer wiederholten Registrierung stammt sie aus der `callbackURL` der Registrierungsanfrage. Newsletter-E-Mails verwenden die mit dem Formular übermittelte Locale; die Benachrichtigung an den Betreiber ist immer in `en-US`.

`withinRecipientRateLimit` (`src/lib/rate-limit.ts`) erlaubt höchstens drei Verifizierungs-, drei Passwort-Reset- und drei Newsletter-Bestätigungs-E-Mails pro Adresse und Stunde, gezählt in der Tabelle `rate_limit` unter einem SHA-256-Hash der Adresse. Über dem Limit wird die E-Mail übersprungen, und die Anfrage erhält trotzdem ihre normale Antwort. Die Bestätigung der E-Mail-Änderung und die Benachrichtigung an den Betreiber sind nicht begrenzt.
