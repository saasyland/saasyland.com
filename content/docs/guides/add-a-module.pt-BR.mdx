---
title: "Adicionar um módulo"
description: "Adicione uma tabela de banco de dados com schema Drizzle, schemas Zod, constantes, tipos e casos de uso."
---

Um módulo é uma tabela do banco de dados. `src/modules/<table>/` existe apenas para tabelas reais; funções de servidor que não pertencem a nenhuma tabela ficam em `src/lib` ou na rota que as usa. `src/modules/category` é o menor exemplo completo.

## Arquivos

| Arquivo                    | Conteúdo                                                                                                                                   |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `<table>.schema.ts`        | Tabela Drizzle, índices, relações e as tuplas de valores enumerados montadas a partir das constantes                                       |
| `<table>.zod.ts`           | Um schema de entrada por operação e os schemas de `drizzle-zod`, exportados como `<table>ZodSchemas`                                       |
| `<table>.constants.ts`     | Valores de domínio nomeados como `CATEGORY_KIND`, limites de colunas e as tuplas de chaves de queries e mutations                          |
| `<table>.types.ts`         | Uma interface com os tipos de linha e o tipo de entrada de cada operação                                                                   |
| `<table>.utils.ts`         | Funções auxiliares opcionais; `license.utils.ts` lê o ambiente do Worker, então é exclusivo do servidor                                    |
| `<table>.<concern>.ts`     | Código opcional que não é uma operação, como `license.webhooks.ts` ou `video.playback.ts` ([Catálogo de módulos](/docs/reference/modules)) |
| `use-cases/<operation>.ts` | Uma função de servidor por arquivo com suas opções de query ou mutation                                                                    |
| `__test__/`                | Testes nomeados pelo arquivo de origem, como `category.schema.test.ts` e `category.zod.test.ts`                                            |

## 1. Defina a tabela

Dê nome aos valores da tabela uma única vez em `category.constants.ts`. O esquema, os esquemas Zod, os casos de uso, os componentes, os testes e os dados e2e os importam de lá em vez de repetir uma string como `"collection"`:

```ts
export const CATEGORY_NAME_MAX_LENGTH = 255

export const CATEGORY_KIND = {
  CATEGORY: "category",
  COLLECTION: "collection",
} as const
```

Monte a tabela a partir desses nomes:

```ts
import { index, sqliteTable, text } from "drizzle-orm/sqlite-core"

import { timestamps } from "~/src/integrations/drizzle-orm/drizzle.columns"

import { CATEGORY_KIND, CATEGORY_NAME_MAX_LENGTH } from "~/src/modules/category/category.constants"

export const CATEGORY_KINDS = [CATEGORY_KIND.CATEGORY, CATEGORY_KIND.COLLECTION] as const

export const category = sqliteTable(
  "category",
  {
    id: text("id").primaryKey(),
    kind: text("kind", { enum: CATEGORY_KINDS }).notNull().default(CATEGORY_KIND.CATEGORY),
    name: text("name", { length: CATEGORY_NAME_MAX_LENGTH }).notNull(),
    ...timestamps(),
  },
  (table) => [index("category_createdAt_idx").on(table.createdAt)],
)
```

- Nomes de coluna usam snake_case; propriedades usam camelCase.
- IDs são chaves primárias `text` preenchidas com `v7()` de `uuid` no caso de uso de inserção.
- `...timestamps()` de `src/integrations/drizzle-orm/drizzle.columns.ts` adiciona `createdAt` e `updatedAt`: timestamps em milissegundos cujo padrão é o momento da inserção; `updatedAt` é renovado a cada atualização. As demais datas são `integer(..., { mode: "timestamp_ms" })`; booleanos são `integer(..., { mode: "boolean" })`.
- Uma coluna enumerada recebe a tupla montada a partir do objeto de constantes, e seu padrão é uma constante como `CATEGORY_KIND.CATEGORY`, nunca um literal de string.
- Chaves estrangeiras usam `.references(() => user.id, { onDelete: "cascade" })`, e `relations(...)` declara os joins (veja `session.schema.ts`).

## 2. Registre o schema

Exporte a tabela, e suas relações se houver, em `src/integrations/drizzle-orm/drizzle.schemas.ts`:

```ts
export { category } from "~/src/modules/category/category.schema"
```

Esse arquivo alimenta o cliente do D1 (`drizzle(env.DB, { schema })`), o adaptador Drizzle do Better Auth e o drizzle-kit. Uma tabela que não estiver nele não recebe migração.

## 3. Gere a migração

```sh
bun run db:generate
bun run db:migrate:local
```

Revise o SQL gerado em `src/integrations/drizzle-orm/migrations/` e faça o commit junto com o schema. [Migrações de banco de dados](/docs/guides/database-migrations) cobre os ambientes remotos.

## 4. Adicione os schemas Zod

Cada operação tem seu próprio schema de entrada. As mensagens de validação são chaves de tradução; um formulário as mostra com `ValidationFieldError` no namespace que ele indica.

```ts
import { createSchemaFactory } from "drizzle-zod"
import zod from "zod/v4"

import { MIN_FIELD_LENGTH, idField } from "~/src/modules/_core/utils/zod-fields"
import { CATEGORY_NAME_MAX_LENGTH } from "~/src/modules/category/category.constants"
import { CATEGORY_KINDS, category } from "~/src/modules/category/category.schema"

const { createInsertSchema, createSelectSchema, createUpdateSchema } = createSchemaFactory({ zodInstance: zod })

const createCategory = zod.object({
  kind: zod.enum(CATEGORY_KINDS),
  name: zod.string().min(MIN_FIELD_LENGTH, { message: "nameRequired" }).max(CATEGORY_NAME_MAX_LENGTH, { message: "nameMaxLength" }),
})

const deleteCategory = zod.object({ categoryId: idField })

export const categoryZodSchemas = {
  createCategory,
  deleteCategory,
  insert: createInsertSchema(category),
  select: createSelectSchema(category),
  update: createUpdateSchema(category),
}
```

Adicione `messages/<locale>/<table>.validations.json` em todos os idiomas, com todas as chaves que os schemas usam. Um formulário só mostra essas chaves quando a rota dele pré-carrega o namespace e o passa para `ValidationFieldError`; os formulários de cursos da administração usam `course.validations`, e os demais formulários usam `auth.validations`.

## 5. Adicione constantes e tipos

```ts
export const CATEGORY_QUERY_KEYS = {
  ALL: ["category"],
  LIST: ["category", "getCategories"],
} as const

export const CATEGORY_MUTATION_KEYS = {
  CREATE: ["category", "createCategory"],
  DELETE: ["category", "deleteCategory"],
  UPDATE: ["category", "updateCategory"],
} as const
```

```ts
import type * as zod from "zod"

import type { category } from "~/src/modules/category/category.schema"
import type { categoryZodSchemas } from "~/src/modules/category/category.zod"

export interface Category {
  select: typeof category.$inferSelect
  insert: typeof category.$inferInsert
  createCategory: zod.input<typeof categoryZodSchemas.createCategory>
  deleteCategory: zod.input<typeof categoryZodSchemas.deleteCategory>
}
```

Toda chave começa com o nome do módulo, então invalidar `ALL` atualiza todas as queries do módulo.

`Category` tem uma chave por esquema de operação; o módulo `category` completo também tem `getCategories`, `getCategory` e `updateCategory`. Uma função de servidor tipa a entrada do validador como `Category["createCategory"]`, e as opções de mutation ou query reutilizam esse tipo. Adicione a chave sempre que adicionar um esquema.

## 6. Adicione permissões e casos de uso

- Adicione as ações da tabela a `APP_STATEMENTS` em `src/integrations/better-auth/auth.access.ts` quando as operações exigirem permissões. Veja [Papéis e permissões](/docs/guides/roles-and-permissions).
- Adicione um arquivo por operação em `use-cases/`. Veja [Adicionar um caso de uso](/docs/guides/add-a-use-case).

## 7. Teste

Adicione `__test__/<table>.schema.test.ts`, `<table>.zod.test.ts` e `<table>.types.test.ts` ao lado do módulo e `use-cases/__test__/<operation>.test.ts` para cada operação. A cobertura mínima é de <RepositoryFact name="coverageThreshold" unit="percent" />; veja [Escrever testes](/docs/guides/writing-tests).
