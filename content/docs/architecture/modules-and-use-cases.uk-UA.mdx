## Модулі

Модуль у `src/modules/<table>` існує лише для справжньої таблиці бази даних. Він містить:

- `<table>.schema.ts`: таблиця Drizzle, яку реекспортує `src/integrations/drizzle-orm/drizzle.schemas.ts`
- `<table>.zod.ts`: схеми вхідних даних, які використовують і форми, і серверні функції
- `<table>.constants.ts`: іменовані доменні значення, як-от `COURSE_STATUS`, ліміти колонок, ключі запитів і мутацій
- `<table>.types.ts`: інтерфейс із назвою модуля, що містить типи рядків і тип вхідних даних кожної операції, наприклад `Course["createCourse"]`
- `<table>.utils.ts`: якщо вони потрібні таблиці
- `use-cases/<operation>.ts`: одна операція на файл

Модулі: <RepositoryFact name="modules" />. `license` володіє двома таблицями, `license` і `revoked_license_order`. Спільні константи та допоміжні функції лежать у [`_core`](/docs/architecture/core). Серверна функція, яка не працює з таблицею, належить до `src/lib` або до єдиного маршруту, що її використовує.

## Сценарії використання

Більшість сценаріїв використання — це серверні функції, які викликаються з браузера. Кожен файл експортує `createServerFn` і відповідні опції запиту чи мутації:

```ts title="src/modules/course/use-cases/create-course.ts"
import { mutationOptions } from "@tanstack/react-query"
import { createServerFn } from "@tanstack/react-start"
import { v7 } from "uuid"

import { authorized } from "~/src/integrations/better-auth/auth.middleware"
import { db } from "~/src/integrations/drizzle-orm/drizzle.database"
import { rethrowAsConflict } from "~/src/integrations/drizzle-orm/drizzle.errors"

import { nextPosition } from "~/src/modules/_core/utils/ordering"
import { COURSE_MUTATION_KEYS } from "~/src/modules/course/course.constants"
import { course } from "~/src/modules/course/course.schema"
import type { Course } from "~/src/modules/course/course.types"
import { courseZodSchemas } from "~/src/modules/course/course.zod"

export const createCourse = createServerFn({ method: "POST" })
  .middleware([authorized({ course: ["create"] })])
  .validator((input: Course["createCourse"]) => courseZodSchemas.createCourse.parse(input))
  .handler(async ({ data }) => {
    const positions = await db.select({ position: course.position }).from(course)

    return db
      .insert(course)
      .values({ ...data, id: v7(), position: nextPosition(positions) })
      .returning({ id: course.id })
      .get()
      .catch(rethrowAsConflict)
  })

export const createCourseMutation = mutationOptions({
  mutationFn: (data: Course["createCourse"]) => createCourse({ data }),
  mutationKey: COURSE_MUTATION_KEYS.CREATE,
})
```

- **Middleware** надходять із `src/integrations/better-auth/auth.middleware.ts`. `authorized()` вимагає сесію, `authorized({ course: ["create"] })` додатково перевіряє дозвіл, а `withRateLimit(kind, RATE_LIMITS.SENSITIVE)` обмежує публічні операції.
- **Валідація** розбирає вхідні дані Zod-схемою модуля ще до запуску обробника.
- **Належність даних** визначається сесією. Операції з власними даними того, хто викликає, фільтрують за `context.auth.user.id` і ніколи не довіряють ідентифікатору користувача з вхідних даних.
- **Помилки** викидаються як `new AppError(ERROR_CODES.X)`. `rethrowAsConflict` перетворює порушення обмеження унікальності, як-от уже зайнятий slug курсу, на `CONFLICT`. `withRequest` перетворює помилку API Better Auth на `AUTH_API_ERROR` з ключем повідомлення помилки, а помилку Zod — на `VALIDATION`; будь-яка інша помилка логується й доходить до клієнта як `INTERNAL_ERROR`.
- **Читання** натомість експортують `queryOptions`, наприклад `getCoursesPageQuery(input)`, який повертає `{ rows, total }` для таблиці даних.

Деякі сценарії використання — це звичайні асинхронні функції, які виконуються лише на сервері й не мають RPC-ендпоінта, як-от `send-verify-email.ts` або `grant-license.ts`. Їх викликають хуки Better Auth та обробники вебхуків Polar.

## Виклик сценарію використання з компонента

Компоненти розгортають експортовані опції в `useMutation`, перекладають помилки через `useErrorMessage()` і після успіху інвалідують ключі запитів модуля:

```tsx
const t = useTranslations("pages.admin.users.actions")
const queryClient = useQueryClient()
const errorMessage = useErrorMessage()

const deleteUser = useMutation({
  ...deleteUserMutation,
  onError: (error) => {
    toast.error(errorMessage(error))
  },
  onSuccess: async () => {
    await queryClient.invalidateQueries({ queryKey: USER_QUERY_KEYS.ALL })
    toast.success(t("feedback.deleteSuccess"))
  },
})
```
