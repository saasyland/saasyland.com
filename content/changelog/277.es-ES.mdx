- Cambiado: las pull requests llegan a `main` a través de la cola de fusión de GitHub, que vuelve a probar cada una sobre `main` y las pull requests que van delante y fusiona un grupo a la vez cuando todas han pasado, así que una pull request lista ya no espera a que alguien haga rebase. `bun scripts/enqueue-pr.ts <number>` pone una pull request en la cola y da a su título el emoji que conserva el commit squash. Consulta [Git y pull requests](/docs/conventions/git-workflow#merging).
- Cambiado: una pull request ya no despliega la preview compartida. La nueva comprobación `Worker upload` sube su Worker de preview a Cloudflare como una versión que no sirve tráfico, lo que demuestra la subida, su tamaño y sus bindings sin sustituir lo que sirve `preview.saasyland.com`, así que las pull requests listas ya no se bloquean entre sí. `main` se despliega en la preview antes que en producción, y `preview.yml` despliega allí a mano una rama probada. Consulta [CI/CD](/docs/tooling/ci-cd#merge-queue).
- Cambiado: un push a `main` que la cola de fusión ya probó se despliega sin volver a ejecutar las comprobaciones, y la comprobación del changelog trata una rama de la cola de fusión como `main`.
- Cambiado: la definición de terminado ejecuta en local `check`, `test:coverage`, `build:test` y las specs de navegador que toca el cambio; CI ejecuta toda la suite de navegador en la pull request y otra vez en la cola de fusión. Consulta [Convenciones](/docs/conventions#definition-of-done).
