---

## Реалізовано

- **Сесії**: сесії Better Auth у D1, префікс cookie `saasyland`, захищені cookie поза локальними режимами, дозволені хости для кожного режиму та `cf-connecting-ip` як адреса клієнта. Клієнтська сесія ніколи не містить токена.
- **Облікові записи**: обов’язкове підтвердження пошти, відкликання сесій після скидання пароля, необов’язковий TOTP з резервними кодами, ідентифікатори підтвердження зберігаються як хеші, токени OAuth зашифровано.
- **Авторизація**: `requireSignedIn` і `requireAdmin` на маршрутах; `authorized(permission)` у серверних функціях із ролями з `auth.access.ts`.
- **Обмеження запитів**: обмежувач Better Auth і middleware `withRateLimit` спільно використовують таблицю `rate_limit` у D1. `RATE_LIMITS.SENSITIVE` дозволяє 3 виклики, а `RATE_LIMITS.TOKEN` — 5 викликів за 60 секунд для кожного клієнта й дії.
- **Помилки**: middleware запитів перетворює збої на коди `AppError` (`src/modules/_core/constants/errors.ts`), тож клієнти ніколи не отримують «сирих» повідомлень сервера; компоненти показують їх через `useErrorMessage`.
- **Вебхуки й форми**: вебхуки Polar перевіряються за допомогою `POLAR_WEBHOOK_SECRET`; запити розсилки приймаються лише з відомих хостів і через HTTPS (`newsletterRequestOrigin`).

## Не реалізовано

- Заголовки безпеки, як-от Content Security Policy: `public/_headers` задає лише кешування.
- Журнал аудиту, зокрема для блокувань, видалень і входу від імені інших користувачів.
- Захист від ботів або CAPTCHA в публічних формах.
- Екран входу від імені користувача ([Вхід від імені користувача](/docs/features/impersonation)).
