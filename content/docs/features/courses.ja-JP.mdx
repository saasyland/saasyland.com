コース、チュートリアル、プロジェクトは D1 に保存され、`/courses` で視聴します。動画のレッスンは、そのレッスンエディターでアップロードした自身の録画を再生します（[動画](/docs/features/videos)を参照）。テキストのレッスンには動画がなく、読んで学びます。レッスンのアクセスレベルによって、誰がそれを開き、その資料をダウンロードできるかが決まります。

コースを編集する場所は管理画面だけです。タイトル、概要、レベル、アイコン、到達目標、前提条件、チャプター、レッスン、説明、主要な場面、動画、アップロード、資料はすべて D1 の行で、`/admin/courses` がすべてのロケールで編集します。コースのコンテンツがソースコードに書かれることはありません。コードが決めるのは管理画面が提供する選択肢だけで、種類、レベル、状態、アクセスレベル、レッスンの形式、アイコン名は名前付き定数です。多数のコースをまとめて変更する場合は、管理画面でコースを JSON ファイルにエクスポートし、編集したファイルをインポートします。[インポートとエクスポート](#import-and-export)を参照してください。

## データモデル

各テーブルは `src/modules` に専用のモジュールを持ちます。マイグレーション `20261113004409_salty_slipstream.sql` が最初の 4 つを作成し、`20261117161820_safe_stardust.sql` が `lesson_attachment` と _新規_ と記した列を、`20261123021636_steady_microchip.sql` が `video_upload` とレッスンの `format` を追加しました。どの列にも既定値があるため、既存の行はそのまま有効です。

| テーブル            | 列                                                                                                                                                                                                                                                                                                           |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `course`            | `slug`（一意）、`kind`（`course`、`tutorial`、`project`）、`status`（`draft`、`published`）、`position`、`title`、`summary`、_新規_: `level`（既定は `beginner`）、`icon`（既定は `book-open`）、`outcomes` と `prerequisites`（既定は `{}`）                                                                |
| `chapter`           | `course_id`、`position`、`title`、_新規_: `summary`（既定は `{}`）                                                                                                                                                                                                                                           |
| `lesson`            | `course_id`、`chapter_id`、`slug`（コース内で一意）、`access`（`preview`、`account`、`paid`）、`status`、`position`、`title`、`summary`、`video_id`、_新規_: `description`（既定は `{}`）、`key_moments`（既定は `[]`）、`format`（既定は `video`、または `text`）                                           |
| `lesson_attachment` | _新規_: `lesson_id`、`position`、`title`、`kind`（`file`、`link`）、ファイルの場合は `object_key`、`size_bytes`、`content_type`、リンクの場合は `url`                                                                                                                                                        |
| `video_upload`      | _新規_: レッスンごとに 1 つ（`lesson_id`、一意）。ファイルの `file_name`、`size_bytes`、`content_type`、`last_modified`、R2 の `object_key` と `multipart_id`、`part_bytes`、保存済みの `parts` とその ETag、`status`、`failure`。[動画](/docs/features/videos#from-the-upload-to-a-lesson-that-plays)を参照 |
| `lesson_progress`   | `user_id` と `lesson_id`（主キー）、`position_ms`、`completed_at`                                                                                                                                                                                                                                            |

- `title`、`summary`、`description` は、`{"en-US": "Billing", "pl-PL": "Płatności"}` のようにロケールをキーとする JSON を保持します（`src/modules/_core/utils/localized-text.ts` の `LocalizedText`）。`localize()` は訪問者のロケールの値を返し、ない場合は `en-US` にフォールバックするため、`en-US` は必ず入力してください。管理画面ではタイトルと概要の入力が必須ですが、チャプターの概要とレッスンの説明は空のままでもかまいません。D1 に直接挿入した行はチェックされません。
- `outcomes` と `prerequisites` は、`{"en-US": ["Deploy to Cloudflare"]}` のようにロケールごとに 1 つのリストを保持します（`LocalizedList`）。`localizeList()` は訪問者のロケールのリストを返し、それがないか空の場合は英語のリストを返します。リストの項目は最大 <RepositoryFact name="localizedListMaxItems" /> 個で、各項目は最大 <RepositoryFact name="localizedListItemMaxLength" /> 文字です。
- `level` は <RepositoryFact name="courseLevels" /> のいずれか（`COURSE_LEVEL`）、`icon` は <RepositoryFact name="courseIcons" /> のいずれか（`COURSE_ICON`）です。各名前を lucide のアイコンに対応付けるのは、`src/data/course-icons.ts` の `COURSE_ICON_COMPONENTS` だけです。
- レッスンの `description` は、ロケールごとに最大 <RepositoryFact name="lessonDescriptionMaxLength" /> 文字のプレーンテキストです。空行で新しい段落が始まり、バッククォートで囲んだテキストはコードになります。`parseRichText`（`src/lib/rich-text.ts`）がそれを段落とコードスパンに分割し、`RichText`（`src/presentation/components/custom/rich-text.tsx`）が React 要素として描画するため、保存されたテキストが HTML として解析されることはありません。
- `key_moments` は `{ "seconds": 135, "label": { "en-US": "Install the CLI" } }` のリストで、最大 <RepositoryFact name="lessonKeyMomentsMaxItems" /> 個まで、時間順に保持されます。管理画面では時間を `2:15` や `1:02:15` の形で入力し、`updateLesson` が秒数を保存します。
- 新しい行は `draft`、新しいレッスンは `paid` になります。一覧表示や配信の対象になるのは `published` のコースとレッスンだけで、それ以外のスラッグでは Not Found ページが表示されます。
- コースは `position` 順、チャプターはコース内の `position` 順、レッスンはチャプター内の `position` 順に並びます。レッスン番号はコース全体を通して振られます。
- `video_id` は `video` テーブルを参照し、動画が削除されると `NULL` になります。コースやチャプターを削除するとそのレッスンが削除され、レッスンを削除するとその資料とアップロードが削除されます。レッスンやユーザーを削除するとその進捗が削除されます。
- `format` は <RepositoryFact name="lessonFormats" /> のいずれかです（`LESSON_FORMAT`）。`text` のレッスンには動画がなく、収録中になることもありません。[テキストのレッスン](#text-lessons)を参照してください。
- `cover` は `20261121231021_overjoyed_bastion.sql` で追加され、既定は `NULL` です。コースのカバー画像の R2 キーを保持し、URL は保持しません。[コースのカバー画像](#course-covers)を参照してください。

## 収録中 [#being-recorded]

動画のレッスンは、動画がない間、つまり録画をアップロードする前、アップロード中、エンコード中は収録中です。このようなレッスンはカリキュラムに表示され、開くこともできますが、再生されることはありません。収録中を表すレッスンの状態はありません。公開側の読み取りは、`video` のレッスンだけを結合する `playableVideo`（`src/modules/lesson/lesson.playable.ts`）でレッスンを動画と結合し、同じファイルの `isBeingRecorded` が判定するため、収録中のレッスンについては次のようになります。

- `getCourse` と `getLesson` は `recording: true` と `durationMs: null` を返し、`getLesson` は字幕のロケールを返しません。
- `getLessonPlayback` は `NOT_FOUND` を返すため、署名済みのストリームは存在しません。
- `getCatalogue` と `getCourseShowcase` はそのレッスンをコースの長さに含めず、準備ができたレッスン、つまり再生されるレッスンとテキストのレッスンだけを数えます（`recorded` と `recordedCount`）。また、`getCourseShowcase` はそのレッスンに `recording` の印を付けます。

コースはレッスンを収録している間も公開でき、各ページはまだ再生されないものを販売する代わりに、収録中であることを伝えます。

- カタログ、コースページ、チャプターの見出しは、それぞれのレッスンがどれも準備できていない間、分数の代わりに脈打つドットとともに **収録中** を表示し、一部の準備ができると **23レッスン中3レッスンが公開済み** のように表示します。
- ランディングページのコースブロックは、収録中の各レッスンに砂時計と **近日公開** を表示し、プレーヤーへのリンクを付けません。
- コースページのパネルは、コースが収録中であり、各レッスンは録画が公開され次第再生されることを伝え、**講座を始める** のリンクを表示しません。一部のレッスンが再生されるようになると、**講座を始める** と **…の続きから** は再生されるレッスンにだけ案内します（`course.utils.ts` の `nextLessonToWatch`）。
- カリキュラムとレッスンページは、レッスンの再生時間が入る位置に砂時計と **近日公開** を表示します。
- 収録中のレッスンは、ロックされている場合でも、プレーヤーの枠の中で暗くしたコースのカバー画像の上に、レッスン番号、**収録中**、録画が近日公開であることを表示するため、そのページが視聴できないレッスンの購入を訪問者に求めることはありません。また、**完了にする** も表示しません。

録画のエンコードが終わるか、**既存の動画を使う** で動画を選ぶと、ほかに何も変えなくても、そのレッスンはどこでも一斉に再生されるようになります。

## テキストのレッスン [#text-lessons]

`format` が `text` のレッスンには、意図的に動画がありません。読むレッスンや、資料だけを提供するレッスンです。管理画面では、**レッスンを追加** ダイアログで **テキストのレッスン（動画なし）** を選ぶか、レッスンエディターで **このレッスンには動画がありません** をオンにすると作成できます。後者を行う `setLessonFormat` は、レッスンに動画またはアップロードがある間は `CONFLICT` で拒否します。公開ページはこれを、収録中のレッスンではなく、準備ができたレッスンとして扱います。

- `getCourse`、`getLesson`、`getCourseShowcase` は `format: "text"`、`recording: false`、`durationMs: null` を返します。`playableVideo` が動画を結合しないため、`getLessonPlayback` は `NOT_FOUND` を返します。
- カリキュラム、コースの内容、ランディングページのコースブロックは、動画のレッスンが再生時間を表示する位置に、ドキュメントのアイコンと **テキストのレッスン** を表示します（`lesson-meta.tsx`）。コースの長さには何も加えず、準備ができたレッスンの数に含まれます。
- そのページにはプレーヤーもその枠もなく、タイトル、アクセスレベル、説明、資料が先頭に来ます。ロックされたテキストのレッスンは、ロックされた動画のレッスンと同じ解放のパネルを表示します。それを開けるサインイン済みの視聴者には **完了にする** が表示され、**講座を始める** と **…の続きから** がそのレッスンに案内することもあります（`course.utils.ts` の `isAvailable`。`isPlayable` は動画のレッスン専用です）。
- レッスンエディターは、動画内の時間である主要な場面を表示しません。

## アクセスレベル [#access-levels]

| `access`  | 視聴できる人                                                                                       |
| --------- | -------------------------------------------------------------------------------------------------- |
| `preview` | サインインの有無を問わず全員                                                                       |
| `account` | サインインしているすべてのユーザー                                                                 |
| `paid`    | ティア `complete` または `agency` の `active` なライセンスを持つユーザー（`COURSE_LICENSE_TIERS`） |

`course: ["read"]` を持つロール（管理者が該当）は、すべてのレッスンを視聴できます。判定は `hasLessonAccess`（`src/modules/lesson/lesson.access.ts`）が行い、その対象となる視聴者は `resolveViewer`（`lesson.viewer.ts`）がセッション、ロール、`COURSE_ACCESS_GRANTS` の付与が与えるコースアクセス（`holdsCourseAccess`）から組み立てます。コースアクセスが有効になるのは確認済みのメールアドレスだけです。アドレスが未確認の保有者には `mustConfirmEmail` が返され、ページは確認を求めます。この判定はページだけでなく、コースのコンテンツを返すすべてのサーバー関数で行われます。

- `getCatalogue`（公開）は、公開済みのコースを、レッスン数、動画の合計時間、無料プレビューと有料レッスンの数、視聴者が完了したレッスンとともに返し、さらに `viewer`（サインインしている人がいるかどうか、その人が有料レッスンを開けるかどうか、アクセス権はあるが先にアドレスの確認が必要かどうか（`mustConfirmEmail`））を返します。
- `getCourseShowcase`（公開）は、ランディングページ用に、公開済みの最初の <RepositoryFact name="courseShowcaseCourses" /> つのコース（`COURSE_SHOWCASE`）を返します。各コースには、レッスン数、収録済みのレッスン、無料レッスンの数（`previewCount`）、動画の合計時間、カリキュラム順で最初の <RepositoryFact name="courseShowcaseLessons" /> つのレッスンが付き、各レッスンにはアクセスレベル、再生時間（`durationMs`）、視聴者が開けるかどうか（`locked`）、収録中かどうかが付きます。
- `getCourse`（公開）は、公開済みのコースを訪問者のロケールで返します。種類、レベル、アイコン、到達目標、前提条件、資料の数、概要付きのチャプター、公開済みのレッスンを含み、各レッスンには視聴者ごとの `locked`、`recording`、`captioned`、`durationMs`、`completed`、`positionMs` が付きます。アウトラインは `readCourseOutline`（`src/modules/course/course.outline.ts`）から取得し、`getLesson` も同じものを使います。
- `getLesson`（公開）は、レッスンページに表示するものすべてを 1 回の呼び出しで返します。同じアウトライン、説明・主要な場面・字幕のロケール・資料を含むレッスン、前後のレッスンです。未公開のコースやレッスンには `NOT_FOUND` を返します。
- `getLessonPlayback`（公開）は、`createPlayback` による署名付きの再生パスを返します。レッスンを視聴できない場合、ゲストには `UNAUTHORIZED`、サインイン済みのユーザーには `FORBIDDEN` を返し、未公開のレッスンや[収録中](#being-recorded)のレッスンには `NOT_FOUND` を返します。レッスンページはこれを <RepositoryFact name="lessonPlaybackStaleHours" unit="hour" />（`LESSON_PLAYBACK_STALE_MS`）のあいだ新しいままの別のクエリとして保持するため、再生中にプレーヤーのアドレスが変わることはありません。
- `saveLessonProgress` はセッションを必要とし、書き込む前に同じアクセス判定を行います。

コースアクセスを持つ視聴者が有料レッスンを開くと、`getLesson` と `getLessonPlayback` は応答する前に `recordPaidLessonOpened`（`lesson.viewer.ts`）でそれを記録します。そのため、レッスンの資料と動画が記録されないまま渡されることはありません。無料プレビュー、サインインしたすべてのユーザー向けのレッスン、コースアクセスを持たないスタッフの視聴では、何も記録されません。

コースアクセスはレッスンが自分で持つリストで、`hasLessonAccess` と同じ `src/modules/lesson/lesson.access.ts` にある `COURSE_ACCESS_GRANTS` です。コースアクセスを販売する機能は、そこに `CourseAccessGrant` を要素として 1 つ追加し、このファイルへの変更はすべて人がレビューします。付与は、ユーザーがアクセスを持つかどうか（`holds`、サーバー専用の関数）、何に含まれるか（`includedWith`、ライセンスページが挙げる名前のメッセージキー）、いくらか（`price`、`TIER_PRICES` の値）、どこで入手するか（`unlock`、視聴者が今いるレッスンから組み立てるリンク）、そのアクセスで開いた有料レッスンをどう記録するか（`recordUse`、`recordCourseAccessUse` がレッスンとユーザーを渡して呼び出すサーバー専用の関数）を示します。現在の唯一の要素はライセンスの付与で、ライセンスのユースケース `getLicense` と `recordLessonOpened`、および `license.constants.ts` のティアを使って、リストの中に直接書かれています。この付与は、`COURSE_LICENSE_TIERS` のティア（Complete または Agency）の `active` なライセンスにアクセスを与え、販売するティアとして `OFFERED_COURSE_TIER`（Complete）を示し、そのアクセスで最初に開いた有料レッスンを購入の最初の使用としてライセンスに記録し（`recordLessonOpened`、[ライセンス](/docs/features/licences#records-and-refunds)を参照）、サインイン中の視聴者を、レッスンを `redirect` にした `/app/license?tier=complete` に案内します。ゲストは登録を経てそこへ進みます。チェックアウトは `redirect` を Polar に渡して戻り、アクティベーションのパネルには **中断したところから続ける** が表示されます。`license` 機能を外してビルドしたサイトでは、その機能のファイルと一緒にこの要素も外れます（[テストは機能に従う](/docs/conventions/testing#tests-follow-the-features)を参照）。付与が 1 つもなければ、有料レッスンを視聴できるのはスタッフだけで、ロックされたパネルにはリンクが表示されません。サブスクリプションなど別の方法でアクセスを与えるサイトは、自分の要素を追加します。コースの文言はティアを名指しせず、付与からさらに 2 つの名前を受け取ります。アクセスの表示、解放のパネル、カタログの説明では `unlock` のリンクが販売するもの（`offer`）を、管理画面の有料アクセスレベルではアクセスを持つ人（`holders`）を使います。ライセンスは Complete と `components.custom.pricing` の `courseAccess.holders` の文言を渡すので、ページの表示はこれまでと同じです。

## 資料 [#materials]

レッスンの資料は `lesson_attachment` にあるファイルとリンクで、`position` 順に並びます。

- ファイルは `MEDIA` バケットの `attachments/<attachmentId>/<fileName>` に保存されます（`lesson-attachment.files.ts` の `attachmentObjectKey`）。アップロードできるのは、最大 <RepositoryFact name="attachmentMaxMegabytes" /> MB の <RepositoryFact name="attachmentFileTypes" /> ファイルです（`LESSON_ATTACHMENT_FILE_TYPES`、`LESSON_ATTACHMENT_MAX_MEGABYTES`）。コンテンツタイプはブラウザーからではなく常に拡張子から決まり、ファイル名には英字、数字、ドット、ハイフン、アンダースコアだけが残ります。
- リンクは、`/docs/getting-started` のようなドキュメントのパスか、`https://` のアドレスです。
- `getLesson` は、各資料のタイトルと種類、ファイルの場合はその名前とサイズを返します。`href` を加えるのは、視聴者がレッスンを開ける場合だけです。この判定にはレッスン自身の `locked` を使い、`hasLessonAccess` が一度だけ計算します。ファイルの場合、`href` は署名済みのパス `/media/downloads/<expiry>.<signature>/<attachmentId>/<fileName>`（`lesson-attachment.download.ts` の `signDownload`）で、少なくとも <RepositoryFact name="signedDownloadHours" unit="hour" />有効です。`serveAttachment`（`lesson-attachment.delivery.ts`）は署名を確認し、`Content-Disposition: attachment` を付けてファイルを配信します。署名が不正または期限切れの場合は `403` が返ります。署名済みパスは、期限が切れるまでベアラーリンクとして機能します。
- 資料、レッスン、チャプター、コースのいずれかを削除すると、行とともにアップロードされたファイルも削除されます。

## ページ

`/courses` レイアウト（`_site._marketing.courses.tsx`）はブログと同じ `_site` と `_marketing` のレイアウトの中にあるため、ヘッダーとフッターもブログと同じです。これらのページは視聴者ごとに D1 を読むため、プリレンダリングされません。`COURSES` は `src/routes.ts` の `REQUEST_RENDERED_ROUTES` に含まれています。それでも検索エンジンはこれらのページを見つけられます。Worker がカタログ、公開済みのすべてのコース、サインインしていない訪問者が視聴できるすべてのレッスンを、D1 からそれぞれの最終更新日付きで `/sitemap-courses.xml` に列挙し、アカウントやライセンスが必要なレッスンと収録中のレッスンには `noindex` が付くからです。コースのページは構造化データでコースを `Course` として、レベル、到達目標、前提条件、オファー、長さとともに記述し、カタログはコースを `ItemList` として列挙します。コースのページとそのレッスンはコースのカバー画像をリンクプレビューとして共有し、カバー画像のないコースはサイトのカードを共有します。[検索エンジンとソーシャルプレビュー](/docs/features/seo)と[コースのカバー画像](#course-covers)を参照してください。

- `/courses`（`course-card.tsx`）: 柔らかなティール色の光を背景にした見出しとリード文の下に、最初の公開済みコースを幅の広い注目カードとして、ほかのコースを 2 列で表示します。各カードの先頭には、ホバーでわずかに拡大するコースのカバー画像があり、種類とレベルのバッジ、タイトルと概要、**収録中** または収録済みの量、レッスン数、分数、無料レッスンの数、そしてレッスンを完了したサインイン済みの視聴者には進捗バーを表示します。カードはホバーで 2 ピクセル浮き上がります。動きを減らす設定では、カードもカバー画像も動きません。カードの下では、有料レッスンを開けない視聴者に **すべてのレッスンがCompleteに含まれます** がライセンスを案内し、すでに Complete を持つゲストには **ログイン** も表示します。アドレスが未確認の保有者には、購入の案内を表示しません。公開済みのコースがない場合は、最初の講座を収録中であることを伝え、フッターの開発日誌への登録を案内します。
- `/courses/<course>`: コースのカバー画像をぼかした光を背景に、コースの種類とレベル、タイトル、概要、数値を表示し、続いてサインイン済みの視聴者向けの進捗バー、到達目標と前提条件から作る **学べること** と **始める前に**、カリキュラムを表示します。複数のチャプターを持つコースは、最初のチャプターを開いた状態のアコーディオン（`curriculum.tsx`、React Aria の `DisclosureGroup` を使う shadcn の `Accordion`）でチャプターを表示します。各見出しには、チャプターの番号、タイトル、レッスン数、無料レッスンの数、分数または **収録中**、そしてサインイン済みの視聴者には `2/9` のような完了したレッスンの数が表示されます。チャプターの見出しは、ホバーで濃くなる色付きの帯の上に置かれるため、レッスンと見分けがつきます。各レッスンのタイトルはチャプターのタイトルと同じ列から始まり、アイコン、番号、鍵はタイトルの 1 行目に揃います。レッスンとチャプターの番号はタイトルと同じ書体でそのベースラインに乗り、アイコン、鍵、チャプターのプラス記号はその行のキャップハイトの中央に置かれるため、幅、ズーム、行数にかかわらず、すべてが同じ中心線に並びます。レッスン横のコースの目次も同じ規則に従い、ランディングページのコースブロックもアイコンを 1 行目の中央に揃えます。チャプターが 1 つのコースは、見出しなしでレッスンを並べます。各レッスンの行には、再生アイコン（完了後はチェック）、番号とタイトルが表示され、タイトルの下にアクセスを示すタグ（**無料プレビュー**、**アカウントがあれば無料**、または **Completeに含まれます**）と再生時間または **近日公開**（`lesson-meta.tsx`）が並び、視聴者が開けない場合は鍵が付きます。ロックされたレッスンのタイトルも、開けるレッスンと同じ明るさと太さで表示され、ロックは鍵で示されます。スクリーンリーダーはタグの代わりに **ロック中: Completeに含まれます** と読み上げます。タグは `Badge` で、無料プレビューは `accent`、それ以外は `neutral` のトーンです。コースページでもランディングページでも、再生時間と 1 本の中心線を共有し、タイトルから一定の間隔を空けて並びます（[テーマ](/docs/ui/theme#badges) を参照）。内容の横には、斜線の入った区切り線で分けられたパネル（`course-panel.tsx`）があります。パネルには、カバー画像、コースの状態（**収録中**、**すべてのレッスンを視聴できます**、または収録済みの量）、該当する場合は **講座を始める** または **…の続きから** と **Completeを入手**、そして **含まれるもの** が表示されます。**含まれるもの** はコースのデータだけから作られ、レッスン数、動画の分数、無料レッスン、資料、レッスンにある場合は字幕と文字起こし、進捗の保存、レベル、オファーで提供される新しいレッスンを挙げます。`lg` ブレークポイント以上では、パネルはヘッダーの高さ（`--spacing-header`）に余白 1 段階分を加えた位置に固定され、ウィンドウより高い場合はパネル自体がスクロールします。スマートフォンでは、コースの紹介の後に続き、固定されません。ロックされたレッスンがある場合、**Completeを入手** は Complete があらかじめ選択された `/app/license?tier=complete` にリンクし（ゲストは登録を経由します）、すでに Complete を持つゲストにはパネルに **ログイン** も表示します。アドレスが未確認の保有者には、代わりに **視聴するにはメールアドレスを確認してください** が表示され、`/auth/verify-email` を開いてコースに戻ります。
- `/courses/<course>/<lesson>`: 左側にコースの内容（`course-contents.tsx`）を表示します。そこには、パンくずリスト、コースのタイトル、視聴者の進捗、そしてアコーディオン形式のチャプターがあり、現在のレッスンのチャプターを開いてそのレッスンを強調します。**目次を隠す** でレッスンを全幅で表示し、スマートフォンでは **講座の内容** が同じ一覧をシートで開きます。シートは次のレッスンに移ると閉じます。最初にプレーヤーがあり、ロックされたレッスンや収録中のレッスンでは、代わりに暗くしたコースのカバー画像の上にそのパネルを表示します（`lesson-stage.tsx`）。開ける[テキストのレッスン](#text-lessons)には、プレーヤーもパネルもありません。アカウントが必要なレッスンでは **無料アカウントを作成** と、すでにアカウントを持つ人向けの **ログイン** が表示され、どちらも `redirect` でレッスンに戻ります。有料レッスンでは商品名と `TIER_PRICES` の価格を示し、**Completeを入手** と、ゲストには **Completeをお持ちですか？ログイン** を表示します。アドレスが未確認の保有者には、**リンクを再送信** とともに **視聴するにはメールアドレスを確認してください** が表示されます。[収録中](#being-recorded)のレッスンでは、ロックされているかどうかにかかわらず、録画が近日公開であることを示します。その下には、再生されるレッスン、または開けるテキストのレッスンでサインイン済みの視聴者に表示される **完了にする** と、次のレッスンのタイトルを示す **次へ** があります。続いて、レッスンのタイトル、アクセスレベル、再生時間、説明・主要な場面・資料のうち 2 つ以上がある場合にそれらへのリンクを並べる **このページの内容**、概要、説明、**主な場面**、**文字起こし**、**資料**、前後のレッスンへのリンクが並びます。ページは 1 回の `getLesson` 呼び出しで読み込まれます。

プレーヤーとその周辺の要素は、1 つの Video.js のストアを共有します。`LessonMedia`（`lesson-media.tsx`）は、要素を描画しない `@videojs/react/video` の `VideoPlayer` プロバイダーでレッスンを包み、プレーヤーのスキンとメディアは専用のチャンク（`video-player.tsx`）で読み込まれます。

- **主な場面**（`key-moments.tsx`）はボタンで、押すとプレーヤーを画面内に表示し、その場面にシークして再生します。`chapters` トラックとしても追加されるため、タイムスライダーにも表示されます。再生されないレッスンでは、主要な場面がボタンなしで一覧表示されます。
- **文字起こし**（`lesson-transcript.tsx`）は、ページの言語の字幕を、なければ英語の字幕を、それもなければ最初の字幕を `metadata` トラックとして読み込み、その行を時刻とともに一覧表示します。再生中の行に印を付けてそれに追従し、行が押されるとその位置にシークします。動画に字幕がないレッスンや、字幕に行がないレッスンでは、文字起こしは表示されません。

### コースのカバー画像 [#course-covers]

`course.cover` はフルサイズのカバー画像の R2 キー `covers/<courseId>/<coverId>.webp` を保持し、小さいサイズは `<coverId>-480.webp` のように幅を名前に含めてその隣に置かれます。`src/modules/course/course.cover.ts` の `courseCoverImage` は、キーを `/media/covers/` 以下の `src` と `srcset`（幅 <RepositoryFact name="courseCoverWidths" /> ピクセル）に変換します。`CourseCover`（`course-cover.tsx`）は、<RepositoryFact name="courseCoverWidth" /> × <RepositoryFact name="courseCoverHeight" /> で `srcset` と `sizes` を付けて描画し、ページで最も大きな画像になる場所では高い優先度で、それ以外では遅延して読み込み、代替テキストにはコースのタイトルを使い、テキストがすでにコース名を示しているカードの中では装飾として扱います。カバー画像のないコースは、代わりにティールの光の上にアイコンを表示します。カタログ、コースページとそのパネル、レッスンページ、ランディングページのコースブロックは、それぞれのクエリ（`getCatalogue`、`getCourse`、`getLesson`、`getCourseShowcase`）からカバー画像を読み込みます。

カバー画像は Worker 自身が配信します。`courses` 機能の `/media/` ハンドラーの後ろで、`serveCover`（`course.delivery.ts`）は、コース ID、カバー ID、任意の幅、`.webp` または `.jpg` を含むパスへの `GET` と `HEAD` に `Cache-Control: public, max-age=31536000, immutable` で応答し、Workers のキャッシュにコピーを保持します。新しいカバー画像には毎回新しい ID が付くため、キャッシュされたコピーが古くなることはありません。コースページとそのすべてのレッスンは、フルサイズのカバー画像をリンクプレビューとして共有します（`courseShareImage`）。`og:image` と `twitter:image` に、その種類、サイズ、代替テキストとしてのコースのタイトルを付けます。カバー画像のないコースはサイトのカードを共有します。

## ランディングページ [#on-the-landing-page]

ランディングページの **ツールキット** セクションにあるコースブロック（`src/presentation/components/custom/landing-page/components/` の `course-showcase.tsx`）は、表示された時点で D1 にある内容を表示するため、存在しないコースやレッスンを載せることはなく、管理画面で変更した後にデプロイする必要もありません。

- ランディングページはプリレンダリングされるため、HTML に含まれるのはブロックの見出し、講座ページの紹介動画、プレースホルダーだけで、コースのデータは含まれません。ブロックが表示領域まで画面 1 つ分以内に近づくと、ブラウザが `courseShowcaseQuery` を通じて `getCourseShowcase` を一度だけ呼び出し、ブロックを埋めます。この呼び出しはそのリクエストのために D1 を読み、訪問者の間でキャッシュされることはありません。そこまでスクロールしない訪問者はリクエストを送りません。管理者がコースを変更すると、次のページ表示からブロックに反映されます。コースを変更するたびに `course` のクエリが無効化されるため、管理者自身のタブではすぐに再取得されます。
- 各コースはタイルで、サムネイルとしてのカバー画像、種類とレベル、ページにリンクするタイトル、カタログのカードと同じ数値（`course-facts.tsx`: **収録中** または収録済みの量、レッスン数、分数、無料レッスンの数）、そして最初のいくつかのレッスンのタイトルを表示します。長いタイトルは省略記号で切らず、複数行に折り返します。各レッスンにはカリキュラムと同じタグ（**無料プレビュー**、**アカウントがあれば無料**、または **Completeに含まれます**）と、再生時間または **近日公開** が付きます。両方が入らない幅の狭いタイルでは、**近日公開** は砂時計だけになり、文言はレッスンのアクセシブルネームに残ります。視聴者が開けるレッスンには再生アイコンが付き、そのページにリンクします。ロックされたレッスンは開けるレッスンと同じ明るさのタイトルのまま鍵を表示し、タグの代わりに **ロック中: Completeに含まれます** のような非表示のラベルを持ち、購入の選択肢を示すそのページにリンクします。収録中のレッスンはどこにもリンクしません。コースにさらにレッスンがある場合は、**+ ほか18レッスン** がコースページにリンクします。
- `md` ブレークポイント以上では、タイルは 2 列に並び、最初のタイルは両方の列にまたがって、そのレッスンを 2 列で並べます。それより狭い画面では、タイルは横にスクロールします。
- プレースホルダーのタイルが <RepositoryFact name="courseShowcaseCourses" /> 件のコース分の場所を確保するのは、リクエストの応答を待つ間だけです。応答が届くとタイルは消え、ブロックの高さは表示する内容と同じになります。つまりコース、またはコースがまだ公開されていないこと、あるいはコースを読み込めなかったことを伝える 1 行です。リクエストはブロックが画面に入る 1 画面分前に始まるため、ブロックの高さはたいていビューポートの下で変わり、画面上では何も動きません。`landing.spec.ts` がデスクトップとスマートフォンで、それぞれの結果の高さとレイアウトシフトを確認します。
- 公開済みのコースがない場合はその旨を表示し、リクエストが失敗した場合は講座一覧へ案内します。**すべての講座を見る** はどの場合も `/courses` にリンクします。
- 講座ページの紹介動画は、`remotion/` プロジェクトの `course-tour` コンポジションです。AVIF と WebP のポスターを持つ静的ファイルとして `src/presentation/assets/motion/` に置かれ、押すとその場でブラウザのコントロール付きで再生されます。レッスンの動画ではなく、静的なアセットです。

## 進捗

サインイン済みの視聴者の場合、プレーヤーは保存された `position_ms` から再生を始め、`useLessonProgress`（`src/hooks/use-lesson-progress.ts`）が再生中に最大 <RepositoryFact name="lessonProgressSaveSeconds" unit="second" />ごとに位置を保存します。これには `VideoPlayer` の `startAt` と `onProgress` プロパティを使います。視聴者が最後まで再生する前に一時停止したときは、その場で位置を保存する（`onPause`）ため、短い視聴でも位置が残ります。動画が最後まで再生されたとき（`onEnded`）や、視聴者が **完了にする** を押したときは、`completed_at` が設定され、保存された位置が先頭に戻り、コースページの進捗が更新されます。一度設定された `completed_at` は保持されます。ゲストも無料プレビューを視聴できますが、何も保存されません。

## レッスンと動画

各動画のレッスンは、それぞれのレッスンエディターで録画を受け取ります。動画専用のページはありません。カタログとカリキュラムの再生時間は `video.duration_ms` から取得し、収録中のレッスンには再生時間がありません。レッスンに動画を付けるには、次の手順に従います。

1. レッスンエディターでレッスンを開き、録画を **動画** カードにドロップするか、**ファイルを選択** を押します。**レッスンを追加** ダイアログにドロップすることもでき、その場合はレッスンを保存するとすぐにアップロードが始まります。
2. カードにはアップロードの進捗が表示され、続いて **エンコーダーを待っています** と、`bun run video:encode:production` のような実行するコマンドが表示されます（[アップロードをエンコードする](/docs/features/videos#encode-the-uploads)を参照）。
3. エンコーダーが終わると、レッスンはすべてのページで一斉に再生されるようになり、その再生時間がコースの長さに加わり、**近日公開** の表示が消えます。

**既存の動画を使う** は、エンコード済みの動画をレッスンに設定するため、複数のレッスンで 1 本の録画を共有できます。後述のカリキュラムのように動画なしでファイルからインポートしたレッスンには動画がまったくなく、これも[収録中](#being-recorded)にあたります。同じ手順で動画を設定できます。

## コースを管理する

管理画面のサイドバーの **コンテンツ → コース** からコースの画面を開きます。そのレイアウト `admin.courses.tsx` は `course.validations` と `pages.admin.courses` の名前空間をプリロードし、`/admin` 配下のすべてのページと同じく `admin: ["access"]` を必要とします。コンポーネントは `src/presentation/components/custom/admin/courses/` にあります。

- `/admin/courses`（`admin.courses.index.tsx`）は、下書きを含むすべてのコースを `useCourseColumns`（`course-columns.tsx`）を使った `DataGrid` に一覧表示し、管理者が並べ替えるまでは `position` 順に並べます。表示するのは、タイトルと `/courses/<slug>` のパス、種類、状態、レッスン数、最終更新日です。`getCourses` はすべての言語のタイトルとスラッグを検索し、タイトル、種類、状態、レッスン数、最終更新日でサーバー側で絞り込みます。入力は `courseZodSchemas.getCourses` で検証されます。各行の先頭には、チェックボックス、ハンドル、カタログ内でのコースの位置（`#`）が並びます。位置はサーバーが並び順全体で数えるため、グリッドに何が表示されていても正しく表示されます。行の末尾には `CourseActions` の ⋯ メニューがあり、**編集**、コースの公開後は **サイトで表示**、**リンクをコピー**、確認を求める **削除** が並びます。選択したコースは、選択バーの **削除** からも同じ確認を経て削除でき、`deleteCourses` が 1 回のリクエストでまとめて削除します。**新しいコース** でフォームを開きます。
- `/admin/courses/create`（`admin.courses.create.tsx`）は空のコースフォームを表示します。**コースを作成** でコースを保存し、そのエディターを開きます。
- `/admin/courses/<courseId>`（`admin.courses.$courseId.tsx`）は、**詳細を保存** を備えたコースフォーム、**カリキュラム**、**コースを表示** を表示します。**コースを表示** は `/courses/<slug>` を新しいタブで開きます。下書きは公開されないため、**コースを表示** はコースを公開してから表示されます。
- `/admin/courses/<courseId>/lessons/<lessonId>`（`admin.courses.$courseId_.lessons.$lessonId.tsx`）はレッスンエディターで、レッスンのテキスト、主要な場面、動画、資料を扱います。**レッスンを表示** は、コースとレッスンが公開されると表示されます。コースエディターと同じ `courseEditorQuery` を読むため、行き来してもリクエストは発生しません。

動画専用のページはありません。各レッスンの録画は、そのレッスンエディターでアップロード、置き換え、削除します。そこにある **既存の動画を使う** ダイアログは、エンコード済みのすべての動画を、それを使うレッスンとともに一覧表示します。

新しいコースはほかのコースの後ろに追加されます。一覧が並べ替えも絞り込みもされていない間は、コースをハンドルでドラッグするか、フォーカスしたハンドルで上下の矢印キーを押すと、公開カタログの並び順が決まります。`moveCourse` は、移動が届いた時点で並び順全体の中にあるコースの位置から、ドラッグまたは矢印キーで動かした数だけコースを移し、その結果どのページに移っても、コースを 1 から番号付けし直します。その間に別の管理者がほかの場所でコースを追加または削除しても、コースの行き先は変わりません。

### 言語 [#languages]

コースのフォーム、チャプターとレッスンのダイアログ、レッスンエディター、教材のダイアログには、ロケールの数にかかわらず、項目の上に言語の切り替えが 1 つずつあります（`form-languages.tsx`）。

- **言語** には `I18N.SUPPORTED_LOCALES` のすべてのロケールが、名前、コード、状態（完了、一部翻訳済み、未翻訳、エラーあり）とともに並びます。入力すると名前またはコードで絞り込めます。言語を選ぶと、フォームのローカライズされた項目がすべてその言語に切り替わり、各項目には表示中の言語のコードが表示されます。
- 別の言語の項目の下には、英語の原文が表示されます。
- 一覧の横には、英語で入力されている項目をすべて埋めた言語の数が表示されます（`src/lib/localized-form.ts` の `localeStatuses`）。
- 表示していない言語にエラーがある状態で保存すると、フォームは最初のその言語に切り替わり、該当する項目にフォーカスが移ります。ほかの言語に残ったエラーは項目の上に言語名で示され、そのエラーを表示するボタンが付きます。
- **すべての言語** を押すと、1 つの項目をすべての言語で並べたパネルが開きます。英語が先頭で、各言語に入力済みか未入力かの印が付きます。言語の検索、未入力の言語だけの表示、フォームのテキスト項目の切り替えができます。パネルで入力したテキストはフォームの一部で、フォームと一緒に保存されます。

### コースの詳細 [#course-details]

コースフォーム（`course-form.tsx`）には次のフィールドがあります。

- **タイトル** と **概要**。選んだ言語で入力します。`en-US` は必須で、空のままのロケールは英語にフォールバックします。
- **URLスラッグ**: 小文字、数字、単独のハイフンのみ、最大 <RepositoryFact name="slugMaxLength" /> 文字で、コース全体で一意です。別のコースがすでに使っているスラッグは、保存時にこの欄でエラーになります。
- **種類**: **コース**、**チュートリアル**、**プロジェクト** のいずれか。
- **状態**: 既定の **下書き** または **公開**。`/courses` に表示されるのは公開済みのコースだけです。
- **レベル**: 既定の **初級**、**中級**、**上級** のいずれか。
- **アイコン**: 名前付きのアイコンのいずれか。フィールドの横に表示されます。
- **受講者ができるようになること** と **前提条件**。選んだ言語で入力します。**到達目標を追加** と **前提条件を追加** で行を追加し、行の横のバツ印でその行を削除します。空の行は受け付けられません。

### カバー [#cover]

コースフォームの下にある **カバー** カード（`course-cover-card.tsx`）は、コースのカバー画像、またはティールの光の上のアイコンを表示します。**画像を選択** は、最大 <RepositoryFact name="courseCoverMaxMegabytes" /> MB の <RepositoryFact name="courseCoverSourceTypes" /> ファイルを受け付けます。**カバーをアップロード**（カバーがある場合は **カバーを置き換える**）は、ブラウザーで画像を中央から 16:9 に切り抜き、`encodeImages`（`src/lib/image-encoding.ts`）で各幅の WebP に、WebP をエンコードできないブラウザーでは JPEG にエンコードして、すべてのサイズを 1 回のリクエストで送信します。**カバーを削除** するとアイコンに戻ります。カバー画像はコースが存在してから付けるため、このカードは作成フォームではなくコースエディターにあります。

### カリキュラム

カリキュラムエディター（`curriculum-editor.tsx`）は、チャプターを順に、それぞれの後にそのレッスンを続けて、1 つの React Aria の `GridList` として表示します。各レッスンの行では、タイトルを 1 行に置き、その下にスラッグと動画、さらにその下にタグと ⋯ メニューの行を置きます。この行はカードが狭くなると折り返すため、どの幅でも文字が重なりません。

### カリキュラムの並べ替え

各チャプターと各レッスンの先頭にはハンドルがあります。レッスンをハンドルでドラッグすると、同じチャプターの中で、または空のチャプターを含む別のチャプターへ移動します。チャプターをドラッグすると、そのすべてのレッスンと一緒に移動します。キーボードでも同じ操作ができます。行にフォーカスし、右矢印キーでそのハンドルに移って Enter を押し、上下の矢印キーで場所を選んでもう一度 Enter を押します。Escape を押すと元の場所のままになります。React Aria は各ステップをページの言語でスクリーンリーダーに読み上げ、カードはタイトルの下で操作方法を説明します。

- 意味のある場所だけが候補になります。レッスンは最初のチャプターより上には置けず、チャプターは別のチャプターの前か最後のレッスンの後にだけ置けます（`src/modules/course/course.curriculum.ts` の `canDropInCurriculum`。同じファイルの `moveInCurriculum` が新しい順序も計算します）。
- 新しい順序は、サーバーの応答を待たずにすぐ表示されます。続いて `reorderCurriculum` が、すべてのチャプターとそれぞれのレッスンを順番どおりに並べたカリキュラム全体を保存し、チャプターか位置が変わった行だけを 1 回の `db.batch` で書き込みます。受け取ったチャプターとレッスンがそのコースのものと正確に一致しない場合、たとえば別のタブで変更があった後には、`CONFLICT` を返します。するとエディターは元の順序に戻し、その理由を伝えてコースを再取得します。移動は、行われた順に 1 つずつ保存されます。

- **章を追加** は `chapter-dialog.tsx` を開き、ロケールごとに **章のタイトル** と任意の **概要** を入力します。各チャプターはタイトルの下に概要を表示し、**レッスンを追加** と、チャプターを編集または削除する ⋯ メニューがあります。
- チャプターの行にある **レッスンを追加** は `lesson-dialog.tsx` を開き、そのチャプターの末尾にレッスンを作成します。
- 各レッスンには、スラッグ、動画と再生時間、アクセスレベル、状態、そして動画の状態が表示されます。動画の状態は、**動画はまだありません**、このタブでアップロードしている間は割合付きの **アップロード中**、**アップロード停止**、**エンコード待ち**、**エンコード中**、**エンコード失敗**、または **テキストのレッスン** です。⋯ メニューからは、レッスンをレッスンエディターで開くか、削除できます。

レッスンのダイアログには次のフィールドがあります。

- **レッスンのタイトル** と **概要**。選んだ言語で入力し、`en-US` は必須です。
- **URLスラッグ**。コース内で一意です。同じコースの別のレッスンがすでに使っているスラッグは、この欄でエラーになります。
- **視聴できる人**: **誰でも（無料プレビュー）**（`preview`）、**サインイン済みの訪問者**（`account`）、または既定の **CompleteとAgencyのライセンス**（`paid`）。
- **状態**: 既定の **下書き** または **公開**。
- **レッスンの種類**: 既定の **動画のレッスン** または **テキストのレッスン（動画なし）**（`format`）。
- **録画**（動画のレッスンの場合）: 録画を受け付けるドロップゾーンで、任意です。レッスンを保存するとすぐにアップロードが始まり、作業を続ける間もカリキュラムにその進捗が表示されます。

### レッスンエディター [#lesson-editor]

レッスンエディターには 3 つのカードがあります。

- **レッスン**（`lesson-form.tsx`）: ロケールごとの **レッスンのタイトル**、**概要**、**説明**、そして **URLスラッグ**、**視聴できる人**、**状態**、**主要な場面**。説明には、受講者に表示されるとおりの段落とコードのプレビューが表示されます。各主要な場面は、`2:15` のような時間とロケールごとのラベルで構成されます。**主要な場面を追加** で追加し、バツ印で削除し、**レッスンを保存** で時間順に保存します。
- **動画**（`lesson-video.tsx`）: 録画のドロップゾーン（`video-drop-zone.tsx`。React Aria の `DropZone` と `FileTrigger`）で、ほかの種類のファイルやサイズの上限を超えるファイルは、何かを送信する前に拒否します。アップロード中はその進捗と **アップロードを取り消す**、アップロード後はエンコーダーまでの状態（[動画](/docs/features/videos#from-the-upload-to-a-lesson-that-plays)を参照）、準備ができた後は動画の長さ、解像度、サイズ、字幕の言語を示すプレーヤーと、**動画を置き換え** と **動画を削除**（ほかのレッスンがその動画を使っている場合は **このレッスンから外す**）を表示します。**既存の動画を使う**（`video-picker-dialog.tsx`）は、エンコード済みの動画をその使用状況とともに一覧表示し、そのうちの 1 本をレッスンに設定し（`replaceLessonVideo`）、どのレッスンも使っていない動画を削除します。その下の **このレッスンには動画がありません** は、レッスンを[テキストのレッスン](#text-lessons)にします。
- **資料**（`lesson-materials.tsx`）: レッスンのファイルとリンクを、カリキュラムと同じ React Aria の `GridList` として順に表示します。それぞれにハンドル、ファイル名とサイズ、またはアドレスが付き、編集または削除する ⋯ メニューがあります。資料はハンドルでドラッグするか、カリキュラムと同じキーボード操作で移動できます。新しい順序はすぐに表示され、`moveLessonAttachment` が資料の新しい位置を保存し、移動が拒否されると順序は元に戻ります。**ファイルをアップロード** ではロケールごとのタイトルとファイルを、**リンクを追加** ではロケールごとのタイトルとアドレスを入力します。リンクの編集ではタイトルとアドレスを変更し、ファイルの編集では名前を変更します。

### 削除

削除はどれも、実行前に確認を求めます。

- コースを削除すると、そのチャプター、レッスン、それらの資料、およびそれらに対する全ユーザーの進捗が削除されます。
- チャプターを削除すると、そのレッスンと、その資料と進捗が削除されます。
- レッスンを削除すると、その資料、進捗、アップロードが削除されます。
- 資料を削除すると、その資料はレッスンから取り除かれます。

行は外部キーの `ON DELETE CASCADE` によって削除され、アップロードされたファイルは削除のユースケースが R2 から削除します（`lesson-attachment.objects.ts` の `attachmentObjectKeys` と `removeAttachmentObjects`、そして未完了のマルチパートアップロードも中止する `video-upload.objects.ts` の `uploadObjects` と `removeUploadObjects`）。ほかのレッスンが再生しているかもしれないため、コース、チャプター、レッスンと一緒に動画が削除されることはありません。どのレッスンももう使っていない動画は、**既存の動画を使う** に **どのレッスンでも未使用** として表示され、そこで削除できます。

コースを削除すると、そのカバー画像のファイルも削除されます（`course.objects.ts` の `removeCoverObjects`）。

### インポートとエクスポート [#import-and-export]

コース一覧には **インポート** と **すべてエクスポート** があり、コースエディターにはそのコース用の **エクスポート** があります。エクスポートは JSON ファイル（`courses-<date>.json` または `<slug>-<date>.json`）を書き出し、インポートはそれを読み込みます。コンポーネントは `import-courses-dialog.tsx` と `export-courses-button.tsx` で、処理は `src/modules/course/course.transfer.ts` が行います。

ファイルには、すべてのコースがコースの順に含まれます。各コースにはチャプター、順に並んだレッスン、すべてのロケールのテキスト、アクセスレベル、状態、説明、主要な場面、リンク、各レッスンの動画の ID、そしてテキストのレッスンでは `"format": "text"` が含まれます。

```json
{
  "courses": [
    {
      "chapters": [
        {
          "lessons": [
            {
              "access": "preview",
              "description": {},
              "keyMoments": [{ "at": "2:15", "label": { "en-US": "Install the CLI" } }],
              "links": [{ "title": { "en-US": "Getting started" }, "url": "/docs/getting-started" }],
              "slug": "what-you-will-build",
              "status": "published",
              "summary": { "en-US": "The finished application." },
              "title": { "en-US": "What you'll build" },
              "videoId": "0195a2b4-6c8d-7e9f-8a0b-1c2d3e4f5a6b"
            }
          ],
          "summary": {},
          "title": { "en-US": "Start" }
        }
      ],
      "icon": "rocket",
      "kind": "course",
      "level": "beginner",
      "outcomes": { "en-US": ["Deploy to Cloudflare"] },
      "prerequisites": { "en-US": ["TypeScript and React"] },
      "slug": "empty-folder-to-production",
      "status": "published",
      "summary": { "en-US": "From an empty folder to production." },
      "title": { "en-US": "Empty folder to production" }
    }
  ],
  "format": "courses",
  "version": 1
}
```

- `format` は <RepositoryFact name="courseDocumentFormat" />、`version` は <RepositoryFact name="courseDocumentVersion" /> です（`COURSE_DOCUMENT`）。各コース、チャプター、レッスン、リンクは、管理画面のフォームが使うスキーマ（`createCourse`、`createChapter`、`updateLesson`、`createLessonAttachment`）で検証されます。これらは `course.zod.ts` の `courseDocument` にまとめられています。形式にないフィールドは拒否されるため、キーのつづりを誤っても、そのキーが黙って無視されることはありません。
- アップロードされたファイルはコースファイルに含まれず、含まれるのはリンクだけです。ダイアログにもそのことが表示されます。ファイルをインポートしても、アップロードされたファイルはそれぞれのレッスンに残ります。
- `videoId` のないレッスンは現在の動画を保ち、新しいレッスンは動画なしで始まるため、[収録中](#being-recorded)になります。インポートがレッスンから動画を外すことはありません。`format` のないレッスンは現在の形式を保ち、新しいレッスンは動画のレッスンになります。別の環境からエクスポートした場合のように、このデータベースにない `videoId` はレッスンの動画を変えず、警告として表示されます。

**インポート** はダイアログを開きます。ファイルを選んでから **ファイルを確認** を押します。確認はドライラン（`dryRun: true` を指定した `importCourses`）で、何も書き込みません。コース、チャプター、レッスン、リンクのそれぞれについて、インポートで追加、更新、変更なし、削除となる数と、ファイルにないが残される数、削除によって消えるアップロード済みファイルの数、そして警告を一覧表示します。続いて **インポート** を押すと、同じ計画が実際に実行されます。ルールに反するファイルの場合は代わりにその問題を一覧表示し、それぞれに `courses.0.chapters.1.lessons.2.slug` のようなフィールドのパスと、管理画面のフォームが表示するメッセージが付きます。表示するのは最初の <RepositoryFact name="courseImportProblemsMax" /> 件で、残りは件数だけを示します。ファイルに問題がなくなるまで、何もインポートされません。

インポートは、データベースにすでにあるものを、行の ID ではなく自然キーで照合します。

- コースはスラッグで、レッスンはコース内のスラッグで照合するため、レッスンを別のチャプターに移動できます。
- チャプターはコース内の順番で照合します。ファイルの最初のチャプターが、コースの最初のチャプターを更新します。
- リンクは、レッスンのリンクの中での順番で照合します。

書き込むのは差分だけなので、同じファイルを 2 回インポートしても、2 回目は何も変わりません。新しいコースは既存のコースの後ろに、ファイルの順で追加されます。チャプターのレッスンはファイルの順に並び、ファイルにないレッスンはその後ろに残ります。1 回のインポートの書き込みはすべて 1 回の `db.batch`（D1 の単一のトランザクション）で実行されるため、インポートは全体が適用されるか、まったく適用されないかのどちらかです。

**ファイルにないものを削除** は既定でオフです。チェックを入れると、インポートはファイルにないコース、チャプター、レッスン、リンクを、それらに含まれる全員の進捗とともに削除し、削除したレッスンのアップロード済みファイルと動画のアップロードを R2 から削除します。1 つのコースをエクスポートし、このオプションを付けてインポートすると、ほかのコースはすべて削除されます。そのことは、何かが書き込まれる前に確認の結果に表示されます。

`importCourses` は `withRateLimit` で、確認とインポートを 1 アドレスあたり 1 分に <RepositoryFact name="courseImportsPerMinute" /> 回までに制限します。1 つのファイルで 3 つの操作すべてを行えるため、`course: ["create", "update", "delete"]` を必要とします。ファイルは最大 <RepositoryFact name="courseDocumentMaxLength" /> 文字のテキストとして読み込みます。それより大きいカタログは、複数のファイルに分けてください。`exportCourses` は `course: ["read"]` を必要とします。

インポートの後は、データベースが信頼できる唯一の情報源です。コースは管理画面で編集し、多数のレッスンをまとめて変更する場合は、エクスポートしてファイルを編集し、インポートしてください。

ファイルにカバー画像は含まれません。インポートは各コースのカバー画像をそのまま残し、コースを削除するインポートはそのカバー画像のファイルも削除します。ドライランではそれらもファイルとして数えます。`content/courses/covers/` には、saasyland.com のコースのカバー画像が各幅で slug を名前にして収められています。`bun run db:seed:local` はカバー画像のないローカルのコースにそれらをアップロードし、本番では管理者が各コースの **カバー** カードで `<slug>.webp` をアップロードします。

`content/courses/saasy-land-courses.json` は、saasyland.com のカリキュラムをすべてのロケールで収めたもので、コースは公開済み、レッスンはすべて収録中です。新しいデータベースにインポートするためのファイルで、アプリケーションが読むデータではありません。コースは、管理者が本番でインポートするか、`bun run db:seed:local` が同じコードでローカルのデータベースにインポートするか、`bun run courses:sync:preview` が本番のコースをプレビューにコピーして初めて存在します（[データベース](/docs/tooling/database#course-data-in-each-environment)を参照）。`course-curriculum.test.ts` は、インポートがこのファイルを受け付けることを確認します。

- `getCourseEditor` は、すべてのレッスンを、説明、主要な場面、形式、動画（長さ、サイズ、解像度、字幕の言語、それを使うレッスンの数を含む）、アップロード（これまでに保存したバイト数を含む）、資料とともに返すため、コースエディターとレッスンエディターは 1 つのクエリを共有します。
- `uploadLessonAttachment` は `FormData`（ファイル、レッスン、ロケールごとのタイトル。`uploadFormData` が組み立てます）を受け取り、さらに `withRateLimit` でアップロードを 1 アドレスあたり 1 分に <RepositoryFact name="attachmentUploadsPerMinute" /> 回までに制限します。行を書き込んでからファイルを書き込み、R2 がファイルを拒否した場合は行を削除します。
- `uploadCourseCover` は `coverFormData` が組み立てた `FormData`（コースと、幅ごとに 1 枚の画像）を受け取ります。さらに `withRateLimit` でアップロードを 1 アドレスあたり 1 分に <RepositoryFact name="courseCoverUploadsPerMinute" /> 回までに制限し、欠けているサイズ、空のファイル、<RepositoryFact name="courseCoverMaxMegabytes" /> MB を超えるファイル、WebP と JPEG 以外の種類、種類の異なるサイズを拒否します。各サイズを R2 に保存し、キーをコースに記録してから、置き換えたカバー画像のファイルを削除します。R2 がサイズを拒否した場合やコースがなくなっていた場合は、保存したものを削除します。`removeCourseCover` はキーを空にしてファイルを削除します。
- アップロードは受講者が視聴できるものを変えるため、ほかのレッスンの書き込みと同じく `course: ["update"]` をチェックします。`startVideoUpload` はさらに `withRateLimit` で、開始を 1 アドレスあたり 1 分に <RepositoryFact name="videoUploadsPerMinute" /> 回までに制限します。`removeLessonVideo` は動画を削除できるため、`video: ["delete"]` も必要とします。
- **既存の動画を使う** の一覧は `getVideos` から取得し、これには `video: ["read"]` が必要です。
- すでに使われているスラッグには `CONFLICT` を返します。`rethrowAsConflict`（`src/integrations/drizzle-orm/drizzle.errors.ts`）が D1 の一意制約エラーを `AppError` に変換します。どの行にも一致しない ID には `NOT_FOUND` を返します。
- 新しいコース、チャプター、レッスンは、同じ階層の行の中で最大の `position` に 1 を足した値を取ります（`nextPosition`）。チャプターとレッスンの順序は、前述の `reorderCurriculum` で決まります。コースと資料は、同じ階層の行の中の指定した位置へ移動します。位置は `FIRST_POSITION`（`src/modules/_core/constants/ordering.ts`）から数えます。`reorder` は行をその位置に置き、両端より外の位置はその端として扱い、同じ階層の行を 1 から番号付けし直し、`position` が変わる行だけを返します。ユースケースはそれらの行を 1 回の `db.batch` で書き込みます。どちらの関数も `src/modules/_core/utils/ordering.ts` にあります。
- すべての書き込みで、タイトルと概要を `localizedTextSchema` で検証します。`en-US` は必須で、各テキストは最大 <RepositoryFact name="localizedTextMaxLength" /> 文字です。スラッグは最大 <RepositoryFact name="slugMaxLength" /> 文字です。フォームのメッセージは `defaultLocaleRequired`、`textTooLong`、`slugInvalid`、`itemRequired`、`timeInvalid`、`urlInvalid`、`fileTooLarge` などで、`course.validations` にあります。上限値は `COURSE_VALIDATION_PARAMS`（`course.constants.ts`）が渡します。
- コースのスラッグと、コース内のレッスンのスラッグは一意であるため、データベースをまたいでコースとレッスンを特定できます。コースのカリキュラムは、そのチャプターを順に並べたものです。
- `courseEditorQuery` は公開側のコースのクエリと同じく `staleTime: COURSE_STALE_MS` を保ち、変更のたびに `course` のクエリが無効化されるため、一覧とエディターが再取得されます。

## テスト

`scripts/seed-test.ts` は、レベル、アイコン、到達目標、前提条件を持つ公開済みのコースを 1 つと、概要付きのチャプターを 2 つ投入します。1 つ目のチャプターには、説明、主要な場面 1 つ、英語の字幕、PDF、ドキュメントへのリンクを持つ無料のレッスン、サインイン済みの訪問者向けのレッスン、PDF を持つ有料のレッスンがあり、2 つ目のチャプターには、動画がなく収録中の有料のレッスンが 3 つあります。また、テスト用の動画、どのレッスンも使わない予備の動画、有効な Complete のライセンスを持つ `learner@example.test` も投入します。

- `e2e/specs/course-pages.spec.ts` は、訪問者、Complete を持たない顧客、Complete の受講者に、それぞれの種類のレッスンを表示します。コースページのバッジ、数値、アコーディオン、スクロールした後もパネルがヘッダーの下の同じ距離に固定されること、主要な場面と文字起こしの行でプレーヤーがシークすること、レッスンの横とスマートフォンのシートに表示されるコースの内容、ポーランド語のページを確認します。さらに、管理画面でコースのタイトルを変更し、デプロイなしでランディングページとカタログにそのタイトルが表示されることを確かめます。
- `e2e/specs/courses.spec.ts` はレッスンを視聴し、`e2e/specs/course-materials.spec.ts` はダウンロードのアクセスルールを確認します。訪問者は無料レッスンのファイルを署名済みのパスでダウンロードでき、偽造したパスには `403` が返ります。訪問者と Complete を持たない顧客には有料レッスンの資料がリンクなしで表示され、Complete のライセンスの保有者はそれらをダウンロードでき、動画のないレッスンがストリームを要求せずに収録中として表示されます。
- `e2e/specs/course-admin.spec.ts` では、管理者がコース、チャプター、無料レッスンを作成し、**既存の動画を使う** でシード済みの動画をそのレッスンに設定し、別のブラウザページの訪問者がそのレッスンを視聴し、管理者がコースの ⋯ メニューから公開ページを開き、リンクをコピーし、エディターを開いた後、そこからコースを削除します。2 つ目のテストは、レッスンの説明と主要な場面を書き、ファイルをアップロードしてリンクを追加し、リンクをファイルの上へドラッグし、訪問者には動画のないレッスンが収録中として表示され、リンクが先頭にあり、ファイルをダウンロードできることを確認し、レッスンに録画を設定して訪問者のページで再生されるようにし、コースを削除するとファイルも削除されることを確認します。3 つ目のテストは、コースを 2 つ作成し、2 つ目を 1 つ目の上へドラッグし、再読み込み後と `/courses` でその順序を確認し、ハンドルで下矢印キーを押して元に戻し、選択バーから両方を削除します。`e2e/specs/course-curriculum.spec.ts` は、コースを作成し、マウスでレッスンをもう一方のチャプターへ、キーボードでチャプターを最初のチャプターの上へ動かし、再読み込み後の順序と、レッスンページの前後のレッスンへのリンクの順序を確認します。`e2e/specs/course-videos.spec.ts` は、小さな録画をレッスンにドロップし、テスト用 Worker のエンコーダーで **エンコーダーを待っています** からプレーヤーまでを追い、署名済みのストリームを確認し、動画を削除し、訪問者がプレーヤーも **近日公開** もなしに読むテキストのレッスンを作成します。
- `e2e/specs/landing.spec.ts` は、コースブロックがシード済みのコースを、開けるレッスン、ロックされたレッスン、収録中のレッスン、**+ ほか1レッスン** とともに表示すること、無料レッスンを開き、講座ページの紹介動画を再生できること、コースが届いたとき、読み込めなかったとき、1 件もないときにブロックが表示内容と同じ高さになること、そしてビューポートの下でコースがブロックを埋めても画面上で何も動かないことを確認します。`e2e/specs/course-access.spec.ts` は、有料レッスンでゲストに表示される価格、登録リンク、サインインリンクを確認し、ライセンスのない顧客としてサインインして、有料レッスンがレッスンを保持した `/app/license?tier=complete` へのリンク付きで Complete を案内することと、概要ページがライセンスの案内の横にロックされたコースを表示することを確認します。`e2e/specs/course-import.spec.ts` では、管理者がダイアログから `content/courses/saasy-land-courses.json` をインポートし、訪問者が `/courses` でそのコースを見つけて最初のコースが収録中であることを確認し、同じファイルをもう一度確認するとインポートするものが何もないことを確かめます。
- `e2e/specs/course-licences.spec.ts` は Polar のテストダブルで新しいアカウントに Agency、Core、Complete を付与します。Agency はすべての有料レッスンを開いて録画を再生し、ファイルをダウンロードできます。Core には Complete が案内され、プレイリストは届きません。返金された Complete ライセンスはその両方を失います。`e2e/specs/course-progress.spec.ts` はレッスンを完了にし、再読み込み後とコースページでその状態を確認し、さらにレッスンを一時停止して、その位置から再開されることを確認します。`e2e/specs/course-editing.spec.ts` はレッスンの説明とキーモーメント、コースの情報と公開状態を編集し、章・レッスン・教材の名前を変えて削除し、下書きが `404` を返すことを確認し、使用中のスラッグ、サイズ上限を超えるか別の種類の教材、1 分あたりの上限を超えるアップロードを拒否し、削除したコースをエクスポートしたファイルからインポートで戻します。`e2e/specs/course-permissions.spec.ts` はビルドに含まれるコースと動画のすべてのサーバー関数を訪問者と顧客として呼び出し、すべて拒否されることを確認します。`e2e/specs/course-videos.spec.ts` はアップロードを途中で切り、保存済みのパーツから続きを送ることも確認します。

`course-import.test.ts` と `course-transfer.test.ts` は、テストデータベースに対してインポートを実行します。対象は、カリキュラムのドライラン、そのインポート、何も変えない 2 回目のインポート、同じドキュメントを返すエクスポート、編集したエクスポートによる更新・移動・新しい行、削除で消えるもの（アップロード済みファイルを含む）、動画の参照、そして壊れたファイルが報告する問題です。
