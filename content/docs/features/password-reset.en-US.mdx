## Requesting a link

`/auth/forgot-password` renders `ForgotPasswordForm`. It calls `requestPasswordReset` (`src/modules/verification/use-cases/request-password-reset.ts`, rate limited with `RATE_LIMITS.SENSITIVE`) with `redirectTo` set to `/auth/reset-password` in the current locale. Better Auth then calls `sendResetPasswordEmail`, which sends the `ResetPasswordEmail` template. It sends at most <RepositoryFact name="recipientEmailsPerHour" /> reset emails per address per hour (`withinRecipientRateLimit`); further requests send nothing and get the same response. The link works for `EMAIL_LINK_LIFETIME_HOURS` (`resetPasswordTokenExpiresIn`), and the email says so.

## Setting a new password

The emailed link opens `/auth/reset-password?token=…`. Without a token, or with `?error=`, the page shows the invalid-link message and a link back to `/auth/forgot-password`. With a token, `ResetPasswordForm` calls `resetPassword` (rate limited with `RATE_LIMITS.TOKEN`) and navigates to `/auth/sign-in`. Because `revokeSessionsOnPasswordReset` is enabled, every existing session of that user ends. `onPasswordReset` then sends `PasswordChangedEmail` in the background, in the locale of the reset page: it says the password changed and every session ended, links to sign-in, and tells someone who did not change it to reset the password and write to `CONTACT_EMAIL` (OWASP's Forgot Password cheat sheet). A failed send is logged and the new password stays.

## Other password changes

- Signed-in users change their password in **Settings → Security** ([Settings](/docs/features/settings)).
- Admins set a password for another user from the users table ([Users (admin)](/docs/features/users-admin)).
