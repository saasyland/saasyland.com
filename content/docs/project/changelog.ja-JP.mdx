## 2026-11-14

- 設定: タイムゾーンが実際に機能する環境設定になりました。新しい `/app/settings` ページと `/admin/settings` の **一般** タブは `PreferencesCard` を共有します。このカードはすべてのタイムゾーンを名前で検索でき、**このブラウザから検出** を備え、新しい `updatePreferences` ユースケースを通じて保存します。`TranslationsProvider` はすべての日付をサインイン中のユーザーのタイムゾーンで表示し、時刻にはタイムゾーンの略称が付きます。[設定](/docs/features/settings)を参照してください。
- 日付は use-intl の `useFormatter` を通じて `I18N.FORMATS` の名前付きフォーマットを使います。`useDateFormatter` は削除しました。ブログ記事の日付のような時刻を持たない日付は UTC のままで、管理画面のユーザーテーブルは日付を閲覧者のタイムゾーンで表示します。[国際化とロケール](/docs/features/internationalization)を参照してください。
- 削除: 管理画面の環境設定カードにあった、どこにも接続されていない言語セレクトとお知らせのスイッチ。言語は引き続き URL 内のロケールです。
- 修正: フランス語とドイツ語の一部のタイムゾーン名で、タイムゾーンの名前の代わりに、ホーチミンが UTC+08:00 になるなど過去の UTC オフセットが表示されていました。

- サイトの文言とブログをコードと照らし合わせて修正しました。価格はすべて `TIER_PRICES` から取得します。ランディングページの説明文も同様で、ブログでは新しい MDX コンポーネント `<TierPrice>` を使います。コンサルティングの料金は `CONSULTING_HOURLY_RATE` から取得し、メッセージはメールアドレスを直接書かずに `CONTACT_EMAIL` を埋め込みます。FAQ とブログでは、キットが席数に応じた価格ではないこと、Agency ではコースと reactprojects.com のチーム席が加わることを説明しています。リリース記事では、CLI のモジュールとオプションを `src/data/cli.ts` の定義どおりに記載し、数は `<RepositoryCount>` から取得します。英語の文言では名詞を「licence」と綴り、`check:i18n` はロケール間で `markdown` のコードブロックも比較します。

## 2026-11-13

- 動画: `bun run video:publish:<environment>` は、FFmpeg で録画をアダプティブ HLS（最大 1440p の H.264 レンディション、共有の AAC トラック 1 つ、ポスター、ストーリーボードのサムネイル、字幕）にエンコードし、新しい `MEDIA` R2 バケットにアップロードして、新しい `video` テーブルに行を追加します。[動画](/docs/features/videos)を参照してください。
- `/admin/videos` で動画の一覧表示、プレビュー、削除ができます。新しい `video` 権限ステートメント（`read`、`delete`）で保護されています。
- Worker は、ロケールミドルウェアより前に、署名済みで期限付きの `/media/` パスで動画ファイルを配信します。`Range` に対応し、Workers のキャッシュを使います。[Cloudflare R2](/docs/integrations/cloudflare-r2) を参照してください。
- `VideoPlayer` は Video.js 10 で動画を再生し、画質、再生速度、字幕、ピクチャー・イン・ピクチャー、シークプレビューに対応します。メディア要素がアダプターの場合にストーリーボードのサムネイル URL が正しくなるよう、`@videojs/utils` 10.3.0 に Bun のパッチを当てています。
- コース: 新しい `course`、`chapter`、`lesson`、`lesson_progress` テーブルが、`/courses`（カタログ）、`/courses/<course>`（カリキュラムと進捗）、`/courses/<course>/<lesson>`（視聴者が止めた位置から再開し、進捗を保存するプレーヤー）を支えます。レッスンは動画ライブラリの動画を再生します。[コース](/docs/features/courses)を参照してください。
- 各レッスンは、無料プレビュー、アカウントがあれば無料、Complete または Agency のライセンスに含まれる、のいずれかで、サーバー関数がこれを強制します。管理者は新しい `course` 権限ステートメントによってすべてのレッスンを視聴できます。レッスンからサインインした訪問者は、そのレッスンに戻ります。
- `VideoPlayer` は `startAt`、`onProgress`、`onEnded` を受け取ります。
- 管理者は **コンテンツ → コース** でコースを管理します。`/admin/courses` は編集リンクと確認を求める削除ボタン付きですべてのコースを一覧表示し、`/admin/courses/create` はコースを作成し、`/admin/courses/<courseId>` はコースの詳細をすべてのロケールで編集してカリキュラムを組み立てます。そこでチャプターとレッスンを追加、編集、上下に移動、削除でき、各レッスンはライブラリから動画を選びます。[コース](/docs/features/courses)を参照してください。一覧の矢印で公開カタログの並び順を決めます。
- 新しいコース、チャプター、レッスンのユースケースは `course` 権限ステートメントをチェックし、すでに使われているスラッグには `CONFLICT` を返し（`rethrowAsConflict`）、新しい行には次の `position` を割り当て（`nextPosition`）、移動時には同じ階層の行を 1 から番号付けし直します（`reorder`）。コースやチャプターを削除するとそのレッスンと進捗が削除されますが、動画はライブラリに残ります。
- 管理画面から書き込むタイトルと概要には英語のテキストが必須で（`localizedTextSchema`）、メッセージは新しい `course.validations` 名前空間にあります。
- 削除: `/admin/courses/create` のデモのコース画面と、`/admin/products` の空の **コース** タブ。
- ランディングページのコースブロックは、コードに書かれたレッスン一覧ではなく、公開済みのコースを表示します。`getCourseShowcase` は最初の 2 つのコースを、それぞれの最初の 6 レッスンと各レッスンのアクセスレベルとともに返します。すべてのコースとレッスンはそれぞれのページにリンクし、**無料レッスンを見る** は動画のある最初の無料プレビューを開きます。ブラウザーはブロックが近くまでスクロールされた時点でこれを読み込むため、プリレンダリングされたページはすべての訪問者に同じ内容のままです。[コース](/docs/features/courses)を参照してください。
- コースブロックは、コースのページを紹介する音声なしの新しい Remotion コンポジション `course-tour` を、押されたときにブラウザーのコントロール付きで再生します。WebM で配信し、MP4 のフォールバックと、幅 1600 ピクセルと 800 ピクセルの WebP と AVIF のポスターを備えています。
- 購入ファネル: ランディングページで選んだプランはサインアップ後も引き継がれ（`redirect=/app?tier=<tier>`）、`/app` と `/app/license` はそのプランを表示して、**決済に進む** を 1 回押すだけで購入に進めます。[決済とライセンス](/docs/features/payments)を参照してください。
- `/app` と `/app/license` は、ライセンスのないアカウントに、ランディングページと同じ地域価格付きのプランのカードと、Complete または Agency のライセンスで視聴できるようになるコースのレッスン（D1 から集計）を表示します。[顧客アプリ](/docs/features/customer-app)を参照してください。
- 支払い後、購入者は自分の言語の `/app?checkoutId=<id>` に戻り、ライセンスが有効になるのを確認できます。Polar が 1 分以内に支払いを確認しない場合は、ページがその旨を伝え、サポートのメールアドレスと購入セッションの参照番号を表示します。
- `startCheckout` はすでに有効なライセンスを持つアカウントを拒否し（`LICENSE_ALREADY_ACTIVE`）、Polar プラグインの `/api/auth/checkout` は HTTP では無効になっているため、すべての購入がこのチェックを通ります。
- ライトテーマの `--ring` を濃くしたため（`oklch(0.55 0.106 208)`）、小さなティール色のラベルもコントラスト比 4.5:1 を満たします。
- アフィリエイトプログラム: 紹介パラメーター付きのリンクはその訪問に限り Affonso のスクリプトを読み込み、購入時に `affonso_referral` Cookie を注文のメタデータとして Polar に渡します。トラッキングは Worker 変数 `AFFONSO_PROGRAM_ID` で有効になります。`/affiliates` は `AFFILIATE_TERMS` の値で規約を公開し、プライバシーポリシーは紹介 Cookie について説明します。[アフィリエイトプログラム](/docs/features/affiliates)を参照してください。
- サインイン後は、サインインを求めたページに戻ります。`redirect` 検索パラメーターは、このサイト内のパスだけを受け付けます。
- `e2e/specs/accessibility.spec.ts` は、WCAG 2.0、2.1、2.2 の A と AA のルールで axe-core を実行し、公開ページ、ブログ記事、コースのページ、両方のワークスペースをライトテーマとダークテーマで検査します。
- ランディングページ、法務ページ、ブログ、コース、ドキュメントで、最初の画面をスクロールし終えるとページトップへ戻るボタンが表示されます。押すとページの先頭に戻り（動きを減らす設定の読者にはアニメーションなし）、フォーカスをページの見出しに移します。[ランディングページ](/docs/features/landing-page)を参照してください。
- 修正: ランディングページのナビゲーションにあるロゴは `/` で何もしませんでした。現在は先頭までスクロールし、アドレスからセクションのハッシュを取り除きます。ブログとコースのヘッダーも同じ `HomeLink` を使います。
- ドキュメントとブログ: すべてのページが両方のテーマで WCAG 2.2 AA を満たします。GitHub Light のオレンジと GitHub Dark のコメントのグレーを `fumadocs.config.ts` で置き換え、すべてのコードトークンが 4.5:1 を満たすようにしました。タスクリストのチェックボックスには項目のテキストで名前が付きます。`@fumadocs/base-ui` 16.19.0 への Bun のパッチにより、コードブロックはタイトルで名前が付く場合にだけ region ランドマークになるため、コードブロックが複数あるページで名前のないランドマークが重複しなくなりました。`accessibility.spec.ts` は規約のすべてのページ、各ドキュメントセクションから 1 ページ、ブログ記事 1 件も両方のテーマでスキャンし、スキャンするページが読み込めなければ失敗します。
- ランディングページとブログの数字はすべて、サイトのビルド時にリポジトリで計測されます（`virtual:repository-facts`、`<RepositoryCount>`）。UI コンポーネント、管理画面のセクション、ロケールの数も対象になりました。
- ドメイン値は、文字列を繰り返し書く代わりに、定数として一度だけ名前を付けるようになりました。対象は、商品のステータスと種類（`PRODUCT_STATUS`、`PRODUCT_TYPE`）、カテゴリーのアイコン、種別、公開状態（`CATEGORY_ICON`、`CATEGORY_KIND`、`CATEGORY_VISIBILITY`）、導出されるユーザーのステータス（`USER_STATUS`）、認証情報と OAuth のプロバイダー ID（`AUTH_PROVIDER`）、メールの用途（`EMAIL_PURPOSE`）、管理画面のブログのデモ記事のステータスです。テスト、e2e のデータ、シードスクリプトは、これらの定数と、ロール、プラン、ステータス、`ERROR_CODES` の定数をインポートします。[モジュールを追加する](/docs/guides/add-a-module)を参照してください。
- `createdAt` と `updatedAt` を持つすべてのテーブルは、`src/integrations/drizzle-orm/drizzle.columns.ts` の `timestamps()` を展開してこれらを定義します。
- `typescript/no-explicit-any` を lint エラーにし、`license.utils.ts` と `video.delivery.ts` をサーバー専用にしました。
- コードと照らし合わせて修正: プライバシー通知（サイトが設定する Cookie と、レート制限の記録が残る期間）、ランディングページとブログの文章、README、このドキュメント。
- デプロイ: `deploy:preview` と `deploy:production` は、`wrangler.jsonc` が宣言するシークレットだけを環境ファイルから `.wrangler/secrets.<environment>.json` に書き出し、その環境の D1 マイグレーションを適用し、それらのシークレットとともに `dist/server/wrangler.json` をデプロイして、`scripts/verify-deployment.ts` で稼働中のサイトを確認します。CI はこの確認を行いません。Cloudflare のボット対策が CI ランナーからのリクエストに 403 を返すためです。[プロジェクトのスクリプト](/docs/tooling/scripts)を参照してください。
- `verify-bindings.ts` は `MEDIA` バケットも必須とし、D1 データベース、KV 名前空間、R2 バケットのいずれかをプレビューと共有している本番環境を拒否します。`verify-build.ts` は環境を受け取り、ビルドされた Worker の設定がその環境を対象にしていることを確認します。
- 新しいスクリプト: `db:reset:test` はローカルのテスト用データベースを作り直すもので、Playwright と CI はこれを実行します。`db:migrations:<environment>` は、リモートデータベースにまだ適用されていないマイグレーションを一覧表示します。スクリプトは Wrangler と `drizzle-kit generate` を `vp exec` 経由で実行し、`package.json` のスクリプトは名前順に並んでいます。
- `wrangler.jsonc` は環境を開発、プレビュー、テスト、本番の順に並べ、各環境には D1、R2、KV のバインディングをこの順で、シークレットを名前順で記述しています。
- ドキュメント: 新しい **規約** セクションは、このリポジトリのコーディング標準です。コードスタイル、ファイルと命名、モジュール、サーバー関数とエラー、データの取得とキャッシュ、ルートファイル、コンポーネントとスタイリング、フォームとテーブル、翻訳とコンテンツ、アクセシビリティ、パフォーマンス、テスト、依存関係、Git とプルリクエストの 14 ページで構成されます。各ルールはそれに従うファイルを示し、コース機能をリファレンス実装としています。[規約](/docs/conventions)を参照してください。
- ドキュメント: **リファレンス → 規約** と **リファレンス → ファイル命名規則** はこのセクションに移り、それぞれ概要と[ファイルと命名](/docs/conventions/files-and-naming)になりました。
- リポジトリのルートにある `AGENTS.md` は、コーディングエージェントに技術スタック、コマンド、例外のないルール、規約へのリンクを提供します。
- [コントリビューション](/docs/project/contributing)に、検証の全手順（`check`、`test:coverage`、`build:test`、`test:e2e:pr`）を記載しました。
- デプロイ用の Worker は、プリレンダリングの後、ドキュメントとブログのページのレンダリングされた MDX と、ランディングと法務の各ページだけが使う翻訳を除いて再ビルドされます。これによりアップロードサイズは 46.4 MiB から 21.9 MiB に減りました。`scripts/verify-build.ts` は、すべてのドキュメントページと公開済みのブログ記事がプリレンダリングされていることを確認します。[Cloudflare Workers](/docs/integrations/cloudflare-workers) を参照してください。
- Worker のエントリは、起動時に TanStack Start のサーバーランタイムを読み込まなくなりました。`parseLocaleCookie` は `i18n.middleware.ts` に移り、`ThemeProvider` は自分でクッキーを読みます。

## 2026-11-12

- Worker のすべてのレスポンスにセキュリティヘッダーが付くようになりました。`X-Content-Type-Options`、`Referrer-Policy`、`X-Frame-Options`、`Cross-Origin-Opener-Policy`、`Permissions-Policy`、フレームへの埋め込み・`<base>` の変更・プラグインを禁止する Content Security Policy に加え、HTTPS では `Strict-Transport-Security` が付きます。Worker を経由せずに配信される静的ファイルには、`public/_headers` がそのサブセットを付けます。
- 確認メール、パスワードリセットメール、ニュースレターの確認メールを、アドレスごとに 1 時間あたり 3 通までに制限しました（`withinRecipientRateLimit`）。
- Better Auth 独自のエンドポイントでも、フォームのパスワード、名前、メールアドレス、画像のルールを適用するようになりました（`auth.hooks.ts` の `enforceInputPolicy`）。
- 修正: Resend の冪等性キーを `<purpose>/<SHA-256 of the token>` にしたため、長いアドレスへの確認メールとメールアドレス変更のメールが拒否されなくなりました。
- 修正: 一部返金でライセンスが取り消されなくなりました。また、決して成功しない Polar の Webhook イベントは、再送させずに受領するようになりました。
- 修正: ニュースレターの確認リンクと配信停止リンクは、訪問者がボタンを押したときにだけ処理を行うようになりました。また、ニュースレターのリンクは `appHostsForMode` のホストだけを受け付けるようになりました。
- ルートの検索パラメーターは、`src/lib/search-params.ts` の `searchText`、`searchFlag`、`searchChoice` で組み立てた Zod スキーマになりました。
- 各モジュールの `<module>.types.ts` は 1 つのインターフェースをエクスポートし、サーバー関数は入力を `Module["operation"]` として型付けするようになりました。ニュースレターのステータスとソースは名前付きの定数になりました。
- 修正: デプロイで Worker のソースマップをアップロードしなくなりました（`upload_source_maps: false`）。ソースマップのせいでアップロードが大きくなりすぎていました。
- Node 26.13.1 以降が必要です。`nvm use` と CI は `.nvmrc` のバージョンを使います。
- 修正: チェックアウトの地域割引を Worker のメモリではなく KV にキャッシュするようにしました。キャンセルされたリクエストが、その後のチェックアウトを止めることはなくなりました。
- 依存関係を更新しました: `@polar-sh/sdk` 1.x、`@polar-sh/better-auth` 2.x、Vite+ 1.6.0、Vitest 5.1.0、`fumadocs-mdx` 15.6.1。

## 2026-09-26

- 国際化を use-intl の名前空間を中心に再構築しました。`messages/<locale>/` に名前空間ごとに 1 つの JSON ファイルを置き、ページルートごとに `NAMESPACE`、レイアウトルートごとに `NAMESPACES` を宣言し、すべての画面で使うルート名前空間を用意し、すべての静的キーを `useTranslations` のスコープ内で解決する `check:i18n` ステップを追加しました。

- ニュースレターのフォームを簡素化しました。
- 修正: ホームページ以外のページでも、ナビゲーションとセクションへのリンクがロケールを保持するようになりました。
- 修正: 管理ダッシュボードのグラフのラベルがローカライズされるようになりました。
- Vitest のカバレッジのゲートを、行、ステートメント、関数、分岐のすべてで 100% に設定しました。
