| Route      | Routendatei                       | Namespace             |
| ---------- | --------------------------------- | --------------------- |
| `/privacy` | `src/routes/_landing.privacy.tsx` | `pages.legal.privacy` |
| `/terms`   | `src/routes/_landing.terms.tsx`   | `pages.legal.terms`   |
| `/refunds` | `src/routes/_landing.refunds.tsx` | `pages.legal.refunds` |
| `/licence` | `src/routes/_landing.licence.tsx` | `pages.legal.licence` |

Jede Routendatei definiert ihre eigene Seitenkomponente, einen statischen `NAMESPACE` und eine Modulkonstante mit den Abschnittsschlüsseln in Anzeigereihenfolge:

```tsx
const SECTIONS = ["operator", "accounts", "purchases", "payments", "licence", "conduct", "refunds", "responsibility", "law"] as const
```

Die Seite rendert `lastUpdated`, `title` und `description` und danach für jeden Schlüssel `sections.<key>.title` und `sections.<key>.body`. Es gibt keine gemeinsame Komponente für rechtliche Seiten.

## Bearbeiten

- Ändern Sie die Texte in `messages/<locale>/pages.legal.<doc>.json` für alle neun Locales und führen Sie `bun run check:i18n` aus.
- Um einen Abschnitt hinzuzufügen, ergänzen Sie seinen Schlüssel in `SECTIONS` und seine Meldungen in jeder Locale.
- Die Footer-Links sind die Konstante `LEGAL_LINKS` in `src/presentation/components/custom/footer.tsx`; die Registrierungsseite verlinkt auf die Nutzungsbedingungen und die Datenschutzerklärung.

Die Lizenzseite trennt die MIT-Lizenz des öffentlichen Repositorys von separat bereitgestelltem kostenpflichtigem Material. Die Rückerstattungsrichtlinie wahrt zwingende Verbraucherrechte. Halten Sie jedes Dokument im Einklang mit dem tatsächlichen Betreiber, Checkout, den Anbietern und der Datenverarbeitung.
