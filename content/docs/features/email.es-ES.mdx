## Plantillas

Las plantillas están en `src/presentation/emails`. Cada archivo contiene solo marcado y exporta su constante de espacio de nombres:

| Plantilla                        | Espacio de nombres                        | La envía                                                                                                       |
| -------------------------------- | ----------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `VerifyEmail`                    | `emails.verify-email`                     | `sendVerifyEmail` (hook de Better Auth)                                                                        |
| `ResetPasswordEmail`             | `emails.reset-password-email`             | `sendResetPasswordEmail` (hook de Better Auth)                                                                 |
| `ChangeEmailConfirmationEmail`   | `emails.change-email-confirmation-email`  | `sendChangeEmailConfirmationEmail` (hook de Better Auth)                                                       |
| `ExistingAccountEmail`           | `emails.existing-account-email`           | `sendExistingAccountEmail` (`onExistingUserSignUp` de Better Auth)                                             |
| `PasswordChangedEmail`           | `emails.password-changed-email`           | `sendPasswordChangedEmail` (`onPasswordReset` de Better Auth, el hook `password-change-notice`, `setPassword`) |
| `DeleteAccountEmail`             | `emails.delete-account-email`             | `sendDeleteAccountEmail` (`sendDeleteAccountVerification` de Better Auth)                                      |
| `InvitationEmail`                | `emails.invitation-email`                 | `sendInvitationEmail` (`createInvitation`, `resendInvitation`)                                                 |
| `NewsletterConfirmationEmail`    | `emails.newsletter-confirmation-email`    | `subscribeToNewsletter`                                                                                        |
| `NewsletterNotificationEmail`    | `emails.newsletter-notification-email`    | `confirmNewsletterSubscription`, a `CONTACT_EMAIL`                                                             |
| `NewsletterIssueEmail`           | `emails.newsletter-issue-email`           | `sendNewsletterIssue`, mediante `sendBatchEmails`, a los suscriptores confirmados                              |
| `PurchaseConfirmationEmail`      | `emails.purchase-confirmation-email`      | `sendPurchaseConfirmationEmail` (`order.paid` de Polar)                                                        |
| `UnmatchedOrderAlertEmail`       | `emails.unmatched-order-alert-email`      | `sendUnmatchedOrderAlert` (`order.paid` de Polar), a `CONTACT_EMAIL`                                           |
| `WithdrawalAcknowledgementEmail` | `emails.withdrawal-acknowledgement-email` | `sendWithdrawalAcknowledgement` (`submitWithdrawal`)                                                           |
| `WithdrawalNotificationEmail`    | `emails.withdrawal-notification-email`    | `sendWithdrawalNotification` (`submitWithdrawal`), a `CONTACT_EMAIL`                                           |

Una plantilla recibe `locale` y `messages` y traduce con `createTranslator` de use-intl:

```tsx
const t = createTranslator({ locale, messages: { emails: { "verify-email": messages } }, namespace: "emails.verify-email" })
```

Los correos de cuenta empiezan con `EmailBrandHeader`, el nombre de la aplicación, y ponen `EmailFallbackLink` bajo su botón: el mismo enlace como texto sin formato, para los clientes que ocultan los botones. Los correos de verificación, de restablecimiento de contraseña, de cambio de correo y de eliminación de la cuenta indican durante cuánto tiempo funciona su enlace, a partir de `EMAIL_LINK_LIFETIME_HOURS`, el valor con el que está configurado Better Auth.

## Envío

El caso de uso toma el idioma y el `redirect` de la URL de callback que le pasa Better Auth, comprueba el límite por destinatario, carga los mensajes, renderiza la plantilla y la envía (`src/modules/verification/use-cases/send-verify-email.ts`):

```ts
if (!(await withinRecipientRateLimit({ kind: VERIFICATION_EMAIL_PURPOSE.VERIFY_EMAIL, recipient: user.email }))) {
  console.warn("[email] verification email not sent: the recipient reached the hourly limit")
  return
}
const callback = new URL(callbackURL, getRequest().url)
const locale = extractLocaleFromPath(callback.pathname) ?? I18N.DEFAULT_LOCALE
const verifyUrl = new URL(localizePathname({ locale, pathname: ROUTES.VERIFY_EMAIL }), getRequest().url)
verifyUrl.search = callback.search
verifyUrl.searchParams.set("token", token)

const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotency: { purpose: VERIFICATION_EMAIL_PURPOSE.VERIFY_EMAIL, token: crypto.randomUUID() },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```

`sendEmail` (`src/integrations/resend/resend.utils.ts`) envía a través de Resend desde `RESEND_EMAIL_FROM`, salvo que se indique un `from` (la notificación al propietario, el aviso de pedido sin cuenta y la notificación de desistimiento usan `NOTIFICATIONS_EMAIL`), pasa la clave de idempotencia y lanza un error si el envío falla. `sendBatchEmails` envía hasta <RepositoryFact name="newsletterBatchSize" /> correos, cada uno con sus propias cabeceras, en una sola petición con una sola clave de idempotencia, registra los que Resend rechaza y devuelve los ID de los demás; solo la usan los números del boletín ([Boletín](/docs/features/newsletter#sending)).

Los correos de cuenta usan el idioma de la página donde empezó el flujo, que se lee del `callbackURL` del enlace del correo; en un registro repetido sale del `callbackURL` de la petición de registro. Un flujo que no indica ningún callback, un inicio de sesión en una cuenta sin verificar o un restablecimiento de contraseña, toma el idioma y el `redirect` de la página que envió la petición (su `Referer`, cuando está en este sitio). La confirmación del boletín usa el idioma enviado con el formulario, y cada número el idioma guardado con la suscripción, o el inglés si el número no tiene una versión completa en él; la notificación al propietario siempre está en `en-US`. La confirmación de compra usa el idioma que `createCheckout` guardó en los metadatos del pedido, y el inglés cuando no hay ninguno; confirma en un soporte duradero el consentimiento del comprador al suministro inmediato, consulta [Licencias](/docs/features/licences#purchase-confirmation). El aviso de pedido sin cuenta, que informa al sitio de un pedido de licencia pagado cuyo cliente no corresponde a ninguna cuenta, está en `I18N.DEFAULT_LOCALE`; consulta [Licencias](/docs/features/licences#orders-that-match-no-account). El acuse de recibo de un desistimiento usa el idioma de la página donde se presentó la declaración, y la notificación de desistimiento al sitio está en `I18N.DEFAULT_LOCALE`; consulta [Licencias](/docs/features/licences#withdrawal-function). El correo de invitación usa el idioma que el administrador eligió para él, guardado en el `locale` de la invitación.

`withinRecipientRateLimit` (`src/lib/rate-limit.ts`) permite como máximo <RepositoryFact name="recipientEmailsPerHour" /> correos de cada tipo (verificación, restablecimiento de contraseña, cuenta existente, eliminación de la cuenta, confirmación del boletín y acuse de recibo de un desistimiento) por dirección y hora, contados en la tabla `rate_limit` con un hash SHA-256 de la dirección. Por encima del límite el correo se omite y la petición sigue recibiendo su respuesta normal. La confirmación del cambio de correo, el aviso de cambio de contraseña, la notificación al propietario, los números del boletín, la confirmación de compra, el aviso de pedido sin cuenta y la notificación de desistimiento no tienen límite; un cambio de contraseña necesita un token de restablecimiento o la contraseña actual, la confirmación de compra y el aviso de pedido sin cuenta los provoca el webhook de Polar, no un visitante, una vez por pedido, un número llega una sola vez a cada suscriptor confirmado y solo lo envía un administrador, y la notificación de desistimiento solo se envía al sitio, como máximo <RepositoryFact name="sensitiveRateLimit" /> por cliente y minuto. El correo de invitación cuenta para el mismo límite, pero al superarlo `sendInvitationEmail` falla con `TOO_MANY_REQUESTS` en lugar de omitir el correo.
