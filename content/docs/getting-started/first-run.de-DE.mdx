## Isolierte Test-Preview

Die Test-Preview baut die Anwendung für die Umgebung `test`: lokale D1 und KV in `.wrangler/test`, Platzhalter-Zugangsdaten aus `.env.test`, per Seed angelegte Konten und abgefangene Anfragen an Resend und Polar. Sie benötigt keine Konten.

```sh
bun run db:migrate:test
bun run db:seed:test
bun run build:test
bun run start:test
```

Öffnen Sie http://127.0.0.1:3000 und melden Sie sich mit einem der angelegten Konten an. Beide verwenden das Passwort `WorkerTestPassword123!` aus `e2e/data/accounts.ts`.

| Rolle | E-Mail                            | Arbeitsbereich |
| ----- | --------------------------------- | -------------- |
| Admin | `admin@saasyland.example.test`    | `/admin`       |
| Kunde | `customer@saasyland.example.test` | `/app`         |

Die Preview liefert einen Build aus; bauen Sie sie daher neu, um Änderungen am Quellcode zu sehen.

## Entwicklung mit Cloudflare

`bun run dev` startet den Dev-Server mit Hot Reload unter http://localhost:3000. Seine Bindings `DB` und `CACHE` verbinden sich mit den entfernten Preview-Ressourcen, daher landen Schreibvorgänge aus der Entwicklung in der Preview-Datenbank.

```sh
bunx wrangler login
cp .env.example .env.development
bun run db:migrate:development
bun run dev
```

1. Melden Sie sich mit Wrangler bei Cloudflare an.
2. Füllen Sie `.env.development` wie unter [Umgebungsvariablen](/docs/getting-started/environment-variables) beschrieben aus, mit `POLAR_SERVER=sandbox`.
3. Legen Sie mit Ihrem eigenen Cloudflare-Konto die D1-Datenbank und den KV-Namespace an und ersetzen Sie die IDs für `development` und `preview` in `wrangler.jsonc`; die eingecheckten IDs gehören zum bestehenden Deployment. Siehe [Eine Preview deployen](/docs/getting-started/deploy-preview).
4. Wenden Sie die Migrationen an und starten Sie den Server.

Die Registrierung per E-Mail benötigt eine funktionierende Resend-Konfiguration, da Konten ihre E-Mail-Adresse vor der Anmeldung bestätigen müssen. Für die Entwicklung gibt es keinen Admin-Seed: Registrieren Sie sich, bestätigen Sie die Adresse und setzen Sie dann mit `bun run db:studio:development` die `role` Ihres Benutzers auf `admin`.
