---
title: "プロジェクトのスクリプト"
description: "package.json のすべてのスクリプトと、その実行内容です。"
---

スクリプトはリポジトリのルートで `bun run <script>` として実行します。Wrangler を呼び出すスクリプトと、drizzle-kit を呼び出す `db:generate` は、それらを `vp exec` 経由で実行します。`vp exec` は `node_modules/.bin` のバイナリを使うため、常に `bun.lock` で固定されたバージョンが使われます。

## 開発とビルド

| スクリプト         | 実行内容                                                                                                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `dev`              | `generate:cn`、`content`、そして `development` 環境の `vp dev` を http://localhost:3000 で実行                                                                                       |
| `build`            | `build:preview` と同じ                                                                                                                                                               |
| `build:preview`    | `dist` のクリーン、`generate:cn`、`content`、`preview` 向けの `vp build`、`scripts/verify-build.ts preview`、`scripts/optimize-prerendered-html.ts`、`scripts/generate-seo-files.ts` |
| `build:production` | `production` 向けに同じ手順を実行                                                                                                                                                    |
| `build:test`       | `test` 環境向けに同じ手順を実行                                                                                                                                                      |
| `start`            | 最新のビルドを `vp preview` で http://127.0.0.1:3000 に配信                                                                                                                          |
| `start:test`       | テスト用ビルドの `vp preview`                                                                                                                                                        |

`verify-build.ts` は、まず `.wrangler/deploy/config.json` が `dist/server/wrangler.json` を指していること、そしてこのファイルが `wrangler.jsonc` でその環境に指定された Worker をデプロイすることを確認します。続いて、ローカライズされたホームページと法的ページのドキュメント言語・正規リンク・代替リンク、フォント、ロケールエイリアスと、Worker がリクエストごとに描画するパス（`REQUEST_RENDERED_ROUTES`）配下のページがプリレンダリングされていないこと、すべてのドキュメントページと公開済みのブログ記事がプリレンダリングされていること、クライアントのアセットが `cloudflare:workers` をインポートしていないこと、ブラウザーのエントリースクリプトの静的インポートにページ名前空間のメッセージのローダーが含まれていないこと、Polar のチェックアウトの埋め込みが、購入者がチェックアウトを始めたときに `import()` だけが読み込む 1 つのクライアントのアセットに収まっていること、そして Worker がコールドスタートで読み込むコードが小さいままであることを確認します。`dist/server/index.js` の静的インポートは `@polar-sh`、`drizzle-orm`、`resend` に到達してはならず、合計が `BOOT_CLOSURE_MAX_BYTES` 以下でなければなりません（[パフォーマンス](/docs/conventions/performance)を参照）。`optimize-prerendered-html.ts` は、プリレンダリングされたページから依存関係の `modulepreload` ヒントを取り除き、エントリーのヒントは低優先度のまま残します。`generate-seo-files.ts` は、各ページ自身のメタデータから `sitemap.xml` と各ロケールのブログフィードを書き出し、プリレンダリングされたすべてのページのソーシャルカードと組織のロゴを描画します。[検索エンジンとソーシャルプレビュー](/docs/features/seo)を参照してください。

## デプロイ

| スクリプト          | 実行内容                                                                                                                                                                                                                                                   |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `deploy:preview`    | `scripts/verify-bindings.ts preview`、`scripts/prepare-deploy-secrets.ts preview`、`scripts/run-deploy-checks.ts preview`、`build:preview`、`db:migrate:preview`、`dist/server/wrangler.json` の `wrangler deploy`、`scripts/verify-deployment.ts preview` |
| `deploy:production` | `production` 向けに同じ手順を実行                                                                                                                                                                                                                          |

- `verify-bindings.ts` は、`development` が宣言しているバインディング（ここでは `DB`、`CACHE`、`MEDIA`、`BUNDLES`）が環境にない場合や D1 または KV のプレースホルダー ID が残っている場合、また本番がデータベース、名前空間、バケットをプレビューと共有している場合に失敗します。
- `prepare-deploy-secrets.ts` は、環境の `secrets.required` に列挙されたキーを `.env.<environment>` から読み込み、いずれかがない、空である、またはプレースホルダーである場合は失敗し、それらのキーだけを `.wrangler/secrets.<environment>.json` に書き出します。プレースホルダーとは、`[UPDATE]` のように括弧（<RepositoryFact name="secretPlaceholderBrackets" />）で囲まれた値、または大文字小文字を問わず、スペース、ハイフン、アンダースコアの有無にかかわらず <RepositoryFact name="secretPlaceholderWords" /> のいずれかの単語である値です。エラーにはキー名が表示され、値は表示されません。キー名は `wrangler.jsonc` から読み込むため、どの機能の名前も挙げずにすべての機能のシークレットを対象にします。ファイル内のその他の変数はアップロードされません。
- `run-deploy-checks.ts` は、`<name>:verify:<environment>` という名前のパッケージスクリプト（機能はこれを追加してデプロイ前チェックを加えます）をすべて実行し、いずれかが失敗するとビルドの前にデプロイを止めます。現在のチェックは、`.env.<environment>` の <RepositoryFact name="oauthClientIdVariables" /> がそれぞれのプロバイダーの形式（`verify-deployment.ts` がデプロイ後に適用するのと同じ形式）のクライアント ID を含んでいない限り失敗する認証機能の `auth:verify` と、`.env.<environment>` の Polar の組織がコードと一致しない場合に失敗する Polar 機能の `polar:verify` です。
- マイグレーションはビルドの後、デプロイの前に実行されます。そのため、ビルドが失敗してもデータベースに手が加わることはなく、新しい Worker が古いスキーマで起動することもありません。
- デプロイでは `env -u CLOUDFLARE_ENV vp exec wrangler deploy --config dist/server/wrangler.json --secrets-file .wrangler/secrets.<environment>.json` を実行します。ビルドされた設定はすでに 1 つの環境を対象にしています。シェルに `CLOUDFLARE_ENV` が残っていると、Wrangler はそのファイルにない環境セクションを探そうとします。
- `verify-deployment.ts` は、環境のドメインで <RepositoryFact name="liveSiteCheckPaths" /> にリクエストを送り、それぞれが期待されるコンテンツタイプで `200` を返さない限り失敗します。<RepositoryFact name="socialSignInPath" /> では、ブラウザと同じ方法でサインインページの各プロバイダー（<RepositoryFact name="oauthProviderIds" />）のサインインを開始し、返された認可 URL がプロバイダー自身のホスト上にあり、そのプロバイダーの形式の `client_id` と、同じドメインの <RepositoryFact name="oauthCallbackPath" /> を指す `redirect_uri` を含んでいない限り失敗します。エラーにはプロバイダー名と問題点が表示され、値そのものは表示されません。失敗したチェックは <RepositoryFact name="liveSiteCheckRetrySeconds" unit="second" />間隔で最大 <RepositoryFact name="liveSiteCheckRetries" /> 回まで再実行します。サインインボタンのクリックでも残る短期間の OAuth ステートと試行回数のカウンターを D1 に残すほかは、何も変更しません。`bun scripts/verify-deployment.ts <preview|production>` は、稼働中のサイトを単独で確認します。

## チェック

| スクリプト                                                                    | 実行内容                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `check`                                                                       | `generate:cn`、`check:comments`、`check:i18n`, `check:content`、`check:glossary`、`check:flows`、`check:skills`、`vp check`（フォーマット、リント、型）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `check:comments`                                                              | `scripts/check-comments.ts`: Git が追跡している、または追加しようとしているすべての TypeScript、JavaScript、CSS、YAML ファイルを、`.gitattributes` が `linguist-generated` と指定しているファイルを除いてパースし、1 行のリンクと固定したアクションのバージョンタグ以外のコメントがあれば、そのファイル、行、修正方法を示して失敗します。[コードスタイル](/docs/conventions/code-style#comments)を参照してください                                                                                                                                                                                                                                   |
| `check:content`                                                               | `scripts/check-content.ts`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `check:features`                                                              | `scripts/check-features.ts`: `scripts/features.ts` の各シナリオ（指定したときはそのシナリオだけ）について、シナリオの機能と、それを必要とする機能のファイルを削除し、残るファイルから、削除したものを指すインポート、リストの要素、プロパティ、JSX 要素、テスト、文、宣言を刈り込み、テストが 1 つも残らないテストファイルを削除します。そのうえで結果を一時ディレクトリにコピーし、刈り込んだファイルを `vp fmt` で整形し、生成ファイルを作ってから `tsc --noEmit` と `check:i18n` を実行します。刈り込めない参照が 1 つでもあれば、ファイルと行を示して失敗します。[テスト](/docs/conventions/testing#tests-follow-the-features)を参照してください |
| `check:fix`                                                                   | 同じ内容を `vp check --fix` で実行                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `check:flows`                                                                 | `scripts/check-flows.ts`: `playwright test --list` でブラウザーのスイートを一覧にし、`e2e/data/<feature>.flows.ts` のフローが、なくなったかスキップされたテストを挙げている場合や、テストがない理由を記載していない場合に失敗します。[テストカバレッジ](/docs/tooling/test-coverage)を参照してください                                                                                                                                                                                                                                                                                                                                               |
| `check:glossary`                                                              | `scripts/check-glossary.ts`：ドイツ語とポーランド語のメッセージ、ドキュメントページ、ブログ記事、変更履歴の項目、ナビゲーションのタイトル、コースのテキストをすべて読み、コード、リンク、引用を除いたうえで、その言語の用語集（`src/data/german-glossary.ts` または `src/data/polish-glossary.ts`）の使わない語の列にある語が活用形を含めて現れるたびに、ファイル、行、用語集が勧める語とともに失敗します。[ドイツ語スタイルガイド](/docs/conventions/german-style#glossary-check)と[ポーランド語スタイルガイド](/docs/conventions/polish-style#glossary-check)を参照                                                                                |
| `check:i18n`                                                                  | `scripts/check-i18n.ts`、`scripts/check-message-formats.ts`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `check:pre-commit`                                                            | `generate:cn`、`check:comments`、`check:i18n`, `check:content`、`check:glossary`、`vp staged`。pre-commit フックから実行されます                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `check:skills`                                                                | `scripts/check-skills.ts`: スキルが説明するパッケージが `skills:update` なしで動いた場合、`SKILL_SOURCES` と `skills-lock.json` が食い違う場合、インストール済みのスキルがロックと異なる場合に失敗します。[エージェントスキル](/docs/tooling/agent-skills#drift-checks)を参照                                                                                                                                                                                                                                                                                                                                                                        |
| `lint`                                                                        | `vp lint`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `format`                                                                      | `vp fmt`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `format:check`                                                                | `vp fmt --check`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `auth:verify:preview`, `auth:verify:production`                               | `scripts/verify-auth.ts`。`.env.<environment>` の OAuth クライアント ID がそれぞれのプロバイダーの形式であることを、ネットワークリクエストなしで確認します                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `polar:verify:development`, `polar:verify:preview`, `polar:verify:production` | `scripts/verify-polar.ts`。その環境の Polar の組織を、GET リクエストだけを使ってコードと比較します。[Polar の設定](/docs/getting-started/polar-setup)を参照してください                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

## 生成とメンテナンス

| スクリプト        | 実行内容                                                                                                                                                                                                                                                                                                       |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `content`         | `fumadocs-mdx`: `content/` から `.source/` を生成します                                                                                                                                                                                                                                                        |
| `generate:cn`     | `src/lib/cn.config.ts` から `.source/cn-tables.ts` にクラスマージ用のテーブルを生成します                                                                                                                                                                                                                      |
| `generate:routes` | `scripts/generate-routes.ts`: 開発サーバーもビルドも使わずに Vite の設定を解決し、TanStack Start のプラグインに `src/routeTree.gen.ts` を書き出させます                                                                                                                                                        |
| `cf-typegen`      | `development` 向けの `wrangler types`: `src/types/worker-configuration.d.ts` を再生成します                                                                                                                                                                                                                    |
| `typegen`         | `cf-typegen`、`generate:cn`、`content`                                                                                                                                                                                                                                                                         |
| `deps:audit`      | `scripts/audit-dependencies.ts`: 本番依存関係に `bun audit` を実行し、`src/data/dependency-audit.ts` に有効な例外のない high または critical のアドバイザリーがあれば失敗します。[依存関係](/docs/conventions/dependencies#security-advisories)を参照                                                          |
| `deps:sbom`       | cdxgen で `bun.lock` から本番依存関係の CycloneDX SBOM `sbom.cdx.json` を書き出し、続いて `scripts/verify-sbom.ts` が `package.json` のすべての依存関係が載っていることを確認します。[CI/CD](/docs/tooling/ci-cd#checks)を参照                                                                                 |
| `deps:update`     | `scripts/update-dependencies.ts`: 新しい Vite+ があれば `vp migrate`、範囲指定のすべての依存関係に `bun update --latest`、続いて `skills:update` を実行して各 GitHub Action を最新リリースに固定し、新しいリリースがある固定パッケージを表示します。[依存関係](/docs/conventions/dependencies#upgrading)を参照 |
| `skills:sync`     | `scripts/sync-skills.ts`: `skills-lock.json` からエージェントスキルを復元します                                                                                                                                                                                                                                |
| `skills:update`   | `scripts/sync-skills.ts update`: `skills-lock.json` のすべてのエージェントスキルを上流の最新コミットに更新します。さらにスキルが説明するパッケージのバージョンを `skills-packages.json` に記録します                                                                                                           |
| `clean`           | `.source`、`.tanstack`、`.wrangler`、`dist`、`coverage`、Playwright の出力、`*.tsbuildinfo` を削除します                                                                                                                                                                                                       |
| `clean:deep`      | `clean` に加えて `node_modules`                                                                                                                                                                                                                                                                                |
| `clean:hardcore`  | `clean:deep` に加えて `bun.lock` と `skills-lock.json`                                                                                                                                                                                                                                                         |
| `prepare`         | インストール時に実行: `vp config --no-agent`（Git フック）、`scripts/verify-git-hooks.ts`、`generate:cn`、`content`                                                                                                                                                                                            |

`clean` は、ローカルの開発用およびテスト用データベースと、デプロイスクリプトが書き出したシークレットファイルを含む `.wrangler` を削除します。残しておきたいローカルデータがあれば、先にエクスポートしてください。
