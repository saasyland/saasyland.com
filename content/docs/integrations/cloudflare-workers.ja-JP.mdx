アプリケーションは 1 つの Cloudflare Worker として動作します。`@cloudflare/vite-plugin` がビルドを行い、`CLOUDFLARE_ENV` で Wrangler の環境を選択します。`wrangler.jsonc` は `main` を `./src/server.ts` に設定し、`nodejs_compat` とオブザーバビリティを有効にし、静的ファイルを `ASSETS` バインディング経由で配信します。`/assets/*`、`/fonts/*`、`/robots.txt`、`/llms.txt` を除くすべてのパスで、最初に Worker が実行されます。ソースマップはアップロードしません（`upload_source_maps` は `false`）。Worker とソースマップを合わせると、Cloudflare が 1 回のアップロードで受け付けるサイズを超えるためです。

| 環境          | Worker                  | D1、KV、R2                            | ドメイン                |
| ------------- | ----------------------- | ------------------------------------- | ----------------------- |
| `development` | `saasyland-development` | リモートのプレビュー用リソース        | `localhost:3000`        |
| `preview`     | `saasyland-preview`     | プレビュー用リソース                  | `preview.saasyland.com` |
| `production`  | `saasyland`             | 本番用リソース                        | `saasyland.com`         |
| `test`        | `saasyland-test`        | `.wrangler/test` 内のローカルリソース | `127.0.0.1:3000`        |

どの環境も D1 を `DB`、KV を `CACHE`、R2 を `MEDIA` としてバインドし、必要なシークレットを列挙します。`test` 環境は `src/platform/testing/worker.ts` をエントリーとして使います。このエントリーは Resend と Polar へのリクエストを横取りし、Playwright 用のテスト専用エンドポイントを公開します。

## リクエストの流れ

`src/server.ts` がすべてのリクエストを処理します。

1. `/media/` 配下のパスは `serveMedia` に渡され、署名済みの動画ファイルが Workers のキャッシュまたは R2 から配信されます（[Cloudflare R2](/docs/integrations/cloudflare-r2) を参照）。以下の手順のうち、これに適用されるのはセキュリティヘッダーだけです。
2. `i18n.middleware.ts` の `resolveLocale` が、`/api` と `/_serverFn` 以外への `GET` と `HEAD` のドキュメントリクエストを検査します。言語エイリアスと正規でないロケールパスをステータス 308 でリダイレクトし、ロケール Cookie が URL のロケールと異なる場合はそれを通知します。
3. `/api` と `/_serverFn` 以外への `GET` と `HEAD` のリクエストは、まず `ASSETS` から配信されます。プリレンダリングされたページもここに含まれます。404 の場合は TanStack Start のハンドラーに処理が移ります。
4. ロケール Cookie の更新が必要な場合、Worker はそれをレスポンスに追加します。HTML レスポンスには、スタイルシートとそのロケールのフォントに対する `Link` プリロードヘッダーも付与されます。
5. HTML レスポンスには地域別の価格が適用されます。`cf-ipcountry` の国が購買力に基づく割引の対象である場合、`HTMLRewriter` が `<html>` に割引の属性を追加し、レスポンスは `private, no-cache` になります。
6. リダイレクト、API 呼び出し、メディアファイルを含むすべてのレスポンスに、[セキュリティと堅牢化](/docs/features/security) のセキュリティヘッダーを付けます。Worker を経由しないファイルには、`public/_headers` のより小さなセットが付きます。

## デプロイ

`bun run deploy:preview` と `bun run deploy:production` は、まずプレースホルダーのままの D1 と KV の ID を拒否する `scripts/verify-bindings.ts` を実行し、続いて対応するビルドと `wrangler deploy --secrets-file .env.<environment>` を実行します。`MEDIA` バケットは名前でバインドされるため、最初のデプロイの前に存在している必要があります。`wrangler r2 bucket create` で作成してください。ビルドは公開ページをプリレンダリングし、`scripts/verify-build.ts` と `scripts/optimize-prerendered-html.ts` を実行します。マイグレーションは別のコマンドです。[プレビューをデプロイする](/docs/getting-started/deploy-preview)と [CI/CD](/docs/tooling/ci-cd) を参照してください。
