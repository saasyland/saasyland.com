This policy covers saasyland.com, including the customer panel and the admin console, the code in this repository, and the paid CLI with its packages: `saasyland`, `create-saasyland` and `@saasyland/stack`. `SECURITY.md` at the repository root says the same.

## Report a vulnerability [#report]

Never report a vulnerability in a public issue, pull request or comment. Report it privately, in either of two ways:

- with GitHub's [private vulnerability reporting](https://github.com/saasyland/saasyland.com/security/advisories/new);
- by email to hello@saasyland.com.

Include what is affected (a URL, route, server function, file or CLI command), the steps to reproduce it or a proof of concept, the impact (what an attacker can read, change or do), and the commit or release you tested. Write in English or Polish.

The site publishes the same contact at <RepositoryFact name="securityTxtPath" />, in the format of RFC 9116, with the languages <RepositoryFact name="securityTxtLanguages" /> and a link to this page. The build writes the file from `src/lib/security-txt.ts`, and `security-txt.test.ts` fails once its `Expires` date has passed or lies more than a year ahead, so it is renewed before it goes stale.

## What happens after you report [#after-you-report]

These are targets, not guarantees:

1. **Acknowledge.** You get a reply within <RepositoryFact name="securityAcknowledgeWorkingDays" /> working days.
2. **Assess.** Within <RepositoryFact name="securityAssessWorkingDays" /> working days we confirm or decline the issue, rate its severity and, when it is confirmed, plan the fix.
3. **Fix.** The fix goes to every supported version below, and we keep you updated until it ships.
4. **Disclose.** Once the fix is available, we publish a GitHub security advisory that names the fixed versions and credits you, unless you prefer not to be named.

Please give us reasonable time to fix a confirmed issue before you disclose it.

## Supported versions [#supported-versions]

| Version                                                                                                                               | Supported |
| ------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| saasyland.com and `main`                                                                                                              | Yes       |
| The latest dated release of the site                                                                                                  | Yes       |
| The newest release of `saasyland`, `create-saasyland` and `@saasyland/stack` on npm's <RepositoryFact name="cliReleaseChannel" /> tag | Yes       |
| Earlier releases and commits                                                                                                          | No        |

Merges to `main` deploy to saasyland.com once CI passes, so a fix reaches the site first ([CI/CD](/docs/tooling/ci-cd)). The CLI and its packages are released together under one version, and a fix ships as a new release on npm; the [release notes](/docs/cli/releases) name it. On an earlier release, update to the newest one to get the fix.

## Scope [#scope]

In scope: saasyland.com, including the customer panel and the admin console, the code in this repository, the paid CLI, licence keys and activations, and the code the CLI generates.

Out of scope: vulnerabilities in third-party services such as Cloudflare, Polar and Resend, unless our configuration causes them, and scanner output without a demonstrated impact.

## EU Cyber Resilience Act [#cyber-resilience-act]

SaaSy Land reports actively exploited vulnerabilities and severe incidents that affect its products through the EU Single Reporting Platform, as the Cyber Resilience Act (Regulation (EU) 2024/2847) requires.
