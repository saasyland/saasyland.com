セットアップが必要なサードパーティのライブラリやサービスは、それぞれ `src/integrations` 配下に 1 つのフォルダーを持ちます。ファイル名は `<prefix>.<concern>.ts` の形式で、プレフィックスにはベンダーの短縮名を使います。

| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `affonso`        | `affonso.constants`、`affonso.program`、`affonso.referral`                                                                                                                                                   | 紹介パラメーター、ピクセルの URL、プログラム ID、チェックアウトのメタデータとして Polar に渡す紹介情報                                                                                                                 |
| `better-auth`    | `auth.server`、`auth.client`、`auth.access`、`auth.roles`、`auth.middleware`、`auth.routes`、`auth.session`、`auth.callbacks`、`auth.errors`、`auth.hooks`、`auth.zod`、`auth.constraints`、`auth.constants` | 認証の設定、ロール、サーバー関数のミドルウェア、ルートガード、セッションクエリ、コールバック URL、プロバイダー ID                                                                                                      |

## インテグレーションではないもの

- GitHub のスター数は、`src/lib/github.ts` のサーバー関数で取得し、KV にキャッシュします。
- レート制限は `src/lib/rate-limit.ts` が担い、`rate_limit` テーブルに保存します。
- Cloudflare のバインディングにアダプターは不要です。サーバーコードは `cloudflare:workers` の `env` からバインディングを読み取ります。

## ビジネスロジックはモジュールに置く

インテグレーションは、ベンダーを設定するためのものです。アプリケーションのデータに関する判断は、そのテーブルを所有するモジュールが担います。

- `src/integrations/better-auth/auth.server.ts` の `plugins` の 1 つである Polar プラグインは、`POLAR_WEBHOOK_SECRET` で Webhook の署名を検証し、各イベントを `src/integrations/polar/polar.webhooks.ts` の `handlePolarEvent` に渡します。`handlePolarEvent` は、そのイベントを列挙している `POLAR_EVENT_HANDLERS` のすべての要素にイベントを渡します。ライセンスの要素は `src/modules/license/license.webhooks.ts` の `licenseWebhookHandlers` を呼び出し、このハンドラーがライセンスのユースケースを呼び出します。注文とサブスクリプションの要素は `recordOrder` と `recordSubscription` を呼び出します。ライセンスのプランの商品 ID である `POLAR_PRODUCT_IDS` もライセンスの機能に属し、`src/modules/license/license.utils.ts` にあります。
- Better Auth のメールフックは、verification、account、user の各モジュールの `sendVerifyEmail`、`sendExistingAccountEmail`、`sendResetPasswordEmail`、`sendPasswordChangedEmail`、`sendDeleteAccountEmail`、`sendChangeEmailConfirmationEmail` を直接呼び出します。
- ユースケースは、呼び出し元から渡されたロケールでメールを送信します（確認メールはコールバック URL からロケールを読み取ります）。テンプレートの名前空間を読み込み、テンプレートをレンダリングしてから `sendEmail` を呼び出します。

```ts
const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotency: { purpose: VERIFICATION_EMAIL_PURPOSE.VERIFY_EMAIL, token: crypto.randomUUID() },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```
