---
title: "Core 共有カーネル"
description: "すべてのモジュールが共有する、src/modules/_core のエラー語彙、カタログ、ヘルパー。"
---

`src/modules/_core` は、テーブルを所有しない唯一のモジュールフォルダーです。複数のモジュールが必要とする値とヘルパーをここにまとめ、各モジュールで再定義しないようにしています。

## 定数

| ファイル                | 内容                                                                                                                 |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `constants/errors.ts`   | `ERROR_CODES`、`ErrorCode` 型、`AppError` クラス                                                                     |
| `constants/api.ts`      | `HTTP_STATUS`、`cf-ipcountry` と `cf-connecting-ip` のヘッダー名、セキュリティヘッダー、ビルドモードごとの許可ホスト |
| `constants/locale.ts`   | `LOCALES` カタログ、`LocaleCode`、`getLocaleName`、`getLocaleDirection`                                              |
| `constants/country.ts`  | `COUNTRIES` カタログと `CountryCode`                                                                                 |
| `constants/currency.ts` | `CURRENCIES` カタログと `CurrencyCode`                                                                               |
| `constants/timezone.ts` | `TIMEZONES` カタログと `TimezoneCode`                                                                                |
| `constants/pricing.ts`  | ストアの通貨 `DEFAULT_CURRENCY_CODE`、通貨のフォーマット、地域別価格の倍率、地域別価格のクッキー                     |
| `constants/ordering.ts` | `MOVE_DIRECTION`（`up`、`down`）、`MOVE_DIRECTIONS`、`MoveDirection` 型                                              |

ロケールカタログには、既知のすべてのロケールが含まれます。アプリケーションが実際に提供するロケールは、`src/integrations/use-intl/i18n.config.ts` の `I18N.SUPPORTED_LOCALES` です。

## ユーティリティ

- `utils/localized-text.ts`：JSON として保存するロケールごとのテキスト `LocalizedText`、`en-US` を必須とし各テキストを最大 <RepositoryFact name="localizedTextMaxLength" /> 文字に制限する `localizedTextSchema`、`en-US` にフォールバックする `localize`
- `utils/ordering.ts`：最大の `position` に 1 を足した値を返す `nextPosition` と、項目を隣と入れ替えて一覧を 1 から番号付けし直す `reorder`。コース、チャプター、レッスンのユースケースはこれらで `position` を詰めた状態に保ちます
- `utils/pagination.ts`：`paginationSchema`（`pageIndex`、`pageSize`）、`DEFAULT_PAGINATION`、`DEFAULT_PAGE_SIZE`
- `utils/zod-fields.ts`：`idField`、`localeField`、`slugField` などの再利用可能な Zod フィールド

## エラー

エラークラスは 1 つ、エラーコードの一覧も 1 つだけです。

```ts
export const ERROR_CODES = {
  AUTH_API_ERROR: "AUTH_API_ERROR",
  CONFLICT: "CONFLICT",
  FORBIDDEN: "FORBIDDEN",
  INTERNAL_ERROR: "INTERNAL_ERROR",
  LICENSE_ALREADY_ACTIVE: "LICENSE_ALREADY_ACTIVE",
  NOT_FOUND: "NOT_FOUND",
  TOO_MANY_REQUESTS: "TOO_MANY_REQUESTS",
  UNAUTHORIZED: "UNAUTHORIZED",
  VALIDATION: "VALIDATION",
} as const

export type ErrorCode = (typeof ERROR_CODES)[keyof typeof ERROR_CODES]

export class AppError extends Error {
  readonly code: ErrorCode

  constructor(code: ErrorCode, message: string = code) {
    super(message)
    this.name = "AppError"
    this.code = code
  }
}
```

サーバー関数は `AppError` をスローします。それ以外のエラーは `withRequest` ミドルウェアが正規化します。Better Auth の API エラーは、Better Auth のエラーキーをメッセージとする `AUTH_API_ERROR` に、Zod のエラーは `VALIDATION` になり、未知のエラーはログに記録されたうえで `INTERNAL_ERROR` になります。ブラウザでは、`src/hooks/use-error-message.ts` の `useErrorMessage()` がメッセージを `auth.errors.*` または `errors.codes.*` の翻訳に対応付けます。
