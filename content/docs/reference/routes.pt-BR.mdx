title: "Rotas"
description: "Todas as páginas e caminhos de API, com a constante em ROUTES, o arquivo de rota e o guard de cada um."
---

Todo caminho tem uma constante em `ROUTES` (`src/routes.ts`), declarada no `src/areas/<area>.shared.ts` da sua área (veja [Caminhos e navegação](/docs/conventions/routes#paths-and-navigation)). Os links usam a constante, por exemplo `<Link to={ROUTES.SIGN_IN}>`, e o router adiciona o prefixo de locale. Cada página abaixo também é servida sob todos os prefixos de locale que não são o padrão, por exemplo `/pl-PL/terms`.

## Páginas públicas

Estas páginas ficam dentro do layout `_site`, que renderiza o cabeçalho do site. Todas, exceto a documentação, também ficam dentro do layout `_marketing` (moldura da página e rodapé), o layout da documentação renderiza o mesmo rodapé por conta própria, e o blog e a documentação têm layouts próprios dentro deles. Todas são pré-renderizadas, exceto as páginas da newsletter.

| ----------------------------- | ------------------------ | -------------------------------------------------------------- |
| `/`                           | `HOME`                   | `_site._marketing.index.tsx`                                   |
| `/licence`                    | `LICENCE`                | `_site._marketing.licence.tsx`                                 |
| `/privacy`                    | `PRIVACY`                | `_site._marketing.privacy.tsx`                                 |
| `/terms`                      | `TERMS`                  | `_site._marketing.terms.tsx`                                   |
| `/refunds`                    | `REFUNDS`                | `_site._marketing.refunds.tsx`                                 |

| `/affiliates`                 | `AFFILIATES`             | `_site._marketing.affiliates.tsx`                              |
| `/newsletter/confirm`         | `NEWSLETTER_CONFIRM`     | `_site._marketing.newsletter.confirm.tsx`                      |
| `/newsletter/unsubscribe`     | `NEWSLETTER_UNSUBSCRIBE` | `_site._marketing.newsletter.unsubscribe.tsx`                  |
| `/blog`                       | `BLOG`                   | `_site._marketing.blog.tsx`, `_site._marketing.blog.index.tsx` |

`/*` é qualquer endereço que nenhuma outra rota reconhece: `_site._marketing.$.tsx` lança `notFound()`, então o servidor responde 404 com a página não encontrada, renderizada a cada requisição (veja [Página não encontrada](/docs/features/landing-page#not-found-page)).

`/blog/rss.xml` não tem arquivo de rota: `scripts/generate-seo-files.ts` grava o feed de cada idioma depois do build (veja [Feed RSS](/docs/features/blog#feed)).

## Cursos

O layout de `/courses` (`_site._marketing.courses.tsx`) fica dentro dos layouts `_site` e `_marketing`, como o blog, e não tem guard: o servidor verifica o nível de acesso de cada aula (veja [Cursos](/docs/features/courses)). Essas páginas leem o D1 a cada requisição e não são pré-renderizadas.

| Caminho                      | Constante | Arquivo de rota                                                      |
| ---------------------------- | --------- | -------------------------------------------------------------------- |
| `/courses`                   | `COURSES` | `_site._marketing.courses.tsx`, `_site._marketing.courses.index.tsx` |
| `/courses/<course>`          | nenhuma   | `_site._marketing.courses.$course.index.tsx`                         |
| `/courses/<course>/<lesson>` | nenhuma   | `_site._marketing.courses.$course.$lesson.tsx`                       |

## API

Os caminhos de API nunca são localizados.

| Caminho                                      | Constante       | Arquivo de rota                                                                                                                                    |
| -------------------------------------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/api`                                       | `API`           | `api/index.ts`                                                                                                                                     |
| `/api/auth/*`                                | `API_AUTH_BASE` | `api/auth.$.ts`                                                                                                                                    |
| <RepositoryFact name="cliApiBasePath" />`/*` | nenhuma         | `api/cli.v1.license.ts`, `api/cli.v1.activations.ts`, `api/cli.v1.activations.$activationId.ts`, `api/cli.v1.activations.$activationId.bundles.ts` |

Os caminhos da API de licenças da CLI vêm do contrato dela, `API_BASE_PATH` e `API_ROUTE` em `@saasyland/stack/api`, e `src/routes/api/__test__/cli.v1.test.ts` verifica se o roteador envia cada um deles para o seu arquivo de rota (veja [API de licenças da CLI](/docs/features/cli-licence-api)).

`ROUTES.API_AUTH` lista os caminhos dos endpoints próprios do Better Auth e dos seus plugins de administração e de dois fatores, relativos a `/api/auth`; `auth.server.ts` os usa para isentar endpoints do rate limiting, e `INPUT_POLICY` em `auth.hooks.ts` para validar os endpoints que aceitam uma senha, um nome, um e-mail ou uma imagem. `ROUTES.API_AUTH_POLAR` lista os webhooks do plugin da Polar, que a área da Polar isenta do rate limiting; ele e `API_AUTH_CUSTOMER_PORTAL` ficam em `src/areas/polar.shared.ts`. `API_AUTH_CUSTOMER_PORTAL` e `API_AUTH_VERIFY_EMAIL` são caminhos completos para endpoints do Better Auth, montados a partir de `API_AUTH_BASE`. `AUTH` e `NEWSLETTER` não têm página própria; junto com `ADMIN`, `APP`, `API` e `COURSES`, elas marcam as áreas que nunca são pré-renderizadas (`UNLISTED_ROUTES` no `src/areas/shared.ts`), e `verify-build.ts` reprova um build que tenha pré-renderizado uma página sob qualquer uma delas.

## Mídia

`/media/<expiry>.<signature>/<videoId>/<file>` serve os arquivos de vídeo assinados. Ele não tem constante em `ROUTES` nem arquivo de rota: `src/server.ts` o envia para `serveMedia` antes do middleware de locale, então ele nunca é localizado. Veja [Cloudflare R2](/docs/integrations/cloudflare-r2).

`/media/covers/<courseId>/<file>` serve as capas públicas dos cursos por meio de `serveCover`, e `/media/downloads/<expiry>.<signature>/<attachmentId>/<fileName>` os materiais assinados das aulas por meio de `serveAttachment`. O handler de `/media/` da área de cursos os envia para lá, então eles também nunca são localizados. Veja [Capas dos cursos](/docs/features/courses#course-covers).

<RepositoryFact name="cliBundleUrlPath" /> serve da mesma forma os pacotes de templates assinados da CLI, por meio de `serveBundle`, e
recebe o seu prefixo de `BUNDLE_PATH_PREFIX` em `license.constants.ts`. Veja [API de licenças da
CLI](/docs/features/cli-licence-api#template-bundles).
