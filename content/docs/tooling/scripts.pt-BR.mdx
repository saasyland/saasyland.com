Execute os scripts a partir da raiz do repositório com `bun run <script>`. Os scripts que chamam o Wrangler, e o `db:generate`, que chama o drizzle-kit, os executam via `vp exec`, que pega o binário de `node_modules/.bin`, então sempre usam as versões travadas no `bun.lock`.

## Desenvolvimento e build

| Script             | Executa                                                                                                                                       |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `dev`              | `generate:cn`, `content` e `vp dev` no ambiente `development` em http://localhost:3000                                                        |
| `build`            | O mesmo que `build:preview`                                                                                                                   |
| `build:preview`    | Limpa `dist`, `generate:cn`, `content`, `vp build` para `preview`, `scripts/verify-build.ts preview` e `scripts/optimize-prerendered-html.ts` |
| `build:production` | As mesmas etapas para `production`                                                                                                            |
| `build:test`       | As mesmas etapas para o ambiente `test`                                                                                                       |
| `start`            | `vp preview` do build mais recente em http://127.0.0.1:3000                                                                                   |
| `start:test`       | `vp preview` do build de testes                                                                                                               |

`verify-build.ts` verifica se `.wrangler/deploy/config.json` aponta para `dist/server/wrangler.json` e se esse arquivo faz o deploy do Worker que o `wrangler.jsonc` define para o ambiente e, em seguida, o idioma do documento, os links canônicos e alternativos da página inicial e das páginas legais localizadas, as fontes, que páginas protegidas e aliases de locale não foram pré-renderizados, que todas as páginas da documentação e todos os posts publicados do blog foram pré-renderizados e que nenhum asset do cliente importa `cloudflare:workers`. `optimize-prerendered-html.ts` remove das páginas pré-renderizadas as dicas `modulepreload` de dependências e mantém a dica da entrada com baixa prioridade.

## Deploy

| Script              | Executa                                                                                                                                                                                                             |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `deploy:preview`    | `scripts/verify-bindings.ts preview`, `build:preview`, `scripts/prepare-deploy-secrets.ts preview`, `db:migrate:preview`, `wrangler deploy` de `dist/server/wrangler.json` e `scripts/verify-deployment.ts preview` |
| `deploy:production` | As mesmas etapas para `production`                                                                                                                                                                                  |

- `verify-bindings.ts` falha quando o ambiente não tem um binding `DB`, `CACHE` ou `MEDIA` ou ainda tem um ID de D1 ou KV de placeholder, e quando a produção compartilha com o preview o banco de dados, o namespace ou o bucket.
- `prepare-deploy-secrets.ts` lê de `.env.<environment>` as chaves listadas em `secrets.required` do ambiente, falha quando alguma está ausente ou vazia e grava apenas essas chaves em `.wrangler/secrets.<environment>.json`. As outras variáveis do arquivo não são enviadas.
- As migrações rodam depois do build e antes do deploy, então um build com falha nunca toca o banco de dados e o novo Worker nunca inicia com um schema antigo.
- O deploy executa `env -u CLOUDFLARE_ENV vp exec wrangler deploy --config dist/server/wrangler.json --secrets-file .wrangler/secrets.<environment>.json`. A configuração gerada pelo build já aponta para um único ambiente; um `CLOUDFLARE_ENV` que tenha ficado no shell faria o Wrangler procurar uma seção de ambiente que esse arquivo não tem.
- `verify-deployment.ts` faz requisições a <RepositoryFact name="liveSiteCheckPaths" /> no domínio do ambiente e falha a menos que cada um responda `200` com o tipo de conteúdo esperado. Ele tenta três vezes um caminho que falha, com cinco segundos de intervalo, e não altera nada. `bun scripts/verify-deployment.ts <preview|production>` verifica um site no ar de forma independente.

## Geração e manutenção

| Script           | Executa                                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------- |
| `content`        | `fumadocs-mdx`: gera `.source/` a partir de `content/`                                                  |
| `generate:cn`    | Gera as tabelas de mesclagem de classes em `.source/cn-tables.ts` a partir de `src/lib/cn.config.ts`    |
| `cf-typegen`     | `wrangler types` para `development`: gera novamente `src/types/worker-configuration.d.ts`               |
| `typegen`        | `cf-typegen`, `generate:cn` e `content`                                                                 |
| `skills:sync`    | `scripts/sync-skills.ts`: restaura as skills para agentes a partir de `skills-lock.json`                |
| `clean`          | Remove `.source`, `.tanstack`, `.wrangler`, `dist`, `coverage`, a saída do Playwright e `*.tsbuildinfo` |
| `clean:deep`     | `clean` e `node_modules`                                                                                |
| `clean:hardcore` | `clean:deep`, `bun.lock` e `skills-lock.json`                                                           |
| `prepare`        | Executado na instalação: `vp config --no-agent` (hooks do Git), `generate:cn` e `content`               |

`clean` apaga `.wrangler`, incluindo os bancos de dados locais de desenvolvimento e de testes e os arquivos de secrets gravados pelos scripts de deploy, então exporte antes os dados locais que quiser manter.
