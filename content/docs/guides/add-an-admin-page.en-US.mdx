---
title: "Add an admin page"
description: "Register the route, sidebar entry, messages and widgets of a new admin page."
---

Admin pages are flat route files under the `/admin` layout (`src/routes/admin.tsx`), which runs `requireAdmin` in `beforeLoad` and renders the sidebar, breadcrumbs and command palette. The steps below add a page at `/admin/reports`; `src/routes/admin.orders.index.tsx` is a complete real example.

## 1. Add the path

Declare the path in its area's routes file, here a new `src/data/reports.routes.ts`, and add a new file to the barrel `src/data/routes.entries.ts`. `ROUTES` then has it:

```ts
export const ADMIN_REPORTS = "/admin/reports"
```

```ts
export { ADMIN_REPORTS } from "~/src/data/reports.routes"
```

## 2. Create the route file

Create `src/routes/admin.reports.tsx`. The route defines only the page component, `NAMESPACE`, the loader, `head` and `pendingComponent`; the router generator registers the file in `src/routeTree.gen.ts`.

```tsx
import type { JSX } from "react"

import { createFileRoute } from "@tanstack/react-router"
import { useTranslations } from "use-intl/react"

import { loadPageMetadata, preloadNamespaces } from "~/src/integrations/use-intl/i18n.messages"
import { getCurrentLocale } from "~/src/integrations/use-intl/i18n.utils"

import { pageHead } from "~/src/lib/seo"

import { AdminPageHeader } from "~/src/presentation/components/custom/admin/admin-page-header"
import { AdminReportsPending } from "~/src/presentation/components/custom/admin/reports-pending"
import { ReportStats } from "~/src/presentation/components/custom/admin/reports/report-stats"

import { ROUTES } from "~/src/routes"

const ReportsPage = (): JSX.Element => {
  const t = useTranslations("pages.admin.reports")

  return (
    <div className="flex w-full flex-col space-y-8">
      <AdminPageHeader description={t("metadata.description")} title={t("metadata.title")} />

      <ReportStats />
    </div>
  )
}

const NAMESPACE = "pages.admin.reports"

export const Route = createFileRoute("/admin/reports")({
  component: ReportsPage,
  head: pageHead(ROUTES.ADMIN_REPORTS),
  loader: async ({ context }) => {
    const locale = getCurrentLocale()
    const [metadata] = await Promise.all([
      loadPageMetadata({ locale, namespace: NAMESPACE }),
      preloadNamespaces({ locale, namespaces: [NAMESPACE], queryClient: context.queryClient }),
    ])
    return { locale, metadata }
  },
  pendingComponent: AdminReportsPending,
  staticData: { namespaces: [NAMESPACE] },
})
```

Queries the page needs go into the same `Promise.all`, for example `context.queryClient.query({ ...getUsersQuery, staleTime: "static" })` in `src/routes/admin.users.all.tsx`. `pageHead` builds the title, description, canonical URL and alternate-locale links from the loader's `metadata`. `AdminReportsPending` is the page's own skeleton, shown only when a navigation takes longer than <RepositoryFact name="navigationPendingMs" unit="millisecond" />. Write it in its area's skeleton file, here a new `custom/admin/reports-pending.tsx`, from `AdminPageHeaderPending` in `admin-page-header.tsx` for the header and the blocks in `pending-blocks.tsx`, so that it mirrors the page's layout. The admin layout skeleton reads it from the route, so it also shows when someone enters `/admin/reports` from outside the admin area.

See [Loading skeletons](/docs/architecture/delivery-layer#loading-skeletons).

## 3. Add the sidebar entry

Add an entry with `placement: NAVIGATION_PLACEMENT.ADMIN` to its area's menu list, here `REPORTS_NAVIGATION` in a new `src/data/reports.navigation.ts`, and add a new file to the barrel `src/data/navigation.entries.ts`. The entry names its `area`, its sidebar group, its `lucide-react` icon and its `order` inside the group: Dashboard is 10, so 30 places Reports after it.

```ts
{
  area: AREA,
  group: ADMIN_NAVIGATION_GROUP.OVERVIEW,
  icon: FileText,
  key: "reports",
  order: 30,
  placement: NAVIGATION_PLACEMENT.ADMIN,
  to: ROUTES.ADMIN_REPORTS,
},
```

Label it with `admin.reports` in the area's `messages/<locale>/navigation.reports.json`, in every locale. A new group also needs a value in `ADMIN_NAVIGATION_GROUP`, its place in `ADMIN_NAVIGATION_GROUPS` and `groups.<group>`. The sidebar, the breadcrumbs and the ⌘K command palette all read `ADMIN_NAVIGATION` (`src/data/navigation.ts`), so the page appears in all three. The landing page counts it among the admin sections, and the admin rail of the `app-tour` landing video lists it after the video is rendered again (see `remotion/README.md`). A third URL segment, such as `/admin/reports/create`, shows the breadcrumb label `breadcrumbs.create` from the same `navigation.reports.json` when the area defines it, and no third crumb when it does not.

## 4. Add the page messages

Create `messages/<locale>/pages.admin.reports.json` in every locale. `metadata` is required because the loader reads it for the document head:

```json
{
  "metadata": {
    "title": "Reports",
    "description": "Revenue and usage reports."
  }
}
```

## 5. Add the widgets

Put each widget, dialog, form and table column set in its own file under `src/presentation/components/custom/admin/reports/`, for example `report-stats.tsx` or `report-columns.tsx`. Widgets call `useTranslations("pages.admin.reports")` and read their own data with `useSuspenseQuery`; the page passes them no labels or data. Tables use the `DataGrid`; see [Add a data grid](/docs/guides/add-a-data-table).

## 6. Protect and test

- The layout guard covers page access. Every server function the page calls still needs `authorized(permission)`; see [Roles and permissions](/docs/guides/roles-and-permissions).
- `/admin` is excluded from prerendering.
- Add the area's route tests in `src/routes/__test__/admin-<area>-routes.component.test.tsx` and `admin-<area>-loaders.test.ts`, widget tests in `src/presentation/components/custom/admin/__test__/` and the page to `e2e/data/<area>.pages.ts`, then run `bun run check:i18n` and `bun run test:coverage`.
