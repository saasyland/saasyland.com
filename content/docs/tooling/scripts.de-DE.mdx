Führen Sie Skripte im Stammverzeichnis des Repositorys mit `bun run <script>` aus. Die Skripte, die Wrangler aufrufen, und `db:generate`, das drizzle-kit aufruft, starten diese Werkzeuge über `vp exec`, das die Binärdatei aus `node_modules/.bin` nimmt, sodass sie immer die in `bun.lock` festgelegten Versionen verwenden.

## Entwicklung und Build

| Skript             | Führt aus                                                                                                                                       |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `dev`              | `generate:cn`, `content` und `vp dev` in der Umgebung `development` unter http://localhost:3000                                                 |
| `build`            | Wie `build:preview`                                                                                                                             |
| `build:preview`    | `dist` leeren, `generate:cn`, `content`, `vp build` für `preview`, `scripts/verify-build.ts preview` und `scripts/optimize-prerendered-html.ts` |
| `build:production` | Dieselben Schritte für `production`                                                                                                             |
| `build:test`       | Dieselben Schritte für die Umgebung `test`                                                                                                      |
| `start`            | `vp preview` des letzten Builds unter http://127.0.0.1:3000                                                                                     |
| `start:test`       | `vp preview` des Test-Builds                                                                                                                    |

`verify-build.ts` prüft, dass `.wrangler/deploy/config.json` auf `dist/server/wrangler.json` verweist und dass diese Datei den Worker deployt, den `wrangler.jsonc` für die Umgebung nennt, danach die Dokumentsprache, die kanonischen und alternativen Links der lokalisierten Startseite und der Rechtstexte, die Schriften, dass geschützte Seiten und Sprachkürzel nicht vorab gerendert wurden, dass jede Doku-Seite und jeder veröffentlichte Blogbeitrag vorab gerendert wurde und dass kein Client-Asset `cloudflare:workers` importiert. `optimize-prerendered-html.ts` entfernt `modulepreload`-Hinweise für Abhängigkeiten aus vorab gerenderten Seiten und behält den Hinweis für den Einstiegspunkt mit niedriger Priorität bei.

## Deployment

| Skript              | Führt aus                                                                                                                                                                                                                                      |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `deploy:preview`    | `scripts/verify-bindings.ts preview`, `polar:verify:preview`, `build:preview`, `scripts/prepare-deploy-secrets.ts preview`, `db:migrate:preview`, `wrangler deploy` von `dist/server/wrangler.json` und `scripts/verify-deployment.ts preview` |
| `deploy:production` | Dieselben Schritte für `production`                                                                                                                                                                                                            |

- `verify-bindings.ts` schlägt fehl, wenn der Umgebung ein `DB`-, `CACHE`- oder `MEDIA`-Binding fehlt oder sie noch eine Platzhalter-ID für D1 oder KV enthält, und wenn die Produktion ihre Datenbank, ihren Namespace oder ihren Bucket mit Preview teilt.
- `polar:verify:<environment>` stoppt das Deployment vor dem Build, wenn die Polar-Organisation in `.env.<environment>` nicht mit dem Code übereinstimmt.
- `prepare-deploy-secrets.ts` liest die Schlüssel, die in `secrets.required` der Umgebung aufgeführt sind, aus `.env.<environment>`, schlägt fehl, wenn einer fehlt oder leer ist, und schreibt nur diese Schlüssel nach `.wrangler/secrets.<environment>.json`. Andere Variablen in der Datei werden nicht hochgeladen.
- Migrationen laufen nach dem Build und vor dem Deployment, sodass ein fehlgeschlagener Build die Datenbank nie berührt und der neue Worker nie mit einem älteren Schema startet.
- Das Deployment führt `env -u CLOUDFLARE_ENV vp exec wrangler deploy --config dist/server/wrangler.json --secrets-file .wrangler/secrets.<environment>.json` aus. Die gebaute Konfiguration zielt bereits auf eine einzige Umgebung; ein in der Shell verbliebenes `CLOUDFLARE_ENV` würde Wrangler nach einem Umgebungsabschnitt suchen lassen, den diese Datei nicht hat.
- `verify-deployment.ts` ruft `/`, `/courses`, `/robots.txt`, `/api` und `/api/auth/get-session` auf der Domain der Umgebung ab und schlägt fehl, sofern nicht jeder Pfad mit `200` und dem erwarteten Inhaltstyp antwortet. Einen fehlschlagenden Pfad ruft es dreimal im Abstand von fünf Sekunden ab und ändert nichts. `bun scripts/verify-deployment.ts <preview|production>` prüft eine Live-Website für sich allein.

## Generierung und Wartung

| Skript           | Führt aus                                                                                                    |
| ---------------- | ------------------------------------------------------------------------------------------------------------ |
| `content`        | `fumadocs-mdx`: erzeugt `.source/` aus `content/`                                                            |
| `generate:cn`    | Erzeugt die Tabellen für das Zusammenführen von Klassen in `.source/cn-tables.ts` aus `src/lib/cn.config.ts` |
| `cf-typegen`     | `wrangler types` für `development`: erzeugt `src/types/worker-configuration.d.ts` neu                        |
| `typegen`        | `cf-typegen`, `generate:cn` und `content`                                                                    |
| `skills:sync`    | `scripts/sync-skills.ts`: stellt die Agent-Skills aus `skills-lock.json` wieder her                          |
| `clean`          | Entfernt `.source`, `.tanstack`, `.wrangler`, `dist`, `coverage`, die Playwright-Ausgabe und `*.tsbuildinfo` |
| `clean:deep`     | `clean` und `node_modules`                                                                                   |
| `clean:hardcore` | `clean:deep`, `bun.lock` und `skills-lock.json`                                                              |
| `prepare`        | Läuft bei der Installation: `vp config --no-agent` (Git-Hooks), `generate:cn` und `content`                  |

`clean` löscht `.wrangler` einschließlich der lokalen Entwicklungs- und Testdatenbanken und der Secrets-Dateien, die die Deploy-Skripte schreiben; exportieren Sie daher vorher alle lokalen Daten, die Sie behalten möchten.
