---

Nazwy wszystkich plików i folderów są w kebab-case. Nazwy są złożone, a nie zagnieżdżone: sufiks mówi, do czego służy plik, więc `src/modules/course/course.constants.ts` leży obok `course.schema.ts`, a nie w folderze `constants/`. Wyjątkami są `src/routes`, gdzie kropki oddzielają segmenty ścieżki, oraz pliki generowane, takie jak `src/routeTree.gen.ts`.

## Gdzie trafia kod

Miejsce nowego kodu wybierz według tego, co ten kod robi, sprawdzając wiersze po kolei:

| Kod                                                                                                                      | Znajduje się w                                                                                                       | Przykład                                                                                                                                        |
| ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Odpowiada za tabelę bazy danych                                                                                          | `src/modules/<table>/`                                                                                               | `src/modules/course/`                                                                                                                           |
| Jest funkcją serwerową, która nie czyta żadnej tabeli (zewnętrzne API, treść)                                            | `src/lib/<topic>.ts` lub jedynej trasie, która jej używa                                                             | `src/lib/github.ts`                                                                                                                             |
| Konfiguruje lub adaptuje bibliotekę albo usługę dostawcy                                                                 | `src/integrations/<vendor>/`                                                                                         | `src/integrations/polar/polar.config.ts`                                                                                                        |
| Renderuje UI                                                                                                             | `src/presentation/components/custom/`                                                                                | `custom/admin/courses/course-form.tsx`                                                                                                          |
| Jest hookiem React używanym przez kilka komponentów                                                                      | `src/hooks/use-<name>.ts`                                                                                            | `src/hooks/use-error-message.ts`                                                                                                                |
| Jest providerem dla całej aplikacji                                                                                      | `src/providers/<name>-provider.tsx`                                                                                  | `src/providers/theme-provider.tsx`                                                                                                              |
| Jest stałą lub listą literałów czytaną przez kilka plików                                                                | `src/data/<topic>.ts`, a stałe ekranów panelu administracyjnego w `src/data/admin.ts` lub `src/data/admin-<page>.ts` | `MARKETING_SECTION_IDS` w `src/data/navigation.constants.ts`, `POLAR_PRODUCT_COLUMN_SIZES` w `src/data/admin-products.ts`                       |
| Jest ścieżką lub pozycją menu                                                                                            | `src/routes.ts` dla ścieżki, lista danego menu w `src/data/navigation.ts` dla pozycji                                | `ROUTES.ADMIN.COURSES.INDEX`, `ADMIN_NAVIGATION`; zobacz [Ścieżki i nawigacja](/docs/conventions/routes#paths-and-navigation)                   |
| Jest wpisem listy, którą renderuje komponent, na przykład statystyką pulpitu                                             | lista w komponencie, który ją renderuje                                                                              | `DASHBOARD_STATS` w `custom/admin/dashboard/stats.tsx`                                                                                          |
| Jest deklaracją uprawnień                                                                                                | `APP_STATEMENTS` w `src/integrations/better-auth/auth.access.ts`                                                     | `course: ["create", "read", "update", "delete"]`                                                                                                |
| Jest wtyczką Vite dostawcy                                                                                               | `src/integrations/<vendor>/<vendor>.vite.ts`                                                                         | `src/integrations/zod/zod.vite.ts`; zobacz [Co uruchamiają Worker i build](/docs/architecture/platform-layer#what-the-worker-and-the-build-run) |
| Jest sprawdzeniem działającej witryny                                                                                    | `LIVE_SITE_CHECKS` w `src/lib/deployment.ts`                                                                         | sprawdzenie kanału bloga                                                                                                                        |
| Jest drobnym narzędziem bez lepszego miejsca                                                                             | `src/lib/<name>.ts`                                                                                                  | `src/lib/search-params.ts`, `src/lib/cn.ts`                                                                                                     |
| Jest kodem błędu, stałą HTTP, katalogiem, polem Zod lub danymi wejściowymi przypadku użycia współdzielonymi przez moduły | `src/modules/_core/`                                                                                                 | `src/modules/_core/constants/errors.ts`                                                                                                         |
| Konfiguruje środowisko uruchomieniowe testów                                                                             | `src/platform/testing/`                                                                                              | `src/platform/testing/mocks/cloudflare.ts`                                                                                                      |

Stała lub funkcja pomocnicza używana przez jeden plik zostaje w tym pliku. Przenosi się go dopiero wtedy, gdy potrzebuje go drugi plik.

## Foldery komponentów

`src/presentation/components/custom` zawiera wyłącznie komponenty `.tsx`, w płaskich folderach:

- Komponent współdzielony przez różne części serwisu leży na najwyższym poziomie: `custom/data-grid.tsx`, `custom/newsletter-form.tsx` oraz `custom/pricing.tsx`, który renderuje karty pakietów zarówno na stronie głównej, jak i w `/app/license`.
- Komponent jednej części serwisu leży w jej folderze: `custom/courses/curriculum.tsx`, `custom/auth/sign-in-form.tsx`.
- Strona administracyjna z kilkoma widżetami dostaje własny folder: `custom/admin/courses/course-form.tsx`, `custom/admin/users/delete-user-dialog.tsx`.
- `custom/landing-page/` ma dwa foldery: `components/` i `sections/`.

Jeden widżet, okno dialogowe, formularz lub zestaw kolumn na plik. Kolumny tabeli to `<entity>-columns.tsx` (`course-columns.tsx`); szkielety są zgrupowane w `<feature>-pending.tsx` w folderze layoutu, który je wyświetla (`admin/products-pending.tsx`, `app/license-pending.tsx`, `legal-pending.tsx` dla layoutu publicznego, `courses/courses-pending.tsx`).

Niedozwolone:

- Podfoldery `components/`, `constants/`, `hooks/`, `lib/` lub `types/` w folderze komponentów.
- Plik `.ts` obok komponentów `.tsx`. Tokeny animacji znajdują się w `src/integrations/motion/motion.tokens.ts`, a funkcje pomocnicze pól w `src/integrations/tanstack-form/form.fields.ts`.
- Dzielenie komponentu na `x.tsx` i `x-content.tsx`, aby leniwie ładować jego połowę, albo fasada nad API dostawcy, taka jak funkcja pomocnicza `toast`. Importuj bibliotekę dostawcy bezpośrednio.

`src/presentation/components/shadcn/` zawiera prymitywy shadcn (zobacz [Komponenty i stylowanie](/docs/conventions/components)), `src/presentation/emails/` szablony React Email, `src/presentation/styles/` arkusze stylów, a `src/presentation/branding` i `src/presentation/theme` stałe identyfikacji wizualnej i motywu.

## Integracje

Folder dostawcy nosi nazwę pakietu lub usługi, a nazwy jego plików składają się ze skróconej nazwy dostawcy i zagadnienia: `<prefix>.<concern>.ts`.

| Sufiks          | Zawiera                                             | Przykład                                                                                        |
| --------------- | --------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `.config.ts`    | Skonfigurowanego klienta                            | `polar/polar.config.ts`, `resend/resend.config.ts`                                              |
| `.constants.ts` | Wartości wyprowadzone ze środowiska lub od dostawcy | `polar/polar.constants.ts`, `better-auth/auth.constants.ts`, `affonso/affonso.constants.ts`     |
| `.server.ts`    | Konfigurację działającą tylko na serwerze           | `better-auth/auth.server.ts`                                                                    |
| `.<concern>.ts` | Jedno zagadnienie integracji                        | `better-auth/auth.middleware.ts`, `use-intl/i18n.messages.ts`, `drizzle-orm/drizzle.columns.ts` |

Prefiksem jest nazwa skrócona, a nie nazwa folderu, dlatego `better-auth` zawiera pliki `auth.*`, `use-intl` pliki `i18n.*`, a `tanstack-form` pliki `form.*`.

## Moduły

Folder modułu nosi nazwę swojej tabeli, a każdy plik powtarza tę nazwę. Pełna lista rodzajów plików i tego, co każdy może zawierać, znajduje się na stronie [Moduły](/docs/conventions/modules).

| Wzorzec                      | Przykład                                             |
| ---------------------------- | ---------------------------------------------------- |
| `<table>.schema.ts`          | `course/course.schema.ts`                            |
| `<table>.zod.ts`             | `course/course.zod.ts`                               |
| `<table>.constants.ts`       | `course/course.constants.ts`                         |
| `<table>.types.ts`           | `course/course.types.ts`                             |
| `<table>.utils.ts`           | `course/course.utils.ts`                             |
| `<table>.<concern>.ts`       | `lesson/lesson.access.ts`, `video/video.delivery.ts` |
| `use-cases/<verb>-<noun>.ts` | `course/use-cases/move-course.ts`                    |

## Trasy

`src/routes` korzysta z płaskich tras plikowych TanStack Start, więc nazwę pliku czyta się jak jego URL.

| Wzorzec                   | Znaczenie                               | Przykład                        |
| ------------------------- | --------------------------------------- | ------------------------------- |
| `<segment>.<segment>.tsx` | Zagnieżdżona ścieżka                    | `admin.courses.create.tsx`      |
| `<path>.tsx`              | Layout wszystkiego, co leży pod ścieżką | `admin.courses.tsx`             |
| `<path>.index.tsx`        | Strona pod samą ścieżką                 | `admin.courses.index.tsx`       |
| `_<name>.tsx`             | Layout bez ścieżki                      | `_site.tsx`                     |
| `$<param>`                | Segment dynamiczny                      | `admin.courses.$courseId.tsx`   |
| `$.tsx`                   | Trasa splat                             | `_site.docs.$.tsx`              |
| `__root.tsx`              | Trasa główna                            | `__root.tsx`                    |
| `api/<name>.ts`           | Handler HTTP                            | `api/auth.$.ts`, `api/index.ts` |

Pliki tras nie mają segmentu języka; router sam dodaje i usuwa prefiks języka.

## Testy

Testy znajdują się w folderze `__test__` obok kodu, który testują, a sufiks wybiera projekt Vitest:

| Wzorzec                               | Projekt       |
| ------------------------------------- | ------------- |
| `__test__/<file>.test.ts`             | `node`        |
| `__test__/<file>.integration.test.ts` | `integration` |
| `__test__/<file>.component.test.tsx`  | `component`   |

Test nosi nazwę pliku, który testuje, czasem z dopiskiem tematu: `course.schema.test.ts`, `auth.client-address.test.ts`. Testy przypadków użycia są grupowane według modułu i odbiorców: `use-cases/__test__/course-use-cases.test.ts` i `course-admin-use-cases.test.ts`. Fixtury leżą w `__test__/fixtures/` obok kodu, do którego należą (`src/modules/course/__test__/fixtures/catalogue.ts`). Testy tras znajdują się w `src/routes/__test__/` i są nazwane według funkcji: `admin-products-routes.component.test.tsx`, `admin-products-loaders.test.ts`, `course-loaders.test.ts`. Plik testów obejmuje jedną funkcję albo jeden plik źródłowy; zobacz [Testy podążają za funkcjami](/docs/conventions/testing#tests-follow-the-features).

Testy przeglądarkowe leżą w katalogu głównym repozytorium: specyfikacje w `e2e/specs/<flow>.spec.ts`, obiekty stron w `e2e/pages/<name>-page.ts`, dane początkowe w `e2e/data/` (dla każdej funkcji: strony w `<feature>.pages.ts`, dane początkowe w `<feature>.seed.ts`, przepływy w `<feature>.flows.ts` i wpisy testowego Workera w `<feature>.worker.ts`), a fixtury Playwright w `e2e/fixtures/`.

## Treści, komunikaty i baza danych

| Wzorzec                                                          | Znaczenie                                                                        |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `messages/<locale>/<namespace>.json`                             | Jedna przestrzeń nazw tłumaczeń: `pages.admin.courses.json`                      |
| `content/docs/<path>/<page>.<locale>.mdx`                        | Jedna strona dokumentacji w jednym języku                                        |
| `content/docs/<path>/meta.<locale>.json`                         | Kolejność w nawigacji i tytuł tego folderu                                       |
| `content/blog/<slug>.<locale>.mdx`                               | Jeden wpis na blogu w jednym języku                                              |
| `content/changelog/<number>.<locale>.mdx`                        | Jedna pozycja listy zmian w jednym języku, nazwana numerem swojego pull requesta |
| `src/integrations/drizzle-orm/migrations/<timestamp>_<name>.sql` | Jedna migracja, generowana przez `bun run db:generate`                           |
| `scripts/<name>.ts`                                              | Skrypt repozytorium uruchamiany przez Bun: `check-content.ts`, `seed-test.ts`    |
