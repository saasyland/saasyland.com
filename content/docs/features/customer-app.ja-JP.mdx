## レイアウト

`src/routes/app.tsx` は認証のエリアに属します。`requireSignedIn` でワークスペースを保護し、自分の名前空間を、ほかのエリアが追加する名前空間（`layoutNamespaces("/app")`。ライセンスのエリアは `pages.license` を追加します）とあわせてプリロードします。

```tsx
const NAMESPACES = ["auth.errors", "pages.app.sidebar", "timezones", ...layoutNamespaces("/app")] as const

export const Route = createFileRoute("/app")({
  beforeLoad: requireSignedIn,
  component: AppLayout,
  loader: ({ context }) => preloadNamespaces({ locale: getCurrentLocale(), namespaces: NAMESPACES, queryClient: context.queryClient }),
  pendingComponent: AppPending,
  staticData: { namespaces: NAMESPACES },
})
```

`AppLayout` は shadcn の `SidebarProvider` の中に、`src/presentation/components/custom/app` の `AppSidebar` と `AppHeader` を表示します。サイドバーは `src/data/navigation.ts` の `APP_NAVIGATION`（概要と設定は `auth.navigation.ts`、ライセンスは `license.navigation.ts` から、ラベルは `navigation.auth.json` と `navigation.license.json` から）でリンクを作り、`APP_RESOURCE_NAVIGATION`（ドキュメントは `content.navigation.ts` から）でリソース欄を作ってサポートの連絡先を続け、ルートコンテキスト（`getRouteApi("/app")`）からユーザーを読み取り、最後に `SignOutButton` を置きます。ヘッダーは現在のページとサイトへ戻るリンクを表示します。サインイン後、管理者は `/admin` に、それ以外のユーザーは `/app` に移動します。

## ページ

| ルート          | 内容                                                                                                                                                                                              |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/app`          | 有効なライセンスがなければ `LicenseOffer`、あれば `LicenseStatusCard`（プラン、ステータス、ライセンスページへのリンク）。[CLI ガイド](/docs/cli)（`ROUTES.DOCS_CLI`）とメールサポートへのリンク。 |
| `/app/license`  | 有効なライセンスがなければ `LicenseOffer`、あれば `LicenseCard`（キー、CLI コマンド、カスタマーポータルへのリンク、プランの変更方法）と、Polar がキーを発行した後は `LicenseActivations`。        |
| `/app/settings` | `PreferencesCard`: ワークスペース内のすべての日付に使うタイムゾーン。検索と **このブラウザから検出** を備えます。[設定](/docs/features/settings)を参照してください。                              |

`LicenseOffer`（`src/presentation/components/custom/app/license-offer.tsx`）は、ランディングページの `PricingTiers` を再利用してプランごとに `CheckoutButton` を置き、購入条件（`CheckoutAgreement`）を加え、最後に、ほかのエリアが追加するセクション（`src/data/license-offer.ts` の `LICENSE_OFFER_SECTIONS`）を、それぞれのスケルトンとページが読み込むデータとともに表示します。コースのエリアは `CourseUnlocks`（`src/data/courses.license-offer.ts`）を追加します。`CourseUnlocks` は有料レッスンのある公開済みコースを、それぞれのロックされたレッスン数とともに示します。この数は `getCatalogue` が D1 から数えます。有料レッスンのあるコースが 1 つもない間、このブロックは表示されません。返金されたライセンスはカードがそのまま残り、その横に購入案内が表示されます。

`src/routes/app.index.tsx` は認証のエリアに属し、ほかのエリアは `src/data/<area>.app-overview.ts` で概要ページに追加します。`src/data/app-overview.entries.ts` がそれらをまとめます。追加するのは、読み取る検索パラメーター（`appOverviewSearchSchema`（`src/data/app-overview.ts`）が検証します）と、セクションです。各セクションはスケルトンと、ページが読み込むデータを持ちます。ライセンスのエリアは `LicenseOverview`（有効化のパネル、選択されたプラン、`LicenseStatusCard`、またはプランの案内）と、`licenseSearchSchema`（`src/data/license.ts`）の 2 つのパラメーターを追加します。`/app/license` も同じスキーマで検証します。どちらのパラメーターも省略可能で、無効な値は無視されます。

| パラメーター | 値                  | 効果                                                                                                                                                                      |
| ------------ | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tier`       | `LICENSE_TIER` の値 | 購入案内の上に `ChosenTier` を表示します。プラン、その価格、**決済に進む** ボタンが含まれます。                                                                           |
| `checkoutId` | Polar の UUID       | ライセンスが有効になるまで購入案内の代わりに `CheckoutActivation` を表示し、有効になるとお礼を表示します。[決済とライセンス](/docs/features/payments)を参照してください。 |

概要ページのローダーは各セクションの読み込みを実行するので、ライセンスのエリアがそこで `currentLicenseQuery` とコースのカタログをプリロードします。`/app/license` はその両方に加えて `licenseActivationsQuery` もプリロードします。`/app/settings` は自身のページの名前空間だけを読み込み、レイアウトの `NAMESPACES` にはタイムゾーン名のための `timezones` が含まれます。購入、Webhook、ライセンスの状態は[決済とライセンス](/docs/features/payments)で説明しています。

## CLI の手順 [#cli-instructions]

`LicenseCard` は、端末でキーを使うコマンド <RepositoryFact name="cliLicenseCommands" /> をそれぞれの働きとともに一覧表示し、CI がキーを <RepositoryFact name="cliLicenseKeyVariable" /> から読み取ることを示します。これらの唯一の情報源は `src/data/cli.ts` で、ランディングページの <RepositoryFact name="scaffoldTarget" /> もここで組み立てます。`CLI_RELEASE_CHANNEL` は CLI を実行する npm のタグを表します。CLI と `@saasyland/stack` は同じバージョンでまとめてリリースされるため、このタグがインストール済みの `@saasyland/stack` の公開時のタグ（プレリリース `x.y.z-beta.n` なら `beta`、安定版なら npm のデフォルトのタグ）でなければ `cli.test.ts` が失敗します。そのため、`@saasyland/stack` を安定版に更新すると、`CLI_RELEASE_CHANNEL` がデフォルトのタグを指すまでテストが失敗し、ライセンスページ、ランディングページ、ドキュメント、[ジャーニースイート](/docs/tooling/playwright#journey-suite)はその値に従います。`@saasyland/stack/package.json` をインポートするとファイル全体が Worker とすべてのページのバンドルに入るため、定数にしています。

## スケルトン

`AppOverviewPending` と `AppSettingsPending`（`app/auth-pending.tsx`。認証のエリアが `src/data/auth.skeletons.ts` で宣言します）は、`app/pending-blocks.tsx` のページヘッダーを描画します。続けて概要ページは各エリアが追加したセクションのスケルトンと、ドキュメントとサポートの案内を、設定ページは `PreferencesCardPending` を描画します。ライセンスのセクションのスケルトンである `LicenseOverviewPending` と、`AppLicensePending`（`app/license-pending.tsx`。ライセンスのエリアが `AppLicensePending` を `src/data/license.skeletons.ts` で宣言します）は、ページが表示することになる状態をそのまま再現します。`licenseSearchSchema` で検索パラメーターを読み取り、クエリクライアントからキャッシュ済みのライセンスとカタログを読み取って、有効化のパネル、選択されたプラン、プランのグリッド（有料レッスンのあるコースごとに 1 行付き）、ライセンスのカードのいずれかを描画します。

`/app` には請求履歴とコースの画面はありません。また、`/app/settings` にはまだプロフィール、メールアドレス、パスワードのフォームはありません。
