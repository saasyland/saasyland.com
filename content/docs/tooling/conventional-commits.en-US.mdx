---
title: "Conventional commits"
description: "Commit message format and the emoji hook."
---

Commit subjects follow `<type>(<scope>): <description>`. The scope is optional and `!` marks a breaking change. Write the subject without an emoji:

```sh
git commit -m "fix(auth): keep the locale in verification links"
```

The `prepare-commit-msg` hook in `.vite-hooks/` runs `bun scripts/commit-msg.ts`, which validates the subject and prefixes the emoji for its type, so the commit above becomes `🐛 fix(auth): keep the locale in verification links`.

| Type       | Emoji |
| ---------- | ----- |
| `build`    | 🛠️    |
| `chore`    | ♻️    |
| `ci`       | ⚙️    |
| `docs`     | 📚    |
| `feat`     | ✨    |
| `fix`      | 🐛    |
| `perf`     | 🚀    |
| `refactor` | 📦    |
| `revert`   | 🗑️    |
| `style`    | 💎    |
| `test`     | 🚨    |

Any other type, or a subject without the conventional format, aborts the commit with the list of allowed types. The hook leaves subjects alone when they already start with an emoji, when Git generated them (`Merge`, `Revert "`, `fixup!`, `squash!`) and for merge, squash and template messages.

Before the message hook, the `pre-commit` hook runs `bun run check:pre-commit`. Do not bypass the hooks.
