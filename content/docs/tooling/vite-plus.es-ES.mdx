Vite+ (`vite-plus`, comando `vp`) reúne Vite, Vitest, oxlint y oxfmt en una sola CLI, y `vite.config.ts` los configura todos. `package.json` sobrescribe `vite` con `@voidzero-dev/vite-plus-core` y fija `vitest` en la versión 5.1.0. `vite-plus` también está fijado a una versión exacta; actualice los tres a la vez con `vp migrate`, no con `bun update`. Los scripts del paquete llaman a `vp`; fuera de ellos, use la CLI global de Vite+ o `bunx vp`.

| Comando           | Usado por                                         |
| ----------------- | ------------------------------------------------- |
| `vp dev`          | `dev`                                             |
| `vp build --mode` | `build:preview`, `build:production`, `build:test` |
| `vp preview`      | `start`, `start:test`                             |
| `vp test`         | `test` y los scripts de Vitest `test:*`           |
| `vp lint`         | `lint`                                            |
| `vp fmt`          | `format`, `format:check`                          |
| `vp check`        | `check`, `check:fix`                              |
| `vp staged`       | `check:pre-commit`                                |
| `vp config`       | `prepare`, que instala los hooks de Git           |

## Configuración

`vite.config.ts` carga sus plugins de forma diferida. Con Vitest solo se cargan `repositoryFacts()` y `@vitejs/plugin-react`; en los demás casos, la pila es:

- `@cloudflare/vite-plugin`: ejecuta el Worker en el entorno de SSR, conserva el estado local (en `.wrangler/test` para el modo `test`) y usa bindings remotos para `development`.
- `fumadocs-mdx`: compila las colecciones de documentación y de blog.
- `repositoryFacts` (`scripts/repository-facts.ts`): sirve el módulo `virtual:repository-facts`, las cifras y versiones medidas en el repositorio durante el build; consulta [Página de inicio](/docs/features/landing-page).
- `@tailwindcss/vite`: Tailwind CSS 4.
- `tanstackStart`: enrutamiento, división de código y prerenderizado de las páginas públicas.
- `@vitejs/plugin-react`.
- `deployedWorker` (`scripts/deployed-worker.ts`): vuelve a compilar el Worker después del prerenderizado sin el MDX renderizado y sin las traducciones de la landing y de las páginas legales; consulta [Cloudflare Workers](/docs/integrations/cloudflare-workers).

El servidor de desarrollo usa el puerto 3000 y falla si está ocupado. `resolve.tsconfigPaths` proporciona el alias de importación `~/`. El mismo archivo contiene las secciones `fmt`, `lint`, `staged` y `test`; consulte [Lint y formato](/docs/tooling/lint-format) y [Pruebas](/docs/tooling/testing).

`build.rolldownOptions.external` enumera las dependencias peer opcionales de `@polar-sh/sdk` (OpenTelemetry e `ioredis`). No están instaladas, y el módulo que las importa se elimina del Worker mediante tree-shaking.

## Hooks de Git

`bun install` ejecuta `prepare`, que llama a `vp config --no-agent` para instalar el despachador de hooks de `.vite-hooks/`. `pre-commit` ejecuta `bun run check:pre-commit`, y `prepare-commit-msg` ejecuta `scripts/commit-msg.ts` (consulte [Commits convencionales](/docs/tooling/conventional-commits)). `vp hooks status` muestra si los hooks están activos en un clon.

Dé preferencia a los scripts del paquete; llame a `vp` directamente para ejecuciones concretas, como formatear o analizar rutas específicas.
