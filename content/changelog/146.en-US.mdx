- Fixed: a signed-in visitor who pressed a landing page header link before the page body had hydrated made React report a hydration mismatch (19 of 20 times at 4× CPU). The prerendered landing page carries the GitHub star count in its dehydrated query cache, and the route guard of the link's target clears that cache the first time it sees a signed-in user, so `ProofSection` hydrated a skeleton where the server had printed the number. The landing loader now also returns the count, and `ProofSection` shows it as the query's `placeholderData` until the query has its own data. `auth-routing.spec.ts` presses the header link right after the router's first render, at 4× CPU in Chromium. See [Data fetching and caching](/docs/conventions/data-fetching).
