`wrangler.jsonc` визначає чотири середовища. `CLOUDFLARE_ENV` вибирає одне з них для dev-сервера та збірок, і кожне зчитує секрети з власного файлу середовища:

| Середовище    | Вибирається через                           | Прив'язки                                | Секрети з          |
| ------------- | ------------------------------------------- | ---------------------------------------- | ------------------ |
| `development` | `bun run dev`                               | Локальні D1, KV і R2 у `.wrangler/state` | `.env.development` |
| `preview`     | `build:preview`, `deploy:preview`           | D1, KV і R2 preview                      | `.env.preview`     |
| `production`  | `build:production`, `deploy:production`     | Продакшн D1, KV і R2                     | `.env.production`  |
| `test`        | `build:test`, `start:test`, `db:reset:test` | Локальні D1, KV і R2 у `.wrangler/test`  | `.env.test`        |

`.env.development`, `.env.preview` і `.env.production` ігноруються Git; `.env.example` перелічує їхні ключі. `.env.test` закомічено, і він містить лише фіктивні значення. Скрипти розгортання завантажують лише ключі, перелічені в `secrets.required` середовища, зчитуючи їх із відповідного файлу.

## Секрети

Кожне середовище перелічує свої секрети в `secrets.required`: ключі Better Auth, OAuth, Resend і Polar, а також `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID` і `CLOUDFLARE_ACCESS_TOKEN` для інструментів Drizzle (середовище `test` ці три не містить). Опис кожного ключа див. у розділі [Змінні середовища](/docs/getting-started/environment-variables).

`AFFONSO_PROGRAM_ID`, публічний ID програми Affonso, потрібний для відстеження партнерських рекомендацій, — це змінна Worker у `vars`, а не секрет, тому її немає ні в `.env.example`, ні в `secrets.required`. Задавайте її лише для середовища, яке приймає справжні платежі; `production` задає ID програми SaaSy Land, а `test` — фіктивний ID для браузерних тестів. Відстеження працює лише тоді, коли Worker має цей ID і програма відкрита: сьогодні `AFFILIATE_PROGRAM` дорівнює <RepositoryFact name="affiliateProgram" /> ([Відкриття програми](/docs/features/affiliates#opening-the-programme)).

Серверний код зчитує секрети через `import { env } from "cloudflare:workers"`. Жоден код не використовує змінних `VITE_`, і жодна з них не може містити секрет, бо Vite відкриває їх браузеру. `scripts/verify-build.ts` зупиняє збірку, коли клієнтський ресурс імпортує `cloudflare:workers`. Канонічний домен береться з `APP_DOMAIN` у `src/presentation/branding/index.ts`, а не зі змінної середовища.

## Прив'язки

| Прив'язка | Тип              | Використання                                               |
| --------- | ---------------- | ---------------------------------------------------------- |
| `DB`      | D1               | База даних застосунку, сесії та ліміти частоти запитів     |
| `CACHE`   | KV               | Кількість зірок на GitHub                                  |
| `MEDIA`   | R2               | Відеофайли, що віддаються через `/media/`                  |
| `BUNDLES` | R2               | Бандли шаблонів CLI, що віддаються через `/bundles/`       |
| `ASSETS`  | Статичні ресурси | Попередньо відрендерені сторінки, шрифти та публічні файли |

Під час розробки використовуються лише локальні прив'язки, тож `bun run dev` ніколи не торкається даних preview чи продакшну; [База даних](/docs/tooling/database#three-databases) пояснює, чому кожна прив'язка локальна. Курси однакові в кожному середовищі: `bun run db:seed:local` імпортує програму курсів локально, а `bun run courses:sync:preview` копіює опубліковані курси production на preview ([Дані курсів у кожному середовищі](/docs/tooling/database#course-data-in-each-environment)). Після зміни прив'язок запустіть `bun run cf-typegen`, щоб перегенерувати `src/types/worker-configuration.d.ts`.

## Тести

Vitest завантажує `.env.test` через `test.env` і розв'язує `cloudflare:workers` у `src/platform/testing/mocks/cloudflare.ts`, який надає в пам'яті D1, KV і бакет для кожної прив'язки R2; `src/platform/testing/mocks/cache.ts` підміняє кеш Workers. Playwright використовує середовище `test` і його точку входу `src/platform/testing/worker.ts`. Жодному з них не потрібні справжні облікові дані.
