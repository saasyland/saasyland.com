Każda ścieżka ma stałą w `ROUTES` (`src/routes.ts`). Linki używają tej stałej, na przykład `<Link to={ROUTES.SIGN_IN}>`, a router dodaje prefiks locale. Każda z poniższych stron jest też serwowana pod prefiksem każdego niedomyślnego locale, na przykład `/pl-PL/terms`.

## Strony publiczne

Te strony używają layoutu `_landing` (nawigacja i stopka), z wyjątkiem bloga i dokumentacji, które mają własne layouty. Wszystkie poza stronami newslettera są prerenderowane.

| Ścieżka                   | Stała                    | Plik trasy                            |
| ------------------------- | ------------------------ | ------------------------------------- |
| `/`                       | `HOME`                   | `_landing.index.tsx`                  |
| `/premium`                | `PREMIUM`                | `_landing.premium.tsx`                |
| `/licence`                | `LICENCE`                | `_landing.licence.tsx`                |
| `/privacy`                | `PRIVACY`                | `_landing.privacy.tsx`                |
| `/terms`                  | `TERMS`                  | `_landing.terms.tsx`                  |
| `/refunds`                | `REFUNDS`                | `_landing.refunds.tsx`                |
| `/newsletter/confirm`     | `NEWSLETTER_CONFIRM`     | `_landing.newsletter.confirm.tsx`     |
| `/newsletter/unsubscribe` | `NEWSLETTER_UNSUBSCRIBE` | `_landing.newsletter.unsubscribe.tsx` |
| `/blog`                   | `BLOG`                   | `blog.tsx`, `blog.index.tsx`          |
| `/blog/*`                 | brak                     | `blog.$.tsx`                          |
| `/docs`                   | `DOCS`                   | `docs.tsx`, `docs.index.tsx`          |
| `/docs/*`                 | brak                     | `docs.$.tsx`                          |

## Uwierzytelnianie

Layout `/auth` (`auth.tsx`) nie ma guarda; mają go poszczególne strony.

| Ścieżka                 | Stała             | Plik trasy                 | Guard                                                          |
| ----------------------- | ----------------- | -------------------------- | -------------------------------------------------------------- |
| `/auth/sign-in`         | `SIGN_IN`         | `auth.sign-in.tsx`         | `redirectIfSignedIn`                                           |
| `/auth/sign-up`         | `SIGN_UP`         | `auth.sign-up.tsx`         | `redirectIfSignedIn`                                           |
| `/auth/forgot-password` | `FORGOT_PASSWORD` | `auth.forgot-password.tsx` | brak                                                           |
| `/auth/reset-password`  | `RESET_PASSWORD`  | `auth.reset-password.tsx`  | brak                                                           |
| `/auth/two-factor`      | `TWO_FACTOR`      | `auth.two-factor.tsx`      | brak                                                           |
| `/auth/verify-email`    | `VERIFY_EMAIL`    | `auth.verify-email.tsx`    | Przekierowuje `token` do endpointu weryfikacyjnego Better Auth |

## API

Ścieżki API nigdy nie są lokalizowane.

| Ścieżka       | Stała           | Plik trasy      |
| ------------- | --------------- | --------------- |
| `/api`        | `API`           | `api/index.ts`  |
| `/api/auth/*` | `API_AUTH_BASE` | `api/auth.$.ts` |
| `/api/search` | brak            | `api/search.ts` |

`ROUTES.API_AUTH` zawiera ścieżki endpointów Better Auth względem `/api/auth`; `auth.server.ts` używa ich, aby wyłączyć te endpointy z limitowania żądań. `API_AUTH_CUSTOMER_PORTAL` i `API_AUTH_VERIFY_EMAIL` to pełne ścieżki do endpointów Better Auth. `AUTH` i `NEWSLETTER` nie mają własnych stron; razem z `ADMIN`, `APP` i `API` oznaczają obszary, które nigdy nie są prerenderowane.
