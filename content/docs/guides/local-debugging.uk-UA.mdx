## Виберіть середовище

| Середовище                      | Команди                                                       | Дані                                                         | Провайдери                                  |
| ------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------- |
| Ізольований попередній перегляд | `db:migrate:test`, `db:seed:test`, `build:test`, `start:test` | Локальні D1 і KV у `.wrangler/test`, тестові облікові записи | Перехоплюються; облікові записи не потрібні |
| Розробка                        | `db:migrate:development`, `dev`                               | Віддалені D1 і KV попереднього перегляду                     | Справжні, з `.env.development`              |

```sh
bun run db:migrate:test
bun run db:seed:test
bun run build:test
bun run start:test
```

Ізольований попередній перегляд віддає збірку за адресою `http://127.0.0.1:3000`; щоб побачити зміни в коді, зберіть її заново. Увійдіть як `admin@saasyland.example.test` або `customer@saasyland.example.test` з паролем із `e2e/data/accounts.ts`. Листи перехоплюються замість надсилання: відкрийте `/__test/emails?to=<address>`, щоб прочитати їх разом із посиланнями підтвердження.

```sh
bunx wrangler login
cp .env.example .env.development
bun run db:migrate:development
bun run dev
```

Сервер розробки працює за адресою `http://localhost:3000` з гарячим перезавантаженням. Його прив'язки `DB` і `CACHE` — це віддалені ресурси попереднього перегляду, тож записи й міграції впливають на спільну базу попереднього перегляду. Використовуйте `POLAR_SERVER=sandbox`.

## Читайте помилки сервера

- Серверна функція, що завершилася збоєм, записує `Server function failed` з початковою помилкою в термінал, де працює `bun run dev`, або в Workers Logs у розгорнутих середовищах. Браузер отримує лише код помилки.
- `Rate-limit storage unavailable` означає, що D1 був недоступний під час перевірки обмеження запитів; запит відхилено.
- `No messages/<locale>/<namespace>.json` означає, що маршрут оголошує простір імен без файлу для цієї мови.

## Переглядайте дані

- Drizzle Studio: `bun run db:studio:development` (а також `:preview` і `:production`). Потребує змінних `CLOUDFLARE_*` у відповідному файлі середовища.
- Локальна тестова база: `bunx wrangler d1 execute DB --env test --local --persist-to .wrangler/test --command "SELECT email, role FROM user"`.

## Виправляйте згенеровані файли

- Застарілі типи прив'язок Worker, таблиці назв класів або вміст документації: `bun run typegen`.
- Переклади не розв'язуються: `bun run check:i18n` виводить відсутні ключі для кожної мови та ключі, які не розв'язуються у своїй області `useTranslations`.
- `bun run clean` видаляє результати збірки, кеші й `.wrangler`, зокрема локальну тестову базу; після цього знову запустіть `db:migrate:test` і `db:seed:test`.

## Налагоджуйте тести

- Запускайте один проєкт або лише зачеплені зміною тести: `bun run test:unit`, `bun run test:component`, `bun run test:changed`, `bun run test:watch`.
- Playwright: `bun run test:e2e:headed` показує браузер, а `bun run test:e2e:ui` відкриває режим UI. Локальні запуски зберігають трасування тестів, що впали, і відкривають HTML-звіт у разі збоїв.
- Перед `bun run test:e2e` зупиніть інші сервери на порту 3000 або задайте `PLAYWRIGHT_BASE_URL`.
