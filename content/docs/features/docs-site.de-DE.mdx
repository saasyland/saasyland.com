## Inhalte

- Seiten liegen unter `content/docs/<section>/<page>.<locale>.mdx`, für jede Locale.
- `meta.<locale>.json` legt in jedem Ordner den Abschnittstitel, das Icon und die Seitenreihenfolge fest.
- `src/integrations/fumadocs/fumadocs.i18n.ts` verwendet den Parser `dot`, `en-US` als Standard und Fallback sowie `hideLocale: "always"`, weil die App das Locale-Präfix selbst verwaltet.
- `bun run content` erzeugt `.source` aus `fumadocs.config.ts`.

## Routen

- Layout `/docs` (`src/routes/docs.tsx`): Eine Serverfunktion liefert den Seitenbaum für die aktuelle Locale; das Layout rendert das Fumadocs-`DocsLayout` mit dem GitHub-Link sowie `LocaleSelect` und `ThemeSwitch` als einheitlich gestaltete Auswahlfelder im Fußbereich der Seitenleiste, ergänzt `BackToTop`, weil das Inhaltsverzeichnis von Fumadocs nur zu Überschriften springt, lädt `docs.css` und zeigt während des Ladens `DocsPending`.
- `/docs/` und `/docs/$` rufen `loadDocsPage` (`fumadocs.docs.ts`) auf, das die Seite auflöst und ihr kompiliertes MDX (`docsContent`) vor dem Rendern vorab lädt.
- `/api/search` stellt die Fumadocs-Suche über alle Locales bereit (`fumadocs.search.ts`).

MDX-Seiten können `mdxComponents` aus `src/presentation/components/custom/mdx.tsx` verwenden: die Fumadocs-Standardkomponenten, Fumadocs `Accordions`, `Steps` und `Tabs` sowie die shadcn-Komponenten `Alert`, `Badge`, `Button`, die Card-Bausteine, `Separator` und die Tabellen-Bausteine sowie `RepositoryFact`, `RepositoryTable` und `TierPrice`, die Werte aus dem Code ausgeben, statt sie von Hand einzutragen ([Übersetzungen und Inhalte](/docs/conventions/translations)). Links werden automatisch lokalisiert.

## Barrierefreiheit

Seiten der Dokumentation erfüllen WCAG 2.2 AA in beiden Themes. Codeblöcke verwenden die Shiki-Themes GitHub Light und GitHub Dark mit zwei ersetzten Token-Farben (`colorReplacements` in `fumadocs.config.ts`), sodass jedes Token 4,5:1 erreicht; der Scrollbereich eines Codeblocks ist fokussierbar, aber nur eine Landmark, wenn der Block einen Titel hat; und eine Checkbox in einer Aufgabenliste wird nach ihrem Eintrag benannt. `e2e/specs/accessibility.spec.ts` scannt die Startseite der Dokumentation, jede Seite des Abschnitts Konventionen und je eine Seite aus jedem anderen Abschnitt; siehe [Barrierefreiheit](/docs/conventions/accessibility).

## Eine Seite hinzufügen

1. Schreiben Sie `<page>.en-US.mdx` mit `title` und `description`.
2. Fügen Sie den Slug in `meta.en-US.json` und in jeder anderen `meta.<locale>.json` in derselben Reihenfolge hinzu.
3. Fügen Sie die Übersetzung für jede andere Locale mit byte-identischen Codeblöcken hinzu.
4. Führen Sie `bun scripts/check-content.ts` (auch Teil von `bun run check:i18n`) und `bun run content` aus.

`bun run build` rendert jede Dokumentationsseite in jeder Locale vorab.
