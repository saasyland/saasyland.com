title: "Affiliate programme"
description: "Referral links tracked by Affonso, credited on the Polar order, with public terms on /affiliates."
---

Affiliates earn commission on the sales they refer. SaaSy Land does not count referrals itself: [Affonso](https://affonso.io) records clicks, receives orders and refunds from Polar, calculates commission and pays affiliates. That keeps every number out of the seller's hands, which is what makes the programme credible to affiliates.

## Opening the programme

Whether the programme is open is `AFFILIATE_PROGRAM` in `src/data/affiliates.ts`, a `FEATURE_STATUS` like `CLI_GENERATION`. It is <RepositoryFact name="affiliateProgram" /> today: Affonso runs a programme only on a paid plan, and SaaSy Land's opens soon, now that the CLI generates projects. The status decides two things:

- **Referral tracking.** `src/data/affiliates.root.ts` mounts `AffiliateReferral` in the root route only while the status is `FEATURE_STATUS.AVAILABLE`. While it is `FEATURE_STATUS.ARRIVING`, the area mounts nothing, so no visit, not even one with a referral parameter, loads Affonso's script, sends Affonso a request or stores the `affonso_referral` cookie. Checkout then finds no cookie and sends Polar no referral, only the buyer's language.
- **How to join.** The page's `description` and `sections.join.body` messages are ICU selects on `program` with an `available` variant and an arriving one (`other`). The open variant links the partner portal; the arriving one asks partners to write to the contact address. Its first sentence is a select on `generation` (see [Landing page](/docs/features/landing-page)): it says the programme opens when the CLI starts generating projects, and once generation ships, that it opens soon. The commission, hold, payouts and every other term stay on the page in both states, because they are the terms that will apply.

To open the programme:

1. In Affonso, start a paid plan. Until then the partner portal answers every visitor that the programme is not yet active.
2. Set `AFFILIATE_PROGRAM` to `FEATURE_STATUS.AVAILABLE` and release the change. The page links the portal again, and visits with a referral parameter load the script.
3. Test it with step 4 of the configuration below.

No secret is involved. The only Affonso value the Worker reads is `AFFONSO_PROGRAM_ID`, the public program ID under `vars`, which stays set while the programme is arriving; nothing in `.env.example` or `secrets.required` belongs to Affonso, and Polar sends orders and refunds to Affonso itself, so the site never calls Affonso's API.

## How a referral travels

1. An affiliate shares any page with a referral parameter, for example `/?via=jane`. The parameters Affonso reads are listed in `AFFONSO.REFERRAL_PARAMS` (`src/integrations/affonso/affonso.constants.ts`): <RepositoryFact name="affonsoReferralParams" />.
2. `AffiliateReferral` (`src/presentation/components/custom/affiliate-referral.tsx`), which `src/data/affiliates.root.ts` mounts once in the root route while the programme is open, checks the URL after hydration. Only when one of those parameters is present does it ask the server for the program ID (`getAffonsoProgramId`, `src/integrations/affonso/affonso.program.ts`) and render Affonso's script with `data-cookie_duration` set to `AFFILIATE_TERMS.COOKIE_DAYS`, <RepositoryFact name="affiliateCookieDays" unit="day" />. Visits without a referral parameter load no third-party script.
3. The script records the click with Affonso and stores the click ID in the first-party `affonso_referral` cookie.
4. When the visitor starts a checkout, `startCheckout` adds `affonsoReferralMetadata(headers)` (`src/integrations/affonso/affonso.referral.ts`) to the checkout `metadata`, next to the buyer's language. It reads the cookie, accepts only letters, digits, `_` and `-` up to 128 characters, and returns `{ affonso_referral: <click ID> }`, or an empty object when there is no valid referral.
5. Polar copies the checkout metadata onto the order and sends `order.created` and `order.refunded` to Affonso, which credits or reverses the commission.

Regional pricing still applies to referred buyers: the referral travels in metadata and the regional price is the checkout's own price, so neither uses Polar's discount slot.

## Configuration

Tracking stays off, even while the programme is open, until the Worker has `AFFONSO_PROGRAM_ID`. It is public (it appears in the script tag), so it is a plain variable rather than a secret. Set it only for the environment that takes real payments:

```jsonc
"production": {
  "vars": {
    "AFFONSO_PROGRAM_ID": "<program ID from Affonso>",
  },
}
```

SaaSy Land's own production Worker sets it in `wrangler.jsonc`, so the live site tracks referrals once the programme opens. The development and preview Workers set none, and `test` sets a dummy ID for the browser tests.

Then, once:

1. Create the programme in Affonso and connect Polar with an organisation access token without expiry. Affonso's Polar guide lists the scopes it needs.
2. In Polar, add the webhook endpoint Affonso shows, with format **Raw** and the events `order.created`, `order.refunded` and `subscription.canceled`.
3. Set the programme to the terms the public page states. The numbers come from `AFFILIATE_TERMS` (`src/data/affiliates.ts`), so the page, the script and Affonso agree:
   - Commission: <RepositoryFact name="affiliateCommissionPercent" unit="percent" /> of every sale, on every product.
   - Hold: <RepositoryFact name="affiliateHoldDays" unit="day" />, longer than the refund period of <RepositoryFact name="refundWithdrawalDays" unit="day" />, so refunds and most payment disputes settle before a commission is approved.
   - Cookie duration: <RepositoryFact name="affiliateCookieDays" unit="day" />, with last-click attribution, so the most recent affiliate link a buyer opened is credited.
   - Payouts: monthly, by PayPal or wire transfer, once a balance reaches <RepositoryFact name="affiliateMinimumPayout" unit="payout" />, paid in <RepositoryFact name="affiliatePayoutCurrency" />.
   - Referral parameters: every name in <RepositoryFact name="affonsoReferralParams" />, with Affonso's default `via` in the links it hands out.
   - Access: public, so anyone can sign up at the partner portal, <RepositoryFact name="affiliatePortalUrl" />, and is approved at once. An invite-only programme needs Affonso's paid Growth plan.
4. Test it by opening `/?atp=test`, checking that the `affonso_referral` cookie is set, and confirming that the Polar checkout carries `affonso_referral` in its metadata.

## Terms page

`/affiliates` (`src/routes/_site._marketing.affiliates.tsx`, messages in `pages.legal.affiliates`) publishes the terms in every locale and is linked from the footer. While the programme is open, its "How to join" section links the partner portal from `AFFILIATE_PORTAL_URL` (`src/data/affiliates.ts`): the message wraps `{portal}`, the portal's host name, in a `<link>` tag that the route renders as a link to the portal. While it is arriving, the section asks partners to write in instead, and the route passes the status as `program` next to `CLI_GENERATION_VALUES`. Every number on it is interpolated from `AFFILIATE_TERMS`; the minimum payout is formatted for the visitor's locale in `AFFILIATE_TERMS.PAYOUT_CURRENCY`, the currency Affonso pays affiliates in, which stays US dollars whatever currency the store charges in. The privacy policy describes the referral cookie, what Affonso receives and the legal basis.

## Tests

- `affonso.referral.test.ts`: a valid cookie becomes metadata; a missing, malformed or oversized value is ignored.
- `license-purchase.integration.test.ts`: the referral reaches the Polar checkout and stays on the paid order; without the cookie, the checkout carries only the buyer's language.
- `affiliate-referral.component.test.tsx`: the script renders only with a referral parameter and a configured program ID.
- `affiliates.root.test.ts`: the area mounts `AffiliateReferral` while the programme is open and nothing while it is arriving.
- `legal-routes.component.test.tsx`: the terms page renders completely in every locale; in each, it links the partner portal while the programme is open, and keeps every term but asks partners to write in, without the portal, while it is arriving.
- `cli-generation.test.ts`: the arriving "How to join" text renders in both generation variants in every locale.
- `affiliates.test.ts`: the hold is longer than the refund period.
- `wrangler.test.ts`: production has a programme ID of its own, and development and preview have none.
- `e2e/specs/affiliates.spec.ts`: expectations follow `AFFILIATE_PROGRAM`. A normal visit loads no script. While the programme is open, a visit with `?via=` loads it with the program ID that `wrangler.jsonc` gives `test` and keeps the referral cookie (the script is stubbed with `page.route`); while it is arriving, the same visit sends Affonso no request and sets no cookie. The terms page prints the commission and minimum payout from `AFFILIATE_TERMS` and the "How to join" text for the status, and links the partner portal only while the programme is open.
- `e2e/specs/accessibility.spec.ts`: `/affiliates` is scanned by axe in light and dark mode.
