## Moduły

Moduł w `src/modules/<table>` istnieje tylko dla prawdziwej tabeli bazy danych. Zawiera:

- `<table>.schema.ts`: tabelę Drizzle, reeksportowaną przez `src/integrations/drizzle-orm/drizzle.schemas.ts`
- `<table>.zod.ts`: schematy danych wejściowych, używane zarówno przez formularze, jak i przez funkcje serwerowe
- `<table>.constants.ts`: nazwane wartości domenowe, takie jak `COURSE_STATUS`, limity kolumn, klucze zapytań i mutacji
- `<table>.types.ts`: interfejs nazwany jak moduł, z typami wierszy i typem wejścia każdej operacji, np. `Course["createCourse"]`
- `<table>.utils.ts`: jeśli tabela ich potrzebuje
- `use-cases/<operation>.ts`: jedną operację na plik

Moduły to <RepositoryFact name="modules" />. Do modułu `license` należą dwie tabele: `license` i `revoked_license_order`. Współdzielone stałe i funkcje pomocnicze znajdują się w [`_core`](/docs/architecture/core). Funkcja serwerowa, która nie operuje na tabeli, należy do `src/lib` lub do jedynej trasy, która jej używa.

## Przypadki użycia

Większość przypadków użycia to funkcje serwerowe wywoływane z przeglądarki. Każdy plik eksportuje funkcję utworzoną przez `createServerFn` oraz jej opcje zapytania lub mutacji:

```ts title="src/modules/course/use-cases/create-course.ts"
import { mutationOptions } from "@tanstack/react-query"
import { createServerFn } from "@tanstack/react-start"
import { v7 } from "uuid"

import { authorized } from "~/src/integrations/better-auth/auth.middleware"
import { db } from "~/src/integrations/drizzle-orm/drizzle.database"
import { rethrowAsConflict } from "~/src/integrations/drizzle-orm/drizzle.errors"

import { nextPosition } from "~/src/modules/_core/utils/ordering"
import { COURSE_MUTATION_KEYS } from "~/src/modules/course/course.constants"
import { course } from "~/src/modules/course/course.schema"
import type { Course } from "~/src/modules/course/course.types"
import { courseZodSchemas } from "~/src/modules/course/course.zod"

export const createCourse = createServerFn({ method: "POST" })
  .middleware([authorized({ course: ["create"] })])
  .validator((input: Course["createCourse"]) => courseZodSchemas.createCourse.parse(input))
  .handler(async ({ data }) => {
    const positions = await db.select({ position: course.position }).from(course)

    return db
      .insert(course)
      .values({ ...data, id: v7(), position: nextPosition(positions) })
      .returning({ id: course.id })
      .get()
      .catch(rethrowAsConflict)
  })

export const createCourseMutation = mutationOptions({
  mutationFn: (data: Course["createCourse"]) => createCourse({ data }),
  mutationKey: COURSE_MUTATION_KEYS.CREATE,
})
```

- **Middleware** pochodzi z `src/integrations/better-auth/auth.middleware.ts`. `authorized()` wymaga sesji, `authorized({ course: ["create"] })` dodatkowo sprawdza uprawnienie, a `withRateLimit(kind, RATE_LIMITS.SENSITIVE)` ogranicza liczbę wywołań operacji publicznych.
- **Walidacja** parsuje dane wejściowe schematem Zod modułu, zanim uruchomi się handler.
- **Własność danych** wynika z sesji. Operacje na własnych danych wywołującego filtrują po `context.auth.user.id` i nigdy nie ufają identyfikatorowi użytkownika z danych wejściowych.
- **Błędy** są rzucane jako `new AppError(ERROR_CODES.X)`. `rethrowAsConflict` zamienia naruszenie ograniczenia unikalności, np. zajęty już slug kursu, na `CONFLICT`. `withRequest` zamienia błąd API Better Auth na `AUTH_API_ERROR` z kluczem komunikatu tego błędu, a błąd Zod na `VALIDATION`; każdy inny błąd jest logowany i trafia do klienta jako `INTERNAL_ERROR`.
- **Odczyty** eksportują zamiast tego `queryOptions`, na przykład `getCoursesPageQuery(input)`, które zwraca `{ rows, total }` dla tabeli danych.

Niektóre przypadki użycia to zwykłe funkcje asynchroniczne, które działają tylko na serwerze i nie mają endpointu RPC, np. `send-verify-email.ts` lub `grant-license.ts`. Wywołują je hooki Better Auth i handlery webhooków Polara.

## Wywoływanie przypadku użycia z komponentu

Komponenty przekazują wyeksportowane opcje do `useMutation` operatorem spread, tłumaczą błędy za pomocą `useErrorMessage()` i po udanej operacji unieważniają klucze zapytań modułu:

```tsx
const t = useTranslations("pages.admin.users.actions")
const queryClient = useQueryClient()
const errorMessage = useErrorMessage()

const deleteUser = useMutation({
  ...deleteUserMutation,
  onError: (error) => {
    toast.error(errorMessage(error))
  },
  onSuccess: async () => {
    await queryClient.invalidateQueries({ queryKey: USER_QUERY_KEYS.ALL })
    toast.success(t("feedback.deleteSuccess"))
  },
})
```
