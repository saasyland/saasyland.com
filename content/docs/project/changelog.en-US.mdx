## 2026-11-13

- Videos: `bun run video:publish:<environment>` encodes a recording with FFmpeg into adaptive HLS (H.264 renditions up to 1440p, one shared AAC track, posters, storyboard thumbnails and captions), uploads it to the new `MEDIA` R2 bucket and adds a row to the new `video` table. See [Videos](/docs/features/videos).
- `/admin/videos` lists, previews and deletes videos, guarded by the new `video` permission statement (`read`, `delete`).
- The Worker serves video files under signed, expiring `/media/` paths before the locale middleware, with `Range` support and the Workers cache. See [Cloudflare R2](/docs/integrations/cloudflare-r2).
- `VideoPlayer` plays them with Video.js 10: quality, speed, captions, picture-in-picture and seek previews. A Bun patch to `@videojs/utils` 10.3.0 fixes storyboard thumbnail URLs when the media element is an adapter.
- Courses: the new `course`, `chapter`, `lesson` and `lesson_progress` tables back `/courses` (the catalogue), `/courses/<course>` (curriculum and progress) and `/courses/<course>/<lesson>` (the player, which resumes where the viewer stopped and saves progress). Lessons play videos from the video library. See [Courses](/docs/features/courses).
- Each lesson is a free preview, free with an account or included with a Complete or Agency licence, and the server functions enforce it; admins can watch every lesson through the new `course` permission statement. A visitor who signs in from a lesson returns to it.
- `VideoPlayer` takes `startAt`, `onProgress` and `onEnded`.
- Admins manage courses under **Content → Courses**: `/admin/courses` lists every course with an edit link and a delete button that asks for confirmation, `/admin/courses/create` creates one, and `/admin/courses/<courseId>` edits its details in every locale and builds its curriculum. Chapters and lessons are added, edited, moved up and down and deleted there, and each lesson picks its video from the library. See [Courses](/docs/features/courses). Arrows in the list set the order of the public catalogue.
- The new course, chapter and lesson use cases check the `course` permission statement, answer `CONFLICT` for a slug that is taken (`rethrowAsConflict`), give a new row the next `position` (`nextPosition`) and renumber the siblings from 1 on a move (`reorder`). Deleting a course or a chapter deletes its lessons and their progress; the videos stay in the library.
- Titles and summaries written from the admin must have English text (`localizedTextSchema`), with messages in the new `course.validations` namespace.
- Removed: the demo course screen at `/admin/courses/create` and the empty **Courses** tab on `/admin/products`.
- The deployed Worker is rebuilt after prerendering without the rendered MDX of docs and blog pages and without the translations that only the landing, legal and premium pages use, which cuts the upload from 45.5 MiB to 21.5 MiB. `scripts/verify-build.ts` checks that every docs page and published blog post was prerendered. See [Cloudflare Workers](/docs/integrations/cloudflare-workers).
- The Worker entry no longer loads the TanStack Start server runtime at startup: `parseLocaleCookie` moved to `i18n.middleware.ts`, and `ThemeProvider` reads its cookie itself.

## 2026-11-12

- Every Worker response carries security headers: `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, `Cross-Origin-Opener-Policy`, a `Permissions-Policy` and a Content Security Policy that blocks framing, `<base>` changes and plugins, plus `Strict-Transport-Security` over HTTPS. `public/_headers` gives static files served without the Worker a subset.
- Verification, password reset and newsletter confirmation emails are limited to three per address per hour (`withinRecipientRateLimit`).
- Better Auth's own endpoints enforce the password, name, email and image rules of the forms (`enforceInputPolicy` in `auth.hooks.ts`).
- Fixed: Resend idempotency keys are `<purpose>/<SHA-256 of the token>`, so verification and change-email emails to long addresses are no longer rejected.
- Fixed: a partial refund no longer revokes a licence, and Polar webhook events that can never succeed are acknowledged instead of retried.
- Fixed: newsletter confirmation and unsubscribe links act only when the visitor presses the button, and newsletter links accept exactly the hosts from `appHostsForMode`.
- Route search params are Zod schemas built from `searchText`, `searchFlag` and `searchChoice` in `src/lib/search-params.ts`.
- Each module's `<module>.types.ts` exports one interface, and server functions type their input as `Module["operation"]`; newsletter statuses and sources are named constants.
- Fixed: deploys no longer upload Worker source maps (`upload_source_maps: false`), which made the upload too large.
- Dependencies updated: `@polar-sh/sdk` 1.x, `@polar-sh/better-auth` 2.x, Vite+ 1.6.0, Vitest 5.1.0 and `fumadocs-mdx` 15.6.1.

## 2026-09-26

- Internationalization rebuilt around use-intl namespaces: one JSON file per namespace in `messages/<locale>/`, a `NAMESPACE` per page route and `NAMESPACES` per layout route, root namespaces for every screen, and a `check:i18n` step that resolves every static key in its `useTranslations` scope.
- Emails split into React Email templates (markup and namespace only) and use cases that load the messages and send through `sendEmail`.
- Components reorganised: route files compose pages, component folders are flat, and every widget, dialog, form and table column set has its own file.
- All forms follow the shadcn TanStack Form pattern with `Field`, `FieldLabel`, `Input` and the module Zod schemas.
- One generic `DataTable` on TanStack Table v9 replaces the individual table implementations.
- Simpler newsletter form.
- Fixed: navigation and section links keep the locale on pages other than the home page.
- Fixed: the admin dashboard chart labels are localized.
- Vitest coverage gate at 100% for lines, statements, functions and branches.
