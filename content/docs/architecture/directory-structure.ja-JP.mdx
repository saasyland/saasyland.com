## 配置のルール

- **ファイルとフォルダーにはケバブケースを使います。** テストは同じ階層の `__test__` フォルダーに置きます。
- **ルートは組み立てるだけ。** ルートファイルが定義するのは、ページまたはレイアウトのコンポーネント、`NAMESPACE` または `NAMESPACES`、ローダー、`head` です。ウィジェット、ダイアログ、カラム定義は置きません。
- **モジュールはデータベーステーブル。** `src/modules/<name>` は、実在するテーブルのためだけに作成します。テーブルを扱わないサーバー関数は `src/lib`（例：`src/lib/github.ts`）に置くか、1 つのルートだけが使う場合はそのルートファイルに置きます。
- **共有コンポーネントはフラットに。** 複数のエリアで使うコンポーネントは、`presentation/components/custom` 直下の単一ファイルにします。
- **エリアとページのフォルダー。** 1 つのエリアだけで使うコンポーネントは、`admin/`、`app/`、`auth/`、`blog/`、`courses/`、`landing-page/`、`settings/` のいずれかに置きます。`settings/` には、`/app/settings` と `/admin/settings` が共有するアカウントのカードを置きます。管理画面のページには、`admin/users/` のように専用のフォルダーを設けます。ランディングページは、`sections/`（ページのセクションごとに 1 ファイル）と `components/`（セクション間で共有する部品）に分かれます。
- **1 ファイルにつきウィジェット、ダイアログ、フォーム、カラムセットは 1 つ。** コンポーネントをラッパーと `-content` ファイルに分割しないでください。
- **ヘルパー用のフォルダーを入れ子にしない。** コンポーネントのフォルダーには `components/`、`constants/`、`hooks/`、`lib/`、`types/` のサブフォルダーを作らず、コンポーネントの隣に `.ts` のヘルパーファイルも置きません。1 つのコンポーネントだけが使う定数は、そのコンポーネントのファイル内に置きます。
- **共有データは `src/data` に置く。** 例：`MARKETING_SECTION_IDS`、CLI の選択肢。各エリアはここで、ダッシュボードの統計も `<area>.dashboard.ts` に宣言し、`*.entries.ts` のバレルがそれらをまとめます（[パスとナビゲーション](/docs/conventions/routes#paths-and-navigation)を参照）。各エリアは、プラットフォームに追加するもの（Worker ハンドラー、Vite プラグイン）もここで宣言します（[エリアが追加するもの](/docs/architecture/platform-layer#what-the-areas-add)を参照）。
- **各エリアのパスは `src/areas/<area>.shared.ts` に置く。** このファイルはブラウザー、Worker、Bun のスクリプト、Playwright、`vite.config.ts` のすべての実行環境が読み込みます。そのため定数だけを持ち、相対パスでインポートします。`src/routes.ts` がすべてのエリアのパスをまとめます（[パスとナビゲーション](/docs/conventions/routes#paths-and-navigation)を参照）。公開サイトのチェックは独自のファイルの種類 `src/areas/<area>.live.ts` です。読み込むのはデプロイ後の検証とドキュメントだけだからです。エリアがページに追加するもの（レイアウトの名前空間、タイムゾーン、ルートコンポーネントなど）は、ブラウザー用ファイル `src/areas/<area>.ts` の `<AREA>_BROWSER` オブジェクト 1 つに置きます。これを読み込むのはブラウザーとサーバーレンダリングだけです。メニュー項目も独自の純粋なファイルの種類 `src/areas/<area>.navigation.ts` で、`src/areas/navigation.entries.ts` がまとめ、`src/data/navigation.ts` が読み込みます。Remotion プロジェクトが管理画面のメニューを読み込み、その CI ジョブは Remotion 自身のパッケージしかインストールしないため、ルーター、TanStack Query、サーバー関数のコードをインポートするエリアのブラウザー用ファイル `src/areas/<area>.ts` を読み込めないからです。権限ステートメントは専用のファイル `src/areas/<area>.access.ts` に置き、変更のたびに人がレビューします。
- **生成ファイルは手で編集しない。** ルータープラグインが `src/routeTree.gen.ts` を、`bun run cf-typegen` が `src/types/worker-configuration.d.ts` を、`bun run content` と `bun run generate:cn` が `.source/` を書き出します。
