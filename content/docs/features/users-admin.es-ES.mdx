## Rutas

`src/routes/admin.users.tsx` es un layout con cuatro pestañas enlazadas; `/admin/users` redirige a `/admin/users/all`. Todas las pestañas usan el espacio de nombres `pages.admin.users`.

| Ruta                       | Contenido                                                               |
| -------------------------- | ----------------------------------------------------------------------- |
| `/admin/users/all`         | Tabla de usuarios real                                                  |
| `/admin/users/invitations` | Filas de demostración (`ADMIN_INVITATION_ROWS`) con búsqueda por correo |
| `/admin/users/roles`       | Filas de demostración (`ADMIN_ROLE_ROWS`)                               |
| `/admin/users/security`    | Estado vacío                                                            |

## Todos los usuarios

```tsx
<DataTable columns={userColumns} options={{ query: getUsersPageQuery, selectable: true }} />
```

- `getUsersPageQuery` llama a la función de servidor `getUsers` (`src/modules/user/use-cases/get-users.ts`, permiso `user: ["list"]`). La paginación y la ordenación se ejecutan en el servidor sobre nombre, rol, estado, verificación del correo, 2FA, zona horaria y las fechas de creación y actualización.
- El estado no es una columna. `getUserStatus` (`user.utils.ts`) deriva `banned`, `pending` o `active` a partir de `banned` y `emailVerified`, y el servidor ordena con la misma expresión SQL `case`.
- `userColumns` está en `src/presentation/components/custom/admin/users/user-columns.tsx`; las fechas se muestran en la zona horaria de cada usuario.

## Acciones por fila

`UserRowActions` (`row-actions.tsx`) es el menú de la última columna:

- **Restablecer contraseña** abre `ResetPasswordDialog`, que llama a `setUserPassword`.
- **Bloquear** o **Desbloquear** llama a `banUser` o `unbanUser`.
- **Eliminar** abre `DeleteUserDialog`, que llama a `deleteUser`.

Cada acción correcta invalida `USER_QUERY_KEYS.ALL` y muestra un aviso; los errores pasan por `useErrorMessage`. Los elementos **Editar** y **Ver perfil** y el botón **Añadir usuario** todavía no hacen nada.

## Sin conectar

`createUser`, `getUser`, `updateUser`, `setUserRole`, `impersonateUser` y `stopImpersonatingUser` existen en `src/modules/user/use-cases` con su middleware de permisos, pero ninguna pantalla los llama. No hay tabla de invitaciones; los roles reales son `admin` y `customer` en `auth.access.ts`.
