どの環境も、`wrangler.jsonc` で R2 バケットを `MEDIA` としてバインドします。本番では `saasyland`、プレビューでは `saasyland-preview`、`bun run dev` ではローカルの `saasyland-local` バケット、テストビルドではローカルの `saasyland-test` バケットです。バケットは非公開です。パブリックアクセスと `r2.dev` の URL は無効のままで、すべての読み取りは Worker を経由します。ライセンスのエリアは、CLI のテンプレートバンドル用に 2 つ目のバケット `BUNDLES` をバインドします（[テンプレートバンドル](#template-bundles)を参照）。

## オブジェクトの配置

各動画のファイルは `videos/<videoId>/` 配下に置かれます。`videoId` は `video` の行の ID です。キーは `src/modules/video/video.files.ts` の `videoObjectKey` と `videoDirectory` が組み立てます。`mediaContentType` は、アップロードまたは配信できるファイル名だけを、そのメディアタイプとともに列挙します。それ以外のファイルは拒否されます。

アップロードされたレッスンの資料は、それぞれ `attachments/<attachmentId>/<fileName>` 配下に置かれます。`attachmentId` は `lesson_attachment` の行の ID で、`fileName` はアップロードされた名前を英字、数字、ドット、ハイフン、アンダースコアだけに絞ったものです。`src/modules/lesson-attachment/lesson-attachment.files.ts` の `attachmentObjectKey` と `attachmentContentType` がキーを組み立て、アップロードまたは配信できる <RepositoryFact name="attachmentFileTypes" /> の拡張子のメディアタイプを返します。

コースのカバー画像は、フルサイズが `covers/<courseId>/<coverId>.<extension>` に置かれ、小さいサイズはその横に `<coverId>-<width>.<extension>` として置かれます。キーは `src/modules/course/course.cover.ts` の `coverObjectKey` と `coverVariantKey` が組み立て、`coverContentType` が保存されたカバー画像（WebP または JPEG）のメディアタイプを返します。

## 署名済みの配信

プレーヤーがバケットのキーを目にすることはありません。サーバー関数が `createPlayback`（`src/modules/video/video.playback.ts`）を呼び出し、この関数が次の形式のパスを返します。

```text
/media/<expiry>.<signature>/<videoId>/master.m3u8
```

- `expiry` は 36 進数の Unix 時刻です。少なくとも <RepositoryFact name="signedMediaHours" unit="hour" />先の時刻を 1 時間単位に切り上げるため、同じ 1 時間のうちに発行されたリンクは同一になり、ブラウザーでキャッシュできる状態が保たれます。
- `signature` は、`AUTH_SECRET` から HKDF で導出した鍵による `<videoId>.<expiry>` の HMAC-SHA-256 です。そのため追加のシークレットは不要で、この鍵はほかの用途には使われません。
- プレイリストはレンディション、セグメント、字幕を相対パスで参照するため、署名済みの 1 つのプレフィックスでストリーム全体をカバーできます。

`src/server.ts` は、すべての `/media/` リクエストを、ロケールミドルウェアと TanStack Start より前に `REQUEST_HANDLERS` にあるコースのエントリーのいずれかへ渡し、通常のセキュリティヘッダーを付けます。これらのエントリーは `/media/covers/` には `serveCover` を、`/media/downloads/` には `serveAttachment` を、それ以外のパスには `serveMedia`（`src/modules/video/video.delivery.ts`）を、それぞれ動的な `import()` で読み込みます。`serveMedia` の動作は次のとおりです。

- `GET` と `HEAD` だけを受け付けます（それ以外は `405`）。
- 一覧にあるメディアファイル以外のパスには `404` を、期限切れまたは不正な署名には `403` を返します。
- `Range` リクエストには `206` と `Content-Range` で応答し、ファイルの範囲外を指定された場合は `416` を返します。
- 可能な場合は、ファイル全体を Workers のキャッシュから配信します。キャッシュには署名を除いた `/media/_/<videoId>/<file>` の下にファイルを保存するため、すべての視聴者がエッジロケーションごとに 1 つのキャッシュ済みコピーを共有します。ブラウザーへのレスポンスは `private, max-age=86400, immutable` です。

署名済みパスは、期限が切れるまでベアラーリンクとして機能します。パスを持っていれば誰でもその動画を再生できます。誰が視聴できるかのチェックは、パスを発行する時点で行われます。

レッスンの資料も、`/media/downloads/<expiry>.<signature>/<attachmentId>/<fileName>` の下で同じ方式を使います。鍵は専用で、有効期間は少なくとも <RepositoryFact name="signedDownloadHours" unit="hour" />です。`getLesson` は、レッスンを開ける視聴者に対してだけ署名します。`serveAttachment`（`src/modules/lesson-attachment/lesson-attachment.delivery.ts`）は `/media/` のハンドラーから `serveMedia` の代わりに `/media/downloads/` 以下のリクエストを受け取り、`GET` と `HEAD` だけを受け付け、期限切れまたは不正な署名には `403` を、存在しないファイルには `404` を返し、`Content-Disposition: attachment` と `Cache-Control: private, no-store` を付けてファイルを配信します。

コースのカバー画像は公開されており、署名なしで `/media/covers/<courseId>/<file>` に置かれます。カタログ、コースのページ、ランディングページがすべての訪問者に表示するためです。`serveCover`（`src/modules/course/course.delivery.ts`）は `GET` と `HEAD` だけを受け付け（それ以外は `405`）、カバー画像を指さないパスと存在しないファイルには `404` を返し、カバー画像を `Cache-Control: public, max-age=31536000, immutable` で配信して、Workers キャッシュ `covers` にコピーを保持します。新しいカバー画像には毎回新しい ID が付くため、キャッシュされたコピーが古くなることはありません。[コースのカバー画像](/docs/features/courses#course-covers)を参照してください。

事業者のロゴも公開で署名なしです。パスは `/media/logos/<file>`、R2 キーは `logos/<logoId>.<extension>` で、`src/modules/business-profile/business-profile.logo.ts` の `logoObjectKey` が組み立て、`logoContentType` がメディアタイプ（WebP または PNG）を返します。`serveBusinessLogo` は同じルールで配信し、Workers キャッシュ `logos` にコピーを保持します。`src/server.ts` はこのハンドラーをコースのハンドラーより前に並べるため、`/media/logos/` がコース側に届くことはありません。[設定](/docs/features/settings#business-profile)を参照してください。

## アップロード

Worker は動画のアップロードを受け付けません。`scripts/publish-video.ts` が、`bunx wrangler login` でのログインを使い、`wrangler r2 bulk put --remote` でバケットに書き込みます。[動画](/docs/features/videos)を参照してください。管理画面から動画を削除すると、バインディングを通じてプレフィックス配下を一覧し、オブジェクトをページ単位で削除します。

Worker が受け付けるアップロードは、レッスンの資料とコースのカバー画像の 2 つです。`uploadLessonAttachment` は管理者から最大 <RepositoryFact name="attachmentMaxMegabytes" /> MB のファイルを受け取り、バインディングを通じて書き込みます。資料、またはそれが属するレッスン、チャプター、コースを削除すると、そのオブジェクトも削除されます。[コース](/docs/features/courses#materials)を参照してください。`uploadCourseCover` は管理者からカバー画像の各サイズをそれぞれ最大 <RepositoryFact name="courseCoverMaxMegabytes" /> MB で受け取り、カバー画像を差し替えるか外すか、コースを削除すると、そのファイルが削除されます。

## テンプレートバンドル [#template-bundles]

どの環境も、ライセンスのエリアの `BUNDLES` バケットもバインドします。

<RepositoryTable columns={["環境", "バケット"]} name="cliBundleBuckets" />

このバケットには、CLI のリリースごとに 1 つのオブジェクト、つまり <RepositoryFact name="cliBundleKey" /> に置かれたそのリリースのテンプレートバンドルが入ります。アップロードするのは CLI のリポジトリのリリースで、内容の SHA-256 をカスタムメタデータ <RepositoryFact name="cliBundleDigestMetadata" /> として付けます。Worker がこのバケットに書き込むことはなく、そのダイジェストはアーカイブではなく `head()` で読み取ります。[CLI ライセンス API](/docs/features/cli-licence-api#template-bundles) は、`/media/` パスと同じ方法で、ただし専用の鍵と <RepositoryFact name="cliApiBundleUrlTtlSeconds" unit="second" />の有効期間で <RepositoryFact name="cliBundleUrlPath" /> の URL に署名し、`serveBundle`（`src/modules/license/license.delivery.ts`）はオブジェクトをキャッシュせずにストリーミングします。[バンドルの公開](/docs/features/cli-licence-api#publishing-bundles)に、キー、コンテンツタイプ、リリースのアップロード先のバケットが記載されています。

## テスト

Vitest では、`cloudflare:workers` が `src/platform/testing/mocks/cloudflare.ts` に解決され、`test` 環境の R2 バインディング（`MEDIA` と `BUNDLES`）ごとに、`get`（範囲指定を含む）、`head`、カスタムメタデータ付きのテキスト、バイト列、ファイルの `put`、`delete`、ページ単位の `list` を備えたインメモリのバケットが提供されます。`src/platform/testing/mocks/cache.ts` は Workers のキャッシュをスタブします。テストビルドは `.wrangler/test` 配下のローカルの `saasyland-test` バケットと `saasyland-bundles-test` バケットを使います。
