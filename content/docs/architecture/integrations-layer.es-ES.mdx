Cada librería o servicio de terceros que necesita configuración tiene su propia carpeta en `src/integrations`. Los archivos se nombran `<prefix>.<concern>.ts`, donde el prefijo es el nombre corto del proveedor.

| Carpeta         | Archivos                                                                                                                                                                     | Responsabilidad                                                                                                                                                        |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `affonso`       | `affonso.constants`, `affonso.program`, `affonso.referral`                                                                                                                   | Los parámetros de referido, la URL del píxel, el ID del programa y el referido que se pasa a Polar como metadatos del checkout                                         |
| `better-auth`   | `auth.server`, `auth.client`, `auth.access`, `auth.middleware`, `auth.routes`, `auth.session`, `auth.errors`, `auth.hooks`, `auth.zod`, `auth.constraints`, `auth.constants` | Configuración de la autenticación, roles, middleware de funciones de servidor, guards de ruta y consulta de sesión, IDs de proveedores                                 |
| `drizzle-orm`   | `drizzle.config`, `drizzle.database`, `drizzle.schemas`, `drizzle.errors`, `drizzle.columns`, `migrations/`                                                                  | El cliente de D1, el registro de esquemas, las migraciones SQL, `rethrowAsConflict` para los errores de restricción única y las columnas compartidas de `timestamps()` |
| `fumadocs`      | `fumadocs.config`, `fumadocs.source`, `fumadocs.docs`, `fumadocs.search`, `fumadocs.i18n`                                                                                    | Colecciones MDX para la documentación y el blog, carga de páginas y búsqueda                                                                                           |
| `motion`        | `motion.features`, `motion.tokens`                                                                                                                                           | El bundle de funcionalidades de Motion con carga diferida y las transiciones compartidas                                                                               |
| `polar`         | `polar.config`, `polar.constants`                                                                                                                                            | El cliente del SDK de Polar y los IDs de producto que se ofrecen en el checkout                                                                                        |
| `resend`        | `resend.config`, `resend.utils`, `resend.constants`                                                                                                                          | El cliente de Resend, `sendEmail` y los nombres de `EMAIL_PURPOSE`                                                                                                     |
| `tanstack-form` | `form.fields`                                                                                                                                                                | Tipos de campo y `fieldErrorMessage` para TanStack Form                                                                                                                |
| `use-intl`      | `i18n.config`, `i18n.messages`, `i18n.middleware`, `i18n.paths`, `i18n.utils`                                                                                                | Locales, carga de mensajes, URL con locale y cookies                                                                                                                   |

## Lo que no es una integración

- El número de estrellas de GitHub es una función de servidor en `src/lib/github.ts`, cacheada en KV.
- La limitación de peticiones está en `src/lib/rate-limit.ts` y se apoya en la tabla `rate_limit`.
- Los bindings de Cloudflare no necesitan adaptador. El código de servidor los lee de `env` en `cloudflare:workers`.

## La lógica de negocio se queda en los módulos

Una integración configura un proveedor. Las decisiones sobre los datos de la aplicación corresponden al módulo que es dueño de la tabla:

- El plugin de Polar en `auth.server.ts` verifica las firmas de los webhooks con `POLAR_WEBHOOK_SECRET` y entrega los eventos a `licenseWebhookHandlers`, en `src/modules/license/license.webhooks.ts`, que llaman a los casos de uso de licencias.
- Los hooks de correo de Better Auth llaman a `sendVerifyEmail`, `sendResetPasswordEmail` y `sendChangeEmailConfirmationEmail`, de los módulos de verificación y de cuenta.
- Un caso de uso envía un correo en el locale que le pasa quien lo llama (el correo de verificación lo lee de la URL de callback): carga el namespace de la plantilla, renderiza la plantilla y llama a `sendEmail`:

```ts
const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotency: { purpose: EMAIL_PURPOSE.VERIFY_EMAIL, token },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```
