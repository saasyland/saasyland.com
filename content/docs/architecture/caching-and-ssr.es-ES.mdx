## Caché de consultas

`getRouter` crea un `QueryClient` nuevo en cada petición, así que en el servidor no se filtran datos entre usuarios. Valores por defecto:

| Ajuste                               | Valor                                                                                                                                                  |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `staleTime` de las consultas         | <RepositoryFact name="queryStaleTimeMinutes" unit="minute" />                                                                                          |
| `gcTime` de las consultas            | <RepositoryFact name="queryGcTimeMinutes" unit="minute" />                                                                                             |
| `defaultStaleTime` del router        | <RepositoryFact name="routerStaleTimeMinutes" unit="minute" />                                                                                         |
| `defaultPreloadStaleTime` del router | <RepositoryFact name="routerStaleTimeMinutes" unit="minute" />                                                                                         |
| Precarga                             | Por intención, y las [páginas de la cabecera](/docs/conventions/performance#the-headers-pages-load-before-a-click) en cuanto una página queda inactiva |

Los loaders llenan la caché con `queryClient.query({ ...options, staleTime: "static" })` y los componentes leen las mismas claves con `useSuspenseQuery`. Las páginas de cursos y el editor de cursos de la administración son la excepción: sus queries usan `staleTime: COURSE_STALE_MS` (<RepositoryFact name="courseStaleMinutes" unit="minute" />), porque `invalidateQueries` nunca vuelve a pedir una query `static`, y al terminar una lección o guardar un cambio en el editor hay que refrescar el temario. `setupRouterSsrQueryIntegration` serializa la caché del servidor en el HTML y la hidrata en el navegador.

- **Los mensajes de traducción** se cachean por locale y namespace con `staleTime` y `gcTime` infinitos.
- **La consulta de sesión** (`getCurrentSessionQuery`) tiene un `staleTime` de <RepositoryFact name="sessionStaleTimeMinutes" unit="minute" />. Los guards de ruta dejan pasar una navegación con la sesión en caché mientras está fresca y la vuelven a pedir cuando caduca. Una función de servidor que responde `UNAUTHORIZED` o `FORBIDDEN` hace que `recheckRefusedSession` en `auth.routes.ts` vuelva a comprobar la sesión, y los guards se ejecutan de nuevo si ha cambiado. Cuando cambia el usuario con sesión iniciada, los guards eliminan todas las consultas que no están marcadas con `meta: { public: true }`. Las consultas públicas, como las traducciones y el número de estrellas con el que se renderizó una página prerenderizada, siguen en caché. Consulta [Consultas públicas](/docs/conventions/data-fetching#public-queries).
- **Las mutaciones** invalidan las claves de consulta de su módulo, por ejemplo `USER_QUERY_KEYS.ALL`, cuando terminan con éxito.

## Prerenderizado

`bun run build` prerenderiza las páginas públicas rastreando los enlaces: la landing, las páginas legales, el blog y la documentación en todos los locales. Se excluyen las rutas bajo `/admin`, `/app`, `/auth`, `/courses`, `/newsletter` y `/api` (con o sin prefijo de locale), así como los enlaces con query string o hash. Las páginas de cursos se excluyen porque muestran los bloqueos y el progreso de cada espectador. El navegador completa el bloque de cursos de la página de inicio con `getCourseShowcase` cuando se acerca al área visible, así que la página de inicio prerenderizada es la misma para todos (consulta [Cursos](/docs/features/courses)).

El Worker sirve el HTML prerenderizado desde el binding `ASSETS` antes de cargar la aplicación. Una página prerenderizada no contiene datos de usuario, así que se puede servir a cualquiera sin riesgo. Cuando un visitante tiene derecho a precios regionales, el Worker reescribe el HTML y marca la respuesta con `Cache-Control: private, no-cache`.

El prerenderizado se ejecuta en un build del Worker que contiene todas las páginas. Después, el Worker desplegado se vuelve a compilar sin las páginas compiladas de la documentación y del blog, y sin las traducciones que solo usan la landing y las páginas legales. No necesita ni unas ni otras: la documentación, el blog y la landing leen su contenido de índices que el build escribe en `/assets/`, en el navegador en una navegación en el cliente, y la búsqueda de la documentación busca en un índice estático dentro del navegador, así que las navegaciones en el cliente y la búsqueda nunca llegan al Worker (consulta [Rendimiento](/docs/conventions/performance#the-worker-holds-no-docs-or-blog-content)). Consulta [Cloudflare Workers](/docs/integrations/cloudflare-workers).

## KV y D1

- **KV (`CACHE`)** guarda el número de estrellas de GitHub para `src/lib/github.ts`. Un número de estrellas con más de <RepositoryFact name="starCountRefreshHours" unit="hour" /> de antigüedad se devuelve al instante y se actualiza en segundo plano con `waitUntil`.
- **D1 (`DB`)** guarda las sesiones y los contadores de límite de peticiones. Las comprobaciones de sesión de las funciones de servidor se saltan la caché de cookies de Better Auth y se memoizan durante el resto de la petición.
- **La caché de Workers** guarda los archivos de vídeo que `serveMedia` lee de R2 bajo `/media/_/<videoId>/<file>`, sin la firma, para que los espectadores de una misma ubicación del edge compartan una única copia en caché. Consulta [Cloudflare R2](/docs/integrations/cloudflare-r2).
- Las funciones de servidor nunca toman una decisión de permisos a partir de datos cacheados.
