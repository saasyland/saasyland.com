---
title: "Add a module"
description: "Add a database table with its Drizzle schema, Zod schemas, constants, types and use cases."
---

A module is one database table. `src/modules/<table>/` exists only for real tables; server functions that do not own a table live in `src/lib` or in the route that uses them. `src/modules/category` is the smallest complete example.

## Files

| File                       | Contents                                                                                                                                  |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `<table>.schema.ts`        | Drizzle table, indexes, relations and the enum tuples built from the constants                                                            |
| `<table>.zod.ts`           | One input schema per operation plus `drizzle-zod` schemas, exported as `<table>ZodSchemas`                                                |
| `<table>.constants.ts`     | Named domain values such as `CATEGORY_KIND`, column limits and the query and mutation key tuples                                          |
| `<table>.types.ts`         | One interface with the row types and the input type of every operation                                                                    |
| `<table>.utils.ts`         | Optional helpers; `license.utils.ts` reads the Worker environment, so it is server-only                                                   |
| `<table>.<concern>.ts`     | Optional code that is not one operation, such as `license.webhooks.ts` or `video.playback.ts` ([Module catalog](/docs/reference/modules)) |
| `use-cases/<operation>.ts` | One server function per file with its query or mutation options                                                                           |
| `__test__/`                | Tests named after the source file, such as `category.schema.test.ts` and `category.zod.test.ts`                                           |

## 1. Define the table

Name the table's values once in `category.constants.ts`. The schema, the Zod schemas, use cases, components, tests and e2e data import them from there instead of repeating a string such as `"collection"`:

```ts
export const CATEGORY_NAME_MAX_LENGTH = 255

export const CATEGORY_KIND = {
  CATEGORY: "category",
  COLLECTION: "collection",
} as const
```

Build the table from those names:

```ts
import { index, sqliteTable, text } from "drizzle-orm/sqlite-core"

import { timestamps } from "~/src/integrations/drizzle-orm/drizzle.columns"

import { CATEGORY_KIND, CATEGORY_NAME_MAX_LENGTH } from "~/src/modules/category/category.constants"

export const CATEGORY_KINDS = [CATEGORY_KIND.CATEGORY, CATEGORY_KIND.COLLECTION] as const

export const category = sqliteTable(
  "category",
  {
    id: text("id").primaryKey(),
    kind: text("kind", { enum: CATEGORY_KINDS }).notNull().default(CATEGORY_KIND.CATEGORY),
    name: text("name", { length: CATEGORY_NAME_MAX_LENGTH }).notNull(),
    ...timestamps(),
  },
  (table) => [index("category_createdAt_idx").on(table.createdAt)],
)
```

- Column names are snake_case, properties camelCase.
- IDs are `text` primary keys filled with `v7()` from `uuid` in the insert use case.
- `...timestamps()` from `src/integrations/drizzle-orm/drizzle.columns.ts` adds `createdAt` and `updatedAt`: millisecond timestamps that default to the insert time, and `updatedAt` is restamped on every update. Other dates are `integer(..., { mode: "timestamp_ms" })`; booleans are `integer(..., { mode: "boolean" })`.
- An enum column takes the tuple built from the constant object, and its default is a constant such as `CATEGORY_KIND.CATEGORY`, never a string literal.
- Foreign keys use `.references(() => user.id, { onDelete: "cascade" })`, and `relations(...)` declares joins (see `session.schema.ts`).

## 2. Register the schema

Export the table, and its relations if it has any, from `src/integrations/drizzle-orm/drizzle.schemas.ts`:

```ts
export { category } from "~/src/modules/category/category.schema"
```

This file feeds the D1 client (`drizzle(env.DB, { schema })`), the Better Auth Drizzle adapter and drizzle-kit. A table that is missing here gets no migration.

## 3. Generate the migration

```sh
bun run db:generate
bun run db:migrate:local
```

Review the generated SQL in `src/integrations/drizzle-orm/migrations/` and commit it with the schema. [Database migrations](/docs/guides/database-migrations) covers the remote environments.

## 4. Add the Zod schemas

Each operation gets its own input schema. Validation messages are translation keys; a form shows them with `ValidationFieldError` in the namespace it names.

```ts
import { createSchemaFactory } from "drizzle-zod"
import zod from "zod/v4"

import { MIN_FIELD_LENGTH, idField } from "~/src/modules/_core/utils/zod-fields"
import { CATEGORY_NAME_MAX_LENGTH } from "~/src/modules/category/category.constants"
import { CATEGORY_KINDS, category } from "~/src/modules/category/category.schema"

const { createInsertSchema, createSelectSchema, createUpdateSchema } = createSchemaFactory({ zodInstance: zod })

const createCategory = zod.object({
  kind: zod.enum(CATEGORY_KINDS),
  name: zod.string().min(MIN_FIELD_LENGTH, { message: "nameRequired" }).max(CATEGORY_NAME_MAX_LENGTH, { message: "nameMaxLength" }),
})

const deleteCategory = zod.object({ categoryId: idField })

export const categoryZodSchemas = {
  createCategory,
  deleteCategory,
  insert: createInsertSchema(category),
  select: createSelectSchema(category),
  update: createUpdateSchema(category),
}
```

Add `messages/<locale>/<table>.validations.json` for every locale with every key the schemas use. A form shows those keys only when its route preloads the namespace and passes it to `ValidationFieldError`; the admin course forms use `course.validations`, and the other forms use `auth.validations`.

## 5. Add constants and types

```ts
export const CATEGORY_QUERY_KEYS = {
  ALL: ["category"],
  LIST: ["category", "getCategories"],
} as const

export const CATEGORY_MUTATION_KEYS = {
  CREATE: ["category", "createCategory"],
  DELETE: ["category", "deleteCategory"],
  UPDATE: ["category", "updateCategory"],
} as const
```

```ts
import type * as zod from "zod"

import type { category } from "~/src/modules/category/category.schema"
import type { categoryZodSchemas } from "~/src/modules/category/category.zod"

export interface Category {
  select: typeof category.$inferSelect
  insert: typeof category.$inferInsert
  createCategory: zod.input<typeof categoryZodSchemas.createCategory>
  deleteCategory: zod.input<typeof categoryZodSchemas.deleteCategory>
}
```

Every key starts with the module name, so invalidating `ALL` refreshes every query of the module.

`Category` has one key per operation schema; the full `category` module also has `getCategories`, `getCategory` and `updateCategory`. A server function types its validator input as `Category["createCategory"]`, and its mutation or query options reuse that type. Add the key whenever you add a schema.

## 6. Add permissions and use cases

- Add the table's actions to `APP_STATEMENTS` in `src/integrations/better-auth/auth.access.ts` when the operations need permissions. See [Roles and permissions](/docs/guides/roles-and-permissions).
- Add one file per operation under `use-cases/`. See [Add a use case](/docs/guides/add-a-use-case).

## 7. Test

Add `__test__/<table>.schema.test.ts`, `<table>.zod.test.ts` and `<table>.types.test.ts` beside the module and `use-cases/__test__/<operation>.test.ts` for every operation. The coverage gate is <RepositoryFact name="coverageThreshold" unit="percent" />; see [Writing tests](/docs/guides/writing-tests).
