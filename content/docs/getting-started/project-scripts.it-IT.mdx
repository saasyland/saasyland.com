description: "I comandi che usi ogni giorno."
---

| Attività                                                        | Comando                  |
| --------------------------------------------------------------- | ------------------------ |
| Avviare il server di sviluppo                                   | `bun run dev`            |
| Controllare formattazione, lint, tipi e traduzioni              | `bun run check`          |
| Eseguire tutti i progetti Vitest                                | `bun run test`           |
| Eseguire la soglia di copertura                                 | `bun run test:coverage`  |
| Eseguire lo smoke test nel browser                              | `bun run test:e2e:smoke` |
| Eseguire tutte le spec browser in Chromium                      | `bun run test:e2e:pr`    |
| Eseguire tutte le spec browser in Chromium e WebKit, come la CI | `bun run test:e2e`       |
| Generare una migrazione                                         | `bun run db:generate`    |
| Compilare il Worker di preview                                  | `bun run build`          |
| Servire l'ultima build                                          | `bun run start`          |
| Eseguire il deploy della preview                                | `bun run deploy:preview` |

Prima di aprire una pull request, esegui la sequenza indicata in [Come contribuire](/docs/project/contributing), con le spec che coprono la tua modifica:

```sh
bun run check
bun run test:coverage
bun run build:test
bunx playwright test e2e/specs/<spec>.spec.ts --project=chromium
```

In locale Playwright ricrea il database di test con `db:reset:test`, compila il Worker di test e lo avvia all'indirizzo indicato da `PLAYWRIGHT_BASE_URL` (`127.0.0.1:3000` se non è impostata), a meno che un server non vi risponda già. Ogni worktree usa una propria porta dell'intervallo di cui la build di test si fida, e l'esecuzione si ferma quando il server sulla sua porta appartiene a un altro worktree: vedi [Eseguire la suite accanto ad altri worktree](/docs/tooling/playwright#running-beside-other-worktrees).

Usa `bun run test`, non `bun test`, così Vitest viene eseguito con la configurazione del progetto. Gli script che terminano con il nome di un ambiente, come `db:migrate:preview` o `deploy:production`, agiscono solo su quell'ambiente.

Vedi [Script del progetto](/docs/tooling/scripts) per l'elenco completo.
