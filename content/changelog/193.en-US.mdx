- Better Auth takes its base path from the route constants. `auth.server.ts` and `auth.client.ts` set `basePath` to `ROUTES.API_AUTH_BASE`, the path `src/routes/api/auth.$.ts` serves, instead of relying on Better Auth's default, and tests check the server, the browser client and the route against it; every URL stays the same. The docs print the OAuth callback paths from the same constants. `disabledPaths` is gone from the auth plugin entries and the Better Auth configuration, and `DISABLED_AUTH_PATHS` with it: no area has closed a path to HTTP since the Polar plugin stopped adding its own checkout. An integration test checks that the Polar plugin's checkout path answers 404, so adding `checkout()` to the plugin again fails the suite. See [Authentication and security](/docs/integrations/better-auth).
