---
title: "Konwencjonalne commity"
description: "Format komunikatów commitów i hook dodający emoji."
---

Tematy commitów mają postać `<type>(<scope>): <description>`. Zakres jest opcjonalny, a `!` oznacza zmianę łamiącą zgodność. Pisz temat bez emoji:

```sh
git commit -m "fix(auth): keep the locale in verification links"
```

Hook `prepare-commit-msg` w `.vite-hooks/` uruchamia `bun scripts/commit-msg.ts`, który waliduje temat i dodaje na jego początku emoji odpowiadające typowi, więc powyższy commit otrzymuje temat `🐛 fix(auth): keep the locale in verification links`.

| Typ        | Emoji |
| ---------- | ----- |
| `build`    | 🛠️    |
| `chore`    | ♻️    |
| `ci`       | ⚙️    |
| `docs`     | 📚    |
| `feat`     | ✨    |
| `fix`      | 🐛    |
| `perf`     | 🚀    |
| `refactor` | 📦    |
| `revert`   | 🗑️    |
| `style`    | 💎    |
| `test`     | 🚨    |

Każdy inny typ lub temat niezgodny z konwencjonalnym formatem przerywa commit i wyświetla listę dozwolonych typów. Hook nie zmienia tematów, które już zaczynają się od emoji, tematów wygenerowanych przez Git (`Merge`, `Revert "`, `fixup!`, `squash!`) ani komunikatów scalenia, squasha i szablonów.

Przed hookiem komunikatu hook `pre-commit` uruchamia `bun run check:pre-commit`. Nie omijaj hooków.
