## Qu'est-ce que SaaSy Land ?

SaaSy Land est un kit de démarrage SaaS React commercial. Une CLI pose des questions de configuration et n'écrit que les modules correspondant à vos réponses : authentification sur votre propre base de données, facturation, e-mails transactionnels, console d'administration, internationalisation et éditeur visuel de pages. Il est livré avec <RepositoryCount fact="testFiles" /> fichiers de tests et un seuil de couverture qui les impose déjà, de sorte que le code que vous recevez est vérifié, et pas seulement présent.

Le code source du site web public est sous licence MIT ; la CLI et les modèles privés, distincts, sont propriétaires. Achetez une licence, connectez-vous sur saasyland.com et obtenez la clé nécessaire pour installer et utiliser la CLI. La validation de licence en ligne s'applique à la CLI. Les applications générées peuvent être modifiées et déployées sous la licence commerciale et ne nécessitent aucune clé à l'exécution. La licence du site web n'accorde aucun droit sur la marque SaaSy Land.

## Choisissez votre stack, lancez une commande

La CLI n'est pas un modèle que vous téléchargez avant de devoir lutter contre lui. Elle demande ce que vous construisez et écrit exactement cela : le même outil génère aussi bien un projet personnel mono-tenant qu'un produit multi-tenant avec un merchant of record.

```bash
bunx saasyland@latest init my-app \
  --framework tanstack \
  --tenancy multi \
  --billing polar \
  --content mdx \
  --email resend
```

Quelques-uns des choix, avec des options volontairement banales pour que la commande supporte d'être collée dans un script plutôt que dans un prompt :

| Question    | Options                                           | Pourquoi c'est une question                                                                                                                                                                           |
| ----------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Framework   | `next`, `tanstack`                                | Les deux sont pris en charge ; choisissez celui que votre équipe connaît déjà                                                                                                                         |
| Tenancy     | `multi`, `single`                                 | Ajouter les organisations après coup touche chaque requête que vous avez écrite                                                                                                                       |
| Facturation | `stripe`, `polar`, `lemonsqueezy`, `--no-billing` | Polar et Lemon Squeezy sont des merchants of record et prennent en charge pour vous la TVA européenne et la taxe de vente américaine. Stripe, non. Un fondateur tranche cette question une seule fois |
| Contenu     | `mdx`, `--no-content`                             | Un blog et une documentation, ou ni l'un ni l'autre                                                                                                                                                   |
| E-mail      | `resend`, `--no-email`                            | Des e-mails transactionnels intégrés aux flux d'authentification, ou aucun                                                                                                                            |

Changez une réponse et la commande change avec elle. Relancez-la pour le projet suivant : les réponses changent, la CLI et les mises à jour à vie restent les mêmes.

### Pourquoi le seuil de couverture compte davantage aujourd'hui qu'au lancement

À la sortie de la 2.0, le chiffre de couverture était un argument de qualité. C'est depuis devenu un argument de débit, car une grande partie du code ajouté aux bases de code SaaS est désormais écrite par un agent.

Dans l'[enquête Stack Overflow 2025 auprès des développeurs](https://survey.stackoverflow.co/2025/ai), 84 % des développeurs déclaraient utiliser ou prévoir d'utiliser des outils d'IA, tandis que la frustration la plus citée, mentionnée par 45 % d'entre eux, était une production d'IA « presque juste, mais pas tout à fait ». Un seuil qui fait échouer le build est la réponse la moins coûteuse à ce problème : un agent ne peut pas ajouter de comportement sans ajouter de test, et tout ce qu'il casse apparaît dans la pull request plutôt que chez un client.

Nous l'avons expliqué en détail dans [pourquoi votre dépôt détermine la qualité du travail de l'agent](/blog/ai-coding-agents-repository-readiness) et dans [comment choisir une stack pour les agents de programmation IA](/blog/choosing-a-saas-stack-for-ai-coding-agents). En bref, ce dépôt obtient 18 sur 20 à notre propre grille d'évaluation de préparation, par construction plutôt qu'à force d'efforts.
