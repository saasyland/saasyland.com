Vite+ exécute Vitest avec la configuration de `vite.config.ts`. Les tests se trouvent dans un dossier `__test__` à côté du code qu'ils couvrent et importent leur API depuis `vite-plus/test`.

| Projet        | Fichiers                                                    | Environnement                     |
| ------------- | ----------------------------------------------------------- | --------------------------------- |
| `node`        | `*.test.ts` et `*.test.tsx`, sauf les deux types ci-dessous | Node                              |
| `integration` | `*.integration.test.ts`                                     | Node, délais d'expiration de 20 s |
| `component`   | `*.component.test.tsx`                                      | jsdom                             |

```sh
bun run test
bun run test:unit
bun run test:integration
bun run test:component
bun run test:watch
bun run test:changed
bun run test:coverage
```

Utilisez `bun run test`, et non `bun test` : le lanceur de tests propre à Bun ignore les projets, les environnements et le fichier de configuration de Vitest.

## Plateforme de test

`src/platform/testing/` contient le câblage partagé ; tout le reste est placé à côté de son propriétaire.

- `setup.ts` enregistre les matchers jest-dom et les hooks partagés.
- `mocks/cloudflare.ts` remplace `cloudflare:workers` : D1 est une base de données `node:sqlite` en mémoire qui applique chaque migration versionnée, et KV est une map en mémoire.
- `lib/server-function.ts` appelle les fonctions serveur via le véritable pipeline de middleware et de validation de TanStack.
- `lib/render.tsx` rend les composants avec un vrai QueryClient et un vrai routeur.
- `mocks/providers.ts` intercepte les requêtes vers Resend et Polar. Seul le Worker de test Playwright (`worker.ts`) l'installe.

Les appels externes d'e-mail, d'OAuth et de paiement ne quittent jamais le processus de test.

## Couverture

`bun run test:coverage` impose 100 % de lignes, d'instructions, de fonctions et de branches pour `src/**/*.{ts,tsx}`. Les tests, les dossiers `__test__`, les fichiers de déclaration, `src/routeTree.gen.ts`, les primitives shadcn et `src/platform/testing/` sont exclus. Les rapports sont écrits dans `coverage/` au format texte, HTML et `coverage-summary.json`. Couvrez le comportement réel et supprimez les branches qui ne peuvent jamais s'exécuter plutôt que de remplacer des globales pour les atteindre. La CI exécute le contrôle de couverture sur chaque pull request.
