## A resposta curta

Se você precisa começar um SaaS com TanStack Start esta semana, com equipes, cobrança por assento e uma área administrativa desde o primeiro dia, as opções pagas maduras são o **MakerKit** e o **supastarter**. O MakerKit se encaixa melhor se você também quer Supabase ou Next.js sob a mesma licença; o supastarter se encaixa melhor se você quer cinco provedores de pagamento e um site de marketing com deploy separado do app.

Se você faz deploy no **Cloudflare Workers**, o **TanStarter** (tanstarter.dev) é o kit pago com o menor preço de tabela que hoje é feito para essa plataforma.

Se você quer algo gratuito e pequeno, o **Cove Stack**, o template que antes se chamava TanStarter, conecta TanStack Start, Better Auth e Drizzle e não deixa nada para você apagar.

O **Open SaaS** é gratuito e completo, mas é construído sobre o Wasp, e não sobre o TanStack Start.

O **SaaSy Land** é a escolha se você quer ler um aplicativo TanStack Start de produção inteiro, no Cloudflare Workers, antes de decidir, sujeito a um gate de cobertura de <RepositoryFact name="coverageThreshold" />% e traduzido para <RepositoryFact name="languages" /> idiomas. A CLI dele está em beta e gera um projeto a partir das opções que você pode escolher no configurador dela, então leia a seção sobre o que o SaaSy Land é hoje antes de comprar.

## Dois nomes que confundem os resultados de busca

**TanStarter agora designa dois produtos diferentes.** O template gratuito de domínio público a partir do qual muitos projetos TanStack Start começaram foi publicado como TanStarter. Em setembro de 2026, o autor o renomeou para **Cove Stack**, porque o nome antigo “is now shared with a growing, unaffiliated product that is commercially offered as a SaaS boilerplate”. Esse produto é o **TanStarter** em tanstarter.dev, um kit pago para o Cloudflare Workers. Os dois são comparados aqui com os nomes que usam hoje, e os links antigos do GitHub redirecionam para o Cove Stack.

**O Open SaaS não é um kit de TanStack Start.** Ele aparece em todas as listas de boilerplates SaaS gratuitos, então tem lugar nesta comparação, mas roda sobre o framework Wasp: React com React Router no navegador, Node.js no servidor, Prisma e PostgreSQL por baixo. O Wasp encapsula o TanStack Query no seu próprio `useQuery`, e é daí que vem a confusão. Se você escolheu o TanStack Start, o Open SaaS é uma decisão diferente, e não um kit diferente.

**MakerKit e supastarter vendem TanStack Start ao lado do Next.js.** Uma licença do MakerKit é vendida por camada de dados, Supabase, Drizzle ou Prisma, e inclui esse kit tanto para Next.js quanto para TanStack Start; a licença Supabase acrescenta o React Router. Uma compra do supastarter cobre um único framework, então a edição TanStack Start dele é comprada separadamente das edições Next.js e Nuxt.

## Você precisa de um kit inicial, ou a CLI oficial basta?

A própria CLI do TanStack cria um projeto: a página de início rápido indica `npx @tanstack/cli@latest create`, que pergunta pelo gerenciador de pacotes e pelos “optional add-ons like Tailwind CSS and ESLint”, e a documentação traz links para projetos de exemplo de integrações como Clerk e Supabase. Esse é o começo certo se você quer escolher e conectar cada camada por conta própria, e o Cove Stack é a mesma ideia levada um passo adiante, com autenticação e um banco de dados já conectados.

Um kit inicial SaaS serve para as camadas que vêm depois: login com verificação de e-mail e dois fatores, cobrança e seus webhooks, uma área administrativa, e-mail transacional, traduções e os testes que mantêm tudo isso funcionando. É dessas camadas que o restante desta comparação trata.

A divisão que importa é **onde o app roda**. Os kits de TanStack Start do MakerKit e do supastarter geram um servidor Node via Nitro e documentam hosts Node: Railway e Docker para as variantes Drizzle e Prisma do MakerKit, e sete hosts para o supastarter. A variante Supabase do MakerKit acrescenta guias para Vercel, Cloudflare e VPS, e o MakerKit anunciou um kit Cloudflare separado, vendido à parte do kit Drizzle e marcado como “Coming soon” no dia da verificação.

O TanStarter e o SaaSy Land são feitos para o Cloudflare Workers desde o início, com o D1 como banco de dados e KV e R2 ao lado. Isso é mais do que um preset de deploy. Não há servidor para provisionar nem para aplicar patches, e o D1 é SQLite, então o modelo de dados é escrito para ele desde a primeira migração, em vez de ser portado do Postgres mais tarde. A [documentação do Cloudflare Workers](/docs/integrations/cloudflare-workers) do SaaSy Land mostra como este site o utiliza.

**A biblioteca de autenticação convergiu.** Todos os kits de TanStack Start aqui usam o Better Auth, exceto a variante Supabase do MakerKit, que usa o Supabase Auth com segurança em nível de linha. Para quem compra, essa é uma boa notícia: os usuários e as sessões ficam no seu próprio banco de dados, e nenhum fornecedor de autenticação cobra você por usuário ativo.

**Autenticação.** O MakerKit e o supastarter vão mais longe: senha, magic link, passkeys, OAuth e dois fatores, com organizações, convites, papéis, um super admin e acesso como outro usuário. O TanStarter traz e-mail e senha com login pelo Google, e papéis de admin e de usuário. O Cove Stack tem e-mail e senha, com GitHub e Google como opções. O Open SaaS usa a autenticação própria do Wasp, com login por e-mail ativado e Google, GitHub e Discord prontos para serem ligados. O site do SaaSy Land roda o Better Auth com verificação de e-mail, redefinição de senha, troca de e-mail, login com GitHub e Google, papéis e dois fatores com códigos de backup. Ele ainda não tem organizações; o multitenancy está a caminho.

**Cobrança.** O supastarter suporta o maior número de provedores, incluindo Creem e Dodo Payments, que atuam como merchant of record. O kit de TanStack Start do MakerKit suporta Stripe ou Polar nas variantes Drizzle e Prisma e Stripe no Supabase, com planos por assento e por uso. O TanStarter suporta Stripe, Creem e Waffo Pancake, e o Open SaaS suporta Stripe, Lemon Squeezy, Polar e Paddle. O Cove Stack deixa a cobrança com você. O próprio site do SaaSy Land recebe pagamentos pela Polar, com checkout e webhooks incluídos, e esse código é público. A cobrança de um projeto gerado está a caminho: hoje a CLI escreve projetos sem ela.

**Idiomas.** O TanStarter traz inglês e chinês com Paraglide JS, o supastarter inclui traduções e um seletor de idioma, e o kit de TanStack Start do MakerKit usa use-intl com inglês ativado por padrão. O SaaSy Land roda em <RepositoryFact name="languages" /> idiomas com use-intl, sua documentação é escrita em todos eles, e uma verificação faz a CI falhar quando falta uma chave ou quando uma tradução quebra. O Cove Stack e o Open SaaS não trazem traduções.

**Testes.** Todos os kits pagos aqui têm testes end-to-end com Playwright e Vitest. O que muda é se alguma coisa impede que código não testado passe pelo merge. O guia de testes do MakerKit diz que não há um script de cobertura para o repositório inteiro: “no repo-wide (root) test:unit:coverage script”. O supastarter roda sua suíte Playwright localmente, e não na CI dos pull requests. O TanStarter documenta suítes unitárias, de navegador, de smoke tests do Worker e de sandbox de pagamento real, o que é mais do que a maioria oferece, e não declara nenhum limite de cobertura. O guia para agentes do Cove Stack diz que não há meta de cobertura, “there is no coverage target”, e o Open SaaS traz uma suíte Playwright sem testes unitários. O `vite.config.ts` do SaaSy Land define <RepositoryFact name="coverageThreshold" />% para instruções, ramificações, funções e linhas, e o merge falha abaixo disso; a [documentação de testes](/docs/tooling/testing) mostra como.

**Administração.** Todos os kits, exceto o Cove Stack, incluem uma área administrativa. As do MakerKit e do supastarter gerenciam usuários e organizações, e a do MakerKit acrescenta assinaturas e acesso como outro usuário. A do TanStarter gerencia usuários, papéis e banimentos, e o Open SaaS tem um painel de usuários e analytics. O console de administração do próprio SaaSy Land tem <RepositoryFact name="adminSections" /> seções, de produtos e pedidos a cursos e à newsletter; o de um projeto gerado tem o dashboard, uma tabela de usuários com suas ações e as configurações.

## Documentação e agentes de programação

Os seis publicam a documentação sem exigir login. A do MakerKit é a maior: a página inicial dele diz que o kit Next.js Supabase “alone has more than 170 pages” (sozinho, tem mais de 170 páginas), e cada variante TanStack Start tem seu próprio conjunto. A documentação de TanStack Start do supastarter cobre configuração, pagamentos, organizações, deploy e as skills para agentes dele, e pode ser baixada como zip. O TanStarter tem um site de documentação para a configuração do Cloudflare, as integrações e a CLI, e o Open SaaS tem um site de documentação construído com Astro Starlight. O Cove Stack se documenta no README e em um conjunto de guias para agentes. A [documentação](/docs) do SaaSy Land é pública em <RepositoryFact name="languages" /> idiomas e imprime seus valores a partir do código, então um número em uma página da documentação não tem como divergir do código que descreve.

Para agentes de programação, MakerKit, supastarter, Open SaaS e Cove Stack trazem um `AGENTS.md` com skills para agentes, e o MakerKit acrescenta um servidor MCP. ## O que o SaaSy Land é hoje, com precisão

Este é o nosso próprio produto, então aqui está exatamente o que você recebe e o que não recebe.

**O código deste site.** O código-fonte do saasyland.com é público sob a licença MIT. É um aplicativo TanStack Start completo em um Cloudflare Worker, com D1 via Drizzle, KV e R2, Better Auth, checkout e webhooks da Polar, Resend, use-intl em <RepositoryFact name="languages" /> idiomas e Fumadocs, sujeito ao gate de cobertura citado acima. Você pode ler cada linha antes de gastar qualquer coisa, o que nenhum dos outros kits pagos aqui oferece para o próprio código.

**A CLI que você compra.** Uma licença compra a CLI proprietária `saasyland`, que roda a partir da tag <RepositoryFact name="cliReleaseChannel" /> do npm. Ela ativa, mostra e libera os dispositivos em que sua chave roda, e o `init` escreve seu projeto a partir das opções que você pode escolher no [configurador](/#cli), o que hoje significa TanStack Start sobre React como monólito no Cloudflare Workers, SQLite no D1 com Drizzle, Better Auth ou nenhuma autenticação, Resend e conteúdo MDX. Qualquer outra opção encerra com o código <RepositoryFact name="cliExitNotAvailable" /> antes de a licença ser verificada; cobrança, Postgres, multitenancy, outros frameworks e outros hosts estão a caminho. A [documentação da CLI](/docs/cli) lista o que funciona agora.

## Qual kit inicial para TanStack Start você deve escolher?

**Escolha o MakerKit** se você está construindo um SaaS B2B que precisa de equipes, papéis e cobrança por assento na primeira versão, se quer Supabase com segurança em nível de linha e testes de banco de dados com pgTAP, ou se quer Next.js e TanStack Start sob uma única licença. Ele é mantido em tempo integral desde 2022, traz um servidor MCP e skills para agentes, e sua documentação é a mais completa entre os kits daqui. Reserve orçamento para o Teams se mais alguém mexer no código ou se você constrói para clientes. A [alternativa ao MakerKit](/blog/makerkit-alternative-for-engineers) o compara com o SaaSy Land em detalhes.

**Escolha o supastarter** se você quer a maior variedade de provedores de pagamento, um site de marketing e um app do produto com deploys separados, ou uma API Hono e oRPC com documentação OpenAPI. Os planos por assento dele vão até dez desenvolvedores, e a página inicial diz que ele tem a confiança de 1.520 desenvolvedores.

**Escolha o TanStarter** se você faz deploy no Cloudflare Workers, quer o menor preço de tabela entre os kits pagos, quer as integrações de IA dele com Workers AI e fal.ai, ou quer inglês e chinês desde o primeiro dia. Pergunte ao autor sobre trabalho para clientes antes de contar com isso, já que os termos não são publicados.

**Escolha o Cove Stack** se você quer TanStack Start, Better Auth, Drizzle e shadcn/ui conectados e nada mais, sob uma licença de domínio público, e não se importa em construir por conta própria a cobrança, o e-mail e a área administrativa.

**Escolha o Open SaaS** se um kit gratuito, sob licença MIT, com pagamentos, um painel administrativo e deploys com um único comando importa mais para você do que o framework, e se você está confortável em adotar o Wasp, que o README do próprio Wasp descreve como em beta.

**Escolha o SaaSy Land** se você quer ler um aplicativo de produção completo antes de decidir, se o Cloudflare Workers com D1 é o seu destino, se você quer que um gate de cobertura de <RepositoryFact name="coverageThreshold" />% e <RepositoryFact name="languages" /> idiomas sejam o ponto de partida, e não o lugar aonde você espera chegar um dia, e se uma licença que conta dispositivos em vez de desenvolvedores combina com a sua equipe. Não o escolha se você precisa de cobrança, equipes ou outro host no projeto que gerar esta semana: em 22 de novembro de 2026 essas opções ainda estavam a caminho, e os kits acima já as oferecem.
