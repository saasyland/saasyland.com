description: "Las claves de .env.example y dónde las lee cada entorno."
---

Copia la plantilla para el entorno en el que trabajes. Git ignora `.env.development`, `.env.preview` y `.env.production`; `.env.test` está incluido en el repositorio con valores ficticios para las pruebas y la preview aislada.

```sh
cp .env.example .env.development
openssl rand -base64 48
```

Usa el valor generado como `AUTH_SECRET`, con un secreto distinto para cada entorno desplegado.

| Variables                                                                       | Propósito                                                                                            |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `AUTH_SECRET`                                                                   | Secreto de firma y cifrado de Better Auth                                                            |
| `AUTH_GITHUB_CLIENT_ID`, `AUTH_GITHUB_CLIENT_SECRET`                            | Aplicación OAuth de GitHub; también autentica la solicitud del recuento de estrellas de GitHub       |
| `AUTH_GOOGLE_CLIENT_ID`, `AUTH_GOOGLE_CLIENT_SECRET`                            | Aplicación OAuth de Google                                                                           |
| `RESEND_API_KEY`, `RESEND_EMAIL_FROM`                                           | Clave de API de Resend y dirección de remitente predeterminada                                       |
| `POLAR_SERVER`                                                                  | `sandbox` para desarrollo y preview, `production` para producción                                    |
| `POLAR_ACCESS_TOKEN`, `POLAR_ORGANIZATION_ID`                                   | Acceso a la API de Polar y la organización para descuentos y claves de licencia                      |
| `POLAR_WEBHOOK_SECRET`                                                          | Verifica los webhooks de Polar en `/api/auth/polar/webhooks`                                         |
| `POLAR_PRODUCT_ID_CORE`, `POLAR_PRODUCT_ID_COMPLETE`, `POLAR_PRODUCT_ID_AGENCY` | Productos de Polar para los tres niveles de checkout                                                 |
| `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID`, `CLOUDFLARE_ACCESS_TOKEN`    | Acceso a la API HTTP de D1 para Drizzle Studio y la introspección; la aplicación usa el binding `DB` |

Los entornos `development`, `preview` y `production` de `wrangler.jsonc` exigen todas las claves anteriores como secretos (`secrets.required`). El código del servidor las lee con `import { env } from "cloudflare:workers"`. Ninguna lleva el prefijo `VITE_`, porque Vite expone esos valores al navegador. `.env.example` enumera las claves en bloques, uno por módulo, en el mismo orden que `secrets.required`, y `src/__test__/wrangler.test.ts` falla cuando no coinciden.

`.env.development` también puede definir `LOCAL_ADMIN_PASSWORD`, la contraseña que `bun run db:seed:local` da al administrador local; no es un secreto del Worker y nunca sale de tu equipo. Consulta [El seed local](/docs/tooling/database#the-local-seed).

`AFFONSO_PROGRAM_ID` no es un secreto y no está en `.env.example`. Es el ID público del programa de Affonso que necesita el seguimiento de referidos de afiliados, así que es una variable de Worker en `vars` dentro de `wrangler.jsonc`, definida solo para el entorno que recibe pagos reales; `production` define el ID de programa de SaaSy Land, y `test`, un ID ficticio para las pruebas en el navegador. El seguimiento solo funciona cuando el Worker tiene el ID y el programa está abierto: hoy `AFFILIATE_PROGRAM` vale <RepositoryFact name="affiliateProgram" />. Consulta [Abrir el programa](/docs/features/affiliates#opening-the-programme).

## Valores en el código

Algunos ajustes forman parte del código, no son variables de entorno:

- `src/presentation/branding/index.ts`: el nombre de la aplicación, `APP_DOMAIN` (la URL canónica es `https://` seguido de ese dominio), el host de preview `APP_PREVIEW_DOMAIN`, las direcciones de contacto y el repositorio de GitHub.
- `src/modules/_core/constants/api.ts`: los hosts de preview y de producción (`DEPLOYED_HOSTS`, tomados de `APP_PREVIEW_DOMAIN` y `APP_DOMAIN`), que aceptan Better Auth y los enlaces del boletín (`appHostsForMode`) y que los scripts de despliegue comprueban después de un despliegue.
- `wrangler.jsonc`: los nombres de los Workers, los dominios personalizados, que `src/__test__/wrangler.test.ts` mantiene iguales a `DEPLOYED_HOSTS`, los ID de D1 y KV y los nombres de los buckets de R2.

## Callbacks de los proveedores

- GitHub y Google: <RepositoryFact name="oauthCallbackUrls" />.
- Webhooks de Polar: `https://<host>/api/auth/polar/webhooks`, firmados con `POLAR_WEBHOOK_SECRET`. [Configuración de Polar](/docs/getting-started/polar-setup) enumera los eventos, los productos, los descuentos y los ámbitos del token, y `bun run polar:verify:<environment>` los comprueba.
