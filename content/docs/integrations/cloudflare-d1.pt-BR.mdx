O Cloudflare D1 (SQLite) é o banco de dados da aplicação, vinculado como `DB`. `src/integrations/drizzle-orm/` o conecta ao Drizzle:

| Arquivo               | Finalidade                                                                                         |
| --------------------- | -------------------------------------------------------------------------------------------------- |
| `drizzle.database.ts` | `db` exclusivo do servidor, criado com `drizzle(env.DB, { schema })`                               |
| `drizzle.schemas.ts`  | Reexporta o schema de cada tabela e suas relações                                                  |
| `drizzle.config.ts`   | drizzle-kit: dialeto SQLite, driver `d1-http`, migrações com prefixo de timestamp em `migrations/` |

## Tabelas

Cada tabela tem o próprio módulo em `src/modules/<table>/` com `<table>.schema.ts` (`drizzle-orm/sqlite-core`), `.zod.ts`, `.constants.ts`, `.types.ts`, `.utils.ts` e `use-cases/`. Os módulos são `account`, `category`, `license`, `newsletter-subscriber`, `product`, `rate-limit`, `session`, `two-factor`, `user` e `verification`. Código que não é dono de uma tabela não ganha um módulo.

Os schemas seguem as mesmas convenções:

- IDs são strings UUID v7.
- Datas são colunas `integer` no modo `timestamp_ms`, com padrão `unixepoch() * 1000`.
- Booleanos são colunas `integer` no modo `boolean`.
- Relações, índices, restrições de unicidade e chaves estrangeiras são declarados no schema.

## Escritas atômicas

O D1 não tem transações interativas. Mantenha uma operação atômica com uma única instrução, como um upsert com `onConflictDoUpdate`, ou agrupe instruções com `db.batch`. Os casos de uso de listas paginadas buscam uma página e o seu total em um único batch (`src/modules/category/use-cases/get-categories.ts`):

```ts
const filter = data.kind === undefined ? undefined : eq(category.kind, data.kind)
const [rows, totals] = await db.batch([
  db
    .select()
    .from(category)
    .where(filter)
    .orderBy(desc(category.createdAt), desc(category.id))
    .limit(data.pageSize)
    .offset(data.pageIndex * data.pageSize),
  db.select({ total: count() }).from(category).where(filter),
])
return { rows, total: totals.reduce((sum, row) => sum + row.total, 0) }
```

O rate limiter em `src/lib/rate-limit.ts` combina limpeza, um upsert atômico e uma leitura em um único batch, para que as instâncias do Worker compartilhem os mesmos limites.

## Migrações

As migrações são arquivos SQL em `src/integrations/drizzle-orm/migrations/`, geradas com `bun run db:generate` e aplicadas com o Wrangler. O Vitest as executa em um banco SQLite em memória. Veja [Migrações de banco de dados](/docs/tooling/database) para os comandos.
