## Arquivos de ambiente

| Arquivo            | Versionado | Usado por                                                                                  |
| ------------------ | ---------- | ------------------------------------------------------------------------------------------ |
| `.env.example`     | Sim        | Lista todas as variáveis com valor vazio                                                   |
| `.env.development` | Não        | `bun run dev`, `db:studio:development`, `db:introspect:development`                        |
| `.env.preview`     | Não        | `deploy:preview` (`--secrets-file`), `db:studio:preview`, `db:introspect:preview`          |
| `.env.production`  | Não        | `deploy:production` (`--secrets-file`), `db:studio:production`, `db:introspect:production` |
| `.env.test`        | Sim        | O Vitest e o ambiente Wrangler `test`; apenas valores fictícios                            |

## Variáveis

| Variável                    | Usada por                                                                        |
| --------------------------- | -------------------------------------------------------------------------------- |
| `AUTH_SECRET`               | Assinatura, criptografia e tokens de verificação de e-mail do Better Auth        |
| `AUTH_GITHUB_CLIENT_ID`     | OAuth do GitHub; também autentica a requisição da contagem de estrelas do GitHub |
| `AUTH_GITHUB_CLIENT_SECRET` | OAuth do GitHub; também autentica a requisição da contagem de estrelas do GitHub |
| `AUTH_GOOGLE_CLIENT_ID`     | OAuth do Google                                                                  |
| `AUTH_GOOGLE_CLIENT_SECRET` | OAuth do Google                                                                  |
| `RESEND_API_KEY`            | O cliente do Resend                                                              |
| `RESEND_EMAIL_FROM`         | O remetente padrão de `sendEmail`                                                |
| `POLAR_ACCESS_TOKEN`        | O cliente do SDK do Polar                                                        |
| `POLAR_SERVER`              | `sandbox` ou `production`                                                        |
| `POLAR_WEBHOOK_SECRET`      | Verificação da assinatura dos webhooks do Polar                                  |
| `POLAR_ORGANIZATION_ID`     | Desativação de chaves de licença e consulta de descontos no Polar                |
| `POLAR_PRODUCT_ID_CORE`     | Produto de checkout do plano Core                                                |
| `POLAR_PRODUCT_ID_COMPLETE` | Produto de checkout do plano Complete                                            |
| `POLAR_PRODUCT_ID_AGENCY`   | Produto de checkout do plano Agency                                              |
| `CLOUDFLARE_ACCOUNT_ID`     | O driver HTTP do D1 usado pelo Drizzle Kit                                       |
| `CLOUDFLARE_DATABASE_ID`    | O driver HTTP do D1 usado pelo Drizzle Kit                                       |
| `CLOUDFLARE_ACCESS_TOKEN`   | O driver HTTP do D1 usado pelo Drizzle Kit                                       |

Cada ambiente em `wrangler.jsonc` lista as variáveis de que precisa em `secrets.required`; o ambiente `test` omite as três variáveis do Cloudflare. O código do Worker as lê de `env` em `cloudflare:workers`, com os tipos definidos em `src/types/bindings.d.ts`. Não existem variáveis `VITE_`: a URL pública e o domínio são constantes em `src/presentation/branding`.

## Bindings

| Binding  | Tipo             | `development`                | `preview` | `production` | `test`                 |
| -------- | ---------------- | ---------------------------- | --------- | ------------ | ---------------------- |
| `DB`     | D1               | Banco de preview, remoto     | Preview   | Produção     | `saasyland_test` local |
| `CACHE`  | KV               | Namespace de preview, remoto | Preview   | Produção     | Local                  |
| `ASSETS` | Assets estáticos | Sim                          | Sim       | Sim          | Sim                    |

Os scripts de deploy de preview e de produção executam primeiro `scripts/verify-bindings.ts`, que falha enquanto um ambiente ainda tiver IDs provisórios de D1 ou KV.
