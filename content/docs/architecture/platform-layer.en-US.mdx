## Worker and bindings

`wrangler.jsonc` sets `src/server.ts` as the Worker entry. The Worker receives four bindings:

| Binding  | Type          | Used for                                               |
| -------- | ------------- | ------------------------------------------------------ |
| `DB`     | D1 database   | All tables, including sessions and rate-limit counters |
| `CACHE`  | KV namespace  | The cached GitHub star count                           |
| `MEDIA`  | R2 bucket     | Video files, served by `serveMedia` under `/media/`    |
| `ASSETS` | Static assets | Prerendered pages and files from `public`              |

Requests for `/assets/*`, `/fonts/*`, `/robots.txt` and `/llms.txt` are served from static assets without running the Worker. Server code reads bindings, secrets and `waitUntil` from `cloudflare:workers`. `src/server.ts` adds the security headers to every response it returns; files served without the Worker get the subset in `public/_headers` ([Security and hardening](/docs/features/security)).

## Environments

`wrangler.jsonc` defines four environments. `CLOUDFLARE_ENV` selects one for `vp dev` and `vp build`.

| Environment   | Bindings                                | Used by                                         |
| ------------- | --------------------------------------- | ----------------------------------------------- |
| `development` | Remote preview D1, KV and R2            | `bun run dev`                                   |
| `preview`     | Preview D1, KV and R2                   | `bun run build:preview`, `deploy:preview`       |
| `production`  | Production D1, KV and R2                | `bun run build:production`, `deploy:production` |
| `test`        | Local D1, KV and R2 in `.wrangler/test` | `bun run build:test`, Playwright                |

Each environment lists its required secrets under `secrets.required`. Values come from the matching `.env.<environment>` file; the deploy scripts pass it to Wrangler with `--secrets-file`. The `test` environment uses `src/platform/testing/worker.ts` as its entry and the committed dummy values in `.env.test`.

## Types

- `src/types/bindings.d.ts` declares `Cloudflare.Env`: the bindings and every secret the Worker reads. The three `CLOUDFLARE_*` secrets are not declared, because only drizzle-kit reads them, from `process.env`.
- `src/types/worker-configuration.d.ts` is generated by `bun run cf-typegen`.
- `src/types/router.d.ts` registers the router type and the `staticData.namespaces` route option.

## Test runtime wiring

`src/platform/testing` holds only what cannot belong to one feature:

- `setup.ts`: jest-dom matchers, a binding reset before each test, and the `createServerFn` replacement that runs server functions in-process
- `mocks/cloudflare.ts`: an in-memory SQLite D1 that runs the checked-in migrations, an in-memory KV, an in-memory `MEDIA` bucket and a `waitUntil` that tests can flush
- `mocks/cache.ts`: `createEdgeCache`, a stub of the Workers cache for the media delivery tests
- `mocks/providers.ts`: fetch interception for Resend and Polar in browser tests, including captured emails
- `mocks/wrksz-themes.ts`: a replacement for the theme library
- `lib/`: the server-function RPC bridge, render helpers, request URL helpers and query runners
- `worker.ts`: the Worker entry for browser tests, which captures outgoing email

See [Testing and CI](/docs/architecture/testing-architecture) for how the suites use them.
