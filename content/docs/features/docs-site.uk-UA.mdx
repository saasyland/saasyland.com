## Вміст

- Сторінки — це файли `content/docs/<section>/<page>.<locale>.mdx` для всіх дев’яти мов.
- `meta.<locale>.json` у кожній теці задає назву розділу, іконку й порядок сторінок.
- `src/integrations/fumadocs/fumadocs.i18n.ts` використовує парсер `dot`, `en-US` як типову й резервну мову та `hideLocale: "always"`, бо префіксом мови застосунок керує сам.
- `bun run content` генерує `.source` з `fumadocs.config.ts`.

## Маршрути

- Макет `/docs` (`src/routes/docs.tsx`): серверна функція повертає дерево сторінок для поточної мови; макет показує `DocsLayout` з Fumadocs із посиланням на GitHub, а також `LocaleSelect` і `ThemeSwitch` як однаково оформлені поля вибору внизу бічної панелі, завантажує `docs.css` і показує `DocsPending` під час завантаження.
- `/docs/` і `/docs/$` викликають `loadDocsPage` (`fumadocs.docs.ts`), яка знаходить сторінку й перед рендерингом попередньо завантажує її скомпільований MDX (`docsContent`).
- `/api/search` надає пошук Fumadocs усіма мовами (`fumadocs.search.ts`).

Сторінки MDX можуть використовувати `mdxComponents` з `src/presentation/components/custom/mdx.tsx`: типові компоненти Fumadocs, `Accordions`, `Steps` і `Tabs` з Fumadocs, а також `Alert`, `Badge`, `Button`, частини картки, `Separator` і частини таблиці з shadcn. Посилання локалізуються автоматично.

## Додавання сторінки

1. Напишіть `<page>.en-US.mdx` з полями `title` і `description`.
2. Додайте slug до `meta.en-US.json` і до кожного іншого `meta.<locale>.json` у тому самому порядку.
3. Додайте вісім перекладів із побайтово ідентичними блоками коду.
4. Запустіть `bun scripts/check-content.ts` (входить до `bun run check:i18n`) і `bun run content`.

`bun run build` попередньо рендерить кожну сторінку документації всіма мовами.
