- API de licencias de la CLI: el Worker sirve el bundle de plantillas de cada versión, que `saasyland init` necesita para generar un proyecto. `POST /api/cli/v1/activations/:activationId/bundles` comprueba la licencia y que la activación pertenece al dispositivo que hace la llamada, y después responde con una URL HTTPS al archivo comprimido de la versión en el nuevo bucket de R2 `BUNDLES` del área de licencias, el SHA-256 del contenido JSON del archivo comprimido (el resumen que la CLI fija para cada versión), el tamaño del archivo comprimido y el momento en que caduca la URL, `API_LIMIT.BUNDLE_URL_TTL_SECONDS` después de emitirse. Si la versión no tiene archivo comprimido, la respuesta es `versionNotFound`, y si el bucket no se puede leer, `serviceUnavailable`. El handler del Worker del área de licencias sirve `/bundles/<expiry>.<signature>/<version>.json.gz` desde R2 cuando la caducidad y un HMAC son válidos, con una clave que HKDF deriva de `AUTH_SECRET` solo para los bundles, así que no hacen falta credenciales de S3; la derivación de claves que usaba la reproducción de vídeo pasa a `src/lib/hmac.ts`, que comparten ambos. La publicación de versiones del repositorio de la CLI sube cada archivo comprimido a los buckets de preview y de producción, y [Publicación de bundles](/docs/features/cli-licence-api#publishing-bundles) indica la clave, el tipo de contenido y los buckets. La política de privacidad indica que una petición de bundle envía la versión y las respuestas del stack, que la API no conserva.
