## The short answer

If you need to start a TanStack Start SaaS this week, with teams, per-seat billing and an admin area on day one, the mature paid choices are **MakerKit** and **supastarter**. MakerKit fits better if you also want Supabase or Next.js under the same licence; supastarter fits better if you want five payment providers and a marketing site that deploys separately from the app.

If you deploy to **Cloudflare Workers**, **TanStarter** (tanstarter.dev) is the paid kit with the lowest list price that is built for it today.

If you want something free and small, **Cove Stack**, the template that used to be called TanStarter, wires TanStack Start, Better Auth and Drizzle together and gives you nothing to delete.

**Open SaaS** is free and full-featured, but it is built on Wasp, not TanStack Start.

**SaaSy Land** is the choice if you want to read the whole of a production TanStack Start app on Cloudflare Workers before you decide, held to a <RepositoryFact name="coverageThreshold" />% coverage gate and translated into <RepositoryFact name="languages" /> languages. Its CLI is in beta and its project generation is arriving, so read the section on what SaaSy Land is today before you buy.

## Two names that muddle the search results

**TanStarter now means two different products.** The free, public-domain template that many TanStack Start projects started from was published as TanStarter. In September 2026 its author renamed it **Cove Stack**, because the old name "is now shared with a growing, unaffiliated product that is commercially offered as a SaaS boilerplate". That product is **TanStarter** at tanstarter.dev, a paid kit for Cloudflare Workers. Both are compared here under the names they use today, and the old GitHub links redirect to Cove Stack.

**Open SaaS is not a TanStack Start kit.** It appears on every list of free SaaS boilerplates, so it belongs in this comparison, but it runs on the Wasp framework: React with React Router in the browser, Node.js on the server, Prisma and PostgreSQL underneath. Wasp wraps TanStack Query in its own `useQuery`, which is where the confusion comes from. If you have chosen TanStack Start, Open SaaS is a different decision rather than a different kit.

**MakerKit and supastarter sell TanStack Start beside Next.js.** A MakerKit licence is sold per data layer, Supabase, Drizzle or Prisma, and includes that kit for both Next.js and TanStack Start; the Supabase licence adds React Router. A supastarter purchase covers one framework, so its TanStack Start edition is bought separately from its Next.js and Nuxt editions.

## Do you need a starter kit, or is the official CLI enough?

TanStack’s own CLI creates a project: its quick-start page gives `npx @tanstack/cli@latest create`, which asks for your package manager and "optional add-ons like Tailwind CSS and ESLint", and the documentation links example projects for integrations such as Clerk and Supabase. That is the right start if you want to choose and wire every layer yourself, and Cove Stack is the same idea one step further, with auth and a database already connected.

A SaaS starter kit is for the layers that come after: sign-in with email verification and two-factor, billing and its webhooks, an admin area, transactional email, translations, and the tests that keep all of it working. Those are the layers the rest of this comparison is about.

SaaSy Land’s CLI reserves an `update` command for a diff against the modules you generated; like project generation, it is not available yet.

The split that matters is **where the app runs**. MakerKit’s and supastarter’s TanStack Start kits build a Node server through Nitro and document Node hosts: Railway and Docker for MakerKit’s Drizzle and Prisma variants, and seven hosts for supastarter. MakerKit’s Supabase variant adds Vercel, Cloudflare and VPS guides, and MakerKit has announced a separate Cloudflare kit, sold apart from the Drizzle kit and marked "Coming soon" on the day of checking.

TanStarter and SaaSy Land are built for Cloudflare Workers from the start, with D1 as the database and KV and R2 beside it. That is more than a deployment preset. There is no server to provision or patch, and D1 is SQLite, so the data model is written for it from the first migration instead of being ported from Postgres later. SaaSy Land’s [Cloudflare Workers documentation](/docs/integrations/cloudflare-workers) shows how this site uses it.

**The auth library has converged.** Every TanStack Start kit here uses Better Auth, except MakerKit’s Supabase variant, which uses Supabase Auth with row-level security. For a buyer that is good news: the users and sessions live in your own database, and no auth vendor bills you per active user.

**Auth.** MakerKit and supastarter go furthest: password, magic link, passkeys, OAuth and two-factor, with organizations, invitations, roles, a super admin and impersonation. TanStarter ships email and password with Google sign-in, and admin and user roles. Cove Stack has email and password, with GitHub and Google as options. Open SaaS uses Wasp’s own auth, with email sign-in enabled and Google, GitHub and Discord ready to switch on. SaaSy Land’s site runs Better Auth with email verification, password reset, email change, GitHub and Google sign-in, roles, and two-factor with backup codes. It has no organizations yet; multi-tenancy is arriving.

**Billing.** supastarter supports the most providers, including the merchants of record Creem and Dodo Payments. MakerKit’s TanStack Start kit supports Stripe or Polar on its Drizzle and Prisma variants and Stripe on Supabase, with per-seat and metered plans. TanStarter supports Stripe, Creem and Waffo Pancake, and Open SaaS supports Stripe, Lemon Squeezy, Polar and Paddle. Cove Stack leaves billing to you. SaaSy Land’s own site takes payment through Polar, checkout and webhooks included, and that code is public. A generated project’s billing is arriving: the first release of project generation writes projects without it.

**Languages.** TanStarter ships English and Chinese with Paraglide JS, supastarter includes translations and a language switcher, and MakerKit’s TanStack Start kit uses use-intl with English enabled by default. SaaSy Land runs in <RepositoryFact name="languages" /> languages with use-intl, its documentation is written in all of them, and a check fails CI when a key is missing or a translation breaks. Cove Stack and Open SaaS ship no translations.

**Tests.** Every paid kit here has Playwright end-to-end tests and Vitest. What differs is whether anything stops untested code from being merged. MakerKit’s testing guide says there is "no repo-wide (root) test:unit:coverage script". supastarter runs its Playwright suite locally rather than in pull-request CI. TanStarter documents unit, browser, Worker smoke and real payment sandbox suites, which is more than most, and states no coverage threshold. Cove Stack’s agent guide says "there is no coverage target", and Open SaaS ships a Playwright suite without unit tests. SaaSy Land’s `vite.config.ts` sets <RepositoryFact name="coverageThreshold" />% for statements, branches, functions and lines, and the merge fails below it; the [testing docs](/docs/tooling/testing) show how.

**Admin.** Every kit except Cove Stack includes an admin area. MakerKit’s and supastarter’s manage users and organizations, and MakerKit’s adds subscriptions and impersonation. TanStarter’s manages users, roles and bans, and Open SaaS has a users and analytics dashboard. SaaSy Land’s admin console has a dashboard, a user table with its actions, and settings.

All six publish their documentation without a sign-in. MakerKit’s is the largest: its homepage says the Next.js Supabase kit "alone has more than 170 pages", and each TanStack Start variant has its own set. supastarter’s TanStack Start docs cover setup, payments, organizations, deployment and its agent skills, and can be downloaded as a zip. TanStarter has a docs site for its Cloudflare setup, integrations and CLI, and Open SaaS has a docs site built with Astro Starlight. Cove Stack documents itself in its README and a set of agent guides. For coding agents, MakerKit, supastarter, Open SaaS and Cove Stack all ship an `AGENTS.md` with agent skills, and MakerKit adds an MCP server. ## Which TanStack Start starter kit should you choose?

**Choose MakerKit** if you are building B2B SaaS that needs teams, roles and per-seat billing in the first release, if you want Supabase with row-level security and pgTAP database tests, or if you want Next.js and TanStack Start under one licence. It has been maintained full-time since 2022, it ships an MCP server and agent skills, and its documentation is the most complete here. Budget for Teams if anyone else touches the code or you build for clients. The [MakerKit alternative](/blog/makerkit-alternative-for-engineers) compares it with SaaSy Land in detail.

**Choose supastarter** if you want the widest choice of payment providers, a marketing site and a product app that deploy separately, or a Hono and oRPC API with OpenAPI documentation. Its seat-based tiers go up to ten developers, and its homepage says it is trusted by 1,520 developers.

**Choose TanStarter** if you deploy to Cloudflare Workers, want the lowest list price of the paid kits, want its AI integrations with Workers AI and fal.ai, or want English and Chinese from the first day. Ask the author about client work before you rely on it, since the terms are not published.

**Choose Cove Stack** if you want TanStack Start, Better Auth, Drizzle and shadcn/ui wired together and nothing else, under a public-domain licence, and you are happy to build billing, email and the admin area yourself.

**Choose Open SaaS** if a free, MIT-licensed kit with payments, an admin dashboard and one-command deploys matters more to you than the framework, and you are comfortable adopting Wasp, which Wasp’s README describes as in beta.

**Choose SaaSy Land** if you want to read a complete production app before you decide, if Cloudflare Workers with D1 is your target, if you want a <RepositoryFact name="coverageThreshold" />% coverage gate and <RepositoryFact name="languages" /> languages to be where you start rather than where you hope to end up, and if a licence that counts machines instead of developers suits your team. Do not choose it if you need to generate a project this week: project generation is arriving, and the kits above ship today.
