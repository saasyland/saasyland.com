`wrangler.jsonc` は 4 つの環境を定義しています。開発サーバーとビルドでは `CLOUDFLARE_ENV` で環境を選択し、各環境はそれぞれの環境ファイルからシークレットを読み込みます。

| 環境          | 選択元                                        | バインディング                         | シークレットの読み込み元 |
| ------------- | --------------------------------------------- | -------------------------------------- | ------------------------ |
| `development` | `bun run dev`                                 | リモートのプレビュー用 D1 と KV        | `.env.development`       |
| `preview`     | `build:preview`, `deploy:preview`             | プレビュー用 D1 と KV                  | `.env.preview`           |
| `production`  | `build:production`, `deploy:production`       | 本番用 D1 と KV                        | `.env.production`        |
| `test`        | `build:test`, `start:test`, `db:migrate:test` | `.wrangler/test` 内のローカル D1 と KV | `.env.test`              |

`.env.development`、`.env.preview`、`.env.production` は Git の管理対象外で、`.env.example` にそれらのキーが列挙されています。`.env.test` はコミットされており、ダミーの値だけを含みます。デプロイスクリプトは、対応するファイルを `wrangler deploy --secrets-file` でアップロードします。

## シークレット

各環境は `secrets.required` にシークレットを列挙します。Better Auth、OAuth、Resend、Polar のキーに加え、Drizzle のツール用に `CLOUDFLARE_ACCOUNT_ID`、`CLOUDFLARE_DATABASE_ID`、`CLOUDFLARE_ACCESS_TOKEN` があります（`test` 環境ではこの 3 つを省略します）。各キーについては[環境変数](/docs/getting-started/environment-variables)を参照してください。

サーバーのコードは `import { env } from "cloudflare:workers"` でシークレットを読み込みます。Vite は `VITE_` 変数をブラウザーに公開するため、`VITE_` 変数はどこでも使っておらず、シークレットを入れることも禁止です。クライアントのアセットが `cloudflare:workers` をインポートしている場合、`scripts/verify-build.ts` がビルドを失敗させます。正規のドメインは環境変数ではなく、`src/presentation/branding/index.ts` の `APP_DOMAIN` から取得します。

## バインディング

| バインディング | 種類         | 用途                                                   |
| -------------- | ------------ | ------------------------------------------------------ |
| `DB`           | D1           | アプリケーションのデータベース、セッション、レート制限 |
| `CACHE`        | KV           | GitHub のスター数                                      |
| `ASSETS`       | 静的アセット | プリレンダリングされたページ、フォント、公開ファイル   |

開発環境では Cloudflare のリモートバインディングを使うため、`bun run dev` はプレビュー用データベースを読み書きします。バインディングを変更した後は `bun run cf-typegen` を実行し、`src/types/worker-configuration.d.ts` を再生成してください。

## テスト

Vitest は `test.env` を通じて `.env.test` を読み込み、`cloudflare:workers` を `src/platform/testing/mocks/cloudflare.ts` に解決します。これによりインメモリの D1 と KV が提供されます。Playwright は `test` 環境と、そのエントリーである `src/platform/testing/worker.ts` を使います。どちらも本物の認証情報を必要としません。
