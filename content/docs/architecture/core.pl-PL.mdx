`src/modules/_core` to jedyny folder modułu, który nie ma własnej tabeli. Zawiera tylko fundament, na którym opierają się schematy, schematy Zod i przypadki użycia modułów, dzięki czemu żaden moduł nie definiuje go od nowa: kody błędów, stałe HTTP i środowisk, katalogi języków, stref czasowych, krajów i walut razem z walutą sklepu, współdzielone pola Zod i teksty w wielu językach oraz dane wejściowe paginacji, kolejności, wyszukiwania i zakresu czasu.

## Stałe

| Plik                    | Zawartość                                                                                                                                         |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `constants/errors.ts`   | `ERROR_CODES`, typ `ErrorCode` i klasa `AppError`                                                                                                 |
| `constants/api.ts`      | `HTTP_STATUS`, nazwy nagłówków `cf-ipcountry` i `cf-connecting-ip`, nagłówki bezpieczeństwa, dozwolone hosty dla każdego trybu builda             |
| `constants/locale.ts`   | Katalog `LOCALES`, `LocaleCode`, `getLocaleName` i `getLocaleDirection`                                                                           |
| `constants/country.ts`  | Katalog `COUNTRIES` i `CountryCode`                                                                                                               |
| `constants/currency.ts` | Katalog `CURRENCIES`, `CurrencyCode` oraz `toMinorUnits` i `fromMinorUnits`, które przeliczają kwotę na najmniejszą jednostkę waluty i z powrotem |
| `constants/timezone.ts` | Katalog `TIMEZONES` i `TimezoneCode`                                                                                                              |
| `constants/pricing.ts`  | Waluta sklepu `DEFAULT_CURRENCY_CODE` i formatowanie walut `CURRENCY_FORMAT`                                                                      |
| `constants/ordering.ts` | `FIRST_POSITION`, czyli miejsce pierwszego elementu na uporządkowanej liście                                                                      |

Katalogi leżą tutaj, bo opiera się na nich fundament: `countryCodeField` i `currencyCodeField`, schematy zamówień, produktów i subskrypcji, stałe użytkownika oraz domyślna waluta produktu. Katalog języków zawiera wszystkie znane języki; języki, które aplikacja obsługuje, definiuje `I18N.SUPPORTED_LOCALES` w `src/integrations/use-intl/i18n.config.ts`. Dane, na których nie opiera się żaden schemat ani przypadek użycia, trafiają do `src/data`, gdzie są tylko stałe i listy literałów, a ogólne funkcje pomocnicze do `src/lib`. Test w `src/__test__/module-tables.test.ts` kończy się błędem, gdy plik w `_core` nie jest opisany na tej stronie, więc każdy nowy plik jest świadomą decyzją.

## Funkcje pomocnicze

- `utils/localized-text.ts`: `LocalizedText`, tekst w każdym języku zapisany jako JSON, `localizedTextSchema`, który wymaga `en-US` i ustala limit znaków każdego tekstu na <RepositoryFact name="localizedTextMaxLength" />, oraz `localize`, który przy braku tłumaczenia sięga po `en-US`
- `utils/ordering.ts`: `nextPosition`, czyli najwyższa `position` plus jeden, oraz `reorder`, który przenosi element na wskazane miejsce wśród elementów jego grupy, miejsce przed początkiem albo za końcem listy traktuje jak jej początek albo koniec, numeruje listę od `FIRST_POSITION` i zwraca tylko elementy, których `position` się zmienia; przypadki użycia kursów, rozdziałów, lekcji i materiałów utrzymują dzięki nim `position` bez luk
- `utils/pagination.ts`: `paginationSchema` (`pageIndex`, `pageSize`) i `DEFAULT_PAGE_SIZE`
- `utils/search.ts`: `searchSchema` i `localizedSearchSchema`, dane wejściowe przypadków użycia wyszukiwania w panelu administracyjnym, ich limity długości i zwracany przez nie `SearchHit`
- `utils/time-series.ts`: `TIME_RANGES` i `timeRangeSchema`, zakresy wykresów przychodów i rejestracji w panelu administracyjnym, `timeSeries`, dzienne lub miesięczne przedziały zakresu, oraz `pointsOf`, który przedziałowi bez wartości daje zero
- `utils/zod-fields.ts`: pola Zod wielokrotnego użytku, takie jak `idField`, `localeField`, `positionField` (liczba całkowita od `FIRST_POSITION`) i `slugField`

## Błędy

Jest jedna klasa błędu i jedna lista kodów:

```ts
export const ERROR_CODES = {
  AUTH_API_ERROR: "AUTH_API_ERROR",
  CONFLICT: "CONFLICT",
  FORBIDDEN: "FORBIDDEN",
  INTERNAL_ERROR: "INTERNAL_ERROR",
  NOT_FOUND: "NOT_FOUND",
  TOO_MANY_REQUESTS: "TOO_MANY_REQUESTS",
  UNAUTHORIZED: "UNAUTHORIZED",
  VALIDATION: "VALIDATION",
} as const

export type ErrorCode = (typeof ERROR_CODES)[keyof typeof ERROR_CODES]

export class AppError extends Error {
  readonly code: ErrorCode

  constructor(code: ErrorCode, message: string = code) {
    super(message)
    this.name = "AppError"
    this.code = code
  }
}
```

Funkcje serwerowe rzucają `AppError`. Middleware `withRequest` normalizuje wszystkie pozostałe błędy: błędy API Better Auth stają się `AUTH_API_ERROR` z kluczem błędu Better Auth jako komunikatem, błędy Zod stają się `VALIDATION`, a nieznane błędy są logowane i zamieniane na `INTERNAL_ERROR`. W przeglądarce `useErrorMessage()` z `src/hooks/use-error-message.ts` mapuje komunikat na tłumaczenia `auth.errors.*` lub `errors.codes.*`.
