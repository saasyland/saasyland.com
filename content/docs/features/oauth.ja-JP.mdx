`auth.server.ts` は Worker の環境変数の認証情報で 2 つのプロバイダーを登録します。キーには `AUTH_PROVIDER`（`auth.constants.ts`）のプロバイダー ID を使います。

```ts
socialProviders: {
  [AUTH_PROVIDER.GITHUB]: { clientId: env.AUTH_GITHUB_CLIENT_ID, clientSecret: env.AUTH_GITHUB_CLIENT_SECRET },
  [AUTH_PROVIDER.GOOGLE]: { clientId: env.AUTH_GOOGLE_CLIENT_ID, clientSecret: env.AUTH_GOOGLE_CLIENT_SECRET },
},
```

## フロー

`OAuthButtons`（`src/presentation/components/custom/auth/oauth-buttons.tsx`）は、サインインと登録の画面に、GitHub を先頭にしてプロバイダーごとのボタンを表示します。ラベルはどちらの画面でも **GitHub で続行** と **Google で続行**（`auth.oauth.continueWith`）です。Better Auth の `lastLoginMethod` プラグインは、ブラウザが最後に使ったサインイン方法（`email`、`github`、`google`）を Cookie `saasyland.last_used_login_method`（`LAST_LOGIN_METHOD_COOKIE`）に保存し、一致するボタン（サインイン画面ではメールアドレスの入力欄の場合もあります）には、ハイドレーション後に **前回使用** バッジが付きます。サインイン画面では、パスワードが違う場合にも両方のプロバイダーを案内します。ローカライズされた `callbackURL`（`/auth/callback`）と `errorCallbackURL`（`/auth/sign-in`）を指定して Better Auth の `signIn.social` を呼び出します。プロバイダーから戻ると、`/auth/callback` が管理者を `/admin` へ、顧客を `/app` へリダイレクトします。失敗した場合は `?error=` 付きでサインイン画面に戻り、翻訳済みの `auth.errors` メッセージが表示されます。

`accountLinking` が有効なため、ソーシャルサインインは同じメールアドレスを持つ既存ユーザーに連携されます。プロバイダーのトークンは `account` テーブルに暗号化して保存されます。

## プロバイダーの設定

使用するすべてのホストについて、コールバック URL <RepositoryFact name="oauthCallbackPaths" /> を登録します。ローカルでは `localhost:3000`、ほかに `preview.saasyland.com` と `saasyland.com` です（`src/modules/_core/constants/api.ts` の `DEPLOYED_HOSTS` を参照）。クライアント ID とシークレットは上記の環境変数に設定します。

`bun run deploy:<environment>` は、プロバイダーが拒否するクライアント ID をビルドの前に拒否します。`scripts/prepare-deploy-secrets.ts` はいずれかのシークレットに `[UPDATE]` のようなプレースホルダーがあると失敗し、認証[機能](/docs/conventions/testing#tests-follow-the-features)のデプロイ前チェック `auth:verify` は、`.env.<environment>` の <RepositoryFact name="oauthClientIdVariables" /> がそれぞれのプロバイダーの形式のクライアント ID を含んでいない限り失敗します。デプロイ後、`scripts/verify-deployment.ts` はデプロイ先のドメインで各プロバイダーのサインインを開始し、プロバイダーの認可 URL がそのプロバイダーのホスト上にない場合、`client_id` がそのプロバイダーの形式ではない場合、`redirect_uri` が同じドメインに戻らない場合に失敗します（[プロジェクトのスクリプト](/docs/tooling/scripts)）。Google の `Error 401: invalid_client` の直し方は [トラブルシューティング](/docs/reference/troubleshooting) で説明しています。

GitHub の認証情報は、`src/lib/github.ts` でリポジトリのスター数を取得するリクエストの認証にも使われます。
