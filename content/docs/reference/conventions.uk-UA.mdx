## Код

- Жодних коментарів у коді. Сенс передають назви та невеликі функції.
- Жодних придушень лінтера, `@ts-expect-error` чи приведень `as`, щоб задовольнити правило. Виправляйте причину.
- Жодних багаторядкових тернарних операторів. Використовуйте ранній return або невеликий компонент.
- Умовні класи використовують об'єктний синтаксис `cn`: `cn("base", { "text-foreground": isActive })`.
- Жодних обгорток, інтерфейсів чи шарів, які лише передають виклики далі. Імпортуйте конкретну функцію.
- Магічні числа стають іменованими константами, наприклад `const SINGLE_ROW = 1`.
- `vp fmt` сортує імпорти за групами: server-only, `cloudflare:workers`, React, пакети, потім папки `src` у фіксованому порядку, потім стилі.

## Маршрути

- Маршрути сторінок визначають `<Name>Page`, константу `NAMESPACE` безпосередньо над `export const Route`, `head: pageHead(ROUTES.X)` і loader-функцію, яка виконує `loadPageMetadata`, `preloadNamespaces` та будь-які запити в одному `Promise.all`.
- Маршрути макетів визначають `<Name>Layout` і масив `NAMESPACES`, оголошений у `staticData` та попередньо завантажений loader-функцією.
- Шляхи беруться з `ROUTES`. Посилання роутера ніколи не додають префікс локалі самостійно; сира URL-адреса в поточній локалі береться з `router.buildLocation(...).publicHref`, а URL-адреса для заданої локалі — з `localizePathname`.
- Масиви елементів для рендерингу — це константи рівня модуля, а не вбудовані літерали в JSX.
- `validateSearch` — це `zod.object` із `searchText()`, `searchFlag()` і `searchChoice(choices, fallback)` з `src/lib/search-params.ts`.

## Компоненти

- Один віджет, діалог, форма або визначення колонок на файл.
- Компоненти самі читають свої переклади й дані. Жодних пропсів із текстом, підписами чи даними, які компонент може прочитати сам.
- Рівно один виклик `useTranslations` на компонент, а функція перекладу називається `t`.
- Форми дотримуються патерну shadcn для TanStack Form: `useForm` із Zod-схемою модуля, `Field`, `FieldLabel`, `Input` і `ValidationFieldError`.
- Таблиці використовують універсальний `<DataTable columns data options filters />` з колонками у файлі `<entity>-columns.tsx`.

## Серверний код

- Сценарії використання називаються `<verb>-<noun>.ts` та експортують серверну функцію разом з її опціями запиту чи мутації.
- `<table>.types.ts` кожного модуля експортує один інтерфейс, названий на честь модуля, з `select`, `insert` і одним ключем на кожну Zod-схему. Вхідні дані серверних функцій типізуються через нього, наприклад `Category["createCategory"]`.
- Статуси, джерела, плани та інші доменні значення оголошуються один раз як іменований об'єкт констант, як-от `LICENSE_STATUS`, `NEWSLETTER_STATUS` чи `POLAR_ORDER_STATUS`, і в коді та тестах на них посилаються за назвою.
- Помилки викидаються як `AppError(ERROR_CODES.X)` і перекладаються в браузері через `useErrorMessage()`.
- Кожна URL-адреса, ключ запиту й ключ мутації береться з константи (`ROUTES`, `<TABLE>_QUERY_KEYS`, `<TABLE>_MUTATION_KEYS`).

## Коміти та pull request

Повідомлення комітів відповідають Conventional Commits: `<type>(<scope>): <description>`. Хук `prepare-commit-msg` запускає `scripts/commit-msg.ts`, який відхиляє невідомі типи й додає на початок теми емодзі, що відповідає типу:

| Тип        | Емодзі |
| ---------- | ------ |
| `feat`     | ✨     |
| `fix`      | 🐛     |
| `perf`     | 🚀     |
| `refactor` | 📦     |
| `docs`     | 📚     |
| `test`     | 🚨     |
| `build`    | 🛠️     |
| `ci`       | ⚙️     |
| `chore`    | ♻️     |
| `style`    | 💎     |
| `revert`   | 🗑️     |

Хук `pre-commit` запускає `bun run check:pre-commit`. Для pull request запускається CI-воркфлоу: `bun run check`, `bun run test:coverage` і набір Playwright, після чого виконується розгортання preview.
