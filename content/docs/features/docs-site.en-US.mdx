## Content

- Pages are `content/docs/<section>/<page>.<locale>.mdx` for every locale.
- `meta.<locale>.json` in each folder sets the section title, icon and page order.
- `src/integrations/fumadocs/fumadocs.i18n.ts` uses the `dot` parser, `en-US` as default and fallback, and `hideLocale: "always"`, because the app handles the locale prefix itself.
- `bun run content` generates `.source` from `fumadocs.config.ts`.

## Routes

- `/docs` layout (`src/routes/_site.docs.tsx`): a server function returns the page tree for the current locale; the layout renders Fumadocs `DocsLayout` inside the `_site` layout, below the site header and above `BackToTop`, which the docs need because the Fumadocs table of contents only jumps to headings. It sets Fumadocs' `--fd-banner-height` to the header's height, so the sidebar and the table of contents stick below the header, titles the sidebar **Docs** with a link to `/docs`, shows the GitHub link, and `LocaleSelect` and `ThemeSwitch` as matching select fields in the sidebar footer, loads `docs.css`, and shows `DocsPending` while loading. Its loader preloads the `fumadocs` namespace with the page tree, and the site's `Footer` follows the docs as it follows every other public page, so the legal pages, the contact address, the newsletter and the language links are one scroll away from any docs page.
- From `md` up the docs sit in the same frame as the site header: the layout gives Fumadocs' container the header's width and padding (`mx-auto max-w-site md:px-10`), so the sidebar starts under the logo and, from `xl` up, the table of contents ends under **Start building**. The sidebar cannot be collapsed (`collapsible: false`), so it stays on screen below the header, with its own scroll and a line on each side that meets the header's line. `e2e/specs/content-chrome.spec.ts` checks both edges and the sidebar's place before and after scrolling.
- On small screens the site header keeps its menu, and one docs bar sits below it: `DocsToolbar` (`custom/docs-toolbar.tsx`), the layout's `header` slot, holds the one button that opens the docs navigation, the title of the current page and the search button. The docs navigation slides in from the side of its button, where the sidebar stands on wider screens (`#nd-sidebar-mobile` in `docs.css`). The bar is a navigation landmark named **Docs**, so the site header remains the page's only banner. Fumadocs sets the bar's height, `--fd-header-height`, only for its own bar, so the docs layout sets it on small screens. Below `xl`, where the table of contents column is hidden, `docs-content.tsx` turns off Fumadocs' table of contents bar and lists the page's headings in a collapsed `InlineTOC` under the description, as a blog post does, so no third bar stays on screen.
- Fumadocs writes the text of its own controls: the search, the sidebar buttons, **On this page**, the copy buttons of code blocks, heading anchors and accordion items, and the links to the previous and next page. `useFumadocsI18n` (`src/hooks/use-fumadocs-i18n.ts`) maps each of those strings to a message of the `fumadocs` namespace and passes them to `RootProvider` with the page's locale, so they come from `messages/<locale>/fumadocs.json` like every other string. `e2e/specs/content-chrome.spec.ts` fails when a Fumadocs string is left in English on a Polish or German docs page or blog post.
- The site header's **Skip to content** link is the page's only skip link. On a docs page it jumps to the article, whose id stays Fumadocs' `nd-page`: the docs layout sets `contentId` in its `staticData` to `DOCS_CONTENT_ID` (`src/data/navigation.constants.ts`), and `Navigation` links to the `contentId` of the deepest matched route that sets one, or to `SITE_CONTENT_ID`. Fumadocs' `DocsLayout` always renders a second, invisible link of its own to `#nd-page`, and Fumadocs declined a slot to leave it out ([fuma-nama/fumadocs#3866](https://github.com/fuma-nama/fumadocs/issues/3866), [fuma-nama/fumadocs#3867](https://github.com/fuma-nama/fumadocs/pull/3867)). `globals.css` hides it with `display: none`, which takes it out of the tab order and the accessibility tree, since the site's link already leads to the same article. `e2e/specs/content-chrome.spec.ts` checks that docs, blog and landing pages each have one skip link, reached by the first Tab, that moves focus into the content, and `e2e/specs/navigation.spec.ts` that the header stays the same element from the landing page to the docs and back.
- `/docs/` and `/docs/$` call `loadDocsPage` (`fumadocs.docs.ts`), which resolves the page and preloads its compiled MDX (`docsContent`) before rendering.
- `/api/search` serves Fumadocs search over every locale (`fumadocs.search.ts`).

MDX pages can use `mdxComponents` from `src/presentation/components/custom/mdx.tsx`: the Fumadocs defaults, Fumadocs `Accordions`, `Steps` and `Tabs`, the shadcn `Alert`, `Badge`, `Button`, card parts, `Separator` and table parts, and `RepositoryFact`, `RepositoryTable`, `TierPrice`, `ActivationLimit` and `RegionalDiscounts`, which print values from the code instead of typing them ([Translations and content](/docs/conventions/translations)). Links are localized automatically: `localizeHref` adds the page's locale to the path of an internal link and keeps its query and fragment, so `/#pricing` opens `/pl-PL#pricing` on a Polish page.

## Accessibility

Docs pages meet WCAG 2.2 AA in both themes. Code blocks use Shiki's GitHub Light and GitHub Dark themes with two token colours replaced (`colorReplacements` in `fumadocs.config.ts`) so every token meets 4.5:1, a code block's scroll area is focusable and is not a landmark, and a task list checkbox is named by its item. `e2e/specs/accessibility.spec.ts` scans the docs home, every Conventions page and one page from each other section; see [Accessibility](/docs/conventions/accessibility).

## Adding a page

1. Write `<page>.en-US.mdx` with a `title` and `description`.
2. Add the slug to `meta.en-US.json` and to every other `meta.<locale>.json` in the same order.
3. Add the translation for every other locale, with byte-identical code blocks.
4. Run `bun scripts/check-content.ts` (also part of `bun run check:i18n`) and `bun run content`.

`bun run build` prerenders every docs page in every locale.
