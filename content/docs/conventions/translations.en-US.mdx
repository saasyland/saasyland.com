SaaSy Land ships in <RepositoryFact name="languages" /> locales, <RepositoryFact name="supportedLocales" />, listed once in `I18N.SUPPORTED_LOCALES` in `src/integrations/use-intl/i18n.config.ts`. English is the source of truth. A change that adds or edits text adds or edits it in every locale in the same commit, and `bun run check:i18n` fails when it does not.

## Namespaces

Messages live in `messages/<locale>/<namespace>.json`, one file per namespace, and the file name is the namespace.

| Namespace                                                      | Holds                                                                                               | Loaded                                            |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| `common`, `errors`, `errors.global`                            | Text every screen may need, including `errors.codes.<CODE>`                                         | For every route                                   |
| `components.custom.<file>`, `components.shadcn.<file>`         | The copy of one shared component, such as `components.custom.newsletter-form`                       | For every route                                   |
| `fumadocs`                                                     | The text of Fumadocs' own controls in the docs and blog, which `useFumadocsI18n` passes to Fumadocs | By the docs and blog layouts                      |
| `pages.<area>`, `pages.<area>.<page>`                          | One layout or page, with `metadata.title` and `metadata.description`                                | By the route, through `NAMESPACE` or `NAMESPACES` |
| `navigation.<area>`, `dashboard.<area>`                        | The labels of one area's menu entries, breadcrumbs and dashboard statistics                         | At the root, with every page                      |
| `<table>.validations`                                          | The Zod messages of one module, such as `course.validations`                                        | By the layout whose forms use them                |
| `auth.errors`, `auth.validations` and the other `auth.*` files | Better Auth errors, validation and auth screens                                                     | By the layouts that need them                     |
| `emails.<template>`                                            | One email template                                                                                  | On the server, by the use case that sends it      |
| `countries`, `currencies`, `locales`, `timezones`              | Catalogues                                                                                          | By the layouts that need them                     |

The root namespaces are found by file name (`common.json`, `components.*.json`, `errors*.json`) in `src/integrations/use-intl/i18n.messages.ts`. A shared component's copy lives in its own `components.custom.<file>` namespace, never inside a page namespace, so it renders the same text wherever it appears. Every namespace a route declares must exist as a file in every locale; `loadNamespace` throws for one that does not.

## One translator per component

A component calls `useTranslations` once, with its namespace, and names the result `t`:

```tsx
const t = useTranslations("pages.admin.courses.form")
```

`scripts/check-i18n.ts` resolves every static `t("key")` in the `.tsx` files of `src` against the namespace of the `useTranslations` call above it and fails on a key that does not exist in English. It also fails on an English key that no source file renders, so removed copy cannot linger in the message files. A key counts as rendered when a `t()` call names it, when a key built from a template, such as `kinds.${kind}`, matches it, or, below a `t()` call that takes a variable, when its path appears as a string in `src`. The `countries`, `currencies`, `locales` and `timezones` catalogues are exempt, and `catalogues.test.ts` checks that their keys equal the constants instead. A constant whose values are shown to users has its labels checked in every locale by `enum-labels.test.ts`, which reads each such constant with the messages that label it from the lists the areas declare in `src/integrations/use-intl/__test__/<area>.labels.ts`. A second `useTranslations` call in the same component would silently re-scope every `t()` after it, which is why there is only one. A component that needs keys from two namespaces calls `useTranslations()` without one and uses full keys, as `sign-in-form.tsx` does with `t("errors.codes.INTERNAL_ERROR")`.

## Messages

- Keys are nested JSON objects with camelCase names, grouped the way the screen is: `table.headers.course`, `delete.confirm`.
- Plurals, numbers and dates use ICU syntax inside the message, never string concatenation in code: `"{e2eSpecs, plural, one {# Playwright suite} other {# Playwright suites}}"`.
- `scripts/check-message-formats.ts` requires the same ICU arguments and tags in every locale, and the English message's file paths and `bun run`, `bunx`, `npx` or `vp` commands character for character. It rejects English text left in another locale, Markdown backticks, which messages do not render, and a [form of address](#one-form-of-address) that the locale does not use.
- Format numbers, dates and currencies for the reader's locale with `useFormatter` from use-intl, never by hand. Dates use a named format from `I18N.FORMATS` (`date`, `time`, `calendarDate`), so the time zone and the zone label stay consistent. A named format holds a date or a time, never both: engines join the two differently, and Safari writes “Jan 1, 2025 at 7:00 AM” where the server writes “Jan 1, 2025, 7:00 AM”, so a date with its time is the `common.dateTime` message, as in `t("common.dateTime", { value })`. A relative time counts from when its data was read, the `dataUpdatedAt` of its query, as in `format.relativeTime(session.updatedAt, dataUpdatedAt)`, never from `new Date()`, which the server and the browser read at different moments. `useCurrencyFormatter` formats an amount in a given currency.
- Zod messages in a module's schemas are keys of its `<table>.validations` namespace (`"slugInvalid"`), and the numbers they mention come from `<MODULE>_VALIDATION_PARAMS`. See [Forms and tables](/docs/conventions/forms-and-tables).
- Text stored in the database that visitors read in several languages is a `LocalizedText` column. English is required and is the fallback that `localize(text, locale)` returns for a missing translation.

## One form of address

Every locale addresses the reader one way, in every message, email, legal page, docs page, blog post and changelog entry: the form that developer tools use in that language. `FORMS_OF_ADDRESS` in `src/lib/forms-of-address.ts` names the form of each locale and lists the forms that contradict it, and `scripts/check-message-formats.ts` and `scripts/check-content.ts` fail when a translation uses one of them outside code, link targets and Japanese 「」 quotations.

<RepositoryTable name="formsOfAddress" columns={["Locale", "Form", "Never", "Never inside a sentence", "Never ending a sentence"]} />

- A word under **Never** fails wherever it stands, capitalised at the start of a sentence too.
- A word under **Never inside a sentence** fails after a word, a number or a comma on the same line. At the start of a sentence the same word is often the third person, as in `Sie laufen im Worker` (“they run in the Worker”), so the check leaves it there for the reviewer.
- A form under **Never ending a sentence** fails before a Japanese full stop.

German says du, in lowercase as Duden recommends, and the legal pages do too: the form of address has no legal effect. Polish capitalises Ty and Twój as a courtesy. Japanese ends its sentences in です・ます, while headings, list items, table cells and taglines may end in a noun or a plain verb, never in the plain copula. The check finds the pronouns and endings that are unambiguous; an imperative or a verb ending that only the meaning of the sentence tells apart, such as Spanish `Ejecute` for `Ejecuta`, is for the reviewer.

## Numbers are measured, not typed

A count of something in the repository, such as test files, Playwright suites, UI components, countries or currencies, is never typed into copy. `scripts/repository-facts.ts` measures them at build time and serves them as the `virtual:repository-facts` module; `src/data/repository-facts.ts` exports them as `REPOSITORY_FACTS`. The size of a catalogue comes from its constant (`COUNTRIES`, `CURRENCY_CODES`, `TIMEZONES`, `ADMIN_NAVIGATION`), never from the message file that translates it. Landing copy interpolates them, as in `t("body", REPOSITORY_FACTS)` with `"{testFiles, number} test files"` in the message, and MDX renders one with `<RepositoryFact name="testFiles" />`. To mention a new number, measure it in that plugin first. A number the business sets rather than measures, such as the affiliate commission, is declared once in `src/data` (`AFFILIATE_TERMS` in `src/data/affiliates.ts`) and interpolated the same way. Prices follow the same rule: `TIER_PRICES` and `CONSULTING_HOURLY_RATE` in `src/data/marketing.ts` reach messages as `{price}` and MDX as `<TierPrice tier="core" />`, and the contact address reaches messages from `CONTACT_EMAIL` as `{email}`. The machine limits in `LICENSE_ACTIVATION_LIMITS` reach the tier cards' `machines` message as `{limit}` and MDX as `<ActivationLimit tier="core" />`. Components read `REPOSITORY_FACTS` directly: the quality section's test run prints `Test Files` with `REPOSITORY_FACTS.testFiles`, the number of files Vitest's `include` patterns match. A number that only running the suite produces, such as the count of individual tests, is not shown.

File paths and commands that copy cites are facts too, so that no locale can translate them. `RecordSection` on the landing page passes `{coverageSummaryPath}`, `{coverageCommand}`, `{ciWorkflowPath}`, `{e2eSpecsPath}`, `{messagesPath}`, `{i18nCheckCommand}` and `{authIntegrationPath}` from `REPOSITORY_FACTS`: the summary's directory is `reportsDirectory` in `vite.config.ts`, the specs directory is `testDir` in `playwright.config.ts`, and `repository-facts.test.ts` checks that every path exists and every command is a `package.json` script.

Docs pages do not type the values the code defines either. `<RepositoryFact name="…" />` in `src/presentation/components/custom/repository-fact.tsx` prints a measured count, a setting `repositoryFacts` reads from `vite.config.ts`, `playwright.config.ts`, `.nvmrc`, `package.json` or a workflow, or a constant imported from the code, such as `RATE_LIMITS` or `PLAYBACK_TTL_SECONDS`. It formats a number for the page locale, with `unit="second"`, `"minute"`, `"hour"`, `"day"` or `"percent"` when the value has a unit, and prints text as code and a list as a list of code. `<RepositoryTable name="…" columns={["…", "…"]} />` prints a table built from the code, such as the permission statements, the commit types or the regional price multipliers, under column names the page translates. The router's cache times and the per-recipient email limit are declared in `src/integrations/tanstack-query/query.cache.ts` and `src/modules/rate-limit/rate-limit.constants.ts` rather than in `src/router.tsx` and the server-only `src/lib/rate-limit.ts`, which the docs cannot import; the component's test compares the values it prints with the router and the limiter. A value that must stay in a code block or in frontmatter is checked by `scripts/check-content.ts` instead.

## Docs and blog

Every page under `content/docs`, every post under `content/blog` and every changelog entry under `content/changelog` exists as `<slug>.<locale>.mdx` in every locale, and every folder's navigation as `meta.<locale>.json`. `scripts/check-content.ts`, run by `bun run check:i18n`, fails when:

- a locale file is missing;
- a code block differs from the English one (code blocks are copied byte for byte);
- a `meta.<locale>.json` lists different slugs from English;
- a title, description or paragraph is still in English;
- a translation of a blog post has a different `date` or `updated` from the English post;
- a machine-translation marker is left in the text;
- a translation addresses the reader in a form that its locale does not use (see [One form of address](#one-form-of-address));
- a bare URL runs straight into the text after it, as one before a full-width bracket or full stop in Japanese does, so its link would take that text too;
- a code block titled with a repository path, such as `title="src/integrations/better-auth/auth.access.ts"`, is not an excerpt of that file;
- a docs page names a local host or an `APP_DOMAIN` subdomain that `appHostsForMode` allows in no build mode;
- a changelog entry is named after neither a pull request number nor a full commit hash, or a pull request's CI run finds no `content/changelog/<number>.en-US.mdx` named after it;
- the routes reference, the scripts page or an environment variables table leaves out a `ROUTES` constant, a `package.json` script or a `wrangler.jsonc` secret, or gives one the wrong value;
- an internal link ends in a slash, `/index` or `.html`, or starts with a locale or a language alias such as `/pl/`: the site redirects such a path, and `localizeHref` adds the page's locale to every internal link;
- a translation leaves out or adds inline code, a component, a component prop other than `title`, `description`, `excerpt` and `unreleased`, or a link to another page, or has a different number of table rows from the English page.

Write translations as a native speaker would, with the terminology the locale already uses in `messages/<locale>/` (Polish, for example, names the tiers Podstawa, Komplet and Agencja and calls a discount a rabat). Code identifiers, file paths, commands and product names stay as they are, and links keep their `/docs/...` paths without a locale prefix, which the site adds when it renders them.
