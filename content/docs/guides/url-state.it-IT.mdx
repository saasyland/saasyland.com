---
title: "Stato nell'URL"
description: "Conserva schede, viste e token monouso in parametri di ricerca validati."
---

I parametri di ricerca conservano lo stato che deve sopravvivere a un ricaricamento o a un link condiviso: la scheda o la vista selezionata, un indirizzo email passato tra le pagine di autenticazione, un token di verifica. Tutto il resto resta nello stato di React. `DataTable` mantiene paginazione, ordinamento, selezione e filtri nello stato del componente.

## Dichiara i parametri

`validateSearch` riceve un oggetto zod, così i parametri di ricerca della route sono tipizzati e validati in un solo punto. I campi vengono da `src/lib/search-params.ts`: `searchText()` e `searchFlag()` valgono `undefined` quando il valore manca, è vuoto o malformato, così i valori assenti non compaiono mai nell’URL; `searchChoice(choices, fallback)` torna a una scelta. `searchParam(schema)` applica la stessa regola a qualsiasi schema zod; le route della newsletter leggono `token` con lo schema del token del modulo. Un valore malformato non porta mai a una pagina di errore. Da `src/routes/admin.blog.index.tsx`:

```tsx
validateSearch: zod.object({
  view: searchChoice([ADMIN_BLOG_VIEW.GRID, ADMIN_BLOG_VIEW.TABLE], ADMIN_BLOG_VIEW.GRID),
}),
search: { middlewares: [stripSearchParams({ view: ADMIN_BLOG_VIEW.GRID })] },
```

`stripSearchParams` rimuove il valore predefinito dall'URL, così `/admin/blog` resta l'indirizzo canonico della vista a griglia.

## Leggili

- Nel componente della route: `const { view } = Route.useSearch()`.
- Con un selettore, il componente si aggiorna solo quando cambia il valore selezionato: `Route.useSearch({ select: (search) => search.error !== undefined })`.
- In un componente fuori dal file della route: `getRouteApi("/auth/reset-password").useSearch()`, come in `reset-password-form.tsx`.

## Modificali

- Link: `<Link search={{ view: id }} to={ROUTES.ADMIN_BLOG}>`.
- I componenti React Aria con un `href`, come `TabsTrigger` in `src/routes/admin.products.index.tsx`, navigano tramite il router perché `AriaProvider` collega React Aria a TanStack Router.
- Codice: `router.navigate({ search: { email }, to: ROUTES.VERIFY_EMAIL })`.
- Guardie e loader: `throw redirect({ replace: true, to: ROUTES.AUTH_CALLBACK })`.

## Carica dati a partire da essi

Un componente legge i parametri di ricerca con `Route.useSearch()`; un loader che dipende da uno di essi lo dichiara in `loaderDeps` e lo legge da `deps`. Non consumare mai un token dell’URL in un loader, perché il precaricamento, i crawler e gli scanner di posta eseguono i loader. Le pagine di conferma e di annullamento dell’iscrizione alla newsletter leggono il token e agiscono solo quando il visitatore preme il pulsante:

```tsx
const { status, token } = Route.useSearch()
```

## Lingue e URL

- I link del router (`<Link to={ROUTES.X}>`) ricevono il prefisso di lingua dal `rewrite` del router. L'inglese non ha prefisso (`/docs`); le altre lingue sì (`/pl-PL/docs`).
- Costruisci un URL grezzo nella lingua corrente con `router.buildLocation({ search, to }).publicHref`, che lo localizza e ne serializza i parametri di ricerca, come fa `useAuthRedirect` per `callbackURL` ed `errorCallbackURL` di Better Auth. `localizePathname({ locale, pathname })` costruisce un URL per una lingua specifica, come i link nelle email; i percorsi `/api` e gli URL esterni restano invariati.
- Il selettore della lingua porta allo stesso percorso nell'altra lingua con un caricamento completo della pagina; query e frammento non vengono mantenuti.
