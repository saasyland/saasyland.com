The `saasyland` CLI, `create-saasyland` and `@saasyland/stack` are released together under one version, and each prerelease below was published on npm's `beta` tag, except 0.1.0-beta.3. The [CLI guide](/docs/cli) describes the current release, and the [changelog](/docs/project/changelog) lists the changes to this website.

## 0.1.0-beta.5

### saasyland

- **Breaking:** `--billing lemonsqueezy` is gone, because Lemon Squeezy is closing: it has taken no new sign-ups since 16 November 2026 and shuts down on 31 March 2027. `--billing polar` and `--billing stripe` remain, and `init --billing lemonsqueezy` now exits with code <RepositoryFact name="cliExitUsage" />, like any other value `--billing` does not have.

### create-saasyland

- **Breaking:** `--billing lemonsqueezy` is gone, as in `saasyland`, and exits with code <RepositoryFact name="cliExitUsage" />.

### @saasyland/stack

- **Breaking:** `BILLING.LEMONSQUEEZY` and the `lemonsqueezy` billing option are gone, because Lemon Squeezy is closing. Polar (`BILLING.POLAR`) and Stripe (`BILLING.STRIPE`) remain.

## 0.1.0-beta.4

This release also ships every change of 0.1.0-beta.3, which was never published.

### saasyland

- `saasyland init` has a new first question, the UI library (`--library react`, `angular`, `vue`, `svelte` or `solid`), which decides the frameworks it offers: Next.js and React Router beside TanStack Start for React, Analog and Angular SSR for Angular, Nuxt for Vue, SvelteKit for Svelte, and SolidStart beside TanStack Start for Solid. `--runtime deno` joins `node` and `bun` for self-hosted projects.
- This release generates React with TanStack Start, which `--yes` answers. `--help` marks the other libraries, their frameworks and Deno as not available yet, and `init` refuses them with exit code <RepositoryFact name="cliExitNotAvailable" />, naming the library before a framework that depends on it.

### create-saasyland

- The UI library question, as in `saasyland`: `--library` comes first and decides the frameworks, and only React with TanStack Start is generated.

### @saasyland/stack

- **Breaking:** the matrix's first question is the UI library: `CHOICE.LIBRARY`, `STACK_FLAG.LIBRARY` (`--library`) and `LIBRARY` (`react`, `angular`, `vue`, `svelte`, `solid`), with `react` in `STACK_DEFAULTS`, and `stackZodSchemas.answers` refuses a full answer set without `library`.
- `FRAMEWORK` adds `analog`, `angular-ssr`, `nuxt`, `sveltekit` and `solid-start`, each visible only with its libraries (`tanstack` with `react` and `solid`), and `RUNTIME` adds `deno`, which Cloudflare and Vercel do not run. `TEMPLATE_SUPPORT` lists `library` as `react` alone, so a configurator built on the matrix lists them all and disables every one but React with TanStack Start.

## 0.1.0-beta.3

Not published to npm: 0.1.0-beta.4 superseded this version before it was approved, and every change below shipped in 0.1.0-beta.4.

### saasyland

- `saasyland --help` and `saasyland init --help` list every value of every question and mark as not available yet the ones this release cannot generate, and the commands that have not arrived.
- `init` refuses such a value at once, before it checks your licence: `--billing polar` exits with code <RepositoryFact name="cliExitNotAvailable" />, says that it is not available in this release and names `--no-billing`, which is. The command `init` prints for you to copy only ever holds answers this release generates.
- `init` generates projects without billing until the billing templates arrive. `--yes`, and a terminal until the questions arrive, answer the billing question with `--no-billing`, which `saasyland.json` records, and every other question with this website's own stack, as before.

### create-saasyland

No changes in this release.

### @saasyland/stack

- New entry point: `@saasyland/stack/cli`, the values the `saasyland` CLI uses and documents: its exit codes (`EXIT_CODE`), the environment variables it reads (`CLI_VARIABLE`), where it keeps your licence and with which permissions (`CREDENTIALS_STORE`), the answers the templates of this release cover (`TEMPLATE_SUPPORT`) and the ID of each template layer (`TEMPLATE_LAYER`). The entry holds only constants, so it also suits a browser bundle.
- `TEMPLATE_SUPPORT` lists billing as `none` alone, because no template of this release generates billing yet; it listed Polar, which no generated project had.
- `resolveAnswers` takes the options a set of templates supports as an optional second argument, and then answers each open question with the default where they include it, and otherwise with the first legal option they include: `resolveAnswers(given, TEMPLATE_SUPPORT.choices)` resolves answers as `saasyland init --yes` does.

## 0.1.0-beta.2

### saasyland

- `saasyland init` creates your project. It checks your licence with saasyland.com on every run, using the licence activated on this machine, the key in <RepositoryFact name="cliLicenseKeyVariable" /> or the key you type when it asks, and downloads the templates of its own release.
- It refuses templates whose size or SHA-256 differ from what saasyland.com sent or from the digest this release pinned, writes the project into a new or empty directory all at once, so Ctrl+C or a failed write leaves nothing behind, and records the release, your answers and the digest of every file in `saasyland.json`. `--dry-run` lists every file it would write without writing anything, and `--cwd` runs it as if it were started in another directory.
- Exit codes say what went wrong: <RepositoryFact name="cliExitTemporaryFailure" /> to try again later, <RepositoryFact name="cliExitProtocol" /> when the templates do not match, <RepositoryFact name="cliExitNoPermission" /> when the licence refuses, <RepositoryFact name="cliExitNotAvailable" /> for an answer this release has no templates for, and <RepositoryFact name="cliExitCancelled" /> after Ctrl+C.
- New projects get sign-in: Better Auth on your own D1 database with email and password, GitHub and Google, email verification, password reset, two-factor authentication, roles, impersonation and revocable sessions, the sign-in pages, the admin console's dashboard, users and settings, and the customer workspace with its settings. The verification, password reset and email change emails are React Email templates sent through Resend, and the project's Playwright suites sign in and verify an address in Chromium and WebKit. `--no-auth` generates a project without sign-in. `--email none` is not available yet, because sign-in sends those emails.
- New projects get a documentation site and a blog. The documentation runs on Fumadocs with search, a getting-started section and the Conventions, the coding standard the project's own code follows; the blog is MDX, with a first post that explains how posts are written and published. Both are in every language the project supports, linked from the home page, prerendered and listed in the sitemap, and the project's checks fail when a page or a post is missing in a language or a translation changes its code, links or tables. Projects without sign-in get them too; `--content none` is not available yet.
- New projects get a README, an `AGENTS.md` for coding agents and a GitHub Actions CI workflow. The README and `AGENTS.md` describe the stack you chose, so a project made with `--no-auth` has no sign-in instructions, and every command they give is one of the project's own scripts. The workflow runs the check and the tests with coverage, then the browser suite against the test build, on every pull request and every push to `main`. Before your first push, run `bun install` and the commands the README lists under Getting started, and commit `bun.lock` and the files they write, which CI reads.
- New projects' documentation takes you from the first install to the first deploy. The installation page writes the lockfile and generates the migrations, the route tree and the Worker types before your first commit; an environment variables page says where every value comes from, including the auth secret, the GitHub and Google OAuth apps and their callback URLs, and the Resend API key and domain; and a deploy page creates the D1 databases, puts their IDs in `wrangler.jsonc`, names your hosts and deploys the preview environment. Each page has only the steps of the stack you chose, in every language the project supports, and the README sums them up.
- `saasyland` now ships the approved licence in `LICENSE.md`, word for word the [licence terms](/licence) on this website, in place of the draft that earlier versions carried.
- The README on npm runs the CLI from the `beta` dist-tag, because `latest` is still the placeholder release, where no command is available. It also says what works: `init` creates a project, and `activate`, `whoami` and `deactivate` manage your licence.
- New projects no longer include an `.editorconfig`. The formatter settings in `vite.config.ts` and `.gitattributes` already set every value it held, so it was a second source of the same settings.

### create-saasyland

- `create-saasyland` now ships the approved licence in `LICENSE.md`, word for word the [licence terms](/licence) on this website.
- Its README on npm runs it from the `beta` dist-tag, because `latest` is still the placeholder release.

### @saasyland/stack

- The package description on npm no longer says that saasyland.com shares the stack matrix.
- The README on npm installs the package from the `beta` dist-tag, because `latest` is still the placeholder release without `@saasyland/stack/api`.

## 0.1.0-beta.1

### saasyland

- `saasyland activate` activates your licence key on this machine: pass the key as an argument or in <RepositoryFact name="cliLicenseKeyVariable" />, or type it when asked, hidden as you type. `saasyland whoami` shows your tier, the slots in use and this machine's name, and `saasyland deactivate` frees this machine's slot.
- The licence is kept in a file only your user can read in your config directory, every run of one CI repository shares one activation, and a licence that was refunded or revoked is removed from the machine.
- Each of the three prints its result as one JSON document with `--json`, and they no longer accept `--cwd` and `--dry-run`, which never applied to them.

### create-saasyland

No changes in this release.

### @saasyland/stack

- `@saasyland/stack/api` caps a CLI version and a release at `API_LIMIT.VERSION_MAX_LENGTH` characters, so the licence API answers a longer one with `invalidRequest` like any other malformed field.

## 0.1.0-beta.0

### saasyland

- First preview of the `saasyland` CLI. `saasyland --help` lists every command, and `saasyland init --help` lists every stack choice as a flag.
- Flags are checked before anything runs: an unknown value or a combination that cannot work, such as `--provider neon` without `--db postgres`, is refused with the reason and exit code <RepositoryFact name="cliExitUsage" />.
- Output is available in English, German, Spanish, French, Italian, Japanese, Polish, Brazilian Portuguese and Ukrainian, chosen with `--locale` or from your system language, and `--json` prints one JSON document for scripts and coding agents.
- Generating a project and activating a licence arrive in the next previews; until then those commands say so and exit with code <RepositoryFact name="cliExitNotAvailable" />.

### create-saasyland

- First preview of `create-saasyland`: `npm create saasyland`, `bun create saasyland`, `pnpm create saasyland` and `yarn create saasyland` run `saasyland init` with the same flags.

### @saasyland/stack

- New entry point: `@saasyland/stack/api`, the contract of the saasyland.com licence API that the `saasyland` CLI calls. It defines the <RepositoryFact name="cliApiBasePath" /> routes, headers, request and response schemas, error codes and limits, and builds and reads every request and response. Importing `@saasyland/stack` alone loads none of it.
