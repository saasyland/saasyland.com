---
title: "Adicionar uma funcionalidade"
description: "Passo a passo completo da tabela no banco de dados até uma página testada, com links para os guias detalhados."
---

Uma funcionalidade costuma envolver todas as camadas: um módulo de tabela, seus casos de uso, uma rota, componentes de apresentação, mensagens e testes. Os cursos mostram o caminho completo: `src/modules/course`, `src/routes/admin.courses.index.tsx` e `src/presentation/components/custom/admin/courses/course-columns.tsx`.

## 1. Modele os dados

Se a funcionalidade armazena dados novos, adicione um módulo para a tabela e gere a migração.

- [Adicionar um módulo](/docs/guides/add-a-module)
- [Migrações de banco de dados](/docs/guides/database-migrations)

## 2. Defina quem pode fazer o quê

Adicione as novas ações à declaração do recurso em `APP_STATEMENTS` (`src/integrations/better-auth/auth.access.ts`) e conceda-as aos papéis em `ROLES`; uma funcionalidade que pode ficar de fora nomeia um recurso novo nos seus `names` em `scripts/features.ts`.

- [Papéis e permissões](/docs/guides/roles-and-permissions)

## 3. Escreva as operações

Adicione um caso de uso por operação, com middleware, validador, handler e opções de query ou mutation.

- [Adicionar um caso de uso](/docs/guides/add-a-use-case)
- [Funções de servidor](/docs/guides/server-functions)

## 4. Adicione a rota

1. Declare o caminho em `src/routes.ts` e os seus itens de menu nas listas de `src/data/navigation.ts`, cada um com a chave completa do seu rótulo, e inclua os caminhos de uma funcionalidade opcional nos `names` dela em `scripts/features.ts` (veja [Caminhos e navegação](/docs/conventions/routes#paths-and-navigation)).
2. Crie um arquivo de rota plano para a área: `src/routes/admin.<feature>.tsx` sob o layout de administração, `src/routes/app.<feature>.tsx` sob o layout do cliente logado ou `src/routes/_site._marketing.<page>.tsx` para uma página pública.
3. Siga a convenção de rotas: `const NAMESPACE`, `staticData: { namespaces: [NAMESPACE] }`, `head: pageHead(ROUTES.X)`, um loader que carrega metadados, mensagens e dados em um único `Promise.all` e o esqueleto próprio da página como `pendingComponent`, que o esqueleto do layout também mostra quando alguém entra no layout vindo de outro lugar (veja [Esqueletos de carregamento](/docs/architecture/delivery-layer#esqueletos-de-carregamento)).
4. O guard `beforeLoad` do layout (`requireAdmin` para `/admin`, `requireSignedIn` para `/app`) protege a página. Mesmo assim, as funções de servidor autorizam cada chamada por conta própria.

- [Adicionar uma página de administração](/docs/guides/add-an-admin-page)
- [Estado na URL](/docs/guides/url-state)

## 5. Construa a interface

Coloque widgets, diálogos, formulários e colunas de tabela na pasta plana da área, `src/presentation/components/custom/<area>/`, ou em `src/presentation/components/custom/admin/<feature>/` para um recurso do admin, um por arquivo. Cada componente lê suas próprias traduções e dados; a rota apenas os compõe.

- [Adicionar uma grade de dados](/docs/guides/add-a-data-table)
- [Formulários e validação](/docs/guides/forms-and-validation)

## 6. Adicione as mensagens

Crie o namespace da página, e se necessário um namespace de validação, em todos os idiomas. Namespaces de página precisam de `metadata.title` e `metadata.description`.

- [Internacionalização e idiomas](/docs/guides/i18n-messages)
- [Templates de e-mail](/docs/guides/email-templates), se a funcionalidade envia e-mails

## 7. Teste e verifique

Cubra os casos de uso, os componentes e a rota com testes e depois execute as verificações e as specs do recurso; a CI executa a suíte de navegador completa antes de o pull request ser mesclado:

```sh
bun run check
bun run test:coverage
bun run build:test
bunx playwright test e2e/specs/<spec>.spec.ts --project=chromium
```

- [Escrever testes](/docs/guides/writing-tests)
- [Checklist de segurança](/docs/guides/security-checklist)
