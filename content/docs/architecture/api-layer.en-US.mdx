title: "TanStack Start HTTP handlers"
description: "The HTTP endpoints under /api and when to add one instead of a server function."
---

The application's own operations are server functions. HTTP handlers exist only where something outside the application's RPC client calls a URL: Better Auth's browser client, OAuth providers, Polar webhooks and the docs search box.

| File                       | Path          | Methods   | Handles                                                                                                                             |
| -------------------------- | ------------- | --------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `src/routes/api/index.ts`  | `/api`        | GET       | A JSON status response `{ runtime: "cloudflare-workers" }`                                                                          |
| `src/routes/api/auth.$.ts` | `/api/auth/*` | GET, POST | Every Better Auth endpoint, including OAuth callbacks, email verification, the Polar customer portal and `/api/auth/polar/webhooks` |
| `src/routes/api/search.ts` | `/api/search` | GET       | Fumadocs search over the documentation                                                                                              |

A handler is declared with `server.handlers` on `createFileRoute`. It receives the Web `Request` and returns a `Response`:

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Rules

- Do not add a REST endpoint for an operation that only this application calls. Write a use case with `createServerFn` instead; it gets typed input, middleware and query options.
- A handler validates its input and checks permissions itself. The server function middleware (`authorized`, `withRateLimit`) does not run for handlers.
- Keep vendor-specific verification in the integration. Polar webhook signatures are verified by the Polar plugin inside Better Auth, not by a custom handler.
- `/api` paths are never localized, never prerendered and skip the Worker's locale handling.
