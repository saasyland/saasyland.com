## Templates

Templates live in `src/presentation/emails`. Each file holds markup only and exports its namespace constant:

| Template                         | Namespace                                 | Sent by                                                                                                      |
| -------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `VerifyEmail`                    | `emails.verify-email`                     | `sendVerifyEmail` (Better Auth hook)                                                                         |
| `ResetPasswordEmail`             | `emails.reset-password-email`             | `sendResetPasswordEmail` (Better Auth hook)                                                                  |
| `ChangeEmailConfirmationEmail`   | `emails.change-email-confirmation-email`  | `sendChangeEmailConfirmationEmail` (Better Auth hook)                                                        |
| `ExistingAccountEmail`           | `emails.existing-account-email`           | `sendExistingAccountEmail` (Better Auth `onExistingUserSignUp`)                                              |
| `PasswordChangedEmail`           | `emails.password-changed-email`           | `sendPasswordChangedEmail` (Better Auth `onPasswordReset`, the `password-change-notice` hook, `setPassword`) |
| `DeleteAccountEmail`             | `emails.delete-account-email`             | `sendDeleteAccountEmail` (Better Auth `sendDeleteAccountVerification`)                                       |
| `InvitationEmail`                | `emails.invitation-email`                 | `sendInvitationEmail` (`createInvitation`, `resendInvitation`)                                               |
| `NewsletterConfirmationEmail`    | `emails.newsletter-confirmation-email`    | `subscribeToNewsletter`                                                                                      |
| `NewsletterNotificationEmail`    | `emails.newsletter-notification-email`    | `confirmNewsletterSubscription`, to `CONTACT_EMAIL`                                                          |
| `NewsletterIssueEmail`           | `emails.newsletter-issue-email`           | `sendNewsletterIssue`, through `sendBatchEmails`, to the confirmed subscribers                               |
| `PurchaseConfirmationEmail`      | `emails.purchase-confirmation-email`      | `sendPurchaseConfirmationEmail` (Polar `order.paid`)                                                         |
| `UnmatchedOrderAlertEmail`       | `emails.unmatched-order-alert-email`      | `sendUnmatchedOrderAlert` (Polar `order.paid`), to `CONTACT_EMAIL`                                           |
| `WithdrawalAcknowledgementEmail` | `emails.withdrawal-acknowledgement-email` | `sendWithdrawalAcknowledgement` (`submitWithdrawal`)                                                         |
| `WithdrawalNotificationEmail`    | `emails.withdrawal-notification-email`    | `sendWithdrawalNotification` (`submitWithdrawal`), to `CONTACT_EMAIL`                                        |

A template receives `locale` and `messages` and translates with use-intl `createTranslator`:

```tsx
const t = createTranslator({ locale, messages: { emails: { "verify-email": messages } }, namespace: "emails.verify-email" })
```

The account emails start with `EmailBrandHeader`, the application's name, and put `EmailFallbackLink` under their button: the same link as plain text, for clients that hide buttons. The verification, password reset, email change and account deletion emails say how long their link works, from `EMAIL_LINK_LIFETIME_HOURS`, the value Better Auth is configured with.

## Sending

The use case takes the locale and the `redirect` from the callback URL Better Auth passes along, checks the per-recipient limit, loads the messages, renders the template and sends it (`src/modules/verification/use-cases/send-verify-email.ts`):

```ts
if (!(await withinRecipientRateLimit({ kind: VERIFICATION_EMAIL_PURPOSE.VERIFY_EMAIL, recipient: user.email }))) {
  console.warn("[email] verification email not sent: the recipient reached the hourly limit")
  return
}
const callback = new URL(callbackURL, getRequest().url)
const locale = extractLocaleFromPath(callback.pathname) ?? I18N.DEFAULT_LOCALE
const verifyUrl = new URL(localizePathname({ locale, pathname: ROUTES.AUTH.VERIFY_EMAIL }), getRequest().url)
verifyUrl.search = callback.search
verifyUrl.searchParams.set("token", token)

const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotency: { purpose: VERIFICATION_EMAIL_PURPOSE.VERIFY_EMAIL, token: crypto.randomUUID() },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```

`sendEmail` (`src/integrations/resend/resend.utils.ts`) sends through Resend from `RESEND_EMAIL_FROM` unless a `from` is given (the owner notification, the unmatched order alert and the withdrawal notification use `NOTIFICATIONS_EMAIL`), passes the idempotency key and throws on failure. `sendBatchEmails` sends up to <RepositoryFact name="newsletterBatchSize" /> emails, each with its own headers, in one request under one idempotency key, logs the ones Resend refuses and returns the IDs of the others; only the newsletter's issues use it ([Newsletter](/docs/features/newsletter#sending)).

Account emails use the locale of the page where the flow started, read from the `callbackURL` in the email link; for a repeated sign-up it comes from the `callbackURL` of the sign-up request. A flow that names no callback, a sign-in to an unverified account or a password reset, takes the locale and `redirect` from the page that sent the request (its `Referer`, when it is on this site). The newsletter confirmation uses the locale submitted with the form, and each issue the locale stored with the subscription, or English when the issue has no complete version in it; the owner notification is always in `en-US`. The purchase confirmation uses the locale that `createCheckout` stored in the order's metadata, and English when there is none; it confirms the buyer's consent to immediate supply on a durable medium, see [Licences](/docs/features/licences#purchase-confirmation). The unmatched order alert, which tells the site about a paid licence order whose customer matches no account, is in `I18N.DEFAULT_LOCALE`, see [Licences](/docs/features/licences#orders-that-match-no-account). The acknowledgement of a withdrawal uses the locale of the page where the statement was submitted, and the withdrawal notification to the site is in `I18N.DEFAULT_LOCALE`, see [Licences](/docs/features/licences#withdrawal-function). The invitation email uses the language the admin chose for it, stored in the invitation's `locale`.

`withinRecipientRateLimit` (`src/lib/rate-limit.ts`) allows at most <RepositoryFact name="recipientEmailsPerHour" /> emails of each kind (verification, password reset, existing account, account deletion, newsletter confirmation and withdrawal acknowledgement) per address per hour, counted in the `rate_limit` table under a SHA-256 hash of the address. Over the limit the email is skipped and the request still gets its normal answer. The change-email confirmation, the password change notice, the owner notification, the newsletter's issues, the purchase confirmation, the unmatched order alert and the withdrawal notification are not limited; a password change needs a reset token or the current password, Polar's webhook, not a visitor, triggers the purchase confirmation and the unmatched order alert, once per order, an issue reaches each confirmed subscriber once and only an admin sends it, and the withdrawal notification goes only to the site, at most <RepositoryFact name="sensitiveRateLimit" /> per client a minute. The invitation email counts against the same limit, but over it `sendInvitationEmail` fails with `TOO_MANY_REQUESTS` instead of skipping the email.
