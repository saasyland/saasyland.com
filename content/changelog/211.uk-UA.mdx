- API ліцензій для CLI: запит доходить до D1 один раз, перш ніж Worker звернеться до Polar. Ліміти запитів для адреси й ліцензійного ключа та пошук ліцензії потребували трьох послідовних звернень до D1; тепер вони виконуються одним пакетом D1, який D1 виконує як одну транзакцію. `rateLimitBatch` у `src/lib/rate-limit.ts` повертає інструкції, які рахують запит, а API додає до них пошук ліцензії. Запит, який відхилив ліміт адреси, як і раніше нічого не записує й не рахується для ключа, невідомий ключ як і раніше рахується для обох лімітів, а `retry-after` як і раніше показує секунди, що лишилися у вікні лічильника, який відхилив запит. Ключ надходить у заголовку `authorization`, тож Worker відхиляє запит понад будь-який із лімітів ще до читання тіла; запит із ключем тепер рахується для цього ключа, навіть коли його тіло чи заголовок машини не вдається прочитати. Прострочені лічильники видаляються раз на запит, а не раз на ліміт. Див. [Обмеження частоти запитів](/docs/features/cli-licence-api#rate-limits).
