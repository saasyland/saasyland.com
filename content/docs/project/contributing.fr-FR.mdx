---
title: "Contribuer"
description: "Comment proposer des modifications à SaaSy Land."
---

1. Discutez d'abord des modifications importantes dans une issue.
2. Créez une branche à partir de `main`.
3. Respectez l'[architecture](/docs/architecture) et les [conventions](/docs/reference/conventions), et lisez la [skill pour agents](/docs/tooling/agent-skills) correspondante avant de modifier l'intégration d'un fournisseur.
4. Placez les tests à côté de leur propriétaire et maintenez le seuil de couverture à 100 %.
5. Exécutez les vérifications ci-dessous.
6. Committez avec un message de [commit conventionnel](/docs/tooling/conventional-commits) et ouvrez une pull request avec un titre conventionnel.

```sh
bun run check
bun run test:coverage
bun run test:e2e:install
bun run test:e2e:smoke
```

Exécutez la suite complète de tests dans le navigateur (`bun run test:e2e`) pour les modifications qui concernent plusieurs routes, l'authentification ou le comportement du navigateur. Validez séparément les intégrations réelles avec les fournisseurs lorsque vous modifiez leur configuration.

Lorsque le comportement change, mettez à jour `content/docs` dans les neuf langues ; `bun run check:i18n` rejette les traductions manquantes, ainsi que les blocs de code et la navigation qui diffèrent. Dans la pull request, décrivez le comportement obtenu, la façon dont vous l'avez vérifié et tout flux de démonstration ou inachevé qu'elle laisse en place.
