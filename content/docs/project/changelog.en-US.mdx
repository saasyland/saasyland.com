## 2026-11-15

- One header on every public page. The landing page, the blog, the courses, the docs, the legal pages, `/premium` and the newsletter pages sit in one pathless layout, `_site` (`src/routes/_site.tsx`), which renders `Navigation` and `BackToTop` once, so no page or child layout renders a header of its own: `ContentNavigation` is gone, and the docs show the site header above their sidebar instead of only Fumadocs' bar. The header lists **Pricing**, **Courses**, **Blog**, **Docs** and **Sign in**, then **Start building**, in that order on every page and in the mobile menu, from the header entries of `src/data/<area>.navigation.ts` (`HEADER_NAVIGATION`, formerly `NAVIGATION_PAGES`): the core adds **Pricing**, which links to the pricing section through the entry's new `hash`, and the auth area adds **Sign in**. The landing page's section anchors left the header, and the current section is marked on every page, **Docs** included. Inside `_site`, the `_marketing` layout (`_site._marketing.tsx`, formerly `_landing.tsx`) gives every page but the docs the page frame, the footer and the dark theme, and loads the newsletter form's messages for the course pages too, which missed them. The header opens with a **Skip to content** link, its height is the `--spacing-header` theme token, and `html` keeps anchors and focused elements clear of it with `scroll-padding-top`. The section ids, `MARKETING_SECTION_IDS`, moved from `src/data/marketing.ts` to `src/data/navigation.constants.ts`, next to the other navigation constants. See [Landing page](/docs/features/landing-page#navigation-and-back-to-top).
- Fixed: the theme select in the docs sidebar was 4 px shorter until it hydrated, so the sidebar footer moved while the page loaded. `ThemeSwitch` now shows a placeholder as tall as the select.
- The polar area owns the Polar plugin, and the areas handle Polar's webhook events through a list of their own. `src/data/polar.auth-plugins.ts` registers the plugin with `webhooks({ onPayload: handlePolarEvent })`, and `handlePolarEvent` (`src/data/polar-events.ts`) hands each event, all at once, to every area that lists it in `src/data/<area>.polar-events.ts`; when one fails, the delivery answers 500 and Polar sends it again. The licence area lists its four events in `src/data/license.polar-events.ts` and passes each to the unchanged `licenseWebhookHandlers`, so licences are granted, refunded and revoked as before. `polar:verify` checks the webhook endpoint against `POLAR_EVENTS`, the events every area handles. `polar.constants.ts` no longer reads the environment, so the browser suite takes Polar's order statuses from it; `POLAR_PRODUCT_IDS` moved to the licence area's `license.utils.ts`, and `API_AUTH_POLAR` and `API_AUTH_CUSTOMER_PORTAL` to `src/data/polar.routes.ts`. An `overrides` entry gives `@polar-sh/adapter-utils` the application's `@polar-sh/sdk` 1.1.0, so the plugin's types accept the payload it validates. `verify-build.ts` now fails a build whose Worker would load Polar, Drizzle or Resend, or more than `BOOT_CLOSURE_MAX_BYTES`, on a cold start. The docs split [Payments](/docs/features/payments) from a new [Licences](/docs/features/licences) page.
- Better Auth takes its base path from the route constants. `auth.server.ts` and `auth.client.ts` set `basePath` to `ROUTES.API_AUTH_BASE`, the path `src/routes/api/auth.$.ts` serves, instead of relying on Better Auth's default, and tests check the server, the browser client and the route against it; every URL stays the same. The docs print the OAuth callback paths from the same constants. `disabledPaths` is gone from the auth plugin entries and the Better Auth configuration, and `DISABLED_AUTH_PATHS` with it: no area has closed a path to HTTP since the Polar plugin stopped adding its own checkout. An integration test checks that the Polar plugin's checkout path answers 404, so adding `checkout()` to the plugin again fails the suite. See [Authentication and security](/docs/integrations/better-auth).
- Fixed: `/app/license` told buyers to run `npx saasyland@latest init` and enter the key when asked, but `latest` is the CLI's placeholder release and `init` takes no key. The page now shows the `activate`, `whoami` and `deactivate` commands with what each does, and that CI reads the key from `SAASYLAND_LICENSE_KEY`. `src/data/cli.ts` is their one source: `CLI_RELEASE_CHANNEL` names the npm tag (today `beta`), and a test fails unless it is the tag that the installed `@saasyland/stack` was published on, so upgrading the dependency to a stable release moves the landing page's command, the release post, the docs and the journey suite to npm's default tag in the same change. The machine list and the overview's documentation card no longer promise scaffolding and an installation guide that do not exist yet. See [CLI instructions](/docs/features/customer-app#cli-instructions).
- The browser no longer downloads Drizzle. Each `<table>.zod.ts` built `insert`, `select` and `update` schemas from its table with `drizzle-zod`, which only tests read, and several enum tuples lived in the `.schema.ts` files, so the forms, the query options and the `/admin` and `/app` pending skeletons brought the tables, `drizzle-orm` and, through `drizzle-zod`, every zod locale to every page. Every enum tuple, `TIMEZONE_CODES` and `LICENSE_STATUSES` included, now sits in its module's `<table>.constants.ts`, the derived schemas and the `drizzle-zod` dependency are gone, and each page loads about 75 KiB less gzipped JavaScript: the landing page went from 526.2 KiB to 450.7 KiB. TanStack Start's import protection denies `drizzle-orm` in the client build, so an import that would bring it back fails the build and prints its import chain. See [Keep the ORM out of the browser](/docs/conventions/performance#keep-the-orm-out-of-the-browser).
- Every page loads about 21 KiB less gzipped JavaScript. The entry script carried the map from every message file to its chunk, every namespace in every locale, twice, because `loadPageMetadata` kept a map of its own, although the first page reads its messages from the query cache the server sends and never needed it. The map now lives in `i18n.loaders.ts`, which `loadNamespace` imports the first time it loads a namespace, and `loadPageMetadata` reads `metadata` from the page's namespace; the landing page went from 462.9 KiB to 442.3 KiB. `scripts/verify-build.ts` fails the build when the entry script's static imports hold the loader of a page namespace. See [Load messages when a page needs them](/docs/conventions/performance#load-messages-when-a-page-needs-them).
- Fixed: the Polar checkout opened with an empty email field for a signed-in buyer, because the Better Auth Polar plugin creates a checkout with the account's ID alone. `startCheckout` now creates the checkout with the Polar SDK and fills in the account's email and name, and the strict Polar double requires both. The Polar plugin no longer adds its own checkout, which was closed to HTTP and no longer used, so `ROUTES.API_AUTH_POLAR` holds only the webhooks and `POLAR_CHECKOUT_PRODUCTS` is gone. See [Payments and licences](/docs/features/payments).
- The core no longer needs sign-in. The admin console and the customer workspace exist only with it, so the auth area owns them: `/admin`, `/admin/settings`, `/app` and `/app/settings`, their menu entries, skeletons and labels, and the `admin` and `settings` permissions; the licence area declares the workspace's **Overview** entry with its page and validates the `tier` and `checkoutId` params on its own pages. `auth.server.ts` names no other area: the licence area adds the Polar plugin, its closed checkout and its webhooks exempt from rate limiting in `src/data/license.auth-plugins.ts`, Resend adds the verification, password reset and email change emails in `src/data/resend.auth-emails.ts`, `ROUTES.API_AUTH_POLAR` holds the Polar plugin's paths and the cookie prefix is `APP_SLUG` from the branding. `src/lib/rate-limit.ts` is a plain D1 limiter: Better Auth's storage moves into `auth.server.ts` and `clientAddress` into `auth.middleware.ts`. `TranslationsProvider` formats dates in the time zone an area supplies in `src/data/<area>.time-zone.ts`, which for the auth area is the signed-in user's, a layout preloads the namespaces other areas add to it in `src/data/<area>.namespaces.ts`, and the test doubles and the browser-test Worker's set-up and endpoints are declared per area. `verify-build.ts` fails a build that prerendered any page under an unlisted path. Sessions, guards, redirects, roles, emails and webhooks behave as before.
- Journey suite: `bun run test:journey` buys each tier on the preview deployment the way a customer does, from its own Playwright configuration in `e2e/journey/`, which pull requests do not run. It signs up with an address of Resend's test inbox and reads the verification email through the Resend API, checks the price for the runner's country, pays on the Polar sandbox checkout with Stripe's test card, and checks the order in Polar and the key on `/app/license`. Then it runs the published CLI, `npx saasyland@beta`, against preview: `activate`, the same slot on a second activation, `whoami`, CI machines up to the tier's limit and one more that is refused, a slot freed on `/app/license`, `deactivate`, and a refund through the Polar sandbox API that `whoami` reports as `licenseRefunded`. `playwright.config.ts` runs only `e2e/specs/` now. See [Journey suite](/docs/tooling/playwright#journey-suite).
- User management works end to end. **Add user** creates an account with a starting password and a role and opens its new profile, `/admin/users/<userId>`, which shows the account and the user's sessions; one session can be revoked, or all of them after a confirmation. The actions menu, in the table and on the profile, renames a user, changes the role, resets the password, bans after a confirmation or unbans, deletes, and impersonates a customer; while an admin impersonates, the workspace shows a banner with a button that returns to the admin account. The dashboard preview links each user to the profile instead of showing **Edit** and **Delete** buttons that did nothing, and the disabled **Last 30 days** button and the empty **Security** tab are gone. `listUserSessions` no longer sends session tokens to the browser and `revokeUserSession` takes a session ID; `updateUser` changes only the name and `createUser` requires a password and a role, the fields the screens send. See [Users (admin)](/docs/features/users-admin) and [Impersonation](/docs/features/impersonation).
- CLI licence API: the Worker answers the `saasyland` CLI. Reading the licence and activating, checking and releasing a machine follow the contract in `@saasyland/stack/api`, which the CLI imports too: `readApiRequest` reads every request, and `apiResponse` and `apiErrorResponse` write every answer. The key is looked up in D1, and the machines are activations of the key in Polar, identified by a machine ID that the CLI derives with an HMAC, so the raw machine ID never leaves the machine. Activating again from the same machine reuses its slot, a full licence answers `activationLimitReached` with the machines in use, requests are rate-limited per IP address and per licence key, and a Polar outage answers `serviceUnavailable` with `retry-after`. See [CLI licence API](/docs/features/cli-licence-api).
- Licences have a third status, `refunded`, which `order.refunded` sets. `benefit_grant.revoked` still sets `revoked` but never replaces `refunded`, because Polar also revokes the benefit of a refunded order and the two events can arrive in either order. `/app` and `/app/license` show a refunded licence as refunded. D1 stores the status as text, so no migration was needed.

The docs print the API's path, header, limits, endpoints and error codes from the contract when the site is built, and `<RepositoryTable>` takes any number of columns.

- Fixed: a build on a busy machine could stop prerendering with `connect ETIMEDOUT ::1` and `connect ECONNREFUSED 127.0.0.1`. The preview server that prerendering starts listened on `localhost`, which Node resolves to `::1` first, and the crawler connected by name, trying `::1` and then `127.0.0.1` with a short timer for each; when the build stalled for longer than that, the crawler gave up on `::1` and found nothing on `127.0.0.1`. `vp preview` now listens on `127.0.0.1`, the `LOCAL_SERVER` address in `src/data/local-server.ts` (at `127.0.0.1:3000` for `start` and `start:test`, on a free port for prerendering), so every local client connects to the address the server binds, without resolving a name.
