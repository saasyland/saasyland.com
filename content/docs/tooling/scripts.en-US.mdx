Run scripts from the repository root with `bun run <script>`. The scripts that call Wrangler, and `db:generate`, which calls drizzle-kit, run them through `vp exec`, which takes the binary from `node_modules/.bin`, so they always use the versions locked in `bun.lock`.

## Development and build

| Script             | Runs                                                                                                                                                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dev`              | `generate:cn`, `content` and `vp dev` in the `development` environment at http://localhost:3000                                                                                 |
| `build`            | Same as `build:preview`                                                                                                                                                         |
| `build:preview`    | Clean `dist`, `generate:cn`, `content`, `vp build` for `preview`, `scripts/verify-build.ts preview`, `scripts/optimize-prerendered-html.ts` and `scripts/generate-seo-files.ts` |
| `build:production` | The same steps for `production`                                                                                                                                                 |
| `build:test`       | The same steps for the `test` environment                                                                                                                                       |
| `start`            | `vp preview` of the latest build at http://127.0.0.1:3000                                                                                                                       |
| `start:test`       | `vp preview` of the test build                                                                                                                                                  |

`verify-build.ts` checks that `.wrangler/deploy/config.json` points to `dist/server/wrangler.json` and that this file deploys the Worker that `wrangler.jsonc` names for the environment, then the document language, canonical and alternate links of the localized home and legal pages, the fonts, that protected pages and locale aliases were not prerendered, that every docs page and published blog post was prerendered and that no client asset imports `cloudflare:workers`. `optimize-prerendered-html.ts` removes dependency `modulepreload` hints from prerendered pages and keeps the entry hint at low priority. `generate-seo-files.ts` writes `sitemap.xml` and renders a social card for every prerendered page from the pages' own metadata; see [Search and social previews](/docs/features/seo).

## Deploy

| Script              | Runs                                                                                                                                                                                                                                          |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `deploy:preview`    | `scripts/verify-bindings.ts preview`, `polar:verify:preview`, `build:preview`, `scripts/prepare-deploy-secrets.ts preview`, `db:migrate:preview`, `wrangler deploy` of `dist/server/wrangler.json` and `scripts/verify-deployment.ts preview` |
| `deploy:production` | The same steps for `production`                                                                                                                                                                                                               |

- `verify-bindings.ts` fails when the environment has no `DB`, `CACHE` or `MEDIA` binding or still has a placeholder D1 or KV ID, and when production shares its database, namespace or bucket with preview.
- `polar:verify:<environment>` stops the deploy before the build when the Polar organisation in `.env.<environment>` does not match the code.
- `prepare-deploy-secrets.ts` reads the keys listed in the environment's `secrets.required` from `.env.<environment>`, fails when one is missing or empty and writes only those keys to `.wrangler/secrets.<environment>.json`. Other variables in the file are not uploaded.
- Migrations run after the build and before the deploy, so a failed build never touches the database and the new Worker never starts on an older schema.
- The deploy runs `env -u CLOUDFLARE_ENV vp exec wrangler deploy --config dist/server/wrangler.json --secrets-file .wrangler/secrets.<environment>.json`. The built config already targets one environment; a `CLOUDFLARE_ENV` left in the shell would make Wrangler look for an environment section that file does not have.
- `verify-deployment.ts` requests <RepositoryFact name="liveSiteCheckPaths" /> on the environment's domain and fails unless each answers `200` with the expected content type. It asks a failing path three times, five seconds apart, and changes nothing. `bun scripts/verify-deployment.ts <preview|production>` checks a live site on its own.

## Generation and maintenance

| Script           | Runs                                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------ |
| `content`        | `fumadocs-mdx`: generates `.source/` from `content/`                                                   |
| `generate:cn`    | Builds the class-merging tables in `.source/cn-tables.ts` from `src/lib/cn.config.ts`                  |
| `cf-typegen`     | `wrangler types` for `development`: regenerates `src/types/worker-configuration.d.ts`                  |
| `typegen`        | `cf-typegen`, `generate:cn` and `content`                                                              |
| `skills:sync`    | `scripts/sync-skills.ts`: restores agent skills from `skills-lock.json`                                |
| `clean`          | Removes `.source`, `.tanstack`, `.wrangler`, `dist`, `coverage`, Playwright output and `*.tsbuildinfo` |
| `clean:deep`     | `clean` and `node_modules`                                                                             |
| `clean:hardcore` | `clean:deep`, `bun.lock` and `skills-lock.json`                                                        |
| `prepare`        | Runs on install: `vp config --no-agent` (Git hooks), `generate:cn` and `content`                       |

`clean` deletes `.wrangler`, including the local development and test databases and the secrets files written by the deploy scripts, so export any local data you want to keep first.
