Run scripts from the repository root with `bun run <script>`. The scripts that call Wrangler, and `db:generate`, which calls drizzle-kit, run them through `vp exec`, which takes the binary from `node_modules/.bin`, so they always use the versions locked in `bun.lock`.

## Development and build

| Script             | Runs                                                                                                                                                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dev`              | `generate:cn`, `content` and `vp dev` in the `development` environment at http://localhost:3000                                                                                 |
| `build`            | Same as `build:preview`                                                                                                                                                         |
| `build:preview`    | Clean `dist`, `generate:cn`, `content`, `vp build` for `preview`, `scripts/verify-build.ts preview`, `scripts/optimize-prerendered-html.ts` and `scripts/generate-seo-files.ts` |
| `build:production` | The same steps for `production`                                                                                                                                                 |
| `build:test`       | The same steps for the `test` environment                                                                                                                                       |
| `start`            | `vp preview` of the latest build at http://127.0.0.1:3000                                                                                                                       |
| `start:test`       | `vp preview` of the test build                                                                                                                                                  |

`verify-build.ts` checks that `.wrangler/deploy/config.json` points to `dist/server/wrangler.json` and that this file deploys the Worker that `wrangler.jsonc` names for the environment, then the document language, canonical and alternate links of the localized home and legal pages, the fonts, that locale aliases and the pages under the areas' unlisted paths were not prerendered, that every docs page and published blog post was prerendered, that no client asset imports `cloudflare:workers`, that the static imports of the browser's entry script hold no loader of a page namespace's messages, and that the code the Worker loads on a cold start stays small: the static imports of `dist/server/index.js` must not reach `@polar-sh`, `drizzle-orm` or `resend` and must add up to at most `BOOT_CLOSURE_MAX_BYTES` (see [Performance](/docs/conventions/performance)). `optimize-prerendered-html.ts` removes dependency `modulepreload` hints from prerendered pages and keeps the entry hint at low priority. `generate-seo-files.ts` writes `sitemap.xml` and the blog's feed in every locale, and renders a social card for every prerendered page and the organisation's logo, all from the pages' own metadata; see [Search and social previews](/docs/features/seo).

## Deploy

| Script              | Runs                                                                                                                                                                                                                                                          |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `deploy:preview`    | `scripts/verify-bindings.ts preview`, `scripts/prepare-deploy-secrets.ts preview`, `scripts/run-deploy-checks.ts preview`, `build:preview`, `db:migrate:preview`, `wrangler deploy` of `dist/server/wrangler.json` and `scripts/verify-deployment.ts preview` |
| `deploy:production` | The same steps for `production`                                                                                                                                                                                                                               |

- `verify-bindings.ts` fails when the environment lacks a binding that `development` declares (`DB`, `CACHE`, `MEDIA` and `BUNDLES` here) or still has a placeholder D1 or KV ID, and when production shares its database, namespace or bucket with preview.
- `prepare-deploy-secrets.ts` reads the keys listed in the environment's `secrets.required` from `.env.<environment>`, fails when one is missing, empty or a placeholder, and writes only those keys to `.wrangler/secrets.<environment>.json`. A placeholder is a value between brackets (<RepositoryFact name="secretPlaceholderBrackets" />), such as `[UPDATE]`, or one of the words <RepositoryFact name="secretPlaceholderWords" /> in any case and with or without spaces, hyphens or underscores. The error names the keys without printing their values. It reads the names from `wrangler.jsonc`, so it covers the secrets of every area without naming one. Other variables in the file are not uploaded.
- `run-deploy-checks.ts` runs `bun run <check>:<environment>` for every deploy check that an area declares in `src/data/<area>.deploy.ts`, and stops the deploy before the build when one fails. The checks today are the auth area's `auth:verify`, which fails unless <RepositoryFact name="oauthClientIdVariables" /> in `.env.<environment>` each hold a client ID in the format of its provider (the formats that `verify-deployment.ts` applies after the deploy), and the Polar area's `polar:verify`, which fails when the Polar organisation in `.env.<environment>` does not match the code.
- Migrations run after the build and before the deploy, so a failed build never touches the database and the new Worker never starts on an older schema.
- The deploy runs `env -u CLOUDFLARE_ENV vp exec wrangler deploy --config dist/server/wrangler.json --secrets-file .wrangler/secrets.<environment>.json`. The built config already targets one environment; a `CLOUDFLARE_ENV` left in the shell would make Wrangler look for an environment section that file does not have.
- `verify-deployment.ts` requests <RepositoryFact name="liveSiteCheckPaths" /> on the environment's domain and fails unless each answers `200` with the expected content type. At <RepositoryFact name="socialSignInPath" /> it starts the sign-in with each provider of the sign-in page, <RepositoryFact name="oauthProviderIds" />, as the browser does, and fails unless the authorize URL it gets back is on the provider's own host and carries a `client_id` in that provider's format and a `redirect_uri` of <RepositoryFact name="oauthCallbackPath" /> on the same domain. The error names the provider and what is wrong without printing the value. It runs a failing check again up to <RepositoryFact name="liveSiteCheckRetries" /> times, <RepositoryFact name="liveSiteCheckRetrySeconds" unit="second" /> apart, and changes nothing but the short-lived OAuth state and attempt counter in D1 that a click on a sign-in button leaves as well. `bun scripts/verify-deployment.ts <preview|production>` checks a live site on its own.

## Checks

| Script                                                                        | Runs                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `check`                                                                       | `generate:cn`, `check:comments`, `check:i18n`, `check:flows` and `vp check` (format, lint and types)                                                                                                                                                                              |
| `check:comments`                                                              | `scripts/check-comments.ts`: parses every TypeScript, JavaScript and CSS file that Git tracks or would add, except the files `.gitattributes` marks `linguist-generated`, and fails on any comment, naming its file, line and fix; see [Code style](/docs/conventions/code-style) |
| `check:fix`                                                                   | The same with `vp check --fix`                                                                                                                                                                                                                                                    |
| `check:flows`                                                                 | `scripts/check-flows.ts`: lists the browser suite with `playwright test --list` and fails when a flow in `e2e/data/<area>.flows.ts` names a test that is gone or skipped, or does not say why it is missing; see [Test coverage](/docs/tooling/test-coverage)                     |
| `check:i18n`                                                                  | `scripts/check-i18n.ts`, `scripts/check-message-formats.ts` and `scripts/check-content.ts`                                                                                                                                                                                        |
| `check:pre-commit`                                                            | `generate:cn`, `check:comments`, `check:i18n` and `vp staged`; run by the pre-commit hook                                                                                                                                                                                         |
| `lint`                                                                        | `vp lint`                                                                                                                                                                                                                                                                         |
| `format`                                                                      | `vp fmt`                                                                                                                                                                                                                                                                          |
| `format:check`                                                                | `vp fmt --check`                                                                                                                                                                                                                                                                  |
| `auth:verify:preview`, `auth:verify:production`                               | `scripts/verify-auth.ts`: checks that the OAuth client IDs in `.env.<environment>` have the formats of their providers, without a network request                                                                                                                                 |
| `polar:verify:development`, `polar:verify:preview`, `polar:verify:production` | `scripts/verify-polar.ts`: compares the environment's Polar organisation with the code, with GET requests only; see [Polar setup](/docs/getting-started/polar-setup)                                                                                                              |

## Generation and maintenance

| Script           | Runs                                                                                                            |
| ---------------- | --------------------------------------------------------------------------------------------------------------- |
| `content`        | `fumadocs-mdx`: generates `.source/` from `content/`                                                            |
| `generate:cn`    | Builds the class-merging tables in `.source/cn-tables.ts` from `src/lib/cn.config.ts`                           |
| `cf-typegen`     | `wrangler types` for `development`: regenerates `src/types/worker-configuration.d.ts`                           |
| `typegen`        | `cf-typegen`, `generate:cn` and `content`                                                                       |
| `skills:sync`    | `scripts/sync-skills.ts`: restores agent skills from `skills-lock.json`                                         |
| `clean`          | Removes `.source`, `.tanstack`, `.wrangler`, `dist`, `coverage`, Playwright output and `*.tsbuildinfo`          |
| `clean:deep`     | `clean` and `node_modules`                                                                                      |
| `clean:hardcore` | `clean:deep`, `bun.lock` and `skills-lock.json`                                                                 |
| `prepare`        | Runs on install: `vp config --no-agent` (Git hooks), `scripts/verify-git-hooks.ts`, `generate:cn` and `content` |

`clean` deletes `.wrangler`, including the local development and test databases and the secrets files written by the deploy scripts, so export any local data you want to keep first.
