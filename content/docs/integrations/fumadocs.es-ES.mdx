title: "Fumadocs"
description: "Colecciones MDX para la documentación y el blog, fuentes localizadas y búsqueda."
---

Fumadocs convierte `content/docs` y `content/blog` en árboles de páginas localizados. `bun run content` ejecuta `fumadocs-mdx` y escribe `.source/`; `dev`, `typegen` y todos los scripts de compilación lo ejecutan primero.

| Archivo              | Propósito                                                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `fumadocs.config.ts` | La colección `docs`, la colección `blog` con su esquema de frontmatter, y los temas y sustituciones de color del resaltado de código             |
| `fumadocs.i18n.ts`   | Los idiomas de `I18N`, `en-US` como idioma predeterminado y de reserva, el parser `dot` para `<slug>.<locale>.mdx` y el prefijo de idioma oculto |
| `fumadocs.source.ts` | `source` en `/docs` con el plugin de iconos de Lucide, `blogSource` en `/blog` y `getPublishedBlogPosts` con el tiempo de lectura                |
| `fumadocs.docs.ts`   | La función de servidor `getDocsPage`, `loadDocsPage` y `docsHead` para la ruta `docs.$`                                                          |
| `fumadocs.search.ts` | El índice de búsqueda servido por `/api/search`                                                                                                  |

El prefijo de idioma se oculta en las URL de Fumadocs porque lo añade el router. El frontmatter del blog exige `title`, `authorName` y `date`, y acepta `description`, `excerpt`, `faq`, `featured`, `image`, `published`, `tags`, `updated` y `authorImage`.

## Componentes

`src/presentation/components/custom/mdx.tsx` asigna los componentes MDX: los predeterminados de Fumadocs (incluidos `Cards` y `Callout`), `Accordions`, `Steps` y `Tabs`, y los componentes de shadcn `Alert`, `Badge`, `Button`, las partes de card, `Separator` y `Table`; `RepositoryFact`, que muestra un valor medido en el repositorio durante el build o definido en el código, como en `<RepositoryFact name="testFiles" />`, y `RepositoryTable`, que muestra una tabla construida a partir del código, como en `<RepositoryTable name="commitTypes" columns={["Type", "Emoji"]} />`. `TierPrice` muestra el precio de lista de un nivel desde `TIER_PRICES` en el idioma de la página, como en `<TierPrice tier="core" />`, para que ninguna página escriba un precio a mano. `ActivationLimit` muestra el límite de activaciones de un nivel desde `LICENSE_ACTIVATION_LIMITS`, como en `<ActivationLimit tier="core" />`, y `RegionalDiscounts` enumera los porcentajes de descuento regional derivados de `PPP_TIERS`. Los enlaces internos se localizan con `localizePathname`, y un elemento de una lista de tareas envuelve su casilla y su texto en un `label`. `docs-content.tsx` y `blog-content.tsx` renderizan las páginas.

`@fumadocs/base-ui` está fijado a 16.19.0 con un parche de Bun: su `CodeBlock` daba al área de desplazamiento de cada bloque de código el rol `region` sin nombre, así que una página con dos bloques de código tenía landmarks duplicados sin nombre. Con el parche, el área de desplazamiento es una región con el nombre del título del bloque cuando lo tiene y, si no, sigue siendo enfocable sin rol. Consulta [Dependencias](/docs/conventions/dependencies).

## Reglas de contenido

Cada página existe una vez por idioma como `<slug>.<locale>.mdx`, y cada carpeta tiene un `meta.<locale>.json` con el mismo array `pages` en todos los idiomas. `icon` en un archivo meta admite el nombre de un icono de Lucide. `scripts/check-content.ts`, que forma parte de `bun run check:i18n`, falla cuando falta una traducción, un bloque de código es distinto, la navegación es distinta o queda un párrafo en inglés en otro idioma.
