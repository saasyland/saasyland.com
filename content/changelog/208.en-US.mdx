- Changed: a bundle request to the CLI licence API reads the head of the release's archive in R2 instead of the archive. The archive's SHA-256 now travels with it as the custom metadata `sha256`, which the CLI repository's `bundle:upload` writes, so the Worker no longer downloads, decompresses and hashes the whole bundle on every request: with today's 1.7 MB bundle a request took about 31 ms of CPU in the local test Worker and now takes about 3 ms, however large the bundle grows. An object without the digest answers `serviceUnavailable`, and the log names it. `bun run db:reset:test` seeds the local bundle with its digest through Wrangler's `getPlatformProxy`, because `wrangler r2 object put` cannot set custom metadata. See [Template bundles](/docs/features/cli-licence-api#template-bundles) and [Publishing bundles](/docs/features/cli-licence-api#publishing-bundles).
