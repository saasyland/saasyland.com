Każda nowa tabela renderuje się przez `DataGrid` w `src/presentation/components/custom/data-grid.tsx` ([Siatka danych](/docs/ui/data-grid)). Zapewnia wyszukiwanie, filtry, sortowanie, układ, który każdy administrator może zmienić i zachować, zaznaczanie, eksport CSV, szkielety wierszy i puste stany. Tabela potrzebuje hooka kolumn i jednego `<DataGrid />`. Pełnym przykładem jest `/admin/orders`: `src/presentation/components/custom/admin/payments/order-columns.tsx` i `src/routes/admin.orders.index.tsx`.

## 1. Napisz hook kolumn

Utwórz `<entity>-columns.tsx` obok pozostałych widżetów strony. Wyeksportuj hook, który odczytuje tłumaczenia i dane oferowane przez filtry oraz zwraca zmemoizowane kolumny. Komórki to małe komponenty w tym samym pliku, które same odczytują swoje tłumaczenia. Skrócona wersja `order-columns.tsx`:

```tsx
const columnHelper = createColumnHelper<DataGridFeatures, OrderRow>()

export const useOrderColumns = (): DataGridColumn<OrderRow>[] => {
  const t = useTranslations()

  const { products } = useSuspenseQuery(orderFiltersQuery).data

  return useMemo(
    () =>
      columnHelper.columns([
        columnHelper.accessor("placedAt", {
          cell: PlacedCell,
          header: t("pages.admin.orders.table.headers.placedAt"),
          meta: { filter: { kind: DATA_GRID_FILTER.DATE_RANGE }, pinned: DATA_GRID_PIN.START },
          size: ORDER_COLUMN_SIZES.placedAt,
        }),
        columnHelper.accessor("description", {
          cell: ProductCell,
          enableSorting: false,
          header: t("pages.admin.orders.table.headers.product"),
          id: "product",
          meta: { filter: { kind: DATA_GRID_FILTER.MULTI_SELECT, options: products.map(({ id, name }) => ({ label: name, value: id })) } },
          size: ORDER_COLUMN_SIZES.product,
        }),
        columnHelper.accessor("refunded", {
          cell: RefundedCell,
          header: t("pages.admin.orders.table.headers.refundedAmount"),
          id: "refundedAmount",
          meta: { export: ({ refunded }) => exportedMoney(refunded), hidden: true },
          size: ORDER_COLUMN_SIZES.refundedAmount,
        }),
      ]),
    [products, t],
  )
}
```

- Wiersze muszą mieć tekstowe `id`; staje się ono identyfikatorem wiersza przy zaznaczaniu.
- `header` to przetłumaczona etykieta jako tekst. Siatka używa jej w nagłówku, menu, chipach filtrów, komunikatach dla czytników ekranu i w CSV.
- `meta.filter` daje kolumnie filtr jednego rodzaju: <RepositoryFact name="dataGridFilterKinds" />. Filtr wyboru wymienia swoje `options` jako `{ label, value }`.
- `meta.hidden` ukrywa kolumnę, dopóki administrator jej nie pokaże, `meta.pinned` przypina ją do `start` albo do `end`, a `meta.export` zapisuje tekst CSV kolumny dla wiersza.
- `size` to początkowa szerokość w pikselach. Trzymaj rozmiary w jednej stałej w `src/data/<area>.ts`, np. `ORDER_COLUMN_SIZES` w `payments.ts`, żeby szkielet trasy też mógł z nich korzystać.
- Kolumna, po której serwer nie umie sortować, ustawia `enableSorting: false`.

## 2. Wyrenderuj ją

Przekaż kolumny, unikalne `id`, `label` tabeli oraz `data` albo `query`:

```tsx
const OrdersPage = (): JSX.Element => {
  const t = useTranslations("pages.admin.orders")
  const columns = useOrderColumns()

  return (
    <DataGrid
      columns={columns}
      empty={t("empty")}
      id={ORDER_GRID_ID}
      label={t("title")}
      query={(request) => getOrdersPageQuery(orderZodSchemas.getOrders.parse(request))}
      search={t("filters.search")}
      selectable
    />
  )
}
```

Z `data` siatka wyszukuje, filtruje, sortuje i stronicuje wiersze w przeglądarce. Z `query` wysyła `{ filters, pageIndex, pageSize, search, sorting }`, a całą resztę robi serwer.

## 3. Odczytaj żądanie na serwerze

Schemat Zod modułu przyjmuje żądanie w takiej postaci, w jakiej przychodzi. `filters` zawiera filtrowane kolumny po id, z wartościami opisanymi na stronie [Siatka danych](/docs/ui/data-grid#filters), więc schemat korzysta ze wspólnych pól; fragment z `src/modules/order/order.zod.ts`:

```ts
const orderFilters = zod.object({
  country: zod.array(countryCodeField).max(COUNTRY_CODES.length).optional(),
  customer: searchField.optional(),
  discount: idField.optional(),
  placedAt: dateRangeField.optional(),
  product: zod.array(idField).max(MAX_FILTER_VALUES).optional(),
  status: zod.array(choiceOf(ORDER_STATUSES)).max(ORDER_STATUSES.length).optional(),
  totalAmount: numberRangeField.optional(),
})

const getOrders = paginationSchema.extend({
  filters: orderFilters.default({}),
  search: searchField.default(""),
  sorting: sortingOf(ORDER_SORT_COLUMNS),
})
```

`numberRangeField`, `dateRangeField` oraz limity `SEARCH_MAX_LENGTH`, `MAX_SORTED_COLUMNS` i `MAX_FILTER_VALUES` pochodzą z `src/modules/_core/utils/`; to te same wartości, których używa siatka, więc pole wyszukiwania przyjmuje <RepositoryFact name="dataGridSearchMaxLength" /> znaków, a siatka sortuje według maksymalnie <RepositoryFact name="dataGridMaxSortedColumns" /> kolumn. `getOrders` zamienia każdy filtr na SQL; zakres kwot porównuje każde zamówienie w jego własnej walucie przez `inMinorUnits`.

Pierwszą stronę wczytaj z wyprzedzeniem w loaderze trasy przez `context.queryClient.query({ ...getOrdersQuery, staleTime: "static" })`; pierwsze żądanie siatki po sparsowaniu daje ten sam klucz zapytania.

## 4. Odwzoruj ją w szkielecie

`pendingComponent` trasy renderuje `DataGridPending` z `data-grid-pending.tsx` z jednym szkieletem komórki i szerokością dla każdej widocznej kolumny, tak jak `AdminOrdersPending` w `payments-pending.tsx`.

## 5. Komunikaty

Pasek narzędzi, filtry, menu, paginacja, zaznaczanie i puste stany siatki pochodzą z `components.custom.data-grid`, które wczytuje każda strona. Etykiety kolumn, opcje filtrów i komunikat o braku danych należą do przestrzeni nazw strony, np. `pages.admin.orders`.

Gdy mutacja zmienia wiersze, unieważnij klucze zapytań modułu; siatka pobierze bieżącą stronę ponownie. Zobacz [Dodawanie przypadku użycia](/docs/guides/add-a-use-case).
