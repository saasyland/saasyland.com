## Page request

1. **Locale canonicalization.** `src/server.ts` calls `resolveLocale` for `GET` and `HEAD` document requests outside `/api` and `/_serverFn`. A language-only or default-locale prefix (`/pl/docs`, `/en-US/docs`) is redirected with `308` to its canonical form (`/pl-PL/docs`, `/docs`). When the URL locale differs from the locale cookie, the cookie is updated on the response.
2. **Static assets first.** The Worker asks the `ASSETS` binding for the path. Static files are returned as they are, and a prerendered page is streamed through `withNonce`, which puts a nonce created for this response on its scripts. Only on a `404` does it load the TanStack Start handler with a dynamic `import()`.
3. **Routing.** `getRouter` creates a new router and `QueryClient`. The router's `rewrite` removes the locale prefix, so `/pl-PL/docs` matches the `/docs` routes.
4. **Root `beforeLoad`** preloads the root translation namespaces (`common`, `components.*`, `errors*`).
5. **Guards.** Layout `beforeLoad` functions such as `requireAdmin` load the session query and redirect when access is not allowed.
6. **Loaders** run in parallel. Each preloads its namespaces, page metadata and queries into the request's `QueryClient`.
7. **Rendering.** The root shell renders `<html lang dir>` and wraps the body in `TranslationsProvider`. The query cache is serialized into the HTML so the browser does not fetch the same data again.
8. **Response headers.** For HTML responses the Worker adds a `Link` preload header for the locale's fonts, sets the locale cookie if needed, applies regional pricing attributes when the `cf-ipcountry` header qualifies for a discount, and sets `data-session` on `<html>` when the request carries the session cookie. Every response the Worker returns then gets the security headers (`SECURITY_HEADERS`, plus `HTTPS_SECURITY_HEADERS` over HTTPS, from `src/modules/_core/constants/api.ts`), replacing any value already set. An HTML response gets `documentPolicy` as its Content Security Policy instead, with the nonce `src/server.ts` created for it, and is `private, no-cache`, with `Vary: Cookie` and without `ETag` or `Last-Modified`, so a browser never reuses it with another response's nonce.
9. **Hydration.** The browser hydrates with the serialized cache. Later navigations run guards and loaders in the browser and fetch data through server functions.

## Server function call

1. The browser calls the server function, which the build replaced with an RPC request to `/_serverFn/…`. The Worker skips locale handling for this path. The URL has no locale prefix, so `getCurrentLocale()` returns `en-US` on the server; a server function that needs the locale takes it as input.
2. Middleware runs in the declared order. `withRequest` captures the request headers and normalizes errors, `withRateLimit` counts the attempt in D1, and `authorized` loads the session and checks the permission.
3. The validator parses the input with the module's Zod schema.
4. The handler queries D1 or calls a provider and returns plain data.
5. The component receives the data or an `AppError` code. On success it invalidates the module's query keys; on failure it shows `useErrorMessage()(error)`.

```text
GET /pl-PL/admin/users/all
  src/server.ts        resolveLocale, ASSETS lookup, TanStack Start handler
  router rewrite       /admin/users/all
  __root beforeLoad    root namespaces
  /admin beforeLoad    requireAdmin
  loaders              metadata, namespaces, queries
  SSR                  HTML with serialized query cache
  src/server.ts        Link header, locale cookie, regional pricing, security headers

POST /_serverFn/…
  withRequest → withRateLimit → authorized → validator → handler → data or AppError
```

## Media request

`src/server.ts` checks the path before anything else: a path that a feature's request handler claims goes to that handler and skips locale handling, the `ASSETS` lookup and TanStack Start. The courses feature claims `/media/`, and its handler loads, each with a dynamic `import()`, `serveCover` (`src/modules/course/course.delivery.ts`) for `/media/covers/`, `serveAttachment` for `/media/downloads/` and `serveMedia` (`src/modules/video/video.delivery.ts`) for every other path. Covers carry no signature, and `serveCover` answers from the Workers cache or R2; `serveAttachment` checks the signature of a download and reads it from R2. `serveMedia` checks the signature and expiry in the path, then answers from the Workers cache or R2, including `Range` requests. It also claims `/sitemap-courses.xml`, whose handler loads `serveCourseSitemap` from the same file and writes the course sitemap from D1 (see [Course sitemap](/docs/features/seo#course-sitemap)). The licence feature claims `/bundles/` in the same way, and its handler loads `serveBundle` (`src/modules/license/license.delivery.ts`), which checks the signature and expiry and streams the CLI's template bundle from R2. The response gets the same security headers as every other. See [Cloudflare R2](/docs/integrations/cloudflare-r2).
