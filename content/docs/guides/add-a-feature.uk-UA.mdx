description: "Наскрізний посібник від таблиці бази даних до протестованої сторінки з посиланнями на детальні посібники."
---

Нова функціональність зазвичай зачіпає всі шари: модуль таблиці, його сценарії використання, маршрут, компоненти представлення, повідомлення й тести. Категорії товарів показують увесь шлях: `src/modules/category`, вкладку категорій у `src/routes/admin.products.index.tsx` та `src/presentation/components/custom/admin/products/category-columns.tsx`.

## 1. Змоделюйте дані

Якщо функціональність зберігає нові дані, додайте модуль для її таблиці та згенеруйте міграцію.

- [Додавання модуля](/docs/guides/add-a-module)
- [Міграції бази даних](/docs/guides/database-migrations)

## 2. Визначте, хто що може робити

Додайте нові дії до `APP_STATEMENTS` у `src/integrations/better-auth/auth.access.ts` і надайте їх ролям.

- [Ролі та дозволи](/docs/guides/roles-and-permissions)

## 3. Напишіть операції

Додайте по одному сценарію використання на операцію з middleware, валідатором, handler і параметрами запиту чи мутації.

- [Додавання сценарію використання](/docs/guides/add-a-use-case)
- [Серверні функції](/docs/guides/server-functions)

## 4. Додайте маршрут

1. Додайте шлях до `ROUTES` у `src/routes.ts`.
2. Створіть плаский файл маршруту для потрібної зони: `src/routes/admin.<feature>.tsx` під layout адмін-панелі, `src/routes/app.<feature>.tsx` під layout клієнта, що увійшов, або `src/routes/_landing.<page>.tsx` для публічної сторінки.
3. Дотримуйтеся конвенції маршрутів: `const NAMESPACE`, `staticData: { namespaces: [NAMESPACE] }`, `head: pageHead(ROUTES.X)`, loader, що завантажує метадані, повідомлення й дані в одному `Promise.all`, і власний скелетон сторінки як `pendingComponent`, зареєстрований у мапі скелетона її layout (див. [Скелетони завантаження](/docs/architecture/delivery-layer#loading-skeletons)).
4. Guard `beforeLoad` layout (`requireAdmin` для `/admin`, `requireSignedIn` для `/app`) захищає сторінку. Серверні функції все одно самостійно авторизують кожен виклик.

- [Додавання сторінки адмін-панелі](/docs/guides/add-an-admin-page)
- [Стан в URL](/docs/guides/url-state)

## 5. Побудуйте інтерфейс

Розмістіть віджети, діалоги, форми й колонки таблиць у `src/presentation/components/custom/<area>/<feature>/`, по одному на файл. Кожен компонент сам читає свої переклади й дані; маршрут лише компонує їх.

- [Додавання таблиці даних](/docs/guides/add-a-data-table)
- [Форми та валідація](/docs/guides/forms-and-validation)

## 6. Додайте повідомлення

Створіть простір імен сторінки, а за потреби й простір імен валідації, для всіх дев'яти мов. Простори імен сторінок потребують `metadata.title` і `metadata.description`.

- [Інтернаціоналізація та мови](/docs/guides/i18n-messages)
- [Шаблони листів](/docs/guides/email-templates), якщо функціональність надсилає листи

## 7. Протестуйте й перевірте

Покрийте тестами сценарії використання, компоненти й маршрут, а потім запустіть усі перевірки:

```sh
bun run check
bun run test:coverage
bun run build
bun run test:e2e:smoke
```

- [Написання тестів](/docs/guides/writing-tests)
- [Чекліст безпеки](/docs/guides/security-checklist)
