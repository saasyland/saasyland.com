## Welche Laufzeitumgebung nutzt die Anwendung?

Cloudflare Workers. Bun installiert Pakete und führt Skripte aus; Vite+ (`vp`) baut, formatiert, lintet und testet die Anwendung.

## Brauchen lokale Tests ein Cloudflare-Konto?

Nein. Vitest verwendet eine SQLite-Datenbank und einen KV im Arbeitsspeicher. Playwright verwendet die Wrangler-Umgebung `test` mit lokaler D1 und lokalem KV in `.wrangler/test` sowie Dummy-Secrets aus `.env.test`. `bun run dev` braucht dagegen Zugriff auf Cloudflare, weil die Umgebung `development` die Remote-Preview-Bindings nutzt.

## Wohin gehört eine neue Operation?

Wenn sie mit einer Datenbanktabelle arbeitet, ist sie ein Use Case im Modul dieser Tabelle: `src/modules/<table>/use-cases/<verb>-<noun>.ts`. Wenn nur eine Route sie nutzt und sie keine Tabelle berührt, definiere sie mit `createServerFn` in dieser Routendatei. Andernfalls gehört sie nach `src/lib`.

## Wann lege ich ein neues Modul an?

Nur wenn du eine neue Datenbanktabelle hinzufügst. Ein Modul ohne Tabelle ist nicht erlaubt.

## Wohin gehört eine neue Komponente?

Eine Komponente, die in mehreren Bereichen genutzt wird, ist eine flache Datei in `src/presentation/components/custom`. Eine Komponente für einen einzelnen Bereich gehört in den Ordner dieses Bereichs, zum Beispiel `custom/admin/users/`. Ein Widget, Dialog oder Formular pro Datei.

## Wie sind die Sprachen organisiert?

en-US verwendet URLs ohne Präfix; die anderen acht Locales verwenden ihr vollständiges Tag als Präfix, zum Beispiel `/de-DE` oder `/pl-PL`. Jede Locale hat dieselben Namespace-Dateien in `messages/<locale>`, und jede Dokumentationsseite existiert als `<page>.<locale>.mdx`.

## Wie übergebe ich Text an eine Komponente?

Gar nicht. Die Komponente ruft `useTranslations` für ihren eigenen Namespace auf und liest den Text selbst.
