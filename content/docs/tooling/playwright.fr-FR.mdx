Playwright teste l'application construite dans de vrais navigateurs. La suite s'exécute sur l'environnement Wrangler `test` : D1, KV et R2 locaux dans `.wrangler/test`, identifiants factices issus de `.env.test` et point d'entrée de test `src/platform/testing/worker.ts`, qui intercepte les requêtes vers Resend et Polar.

```sh
bun run test:e2e:install
bun run test:e2e
bun run test:e2e:smoke
bun run test:e2e:pr
bun run test:e2e:headed
bun run test:e2e:ui
```

| Script             | Exécute                                                            |
| ------------------ | ------------------------------------------------------------------ |
| `test:e2e:install` | Installe Chromium et WebKit avec les dépendances système           |
| `test:e2e`         | Toutes les specs dans Chromium et WebKit                           |
| `test:e2e:smoke`   | `e2e/specs/smoke.spec.ts` dans Chromium                            |
| `test:e2e:pr`      | Toutes les specs dans Chromium, comme dans la CI des pull requests |
| `test:e2e:headed`  | Toutes les specs dans des navigateurs visibles                     |
| `test:e2e:ui`      | Mode UI de Playwright                                              |

## Configuration

`playwright.config.ts` définit les projets `chromium` (Desktop Chrome) et `webkit` (Desktop Safari) et utilise `PLAYWRIGHT_BASE_URL` ou `http://127.0.0.1:3000`. En local, la commande du serveur web exécute `db:reset:test`, `build:test` et `start:test`, et réutilise un serveur qui répond déjà à cette URL : arrêtez donc d'abord les autres serveurs sur `127.0.0.1:3000`. En CI, le workflow prépare le build et Playwright se contente de démarrer le serveur.

| Paramètre  | Local                                            | CI                                            |
| ---------- | ------------------------------------------------ | --------------------------------------------- |
| Relances   | <RepositoryFact name="playwrightLocalRetries" /> | <RepositoryFact name="playwrightCiRetries" /> |
| Workers    | <RepositoryFact name="playwrightLocalWorkers" /> | <RepositoryFact name="playwrightCiWorkers" /> |
| Traces     | Conservées en cas d'échec                        | À la première relance                         |
| Vidéos     | Désactivées                                      | Conservées en cas d'échec                     |
| Rapporteur | Liste et HTML                                    | GitHub et HTML                                |

## Organisation

- `e2e/specs/` : specs pour les vérifications de fumée, la page d'accueil, la navigation, les langues, l'authentification, les espaces de travail, la newsletter, le contenu, le thème, la tarification régionale, le tunnel de paiement, l'affiliation, les vidéos, les cours, l'administration des cours et l'accessibilité.
- `e2e/pages/` : objets de page.
- `e2e/fixtures/` : la fixture `test` étendue, des utilitaires pour les e-mails capturés, `deliverPaidOrder` dans `polar.ts`, qui envoie un webhook `order.paid` signé pour accorder une licence, et `accessibilityViolations` avec les `COLOR_SCHEMES` clair et sombre dans `accessibility.ts`.
- `e2e/data/accounts.ts` : les comptes administrateur et client créés par le seed, ainsi que leur mot de passe.
- `e2e/data/videos.ts` et `e2e/data/courses.ts` : la vidéo de test créée par le seed, dont les fichiers sont dans `e2e/fixtures/video/`, et le cours créé par le seed : un chapitre avec un aperçu gratuit, une leçon réservée aux comptes et deux leçons payantes, dont une sans vidéo.

Le Worker de test expose `/__test/emails` pour lire les e-mails capturés par le mock de Resend et `/__test/newsletter` pour lire l'état d'un abonné.

## Accessibilité

`e2e/specs/accessibility.spec.ts` exécute [axe-core](https://github.com/dequelabs/axe-core) via `@axe-core/playwright` sur les pages publiques, les pages de cours, l'accueil de la documentation, chaque page de Conventions et une page de chacune des autres sections de la documentation, un article du blog et les espaces de travail administrateur et client, dans les thèmes clair et sombre. Les pages d'administration comprennent `/admin/courses`, `/admin/courses/create` et l'éditeur du cours de test, que `e2e/specs/workspaces.spec.ts` visite aussi. Il applique les règles A et AA des WCAG 2.0, 2.1 et 2.2 ainsi que les bonnes pratiques d'axe, échoue si une page ne se charge pas avec un statut de succès, fait défiler la page pour que les sections qui apparaissent au défilement soient aussi vérifiées, attend la fin des animations finies et échoue à la moindre violation en indiquant la règle, son impact et les sélecteurs concernés.
