## 隔離されたテストプレビュー

テストプレビューは、アプリケーションを `test` 環境向けにビルドします。`.wrangler/test` 内のローカル D1、KV、R2、`.env.test` のダミー認証情報、シードされたアカウントを使い、Resend と Polar へのリクエストは横取りされます。アカウントは必要ありません。

```sh
bun run db:reset:test
bun run build:test
bun run start:test
```

<RepositoryFact name="localServerOrigin" /> を開き、`e2e/data/accounts.ts`
がシードするアカウントのいずれかでサインインします。どのアカウントもパスワード <RepositoryFact name="testPassword" /> を使います。管理者は
`/admin` に、顧客は `/app` に移動します。ライセンス付きのアカウントとそれぞれのライセンスは `e2e/data/licenses.ts` にあります。Complete
のライセンスでは、サンプルコースのすべての有料レッスンを開けます。

<RepositoryTable columns={["メールアドレス", "ロール", "ライセンス"]} name="seededAccounts" />

プレビューはビルド済みの成果物を配信するため、ソースの変更を反映するには再ビルドしてください。

## Cloudflare を使った開発

`bun run dev` は、ホットリロード付きの開発サーバーを http://localhost:3000 で起動します。`DB`、`CACHE`、`MEDIA`、`BUNDLES` のバインディングは `.wrangler/state` 内のローカルのものです。そのため、開発中にプレビューや本番のデータを読み書きすることはなく、Cloudflare へのログインも必要ありません。

```sh
cp .env.example .env.development
bun run db:reset:local
bun run db:seed:local
bun run dev
```

1. [環境変数](/docs/getting-started/environment-variables)の説明に従って `.env.development` に値を記入し、`POLAR_SERVER=sandbox` を設定します。
2. `db:reset:local` でローカルのデータベースを作成し、マイグレーションを適用します。
3. `db:seed:local` でシードを投入します。管理者、コースのカリキュラム、ライセンス、注文が入ります。
4. サーバーを起動し、<RepositoryFact name="localAdminEmail" /> と、`.env.development` の `LOCAL_ADMIN_PASSWORD`（設定されていない場合は <RepositoryFact name="localAdminPassword" />）でサインインします。

`bun run db:studio:local` は、ローカルのデータを Drizzle Studio で開きます。メールによるサインアップには動作する Resend の設定が必要です。新しいアカウントはすぐにサインイン済みになりますが、ライセンスキーと有料レッスンは確認リンクを開くまで使えず、再度サインインするには確認済みのアドレスが必要です。[データベース](/docs/tooling/database)では、3 つのデータベース、シード、プレビューと本番で最初の管理者を作成する方法を説明しています。
