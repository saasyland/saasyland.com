## Requisição de página

1. **Canonicalização do locale.** `src/server.ts` chama `resolveLocale` para as requisições de documento `GET` e `HEAD` fora de `/api` e `/_serverFn`. Um prefixo só de idioma ou do locale padrão (`/pl/docs`, `/en-US/docs`) é redirecionado com `308` para a forma canônica (`/pl-PL/docs`, `/docs`). Quando o locale da URL difere do cookie de locale, o cookie é atualizado na resposta.
2. **Assets estáticos primeiro.** O Worker pede o caminho ao binding `ASSETS`. Arquivos estáticos são retornados sem alteração, e uma página pré-renderizada é transmitida por meio de `withNonce`, que coloca nos scripts dela um nonce criado para esta resposta. Só quando recebe um `404` ele carrega o handler do TanStack Start com um `import()` dinâmico.
3. **Roteamento.** `getRouter` cria um novo router e um novo `QueryClient`. O `rewrite` do router remove o prefixo de locale, então `/pl-PL/docs` corresponde às rotas de `/docs`.
4. **O `beforeLoad` da raiz** pré-carrega os namespaces de tradução raiz (`common`, `components.*`, `errors*`).
5. **Guards.** Funções `beforeLoad` de layouts, como `requireAdmin`, carregam a query de sessão e redirecionam quando o acesso não é permitido.
6. **Loaders** rodam em paralelo. Cada um pré-carrega seus namespaces, os metadados da página e as queries no `QueryClient` da requisição.
7. **Renderização.** O shell raiz renderiza `<html lang dir>` e envolve o body no `TranslationsProvider`. O cache de queries é serializado no HTML para que o navegador não busque os mesmos dados de novo.
8. **Headers da resposta.** Em respostas HTML, o Worker adiciona um header `Link` de preload para as fontes do locale, define o cookie de locale quando necessário, aplica os atributos de preços regionais quando o header `cf-ipcountry` dá direito a um desconto e define `data-session` no `<html>` quando a requisição traz o cookie de sessão. Em seguida, toda resposta que o Worker retorna recebe os headers de segurança (`SECURITY_HEADERS`, mais `HTTPS_SECURITY_HEADERS` sobre HTTPS, de `src/modules/_core/constants/api.ts`), que substituem qualquer valor já definido. Uma resposta HTML recebe, em vez disso, `documentPolicy` como Content Security Policy, com o nonce que `src/server.ts` criou para ela, e é `private, no-cache`, com `Vary: Cookie` e sem `ETag` nem `Last-Modified`, de modo que um navegador nunca a reutiliza com o nonce de outra resposta.
9. **Hidratação.** O navegador faz a hidratação com o cache serializado. As navegações seguintes executam os guards e os loaders no navegador e buscam os dados por meio de server functions.

## Chamada de server function

1. O navegador chama a server function, que o build substituiu por uma requisição RPC para `/_serverFn/…`. O Worker pula o tratamento de locale nesse caminho. A URL não tem prefixo de locale, então `getCurrentLocale()` retorna `en-US` no servidor; uma server function que precisa do locale o recebe como entrada.
2. O middleware roda na ordem declarada. `withRequest` captura os headers da requisição e normaliza os erros, `withRateLimit` contabiliza a tentativa no D1 e `authorized` carrega a sessão e verifica a permissão.
3. O validator analisa a entrada com o schema Zod do módulo.
4. O handler consulta o D1 ou chama um provedor e retorna dados simples.
5. O componente recebe os dados ou um código de `AppError`. Em caso de sucesso, ele invalida as chaves de query do módulo; em caso de falha, exibe `useErrorMessage()(error)`.

```text
GET /pl-PL/admin/users/all
  src/server.ts        resolveLocale, ASSETS lookup, TanStack Start handler
  router rewrite       /admin/users/all
  __root beforeLoad    root namespaces
  /admin beforeLoad    requireAdmin
  loaders              metadata, namespaces, queries
  SSR                  HTML with serialized query cache
  src/server.ts        Link header, locale cookie, regional pricing, security headers

POST /_serverFn/…
  withRequest → withRateLimit → authorized → validator → handler → data or AppError
```

## Requisição de mídia

`src/server.ts` verifica o caminho antes de qualquer outra coisa: um caminho que o handler de requisições de uma funcionalidade reivindica vai para esse handler e pula o tratamento de locale, a consulta a `ASSETS` e o TanStack Start. A funcionalidade de cursos reivindica `/media/`, e o handler dela carrega, cada um com um `import()` dinâmico, `serveCover` (`src/modules/course/course.delivery.ts`) para `/media/covers/`, `serveAttachment` para `/media/downloads/` e `serveMedia` (`src/modules/video/video.delivery.ts`) para qualquer outro caminho. As capas não têm assinatura, e `serveCover` responde a partir do cache do Workers ou do R2; `serveAttachment` verifica a assinatura de um download e o lê do R2. `serveMedia` verifica a assinatura e a expiração no caminho e depois responde a partir do cache do Workers ou do R2, incluindo requisições `Range`. A funcionalidade de cursos também reivindica `/sitemap-courses.xml`, cujo handler carrega `serveCourseSitemap` do mesmo arquivo e grava o sitemap dos cursos a partir do D1 (veja [Sitemap dos cursos](/docs/features/seo#course-sitemap)). A funcionalidade de licenças reivindica `/bundles/` da mesma forma, e o handler dela carrega `serveBundle` (`src/modules/license/license.delivery.ts`), que verifica a assinatura e a expiração e transmite o pacote de templates da CLI a partir do R2. A resposta recebe os mesmos cabeçalhos de segurança que todas as outras. Veja [Cloudflare R2](/docs/integrations/cloudflare-r2).
