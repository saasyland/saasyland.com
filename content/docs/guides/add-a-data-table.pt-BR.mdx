Toda tabela nova é renderizada pelo `DataGrid` em `src/presentation/components/custom/data-grid.tsx` ([Grade de dados](/docs/ui/data-grid)). Ele traz a busca, os filtros, a ordenação, o layout que cada administrador pode reorganizar e manter, a seleção, a exportação em CSV, as linhas de esqueleto e os estados vazios. Uma tabela precisa de um hook de colunas e de um `<DataGrid />`. `/admin/orders` é o exemplo completo: `src/presentation/components/custom/admin/payments/order-columns.tsx` e `src/routes/admin.orders.index.tsx`.

## 1. Escreva o hook de colunas

Crie `<entity>-columns.tsx` ao lado dos outros widgets da página. Exporte um hook que lê as traduções e os dados que os filtros oferecem e retorna as colunas memoizadas. As células são pequenos componentes no mesmo arquivo, que leem as suas próprias traduções. Versão resumida de `order-columns.tsx`:

```tsx
const columnHelper = createColumnHelper<DataGridFeatures, OrderRow>()

export const useOrderColumns = (): DataGridColumn<OrderRow>[] => {
  const t = useTranslations()

  const { products } = useSuspenseQuery(orderFiltersQuery).data

  return useMemo(
    () =>
      columnHelper.columns([
        columnHelper.accessor("placedAt", {
          cell: PlacedCell,
          header: t("pages.admin.orders.table.headers.placedAt"),
          meta: { filter: { kind: DATA_GRID_FILTER.DATE_RANGE }, pinned: DATA_GRID_PIN.START },
          size: ORDER_COLUMN_SIZES.placedAt,
        }),
        columnHelper.accessor("description", {
          cell: ProductCell,
          enableSorting: false,
          header: t("pages.admin.orders.table.headers.product"),
          id: "product",
          meta: { filter: { kind: DATA_GRID_FILTER.MULTI_SELECT, options: products.map(({ id, name }) => ({ label: name, value: id })) } },
          size: ORDER_COLUMN_SIZES.product,
        }),
        columnHelper.accessor("refunded", {
          cell: RefundedCell,
          header: t("pages.admin.orders.table.headers.refundedAmount"),
          id: "refundedAmount",
          meta: { export: ({ refunded }) => exportedMoney(refunded), hidden: true },
          size: ORDER_COLUMN_SIZES.refundedAmount,
        }),
      ]),
    [products, t],
  )
}
```

- As linhas precisam de um `id` do tipo string, que vira o identificador da linha na seleção.
- `header` é o rótulo traduzido como string. A grade o usa no cabeçalho, nos menus, nos chips de filtro, nos seus anúncios e no CSV.
- `meta.filter` dá à coluna um filtro de um tipo: <RepositoryFact name="dataGridFilterKinds" />. Uma escolha lista as suas `options` como `{ label, value }`.
- `meta.hidden` oculta a coluna até o administrador mostrá-la, `meta.pinned` a fixa no `start` ou no `end`, e `meta.export` escreve o texto da coluna no CSV para uma linha.
- `size` é a largura inicial em pixels. Mantenha os tamanhos em uma constante em `src/data/<feature>.ts`, como `ORDER_COLUMN_SIZES` em `payments.ts`, para que o esqueleto da rota também possa usá-los.
- Uma coluna pela qual o servidor não consegue ordenar define `enableSorting: false`.

## 2. Renderize

Passe as colunas, um `id` único, o `label` da tabela e `data` ou `query`:

```tsx
const OrdersPage = (): JSX.Element => {
  const t = useTranslations("pages.admin.orders")
  const columns = useOrderColumns()

  return (
    <DataGrid
      columns={columns}
      empty={t("empty")}
      id={ORDER_GRID_ID}
      label={t("title")}
      query={(request) => getOrdersPageQuery(orderZodSchemas.getOrders.parse(request))}
      search={t("filters.search")}
      selectable
    />
  )
}
```

Com `data`, a grade busca, filtra, ordena e pagina as linhas no navegador. Com `query`, ela envia `{ filters, pageIndex, pageSize, search, sorting }` e o servidor faz tudo isso.

## 3. Leia a requisição no servidor

O schema Zod do módulo recebe a requisição como ela chega. `filters` guarda as colunas filtradas por id com os valores descritos em [Grade de dados](/docs/ui/data-grid#filters), então o schema reutiliza os campos compartilhados, de `src/modules/order/order.zod.ts`:

```ts
const orderFilters = zod.object({
  country: zod.array(countryCodeField).max(COUNTRY_CODES.length).optional(),
  customer: searchField.optional(),
  discount: idField.optional(),
  placedAt: dateRangeField.optional(),
  product: zod.array(idField).max(MAX_FILTER_VALUES).optional(),
  status: zod.array(choiceOf(ORDER_STATUSES)).max(ORDER_STATUSES.length).optional(),
  totalAmount: numberRangeField.optional(),
})

const getOrders = paginationSchema.extend({
  filters: orderFilters.default({}),
  search: searchField.default(""),
  sorting: sortingOf(ORDER_SORT_COLUMNS),
})
```

`numberRangeField`, `dateRangeField` e os limites `SEARCH_MAX_LENGTH`, `MAX_SORTED_COLUMNS` e `MAX_FILTER_VALUES` vêm de `src/modules/_core/utils/`, os mesmos valores que a grade usa, de modo que a caixa de busca aceita <RepositoryFact name="dataGridSearchMaxLength" /> caracteres e a grade ordena por até <RepositoryFact name="dataGridMaxSortedColumns" /> colunas. `getOrders` transforma cada filtro em SQL; um intervalo de valores em dinheiro compara cada pedido na sua própria moeda com `inMinorUnits`.

Pré-carregue a primeira página no loader da rota com `context.queryClient.query({ ...getOrdersQuery, staleTime: "static" })`; a primeira requisição da grade gera a mesma chave de query.

## 4. Espelhe no esqueleto

O `pendingComponent` da rota renderiza `DataGridPending` de `data-grid-pending.tsx` com um esqueleto de célula e uma largura por coluna visível, como `AdminOrdersPending` faz em `payments-pending.tsx`.

## 5. Mensagens

A barra de ferramentas, os filtros, os menus, a paginação, a seleção e os estados vazios da grade vêm de `components.custom.data-grid`, que toda página carrega. Os rótulos das colunas, as opções dos filtros e a mensagem de vazio pertencem ao namespace da página, como `pages.admin.orders`.

Quando uma mutation altera as linhas, invalide as chaves de query do módulo; a grade busca a página atual novamente. Veja [Adicionar um caso de uso](/docs/guides/add-a-use-case).
