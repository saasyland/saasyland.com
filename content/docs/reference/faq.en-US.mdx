## Which runtime does the application use?

Cloudflare Workers. Bun installs packages and runs scripts; Vite+ (`vp`) builds, formats, lints and tests the application.

## Do local tests need a Cloudflare account?

No. Vitest uses an in-memory SQLite database and in-memory KV. Playwright uses the `test` Wrangler environment with local D1 and KV in `.wrangler/test` and dummy secrets from `.env.test`. `bun run dev` does need Cloudflare access, because the `development` environment uses remote preview bindings.

## Where does a new operation go?

If it works on a database table, it is a use case in that table's module: `src/modules/<table>/use-cases/<verb>-<noun>.ts`. If only one route uses it and it touches no table, define it with `createServerFn` in that route file. Otherwise, put it in `src/lib`.

## When do I create a new module?

Only when you add a new database table. A module without a table is not allowed.

## Where does a new component go?

A component shared across areas is a flat file in `src/presentation/components/custom`. A component for one area goes in that area's folder, for example `custom/admin/users/`. One widget, dialog or form per file.

## How are languages organized?

en-US uses unprefixed URLs; the other eight locales use their full tag as a prefix, for example `/de-DE` or `/pl-PL`. Every locale has the same namespace files in `messages/<locale>`, and every documentation page exists as `<page>.<locale>.mdx`.

## How do I pass text to a component?

You don't. The component calls `useTranslations` for its own namespace and reads the text itself.
