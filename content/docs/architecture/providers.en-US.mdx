title: "Providers"
description: "The four application providers in src/providers, where each one is mounted and why."
---

`src/providers` contains four providers. Each is mounted as close to its consumers as possible.

| Provider               | Wraps                                                                                                               | Mounted in                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `TranslationsProvider` | use-intl `IntlProvider` with the root and matched route namespaces, the named date formats and the user's time zone | The root shell, around the document body                                    |
| `AriaProvider`         | React Aria `I18nProvider` and `RouterProvider`                                                                      | The root component, around every route                                      |
| `ThemeProvider`        | The `@wrksz/themes` provider, stored in a cookie                                                                    | Around the `Toaster` in the root and the theme switch in the docs sidebar   |
| `MotionProvider`       | Motion `LazyMotion` (strict) and `MotionConfig` with `reducedMotion="user"`                                         | The landing page, the blog index, the blog archive pages and `LicenseOffer` |

## Root composition

`src/routes/__root.tsx` renders the document in `shellComponent` and the application in `component`:

```tsx
const RootComponent = () => (
  <AriaProvider>
    <OfflineBanner />
    <AffiliateReferral />
    <Outlet />
    <ThemeProvider>
      <Toaster />
    </ThemeProvider>
  </AriaProvider>
)
```

- **TranslationsProvider** sits in the shell's `<body>`, so every screen is translated, including the default error and not-found components and the route skeletons. It reads the namespaces from the root namespaces plus each matched route's `staticData.namespaces`, loads them with `useSuspenseQueries` and builds one message tree. It also passes `I18N.FORMATS` and the time zone of the first hook in its `TIME_ZONE_HOOKS`, `UTC` without one. That hook is `useSessionTimeZone`, which reads the session that the route guards loaded, `UTC` without one, and never fetches it; see [Internationalization and locales](/docs/features/internationalization).
- **AriaProvider** passes the current locale to React Aria and connects React Aria links to TanStack Router. Its `useHref` localizes paths, so an `href` on a React Aria component gets the locale prefix.
- **ThemeProvider** does not wrap the route outlet. A provider that updates after hydration would re-render every page, so it wraps only the components that need it. The initial theme is applied before hydration by `ThemeScript` in the document head.
- **MotionProvider** loads the `domMax` feature bundle on demand and is mounted only where animations run: `_site._marketing.index.tsx`, `_site._marketing.blog.index.tsx`, `_site._marketing.blog.page.$page.tsx` and `license-offer.tsx`, the tier cards on `/app` and `/app/license`. A Bun patch to `framer-motion` 14.14.0 makes `LazyMotion` ignore a bundle that fails to load, as when Safari cancels it because the visitor is leaving, so the components render without animation instead of the page reporting an unhandled rejection.
- **AffiliateReferral** is not a provider. It sits beside the outlet and renders Affonso's script only while the affiliate programme is open (`AFFILIATE_PROGRAM`) and the visit carries a referral parameter ([Affiliate programme](/docs/features/affiliates)).

## Not a provider component

- **QueryClient.** `src/router.tsx` creates it per request, puts it in the router context and connects it with `setupRouterSsrQueryIntegration`.
- **Fumadocs.** The `/docs` layout mounts Fumadocs' `RootProvider` with its own theme handling disabled.
- **Presses after a drag.** After any drag and drop, Safari reports the next press of the mouse button as a `pointermove` instead of a `pointerdown` ([WebKit bug 202287](https://bugs.webkit.org/show_bug.cgi?id=202287)), so React Aria, which starts a press on `pointerdown`, ignored the first click after a drag. The root component runs `restoreLostPointerDowns` from `src/lib/lost-pointer-down.ts` in an effect: for a `pointermove` that reports a press of the primary mouse button with no other button held, which no browser sends otherwise, it dispatches the missing `pointerdown` at the same place.
