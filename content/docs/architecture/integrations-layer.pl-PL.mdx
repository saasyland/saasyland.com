Każda zewnętrzna biblioteka lub usługa wymagająca konfiguracji ma jeden własny folder w `src/integrations`. Pliki mają nazwy w formacie `<prefix>.<concern>.ts`, gdzie prefiks to krótka nazwa dostawcy.

| Folder           | Pliki                                                                                                                                                                                      | Odpowiedzialność                                                                                                                     |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| `affonso`        | `affonso.constants`, `affonso.program`, `affonso.referral`                                                                                                                                 | Parametry polecenia, URL piksela, ID programu i polecenie przekazywane do Polar jako metadane sesji płatności                        |
| `better-auth`    | `auth.server`, `auth.client`, `auth.access`, `auth.roles`, `auth.middleware`, `auth.routes`, `auth.session`, `auth.errors`, `auth.hooks`, `auth.zod`, `auth.constraints`, `auth.constants` | Konfiguracja uwierzytelniania, role, middleware funkcji serwerowych, guardy tras, zapytanie o sesję, identyfikatory dostawców        |
| `drizzle-orm`    | `drizzle.config`, `drizzle.database`, `drizzle.schemas`, `drizzle.errors`, `drizzle.columns`, `migrations/`                                                                                | Klient D1, rejestr schematów, migracje SQL, `rethrowAsConflict` dla błędów ograniczenia unikalności i wspólne kolumny `timestamps()` |
| `fumadocs`       | `fumadocs.config`, `fumadocs.schema`, `fumadocs.indexes`, `fumadocs.docs`, `fumadocs.blog`, `fumadocs.i18n`                                                                                | Kolekcje MDX dla dokumentacji i bloga, generowane podczas budowania indeksy dokumentacji, bloga i wyszukiwania oraz ładowanie stron  |
| `motion`         | `motion.features`, `motion.tokens`                                                                                                                                                         | Leniwie ładowany pakiet funkcji Motion i współdzielone przejścia                                                                     |
| `polar`          | `polar.config`, `polar.constants`, `polar.customers`                                                                                                                                       | Klient Polar SDK, własne wartości Polar sprawdzane względem SDK i konto klienta Polar                                                |
| `resend`         | `resend.config`, `resend.utils`, `resend.constants`                                                                                                                                        | Klient Resend, `sendEmail` i nazwy z `EMAIL_PURPOSE`                                                                                 |
| `tanstack-form`  | `form.fields`                                                                                                                                                                              | Typy pól i `fieldErrorMessage` dla TanStack Form                                                                                     |

## Co nie jest integracją

- Liczba gwiazdek na GitHubie to funkcja serwerowa w `src/lib/github.ts`, przechowywana w cache KV.
- Limitowanie żądań realizuje `src/lib/rate-limit.ts`, oparte na tabeli `rate_limit`.
- Bindingi Cloudflare nie potrzebują adaptera. Kod serwerowy odczytuje je z `env` w `cloudflare:workers`.

## Logika biznesowa pozostaje w modułach

Integracja konfiguruje dostawcę. Decyzje dotyczące danych aplikacji należą do modułu, który jest właścicielem tabeli:

- Plugin Polar, który obszar Polar dodaje do Better Auth w `src/data/polar.auth-plugins.ts`, weryfikuje podpisy webhooków za pomocą `POLAR_WEBHOOK_SECRET` i przekazuje każde zdarzenie do `handlePolarEvent` w `src/data/polar-events.ts`. Ta funkcja przekazuje je każdemu obszarowi, który wymienia to zdarzenie w swoim `<area>.polar-events.ts`; `src/data/license.polar-events.ts` obszaru licencji wywołuje `licenseWebhookHandlers` w `src/modules/license/license.webhooks.ts`, które wywołują przypadki użycia licencji. Identyfikatory produktów planów licencji, `POLAR_PRODUCT_IDS`, również należą do obszaru licencji i znajdują się w `src/modules/license/license.utils.ts`.
- Hooki e-mailowe Better Auth wywołują `sendVerifyEmail`, `sendResetPasswordEmail` i `sendChangeEmailConfirmationEmail` z modułów weryfikacji i kont, które Resend dodaje w `src/data/resend.auth-emails.ts`.
- Przypadek użycia wysyła e-mail w locale przekazanym przez wywołującego (e-mail weryfikacyjny odczytuje locale z adresu zwrotnego): ładuje przestrzeń nazw szablonu, renderuje szablon i wywołuje `sendEmail`:

```ts
const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotency: { purpose: EMAIL_PURPOSE.VERIFY_EMAIL, token: crypto.randomUUID() },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```
