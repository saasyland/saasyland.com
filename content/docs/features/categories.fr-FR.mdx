## Données

`src/modules/category/category.schema.ts` définit la table `category` : `name`, `description`, `kind` (`category` ou `collection`), `visibility` (`public` ou `hidden`), `icon` (`Archive`, `FolderOpen` ou `Puzzle`) et les horodatages.

Cas d’usage dans `src/modules/category/use-cases`, chacun protégé par la permission `category` correspondante : `getCategories` (paginé, `kind` facultatif), `getCategory`, `createCategory`, `updateCategory` et `deleteCategory`. Aucune route, aucun composant ni aucun autre cas d’usage ne les appelle : seuls `drizzle.schemas.ts`, qui donne à Drizzle toutes les tables, et un fixture de test importent le module. Ce n’est pas un modèle à copier ; pour copier un cas d’usage, prenez-en un d’un module qu’un écran utilise, comme `src/modules/course`.

Un identifiant qui ne correspond à aucune catégorie répond `NOT_FOUND`, que `useErrorMessage` affiche avec son message de `errors.codes`, si bien que le module n’a pas d’espace de noms de messages à lui. Aucun formulaire ne modifie encore les catégories, leurs messages Zod recevront donc un espace de noms `category.validations` avec le premier formulaire qui les affiche.

## Écran d’administration

Aucun écran ne liste, ne crée, ne modifie ni ne supprime de catégorie, et les produits n’ont pas de relation avec les catégories. `/admin/products` liste le catalogue de Polar (voir [Produits](/docs/features/products)).
