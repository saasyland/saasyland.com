## Werkzeuge

| Werkzeug | Version                                          | Wozu                                                                                               |
| -------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| Bun      | <RepositoryFact name="bunVersion" />             | Paketmanager und Skript-Runner; `packageManager` in `package.json` und die CI fixieren die Version |
| Node.js  | <RepositoryFact name="nodeVersion" /> oder neuer | Die Version aus `.nvmrc`, die `nvm use` und die CI lesen. Die Testdatenbank nutzt `node:sqlite`    |
| Git      | Jede aktuelle Version                            | Der Installationsschritt richtet Git-Hooks ein                                                     |

Wrangler, drizzle-kit, Playwright und die Vite+ CLI sind Dev-Abhängigkeiten; führe sie über die Paketskripte oder `bunx` aus. Browsertests benötigen außerdem die Playwright-Browser aus `bun run test:e2e:install`.

## Konten

Die isolierte Test-Preview und alle automatisierten Tests benötigen weder Konten noch Zugangsdaten. Entwicklung und Deployment verwenden echte Dienste:

- Ein Cloudflare-Konto mit D1, KV, R2 und Workers für die Preview- und die Produktionsumgebung. Der Dev-Server läuft auf lokalen Ressourcen und braucht kein Konto.
- OAuth-Apps bei GitHub und Google für die Anmeldung über soziale Konten.
- Resend mit einem verifizierten Absender. Ein neues E-Mail-Konto ist sofort angemeldet, aber ohne Resend kommt kein Bestätigungslink an, sodass der Lizenzschlüssel, das Kundenportal, kostenpflichtige Lektionen und eine erneute Anmeldung gesperrt bleiben.
- Polar, für die Entwicklung mit der Sandbox, mit drei Produkten für die Pakete Core, Complete und Agency.
