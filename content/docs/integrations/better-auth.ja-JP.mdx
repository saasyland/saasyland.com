Better Auth は、ユーザー、アカウント、セッション、検証トークンを Drizzle アダプター経由で D1 に保存します。メールアドレスとパスワードによるサインアップ（メール認証必須）、GitHub と Google によるサインイン、パスワードリセット、メールアドレスの変更、TOTP による二要素認証、管理者によるユーザー管理、Polar のチェックアウトを提供します。HTTP API は `src/routes/api/auth.$.ts` から提供されます。

## ファイル

| ファイル                                               | 役割                                                                                                                                                                       |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auth.server.ts`                                       | `betterAuth` インスタンス。プロバイダー、`admin`・`twoFactor`・Polar・`tanstackStartCookies` の各プラグイン、許可するホスト、D1 によるレート制限、メールフックを設定します |
| `auth.client.ts`                                       | `authClient` とそのメソッド（`signIn`、`signUp`、`signOut`、`useSession`、`twoFactor` など）                                                                               |
| `auth.routes.ts`                                       | `beforeLoad` 用のルートガード                                                                                                                                              |
| `auth.middleware.ts`                                   | サーバー関数のミドルウェア: `withRequest`、`authorized`、`withRateLimit`、`RATE_LIMITS`                                                                                    |
| `auth.access.ts`                                       | ロール、権限ステートメント、`hasPermission`                                                                                                                                |
| `auth.session.ts`                                      | `getRequestSession`、`getCurrentSession` サーバー関数、`getCurrentSessionQuery`                                                                                            |
| `auth.errors.ts`, `auth.zod.ts`, `auth.constraints.ts` | エラーキー、フォームのスキーマ、パスワードの制限                                                                                                                           |

## ルートガード

| ガード               | 使用箇所                         | 動作                                                                                  |
| -------------------- | -------------------------------- | ------------------------------------------------------------------------------------- |
| `requireSignedIn`    | `/app`                           | セッションがなければサインインへリダイレクトし、セッションを返します                  |
| `requireAdmin`       | `/admin`                         | さらに `admin: ["access"]` 権限を要求し、持っていなければ `/app` へリダイレクトします |
| `redirectIfSignedIn` | `/auth/sign-in`, `/auth/sign-up` | サインイン済みのユーザーを、ロールに応じて `/admin` または `/app` へ送ります          |
| `redirectAfterAuth`  | `/auth/callback`                 | セッションを要求し、ロールに対応するワークスペースへリダイレクトします                |

ガードはクエリキャッシュを通じてセッションを読み込み、サインイン中のユーザーが変わるとキャッシュをクリアします。

## サーバー関数

ページのガードが保護するのはナビゲーションだけです。そのため、保護されたサーバー関数はすべて `auth.middleware.ts` のミドルウェアで呼び出し元を改めてチェックします。

- `authorized(permission?)` はセッションを要求し、必要に応じて権限をチェックし、セッションを `context.auth` としてコンテキストに追加します。呼び出し元自身のデータに対する操作では、入力に含まれるユーザー ID ではなく、必ず `context.auth.user.id` を使います。
- `withRateLimit(kind, RATE_LIMITS.SENSITIVE)`（60 秒あたり 3 リクエスト）または `RATE_LIMITS.TOKEN`（60 秒あたり 5 リクエスト）は、`cf-connecting-ip` から取得したクライアント IP ごとに公開操作を制限します。
- 上記の両方に含まれる `withRequest` は、エラーを `AppError` のコードに変換します。Better Auth のエラーはエラーキー付きの `AUTH_API_ERROR` に、Zod のエラーは `VALIDATION` になり、予期しないエラーはログに記録されたうえで `INTERNAL_ERROR` として返されます。

## ロールと権限

`auth.access.ts` は 2 つのロールを定義します。`admin` と `customer`（新規アカウントのデフォルト）です。アプリケーションのステートメントは `admin`、`category`、`order`、`product`、`settings` を対象とし、admin ロールには Better Auth の管理者用ステートメントも付与されます。`hasPermission({ permission, role })` はガード、ミドルウェア、UI で共有されます。

## メールとレート制限

`auth.server.ts` のメールフックは、`sendVerifyEmail`、`sendResetPasswordEmail`、`sendChangeEmailConfirmationEmail` の各ユースケースを呼び出します。Better Auth 自身のレートリミッターは、`src/lib/rate-limit.ts` の `authRateLimitStorage` を通じて D1 の `rate_limit` テーブルにカウンターを保存します。このストレージはアトミックなアップサートを使い、ストレージが利用できない場合はリクエストを拒否します。`getRequestSession` は Cookie キャッシュを経由しないため、認可では常に D1 からセッションを読み込みます。
