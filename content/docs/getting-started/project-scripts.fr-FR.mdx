| Tâche                                                                     | Commande                 |
| ------------------------------------------------------------------------- | ------------------------ |
| Démarrer le serveur de développement                                      | `bun run dev`            |
| Vérifier le formatage, le lint, les types et les traductions              | `bun run check`          |
| Exécuter tous les projets Vitest                                          | `bun run test`           |
| Exécuter le contrôle de couverture                                        | `bun run test:coverage`  |
| Exécuter le test de fumée dans le navigateur                              | `bun run test:e2e:smoke` |
| Exécuter toutes les specs navigateur dans Chromium                        | `bun run test:e2e:pr`    |
| Exécuter toutes les specs navigateur dans Chromium et WebKit, comme la CI | `bun run test:e2e`       |
| Générer une migration                                                     | `bun run db:generate`    |
| Construire le Worker de préversion                                        | `bun run build`          |
| Servir le dernier build                                                   | `bun run start`          |
| Déployer la préversion                                                    | `bun run deploy:preview` |

Avant d'ouvrir une pull request, exécutez la séquence de [Contribuer](/docs/project/contributing), avec les specs qui couvrent votre modification :

```sh
bun run check
bun run test:coverage
bun run build:test
bunx playwright test e2e/specs/<spec>.spec.ts --project=chromium
```

En local, Playwright recrée la base de données de test avec `db:reset:test`, construit le Worker de test et le démarre à l'adresse qu'indique `PLAYWRIGHT_BASE_URL` (`127.0.0.1:3000` si elle n'est pas définie), sauf si un serveur y répond déjà. Chaque worktree prend son propre port dans la plage à laquelle le build de test fait confiance, et l'exécution s'arrête quand le serveur de son port appartient à un autre worktree : voir [Lancer la suite à côté d'autres worktrees](/docs/tooling/playwright#running-beside-other-worktrees).

Utilisez `bun run test`, et non `bun test`, pour que Vitest s'exécute avec la configuration du projet. Les scripts qui se terminent par un nom d'environnement, comme `db:migrate:preview` ou `deploy:production`, n'agissent que sur cet environnement.

Voir [Scripts du projet](/docs/tooling/scripts) pour la liste complète.
