## Projetos do Vitest

`vp test` executa o Vitest pelo Vite+ com três projetos definidos em `vite.config.ts`. Os testes ficam em uma pasta `__test__` ao lado do código que cobrem e importam as APIs de teste de `vite-plus/test`.

| Projeto       | Ambiente | Padrão de arquivo       |
| ------------- | -------- | ----------------------- |
| `node`        | Node     | `*.test.ts`             |
| `integration` | Node     | `*.integration.test.ts` |
| `component`   | jsdom    | `*.component.test.tsx`  |

Nenhum teste acessa uma conta real do Cloudflare ou um provedor real:

- O D1 é um banco SQLite em memória que executa as migrações versionadas no repositório, e o KV é um mapa em memória. O KV e os contadores de rate limit são reiniciados antes de cada teste.
- `createServerFn` é substituído para que uma server function rode no próprio processo, passando pelo middleware e pelo validator reais.
- Os testes de componente renderizam com um `QueryClient` e um router reais.
- As requisições de e-mail, OAuth e pagamento são mockadas.

## Cobertura

`bun run test:coverage` exige 100% de linhas, instruções, funções e branches em todo o `src`. Ficam de fora os primitivos do shadcn, `src/platform/testing`, os arquivos gerados e as declarações de tipos. Cubra o comportamento real e apague branches que nunca podem ser executados, em vez de fazer stub de globais para alcançá-los.

## Testes de navegador

As specs do Playwright ficam em `e2e/specs`, com os page objects em `e2e/pages` e as fixtures em `e2e/fixtures`. Elas rodam contra um build semelhante ao de produção que usa o ambiente Wrangler `test`: D1 e KV locais em `.wrangler/test`, secrets fictícios de `.env.test` e um Worker de teste que captura os e-mails enviados, para que uma spec possa seguir um link de verificação real. Localmente, o próprio Playwright aplica as migrações, popula o banco, faz o build e inicia o app. A suíte roda no Chromium e no WebKit.


## CI

`.github/workflows/ci.yml` roda em pull requests e em pushes para `main`:

1. `bun run check`: formatação, lint, verificação de tipos e `check:i18n`
2. `bun run test:coverage`
3. Um build de teste e a suíte do Playwright no Chromium
4. Um deploy de preview para pull requests ou um deploy de produção para `main`
