---
title: "Matriz de permissões"
description: "Papéis, declarações de permissão e as server functions que as verificam."
---

Papéis e permissões são definidos em `src/integrations/better-auth/auth.access.ts` com o controle de acesso do Better Auth. As mesmas definições são usadas pelo servidor (`authorized`, guards de rota) e pelo cliente do Better Auth.

## Papéis

| Papel   | Código     | Permissões                                                                                                             |
| ------- | ---------- | ---------------------------------------------------------------------------------------------------------------------- |
| Admin   | `admin`    | Todas as declarações da aplicação listadas abaixo, mais as declarações de admin do Better Auth para `user` e `session` |
| Cliente | `customer` | Nenhuma. Clientes podem chamar server functions que exigem apenas uma sessão.                                          |

Novos usuários recebem `customer` (`DEFAULT_ROLE_CODE`).

## Declarações

Declarações da aplicação (`APP_STATEMENTS`):

| Recurso    | Ações                                           |
| ---------- | ----------------------------------------------- |
| `admin`    | `access`                                        |
| `category` | `create`, `read`, `update`, `delete`            |
| `order`    | `read`, `update`, `refund`                      |
| `product`  | `create`, `read`, `update`, `delete`, `publish` |
| `settings` | `manage`                                        |

Declarações do Better Auth concedidas aos admins:

| Recurso   | Ações                                                                                                      |
| --------- | ---------------------------------------------------------------------------------------------------------- |
| `user`    | `create`, `list`, `set-role`, `ban`, `impersonate`, `delete`, `set-password`, `set-email`, `get`, `update` |
| `session` | `list`, `revoke`, `delete`                                                                                 |

## Onde as permissões são verificadas

| Permissão                 | Verificada por                                                                                                                    |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `admin: ["access"]`       | `requireAdmin` no layout de `/admin` e o redirecionamento após o login                                                            |
| Ações de `category`       | Os casos de uso de categoria: `read`, `create`, `update`, `delete`                                                                |
| Ações de `product`        | Os casos de uso de produto: `read`, `create`, `update`, `delete`                                                                  |
| Ações de `user`           | Os casos de uso de usuário, uma ação cada; `ban` cobre tanto `ban-user` quanto `unban-user`                                       |
| Ações de `session`        | `list-user-sessions` (`list`), `revoke-user-session` e `revoke-user-sessions` (`revoke`)                                          |
| Uma sessão, sem permissão | Os casos de uso de conta, licença, dois fatores, preferências de newsletter e sessões próprias, além de `stop-impersonating-user` |

`order`, `product: ["publish"]` e `settings` estão declarados, mas ainda não são verificados por nenhuma server function.

## Verificando uma permissão

As server functions usam o middleware, por exemplo `authorized({ category: ["read"] })`. O restante do código chama `hasPermission`, como faz o guard de admin:

```ts
export const requireAdmin = async (context: AuthRouteContext) => {
  const result = await requireSignedIn(context)
  if (!hasPermission({ permission: { admin: ["access"] }, role: result.session.user.role })) {
    throw redirect({ replace: true, to: ROUTES.APP })
  }
  return result
}
```
