## Code coverage

`bun run test:coverage` runs the Vitest projects <RepositoryFact name="vitestProjects" /> and fails when lines, statements, functions or branches fall below <RepositoryFact name="coverageThreshold" unit="percent" /> of <RepositoryFact name="coverageInclude" />. It leaves out <RepositoryFact name="coverageExclude" />. CI runs it on every pull request and every push to `main`.

The browser suite does not count toward this number: Playwright drives the built test Worker, and no coverage is collected there. Full code coverage means that every measured line ran under a test that asserted something. It does not mean that the pieces work together through the Worker, D1, the browser and the providers: the CLI licence API's bundle spec sends only the default answers, so a bundle request with another answer could fail in production while every line of the handler is covered. Flow coverage measures that second question.

## Flow coverage

The flow inventory lists every flow of the site, the customer workspace and the admin console. Each area declares its flows in `e2e/data/<area>.flows.ts`, joined by `e2e/data/flows.entries.ts`, with the types and constants in `e2e/data/flows.ts`, as the areas declare their pages and seeds. A flow has an id, an area, the outcome a test must assert and one of three statuses:

- **covered**: a Playwright test performs the flow end to end and asserts its outcome. The flow names the spec and the full title of each such test.
- **missing**: the feature exists, but no browser test performs it end to end. The flow says what is missing, and names the tests that do part of it and the journey step that performs it, if any.
- **to build**: the feature does not exist yet, such as the admin screens for products, prices and discounts, which show sample data. The flow says what stands in its place.

`bun run check` runs `bun run check:flows`, which lists the browser suite with `playwright test --list` in Chromium, as pull requests run it, and fails when:

- a flow names a spec or a test title that the suite does not have, which is what renaming or deleting the test does;
- a flow names a test that is skipped;
- two flows share an id;
- a missing flow or a flow to build does not say why;
- a flow names a step that the journey suite does not have.

A covered flow therefore loses its test only when the same pull request changes its status and writes down why.

The browser suite has <RepositoryFact name="e2eTests" /> tests in <RepositoryFact name="e2eSpecs" /> spec files.

## Journey suite

The [journey suite](/docs/tooling/playwright#journey-suite) buys each tier on preview in the Polar sandbox with Stripe's test card, waits for the webhooks to issue the key, uses the published CLI on as many machines as the tier allows and refunds the order. It performs <RepositoryFact name="flowsInJourney" /> of the missing flows, which the missing table names in its last column, but no CI workflow runs it, so those flows count as missing. Running it in CI takes three steps that only the owner can take:

1. **Secrets.** The GitHub environment `Preview` holds `POLAR_ACCESS_TOKEN`, a sandbox token with the `orders:read` and `refunds:write` scopes; `POLAR_PRODUCT_ID_CORE`, `POLAR_PRODUCT_ID_COMPLETE` and `POLAR_PRODUCT_ID_AGENCY`, the sandbox products; and `RESEND_API_KEY`, a full-access key that can read the emails preview sends. `POLAR_SERVER` is `sandbox` and needs no secret.
2. **Sandbox.** The sandbox organisation matches the code, which `bun run polar:verify:preview` checks, and its webhook points at preview.
3. **Workflow.** A job runs `bun run test:journey` with Chromium installed after the **Deploy preview** job, which deploys a pull request's branch to preview. Workflows need a person's review in this repository, so the job is proposed rather than added.

## Planned

- **Mutation testing.** A mutation tool changes the code under test, one operator or condition at a time, and counts the changes that no test notices. It measures whether the tests assert outcomes or only run lines. It would start with the licence, payment, pricing, course access and auth code. Nothing is set up yet.
- **Browser code coverage.** Collecting V8 coverage while the browser suite runs the built application would show which code no browser test reaches. It would be reported beside the Vitest number, not added to it, and not gated. Nothing is set up yet.
