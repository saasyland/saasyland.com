---
title: "Adicionar uma página de administração"
description: "Registre a rota, o item da barra lateral, as mensagens e os widgets de uma nova página de administração."
---

Páginas de administração são arquivos de rota planos sob o layout `/admin` (`src/routes/admin.tsx`), que executa `requireAdmin` em `beforeLoad` e renderiza a barra lateral, a trilha de navegação e a paleta de comandos. Os passos abaixo adicionam uma página em `/admin/reports`; `src/routes/admin.payments.tsx` é um exemplo real completo.

## 1. Adicione o caminho

Declare o caminho no arquivo de rotas da área, aqui um novo `src/data/reports.routes.ts`, e adicione um arquivo novo ao barrel `src/data/routes.entries.ts`. A partir daí, `ROUTES` o inclui:

```ts
export const ADMIN_REPORTS = "/admin/reports"
```

```ts
export { ADMIN_REPORTS } from "~/src/data/reports.routes"
```

## 2. Crie o arquivo da rota

Crie `src/routes/admin.reports.tsx`. A rota define apenas o componente da página, `NAMESPACE`, o loader, `head` e `pendingComponent`; o gerador do router registra o arquivo em `src/routeTree.gen.ts`.

```tsx
import type { JSX } from "react"

import { createFileRoute } from "@tanstack/react-router"
import { useTranslations } from "use-intl/react"

import { loadPageMetadata, preloadNamespaces } from "~/src/integrations/use-intl/i18n.messages"
import { getCurrentLocale } from "~/src/integrations/use-intl/i18n.utils"

import { pageHead } from "~/src/lib/seo"

import { AdminPageHeader } from "~/src/presentation/components/custom/admin/admin-page-header"
import { AdminReportsPending } from "~/src/presentation/components/custom/admin/reports-pending"
import { ReportStats } from "~/src/presentation/components/custom/admin/reports/report-stats"

import { ROUTES } from "~/src/routes"

const ReportsPage = (): JSX.Element => {
  const t = useTranslations("pages.admin.reports")

  return (
    <div className="flex w-full flex-col space-y-8">
      <AdminPageHeader description={t("metadata.description")} title={t("metadata.title")} />

      <ReportStats />
    </div>
  )
}

const NAMESPACE = "pages.admin.reports"

export const Route = createFileRoute("/admin/reports")({
  component: ReportsPage,
  head: pageHead(ROUTES.ADMIN_REPORTS),
  loader: async ({ context }) => {
    const locale = getCurrentLocale()
    const [metadata] = await Promise.all([
      loadPageMetadata({ locale, namespace: NAMESPACE }),
      preloadNamespaces({ locale, namespaces: [NAMESPACE], queryClient: context.queryClient }),
    ])
    return { locale, metadata }
  },
  pendingComponent: AdminReportsPending,
  staticData: { namespaces: [NAMESPACE] },
})
```

As queries de que a página precisa entram no mesmo `Promise.all`, por exemplo `context.queryClient.query({ ...getUsersQuery, staleTime: "static" })` em `src/routes/admin.users.all.tsx`. `pageHead` monta o título, a descrição, a URL canônica e os links para os outros idiomas a partir de `metadata` do loader. `AdminReportsPending` é o esqueleto próprio da página, exibido apenas quando uma navegação leva mais de um segundo. Escreva-o no arquivo de esqueletos da área, aqui um novo `custom/admin/reports-pending.tsx`, a partir de `AdminPageHeaderPending` de `admin-page-header.tsx` para o cabeçalho e dos blocos de `pending-blocks.tsx`, para que ele reproduza a estrutura da página. Depois, adicione-o à lista de esqueletos da área, aqui `REPORTS_SKELETONS` em um novo `src/data/reports.skeletons.ts`, e adicione o arquivo novo ao barrel `src/data/skeletons.entries.ts`, para que o esqueleto do layout de administração o exiba quando alguém entrar em `/admin/reports` vindo de fora da área de administração:

```ts
export const REPORTS_SKELETONS = [
  { pendingComponent: AdminReportsPending, to: ROUTES.ADMIN_REPORTS },
] as const satisfies readonly PageSkeleton[]
```

Veja [Esqueletos de carregamento](/docs/architecture/delivery-layer#esqueletos-de-carregamento).

## 3. Adicione o item da barra lateral

Adicione um item com `placement: NAVIGATION_PLACEMENT.ADMIN` à lista de menu da área, aqui `REPORTS_NAVIGATION` em um novo `src/data/reports.navigation.ts`, e adicione um arquivo novo ao barrel `src/data/navigation.entries.ts`. O item indica a sua `area`, o seu grupo da barra lateral, o seu ícone do `lucide-react` e o seu `order` dentro do grupo: Painel é 10, então 30 coloca Reports depois dele.

```ts
{
  area: AREA,
  group: ADMIN_NAVIGATION_GROUP.OVERVIEW,
  icon: FileText,
  key: "reports",
  order: 30,
  placement: NAVIGATION_PLACEMENT.ADMIN,
  to: ROUTES.ADMIN_REPORTS,
},
```

Rotule-o com `admin.reports` no `messages/<locale>/navigation.reports.json` da área, em todos os idiomas. Um grupo novo também precisa de um valor em `ADMIN_NAVIGATION_GROUP`, do seu lugar em `ADMIN_NAVIGATION_GROUPS` e de `groups.<group>`. A barra lateral, a trilha de navegação e a paleta de comandos ⌘K leem `ADMIN_NAVIGATION` (`src/data/navigation.ts`), então a página aparece nos três lugares. A landing page a conta entre as seções do admin, e a barra lateral do admin no vídeo `app-tour` da landing page passa a listá-la depois que o vídeo é renderizado de novo (veja `remotion/README.md`). Um terceiro segmento de URL, como `/admin/reports/create`, mostra na trilha o rótulo `breadcrumbs.create` do mesmo `navigation.reports.json` quando a área o define, e nenhum terceiro nível na trilha quando não o define.

## 4. Adicione as mensagens da página

Crie `messages/<locale>/pages.admin.reports.json` em todos os idiomas. `metadata` é obrigatório porque o loader o lê para o cabeçalho do documento:

```json
{
  "metadata": {
    "title": "Reports",
    "description": "Revenue and usage reports."
  }
}
```

## 5. Adicione os widgets

Coloque cada widget, diálogo, formulário e conjunto de colunas de tabela em seu próprio arquivo em `src/presentation/components/custom/admin/reports/`, por exemplo `report-stats.tsx` ou `report-columns.tsx`. Os widgets chamam `useTranslations("pages.admin.reports")` e leem seus próprios dados com `useSuspenseQuery`; a página não passa rótulos nem dados para eles. Tabelas usam o `DataGrid`; veja [Adicionar uma grade de dados](/docs/guides/add-a-data-table).

## 6. Proteja e teste

- O guard do layout controla o acesso à página. Toda função de servidor chamada pela página ainda precisa de `authorized(permission)`; veja [Papéis e permissões](/docs/guides/roles-and-permissions).
- `/admin` fica fora da pré-renderização.
- Adicione os testes de rota da área em `src/routes/__test__/admin-<area>-routes.component.test.tsx` e `admin-<area>-loaders.test.ts`, os testes de widget em `src/presentation/components/custom/admin/__test__/` e a página em `e2e/data/<area>.pages.ts`, depois execute `bun run check:i18n` e `bun run test:coverage`.
