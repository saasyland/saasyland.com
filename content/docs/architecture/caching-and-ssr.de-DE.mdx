## Query-Cache

`getRouter` erstellt für jeden Request einen neuen `QueryClient`, sodass auf dem Server keine Daten zwischen Nutzern durchsickern. Standardwerte:

| Einstellung               | Wert       |
| ------------------------- | ---------- |
| Query `staleTime`         | 1 Minute   |
| Query `gcTime`            | 5 Minuten  |
| Router `defaultStaleTime` | 1 Minute   |
| Preloading                | Bei Intent |

Loader füllen den Cache mit `queryClient.query({ ...options, staleTime: "static" })`, und Komponenten lesen dieselben Keys mit `useSuspenseQuery`. Ausnahme sind die Kursseiten und der Kurseditor im Admin: Ihre Queries behalten `staleTime: COURSE_STALE_MS` (eine Minute), weil `invalidateQueries` eine `static`-Query nie neu lädt und der Lehrplan nach einer abgeschlossenen Lektion oder einer im Editor gespeicherten Änderung aktualisiert werden muss. `setupRouterSsrQueryIntegration` serialisiert den Server-Cache ins HTML und hydratisiert ihn im Browser.

- **Übersetzungsnachrichten** werden pro Locale und Namespace mit unendlicher `staleTime` und `gcTime` gecacht.
- **Die Session-Query** (`getCurrentSessionQuery`) hat eine `staleTime` von einer Minute. Route-Guards laden sie bei echten Navigationen neu und leeren den gesamten Cache, wenn sich der angemeldete Nutzer ändert.
- **Mutationen** invalidieren nach erfolgreichem Abschluss die Query-Keys ihres Moduls, zum Beispiel `USER_QUERY_KEYS.ALL`.

## Prerendering

`bun run build` rendert die öffentlichen Seiten vor, indem es Links folgt: Landing-, Rechts-, Blog- und Doku-Seiten in allen neun Locales. Ausgenommen sind Pfade unter `/admin`, `/app`, `/auth`, `/courses`, `/newsletter` und `/api` (mit oder ohne Locale-Präfix) sowie Links mit Query-String oder Hash. Die Kursseiten sind ausgenommen, weil sie für jeden Betrachter Sperren und Fortschritt zeigen. Den Kursblock der Landingpage füllt der Browser aus `getCourseShowcase`, sobald er in die Nähe des sichtbaren Bereichs kommt; die vorgerenderte Landingpage bleibt daher für alle gleich (siehe [Kurse](/docs/features/courses)).

Der Worker liefert vorgerendertes HTML aus dem `ASSETS`-Binding aus, bevor er die Anwendung lädt. Eine vorgerenderte Seite enthält keine Nutzerdaten und kann daher gefahrlos an alle ausgeliefert werden. Qualifiziert sich ein Besucher für regionale Preise, schreibt der Worker das HTML um und markiert die Antwort mit `Cache-Control: private, no-cache`.

## KV und D1

- **KV (`CACHE`)** speichert die Anzahl der GitHub-Sterne für `src/lib/github.ts` und die regionalen Checkout-Rabatte für `src/modules/license/license.ppp.ts`. Eine Sternezahl, die älter als eine Stunde ist, wird sofort zurückgegeben und im Hintergrund mit `waitUntil` aktualisiert; Rabatte, die älter als fünf Minuten sind, werden erneut bei Polar abgefragt.
- **D1 (`DB`)** speichert Sessions und Rate-Limit-Zähler. Session-Prüfungen für Server Functions umgehen den Cookie-Cache von Better Auth und werden für den Rest des Requests memoisiert.
- **Der Workers-Cache** hält die Videodateien, die `serveMedia` aus R2 liest, unter `/media/_/<videoId>/<file>` ohne die Signatur vor, sodass sich die Zuschauer an einem Edge-Standort eine einzige gecachte Kopie teilen. Siehe [Cloudflare R2](/docs/integrations/cloudflare-r2).
- Server Functions treffen nie eine Berechtigungsentscheidung auf Basis gecachter Daten.
