| Task                                                      | Command                  |
| --------------------------------------------------------- | ------------------------ |
| Start the dev server                                      | `bun run dev`            |
| Check format, lint, types and translations                | `bun run check`          |
| Run all Vitest projects                                   | `bun run test`           |
| Run the coverage gate                                     | `bun run test:coverage`  |
| Run the browser smoke test                                | `bun run test:e2e:smoke` |
| Run every browser spec in Chromium                        | `bun run test:e2e:pr`    |
| Run every browser spec in Chromium and WebKit, as CI does | `bun run test:e2e`       |
| Generate a migration                                      | `bun run db:generate`    |
| Build the preview Worker                                  | `bun run build`          |
| Serve the latest build                                    | `bun run start`          |
| Deploy the preview                                        | `bun run deploy:preview` |

Before opening a pull request, run the sequence from [Contributing](/docs/project/contributing), with the specs that cover your change:

```sh
bun run check
bun run test:coverage
bun run build:test
bunx playwright test e2e/specs/<spec>.spec.ts --project=chromium
```

Locally, Playwright recreates the test database with `db:reset:test`, builds the test Worker and starts it on the address `PLAYWRIGHT_BASE_URL` names (`127.0.0.1:3000` when it is unset), unless a server already answers there. Each worktree takes its own port from the range the test build trusts, and the run stops when the server on its port belongs to another worktree: see [Running beside other worktrees](/docs/tooling/playwright#running-beside-other-worktrees).

Use `bun run test`, not `bun test`, so Vitest runs with the project setup. Scripts that end in an environment name, such as `db:migrate:preview` or `deploy:production`, act on that environment only.

See [Project scripts](/docs/tooling/scripts) for the complete list.
