`src/integrations/resend/resend.config.ts` は `resendClient` をエクスポートし、メールを送るたびに `RESEND_API_KEY` から Resend クライアントを作成します。Resend SDK はキーがないと例外をスローしますが、こうすることで、ビルドやプリレンダリングされたページ、メールを送らないリクエストはキーなしで動きます。`resend.utils.ts` は、メールを送信する関数 `sendEmail` と `sendBatchEmails` をエクスポートします。メールを送るのはこの 2 つだけです。`sendBatchEmails` は最大 <RepositoryFact name="newsletterBatchSize" /> 通（`resend.constants.ts` の `RESEND_BATCH_LIMIT`）のメールを `batchValidation: "permissive"` で 1 回のリクエストにまとめて送るため、Resend が拒否したアドレスはログに記録され、残りはそのまま送られます（[ニュースレター](/docs/features/newsletter#sending)）。`resend.constants.ts` は、`List-Unsubscribe` と `List-Unsubscribe-Post` のヘッダー名と、号に付けるワンクリック配信停止の値も定義しています。`from` のデフォルトは `RESEND_EMAIL_FROM` です。必須の `idempotency` オプションでメールの目的ときっかけとなったトークンを渡すと、`sendEmail` がそれをキー `${purpose}/${sha256Hex(token)}` に変換します。このキーにより、再試行されたリクエストを Resend が二重に送信することはなく、Resend の 256 文字の上限にも収まります。Resend のエラーは例外としてスローされます。どちらのファイルもサーバー専用です。メールを送る各モジュールは、`verification.constants.ts` の `VERIFICATION_EMAIL_PURPOSE` のように、自分の `<module>.constants.ts` で目的に名前を付けます。2 つのモジュールが同じ目的を使うと `email-purposes.test.ts` が失敗します。ユースケースは同じ名前を受信者ごとの上限の `kind` にも渡します。

## テンプレートとユースケース

`src/presentation/emails/` にあるテンプレートは、マークアップだけを持つ React Email コンポーネントです。各テンプレートは `*_NAMESPACE` 定数をエクスポートし、`locale` と `messages` をプロパティとして受け取り、use-intl の `createTranslator` で翻訳します。メールを送信するユースケースは呼び出し元からロケールを受け取り（確認メールはコールバック URL からロケールを読み取ります）、メッセージを読み込み、テンプレートを描画して `sendEmail` を呼び出します。

```ts
const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotency: { purpose: VERIFICATION_EMAIL_PURPOSE.VERIFY_EMAIL, token: crypto.randomUUID() },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```

最初の 6 つのユースケースは、Better Auth が `auth.server.ts` のフックから直接呼び出します。ニュースレターの配信号は、各購読者が登録したときの言語で届きます。その言語で書かれていない号は英語で届きます（[ニュースレター](/docs/features/newsletter)）。ニュースレターの通知は、購読が確認された後にサイトのオーナーへ英語で送信されます。ライセンス機能の `order.paid` ハンドラーは、注文に保存された言語で購入確認メールを送信します。顧客がどのアカウントにも対応しないライセンスの注文の場合は、代わりにアカウントに対応しない注文のアラートを英語でサイトのオーナーに送信します。撤回の意思表示には、送信元のページの言語で受領確認が送られ、サイトのオーナーには英語で通知が送られます。メール内のリンクは `localizePathname` で組み立てられるため、メールのロケールで開きます。`createInvitation` と `resendInvitation` は、管理者が選んだ言語で招待を送信します。

確認メール、パスワードリセット、既存アカウント、ニュースレターの確認の各ユースケースは、最初に `src/lib/rate-limit.ts` の `withinRecipientRateLimit` を呼び出します。アドレスの SHA-256 ハッシュをキーとして、各種類のメールはアドレスごとに 1 時間あたり最大 <RepositoryFact name="recipientEmailsPerHour" /> 通までです。上限を超えると、エラーを出さずにメールをスキップします。`sendInvitationEmail` も同じ上限を確認しますが、上限を超えると `TOO_MANY_REQUESTS` で失敗するため、管理者にエラーが表示されます。

## テスト

Vitest はプロバイダーの呼び出しをモックします。Playwright のテスト用 Worker では、Resend API へのリクエストは送信されずにキャプチャされ、`/__test/emails?to=<address>` でキャプチャされたメールを取得できます。
