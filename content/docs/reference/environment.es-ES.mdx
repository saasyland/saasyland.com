## Archivos de entorno

| Archivo            | Versionado | Lo usa                                                                                                                                                 |
| ------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `.env.example`     | Sí         | Enumera todos los secretos con el valor vacío                                                                                                          |
| `.env.development` | No         | `bun run dev`, `polar:verify:development`, `db:seed:local` (`LOCAL_ADMIN_PASSWORD`)                                                                    |
| `.env.preview`     | No         | `deploy:preview` (los secretos declarados), `auth:verify:preview`, `polar:verify:preview`, `db:studio:preview`, `db:introspect:preview`                |
| `.env.production`  | No         | `deploy:production` (los secretos declarados), `auth:verify:production`, `polar:verify:production`, `db:studio:production`, `db:introspect:production` |
| `.env.test`        | Sí         | Vitest y el entorno `test` de Wrangler; solo valores ficticios                                                                                         |

## Variables

| Variable                    | Uso                                                                                                                                                                                                                                     |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AUTH_SECRET`               | Firma, cifrado y tokens de verificación de correo de Better Auth                                                                                                                                                                        |
| `AUTH_GITHUB_CLIENT_ID`     | OAuth de GitHub; también autentica la petición del número de estrellas de GitHub                                                                                                                                                        |
| `AUTH_GITHUB_CLIENT_SECRET` | OAuth de GitHub; también autentica la petición del número de estrellas de GitHub                                                                                                                                                        |
| `AUTH_GOOGLE_CLIENT_ID`     | OAuth de Google                                                                                                                                                                                                                         |
| `AUTH_GOOGLE_CLIENT_SECRET` | OAuth de Google                                                                                                                                                                                                                         |
| `RESEND_API_KEY`            | El cliente de Resend                                                                                                                                                                                                                    |
| `RESEND_EMAIL_FROM`         | El remitente por defecto de `sendEmail`                                                                                                                                                                                                 |
| `POLAR_ACCESS_TOKEN`        | El cliente del SDK de Polar                                                                                                                                                                                                             |
| `POLAR_SERVER`              | `sandbox` para desarrollo y preview, `production` para producción                                                                                                                                                                       |
| `POLAR_WEBHOOK_SECRET`      | Verificación de las firmas de los webhooks de Polar                                                                                                                                                                                     |
| `POLAR_ORGANIZATION_ID`     | Acota a la organización las llamadas a Polar: la activación y desactivación de claves de licencia (la API de licencias de la CLI y `/app/license`), el listado de pedidos para el precio de una mejora y los listados de `polar:verify` |
| `POLAR_PRODUCT_ID_CORE`     | Producto de checkout del plan Core                                                                                                                                                                                                      |
| `POLAR_PRODUCT_ID_COMPLETE` | Producto de checkout del plan Complete                                                                                                                                                                                                  |
| `POLAR_PRODUCT_ID_AGENCY`   | Producto de checkout del plan Agency                                                                                                                                                                                                    |
| `CLOUDFLARE_ACCOUNT_ID`     | Driver HTTP de D1 de Drizzle Kit                                                                                                                                                                                                        |
| `CLOUDFLARE_DATABASE_ID`    | Driver HTTP de D1 de Drizzle Kit                                                                                                                                                                                                        |
| `CLOUDFLARE_ACCESS_TOKEN`   | Driver HTTP de D1 de Drizzle Kit                                                                                                                                                                                                        |
| `AFFONSO_PROGRAM_ID`        | ID público opcional del programa de Affonso que necesita el seguimiento de referidos de afiliados mientras el programa está abierto                                                                                                     |
| `LOCAL_ADMIN_PASSWORD`      | Contraseña opcional del administrador local que crea `bun run db:seed:local`; nunca es un secreto del Worker                                                                                                                            |
| `FFMPEG`, `FFPROBE`         | Binarios opcionales de FFmpeg y ffprobe para `scripts/publish-video.ts`; por defecto, `ffmpeg` y `ffprobe`                                                                                                                              |

Cada entorno de `wrangler.jsonc` enumera los secretos que necesita en `secrets.required`; el entorno `test` omite las tres variables de Cloudflare. `AFFONSO_PROGRAM_ID` no es un secreto: aparece en la etiqueta del script de la página, así que es una variable de Worker en `vars`, definida solo para el entorno que recibe pagos reales. `production` define el ID de programa de SaaSy Land y `test`, un ID ficticio para las pruebas en el navegador. El seguimiento solo funciona cuando el Worker tiene el ID y el programa está abierto: hoy `AFFILIATE_PROGRAM` vale <RepositoryFact name="affiliateProgram" /> ([Abrir el programa](/docs/features/affiliates#opening-the-programme)). `FFMPEG` y `FFPROBE` son variables de shell opcionales para `scripts/publish-video.ts`, no secretos del Worker. El código del Worker las lee de `env` en `cloudflare:workers`, con los tipos de `src/types/worker-configuration.d.ts`, que `bun run cf-typegen` genera a partir de `wrangler.jsonc`, y de los archivos de cada funcionalidad en `src/types`. No hay variables `VITE_`: la URL pública y el dominio son constantes en `src/presentation/branding`.

## Bindings

| Binding   | Tipo               | `development`                   | `preview` | `production` | `test`                         |
| --------- | ------------------ | ------------------------------- | --------- | ------------ | ------------------------------ |
| `DB`      | D1                 | `saasyland_local` local         | Preview   | Producción   | `saasyland_test` local         |
| `CACHE`   | KV                 | Local                           | Preview   | Producción   | Local                          |
| `MEDIA`   | R2                 | `saasyland-local` local         | Preview   | Producción   | `saasyland-test` local         |
| `BUNDLES` | R2                 | `saasyland-bundles-local` local | Preview   | Producción   | `saasyland-bundles-test` local |
| `ASSETS`  | Recursos estáticos | Sí                              | Sí        | Sí           | Sí                             |

Los scripts de despliegue de preview y de producción ejecutan primero `scripts/verify-bindings.ts`, que falla mientras a un entorno le falte un binding o siga teniendo IDs provisionales de D1 o KV, y cuando producción comparte un recurso con preview. Los buckets de R2 se vinculan por nombre, el `bucket_name` de cada entrada de `r2_buckets` de un entorno en `wrangler.jsonc`, y deben existir antes de un despliegue; los buckets de `development` y `test` son locales y no necesitan configuración.
