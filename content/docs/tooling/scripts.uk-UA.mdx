Запускайте скрипти з кореня репозиторію командою `bun run <script>`. Скрипти, які викликають Wrangler, а також `db:generate`, що викликає drizzle-kit, запускають їх через `vp exec`, який бере виконуваний файл із `node_modules/.bin`, тож вони завжди використовують версії, зафіксовані в `bun.lock`.

## Розробка та збірка

| Скрипт             | Що запускає                                                                                                                                     |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `dev`              | `generate:cn`, `content` і `vp dev` у середовищі `development` за адресою http://localhost:3000                                                 |
| `build`            | Те саме, що `build:preview`                                                                                                                     |
| `build:preview`    | Очищення `dist`, `generate:cn`, `content`, `vp build` для `preview`, `scripts/verify-build.ts preview` і `scripts/optimize-prerendered-html.ts` |
| `build:production` | Ті самі кроки для `production`                                                                                                                  |
| `build:test`       | Ті самі кроки для середовища `test`                                                                                                             |
| `start`            | `vp preview` останньої збірки за адресою http://127.0.0.1:3000                                                                                  |
| `start:test`       | `vp preview` тестової збірки                                                                                                                    |

`verify-build.ts` перевіряє, що `.wrangler/deploy/config.json` вказує на `dist/server/wrangler.json` і що цей файл розгортає Worker, який `wrangler.jsonc` називає для цього середовища, а потім мову документа, канонічні та альтернативні посилання локалізованих головної і юридичних сторінок, шрифти, те, що захищені сторінки й псевдоніми локалей не були попередньо відрендерені, те, що кожну сторінку документації та кожен опублікований допис блогу попередньо відрендерено, а також те, що жоден клієнтський ресурс не імпортує `cloudflare:workers`. `optimize-prerendered-html.ts` видаляє підказки `modulepreload` для залежностей з попередньо відрендерених сторінок і залишає підказку для точки входу з низьким пріоритетом.

## Розгортання

| Скрипт              | Що запускає                                                                                                                                                                                                          |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `deploy:preview`    | `scripts/verify-bindings.ts preview`, `build:preview`, `scripts/prepare-deploy-secrets.ts preview`, `db:migrate:preview`, `wrangler deploy` для `dist/server/wrangler.json` і `scripts/verify-deployment.ts preview` |
| `deploy:production` | Ті самі кроки для `production`                                                                                                                                                                                       |

- `verify-bindings.ts` завершується помилкою, коли середовище не має прив'язки `DB`, `CACHE` або `MEDIA` чи досі має ідентифікатор-заглушку D1 або KV, а також коли production використовує ту саму базу даних, простір імен або бакет, що й preview.
- `prepare-deploy-secrets.ts` зчитує з `.env.<environment>` ключі, перелічені в `secrets.required` середовища, завершується помилкою, коли якийсь із них відсутній або порожній, і записує лише ці ключі в `.wrangler/secrets.<environment>.json`. Інші змінні з файлу не завантажуються.
- Міграції виконуються після збірки й перед розгортанням, тож невдала збірка ніколи не зачіпає базу даних, а новий Worker ніколи не запускається на старішій схемі.
- Розгортання запускає `env -u CLOUDFLARE_ENV vp exec wrangler deploy --config dist/server/wrangler.json --secrets-file .wrangler/secrets.<environment>.json`. Зібрана конфігурація вже націлена на одне середовище; `CLOUDFLARE_ENV`, що залишився в оболонці, змусив би Wrangler шукати розділ середовища, якого в цьому файлі немає.
- `verify-deployment.ts` надсилає запити до <RepositoryFact name="liveSiteCheckPaths" /> на домені середовища й завершується помилкою, якщо котрийсь із них не відповідає `200` з очікуваним типом вмісту. Шлях, що не пройшов перевірку, він запитує тричі з інтервалом у п'ять секунд і нічого не змінює. `bun scripts/verify-deployment.ts <preview|production>` окремо перевіряє розгорнутий сайт.

## Перевірки

| Скрипт             | Що запускає                                                                              |
| ------------------ | ---------------------------------------------------------------------------------------- |
| `check`            | `generate:cn`, `check:i18n` і `vp check` (форматування, лінтинг і типи)                  |
| `check:fix`        | Те саме з `vp check --fix`                                                               |
| `check:i18n`       | `scripts/check-i18n.ts`, `scripts/check-message-formats.ts` і `scripts/check-content.ts` |
| `check:pre-commit` | `generate:cn`, `check:i18n` і `vp staged`; запускається хуком pre-commit                 |
| `lint`             | `vp lint`                                                                                |
| `format`           | `vp fmt`                                                                                 |
| `format:check`     | `vp fmt --check`                                                                         |

## Генерування та обслуговування

| Скрипт           | Що запускає                                                                                              |
| ---------------- | -------------------------------------------------------------------------------------------------------- |
| `content`        | `fumadocs-mdx`: генерує `.source/` з `content/`                                                          |
| `generate:cn`    | Будує таблиці злиття класів у `.source/cn-tables.ts` з `src/lib/cn.config.ts`                            |
| `cf-typegen`     | `wrangler types` для `development`: перегенеровує `src/types/worker-configuration.d.ts`                  |
| `typegen`        | `cf-typegen`, `generate:cn` і `content`                                                                  |
| `skills:sync`    | `scripts/sync-skills.ts`: відновлює навички агентів з `skills-lock.json`                                 |
| `clean`          | Видаляє `.source`, `.tanstack`, `.wrangler`, `dist`, `coverage`, результати Playwright і `*.tsbuildinfo` |
| `clean:deep`     | `clean` і `node_modules`                                                                                 |
| `clean:hardcore` | `clean:deep`, `bun.lock` і `skills-lock.json`                                                            |
| `prepare`        | Запускається під час встановлення: `vp config --no-agent` (Git-хуки), `generate:cn` і `content`          |

`clean` видаляє `.wrangler`, зокрема локальні бази даних для розробки й тестів і файли секретів, записані скриптами розгортання, тож спершу експортуйте локальні дані, які хочете зберегти.
