`src/modules/_core` es la única carpeta de módulo que no es dueña de ninguna tabla. Solo reúne la base sobre la que se construyen los esquemas, los esquemas de Zod y los casos de uso de los módulos, para que ninguno tenga que volver a definirla: los códigos de error, las constantes HTTP y de entorno, los campos de Zod y los textos localizados compartidos, y las entradas de paginación, orden y búsqueda.

## Constantes

| Archivo                 | Contenido                                                                                                                                                |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `constants/errors.ts`   | `ERROR_CODES`, el tipo `ErrorCode` y la clase `AppError`                                                                                                 |
| `constants/api.ts`      | `HTTP_STATUS`, los nombres de las cabeceras `cf-ipcountry` y `cf-connecting-ip`, las cabeceras de seguridad y los hosts permitidos en cada modo de build |
| `constants/ordering.ts` | `FIRST_POSITION`, el lugar del primer elemento de una lista ordenada                                                                                     |

Los datos y las utilidades que los módulos usan pero sobre los que no se construyen viven fuera de `_core`: los catálogos de países, monedas, locales y zonas horarias en `src/data/countries.ts`, `src/data/currencies.ts`, `src/data/locales.ts` y `src/data/timezones.ts`, la moneda de la tienda y el formato de los precios en `src/data/pricing.ts`, y los periodos y los intervalos de los gráficos del panel de administración en `src/lib/time-series.ts`. El catálogo de locales recoge todos los locales conocidos; los locales que sirve la aplicación son `I18N.SUPPORTED_LOCALES`, en `src/integrations/use-intl/i18n.config.ts`. Una prueba de `src/__test__/module-tables.test.ts` falla cuando un archivo de `_core` no está descrito en esta página, así que cada archivo nuevo es una decisión consciente.

## Utilidades

- `utils/localized-text.ts`: `LocalizedText`, un texto por locale guardado como JSON, `localizedTextSchema`, que exige `en-US` y admite como máximo <RepositoryFact name="localizedTextMaxLength" /> caracteres por texto, y `localize`, que recurre a `en-US`
- `utils/ordering.ts`: `nextPosition`, la `position` más alta más uno, y `reorder`, que mueve un elemento a un lugar entre sus hermanos, ajusta al extremo un lugar que se salga por cualquiera de los dos, numera la lista desde `FIRST_POSITION` y devuelve solo los elementos cuya `position` cambia; los casos de uso de cursos, capítulos, lecciones y materiales mantienen `position` sin huecos con ellas
- `utils/pagination.ts`: `paginationSchema` (`pageIndex`, `pageSize`) y `DEFAULT_PAGE_SIZE`
- `utils/search.ts`: `searchSchema` y `localizedSearchSchema`, la entrada de los casos de uso de búsqueda del panel de administración, sus límites de longitud y el `SearchHit` que devuelven
- `utils/zod-fields.ts`: campos Zod reutilizables como `idField`, `localeField`, `positionField` (un número entero desde `FIRST_POSITION`) y `slugField`

## Errores

Hay una sola clase de error y una sola lista de códigos:

```ts
export const ERROR_CODES = {
  AUTH_API_ERROR: "AUTH_API_ERROR",
  CONFLICT: "CONFLICT",
  FORBIDDEN: "FORBIDDEN",
  INTERNAL_ERROR: "INTERNAL_ERROR",
  NOT_FOUND: "NOT_FOUND",
  TOO_MANY_REQUESTS: "TOO_MANY_REQUESTS",
  UNAUTHORIZED: "UNAUTHORIZED",
  VALIDATION: "VALIDATION",
} as const

export type ErrorCode = (typeof ERROR_CODES)[keyof typeof ERROR_CODES]

export class AppError extends Error {
  readonly code: ErrorCode

  constructor(code: ErrorCode, message: string = code) {
    super(message)
    this.name = "AppError"
    this.code = code
  }
}
```

Las funciones de servidor lanzan `AppError`. El middleware `withRequest` normaliza todo lo demás: los errores de la API de Better Auth se convierten en `AUTH_API_ERROR` con la clave de error de Better Auth como mensaje, los errores de Zod en `VALIDATION`, y los errores desconocidos se registran en el log y se convierten en `INTERNAL_ERROR`. En el navegador, `useErrorMessage()` de `src/hooks/use-error-message.ts` asocia el mensaje a las traducciones `auth.errors.*` o `errors.codes.*`.
