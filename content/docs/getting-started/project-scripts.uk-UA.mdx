---
title: "Скрипти проєкту"
description: "Команди, якими ви користуєтеся щодня."
---

| Завдання                                              | Команда                  |
| ----------------------------------------------------- | ------------------------ |
| Запустити dev-сервер                                  | `bun run dev`            |
| Перевірити форматування, лінтинг, типи та переклади   | `bun run check`          |
| Запустити всі проєкти Vitest                          | `bun run test`           |
| Запустити перевірку покриття                          | `bun run test:coverage`  |
| Запустити браузерний smoke-тест                       | `bun run test:e2e:smoke` |
| Запустити набір браузерних тестів у Chromium, як у CI | `bun run test:e2e:pr`    |
| Згенерувати міграцію                                  | `bun run db:generate`    |
| Зібрати Worker для preview                            | `bun run build`          |
| Запустити останню збірку                              | `bun run start`          |
| Розгорнути preview                                    | `bun run deploy:preview` |

Перш ніж відкрити pull request, виконайте послідовність із розділу [Участь у розробці](/docs/project/contributing) зі специфікаціями, що покривають вашу зміну:

```sh
bun run check
bun run test:coverage
bun run build:test
bunx playwright test e2e/specs/<spec>.spec.ts --project=chromium
```

Локально Playwright заново створює тестову базу даних за допомогою `db:reset:test`, збирає тестовий Worker і запускає його за адресою з `PLAYWRIGHT_BASE_URL` (`127.0.0.1:3000`, якщо змінну не задано), якщо там ще не відповідає сервер. Кожен worktree бере власний порт із діапазону, якому довіряє тестова збірка, а запуск зупиняється, коли сервер на його порту належить іншому worktree: див. [Запуск поряд з іншими worktree](/docs/tooling/playwright#running-beside-other-worktrees).

Використовуйте `bun run test`, а не `bun test`, щоб Vitest запускався з налаштуваннями проєкту. Скрипти, назва яких закінчується назвою середовища, як-от `db:migrate:preview` чи `deploy:production`, діють лише на це середовище.

Повний список наведено в розділі [Скрипти проєкту](/docs/tooling/scripts).
