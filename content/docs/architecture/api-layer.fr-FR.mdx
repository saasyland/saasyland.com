---
title: "Handlers HTTP de TanStack Start"
description: "Les endpoints HTTP sous /api, et quand en ajouter un plutôt qu'une fonction serveur."
---

Les opérations propres à l'application sont des fonctions serveur. Les handlers HTTP n'existent que là où un élément extérieur au client RPC de l'application appelle une URL : le client navigateur de Better Auth, les fournisseurs OAuth, les webhooks Polar et la CLI `saasyland`. La recherche de la documentation n'en a pas besoin : elle parcourt un index statique dans le navigateur (voir [Site de documentation](/docs/features/docs-site#search)).

| Fichier                      | Chemin                                       | Méthodes          | Traite                                                                                                                                                      |
| ---------------------------- | -------------------------------------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/routes/api/index.ts`    | `/api`                                       | GET               | Une réponse d'état JSON `{ runtime: "cloudflare-workers" }`                                                                                                 |
| `src/routes/api/auth.$.ts`   | `/api/auth/*`                                | GET, POST         | Tous les endpoints Better Auth, y compris les callbacks OAuth, la vérification d'e-mail, le portail client Polar et `/api/auth/polar/webhooks`              |
| `src/routes/api/cli.v1.*.ts` | <RepositoryFact name="cliApiBasePath" />`/*` | GET, POST, DELETE | L'[API de licence de la CLI](/docs/features/cli-licence-api) : la licence, ses machines et le bundle de modèles de chaque version, via `licenseApiHandlers` |

Le Worker répond aussi lui-même à `/media/<expiry>.<signature>/<videoId>/<file>`. Ce n'est pas une route : `src/server.ts` envoie ces requêtes à `serveMedia` (`src/modules/video/video.delivery.ts`) avant le middleware de langue et TanStack Start, et `serveMedia` vérifie la signature puis sert le fichier vidéo depuis le cache des Workers ou le bucket `MEDIA`. Voir [Cloudflare R2](/docs/integrations/cloudflare-r2). Il répond de la même manière à <RepositoryFact name="cliBundleUrlPath" /> : le handler de la zone des licences l'envoie à `serveBundle` (`src/modules/license/license.delivery.ts`), qui vérifie la signature et diffuse en flux le bundle de modèles de la CLI depuis le bucket `BUNDLES`. Voir [API de licence de la CLI](/docs/features/cli-licence-api#template-bundles).

Un handler se déclare avec `server.handlers` dans `createFileRoute`. Il reçoit la `Request` Web et renvoie une `Response` :

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Règles

- N'ajoutez pas d'endpoint REST pour une opération que seule cette application appelle. Écrivez plutôt un cas d'usage avec `createServerFn` : il bénéficie d'une entrée typée, des middlewares et des options de query.
- Un handler valide lui-même son entrée et vérifie lui-même les permissions. Les middlewares des fonctions serveur (`authorized`, `withRateLimit`) ne s'exécutent pas pour les handlers. L'API de licence de la CLI compte chaque requête et lit sa licence dans un seul batch D1 avec `rateLimitBatch` de `src/lib/rate-limit.ts`, lit une requête admise avec `readApiRequest` du contrat et répond à toute défaillance qui lui est propre, comme une panne de D1 ou de Polar, par `serviceUnavailable` du contrat.
- Laissez la vérification propre à un fournisseur dans son intégration. Les signatures des webhooks Polar sont vérifiées par le plugin Polar dans Better Auth, et non par un handler personnalisé.
- Les chemins `/api` et `/media` ne sont jamais localisés ni prérendus, et le Worker ne leur applique pas sa gestion des locales.
