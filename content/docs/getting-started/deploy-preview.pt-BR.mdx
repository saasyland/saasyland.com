---
title: "Deploy de um preview"
description: "Provisione os recursos da Cloudflare e faça o deploy do Worker de preview."
---

O ambiente `preview` faz o deploy do Worker `saasyland-preview` em `preview.saasyland.com`. Por padrão, `development` e `preview` compartilham um banco de dados D1 e um namespace KV.

## Provisionar os recursos

```sh
bunx wrangler login
bunx wrangler d1 create saasyland_com_preview
bunx wrangler kv namespace create CACHE --env preview
```

Em `wrangler.jsonc`, substitua `database_id`, `database_name` e o `id` do KV tanto em `development` quanto em `preview`. Mantenha os nomes de binding `DB` e `CACHE` e o `migrations_dir`, e atualize os nomes dos Workers e as rotas de domínio personalizado para a sua conta. Para produção, crie recursos separados e atualize o bloco `production`. Defina `APP_DOMAIN` em `src/presentation/branding/index.ts`. `appHostsForMode`, em `src/modules/_core/constants/api.ts`, deriva dele os hosts permitidos: `APP_DOMAIN` em produção, `preview.<APP_DOMAIN>` em preview e `localhost:3000` ou `127.0.0.1:3000` em desenvolvimento e teste. Edite `HOSTS_BY_MODE` nesse mesmo arquivo apenas se o seu host de preview tiver outro nome.

## Deploy

Preencha `.env.preview` e, em seguida, aplique as migrações e faça o deploy:

```sh
bun run db:migrate:preview
bun run deploy:preview
```

`deploy:preview` executa `scripts/verify-bindings.ts preview`, que rejeita IDs de placeholder, depois `build:preview`, que pré-renderiza as páginas públicas e verifica a saída, e por fim `wrangler deploy --secrets-file .env.preview`, que também envia os secrets. O build e o deploy nunca aplicam migrações; execute `db:migrate:preview` antes de fazer o deploy de código que precisa de um novo schema.

Registre os callbacks de OAuth e o webhook da Polar para o host de preview, conforme listado em [Variáveis de ambiente](/docs/getting-started/environment-variables).

## Deploys automáticos

A CI faz o deploy de todo pull request de uma branch deste repositório no preview compartilhado, e de todo push para `main` em produção, depois que as verificações e os testes no navegador passam. Veja [CI/CD](/docs/tooling/ci-cd) para os secrets do GitHub necessários.
