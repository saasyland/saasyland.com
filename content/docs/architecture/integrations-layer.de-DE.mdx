Jede Drittanbieter-Bibliothek und jeder Dienst, der eingerichtet werden muss, besitzt einen eigenen Ordner unter `src/integrations`. Die Dateien heißen `<prefix>.<concern>.ts`, wobei das Präfix der Kurzname des Anbieters ist.

| Ordner          | Dateien                                                                                                                                      | Zuständigkeit                                                                            |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `better-auth`   | `auth.server`, `auth.client`, `auth.access`, `auth.middleware`, `auth.routes`, `auth.session`, `auth.errors`, `auth.zod`, `auth.constraints` | Auth-Konfiguration, Rollen, Middleware für Server Functions, Route-Guards, Session-Query |
| `drizzle-orm`   | `drizzle.config`, `drizzle.database`, `drizzle.schemas`, `migrations/`                                                                       | Der D1-Client, die Schema-Registry und die SQL-Migrationen                               |
| `fumadocs`      | `fumadocs.config`, `fumadocs.source`, `fumadocs.docs`, `fumadocs.search`, `fumadocs.i18n`                                                    | MDX-Collections für Doku und Blog, Laden der Seiten und Suche                            |
| `motion`        | `motion.features`, `motion.tokens`                                                                                                           | Das lazy geladene Feature-Bundle von Motion und gemeinsame Transitions                   |
| `polar`         | `polar.config`, `polar.constants`                                                                                                            | Der Polar-SDK-Client und die im Checkout angebotenen Produkt-IDs                         |
| `resend`        | `resend.config`, `resend.utils`                                                                                                              | Der Resend-Client und `sendEmail`                                                        |
| `tanstack-form` | `form.fields`                                                                                                                                | Feldtypen und `fieldErrorMessage` für TanStack Form                                      |
| `use-intl`      | `i18n.config`, `i18n.messages`, `i18n.middleware`, `i18n.paths`, `i18n.utils`                                                                | Locales, Laden der Nachrichten, Locale-URLs und Cookies                                  |

## Was keine Integration ist

- Die Anzahl der GitHub-Sterne ist eine Server Function in `src/lib/github.ts`, gecacht in KV.
- Rate Limiting ist `src/lib/rate-limit.ts` und basiert auf der Tabelle `rate_limit`.
- Cloudflare-Bindings brauchen keinen Adapter. Servercode liest sie aus `env` in `cloudflare:workers`.

## Geschäftslogik bleibt in Modulen

Eine Integration konfiguriert einen Anbieter. Entscheidungen über Anwendungsdaten gehören in das Modul, dem die Tabelle gehört:

- Das Polar-Plugin in `auth.server.ts` prüft Webhook-Signaturen mit `POLAR_WEBHOOK_SECRET` und übergibt die Events an `licenseWebhookHandlers` in `src/modules/license/license.webhooks.ts`, die wiederum die Lizenz-Use-Cases aufrufen.
- Die E-Mail-Hooks von Better Auth rufen `sendVerifyEmail`, `sendResetPasswordEmail` und `sendChangeEmailConfirmationEmail` aus den Modulen verification und account auf.
- Ein Use Case versendet eine E-Mail, indem er den Namespace des Templates lädt, das Template rendert und `sendEmail` aufruft:

```ts
const locale = getCurrentLocale()
const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotencyKey: `verify-email/${token}`,
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```
