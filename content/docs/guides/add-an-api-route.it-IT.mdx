---
title: "Aggiungere una route API"
description: "Aggiungi un handler HTTP sotto /api per webhook e altri chiamanti esterni."
---

Le route API sono handler server di TanStack Start in `src/routes/api/`. Le schermate dell'applicazione non ne hanno mai bisogno: chiamano funzioni server. Aggiungi una route API solo per chiamanti esterni all'applicazione, come webhook, client di terze parti o crawler.

## Route esistenti

| File                       | Percorso      | Scopo                                                                                      |
| -------------------------- | ------------- | ------------------------------------------------------------------------------------------ |
| `src/routes/api/auth.$.ts` | `/api/auth/*` | Better Auth: accesso, callback OAuth, verifica email, checkout, portale e webhook di Polar |
| `src/routes/api/search.ts` | `/api/search` | Ricerca Fumadocs per la documentazione                                                     |
| `src/routes/api/index.ts`  | `/api`        | Controllo del runtime che restituisce `{ "runtime": "cloudflare-workers" }`                |

I webhook di Polar arrivano su `/api/auth/polar/webhooks`; il plugin Polar per Better Auth ne verifica la firma con `POLAR_WEBHOOK_SECRET` prima che `license.webhooks.ts` li gestisca.

## Scrivi un handler

Dichiara i metodi in `server.handlers`. Ogni handler riceve la `Request` web e restituisce una `Response` web:

```ts
import { createFileRoute } from "@tanstack/react-router"

import { search } from "~/src/integrations/fumadocs/fumadocs.search"

export const Route = createFileRoute("/api/search")({
  server: {
    handlers: {
      GET: ({ request }) => search.GET(request),
    },
  },
})
```

All'interno di un handler:

- Valida la query o il corpo con uno schema Zod e restituisci `HTTP_STATUS.BAD_REQUEST` (da `src/modules/_core/constants/api.ts`) quando la validazione fallisce. Se all'handler serve un nuovo stato, aggiungilo lì.
- Leggi la sessione con `getRequestSession(request)` e controllala con `hasPermission`. Il middleware di funzione, come `authorized`, vale per le funzioni server, non per gli handler.
- Limita le richieste agli endpoint pubblici con `withinRateLimit({ key, limit, windowSeconds })` e `clientAddress(request.headers)` di `src/lib/rate-limit.ts`.
- Verifica le firme prima di fidarti del contenuto di un webhook.
- Restituisci corpi di errore sicuri e registra i dettagli con `console.error`.

## Regole di routing

- I percorsi `/api` non hanno mai un prefisso di lingua e il Worker salta per essi la ricerca delle risorse statiche e i reindirizzamenti di lingua.
- Gli URL `/api` non contengono la lingua, quindi `getCurrentLocale()` lì restituisce la lingua predefinita. Una risposta localizzata prende la lingua dalla richiesta, come fa `/api/search` con il parametro di query `locale`.
- `/api` è escluso dal prerendering.

## Test

Chiama l'handler tramite le opzioni della route, come fa `src/routes/api/__test__/handlers.test.ts` con `Route.options.server.handlers`, e simula il provider a cui inoltra la richiesta.
