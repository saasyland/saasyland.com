## Fonts

Geist and Geist Mono are self-hosted as variable WOFF2 subsets in `public/fonts`, served with a one-year immutable cache (`public/_headers`). `src/presentation/styles/fonts.css` declares an `@font-face` per unicode range (Latin, Latin Extended, Cyrillic), metric-matched fallback faces, and the `--font-geist-sans` and `--font-geist-mono` variables. `globals.css` maps them to `--font-sans`, `--font-heading` and `--font-mono`. Japanese text falls back to the system font stack. Geist sets all text; Geist Mono is kept for code, commands, keys and identifiers. See [Theme](/docs/ui/theme#type-scale).

## Preloads

`src/presentation/document-assets.ts` exports `DOCUMENT_STYLESHEET` (`globals.css`) and the font preloads for a locale:

```ts
export const fontPreloads = (locale: SupportedLocale) => {
  const fonts = [GEIST_LATIN, GEIST_MONO_LATIN]
  if (locale === "pl-PL") {
    fonts.push(GEIST_LATIN_EXT)
  } else if (locale === "uk-UA") {
    fonts.push(GEIST_CYRILLIC)
  }
  return fonts
}
```

The root route adds them as `link` tags, and the Worker (`src/server.ts`) sends the same fonts in a `Link` preload header on every HTML response, which Cloudflare replays as Early Hints. The font file names are content hashes: when you replace a font, update both `fonts.css` and `document-assets.ts`.

## Brand constants

`src/presentation/branding/index.ts` is the single source of the brand:

```ts title="src/presentation/branding/index.ts"
export const APP_NAME = "SaaSy Land"
export const APP_SLUG = "saasyland"
export const APP_LOGO_PATH = "M6 0H15V9H24V18A6 6 0 0 1 18 24H6A6 6 0 0 1 0 18V6A6 6 0 0 1 6 0Z"
export const APP_DOMAIN = "saasyland.com"
export const APP_PREVIEW_DOMAIN = `preview.${APP_DOMAIN}`

export const APP_URL = `https://${APP_DOMAIN}`
export const CONTACT_EMAIL = `hello@${APP_DOMAIN}`
export const NOTIFICATIONS_EMAIL = `notifications@${APP_DOMAIN}`

export const APP_FOUNDED_YEAR = 2023

export const APP_GITHUB_OWNER = "saasyland"
export const APP_GITHUB_REPO = APP_DOMAIN
export const APP_GITHUB_OWNER_URL = `https://github.com/${APP_GITHUB_OWNER}`
export const APP_GITHUB_URL = `${APP_GITHUB_OWNER_URL}/${APP_GITHUB_REPO}`

export const APP_INSTAGRAM_URL = "https://www.instagram.com/saasyland/"
```

They feed the Better Auth app name and 2FA issuer, the theme and locale cookie names, the allowed hosts, the footer, the docs navigation, the GitHub star count, the structured data of the home page and blog posts, and the email senders and recipients. `APP_GITHUB_OWNER_URL` and `APP_INSTAGRAM_URL` are the organisation's profiles on other sites: the footer links the Instagram profile next to the repository, and the structured data lists both in `sameAs`; see [Search and social previews](/docs/features/seo#structured-data).

## Logo and media

- `Wordmark` (`src/presentation/components/custom/wordmark.tsx`) renders the logo, `APP_LOGO_PATH`, as inline SVG next to `APP_NAME`. The social cards draw the same path with the same fonts; see [Search and social previews](/docs/features/seo). `HomeLink` (`home-link.tsx`) makes it the link home in the landing, blog and course headers; see [Landing page](/docs/features/landing-page).
- The favicon is `public/favicon.ico`; blog images live in `public/images/blog`.
- Landing-page videos live in `src/presentation/assets/motion` as WebM files with WebP posters. A poster must keep the dimensions of its video. The course tour, which plays on request with controls, also has an MP4 fallback and AVIF posters.
