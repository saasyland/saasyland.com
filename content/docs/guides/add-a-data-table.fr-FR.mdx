description: "Écrivez un hook de colonnes avec des filtres, des colonnes masquées et épinglées et des valeurs CSV, puis affichez-le avec DataGrid à partir de lignes côté client ou d'une query serveur."

Chaque nouveau tableau s'affiche avec `DataGrid` dans `src/presentation/components/custom/data-grid.tsx` ([Grille de données](/docs/ui/data-grid)). Il apporte la recherche, les filtres, le tri, la disposition que chaque administrateur peut réorganiser et conserver, la sélection, l'export CSV, les lignes squelettes et les états vides. Un tableau a besoin d'un hook de colonnes et d'un `<DataGrid />`. `/admin/orders` est l'exemple complet : `src/presentation/components/custom/admin/payments/order-columns.tsx` et `src/routes/admin.orders.index.tsx`.

## 1. Écrire le hook de colonnes

Créez `<entity>-columns.tsx` à côté des autres widgets de la page. Exportez un hook qui lit les traductions et les données que proposent les filtres, et qui renvoie les colonnes mémoïsées. Les cellules sont de petits composants du même fichier qui lisent leurs propres traductions. Version condensée de `order-columns.tsx` :

```tsx
const columnHelper = createColumnHelper<DataGridFeatures, OrderRow>()

export const useOrderColumns = (): DataGridColumn<OrderRow>[] => {
  const t = useTranslations()

  const { products } = useSuspenseQuery(orderFiltersQuery).data

  return useMemo(
    () =>
      columnHelper.columns([
        columnHelper.accessor("placedAt", {
          cell: PlacedCell,
          header: t("pages.admin.orders.table.headers.placedAt"),
          meta: { filter: { kind: DATA_GRID_FILTER.DATE_RANGE }, pinned: DATA_GRID_PIN.START },
          size: ORDER_COLUMN_SIZES.placedAt,
        }),
        columnHelper.accessor("description", {
          cell: ProductCell,
          enableSorting: false,
          header: t("pages.admin.orders.table.headers.product"),
          id: "product",
          meta: { filter: { kind: DATA_GRID_FILTER.MULTI_SELECT, options: products.map(({ id, name }) => ({ label: name, value: id })) } },
          size: ORDER_COLUMN_SIZES.product,
        }),
        columnHelper.accessor("refunded", {
          cell: RefundedCell,
          header: t("pages.admin.orders.table.headers.refundedAmount"),
          id: "refundedAmount",
          meta: { export: ({ refunded }) => exportedMoney(refunded), hidden: true },
          size: ORDER_COLUMN_SIZES.refundedAmount,
        }),
      ]),
    [products, t],
  )
}
```

- Les lignes doivent avoir un `id` de type chaîne ; il sert d'identifiant de ligne pour la sélection.
- `header` est le libellé traduit, sous forme de chaîne. La grille l'utilise dans l'en-tête, les menus, les puces de filtre, ses annonces et le CSV.
- `meta.filter` donne à la colonne un filtre d'un type : <RepositoryFact name="dataGridFilterKinds" />. Un choix liste ses `options` sous la forme `{ label, value }`.
- `meta.hidden` masque la colonne jusqu'à ce que l'administrateur l'affiche, `meta.pinned` l'épingle côté `start` ou côté `end`, et `meta.export` écrit le texte CSV de la colonne pour une ligne.
- `size` est la largeur de départ en pixels. Gardez les tailles dans une constante de `src/data/<feature>.ts`, comme `ORDER_COLUMN_SIZES` dans `payments.ts`, pour que le squelette de la route puisse aussi s'en servir.
- Une colonne selon laquelle le serveur ne peut pas trier définit `enableSorting: false`.

## 2. L'afficher

Passez les colonnes, un `id` unique, le `label` du tableau et soit `data`, soit `query` :

```tsx
const OrdersPage = (): JSX.Element => {
  const t = useTranslations("pages.admin.orders")
  const columns = useOrderColumns()

  return (
    <DataGrid
      columns={columns}
      empty={t("empty")}
      id={ORDER_GRID_ID}
      label={t("title")}
      query={(request) => getOrdersPageQuery(orderZodSchemas.getOrders.parse(request))}
      search={t("filters.search")}
      selectable
    />
  )
}
```

Avec `data`, la grille recherche, filtre, trie et pagine les lignes dans le navigateur. Avec `query`, elle envoie `{ filters, pageIndex, pageSize, search, sorting }` et le serveur fait tout cela.

## 3. Lire la demande sur le serveur

Le schéma Zod du module prend la demande telle quelle. `filters` contient les colonnes filtrées par identifiant avec les valeurs décrites dans [Grille de données](/docs/ui/data-grid#filters), si bien que le schéma réutilise les champs partagés, depuis `src/modules/order/order.zod.ts` :

```ts
const orderFilters = zod.object({
  country: zod.array(countryCodeField).max(COUNTRY_CODES.length).optional(),
  customer: searchField.optional(),
  discount: idField.optional(),
  placedAt: dateRangeField.optional(),
  product: zod.array(idField).max(MAX_FILTER_VALUES).optional(),
  status: zod.array(choiceOf(ORDER_STATUSES)).max(ORDER_STATUSES.length).optional(),
  totalAmount: numberRangeField.optional(),
})

const getOrders = paginationSchema.extend({
  filters: orderFilters.default({}),
  search: searchField.default(""),
  sorting: sortingOf(ORDER_SORT_COLUMNS),
})
```

`numberRangeField`, `dateRangeField` et les limites `SEARCH_MAX_LENGTH`, `MAX_SORTED_COLUMNS` et `MAX_FILTER_VALUES` viennent de `src/modules/_core/utils/`, les mêmes valeurs que celles de la grille, si bien que le champ de recherche accepte <RepositoryFact name="dataGridSearchMaxLength" /> caractères et que la grille trie selon <RepositoryFact name="dataGridMaxSortedColumns" /> colonnes au plus. `getOrders` transforme chaque filtre en SQL ; une plage de montants compare chaque commande dans sa propre devise avec `inMinorUnits`.

Préchargez la première page dans le loader de la route avec `context.queryClient.query({ ...getOrdersQuery, staleTime: "static" })` ; la première demande de la grille se ramène à la même clé de query.

## 4. Le reproduire dans le squelette

Le `pendingComponent` de la route affiche `DataGridPending` de `data-grid-pending.tsx` avec un squelette de cellule et une largeur par colonne visible, comme le fait `AdminOrdersPending` dans `payments-pending.tsx`.

## 5. Messages

La barre d'outils, les filtres, les menus, la pagination, la sélection et les états vides de la grille proviennent de `components.custom.data-grid`, chargé par toutes les pages. Les libellés de colonnes, les options de filtre et le message vide appartiennent à l'espace de noms de la page, comme `pages.admin.orders`.

Lorsqu'une mutation modifie les lignes, invalidez les clés de query du module ; la grille recharge la page courante. Voir [Ajouter un cas d'usage](/docs/guides/add-a-use-case).
