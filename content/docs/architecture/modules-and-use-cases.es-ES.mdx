## Módulos

Un módulo en `src/modules/<table>` existe solo para una tabla real de la base de datos. Contiene:

- `<table>.schema.ts`: la tabla de Drizzle, reexportada por `src/integrations/drizzle-orm/drizzle.schemas.ts`
- `<table>.zod.ts`: los esquemas de entrada, que usan tanto los formularios como las funciones de servidor
- `<table>.constants.ts`: claves de consulta y de mutación, enums
- `<table>.types.ts` y `<table>.utils.ts`: cuando la tabla los necesita
- `use-cases/<operation>.ts`: una operación por archivo

Módulos actuales: account, category, license, newsletter-subscriber, product, rate-limit, session, two-factor, user y verification. Las constantes y utilidades compartidas viven en [`_core`](/docs/architecture/core). Una función de servidor que no trabaja sobre una tabla va en `src/lib` o en la única ruta que la usa.

## Casos de uso

La mayoría de los casos de uso son funciones de servidor a las que se llama desde el navegador. Cada archivo exporta la `createServerFn` y sus opciones de consulta o de mutación:

```ts
import { mutationOptions } from "@tanstack/react-query"
import { createServerFn } from "@tanstack/react-start"
import { v7 } from "uuid"
import type * as zod from "zod"

import { authorized } from "~/src/integrations/better-auth/auth.middleware"
import { db } from "~/src/integrations/drizzle-orm/drizzle.database"

import { CATEGORY_MUTATION_KEYS } from "~/src/modules/category/category.constants"
import { category } from "~/src/modules/category/category.schema"
import { categoryZodSchemas } from "~/src/modules/category/category.zod"

export const createCategory = createServerFn({ method: "POST" })
  .middleware([authorized({ category: ["create"] })])
  .validator((input: zod.input<typeof categoryZodSchemas.createCategory>) => categoryZodSchemas.createCategory.parse(input))
  .handler(({ data }) =>
    db
      .insert(category)
      .values({
        description: data.description ?? "",
        icon: data.icon ?? "FolderOpen",
        id: v7(),
        kind: data.kind,
        name: data.name,
        visibility: data.visibility ?? "public",
      })
      .returning()
      .get(),
  )

export const createCategoryMutation = mutationOptions({
  mutationFn: (data: Parameters<typeof createCategory>[0]["data"]) => createCategory({ data }),
  mutationKey: CATEGORY_MUTATION_KEYS.CREATE,
})
```

- **El middleware** viene de `src/integrations/better-auth/auth.middleware.ts`. `authorized()` exige una sesión, `authorized({ category: ["create"] })` además comprueba un permiso, y `withRateLimit(kind, RATE_LIMITS.SENSITIVE)` limita las operaciones públicas.
- **La validación** parsea la entrada con el esquema Zod del módulo antes de que se ejecute el handler.
- **La propiedad de los datos** se determina a partir de la sesión. Las operaciones sobre los datos del propio usuario filtran por `context.auth.user.id` y nunca se fían de un ID de usuario que llegue en la entrada.
- **Los errores** se lanzan como `new AppError(ERROR_CODES.X)`. Cualquier otro error se registra y llega al cliente como `INTERNAL_ERROR`.
- **Las lecturas** exportan en su lugar `queryOptions`, por ejemplo `getCategoriesPageQuery(input)`, que resuelve `{ rows, total }` para la tabla de datos.

Algunos casos de uso son funciones async normales que solo se ejecutan en el servidor y no tienen endpoint RPC, como `send-verify-email.ts` o `grant-license.ts`. Los llaman los hooks de Better Auth y los handlers de webhooks de Polar.

## Llamar a un caso de uso desde un componente

Los componentes expanden las opciones exportadas en `useMutation`, traducen los errores con `useErrorMessage()` e invalidan las claves de consulta del módulo cuando la operación tiene éxito:

```tsx
const t = useTranslations("pages.admin.users.actions")
const queryClient = useQueryClient()
const errorMessage = useErrorMessage()

const deleteUser = useMutation({
  ...deleteUserMutation,
  onError: (error) => {
    toast.error(errorMessage(error))
  },
  onSuccess: async () => {
    await queryClient.invalidateQueries({ queryKey: USER_QUERY_KEYS.ALL })
    toast.success(t("feedback.deleteSuccess"))
  },
})
```
