- Виправлено: API ліцензій для CLI повідомляв про власні збої не тією помилкою. Коли D1 не міг порахувати запит, обмеження запитів відхиляло його, і CLI казав, що запитів забагато; коли D1 не міг прочитати ліцензію або Polar відхиляв запит у спосіб, якого контракт не називає, Worker відповідав HTTP 500, який CLI не вміє прочитати, тож він просив користувача оновити CLI. Тепер кожен ендпоінт, зокрема ендпоінт бандлів, відповідає на будь-який збій сайту кодом `serviceUnavailable` із `retry-after`. Перехоплює його лише `serve` у `license.api.ts` і записує в лог `[license] <method> <path> failed` з помилкою, її причиною та стеком викликів, із `[licence key]` замість ключа того, хто викликає, який інакше потрапив би до Workers Logs у помилках запитів Drizzle і помилках валідації Polar. API рахує запити через `countRequest`, що кидає помилку, коли збоїть його сховище; вхід, серверні функції та ліміти листів і далі використовують `consumeRateLimit`, що, як і раніше, відхиляє запит, якого не може порахувати. Див. [API ліцензій для CLI](/docs/features/cli-licence-api).
