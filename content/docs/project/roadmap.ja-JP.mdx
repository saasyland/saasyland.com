## いま取り組んでいること

- CLI での Polar による課金。下に挙げるオプションの最初の項目です。その元になるアプリケーションの汎用的な課金はすでに公開しています。どの Polar 製品でも購入できるチェックアウト、`/admin/products` の Polar カタログ、アカウントの注文・サブスクリプション・請求書と Polar のカスタマーポータルをまとめた請求ページ、そしてその上に作ったライセンスです。まず CLI のテンプレートをアプリケーションの現状に合わせ、そのうえでチェックアウト、Webhook、注文とサブスクリプションのコピー、カスタマーポータル、生成される管理画面の注文と顧客を加えます。
- 管理画面の設定でのビジネスプロフィール。名前、サポート用のメールアドレス、住所、ロゴ（アプリケーション）。
- 既知の制限事項でテストがないとされているすべてのフローに、ブラウザーテストを用意します。

## 次に取り組むこと

- Polar による課金に続くオプション。下のリストの順に、追加機能のサブスクリプション型コース、Stripe による課金、Plunk によるメール、Prisma、Docker によるセルフホスティング、分割アーキテクチャ、追加機能のリアルタイムです。

## CLI：コンフィギュレーターのすべてのオプション

[コンフィギュレーター](/#cli)には、CLI のスタックパッケージにあるすべてのオプションと追加機能が表示されており、CLI はそのすべてを生成するようになります。さらに 2 つを計画しており、そのパッケージのリリースとともにコンフィギュレーターに加わります。Prisma を通じた MongoDB と、追加機能のリアルタイムです。オプションがコンフィギュレーターで有効になり、`init` に受け付けられるのは、そのオプションで生成したプロジェクトが、それに影響しうるすべての変更について、CI でインストール、型チェック、<RepositoryFact name="coverageThreshold" />% のカバレッジでのテスト合格、ビルド、起動まで通ったときだけです。それまでは、コンフィギュレーターでは無効として表示され、`init` はライセンスを確認する前に終了コード <RepositoryFact name="cliExitNotAvailable" /> で拒否します。

回答の中には、ほかの回答に左右されるものがあります。API の質問は分割 API とマイクロサービスのアーキテクチャにだけ関係し、ランタイムやプロバイダーの中には、Cloudflare Workers 上の Bun ランタイムのように、すべてのデプロイ先で動くわけではないものがあります。コンフィギュレーターは、デプロイ先で動かせない組み合わせを無効にします。

オプションは次の順で提供します。

1. Polar による課金と、生成される管理画面の注文と顧客（いま取り組んでいること）。
2. 追加機能のサブスクリプション型コースと、生成される管理画面のコース。課金が前提です。
3. Stripe による課金と、Plunk によるメール。
4. Prisma。まず Cloudflare D1 で、その後は各データベースの提供に合わせて対応します。続いて Prisma を通じた MongoDB。Drizzle では MongoDB を使えません。
5. Docker による自前のサーバー。root 以外のユーザーで動き、ヘルスチェックを備え、シークレットをどのレイヤーにも残さない本番用イメージ、データベースと TLS プロキシを含む Compose の構成、CI でのイメージのビルドとスキャン、そしてアップグレードとバックアップのガイド。
6. 分割アーキテクチャ。Web アプリ、Hono の API、共有コントラクトからなるモノレポで、oRPC がそのコントラクトから Web アプリへの型付きの呼び出しと、OpenAPI の定義付きの REST API を提供します。
7. 追加機能としてのリアルタイム。すべてのランタイムでのサーバーからブラウザーへのストリーミング、双方向の WebSocket（Cloudflare Workers では Durable Objects、Node と Bun では Hono の WebSocket ヘルパー）、そして生成される管理画面での両方のライブデモ。
8. メールを外す回答と、コンテンツを外す回答。メールがない場合、サインインにはメールを送らないフローが必要です。コンテンツがない場合、生成されたプロジェクトのエージェント向け指示が参照するコーディング規約を、ドキュメントの外に置く必要があります。
9. Neon、Supabase、または自前のサーバー上の Postgres。Turso。ローカルの SQLite ファイル。
10. Vercel へのデプロイ。Bun と Deno のランタイム。
11. Elysia の API、続いてマイクロサービス。
12. React 向けの Next.js と React Router。
13. Solid と SolidStart・TanStack Start、Vue と Nuxt、Svelte と SvelteKit、Angular と Analog・Angular SSR。
14. マルチテナント。アプリケーションに組織とロールが入ってからです。
15. サンプル商品付きストア、ビジュアルページビルダー、ビジュアル投稿エディター。いずれも、それぞれが生成する機能をアプリケーションがリリースした後です。

### コマンドとリリース

- ターミナルでの対話式の質問。現在のターミナルのセッションは、`--yes` と同じように、フラグで渡さなかった質問すべてに既定値で答えます。
- プロジェクトのリリース、回答、ライセンスを表示する `status`。
- 既存のプロジェクトに対して、別の回答で CLI をもう一度実行する `change`。まずモジュールを、プラットフォームの切り替えはその後に対応します。
- プロジェクトを 1 つのコマンドで新しいリリースに更新する `update`。3 方向マージで、自分で加えた編集を残します。update と change のシナリオは、最近のリリースをまたいで毎晩実行します。
- [CLI ガイド](/docs/cli)に載せる、すべてのコマンドとフラグの自動生成リファレンスと、CLI のアップグレード、ライセンスキーのローテーション、トラブルシューティング、プロジェクトの更新と変更の各ガイド。ガイドにあるすべてのコマンドは、テスト対象の CLI に対して CI で実行します。
- CLI 自身の README とリリース関連のドキュメントを修正する、次のベータ版。
- npm の既定タグでの安定版リリース。それまでは、CLI を <RepositoryFact name="cliPackageSpec" /> として実行してください。安定版をリリースするのは、課金と追加機能のサブスクリプション型コースが入り、夜間のジャーニースイートがパッケージマネージャーごとにプロジェクトを生成し、ビルドし、テストを実行し、ライセンスをエンドツーエンドで確認するようになったときです。そのうえで、サイトのコマンドを既定タグに切り替え、リリースノートとリリース記事を公開します。

## アプリケーション

1. 管理画面の設定でのビジネスプロフィール。名前、サポート用のメールアドレス、住所、ロゴ（いま取り組んでいること）。
2. サイト上の価格を Polar から読み込み、価格を 1 か所で変えられるようにします。
3. Polar を通じた、管理画面からの商品の作成、編集、削除。一回払いと定期払いの料金モデル。割引コード。
4. 注文ページからの返金（注文ページには、Polar に記録された返金がすでに表示されています）。ライセンスが返金または取り消されたときの購入者へのメール。そして注文ページでの支払いの異議申し立てと、その結果のライセンスへの反映。
5. ライセンスページからの下位プランへの変更。現在はサポートへのメールで対応しています。
6. 実データに基づくダッシュボードの指標。プライバシーに配慮した、サインアップとチェックアウトのファネル計測。ページビュー、訪問者、リテンション、チャーンを表示するアナリティクス画面。
7. 顧客ワークスペースでのニュースレターのオン・オフ。
8. 権限。エディターのロール、権限で絞り込まれるメニュー、ロールエディター。
9. 組織とチーム、続いて Agency のチーム席。
10. アカウント停止、削除、なりすましの監査ログ。
11. プルリクエストを通じて Git にコミットするビジュアルエディターでの、管理画面からのブログ編集。続いてドキュメントの編集。
12. セクションのレジストリから組み立てるランディングページ。続いてビジュアルなページデザイナー、料金ページ、セクションライブラリ、キャンペーンページ。
13. アフィリエイトプログラムの開始。
14. 埋め込みチェックアウトでの Apple Pay と Google Pay。埋め込みチェックアウトでこれらを使うには、Polar 側で有効にしてもらう必要があります。

その後：

- ストアフロントでの販売。追加機能のストアと marte-bizuteria.pl の事例が、これを待っています
- 高度なアナリティクスのパイプライン

- アップロード中のブラウザーでのエンコード。これにより、エンコードの工程を別に設けなくても、レッスンの動画がすぐに使えるようになります。
- 管理画面で、アップロードと一緒に字幕を追加できるようにします。
- コースとレッスンの Markdown の説明文と、動画ごとの詳細ページ。
- 生成するプロジェクト向けの、追加機能のサブスクリプション型コース（CLI）。

## コンテンツとドキュメント

- AI エンジニアリングのシリーズの続き。ごまかさずに達成する 100% カバレッジ、実際の SaaS の AGENTS.md の注釈付き解説、そしてもう 1 本の記事。
- 記事に出てくる SaaSy Land に関するすべての数値をコードから出力します。Cloudflare の記事の計測値も含みます。あわせて、タイトルのないコードの抜粋、「最終更新」の行、手入力のステータスを防ぐガードを設けます。
- ランディングページの機能の数を、このリポジトリの数と並べて、生成されるプロジェクトの中身から出力します。
- 細かな修正。いくつかのメッセージの文言と、古いフォルダ構成のままのコースの文章。
- 最新のスクリーンショットと、コードから生成するバッジを載せた、より短い README。
- 言語ごとのスタイルガイドと用語集を使った、すべての翻訳のネイティブ品質でのレビュー。ドイツ語から始めます。ポーランド語は完了しています。

## 品質とエンジニアリング

- 夜間のジャーニースイートをプレビューサイトと Polar のサンドボックスに対して実行し、その後、CLI でプロジェクトを生成し、パッケージマネージャーごとにビルドしてテストを実行するところまで広げます。
- 下の表で未カバーとして挙げているすべてのフローのブラウザーテスト。まだ実装していないフローには、機能のリリースに合わせてテストを加えます。
- ライセンス、決済、アクセス制御のコードに対するミューテーションテストと、Playwright のスイートによるブラウザーのコードカバレッジ。
- 非 null アサーションと空の `catch` ブロックを禁じる lint ルールと、コーディングエージェント向けのガードレール。チェック付きのルールのレジストリ、規約から生成しドリフトを検出するリポジトリのスキル、そしてコミットされたフック。
- 生成されるプロジェクトで境界を守らせる lint ルールと、最新の依存関係で生成されるプロジェクトの毎晩のビルド。
- パフォーマンス。管理コンソール、商品ページ、請求ページの遅いセクションをスケルトンへストリーミングすること、ログインしていない訪問者向けに講座ページをエッジでキャッシュすること、modulepreload の除去の A/B テスト、Worker の Server-Timing、そしてライセンスの有効化をページにストリーミングすること。
- 依存関係を最新のリリースに保ち、修正がアップストリームでリリースされたパッチはそのつど外します。
- 以前の Next.js のコードベースの古い Issue を、説明を添えてクローズします。

現時点で部分的なもの：

- 生成されるプロジェクトの管理画面にあるのは、ダッシュボード、ユーザー、設定です。サインインを外すと、管理画面も外れます。
- 返金は注文ページに表示されますが、返金の手続きは Polar のダッシュボードで行います。
- 下位プランへの変更はメールで受け付けています。
- レッスンの動画は、アップロードの後に FFmpeg を備えたマシンでエンコードし、字幕はコマンドラインから追加します。
- 購読者は顧客ワークスペースからニュースレターをオン・オフできません。配信を止めるには、各号にある配信停止リンクを使います。
- どのコースのレッスンにも「収録中」と表示されます。
- ライセンスが必要な CLI のコマンドは、どれもライセンスをオンラインで確認します。オフラインモードはありません。
- アフィリエイトプログラムはまだ始まっていません。アフィリエイトのページでは、参加を希望するパートナーに連絡を呼びかけています。
- 夜間のジャーニースイートは、まだ一度も実行を完了していません。
- `updates.yml` は UTC のスケジュール <RepositoryFact name="updatesSchedule" /> で依存関係の更新を確認します。実行の合間には最新リリースより遅れるパッケージがいくつかあり、パッチを当てたパッケージは、その修正がアップストリームでリリースされるまで固定されたままです。
