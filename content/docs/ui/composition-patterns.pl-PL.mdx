## Trasy składają strony

Plik trasy definiuje komponent `<Name>Page` lub `<Name>Layout`, `NAMESPACE` lub `NAMESPACES`, loader i `head`. Strona jedynie rozmieszcza widżety; widżety znajdują się w `src/presentation/components/custom/<area>/`. Tak wygląda layout (`src/routes/app.tsx`):

```tsx title="src/routes/app.tsx"
const AppLayout = (): JSX.Element => (
  <SidebarProvider className="h-svh overflow-hidden">
    <AppSidebar />
    <SidebarInset className="relative min-h-0 min-w-0 overflow-hidden">
      <Background className="z-[-1]" glow={false} />
      <ImpersonationBanner />
      <AppHeader />
      <div
        className="custom-scrollbar flex min-h-0 flex-1 flex-col overflow-y-auto px-4 pt-5 pb-6 md:px-6 md:pt-7 md:pb-8"
        data-page-scroller
      >
        <div className="mx-auto w-full max-w-5xl">
          <EmailVerificationBanner />
          <Outlet />
        </div>
      </div>
    </SidebarInset>
  </SidebarProvider>
)
```

Zamiast okna przewija się obszar treści, dlatego ma on `data-page-scroller`; zobacz [Paski przewijania](/docs/ui/theme#scrollbars).

Funkcję serwerową używaną tylko przez jedną trasę można zdefiniować w pliku tej trasy za pomocą `createServerFn`.

## Jeden widżet, okno dialogowe lub formularz na plik

Każdy widżet, okno dialogowe, formularz lub zestaw kolumn ma własny plik: `admin/users/row-actions.tsx`, `delete-user-dialog.tsx`, `reset-password-dialog.tsx`, `user-columns.tsx`. Foldery komponentów są płaskie: bez podfolderów `components/`, `hooks/`, `constants/` ani `types/` i bez podziału na `x.tsx` oraz `x-content.tsx`. Komponenty współdzielone leżą bezpośrednio w `custom/`.

## Komponenty same odczytują swoje dane

Komponent sam pobiera teksty i dane, zamiast dostawać je w propsach:

- tłumaczenia przez `useTranslations`;
- dane zapytań przez `useSuspenseQuery`, wcześniej pobrane przez loader trasy;
- dane loadera, kontekst trasy i parametry adresu URL przez `getRouteApi("…")`.

```tsx title="src/presentation/components/custom/blog/post-meta.tsx"
const route = getRouteApi("/_site/_marketing/blog/$")

const timeTag =
  (value: Date) =>
  (chunks: ReactNode): JSX.Element => (
    <time className="tabular-nums" dateTime={value.toISOString()}>
      {chunks}
    </time>
  )

export const PostMeta = (): JSX.Element => {
  const { post } = route.useLoaderData()
  const t = useTranslations("pages.blog")
  const format = useFormatter()

  const published = new Date(post.date)
  const updated = new Date(post.updated ?? post.date)
  const dateOf = (value: Date): string => format.dateTime(value, "calendarDate", { month: "long" })
  const tags = post.tags.map((tag) => t(`tags.${tag}`)).join(", ")
  const details = [BLOG_AUTHORS[post.author].name, t("post.readingTime", { minutes: post.readingTimeMinutes }), tags].filter(
    (item) => item.trim().length > 0,
  )

  return (
    <div className="flex flex-wrap items-center gap-x-3 gap-y-2 py-1 text-body-sm text-muted-foreground tabular-nums">
      <span className="flex items-center gap-2.5">
        <span aria-hidden className="size-1.25 shrink-0 rounded-full bg-ring" />
        <span>{t.rich("post.published", { date: dateOf(published), time: timeTag(published) })}</span>
      </span>
      {updated.getTime() > published.getTime() && (
        <span className="flex items-center gap-3">
          <span aria-hidden className="text-border">
            &middot;
          </span>
          <span>{t.rich("post.updated", { date: dateOf(updated), time: timeTag(updated) })}</span>
        </span>
      )}
      {details.map((item) => (
        <span className="flex items-center gap-3" key={item}>
          <span aria-hidden className="text-border">
            &middot;
          </span>
          {item}
        </span>
      ))}
    </div>
  )
}
```

Propsy przekazują tożsamość lub stan znany tylko rodzicowi, na przykład `user` okna dialogowego razem z `isOpen` i `onOpenChange` albo `activationId`. Nie ma propsów z tekstem ani etykietami, prop drillingu ani komponentów opakowujących, które tylko zmieniają nazwy propsów lub przekazują dzieci. Stała używana w jednym pliku zostaje w tym pliku; dane współdzielone przez wiele plików trafiają do `src/data`.

## Tekst sformatowany

Mapy znaczników dla `t.rich` to stałe na poziomie modułu, nigdy obiekty tworzonymi podczas renderowania:

```tsx
const REUSE_TAGS = { accent: (chunks: ReactNode) => <strong className="font-medium text-foreground">{chunks}</strong> }
```

## Klasy warunkowe

Używaj `cn` z `~/src/lib/cn` ze składnią obiektową:

```tsx
<p className={cn("font-medium", { "text-foreground": !banned, "text-muted-foreground line-through": banned })}>{name}</p>
```

Alternatywy renderuj za pomocą pary warunków `&&` lub wczesnego powrotu zamiast wielowierszowego operatora trójargumentowego.

## Providery

Providery, które zmieniają się po hydratacji, otaczają tylko potrzebujące ich widżety, nigdy `Outlet` trasy: `ThemeProvider` otacza `Toaster` i `ThemeSwitch` dokumentacji, a `MotionProvider` sekcje strony głównej, listę wpisów bloga, strony archiwum bloga i karty pakietów w `LicenseOffer`. `AriaProvider` otacza główny outlet, a `TranslationsProvider` body dokumentu, ponieważ potrzebuje ich każdy ekran.
