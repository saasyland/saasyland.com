Cloudflare D1 (SQLite) — це база даних застосунку, прив'язана як `DB`. `src/integrations/drizzle-orm/` підключає її до Drizzle:

| Файл                  | Призначення                                                                                      |
| --------------------- | ------------------------------------------------------------------------------------------------ |
| `drizzle.database.ts` | Серверний `db`, створений через `drizzle(env.DB, { schema })`                                    |
| `drizzle.schemas.ts`  | Повторно експортує схему кожної таблиці та її зв'язки                                            |
| `drizzle.config.ts`   | drizzle-kit: діалект SQLite, драйвер `d1-http`, міграції з префіксом-міткою часу в `migrations/` |

## Таблиці

Кожна таблиця має власний модуль у `src/modules/<table>/` з `<table>.schema.ts` (`drizzle-orm/sqlite-core`), `.zod.ts`, `.constants.ts`, `.types.ts`, `.utils.ts` і `use-cases/`. Модулі: `account`, `category`, `license`, `newsletter-subscriber`, `product`, `rate-limit`, `session`, `two-factor`, `user` і `verification`. Код, який не володіє таблицею, не отримує модуля.

Схеми дотримуються однакових конвенцій:

- Ідентифікатори — це рядки UUID v7.
- Дати — це стовпці `integer` у режимі `timestamp_ms` з типовим значенням `unixepoch() * 1000`.
- Булеві значення — це стовпці `integer` у режимі `boolean`.
- Зв'язки, індекси, обмеження унікальності та зовнішні ключі оголошуються в схемі.

## Атомарні записи

D1 не підтримує інтерактивних транзакцій. Зберігайте атомарність операції за допомогою одного запиту, наприклад upsert з `onConflictDoUpdate`, або групуйте запити через `db.batch`. Сценарії використання посторінкових списків отримують сторінку та загальну кількість в одному пакеті (`src/modules/category/use-cases/get-categories.ts`):

```ts
const filter = data.kind === undefined ? undefined : eq(category.kind, data.kind)
const [rows, totals] = await db.batch([
  db
    .select()
    .from(category)
    .where(filter)
    .orderBy(desc(category.createdAt), desc(category.id))
    .limit(data.pageSize)
    .offset(data.pageIndex * data.pageSize),
  db.select({ total: count() }).from(category).where(filter),
])
return { rows, total: totals.reduce((sum, row) => sum + row.total, 0) }
```

Обмежувач частоти запитів у `src/lib/rate-limit.ts` поєднує очищення, атомарний upsert і читання в одному пакеті, тож екземпляри Worker мають спільні ліміти.

## Міграції

Міграції — це SQL-файли в `src/integrations/drizzle-orm/migrations/`, які генерує `bun run db:generate` і застосовує Wrangler. Vitest запускає їх на SQLite-базі в пам'яті. Команди описано в розділі [Міграції бази даних](/docs/tooling/database).
