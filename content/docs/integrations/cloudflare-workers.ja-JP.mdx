アプリケーションは 1 つの Cloudflare Worker として動作します。`@cloudflare/vite-plugin` がビルドを行い、`CLOUDFLARE_ENV` で Wrangler の環境を選択します。`wrangler.jsonc` は `main` を `./src/server.ts` に設定し、`nodejs_compat` とオブザーバビリティを有効にし、静的ファイルを `ASSETS` バインディング経由で配信します。`/assets/*`、`/fonts/*`、`/robots.txt`、`/llms.txt` を除くすべてのパスで、最初に Worker が実行されます。ソースマップはアップロードしません（`upload_source_maps` は `false`）。Worker とソースマップを合わせると、Cloudflare が 1 回のアップロードで受け付けるサイズを超えるためです。

| 環境          | Worker                  | D1、KV、R2                            | ドメイン                |
| ------------- | ----------------------- | ------------------------------------- | ----------------------- |
| `development` | `saasyland-development` | リモートのプレビュー用リソース        | `localhost:3000`        |
| `preview`     | `saasyland-preview`     | プレビュー用リソース                  | `preview.saasyland.com` |
| `production`  | `saasyland`             | 本番用リソース                        | `saasyland.com`         |
| `test`        | `saasyland-test`        | `.wrangler/test` 内のローカルリソース | `127.0.0.1:3000`        |

どの環境も D1 を `DB`、KV を `CACHE`、R2 を `MEDIA` としてバインドし、必要なシークレットを列挙します。アフィリエイトの紹介トラッキングを有効にする `AFFONSO_PROGRAM_ID` は `vars` の下の通常の変数で、現時点では `test` にだけ設定されています。`test` 環境は `src/platform/testing/worker.ts` をエントリーとして使います。このエントリーは Resend と Polar へのリクエストを横取りし、Playwright 用のテスト専用エンドポイントを公開します。

## リクエストの流れ

`src/server.ts` がすべてのリクエストを処理します。

1. `/media/` 配下のパスは `serveMedia` に渡され、署名済みの動画ファイルが Workers のキャッシュまたは R2 から配信されます（[Cloudflare R2](/docs/integrations/cloudflare-r2) を参照）。以下の手順のうち、これに適用されるのはセキュリティヘッダーだけです。
2. `i18n.middleware.ts` の `resolveLocale` が、`/api` と `/_serverFn` 以外への `GET` と `HEAD` のドキュメントリクエストを検査します。言語エイリアスと正規でないロケールパスをステータス 308 でリダイレクトし、ロケール Cookie が URL のロケールと異なる場合はそれを通知します。
3. `/api` と `/_serverFn` 以外への `GET` と `HEAD` のリクエストは、まず `ASSETS` から配信されます。プリレンダリングされたページもここに含まれます。404 の場合は TanStack Start のハンドラーに処理が移ります。
4. ロケール Cookie の更新が必要な場合、Worker はそれをレスポンスに追加します。HTML レスポンスには、スタイルシートとそのロケールのフォントに対する `Link` プリロードヘッダーも付与されます。
5. HTML レスポンスには地域別の価格が適用されます。`cf-ipcountry` の国が購買力に基づく割引の対象である場合、`HTMLRewriter` が `<html>` に割引の属性を追加し、レスポンスは `private, no-cache` になります。
6. リダイレクト、API 呼び出し、メディアファイルを含むすべてのレスポンスに、[セキュリティと堅牢化](/docs/features/security) のセキュリティヘッダーを付けます。Worker を経由しないファイルには、`public/_headers` から同じセットが付きます。

## デプロイ

`bun run deploy:preview` と `bun run deploy:production` は、まずバインディングの欠落とプレースホルダーのままの D1 と KV の ID を拒否する `scripts/verify-bindings.ts` を実行し、続いて対応するビルド、`scripts/prepare-deploy-secrets.ts`、その環境の D1 マイグレーション、`wrangler.jsonc` が宣言するシークレットを使った `dist/server/wrangler.json` の `wrangler deploy`、そして稼働中のサイトを確認する `scripts/verify-deployment.ts` を実行します。`MEDIA` バケットは名前でバインドされるため、最初のデプロイの前に存在している必要があります。`wrangler r2 bucket create` で作成してください。ビルドは公開ページをプリレンダリングし、`scripts/verify-build.ts` と `scripts/optimize-prerendered-html.ts` を実行します。[プレビューをデプロイする](/docs/getting-started/deploy-preview)、[プロジェクトのスクリプト](/docs/tooling/scripts)、[CI/CD](/docs/tooling/ci-cd) を参照してください。

ビルドのたびに Worker を 2 回コンパイルします。最初の Worker にはすべてのページが含まれ、公開ページをプリレンダリングします。プリレンダリングの後、`scripts/deployed-worker.ts` が、プリレンダリングにしか使わないものを除いてデプロイ用の Worker を再ビルドします。ドキュメントとブログのページはフロントマター、見出し、検索用テキストを保持しますが、レンダリングされた MDX は含まれません。ランディングと法務の各ページだけが使う翻訳も除外されます。プリレンダリング済みのページは `ASSETS` から返され、クライアント側のナビゲーションはブラウザ用チャンクから MDX をレンダリングするため、デプロイされた Worker が MDX をレンダリングすることはありません。ドキュメントのページまたは公開済みのブログ記事がプリレンダリングされていない場合、`scripts/verify-build.ts` がビルドを失敗させます。
