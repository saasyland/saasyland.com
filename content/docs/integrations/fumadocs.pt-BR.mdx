---
title: "Fumadocs"
description: "Coleções MDX para a documentação e o blog, fontes localizadas e busca."
---

O Fumadocs transforma `content/docs` e `content/blog` em árvores de páginas localizadas. `bun run content` executa `fumadocs-mdx` e grava `.source/`; `dev`, `typegen` e todos os scripts de build o executam antes.

| Arquivo              | Finalidade                                                                                                                |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `fumadocs.config.ts` | A coleção `docs`, a coleção `blog` com seu schema de frontmatter, e os temas e substituições de cor do realce de código   |
| `fumadocs.i18n.ts`   | Os locales de `I18N`, `en-US` como padrão e fallback, o parser `dot` para `<slug>.<locale>.mdx`, prefixo de locale oculto |
| `fumadocs.source.ts` | `source` em `/docs` com o plugin de ícones Lucide, `blogSource` em `/blog`, `getPublishedBlogPosts` com tempo de leitura  |
| `fumadocs.docs.ts`   | A server function `getDocsPage`, `loadDocsPage` e `docsHead` para a rota `docs.$`                                         |
| `fumadocs.search.ts` | O índice de busca servido por `/api/search`                                                                               |

O prefixo de locale fica oculto nas URLs do Fumadocs porque o roteador o adiciona. O frontmatter do blog exige `title`, `authorName` e `date` e aceita `description`, `excerpt`, `faq`, `featured`, `image`, `published`, `tags`, `updated` e `authorImage`.

## Componentes

`src/presentation/components/custom/mdx.tsx` mapeia os componentes MDX: os padrões do Fumadocs (incluindo `Cards` e `Callout`), `Accordions`, `Steps` e `Tabs`, além de `Alert`, `Badge`, `Button`, as partes de card, `Separator` e `Table` do shadcn; `RepositoryFact`, que mostra um valor medido no repositório durante o build ou definido no código, como em `<RepositoryFact name="testFiles" />`, e `RepositoryTable`, que mostra uma tabela montada a partir do código, como em `<RepositoryTable name="commitTypes" columns={["Type", "Emoji"]} />`. `TierPrice` mostra o preço de tabela de um plano a partir de `TIER_PRICES` no idioma da página, como em `<TierPrice tier="core" />`, para que nenhuma página digite um preço. `ActivationLimit` mostra o limite de ativações de um plano a partir de `LICENSE_ACTIVATION_LIMITS`, como em `<ActivationLimit tier="core" />`, e `RegionalDiscounts` lista os percentuais dos descontos regionais derivados de `PPP_TIERS`. Os links internos são localizados com `localizePathname`, e um item de lista de tarefas envolve a caixa de seleção e o texto em um `label`. `docs-content.tsx` e `blog-content.tsx` renderizam as páginas.

`@fumadocs/base-ui` está fixado na 16.19.0 com um patch do Bun: o `CodeBlock` dele dava à área de rolagem de cada bloco de código o papel `region` sem nome, então uma página com dois blocos de código tinha landmarks duplicados sem nome. Com o patch, a área de rolagem é uma região nomeada pelo título do bloco quando ele existe e, caso contrário, continua focável sem papel. Veja [Dependências](/docs/conventions/dependencies).

## Regras de conteúdo

Toda página existe uma vez por locale como `<slug>.<locale>.mdx`, e cada pasta tem um `meta.<locale>.json` com o mesmo array `pages` em todos os locales. `icon` em um arquivo meta recebe o nome de um ícone Lucide. `scripts/check-content.ts`, parte de `bun run check:i18n`, falha quando falta uma tradução, um bloco de código difere, a navegação difere ou um parágrafo em inglês permanece em outro locale.
