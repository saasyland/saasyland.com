A aplicação é um app TanStack Start. `src/router.tsx` cria o roteador com um QueryClient por requisição, a integração de queries com SSR, componentes padrão de erro e de página não encontrada, pré-carregamento por intenção, um stale time dos pré-carregamentos igual ao seu stale time e o `rewrite` de locale. Não há componente de carregamento padrão: cada rota define o seu próprio esqueleto (veja [Esqueletos de carregamento](/docs/architecture/delivery-layer#esqueletos-de-carregamento)). `src/routes.ts` exporta `ROUTES`, as constantes de caminho usadas por links, guards e tags do head.

O repositório carrega patches do Bun para `@tanstack/router-core` 1.171.39 e `@tanstack/react-router` 1.170.46 e fixa `@tanstack/router-core`, `@tanstack/react-router` e `@tanstack/react-start` para que as versões com patch continuem instaladas. A primeira renderização do router após a hidratação redefinia a posição de rolagem da janela, que o navegador e o script de restauração inline do router já tinham definido, então um visitante que rolava enquanto a página hidratava voltava ao topo; com o patch, a hidratação não mexe na posição de rolagem. `lazyRouteComponent` recarrega a página quando um chunk de rota não carrega, para pegar um novo deploy, e o Safari e o Firefox fazem falhar da mesma forma os chunks de uma página que o visitante está deixando, então o recarregamento trocava a navegação do visitante pela página que ele deixava; com o patch, um chunk que falha depois de `beforeunload` espera e volta a carregar se o visitante ficar. O chunk do loader de uma rota não tem essa recarga; depois de um deploy, é o componente de erro padrão do router que carrega a página de novo (veja [Rotas e entrega](/docs/architecture/delivery-layer#after-a-deploy)). Veja [Dependências](/docs/conventions/dependencies).

## Rotas

`src/routes/` contém rotas de arquivo planas: `admin.users.all.tsx` serve `/admin/users/all`, `_site.tsx` é um layout sem caminho e `_site.docs.$.tsx` é uma rota splat. O ID em `createFileRoute("…")` é uma string literal mantida pelo gerador de rotas em `src/routeTree.gen.ts`; pastas `__test__` são ignoradas como rotas.

Um arquivo de rota apenas compõe sua página. Ele define o componente `<Name>Page` ou `<Name>Layout`, `NAMESPACE` ou `NAMESPACES`, um loader que executa o carregamento de metadados, mensagens e dados em um único `Promise.all`, `head: pageHead(ROUTES.X)` e, nas áreas protegidas, um guard em `beforeLoad`. Widgets, diálogos, formulários e colunas de tabela ficam em `src/presentation/components/custom/` e leem as próprias traduções e dados. Veja [use-intl](/docs/integrations/use-intl) para o loader e [Better Auth](/docs/integrations/better-auth) para os guards.

## Server functions

As operações são funções `createServerFn` nativas exportadas pelos casos de uso dos módulos, portanto a aplicação não expõe um endpoint REST para elas. Veja [Server functions e casos de uso](/docs/integrations/server-functions).

## Handlers HTTP

Estas rotas declaram `server.handlers` em `src/routes/api/`:

| Rota                                         | Handler                                                                                     |
| -------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `/api`                                       | Retorna o runtime como JSON                                                                 |
| `/api/auth/$`                                | Better Auth, incluindo callbacks de OAuth e webhooks da Polar em `/api/auth/polar/webhooks` |
| <RepositoryFact name="cliApiBasePath" />`/*` | A API de licenças da CLI, `licenseApiHandlers` em `src/modules/license/license.api.ts`      |

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Pré-renderização

O plugin do TanStack Start em `vite.config.ts` habilita a pré-renderização com rastreamento de links, e `shouldPrerender` (`src/lib/prerender.ts`) filtra os caminhos rastreados. `build:preview`, `build:production` e `build:test` pré-renderizam as páginas públicas (landing page, páginas legais, blog e documentação) em todos os locales. O filtro ignora `/admin`, `/api`, `/app`, `/auth`, `/courses` e `/newsletter`, com ou sem prefixo de locale, bem como links que contêm `?` ou `#`. As páginas ignoradas são renderizadas no Worker a cada requisição.
