## コマンドを入力する前に起こる決定

すべてのスターターキットは、他の人に答える前に1つの質問に答えます: **買い手が受け取るものは?**

全く2つの答えがあり、それらは全く異なる2年の経験を作り出します。

**回答:すべて、削除します。** 製品がサポートするすべての機能を含むリポジトリをクローン化します。 組織、すべての5つの決済プロバイダ、docsアプリ、メールプレビューアプリ、AIモジュール。 次に、不要なものを取り除きます。 Supastarter の文書化された開始は、 `npx supastarter new my-awesome-project`, docs はクローニングとして記述します。, 設定とインストール.

**2 回答: 回答のみ。** お問い合わせ ジェネレータは、あなたの答えと他に何も対応するモジュールを書きます。 単一テナントプロジェクトでは、組織のコードがどこにも存在しません。 請求なしのプロジェクトは、過去に読み込むために Stripe webhook ハンドラはありません。 これは、 [CLI コンフィギュレータ](/#cli) 当ホームページでは、12つの質問、4つのオプション機能、そして回答として変更するコマンドについて、お客様の目の前に住んでいます。

どちらも正当です。 回答 1 は、あなたが勉強できる完全な参照実装を提供し、必要なコードを持っていない日がそれを持っているよりも優れている。 答え2は、より小さいリポジトリを与えます。これは、それがそうすべきように聞こえるよりも重要です。

こんな感じで音が聞こえるのはなぜか。

**未使用コードは無料ではありません。** 参加するすべての開発者が読んでいます。 すべての grep によって検索されます。 すべての「使用方法を見つける」に現れます。それはあなたのバンドラーによって歩かれます。 リポジトリにあるすべてのコーディングエージェントのコンテクストウィンドウにロードされ、メタファーではなく実際の予算になります。 そして、すべて、 **それはあなたが責任を負っているコードであり、書きませんでした**ソフトウェアの最悪のコンビネーションである。

引数の最もクリアなバージョン: 単一テナントを足場すれば、組織スコープのクエリがまだどこかで実行されていないのは、どのように確信していますか? 回答2では、コードが存在しないため、問題は無意味です。

## E2Eテストとカバレッジゲートは異なるクレームです

Supastarter のドキュメントは、E2E のテストを Playwright でリストします。 それは本当です、それはほとんどの競争相手の提供以上であり、私はそうでなければ先行するつもりはないです。

また、このコードベースとは異なるクレームであり、両方が「テスト」の下でファイルされるので、差は理解する価値があります。

**E2Eスイートは、今日の作業のためにテストを書いたパスを証明しています。** サインアップ、チェックアウト、およびいくつかのフローを使用してブラウザを実行します。 特異を捕まえて壊滅的かつ役に立たないキャッチで抜群です。

**カバレッジゲートは、未確認のブランチがまったくマージされるのを防ぎます。** ここでは、このリポジトリの実際の構成です。 `vite.config.ts`:

```ts
coverage: {
  thresholds: {
    branches: 100,
    functions: 100,
    lines: 100,
    statements: 100,
  },
}
```

4つの数字、それらのすべて100、それらのすべてが強制されます。 門が走る今日 **141テストファイルと472テスト**. . ザ・オブ・ザ・ザ・ `src/app/**` ルートレイヤーと生成されたインテグレーションコードは非表示ではなくコンフィグに記述されます。フレームワークのgatingは何も主張するテストを生成します。

実際の違いは、特定の場所に表示されます: エラーブランチ。 Webhookハンドラは、検証しない署名のパスを持っています。 招待状の流れには、期限が切れたトークンのパスがあります。 あなたの許可チェックには、falseを返すパスがあります。 **E2E スイートは、ほぼこれらのエクササイズをしません。**ブラウザテストで失敗したシグネチャを設定すると、誰もがそれをスキップします。 100の分岐カバーゲートは、それらを未確認にマージしません。

そして、それらの枝は、出荷前に誰も手作業で動かないので、正確に SaaS製品が失敗する場所です。

## あなたが望まないかもしれない4つのアプリ

上記の4アプリモノレポは、Supastarter 利点としてリストされ、正しい買い手の場合です。 「モノレポ」は、人々が自動的に良いように受け入れる言葉であるため、コストを命名する価値もあります。

4つのアプリは4つのアプリを意味します `package.json` ファイル、4 `tsconfig.json` ファイル、4つの次のコンフィグ、4つのビルドパイプライン、4つの依存性アップグレード。 1つのプロダクトを造る1人の人なら、ソロ・ファインダーの時と共にプラットホームのチームの構造を今作動させます。

代替手段は「モノレポなし」ではありません。 **継承ではなく、決定する。** ザ・オブ・ザ・ザ・ [CLI コンフィギュレータ](/#cli) モノリス、スプリット API、またはマイクロサービスに直接形状の質問を要求します。 モノリスを選ぶと、デプロイ可能で1つの依存ツリーが取得できます。 分割してフロントエンドと別々の API を取得します。 アーキテクチャは、購入した製品のプロパティではなく、質問に対するあなたの答えです。

## 実行可能であるアーキテクチャ

どちらの製品もアーキテクチャを持っています。 差はコンパイラがそれについて知っているかどうかです。

このコードベースのモジュールの境界は、ドキュメントではなく、lint ルールです。

```ts
// vite.config.ts, abridged
lint: {
  options: { typeAware: true, typeCheck: true },
}
```

同じファイルで3つのルール。 ドメインコードは、React、Next、ORM、インフラ、アプリケーションコードをインポートできません。 アプリケーションコードはインフラをインポートできません。 プレゼンテーションコードは Drizzle をインポートできず、アプリケーションユースケースを経由して行ってください。

結果: **誤ってデータベースクエリを React コンポーネントに入れることができません。** ビルドが失敗し、なぜ説明するメッセージで。 これは、クリーンなアーキテクチャと1つを持っているために使用されるコードベースの違いです。

これは、毎月、人間の開発者とは何の関係もないという理由のために、より重要である。 コーディングエージェントは、読み出しではなく、失敗からコードベースのルールを学びます。 ビルドに失敗する境界線は、その2番目の試みでエージェントが尊重する境界線です。 慣習である境界は、丁寧かつ繰り返しに違反する1つです。 それについて書いています [AIコーディングエージェントのリポジトリの信頼性](/blog/ai-coding-agents-repository-readiness).

SaaSy Land は **$249** コードベースでは、 **$399** ビデオマスタークラスと、 **$899** 代理店の層のため。 ワンタイム。 無制限のプロジェクト。 座席数が制限されていません。

そのためには、スタートアップとAgencyの層には、シートを越えた実際のものが含まれます。 執筆者との6分のコンサルティングコールは価値があります。 優先サポートには価値があります。 プライベート Discord のファウンダーアクセスは、値を持っています。 あなたが望むものであれば、価格は守られており、あなたが望むものを買うべきです。

しかし、ソースコードが欲しいのであれば、シートカウントは商品ではなくライセンスの決定であり、あなたの会社がうまく行くと正確に刺激されるという決定のソートです。

## 誰が購入する必要があります Supastarter

箱から4アプリのモノレポを望むなら、Supastarterを購入し、とにかく1つをビルドします。 特にCreemやDodo支払いが必要な場合は、他の人がそれらをサポートしていないためです。 完全な参照の実装を値するなら、自分を自分で読み出し、自分を決めるジェネレータをプルーンすることができます。 著者との6分の呼び出しがあなたに数億ドルの価値があるならば、それはいくつかの買い手が明確です。 プリスマにいるとそこに滞在するつもりです。

本物のお客様と良い製品で、恥ずかしがりません。

## 誰がこの代わりに買うべきか

あなたが要求したコードだけを含むリポジトリが必要な場合は、これを購入してください。 100%のカバレッジゲートが実際に維持する何かなら、週2で無効にする人には価値がないからです。 アーキテクチャがlinterによって強制されたいと思うのに十分な問題がある場合。 チームが1つよりも大きい場合、席数がカウントされません。 TanStack Start と React のルータがオプションなので、 Next.js を望まないかもしれません。 サンプル製品、サブスクリプションコース、ページビルダー、またはビジュアルポストエディタでストアを望むなら、ここでオプションの追加と提供されていない。

あなたは、コーディングエージェントと作業しているあなたの日の大きな部分を費やすと、これを購入します, 上記のすべてが強化された境界について、より小さなリポジトリは、それがあなたよりもエージェントに価値があるため.

## よくある質問

<Accordions>

<Accordion title={"最高の Supastarter の代替品は何ですか?"}>

Supastarter を評価するほとんどの人にとって、正直な答えは Supastarter です。 それはそれの背後にある1,460の開発者が付いている深刻な、よく維持されたプロダクトです。 3つの特定の事柄があなたにとって重要である場合、他の場所を見てください:あなたがプルーンの完全なクローンではなく、選択したモジュールだけを記述するジェネレータ、E2Eテストだけでではなく、強制的なカバレッジゲート、および1つの価格は、シートライセンスではなく、あなたのチーム全体をカバーします。

</Accordion>

<Accordion title={"Supastarter はどのように配信され、インストールされますか?"}>

リポジトリをクローンする CLI を通して。 その文書は、 `npx supastarter new my-awesome-project`, クローン, 設定し、インストール, マニュアルで `git clone` フォールバックとして。 セットアップでは、Supastarter リポジトリを git upstream リモートとして追加するため、将来のバージョンはプロジェクトにマージとして到着します。

</Accordion>

<Accordion title={"git アップストリーム更新モデルで何が間違っていますか?"}>

あなたがカスタマイズするまで、何もありません。 マージの対立面は、変化と変化の交差であり、それは成長するだけです。 ワース、削除は記憶されません:上流にまだ必要とされていないので削除したコードは、すべての将来のマージが再び提案し、あなたは永遠に同じ質問を再決定します。

</Accordion>

<Accordion title={"Supastarter のコストは SaaSy Land と比べてどれくらいかかりますか?"}>

Supastarter は 1 つのデベロッパシートで $299 をリストします。$ 799 は最大 5 と $ 1,499 まで 10 です。SaaSy Land は商用ライセンスで無制限のプロジェクトで $ 249 です。 ソロの創始者のためにギャップは50ドルです。 5人のチームでは$ 550で、10の代理店は$ 1,250です。

</Accordion>

<Accordion title={"Supastarter にはテストがありますか?"}>

そのドキュメントは、E2E のテストを Playwright でリストします。これは現実的で有用です。 パブリック・ドキュメンテーションとは、強制的なカバレッジのしきい値を持つユニットまたはインテグレーション・テスト・スイートです。 E2Eテストでは、今日のハッピーパスが証明されていることを明確にしています。カバレッジゲートは、これまでにないブランチがマージされるのを防ぎます。

</Accordion>

<Accordion title={"4つのアプリでモノレポは良いことですか?"}>

マーケティングサイト、アプリ、ドキュメント、メールプレビューを1日ごとに別々に展開したい場合、それは本当の利点です。 デプロイ可能であればコストです。4つのpackage.jsonファイル、4つのtsconfigsと4つのビルドパイプラインを1人の人が書いている製品に維持できるようになりました。

</Accordion>

<Accordion title={"クライアントプロジェクトに Supastarter を使うことはできますか?"}>

はい、$ 1,499で最大10席でAgency tierで、明示的に白いラベルの準備が整っています。 作成する価値の比較は、11番目の開発者と5分のクライアントプロジェクトが追加費用なしで、すべての座席数を持つ商用ライセンスに対してあります。

</Accordion>

<Accordion title={"AI のコーディングのエージェントはどれが良いですか?"}>

境界が実行可能であるもの。 エージェントは、読み出しではなく、失敗したものから構造を読みます。 ドメインコードを物理的にインポートできないコードベースは、ORM が 1 つのエラーメッセージでそのアーキテクチャを教えます。 ルールが慣習であるコードベースは、間違ったパッケージに正しいコードを置くためにエージェントのより多くの場所を与えます。

</Accordion>

<Accordion title={"どちらの製品もあなたに生涯の更新を与えますか?"}>

サブスクリプション無しで広告の生涯アクセスの両方。 違いは必須ではありません、それは配達です。 カスタマイズしたプロジェクトに上流モノレポをマージするのは、実際に生成したモジュールの差分をとり、作業を続ける毎月の差分コンパウンドのことです。

</Accordion>

<Accordion title={"既にSupastarterを買った場合、切り替える必要がありますか?"}>

おそらく、それが働いていると、あなたはそれに出荷されている場合は、そうではありません。 スイッチングコストは現実的で優れたアーキテクチャであり、それ自体に書き換える価値はほとんどありません。 次のプロジェクトをとにかく起動すると、比較が無料になる唯一の瞬間です。

</Accordion>
