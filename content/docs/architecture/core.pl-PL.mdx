`src/modules/_core` to jedyny folder modułu, który nie ma własnej tabeli. Zawiera wartości i helpery potrzebne kilku modułom, dzięki czemu żaden moduł nie definiuje ich od nowa.

## Stałe

| Plik                    | Zawartość                                                                                                                             |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `constants/errors.ts`   | `ERROR_CODES`, typ `ErrorCode` i klasa `AppError`                                                                                     |
| `constants/api.ts`      | `HTTP_STATUS`, nazwy nagłówków `cf-ipcountry` i `cf-connecting-ip`, nagłówki bezpieczeństwa, dozwolone hosty dla każdego trybu builda |
| `constants/locale.ts`   | Katalog `LOCALES`, `LocaleCode`, `getLocaleName` i `getLocaleDirection`                                                               |
| `constants/country.ts`  | Katalog `COUNTRIES` i `CountryCode`                                                                                                   |
| `constants/currency.ts` | Katalog `CURRENCIES` i `CurrencyCode`                                                                                                 |
| `constants/timezone.ts` | Katalog `TIMEZONES` i `TimezoneCode`                                                                                                  |
| `constants/pricing.ts`  | Waluta sklepu `DEFAULT_CURRENCY_CODE`, formatowanie walut, mnożniki cen regionalnych i cookie cen regionalnych                        |
| `constants/ordering.ts` | `MOVE_DIRECTION` (`up`, `down`), `MOVE_DIRECTIONS` i typ `MoveDirection`                                                              |

Katalog locale zawiera wszystkie znane locale. Locale, które aplikacja faktycznie obsługuje, definiuje `I18N.SUPPORTED_LOCALES` w `src/integrations/use-intl/i18n.config.ts`.

## Narzędzia

- `utils/localized-text.ts`: `LocalizedText`, tekst dla każdego locale zapisywany jako JSON, `localizedTextSchema`, który wymaga `en-US` i ustala limit znaków każdego tekstu na <RepositoryFact name="localizedTextMaxLength" />, oraz `localize`, który wraca do `en-US`
- `utils/ordering.ts`: `nextPosition`, czyli najwyższa `position` plus jeden, oraz `reorder`, który zamienia element z sąsiadem i numeruje listę od 1; przypadki użycia kursów, rozdziałów i lekcji utrzymują dzięki nim `position` bez luk
- `utils/pagination.ts`: `paginationSchema` (`pageIndex`, `pageSize`), `DEFAULT_PAGINATION` i `DEFAULT_PAGE_SIZE`
- `utils/zod-fields.ts`: pola Zod wielokrotnego użytku, takie jak `idField`, `localeField` i `slugField`

## Błędy

Istnieje jedna klasa błędu i jedna lista kodów:

```ts
export const ERROR_CODES = {
  AUTH_API_ERROR: "AUTH_API_ERROR",
  CONFLICT: "CONFLICT",
  FORBIDDEN: "FORBIDDEN",
  INTERNAL_ERROR: "INTERNAL_ERROR",
  LICENSE_ALREADY_ACTIVE: "LICENSE_ALREADY_ACTIVE",
  NOT_FOUND: "NOT_FOUND",
  TOO_MANY_REQUESTS: "TOO_MANY_REQUESTS",
  UNAUTHORIZED: "UNAUTHORIZED",
  VALIDATION: "VALIDATION",
} as const

export type ErrorCode = (typeof ERROR_CODES)[keyof typeof ERROR_CODES]

export class AppError extends Error {
  readonly code: ErrorCode

  constructor(code: ErrorCode, message: string = code) {
    super(message)
    this.name = "AppError"
    this.code = code
  }
}
```

Funkcje serwerowe rzucają `AppError`. Middleware `withRequest` normalizuje wszystkie pozostałe błędy: błędy API Better Auth stają się `AUTH_API_ERROR` z kluczem błędu Better Auth jako komunikatem, błędy Zod stają się `VALIDATION`, a nieznane błędy są logowane i zamieniane na `INTERNAL_ERROR`. W przeglądarce `useErrorMessage()` z `src/hooks/use-error-message.ts` mapuje komunikat na tłumaczenia `auth.errors.*` lub `errors.codes.*`.
