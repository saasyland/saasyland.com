---

SaaSy Land est une seule application TanStack Start qui s'exécute comme un Cloudflare Worker. Le code est découpé par responsabilité :

- Les **routes** (`src/routes`) composent les pages. Un fichier de route déclare ses namespaces de traduction, son guard, son loader et ses balises head, puis rend des composants.
- Les **modules** (`src/modules/<table>`) n'existent que pour de vraies tables de la base de données. Un module possède le schéma Drizzle de la table, ses schémas Zod, ses constantes, ses types et les cas d'usage qui la lisent ou la modifient.
- Les **intégrations** (`src/integrations/<vendor>`) configurent les bibliothèques et services tiers.
- La **présentation** (`src/presentation`) regroupe les primitives shadcn, les composants de l'application, les modèles React Email, les styles, le thème et l'identité visuelle.
- Le **code partagé** se trouve dans `src/data` (données utilisées par plusieurs fichiers), `src/lib` (petits utilitaires), `src/hooks` et `src/providers`.

```text
src/
├── routes/          Flat file routes that compose pages
├── modules/         One folder per database table, plus _core
├── integrations/    One folder per vendor
├── presentation/    Components, emails, styles, theme, branding
├── data/            Data shared by several files
├── lib/             Small shared utilities
├── hooks/           Shared React hooks
├── providers/       Application providers
├── platform/        Test runtime wiring
├── types/           Global type declarations
├── router.tsx       Router and per-request QueryClient
├── routes.ts        ROUTES path constants
└── server.ts        Cloudflare Worker entry
```

## Règles qui façonnent le code

- Les fichiers de route ne font que composer. Les widgets, boîtes de dialogue, formulaires et colonnes de tableau se trouvent dans `src/presentation/components/custom`, un par fichier.
- Les composants lisent eux-mêmes leurs traductions et leurs données avec `useTranslations`, `useSuspenseQuery` ou les données du loader de la route. Les routes ne leur transmettent ni libellés ni données sous forme de props.
- Une fonction serveur qui travaille sur une table est un cas d'usage dans le module de cette table. Une fonction serveur utilisée par une seule route peut être définie dans le fichier de route. Tout le reste va dans `src/lib`.
- Il n'y a ni conteneur d'injection de dépendances ni couche de wrappers. Importez la fonction concrète depuis le dossier qui la possède.
- Une constante utilisée par un seul fichier reste dans ce fichier. Seules les données partagées par plusieurs fichiers vont dans `src/data`.
