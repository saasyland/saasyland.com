## Content

- Pages are `content/docs/<section>/<page>.<locale>.mdx` for every locale.
- `meta.<locale>.json` in each folder sets the section title, icon and page order. The icon is one of `DOCS_ICONS` in `fumadocs.icons.ts`.
- `src/integrations/fumadocs/fumadocs.i18n.ts` uses the `dot` parser, `en-US` as default and fallback, and `hideLocale: "always"`, because the app handles the locale prefix itself.
- `bun run content` generates `.source` from `fumadocs.config.ts`.

## Routes

- `/docs` layout (`src/routes/_site.docs.tsx`): its loader reads the page tree of the current locale from the docs index (see [Fumadocs](/docs/integrations/fumadocs#content-indexes)); the layout renders Fumadocs `DocsLayout` inside the `_site` layout, below the site header and above `BackToTop`, which the docs need because the Fumadocs table of contents only jumps to headings. It sets Fumadocs' `--fd-banner-height` to the header's height, so the sidebar and the table of contents stick below the header, titles the sidebar **Docs** with a link to `/docs`, shows the GitHub link, and `LocaleSelect` and `ThemeSwitch` as matching select fields in the sidebar footer, loads `docs.css`, and shows `DocsPending`, the sidebar and the page at the current path, while it loads. Its loader preloads the `fumadocs` namespace, and the `stack` and `flow-areas` labels that the roadmap's and the test coverage page's tables print, with the page tree, and the site's `Footer` follows the docs as it follows every other public page, so the legal pages, the contact address, the newsletter and the language links are one scroll away from any docs page.
- From `md` up the docs sit in the site's frame, like every other public page: the layout gives Fumadocs' container the header's width and padding (`mx-auto max-w-site md:px-10`), so the sidebar starts under the logo and, from `xl` up, the table of contents ends under **Start building**, and the header keeps its width and place when a visitor moves between the docs and the rest of the site. The sidebar is `--container-docs-sidebar` wide and the table of contents `--container-docs-toc` (see [Theme](/docs/ui/theme)), both narrower than Fumadocs' own, so the article fills the column between them at a comfortable line length; a title too long for one line in either of them wraps into balanced lines (`text-wrap: balance` in `docs.css`). The sidebar cannot be collapsed (`collapsible: false`), so it stays on screen below the header, with its own scroll and a line on each side that meets the header's line. `e2e/specs/content-chrome.spec.ts` checks both edges, the frame's width against the header's, the article's line length and that it fills the column between the sidebar and the table of contents, and the sidebar's place before and after scrolling, and `e2e/specs/navigation.spec.ts` checks that the header and the footer have the same width and place on the landing page, the blog, the courses and the docs, and that the header does not move in any frame of a client navigation between them.
- From `xl` up, `docs-content.tsx` replaces Fumadocs' table of contents with `DocsToc` (`custom/docs-toc.tsx`) through the `slots.toc.main` of `DocsPage`. It keeps the `#nd-toc` column and its **On this page** heading and lists the headings with the blog's `TableOfContents`, so a docs page and a blog post mark the section being read and move its line the same way (see [Blog](/docs/features/blog)).
- On small screens the site header keeps its menu, and one docs bar sits below it: `DocsToolbar` (`custom/docs-toolbar.tsx`), the layout's `header` slot, holds the one button that opens the docs navigation, the title of the current page and the search button. The docs navigation slides in from the side of its button, where the sidebar stands on wider screens (`#nd-sidebar-mobile` in `docs.css`). The bar is a navigation landmark named **Docs**, so the site header remains the page's only banner. Fumadocs sets the bar's height, `--fd-header-height`, only for its own bar, so the docs layout sets it on small screens. Below `xl`, where the table of contents column is hidden, `docs-content.tsx` turns off Fumadocs' table of contents bar and lists the page's headings in a collapsed `InlineTOC` under the description, as a blog post does, so no third bar stays on screen.
- Fumadocs writes the text of its own controls: the search, the sidebar buttons, **On this page**, the copy buttons of code blocks, heading anchors and accordion items, and the links to the previous and next page. `useFumadocsI18n` (`src/hooks/use-fumadocs-i18n.ts`) maps each of those strings to a message of the `fumadocs` namespace and passes them to `RootProvider` with the page's locale, so they come from `messages/<locale>/fumadocs.json` like every other string. `e2e/specs/content-chrome.spec.ts` fails when a Fumadocs string is left in English on a Polish or German docs page or blog post.
- The site header's **Skip to content** link is the page's only skip link. On a docs page it jumps to the article, whose id stays Fumadocs' `nd-page`: the docs layout sets `contentId` in its `staticData` to `DOCS_CONTENT_ID` (`src/data/navigation.constants.ts`), and `Navigation` links to the `contentId` of the deepest matched route that sets one, or to `SITE_CONTENT_ID`. Fumadocs' `DocsLayout` always renders a second, invisible link of its own to `#nd-page`, and Fumadocs declined a slot to leave it out ([fuma-nama/fumadocs#3866](https://github.com/fuma-nama/fumadocs/issues/3866), [fuma-nama/fumadocs#3867](https://github.com/fuma-nama/fumadocs/pull/3867)). `globals.css` hides it with `display: none`, which takes it out of the tab order and the accessibility tree, since the site's link already leads to the same article. The rule sits outside Tailwind's layers, so the button classes Fumadocs gives the link since 16.19.5, such as `inline-flex`, cannot show it again. `e2e/specs/content-chrome.spec.ts` checks that docs, blog and landing pages each have one skip link, reached by the first Tab, that moves focus into the content, and `e2e/specs/navigation.spec.ts` that the header stays the same element from the landing page to the docs and back.
- `/docs/` and `/docs/$` call `loadDocsPage` (`fumadocs.docs.ts`), which finds the page by its slug in the docs index of the current locale, with its title, description, section and MDX file, and preloads its compiled MDX (`docsContent`) before rendering. While they load, `DocsIndexPending` and `DocsPagePending` stand in for the article and its table of contents, and the sidebar stays on screen.
- Both loaders run in the browser on a client navigation, and the docs index and the compiled MDX are files under `/assets/`, so moving through the docs never reaches the Worker (see [Performance](/docs/conventions/performance#the-worker-holds-no-docs-or-blog-content)).

MDX pages can use `mdxComponents` from `src/presentation/components/custom/mdx.tsx`: the Fumadocs defaults, Fumadocs `Accordions`, `Steps` and `Tabs`, the shadcn `Alert`, `Badge`, `Button`, card parts, `Separator` and table parts, and `RepositoryFact`, `RepositoryTable`, `TierPrice`, `ActivationLimit` and `RegionalDiscounts`, which print values from the code instead of typing them ([Translations and content](/docs/conventions/translations)). Links are localized automatically: `localizeHref` adds the page's locale to the path of an internal link and keeps its query and fragment, so `/#pricing` opens `/pl-PL#pricing` on a Polish page.

## Search

The search button and <kbd>Ctrl</kbd> or <kbd>⌘</kbd> + <kbd>K</kbd> open `DocsSearchDialog` (`custom/docs-search-dialog.tsx`), which the docs layout passes to Fumadocs' `RootProvider` and loads with `lazy`. It searches with Fumadocs' static client, `useStaticSearch`, in the browser: the first query of a visit downloads the search index of the page's locale, `/assets/search-index-<locale>-<hash>.json`, which every build writes from the headings and text of each docs page in that locale, and every result after that comes from memory. The file name changes with the content, so the browser keeps the index for a year. There is no search endpoint; see [Fumadocs](/docs/integrations/fumadocs#content-indexes).

## Accessibility

Docs pages meet WCAG 2.2 AA in both themes. Code blocks use Shiki's GitHub Light and GitHub Dark themes with two token colours replaced (`colorReplacements` in `fumadocs.config.ts`) so every token meets 4.5:1, a code block's scroll area is focusable and is not a landmark, and a task list checkbox is named by its item. `e2e/specs/accessibility.spec.ts` scans the docs home, every Conventions page and one page from each other section; see [Accessibility](/docs/conventions/accessibility).

## Adding a page

1. Write `<page>.en-US.mdx` with a `title` and `description`.
2. Add the slug to `meta.en-US.json` and to every other `meta.<locale>.json` in the same order.
3. Add the translation for every other locale, with byte-identical code blocks.
4. Run `bun scripts/check-content.ts` (also part of `bun run check:i18n`) and `bun run content`.

`bun run build` prerenders every docs page in every locale.
