description: "Os endpoints HTTP em /api e quando criar um deles em vez de uma server function."

As operações da própria aplicação são server functions. Handlers HTTP existem apenas quando algo fora do cliente RPC da aplicação chama uma URL: o cliente de navegador do Better Auth, os provedores OAuth, os webhooks da Polar e a CLI `saasyland`. A busca da documentação não precisa de nenhum: ela faz a busca em um índice estático no navegador (veja [Site de documentação](/docs/features/docs-site#search)).

| Arquivo                      | Caminho                                      | Métodos           | Responsável por                                                                                                                                                      |
| ---------------------------- | -------------------------------------------- | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/routes/api/index.ts`    | `/api`                                       | GET               | Uma resposta de status em JSON `{ runtime: "cloudflare-workers" }`                                                                                                   |
| `src/routes/api/auth.$.ts`   | `/api/auth/*`                                | GET, POST         | Todos os endpoints do Better Auth, incluindo os callbacks OAuth, a verificação de e-mail, o portal do cliente da Polar e `/api/auth/polar/webhooks`                  |
| `src/routes/api/cli.v1.*.ts` | <RepositoryFact name="cliApiBasePath" />`/*` | GET, POST, DELETE | A [API de licenças da CLI](/docs/features/cli-licence-api): a licença, os dispositivos dela e o pacote de templates de cada versão, por meio de `licenseApiHandlers` |

O Worker também responde por conta própria a `/media/<expiry>.<signature>/<videoId>/<file>`. Não é uma rota: `src/server.ts` envia essas requisições para `serveMedia` (`src/modules/video/video.delivery.ts`) antes do middleware de locale e do TanStack Start, e `serveMedia` verifica a assinatura e serve o arquivo de vídeo a partir do cache do Workers ou do bucket `MEDIA`. Veja [Cloudflare R2](/docs/integrations/cloudflare-r2). Ele responde a <RepositoryFact name="cliBundleUrlPath" /> da mesma forma: o handler da funcionalidade de licenças envia essas requisições para `serveBundle` (`src/modules/license/license.delivery.ts`), que verifica a assinatura e transmite o pacote de templates da CLI a partir do bucket `BUNDLES`. Veja [API de licenças da CLI](/docs/features/cli-licence-api#template-bundles). Em `/media/` ele também responde a `/media/covers/<courseId>/<file>`, as capas públicas dos cursos, com `serveCover` (`src/modules/course/course.delivery.ts`), e a `/media/downloads/<expiry>.<signature>/<attachmentId>/<fileName>`, os materiais assinados das aulas, com `serveAttachment` (`src/modules/lesson-attachment/lesson-attachment.delivery.ts`).

Um handler é declarado com `server.handlers` em `createFileRoute`. Ele recebe o `Request` da Web e retorna uma `Response`:

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Regras

- Não adicione um endpoint REST para uma operação que só esta aplicação chama. Escreva um caso de uso com `createServerFn`; ele ganha entrada tipada, middleware e query options.
- Um handler valida a própria entrada e verifica as permissões por conta própria. O middleware das server functions (`authorized`, `withRateLimit`) não roda para handlers. A API de licenças da CLI contabiliza cada requisição e lê a sua licença em um único batch do D1 com `rateLimitBatch` de `src/lib/rate-limit.ts`, lê uma requisição admitida com o `readApiRequest` do contrato e responde a qualquer falha própria, como uma falha do D1 ou da Polar, com o `serviceUnavailable` do contrato.
- Mantenha a verificação específica de cada fornecedor na integração. As assinaturas dos webhooks da Polar são verificadas pelo plugin da Polar dentro do Better Auth, não por um handler próprio.
- Caminhos em `/api` e `/media` nunca são localizados, nunca são pré-renderizados e ficam de fora do tratamento de locale do Worker.
