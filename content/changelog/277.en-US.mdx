- Changed: pull requests reach `main` through GitHub's merge queue, which tests each one again on top of `main` and the pull requests ahead of it and lands a group together once each has passed, so a ready pull request no longer waits to be rebased. `bun scripts/enqueue-pr.ts <number>` puts a pull request in the queue and gives its title the emoji the squash commit keeps. See [Git and pull requests](/docs/conventions/git-workflow#merging).
- Changed: a pull request no longer deploys the shared preview. The new `Worker upload` check uploads its preview Worker to Cloudflare as a version that serves no traffic, which proves the upload, its size and its bindings without replacing what `preview.saasyland.com` serves, so ready pull requests no longer block each other. `main` is deployed to the preview before production, and `preview.yml` deploys a tested branch there by hand. See [CI/CD](/docs/tooling/ci-cd#merge-queue).
- Changed: a push to `main` that the merge queue already tested deploys without running the checks again, and the changelog gate treats a merge queue branch like `main`.
- Changed: the definition of done runs `check`, `test:coverage`, `build:test` and the browser specs the change touches locally; CI runs the whole browser suite on the pull request and again in the merge queue. See [Conventions](/docs/conventions#definition-of-done).
