Playwright tests the built application in real browsers. The suite runs against the `test` Wrangler environment: local D1 and KV in `.wrangler/test`, dummy credentials from `.env.test` and the test entry `src/platform/testing/worker.ts`, which intercepts Resend and Polar requests.

```sh
bun run test:e2e:install
bun run test:e2e
bun run test:e2e:smoke
bun run test:e2e:pr
bun run test:e2e:headed
bun run test:e2e:ui
```

| Script             | Runs                                                  |
| ------------------ | ----------------------------------------------------- |
| `test:e2e:install` | Installs Chromium and WebKit with system dependencies |
| `test:e2e`         | All specs in Chromium and WebKit                      |
| `test:e2e:smoke`   | `e2e/specs/smoke.spec.ts` in Chromium                 |
| `test:e2e:pr`      | All specs in Chromium, as in pull request CI          |
| `test:e2e:headed`  | All specs in visible browsers                         |
| `test:e2e:ui`      | Playwright UI mode                                    |

## Configuration

`playwright.config.ts` defines the `chromium` (Desktop Chrome) and `webkit` (Desktop Safari) projects and uses `PLAYWRIGHT_BASE_URL` or `http://127.0.0.1:3000`. Locally the web server command runs `db:migrate:test`, `db:seed:test`, `build:test` and `start:test`, and reuses a server that already answers at that URL, so stop other servers on port 3000 first. In CI the workflow prepares the build and Playwright only starts the server.

| Setting  | Local           | CI              |
| -------- | --------------- | --------------- |
| Retries  | 0               | 2               |
| Workers  | 1               | 2               |
| Traces   | Kept on failure | On first retry  |
| Videos   | Off             | Kept on failure |
| Reporter | List and HTML   | GitHub and HTML |

## Layout

- `e2e/specs/`: specs for smoke checks, landing page, navigation, locales, auth, workspaces, newsletter, content, theme and regional pricing.
- `e2e/pages/`: page objects.
- `e2e/fixtures/`: the extended `test` fixture and helpers for captured emails.
- `e2e/data/accounts.ts`: the seeded admin and customer accounts and their password.

The test Worker exposes `/__test/emails` to read emails captured from the Resend mock and `/__test/newsletter` to read a subscriber's state.
