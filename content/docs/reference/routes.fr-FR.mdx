title: "Routes"
description: "Chaque chemin de page et d'API, sa constante ROUTES, son fichier de route et son guard."
---

Chaque chemin a une constante dans `ROUTES` (`src/routes.ts`). Les liens utilisent la constante, par exemple `<Link to={ROUTES.SIGN_IN}>`, et le routeur ajoute le préfixe de locale. Chaque page ci-dessous est aussi servie sous le préfixe de chaque locale autre que la locale par défaut, par exemple `/pl-PL/terms`.

## Pages publiques

Ces pages utilisent le layout `_landing` (navigation et pied de page), à l'exception du blog et de la documentation, qui ont leurs propres layouts. Elles sont toutes prérendues, sauf les pages de newsletter.

| Chemin                    | Constante                | Fichier de route                      |
| ------------------------- | ------------------------ | ------------------------------------- |
| `/`                       | `HOME`                   | `_landing.index.tsx`                  |
| `/premium`                | `PREMIUM`                | `_landing.premium.tsx`                |
| `/licence`                | `LICENCE`                | `_landing.licence.tsx`                |
| `/privacy`                | `PRIVACY`                | `_landing.privacy.tsx`                |
| `/terms`                  | `TERMS`                  | `_landing.terms.tsx`                  |
| `/refunds`                | `REFUNDS`                | `_landing.refunds.tsx`                |
| `/newsletter/confirm`     | `NEWSLETTER_CONFIRM`     | `_landing.newsletter.confirm.tsx`     |
| `/newsletter/unsubscribe` | `NEWSLETTER_UNSUBSCRIBE` | `_landing.newsletter.unsubscribe.tsx` |
| `/blog`                   | `BLOG`                   | `blog.tsx`, `blog.index.tsx`          |
| `/blog/*`                 | aucune                   | `blog.$.tsx`                          |
| `/docs`                   | `DOCS`                   | `docs.tsx`, `docs.index.tsx`          |
| `/docs/*`                 | aucune                   | `docs.$.tsx`                          |

## Authentification

Le layout `/auth` (`auth.tsx`) n'a pas de guard ; ce sont les pages individuelles qui en ont un.

| Chemin                  | Constante         | Fichier de route           | Guard                                                              |
| ----------------------- | ----------------- | -------------------------- | ------------------------------------------------------------------ |
| `/auth/sign-in`         | `SIGN_IN`         | `auth.sign-in.tsx`         | `redirectIfSignedIn`                                               |
| `/auth/sign-up`         | `SIGN_UP`         | `auth.sign-up.tsx`         | `redirectIfSignedIn`                                               |
| `/auth/forgot-password` | `FORGOT_PASSWORD` | `auth.forgot-password.tsx` | aucun                                                              |
| `/auth/reset-password`  | `RESET_PASSWORD`  | `auth.reset-password.tsx`  | aucun                                                              |
| `/auth/two-factor`      | `TWO_FACTOR`      | `auth.two-factor.tsx`      | aucun                                                              |
| `/auth/verify-email`    | `VERIFY_EMAIL`    | `auth.verify-email.tsx`    | Redirige un `token` vers l'endpoint de vérification de Better Auth |
| `/auth/callback`        | `AUTH_CALLBACK`   | `auth.callback.tsx`        | `redirectAfterAuth`                                                |

## API

Les chemins d'API ne sont jamais localisés.

| Chemin        | Constante       | Fichier de route |
| ------------- | --------------- | ---------------- |
| `/api`        | `API`           | `api/index.ts`   |
| `/api/auth/*` | `API_AUTH_BASE` | `api/auth.$.ts`  |
| `/api/search` | aucune          | `api/search.ts`  |

`ROUTES.API_AUTH` liste les chemins des endpoints Better Auth relatifs à `/api/auth` ; `auth.server.ts` s'en sert pour exempter certains endpoints de la limitation de débit. `API_AUTH_CUSTOMER_PORTAL` et `API_AUTH_VERIFY_EMAIL` sont des chemins complets vers des endpoints Better Auth. `AUTH` et `NEWSLETTER` n'ont pas de page propre ; avec `ADMIN`, `APP` et `API`, ils délimitent les zones qui ne sont jamais prérendues.
