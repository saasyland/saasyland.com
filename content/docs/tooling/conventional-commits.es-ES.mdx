---
title: "Commits convencionales"
description: "Formato de los mensajes de commit y el hook de emojis."
---

Los asuntos de los commits siguen el formato `<type>(<scope>): <description>`. El ámbito es opcional y `!` indica un cambio incompatible. Escribe el asunto sin emoji:

```sh
git commit -m "fix(auth): keep the locale in verification links"
```

El hook `prepare-commit-msg` de `.vite-hooks/` ejecuta `bun scripts/commit-msg.ts`, que valida el asunto y le antepone el emoji correspondiente a su tipo, de modo que el commit anterior pasa a ser `🐛 fix(auth): keep the locale in verification links`.

<RepositoryTable name="commitTypes" columns={["Tipo", "Emoji"]} />

Cualquier otro tipo, o un asunto que no siga el formato convencional, cancela el commit y muestra la lista de tipos permitidos. El hook no modifica los asuntos que ya empiezan por un emoji ni los que ha generado Git (`Merge`, `Revert "`, `fixup!`, `squash!`), y tampoco los mensajes de merge, de squash ni de plantilla.

Antes del hook del mensaje, el hook `pre-commit` ejecuta `bun run check:pre-commit`. Después, el hook `commit-msg` ejecuta `bun scripts/verify-commit-msg.ts` sobre el mensaje que Git está a punto de registrar y cancela un commit que atribuye el trabajo a una herramienta de IA: un trailer `Co-Authored-By`, `Signed-off-by` u otro trailer `-by:` que nombra una de las herramientas de `AI_TOOLS`, o una línea que empieza por «Generated with». Omite las líneas que Git descarta, es decir, los comentarios y el diff que queda debajo de la línea de tijeras de `git commit -v`, e indica cada línea que hay que quitar. No omitas los hooks.
