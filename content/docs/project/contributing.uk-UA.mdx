---
title: "Участь у розробці"
description: "Як запропонувати зміни до SaaSy Land."
---

1. Спершу обговоріть великі зміни в issue.
2. Створіть гілку від `main`.
3. Дотримуйтеся [архітектури](/docs/architecture) та [конвенцій](/docs/reference/conventions), а перед зміною інтеграції з постачальником прочитайте відповідну [навичку агента](/docs/tooling/agent-skills).
4. Розміщуйте тести поруч із їхнім власником і підтримуйте поріг покриття 100%.
5. Запустіть наведені нижче перевірки.
6. Зробіть коміт із повідомленням у форматі [conventional commits](/docs/tooling/conventional-commits) і відкрийте pull request із заголовком у тому самому форматі.

```sh
bun run check
bun run test:coverage
bun run test:e2e:install
bun run test:e2e:smoke
```

Для змін, які зачіпають кілька маршрутів, автентифікацію або поведінку браузера, запускайте повний набір браузерних тестів (`bun run test:e2e`). Коли змінюєте конфігурацію реальних інтеграцій із провайдерами, перевіряйте їх окремо.

Коли змінюється поведінка, оновіть `content/docs` в усіх дев'яти локалях; `bun run check:i18n` відхиляє відсутні переклади, а також відмінності в блоках коду та навігації. У pull request опишіть підсумкову поведінку, як ви її перевірили, а також демонстраційні чи незавершені сценарії, які залишаються.
