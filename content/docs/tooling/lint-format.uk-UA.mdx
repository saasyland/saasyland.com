title: "Лінтинг і форматування"
description: "oxlint і oxfmt через Vite+ та скрипти перевірок."
---

Vite+ запускає oxfmt для форматування та oxlint для лінтингу; обидва налаштовано в секціях `fmt` і `lint` файлу `vite.config.ts`. `bun run check` — це перевірка, яку запускає CI:

```sh
bun run check
```

Вона запускає `generate:cn`, `check:comments`, `check:i18n`, `check:flows` і `vp check`, що перевіряє форматування, застосовує правила лінтера та перевіряє типи проєкту. Щоб запустити лише один інструмент, використовуйте `bun run lint`, `bun run format` і `bun run format:check`.

## Форматування

- Без крапок з комою, подвійні лапки, завершальні коми, відступ (кількість пробілів: <RepositoryFact name="tabWidth" />), ширина рядка <RepositoryFact name="printWidth" /> і закінчення рядків LF.
- Імпорти впорядковано у фіксовані групи: лише серверні, `cloudflare:workers`, React, зовнішні пакети, потім області `~/src` (platform, providers, integrations, modules, routes, hooks, дані й тема, types, lib, branding, компоненти shadcn, власні компоненти, стилі), а потім відносні імпорти.
- Класи Tailwind сортуються в `className` і всередині викликів `cn`, `cva`, `clsx` і `tw`.

## Лінтинг

- Категорії `correctness`, `nursery`, `pedantic`, `perf`, `style` і `suspicious` є помилками.
- Увімкнено правила з урахуванням типів і перевірку типів (`typeAware` і `typeCheck`).
- Помітні обмеження: максимальна кількість рядків на файл — <RepositoryFact name="maxLines" />, рядків на функцію — <RepositoryFact name="maxLinesPerFunction" />, інструкцій на функцію — <RepositoryFact name="maxStatements" />, жодних магічних чисел, крім `0` і `1`, жодного явного `any` (`typescript/no-explicit-any`) та ідентифікатори щонайменше з двох символів, за винятком `_`, `m` і `t`.
- Перевизначення послаблюють кілька правил для тестів, коду представлення та хуків, тестових моків і файлів маршрутів.
- `jsPlugins` завантажує власні oxlint-плагіни репозиторію: `scripts/code-style-lint-plugin.ts`, чиї правила `code-style/no-comments`, `code-style/no-multiline-ternary` і `code-style/no-undefined-fallback` відхиляють кожен коментар, кожен тернарний оператор, що займає кілька рядків, і кожен `?? undefined` (див. [Стиль коду](/docs/conventions/code-style)), `scripts/hydration-lint-plugin.ts`, чиє правило `hydration/no-clock-or-locale-in-render` не дає коду рендерингу читати годинник чи локаль середовища виконання (див. [Стиль коду](/docs/conventions/code-style)), `scripts/admin-data-lint-plugin.ts`, чиє правило `admin-data/no-literal-data` не пускає демонстраційні дані в код адмінпанелі (див. [Панель адміністратора](/docs/features/admin-dashboard#real-data-only)), і `scripts/radius-lint-plugin.ts`, чиє правило `radius/no-off-scale` тримає кожен кут на шкалі заокруглень (див. [Тема](/docs/ui/theme#corner-radius)).
- Обхідні шляхи заборонено поіменно: `typescript/ban-ts-comment` відхиляє `@ts-expect-error`, `@ts-ignore` і `@ts-nocheck` навіть із поясненням, `typescript/consistent-type-assertions` з `assertionStyle: "never"` відхиляє кожне твердження типу, крім `as const`, а `respectEslintDisableDirectives: false` робить так, що коментар `eslint-disable` нічого не вимикає. `code-style/no-comments` замінює `capitalized-comments`, `no-inline-comments` і `no-warning-comments`, які вмикають категорії і кожне з яких бачило лише частину коментарів, тож ці три правила вимкнено.

Обидва інструменти ігнорують згенеровані та зовнішні файли: файли оголошень, `src/routeTree.gen.ts`, міграції, `.source`, `dist`, `coverage`, `e2e`, `remotion`, папки агентів і результати Playwright. `scripts/` форматується та лінтиться так само, як `src/`. `bun run check:comments` також читає те, що пропускає лінтер: `e2e`, `remotion`, файли оголошень і таблиці стилів.

Форматер також сортує `package.json`, зокрема його `scripts` за абеткою (`sortPackageJson: { sortScripts: true }`), тож `vp check` завершується помилкою, коли скрипт стоїть не на своєму місці.

Усувайте причину помилки лінтера. Не додавайте коментарів вимкнення, `@ts-expect-error` чи приведень `as`, щоб задовольнити правило. Коментар вимкнення — це теж коментар, і лінтер підкоряється йому раніше, ніж його побачить будь-яке правило, тож `bun run check:comments`, що працює поза лінтером, відхиляє його, де б він не стояв.

## Виправлення

Хук pre-commit запускає `bun run check:pre-commit`; його крок `vp staged` запускає `vp check --fix` лише для проіндексованих файлів. `bun run check:fix` застосовує виправлення в усьому репозиторії й може переписати файли, яких ви не торкалися, тож перегляньте його diff перед комітом. Щоб виправити лише власні зміни, передайте їхні шляхи до `vp` (глобального Vite+ CLI або `bunx vp`):

```sh
vp fmt src/routes/admin.users.all.tsx
vp lint --fix src/routes/admin.users.all.tsx
```
