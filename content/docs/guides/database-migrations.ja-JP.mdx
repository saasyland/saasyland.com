---
title: "データベースマイグレーション"
description: "Drizzle スキーマを変更し、SQL マイグレーションを生成して、各 D1 データベースに適用します。"
---

アプリケーションのデータベースは Cloudflare D1（SQLite）です。モジュールのスキーマは `drizzle-orm/sqlite-core` を使い、`src/integrations/drizzle-orm/drizzle.schemas.ts` がそれらを集約します。drizzle-kit は、タイムスタンプのプレフィックスを付けてマイグレーションを `src/integrations/drizzle-orm/migrations/` に書き出します。

## ワークフロー

1. `<table>.schema.ts` を変更します。新しいテーブルの場合は、`drizzle.schemas.ts` からもエクスポートします。
2. SQL を生成します。

```sh
bun run db:generate
```

3. 生成されたファイルを確認し、スキーマの変更と一緒にコミットします。
4. 作業中のデータベースに適用します。`deploy:preview`、`deploy:production`、CI は、デプロイの前にプレビューまたは本番のデータベースに適用します。

## コマンド

| コマンド                        | データベース                                                                             |
| ------------------------------- | ---------------------------------------------------------------------------------------- |
| `bun run db:migrate:local`      | `.wrangler/state` にあるローカルの開発用データベース。`bun run dev` で使用               |
| `bun run db:reset:local`        | ローカルの開発用データベースを削除後、再度マイグレーション                               |
| `bun run db:migrate:test`       | `.wrangler/test` にあるローカルのテスト用データベース。Playwright と分離プレビューで使用 |
| `bun run db:reset:test`         | `.wrangler/test` を削除後、ローカルのテスト用データベースを再度マイグレーションしシード  |
| `bun run db:migrate:preview`    | リモートのプレビュー用データベース                                                       |
| `bun run db:migrate:production` | リモートの本番データベース                                                               |

`bun run db:migrations:local`、`db:migrations:preview`、`db:migrations:production` は、データベースにまだ適用されていないマイグレーションを一覧表示します。`bun run db:studio:local` は、ローカルのデータベースファイルを対象に Drizzle Studio を開きます。`db:studio:preview` と `db:studio:production` はリモートのデータベースを対象に Drizzle Studio を開き、`db:introspect:*` スクリプトはリモートのデータベースをイントロスペクトします。どちらも、対応する環境ファイルの `CLOUDFLARE_ACCOUNT_ID`、`CLOUDFLARE_DATABASE_ID`、`CLOUDFLARE_ACCESS_TOKEN` を使い、D1 HTTP API 経由で動作します。[データベース](/docs/tooling/database)を参照してください。

## スキーマの規約

- 日付は `integer(..., { mode: "timestamp_ms" })` で、デフォルト値は `(unixepoch() * 1000)` です。テーブルの `createdAt` と `updatedAt` は `src/integrations/drizzle-orm/drizzle.columns.ts` の `...timestamps()` で追加します。
- 真偽値は `integer(..., { mode: "boolean" })` です。
- インデックス、ユニーク制約、外部キー、リレーションは、スキーマファイルに置きます。
- D1 には対話型のトランザクションがありません。`getUsers` やレートリミッターのように、単一の SQL 文または `db.batch([...])` で操作をアトミックに保ちます。

## テスト

テスト用の D1 バインディングは、マイグレーションフォルダー内のすべての SQL ファイルをインメモリの SQLite データベースに適用するため、D1 を使うテストはマイグレーション済みのスキーマに対して実行されます。`src/integrations/drizzle-orm/__test__/` は、スキーマ、インデックス、外部キーが実際に作成されることをチェックします。その中の `migrations.test.ts` は、`order` と `subscription` のテーブルを追加するマイグレーションを、それらのテーブルとインデックスの `CREATE` 文だけに限定し、その直前のマイグレーションまで適用したデータベースで、それ以前のテーブルとインデックスがすべて元のまま残ることをチェックします。また、ライセンスの記録を追加するマイグレーションを、NULL を許容する列を追加する 3 つの `ALTER TABLE … ADD` 文だけに限定し、ほかのすべてのテーブル、すべてのインデックス、既存のライセンスが元のまま残り、新しい列が空であることをチェックします。さらに、コースのコンテンツを追加するマイグレーションを、`lesson_attachment` の 1 つの `CREATE TABLE` と 1 つの `CREATE INDEX`、それに続く既定値を持つ列を追加する `ALTER TABLE … ADD` 文だけに限定し、ほかのすべてのテーブルとインデックス、既存のコース、チャプター、レッスン、動画が元のまま残り、新しい列が既定値になっていること、そしてレッスンを削除するとその資料が削除されることをチェックします。加えて、最初の有料レッスンを記録するマイグレーションを、`license` に NULL を許容する列を追加する 2 つの `ALTER TABLE … ADD` 文だけに限定し、ほかのすべてのテーブル、すべてのインデックス、既存のライセンスが元のまま残り、新しい列が空であることをチェックします。[テストを書く](/docs/guides/writing-tests) を参照してください。

## 既存の PostgreSQL のデータ

これらのマイグレーションが作成するのは SQLite のスキーマだけです。以前の PostgreSQL 環境からデータを移行するには、別途レビューを経たエクスポートとインポートが必要です。
