---
title: "Plantillas de correo"
description: "Escribe plantillas de React Email con mensajes traducidos y envíalas desde casos de uso a través de Resend."
---

Un correo tiene tres partes: una plantilla en `src/presentation/emails/`, un espacio de nombres de mensajes en `messages/<locale>/emails.<name>.json` y el caso de uso que carga los mensajes, renderiza la plantilla y la envía. Plantillas: `verify-email`, `reset-password-email`, `change-email-confirmation-email`, `newsletter-confirmation-email` y `newsletter-notification-email`.

## Plantilla

Una plantilla contiene solo marcado y exporta su espacio de nombres. Traduce con `createTranslator` de `use-intl` porque se renderiza fuera del contexto de React. `src/presentation/emails/verify-email.tsx`:

```tsx
import type { JSX } from "react"

import { Body, Button, Container, Head, Heading, Html, Preview, Section, Tailwind, Text, pixelBasedPreset } from "react-email"
import { createTranslator } from "use-intl"

import type { SupportedLocale } from "~/src/integrations/use-intl/i18n.config"

import type emailMessages from "~/messages/en-US/emails.verify-email.json"

export const VERIFY_EMAIL_NAMESPACE = "emails.verify-email"

const TAILWIND_CONFIG = { presets: [pixelBasedPreset] }

interface VerifyEmailProps {
  readonly locale: SupportedLocale
  readonly messages: typeof emailMessages
  readonly name: string
  readonly verifyUrl: string
}

export const VerifyEmail = ({ messages, locale, name, verifyUrl }: Readonly<VerifyEmailProps>): JSX.Element => {
  const t = createTranslator({ locale, messages: { emails: { "verify-email": messages } }, namespace: "emails.verify-email" })

  return (
    <Html lang={locale}>
      <Tailwind config={TAILWIND_CONFIG}>
        <Head />
        <Body className="font-sans">
          <Preview>{t("preview")}</Preview>
          <Container className="mx-auto px-5 py-10">
            <Section>
              <Heading className="m-0 mb-4 text-2xl font-bold">{t("heading")}</Heading>
              <Text className="m-0 mb-6 text-base text-neutral-600">{t("body", { name })}</Text>
              <Button
                href={verifyUrl}
                className="box-border rounded-md bg-neutral-900 px-5 py-3 text-center text-base text-white no-underline"
              >
                {t("button")}
              </Button>
              <Text className="mt-6 text-sm text-neutral-500">{t("footer")}</Text>
            </Section>
          </Container>
        </Body>
      </Tailwind>
    </Html>
  )
}
```

## Mensajes

Crea `messages/<locale>/emails.<name>.json` en los nueve idiomas. Incluye una clave `subject`; el caso de uso la traduce aparte del cuerpo.

```json
{
  "subject": "Verify your email address",
  "preview": "Verify your email for SaaSy Land",
  "heading": "Verify your email",
  "body": "Hi {name}, thanks for signing up. Confirm your email address to finish setting up your account.",
  "button": "Verify email",
  "footer": "If you did not create an account, you can safely ignore this email."
}
```

Las rutas nunca precargan los espacios de nombres de correo; los carga en el servidor el caso de uso que envía el mensaje.

## Envío

El caso de uso recibe el idioma, carga los mensajes, construye enlaces absolutos con `localizePathname` y llama a `sendEmail`. `src/modules/verification/use-cases/send-verify-email.ts`:

```ts
export const sendVerifyEmail = async ({
  locale,
  token,
  user,
}: {
  locale: SupportedLocale
  token: string
  user: { email: string; name: string }
}): Promise<void> => {
  const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
  const verifyUrl = new URL(localizePathname({ locale, pathname: ROUTES.VERIFY_EMAIL }), getRequest().url)
  verifyUrl.searchParams.set("token", token)

  await sendEmail({
    idempotencyKey: `verify-email/${token}`,
    react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
    subject: createTranslator({ locale, messages })("subject"),
    to: user.email,
  })
}
```

`sendEmail` (`src/integrations/resend/resend.utils.ts`) envía a través de Resend desde `RESEND_EMAIL_FROM` salvo que se indique `from`, pasa la clave de idempotencia para que un reintento nunca envíe dos veces y lanza un error cuando Resend lo devuelve.

## Quién envía qué

- Los hooks de Better Auth en `src/integrations/better-auth/auth.server.ts` llaman a los casos de uso: `sendVerifyEmail` para `emailVerification.sendVerificationEmail` y para los registros repetidos de cuentas sin verificar, `sendResetPasswordEmail` para `emailAndPassword.sendResetPassword` y `sendChangeEmailConfirmationEmail` para `user.changeEmail`.
- Las peticiones de Better Auth llegan a `/api/auth` sin prefijo de idioma, así que los hooks toman el idioma del correo del `callbackURL` del flujo, una ruta de página localizada, con `extractLocaleFromCallbackURL` o `extractLocaleFromPath` de `src/integrations/use-intl/i18n.paths.ts`. El inglés es el idioma de reserva.
- Los casos de uso del boletín envían ellos mismos los correos de confirmación y de notificación, por ejemplo `subscribeToNewsletter`.

## Añade un correo

1. Añade la plantilla en `src/presentation/emails/<name>.tsx` con su `<NAME>_NAMESPACE` exportado.
2. Añade `messages/<locale>/emails.<name>.json` en los nueve idiomas.
3. Envíalo desde el caso de uso al que pertenece la acción, con una clave de idempotencia derivada del token o registro que lo desencadena.
4. Prueba la plantilla en `src/presentation/emails/__test__/` y el caso de uso con `sendEmail` simulado.

Credenciales de Resend: `RESEND_API_KEY` y `RESEND_EMAIL_FROM`. Los tests nunca contactan con Resend.
