## Маршрути складають сторінки

Файл маршруту визначає компонент `<Name>Page` або `<Name>Layout`, `NAMESPACE` або `NAMESPACES`, loader і `head`. Сторінка лише розміщує віджети; віджети розташовані в `src/presentation/components/custom/<area>/`. Так виглядає макет (`src/routes/app.tsx`):

```tsx title="src/routes/app.tsx"
const AppLayout = (): JSX.Element => (
  <SidebarProvider className="h-svh overflow-hidden">
    <AppSidebar />
    <SidebarInset className="relative min-h-0 min-w-0 overflow-hidden">
      <Background className="z-[-1]" glow={false} />
      <ImpersonationBanner />
      <AppHeader />
      <div
        className="custom-scrollbar flex min-h-0 flex-1 flex-col overflow-y-auto px-4 pt-5 pb-6 md:px-6 md:pt-7 md:pb-8"
        data-page-scroller
      >
        <div className="mx-auto w-full max-w-5xl">
          <EmailVerificationBanner />
          <Outlet />
        </div>
      </div>
    </SidebarInset>
  </SidebarProvider>
)
```

Замість вікна прокручується область вмісту, тому вона має `data-page-scroller`; див. [Смуги прокручування](/docs/ui/theme#scrollbars).

Серверну функцію, яку використовує лише один маршрут, можна визначити в його файлі через `createServerFn`.

## Один віджет, діалог або форма на файл

Кожен віджет, діалог, форма чи набір стовпців має власний файл: `admin/users/row-actions.tsx`, `delete-user-dialog.tsx`, `reset-password-dialog.tsx`, `user-columns.tsx`. Теки компонентів пласкі: без вкладених тек `components/`, `hooks/`, `constants/` чи `types/` і без поділу на `x.tsx` та `x-content.tsx`. Спільні компоненти лежать безпосередньо в `custom/`.

## Компоненти самі читають свої дані

Компонент сам отримує тексти й дані, а не приймає їх через властивості:

- переклади — через `useTranslations`;
- дані запитів — через `useSuspenseQuery`, уже завантажені loader маршруту;
- дані loader, контекст маршруту й параметри пошуку — через `getRouteApi("…")`.

```tsx title="src/presentation/components/custom/blog/post-meta.tsx"
const route = getRouteApi("/_site/_marketing/blog/$")

const timeTag =
  (value: Date) =>
  (chunks: ReactNode): JSX.Element => (
    <time className="tabular-nums" dateTime={value.toISOString()}>
      {chunks}
    </time>
  )

export const PostMeta = (): JSX.Element => {
  const { post } = route.useLoaderData()
  const t = useTranslations("pages.blog")
  const format = useFormatter()

  const published = new Date(post.date)
  const updated = new Date(post.updated ?? post.date)
  const dateOf = (value: Date): string => format.dateTime(value, "calendarDate", { month: "long" })
  const tags = post.tags.map((tag) => t(`tags.${tag}`)).join(", ")
  const details = [BLOG_AUTHORS[post.author].name, t("post.readingTime", { minutes: post.readingTimeMinutes }), tags].filter(
    (item) => item.trim().length > 0,
  )

  return (
    <div className="flex flex-wrap items-center gap-x-3 gap-y-2 py-1 text-body-sm text-muted-foreground tabular-nums">
      <span className="flex items-center gap-2.5">
        <span aria-hidden className="size-1.25 shrink-0 rounded-full bg-ring" />
        <span>{t.rich("post.published", { date: dateOf(published), time: timeTag(published) })}</span>
      </span>
      {updated.getTime() > published.getTime() && (
        <span className="flex items-center gap-3">
          <span aria-hidden className="text-border">
            &middot;
          </span>
          <span>{t.rich("post.updated", { date: dateOf(updated), time: timeTag(updated) })}</span>
        </span>
      )}
      {details.map((item) => (
        <span className="flex items-center gap-3" key={item}>
          <span aria-hidden className="text-border">
            &middot;
          </span>
          {item}
        </span>
      ))}
    </div>
  )
}
```

Властивості передають ідентичність або стан, відомий лише батьківському компоненту, наприклад `user` діалогу разом з `isOpen` і `onOpenChange` або `activationId`. Немає властивостей із текстом чи мітками, передавання властивостей крізь кілька рівнів і обгорток, які лише перейменовують властивості або передають дочірні елементи. Константа, яку використовує один файл, залишається в ньому; дані, спільні для кількох файлів, потрапляють до `src/data`.

## Форматований текст

Мапи тегів для `t.rich` — це константи модуля, а не об’єкти, створені під час рендерингу:

```tsx
const REUSE_TAGS = { accent: (chunks: ReactNode) => <strong className="font-medium text-foreground">{chunks}</strong> }
```

## Умовні класи

Використовуйте `cn` з `~/src/lib/cn` з об’єктним синтаксисом:

```tsx
<p className={cn("font-medium", { "text-foreground": !banned, "text-muted-foreground line-through": banned })}>{name}</p>
```

Альтернативи рендерте парою умов `&&` або раннім поверненням замість багаторядкового тернарного оператора.

## Провайдери

Провайдери, що змінюються після гідратації, обгортають лише віджети, яким вони потрібні, і ніколи — `Outlet` маршруту: `ThemeProvider` обгортає `Toaster` і `ThemeSwitch` документації, а `MotionProvider` — розділи головної сторінки, список дописів блогу, сторінки архіву блогу та картки планів `LicenseOffer`. `AriaProvider` обгортає кореневий outlet, а `TranslationsProvider` — тіло документа, бо вони потрібні кожному екрану.
