`src/modules/account` possède la table `account` de Better Auth (`account.schema.ts`) : une ligne par identifiant ou fournisseur OAuth lié à un utilisateur. Les jetons OAuth qu’elle contient sont chiffrés.

## Cas d’usage

| Cas d’usage                        | Middleware       | Utilisé par                                                                   |
| ---------------------------------- | ---------------- | ----------------------------------------------------------------------------- |
| `signUpWithPassword`               | limité           | `SignUpForm`                                                                  |
| `signOutUser`                      | connecté         | `useSignOut`                                                                  |
| `changePassword`                   | connecté, limité | `PasswordCard`                                                                |
| `setPassword`                      | connecté, limité | `PasswordCard`                                                                |
| `changeEmail`                      | connecté, limité | `ChangeEmailForm`                                                             |
| `listAccounts`                     | connecté         | `PasswordCard`, `TwoFactorCard`, `ConnectedAccountsCard`, `DeleteAccountCard` |
| `unlinkAccount`                    | connecté, limité | `ConnectedAccountsCard`                                                       |
| `updateUser`                       | connecté         | aucun écran                                                                   |
| `sendChangeEmailConfirmationEmail` | hook Better Auth | `user.changeEmail` dans `auth.server.ts`                                      |

`sendChangeEmailConfirmationEmail` envoie `ChangeEmailConfirmationEmail` à l’adresse actuelle avec le lien de confirmation fourni par Better Auth. `changePassword` révoque toujours les autres sessions. `setPassword` ajoute un mot de passe à un compte qui ne se connecte qu’avec GitHub ou Google, via le `setPassword` de Better Auth réservé au serveur, révoque les autres sessions et envoie `PasswordChangedEmail`. `listAccounts` renvoie, pour chaque moyen de connexion, l’ID de sa ligne, son fournisseur et sa date de création, sans les jetons, et `unlinkAccount` transmet un ID de ligne à `unlinkAccount` de Better Auth, qui refuse de dissocier le dernier.

## Supprimer un compte

La suppression retire l’utilisateur : ses cas d’usage se trouvent donc dans le module utilisateur. `requestAccountDeletion` (connecté, limité) demande à `deleteUser` de Better Auth de vérifier le mot de passe et d’envoyer par e-mail un lien de confirmation, et `confirmAccountDeletion` (connecté, limité comme un jeton) supprime le compte avec le jeton du lien. `sendDeleteAccountEmail` (`src/modules/user/use-cases/send-delete-account-email.ts`) est le hook `sendDeleteAccountVerification`. Voir [Paramètres](/docs/features/settings#delete-account).

## Préférences

Le fuseau horaire qu’un utilisateur choisit dans les [Paramètres](/docs/features/settings) est une colonne de la table `user` : son cas d’usage se trouve donc dans le module utilisateur. `updatePreferences` (`src/modules/user/use-cases/update-preferences.ts`) exige un utilisateur connecté, valide la saisie avec `userZodSchemas.updatePreferences` et l’enregistre via `updateUser` de Better Auth, par le même chemin que la mise à jour du profil ci-dessus. `PreferencesCard` l’appelle sur `/app/settings` et `/admin/settings`. La langue correspond à la locale de l’URL et n’est pas enregistrée.

## Déconnexion

`useSignOut` (`src/hooks/use-sign-out.ts`) exécute `signOutUserMutation`, supprime du cache des requêtes les données du compte, navigue vers `/auth/sign-in` et affiche une notification. Le widget utilisateur de l’administration et la barre latérale de `/app` affichent chacun un `SignOutButton` qui l’utilise.
