<LegalNotice />

Polar は 3 つのプランをチェックアウトが送る価格で販売し、そのライセンスキーを発行し、税を課します。コードは Polar 側に決まった設定があることを前提としていますが、両者が食い違っても Polar は警告しません。たとえば、ライセンスキーの特典がない商品でも支払いは受け付けますが、キーは発行されません。`bun run polar:verify:<environment>` は Polar とコードを比較し、デプロイスクリプトは手動デプロイのたびに事前にこれを実行します。

## 本番とサンドボックス

Polar は 2 つの独立したサービスを運営しています。本番（`polar.sh`、API は `api.polar.sh`）は実際のカードに請求し、サンドボックス（`sandbox.polar.sh`、API は `sandbox-api.polar.sh`）はテスト用のカードしか受け付けません。両者は何も共有しません。アカウント、組織、トークン、商品、割引、Webhook はどれも一方のサービスにしか存在しないため、`sandbox.polar.sh` には別途サインアップし、それぞれのサービスを個別に設定してください。

| 環境ファイル       | `POLAR_SERVER` | Polar の組織   |
| ------------------ | -------------- | -------------- |
| `.env.development` | `sandbox`      | サンドボックス |
| `.env.preview`     | `sandbox`      | サンドボックス |
| `.env.production`  | `production`   | 本番           |

開発とプレビューはサンドボックスの組織を 1 つ共有できますが、その組織の Webhook が届くのはプレビューだけです。Webhook はプレビューのホストに送信され、プレビューの D1 データベースに書き込まれますが、`bun run dev` は専用のローカルデータベースを使います。そのため、開発で行ったテスト購入ではローカルにライセンスが付与されません。購入を最初から最後まで試すにはプレビューを使ってください。

`.env.development` や `.env.preview` に、本番のトークン、組織 ID、商品 ID を入れないでください。サンドボックスの API は本番のトークンを拒否します。また `POLAR_SERVER=production` にすると、テスト購入で実際のカードに請求され、ローカルまたはプレビューのデータベースでライセンスが付与されてしまいます。`polar:verify` は、開発とプレビューでは `POLAR_SERVER=production` を、本番では `POLAR_SERVER=sandbox` を拒否します。

## 組織とトークン

サンドボックスで、次に本番で、以下を行います。

1. 組織を作成し、組織の設定からその ID を `POLAR_ORGANIZATION_ID` にコピーします。両方の組織のスラッグを `POLAR_ORGANIZATION_SLUG`（`src/integrations/polar/polar.constants.ts`）の値にするか、この定数を組織のスラッグに変更します。[アカウントに対応しない注文のアラートと管理画面の一覧](/docs/features/licences#orders-that-match-no-account)は、このスラッグを使って各注文を Polar のダッシュボードにリンクします。
2. 組織の設定で、次のスコープだけを持ち、それ以外のスコープを持たない組織アクセストークンを作成し、`POLAR_ACCESS_TOKEN` にコピーします。

| スコープ                  | 必要とする箇所                                                                                                                                                                                                                                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `checkouts:write`         | Polar SDK（`polar.checkouts.create`）ですべての購入セッションを作成する `createCheckout`                                                                                                                                                                                                               |
| `customer_sessions:write` | カスタマーポータルへのリンク `/api/auth/customer/portal`                                                                                                                                                                                                                                               |
| `license_keys:write`      | キーとそのアクティベーションの読み取り、端末のアクティベート、およびアクティベーションの解除（`deactivateLicense` と [CLI ライセンス API](/docs/features/cli-licence-api)）、さらにアップグレードでのキーのアクティベーション数の上限の引き上げと、アップグレードの注文に Polar が発行するキーの無効化 |
| `orders:read`             | ライセンスの元になった注文と、イベントがどのアカウントにも対応しない注文の現在の顧客を読み取る Webhook ハンドラー、顧客がライセンスに支払った額を合計してアップグレードの価格を求める処理、注文とその請求書を読み取る管理画面の注文ページ、各注文の割引と請求先の国をコピーする `orders:backfill`      |
| `organizations:read`      | チェックアウトのローカライズがオンかどうか、デフォルトの税の扱い、チェックアウトを埋め込めるホストを読み取る `polar:verify`                                                                                                                                                                            |
| `products:read`           | `/admin/products` に商品を一覧表示し、ダッシュボードで数える `getPolarProducts`（[商品](/docs/features/products)）と `polar:verify`                                                                                                                                                                    |
| `webhooks:read`           | `polar:verify`                                                                                                                                                                                                                                                                                         |

書き込みスコープには読み取りも含まれるため、`license_keys:write` でキーの読み取りもできます。組織トークンは、もともと自分の組織として動作します。それでも `polar:verify` は、アップグレードのための注文の一覧取得や `getPolarProducts` と同じように `POLAR_ORGANIZATION_ID` を `organization_id` クエリパラメーターとして送信するため、別の組織の ID を指定していると、商品がないものとして検出されます。デプロイ済みの Worker は、最後の `deploy:preview` または `deploy:production` がアップロードしたトークンを使い続けるため、新しいトークンがサイトに反映されるのは次の手動デプロイのときです。

## 商品

プランごとに 1 つの商品を作成します。サブスクリプションではなく買い切りの商品とし、価格は `DEFAULT_CURRENCY_CODE`（米ドル）建ての固定価格で、`src/data/license.ts` の `TIER_PRICES` と同じ額にします。各商品の ID を対応するキーにコピーします。

| プラン   | キー                        | 価格                          | キーあたりのアクティベーション数    |
| -------- | --------------------------- | ----------------------------- | ----------------------------------- |
| Core     | `POLAR_PRODUCT_ID_CORE`     | <TierPrice tier="core" />     | <ActivationLimit tier="core" />     |
| Complete | `POLAR_PRODUCT_ID_COMPLETE` | <TierPrice tier="complete" /> | <ActivationLimit tier="complete" /> |
| Agency   | `POLAR_PRODUCT_ID_AGENCY`   | <TierPrice tier="agency" />   | <ActivationLimit tier="agency" />   |

Polar は価格を通貨の補助単位（米ドルではセント）で保存し、`polar:verify` は比較の前に `TIER_PRICES` を同じように変換します。アーカイブ済みの価格は無視します。

## ライセンスキー

プランごとに **License Keys** タイプの特典を 1 つ作成し、そのプランの商品だけに付けて、次のように設定します。

- **アクティベーション**: 上の表の数、つまり `src/modules/license/license.constants.ts` の `LICENSE_ACTIVATION_LIMITS` に制限します。`/app/license` 自体がアクティベーションを一覧表示して解除できるため、顧客に Polar でアクティベーションを管理させるかどうかは任意です。
- **有効期限**: なし。購入は 1 回限りの支払いなので、キーは失効しません。
- **使用回数の上限**: なし。
- **プレフィックス**: 任意です。`polar:verify` はチェックしません。

各商品には、ライセンスキーの特典がちょうど 1 つ必要です。それ以外の特典が一緒に付いていても問題ありません。Polar が特典を付与すると、`benefit_grant.created` Webhook がキーを購入者のライセンスに保存します。

## 同意のチェックボックス [#consent-checkbox]

購入者は Polar のチェックアウトで即時提供に同意し、同意を求めるのはこのフィールドだけです（[ライセンス](/docs/features/licences#consent-to-immediate-supply)を参照）。Polar はその同意を注文に記録します。組織にカスタムフィールドを 1 つ作成し、3 つの商品に付けてください。

- **タイプ**: チェックボックス。
- **スラッグ**: <RepositoryFact name="licenseWithdrawalConsentField" />。`src/modules/license/license.constants.ts` の `LICENSE_CHECKOUT_FIELD.WITHDRAWAL_CONSENT` です。注文は、チェックされたボックスを `custom_field_data` のこのキーに保存します。
- **ラベル**: `src/lib/polar.ts` の `WITHDRAWAL_CONSENT_FIELD.label` と完全に同じにします。これは `REFUND_TERMS.WITHDRAWAL_DAYS` から組み立てる英語の文で、本番の返金ポリシーへの Markdown リンクで終わります。
- **名前**: 任意です。コードが提案するのは `WITHDRAWAL_CONSENT_FIELD.name` で、`polar:verify` はチェックしません。
- **必須**: 3 つの商品のそれぞれで必須にします。商品が求めるほかのフィールドは残しておいてかまいません。

3 つのプランのチェックアウトを開始するライセンスの `startCheckout` (`src/modules/license/use-cases/start-checkout.ts`) はこのフィールドに値を送らないため、ボックスは空の状態で始まり、購入者がチェックを入れます。必須のボックスが空のままでは Polar は支払いを受け付けません。Polar は、商品が求めるフィールドの値しか保持しません。そのため、フィールドを付ける前でもチェックアウトは機能しますが、注文には同意が記録されず、[購入確認メール](/docs/features/licences#purchase-confirmation)では代わりに法定の撤回権が案内されます。

フィールドを作成して商品に付けるには `custom_fields:write` と `products:write` のスコープが必要ですが、上記のトークンにはこれらのスコープがありません。Polar のダッシュボードで作成して付けるか、これらのスコープを持つ別のトークンを使って API で行ってください。`polar:verify` は商品の一覧から付いているフィールドを読み取るため、ほかのスコープは必要ありません。

## チェックアウトの言語 [#checkout-language]

Polar が `createCheckout` の求める言語でチェックアウトを表示するのは、組織でチェックアウトのローカライズがオンになっている間だけです。オフの場合、すべてのチェックアウトは英語で開きます。組織の設定でオンにしてください。Polar の[チェックアウトのローカライズのガイド](https://polar.sh/docs/features/checkout/localization)はこれを機能フラグと呼び、API は組織の `feature_settings.checkout_localization_enabled` として返します。コードが求める言語は `src/integrations/polar/polar.constants.ts` の `POLAR_CHECKOUT_LANGUAGES` にあり、ローカライズがオフの間は `polar:verify` が失敗します。

## 税の扱い [#tax-behaviour]

料金カードには、価格が米ドルであること、EU では付加価値税が含まれること、米国、カナダ、インドではチェックアウト時に売上税が加算されることが書かれています。Polar がそのとおりに税を課すのは、組織のデフォルトの税の扱いが所在地に基づく設定になっている場合なので、組織の設定でそのように設定してください。API はこれを組織の `default_tax_behavior` として返し、これが `location` でない間は `polar:verify` が失敗します（`src/lib/polar.ts` の `POLAR_TAX_BEHAVIOR.LOCATION`）。

## 埋め込み [#embedding]

購入ボタンは Polar のチェックアウトを iframe でサイトの上に開きます（[ライセンス](/docs/features/licences#the-checkout-over-the-page)）。Polar がチェックアウトのフレーム表示を許可するのは、組織に登録されたホストだけです。**Settings > Embedding** で、各環境で `appHostsForMode` が配信するホストを、スキームを付けずに、ポートがある場合はポートを付けて登録してください。

| 環境          | 組織           | ホスト                             |
| ------------- | -------------- | ---------------------------------- |
| `development` | サンドボックス | `localhost:3000`、`127.0.0.1:3000` |
| `preview`     | サンドボックス | `preview.saasyland.com`            |
| `production`  | 本番           | `saasyland.com`                    |

`*.saasyland.com` というエントリーは `preview.saasyland.com` を含みますが、`saasyland.com` は含みません。組織の検証済みドメインは、Polar が自動的にリストに加えます。API はこのリストを組織の `embed_hosts` として返し、環境のホストが 1 つでも欠けている間は `polar:verify` が失敗します。登録されるまで、そのホストでは Polar のフレームは空白のままになり、<RepositoryFact name="checkoutOverlayGraceSeconds" unit="second" />後にボタンが代わりに購入者を Polar のチェックアウトページに移動させます。そのため、少し遅れはしますが、購入者は支払いを済ませられます。

## 地域価格 [#regional-prices]

地域価格のために Polar で設定するものはありません。`PPP_TIERS`（`src/modules/license/license.pricing.ts`）の国の購入者には、区分に応じて <RegionalDiscounts /> を割り引いた価格をライセンスの `startCheckout` がそのまま送ります。`regionalPrice` がプランの価格のドル未満を切り捨てた、プランのカードに表示されるのと同じ金額です。チェックアウトはこれを `prices` に、そのチェックアウトだけで有効なプランの商品の固定価格として持つため、商品自体の価格は `TIER_PRICES` のままです。[アップグレード](/docs/features/licences#upgrades)も同じ方法で価格を送ります。プランを受け付けない注文モジュールの汎用的な `startCheckout` (`src/modules/order/use-cases/start-checkout.ts`) は、地域価格を送りません。以前の設定で作成した割引はもう使われないため、削除してかまいません。

## Webhook

デプロイする環境ごとに、その環境が使う組織で Webhook エンドポイントを 1 つ作成します。

| 環境         | 組織           | URL                                                     |
| ------------ | -------------- | ------------------------------------------------------- |
| `preview`    | サンドボックス | `https://preview.saasyland.com/api/auth/polar/webhooks` |
| `production` | 本番           | `https://saasyland.com/api/auth/polar/webhooks`         |

ホストは `DEPLOYED_HOSTS` から、パスは `ROUTES` から取得されます。形式は Raw を選び、エンドポイントを有効のままにして、`POLAR_EVENTS`（`src/integrations/polar/polar.webhooks.ts`）のイベントだけを過不足なく購読させます。`POLAR_EVENTS` は、`POLAR_EVENT_HANDLERS` のすべてのハンドラーのイベントをまとめたものです（[決済](/docs/features/payments#webhooks)を参照）。現在は、ライセンスが `LICENSE_WEBHOOK_EVENTS`（`src/modules/license/license.constants.ts`）のイベントを、注文とサブスクリプションのコピーが `ORDER_WEBHOOK_EVENTS` と `SUBSCRIPTION_WEBHOOK_EVENTS` のイベントを処理します。

| イベント                | ライセンス機能                                         | 請求機能                               |
| ----------------------- | ------------------------------------------------------ | -------------------------------------- |
| `benefit_grant.created` | ライセンスキーを保存します                             |                                        |
| `benefit_grant.revoked` | ライセンスを取り消します                               |                                        |
| `order.created`         |                                                        | 注文を D1 にコピーします               |
| `order.paid`            | ライセンスを付与します                                 | 注文のコピーを更新します               |
| `order.refunded`        | 注文が全額返金された時点でライセンスを返金済みにします | 注文のコピーを更新します               |
| `order.updated`         |                                                        | 注文のコピーを更新します               |
| `subscription.created`  |                                                        | サブスクリプションを D1 にコピーします |
| `subscription.updated`  |                                                        | サブスクリプションのコピーを更新します |

ある機能が新しいイベントを処理し始めるときは、そのコードをデプロイする前に、各エンドポイントにそのイベントを追加してください。それまでデプロイされているコードは、どの機能も処理しないイベントに 200 を返して何もしないため、先にイベントを追加しても問題ありません。また、エンドポイントが `POLAR_EVENTS` のすべてのイベントを送らない限り、`polar:verify` はデプロイを失敗させます。

エンドポイントの署名シークレットを、同じ環境ファイルの `POLAR_WEBHOOK_SECRET` にコピーします。Polar は `localhost` に到達できないため、開発用のエンドポイントは不要です。

本番の組織にプレビューのエンドポイントを、サンドボックスに本番のエンドポイントを追加しないでください。実際の支払いがプレビューに届いたり、テスト購入で本番のライセンスが付与されたりしてしまいます。

## 設定を確認する

```sh
bun run polar:verify:development
bun run polar:verify:preview
bun run polar:verify:production
```

各スクリプトは `.env.<environment>` から Polar のキーを読み込み、`POLAR_SERVER` が示す API に GET リクエストだけを送ります。組織を読み取り、その商品と Webhook エンドポイントを一覧で取得するだけで、何も変更しません。確認する内容は次のとおりです。

- 環境ファイルにすべての Polar のキーが設定されており、開発とプレビューでは `POLAR_SERVER=sandbox`、本番では `POLAR_SERVER=production` になっていること。
- 組織でチェックアウトのローカライズがオンになっており、デフォルトの税の扱いが所在地に基づく設定になっていて、環境のすべてのホストにチェックアウトの埋め込みを許可していること。
- 各 `POLAR_PRODUCT_ID_*` が、アーカイブ済みでもサブスクリプションでもない組織の商品を指し、その価格が固定価格で、`DEFAULT_CURRENCY_CODE` 建てで、`TIER_PRICES` と等しいこと。
- 各商品にライセンスキーの特典がちょうど 1 つあり、その特典が `LICENSE_ACTIVATION_LIMITS` にあるプランの上限を持ち、有効期限も使用回数の上限もないこと。
- 各商品が、`WITHDRAWAL_CONSENT_FIELD` のラベルを持つチェックボックスのフィールド <RepositoryFact name="licenseWithdrawalConsentField" /> を必須にしていること。
- プレビューと本番の Webhook URL に、有効な Raw 形式のエンドポイントがあり、`POLAR_WEBHOOK_SECRET` で署名され、`POLAR_EVENTS` だけを過不足なく購読していること。
- もう一方の Polar サービスを使う環境のホストに送信するエンドポイントがないこと。

`polar:verify` は、スクリプトの名前が `polar:verify:<environment>` の形なので Polar 機能のデプロイ前チェックになります。そのため、`deploy:preview` と `deploy:production` は `scripts/verify-bindings.ts` と `scripts/prepare-deploy-secrets.ts` の後、ビルドの前に `scripts/run-deploy-checks.ts` を通じてこれを実行します。CI のデプロイでは、`polar:verify` を含め、デプロイ前チェックをいずれも実行しません。`deploy-reusable.yml` には `scripts/run-deploy-checks.ts` を実行するステップがなく、GitHub の環境には Polar のトークンもありません。Worker は Cloudflare にすでに設定されている Polar のシークレットをそのまま使います。Polar で何かを変更したら、そのたびに自分で `polar:verify` を実行してください。

## 失敗した場合

スクリプトは、見つかったすべての問題を 1 行に 1 つずつ列挙したエラーで終了します。

```text
Polar production does not match the code for production:
The core product (POLAR_PRODUCT_ID_CORE) has 0 licence-key benefits; it needs exactly one.
A webhook endpoint posts to https://preview.saasyland.com/api/auth/polar/webhooks, the preview host, from this Polar production organisation; remove it.
```

失敗すると、ビルド、マイグレーション、アップロードのいずれも行われる前にデプロイが止まります。スクリプトが Polar を変更することはないため、Polar を修正してから再度実行してください。各メッセージには、修正すべきキー、定数、設定が示されます。

- **`Set … in .env.<environment>`**: Polar のキーがないか空になっているか、`POLAR_SERVER` が誤ったサービスを指しています。
- **`rejects POLAR_ACCESS_TOKEN`**: トークンが無効か、取り消されているか、`.env.preview` に入れた本番のトークンのように、もう一方のサービスのものです。
- **`lacks the … scope`**: 上記のスコープを持つトークンを作成してください。`products:read` の場合は、デプロイ済みのサイトにもこのスコープが必要であることがメッセージに加わります。このスコープがないと、`/admin/products` とダッシュボードの商品数は Polar から商品を受け取れません。
- **`names no product of the organisation`**: 商品 ID または `POLAR_ORGANIZATION_ID` が間違っているか、もう一方のサービスのものです。
- **価格またはライセンスキー**: コードに合わせて Polar 側を変更してください。ビジネス上の値を意図的に変える場合は、先に `TIER_PRICES` か `LICENSE_ACTIVATION_LIMITS` を変更し、その後で Polar を変更します。
- **`does not ask for the … checkout field`、`without requiring it`、`instead of a checkbox`、`label differs`**: [同意のチェックボックス](#consent-checkbox)を作成するか、商品に付けるか、修正してください。文言を意図的に変える場合は、先に `WITHDRAWAL_CONSENT_FIELD.label` を変更し、その後で Polar のラベルを変更します。
- **`Checkout localization is off`**: 組織で[チェックアウトのローカライズ](#checkout-language)をオンにしてください。
- **`default tax behaviour is not location`**: 組織の[税の扱い](#tax-behaviour)を所在地に基づく設定にしてください。
- **`does not let … embed its checkout`**: メッセージが示すホストを [Settings > Embedding](#embedding) に追加してください。
- **Webhook エンドポイント**: メッセージが示すエンドポイントを修正するか、別の環境のホストに送信しているエンドポイントを削除してください。
