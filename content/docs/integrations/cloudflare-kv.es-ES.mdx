Todos los entornos vinculan un espacio de nombres de KV como `CACHE`. Contiene una entrada.

## Recuento de estrellas de GitHub

El recuento de estrellas que se muestra en el sitio, implementado en `src/lib/github.ts`:

- `getStarCount` lee la entrada `github:<owner>/<repo>:stars`.
- Si no hay entrada, obtiene el repositorio de la API de GitHub con un tiempo de espera de <RepositoryFact name="starCountFetchTimeoutSeconds" unit="second" />, devuelve el recuento y escribe `count` y `fetchedAt` en KV con `waitUntil`.
- Cuando la entrada tiene más de <RepositoryFact name="starCountRefreshHours" unit="hour" /> (`STAR_COUNT_REFRESH_AFTER_MS`), devuelve el recuento en caché y lo actualiza en segundo plano.
- `starCountQuery` conserva el resultado en la caché de consultas el mismo tiempo: `STAR_COUNT_REFRESH_AFTER_MS` es también su `gcTime` y, en todas las builds salvo la de pruebas, su `staleTime`. El Worker de pruebas responde a la API de GitHub con un recuento fijo, así que allí `starCountStaleTime` nunca deja que se quede obsoleto, y una página que `build:test` prerenderizó no pide el número de estrellas, por mucho tiempo que haya pasado desde la build.

Las entradas no tienen caducidad en KV; `fetchedAt` determina cuándo se actualizan. La solicitud a GitHub se autentica con las credenciales de la aplicación OAuth de GitHub `AUTH_GITHUB_CLIENT_ID` y `AUTH_GITHUB_CLIENT_SECRET`.

## Consistencia y pruebas

KV tiene consistencia eventual. Las sesiones, los límites de frecuencia y todo lo que se usa para la autorización se almacenan en D1.

En Vitest, `cloudflare:workers` se resuelve como `src/platform/testing/mocks/cloudflare.ts`, que proporciona un `CACHE` en memoria. El entorno de Wrangler `test` usa un espacio de nombres local en `.wrangler/test`.
