## ロケールと URL

SaaSy Land は、en-US（デフォルト）、de-DE、es-ES、fr-FR、it-IT、ja-JP、pl-PL、pt-BR、uk-UA の 9 つのロケールを提供します。デフォルトロケールにはプレフィックスがなく（`/docs`）、それ以外のロケールは完全なタグを使います（`/pl-PL/docs`）。Worker は、`/pl/docs` や `/en-US/docs` のような言語コードのみのプレフィックスやデフォルトロケールのプレフィックスを、正規の URL にリダイレクトします。

`getCurrentLocale()` はアイソモーフィックです。サーバーでは URL を読み取り、`/api` とサーバー関数のリクエストではロケールクッキーを読み取ります。ブラウザでは URL を読み取ります。Worker はクッキーをページの URL と同期させます。ローカライズされたコンテンツを返すサーバー関数は、クッキーに頼らず、ロケールを入力として受け取ります。

## メッセージ

翻訳は `messages/<locale>/<namespace>.json` に置かれます。ファイル名がそのまま名前空間になります。例：`pages.admin.users`、`components.custom.footer`、`emails.verify-email`、`auth.validations`、`common`。ドット区切りの名前空間は 1 つのメッセージツリーにマージされるため、`useTranslations("pages.admin.users")` は `pages.admin.users.json` を読み取ります。すべてのページ名前空間には、head タグ用の `metadata.title` と `metadata.description` があります。メッセージは、生成された型を持たないプレーンな JSON です。

## 読み込み

- **root 名前空間**（`common`、`components.*`、`errors*`）は、root の `beforeLoad` でプリロードされます。
- **ページルート**は `const NAMESPACE = "pages.x"` を宣言し、ローダーでプリロードして、`staticData.namespaces` に列挙します。
- **レイアウトルート**は `const NAMESPACES = [...] as const` を宣言し、同じ処理を行います。
- **`TranslationsProvider`** は、root シェル内でドキュメントの body をラップします。root 名前空間と、マッチしたルートの `staticData.namespaces` を組み合わせて `IntlProvider` に渡すため、エラー画面を含むすべての画面が翻訳されます。
- **メール**は、それを送信するユースケースの中で、`loadNamespace` を使ってサーバー上で名前空間を読み込みます。

## リンク

ルーターのリンクでは、ロケールを扱う必要はありません。`<Link to={ROUTES.SIGN_IN}>` には、ルーターの `rewrite` によってプレフィックスが付きます。`localizePathname` を使うのは、ルーターを経由しない生の URL だけです。たとえば、Better Auth の `callbackURL` の値、メール内のリンク、手動で組み立てた `<a href>` 要素がこれにあたります。

```ts
const callbackURL = localizePathname({ locale: getCurrentLocale(), pathname: `${ROUTES.VERIFY_EMAIL}?verified=true` })
```

ロケールスイッチャーは、各ロケールの同じパスへのプレーンなリンクを描画します。そのため、言語を切り替えると新しいドキュメントが読み込まれます。

## コンポーネントでの翻訳

コンポーネントは `useTranslations` をちょうど 1 回だけ呼び出し、翻訳関数を `t` と名付けます。i18n-ally は、後から `useTranslations` が呼ばれると、それ以降のすべての `t()` 呼び出しのスコープを付け替えます。また、`bun run check:i18n` は、スコープ内で解決できないキーがあると失敗します。関連のない 2 つの名前空間が必要なコンポーネントは、それらに共通する親の名前空間を使うか、完全なキーを指定して `useTranslations()` を使います。

`bun run check:i18n` は 3 つのスクリプトを実行します。`check-i18n.ts`（ロケール間のキーの一致とスコープ付きキーの解決）、`check-message-formats.ts`（ICU メッセージの構文）、`check-content.ts`（ロケール間でのドキュメントとブログの一致）です。
