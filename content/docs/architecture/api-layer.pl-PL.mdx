description: "Endpointy HTTP pod /api oraz sytuacje, w których dodaje się endpoint zamiast funkcji serwerowej."
---

Własne operacje aplikacji są funkcjami serwerowymi. Handlery HTTP istnieją tylko tam, gdzie adres URL wywołuje coś spoza klienta RPC aplikacji: przeglądarkowy klient Better Auth, dostawcy OAuth, webhooki Polar i pole wyszukiwania w dokumentacji.

| Plik                       | Ścieżka       | Metody    | Obsługuje                                                                                                                            |
| -------------------------- | ------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `src/routes/api/index.ts`  | `/api`        | GET       | Odpowiedź JSON ze statusem `{ runtime: "cloudflare-workers" }`                                                                       |
| `src/routes/api/auth.$.ts` | `/api/auth/*` | GET, POST | Wszystkie endpointy Better Auth, w tym callbacki OAuth, weryfikację adresu e-mail, portal klienta Polar i `/api/auth/polar/webhooks` |
| `src/routes/api/search.ts` | `/api/search` | GET       | Wyszukiwanie Fumadocs w dokumentacji                                                                                                 |

Handler deklaruje się przez `server.handlers` w `createFileRoute`. Otrzymuje webowy obiekt `Request` i zwraca `Response`:

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Zasady

- Nie dodawaj endpointu REST dla operacji, którą wywołuje wyłącznie ta aplikacja. Zamiast tego napisz przypadek użycia z `createServerFn`; otrzymuje on typowane dane wejściowe, middleware i opcje zapytania.
- Handler sam waliduje dane wejściowe i sprawdza uprawnienia. Middleware funkcji serwerowych (`authorized`, `withRateLimit`) nie jest uruchamiane dla handlerów.
- Weryfikacja specyficzna dla dostawcy pozostaje w integracji. Podpisy webhooków Polar weryfikuje plugin Polar w Better Auth, a nie własny handler.
- Ścieżki `/api` nigdy nie są lokalizowane ani prerenderowane i omijają obsługę locale w Workerze.
