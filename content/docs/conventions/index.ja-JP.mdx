これらのページは、このリポジトリのコーディング標準です。コードをどう書けるかではなく、ここで実際にどう書いているかを説明し、各ルールにはそれに従っているファイルを示します。ほとんどのルールはコマンドで強制されます。`bun run check`（フォーマット、リント、型、翻訳、ドキュメントの構成）、`bun run test:coverage`（<RepositoryFact name="coverageThreshold" unit="percent" /> のゲート）、または E2E スイートです。残りはレビューで守られており、どのルールがそうなのかは各ページに記載しています。

書き方に迷ったら、同じ種類のもので最も近い既存の例を探して読み、その形をそのまま真似てください。一貫性は、局所的により良いアイデアよりも価値があります。同じことを行う方法が 2 つあると、後から読む人は人間でもエージェントでも、その両方を覚えなければならなくなります。

## リファレンス実装

コース機能はリポジトリで最も新しいコードであり、真似るべき形です。テーブルのモジュール、公開ルートと管理画面のルート、フォーム、ダイアログ、データテーブル、スケルトン、テストを含みます。

| テーブルのモジュール                     | `src/modules/course/` と、その隣の `chapter`、`lesson`、`video`        |

| テーブル用のページ分割された一覧         | `src/modules/course/use-cases/get-courses.ts`                          |

## 例外のないルール

ほかにどれほど優れた点があっても、これらのいずれかに違反する変更は却下されます。

1. コード、テスト、スクリプト、設定、CSS にコメントを書きません。[コードスタイル](/docs/conventions/code-style)を参照してください。
2. ルールを回避するために `oxlint-disable`、`eslint-disable`、`@ts-expect-error`、`@ts-ignore`、`@ts-nocheck`、`as` によるキャスト、`any` を使いません。原因を修正してください。
3. 複数行の三項演算子と `?? undefined` を使いません。テストと `src/platform/testing` 以外で `null` を書くのは、API がそれを決めている箇所だけです。`null` になりうる値との比較と、React の DOM ref（`useRef<HTMLElement>(null)`）がそれにあたります。[コードスタイル](/docs/conventions/code-style)を参照してください。
4. ステータス、種別、ティア、ロールなどのドメインの値は名前付きの定数にし、テストでも文字列リテラルを繰り返しません。保存される値をそのまま書くのは、スキーマのテストだけです。[テスト](/docs/conventions/testing)を参照してください。
5. `src/modules` 内のフォルダーは、データベーステーブルのためだけに存在します。[モジュール](/docs/conventions/modules)を参照してください。
6. ユーザーに表示されるすべての文字列はどのロケールにも存在し、すべてのドキュメントページも同様です。サイトに表示する数値は計測したものか `src/data` で一度だけ宣言したものであり、手入力はしません。[翻訳とコンテンツ](/docs/conventions/translations)を参照してください。
7. カバレッジは、行、ステートメント、関数、分岐のすべてで <RepositoryFact name="coverageThreshold" unit="percent" /> を維持します。[テスト](/docs/conventions/testing)を参照してください。
8. 変更によって不正確になった README、ドキュメント、サイトの文言は、同じプルリクエストで更新します。
9. コミットとプルリクエストには、AI の帰属表示も `Co-Authored-By` トレーラーも付けません。[Git とプルリクエスト](/docs/conventions/git-workflow)を参照してください。

## 完了の定義

プッシュしようとしているブランチで、次のコマンドがこの順序ですべて成功したら、その変更は完了です。

```sh
bun run check
bun run test:coverage
bun run build:test
bun run test:e2e:pr
```

`check` とテストは Cloudflare のビルドを検証しません。以前、本番ビルドが壊れていたのに、依存関係のアップグレードがその両方を通過したことがあります。`build:test` はすべての変更で、ブラウザーのスイートはドキュメント以外のすべての変更で実行してください。コミットする前に自分の差分を読み、コメント、定数にすべき文字列リテラル、変更によって誤りになった文言やドキュメントがないかを確認してください。

## このセクションの内容

- [コードスタイル](/docs/conventions/code-style)：フォーマッター、リンター、コンパイラーが強制すること、そしてそれらでは検出できない禁止事項。
- [ファイルと命名](/docs/conventions/files-and-naming)：各種ファイルの置き場所と命名方法。
- [モジュール](/docs/conventions/modules)：テーブルのモジュールの構造。
- [サーバー関数とエラー](/docs/conventions/server-functions)：ミドルウェア、権限、バリデーション、エラーコード。
- [データの取得とキャッシュ](/docs/conventions/data-fetching)：クエリオプション、キー、データの鮮度、無効化。
- [ルートファイル](/docs/conventions/routes)：すべてのルートファイルに共通する 1 つの形。
- [コンポーネントとスタイリング](/docs/conventions/components)：コンポジション、データへのアクセス、クラス名、プロバイダー。
- [フォームとテーブル](/docs/conventions/forms-and-tables)：shadcn のフィールドを使う TanStack Form と、唯一の `DataTable`。
- [翻訳とコンテンツ](/docs/conventions/translations)：名前空間、ロケール、ドキュメント、生成される数値。
- [アクセシビリティ](/docs/conventions/accessibility)：WCAG 2.2 AA と、それを守る axe のスキャン。
- [パフォーマンス](/docs/conventions/performance)：ページを高速に保つ、計測に基づくルール。
- [テスト](/docs/conventions/testing)：テストプロジェクト、命名、カバレッジのゲート。
- [依存関係](/docs/conventions/dependencies)：常に最新バージョンを使い、アップストリームのバグにはパッチを当てること。
- [Git とプルリクエスト](/docs/conventions/git-workflow)：コミット、ブランチ、プルリクエスト、そしてそれらで更新すべきもの。

リポジトリのルートにある `AGENTS.md` は、これらのルールをコーディングエージェント向けに要約し、このセクションへのリンクを載せています。
