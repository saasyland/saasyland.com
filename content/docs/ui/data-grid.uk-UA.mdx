`DataGrid` (`src/presentation/components/custom/data-grid.tsx`) — це компонент таблиці. Він будує екземпляр TanStack Table v9 з можливостей у `src/integrations/tanstack-table/table.features.ts` і рендерить його примітивами таблиці shadcn та елементами керування React Aria. Сторінка передає йому свої стовпці й або свої рядки, або запит; усе інше, від панелі інструментів до панелі пагінації, міститься всередині нього.

```tsx
<DataGrid
  columns={columns}
  empty={t("empty")}
  id={ORDER_GRID_ID}
  label={t("title")}
  query={(request) => getOrdersPageQuery(orderZodSchemas.getOrders.parse(request))}
  search={t("filters.search")}
  selectable
/>
```

## Пропси

| Проп          | Призначення                                                                                                    |
| ------------- | -------------------------------------------------------------------------------------------------------------- |
| `columns`     | Набір стовпців з `<entity>-columns.tsx` сторінки. Кожен рядок потребує рядкового `id`, який слугує ID рядка    |
| `id`          | Дає сітці назву: ключ її збереженого макета в браузері й початок назви її CSV-файлу                            |
| `label`       | Доступна назва таблиці, зазвичай заголовок сторінки                                                            |
| `data`        | Рядки в пам’яті, для сітки, яка шукає, фільтрує, сортує й ділить на сторінки на клієнті                        |
| `query`       | Серверний режим: функція від запиту сітки, яка повертає параметри запиту, що розв’язуються в `{ rows, total }` |
| `search`      | Мітка й плейсхолдер поля пошуку; без неї сітка не має пошуку                                                   |
| `empty`       | Що каже сітка, поки в ній немає рядків і не задано ні пошуку, ні фільтра                                       |
| `selectable`  | Додає стовпець прапорців і панель вибору                                                                       |
| `bulkActions` | Функція від вибраних рядків, яка рендерить додаткові кнопки на панелі вибору                                   |

## Стовпці

Набір стовпців — це хук у `custom/<area>/<entity>-columns.tsx`, наприклад `useOrderColumns`. Він читає свої переклади й дані, які пропонують його фільтри, і повертає мемоізовані стовпці, тож кожна мітка — це простий рядок, який сітка може використати у своїх меню, оголошеннях і заголовку CSV. Кожна клітинка — невеликий компонент у тому самому файлі, який сам читає свої переклади.

```tsx
columnHelper.accessor("status", {
  cell: StatusCell,
  header: t("pages.admin.orders.table.headers.status"),
  meta: {
    export: ({ status }) => t(`pages.admin.orders.status.${status}`),
    filter: {
      kind: DATA_GRID_FILTER.MULTI_SELECT,
      options: ORDER_STATUSES.map((value) => ({ label: t(`pages.admin.orders.status.${value}`), value })),
    },
  },
  size: ORDER_COLUMN_SIZES.status,
})
```

`meta` — це те, що сітка читає зі стовпця:

| Ключ     | Дія                                                                                                                        |
| -------- | -------------------------------------------------------------------------------------------------------------------------- |
| `filter` | Фільтр стовпця: його `kind`, а для вибору — `options` у вигляді `{ label, value }`                                         |
| `hidden` | Прихований, доки адміністратор не покаже його з меню Стовпці                                                               |
| `pinned` | Закріплений на `start` або на `end`, доки адміністратор його не відкріпить                                                 |
| `export` | Текст, який CSV отримує для рядка. Без нього CSV бере рядки й числа як є, дати як моменти ISO, а все інше залишає порожнім |

`size` — початкова ширина стовпця в пікселях. Стовпець можна сортувати, якщо він не задає `enableSorting: false`; у серверному режимі сортуватися мають лише ті стовпці, за якими вміє сортувати схема Zod модуля.

## Фільтри [#filters]

Види фільтрів: <RepositoryFact name="dataGridFilterKinds" />. Кожен має власний редактор, який відкривається кнопкою Фільтр на панелі інструментів або з чипа фільтра:

| Вид           | Редактор                                                                                                              | Значення                    |
| ------------- | --------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| `text`        | Текстове поле, що застосовується, щойно введення призупиняється на <RepositoryFact name="dataGridTypingDelayMs" /> мс | Текст без пробілів на краях |
| `select`      | Список варіантів; повторний вибір вибраного варіанта знімає його                                                      | Одне `value`                |
| `multiSelect` | Список варіантів, кілька одночасно; довгий список отримує поле пошуку                                                 | Масив `value`               |
| `numberRange` | Два числові поля, щонайменше й щонайбільше, будь-яке з них можна залишити порожнім                                    | `{ min?, max? }`            |
| `dateRange`   | Останні 7 днів, останні 30 днів, останні 12 місяців або будь-які дні в календарі                                      | `{ from?, to? }` у мс       |

Дні перетворюються на моменти в часовому поясі адміністратора, від початку першого дня до останньої мілісекунди останнього, тож сервер порівнює прості моменти. Кожен активний фільтр показується як чип із коротким підсумком, наприклад щонайменше 40, Оплачено або Повернено чи вибрано: 3; його × прибирає його, а Прибрати фільтри прибирає всі. Зміна пошуку, фільтра або сортування повертає до першої сторінки й очищує вибір.

## Серверний режим

З `query` сітка ділить на сторінки, сортує, шукає й фільтрує на сервері. Вона викликає `query` з:

```ts
interface DataGridRequest {
  readonly filters: Readonly<Record<string, unknown>>
  readonly pageIndex: number
  readonly pageSize: number
  readonly search: string
  readonly sorting: SortingState
}
```

`filters` містить id кожного відфільтрованого стовпця з його значенням. Маршрут перевіряє запит схемою Zod модуля, перш ніж той дійде до серверної функції, як це робить `/admin/orders` через `orderZodSchemas.getOrders.parse(request)`. Поки не надійде перша сторінка, сітка показує рядки-скелетони; поки завантажується наступна сторінка, вона залишає попередні рядки приглушеними, позначає таблицю як зайняту й вимикає перемикання сторінок. Помилки запиту доходять до error boundary маршруту.

## Макет

Адміністратор переставляє сітку, а браузер зберігає це під `id` сітки в `localStorage` (`src/hooks/use-data-grid-preferences.ts`): які стовпці показано, їхній порядок, які закріплено, їхні ширини, щільність рядків і розмір сторінки. Пошук, фільтри, сортування й вибір не зберігаються. Скинути макет повертає типові значення. Якщо браузер відмовляє в сховищі, макет живе лише до кінця візиту.

- **Меню Стовпці.** Показує й ховає кожен стовпець, який можна сховати.
- **Меню стовпця.** Кнопка ⋮ кожного заголовка сортує за зростанням або за спаданням, скасовує сортування, закріплює стовпець ліворуч або праворуч, відкріплює його, посуває його на одне місце ліворуч або праворуч у межах його боку й ховає його.
- **Перетягування.** Заголовок, перетягнутий на інший заголовок того самого боку, займає його місце.
- **Зміна ширини.** Край заголовка можна перетягнути, щоб змінити ширину; це також роздільник, який клавіші зі стрілками розширюють або звужують, а подвійне клацання повертає початкову ширину.
- **Сортування.** Натискання на заголовок сортує за ним; із Shift воно додає стовпець до сортування, до <RepositoryFact name="dataGridMaxSortedColumns" /> стовпців, пронумерованих у заголовку.
- **Щільність.** Просторі або щільні рядки.
- **Розмір сторінки.** <RepositoryFact name="dataGridPageSizes" /> рядків на сторінку.

Рядок заголовків лишається на виду, поки рядки прокручуються всередині сітки, а закріплені стовпці лишаються на виду, поки сітка прокручується вбік; так телефон показує широку таблицю.

## Вибір і експорт

З `selectable` прапорець вибирає рядок, а прапорець у заголовку вибирає сторінку. Тоді внизу вікна з’являється плаваюча панель із кількістю, Експортувати вибрані, `bulkActions` сторінки й Скасувати вибір.

Експортувати CSV завантажує кожен рядок, який знаходять пошук і фільтри, а не лише сторінку на екрані: на сервері експорт запитує сторінки по <RepositoryFact name="dataGridExportPageSize" /> рядків, доки не отримає всі. Файл містить видимі стовпці в їхньому порядку, починається з мітки порядку байтів, щоб електронні таблиці читали його як UTF-8, і ставить `'` перед кожною клітинкою, яка починала б формулу. Записує його `src/lib/csv.ts`.

## Доступність

- Таблиця має `label` як назву та `aria-rowcount`; кожен рядок — свій `aria-rowindex`, порахований наскрізно через сторінки.
- Заголовки, за якими можна сортувати, — це кнопки з `aria-sort`.
- Кожен елемент керування працює з клавіатури: меню й списки підтримують клавіші зі стрілками та пошук під час введення з React Aria, Escape їх закриває, а зміна ширини використовує стрілки на роздільнику заголовка.
- Переміщення, закріплення, приховування, сортування з меню та скидання макета оголошуються у ввічливій live-області; кількість результатів і кількість вибраних рядків теж оголошуються наживо.

## Переклади

Власні тексти сітки лежать у `messages/<locale>/components.custom.data-grid.json`. Сторінка передає їй лише мітки стовпців, варіанти фільтрів, мітку пошуку й повідомлення про порожній стан.

## DataTable

Старіший `DataTable` (`src/presentation/components/custom/data-table.tsx`) досі рендерить таблиці, які ще не перейшли на сітку: користувачів, клієнтів, курси, продукти й категорії, відео та таблиці панелі адміністратора. Він приймає `columns`, `data`, `empty`, `filters` (елементи пошуку й вибору, прив’язані до ідентифікаторів стовпців) і `options` (`query`, `selectable`, `initialState`) і не має нічого з макета, фільтрів за типом чи експорту сітки. Кожна з цих таблиць переходить на `DataGrid` в окремій зміні, а `DataTable` зникне, коли не залишиться жодної.
