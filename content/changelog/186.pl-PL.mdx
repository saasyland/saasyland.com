- Naprawiono: API licencji CLI zgłaszało własne awarie jako niewłaściwy błąd. Gdy D1 nie mogło zliczyć żądania, limit żądań je odrzucał, a CLI informowało o zbyt wielu żądaniach; gdy D1 nie mogło odczytać licencji albo Polar odrzucił żądanie w sposób, którego kontrakt nie nazywa, Worker odpowiadał HTTP 500, którego CLI nie potrafi odczytać, więc prosiło użytkownika o aktualizację. Każdy endpoint, także endpoint paczek, odpowiada teraz na każdą awarię witryny kodem `serviceUnavailable` z nagłówkiem `retry-after`. Przechwytuje ją tylko `serve` w `license.api.ts` i zapisuje w logu `[license] <method> <path> failed` z błędem, jego przyczyną i stosem wywołań, z `[licence key]` w miejscu klucza wywołującego, który w przeciwnym razie trafiłby do Workers Logs w błędach zapytań Drizzle i błędach walidacji Polara. API zlicza żądania przez `countRequest`, które zgłasza błąd, gdy zawiedzie jego magazyn; logowanie, funkcje serwerowe i limity e-maili nadal korzystają z `consumeRateLimit`, które wciąż odrzuca żądanie, którego nie może zliczyć. Zobacz [API licencji CLI](/docs/features/cli-licence-api).
