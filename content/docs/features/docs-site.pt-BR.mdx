## Conteúdo

- As páginas são arquivos `content/docs/<section>/<page>.<locale>.mdx` para todos os idiomas.
- `meta.<locale>.json` em cada pasta define o título da seção, o ícone e a ordem das páginas.
- `src/integrations/fumadocs/fumadocs.i18n.ts` usa o parser `dot`, `en-US` como idioma padrão e de fallback, e `hideLocale: "always"`, porque o aplicativo cuida do prefixo de idioma por conta própria.
- `bun run content` gera `.source` a partir de `fumadocs.config.ts`.

## Rotas

- Layout `/docs` (`src/routes/_site.docs.tsx`): uma função de servidor retorna a árvore de páginas do idioma atual; o layout mostra o `DocsLayout` do Fumadocs dentro do layout `_site`, abaixo do cabeçalho do site e acima de `BackToTop`, de que a documentação precisa porque o sumário do Fumadocs só leva aos títulos. Ele define o `--fd-banner-height` do Fumadocs com a altura do cabeçalho, para que a barra lateral e o sumário fiquem fixos abaixo do cabeçalho, dá à barra lateral o título **Documentação** com um link para `/docs`, mostra o link do GitHub e, no rodapé da barra lateral, `LocaleSelect` e `ThemeSwitch` como campos de seleção no mesmo estilo, carrega `docs.css` e mostra `DocsPending` durante o carregamento.
- Em telas pequenas, a barra do próprio Fumadocs, com a busca e o botão da barra lateral, fica abaixo do cabeçalho do site. `DocsToolbar` (`custom/docs-toolbar.tsx`) a coloca em um landmark de navegação chamado **Documentação**, para que o cabeçalho do site continue sendo o único banner da página. O Fumadocs só define a altura da barra, `--fd-header-height`, quando ela é filha direta do layout, então o layout da documentação a define por conta própria em telas pequenas. O link **Pular para o conteúdo** do cabeçalho do site leva ao artigo da documentação, e `docs.css` esconde o link de pular para o conteúdo do próprio Fumadocs, que já não é o primeiro elemento da página.
- `/docs/` e `/docs/$` chamam `loadDocsPage` (`fumadocs.docs.ts`), que resolve a página e pré-carrega seu MDX compilado (`docsContent`) antes de renderizar.
- `/api/search` oferece a busca do Fumadocs em todos os idiomas (`fumadocs.search.ts`).

As páginas MDX podem usar `mdxComponents` de `src/presentation/components/custom/mdx.tsx`: os componentes padrão do Fumadocs, `Accordions`, `Steps` e `Tabs` do Fumadocs, `Alert`, `Badge`, `Button`, as partes de card, `Separator` e as partes de tabela do shadcn, e `RepositoryFact`, `RepositoryTable`, `TierPrice`, `ActivationLimit` e `RegionalDiscounts`, que mostram valores do código em vez de digitá-los ([Traduções e conteúdo](/docs/conventions/translations)). Os links são localizados automaticamente.

## Acessibilidade

As páginas da documentação atendem à WCAG 2.2 AA nos dois temas. Os blocos de código usam os temas GitHub Light e GitHub Dark do Shiki com duas cores de token substituídas (`colorReplacements` em `fumadocs.config.ts`), para que todo token atinja 4,5:1; a área de rolagem de um bloco de código é focável e não é um landmark; e a caixa de seleção de uma lista de tarefas recebe o nome do seu item. `e2e/specs/accessibility.spec.ts` varre a página inicial da documentação, todas as páginas de Convenções e uma página de cada uma das outras seções; veja [Acessibilidade](/docs/conventions/accessibility).

## Adicionar uma página

1. Escreva `<page>.en-US.mdx` com `title` e `description`.
2. Adicione o slug a `meta.en-US.json` e a cada outro `meta.<locale>.json` na mesma ordem.
3. Adicione a tradução para cada um dos outros idiomas, com blocos de código idênticos byte a byte.
4. Rode `bun scripts/check-content.ts` (também faz parte de `bun run check:i18n`) e `bun run content`.

`bun run build` pré-renderiza todas as páginas da documentação em todos os idiomas.
