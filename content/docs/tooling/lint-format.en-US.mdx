Vite+ runs oxfmt for formatting and oxlint for linting, both configured in the `fmt` and `lint` sections of `vite.config.ts`. `bun run check` is the gate that CI runs:

```sh
bun run check
```

It runs `generate:cn`, `check:comments`, `check:i18n`, `check:flows` and `vp check`, which checks formatting, runs the lint rules and type-checks the project. Use `bun run lint`, `bun run format` and `bun run format:check` for one tool at a time.

## Formatting

- No semicolons, double quotes, trailing commas, <RepositoryFact name="tabWidth" />-space indentation, a print width of <RepositoryFact name="printWidth" /> and LF line endings.
- Imports are sorted into fixed groups: server-only, `cloudflare:workers`, React, external packages, then the `~/src` areas (platform, providers, integrations, modules, routes, hooks, data and theme, types, lib, branding, shadcn components, custom components, styles), then relative imports.
- Tailwind classes are sorted in `className` and inside `cn`, `cva`, `clsx` and `tw` calls.

## Linting

- The `correctness`, `nursery`, `pedantic`, `perf`, `style` and `suspicious` categories are errors.
- Type-aware rules and type checking are enabled (`typeAware` and `typeCheck`).
- Notable limits: <RepositoryFact name="maxLines" /> lines per file, <RepositoryFact name="maxLinesPerFunction" /> lines per function, <RepositoryFact name="maxStatements" /> statements per function, no magic numbers other than `0` and `1`, no explicit `any` (`typescript/no-explicit-any`), and identifiers of at least two characters except `_`, `m` and `t`.
- Overrides relax a few rules for tests, presentation code and hooks, test mocks and route files.
- `jsPlugins` loads the repository's own oxlint plugins: `scripts/code-style-lint-plugin.ts`, whose rules `code-style/no-comments`, `code-style/no-multiline-ternary`, `code-style/no-undefined-branch`, `code-style/no-undefined-fallback` and `code-style/zod-namespace-import` fail every comment, every ternary that spans lines, every ternary with an `undefined` or `null` branch, every `return undefined`, every `?? undefined` and every Zod import other than `import * as zod from "zod"` (see [Code style](/docs/conventions/code-style)), `scripts/hydration-lint-plugin.ts`, whose rule `hydration/no-clock-or-locale-in-render` keeps render code from reading the clock or the runtime's locale (see [Code style](/docs/conventions/code-style)), `scripts/admin-data-lint-plugin.ts`, whose rule `admin-data/no-literal-data` keeps demo data out of admin code (see [Admin dashboard](/docs/features/admin-dashboard#real-data-only)), and `scripts/radius-lint-plugin.ts`, whose rule `radius/no-off-scale` keeps every corner on the radius scale (see [Theme](/docs/ui/theme#corner-radius)). `scripts/type-lint-plugin.ts` adds `type/no-off-scale` and `type/mono-for-code`, which keep every text size on the type scale and the monospaced face on code (see [Theme](/docs/ui/theme#type-scale)).
- The escape hatches are banned by name: `typescript/ban-ts-comment` rejects `@ts-expect-error`, `@ts-ignore` and `@ts-nocheck` even with a description, `typescript/consistent-type-assertions` with `assertionStyle: "never"` rejects every type assertion except `as const`, and `respectEslintDisableDirectives: false` makes an `eslint-disable` comment switch nothing off. `code-style/no-comments` replaces `capitalized-comments`, `no-inline-comments` and `no-warning-comments`, which the categories turn on and which each saw only some comments, so those three are off.

Both tools ignore generated and external files: declaration files, `src/routeTree.gen.ts`, migrations, `.source`, `dist`, `coverage`, `e2e`, `remotion`, the agent folders and Playwright output. `scripts/` is formatted and linted like `src/`. `bun run check:comments` reads what the linter skips as well: `e2e`, `remotion`, the declaration files and the stylesheets.

The formatter also sorts `package.json`, including its `scripts` alphabetically (`sortPackageJson: { sortScripts: true }`), so `vp check` fails when a script is out of order.

Fix the cause of a lint error. Do not add disable comments, `@ts-expect-error` or `as` casts to satisfy a rule. A disable comment is a comment, and the linter obeys it before any rule sees it, so `bun run check:comments`, which runs outside the linter, fails it wherever it is.

## Fixing

The pre-commit hook runs `bun run check:pre-commit`; its `vp staged` step runs `vp check --fix` on the staged files only. `bun run check:fix` applies fixes across the whole repository and can rewrite files you did not touch, so review its diff before committing. To fix only your own changes, pass their paths to `vp` (the global Vite+ CLI, or `bunx vp`):

```sh
vp fmt src/routes/admin.users.all.tsx
vp lint --fix src/routes/admin.users.all.tsx
```
