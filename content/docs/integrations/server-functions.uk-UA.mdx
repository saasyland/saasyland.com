Бізнес-операції зберігаються в `src/modules/<table>/use-cases/<operation>.ts`, по одній операції на файл. Кожен файл експортує нативну `createServerFn` з її middleware, валідацією Zod і обробником, а також параметри запиту чи мутації, які використовують компоненти. Серверна функція, що не належить жодній таблиці, розміщується в `src/lib` (наприклад, `getStarCount` у `src/lib/github.ts`), а функцію, яку використовує лише один маршрут, можна визначити у файлі цього маршруту (`getBlogPosts` у `src/routes/blog.index.tsx`).

```ts
export const createCategory = createServerFn({ method: "POST" })
  .middleware([authorized({ category: ["create"] })])
  .validator((input: zod.input<typeof categoryZodSchemas.createCategory>) => categoryZodSchemas.createCategory.parse(input))
  .handler(({ data }) =>
    db
      .insert(category)
      .values({
        description: data.description ?? "",
        icon: data.icon ?? "FolderOpen",
        id: v7(),
        kind: data.kind,
        name: data.name,
        visibility: data.visibility ?? "public",
      })
      .returning()
      .get(),
  )

export const createCategoryMutation = mutationOptions({
  mutationFn: (data: Parameters<typeof createCategory>[0]["data"]) => createCategory({ data }),
  mutationKey: CATEGORY_MUTATION_KEYS.CREATE,
})
```

## Правила

- Middleware виконується перед валідацією та обробником. Використовуйте `authorized(permission?)` для захищених операцій і `withRateLimit(kind, RATE_LIMITS.SENSITIVE)` або `RATE_LIMITS.TOKEN` для чутливих публічних; див. [Better Auth](/docs/integrations/better-auth).
- Валідуйте вхідні дані схемою Zod модуля (`<table>.zod.ts`).
- Повертайте дані напряму й викидайте `AppError(ERROR_CODES.X)` з `src/modules/_core/constants/errors.ts` для очікуваних збоїв. Інші помилки доходять до клієнта як `INTERNAL_ERROR`, тож деталі постачальника залишаються на сервері.
- Ключі запитів і мутацій — це readonly-кортежі в `<table>.constants.ts` модуля, а ключі запитів містять кожен вхідний параметр, що впливає на результат.
- Зберігайте атомарність операцій за допомогою одного SQL-запиту або `db.batch`; D1 не підтримує інтерактивних транзакцій.

## Використання сценарію

Компоненти розгортають експортовані параметри в `useQuery`, `useSuspenseQuery` або `useMutation`, перекладають помилки за допомогою `useErrorMessage()` з `src/hooks/use-error-message.ts` і після успішної мутації інвалідують ключі запитів модуля:

```tsx
const deleteUser = useMutation({
  ...deleteUserMutation,
  onError: (error) => {
    toast.error(errorMessage(error))
  },
  onSuccess: async () => {
    await queryClient.invalidateQueries({ queryKey: USER_QUERY_KEYS.ALL })
    toast.success(t("feedback.deleteSuccess"))
  },
})
```

Завантажувачі попередньо завантажують ті самі параметри запитів у своєму `Promise.all`, тож серверний рендеринг і клієнт використовують один запис кешу.
