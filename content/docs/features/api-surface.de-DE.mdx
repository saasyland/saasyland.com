Die App stellt drei HTTP-Routen bereit, deklariert mit `server.handlers` auf `createFileRoute` in `src/routes/api`:

| Route         | Methoden  | Handler                                                                                                                                                             |
| ------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/api`        | GET       | Gibt `{ "runtime": "cloudflare-workers" }` zurück.                                                                                                                  |
| `/api/auth/$` | GET, POST | Better Auth: Anmeldung, OAuth-Callbacks, `/api/auth/verify-email` sowie die Endpunkte des Polar-Plugins `/api/auth/polar/webhooks` und `/api/auth/customer/portal`. |
| `/api/search` | GET       | Fumadocs-Suche (`fumadocs.search.ts`).                                                                                                                              |

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Serverfunktionen statt REST

Anwendungsoperationen sind `createServerFn`-Funktionen in `src/modules/<table>/use-cases`. Die übrigen liegen in `src/lib` (`getStarCount` in `github.ts`), in einer Integration (`getCurrentSession` in `auth.session.ts`, `getDocsPage` in `fumadocs.docs.ts`) oder inline in der einzigen Route, die sie verwendet (`getBlogPosts` in `blog.index.tsx`). TanStack Start ruft sie per RPC unter `/_serverFn` auf, mit Middleware für Sitzungen, Berechtigungen und Rate-Limits. Fügen Sie keinen REST-Endpunkt für eine Operation hinzu, die nur diese App aufruft; legen Sie HTTP-Routen nur für externe Aufrufer wie Webhooks an und prüfen Sie deren Signaturen in der Anbieter-Integration.

## Verhalten

- Der Worker überspringt Locale-Weiterleitungen für `/api` und `/_serverFn`. Ihre URLs enthalten keine Locale, daher gibt `getCurrentLocale()` für sie auf dem Server `en-US` zurück; Code, der eine Locale braucht, erhält sie als Eingabe oder liest sie aus einer `callbackURL`.
- Der Build rendert `/api` nicht vorab.
- Die Handler-Tests liegen in `src/routes/api/__test__/handlers.test.ts`.
