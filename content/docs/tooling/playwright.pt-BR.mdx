O Playwright testa a aplicação compilada em navegadores reais. A suíte é executada contra o ambiente `test` do Wrangler: D1, KV e R2 locais em `.wrangler/test`, credenciais fictícias de `.env.test` e a entrada de testes `src/platform/testing/worker.ts`, que intercepta as requisições ao Resend e à Polar.

```sh
bun run test:e2e:install
bun run test:e2e
bun run test:e2e:smoke
bun run test:e2e:pr
bun run test:e2e:headed
bun run test:e2e:ui
```

| Script             | Executa                                                      |
| ------------------ | ------------------------------------------------------------ |
| `test:e2e:install` | Instala o Chromium e o WebKit com as dependências do sistema |
| `test:e2e`         | Todas as specs no Chromium e no WebKit                       |
| `test:e2e:smoke`   | `e2e/specs/smoke.spec.ts` no Chromium                        |
| `test:e2e:pr`      | Todas as specs no Chromium, como na CI de pull requests      |
| `test:e2e:headed`  | Todas as specs em navegadores visíveis                       |
| `test:e2e:ui`      | Modo UI do Playwright                                        |

## Configuração

`playwright.config.ts` define os projetos `chromium` (Desktop Chrome) e `webkit` (Desktop Safari) e usa `PLAYWRIGHT_BASE_URL` ou `http://127.0.0.1:3000`. Localmente, o comando do servidor web executa `db:reset:test`, `build:test` e `start:test`, e reutiliza um servidor que já responda nessa URL, então encerre antes outros servidores em `127.0.0.1:3000`. Na CI, o workflow prepara o build e o Playwright apenas inicia o servidor.

| Configuração     | Local                                            | CI                                            |
| ---------------- | ------------------------------------------------ | --------------------------------------------- |
| Novas tentativas | <RepositoryFact name="playwrightLocalRetries" /> | <RepositoryFact name="playwrightCiRetries" /> |
| Workers          | <RepositoryFact name="playwrightLocalWorkers" /> | <RepositoryFact name="playwrightCiWorkers" /> |
| Traces           | Mantidos em falhas                               | Na primeira nova tentativa                    |
| Vídeos           | Desativados                                      | Mantidos em falhas                            |
| Relatórios       | List e HTML                                      | GitHub e HTML                                 |

## Estrutura

- `e2e/specs/`: specs para smoke checks, landing page, navegação, locales, autenticação, workspaces, newsletter, conteúdo, tema, preços regionais, o funil de checkout, afiliados, vídeos, cursos, administração de cursos e acessibilidade.
- `e2e/pages/`: page objects.
- `e2e/fixtures/`: a fixture `test` estendida, helpers para os e-mails capturados, `deliverPaidOrder` em `polar.ts`, que envia um webhook `order.paid` assinado para conceder uma licença, e `accessibilityViolations` com os `COLOR_SCHEMES` claro e escuro em `accessibility.ts`.
- `e2e/data/accounts.ts`: as contas de administrador e de cliente criadas pelo seed e sua senha.
- `e2e/data/videos.ts` e `e2e/data/courses.ts`: o vídeo de teste criado pelo seed, cujos arquivos ficam em `e2e/fixtures/video/`, e o curso criado pelo seed: um capítulo com uma prévia gratuita, uma aula para contas e duas aulas pagas, uma delas sem vídeo.

O Worker de testes expõe `/__test/emails` para ler os e-mails capturados pelo mock do Resend e `/__test/newsletter` para ler o estado de um inscrito.

## Acessibilidade

`e2e/specs/accessibility.spec.ts` executa o [axe-core](https://github.com/dequelabs/axe-core) por meio do `@axe-core/playwright` nas páginas públicas, nas páginas de cursos, na página inicial da documentação, em todas as páginas de Convenções e em uma página de cada uma das outras seções da documentação, em um post do blog e nos workspaces de administrador e de cliente, nos temas claro e escuro. As páginas de administração incluem `/admin/courses`, `/admin/courses/create` e o editor do curso semeado, que `e2e/specs/workspaces.spec.ts` também visita. Aplica as regras A e AA das WCAG 2.0, 2.1 e 2.2 e as boas práticas do axe, falha quando uma página não carrega com um status de sucesso, rola a página para que as seções que aparecem com a rolagem também sejam verificadas, espera as animações finitas terminarem e falha em qualquer violação, informando a regra, o impacto e os seletores afetados.
