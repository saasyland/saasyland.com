## レイアウト

`src/routes/app.tsx` は認証のエリアに属します。`requireSignedIn` でワークスペースを保護し、ライセンスのページとカードのものも含め、自分の名前空間をプリロードします。

```tsx
const NAMESPACES = ["auth.errors", "pages.app.sidebar", "pages.license", "timezones"] as const

export const Route = createFileRoute("/app")({
  beforeLoad: requireSignedIn,
  component: AppLayout,
  loader: ({ context }) => preloadNamespaces({ locale: getCurrentLocale(), namespaces: NAMESPACES, queryClient: context.queryClient }),
  pendingComponent: AppPending,
  staticData: { namespaces: NAMESPACES },
})
```

`AppLayout` は shadcn の `SidebarProvider` の中に、`src/presentation/components/custom/app` の `AppSidebar` と `AppHeader` を表示します。サイドバーは `src/data/navigation.ts` の `APP_NAVIGATION`（概要、ライセンス、講座、設定。ラベルは `navigation.auth.json`、`navigation.license.json`、`navigation.courses.json` から）でリンクを作り、`APP_RESOURCE_NAVIGATION`（ドキュメント。ラベルは `navigation.content.json` から）でリソース欄を作ってサポートの連絡先を続け、ルートコンテキスト（`getRouteApi("/app")`）からユーザーを読み取り、最後に `SignOutButton` を置きます。ヘッダーは現在のページとサイトへ戻るリンクを表示します。サインイン後、管理者は `/admin` に、それ以外のユーザーは `/app` に移動します。サイドバー上部のワードマークはホームページにリンクします。

`AppSidebar` は、**講座** 項目の横の `SidebarMenuBadge` にコースのエリアのバッジを描きます。バッジは `CourseProgressBadge`（`custom/courses/course-progress-badge.tsx`）で、公開済みのすべてのレッスンのうち顧客が完了したレッスンの数を `completedLessonsQuery`（`src/modules/lesson-progress/use-cases/get-completed-lessons.ts`）から示します。コースのないプロジェクトには、この項目もバッジもありません。

## ページ

| ルート          | 内容                                                                                                                                                                                                                                                                                                                    |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/app`          | 有効なライセンスがなければ `LicenseOffer`、あれば `LicenseStatusCard`（プラン、ステータス、ライセンスページへのリンク）と、最初のプロジェクトまでのステップである `GetStarted`。[CLI ガイド](/docs/cli)（`ROUTES.DOCS_CLI`）とメールサポートへのリンク。                                                                |
| `/app/license`  | 有効なライセンスがなければ `LicenseOffer`、あれば `LicenseCard`（コピーできるキーと CLI コマンド、カスタマーポータルへのリンク、上位の各プランへのアップグレードのリンク）と、Polar がキーを発行した後は `LicenseActivations`。返金済みまたは取り消されたライセンスには、キーを表示せずにその旨を示すカードが残ります。 |
| `/app/settings` | **一般**: `PreferencesCard`（ワークスペース内のすべての日付に使うタイムゾーン）、`EmailCard`、`DeleteAccountCard`。**セキュリティ**: パスワード、二要素認証、連携アカウント、セッション。[設定](/docs/features/settings)を参照してください。                                                                            |

`LicenseOffer`（`src/presentation/components/custom/app/license-offer.tsx`）は、ランディングページの `PricingTiers` を再利用してプランごとに `CheckoutButton` を置きます。`CheckoutButton` は押されるとすぐに Polar のチェックアウトをページの上に開き、カードの下には `CheckoutNotice` を表示します（[ライセンス](/docs/features/licences#consent-to-immediate-supply)を参照）。`LicenseOffer` は最後に、コースのエリアの `CourseUnlocks`（`app/course-unlocks.tsx`）を表示します。ライセンスのエリアは `CourseUnlocks` を、そのスケルトンである `CourseUnlocksPending` とともに直接インポートし、そのカタログはライセンスのページが読み込みます。`CourseUnlocks` は有料レッスンのある公開済みコースを、それぞれのロックされたレッスン数とともに示します。この数は `getCatalogue` が D1 から数えます。有料レッスンのあるコースが 1 つもない間、このブロックは表示されません。`tier` を選んでいる場合、カードは `ChosenTier` の下にある **パッケージを比較** の折りたたみ表示にまとめられます。返金されたライセンスはカードがそのまま残り、その横に購入案内が表示されます。

`src/routes/app.index.tsx` は認証のエリアに属し、ライセンスのエリアの `LicenseOverview`（`custom/app/license-overview.tsx`）を描画します。内容は、有効化のパネル、選択されたプラン、`LicenseStatusCard`、またはプランの案内です。このルートのローダーは同じファイルの `loadLicenseOverview` を実行し、`AppOverviewPending` は `LicenseOverviewPending` を描画します。検索スキーマは `licenseSearchSchema`（`src/modules/license/license.zod.ts`）の 2 つのパラメーターを受け取り、`/app/license` も同じスキーマで検証します。ライセンスのないプロジェクトの概要ページには、これらがありません。どちらのパラメーターも省略可能で、無効な値は無視されます。

| パラメーター | 値                  | 効果                                                                                                                                                                                                                                                                                                  |
| ------------ | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tier`       | `LICENSE_TIER` の値 | 有効なライセンスがなければ、購入案内の上に `ChosenTier` を表示します。プラン、その価格、**決済に進む** ボタンが含まれます。より下位のプランの有効なライセンスがあれば、`UpgradeOffer` で[アップグレード](/docs/features/licences#upgrades)の価格を表示します。                                        |
| `checkoutId` | Polar の UUID       | ライセンスが有効になるまで購入案内の代わりに `CheckoutActivation` を表示し、有効になるとお礼を表示します。`tier`（チェックアウトで購入したプラン）があるときはライセンスがそのプランになるまで待ち、ページは `UpgradeOffer` を表示しません。[ライセンス](/docs/features/licences)を参照してください。 |

概要ページのローダーは各セクションの読み込みを実行するので、ライセンスのエリアがそこで `currentLicenseQuery` とコースのカタログをプリロードします。`/app/license` はその両方に加えて、ライセンスにキーがあればそのキーとプランの `licenseActivationsQuery` もプリロードします。そのため、ポーリングで届いたキーやアップグレードでは、マシン数の上限をあらためて読み込みます。`/app/settings` はセッション一覧、サインイン方法、アカウント削除の案内をプリロードし、レイアウトの `NAMESPACES` には、設定のカードのための `auth.security`、セッションの国のための `countries`、タイムゾーン名のための `timezones` が含まれます。`/app/settings/delete-account` は、メールで届いたリンクからアカウントの削除を確定します（[設定](/docs/features/settings#delete-account)）。購入、Webhook、ライセンスの状態は[ライセンス](/docs/features/licences)で説明しています。

## CLI の手順 [#cli-instructions]

`LicenseCard` は、`CLI_KEY_LINES` のコマンド <RepositoryFact name="cliLicenseCommands" /> をそれぞれの働きとコピーボタンとともに一覧表示し、CI がキーを <RepositoryFact name="cliLicenseKeyVariable" /> から読み取ることを示します。コマンドの情報源は `src/data/cli.ts` で、ランディングページの <RepositoryFact name="scaffoldTarget" /> もここで組み立てます。変数は、CLI 自身が読む名前である `@saasyland/stack/cli` の `CLI_VARIABLE` から来ます。`CLI_RELEASE_CHANNEL` は CLI を実行する npm のタグを表します。CLI と `@saasyland/stack` は同じバージョンでまとめてリリースされるため、このタグがインストール済みの `@saasyland/stack` の公開時のタグ（プレリリース `x.y.z-beta.n` なら `beta`、安定版なら npm のデフォルトのタグ）でなければ `cli.test.ts` が失敗します。そのため、`@saasyland/stack` を安定版に更新すると、`CLI_RELEASE_CHANNEL` がデフォルトのタグを指すまでテストが失敗し、ライセンスページ、ランディングページ、ドキュメント、[ジャーニースイート](/docs/tooling/playwright#journey-suite)はその値に従います。`@saasyland/stack/package.json` をインポートするとファイル全体が Worker とすべてのページのバンドルに入るため、定数にしています。

## スケルトン

`AppOverviewPending` と `AppSettingsPending`（`app/auth-pending.tsx`。`app.index.tsx` と `app.settings.tsx` の `pendingComponent` です）は、`app/pending-blocks.tsx` のページヘッダーを描画します。続けて概要ページは各エリアが追加したセクションのスケルトンと、ドキュメントとサポートの案内を、設定ページはタブと一般タブのカードを描画し、`AppDeleteAccountPending` は削除のカードを描画します。ライセンスのセクションのスケルトンである `LicenseOverviewPending` と、`AppLicensePending`（`app/license-pending.tsx`。`app.license.tsx` の `pendingComponent` です）は、ページが表示することになる状態をそのまま再現します。`licenseSearchSchema` で検索パラメーターを読み取り、クエリクライアントからキャッシュ済みのライセンスとカタログを読み取って、有効化のパネル、選択されたプランかアップグレード、有料レッスンのあるコースごとに 1 行を添えたプランのグリッド（プランが選ばれている場合は **パッケージを比較** の行）、ライセンスのカードのいずれかを描画します。ライセンスが有効になると最初のステップも描き、ライセンスのカードのスケルトンはライセンスのステータスに合わせます。

`/app` には請求履歴とコースの画面はありません。また、`/app/settings` にはプロフィールのフォームはありません。名前は登録時に設定します。
