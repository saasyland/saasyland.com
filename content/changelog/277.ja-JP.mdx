- 変更: プルリクエストは GitHub のマージキューを通って `main` に入るようになりました。マージキューは各プルリクエストを `main` と先に並んだプルリクエストの上でもう一度テストし、全員が成功したグループをまとめてマージするため、準備のできたプルリクエストがリベースを待つことはなくなりました。`bun scripts/enqueue-pr.ts <number>` はプルリクエストをキューに入れ、squash コミットに残る絵文字をタイトルに付けます。[Git とプルリクエスト](/docs/conventions/git-workflow#merging) を参照してください。
- 変更: プルリクエストは共有プレビューにデプロイしなくなりました。新しいチェック `Worker upload` は、トラフィックを受けないバージョンとしてプレビュー用 Worker を Cloudflare にアップロードします。これで `preview.saasyland.com` が配信しているものを置き換えずに、アップロード、サイズ、バインディングを確認できるため、準備のできたプルリクエスト同士がブロックし合うことはなくなりました。`main` は本番の前にプレビューへデプロイされ、`preview.yml` はテスト済みのブランチを手動でそこへデプロイします。[CI/CD](/docs/tooling/ci-cd#merge-queue) を参照してください。
- 変更: マージキューですでにテストされた `main` へのプッシュは、チェックを再実行せずにデプロイされます。また、changelog のチェックはマージキューのブランチを `main` と同じように扱います。
- 変更: 完了の定義では、ローカルで `check`、`test:coverage`、`build:test` と、変更が関わるブラウザースペックを実行します。CI はプルリクエストで、さらにマージキューでもう一度、ブラウザースイート全体を実行します。[規約](/docs/conventions#definition-of-done) を参照してください。
