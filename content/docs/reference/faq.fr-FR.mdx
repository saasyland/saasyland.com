## Quel runtime l'application utilise-t-elle ?

Cloudflare Workers. Bun installe les paquets et exécute les scripts ; Vite+ (`vp`) compile, formate, analyse (lint) et teste l'application.

## Les tests locaux nécessitent-ils un compte Cloudflare ?

Non. Vitest utilise une base SQLite en mémoire et un KV en mémoire. Playwright utilise l'environnement Wrangler `test` avec D1 et KV locaux dans `.wrangler/test` et des secrets factices issus de `.env.test`. En revanche, `bun run dev` nécessite un accès à Cloudflare, car l'environnement `development` utilise les bindings de preview distants.

## Où placer une nouvelle opération ?

Si elle travaille sur une table de la base de données, c'est un cas d'usage dans le module de cette table : `src/modules/<table>/use-cases/<verb>-<noun>.ts`. Si une seule route l'utilise et qu'elle ne touche aucune table, définissez-la avec `createServerFn` dans ce fichier de route. Sinon, placez-la dans `src/lib`.

## Quand créer un nouveau module ?

Uniquement lorsque vous ajoutez une nouvelle table à la base de données. Un module sans table n'est pas autorisé.

## Où placer un nouveau composant ?

Un composant partagé entre plusieurs zones est un fichier à plat dans `src/presentation/components/custom`. Un composant propre à une zone va dans le dossier de cette zone, par exemple `custom/admin/users/`. Un widget, une boîte de dialogue ou un formulaire par fichier.

## Comment les langues sont-elles organisées ?

en-US utilise des URL sans préfixe ; les huit autres locales utilisent leur code complet comme préfixe, par exemple `/de-DE` ou `/pl-PL`. Chaque locale possède les mêmes fichiers de namespace dans `messages/<locale>`, et chaque page de documentation existe sous la forme `<page>.<locale>.mdx`.

## Comment transmettre du texte à un composant ?

Vous n'en transmettez pas. Le composant appelle `useTranslations` pour son propre namespace et lit lui-même le texte.
