Polar sprzedaje trzy pakiety po cenach przekazywanych przy tworzeniu płatności, wydaje ich klucze licencyjne i nalicza podatek. Kod oczekuje w Polarze ściśle określonej konfiguracji, a Polar nie ostrzega, gdy jedno rozjedzie się z drugim: produkt bez benefitu kluczy licencyjnych nadal przyjmuje płatność, ale nie wydaje klucza. `bun run polar:verify:<environment>` porównuje konfigurację w Polarze z kodem, a skrypty wdrożeniowe uruchamiają go przed każdym ręcznym wdrożeniem.

## Produkcja i sandbox

Polar działa jako dwie oddzielne usługi. Produkcja (`polar.sh`, API `api.polar.sh`) obciąża prawdziwe karty, a sandbox (`sandbox.polar.sh`, API `sandbox-api.polar.sh`) przyjmuje tylko karty testowe. Nie mają nic wspólnego: konto, organizacja, token, produkt, rabat czy webhook istnieje tylko w jednej z nich, więc zarejestruj się osobno na `sandbox.polar.sh` i skonfiguruj każdą usługę oddzielnie.

| Plik środowiskowy  | `POLAR_SERVER` | Organizacja w Polarze |
| ------------------ | -------------- | --------------------- |
| `.env.development` | `sandbox`      | Sandbox               |
| `.env.preview`     | `sandbox`      | Sandbox               |
| `.env.production`  | `production`   | Produkcyjna           |

Tryb deweloperski i preview mogą współdzielić jedną organizację sandbox, ale jej webhook dociera tylko do preview: wysyła zdarzenia do hosta preview, który zapisuje je w bazie D1 preview, a `bun run dev` używa własnej, lokalnej bazy. Testowy zakup wykonany w trybie deweloperskim nie przyznaje więc lokalnie licencji; pełną ścieżkę zakupu testuj na preview.

Nigdy nie wpisuj do `.env.development` ani `.env.preview` tokenu, ID organizacji ani ID produktu z produkcji. API sandbox odrzuca token produkcyjny, a przy `POLAR_SERVER=production` testowa płatność obciążyłaby prawdziwą kartę i przyznała licencję w lokalnej bazie danych lub w bazie preview. `polar:verify` odrzuca `POLAR_SERVER=production` dla trybu deweloperskiego i preview oraz `POLAR_SERVER=sandbox` dla produkcji.

## Organizacja i token

Najpierw w usłudze sandbox, potem w produkcyjnej:

1. Utwórz organizację i skopiuj jej ID z ustawień organizacji do `POLAR_ORGANIZATION_ID`. Nadaj obu organizacjom slug z `POLAR_ORGANIZATION_SLUG` (`src/data/polar.ts`) albo zmień tę stałą na ich slug: [alert i lista zamówień niepasujących do żadnego konta w panelu administracyjnym](/docs/features/licences#orders-that-match-no-account) podają przy każdym zamówieniu link do panelu Polara z tym slugiem.
2. W ustawieniach organizacji utwórz token dostępu organizacji z poniższymi zakresami uprawnień, i tylko z nimi, a następnie skopiuj go do `POLAR_ACCESS_TOKEN`.

| Zakres                    | Wymagany przez                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `checkouts:write`         | `startCheckout`, który tworzy sesję płatności przez SDK Polara (`polar.checkouts.create`)                                                                                                                                                                                                                                                                                                                                    |
| `customer_sessions:write` | Link do portalu klienta, `/api/auth/customer/portal`                                                                                                                                                                                                                                                                                                                                                                         |
| `license_keys:write`      | Odczyt klucza i jego aktywacji, aktywacja urządzenia oraz usuwanie aktywacji (`deactivateLicense` i [API licencji CLI](/docs/features/cli-licence-api)), a przy przejściu na wyższy pakiet podniesienie limitu aktywacji klucza i wyłączenie klucza, który Polar wydaje dla zamówienia za przejście                                                                                                                          |
| `orders:read`             | Handlery webhooków, które odczytują zamówienie powiązane z licencją oraz bieżącego klienta zamówienia, którego zdarzenie nie pasuje do żadnego konta, obliczanie ceny przejścia na wyższy pakiet, które sumuje to, co klient zapłacił za licencje, strona zamówienia w panelu administracyjnym, która odczytuje zamówienie i jego fakturę, oraz `orders:backfill`, który kopiuje rabat i kraj rozliczenia każdego zamówienia |
| `organizations:read`      | `polar:verify`, który odczytuje, czy lokalizacja płatności jest włączona, domyślny sposób naliczania podatku oraz hosty, które mogą osadzać płatność                                                                                                                                                                                                                                                                         |
| `products:read`           | `polar:verify`                                                                                                                                                                                                                                                                                                                                                                                                               |
| `webhooks:read`           | `polar:verify`                                                                                                                                                                                                                                                                                                                                                                                                               |

Zakres zapisu obejmuje odczyt, więc `license_keys:write` pozwala też odczytywać klucze. Token organizacji działa już w imieniu własnej organizacji. `polar:verify` mimo to wysyła `POLAR_ORGANIZATION_ID` jako parametr zapytania `organization_id`, tak jak robi to pobieranie listy zamówień przy przejściu na wyższy pakiet, więc ID innej organizacji objawia się brakującymi produktami.

## Produkty

Utwórz po jednym produkcie dla każdego pakietu: zakup jednorazowy, a nie subskrypcję, ze stałą ceną w `DEFAULT_CURRENCY_CODE` (w dolarach amerykańskich) równą `TIER_PRICES` w `src/data/marketing.ts`. Skopiuj ID każdego produktu do odpowiadającego mu klucza.

| Pakiet   | Klucz                       | Cena                          | Aktywacje na klucz                  |
| -------- | --------------------------- | ----------------------------- | ----------------------------------- |
| Podstawa | `POLAR_PRODUCT_ID_CORE`     | <TierPrice tier="core" />     | <ActivationLimit tier="core" />     |
| Komplet  | `POLAR_PRODUCT_ID_COMPLETE` | <TierPrice tier="complete" /> | <ActivationLimit tier="complete" /> |
| Agencja  | `POLAR_PRODUCT_ID_AGENCY`   | <TierPrice tier="agency" />   | <ActivationLimit tier="agency" />   |

Polar przechowuje cenę w najmniejszych jednostkach waluty, w przypadku dolarów amerykańskich w centach, a `polar:verify` przed porównaniem przelicza `TIER_PRICES` w ten sam sposób. Zarchiwizowane ceny pomija.

## Klucze licencyjne

Dla każdego pakietu utwórz jeden benefit typu **License Keys** (klucze licencyjne) i dołącz go wyłącznie do produktu tego pakietu:

- **Aktywacje**: ograniczone do liczby z tabeli powyżej, czyli `LICENSE_ACTIVATION_LIMITS` w `src/modules/license/license.constants.ts`. Umożliwienie klientom zarządzania aktywacjami w Polarze jest opcjonalne, ponieważ `/app/license` sam je wyświetla i usuwa.
- **Wygaśnięcie**: brak. Klucze nigdy nie wygasają, ponieważ zakup jest płatnością jednorazową.
- **Limit użycia**: brak.
- **Prefiks**: dowolny; `polar:verify` go nie sprawdza.

Każdy produkt potrzebuje dokładnie jednego benefitu kluczy licencyjnych; inne benefity obok niego nie przeszkadzają. Gdy Polar przyzna benefit, webhook `benefit_grant.created` zapisuje klucz w licencji kupującego.

## Pole wyboru zgody [#consent-checkbox]

Kupujący wyraża zgodę na natychmiastowe dostarczenie na stronie płatności Polara, a to pole jest jedynym miejscem, w którym jest o nią proszony (zobacz [Licencje](/docs/features/licences#consent-to-immediate-supply)); Polar zapisuje ją w zamówieniu. Utwórz w organizacji jedno pole niestandardowe i dołącz je do trzech produktów:

- **Typ**: pole wyboru (Checkbox).
- **Slug**: <RepositoryFact name="licenseWithdrawalConsentField" />, czyli `LICENSE_CHECKOUT_FIELD.WITHDRAWAL_CONSENT` w `src/modules/license/license.constants.ts`. Zamówienie zapisuje zaznaczone pole pod tym kluczem w `custom_field_data`.
- **Etykieta**: dokładnie `WITHDRAWAL_CONSENT_FIELD.label` z `src/lib/polar.ts`, czyli angielskie zdanie zbudowane na podstawie `REFUND_TERMS.WITHDRAWAL_DAYS`, zakończone linkiem Markdown do produkcyjnych Zasad zwrotów.
- **Nazwa**: dowolna; `WITHDRAWAL_CONSENT_FIELD.name` to nazwa, którą proponuje kod, a `polar:verify` jej nie sprawdza.
- **Wymagane** w każdym z trzech produktów. Inne pola, o które proszą produkty, mogą pozostać.

`startCheckout` nie wysyła żadnej wartości tego pola, więc jest ono na początku puste i zaznacza je kupujący; Polar nie przyjmie płatności, dopóki obowiązkowe pole jest puste. Polar zachowuje tylko wartości pól, o które prosi produkt: zanim pole zostanie dołączone, płatność nadal działa, ale zamówienie nie zapisuje zgody, a [potwierdzenie zakupu](/docs/features/licences#purchase-confirmation) informuje zamiast tego o ustawowym prawie odstąpienia od umowy.

Utworzenie pola i dołączenie go do produktu wymagają zakresów `custom_fields:write` i `products:write`, których nie ma opisany powyżej token. Utwórz i dołącz pole w panelu Polara albo przez API, używając osobnego tokenu z tymi zakresami. `polar:verify` odczytuje dołączone pola z listy produktów, więc nie potrzebuje żadnego innego zakresu.

## Język płatności [#checkout-language]

Polar pokazuje swoją płatność w języku, o który prosi `startCheckout`, tylko wtedy, gdy lokalizacja płatności jest włączona dla organizacji; w przeciwnym razie każda płatność otwiera się po angielsku. Włącz ją w ustawieniach organizacji. W [przewodniku po lokalizacji płatności](https://polar.sh/docs/features/checkout/localization) Polar nazywa ją flagą funkcji, a API zwraca ją jako `feature_settings.checkout_localization_enabled` w organizacji. `POLAR_CHECKOUT_LANGUAGES` w `src/data/polar.ts` wymienia języki, o które prosi kod, a `polar:verify` kończy się błędem, dopóki lokalizacja jest wyłączona.

## Sposób naliczania podatku [#tax-behaviour]

Karty cennika podają, że ceny są w dolarach amerykańskich, że w UE VAT jest wliczony, a w USA, Kanadzie i Indiach podatek od sprzedaży dolicza się przy płatności. Polar nalicza podatek w ten sposób, gdy domyślny sposób naliczania podatku w organizacji zależy od lokalizacji, więc ustaw go tak w ustawieniach organizacji. API zwraca go jako `default_tax_behavior` w organizacji, a `polar:verify` kończy się błędem, dopóki nie ma on wartości `location` (`POLAR_TAX_BEHAVIOR.LOCATION` w `src/lib/polar.ts`).

## Osadzanie [#embedding]

Przyciski zakupu otwierają płatność Polara nad stroną w ramce iframe ([Licencje](/docs/features/licences#the-checkout-over-the-page)), a Polar pozwala osadzać swoją płatność w ramce tylko hostom, które wymienia jego organizacja. W **Settings > Embedding** wpisz hosty, które `appHostsForMode` obsługuje w każdym środowisku, bez schematu i z portem, jeśli jest:

| Środowisko    | Organizacja | Hosty                              |
| ------------- | ----------- | ---------------------------------- |
| `development` | Sandbox     | `localhost:3000`, `127.0.0.1:3000` |
| `preview`     | Sandbox     | `preview.saasyland.com`            |
| `production`  | Produkcyjna | `saasyland.com`                    |

Wpis `*.saasyland.com` obejmuje `preview.saasyland.com`, ale nie `saasyland.com`. Polar sam dodaje do listy zweryfikowane domeny organizacji. API zwraca listę jako `embed_hosts` w organizacji, a `polar:verify` kończy się błędem, dopóki brakuje któregoś hosta środowiska. Dopóki host nie jest na liście, ramka Polara pozostaje na nim pusta, a gdy minie <RepositoryFact name="checkoutOverlayGraceSeconds" unit="second" />, przycisk kieruje kupującego na stronę płatności Polara, więc kupujący nadal mogą zapłacić, tylko nieco później.

## Ceny regionalne [#regional-prices]

Ceny regionalne nie wymagają niczego w Polarze. Dla kupującego z kraju ujętego w `PPP_TIERS` (`src/modules/license/license.pricing.ts`), gdzie przedziały obniżają cenę o <RegionalDiscounts />, `startCheckout` wysyła gotową cenę: `regionalPrice` zaokrągla cenę pakietu w dół do pełnych dolarów, czyli do kwoty, którą pokazują karty pakietów, a płatność przekazuje ją w `prices` jako stałą cenę produktu pakietu obowiązującą tylko w tej płatności, więc produkt zachowuje swoją cenę z `TIER_PRICES`. [Przejście na wyższy pakiet](/docs/features/licences#upgrades) wysyła swoją cenę w ten sam sposób. Rabaty utworzone przy wcześniejszej konfiguracji nie są już używane i można je usunąć.

## Webhook

Utwórz po jednym endpoincie webhooka dla każdego wdrożonego środowiska, w organizacji, której to środowisko używa.

| Środowisko   | Organizacja | URL                                                     |
| ------------ | ----------- | ------------------------------------------------------- |
| `preview`    | Sandbox     | `https://preview.saasyland.com/api/auth/polar/webhooks` |
| `production` | Produkcyjna | `https://saasyland.com/api/auth/polar/webhooks`         |

Host pochodzi z `DEPLOYED_HOSTS`, a ścieżka z `ROUTES`. Wybierz format Raw, pozostaw endpoint włączony i zasubskrybuj w nim dokładnie zdarzenia z `POLAR_EVENTS` (`src/integrations/polar/polar.webhooks.ts`), które łączy zdarzenia wszystkich handlerów z `POLAR_EVENT_HANDLERS` (zobacz [Płatności](/docs/features/payments#webhooks)). Obecnie kod licencji obsługuje zdarzenia z `LICENSE_WEBHOOK_EVENTS` (`src/modules/license/license.constants.ts`), a kopie zamówień i subskrypcji te z `ORDER_WEBHOOK_EVENTS` i `SUBSCRIPTION_WEBHOOK_EVENTS`:

| Zdarzenie               | Obszar licencji                                                       | Obszar rozliczeń              |
| ----------------------- | --------------------------------------------------------------------- | ----------------------------- |
| `benefit_grant.created` | Zapisuje klucz licencyjny                                             |                               |
| `benefit_grant.revoked` | Cofa licencję                                                         |                               |
| `order.created`         |                                                                       | Kopiuje zamówienie do D1      |
| `order.paid`            | Przyznaje licencję                                                    | Aktualizuje kopię zamówienia  |
| `order.refunded`        | Oznacza licencję jako zwróconą, gdy całe zamówienie zostanie zwrócone | Aktualizuje kopię zamówienia  |
| `order.updated`         |                                                                       | Aktualizuje kopię zamówienia  |
| `subscription.created`  |                                                                       | Kopiuje subskrypcję do D1     |
| `subscription.updated`  |                                                                       | Aktualizuje kopię subskrypcji |

Gdy obszar zaczyna obsługiwać nowe zdarzenie, dodaj je do każdego endpointu, zanim wdrożysz ten kod. Wdrożony do tego czasu kod odpowiada 200 na zdarzenie, którego nie obsługuje żaden obszar, i nic z nim nie robi, więc wcześniejsze dodanie zdarzenia niczego nie psuje, a `polar:verify` przerywa wdrożenie, dopóki któryś endpoint nie wysyła wszystkich zdarzeń z `POLAR_EVENTS`.

Skopiuj sekret podpisu endpointu do `POLAR_WEBHOOK_SECRET` w pliku środowiskowym tego samego środowiska. Tryb deweloperski nie potrzebuje endpointu, ponieważ Polar nie może dotrzeć do `localhost`.

Nigdy nie dodawaj endpointu preview do organizacji produkcyjnej ani endpointu produkcyjnego do organizacji sandbox: prawdziwe płatności trafiałyby do preview albo testowe zakupy przyznawałyby licencje na produkcji.

## Sprawdzenie konfiguracji

```sh
bun run polar:verify:development
bun run polar:verify:preview
bun run polar:verify:production
```

Każdy skrypt odczytuje klucze Polara z `.env.<environment>` i wysyła wyłącznie żądania GET do API wskazanego przez `POLAR_SERVER`: odczytuje organizację, pobiera listę jej produktów i endpointów webhooków i niczego nie zmienia. Sprawdza, czy:

- plik środowiskowy ustawia każdy klucz Polara, z `POLAR_SERVER=sandbox` dla trybu deweloperskiego i preview oraz `POLAR_SERVER=production` dla produkcji;
- lokalizacja płatności jest włączona dla organizacji, jej domyślny sposób naliczania podatku zależy od lokalizacji, a organizacja pozwala każdemu hostowi środowiska osadzać swoją płatność;
- każdy `POLAR_PRODUCT_ID_*` wskazuje produkt organizacji, który nie jest zarchiwizowany ani nie jest subskrypcją, a jego ceny są stałe, w `DEFAULT_CURRENCY_CODE` i równe `TIER_PRICES`;
- każdy produkt ma dokładnie jeden benefit kluczy licencyjnych z limitem pakietu z `LICENSE_ACTIVATION_LIMITS`, bez wygaśnięcia i bez limitu użycia;
- każdy produkt wymaga pola wyboru <RepositoryFact name="licenseWithdrawalConsentField" /> z etykietą z `WITHDRAWAL_CONSENT_FIELD`;
- preview i produkcja mają włączony endpoint w formacie Raw pod swoim adresem URL webhooka, podpisany za pomocą `POLAR_WEBHOOK_SECRET` i zasubskrybowany dokładnie na `POLAR_EVENTS`;
- żaden endpoint nie wysyła zdarzeń do hosta środowiska, które używa drugiej usługi Polara.

`polar:verify` jest sprawdzeniem przed wdrożeniem z obszaru polar, ponieważ jego skrypty nazywają się `polar:verify:<environment>`. Dlatego `deploy:preview` i `deploy:production` uruchamiają go przez `scripts/run-deploy-checks.ts`, po `scripts/verify-bindings.ts` i `scripts/prepare-deploy-secrets.ts`, a przed buildem. Wdrożenia z CI nie uruchamiają żadnego sprawdzenia przed wdrożeniem, w tym `polar:verify`: `deploy-reusable.yml` nie ma kroku z `scripts/run-deploy-checks.ts`, środowiska GitHuba nie przechowują tokenu Polara, a Worker zachowuje sekrety Polara ustawione już w Cloudflare. Po każdej zmianie w Polarze uruchom `polar:verify` samodzielnie.

## Gdy kontrola kończy się błędem

Skrypt kończy się błędem, który wymienia każdy znaleziony problem, po jednym w wierszu:

```text
Polar production does not match the code for production:
The core product (POLAR_PRODUCT_ID_CORE) has 0 licence-key benefits; it needs exactly one.
A webhook endpoint posts to https://preview.saasyland.com/api/auth/polar/webhooks, the preview host, from this Polar production organisation; remove it.
```

Błąd zatrzymuje wdrożenie, zanim cokolwiek zostanie zbudowane, zmigrowane lub przesłane. Skrypt nigdy niczego nie zmienia w Polarze: popraw konfigurację w Polarze, a potem uruchom go ponownie. Każdy komunikat wskazuje klucz, stałą lub ustawienie do poprawienia:

- **`Set … in .env.<environment>`**: brakuje klucza Polara, jest on pusty albo `POLAR_SERVER` wskazuje niewłaściwą usługę.
- **`rejects POLAR_ACCESS_TOKEN`**: token jest nieprawidłowy, unieważniony lub pochodzi z drugiej usługi, na przykład token produkcyjny w `.env.preview`.
- **`lacks the … scope`**: utwórz token z zakresami uprawnień wymienionymi powyżej.
- **`names no product of the organisation`**: ID produktu lub `POLAR_ORGANIZATION_ID` jest błędne albo należy do drugiej usługi.
- **Cena lub klucz licencyjny**: zmień ustawienie w Polarze tak, aby zgadzało się z kodem. Gdy wartość biznesowa zmienia się celowo, najpierw zmień `TIER_PRICES` lub `LICENSE_ACTIVATION_LIMITS`, a dopiero potem konfigurację w Polarze.
- **`does not ask for the … checkout field`, `without requiring it`, `instead of a checkbox` lub `label differs`**: utwórz, dołącz lub popraw [pole wyboru zgody](#consent-checkbox). Gdy brzmienie etykiety zmienia się celowo, najpierw zmień `WITHDRAWAL_CONSENT_FIELD.label`, a dopiero potem etykietę w Polarze.
- **`Checkout localization is off`**: włącz [lokalizację płatności](#checkout-language) dla organizacji.
- **`default tax behaviour is not location`**: ustaw [sposób naliczania podatku](#tax-behaviour) w organizacji na zależny od lokalizacji.
- **`does not let … embed its checkout`**: dodaj host wskazany w komunikacie w [Settings > Embedding](#embedding).
- **Endpoint webhooka**: popraw endpoint wskazany w komunikacie albo usuń endpoint, który wysyła zdarzenia do hosta innego środowiska.
