---
title: "Lint e formatação"
description: "oxlint e oxfmt pelo Vite+ e os scripts de verificação."
---

O Vite+ executa o oxfmt para formatação e o oxlint para lint, ambos configurados nas seções `fmt` e `lint` de `vite.config.ts`. `bun run check` é a verificação que a CI executa:

```sh
bun run check
```

Ele executa `generate:cn`, `check:i18n` e `vp check`, que verifica a formatação, aplica as regras de lint e faz a checagem de tipos do projeto. Use `bun run lint`, `bun run format` e `bun run format:check` para uma ferramenta de cada vez.

## Formatação

- Sem ponto e vírgula, aspas duplas, vírgulas finais, indentação de dois espaços, largura de linha de 140 e quebras de linha LF.
- Os imports são ordenados em grupos fixos: server-only, `cloudflare:workers`, React, pacotes externos e, em seguida, as áreas de `~/src` (platform, providers, integrations, modules, routes, hooks, data e theme, types, lib, branding, componentes shadcn, componentes custom, styles) e, por fim, os imports relativos.
- As classes do Tailwind são ordenadas em `className` e dentro de chamadas a `cn`, `cva`, `clsx` e `tw`.

## Lint

- As categorias `correctness`, `nursery`, `pedantic`, `perf`, `style` e `suspicious` são erros.
- Regras com reconhecimento de tipos e checagem de tipos estão habilitadas (`typeAware` e `typeCheck`).
- Limites importantes: 800 linhas por arquivo, 150 linhas por função, 20 instruções por função, nenhum número mágico além de `0` e identificadores com pelo menos dois caracteres, exceto `_`, `m` e `t`.
- Overrides relaxam algumas regras para testes, código de apresentação e hooks, mocks de teste e arquivos de rota.

As duas ferramentas ignoram arquivos gerados e externos: arquivos de declaração, `src/routeTree.gen.ts`, migrações, `.source`, `dist`, `coverage`, `e2e`, `remotion`, as pastas de agentes e a saída do Playwright. `scripts/` é formatado e verificado pelo lint da mesma forma que `src/`.

Corrija a causa de um erro de lint. Não adicione comentários de desativação, `@ts-expect-error` nem casts com `as` para satisfazer uma regra.

## Correções

O hook de pre-commit executa `bun run check:pre-commit`; a etapa `vp staged` executa `vp check --fix` apenas nos arquivos em stage. `bun run check:fix` aplica correções em todo o repositório e pode reescrever arquivos que você não alterou, então revise o diff antes de fazer o commit. Para corrigir apenas as suas alterações, passe os caminhos delas para o `vp` (a CLI global do Vite+ ou `bunx vp`):

```sh
vp fmt src/routes/admin.users.all.tsx
vp lint --fix src/routes/admin.users.all.tsx
```
