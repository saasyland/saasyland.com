Os dados chegam a uma tela pelo TanStack Query. Um caso de uso exporta as suas options ao lado da sua função de servidor, e o loader da rota, o componente e o teste usam todos essas mesmas options, então compartilham uma única entrada de cache por construção.

## Query options

```ts
export const courseEditorQuery = (input: Course["getCourseEditor"]) =>
  queryOptions({
    queryFn: () => getCourseEditor({ data: input }),
    queryKey: [...COURSE_QUERY_KEYS.EDITOR, input.courseId],
    staleTime: COURSE_STALE_MS,
  })
```

| Tipo de leitura                | Exportação                                                                | Exemplo                                          |
| ------------------------------ | ------------------------------------------------------------------------- | ------------------------------------------------ |
| Recebe uma entrada             | Uma função que retorna options, chamada `<noun>Query`                     | `courseEditorQuery(input)`, `courseQuery(input)` |
| Não recebe entrada             | Uma constante chamada `<noun>Query`                                       | `currentLicenseQuery`                            |
| Lista paginada para uma tabela | `get<Things>PageQuery(input)` e a primeira página como `get<Things>Query` | `getOrdersPageQuery`, `getOrdersQuery`           |

## Chaves de query

Uma chave começa com o prefixo do módulo, de `<table>.constants.ts`, depois a operação e, em seguida, toda entrada que muda o resultado:

```ts
queryKey: [...COURSE_QUERY_KEYS.CATALOGUE, input.locale]
queryKey: [...COURSE_QUERY_KEYS.DETAIL, input.locale, input.slug]
queryKey: [...COURSE_QUERY_KEYS.LIST, courseZodSchemas.getCourses.parse(input)]
```

A chave da lista guarda a entrada já analisada, então `getCoursesPageQuery()` e `getCoursesPageQuery({ pageIndex: 0, pageSize: 10 })` resolvem para a mesma entrada de cache. Um locale entra na chave sempre que o servidor localiza o resultado. Nunca escreva uma chave diretamente em um componente: leia-a das options ou, para invalidar, do objeto `<MODULE>_QUERY_KEYS`.

## Queries públicas [#public-queries]

Uma query cujo resultado é o mesmo para todo visitante, seja qual for o usuário autenticado, declara `meta: { public: true }`:

```ts title="src/lib/github.ts"
export const starCountQuery = queryOptions({
  gcTime: STAR_COUNT_REFRESH_AFTER_MS,
  meta: { public: true },
  queryFn: () => getStarCount(),
  queryKey: ["github", "stars"],
  staleTime: STAR_COUNT_REFRESH_AFTER_MS,
})
```

As traduções (`messagesQueryOptions`) e a contagem de estrelas do GitHub (`starCountQuery`) são queries públicas. Todas as outras queries pertencem ao usuário autenticado. Quando o usuário muda, `removeUserData` em `auth.session.ts` remove essas queries e todas as mutations e mantém as públicas, então o próximo usuário nunca vê os dados do anterior e uma página pré-renderizada mantém os dados com que foi renderizada: a flag acompanha cada query que o servidor desidrata na página. Uma query sem a flag é buscada de novo para o próximo usuário, o que custa uma requisição e nunca vaza dados, então marque uma query como pública apenas quando a sua função de servidor nunca lê a sessão. `auth.session.test.ts` executa todas as queries públicas e falha se alguma delas ler a sessão, ou se um arquivo de código declarar uma query pública que o teste não executa. O teste as lista em `PUBLIC_QUERIES`, cada uma sob a chave do arquivo de código que a declara.

## Validade

`getRouter()` em `src/router.tsx` cria um `QueryClient` por requisição com os tempos de cache de `src/integrations/tanstack-query/query.cache.ts`. O router define `defaultPreloadStaleTime` como `ROUTER_PRELOAD_STALE_TIME_MS` e deixa `defaultStaleTime` no valor padrão, então só esses tempos de cache decidem o que está fresco:

```ts
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      gcTime: QUERY_GC_TIME_MS,
      staleTime: QUERY_STALE_TIME_MS,
    },
  },
})
```

Uma query que precisa de outra validade define `staleTime` com uma constante nomeada que diz o porquê: `PLAYBACK_STALE_MS` (uma hora, dentro do tempo de vida de uma URL de reprodução assinada), `STAR_COUNT_REFRESH_AFTER_MS` para a contagem de estrelas do GitHub, `Infinity` para as mensagens de tradução, que só mudam com um deploy. Nunca crie um `QueryClient` no nível do módulo; no servidor, ele compartilharia os dados de um usuário com a requisição seguinte.

## Os loaders pré-carregam, os componentes leem

Um loader de página pré-carrega as queries que os seus componentes leem: as de que a primeira parte da resposta precisa, dentro do único `Promise.all` descrito em [Arquivos de rota](/docs/conventions/routes), e as demais sem aguardá-las, para que cheguem por streaming ([Seções em streaming](/docs/conventions/routes#streamed-sections)). De `src/routes/app.license.tsx`:

```ts
context.queryClient.query({ ...currentLicenseQuery, staleTime: "static" })
```

`staleTime: "static"` faz o loader retornar qualquer dado em cache em vez de buscá-lo de novo. O componente então lê as mesmas options e aplica o `staleTime` da própria query:

```tsx
const { license } = useSuspenseQuery(currentLicenseQuery).data
```

Assim, navegar para uma página cujos dados já estão em cache renderiza na hora, e os dados desatualizados são atualizados em segundo plano em vez de segurar a navegação.

Uma leitura `"static"` também ignora a invalidação: ela retorna os dados em cache mesmo depois que uma mutation os invalidou, e os dados novos só chegam quando o componente busca de novo. Por isso, um loader aguarda a query com o `staleTime` da própria query quando a página nunca pode mostrar dados mais antigos do que algo que o visitante acabou de fazer, ou quando o próprio loader precisa dos dados, para o título ou para responder 404. As páginas de cursos e o editor de cursos da administração fazem isso, porque concluir uma aula ou salvar o editor precisa mostrar o conteúdo programático atualizado na tela seguinte:

```ts
context.queryClient.query(courseQuery({ locale, slug: params.course })).catch(rethrowAsNotFound)
```

- Use `useSuspenseQuery` para os dados que o loader pré-carregou, e `useQuery` apenas para dados que podem chegar depois sem bloquear a página, como a contagem de estrelas em `proof-section.tsx`. Uma query que o loader envia por streaming é sempre lida com `useSuspenseQuery` dentro de um boundary de `Suspense`; lida com `useQuery`, ela seria renderizada sem os dados no servidor e com eles no navegador.
- Não busque dados em `useEffect` nem repasse resultados de queries como props: cada componente chama as options de que precisa.
- Um `DataGrid` recebe uma função que vai da sua requisição às options, `query={(request) => getOrdersPageQuery(orderZodSchemas.getOrders.parse(request))}`, e executa a query ele mesmo.

## Mutations e invalidação

Um componente espalha as mutation options em `useMutation` e adiciona apenas os seus próprios callbacks. Depois de uma gravação bem-sucedida, ele invalida o prefixo do módulo e então dá o retorno ao usuário:

```tsx
const update = useMutation({
  ...updateCourseMutation,
  onError,
  onSuccess: async () => {
    await queryClient.invalidateQueries({ queryKey: COURSE_QUERY_KEYS.ALL })
    toast.success(t("saved"))
  },
})
```

- Invalide o prefixo mais estreito que cubra todas as telas que mostram os dados alterados. As mutations de capítulos e aulas invalidam `COURSE_QUERY_KEYS.ALL`, porque o editor de cursos e as páginas públicas de cursos os mostram. `useLessonProgress` invalida apenas `COURSE_QUERY_KEYS.DETAIL`, e só quando uma aula é concluída.
- Aguarde a invalidação antes de sair da página ou fechar um diálogo, para que a tela seguinte renderize dados atualizados.
- Os erros passam por `useErrorMessage()`; veja [Funções de servidor e erros](/docs/conventions/server-functions).
- Nunca atualize o cache à mão para simular um resultado. A única exceção é a sessão: quando o usuário autenticado muda, `loadRouteSession` em `auth.routes.ts` remove os dados do usuário anterior com `removeUserData` e guarda a nova sessão, para que nenhum dado privado sobreviva a um logout ou a uma troca de conta. Veja [Queries públicas](#public-queries).
