title: "Stan w adresie URL"
description: "Przechowuj zakładki, widoki i jednorazowe tokeny w zwalidowanych parametrach adresu URL."
---

Parametry adresu URL przechowują stan, który ma przetrwać przeładowanie strony albo udostępnienie linku: wybraną zakładkę lub widok, adres e-mail przekazywany między stronami uwierzytelniania, token weryfikacyjny. Wszystko inne zostaje w stanie Reacta. `DataGrid` trzyma paginację, sortowanie, zaznaczenie, wyszukiwanie i filtry w stanie komponentu, a swój układ w pamięci przeglądarki.

## Zadeklaruj parametry

`validateSearch` przyjmuje obiekt zod, więc parametry URL trasy mają typy i walidację w jednym miejscu. Pola pochodzą z `src/lib/search-params.ts`: `searchText()` i `searchFlag()` mają wartość `undefined`, gdy wartości brak, jest pusta lub błędna, więc brakujące wartości nigdy nie trafiają do URL-a; `searchChoice(choices, fallback)` podstawia wtedy wartość zapasową z listy opcji. `searchParam(schema)` stosuje tę samą zasadę do dowolnego schematu zod; trasy newslettera odczytują `token` schematem tokenu z modułu. Błędna wartość nigdy nie prowadzi do strony błędu. Z `src/integrations/better-auth/auth.zod.ts`:

```tsx
export const settingsSearchSchema = zod.object({
  error: searchText(),
  tab: searchChoice(SETTINGS_TABS, SETTINGS_TAB.GENERAL),
})
```

`src/routes/app.settings.tsx` przekazuje ten schemat do `validateSearch` i usuwa domyślną zakładkę z adresu przez `stripSearchParams({ tab: SETTINGS_TAB.GENERAL })`, więc `/app/settings` pozostaje kanonicznym adresem zakładki **Ogólne**.

## Odczytaj je

- W komponencie trasy: `const { tab } = Route.useSearch()`.
- Z selektorem komponent renderuje się ponownie tylko wtedy, gdy zmieni się wybrana wartość: `Route.useSearch({ select: (search) => search.error !== undefined })`.
- W komponencie poza plikiem trasy: `getRouteApi("/auth/verify-email").useSearch()`, jak w `verify-email-form.tsx`. Trasa może też przekazać zwalidowaną wartość jako prop, tak jak `auth.reset-password.tsx` przekazuje `token` do `ResetPasswordForm`.

## Zmień je

- Linki: `<Link search={{ tier: higher }} to={ROUTES.APP.LICENSE}>`.
- Komponenty React Aria z atrybutem `href`, np. `TabsTrigger` w `src/presentation/components/custom/settings/settings-tabs.tsx`, nawigują przez router, ponieważ `AriaProvider` łączy React Aria z TanStack Router.
- Kod: `router.navigate({ search: { email }, to: ROUTES.AUTH.VERIFY_EMAIL })`.
- Guardy tras i loadery: `throw redirect({ replace: true, to: ROUTES.AUTH.CALLBACK })`.

## Ładuj dane na ich podstawie

Komponent odczytuje parametry URL przez `Route.useSearch()`; loader, który zależy od parametru, deklaruje go w `loaderDeps` i odczytuje z `deps`. Nigdy nie zużywaj w loaderze tokenu z adresu URL, bo loader uruchamia się także przy wstępnym ładowaniu, a uruchamiają go też roboty indeksujące i skanery poczty. Strony potwierdzenia i rezygnacji z newslettera odczytują swój token i działają dopiero po naciśnięciu przycisku:

```tsx
const { status, token } = Route.useSearch()
```

## Języki i adresy URL

- Linki routera (`<Link to={ROUTES.X}>`) dostają prefiks języka z `rewrite` routera. Angielski nie ma prefiksu (`/docs`), pozostałe języki go mają (`/pl-PL/docs`).
- Surowy adres w bieżącym języku buduj przez `router.buildLocation({ search, to }).publicHref`, które go lokalizuje i serializuje jego parametry URL, tak jak robi to `useAuthRedirect` dla `callbackURL` i `errorCallbackURL` w Better Auth. `localizePathname({ locale, pathname })` buduje adres dla wskazanego języka, na przykład linki w e-mailach; ścieżki `/api` i zewnętrzne adresy pozostają bez zmian.
- Przełącznik języka prowadzi do tej samej ścieżki w innym języku z pełnym przeładowaniem strony; parametry zapytania i fragment nie są przenoszone.
