title: "Routes"
description: "Every page and API path, its ROUTES constant, its route file and its guard."
---

Every path has a constant in `ROUTES` (`src/routes.ts`), declared in its area's `src/data/<area>.routes.ts` (see [Paths and navigation](/docs/conventions/routes#paths-and-navigation)). Links use the constant, for example `<Link to={ROUTES.SIGN_IN}>`, and the router adds the locale prefix. Each page below is also served under every non-default locale prefix, for example `/pl-PL/terms`.

## Public pages

These pages sit in the `_site` layout, which renders the site header. All but the docs also sit in the `_marketing` layout (page frame and footer), the docs layout renders the same footer itself, and the blog and the docs have layouts of their own inside them. All of them are prerendered except the newsletter pages.

| Path                          | Constant                 | Route file                                                     |
| ----------------------------- | ------------------------ | -------------------------------------------------------------- |
| `/`                           | `HOME`                   | `_site._marketing.index.tsx`                                   |
| `/licence`                    | `LICENCE`                | `_site._marketing.licence.tsx`                                 |
| `/privacy`                    | `PRIVACY`                | `_site._marketing.privacy.tsx`                                 |
| `/terms`                      | `TERMS`                  | `_site._marketing.terms.tsx`                                   |
| `/refunds`                    | `REFUNDS`                | `_site._marketing.refunds.tsx`                                 |
| `/affiliates`                 | `AFFILIATES`             | `_site._marketing.affiliates.tsx`                              |
| `/newsletter/confirm`         | `NEWSLETTER_CONFIRM`     | `_site._marketing.newsletter.confirm.tsx`                      |
| `/newsletter/unsubscribe`     | `NEWSLETTER_UNSUBSCRIBE` | `_site._marketing.newsletter.unsubscribe.tsx`                  |
| `/blog`                       | `BLOG`                   | `_site._marketing.blog.tsx`, `_site._marketing.blog.index.tsx` |
| `/blog/*`                     | none                     | `_site._marketing.blog.$.tsx`                                  |
| `/docs`                       | `DOCS`                   | `_site.docs.tsx`, `_site.docs.index.tsx`                       |
| `/docs/cli`                   | `DOCS_CLI`               | `_site.docs.$.tsx`                                             |
| `/docs/tooling/test-coverage` | `DOCS_TEST_COVERAGE`     | `_site.docs.$.tsx`                                             |
| `/docs/*`                     | none                     | `_site.docs.$.tsx`                                             |
| `/*`                          | none                     | `_site._marketing.$.tsx`                                       |

`/*` is every path no other route matches: `_site._marketing.$.tsx` throws `notFound()`, so the server answers 404 with the not-found page, rendered on each request (see [Not-found page](/docs/features/landing-page#not-found-page)).

## Courses

The `/courses` layout (`_site._marketing.courses.tsx`) sits in the `_site` and `_marketing` layouts like the blog and has no guard: the server checks each lesson's access level (see [Courses](/docs/features/courses)). These pages read D1 on every request and are not prerendered.

| Path                         | Constant  | Route file                                                           |
| ---------------------------- | --------- | -------------------------------------------------------------------- |
| `/courses`                   | `COURSES` | `_site._marketing.courses.tsx`, `_site._marketing.courses.index.tsx` |
| `/courses/<course>`          | none      | `_site._marketing.courses.$course.index.tsx`                         |
| `/courses/<course>/<lesson>` | none      | `_site._marketing.courses.$course.$lesson.tsx`                       |

## Authentication

The `/auth` layout (`auth.tsx`) has no guard; individual pages do.

| Path                    | Constant          | Route file                 | Guard                                                      |
| ----------------------- | ----------------- | -------------------------- | ---------------------------------------------------------- |
| `/auth/sign-in`         | `SIGN_IN`         | `auth.sign-in.tsx`         | `redirectIfSignedIn`                                       |
| `/auth/sign-up`         | `SIGN_UP`         | `auth.sign-up.tsx`         | `redirectIfSignedIn`                                       |
| `/auth/forgot-password` | `FORGOT_PASSWORD` | `auth.forgot-password.tsx` | none                                                       |
| `/auth/reset-password`  | `RESET_PASSWORD`  | `auth.reset-password.tsx`  | none                                                       |
| `/auth/two-factor`      | `TWO_FACTOR`      | `auth.two-factor.tsx`      | none                                                       |
| `/auth/verify-email`    | `VERIFY_EMAIL`    | `auth.verify-email.tsx`    | Redirects a `token` to Better Auth's verification endpoint |
| `/auth/callback`        | `AUTH_CALLBACK`   | `auth.callback.tsx`        | `redirectAfterAuth`                                        |

## API

API paths are never localized.

| Path                                         | Constant        | Route file                                                                                                                                         |
| -------------------------------------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/api`                                       | `API`           | `api/index.ts`                                                                                                                                     |
| `/api/auth/*`                                | `API_AUTH_BASE` | `api/auth.$.ts`                                                                                                                                    |
| <RepositoryFact name="cliApiBasePath" />`/*` | none            | `api/cli.v1.license.ts`, `api/cli.v1.activations.ts`, `api/cli.v1.activations.$activationId.ts`, `api/cli.v1.activations.$activationId.bundles.ts` |

The CLI licence API's paths come from its contract, `API_BASE_PATH` and `API_ROUTE` in `@saasyland/stack/api`, and `src/routes/api/__test__/cli.v1.test.ts` checks that the router sends each of them to its route file (see [CLI licence API](/docs/features/cli-licence-api)).

`ROUTES.API_AUTH` lists the paths of Better Auth's own endpoints and those of its admin and two-factor plugins, relative to `/api/auth`; `auth.server.ts` uses them to exempt endpoints from rate limiting, and `INPUT_POLICY` in `auth.hooks.ts` to validate the endpoints that accept a password, name, email or image. `ROUTES.API_AUTH_POLAR` lists the Polar plugin's webhooks, which the polar area exempts from rate limiting; it and `API_AUTH_CUSTOMER_PORTAL` are in `src/data/polar.routes.ts`. `API_AUTH_CUSTOMER_PORTAL` and `API_AUTH_VERIFY_EMAIL` are full paths to Better Auth endpoints, built from `API_AUTH_BASE`. `AUTH` and `NEWSLETTER` have no page of their own; together with `ADMIN`, `APP`, `API` and `COURSES` they mark the areas that are never prerendered (`UNLISTED_ROUTES` in `src/data/unlisted.ts`), and `verify-build.ts` fails a build that prerendered a page under any of them.

## Media

`/media/<expiry>.<signature>/<videoId>/<file>` serves signed video files. It has no `ROUTES` constant and no route file: `src/server.ts` sends it to `serveMedia` before the locale middleware, so it is never localized. See [Cloudflare R2](/docs/integrations/cloudflare-r2).

<RepositoryFact name="cliBundleUrlPath" /> serves the CLI's signed template bundles in the same way, through `serveBundle`, and takes its
prefix from `BUNDLE_PATH_PREFIX` in `license.constants.ts`. See [CLI licence API](/docs/features/cli-licence-api#template-bundles).
