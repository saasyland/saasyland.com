Fumadocs は `content/docs` と `content/blog` を、ローカライズされたページに変換します。`bun run content` は `fumadocs-mdx` を実行して `.source/` を書き出します。`dev`、`typegen`、すべてのビルドスクリプトは、最初にこれを実行します。アプリは、ページのコンパイル済み MDX をブラウザーでもプリレンダリング中も `.source/browser.ts` から読み、コンテンツに関するそれ以外のすべてを以下のインデックスから読みます。そのため、デプロイされた Worker はコンテンツを一切保持しません（[パフォーマンス](/docs/conventions/performance#the-worker-holds-no-docs-or-blog-content)を参照）。

| ファイル                | 目的                                                                                                                                                                                                                                                                                                                                      |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `fumadocs.config.ts`    | `docs` と `blog` のコレクション（どちらも `async`）、コードハイライトのテーマと色の置き換え                                                                                                                                                                                                                                               |
| `fumadocs.schema.ts`    | ブログのフロントマターのスキーマ                                                                                                                                                                                                                                                                                                          |
| `fumadocs.i18n.ts`      | `I18N` のロケール、デフォルトかつフォールバックとしての `en-US`、`<slug>.<locale>.mdx` 用の `dot` パーサー、非表示のロケールプレフィックス                                                                                                                                                                                                |
| `fumadocs.indexes.ts`   | ビルド時に実行され、`content/docs` と `content/blog` を読んで、各ロケールのドキュメントのインデックス、ブログのインデックス、検索インデックスを作ります                                                                                                                                                                                   |
| `fumadocs.icons.ts`     | `DOCS_ICONS`（meta ファイルが名前を挙げる Lucide のアイコン）と、meta ファイルの `icon` を対応するアイコンに変換する `docsIcon`                                                                                                                                                                                                           |
| `fumadocs.docs.ts`      | `docs.$` ルート用の `loadDocsPage` と `docsHead`                                                                                                                                                                                                                                                                                          |
| `fumadocs.blog.ts`      | 記事のタイトルを整形し、その URL をローカライズする `toBlogPostSummary`                                                                                                                                                                                                                                                                   |
| `fumadocs.changelog.ts` | `changelogEntries` プラグイン。変更履歴ページの `<ChangelogEntries unreleased="…" />` を、ページのロケールの `content/changelog` のエントリに置き換え、それぞれが `main` に入った UTC の日付ごとに並べ、各エントリの末尾に `<ChangelogLinks>` を付ける。CI では、未リリースであってはならないエントリが未リリースの間はビルドを失敗させる |

ロケールプレフィックスはルーターが付与するため、Fumadocs の URL では非表示になっています。ブログのフロントマターでは `title`、`authorName`、`date` が必須で、`description`、`excerpt`、`faq`、`featured`、`image`、`published`、`tags`、`updated`、このサイト上のパスでなければならない `authorImage`、著者のプロフィールの URL である `authorUrl` も指定できます。

## コンテンツのインデックス [#content-indexes]

`scripts/content-indexes.ts` は Vite プラグインです。Vite のモジュールランナーで `fumadocs.indexes.ts` を読み込み、それが作ったものを仮想モジュールとして提供します。ビルドでも開発サーバーでも同じように動き、開発サーバーでは `content/` 配下を編集するとインデックスが作り直されます。

- `virtual:content-indexes`: `loadDocsIndex(locale)` は、ロケールのシリアライズされたページツリーと、スラッグごとのページを返します。各ページはタイトル、説明、セクション、MDX ファイルを持ちます。`loadBlogIndex(locale)` は、ロケールの公開済みの記事を新しい順に、そのフロントマター、目次、読了時間とともに返します。各ロケールのインデックスはそれぞれ専用のチャンクで、ローダーが最初に必要としたときにインポートします。
- `virtual:docs-search`: `SEARCH_INDEXES` は、各ロケールの検索インデックスの URL を返します。ビルドは Fumadocs の `createSearchAPI("advanced")` で各インデックスを `/assets/search-index-<locale>-<hash>.json` に書き出します。元になるのは Fumadocs の `structure` が各ページから読み取る見出しと本文で、変更履歴ページには変更履歴のエントリが含まれ、各ページには Fumadocs 自身の検索が付けるのと同じパンくずリストが付きます。

`fumadocs.indexes.ts` は、各ページのフロントマターをコレクションのスキーマで検証し、Fumadocs の `loader`、`fumadocs.i18n.ts` の i18n 設定、`docsIcon` のアイコンを使ってツリーを作ります。ブログ記事の目次は `getTableOfContents` から、読了時間は本文の単語数から求めます。単語はその記事のロケール向けの `Intl.Segmenter` で数えます。

## コンポーネント

`src/presentation/components/custom/mdx.tsx` が MDX コンポーネントをマッピングします。Fumadocs のデフォルト（`Cards` と `Callout` を含む）、`Accordions`、`Steps`、`Tabs`、そして shadcn の `Alert`、`Badge`、`Button`、カードの各パーツ、`Separator`、`Table` です。さらに、ビルド時にリポジトリから計測した値やコードで定義された値を表示する `RepositoryFact`（例: `<RepositoryFact name="testFiles" />`）と、コードから組み立てた表を表示する `RepositoryTable`（例: `<RepositoryTable name="commitTypes" columns={["Type", "Emoji"]} />`）があります。`TierPrice` は `TIER_PRICES` からプランの定価をページの言語で表示します（例: `<TierPrice tier="core" />`）。そのため、どのページにも価格を手入力することはありません。`ActivationLimit` は `LICENSE_ACTIVATION_LIMITS` からプランのアクティベーション数の上限を表示し（例: `<ActivationLimit tier="core" />`）、`RegionalDiscounts` は `PPP_TIERS` から導き出した地域割引の割引率を一覧表示します。`ChangelogLinks` は変更履歴ページが各エントリの末尾に付けるもので、エントリのプルリクエスト（例: `<ChangelogLinks pullRequest="257" />`）またはコミットにリンクし、`release` があればエントリを最初に出荷したリリースにもリンクし、スクリーンリーダー向けのリンク名を `components.custom.changelog-links` 名前空間から取ります。内部リンクは `localizePathname` でローカライズされ、タスクリストの項目はチェックボックスとテキストを `label` で囲みます。ページの描画は `docs-content.tsx` と `blog-content.tsx` が担当します。検索、**このページの内容**、コピーボタンなど、Fumadocs 自身のコントロールの文言は `fumadocs` 名前空間から取られます。`useFumadocsI18n` がページの言語と一緒に、ドキュメントとブログのレイアウトの `RootProvider` に渡します。

## コンテンツのルール

すべてのページは、ロケールごとに `<slug>.<locale>.mdx` として 1 つずつ存在します。各フォルダーには `meta.<locale>.json` があり、どのロケールでも同じ `pages` 配列を持ちます。meta ファイルの `icon` には `DOCS_ICONS` にあるアイコンの名前を指定します。新しいアイコンはそこでインポートしてください。meta ファイルがインポートされていないアイコンを指定した場合や、インポートされたアイコンがどの meta ファイルからも指定されなくなった場合、`fumadocs.icons.test.ts` は失敗します。`bun run check:i18n` の一部である `scripts/check-content.ts` は、翻訳の欠落、コードブロック・インラインコード・コンポーネント・リンク・表・ナビゲーションの英語との差異、他のロケールに英語の段落が残っている場合に失敗します。
