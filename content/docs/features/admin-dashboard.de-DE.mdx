## Admin-Shell

`src/routes/admin.tsx` schützt jede Admin-Seite mit `requireAdmin` und lädt die gemeinsamen Admin-Namespaces vorab. Das Layout rendert:

- `AdminSidebar`, `AdminBreadcrumbs` und `AdminCommandPalette` (Öffnen mit ⌘K), alle aufgebaut aus `ADMIN_NAVIGATION` in `src/data/navigation.ts`, das die Einträge der Bereiche samt Icon gruppiert: Überblick (Dashboard, Analytik), Angebote (Produkte, Preismodelle), Inhalte (Blog, Kurse, Videos, Landingpage) und Verwaltung (Benutzerverwaltung, Zahlungen, Einstellungen).
- Das Benutzer-Widget im Fußbereich der Seitenleiste mit einem Link zu den Einstellungen und `SignOutButton`.

## Dashboard

`/admin` (`src/routes/admin.index.tsx`) lädt im Loader `getUsersQuery` und, über ihr `prefetch`, die Query jeder Dashboard-Statistik und jedes Panels, das Daten liest, vorab und setzt die Widgets aus `src/presentation/components/custom/admin/dashboard` mit den Panels zusammen, die die Bereiche hinzufügen:

- `DashboardActions`: ein Link für jeden Eintrag von `ADMIN_DASHBOARD_ACTIONS`, nach seinem `order` sortiert, etwa **Produkt hinzufügen** aus `src/data/products.navigation.ts`, beschriftet aus `navigation.products.json`.
- `DashboardStats` (live): die Statistiken von `ADMIN_DASHBOARD_STATS`, die Einträge der `src/data/<area>.dashboard.ts` mit der Platzierung `DASHBOARD_PLACEMENT.STAT`, nach ihrem `order` sortiert: die Anzahl der Benutzer und die Benutzer, deren E-Mail-Bestätigung noch aussteht, aus `src/data/auth.dashboard.ts` sowie die Anzahl der Produkte aus `src/data/products.dashboard.ts`, jeweils beschriftet aus der `dashboard.<area>.json` ihres Bereichs.
- Die Panels von `ADMIN_DASHBOARD_PANELS`, die Einträge mit der Platzierung `DASHBOARD_PLACEMENT.PANEL`, nach ihrem `order` sortiert, jeweils mit dem Skeleton, das `AdminDashboardPending` dafür zeigt:
  - Der Lizenzbereich fügt in `src/data/license.dashboard.ts` `UnlicensedOrders` (live) hinzu: die bezahlten Lizenzbestellungen ohne Lizenz, jede mit einem Link zur Bestellung in Polar, oder eine Zeile, die sagt, dass es keine gibt, beschriftet aus `dashboard.license.json` (siehe [Lizenzen](/docs/features/licences#orders-that-match-no-account)).
  - Der Zahlungsbereich fügt in `src/data/payments.dashboard.ts` `RevenueChart` (Demo) hinzu, ein statisches SVG mit festen Achsen, beschriftet aus `dashboard.payments.json`; die Zeitraum-Schaltflächen haben keine Funktion.
- Eine Benutzerkarte (live): die neuesten Benutzer mit Suche und Statusfiltern, <RepositoryFact name="adminPreviewPageSize" /> Zeilen pro Seite. Jeder Name verlinkt auf das Profil des Benutzers, wo die Aktionen liegen.

```tsx
<DataTable
  columns={dashboardUserColumns}
  data={users.rows}
  filters={[
    { columnId: "user", placeholder: t("users.search"), type: "search" },
    {
      columnId: "status",
      label: t("users.filters.status"),
      options: USER_STATUSES.map((status) => ({ label: t(`users.table.status.${status}`), value: status })),
      type: "select",
    },
  ]}
  options={{ initialState: { pagination: ADMIN_DASHBOARD_PREVIEW_PAGINATION }, selectable: true }}
/>
```

Die Tabelle arbeitet im Browser mit der ersten Seite von `getUsersQuery` (<RepositoryFact name="defaultPageSize" /> Benutzer). **Alle anzeigen** verlinkt auf `/admin/users`. **Produkt hinzufügen**, der Eintrag des Produktbereichs in `ADMIN_DASHBOARD_ACTIONS`, verlinkt auf `/admin/products/create`.
