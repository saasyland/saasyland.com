## Szablony

Szablony znajdują się w `src/presentation/emails`. Każdy plik zawiera wyłącznie znaczniki i eksportuje stałą ze swoją przestrzenią nazw:

| Szablon                        | Przestrzeń nazw                          | Wysyła go                                             |
| ------------------------------ | ---------------------------------------- | ----------------------------------------------------- |
| `VerifyEmail`                  | `emails.verify-email`                    | `sendVerifyEmail` (hook Better Auth)                  |
| `ResetPasswordEmail`           | `emails.reset-password-email`            | `sendResetPasswordEmail` (hook Better Auth)           |
| `ChangeEmailConfirmationEmail` | `emails.change-email-confirmation-email` | `sendChangeEmailConfirmationEmail` (hook Better Auth) |
| `NewsletterConfirmationEmail`  | `emails.newsletter-confirmation-email`   | `subscribeToNewsletter`                               |
| `NewsletterNotificationEmail`  | `emails.newsletter-notification-email`   | `confirmNewsletterSubscription`, na `CONTACT_EMAIL`   |

Szablon otrzymuje `locale` i `messages` i tłumaczy za pomocą `createTranslator` z use-intl:

```tsx
const t = createTranslator({ locale, messages: { emails: { "verify-email": messages } }, namespace: "emails.verify-email" })
```

## Wysyłka

Przypadek użycia otrzymuje język od wywołującego, sprawdza limit na odbiorcę, ładuje komunikaty, renderuje szablon i go wysyła (`src/modules/verification/use-cases/send-verify-email.ts`):

```ts
if (!(await withinRecipientRateLimit({ kind: "verify-email", recipient: user.email }))) {
  console.warn("[email] verification email not sent: the recipient reached the hourly limit")
  return
}
const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
const verifyUrl = new URL(localizePathname({ locale, pathname: ROUTES.VERIFY_EMAIL }), getRequest().url)
verifyUrl.searchParams.set("token", token)
await sendEmail({
  idempotency: { purpose: "verify-email", token },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```

`sendEmail` (`src/integrations/resend/resend.utils.ts`) wysyła przez Resend z adresu `RESEND_EMAIL_FROM`, chyba że podano `from` (powiadomienie dla właściciela używa `NOTIFICATIONS_EMAIL`), przekazuje klucz idempotencji i zgłasza błąd, gdy wysyłka się nie powiedzie.

E-maile dotyczące konta używają języka strony, na której rozpoczął się przepływ, odczytanego z `callbackURL` w linku e-maila; przy ponownej rejestracji pochodzi on z `callbackURL` żądania rejestracji. E-maile newslettera używają języka przesłanego z formularzem; powiadomienie dla właściciela jest zawsze w `en-US`.

`withinRecipientRateLimit` (`src/lib/rate-limit.ts`) pozwala na najwyżej trzy e-maile weryfikacyjne, trzy e-maile resetu hasła i trzy e-maile potwierdzające subskrypcję newslettera na adres na godzinę, liczone w tabeli `rate_limit` pod skrótem SHA-256 adresu. Powyżej limitu e-mail jest pomijany, a żądanie i tak dostaje zwykłą odpowiedź. Potwierdzenie zmiany adresu e-mail i powiadomienie dla właściciela nie są ograniczone.
