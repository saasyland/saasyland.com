Um e-mail tem três partes: um template em `src/presentation/emails/`, um namespace de mensagens em `messages/<locale>/emails.<name>.json` e o caso de uso que carrega as mensagens, renderiza o template e o envia. Templates: `verify-email`, `reset-password-email`, `change-email-confirmation-email`, `newsletter-confirmation-email`, `newsletter-notification-email` e `purchase-confirmation-email`.

## Template

Um template contém apenas marcação e exporta seu namespace. Ele traduz com `createTranslator` de `use-intl` porque é renderizado fora do contexto do React. `src/presentation/emails/verify-email.tsx`:

```tsx
import type { JSX } from "react"

import { Body, Button, Container, Head, Heading, Html, Preview, Section, Tailwind, Text, pixelBasedPreset } from "react-email"
import { createTranslator } from "use-intl"

import type { SupportedLocale } from "~/src/integrations/use-intl/i18n.config"

import type emailMessages from "~/messages/en-US/emails.verify-email.json"

export const VERIFY_EMAIL_NAMESPACE = "emails.verify-email"

const TAILWIND_CONFIG = { presets: [pixelBasedPreset] }

interface VerifyEmailProps {
  readonly locale: SupportedLocale
  readonly messages: typeof emailMessages
  readonly name: string
  readonly verifyUrl: string
}

export const VerifyEmail = ({ messages, locale, name, verifyUrl }: Readonly<VerifyEmailProps>): JSX.Element => {
  const t = createTranslator({ locale, messages: { emails: { "verify-email": messages } }, namespace: "emails.verify-email" })

  return (
    <Html lang={locale}>
      <Tailwind config={TAILWIND_CONFIG}>
        <Head />
        <Body className="font-sans">
          <Preview>{t("preview")}</Preview>
          <Container className="mx-auto px-5 py-10">
            <Section>
              <Heading className="m-0 mb-4 text-2xl font-bold">{t("heading")}</Heading>
              <Text className="m-0 mb-6 text-base text-neutral-600">{t("body", { name })}</Text>
              <Button
                href={verifyUrl}
                className="box-border rounded-md bg-neutral-900 px-5 py-3 text-center text-base text-white no-underline"
              >
                {t("button")}
              </Button>
              <Text className="mt-6 text-sm text-neutral-500">{t("footer")}</Text>
            </Section>
          </Container>
        </Body>
      </Tailwind>
    </Html>
  )
}
```

## Mensagens

Crie `messages/<locale>/emails.<name>.json` em todos os idiomas. Inclua uma chave `subject`; o caso de uso a traduz separadamente do corpo.

```json
{
  "subject": "Verify your email address",
  "preview": "Verify your email for SaaSy Land",
  "heading": "Verify your email",
  "body": "Hi {name}, thanks for signing up. Confirm your email address to finish setting up your account.",
  "button": "Verify email",
  "footer": "If you did not create an account, you can safely ignore this email."
}
```

As rotas nunca pré-carregam namespaces de e-mail; quem os carrega no servidor é o caso de uso que envia a mensagem.

## Envio

O caso de uso obtém o idioma da URL de callback que recebe, verifica o limite por destinatário, carrega as mensagens, monta links absolutos com `localizePathname` e chama `sendEmail`. `src/modules/verification/use-cases/send-verify-email.ts`:

```ts
export const sendVerifyEmail = async ({
  callbackURL,
  token,
  user,
}: {
  callbackURL: string
  token: string
  user: { email: string; name: string }
}): Promise<void> => {
  if (!(await withinRecipientRateLimit({ kind: EMAIL_PURPOSE.VERIFY_EMAIL, recipient: user.email }))) {
    console.warn("[email] verification email not sent: the recipient reached the hourly limit")
    return
  }

  const callback = new URL(callbackURL, getRequest().url)
  const locale = extractLocaleFromPath(callback.pathname) ?? I18N.DEFAULT_LOCALE
  const verifyUrl = new URL(localizePathname({ locale, pathname: ROUTES.VERIFY_EMAIL }), getRequest().url)
  verifyUrl.search = callback.search
  verifyUrl.searchParams.set("token", token)

  const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })

  await sendEmail({
    idempotency: { purpose: EMAIL_PURPOSE.VERIFY_EMAIL, token: crypto.randomUUID() },
    react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
    subject: createTranslator({ locale, messages })("subject"),
    to: user.email,
  })
}
```

`sendEmail` (`src/integrations/resend/resend.utils.ts`) envia pelo Resend a partir de `RESEND_EMAIL_FROM`, a menos que `from` seja informado, repassa a chave de idempotência para que uma nova tentativa nunca envie duas vezes e lança um erro quando o Resend retorna um.

O e-mail de verificação usa uma chave nova a cada envio, `crypto.randomUUID()`, como os e-mails de conta existente e de senha alterada: o Better Auth assina seus tokens de verificação com carimbos de tempo em segundos inteiros, então um cadastro e um login no mesmo segundo levam o mesmo token, e o Resend trataria o segundo e-mail como uma nova tentativa do primeiro.

## Quem envia o quê

- Os hooks do Better Auth em `src/integrations/better-auth/auth.server.ts` chamam os casos de uso por meio de `RESEND_AUTH_EMAILS` (`src/data/resend.auth-emails.ts`): `sendVerifyEmail` para `emailVerification.sendVerificationEmail` e para novos cadastros de contas não verificadas, `sendExistingAccountEmail` para novos cadastros de contas verificadas, `sendResetPasswordEmail` para `emailAndPassword.sendResetPassword`, `sendPasswordChangedEmail` para `emailAndPassword.onPasswordReset` e `sendChangeEmailConfirmationEmail` para `user.changeEmail`.
- As requisições do Better Auth chegam em `/api/auth` sem prefixo de idioma, então os hooks obtêm o idioma do e-mail a partir do `callbackURL` do fluxo, um caminho de página localizado, com `extractLocaleFromCallbackURL` ou `extractLocaleFromPath` de `src/integrations/use-intl/i18n.paths.ts`. O inglês é o idioma de reserva.
- Os casos de uso da newsletter enviam eles mesmos os e-mails de confirmação e de notificação, por exemplo `subscribeToNewsletter`.
- O handler de webhook `onOrderPaid` da área de licenças chama `sendPurchaseConfirmationEmail` depois de conceder a licença. O e-mail obtém o idioma do `metadata.locale` do pedido, os links do host que recebeu o webhook e o token de idempotência do ID do pedido na Polar, e um envio que falha faz o handler falhar, para que a Polar tente de novo.
- `sendVerifyEmail`, `sendResetPasswordEmail`, `sendExistingAccountEmail` e `subscribeToNewsletter` chamam `withinRecipientRateLimit` (`src/lib/rate-limit.ts`) antes de enviar: no máximo <RepositoryFact name="recipientEmailsPerHour" /> e-mails de um tipo por endereço por hora, com a chave em um hash SHA-256 do endereço. Acima do limite, eles registram um aviso em log e não enviam nada. Adicione a mesma verificação a qualquer e-mail que um visitante possa disparar sem conta.

## Adicione um e-mail

1. Adicione o template em `src/presentation/emails/<name>.tsx` com o `<NAME>_NAMESPACE` exportado.
2. Adicione `messages/<locale>/emails.<name>.json` em todos os idiomas.
3. Dê nome ao propósito dele no `src/data/<area>.email-purposes.ts` da área, que `src/data/email-purposes.entries.ts` reúne em `EMAIL_PURPOSE`, e envie-o a partir do caso de uso dono da ação, passando `idempotency: { purpose, token }` com o token ou o id do registro que o dispara.
4. Teste o template em `src/presentation/emails/__test__/` e o caso de uso com `sendEmail` simulado.

Credenciais do Resend: `RESEND_API_KEY` e `RESEND_EMAIL_FROM`. Os testes nunca acessam o Resend.
