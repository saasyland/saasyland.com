---
title: "Ajouter une page d'administration"
description: "Enregistrez la route, l'entrée de barre latérale, les messages et les widgets d'une nouvelle page d'administration."
---

Les pages d'administration sont des fichiers de route plats sous le layout `/admin` (`src/routes/admin.tsx`), qui exécute `requireAdmin` dans `beforeLoad` et affiche la barre latérale, le fil d'Ariane et la palette de commandes. Les étapes ci-dessous ajoutent une page sur `/admin/reports` ; `src/routes/admin.orders.index.tsx` est un exemple réel complet.

## 1. Ajouter le chemin

Déclarez le chemin dans le fichier de routes de sa zone, ici un nouveau `src/data/reports.routes.ts`, et ajoutez un nouveau fichier au barrel `src/data/routes.entries.ts`. `ROUTES` le contient alors :

```ts
export const ADMIN_REPORTS = "/admin/reports"
```

```ts
export { ADMIN_REPORTS } from "~/src/data/reports.routes"
```

## 2. Créer le fichier de route

Créez `src/routes/admin.reports.tsx`. La route ne définit que le composant de page, `NAMESPACE`, le loader, `head` et `pendingComponent` ; le générateur du routeur enregistre le fichier dans `src/routeTree.gen.ts`.

```tsx
import type { JSX } from "react"

import { createFileRoute } from "@tanstack/react-router"
import { useTranslations } from "use-intl/react"

import { loadPageMetadata, preloadNamespaces } from "~/src/integrations/use-intl/i18n.messages"
import { getCurrentLocale } from "~/src/integrations/use-intl/i18n.utils"

import { pageHead } from "~/src/lib/seo"

import { AdminPageHeader } from "~/src/presentation/components/custom/admin/admin-page-header"
import { AdminReportsPending } from "~/src/presentation/components/custom/admin/reports-pending"
import { ReportStats } from "~/src/presentation/components/custom/admin/reports/report-stats"

import { ROUTES } from "~/src/routes"

const ReportsPage = (): JSX.Element => {
  const t = useTranslations("pages.admin.reports")

  return (
    <div className="flex w-full flex-col space-y-8">
      <AdminPageHeader description={t("metadata.description")} title={t("metadata.title")} />

      <ReportStats />
    </div>
  )
}

const NAMESPACE = "pages.admin.reports"

export const Route = createFileRoute("/admin/reports")({
  component: ReportsPage,
  head: pageHead(ROUTES.ADMIN_REPORTS),
  loader: async ({ context }) => {
    const locale = getCurrentLocale()
    const [metadata] = await Promise.all([
      loadPageMetadata({ locale, namespace: NAMESPACE }),
      preloadNamespaces({ locale, namespaces: [NAMESPACE], queryClient: context.queryClient }),
    ])
    return { locale, metadata }
  },
  pendingComponent: AdminReportsPending,
  staticData: { namespaces: [NAMESPACE] },
})
```

Les queries nécessaires à la page vont dans le même `Promise.all`, par exemple `context.queryClient.query({ ...getUsersQuery, staleTime: "static" })` dans `src/routes/admin.users.all.tsx`. `pageHead` construit le titre, la description, l'URL canonique et les liens vers les autres langues à partir de `metadata` du loader. `AdminReportsPending` est le squelette propre à la page, affiché uniquement lorsqu'une navigation dure plus de <RepositoryFact name="navigationPendingMs" unit="millisecond" />. Écrivez-le dans le fichier de squelettes de sa zone, ici un nouveau `custom/admin/reports-pending.tsx`, à partir de `AdminPageHeaderPending` de `admin-page-header.tsx` pour l'en-tête et des blocs de `pending-blocks.tsx`, afin qu'il reproduise la structure de la page. Le squelette du layout d'administration le lit dans la route, il s'affiche donc aussi lorsque quelqu'un arrive sur `/admin/reports` depuis l'extérieur de la zone d'administration.

Voir [Squelettes de chargement](/docs/architecture/delivery-layer#squelettes-de-chargement).

## 3. Ajouter l'entrée de barre latérale

Ajoutez une entrée avec `placement: NAVIGATION_PLACEMENT.ADMIN` à la liste de menu de sa zone, ici `REPORTS_NAVIGATION` dans un nouveau `src/data/reports.navigation.ts`, et ajoutez un nouveau fichier au barrel `src/data/navigation.entries.ts`. L'entrée nomme son `area`, son groupe de barre latérale, son icône `lucide-react` et son `order` dans le groupe : Tableau de bord vaut 10, donc 30 place Reports après lui.

```ts
{
  area: AREA,
  group: ADMIN_NAVIGATION_GROUP.OVERVIEW,
  icon: FileText,
  key: "reports",
  order: 30,
  placement: NAVIGATION_PLACEMENT.ADMIN,
  to: ROUTES.ADMIN_REPORTS,
},
```

Donnez à l'entrée le libellé `admin.reports` dans le fichier `messages/<locale>/navigation.reports.json` de la zone, dans toutes les langues. Un nouveau groupe nécessite aussi une valeur dans `ADMIN_NAVIGATION_GROUP`, sa place dans `ADMIN_NAVIGATION_GROUPS` et `groups.<group>`. La barre latérale, le fil d'Ariane et la palette de commandes ⌘K lisent tous `ADMIN_NAVIGATION` (`src/data/navigation.ts`) : la page apparaît donc aux trois endroits. La page d'accueil la compte parmi les sections de l'administration, et la barre latérale d'administration de la vidéo `app-tour` de la page d'accueil l'affiche une fois la vidéo régénérée (voir `remotion/README.md`). Un troisième segment d'URL, comme `/admin/reports/create`, affiche dans le fil d'Ariane le libellé `breadcrumbs.create` du même `navigation.reports.json` quand la zone le définit, et aucun troisième élément quand elle ne le définit pas.

## 4. Ajouter les messages de la page

Créez `messages/<locale>/pages.admin.reports.json` dans toutes les langues. `metadata` est obligatoire, car le loader le lit pour l'en-tête du document :

```json
{
  "metadata": {
    "title": "Reports",
    "description": "Revenue and usage reports."
  }
}
```

## 5. Ajouter les widgets

Placez chaque widget, boîte de dialogue, formulaire et jeu de colonnes de tableau dans son propre fichier sous `src/presentation/components/custom/admin/reports/`, par exemple `report-stats.tsx` ou `report-columns.tsx`. Les widgets appellent `useTranslations("pages.admin.reports")` et lisent leurs propres données avec `useSuspenseQuery` ; la page ne leur transmet ni libellés ni données. Les tableaux utilisent le `DataGrid` ; voir [Ajouter une grille de données](/docs/guides/add-a-data-table).

## 6. Protéger et tester

- Le garde du layout contrôle l'accès à la page. Chaque fonction serveur appelée par la page a quand même besoin de `authorized(permission)` ; voir [Rôles et permissions](/docs/guides/roles-and-permissions).
- `/admin` est exclu du prérendu.
- Ajoutez les tests de route de la zone dans `src/routes/__test__/admin-<area>-routes.component.test.tsx` et `admin-<area>-loaders.test.ts`, les tests de widgets dans `src/presentation/components/custom/admin/__test__/` et la page dans `e2e/data/<area>.pages.ts`, puis lancez `bun run check:i18n` et `bun run test:coverage`.
