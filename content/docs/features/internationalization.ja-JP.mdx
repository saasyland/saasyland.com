## 言語

`src/integrations/use-intl/i18n.config.ts` の `I18N` は、`en-US`（既定）、`de-DE`、`es-ES`、`fr-FR`、`it-IT`、`ja-JP`、`pl-PL`、`pt-BR`、`uk-UA`、Cookie `saasyland.com_locale`、既定のタイムゾーン `UTC`、名前付きの日付フォーマット `FORMATS` を定義します。

## URL

既定言語にはプレフィックスがなく、それ以外の言語はパスのプレフィックスになります。たとえば `/docs` と `/pl-PL/docs` です。ドキュメントへのリクエストでは、Worker（`i18n.middleware.ts` の `resolveLocale`）が正規でないパスを 308 でリダイレクトします。`/en-US/docs` は `/docs` に、`/pl/docs` は `/pl-PL/docs` になります。`/api` と `/_serverFn` のパスにはプレフィックスが付きません。

`src/router.tsx` のルーター `rewrite` は、受信した URL からプレフィックスを取り除き、送出する URL に付け加えます。そのためルートとリンクはプレフィックスなしのパスを使います（例: `<Link to={ROUTES.SIGN_IN}>`）。Better Auth の `callbackURL` や `errorCallbackURL` など、現在の言語の生の URL は `router.buildLocation(...).publicHref` から作ります。`localizePathname({ locale, pathname })` は、言語切り替えのリンクやメール内のリンクなど、指定した言語の URL を組み立てます。`AriaProvider` は React Aria コンポーネントの `href` をローカライズします。

## 言語 Cookie

ドキュメントの URL の言語が Cookie と異なる場合、Worker はレスポンスで Cookie を設定します。Cookie から言語を選ぶコードはありません。`getCurrentLocale()` はサーバーとブラウザーの両方で動き、URL のパスを読み取って、`en-US` にフォールバックします。`/api` とサーバー関数の URL にはプレフィックスがないため、サーバーではこれらに対して `en-US` を返します。メールは代わりにフローから言語を取得します。認証メールはフローの `callbackURL` から、ニュースレターの確認メールはフォームが送る `locale` から取得します。

## メッセージ

メッセージは `messages/<locale>/<namespace>.json` で、ファイル名が名前空間です。例: `pages.admin.users`、`components.custom.footer`、`emails.verify-email`、`auth.validations`、`common`。ページの名前空間にはすべて `metadata.title` と `metadata.description` があります。

- ルート名前空間（`common`、`components.*`、`errors*`）はルートの `beforeLoad` でプリロードされます。
- レイアウトは `NAMESPACES` を、ページは `NAMESPACE` を宣言します。どちらも `staticData.namespaces` に入り、ローダーがプリロードします。

```ts
loader: async ({ context }) => {
  const locale = getCurrentLocale()
  const [metadata] = await Promise.all([
    loadPageMetadata({ locale, namespace: NAMESPACE }),
    preloadNamespaces({ locale, namespaces: [NAMESPACE], queryClient: context.queryClient }),
  ])
  return { locale, metadata }
},
```

- `TranslationsProvider` はドキュメントの body を包み、ルート名前空間と一致したルートの名前空間を 1 つの `IntlProvider` にまとめます。そのためエラー画面も翻訳されます。
- メールはサーバー側で `loadNamespace` を使って名前空間を読み込みます。

## コンポーネント

各コンポーネントは `useTranslations` を 1 回だけ呼び出し、翻訳関数を `t` と名付けます。2 つの名前空間が必要なコンポーネントは、共通の親名前空間か、完全なキーを使う `useTranslations()` を使います。

## 日付、数値、タイムゾーン

日付と数値は use-intl の `useFormatter`（`format.dateTime`、`format.number`、`format.relativeTime`、`format.list`）でフォーマットします。日と月の順序、12 時間制か 24 時間制か、区切り文字といった表記の慣習はロケールで決まります。ユーザーが保存する表示設定はタイムゾーンだけです。

`TranslationsProvider` は `IntlProvider` にさらに 2 つの値を渡します。

- `timeZone`: 現在のセッションクエリから得た、サインイン中のユーザーの `timezone` です。セッションがなければ `I18N.DEFAULT_TIMEZONE`（`UTC`）になります。プロバイダーは `/app`、`/admin`、認証の各ルートガードが読み込んだセッションを読み取るだけで、自分では取得しません。そのため、プリレンダリングされた公開ページはどの訪問者にも同じ内容になり、そのままハイドレーションされます。たとえばユーザーが[設定](/docs/features/settings)で新しいタイムゾーンを保存してセッションクエリが変わると、すべての日付が再レンダリングされます。
- `formats`: 名前付きの日付フォーマットである `I18N.FORMATS` です。`src/types/use-intl.d.ts` がその名前を use-intl に登録するため、未知の名前を使うと型チェックが失敗します。

| 名前            | 英語での例                | 用途                                                                                                     |
| --------------- | ------------------------- | -------------------------------------------------------------------------------------------------------- |
| `date`          | Nov 14, 2026              | 読者のタイムゾーンにおける、ある時点の日付。テーブルで使います                                           |
| `dateTime`      | Nov 14, 2026, 3:04 PM UTC | 時刻とタイムゾーンの略称を含む時点。ライセンスの有効化と、管理画面のアカウントの日付で使います           |
| `calendarDate`  | Nov 14, 2026              | ブログ記事の日付のような、時刻を持たない日付。UTC でフォーマットするため、別の日にずれることはありません |
| `calendarDay`   | November 14               | 管理画面のアナリティクスのグラフにある日付ラベル                                                         |
| `calendarMonth` | Nov                       | 管理画面のダッシュボードのグラフにある月ラベル                                                           |

呼び出しごとに、名前付きフォーマットのオプションを 1 つ上書きできます（例: `format.dateTime(new Date(post.date), "calendarDate", { month: "long" })`）。管理画面のテーブルは、他のユーザーの日付を閲覧者自身のタイムゾーンで略称付きで表示するため、1 つの列が 1 つのタイムゾーンで表示され、並べ替えられます。ユーザーのタイムゾーンは独立した列で表示されます。

## 言語の切り替え

`locale-switcher.tsx` には 2 つの言語切り替えコントロールがあります。マーケティングページのフッターにある `LocaleSwitcher` は `<details>` メニューで、各言語について現在のパスへの通常のリンクを表示するため、ハイドレーション前から動作します。ドキュメントと顧客アプリのサイドバーにある `LocaleSelect` は `ThemeSwitch` と同じスタイルのセレクトフィールドで、同じ URL を開きます。どちらの場合も、言語を選ぶと新しいドキュメントが読み込まれ、クエリ文字列とフラグメントは引き継がれません。ポーランド語とウクライナ語のページでは、ラテン拡張とキリル文字のフォントサブセットもプリロードされます（[フォントとブランディング](/docs/ui/fonts-and-branding)）。

## チェック

`bun run check:i18n` は、言語間のキーの一致、`useTranslations` のスコープ内での静的キーの解決、ICU メッセージ構文の検証、ドキュメントとブログのコンテンツの一致を確認します。
