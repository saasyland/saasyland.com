title: "Authentication flows"
description: "How sign-in, sign-up with email verification, password reset, two-factor authentication, OAuth and sign-out work."
---

Better Auth (`src/integrations/better-auth/auth.server.ts`) stores users, sessions and verification tokens in D1 and serves its endpoints under `/api/auth`. The auth pages live under the `/auth` layout; their forms are in `src/presentation/components/custom/auth/`.

## Route guards

`src/integrations/better-auth/auth.routes.ts` exports the guards used in `beforeLoad`:

| Guard                | Used on                          | Effect                                                              |
| -------------------- | -------------------------------- | ------------------------------------------------------------------- |
| `requireSignedIn`    | `/app` layout                    | Redirects to `/auth/sign-in` without a session                      |
| `requireAdmin`       | `/admin` layout                  | Also redirects to `/app` without the `admin: ["access"]` permission |
| `redirectIfSignedIn` | `/auth/sign-in`, `/auth/sign-up` | Sends a signed-in user to `/admin` or `/app`                        |
| `redirectAfterAuth`  | `/auth/callback`                 | Sends the new session to `/admin` or `/app` by role                 |

`requireSignedIn` and `requireAdmin` recheck the session on every navigation, `redirectIfSignedIn` uses the cached session, and every guard clears the query cache when the signed-in user changes.

## Sign-in

1. `SignInForm` calls the Better Auth client's `signIn.email`.
2. An unverified account gets the `EMAIL_NOT_VERIFIED` error and is sent to `/auth/verify-email` with its email address.
3. An account with two-factor authentication receives `twoFactorRedirect`; the client plugin then opens `/auth/two-factor` in the current locale.
4. On success, `usePostAuthRedirect` clears the query and router caches and navigates to `/auth/callback`, which redirects by role.

Errors that Better Auth reports by redirect arrive as `?error=` on `/auth/sign-in` and are shown from `auth.errors`.

## Sign-up and email verification

1. `SignUpForm` validates `signUpWithPasswordSchema` and calls `signUpWithPasswordMutation`, a rate-limited server function that calls `auth.api.signUpEmail`.
2. Better Auth creates the user and calls `sendVerifyEmail`, which emails a link to `/auth/verify-email?token=…` in the locale of the page where the sign-up started. Signing up again with an unverified address sends a fresh link.
3. The form navigates to `/auth/verify-email?email=…`, where `VerifyEmailForm` can resend the link through the rate-limited `sendVerificationEmailMutation`.
4. Opening the link: the route's `beforeLoad` hands the token to `/api/auth/verify-email`. Better Auth verifies it, signs the user in and returns to `/auth/verify-email?verified=true`, which redirects to `/auth/callback`. An invalid or expired link returns with `error` and the page offers a new one.

Sign-in is blocked until the email is verified (`requireEmailVerification: true`).

## Password reset

1. `/auth/forgot-password`: `ForgotPasswordForm` calls `requestPasswordResetMutation` with `redirectTo` set to the localized `/auth/reset-password`.
2. Better Auth calls `sendResetPasswordEmail`. The emailed link passes through Better Auth, which redirects to `/auth/reset-password?token=…`, or with `error` when the token is invalid or expired.
3. `ResetPasswordForm` submits the new password through `resetPasswordMutation`. Better Auth revokes every existing session (`revokeSessionsOnPasswordReset: true`) and the form navigates to sign-in.

## Two-factor authentication

- Enabling (admin settings, Security): `TwoFactorDialog` asks for the password (`enableTwoFactorMutation`), shows the TOTP secret to add to an authenticator app, confirms one code (`verifyTotpMutation`) and then shows the backup codes. `disableTwoFactorMutation` turns it off.
- Signing in: `/auth/two-factor` accepts an authenticator code (`verifyTotpMutation`) or a backup code (`verifyBackupCodeMutation`), both rate-limited, with an option to trust the device. Success runs `usePostAuthRedirect`.

## OAuth

`OAuthButtons` calls `authClient.signIn.social` for Google or GitHub with `callbackURL` set to the localized `/auth/callback` and `errorCallbackURL` to the localized `/auth/sign-in`. The providers are configured in `socialProviders`; register `https://<host>/api/auth/callback/google` and `https://<host>/api/auth/callback/github` with them. Accounts with the same email link automatically, and provider tokens are stored encrypted.

## Sign-out

`useSignOut` calls `signOutUserMutation`, clears the query cache, navigates to `/auth/sign-in` and clears the router cache.
