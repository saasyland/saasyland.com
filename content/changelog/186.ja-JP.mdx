- 修正: CLI ライセンス API が、自身の失敗を誤ったエラーとして報告していました。D1 がリクエストをカウントできないとレート制限がそのリクエストを拒否し、CLI はリクエストが多すぎると表示していました。D1 がライセンスを読み取れないときや、コントラクトが定めていない形で Polar がリクエストを拒否したときは、Worker が CLI の読み取れない HTTP 500 を返し、CLI はユーザーに CLI の更新を促していました。現在は、バンドルのエンドポイントを含むすべてのエンドポイントが、サイトのあらゆる失敗に `serviceUnavailable` と `retry-after` を返します。それを捕捉するのは `license.api.ts` の `serve` だけで、エラーとその原因、スタックとともに `[license] <method> <path> failed` をログに記録します。呼び出し元のキーは `[licence key]` に置き換わります。置き換えなければ、Drizzle のクエリエラーや Polar の検証エラーがキーを Workers Logs に持ち込んでしまいます。API は `countRequest` でリクエストをカウントし、ストレージが失敗するとエラーを投げます。サインイン、サーバー関数、メールの上限は引き続き `consumeRateLimit` を使い、カウントできないリクエストを拒否します。[CLI ライセンス API](/docs/features/cli-licence-api) を参照してください。
