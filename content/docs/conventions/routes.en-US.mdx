title: "Route files"
description: "The one shape of a page route and a layout route: NAMESPACE or NAMESPACES, a single Promise.all loader, a skeleton that mirrors the page, search schemas and links."
---

Every file in `src/routes` has the same shape, so a reader who knows one knows all of them. A route file composes: it declares what the page needs and places components. Widgets, forms, dialogs and table columns live in `src/presentation/components/custom`.

## Page routes

`src/routes/admin.courses.index.tsx`:

```tsx
const CoursesPage = (): JSX.Element => {
  const t = useTranslations("pages.admin.courses")

  return (
    <div className="flex w-full animate-in flex-col space-y-8 duration-500 fade-in-50">
      <div className="flex flex-col gap-4 sm:flex-row sm:items-end sm:justify-between">
        <div>
          <h1 className="text-statement font-semibold text-foreground">{t("title")}</h1>
          <p className="text-sm text-muted-foreground">{t("description")}</p>
        </div>
        <LinkButton className="h-9 gap-2" href={ROUTES.ADMIN_COURSES_CREATE} size="sm">
          <PlusCircle aria-hidden className="size-4" />
          {t("actions.create")}
        </LinkButton>
      </div>

      <DataTable columns={courseColumns} options={{ query: ({ pageIndex, pageSize }) => getCoursesPageQuery({ pageIndex, pageSize }) }} />
    </div>
  )
}

const NAMESPACE = "pages.admin.courses"

export const Route = createFileRoute("/admin/courses/")({
  component: CoursesPage,
  head: pageHead(ROUTES.ADMIN_COURSES),
  loader: async ({ context }) => {
    const locale = getCurrentLocale()
    const [metadata] = await Promise.all([
      loadPageMetadata({ locale, namespace: NAMESPACE }),
      preloadNamespaces({ locale, namespaces: [NAMESPACE], queryClient: context.queryClient }),
      context.queryClient.query({ ...getCoursesQuery, staleTime: "static" }),
    ])
    return { locale, metadata }
  },
  pendingComponent: AdminCoursesPending,
  staticData: { namespaces: [NAMESPACE] },
})
```

- **The component** is a local `const` named `<Name>Page`, defined first. Small markup used only by this page may sit above it as local components, as `CourseProgress` and `StartLink` do in `courses.$course.index.tsx`; anything with its own data, mutation or state goes to a component file.
- **One namespace.** `const NAMESPACE = "pages.<area>.<page>"` sits directly above `export const Route` and is used in `loadPageMetadata`, `preloadNamespaces` and `staticData`. Anything else the page needs is declared by its layout.
- **One `Promise.all`.** The loader starts every piece of work at once: page metadata, the namespace and every query the components read. It returns `{ locale, metadata }` for `head`. Never await one of them before starting the next.
- **`head: pageHead(ROUTES.X)`** builds the title, description, canonical URL and alternates from the metadata in the namespace file.
- **Paths come from `ROUTES`** in `src/routes.ts`, which joins the paths of every area (see [Paths and navigation](#paths-and-navigation)); never write a path literal.

A page whose title comes from a record awaits that record and builds its head from the loader data, as `admin.courses.$courseId.tsx` does:

```tsx
export const Route = createFileRoute("/admin/courses/$courseId")({
  component: CourseEditorPage,
  head: ({ loaderData }: { loaderData?: { locale: SupportedLocale; pathname: string; title: string } | undefined }) =>
    buildPageHead({ locale: loaderData?.locale, pathname: loaderData?.pathname ?? ROUTES.ADMIN_COURSES, title: loaderData?.title }),
  loader: async ({ context, params }) => {
    const locale = getCurrentLocale()
    const data = await context.queryClient.query(courseEditorQuery({ courseId: params.courseId })).catch(rethrowAsNotFound)
    return { locale, pathname: `${ROUTES.ADMIN_COURSES}/${data.course.id}`, title: localize(data.course.title, locale) }
  },
  pendingComponent: AdminCourseEditorPending,
})
```

## Layout routes

`src/routes/admin.courses.tsx`:

```tsx
const NAMESPACES = ["course.validations", "pages.admin.courses"] as const

export const Route = createFileRoute("/admin/courses")({
  loader: ({ context }) => preloadNamespaces({ locale: getCurrentLocale(), namespaces: NAMESPACES, queryClient: context.queryClient }),
  pendingComponent: AdminCourseSectionPending,
  staticData: { namespaces: NAMESPACES },
})
```

- A layout declares `const NAMESPACES = [...] as const` above `export const Route` and preloads it. When it has none, it omits the option; there is no `namespaces: []`.
- A namespace that a component of another area needs in the layout is added by that area in `src/data/<area>.namespaces.ts`, which names the layout by its route id, and the layout spreads `...layoutNamespaces("/app")` into its `NAMESPACES`. The licence area adds `pages.license` to `/app`, whose overview shows the licence card and offer, and the newsletter area adds `auth.validations` to `/_landing` and `/blog`, whose footer shows the newsletter form. `namespaces.test.ts` checks at compile time that every layout an area names is a route id.
- The component, when the layout renders one, is named `<Name>Layout` and places an `<Outlet />`.
- A guard goes in `beforeLoad` on the layout that owns the area: `beforeLoad: requireAdmin` in `admin.tsx`, `requireSignedIn` in `app.tsx`, both layouts of the auth area. Guards decide navigation only; every server function still checks its own permission.

## Option order

`sort-keys` is off in `src/routes` because TanStack Router infers types in declaration order. Options are alphabetical, except that `validateSearch` comes first, before anything that reads the search:

```tsx
export const Route = createFileRoute("/auth/reset-password")({
  validateSearch: zod.object({
    error: searchText(),
    token: searchText(),
  }),
  component: ResetPasswordPage,
```

Never inline an array or object of data inside `createFileRoute`; declare it as a constant above.

## Search params

`validateSearch` is a `zod.object` built from the helpers in `src/lib/search-params.ts`:

| Helper                            | Value when the param is missing or malformed | Use                              |
| --------------------------------- | -------------------------------------------- | -------------------------------- |
| `searchText()`                    | `undefined`                                  | Tokens, emails, error codes      |
| `searchFlag()`                    | `undefined`                                  | Booleans                         |
| `searchParam(schema)`             | `undefined`                                  | Any other schema, such as a path |
| `searchChoice(choices, fallback)` | `fallback`                                   | A tab or a view                  |

Absent text stays `undefined`, so a default never leaks into a URL the router builds. A `searchChoice` param is paired with `search: { middlewares: [stripSearchParams({ tab: DEFAULT_TAB })] }`, which removes the default from the URL. Never hand-write `typeof search["x"] === "string"` checks; add a helper when a new kind of field is needed. When a child needs a param that the page has validated as present, the page narrows it and passes it down, as `auth.reset-password.tsx` passes `token` to `ResetPasswordForm`. A layout validates the params its whole area reads, as `app.tsx` does with `validateSearch: appSearchSchema`; the schema lives in `src/data/app.ts` because the layout's skeleton parses the same params.

## Skeletons

Navigation must feel instant, so every route that renders a page has a `pendingComponent` that mirrors it: the same layout, the same cards and the same number of rows.

- Skeletons live in the area's pending file (`admin/products-pending.tsx`, `courses/courses-pending.tsx`) and use `Skeleton` from shadcn.
- A text placeholder takes the real type token plus `h-lh scale-y-70`, so it has the height of the line it replaces: `<Skeleton className="h-lh w-28 scale-y-70 font-mono text-label" />`.
- List lengths come from the constants the page uses: `PAGE_ROWS` in `admin/pending-blocks.tsx` has `DEFAULT_PAGE_SIZE` rows, the page size of every admin table.
- A layout skeleton picks the page skeleton for the current path from a map, as `AdminPending`, `AppPending` and `MarketingPending` do with `PAGE_SKELETONS` and `AdminCourseSectionPending` with `COURSE_PAGES` in `admin/courses-pending.tsx`. Each area adds its pages to `PAGE_SKELETONS` in `src/data/<area>.skeletons.ts` (see [Paths and navigation](#paths-and-navigation)); a page of a layout that belongs to one area, such as a course section, is added to that layout's own map.
- There is no router-wide `defaultPendingComponent`, and `pendingMs` keeps TanStack's default. The docs routes are the one exception: `pendingMs: Number.POSITIVE_INFINITY` and `wrapInSuspense: false`. The page component hydrates with the docs layout and renders the MDX in its own `<Suspense key={path}>`, so the sidebar works before the page's MDX chunk has loaded, and a navigation replaces the previous page's server HTML instead of hydrating it with the next page's data.

## Links

- Router links take a constant: `<Link to={ROUTES.COURSES}>`, `<Link hash={MARKETING_SECTION_IDS.PRICING} to={ROUTES.HOME}>`, or a route pattern with `params` for dynamic paths. shadcn `LinkButton` takes an `href`.
- Never add the locale prefix to a router link; the router's rewrite adds it. A full URL in the current locale, for a value that leaves the router as a string, comes from `router.buildLocation({ ... }).publicHref`, as `use-auth-redirect.ts` builds its sign-in links. `localizePathname` is for URLs built outside a router context or for another locale: emails, Better Auth redirect targets, links inside MDX and the language switcher.

## Paths and navigation

No file lists every area of the application. Each area, such as the courses, the products or the legal pages, declares its own paths, menu entries and their labels, page skeletons and permissions, and a barrel joins them, so an area is added or left out with its own files. This is how the `saasyland` CLI builds a project from template layers.

| What                            | Each area declares                                             | Barrel                           | Read from                                                                                                                                                          |
| ------------------------------- | -------------------------------------------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Paths                           | `src/data/<area>.routes.ts`: one `export const` per path       | `src/data/routes.entries.ts`     | `ROUTES` in `src/routes.ts`                                                                                                                                        |
| Menu entries                    | `src/data/<area>.navigation.ts`: one `<AREA>_NAVIGATION` list  | `src/data/navigation.entries.ts` | `ADMIN_NAVIGATION`, `ADMIN_DASHBOARD_ACTIONS`, `APP_NAVIGATION`, `APP_RESOURCE_NAVIGATION`, `NAVIGATION_PAGES` and `FOOTER_NAVIGATION` in `src/data/navigation.ts` |
| Dashboard statistics and panels | `src/data/<area>.dashboard.ts`: one `<AREA>_DASHBOARD` list    | `src/data/dashboard.entries.ts`  | `ADMIN_DASHBOARD_STATS` and `ADMIN_DASHBOARD_PANELS` in `src/data/dashboard.ts`                                                                                    |
| Page skeletons                  | `src/data/<area>.skeletons.ts`: one `<AREA>_SKELETONS` list    | `src/data/skeletons.entries.ts`  | `PAGE_SKELETONS` in `src/data/skeletons.ts`                                                                                                                        |
| Permissions                     | `src/data/<area>.access.ts`: one `<AREA>_ACCESS` object        | `src/data/access.entries.ts`     | `APP_STATEMENTS` and `grantsOf` in `src/data/access.ts`                                                                                                            |
| Unlisted paths                  | `src/data/<area>.routes.ts`: one `<AREA>_UNLISTED_ROUTES` list | `src/data/unlisted.entries.ts`   | `UNLISTED_ROUTES` and `isUnlistedRoute` in `src/data/unlisted.ts`                                                                                                  |
| Layout namespaces               | `src/data/<area>.namespaces.ts`: one `<AREA>_NAMESPACES` list  | `src/data/namespaces.entries.ts` | `layoutNamespaces(layout)` in `src/data/namespaces.ts`                                                                                                             |

A barrel holds only `export { … } from` lines, one per area file, sorted by module, like `src/integrations/drizzle-orm/drizzle.schemas.ts`. A barrel that only optional areas fill, such as the layout namespaces, also gets an empty list from the core (`CORE_NAMESPACES` in `src/data/core.namespaces.ts`), so a project without those areas still type-checks and lints. `src/routes.ts` re-exports the paths as one namespace, so each path keeps its literal type and `<Link to={ROUTES.COURSES}>` is still checked against the route tree:

```ts title="src/routes.ts"
export * as ROUTES from "~/src/data/routes.entries"
```

A menu entry names where it appears with `placement` (`NAVIGATION_PLACEMENT` in `src/data/navigation.constants.ts`): the admin sidebar, the buttons above the dashboard, the customer sidebar and its resources, the public header or the footer. Its `order` sorts it among the entries of the other areas, so no list depends on the order of files. Admin entries also name their sidebar `group`, and footer links their `column`; `ADMIN_NAVIGATION_GROUPS` and `FOOTER_COLUMNS` fix the order of groups and columns, and one that no area fills is left out. The admin console and the customer workspace exist only with sign-in, so the auth area owns them: their paths, `/admin`, `/admin/settings`, `/app` and `/app/settings`, and their dashboard, overview, settings and user management entries:

```ts title="src/data/auth.navigation.ts"
const AREA = "auth"

export const AUTH_NAVIGATION = [
  {
    area: AREA,
    group: ADMIN_NAVIGATION_GROUP.OVERVIEW,
    icon: Home,
    key: "dashboard",
    order: 10,
    placement: NAVIGATION_PLACEMENT.ADMIN,
    status: FEATURE_STATUS.AVAILABLE,
    to: ROUTES.ADMIN,
  },
  {
    area: AREA,
    group: ADMIN_NAVIGATION_GROUP.ADMINISTRATION,
    icon: Users,
    key: "userManagement",
    order: 10,
    placement: NAVIGATION_PLACEMENT.ADMIN,
    status: FEATURE_STATUS.AVAILABLE,
    to: ROUTES.ADMIN_USERS,
  },
  {
    area: AREA,
    group: ADMIN_NAVIGATION_GROUP.ADMINISTRATION,
    icon: Settings,
    key: "settings",
    order: 30,
    placement: NAVIGATION_PLACEMENT.ADMIN,
    status: FEATURE_STATUS.AVAILABLE,
    to: ROUTES.ADMIN_SETTINGS,
  },
  { area: AREA, icon: Home, key: "overview", order: 10, placement: NAVIGATION_PLACEMENT.APP, to: ROUTES.APP },
  { area: AREA, icon: Settings, key: "settings", order: 30, placement: NAVIGATION_PLACEMENT.APP, to: ROUTES.APP_SETTINGS },
  { area: AREA, column: FOOTER_COLUMN.PRODUCT, key: "signIn", order: 40, placement: NAVIGATION_PLACEMENT.FOOTER, to: ROUTES.SIGN_IN },
] as const satisfies readonly NavigationEntry[]
```

An admin entry also says whether its section works or is arriving, with `status` (`FEATURE_STATUS` in `src/data/navigation.constants.ts`); the landing page counts only the working sections.

The licence area adds its **Licence** entry to the customer sidebar, and the content area adds **Documentation** to the sidebar's resources, above the support address. The core area declares only `/` and `/api`.

A dashboard statistic has a `prefetch`, which the `/admin` loader runs, and a `useValue` hook, which `DashboardStats` calls to read the number.

A page skeleton pairs the page's `to` with its `pendingComponent`, the same skeleton the page's route sets. The layout skeletons `AdminPending`, `AppPending` and `MarketingPending` draw the one for the current path when someone enters their layout from elsewhere. An area declares the skeletons of all its pages, whichever layout shows them: the licence area declares `/app`, `/app/license` and `/premium`, and the legal area its five public pages.

An area's access file declares the permission statements of its resources and the roles it grants them to. `auth.access.ts` builds Better Auth's access control from `APP_STATEMENTS` and each role from `grantsOf(role)`, so the auth integration names no area, and `APP_STATEMENTS` fails when two areas declare the same resource (see [Roles and permissions](/docs/guides/roles-and-permissions)).

The lists in `src/data/navigation.ts` and `PAGE_SKELETONS` have declared types, `NavigationEntry` and `PageSkeleton`, rather than the types of the entries the areas happen to declare, so a placement that no area fills, such as the dashboard actions in a project without the products area, is an empty list that still type-checks. `navigation.test.ts` and `skeletons.test.ts` check at compile time that the `to` of every entry and skeleton an area declares is a path of the route tree (`FileRouteTypes["to"]` from `src/routeTree.gen.ts`).

An entry names its `area`, and the area labels it in its own message file: `<placement>.<key>` in `messages/<locale>/navigation.<area>.json`, such as `admin.courses` and `header.courses` in `navigation.courses.json`. A dashboard statistic is labelled by its `key` in `dashboard.<area>.json`, and an admin section labels its sub-pages for the breadcrumbs under `breadcrumbs.<segment>` in its `navigation.<area>.json`, such as `breadcrumbs.create`; a user management tab is labelled under `userTabs.<key>`, which names the tab and its page in the breadcrumbs, and a dashboard panel keeps its copy under its `key` in `dashboard.<area>.json`. Both kinds of file are root namespaces, so every menu can label every entry, and `useNavigationLabel` in `src/hooks/use-navigation-label.ts` returns an entry's label. What belongs to a menu itself stays in its namespace: `groups.<group>` in `pages.admin.sidebar`, `columns.<column>` in `components.custom.footer` and the landing sections in `components.custom.navigation`. `enum-labels.test.ts` fails when an entry or statistic has no label in a locale.

An area whose pages render on the Worker for each request, such as `/admin`, `/auth` or `/courses`, lists those paths in `<AREA>_UNLISTED_ROUTES`. The TanStack Start plugin in `src/data/tanstack.vite.ts` keeps them out of prerendering with `isUnlistedRoute`, and `buildPageHead` gives them the site card instead of a page card (see [Search and social previews](/docs/features/seo)). Vite does not resolve the `~` alias while it loads its own configuration, so `unlisted.entries.ts` and `unlisted.ts` import the area files by relative path.
