- Changed: `bun run check:areas` now also prunes, as the `saasyland` CLI does, the tests that name a removed area. A test whose callback names it goes whole, a row of an `.each` table goes on its own, a setup hook loses the statements that name it, every `vi.mock` of a deleted module goes, and so does a `describe` or a test file left without a test. See [Testing](/docs/conventions/testing#tests-follow-the-areas).
- Changed: it also prunes the code built from a removed area. A variable declarator whose value comes only from the area goes with every use of the names it binds, and a statement that names the area goes at the top of a module, a `describe` or a hook. A value that also draws on code that stays, such as a menu link built from an entry that stays, and a function, condition or export are reported instead, because the design has to change, not the pruning.
