---

Copy the template for the environment you work in. `.env.development`, `.env.preview` and `.env.production` are ignored by Git; `.env.test` is committed with dummy values for tests and the isolated preview.

```sh
cp .env.example .env.development
openssl rand -base64 48
```

Use the generated value as `AUTH_SECRET`, with a different secret for each deployed environment.

| Variables                                                                       | Purpose                                                                                        |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `AUTH_SECRET`                                                                   | Better Auth signing and encryption secret                                                      |
| `AUTH_GITHUB_CLIENT_ID`, `AUTH_GITHUB_CLIENT_SECRET`                            | GitHub OAuth app; also authenticates the GitHub star count request                             |
| `AUTH_GOOGLE_CLIENT_ID`, `AUTH_GOOGLE_CLIENT_SECRET`                            | Google OAuth app                                                                               |
| `RESEND_API_KEY`, `RESEND_EMAIL_FROM`                                           | Resend API key and the default sender address                                                  |
| `POLAR_SERVER`                                                                  | `sandbox` for development and preview, `production` for production                             |
| `POLAR_ACCESS_TOKEN`, `POLAR_ORGANIZATION_ID`                                   | Polar API access and the organization for discounts and licence keys                           |
| `POLAR_WEBHOOK_SECRET`                                                          | Verifies Polar webhooks at `/api/auth/polar/webhooks`                                          |
| `POLAR_PRODUCT_ID_CORE`, `POLAR_PRODUCT_ID_COMPLETE`, `POLAR_PRODUCT_ID_AGENCY` | Polar products for the three checkout tiers                                                    |
| `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID`, `CLOUDFLARE_ACCESS_TOKEN`    | D1 HTTP API access for Drizzle Studio and introspection; the application uses the `DB` binding |

The `development`, `preview` and `production` environments in `wrangler.jsonc` require every key above as a secret (`secrets.required`). Server code reads them with `import { env } from "cloudflare:workers"`. None has a `VITE_` prefix, because Vite exposes those values to the browser. `.env.example` lists the keys in blocks, one per module, in the same order as `secrets.required`, and `src/__test__/wrangler.test.ts` fails when the two differ.

`.env.development` may also set `LOCAL_ADMIN_PASSWORD`, the password `bun run db:seed:local` gives the local admin; it is not a Worker secret and never leaves your machine. See [The local seed](/docs/tooling/database#the-local-seed).

`AFFONSO_PROGRAM_ID` is not a secret and is not in `.env.example`. It is the public Affonso program ID that affiliate referral tracking needs, so it is a Worker variable under `vars` in `wrangler.jsonc`, set only for the environment that takes real payments: `production` sets SaaSy Land's programme ID, and `test` a dummy ID for the browser tests. Tracking runs only when the Worker has the ID and the programme is open: `AFFILIATE_PROGRAM` is <RepositoryFact name="affiliateProgram" /> today. See [Opening the programme](/docs/features/affiliates#opening-the-programme).

## Values in code

Some settings are code, not environment variables:

- `src/presentation/branding/index.ts`: the application name, `APP_DOMAIN` (the canonical URL is `https://` plus that domain), the preview host `APP_PREVIEW_DOMAIN`, contact addresses and the GitHub repository.
- `src/modules/_core/constants/api.ts`: the preview and production hosts (`DEPLOYED_HOSTS`, read from `APP_PREVIEW_DOMAIN` and `APP_DOMAIN`), which Better Auth and newsletter links accept (`appHostsForMode`) and the deploy scripts check after a deploy.
- `wrangler.jsonc`: Worker names, custom domains, which `src/__test__/wrangler.test.ts` keeps equal to `DEPLOYED_HOSTS`, the D1 and KV IDs and the R2 bucket names.

## Provider callbacks

- GitHub and Google: <RepositoryFact name="oauthCallbackUrls" />.
- Polar webhooks: `https://<host>/api/auth/polar/webhooks`, signed with `POLAR_WEBHOOK_SECRET`. [Polar setup](/docs/getting-started/polar-setup) lists the events, products, discounts and token scopes, and `bun run polar:verify:<environment>` checks them.
