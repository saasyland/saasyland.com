## Datos

`src/modules/category/category.schema.ts` define la tabla `category`: `name`, `description`, `kind` (`category` o `collection`), `visibility` (`public` o `hidden`), `icon` (`Archive`, `FolderOpen` o `Puzzle`) y marcas de tiempo.

Casos de uso en `src/modules/category/use-cases`, cada uno protegido por el permiso `category` correspondiente: `getCategories` (paginado, con `kind` opcional), `getCategory`, `createCategory`, `updateCategory` y `deleteCategory`. Ninguna ruta, componente ni otro caso de uso los llama: solo importan el módulo `drizzle.schemas.ts`, que entrega a Drizzle todas las tablas, y un fixture de pruebas. No es un modelo que copiar; para copiar un caso de uso, toma uno de un módulo que use una pantalla, como `src/modules/course`.

Los mensajes de error están en el espacio de nombres `category.errors`. Todavía ningún formulario edita categorías, así que sus mensajes de Zod tendrán un espacio de nombres `category.validations` con el primer formulario que los muestre.

## Pantalla de administración

Ninguna pantalla lista, crea, edita ni elimina categorías, y los productos no tienen relación con las categorías. `/admin/products` muestra el catálogo de Polar (consulta [Productos](/docs/features/products)).
