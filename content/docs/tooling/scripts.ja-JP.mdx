description: "package.json のすべてのスクリプトと、その実行内容です。"

スクリプトはリポジトリのルートで `bun run <script>` として実行します。Wrangler を呼び出すスクリプトと、drizzle-kit を呼び出す `db:generate` は、それらを `vp exec` 経由で実行します。`vp exec` は `node_modules/.bin` のバイナリを使うため、常に `bun.lock` で固定されたバージョンが使われます。

## 開発とビルド

| スクリプト         | 実行内容                                                                                                                                            |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dev`              | `generate:cn`、`content`、そして `development` 環境の `vp dev` を http://localhost:3000 で実行                                                      |
| `build`            | `build:preview` と同じ                                                                                                                              |
| `build:preview`    | `dist` のクリーン、`generate:cn`、`content`、`preview` 向けの `vp build`、`scripts/verify-build.ts preview`、`scripts/optimize-prerendered-html.ts` |
| `build:production` | `production` 向けに同じ手順を実行                                                                                                                   |
| `build:test`       | `test` 環境向けに同じ手順を実行                                                                                                                     |
| `start`            | 最新のビルドを `vp preview` で http://127.0.0.1:3000 に配信                                                                                         |
| `start:test`       | テスト用ビルドの `vp preview`                                                                                                                       |

`verify-build.ts` は、まず `.wrangler/deploy/config.json` が `dist/server/wrangler.json` を指していること、そしてこのファイルが `wrangler.jsonc` でその環境に指定された Worker をデプロイすることを確認します。続いて、ローカライズされたホームページと法的ページのドキュメント言語・正規リンク・代替リンク、フォント、保護されたページとロケールエイリアスがプリレンダリングされていないこと、そしてクライアントのアセットが `cloudflare:workers` をインポートしていないことを確認します。`optimize-prerendered-html.ts` は、プリレンダリングされたページから依存関係の `modulepreload` ヒントを取り除き、エントリーのヒントは低優先度のまま残します。

## デプロイ

| スクリプト          | 実行内容                                                                                                                                                                                                           |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `deploy:preview`    | `scripts/verify-bindings.ts preview`、`build:preview`、`scripts/prepare-deploy-secrets.ts preview`、`db:migrate:preview`、`dist/server/wrangler.json` の `wrangler deploy`、`scripts/verify-deployment.ts preview` |
| `deploy:production` | `production` 向けに同じ手順を実行                                                                                                                                                                                  |

- `verify-bindings.ts` は、環境に `DB`、`CACHE`、`MEDIA` のいずれかのバインディングがない場合や D1 または KV のプレースホルダー ID が残っている場合、また本番がデータベース、名前空間、バケットをプレビューと共有している場合に失敗します。
- `prepare-deploy-secrets.ts` は、環境の `secrets.required` に列挙されたキーを `.env.<environment>` から読み込み、いずれかがないか空の場合は失敗し、それらのキーだけを `.wrangler/secrets.<environment>.json` に書き出します。ファイル内のその他の変数はアップロードされません。
- マイグレーションはビルドの後、デプロイの前に実行されます。そのため、ビルドが失敗してもデータベースに手が加わることはなく、新しい Worker が古いスキーマで起動することもありません。
- デプロイでは `env -u CLOUDFLARE_ENV vp exec wrangler deploy --config dist/server/wrangler.json --secrets-file .wrangler/secrets.<environment>.json` を実行します。ビルドされた設定はすでに 1 つの環境を対象にしています。シェルに `CLOUDFLARE_ENV` が残っていると、Wrangler はそのファイルにない環境セクションを探そうとします。
- `verify-deployment.ts` は、環境のドメインで `/`、`/courses`、`/robots.txt`、`/api`、`/api/auth/get-session` にリクエストを送り、それぞれが期待されるコンテンツタイプで `200` を返さない限り失敗します。失敗したパスには 5 秒間隔で 3 回リクエストし、何も変更しません。`bun scripts/verify-deployment.ts <preview|production>` は、稼働中のサイトを単独で確認します。

## チェック

| スクリプト         | 実行内容                                                                                |
| ------------------ | --------------------------------------------------------------------------------------- |
| `check`            | `generate:cn`、`check:i18n`、`vp check`（フォーマット、リント、型）                     |
| `check:fix`        | 同じ内容を `vp check --fix` で実行                                                      |
| `check:i18n`       | `scripts/check-i18n.ts`、`scripts/check-message-formats.ts`、`scripts/check-content.ts` |
| `check:pre-commit` | `generate:cn`、`check:i18n`、`vp staged`。pre-commit フックから実行されます             |
| `lint`             | `vp lint`                                                                               |
| `format`           | `vp fmt`                                                                                |
| `format:check`     | `vp fmt --check`                                                                        |

## テスト

| スクリプト                                                                                        | 実行内容                                                              |
| ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `test`                                                                                            | すべての Vitest プロジェクトに対する `vp test run`                    |
| `test:unit`, `test:integration`, `test:component`                                                 | 1 つの Vitest プロジェクト（`node`、`integration`、`component`）      |
| `test:changed`                                                                                    | 変更されたファイルの影響を受けるテスト                                |
| `test:watch`                                                                                      | ウォッチモードの Vitest                                               |
| `test:coverage`                                                                                   | カバレッジのゲート付きで全プロジェクト                                |
| `test:all`                                                                                        | `test` の後に `test:e2e:smoke`                                        |
| `test:e2e`, `test:e2e:smoke`, `test:e2e:pr`, `test:e2e:headed`, `test:e2e:ui`, `test:e2e:install` | Playwright。[Playwright](/docs/tooling/playwright) を参照してください |

## データベース

| スクリプト                                                                       | 実行内容                                                            |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| `db:generate`                                                                    | drizzle-kit によるマイグレーションの生成                            |
| `db:migrate:local`, `db:migrate:test`                                            | ローカルのデータベースに対する Wrangler のマイグレーション          |
| `db:migrate:development`, `db:migrate:preview`, `db:migrate:production`          | リモートのデータベースに対する Wrangler のマイグレーション          |
| `db:migrations:development`, `db:migrations:preview`, `db:migrations:production` | リモートのデータベースにまだ適用されていないマイグレーション        |
| `db:seed:test`                                                                   | `scripts/seed-test.ts`: テストアカウント、動画、コース              |
| `db:reset:test`                                                                  | `.wrangler/test` の削除、続いて `db:migrate:test` と `db:seed:test` |
| `db:studio:development`, `db:studio:preview`, `db:studio:production`             | Drizzle Studio                                                      |
| `db:introspect:development`, `db:introspect:preview`, `db:introspect:production` | drizzle-kit のイントロスペクション                                  |

## 動画

## 生成とメンテナンス

| スクリプト       | 実行内容                                                                                                 |
| ---------------- | -------------------------------------------------------------------------------------------------------- |
| `content`        | `fumadocs-mdx`: `content/` から `.source/` を生成します                                                  |
| `generate:cn`    | `src/lib/cn.config.ts` から `.source/cn-tables.ts` にクラスマージ用のテーブルを生成します                |
| `cf-typegen`     | `development` 向けの `wrangler types`: `src/types/worker-configuration.d.ts` を再生成します              |
| `typegen`        | `cf-typegen`、`generate:cn`、`content`                                                                   |
| `skills:sync`    | `scripts/sync-skills.ts`: `skills-lock.json` からエージェントスキルを復元します                          |
| `clean`          | `.source`、`.tanstack`、`.wrangler`、`dist`、`coverage`、Playwright の出力、`*.tsbuildinfo` を削除します |
| `clean:deep`     | `clean` に加えて `node_modules`                                                                          |
| `clean:hardcore` | `clean:deep` に加えて `bun.lock` と `skills-lock.json`                                                   |
| `prepare`        | インストール時に実行: `vp config --no-agent`（Git フック）、`generate:cn`、`content`                     |

`clean` は、ローカルの開発用およびテスト用データベースと、デプロイスクリプトが書き出したシークレットファイルを含む `.wrangler` を削除します。残しておきたいローカルデータがあれば、先にエクスポートしてください。
