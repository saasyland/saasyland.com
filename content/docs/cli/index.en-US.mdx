A SaaSy Land licence is a licence to the `saasyland` command line. This page describes the release on npm's <RepositoryFact name="cliReleaseChannel" /> tag, <RepositoryFact name="cliPackageSpec" />, and the [release notes](/docs/cli/releases) list what each release changed.

## What works today

- <RepositoryFact name="cliInit" /> creates a project: React with TanStack Start on a Cloudflare Worker, with Cloudflare D1 through Drizzle,
  with Better Auth sign-in or without it. [Create a project](#create-a-project) says what it writes.
- `activate`, `whoami` and `deactivate` manage your licence key on a machine.
- `--help` and `--version` work fully, and every command takes `--json` and `--locale`.
- `change`, `update` and `status` are not available yet: they check their flags and exit with code <RepositoryFact name="cliExitNotAvailable" />. The [configurator](/#cli) on the landing page lets you pick only what `init` writes today and shows every other option disabled, `init` refuses those options with the same code, and the [roadmap](/docs/project/roadmap) lists what follows.

## Run it

Run the CLI from the <RepositoryFact name="cliReleaseChannel" /> tag with your package manager. Nothing needs to be installed globally:

<RepositoryTable columns={["Package manager", "Command"]} name="cliRunners" />

Without the tag, your package manager runs npm's `latest` tag, which still holds the placeholder release that reserved the name, and none of its commands work. The CLI needs Node.js <RepositoryFact name="cliNodeEngine" />, or Bun.

## Activate your key

1. Sign in and copy your key from [your licence page](/app/license).
2. Run <RepositoryFact name="cliActivate" />. In a terminal, the CLI asks for the key and hides it while you type.
3. Instead of typing it, you can pass the key as an argument, which stays in your shell history, or set <RepositoryFact name="cliLicenseKeyVariable" />, which does not. Without a key, `activate` uses the key already activated on this machine.

`--label` names the machine on your licence page; by default the name is the host name. Activating a machine again keeps the slot it already has.

## Create a project

Run <RepositoryFact name="cliInitCommand" /> with the flags the [configurator](/#cli) builds from your answers, or with `--yes` for the defaults below.

`init` writes the project into the directory you name, which must not exist yet or must be empty, or into the current directory when you name none; `--cwd` runs it as if it were started in another directory. Answers are flags. `--yes` takes the default for every answer no flag gives, and so does a session in a terminal until the questions arrive in a later release. In CI, in a coding agent or without a terminal, `init` without `--yes` names the flags that are missing and prints a command with every answer to copy.

The defaults are this website's own stack wherever the release has templates for it: React with TanStack Start, a single-tenant monolith on a Cloudflare Worker, SQLite on Cloudflare D1 through Drizzle, Better Auth, Resend, the Fumadocs documentation and the MDX blog, without billing (`--no-billing`). `--no-auth` writes the same project without sign-in. Any other answer, `--billing polar` included, exits with code <RepositoryFact name="cliExitNotAvailable" /> before your licence is checked, says that it is not available in this release and names the answers that are.

Every run checks your licence online and downloads the templates of its own release from saasyland.com; there is no offline mode. It uses the licence activated on this machine. When there is none, or <RepositoryFact name="cliLicenseKeyVariable" /> holds another key, it first activates the key in that variable, or in a terminal asks for your key and activates it. Before it uses the templates, it checks their size and SHA-256 against what saasyland.com sent and against the digest this release of the CLI pinned, and refuses them on any difference. It writes the project into a temporary directory beside the target and then moves it into place, so Ctrl+C or a failed write leaves nothing behind. `--dry-run` downloads and checks the templates and lists every file `init` would write, without writing any.

`saasyland.json` in the project records the release, your answers and the SHA-256 of every file `init` wrote, and never holds your licence key. Run `init` again with the answers it records to get a clean project to compare with yours.

The project's README takes you through the first install: `bun install` writes the lockfile, and three scripts generate the Worker types, the route tree and the database migrations before your first commit. Its documentation site, at `/docs` in the project, goes from that install to the first deploy.

## Machines

Each machine you activate takes one of your licence's slots: <ActivationLimit tier="core" /> on Core, <ActivationLimit tier="complete" /> on Complete and <ActivationLimit tier="agency" /> on Agency.

- <RepositoryFact name="cliWhoami" /> shows your tier, the slots in use and this machine's name.
- <RepositoryFact name="cliDeactivate" /> frees this machine's slot and removes the licence from it.
- To free the slot of a machine you no longer use, remove it under **Machines** on [your licence page](/app/license). The next `whoami` or `deactivate` on that machine notices.

When every slot is taken, `activate` lists the machines that hold them and sends you to your licence page to free one.

## CI

Store the key as a secret in <RepositoryFact name="cliLicenseKeyVariable" />. On <RepositoryFact name="cliCiProviders" />, every run of one repository derives the same machine ID, so the repository takes one slot however often it runs, labelled with the provider and the repository's name. On any other CI system, or in a container without a machine ID, set <RepositoryFact name="cliCiRepositoryVariable" /> to the repository's name.

## Where the licence is kept

The CLI keeps the licence in <RepositoryFact name="cliCredentialsFile" />, which only your user can read (mode <RepositoryFact name="cliCredentialsFileMode" />), in your config directory:

<RepositoryTable columns={["System", "Directory"]} name="cliCredentialDirectories" />

When `XDG_CONFIG_HOME` is not set, Linux uses <RepositoryFact name="cliCredentialsLinuxFallback" />. The CLI sends saasyland.com a keyed hash of this machine's ID, never the ID itself. When saasyland.com reports the licence as refunded or revoked, the CLI removes it from the machine and points you to your licence page and to support.

## Environment variables

| Variable                                          | What it sets                                                                                                 |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| <RepositoryFact name="cliLicenseKeyVariable" />   | The licence key, for CI and for sessions that cannot ask for it                                              |
| <RepositoryFact name="cliCiRepositoryVariable" /> | The repository's name on a CI system the CLI does not recognise                                              |
| <RepositoryFact name="cliLocaleVariable" />       | The language of the output: `--locale` comes first, then this variable, then your system language            |
| <RepositoryFact name="cliApiUrlVariable" />       | Another deployment of saasyland.com, such as a preview: an `https` URL, or an `http` URL on your own machine |

## Scripts and coding agents

`--json` prints the result or the error as one JSON document. In CI, in a coding agent or without a terminal, the CLI never waits for input: `activate` without a key, and `init` without an answer it needs, stop with exit code <RepositoryFact name="cliExitUsage" /> and say how to pass it.

| Exit code                                         | When                                                                                                                                                                                                |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <RepositoryFact name="cliExitSuccess" />          | The command did what it says                                                                                                                                                                        |
| <RepositoryFact name="cliExitFailure" />          | Something went wrong inside the CLI                                                                                                                                                                 |
| <RepositoryFact name="cliExitUsage" />            | A flag or <RepositoryFact name="cliApiUrlVariable" /> is invalid, the key or an answer is missing in a session that cannot ask for it, or the project's directory is not empty or cannot be written |
| <RepositoryFact name="cliExitNotAvailable" />     | The command, or one of your answers, is not available in this release, this machine's ID cannot be read, or the system is not Linux, macOS or Windows                                               |
| <RepositoryFact name="cliExitTemporaryFailure" /> | saasyland.com cannot be reached or asks you to try again later, or the templates could not be downloaded                                                                                            |
| <RepositoryFact name="cliExitProtocol" />         | saasyland.com and this version of the CLI cannot understand each other, or the templates do not match their digests; update the CLI                                                                 |
| <RepositoryFact name="cliExitNoPermission" />     | No licence is activated here, this machine's slot was freed, the key is invalid, revoked or refunded, or every slot is taken                                                                        |
| <RepositoryFact name="cliExitCancelled" />        | You cancelled the question with Ctrl+C, or stopped `init` with it; nothing was written                                                                                                              |
