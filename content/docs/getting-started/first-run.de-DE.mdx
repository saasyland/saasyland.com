## Isolierte Test-Preview

Die Test-Preview baut die Anwendung für die Umgebung `test`: lokale D1, KV und R2 in `.wrangler/test`, Platzhalter-Zugangsdaten aus `.env.test`, per Seed angelegte Konten und abgefangene Anfragen an Resend und Polar. Sie benötigt keine Konten.

```sh
bun run db:reset:test
bun run build:test
bun run start:test
```

Öffne http://127.0.0.1:3000 und melde dich mit einem der Konten an, die `e2e/data/accounts.ts` anlegt. Jedes verwendet das Passwort <RepositoryFact name="testPassword" />. Admins landen auf `/admin`, Kunden auf `/app`, und das lizenzierte Konto und seine Lizenz stammen aus `e2e/data/licenses.ts`.

Die Preview liefert einen Build aus; baue sie daher neu, um Änderungen am Quellcode zu sehen.

## Entwicklung mit Cloudflare

`bun run dev` startet den Dev-Server mit Hot Reload unter http://localhost:3000. Seine Bindings `DB`, `CACHE`, `MEDIA` und `BUNDLES` verbinden sich mit den entfernten Preview-Ressourcen, daher landen Schreibvorgänge aus der Entwicklung in der Preview-Datenbank.

```sh
bunx wrangler login
cp .env.example .env.development
bun run db:migrate:development
bun run dev
```

1. Melde dich mit Wrangler bei Cloudflare an.
2. Fülle `.env.development` wie unter [Umgebungsvariablen](/docs/getting-started/environment-variables) beschrieben aus, mit `POLAR_SERVER=sandbox`.
3. Lege mit deinem eigenen Cloudflare-Konto die D1-Datenbank, den KV-Namespace und die R2-Buckets an und ersetze dann die IDs und Bucket-Namen für `development` und `preview` in `wrangler.jsonc`; die eingecheckten Werte gehören zum bestehenden Deployment. Siehe [Eine Preview deployen](/docs/getting-started/deploy-preview).
4. Wende die Migrationen an und starte den Server.

Die Registrierung per E-Mail benötigt eine funktionierende Resend-Konfiguration, da Konten ihre E-Mail-Adresse vor der Anmeldung bestätigen müssen. Für die Entwicklung gibt es keinen Admin-Seed: Registriere dich, bestätige die Adresse und setze dann mit `bun run db:studio:development` die `role` deines Benutzers auf `admin`.
