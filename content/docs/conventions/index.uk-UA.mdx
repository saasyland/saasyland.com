Ці сторінки — стандарт коду цього репозиторію. Вони описують, як код пишуть тут, а не як його можна було б написати, і кожне правило називає файли, які йому відповідають. Більшість правил забезпечує команда: `bun run check` (форматування, лінтинг, типи, переклади та структура документації), `bun run test:coverage` (поріг 100%) або набір наскрізних тестів. Решту перевіряють під час рев’ю, і кожна сторінка вказує, які саме.

Якщо ви не знаєте, як щось написати, знайдіть найближчий наявний приклад того самого типу, прочитайте його й повторіть його форму. Послідовність цінніша за локально кращу ідею: другий спосіб зробити те саме змушує кожного наступного читача, людину чи агента, вивчати обидва.

## Еталонна реалізація

Функціональність курсів — найновіший код у репозиторії й зразок для наслідування. Вона охоплює модуль таблиці, публічні й адміністративні маршрути, форми, діалоги, таблицю даних, скелетони та тести.

| Тип                               | Звідки копіювати                                                       |
| --------------------------------- | ---------------------------------------------------------------------- |
| Модуль таблиці                    | `src/modules/course/`, а поруч `chapter`, `lesson` і `video`           |
| Читання з опціями запиту          | `src/modules/course/use-cases/get-course-editor.ts`                    |
| Посторінковий список для таблиці  | `src/modules/course/use-cases/get-courses.ts`                          |
| Мутація з опціями мутації         | `src/modules/course/use-cases/update-course.ts`                        |
| Маршрут макета                    | `src/routes/admin.courses.tsx`                                         |
| Маршрут сторінки з таблицею даних | `src/routes/admin.courses.index.tsx`                                   |
| Маршрут сторінки з параметром     | `src/routes/admin.courses.$courseId.tsx`                               |
| Форма                             | `src/presentation/components/custom/admin/courses/course-form.tsx`     |

| Браузерні тести                   | `e2e/specs/course-admin.spec.ts`                                       |

## Правила без винятків

Порушення будь-якого з них означає, що зміну відхилять, хоч би що ще вона робила добре.

1. Жодних коментарів у коді, тестах, скриптах, конфігурації чи CSS. Див. [Стиль коду](/docs/conventions/code-style).
2. Жодних `oxlint-disable`, `eslint-disable`, `@ts-expect-error`, `@ts-ignore`, приведень `as` чи `any`, щоб обійти правило. Виправляйте причину.
3. Жодних багаторядкових тернарних операторів, жодного `?? undefined` і жодних літералів `null`.
4. Статуси, види, тарифи, ролі та інші доменні значення — це іменовані константи, а не повторювані рядкові літерали, і в тестах також.
5. Папка в `src/modules` існує лише для таблиці бази даних. Див. [Модулі](/docs/conventions/modules).
6. Кожен рядок, який бачить користувач, існує в усіх дев’яти локалях, як і кожна сторінка документації. Числа на сайті вимірюються або оголошуються один раз у `src/data`, а не вписуються вручну. Див. [Переклади та контент](/docs/conventions/translations).
7. Покриття залишається на рівні 100% для рядків, інструкцій, функцій і гілок. Див. [Тестування](/docs/conventions/testing).
8. Зміна оновлює README, документацію й тексти сайту, які вона робить неточними, у тому самому pull request.
9. Коміти й pull request не містять жодної атрибуції ШІ та трейлера `Co-Authored-By`. Див. [Git і pull request](/docs/conventions/git-workflow).

## Критерії готовності

Зміна готова, коли ці команди проходять у такому порядку в гілці, яку ви збираєтеся надіслати:

```sh
bun run check
bun run test:coverage
bun run build:test
bun run test:e2e:pr
```

`check` і тести не перевіряють збірку Cloudflare: одного разу оновлення залежності пройшло обидва, хоча продакшн-збірка була зламана. Запускайте `build:test` для кожної зміни, а набір браузерних тестів — для всього, що не є документацією. Перед комітом перегляньте власний diff: чи немає коментарів, рядкових літералів, які мають бути константами, і текстів або документації, які зміна зробила хибними.

- [Стиль коду](/docs/conventions/code-style): що забезпечують форматер, лінтер і компілятор, а також заборони, яких вони перевірити не можуть.
- [Файли та іменування](/docs/conventions/files-and-naming): де лежить кожен тип файлів і як він називається.
- [Модулі](/docs/conventions/modules): будова модуля таблиці.
- [Серверні функції та помилки](/docs/conventions/server-functions): middleware, дозволи, валідація та коди помилок.
- [Отримання даних і кешування](/docs/conventions/data-fetching): опції запитів, ключі, актуальність та інвалідація.
- [Файли маршрутів](/docs/conventions/routes): єдина форма, яку має кожен файл маршруту.
- [Компоненти та стилізація](/docs/conventions/components): композиція, доступ до даних, імена класів і провайдери.
- [Форми та таблиці](/docs/conventions/forms-and-tables): TanStack Form із полями shadcn і єдиний `DataTable`.
- [Переклади та контент](/docs/conventions/translations): простори імен, дев’ять локалей, документація та згенеровані числа.
- [Доступність](/docs/conventions/accessibility): WCAG 2.2 AA і перевірки axe, які це гарантують.
- [Продуктивність](/docs/conventions/performance): виміряні правила, що зберігають сторінки швидкими.
- [Тестування](/docs/conventions/testing): тестові проєкти, іменування та поріг покриття.
- [Залежності](/docs/conventions/dependencies): найновіші версії та патчі для помилок в upstream.
- [Git і pull request](/docs/conventions/git-workflow): коміти, гілки, pull request і те, що вони мають оновлювати.
