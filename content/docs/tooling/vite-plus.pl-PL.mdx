Vite+ (`vite-plus`, polecenie `vp`) łączy Vite, Vitest, oxlint i oxfmt w jednym CLI, a `vite.config.ts` konfiguruje je wszystkie. `package.json` nadpisuje `vite` pakietem `@voidzero-dev/vite-plus-core` i przypina `vitest` do wersji 5.1.0. `vite-plus` również jest przypięty do dokładnej wersji; aktualizuj wszystkie trzy razem przez `vp migrate`, a nie `bun update`. Skrypty pakietu wywołują `vp`; poza nimi używaj globalnego CLI Vite+ lub `bunx vp`.

| Polecenie         | Używane przez                                     |
| ----------------- | ------------------------------------------------- |
| `vp dev`          | `dev`                                             |
| `vp build --mode` | `build:preview`, `build:production`, `build:test` |
| `vp preview`      | `start`, `start:test`                             |
| `vp test`         | `test` i skrypty Vitest `test:*`                  |
| `vp lint`         | `lint`                                            |
| `vp fmt`          | `format`, `format:check`                          |
| `vp check`        | `check`, `check:fix`                              |
| `vp staged`       | `check:pre-commit`                                |
| `vp config`       | `prepare`, który instaluje hooki Git              |

## Konfiguracja

`vite.config.ts` sam nie wymienia żadnego pluginu: leniwie ładuje pluginy, które każdy obszar deklaruje w `src/data/<area>.vite.ts`, a `src/data/vite.entries.ts` łączy i `vitePlugins` w `src/data/vite.ts` ustawia według ich `order` (zobacz [Co dodają obszary](/docs/architecture/platform-layer#what-the-areas-add)). Pod Vitest ładują się tylko wpisy oznaczone `vitest`, czyli `repositoryFacts()` i `@vitejs/plugin-react`; w pozostałych przypadkach zestaw pluginów wygląda następująco:

- `@cloudflare/vite-plugin`: uruchamia Workera w środowisku SSR, utrwala stan lokalny (w `.wrangler/test` dla trybu `test`) i używa zdalnych bindingów dla `development`.
- `fumadocs-mdx`: kompiluje kolekcje dokumentacji i bloga.
- `saasyland:fumadocs-bundled`: zostawia `fumadocs-core` i `@fumadocs/base-ui` w bundlu serwera (`resolve.noExternal`).
- `repositoryFacts` (`scripts/repository-facts.ts`): udostępnia moduł `virtual:repository-facts`: liczby, wersje i ustawienia narzędzi odczytywane z repozytorium podczas budowania i wyświetlane na stronie głównej oraz w dokumentacji; zobacz [Tłumaczenia i treści](/docs/conventions/translations).
- `unused-primitives` (`scripts/unused-primitives.ts`): przed Tailwindem pomija klasy każdego prymitywu shadcn, którego nie importuje żaden kod źródłowy aplikacji; zobacz [Komponenty shadcn](/docs/ui/shadcn-components).
- `@tailwindcss/vite`: Tailwind CSS 4.
- `tanstackStart`: routing, dzielenie kodu i prerendering stron publicznych.
- `@vitejs/plugin-react`.
- `deployedWorker` (`scripts/deployed-worker.ts`): po prerenderingu buduje Workera od nowa bez wyrenderowanego MDX i bez tłumaczeń landingu i stron prawnych; zobacz [Cloudflare Workers](/docs/integrations/cloudflare-workers).
- `saasyland:polar-sdk-optional-peers`: oznacza jako zewnętrzne nieinstalowane opcjonalne zależności peer pakietu `@polar-sh/sdk` (`build.rolldownOptions.external`); zobacz [Zależności](/docs/conventions/dependencies).

Serwer deweloperski nasłuchuje pod adresem `localhost:3000` i kończy się błędem, jeśli port jest zajęty. `resolve.tsconfigPaths` zapewnia alias importu `~/`. Ten sam plik zawiera sekcje `fmt`, `lint`, `staged` i `test`; zobacz [Lint i formatowanie](/docs/tooling/lint-format) oraz [Testy](/docs/tooling/testing).

`vp preview`, które uruchamiają `start`, `start:test` i prerendering, nasłuchuje pod adresem `127.0.0.1:3000`, czyli `LOCAL_SERVER` z `src/data/local-server.ts`, i ten sam adres otwiera Playwright; prerendering używa tego adresu z wolnym portem. Z `localhost` serwer nasłuchiwałby tylko pod pierwszym adresem, na który Node rozwiązuje tę nazwę, czyli `::1`, a każdy klient próbowałby najpierw `::1`, potem `127.0.0.1` i dawał każdemu adresowi tylko chwilę na odpowiedź: na obciążonej maszynie ta chwila mija, zanim klient zauważy połączenie, klient porzuca `::1`, pod `127.0.0.1` nic nie znajduje, a prerendering kończy się błędami `ETIMEDOUT ::1` i `ECONNREFUSED 127.0.0.1`.

`src/data/polar.vite.ts` dodaje plugin, którego hook `config` wymienia w `build.rolldownOptions.external` opcjonalne zależności peer pakietu `@polar-sh/sdk` (OpenTelemetry i `ioredis`). Nie są zainstalowane, a moduł, który je importuje, jest usuwany z Workera przez tree-shaking.

## Hooki Git

`bun install` uruchamia `prepare`, który wywołuje `vp config --no-agent`, aby zainstalować dyspozytor hooków dla `.vite-hooks/`. `pre-commit` uruchamia `bun run check:pre-commit`, a `prepare-commit-msg` uruchamia `scripts/commit-msg.ts` (zobacz [Konwencjonalne commity](/docs/tooling/conventional-commits)). `vp hooks status` pokazuje, czy hooki są aktywne w danym klonie repozytorium.

Preferuj skrypty pakietu; `vp` wywołuj bezpośrednio przy uruchomieniach punktowych, np. przy formatowaniu lub lintowaniu konkretnych ścieżek.
