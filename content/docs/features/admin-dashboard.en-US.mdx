## Admin shell

`src/routes/admin.tsx` guards every admin page with `requireAdmin` and preloads the shared admin namespaces. The layout renders:

- `AdminSidebar`, `AdminBreadcrumbs` and `AdminCommandPalette` (opened with ⌘K), all built from `ADMIN_NAVIGATION` in `src/data/navigation.ts`, which groups the entries the areas contribute, each with its icon: Overview (Dashboard, Analytics), Offerings (Products, Pricing models), Content (Blog, Courses, Videos, Landing page) and Administration (User management, Payments, Settings).
- The user widget in the sidebar footer, with a link to settings and `SignOutButton`.

## Dashboard

`/admin` (`src/routes/admin.index.tsx`) preloads `getUsersQuery` and, through their `prefetch`, the query of every dashboard statistic and of every panel that reads data in its loader, and composes the widgets of `src/presentation/components/custom/admin/dashboard` with the panels the areas add:

- `DashboardActions`: a link for each entry of `ADMIN_DASHBOARD_ACTIONS` by its `order`, such as **Add product** from `src/data/products.navigation.ts`, labelled by `navigation.products.json`.
- `DashboardStats` (live): the statistics of `ADMIN_DASHBOARD_STATS`, the entries of `src/data/<area>.dashboard.ts` placed as `DASHBOARD_PLACEMENT.STAT`, by their `order`: the number of users and the users waiting for email verification from `src/data/auth.dashboard.ts`, and the number of products from `src/data/products.dashboard.ts`, each labelled by its area's `dashboard.<area>.json`.
- The panels of `ADMIN_DASHBOARD_PANELS`, the entries placed as `DASHBOARD_PLACEMENT.PANEL`, by their `order`, each with the skeleton that `AdminDashboardPending` shows for it:
  - the licence area adds `UnlicensedOrders` (live) in `src/data/license.dashboard.ts`: the paid licence orders that have no licence, each linked to the order in Polar, or a line saying there are none, labelled by `dashboard.license.json` (see [Licences](/docs/features/licences#orders-that-match-no-account));
  - the payments area adds `RevenueChart` (demo) in `src/data/payments.dashboard.ts`, a static SVG with fixed axes labelled by `dashboard.payments.json`; the range buttons do nothing.
- A users card (live): the newest users with search and status filters, <RepositoryFact name="adminPreviewPageSize" /> rows per page. Each name links to the user's profile, where the actions are.

```tsx
<DataTable
  columns={dashboardUserColumns}
  data={users.rows}
  filters={[
    { columnId: "user", placeholder: t("users.search"), type: "search" },
    {
      columnId: "status",
      label: t("users.filters.status"),
      options: USER_STATUSES.map((status) => ({ label: t(`users.table.status.${status}`), value: status })),
      type: "select",
    },
  ]}
  options={{ initialState: { pagination: ADMIN_DASHBOARD_PREVIEW_PAGINATION }, selectable: true }}
/>
```

The table works on the first page of `getUsersQuery` (<RepositoryFact name="defaultPageSize" /> users) in the browser. **View all** links to `/admin/users`. **Add product**, the products area's entry in `ADMIN_DASHBOARD_ACTIONS`, links to `/admin/products/create`.
