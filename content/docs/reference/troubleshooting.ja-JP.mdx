## データベース

**`bun run dev` で `no such table` が発生する。** `development` 環境は、リモートのプレビュー用 D1 データベースを使います。`bun run db:migrate:development` で、そのデータベースにマイグレーションを適用してください。`bun run db:migrate:local` がマイグレーションするのは、`bun run dev` が使わないローカルのデータベースだけです。

**Playwright で `no such table` が発生する。** ブラウザテストは専用のローカルデータベースを使います。`bun run db:reset:test` を実行するか、Playwright にアプリを起動させてください。後者の場合はこのコマンドが自動で実行されます。

**Vitest のテーブルが古い。** D1 のモックは、起動時に `src/integrations/drizzle-orm/migrations` 内のすべての SQL ファイルを適用します。スキーマを変更したら、`bun run db:generate` でマイグレーションを生成してください。

## 開発サーバー

**開発サーバーが起動しない。** 開発サーバーは `strictPort` を指定して `localhost:3000` で待ち受けるため、ポートが使用中だと起動に失敗します。そのポートを使っている他のプロセスを停止してください。

**サインインや OAuth が失敗する。** 環境ファイルの `AUTH_SECRET` と OAuth クライアントの認証情報を確認してください。また、プロバイダーのコールバック URL が、使用しているホストの <RepositoryFact name="oauthCallbackPath" /> を指していることも確認します。Better Auth は、ビルドモードごとに設定されたホストだけを受け付けます。development では `localhost:3000` と `127.0.0.1:3000` です。

**Worker の型にバインディングやシークレットが含まれていない。** `wrangler.jsonc` を変更した後に `bun run cf-typegen` を実行してください。すべてのバインディングと `secrets.required` のすべてのシークレットに型が付きます。`test` だけが設定する変数のように Wrangler が導き出せない値は、そのエリアの `src/types/<area>.d.ts` で宣言します。

**カスタムの `text-*` クラスがマージ時に消える。** `cn` は、`src/lib/cn.config.ts` から生成されたテーブルに依存しています。このテーブルは `bun run dev`、`bun run check`、各ビルドで再生成されます。`.source/cn-tables.ts` が存在しない場合は、`bun run generate:cn` を実行してください。

## 翻訳

**`No messages/<locale>/<namespace>.json` と表示される。** ルートが、そのロケールにファイルが存在しない名前空間を宣言しています。すべてのロケールでファイルを作成してください。

**キーがパスのまま表示される、または `check:i18n` がキーの欠落を報告する。** そのキーがいずれかのロケールで欠けているか、コンポーネントが `useTranslations` 呼び出しのスコープ外でキーを読み取っています。コンポーネントごとに `useTranslations` を 1 回だけ使い、`bun run check:i18n` を実行してください。

## ドキュメント

**ドキュメントページが 404 を返す。** ファイル名を `<page>.<locale>.mdx` にし、フォルダーの `meta.<locale>.json` の `pages` に列挙する必要があります。`bun run content` を実行して `.source` を再生成してください。

**`check-content.ts` が失敗する。** このスクリプトは、すべてのロケールを en-US と比較します。`Changed code examples` は、コードブロックが英語版と異なることを意味します。コードブロックは同一でなければなりません。`Untranslated English paragraph` は、段落が翻訳されずにコピーされたことを意味します。`Missing <file>` は、ロケールのファイルが存在しないことを意味します。`leaves out … from the English page` と `adds …, which the English page does not have` は、翻訳がインラインコード、コンポーネントやその props、ほかのページへのリンクを落としたり加えたりしたことを意味します。英語のページのとおりに写してください。`has … table rows where the English page has …` は、表の行が減ったか増えたことを意味します。`links to … instead of …` は、サイトがリダイレクトする内部リンク、またはロケールを含む内部リンクがあることを意味します。メッセージが示すパスに書き換えてください。

**`check-message-formats.ts` が失敗する。** `changed the path or command …` は、翻訳が英語のメッセージのファイルパスやコマンドを変えたことを意味します。そのまま残すか、`REPOSITORY_FACTS` から ICU 引数として渡してください。`unexpected Markdown code` は、翻訳がバッククォートを加えたことを意味します。メッセージはバッククォートをそのまま表示します。

## テストとデプロイ

**`test:coverage` が失敗する。** カバレッジは、行、ステートメント、関数、分岐のすべてで <RepositoryFact name="coverageThreshold" unit="percent" /> である必要があります。カバーされていない行は、`coverage/` のレポートで確認できます。

**デプロイが `verify-bindings.ts` で止まる。** `wrangler.jsonc` の対象環境に `development` 環境が宣言しているバインディング（`DB`、`CACHE`、`MEDIA`、`BUNDLES`）のいずれかがないか、D1 や KV のプレースホルダー ID が残っているか、本番の場合はプレビューとリソースを共有しています。Cloudflare でリソースを作成し、ID を置き換えてください。

**デプロイが `polar:verify` で止まる。** Polar がコードと一致していません。`.env.<environment>` のキーがないか誤った Polar サービスを指している、トークンが拒否されたかスコープが足りない、あるいは商品、価格、ライセンスキー、地域割引、Webhook のいずれかがコードの前提と異なっています。エラーには各問題が列挙され、各メッセージの意味は [Polar の設定](/docs/getting-started/polar-setup)で説明しています。`bun run polar:verify:<environment>` でチェックを再実行できます。

**デプロイが `prepare-deploy-secrets.ts` で止まる。** 環境の `secrets.required` に列挙されたキーが、`.env.<environment>` にないか空になっています。エラーにそのキーが表示されます。

**デプロイが `verify-deployment.ts` で止まる。** Worker はデプロイされましたが、確認対象のパスが期待されるコンテンツタイプで `200` を返さなかったか、サインインが本来のとおりにプロバイダーへ届きませんでした。エラーには各リクエストと問題点が表示されます。その URL を開き、Cloudflare で Worker のログを確認してください。`client_id is not a Google OAuth client ID.` で終わる行は、Worker がそのプロバイダーの正しいクライアント ID を持っていないことを意味します。次の項目を参照してください。`bun scripts/verify-deployment.ts <preview|production>` で確認をもう一度実行できます。

**Google が `Error 401: invalid_client` と `The OAuth client was not found.` を返す。** Worker が Google の知らないクライアント ID を送っています。たとえば、`.env.<environment>` に残っていたプレースホルダーが、デプロイによって `AUTH_GOOGLE_CLIENT_ID` シークレットとしてアップロードされた場合です。次の手順で修正します。

1. Google Cloud コンソールで **Google Auth Platform → Clients** を開き、種類が **Web application** のクライアントを作成するか、使いたいクライアントを開きます。そのクライアント ID は `.apps.googleusercontent.com` で終わります。
2. デプロイ先のすべてのホストについて、**Authorized JavaScript origins** に `https://<host>` を、**Authorized redirect URIs** に <RepositoryFact name="googleCallbackUrl" /> を追加します。Google が反映するまで数分かかることがあります。
3. **Google Auth Platform → Audience** で **Publish app** を選び、テストユーザーだけでなくすべての Google アカウントがサインインできるようにします。
4. クライアント ID とシークレットを `.env.<environment>` の `AUTH_GOOGLE_CLIENT_ID` と `AUTH_GOOGLE_CLIENT_SECRET` に設定し、`bun run deploy:<environment>` を実行します。このスクリプトが 2 つの Worker シークレットをアップロードし、サインインをもう一度確認します。

**プリレンダリングのビルドが失敗する。** ビルドの出力に、最初に失敗した URL が表示されます。`bun run dev` でそのページを開き、エラーを確認してください。
