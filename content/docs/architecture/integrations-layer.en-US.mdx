---

Each third-party library or service that needs setup owns one folder under `src/integrations`. Files are named `<prefix>.<concern>.ts`, where the prefix is the vendor's short name.

| Folder          | Files                                                                                                                                        | Responsibility                                                                     |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `better-auth`   | `auth.server`, `auth.client`, `auth.access`, `auth.middleware`, `auth.routes`, `auth.session`, `auth.errors`, `auth.zod`, `auth.constraints` | Auth configuration, roles, server function middleware, route guards, session query |
| `drizzle-orm`   | `drizzle.config`, `drizzle.database`, `drizzle.schemas`, `migrations/`                                                                       | The D1 client, the schema registry and SQL migrations                              |
| `fumadocs`      | `fumadocs.config`, `fumadocs.source`, `fumadocs.docs`, `fumadocs.search`, `fumadocs.i18n`                                                    | MDX collections for docs and blog, page loading and search                         |
| `motion`        | `motion.features`, `motion.tokens`                                                                                                           | The lazily loaded Motion feature bundle and shared transitions                     |
| `polar`         | `polar.config`, `polar.constants`                                                                                                            | The Polar SDK client and the product IDs offered at checkout                       |
| `resend`        | `resend.config`, `resend.utils`                                                                                                              | The Resend client and `sendEmail`                                                  |
| `tanstack-form` | `form.fields`                                                                                                                                | Field types and `fieldErrorMessage` for TanStack Form                              |
| `use-intl`      | `i18n.config`, `i18n.messages`, `i18n.middleware`, `i18n.paths`, `i18n.utils`                                                                | Locales, message loading, locale URLs and cookies                                  |

## What is not an integration

- The GitHub star count is a server function in `src/lib/github.ts`, cached in KV.
- Rate limiting is `src/lib/rate-limit.ts`, backed by the `rate_limit` table.
- Cloudflare bindings need no adapter. Server code reads them from `env` in `cloudflare:workers`.

## Business logic stays in modules

An integration configures a vendor. Decisions about application data belong to the module that owns the table:

- The Polar plugin in `auth.server.ts` verifies webhook signatures with `POLAR_WEBHOOK_SECRET` and hands the events to `licenseWebhookHandlers` in `src/modules/license/license.webhooks.ts`, which call the license use cases.
- Better Auth email hooks call `sendVerifyEmail`, `sendResetPasswordEmail` and `sendChangeEmailConfirmationEmail` from the verification and account modules.
- A use case sends email by loading the template's namespace, rendering the template and calling `sendEmail`:

```ts
const locale = getCurrentLocale()
const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotencyKey: `verify-email/${token}`,
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```
