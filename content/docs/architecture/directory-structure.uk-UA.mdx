## Правила розміщення

- **Файли й папки називаються в kebab-case.** Тести лежать у сусідній папці `__test__`.
- **Маршрути лише компонують.** Файл маршруту визначає компонент сторінки або макета, `NAMESPACE` чи `NAMESPACES`, loader-функцію та `head`. Він не містить віджетів, діалогів чи визначень колонок.
- **Модулі — це таблиці бази даних.** Створюйте `src/modules/<name>` лише для справжньої таблиці. Серверна функція, яка не працює з таблицею, потрапляє в `src/lib` (наприклад, `src/lib/github.ts`) або, якщо її використовує один маршрут, у файл цього маршруту.
- **Спільні компоненти лежать пласко.** Компонент, який використовується в кількох розділах, — це окремий файл безпосередньо в `presentation/components/custom`.
- **Папки розділів і сторінок.** Компоненти одного розділу лежать в `admin/`, `app/`, `auth/`, `blog/`, `courses/`, `landing-page/` або `settings/`, де лежать картки облікового запису, спільні для `/app/settings` і `/admin/settings`. Сторінки адмін-панелі мають власну папку, як-от `admin/users/`. Лендинг поділено на `sections/` (по одному файлу на кожну секцію сторінки) і `components/` (частини, спільні для секцій).
- **Один віджет, діалог, форма або набір колонок на файл.** Не розділяйте компонент на обгортку та файл `-content`.
- **Жодних вкладених допоміжних папок.** Папки компонентів ніколи не містять підпапок `components/`, `constants/`, `hooks/`, `lib/` або `types/`, і жоден допоміжний файл `.ts` не лежить поруч із компонентом. Константа, яку використовує один компонент, залишається у файлі цього компонента.
- **Спільні дані — у `src/data`.** Приклади: `MARKETING_SECTION_IDS` і варіанти вибору для CLI. Там же кожен розділ оголошує свої пункти меню, статистику панелі й декларації дозволів — у `<area>.navigation.ts`, `<area>.dashboard.ts` і `<area>.access.ts`, які об’єднують barrel-файли `*.entries.ts` (див. [Шляхи та навігація](/docs/conventions/routes#paths-and-navigation)). Там же розділи оголошують, що вони додають до платформи: обробники Worker, кореневі компоненти, плагіни Vite і перевірки живого сайту (див. [Що додають розділи](/docs/architecture/platform-layer#what-the-areas-add)).
- **Шляхи кожного розділу — у `src/areas/<area>.shared.ts`.** Цей файл завантажує кожне середовище виконання: браузер, Worker, скрипти Bun, Playwright і `vite.config.ts`. Тому він містить лише константи й імпортує за відносними шляхами, а `src/routes.ts` об’єднує шляхи всіх розділів (див. [Шляхи та навігація](/docs/conventions/routes#paths-and-navigation)).
- **Згенеровані файли не редагуються вручну.** Плагін роутера записує `src/routeTree.gen.ts`, `bun run cf-typegen` записує `src/types/worker-configuration.d.ts`, а `bun run content` і `bun run generate:cn` записують `.source/`.
