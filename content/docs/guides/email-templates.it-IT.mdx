Un'email ha tre parti: un modello in `src/presentation/emails/`, un namespace di messaggi in `messages/<locale>/emails.<name>.json` e il caso d'uso che carica i messaggi, genera il modello e lo invia. Modelli: `verify-email`, `reset-password-email`, `change-email-confirmation-email`, `newsletter-confirmation-email` e `newsletter-notification-email`.

## Modello

Un modello contiene solo markup ed esporta il proprio namespace. Traduce con `createTranslator` di `use-intl` perché viene reso fuori dal contesto React. `src/presentation/emails/verify-email.tsx`:

```tsx
import type { JSX } from "react"

import { Body, Button, Container, Head, Heading, Html, Preview, Section, Tailwind, Text, pixelBasedPreset } from "react-email"
import { createTranslator } from "use-intl"

import type { SupportedLocale } from "~/src/integrations/use-intl/i18n.config"

import type emailMessages from "~/messages/en-US/emails.verify-email.json"

export const VERIFY_EMAIL_NAMESPACE = "emails.verify-email"

const TAILWIND_CONFIG = { presets: [pixelBasedPreset] }

interface VerifyEmailProps {
  readonly locale: SupportedLocale
  readonly messages: typeof emailMessages
  readonly name: string
  readonly verifyUrl: string
}

export const VerifyEmail = ({ messages, locale, name, verifyUrl }: Readonly<VerifyEmailProps>): JSX.Element => {
  const t = createTranslator({ locale, messages: { emails: { "verify-email": messages } }, namespace: "emails.verify-email" })

  return (
    <Html lang={locale}>
      <Tailwind config={TAILWIND_CONFIG}>
        <Head />
        <Body className="font-sans">
          <Preview>{t("preview")}</Preview>
          <Container className="mx-auto px-5 py-10">
            <Section>
              <Heading className="m-0 mb-4 text-2xl font-bold">{t("heading")}</Heading>
              <Text className="m-0 mb-6 text-base text-neutral-600">{t("body", { name })}</Text>
              <Button
                href={verifyUrl}
                className="box-border rounded-md bg-neutral-900 px-5 py-3 text-center text-base text-white no-underline"
              >
                {t("button")}
              </Button>
              <Text className="mt-6 text-sm text-neutral-500">{t("footer")}</Text>
            </Section>
          </Container>
        </Body>
      </Tailwind>
    </Html>
  )
}
```

## Messaggi

Crea `messages/<locale>/emails.<name>.json` in tutte e nove le lingue. Includi una chiave `subject`; il caso d'uso la traduce separatamente dal corpo.

```json
{
  "subject": "Verify your email address",
  "preview": "Verify your email for SaaSy Land",
  "heading": "Verify your email",
  "body": "Hi {name}, thanks for signing up. Confirm your email address to finish setting up your account.",
  "button": "Verify email",
  "footer": "If you did not create an account, you can safely ignore this email."
}
```

Le route non precaricano mai i namespace delle email; li carica sul server il caso d'uso che invia il messaggio.

## Invio

Il caso d'uso riceve la lingua, carica i messaggi, costruisce link assoluti con `localizePathname` e chiama `sendEmail`. `src/modules/verification/use-cases/send-verify-email.ts`:

```ts
export const sendVerifyEmail = async ({
  locale,
  token,
  user,
}: {
  locale: SupportedLocale
  token: string
  user: { email: string; name: string }
}): Promise<void> => {
  const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
  const verifyUrl = new URL(localizePathname({ locale, pathname: ROUTES.VERIFY_EMAIL }), getRequest().url)
  verifyUrl.searchParams.set("token", token)

  await sendEmail({
    idempotencyKey: `verify-email/${token}`,
    react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
    subject: createTranslator({ locale, messages })("subject"),
    to: user.email,
  })
}
```

`sendEmail` (`src/integrations/resend/resend.utils.ts`) invia tramite Resend da `RESEND_EMAIL_FROM` a meno che non venga indicato `from`, passa la chiave di idempotenza in modo che un nuovo tentativo non invii mai due volte e genera un errore quando Resend ne restituisce uno.

## Chi invia cosa

- Gli hook di Better Auth in `src/integrations/better-auth/auth.server.ts` chiamano i casi d'uso: `sendVerifyEmail` per `emailVerification.sendVerificationEmail` e per le registrazioni ripetute di account non verificati, `sendResetPasswordEmail` per `emailAndPassword.sendResetPassword` e `sendChangeEmailConfirmationEmail` per `user.changeEmail`.
- Le richieste di Better Auth arrivano su `/api/auth` senza prefisso di lingua, quindi gli hook ricavano la lingua dell'email dal `callbackURL` del flusso, un percorso di pagina localizzato, con `extractLocaleFromCallbackURL` o `extractLocaleFromPath` di `src/integrations/use-intl/i18n.paths.ts`. L'inglese è la lingua di riserva.
- I casi d'uso della newsletter inviano da soli le email di conferma e di notifica, ad esempio `subscribeToNewsletter`.

## Aggiungi un'email

1. Aggiungi il modello in `src/presentation/emails/<name>.tsx` con il suo `<NAME>_NAMESPACE` esportato.
2. Aggiungi `messages/<locale>/emails.<name>.json` in tutte e nove le lingue.
3. Invialo dal caso d'uso a cui appartiene l'azione, con una chiave di idempotenza derivata dal token o dal record che lo attiva.
4. Testa il modello in `src/presentation/emails/__test__/` e il caso d'uso con `sendEmail` simulato.

Credenziali Resend: `RESEND_API_KEY` e `RESEND_EMAIL_FROM`. I test non contattano mai Resend.
