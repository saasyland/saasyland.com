| Tarea                                                        | Comando                  |
| ------------------------------------------------------------ | ------------------------ |
| Iniciar el servidor de desarrollo                            | `bun run dev`            |
| Comprobar el formato, el lint, los tipos y las traducciones  | `bun run check`          |
| Ejecutar todos los proyectos de Vitest                       | `bun run test`           |
| Ejecutar el umbral de cobertura                              | `bun run test:coverage`  |
| Ejecutar la prueba smoke en el navegador                     | `bun run test:e2e:smoke` |
| Ejecutar la suite de navegador en Chromium que ejecuta la CI | `bun run test:e2e:pr`    |
| Generar una migración                                        | `bun run db:generate`    |
| Compilar el Worker de preview                                | `bun run build`          |
| Servir la última compilación                                 | `bun run start`          |
| Desplegar la preview                                         | `bun run deploy:preview` |

Antes de abrir una pull request, ejecuta la secuencia de [Contribuir](/docs/project/contributing), con las specs que cubren tu cambio:

```sh
bun run check
bun run test:coverage
bun run build:test
bunx playwright test e2e/specs/<spec>.spec.ts --project=chromium
```

En local, Playwright recrea la base de datos de pruebas con `db:reset:test`, compila el Worker de pruebas y lo inicia en la dirección que indica `PLAYWRIGHT_BASE_URL` (`127.0.0.1:3000` si no está definida), salvo que ya haya un servidor que responda allí. Cada worktree usa su propio puerto del rango en el que confía la build de pruebas, y la ejecución se detiene cuando el servidor de su puerto pertenece a otro worktree: consulta [Ejecutar junto a otros worktrees](/docs/tooling/playwright#running-beside-other-worktrees).

Usa `bun run test`, no `bun test`, para que Vitest se ejecute con la configuración del proyecto. Los scripts que terminan con el nombre de un entorno, como `db:migrate:preview` o `deploy:production`, solo actúan sobre ese entorno.

Consulta [Scripts del proyecto](/docs/tooling/scripts) para ver la lista completa.
