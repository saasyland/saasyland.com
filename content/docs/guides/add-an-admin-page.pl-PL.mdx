---
title: "Dodawanie strony panelu administracyjnego"
description: "Zarejestruj trasę, pozycję w pasku bocznym, komunikaty i widżety nowej strony panelu administracyjnego."
---

Strony panelu administracyjnego to płaskie pliki tras pod layoutem `/admin` (`src/routes/admin.tsx`), który uruchamia `requireAdmin` w `beforeLoad` i renderuje pasek boczny, ścieżkę nawigacyjną oraz paletę poleceń. Poniższe kroki dodają stronę pod `/admin/reports`; pełnym, prawdziwym przykładem jest `src/routes/admin.orders.index.tsx`.

## 1. Dodaj ścieżkę

Zadeklaruj ścieżkę w `src/routes.ts`, w jej miejscu w porządku alfabetycznym. Od tej chwili `ROUTES` ją zawiera:

```ts
export const ADMIN_REPORTS = "/admin/reports"
```

Jeśli strona należy do funkcji, którą projekt może pominąć, dodaj też tę nazwę do `names` tej funkcji w `scripts/features.ts`, aby `bun run check:features` usuwało razem z funkcją ścieżkę i każdą pozycję, która ją wskazuje.

## 2. Utwórz plik trasy

Utwórz `src/routes/admin.reports.tsx`. Trasa definiuje tylko komponent strony, `NAMESPACE`, loader, `head` i `pendingComponent`; generator routera rejestruje plik w `src/routeTree.gen.ts`.

```tsx
import type { JSX } from "react"

import { createFileRoute } from "@tanstack/react-router"
import { useTranslations } from "use-intl/react"

import { loadPageMetadata, preloadNamespaces } from "~/src/integrations/use-intl/i18n.messages"
import { getCurrentLocale } from "~/src/integrations/use-intl/i18n.utils"

import { pageHead } from "~/src/lib/seo"

import { AdminPageHeader } from "~/src/presentation/components/custom/admin/admin-page-header"
import { AdminReportsPending } from "~/src/presentation/components/custom/admin/reports-pending"
import { ReportStats } from "~/src/presentation/components/custom/admin/reports/report-stats"

import * as ROUTES from "~/src/routes"

const ReportsPage = (): JSX.Element => {
  const t = useTranslations("pages.admin.reports")

  return (
    <div className="flex w-full flex-col space-y-8">
      <AdminPageHeader description={t("metadata.description")} title={t("metadata.title")} />

      <ReportStats />
    </div>
  )
}

const NAMESPACE = "pages.admin.reports"

export const Route = createFileRoute("/admin/reports")({
  component: ReportsPage,
  head: pageHead(ROUTES.ADMIN_REPORTS),
  loader: async ({ context }) => {
    const locale = getCurrentLocale()
    const [metadata] = await Promise.all([
      loadPageMetadata({ locale, namespace: NAMESPACE }),
      preloadNamespaces({ locale, namespaces: [NAMESPACE], queryClient: context.queryClient }),
    ])
    return { locale, metadata }
  },
  pendingComponent: AdminReportsPending,
  staticData: { namespaces: [NAMESPACE] },
})
```

Zapytania potrzebne stronie trafiają do tego samego `Promise.all`, np. `context.queryClient.query({ ...getUsersQuery, staleTime: "static" })` w `src/routes/admin.users.all.tsx`. `pageHead` buduje tytuł, opis, kanoniczny URL i odnośniki do innych wersji językowych na podstawie `metadata` z loadera. `AdminReportsPending` to własny szkielet strony, wyświetlany tylko wtedy, gdy nawigacja trwa dłużej niż <RepositoryFact name="navigationPendingMs" unit="millisecond" />. Zbuduj go w pliku szkieletów jej obszaru, tutaj w nowym `custom/admin/reports-pending.tsx`, z `AdminPageHeaderPending` z `admin-page-header.tsx` dla nagłówka i z bloków z `pending-blocks.tsx`, tak aby odwzorowywał układ strony. Szkielet layoutu panelu administracyjnego odczytuje go z trasy, więc pojawia się on także wtedy, gdy ktoś wchodzi na `/admin/reports` spoza panelu administracyjnego.

Zobacz [Szkielety ładowania](/docs/architecture/delivery-layer#loading-skeletons).

## 3. Dodaj pozycję w pasku bocznym

Dodaj pozycję do `items` jej grupy paska bocznego w `ADMIN_NAVIGATION` (`src/data/navigation.ts`), w miejscu, w którym ma się pojawić, na przykład za pozycją Pulpit w grupie przeglądu. Pozycja wskazuje swoją ikonę z `lucide-react`, pełny klucz swojej etykiety i swoją ścieżkę:

```ts
{ icon: FileText, label: "navigation.reports.admin.reports", to: ROUTES.ADMIN_REPORTS },
```

Dodaj etykietę jako `admin.reports` do `messages/<locale>/navigation.reports.json`, w każdym języku. Nowa grupa wymaga też wartości w `ADMIN_NAVIGATION_GROUP`, miejsca wśród grup `ADMIN_NAVIGATION` i `groups.<group>` w `pages.admin.sidebar`. Pasek boczny, ścieżka nawigacyjna i paleta poleceń ⌘K odczytują `ADMIN_NAVIGATION` (`src/data/navigation.ts`), więc strona pojawia się we wszystkich trzech miejscach. Strona główna liczy ją wśród sekcji panelu administracyjnego, a pasek panelu administracyjnego w filmie `app-tour` na stronie głównej pokazuje ją po ponownym wyrenderowaniu filmu (zobacz `remotion/README.md`). Trzeci segment adresu, np. `/admin/reports/create`, pokazuje element ścieżki nawigacyjnej, gdy `breadcrumbs` pozycji wskazuje dla niego etykietę, np. `breadcrumbs: { create: "navigation.reports.breadcrumbs.create" }`, a jeśli nie wskazuje, trzeciego elementu nie ma.

## 4. Dodaj komunikaty strony

Utwórz `messages/<locale>/pages.admin.reports.json` w każdym języku. `metadata` jest wymagane, bo loader odczytuje je na potrzeby nagłówka dokumentu:

```json
{
  "metadata": {
    "title": "Reports",
    "description": "Revenue and usage reports."
  }
}
```

## 5. Dodaj widżety

Umieść każdy widżet, okno dialogowe, formularz i zestaw kolumn tabeli w osobnym pliku w `src/presentation/components/custom/admin/reports/`, np. `report-stats.tsx` lub `report-columns.tsx`. Widżety wywołują `useTranslations("pages.admin.reports")` i same odczytują swoje dane przez `useSuspenseQuery`; strona nie przekazuje im etykiet ani danych. Tabele używają `DataGrid`; zobacz [Dodawanie siatki danych](/docs/guides/add-a-data-table).

## 6. Zabezpiecz i przetestuj

- Guard layoutu kontroluje dostęp do strony. Każda funkcja serwerowa wywoływana przez stronę nadal wymaga `authorized(permission)`; zobacz [Role i uprawnienia](/docs/guides/roles-and-permissions).
- `/admin` jest wyłączone z prerenderingu.
- Dodaj testy tras funkcji w `src/routes/__test__/admin-<feature>-routes.component.test.tsx` i `admin-<feature>-loaders.test.ts`, testy widżetów w `src/presentation/components/custom/admin/__test__/` i stronę w `e2e/data/<feature>.pages.ts`, a następnie uruchom `bun run check:i18n`, `bun run test:coverage` i `bun run check:features`.
