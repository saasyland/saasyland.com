- O Better Auth tira o caminho base das constantes de rotas. `auth.server.ts` e `auth.client.ts` definem `basePath` como `ROUTES.API_AUTH_BASE`, o caminho que `src/routes/api/auth.$.ts` atende, em vez de depender do padrão do Better Auth, e testes conferem o servidor, o cliente do navegador e a rota com ele; todas as URLs continuam as mesmas. A documentação mostra os caminhos de callback do OAuth a partir das mesmas constantes. `disabledPaths` sai das entradas dos plugins de autenticação e da configuração do Better Auth, e `DISABLED_AUTH_PATHS` com ele: nenhuma área fecha um caminho via HTTP desde que o plugin do Polar deixou de adicionar o próprio checkout. Um teste de integração confere que o caminho do checkout do plugin do Polar responde 404, então adicionar `checkout()` de novo ao plugin faz a suíte falhar. Veja [Autenticação e segurança](/docs/integrations/better-auth).
