Саме в компонентах найлегше наростають шари, яких ніхто не просив. Наведені нижче правила зберігають кожен екран зрозумілим з одного файлу: ви відкриваєте компонент і бачите дані, які він читає, текст, який він показує, і класи, які він застосовує.

## Мінімум абстракцій

- **Один очевидний механізм на завдання.** Викликайте бібліотеку напряму: `toast.error(...)` із `sonner`, `hasPermission(...)` з `auth.access.ts`, `Button` із shadcn. Не додавайте фасад, фабрику, провайдер чи компонент-обгортку, які лише передають або перейменовують властивості.
- **Абстрагуйте на третьому використанні, а не на першому.** Допоміжна функція заслуговує на існування, коли щонайменше три місця виклику мають спільну нетривіальну логіку, і вона лежить в одному файлі, якому належить це завдання. `course-fields.tsx` існує, бо форма курсу, діалог розділу й діалог уроку рендерять те саме локалізоване текстове поле з тим самим відображенням валідації.
- **Видаляйте, перш ніж розширювати.** Коли механізм більше не виправдовує себе, приберіть його, а не додавайте до нього опції. Спекулятивні опції, властивості й параметри «на потім» не додаються.
- **Жодної косметичної машинерії.** Константи чи допоміжні функції, єдине завдання яких — виглядати охайно, як-от будівник для одного емодзі чи властивість `className` для одного місця виклику, не додаються.

## Компоненти самі читають свої дані

Компонент сам отримує свій текст і дані:

- переклади — через `useTranslations`, обмежений власним простором імен (див. [Переклади та контент](/docs/conventions/translations));
- дані запитів — через `useSuspenseQuery(options)`, які loader маршруту завантажив наперед;
- дані маршруту — через `Route.useParams()` у файлі маршруту або `getRouteApi("/blog/$")` у файлі компонента, як це робить `post-meta.tsx`.

Властивості передають лише те, що знає тільки батьківський компонент: запис, який редагує діалог (`chapter`), ідентифікатор, до якого належить форма (`courseId`), елемент-тригер, `isOpen` і `onOpenChange`. Компонент, який може сам прочитати мітку, список чи результат запиту, не отримує їх через властивість, і значення ніколи не проходить через компонент, який його не використовує. Мапи тегів форматованого тексту для `t.rich` — це константи рівня модуля поруч із компонентом, що їх використовує, а не об’єкти, створені під час рендерингу.

## Форма файлу компонента

`src/presentation/components/custom/admin/courses/chapter-dialog.tsx` — типовий файл:

```tsx
interface ChapterDialogProps {
  readonly chapter?: { readonly id: string; readonly title: LocalizedText }
  readonly courseId: string
  readonly trigger: ReactNode
}

export const ChapterDialog = ({ chapter, courseId, trigger }: ChapterDialogProps): JSX.Element => {
  const t = useTranslations("pages.admin.courses.chapter")
  const queryClient = useQueryClient()
  const errorMessage = useErrorMessage()
  const [isOpen, setOpen] = useState(false)
```

- Один експортований компонент на файл, оголошений як `export const Name = (...): JSX.Element =>`. Компонент, який може нічого не рендерити, повертає `JSX.Element | undefined`.
- Властивості мають модифікатор `readonly` і оголошуються в інтерфейсі `<Name>Props` над компонентом або вбудовано, коли властивість одна.
- Спершу йдуть хуки в порядку й з відступами, описаними на сторінці [Стиль коду](/docs/conventions/code-style), потім локальні колбеки, потім JSX.
- Вибір між двома фрагментами JSX робиться парами `&&` або раннім поверненням, а не багаторядковим тернарним оператором.

## Імена класів

Стилізація — це утиліти Tailwind у `className`. Умовні класи проходять через `cn` з `~/src/lib/cn` з об’єктним синтаксисом, ніколи не через тернарний оператор усередині виклику:

```tsx
className={cn("flex items-center gap-4 border-b transition-colors duration-200 ease-exp", {
  "border-border focus-within:border-foreground": !isInvalid,
  "border-destructive": isInvalid,
})}
```

Вибір із двох варіантів — це два записи, другий із запереченням, як у `newsletter-form.tsx` вище. Ключі можуть бути обчисленими: `course-columns.tsx` пише `[ADMIN_STATUS_BADGE_CLASSES.emerald]: status === COURSE_STATUS.PUBLISHED`. Довгий рядок класів, який використовується у файлі більше одного разу, стає константою в цьому файлі, як-от `NAV_LINK_CLASSNAME` у `src/routes/courses.tsx`.

`~/src/lib/cn` обов’язковий, це не питання вподобань. Це `createCn`, побудований з `src/lib/cn.config.ts` і таблиць, які `bun run generate:cn` записує в `.source/cn-tables.ts`. Конфігурація реєструє типографічні токени проєкту (`text-body`, `text-body-sm`, `text-label`, `text-spec`, `text-lead`, `text-title`, `text-statement`, `text-price` і розміри `text-headline-*` та `text-display-*`) як розміри шрифту. Звичайний `cn` сприйняв би їх як кольори й відкинув би один із двох класів, які він вважає конфліктними: `cn("text-body-sm text-muted-foreground", { "text-foreground": true })` втратив би розмір шрифту. Використовуйте ці токени для типографіки замість сирих розмірів і кольори теми (`text-foreground`, `text-muted-foreground`, `bg-card`) замість фіксованих.

## Примітиви shadcn

`src/presentation/components/shadcn/` містить примітиви shadcn/ui стилю `aria-lyra`, указаного в `components.json`, побудовані на React Aria Components. Екрани імпортують їх напряму; жодного шару обгорток немає. Додавайте примітив через shadcn CLI і змінюйте файл примітива лише для виправлення самого примітива, як-от його поведінки фокусу чи доступності, але ніколи заради вигляду одного екрана. Властивості React Aria відрізняються від звичок DOM: `onPress`, `isDisabled`, `isOpen` з `onOpenChange`, `isSelected`. Повну таблицю та список `@source not` у `globals.css` наведено на сторінці [Компоненти shadcn](/docs/ui/shadcn-components).

## Кільця фокусу

Компоненти React Aria стилізують кільце фокусу варіантами `data-focus-visible:`, як це роблять `select.tsx`, `checkbox.tsx`, `switch.tsx` і `radio-group.tsx`. React Aria встановлює `data-focus-visible` лише для фокусу з клавіатури. Натомість `:focus-visible` у Chrome спрацьовує й тоді, коли поповер закривається після кліку поза ним, а React Aria повертає фокус на його тригер, тож `focus-visible:` на тригері малює кільце після суто мишачої взаємодії. Звичайні посилання й елементи, які не є компонентами React Aria, зберігають `focus-visible:`, бо ніколи не отримують `data-focus-visible`; саме тому `button-variants.ts`, який стилізує й посилання, використовує `focus-visible:`.

## Провайдери

Провайдер, значення якого змінюється після гідратації, ніколи не обгортає `<Outlet />` маршруту. Його монтують поруч із компонентами, що його використовують:

- `AriaProvider` обгортає кореневий outlet у `__root.tsx`, а `TranslationsProvider` — тіло документа, бо вони потрібні кожному екрану, а їхні значення готові на момент гідратації.
- `ThemeProvider` обгортає лише `Toaster` у `__root.tsx` і `ThemeSwitch` у `docs.tsx`.
- `MotionProvider` обгортає розділи лендингу в `_landing.index.tsx` і список дописів у `blog.index.tsx`.

Причину, підтверджену вимірюваннями, наведено на сторінці [Продуктивність](/docs/conventions/performance).
