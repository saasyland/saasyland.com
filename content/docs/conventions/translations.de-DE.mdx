SaaSy Land wird in <RepositoryFact name="languages" /> Locales ausgeliefert: <RepositoryFact name="supportedLocales" />, einmal aufgeführt in `I18N.SUPPORTED_LOCALES` in `src/integrations/use-intl/i18n.config.ts`. Englisch ist die maßgebliche Quelle. Eine Änderung, die Text hinzufügt oder bearbeitet, fügt ihn im selben Commit in jeder Locale hinzu oder bearbeitet ihn dort, und `bun run check:i18n` schlägt fehl, wenn sie das nicht tut.

## Namespaces

Nachrichten liegen in `messages/<locale>/<namespace>.json`, eine Datei pro Namespace, und der Dateiname ist der Namespace.

| Namespace                                                          | Enthält                                                                                                                                                 | Geladen                                              |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| `common`, `errors`, `errors.global`                                | Text, den jeder Bildschirm brauchen kann, einschließlich `errors.codes.<CODE>`                                                                          | Für jede Route                                       |
| `components.custom.<file>`, `components.shadcn.<file>`             | Die Texte einer gemeinsam genutzten Komponente, etwa `components.custom.newsletter-form`                                                                | Für jede Route                                       |
| `fumadocs`                                                         | Die Texte der eigenen Bedienelemente von Fumadocs in Dokumentation und Blog, die `useFumadocsI18n` an Fumadocs übergibt                                 | Von den Layouts der Dokumentation und des Blogs      |
| `pages.<feature>`, `pages.<feature>.<page>`                        | Ein Layout oder eine Seite, mit `metadata.title` und `metadata.description`                                                                             | Von der Route, über `NAMESPACE` oder `NAMESPACES`    |
| `navigation.<feature>`, `dashboard.<feature>`                      | Die Beschriftungen der Menüeinträge, Breadcrumbs und Dashboard-Statistiken eines Features, die ein Menüeintrag über ihren vollständigen Schlüssel nennt | Auf Root-Ebene, mit jeder Seite                      |
| `<table>.validations`                                              | Die Zod-Meldungen eines Moduls, etwa `course.validations`                                                                                               | Vom Layout, dessen Formulare sie verwenden           |
| `auth.errors`, `auth.validations` und die anderen `auth.*`-Dateien | Fehler von Better Auth, Validierung und Auth-Bildschirme                                                                                                | Von den Layouts, die sie brauchen                    |
| `emails.<template>`                                                | Eine E-Mail-Vorlage                                                                                                                                     | Auf dem Server, vom Use Case, der sie sendet         |
| `countries`, `currencies`, `flow-features`, `locales`, `timezones` | Kataloge                                                                                                                                                | Von den Layouts, die sie brauchen                    |
| `stack`                                                            | Die Beschriftungen der Fragen, Optionen und Extras der CLI aus `@saasyland/stack`, mit dem Hinweis jeder Frage                                          | Von der Landingpage und dem Layout der Dokumentation |

Die Root-Namespaces werden in `src/integrations/use-intl/i18n.messages.ts` am Dateinamen erkannt (`common.json`, `components.*.json`, `errors*.json`). Die Texte einer gemeinsam genutzten Komponente liegen in ihrem eigenen Namespace `components.custom.<file>`, niemals in einem Seiten-Namespace, sodass die Komponente überall, wo sie erscheint, denselben Text rendert. Jeder Namespace, den eine Route deklariert, muss in jeder Locale als Datei existieren; `loadNamespace` wirft bei einem fehlenden Namespace einen Fehler.

## Eine Übersetzungsfunktion pro Komponente

Eine Komponente ruft `useTranslations` einmal mit ihrem Namespace auf und nennt das Ergebnis `t`:

```tsx
const t = useTranslations("pages.admin.courses.form")
```

`scripts/check-i18n.ts` löst jedes statische `t("key")` in den `.tsx`-Dateien von `src` gegen den Namespace des `useTranslations`-Aufrufs darüber auf und schlägt bei einem Schlüssel fehl, der im Englischen nicht existiert. Es schlägt auch bei einem englischen Schlüssel fehl, den keine Quelldatei rendert, damit entfernte Texte nicht in den Nachrichtendateien liegen bleiben. Ein Schlüssel gilt als gerendert, wenn ein `t()`-Aufruf ihn oder einen Schlüssel darüber nennt, wenn ein Template wie `kinds.${kind}` ihn bildet und jeder Platzhalter dabei mit einem String gefüllt wird, den `src` oder der CLI-Vertrag `@saasyland/stack` deklariert, oder, unterhalb eines `t()`-Aufrufs mit einer Variablen, wenn ein solcher String oder ein Namespace-String gefolgt von einem solchen String den Rest seines Pfads ergibt. Ein Schlüssel, den ein Platzhalter nur über ein anderswo verwendetes Wort erreichen könnte, etwa `filters.status` unterhalb der Spaltenköpfe einer Tabelle, schlägt deshalb fehl. Außerdem prüft `navigation.website.test.ts`, dass die Dateien `navigation.<feature>.json` genau die Menüeinträge und Benutzer-Tabs beschriften, die die Bereiche deklarieren. Die Kataloge `countries`, `currencies`, `flow-features`, `locales` und `timezones` sind ausgenommen; stattdessen prüft `catalogues.test.ts`, dass ihre Schlüssel den Konstanten entsprechen, bei `flow-features` der Konstante `FLOW_FEATURE` in `e2e/data/flows.ts`. Bei einer Konstante, deren Werte Nutzern angezeigt werden, prüft `enum-labels.test.ts` die Beschriftungen in jeder Locale; der Test liest jede solche Konstante mit den Nachrichten, die sie beschriften, aus den Listen, die die Bereiche in `src/integrations/use-intl/__test__/<feature>.labels.ts` deklarieren. Ein zweiter `useTranslations`-Aufruf in derselben Komponente würde stillschweigend den Scope jedes folgenden `t()` ändern, weshalb es nur einen gibt. Eine Komponente, die Schlüssel aus zwei Namespaces braucht, ruft `useTranslations()` ohne Namespace auf und verwendet vollständige Schlüssel, wie `sign-in-form.tsx` mit `t("pages.auth.sign-in.form.resetPassword")`.

## Nachrichten

- Schlüssel sind verschachtelte JSON-Objekte mit Namen in camelCase, gruppiert so, wie der Bildschirm aufgebaut ist: `table.headers.course`, `delete.confirm`.
- Pluralformen, Zahlen und Datumsangaben verwenden ICU-Syntax in der Nachricht, niemals String-Verkettung im Code: `"{e2eSpecs, plural, one {# Playwright suite} other {# Playwright suites}}"`.
- `scripts/check-message-formats.ts` verlangt in jeder Locale dieselben ICU-Argumente und Tags sowie jeden Dateipfad und jeden Befehl mit `bun run`, `bunx`, `npx` oder `vp` aus der englischen Nachricht unverändert. Es weist englischen Text zurück, der in einer anderen Locale stehen geblieben ist, Markdown-Backticks, die Nachrichten nicht rendern, und eine [Anrede](#one-form-of-address), die die Locale nicht verwendet.
- Formatiere Zahlen, Datumsangaben und Währungen für die Locale des Lesers mit `useFormatter` aus use-intl, niemals von Hand. Datumsangaben verwenden ein benanntes Format aus `I18N.FORMATS` (`date`, `time`, `calendarDate`), damit die Zeitzone und ihre Bezeichnung einheitlich bleiben. Ein benanntes Format enthält ein Datum oder eine Uhrzeit, nie beides: Engines verbinden die beiden unterschiedlich, und Safari schreibt „Jan 1, 2025 at 7:00 AM“, wo der Server „Jan 1, 2025, 7:00 AM“ schreibt, deshalb ist ein Datum mit Uhrzeit die Nachricht `common.dateTime`, etwa `t("common.dateTime", { value })`. Eine relative Zeit zählt ab dem Lesen ihrer Daten, dem `dataUpdatedAt` ihrer Query, etwa `format.relativeTime(session.updatedAt, dataUpdatedAt)`, niemals ab `new Date()`, das Server und Browser zu verschiedenen Zeitpunkten lesen. Ein Preis ist ebenfalls eine Zahl: `format.number(TIER_PRICES[tier], CURRENCY_FORMAT)` gibt ihn in der Währung des Shops aus, wie es `TierPrice` tut.
- Zod-Meldungen in den Schemas eines Moduls sind Schlüssel seines Namespace `<table>.validations` (`"slugInvalid"`), und die Zahlen, die sie nennen, stammen aus `<MODULE>_VALIDATION_PARAMS`. Siehe [Formulare und Tabellen](/docs/conventions/forms-and-tables).
- In der Datenbank gespeicherter Text, den Besucher in mehreren Sprachen lesen, ist eine Spalte vom Typ `LocalizedText`. Englisch ist Pflicht und der Fallback, den `localize(text, locale)` für eine fehlende Übersetzung zurückgibt.

## Eine Anrede [#one-form-of-address]

Jede Locale spricht die Leser auf eine Weise an, in jeder Nachricht, jeder E-Mail, jeder Rechtsseite, jeder Docs-Seite, jedem Blogbeitrag und jedem Changelog-Eintrag: in der Form, die Entwicklerwerkzeuge in dieser Sprache verwenden. `FORMS_OF_ADDRESS` in `src/lib/forms-of-address.ts` nennt die Form jeder Locale und listet die Formen auf, die ihr widersprechen, und `scripts/check-message-formats.ts` und `scripts/check-content.ts` schlagen fehl, wenn eine Übersetzung eine davon außerhalb von Code, Linkzielen und japanischen 「」-Zitaten verwendet.

  columns={[
    "Locale",

/>

- Ein Wort unter **Nie** schlägt überall fehl, auch großgeschrieben am Satzanfang.
- Ein Wort unter **Nie innerhalb eines Satzes** schlägt nach einem Wort, einer Zahl oder einem Komma in derselben Zeile fehl. Am Satzanfang ist dasselbe Wort oft die dritte Person, wie in `Sie laufen im Worker`, deshalb lässt die Prüfung es dort stehen und überlässt es dem Review.
- Eine Form unter **Nie am Satzende** schlägt vor einem japanischen Satzpunkt fehl.
- Ein Wort unter **Nie am Anfang eines Teilsatzes** schlägt am Anfang einer Zeile, einer Überschrift, eines Listenpunkts oder eines Satzes fehl, nach einem Doppelpunkt oder Semikolon und nach einer der **Teilsatzeinleitungen** der Locale. Ein Teilsatz, der dort beginnt, ist ein Hauptsatz, in dem die Form nur ein Imperativ sein kann, wie in `Ejecute la suite` statt `Ejecuta la suite`.

Deutsch duzt, kleingeschrieben, wie der Duden es empfiehlt, auch auf den Rechtsseiten: Die Anrede hat keine rechtliche Wirkung. Polnisch schreibt Ty und Twój aus Höflichkeit groß. Japanisch beendet seine Sätze mit です・ます, während Überschriften, Listenpunkte, Tabellenzellen und Slogans auf ein Substantiv oder ein Verb in der einfachen Form enden dürfen, nie auf die einfache Kopula. Die Prüfung findet die eindeutigen Pronomen, Endungen und Imperative; eine Verbform, die erst die Bedeutung des Satzes unterscheidet, prüft das Review, etwa spanisch `ejecute` in `espera a que arranque y ejecute la suite`: ein Konjunktiv, wenn der Server die Suite ausführt, und ein höflicher Imperativ, wenn der Leser es tut.

## Zahlen werden gemessen, nicht eingetippt

Eine Anzahl von etwas im Repository, etwa Testdateien, Playwright-Suites, UI-Komponenten, Länder oder Währungen, wird nie von Hand in Texte geschrieben. `scripts/repository-facts.ts` misst sie zur Build-Zeit und stellt sie als Modul `virtual:repository-facts` bereit; `src/lib/repository-facts.ts` exportiert sie als `REPOSITORY_FACTS`. Die Größe eines Katalogs stammt aus seiner Konstante (`COUNTRIES`, `CURRENCY_CODES`, `TIMEZONES`, `ADMIN_NAVIGATION`), nie aus der Nachrichtendatei, die ihn übersetzt. Die Texte der Landingpage interpolieren sie, etwa mit `t("body", REPOSITORY_FACTS)` und `"{testFiles, number} test files"` in der Nachricht, und MDX rendert eine Zahl mit `<RepositoryFact name="testFiles" />`. Um eine neue Zahl zu erwähnen, miss sie zuerst in diesem Plugin. Eine Zahl, die das Unternehmen festlegt, statt sie zu messen, etwa die Affiliate-Provision, wird einmal in `src/data` deklariert (`AFFILIATE_TERMS` in `src/data/affiliates.ts`) und auf dieselbe Weise interpoliert. Für Preise gilt dieselbe Regel: `TIER_PRICES` (`src/data/license.ts`) und `CONSULTING_HOURLY_RATE` in `src/data/marketing.ts` erreichen Messages als `{price}` und MDX als `<TierPrice tier="core" />`, und die Kontaktadresse erreicht Messages aus `CONTACT_EMAIL` in `src/presentation/branding/index.ts` als `{email}`. Die Gerätelimits aus `LICENSE_ACTIVATION_LIMITS` erreichen die Message `machines` der Stufenkarten als `{limit}` und MDX als `<ActivationLimit tier="core" />`. Komponenten lesen `REPOSITORY_FACTS` direkt: Der Testlauf im Qualitätsabschnitt gibt `Test Files` mit `REPOSITORY_FACTS.testFiles` aus, der Anzahl der Dateien, auf die die `include`-Muster von Vitest passen. Eine Zahl, die nur ein Lauf der Suite liefert, etwa die Anzahl der einzelnen Tests, wird nicht angezeigt.

Auch Dateipfade und Befehle, die ein Text nennt, sind Fakten, damit keine Locale sie übersetzen kann. `RecordSection` auf der Landingpage übergibt `{coverageSummaryPath}`, `{coverageCommand}`, `{ciWorkflowPath}`, `{e2eSpecsPath}`, `{messagesPath}`, `{i18nCheckCommand}` und `{authIntegrationPath}` aus `REPOSITORY_FACTS`: Das Verzeichnis der Zusammenfassung ist `reportsDirectory` in `vite.config.ts`, das Verzeichnis der Specs ist `testDir` in `playwright.config.ts`, und `repository-facts.test.ts` prüft, dass jeder Pfad existiert und jeder Befehl ein Skript aus `package.json` ist.

Auch Dokumentationsseiten tippen die Werte, die der Code definiert, nicht ein. `<RepositoryFact name="…" />` in `src/presentation/components/custom/repository-fact.tsx` gibt eine gemessene Anzahl aus, eine Einstellung, die `repositoryFacts` aus `vite.config.ts`, `playwright.config.ts`, `.nvmrc`, `package.json` oder einem Workflow liest, oder eine aus dem Code importierte Konstante, etwa `RATE_LIMITS` oder `PLAYBACK_TTL_SECONDS`. Die Komponente formatiert eine Zahl für die Locale der Seite, mit `unit="second"`, `"minute"`, `"hour"`, `"day"` oder `"percent"`, wenn der Wert eine Einheit hat, und gibt Text als Code und eine Liste als Liste von Code aus. `<RepositoryTable name="…" columns={["…", "…"]} />` gibt eine aus dem Code erzeugte Tabelle aus, etwa die Berechtigungs-Statements, die Commit-Typen oder die regionalen Preismultiplikatoren, unter Spaltennamen, die die Seite übersetzt. Eine Zelle, die eine Nachricht über ihren vollständigen Schlüssel nennt, `{ label: "components.custom.pricing.status.arriving" }` mit ihren `values`, wenn die Nachricht Argumente erwartet, gibt diese Nachricht in der Sprache der Seite aus. So zeigen die Tabellen der Roadmap zu den Optionen der CLI und den Funktionen der Stufen dieselben Beschriftungen wie der Konfigurator und die Stufenkarten, und die Tabellen der Abläufe zeigen die Beschriftung jedes Bereichs aus `flow-features`. Eine Zelle `{ text: "…" }` gibt Fließtext als einfachen Text aus, etwa das Ergebnis eines Ablaufs. Jede andere Textzelle ist ein Wert aus dem Code und wird als Code ausgegeben: Ein Wert ohne Leerzeichen bricht nie um, und einer aus mehreren Wörtern bricht nur zwischen ihnen um. Mit `grouped` nimmt die Tabelle die erste Zelle jeder Zeile als Überschrift einer eigenen Tabelle, sodass die Roadmap die Abläufe, die noch zu testen oder zu bauen sind, in einer kleinen Tabelle pro Bereich auflistet. Die Cache-Zeiten des Routers und das E-Mail-Limit pro Empfänger sind in `src/integrations/tanstack-query/query.cache.ts` und `src/modules/rate-limit/rate-limit.constants.ts` deklariert statt in `src/router.tsx` und dem nur serverseitigen `src/lib/rate-limit.ts`, die die Dokumentation nicht importieren kann; der Test der Komponente vergleicht die ausgegebenen Werte mit dem Router und dem Limiter. Ein Wert, der in einem Codeblock oder im Frontmatter stehen bleiben muss, wird stattdessen von `scripts/check-content.ts` geprüft.

## Dokumentation und Blog

Jede Seite unter `content/docs`, jeder Beitrag unter `content/blog` und jeder Changelog-Eintrag unter `content/changelog` existiert als `<slug>.<locale>.mdx` in jeder Locale, und die Navigation jedes Ordners als `meta.<locale>.json`. `scripts/check-content.ts`, ausgeführt von `bun run check:content`, schlägt fehl, wenn:

- eine Locale-Datei fehlt;
- ein Codeblock vom englischen abweicht (Codeblöcke werden Byte für Byte kopiert);
- eine `meta.<locale>.json` andere Slugs auflistet als die englische;
- ein Titel, eine Beschreibung oder ein Absatz noch auf Englisch ist;
- die Übersetzung eines Blogbeitrags ein anderes `date` oder `updated` hat als der englische Beitrag;
- eine Markierung einer maschinellen Übersetzung im Text zurückgeblieben ist;
- eine Übersetzung die Leser in einer Form anspricht, die ihre Locale nicht verwendet (siehe [Eine Anrede](#one-form-of-address));
- eine nackte URL ohne Leerzeichen in den folgenden Text übergeht, etwa vor einer Klammer oder einem Punkt in voller Breite im Japanischen, sodass ihr Link diesen Text mitnehmen würde;
- ein Codeblock, dessen Titel ein Repository-Pfad ist, etwa `title="src/integrations/better-auth/auth.access.ts"`, kein Auszug aus dieser Datei ist;
- eine Dokumentationsseite einen lokalen Host oder eine Subdomain von `APP_DOMAIN` nennt, die `appHostsForMode` in keinem Build-Modus zulässt;
- ein Changelog-Eintrag weder nach einer Pull-Request-Nummer noch nach einem vollständigen Commit-Hash benannt ist oder der CI-Lauf eines Pull Requests keine nach ihm benannte `content/changelog/<number>.en-US.mdx` findet;
- die Routen-Referenz, die Seite der Projektskripte oder eine Tabelle mit Umgebungsvariablen eine Konstante aus `ROUTES`, ein Skript aus `package.json` oder ein Secret aus `wrangler.jsonc` auslässt oder einem davon den falschen Wert gibt;
- ein interner Link auf einen Schrägstrich, `/index` oder `.html` endet oder mit einer Locale oder einem Sprachkürzel wie `/pl/` beginnt: Die Website leitet einen solchen Pfad um, und `localizeHref` fügt jedem internen Link die Locale der Seite hinzu;
- eine Übersetzung Inline-Code, eine Komponente, eine Prop einer Komponente außer `title`, `description`, `excerpt` und `unreleased` oder einen Link auf eine andere Seite auslässt oder hinzufügt oder eine andere Zahl von Tabellenzeilen hat als die englische Seite.

Schreibe Übersetzungen so, wie es ein Muttersprachler tun würde, mit der Terminologie, die die Locale in `messages/<locale>/` bereits verwendet (Polnisch etwa nennt die Stufen Podstawa, Komplet und Agencja und einen Rabatt „rabat“). Code-Bezeichner, Dateipfade, Befehle und Produktnamen bleiben unverändert, und Links behalten ihre `/docs/...`-Pfade ohne Locale-Präfix, das die Website beim Rendern ergänzt. Polnisch folgt dem [polnischen Styleguide](/docs/conventions/polish-style), dessen Glossar jeden polnischen Begriff festlegt.
