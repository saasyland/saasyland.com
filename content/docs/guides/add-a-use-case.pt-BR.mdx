---
title: "Adicionar um caso de uso"
description: "Adicione uma operação: uma função de servidor com suas opções de query ou mutation, invalidação de cache e tratamento de erros."
---

Um caso de uso é uma operação sobre uma tabela. Ele fica em `src/modules/<table>/use-cases/<operation>.ts` e exporta a função de servidor junto com as opções que os componentes usam. [Funções de servidor](/docs/guides/server-functions) explica as peças.

## Escreva uma mutation

`src/modules/category/use-cases/create-category.ts`:

```ts
import { mutationOptions } from "@tanstack/react-query"
import { createServerFn } from "@tanstack/react-start"
import { v7 } from "uuid"
import type * as zod from "zod"

import { authorized } from "~/src/integrations/better-auth/auth.middleware"
import { db } from "~/src/integrations/drizzle-orm/drizzle.database"

import { CATEGORY_MUTATION_KEYS } from "~/src/modules/category/category.constants"
import { category } from "~/src/modules/category/category.schema"
import { categoryZodSchemas } from "~/src/modules/category/category.zod"

export const createCategory = createServerFn({ method: "POST" })
  .middleware([authorized({ category: ["create"] })])
  .validator((input: zod.input<typeof categoryZodSchemas.createCategory>) => categoryZodSchemas.createCategory.parse(input))
  .handler(({ data }) =>
    db
      .insert(category)
      .values({
        description: data.description ?? "",
        icon: data.icon ?? "FolderOpen",
        id: v7(),
        kind: data.kind,
        name: data.name,
        visibility: data.visibility ?? "public",
      })
      .returning()
      .get(),
  )

export const createCategoryMutation = mutationOptions({
  mutationFn: (data: Parameters<typeof createCategory>[0]["data"]) => createCategory({ data }),
  mutationKey: CATEGORY_MUTATION_KEYS.CREATE,
})
```

- Escritas usam `method: "POST"`; leituras usam `method: "GET"`.
- O middleware protege a chamada: `authorized(permission)` para usuários logados com uma permissão, `authorized()` para qualquer usuário logado e `withRateLimit(kind, RATE_LIMITS.SENSITIVE)` para operações públicas.
- O validador analisa o schema do módulo; o handler recebe `data` já validado.
- O handler retorna o resultado diretamente. Operações sobre os dados de quem chama leem o usuário de `context.auth.user.id`, nunca da entrada.

## Escreva uma query

Queries exportam opções cuja chave contém a entrada validada, de modo que cada página ou filtro tem sua própria entrada no cache (`src/modules/category/use-cases/get-categories.ts`):

```ts
export const getCategoriesPageQuery = (input: zod.input<typeof listCategoriesSchema> = {}) =>
  queryOptions<Awaited<ReturnType<typeof getCategories>>>({
    queryFn: () => getCategories({ data: input }),
    queryKey: [...CATEGORY_QUERY_KEYS.LIST, listCategoriesSchema.parse(input)],
  })

export const getCategoriesQuery = getCategoriesPageQuery()
```

Pré-carregue a query no `Promise.all` do loader da rota com `context.queryClient.query({ ...getCategoriesQuery, staleTime: "static" })` e leia-a no componente com `useSuspenseQuery(getCategoriesQuery)`.

## Trate falhas

Para falhas esperadas, lance `AppError` com um código de `src/modules/_core/constants/errors.ts`:

```ts
if (row === undefined) {
  throw new AppError(ERROR_CODES.NOT_FOUND)
}
```

Os códigos são `AUTH_API_ERROR`, `CONFLICT`, `FORBIDDEN`, `INTERNAL_ERROR`, `NOT_FOUND`, `TOO_MANY_REQUESTS`, `UNAUTHORIZED` e `VALIDATION`. O middleware `withRequest`, incluído em `authorized` e `withRateLimit`, repassa apenas o código de um `AppError`, transforma erros da API do Better Auth em `AUTH_API_ERROR` com a chave de erro de autenticação, transforma erros do Zod em `VALIDATION` e registra qualquer outro erro antes de substituí-lo por `INTERNAL_ERROR`.

## Use em um componente

Espalhe as opções exportadas em `useMutation`, traduza os erros com `useErrorMessage` e invalide as queries do módulo em caso de sucesso (`src/presentation/components/custom/admin/users/delete-user-dialog.tsx`):

```tsx
const queryClient = useQueryClient()
const errorMessage = useErrorMessage()

const deleteUser = useMutation({
  ...deleteUserMutation,
  onError: (error) => {
    toast.error(errorMessage(error))
  },
  onSuccess: async () => {
    await queryClient.invalidateQueries({ queryKey: USER_QUERY_KEYS.ALL })
    toast.success(t("feedback.deleteSuccess"))
  },
})
```

`useErrorMessage` mapeia chaves de erro de autenticação para `auth.errors.<key>`, códigos de erro para `errors.codes.<CODE>` e qualquer coisa desconhecida para `errors.codes.INTERNAL_ERROR`. Invalide apenas os módulos cujos dados a mutation altera.

## Teste

Adicione `use-cases/__test__/<operation>.test.ts`. `executeMutation` e `executeQuery` de `~/src/platform/testing/lib/query` executam as opções com um `QueryClient` real, e a configuração de testes passa a função de servidor pelo middleware e pelo validador reais. Cubra o sucesso, cada código lançado e a verificação de permissão. Veja [Escrever testes](/docs/guides/writing-tests).
