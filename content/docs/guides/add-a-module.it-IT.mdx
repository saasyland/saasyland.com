---
title: "Aggiungere un modulo"
description: "Aggiungi una tabella del database con schema Drizzle, schemi Zod, costanti, tipi e casi d'uso."
---

Un modulo corrisponde a una tabella del database. `src/modules/<table>/` esiste solo per tabelle reali; le funzioni server che non appartengono a una tabella stanno in `src/lib` o nella route che le usa. `src/modules/category` è il più piccolo esempio completo.

## File

| File                       | Contenuto                                                                                                                                              |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `<table>.schema.ts`        | Tabella Drizzle, indici, relazioni e tuple di valori enumerati costruite dalle costanti                                                                |
| `<table>.zod.ts`           | Uno schema di input per operazione più gli schemi `drizzle-zod`, esportati come `<table>ZodSchemas`                                                    |
| `<table>.constants.ts`     | Valori di dominio con nome come `CATEGORY_KIND`, limiti delle colonne e tuple di chiavi di query e mutation                                            |
| `<table>.types.ts`         | Un’interfaccia con i tipi di riga e il tipo di input di ogni operazione                                                                                |
| `<table>.utils.ts`         | Funzioni di supporto facoltative; `license.utils.ts` legge l’ambiente del Worker, quindi è solo lato server                                            |
| `<table>.<concern>.ts`     | Codice facoltativo che non è una singola operazione, come `license.webhooks.ts` o `video.playback.ts` ([Catalogo dei moduli](/docs/reference/modules)) |
| `use-cases/<operation>.ts` | Una funzione server per file con le sue opzioni di query o mutation                                                                                    |
| `__test__/`                | Test con il nome del file sorgente, come `category.schema.test.ts` e `category.zod.test.ts`                                                            |

## 1. Definisci la tabella

Dai un nome ai valori della tabella una sola volta in `category.constants.ts`. Lo schema, gli schemi Zod, i casi d'uso, i componenti, i test e i dati e2e li importano da lì invece di ripetere una stringa come `"collection"`:

```ts
export const CATEGORY_NAME_MAX_LENGTH = 255

export const CATEGORY_KIND = {
  CATEGORY: "category",
  COLLECTION: "collection",
} as const
```

Costruisci la tabella a partire da quei nomi:

```ts
import { index, sqliteTable, text } from "drizzle-orm/sqlite-core"

import { timestamps } from "~/src/integrations/drizzle-orm/drizzle.columns"

import { CATEGORY_KIND, CATEGORY_NAME_MAX_LENGTH } from "~/src/modules/category/category.constants"

export const CATEGORY_KINDS = [CATEGORY_KIND.CATEGORY, CATEGORY_KIND.COLLECTION] as const

export const category = sqliteTable(
  "category",
  {
    id: text("id").primaryKey(),
    kind: text("kind", { enum: CATEGORY_KINDS }).notNull().default(CATEGORY_KIND.CATEGORY),
    name: text("name", { length: CATEGORY_NAME_MAX_LENGTH }).notNull(),
    ...timestamps(),
  },
  (table) => [index("category_createdAt_idx").on(table.createdAt)],
)
```

- I nomi delle colonne sono in snake_case, le proprietà in camelCase.
- Gli ID sono chiavi primarie `text` valorizzate con `v7()` di `uuid` nel caso d'uso di inserimento.
- `...timestamps()` di `src/integrations/drizzle-orm/drizzle.columns.ts` aggiunge `createdAt` e `updatedAt`: timestamp in millisecondi che per default valgono l'istante dell'inserimento; `updatedAt` viene aggiornato a ogni update. Le altre date sono `integer(..., { mode: "timestamp_ms" })`; i booleani sono `integer(..., { mode: "boolean" })`.
- Una colonna enumerata riceve la tupla costruita dall'oggetto di costanti e il suo default è una costante come `CATEGORY_KIND.CATEGORY`, mai una stringa letterale.
- Le chiavi esterne usano `.references(() => user.id, { onDelete: "cascade" })` e `relations(...)` dichiara i join (vedi `session.schema.ts`).

## 2. Registra lo schema

Esporta la tabella, e le sue relazioni se ne ha, da `src/integrations/drizzle-orm/drizzle.schemas.ts`:

```ts
export { category } from "~/src/modules/category/category.schema"
```

Questo file alimenta il client D1 (`drizzle(env.DB, { schema })`), l'adattatore Drizzle di Better Auth e drizzle-kit. Una tabella assente da qui non riceve alcuna migrazione.

## 3. Genera la migrazione

```sh
bun run db:generate
bun run db:migrate:local
```

Rivedi l'SQL generato in `src/integrations/drizzle-orm/migrations/` ed esegui il commit insieme allo schema. [Migrazioni del database](/docs/guides/database-migrations) tratta gli ambienti remoti.

## 4. Aggiungi gli schemi Zod

Ogni operazione ha il proprio schema di input. I messaggi di validazione sono chiavi di traduzione; un form li mostra con `ValidationFieldError` nel namespace che indica.

```ts
import { createSchemaFactory } from "drizzle-zod"
import zod from "zod/v4"

import { MIN_FIELD_LENGTH, idField } from "~/src/modules/_core/utils/zod-fields"
import { CATEGORY_NAME_MAX_LENGTH } from "~/src/modules/category/category.constants"
import { CATEGORY_KINDS, category } from "~/src/modules/category/category.schema"

const { createInsertSchema, createSelectSchema, createUpdateSchema } = createSchemaFactory({ zodInstance: zod })

const createCategory = zod.object({
  kind: zod.enum(CATEGORY_KINDS),
  name: zod.string().min(MIN_FIELD_LENGTH, { message: "nameRequired" }).max(CATEGORY_NAME_MAX_LENGTH, { message: "nameMaxLength" }),
})

const deleteCategory = zod.object({ categoryId: idField })

export const categoryZodSchemas = {
  createCategory,
  deleteCategory,
  insert: createInsertSchema(category),
  select: createSelectSchema(category),
  update: createUpdateSchema(category),
}
```

Aggiungi `messages/<locale>/<table>.validations.json` in tutte e nove le lingue con tutte le chiavi usate dagli schemi. Un form mostra quelle chiavi solo quando la sua route precarica il namespace e lo passa a `ValidationFieldError`; i form dei corsi dell'amministrazione usano `course.validations` e gli altri form usano `auth.validations`.

## 5. Aggiungi costanti e tipi

```ts
export const CATEGORY_QUERY_KEYS = {
  ALL: ["category"],
  LIST: ["category", "getCategories"],
} as const

export const CATEGORY_MUTATION_KEYS = {
  CREATE: ["category", "createCategory"],
  DELETE: ["category", "deleteCategory"],
  UPDATE: ["category", "updateCategory"],
} as const
```

```ts
import type * as zod from "zod"

import type { category } from "~/src/modules/category/category.schema"
import type { categoryZodSchemas } from "~/src/modules/category/category.zod"

export interface Category {
  select: typeof category.$inferSelect
  insert: typeof category.$inferInsert
  createCategory: zod.input<typeof categoryZodSchemas.createCategory>
  deleteCategory: zod.input<typeof categoryZodSchemas.deleteCategory>
}
```

Ogni chiave inizia con il nome del modulo, quindi invalidare `ALL` aggiorna tutte le query del modulo.

`Category` ha una chiave per ogni schema di operazione; il modulo `category` completo ha anche `getCategories`, `getCategory` e `updateCategory`. Una funzione server tipizza l’input del suo validatore come `Category["createCategory"]` e le sue opzioni di mutation o query riusano quel tipo. Aggiungi la chiave ogni volta che aggiungi uno schema.

## 6. Aggiungi permessi e casi d'uso

- Aggiungi le azioni della tabella a `APP_STATEMENTS` in `src/integrations/better-auth/auth.access.ts` quando le operazioni richiedono permessi. Vedi [Ruoli e permessi](/docs/guides/roles-and-permissions).
- Aggiungi un file per operazione in `use-cases/`. Vedi [Aggiungere un caso d'uso](/docs/guides/add-a-use-case).

## 7. Testa

Aggiungi `__test__/<table>.schema.test.ts`, `<table>.zod.test.ts` e `<table>.types.test.ts` accanto al modulo e `use-cases/__test__/<operation>.test.ts` per ogni operazione. La soglia di copertura è del 100%; vedi [Scrivere i test](/docs/guides/writing-tests).
