- Tests follow the areas. A test file covers one area or one source file, so leaving an area out removes its tests and every other test stays valid: the admin page and loader tests are split into `admin-<area>-routes.component.test.tsx` and `admin-<area>-loaders.test.ts`, and the API handler, skeleton and shared component tests into one file per source file. Lists that span the areas are declared per area and joined by barrels: the admin query data (`<area>.fixtures.ts`), the enum labels (`<area>.labels.ts`), the D1 rows (`<area>.rows.ts`), the pages the accessibility and workspace specs visit (`e2e/data/<area>.pages.ts`) and the test database seed (`e2e/data/<area>.seed.ts`). Navigation regressions moved to the specs of their areas, the user table checks to `admin-users.spec.ts` and the licence navigation to `license.spec.ts`, and the workspace spec now moves between the overview and the settings. See [Tests follow the areas](/docs/conventions/testing#tests-follow-the-areas).
