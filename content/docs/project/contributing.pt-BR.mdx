---
title: "Como contribuir"
description: "Como propor alterações ao SaaSy Land."
---

1. Discuta alterações grandes primeiro em uma issue, aberta pelo formulário de relatório de bug ou de solicitação de funcionalidade.
2. Crie uma branch a partir de `main`.
3. Siga as [convenções](/docs/conventions) e a [arquitetura](/docs/architecture), e leia a [skill para agentes](/docs/tooling/agent-skills) correspondente antes de alterar a integração com um fornecedor. Os agentes de código começam por `AGENTS.md`, na raiz do repositório.
4. Mantenha os testes ao lado do código a que pertencem e preserve a exigência de <RepositoryFact name="coverageThreshold" unit="percent" /> de cobertura.
5. Execute as verificações abaixo.
6. Faça o commit com uma mensagem no formato de [conventional commit](/docs/tooling/conventional-commits), abra um pull request com um título no formato convencional e preencha o template dele.

```sh
bun run check
bun run test:coverage
bun run build:test
bun run test:e2e:install
bun run test:e2e:pr
```

`build:test` executa o build completo do Cloudflare, que `check` e os testes unitários não exercitam. `test:e2e:pr` compila e serve o Worker de teste quando nenhum servidor está rodando e executa todas as specs no Chromium, como faz a CI de pull requests. Execute também a suíte completa de testes no navegador (`bun run test:e2e`) para alterações que podem se comportar de forma diferente no WebKit. Valide separadamente as integrações reais com provedores quando alterar a configuração delas.

Quando o comportamento mudar, atualize `content/docs` em todos os locales; `bun run check:i18n` rejeita traduções ausentes, blocos de código divergentes e navegação divergente. O template do pull request traz um resumo, um plano de testes com as verificações acima e a lista da documentação atualizada; descreva nele o comportamento resultante, como você o verificou e qualquer demonstração ou fluxo inacabado que ele deixe.

`CONTRIBUTING.md`, na raiz do repositório, é a versão curta desta página, e `SUPPORT.md` indica onde obter ajuda. Todas as pessoas que participam seguem o `CODE_OF_CONDUCT.md`, o Contributor Covenant 2.1. Relate vulnerabilidades de segurança de forma privada, como descreve o `SECURITY.md`, nunca em uma issue pública.
