---
title: "コントリビューション"
description: "SaaSy Land への変更を提案する方法です。"
---

1. 大きな変更は、まず Issue で議論してください。
2. `main` からブランチを作成します。
3. [アーキテクチャ](/docs/architecture)と[規約](/docs/reference/conventions)に従い、ベンダーとの連携を変更する前には対応する[エージェントスキル](/docs/tooling/agent-skills)を読んでください。
4. テストは対象のコードのそばに置き、100% のカバレッジのゲートを維持します。
5. 以下のチェックを実行します。
6. [Conventional Commits](/docs/tooling/conventional-commits) 形式のメッセージでコミットし、規約に沿ったタイトルでプルリクエストを作成します。

```sh
bun run check
bun run test:coverage
bun run test:e2e:install
bun run test:e2e:smoke
```

複数のルート、認証、ブラウザーの挙動に影響する変更では、ブラウザーテストのフルスイート（`bun run test:e2e`）を実行してください。実際のプロバイダーとの連携の設定を変更した場合は、それを別途検証してください。

挙動が変わる場合は、9 つのロケールすべてで `content/docs` を更新してください。`bun run check:i18n` は、翻訳の欠落、コードブロックやナビゲーションの差異を検出して失敗します。プルリクエストには、変更後の挙動、その検証方法、残っているデモや未完成のワークフローを記載してください。
