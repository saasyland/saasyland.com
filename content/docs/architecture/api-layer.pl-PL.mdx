Własne operacje aplikacji są funkcjami serwerowymi. Handlery HTTP istnieją tylko tam, gdzie adres URL wywołuje coś spoza klienta RPC aplikacji: przeglądarkowy klient Better Auth, dostawcy OAuth, webhooki Polar, pole wyszukiwania w dokumentacji i CLI `saasyland`.

| Plik                         | Ścieżka                                      | Metody            | Obsługuje                                                                                                                                |
| ---------------------------- | -------------------------------------------- | ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `src/routes/api/index.ts`    | `/api`                                       | GET               | Odpowiedź JSON ze statusem `{ runtime: "cloudflare-workers" }`                                                                           |
| `src/routes/api/auth.$.ts`   | `/api/auth/*`                                | GET, POST         | Wszystkie endpointy Better Auth, w tym callbacki OAuth, weryfikację adresu e-mail, portal klienta Polar i `/api/auth/polar/webhooks`     |
| `src/routes/api/search.ts`   | `/api/search`                                | GET               | Wyszukiwanie Fumadocs w dokumentacji                                                                                                     |
| `src/routes/api/cli.v1.*.ts` | <RepositoryFact name="cliApiBasePath" />`/*` | GET, POST, DELETE | [API licencji CLI](/docs/features/cli-licence-api): licencja, jej maszyny i paczka szablonów każdego wydania, przez `licenseApiHandlers` |

Worker sam obsługuje też `/media/<expiry>.<signature>/<videoId>/<file>`. Nie jest to trasa: `src/server.ts` przekazuje te żądania do `serveMedia` (`src/modules/video/video.delivery.ts`) przed middleware języka i TanStack Start, a `serveMedia` sprawdza podpis i serwuje plik wideo z cache Workers lub z bucketu `MEDIA`. Zobacz [Cloudflare R2](/docs/integrations/cloudflare-r2). W ten sam sposób Worker odpowiada na <RepositoryFact name="cliBundleUrlPath" />: handler obszaru licencji przekazuje tę ścieżkę do `serveBundle` (`src/modules/license/license.delivery.ts`), który sprawdza podpis i strumieniuje paczkę szablonów CLI z bucketu `BUNDLES`. Zobacz [API licencji CLI](/docs/features/cli-licence-api#template-bundles).

Handler deklaruje się przez `server.handlers` w `createFileRoute`. Otrzymuje webowy obiekt `Request` i zwraca `Response`:

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Zasady

- Nie dodawaj endpointu REST dla operacji, którą wywołuje wyłącznie ta aplikacja. Zamiast tego napisz przypadek użycia z `createServerFn`; otrzymuje on typowane dane wejściowe, middleware i opcje zapytania.
- Handler sam waliduje dane wejściowe i sprawdza uprawnienia. Middleware funkcji serwerowych (`authorized`, `withRateLimit`) nie jest uruchamiane dla handlerów. API licencji CLI odczytuje każde żądanie funkcją `readApiRequest` z kontraktu, zlicza je i odczytuje jego licencję w jednym batchu D1 przez `rateLimitBatch` z `src/lib/rate-limit.ts` i na każdą własną awarię, na przykład D1 albo Polar, odpowiada kodem `serviceUnavailable` z kontraktu.
- Weryfikacja specyficzna dla dostawcy pozostaje w integracji. Podpisy webhooków Polar weryfikuje plugin Polar w Better Auth, a nie własny handler.
- Ścieżki `/api` i `/media` nigdy nie są lokalizowane ani prerenderowane i omijają obsługę locale w Workerze.
