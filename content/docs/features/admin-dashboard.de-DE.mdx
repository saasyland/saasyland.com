## Admin-Shell

`src/routes/admin.tsx` schützt jede Admin-Seite mit `requireAdmin` und lädt die gemeinsamen Admin-Namespaces vorab. Das Layout rendert:

- `AdminSidebar`, `AdminBreadcrumbs` und `AdminCommandPalette` (Öffnen mit ⌘K), alle aufgebaut aus `ADMIN_NAVIGATION` in `src/data/navigation.ts`, das die Einträge der Bereiche samt Icon gruppiert: Überblick (Dashboard, Analytics), Angebote (Produkte, Preismodelle), Inhalte (Blog, Kurse, Videos, Landingpage) und Verwaltung (Benutzerverwaltung, Zahlungen, Einstellungen).
- Das Benutzer-Widget im Fußbereich der Seitenleiste mit einem Link zu den Einstellungen und `SignOutButton`.

## Dashboard

`/admin` (`src/routes/admin.index.tsx`) lädt im Loader `getUsersQuery` und die Query jeder Dashboard-Statistik vorab und setzt die Widgets aus `src/presentation/components/custom/admin/dashboard` mit den Panels zusammen, die die Bereiche hinzufügen:

- `DashboardActions`: der deaktivierte Zeitraum **Letzte 30 Tage** und ein Link für jeden Eintrag von `ADMIN_DASHBOARD_ACTIONS`, nach seinem `order` sortiert, etwa **Produkt hinzufügen** aus `src/data/products.navigation.ts`, beschriftet aus `navigation.products.json`.
- `DashboardStats` (live): die Statistiken von `ADMIN_DASHBOARD_STATS`, die Einträge der `src/data/<area>.dashboard.ts` mit der Platzierung `DASHBOARD_PLACEMENT.STAT`, nach ihrem `order` sortiert: die Anzahl der Benutzer und die Benutzer, deren E-Mail-Bestätigung noch aussteht, aus `src/data/auth.dashboard.ts` sowie die Anzahl der Produkte aus `src/data/products.dashboard.ts`, jeweils beschriftet aus der `dashboard.<area>.json` ihres Bereichs.
- Die Panels von `ADMIN_DASHBOARD_PANELS`, die Einträge mit der Platzierung `DASHBOARD_PLACEMENT.PANEL`, jeweils mit dem Skeleton, das `AdminDashboardPending` dafür zeigt: Der Zahlungsbereich fügt in `src/data/payments.dashboard.ts` `RevenueChart` (Demo) hinzu, ein statisches SVG mit festen Achsen, beschriftet aus `dashboard.payments.json`; die Zeitraum-Schaltflächen haben keine Funktion.
- Eine Benutzerkarte (live): die neuesten Benutzer mit Suche und Statusfiltern, <RepositoryFact name="adminPreviewPageSize" /> Zeilen pro Seite.

```tsx
<DataTable
  columns={dashboardUserColumns}
  data={users.rows}
  filters={[
    { columnId: "user", placeholder: t("users.search"), type: "search" },
    {
      columnId: "status",
      label: t("users.filters.status"),
      options: USER_STATUSES.map((status) => ({ label: t(`users.table.status.${status}`), value: status })),
      type: "select",
    },
  ]}
  options={{ initialState: { pagination: ADMIN_DASHBOARD_PREVIEW_PAGINATION }, selectable: true }}
/>
```

Die Tabelle arbeitet im Browser mit der ersten Seite von `getUsersQuery` (<RepositoryFact name="defaultPageSize" /> Benutzer). **Alle anzeigen** verlinkt auf `/admin/users`, wenn es weitere Benutzer gibt. **Produkt hinzufügen**, der Eintrag des Produktbereichs in `ADMIN_DASHBOARD_ACTIONS`, verlinkt auf `/admin/products/create`; **Letzte 30 Tage** ist deaktiviert.
