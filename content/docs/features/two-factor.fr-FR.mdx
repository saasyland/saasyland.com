Le plugin `twoFactor` de Better Auth utilise `APP_NAME` comme émetteur. Ses fonctions serveur se trouvent dans `src/modules/two-factor/use-cases` :

| Cas d’usage           | Middleware       | Utilisé par                            |
| --------------------- | ---------------- | -------------------------------------- |
| `enableTwoFactor`     | connecté, limité | `TwoFactorPasswordStep`                |
| `disableTwoFactor`    | connecté, limité | `TwoFactorPasswordStep`                |
| `generateBackupCodes` | connecté, limité | `TwoFactorPasswordStep`                |
| `verifyTotp`          | limité           | `TwoFactorVerifyStep`, `TwoFactorForm` |
| `verifyBackupCode`    | limité           | `TwoFactorForm`                        |

## Configuration

L’onglet **Sécurité** de `/app/settings` et `/admin/settings` affiche `TwoFactorCard`, qui ouvre `TwoFactorDialog` (`src/presentation/components/custom/settings`) avec l’une des valeurs de `TWO_FACTOR_INTENT` dans `src/data/auth.ts` :

1. L’étape du mot de passe appelle `enableTwoFactor` et reçoit l’URI TOTP et les codes de secours.
2. L’étape de vérification dessine l’URI sous forme de code QR (`TwoFactorQrCode`, qui l’encode avec `uqr` et dessine les modules en un seul tracé SVG, noir sur blanc dans les deux thèmes), affiche la clé de configuration extraite de l’URI (`extractTotpSecret`) avec un bouton de copie pour la saisie manuelle, et confirme un code à <RepositoryFact name="twoFactorCodeLength" /> chiffres avec `verifyTotp`. Better Auth n’active la 2FA qu’après ce code.
3. `BackupCodes` affiche les codes une seule fois, avec **Copier les codes** et **Télécharger**, un fichier texte nommé d’après `APP_SLUG` et dont l’en-tête porte le nom de l’application et l’adresse du compte, et un clic en dehors de la boîte de dialogue ne la ferme pas tant que **Je les ai enregistrés** n’a pas été choisi.

Lorsque la 2FA est active, **Nouveaux codes de secours** demande le mot de passe, appelle `generateBackupCodes`, qui remplace tous les codes, et affiche les nouveaux de la même façon ; **Désactiver** demande le mot de passe et appelle `disableTwoFactor`. La carte lit `twoFactorEnabled` dans la session courante et garde ses boutons désactivés pendant qu’une requête de double authentification est en cours, et une étape fermée avant la fin de sa requête n’affiche rien quand celle-ci aboutit. Better Auth exige un mot de passe pour ces appels : un compte qui ne se connecte qu’avec GitHub ou Google est donc invité à en définir un d’abord.

## Vérification à la connexion

Pour un compte avec 2FA, Better Auth répond à la connexion par `twoFactorRedirect`, et `SignInForm` ouvre `/auth/two-factor` en conservant `redirect`. `TwoFactorForm` accepte un code à <RepositoryFact name="twoFactorCodeLength" /> chiffres (`InputOTP`) ou, après basculement, un code de secours, et envoie `trustDevice: true`. En cas de succès, `finishSignIn` de `useAuthRedirect` continue vers `/auth/callback`. Chaque code de secours ne permet de se connecter qu’une fois.

Les longueurs des codes se trouvent dans `auth.constraints.ts` : `TWO_FACTOR_CODE_LENGTH` vaut <RepositoryFact name="twoFactorCodeLength" /> et les codes de secours comptent de <RepositoryFact name="backupCodeMinLength" /> à <RepositoryFact name="backupCodeMaxLength" /> caractères.
