description: "How SaaSy Land is organized: routes compose pages, modules own database tables, integrations wrap vendors."

SaaSy Land is one TanStack Start application that runs as a Cloudflare Worker. The code is split by responsibility:

- **Routes** (`src/routes`) compose pages. A route file declares its translation namespaces, guard, loader and head tags, then renders components.
- **Modules** (`src/modules/<table>`) exist only for real database tables. A module owns the table's Drizzle schema, Zod schemas, constants, types and the use cases that read or change it.
- **Integrations** (`src/integrations/<vendor>`) configure third-party libraries and services.
- **Presentation** (`src/presentation`) holds shadcn primitives, application components, React Email templates, styles, theme and branding.
- **Shared code** lives in `src/data` (data used by several files), `src/lib` (small utilities), `src/hooks` and `src/providers`.

```text
src/
├── routes/          Flat file routes that compose pages
├── modules/         One folder per database table, plus _core
├── integrations/    One folder per vendor
├── presentation/    Components, emails, styles, theme, branding
├── data/            Data shared by several files
├── lib/             Small shared utilities
├── hooks/           Shared React hooks
├── providers/       Application providers
├── platform/        Test runtime wiring
├── types/           Global type declarations
├── router.tsx       Router and per-request QueryClient
├── routes.ts        ROUTES path constants
└── server.ts        Cloudflare Worker entry
```

## Rules that shape the code

- Route files only compose. Widgets, dialogs, forms and table columns live in `src/presentation/components/custom`, one per file.
- Components read their own translations and data with `useTranslations`, `useSuspenseQuery` or the route's loader data. Routes do not pass labels or data down as props.
- A server function that works on a table is a use case in that table's module. A server function used by a single route can be defined in the route file. Everything else belongs in `src/lib`.
- There is no dependency injection container and no wrapper layer. Import the concrete function from the folder that owns it.
- A constant used by one file stays in that file. Only data shared by several files moves to `src/data`.
