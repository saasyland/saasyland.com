---
title: "Contribuer"
description: "Comment proposer des modifications à SaaSy Land."
---

1. Discutez d'abord des modifications importantes dans une issue, ouverte depuis le formulaire de rapport de bug ou de demande de fonctionnalité.
2. Créez une branche à partir de `main`.
3. Respectez les [conventions](/docs/conventions) et l'[architecture](/docs/architecture), et lisez la [skill pour agents](/docs/tooling/agent-skills) correspondante avant de modifier l'intégration d'un fournisseur. Les agents de code partent de `AGENTS.md` à la racine du dépôt.
4. Placez les tests à côté de leur propriétaire et maintenez le seuil de couverture à <RepositoryFact name="coverageThreshold" unit="percent" />.
5. Exécutez les vérifications ci-dessous.
6. Committez avec un message de [commit conventionnel](/docs/tooling/conventional-commits), ouvrez une pull request avec un titre conventionnel et remplissez son modèle.

```sh
bun run check
bun run test:coverage
bun run build:test
bun run test:e2e:install
bun run test:e2e:pr
```

`build:test` exécute le build Cloudflare complet, que `check` et les tests unitaires ne sollicitent pas. `test:e2e:pr` construit et sert le Worker de test lorsqu'aucun serveur ne tourne, puis exécute chaque spec dans Chromium, comme le fait la CI des pull requests. Exécutez aussi la suite complète de tests dans le navigateur (`bun run test:e2e`) pour les modifications qui peuvent se comporter différemment dans WebKit. Validez séparément les intégrations réelles avec les fournisseurs lorsque vous modifiez leur configuration.

Lorsque le comportement change, mettez à jour `content/docs` dans toutes les langues ; `bun run check:i18n` rejette les traductions manquantes, ainsi que les blocs de code et la navigation qui diffèrent. Le modèle de pull request comprend un résumé, un plan de test avec les vérifications ci-dessus et la liste de la documentation mise à jour ; décrivez-y le comportement obtenu, la façon dont vous l'avez vérifié et tout flux de démonstration ou inachevé qu'elle laisse en place.

`CONTRIBUTING.md`, à la racine du dépôt, est la version courte de cette page, et `SUPPORT.md` indique où obtenir de l'aide. Toutes les personnes qui participent respectent `CODE_OF_CONDUCT.md`, le Contributor Covenant 2.1. Signalez les vulnérabilités de sécurité en privé, comme le décrit `SECURITY.md`, jamais dans une issue publique.
