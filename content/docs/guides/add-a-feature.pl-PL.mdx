title: "Dodawanie funkcji"

---

Nowa funkcja zwykle obejmuje każdą warstwę: moduł tabeli, jego przypadki użycia, trasę, komponenty prezentacji, komunikaty i testy. Kategorie produktów pokazują całą ścieżkę: `src/modules/category`, zakładkę kategorii w `src/routes/admin.products.index.tsx` oraz `src/presentation/components/custom/admin/products/category-columns.tsx`.

## 1. Zamodeluj dane

Jeśli funkcja zapisuje nowe dane, dodaj moduł dla jej tabeli i wygeneruj migrację.

- [Dodawanie modułu](/docs/guides/add-a-module)
- [Migracje bazy danych](/docs/guides/database-migrations)

## 2. Ustal, kto może co robić

Dodaj nowe akcje do `APP_STATEMENTS` w `src/integrations/better-auth/auth.access.ts` i przypisz je do ról.

- [Role i uprawnienia](/docs/guides/roles-and-permissions)

## 3. Napisz operacje

Dodaj po jednym przypadku użycia na operację, z middleware, walidatorem, handlerem oraz opcjami zapytania lub mutacji.

- [Dodawanie przypadku użycia](/docs/guides/add-a-use-case)
- [Funkcje serwerowe](/docs/guides/server-functions)

## 4. Dodaj trasę

1. Dodaj ścieżkę do `ROUTES` w `src/routes.ts`.
2. Utwórz płaski plik trasy dla danego obszaru: `src/routes/admin.<feature>.tsx` pod layoutem panelu administracyjnego, `src/routes/app.<feature>.tsx` pod layoutem zalogowanego klienta albo `src/routes/_landing.<page>.tsx` dla strony publicznej.
3. Zachowaj konwencję tras: `const NAMESPACE`, `staticData: { namespaces: [NAMESPACE] }`, `head: pageHead(ROUTES.X)`, loader, który wczytuje metadane, komunikaty i dane w jednym `Promise.all`, oraz własny szkielet strony jako `pendingComponent`, zarejestrowany w mapie szkieletu jej layoutu (zobacz [Szkielety ładowania](/docs/architecture/delivery-layer#loading-skeletons)).
4. Strażnik `beforeLoad` layoutu (`requireAdmin` dla `/admin`, `requireSignedIn` dla `/app`) chroni stronę. Funkcje serwerowe i tak autoryzują każde wywołanie samodzielnie.

- [Dodawanie strony panelu administracyjnego](/docs/guides/add-an-admin-page)
- [Stan w adresie URL](/docs/guides/url-state)

## 5. Zbuduj interfejs

Umieść widżety, okna dialogowe, formularze i kolumny tabel w `src/presentation/components/custom/<area>/<feature>/`, po jednym w pliku. Każdy komponent sam odczytuje swoje tłumaczenia i dane; trasa tylko je składa.

- [Dodawanie tabeli danych](/docs/guides/add-a-data-table)
- [Formularze i walidacja](/docs/guides/forms-and-validation)

## 6. Dodaj komunikaty

Utwórz przestrzeń nazw strony, a w razie potrzeby także przestrzeń nazw walidacji, we wszystkich dziewięciu językach. Przestrzenie nazw stron wymagają `metadata.title` i `metadata.description`.

- [Internacjonalizacja i języki](/docs/guides/i18n-messages)
- [Szablony e-maili](/docs/guides/email-templates), jeśli funkcja wysyła e-maile

## 7. Przetestuj i zweryfikuj

Pokryj testami przypadki użycia, komponenty i trasę, a następnie uruchom pełne kontrole:

```sh
bun run check
bun run test:coverage
bun run build
bun run test:e2e:smoke
```

- [Pisanie testów](/docs/guides/writing-tests)
- [Lista kontrolna bezpieczeństwa](/docs/guides/security-checklist)
