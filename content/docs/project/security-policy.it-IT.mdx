Questa politica copre saasyland.com, compresi l'area cliente e la console di amministrazione, il codice di questo repository e la CLI a pagamento con i suoi pacchetti: `saasyland`, `create-saasyland` e `@saasyland/stack`. `SECURITY.md`, nella radice del repository, dice lo stesso.

## Segnalare una vulnerabilità [#report]

Non segnalare mai una vulnerabilità in una issue, una pull request o un commento pubblici. Segnalala in privato, in uno di questi due modi:

- con la [segnalazione privata delle vulnerabilità](https://github.com/saasyland/saasyland.com/security/advisories/new) di GitHub;
- via email a hello@saasyland.com.

Indica cosa è coinvolto (un URL, una route, una funzione server, un file o un comando della CLI), i passaggi per riprodurre il problema o un proof of concept, l'impatto (cosa può leggere, modificare o fare un attaccante) e il commit o la release che hai provato. Scrivi in inglese o in polacco.

Il sito pubblica lo stesso contatto in <RepositoryFact name="securityTxtPath" />, nel formato della RFC 9116, con le lingue <RepositoryFact name="securityTxtLanguages" /> e un link a questa pagina. La build scrive il file a partire da `src/lib/security-txt.ts`, e `security-txt.test.ts` fallisce quando la sua data `Expires` è passata o cade a più di un anno, così il file viene rinnovato prima che diventi obsoleto.

## Cosa succede dopo la segnalazione [#after-you-report]

Sono obiettivi, non garanzie:

1. **Conferma di ricezione.** Ricevi una risposta entro <RepositoryFact name="securityAcknowledgeWorkingDays" /> giorni lavorativi.
2. **Valutazione.** Entro <RepositoryFact name="securityAssessWorkingDays" /> giorni lavorativi confermiamo o respingiamo il problema, ne valutiamo la gravità e, se è confermato, pianifichiamo la correzione.
3. **Correzione.** La correzione arriva in ogni versione supportata qui sotto, e ti teniamo aggiornato finché non viene rilasciata.
4. **Divulgazione.** Quando la correzione è disponibile, pubblichiamo un avviso di sicurezza su GitHub che indica le versioni corrette e ti riconosce la scoperta, a meno che tu preferisca non comparire.

Concedici un tempo ragionevole per correggere un problema confermato prima di divulgarlo.

## Versioni supportate [#supported-versions]

| Versione                                                                                                                         | Supportata |
| -------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| saasyland.com e `main`                                                                                                           | Sì         |
| L'ultima release datata del sito                                                                                                 | Sì         |
| L'ultima release di `saasyland`, `create-saasyland` e `@saasyland/stack` sul tag npm <RepositoryFact name="cliReleaseChannel" /> | Sì         |
| Release e commit precedenti                                                                                                      | No         |

Ciò che viene unito in `main` viene distribuito su saasyland.com quando la CI passa, quindi una correzione arriva prima sul sito ([CI/CD](/docs/tooling/ci-cd)). La CLI e i suoi pacchetti escono insieme con un'unica versione, e una correzione esce come nuova release su npm, indicata nelle [note di rilascio](/docs/cli/releases). Se usi una release precedente, aggiorna all'ultima per ricevere la correzione.

## Ambito [#scope]

Nell'ambito: saasyland.com, compresi l'area cliente e la console di amministrazione, il codice di questo repository, la CLI a pagamento, le chiavi di licenza e le attivazioni, e il codice che la CLI genera.

Fuori ambito: vulnerabilità nei servizi di terzi come Cloudflare, Polar e Resend, a meno che non le causi la nostra configurazione, e output di scanner senza un impatto dimostrato.

## Regolamento UE sulla ciberresilienza [#cyber-resilience-act]

SaaSy Land notifica le vulnerabilità attivamente sfruttate e gli incidenti gravi che riguardano i suoi prodotti tramite la piattaforma unica di segnalazione dell'UE (Single Reporting Platform), come richiede il regolamento sulla ciberresilienza (regolamento (UE) 2024/2847).
