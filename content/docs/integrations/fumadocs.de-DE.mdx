---
title: "Fumadocs"
description: "MDX-Collections für Docs und Blog, lokalisierte Quellen und Suche."
---

Fumadocs macht aus `content/docs` und `content/blog` lokalisierte Seitenbäume. `bun run content` führt `fumadocs-mdx` aus und schreibt `.source/`; `dev`, `typegen` und jedes Build-Skript führen es zuerst aus. Beide Collections sind `async`: Der Worker hält das Frontmatter jeder Seite bereit und importiert das kompilierte MDX einer Seite mit `page.data.load()`, wenn eine Anfrage deren Überschriften oder Suchtext braucht (siehe [Performance](/docs/conventions/performance#keep-the-route-tree-light)).

| Datei                   | Zweck                                                                                                                                                                                                                                  |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `fumadocs.config.ts`    | Die Collections `docs` und `blog`, beide `async`, das Frontmatter-Schema des Blogs sowie die Themes und Farbersetzungen der Syntaxhervorhebung                                                                                         |
| `fumadocs.i18n.ts`      | Die Sprachen aus `I18N`, `en-US` als Standard und Fallback, der `dot`-Parser für `<slug>.<locale>.mdx`, ausgeblendetes Sprachpräfix                                                                                                    |
| `fumadocs.source.ts`    | `source` unter `/docs` mit den Icons von `docsIcon`, `blogSource` unter `/blog`, `getPublishedBlogPages` und `getPublishedBlogPosts` mit Lesezeit                                                                                      |
| `fumadocs.icons.ts`     | `DOCS_ICONS`, die Lucide-Icons, die die Meta-Dateien nennen, und `docsIcon`, das das `icon` einer Meta-Datei in sein Icon umwandelt                                                                                                    |
| `fumadocs.docs.ts`      | Die Serverfunktion `getDocsPage`, `loadDocsPage` und `docsHead` für die Route `docs.$`                                                                                                                                                 |
| `fumadocs.search.ts`    | Der Suchindex, den `/api/search` ausliefert                                                                                                                                                                                            |
| `fumadocs.changelog.ts` | Das Plugin `changelogEntries`, das `<ChangelogEntries unreleased="…" />` auf der Changelog-Seite durch die Einträge aus `content/changelog` in der Sprache der Seite ersetzt, unter dem UTC-Tag, an dem jeder in `main` angekommen ist |

Das Sprachpräfix ist in Fumadocs-URLs ausgeblendet, weil der Router es hinzufügt. Das Blog-Frontmatter verlangt `title`, `authorName` und `date` und akzeptiert `description`, `excerpt`, `faq`, `featured`, `image`, `published`, `tags`, `updated` und `authorImage`.

## Komponenten

`src/presentation/components/custom/mdx.tsx` ordnet die MDX-Komponenten zu: die Fumadocs-Standards (einschließlich `Cards` und `Callout`), `Accordions`, `Steps` und `Tabs`, die shadcn-Komponenten `Alert`, `Badge`, `Button`, Card-Bausteine, `Separator` und `Table`; `RepositoryFact`, das einen zur Build-Zeit aus dem Repository gemessenen oder im Code definierten Wert ausgibt, etwa `<RepositoryFact name="testFiles" />`, und `RepositoryTable`, das eine aus dem Code erzeugte Tabelle ausgibt, etwa `<RepositoryTable name="commitTypes" columns={["Type", "Emoji"]} />`. `TierPrice` gibt den Listenpreis einer Stufe aus `TIER_PRICES` in der Locale der Seite aus, etwa `<TierPrice tier="core" />`, sodass keine Seite einen Preis von Hand einträgt. `ActivationLimit` gibt das Aktivierungslimit einer Stufe aus `LICENSE_ACTIVATION_LIMITS` aus, etwa `<ActivationLimit tier="core" />`, und `RegionalDiscounts` listet die aus `PPP_TIERS` abgeleiteten Prozentsätze der regionalen Rabatte auf. Interne Links werden mit `localizePathname` lokalisiert, und ein Eintrag einer Aufgabenliste umschließt seine Checkbox und seinen Text mit einem `label`. `docs-content.tsx` und `blog-content.tsx` rendern die Seiten. Die eigenen Bedienelemente von Fumadocs, etwa die Suche, **Auf dieser Seite** und die Kopier-Buttons, beziehen ihre Texte aus dem Namespace `fumadocs`: `useFumadocsI18n` übergibt sie mit der Locale der Seite an den `RootProvider` der Layouts von Dokumentation und Blog.

## Regeln für Inhalte

Jede Seite existiert einmal pro Sprache als `<slug>.<locale>.mdx`, und jeder Ordner hat eine `meta.<locale>.json` mit demselben `pages`-Array in jeder Sprache. `icon` in einer Meta-Datei erwartet den Namen eines Icons aus `DOCS_ICONS`; importiere ein neues Icon dort, und `fumadocs.icons.test.ts` schlägt fehl, wenn eine Meta-Datei eines nennt, das nicht importiert ist, oder wenn ein importiertes nicht mehr genannt wird. `scripts/check-content.ts`, Teil von `bun run check:i18n`, schlägt fehl, wenn eine Übersetzung fehlt, wenn ihre Codeblöcke, ihr Inline-Code, ihre Komponenten, Links, Tabellen oder ihre Navigation vom Englischen abweichen oder wenn in einer anderen Sprache ein englischer Absatz stehen bleibt.
