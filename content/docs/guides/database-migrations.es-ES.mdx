---
title: "Migraciones de base de datos"
description: "Cambia un esquema de Drizzle, genera la migración SQL y aplícala a cada base de datos D1."
---

Cloudflare D1 (SQLite) es la base de datos de la aplicación. Los esquemas de los módulos usan `drizzle-orm/sqlite-core`, `src/integrations/drizzle-orm/drizzle.schemas.ts` los reúne y drizzle-kit escribe las migraciones en `src/integrations/drizzle-orm/migrations/` con un prefijo de marca de tiempo.

## Flujo de trabajo

1. Cambia `<table>.schema.ts`. Si es una tabla nueva, expórtala también desde `drizzle.schemas.ts`.
2. Genera el SQL:

```sh
bun run db:generate
```

3. Revisa el archivo generado y haz commit junto con el cambio de esquema.
4. Aplícalo a la base de datos con la que trabajas. `deploy:preview`, `deploy:production` y la CI lo aplican a la base de datos de la vista previa o de producción antes de desplegar.

## Comandos

| Comando                         | Base de datos                                                                                      |
| ------------------------------- | -------------------------------------------------------------------------------------------------- |
| `bun run db:migrate:local`      | Base de datos local de desarrollo en `.wrangler/state`, usada por `bun run dev`                    |
| `bun run db:reset:local`        | Elimina la base de datos local de desarrollo y después vuelve a migrarla                           |
| `bun run db:migrate:test`       | Base de datos local de pruebas en `.wrangler/test`, usada por Playwright y la vista previa aislada |
| `bun run db:reset:test`         | Elimina `.wrangler/test` y después vuelve a migrar y a sembrar la base de datos local de pruebas   |
| `bun run db:migrate:preview`    | Base de datos remota de la vista previa                                                            |
| `bun run db:migrate:production` | Base de datos remota de producción                                                                 |

`bun run db:migrations:local`, `db:migrations:preview` y `db:migrations:production` enumeran las migraciones que una base de datos aún no ha aplicado. `bun run db:studio:local` abre Drizzle Studio sobre el archivo de la base de datos local. `db:studio:preview` y `db:studio:production` lo abren sobre una base de datos remota, y los scripts `db:introspect:*` la inspeccionan, ambos a través de la API HTTP de D1 con `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID` y `CLOUDFLARE_ACCESS_TOKEN` del archivo de entorno correspondiente. Consulta [Base de datos](/docs/tooling/database).

## Convenciones del esquema

- Las fechas son `integer(..., { mode: "timestamp_ms" })` con el valor por defecto `(unixepoch() * 1000)`. Las tablas obtienen `createdAt` y `updatedAt` con `...timestamps()` de `src/integrations/drizzle-orm/drizzle.columns.ts`.
- Los booleanos son `integer(..., { mode: "boolean" })`.
- Los índices, las restricciones de unicidad, las claves foráneas y las relaciones se quedan en el archivo del esquema.
- D1 no tiene transacciones interactivas. Mantén una operación atómica con una sola sentencia SQL o con `db.batch([...])`, como hacen `getUsers` y el limitador de peticiones.

## Tests

El binding D1 de pruebas aplica cada archivo SQL de la carpeta de migraciones a una base de datos SQLite en memoria, así que los tests que usan D1 se ejecutan contra el esquema migrado. `src/integrations/drizzle-orm/__test__/` comprueba que el esquema, sus índices y sus claves foráneas se materializan. Su `migrations.test.ts` limita la migración que añade las tablas `order` y `subscription` a sentencias `CREATE` para esas tablas y sus índices, y comprueba, en una base de datos migrada hasta la migración anterior, que cada tabla y cada índice que ya existían siguen como estaban. Limita la migración que añade los registros de la licencia a tres sentencias `ALTER TABLE … ADD` de columnas que admiten valores nulos, y comprueba que todas las demás tablas, todos los índices y una licencia existente siguen como estaban, con las columnas nuevas vacías. Limita la migración que añade el contenido de los cursos a un `CREATE TABLE` y un `CREATE INDEX` para `lesson_attachment` seguidos solo de sentencias `ALTER TABLE … ADD` de columnas con valor por defecto, y comprueba que todas las demás tablas e índices y un curso, un capítulo, una lección y un vídeo existentes siguen como estaban, con las columnas nuevas en sus valores por defecto, y que eliminar una lección elimina sus materiales. Consulta [Escribir tests](/docs/guides/writing-tests).

## Datos existentes de PostgreSQL

Estas migraciones solo crean el esquema de SQLite. Mover datos desde una instalación anterior de PostgreSQL requiere una exportación e importación aparte y revisadas.
