title: "Міграції бази даних"
description: "Змініть схему Drizzle, згенеруйте SQL-міграцію й застосуйте її до кожної бази D1."
---

Базою даних застосунку є Cloudflare D1 (SQLite). Схеми модулів використовують `drizzle-orm/sqlite-core`, `src/integrations/drizzle-orm/drizzle.schemas.ts` збирає їх, а drizzle-kit записує міграції в `src/integrations/drizzle-orm/migrations/` з префіксом часової позначки.

## Порядок роботи

1. Змініть `<table>.schema.ts`. Нову таблицю також експортуйте з `drizzle.schemas.ts`.
2. Згенеруйте SQL:

```sh
bun run db:generate
```

3. Перегляньте згенерований файл і закомітьте його разом зі зміною схеми.
4. Застосуйте його до бази, з якою працюєте. `deploy:preview`, `deploy:production` і CI застосовують його до бази попереднього перегляду або продакшн-бази перед розгортанням.

## Команди

| Команда                         | База даних                                                                                                 |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `bun run db:migrate:local`      | Локальна база для розробки в `.wrangler/state`, яку використовує `bun run dev`                             |
| `bun run db:reset:local`        | Видаляє локальну базу для розробки, а потім знову застосовує до неї міграції                               |
| `bun run db:migrate:test`       | Локальна тестова база в `.wrangler/test`, яку використовують Playwright та ізольований попередній перегляд |
| `bun run db:reset:test`         | Видаляє `.wrangler/test`, а потім знову застосовує міграції до локальної тестової бази й наповнює її       |
| `bun run db:migrate:preview`    | Віддалена база попереднього перегляду                                                                      |
| `bun run db:migrate:production` | Віддалена продакшн-база                                                                                    |

`bun run db:migrations:local`, `db:migrations:preview` і `db:migrations:production` показують міграції, які база ще не застосувала. `bun run db:studio:local` відкриває Drizzle Studio на файлі локальної бази. `db:studio:preview` і `db:studio:production` відкривають його на віддаленій базі, а скрипти `db:introspect:*` її аналізують, обидва через HTTP API D1 з `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID` і `CLOUDFLARE_ACCESS_TOKEN` з відповідного файлу середовища. Див. [База даних](/docs/tooling/database).

## Конвенції схеми

- Дати — це `integer(..., { mode: "timestamp_ms" })` з типовим значенням `(unixepoch() * 1000)`. Таблиці отримують `createdAt` і `updatedAt` через `...timestamps()` з `src/integrations/drizzle-orm/drizzle.columns.ts`.
- Булеві значення — це `integer(..., { mode: "boolean" })`.
- Індекси, обмеження унікальності, зовнішні ключі й зв'язки лишаються у файлі схеми.
- D1 не має інтерактивних транзакцій. Зберігайте атомарність операції за допомогою однієї SQL-інструкції або `db.batch([...])`, як це роблять `getUsers` і обмежувач запитів.

## Тести

Тестова прив'язка D1 застосовує кожен SQL-файл із теки міграцій до бази SQLite в пам'яті, тож тести, що використовують D1, працюють зі схемою після міграцій. `src/integrations/drizzle-orm/__test__/` перевіряє, що схема, її індекси й зовнішні ключі створюються коректно. Її файл `migrations.test.ts` обмежує міграцію, що додає таблиці `order` і `subscription`, інструкціями `CREATE` для цих таблиць та їхніх індексів і на базі, мігрованій до попередньої міграції, перевіряє, що кожна раніша таблиця й кожен індекс лишаються такими, як були. Він також обмежує міграцію, що додає записи ліцензії, трьома інструкціями `ALTER TABLE … ADD` для стовпців, які допускають NULL, і перевіряє, що кожна інша таблиця, кожен індекс та наявна ліцензія лишаються такими, як були, а нові стовпці — порожніми. Він також обмежує міграцію, що додає вміст курсів, одним `CREATE TABLE` і одним `CREATE INDEX` для `lesson_attachment`, за якими йдуть лише інструкції `ALTER TABLE … ADD` для стовпців зі значеннями за замовчуванням, і перевіряє, що кожна інша таблиця й кожен індекс, а також наявні курс, розділ, урок і відео лишаються такими, як були, а нові стовпці мають значення за замовчуванням, і що видалення уроку видаляє його матеріали. Він також обмежує міграцію, що записує перший платний урок, двома інструкціями `ALTER TABLE … ADD` для стовпців `license`, які допускають NULL, і перевіряє, що кожна інша таблиця, кожен індекс та наявна ліцензія лишаються такими, як були, а нові стовпці — порожніми. Див. [Написання тестів](/docs/guides/writing-tests).

## Наявні дані PostgreSQL

Ці міграції створюють лише схему SQLite. Перенесення даних із попередньої інсталяції PostgreSQL потребує окремих, перевірених експорту й імпорту.
