Jede neue Tabelle wird über `DataGrid` in `src/presentation/components/custom/data-grid.tsx` gerendert ([Datenraster](/docs/ui/data-grid)). Es bringt die Suche, die Filter, die Sortierung, das Layout, das jeder Admin umstellen und behalten kann, die Auswahl, den CSV-Export, Skeleton-Zeilen und die Leerzustände mit. Eine Tabelle braucht einen Spalten-Hook und ein `<DataGrid />`. `/admin/orders` ist das vollständige Beispiel: `src/presentation/components/custom/admin/payments/order-columns.tsx` und `src/routes/admin.orders.index.tsx`.

## 1. Den Spalten-Hook schreiben

`<entity>-columns.tsx` neben den anderen Widgets der Seite anlegen. Einen Hook exportieren, der die Übersetzungen und die Daten liest, die die Filter anbieten, und die Spalten memoisiert zurückgibt. Zellen sind kleine Komponenten in derselben Datei, die ihre eigenen Übersetzungen lesen. Gekürzt aus `order-columns.tsx`:

```tsx
const columnHelper = createColumnHelper<DataGridFeatures, OrderRow>()

export const useOrderColumns = (): DataGridColumn<OrderRow>[] => {
  const t = useTranslations()

  const { products } = useSuspenseQuery(orderFiltersQuery).data

  return useMemo(
    () =>
      columnHelper.columns([
        columnHelper.accessor("placedAt", {
          cell: PlacedCell,
          header: t("pages.admin.orders.table.headers.placedAt"),
          meta: { filter: { kind: DATA_GRID_FILTER.DATE_RANGE }, pinned: DATA_GRID_PIN.START },
          size: ORDER_COLUMN_SIZES.placedAt,
        }),
        columnHelper.accessor("description", {
          cell: ProductCell,
          enableSorting: false,
          header: t("pages.admin.orders.table.headers.product"),
          id: "product",
          meta: { filter: { kind: DATA_GRID_FILTER.MULTI_SELECT, options: products.map(({ id, name }) => ({ label: name, value: id })) } },
          size: ORDER_COLUMN_SIZES.product,
        }),
        columnHelper.accessor("refunded", {
          cell: RefundedCell,
          header: t("pages.admin.orders.table.headers.refundedAmount"),
          id: "refundedAmount",
          meta: { export: ({ refunded }) => exportedMoney(refunded), hidden: true },
          size: ORDER_COLUMN_SIZES.refundedAmount,
        }),
      ]),
    [products, t],
  )
}
```

- Zeilen müssen eine `id` vom Typ String haben; sie wird zur Zeilen-ID für die Auswahl.
- `header` ist die übersetzte Beschriftung als String. Das Raster verwendet sie in der Kopfzeile, den Menüs, den Filter-Chips, seinen Ansagen und der CSV.
- `meta.filter` gibt der Spalte einen Filter einer Art: <RepositoryFact name="dataGridFilterKinds" />. Eine Auswahl listet ihre `options` als `{ label, value }`.
- `meta.hidden` blendet die Spalte aus, bis der Admin sie einblendet, `meta.pinned` heftet sie am `start` oder am `end` an, und `meta.export` schreibt den CSV-Text der Spalte für eine Zeile.
- `size` ist die Anfangsbreite in Pixeln. Die Größen in einer Konstante in `src/data/<area>.ts` halten, etwa `ORDER_COLUMN_SIZES` in `payments.ts`, damit auch das Skeleton der Route sie verwenden kann.
- Eine Spalte, nach der der Server nicht sortieren kann, setzt `enableSorting: false`.

## 2. Rendern

Die Spalten, eine eindeutige `id`, das `label` der Tabelle und entweder `data` oder `query` übergeben:

```tsx
const OrdersPage = (): JSX.Element => {
  const t = useTranslations("pages.admin.orders")
  const columns = useOrderColumns()

  return (
    <DataGrid
      columns={columns}
      empty={t("empty")}
      id={ORDER_GRID_ID}
      label={t("title")}
      query={(request) => getOrdersPageQuery(orderZodSchemas.getOrders.parse(request))}
      search={t("filters.search")}
      selectable
    />
  )
}
```

Mit `data` sucht, filtert, sortiert und paginiert das Raster die Zeilen im Browser. Mit `query` sendet es `{ filters, pageIndex, pageSize, search, sorting }`, und der Server erledigt all das.

## 3. Die Anfrage auf dem Server lesen

Das Zod-Schema des Moduls nimmt die Anfrage so, wie sie ist. `filters` enthält die gefilterten Spalten nach ID mit den Werten, die unter [Datenraster](/docs/ui/data-grid#filters) beschrieben sind, also verwendet das Schema die gemeinsamen Felder wieder, aus `src/modules/order/order.zod.ts`:

```ts
const orderFilters = zod.object({
  country: zod.array(countryCodeField).max(COUNTRY_CODES.length).optional(),
  customer: searchField.optional(),
  discount: idField.optional(),
  placedAt: dateRangeField.optional(),
  product: zod.array(idField).max(MAX_FILTER_VALUES).optional(),
  status: zod.array(choiceOf(ORDER_STATUSES)).max(ORDER_STATUSES.length).optional(),
  totalAmount: numberRangeField.optional(),
})

const getOrders = paginationSchema.extend({
  filters: orderFilters.default({}),
  search: searchField.default(""),
  sorting: sortingOf(ORDER_SORT_COLUMNS),
})
```

`numberRangeField`, `dateRangeField` und die Grenzen `SEARCH_MAX_LENGTH`, `MAX_SORTED_COLUMNS` und `MAX_FILTER_VALUES` stammen aus `src/modules/_core/utils/`, dieselben Werte, die das Raster verwendet, sodass das Suchfeld <RepositoryFact name="dataGridSearchMaxLength" /> Zeichen zulässt und das Raster nach bis zu <RepositoryFact name="dataGridMaxSortedColumns" /> Spalten sortiert. `getOrders` übersetzt jeden Filter in SQL; ein Bereich von Geldbeträgen vergleicht jede Bestellung mit `inMinorUnits` in ihrer eigenen Währung.

Die erste Seite im Route-Loader mit `context.queryClient.query({ ...getOrdersQuery, staleTime: "static" })` vorab laden; die erste Anfrage des Rasters wird zum selben Query-Key geparst.

## 4. Im Skeleton spiegeln

Das `pendingComponent` der Route rendert `DataGridPending` aus `data-grid-pending.tsx` mit einem Zellen-Skeleton und einer Breite pro sichtbarer Spalte, so wie `AdminOrdersPending` in `payments-pending.tsx`.

## 5. Messages

Werkzeugleiste, Filter, Menüs, Paginierung, Auswahl und Leerzustände des Rasters stammen aus `components.custom.data-grid`, das jede Seite lädt. Spaltenbeschriftungen, Filteroptionen und die Leermeldung gehören in den Seiten-Namespace, etwa `pages.admin.orders`.

Nachdem eine Mutation die Zeilen geändert hat, die Query-Keys des Moduls invalidieren; das Raster lädt die aktuelle Seite neu. Siehe [Use Case hinzufügen](/docs/guides/add-a-use-case).
