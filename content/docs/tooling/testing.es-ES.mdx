Vite+ ejecuta Vitest con la configuración de `vite.config.ts`. Las pruebas se encuentran en una carpeta `__test__` junto al código que cubren e importan su API desde `vite-plus/test`.

| Proyecto      | Archivos                                                     | Entorno                                |
| ------------- | ------------------------------------------------------------ | -------------------------------------- |
| `node`        | `*.test.ts` y `*.test.tsx`, excepto los dos tipos siguientes | Node                                   |
| `integration` | `*.integration.test.ts`                                      | Node, tiempos de espera de 20 segundos |
| `component`   | `*.component.test.tsx`                                       | jsdom                                  |

```sh
bun run test
bun run test:unit
bun run test:integration
bun run test:component
bun run test:watch
bun run test:changed
bun run test:coverage
```

Use `bun run test`, no `bun test`: el ejecutor de pruebas propio de Bun ignora los proyectos, los entornos y el archivo de configuración inicial de Vitest.

## Plataforma de pruebas

`src/platform/testing/` contiene la infraestructura compartida; todo lo demás se ubica junto a su propietario.

- `setup.ts` registra los matchers de jest-dom y los hooks compartidos.
- `mocks/cloudflare.ts` sustituye a `cloudflare:workers`: D1 es una base de datos `node:sqlite` en memoria que aplica todas las migraciones del repositorio, y KV es un mapa en memoria.
- `lib/server-function.ts` llama a las funciones de servidor a través del pipeline real de middleware y validación de TanStack.
- `lib/render.tsx` renderiza componentes con un QueryClient y un router reales.
- `mocks/providers.ts` intercepta las solicitudes a Resend y a Polar. Solo lo instala el Worker de pruebas de Playwright (`worker.ts`).

Las llamadas externas de correo electrónico, OAuth y pagos nunca salen del proceso de pruebas.

## Cobertura

`bun run test:coverage` exige un 100 % de líneas, sentencias, funciones y ramas para `src/**/*.{ts,tsx}`. Quedan excluidos las pruebas, las carpetas `__test__`, los archivos de declaración, `src/routeTree.gen.ts`, las primitivas de shadcn y `src/platform/testing/`. Los informes se escriben en `coverage/` como texto, HTML y `coverage-summary.json`. Cubra el comportamiento real y elimine las ramas que nunca pueden ejecutarse en lugar de sustituir globales para alcanzarlas. CI ejecuta el umbral de cobertura en cada pull request.
