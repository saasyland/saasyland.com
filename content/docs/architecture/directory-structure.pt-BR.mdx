## Regras de organização

- **Arquivos e pastas usam kebab-case.** Os testes ficam em uma pasta irmã `__test__`.
- **Rotas apenas compõem.** Um arquivo de rota define o componente de página ou de layout, `NAMESPACE` ou `NAMESPACES`, o loader e o `head`. Ele não contém widgets, diálogos nem definições de colunas.
- **Módulos são tabelas do banco de dados.** Crie `src/modules/<name>` apenas para uma tabela real. Uma server function que não trabalha com uma tabela vai para `src/lib` (por exemplo, `src/lib/github.ts`) ou, se uma única rota a usa, para o arquivo dessa rota.
- **Componentes compartilhados ficam no nível plano.** Um componente usado em várias áreas é um único arquivo diretamente em `presentation/components/custom`.
- **Pastas de área e de página.** Componentes usados por uma única área ficam em `admin/`, `app/`, `auth/`, `blog/` ou `landing-page/`. As páginas do admin têm pasta própria, como `admin/users/` ou `admin/settings/`. A landing page se divide em `sections/` (um arquivo por seção da página) e `components/` (partes compartilhadas entre as seções).
- **Um widget, diálogo, formulário ou conjunto de colunas por arquivo.** Não divida um componente em um wrapper e um arquivo `-content`.
- **Sem pastas auxiliares aninhadas.** Pastas de componentes nunca contêm subpastas `components/`, `constants/`, `hooks/`, `lib/` ou `types/`, e nenhum arquivo auxiliar `.ts` fica ao lado de um componente. Uma constante usada por um único componente permanece no arquivo desse componente.
- **Dados compartilhados vão para `src/data`.** Exemplos: os grupos da barra lateral do admin, `MARKETING_SECTION_IDS`, a navegação do app, as opções da CLI e as linhas de demonstração.
- **Arquivos gerados não são editados à mão.** O plugin do router escreve `src/routeTree.gen.ts`, `bun run cf-typegen` escreve `src/types/worker-configuration.d.ts`, e `bun run content` e `bun run generate:cn` escrevem `.source/`.
