title: "Add a data grid"
description: "Write a columns hook with filters, hidden and pinned columns and CSV values, then render it with DataGrid from client-side rows or a server query."
---

Every new table renders through `DataGrid` in `src/presentation/components/custom/data-grid.tsx` ([Data grid](/docs/ui/data-grid)). It brings the search, the filters, sorting, the layout each admin can rearrange and keep, selection, CSV export, skeleton rows and the empty states. A table needs a columns hook and one `<DataGrid />`. `/admin/orders` is the complete example: `src/presentation/components/custom/admin/payments/order-columns.tsx` and `src/routes/admin.orders.index.tsx`.

## 1. Write the columns hook

Create `<entity>-columns.tsx` beside the page's other widgets. Export a hook that reads the translations and the data the filters offer, and returns the columns memoised. Cells are small components in the same file that read their own translations. Condensed from `order-columns.tsx`:

```tsx
const columnHelper = createColumnHelper<DataGridFeatures, OrderRow>()

export const useOrderColumns = (): DataGridColumn<OrderRow>[] => {
  const t = useTranslations()

  const { products } = useSuspenseQuery(orderFiltersQuery).data

  return useMemo(
    () =>
      columnHelper.columns([
        columnHelper.accessor("placedAt", {
          cell: PlacedCell,
          header: t("pages.admin.orders.table.headers.placedAt"),
          meta: { filter: { kind: DATA_GRID_FILTER.DATE_RANGE }, pinned: DATA_GRID_PIN.START },
          size: ORDER_COLUMN_SIZES.placedAt,
        }),
        columnHelper.accessor("description", {
          cell: ProductCell,
          enableSorting: false,
          header: t("pages.admin.orders.table.headers.product"),
          id: "product",
          meta: { filter: { kind: DATA_GRID_FILTER.MULTI_SELECT, options: products.map(({ id, name }) => ({ label: name, value: id })) } },
          size: ORDER_COLUMN_SIZES.product,
        }),
        columnHelper.accessor("refunded", {
          cell: RefundedCell,
          header: t("pages.admin.orders.table.headers.refundedAmount"),
          id: "refundedAmount",
          meta: { export: ({ refunded }) => exportedMoney(refunded), hidden: true },
          size: ORDER_COLUMN_SIZES.refundedAmount,
        }),
      ]),
    [products, t],
  )
}
```

- Rows must have a string `id`; it becomes the row id for selection.
- `header` is the translated label as a string. The grid uses it in the header, the menus, the filter chips, its announcements and the CSV.
- `meta.filter` gives the column a filter of one kind: <RepositoryFact name="dataGridFilterKinds" />. A choice lists its `options` as `{ label, value }`.
- `meta.hidden` hides the column until the admin shows it, `meta.pinned` pins it to the `start` or the `end`, and `meta.export` writes the column's CSV text for a row.
- `size` is the starting width in pixels. Keep the sizes in one constant in `src/data/<area>.ts`, such as `ORDER_COLUMN_SIZES` in `payments.ts`, so the route's skeleton can use them too.
- A column the server cannot sort by sets `enableSorting: false`.

## 2. Render it

Pass the columns, a unique `id`, the table's `label` and either `data` or `query`:

```tsx
const OrdersPage = (): JSX.Element => {
  const t = useTranslations("pages.admin.orders")
  const columns = useOrderColumns()

  return (
    <DataGrid
      columns={columns}
      empty={t("empty")}
      id={ORDER_GRID_ID}
      label={t("title")}
      query={(request) => getOrdersPageQuery(orderZodSchemas.getOrders.parse(request))}
      search={t("filters.search")}
      selectable
    />
  )
}
```

With `data`, the grid searches, filters, sorts and pages the rows in the browser. With `query`, it sends `{ filters, pageIndex, pageSize, search, sorting }` and the server does all of it.

## 3. Read the request on the server

The module's Zod schema takes the request as it is. `filters` holds the filtered columns by id with the values described in [Data grid](/docs/ui/data-grid#filters), so the schema reuses the shared fields: from `src/modules/order/order.zod.ts`:

```ts
const orderFilters = zod.object({
  country: zod.array(countryCodeField).max(COUNTRY_CODES.length).optional(),
  customer: searchField.optional(),
  discount: idField.optional(),
  placedAt: dateRangeField.optional(),
  product: zod.array(idField).max(MAX_FILTER_VALUES).optional(),
  status: zod.array(choiceOf(ORDER_STATUSES)).max(ORDER_STATUSES.length).optional(),
  totalAmount: numberRangeField.optional(),
})

const getOrders = paginationSchema.extend({
  filters: orderFilters.default({}),
  search: searchField.default(""),
  sorting: sortingOf(ORDER_SORT_COLUMNS),
})
```

`numberRangeField`, `dateRangeField` and the limits `SEARCH_MAX_LENGTH`, `MAX_SORTED_COLUMNS` and `MAX_FILTER_VALUES` come from `src/modules/_core/utils/`, the same values the grid uses, so the search box allows <RepositoryFact name="dataGridSearchMaxLength" /> characters and the grid sorts by up to <RepositoryFact name="dataGridMaxSortedColumns" /> columns. `getOrders` turns each filter into SQL; a range in money compares each order in its own currency with `inMinorUnits`.

Prefetch the first page in the route loader with `context.queryClient.query({ ...getOrdersQuery, staleTime: "static" })`; the grid's first request parses to the same query key.

## 4. Mirror it in the skeleton

The route's `pendingComponent` renders `DataGridPending` from `data-grid-pending.tsx` with one cell skeleton and width per visible column, as `AdminOrdersPending` does in `payments-pending.tsx`.

## 5. Messages

The grid's toolbar, filters, menus, pagination, selection and empty states come from `components.custom.data-grid`, which every page loads. Column labels, filter options and the empty message belong to the page namespace, such as `pages.admin.orders`.

After a mutation changes the rows, invalidate the module's query keys; the grid refetches the current page. See [Add a use case](/docs/guides/add-a-use-case).
