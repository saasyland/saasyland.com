- Fixed: a docs sidebar link pressed after the layout had hydrated but before the page content had could make React report a hydration mismatch. The content then hydrated while the router loaded the next page, and Fumadocs' TanStack adapter gave its previous and next links the pathname of the page being loaded, so they named the next page's neighbours where the server had rendered the current page's. A Bun patch to `fumadocs-core` 16.19.0 makes `usePathname` return the resolved location while the router loads, and the docs pages render their MDX in a `<Suspense>` keyed by the page, so a page the router has already left is replaced instead of hydrated with the next page's data. `navigation.spec.ts` holds the page's MDX and the next page's until the content has rendered and checks its links, in Chromium and WebKit. See [Fumadocs](/docs/integrations/fumadocs).
