## Theme selection

`THEME` in `src/presentation/theme/index.ts` defines the themes `light`, `dark` and `system` (the default) and the cookie `saasyland.com_theme`. The app uses `@wrksz/themes`:

- `ThemeScript` in the `head` of the root document (`src/routes/__root.tsx`) reads the cookie and sets the theme class before the first paint, so there is no flash.
- `ThemeProvider` (`src/providers/theme-provider.tsx`) starts from the cookie (`getStoredTheme`), stores changes in the cookie and keeps every `ThemeProvider` in the same document in sync (`enableSameDocumentSync`). It does not sync other tabs.
- `ThemeProvider` wraps only the widgets that read or change the theme: the root `Toaster` and the `ThemeSwitch` in the docs sidebar. It never wraps a route `Outlet`, because a provider that updates after hydration would re-render the whole page.

```tsx
const RootComponent = () => (
  <AriaProvider>
    <OfflineBanner />
    {ROOT_COMPONENTS.map(({ component: Component, key }) => (
      <Component key={key} />
    ))}
    <Outlet />
    <ThemeProvider>
      <Toaster />
    </ThemeProvider>
  </AriaProvider>
)
```

`/admin`, `/app` and `/docs` follow the stored theme; the only theme switch is in the docs sidebar. The `_site` layout adds the `dark` class to its wrapper while a matched route sets `dark: true` in its `staticData`, as the `_marketing` layout of the landing, legal, blog and course pages does, and the auth layout adds it to its own wrapper; these pages always render dark. `globals.css` also gives `html` the dark tokens while one of these wrappers is a direct child of `body` (`:root:has(> body > .dark)`), so the window around the page, behind the scrollbar included, is dark in the light theme too.

## Tokens

`src/presentation/styles/globals.css` defines the shadcn tokens as OKLCH variables in `:root` (light) and `.dark`: `background`, `foreground`, `card`, `popover`, `primary`, `secondary`, `muted`, `accent`, `destructive`, `border`, `input`, `ring`, `chart-1` to `chart-5`, the `sidebar-*` set and `radius`. The brand accent is `ring`: it colours focus rings, active states and highlights, and matches `chart-1`. `dark:` utilities follow the class:

```css
@custom-variant dark (&:is(.dark *));
```

`@theme inline` maps the variables to Tailwind colours, sets the font families and defines the type scale. `globals.css` also imports the Fumadocs UI styles, so the docs use the same tokens.

## Scrollbars

The window keeps room for its scrollbar on every page, so the content stays in place when a page is too short to scroll, when it grows and when a dialog, popover or menu stops the page from scrolling. `globals.css` sets `scrollbar-gutter: stable` on `html`, next to the thin page scrollbar: browsers style the window's scrollbar from the `scrollbar-color` and `scrollbar-width` of `html`, never of `body`.

```css
html {
  scroll-behavior: smooth;
  scroll-padding-top: var(--spacing-header);
  scrollbar-color: color-mix(in oklab, var(--foreground) 20%, transparent) transparent;
  scrollbar-gutter: stable;
  scrollbar-width: thin;
}
html:has([data-page-scroller]) {
  scrollbar-gutter: auto;
}
[data-page-scroller] {
  scrollbar-gutter: stable;
}
```

`/app` and `/admin` fill the window and scroll their content area instead, so that element carries `data-page-scroller`, in the layouts and in their loading skeletons alike: the room moves there, and the workspace takes the full width of the window. React Aria's `usePreventScroll` and Base UI, which runs the docs search, also keep the page still with `scrollbar-gutter: stable` rather than with padding, so nothing makes up for the room twice. Fixed layers such as the header, the page frame and the back-to-top button are placed in the window without that room and line up with the content, and the scrollbar's track is transparent, so the room shows the page's own background.

## Type scale

Use the named text utilities instead of raw sizes: `text-display-hero`, `text-display-gate`, `text-display-blast`, `text-headline-peak`, `text-headline-support`, `text-price`, `text-title`, `text-statement`, `text-lead`, `text-body`, `text-body-sm`, `text-spec` and `text-label`. Each sets size, line height, letter spacing and, for headings, weight. `src/lib/cn.config.ts` registers them so `cn` keeps them when merging classes; `bun run generate:cn` rebuilds the lookup tables.

## Page titles and calls to action

The content pages, which are the blog index, the course catalogue, the newsletter pages, the legal pages and the not-found page, open with `ContentPage` (`src/presentation/components/custom/content-page.tsx`): the `h1` in `text-headline-peak` and the lead in `text-lead`, at the same distance below the site header on every page, and `ContentPagePending` draws the same block in their skeletons. Blog posts keep the larger `text-display-gate` for the article title. Calls to action on the public pages use `CTA_CLASSES.PRIMARY` or `CTA_CLASSES.SECONDARY` from `src/data/cta.ts`, so every one has the same height (`h-11`), padding and type; `BackHomeLink` is the primary one back to `/`, labelled from `common.backHome`, on the not-found page and the newsletter pages.

## Route stylesheets

`docs.css` holds the `typeset` prose styles for docs and blog articles. It is plain CSS, loaded by the `/docs` and `/blog` layouts as a `?url` stylesheet link. Route stylesheets must not run a second Tailwind build.
