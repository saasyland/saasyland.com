- Modificato: una richiesta di bundle all’API delle licenze della CLI legge l’header dell’archivio della release in R2 invece dell’archivio. Lo SHA-256 dell’archivio ora lo accompagna come metadato personalizzato `sha256`, che `bundle:upload` del repository della CLI scrive, quindi il Worker non scarica, decomprime e calcola più l’hash dell’intero bundle a ogni richiesta: con il bundle attuale da 1,7 MB una richiesta richiedeva circa 31 ms di CPU nel Worker di test locale e ora circa 3 ms, per quanto grande diventi il bundle. Un oggetto senza digest risponde `serviceUnavailable`, e il log lo indica. `bun run db:reset:test` popola il bundle locale con il suo digest tramite `getPlatformProxy` di Wrangler, perché `wrangler r2 object put` non può impostare metadati personalizzati. Vedi [Bundle di template](/docs/features/cli-licence-api#template-bundles) e [Pubblicare i bundle](/docs/features/cli-licence-api#publishing-bundles).
