O SaaSy Land é uma única aplicação TanStack Start que roda como um Cloudflare Worker. O código é dividido por responsabilidade:

- **Rotas** (`src/routes`) compõem páginas. Um arquivo de rota declara seus namespaces de tradução, o guard, o loader e as tags de head, e depois renderiza componentes.
- **Módulos** (`src/modules/<table>`) existem apenas para tabelas reais do banco de dados. Um módulo é dono do schema Drizzle da tabela, dos schemas Zod, das constantes, dos tipos e dos casos de uso que leem ou alteram essa tabela.
- **Integrações** (`src/integrations/<vendor>`) configuram bibliotecas e serviços de terceiros.
- **Apresentação** (`src/presentation`) reúne os primitivos do shadcn, os componentes da aplicação, os templates do React Email, os estilos, o tema e a identidade visual.
- **Código compartilhado** fica em `src/data` (dados usados por vários arquivos), `src/lib` (pequenos utilitários), `src/hooks` e `src/providers`.

```text
src/
├── routes/          Flat file routes that compose pages
├── modules/         One folder per database table, plus _core
├── integrations/    One folder per vendor
├── presentation/    Components, emails, styles, theme, branding
├── data/            Data shared by several files
├── lib/             Small shared utilities
├── hooks/           Shared React hooks
├── providers/       Application providers
├── platform/        Test runtime wiring
├── types/           Global type declarations
├── router.tsx       Router and per-request QueryClient
├── routes.ts        ROUTES path constants
└── server.ts        Cloudflare Worker entry
```

## Regras que moldam o código

- Arquivos de rota apenas compõem. Widgets, diálogos, formulários e colunas de tabela ficam em `src/presentation/components/custom`, um por arquivo.
- Os componentes leem suas próprias traduções e dados com `useTranslations`, `useSuspenseQuery` ou os dados do loader da rota. As rotas não repassam rótulos nem dados como props.
- Uma server function que trabalha com uma tabela é um caso de uso no módulo dessa tabela. Uma server function usada por uma única rota pode ser definida no arquivo da rota. Todo o resto vai para `src/lib`.
- Não há contêiner de injeção de dependência nem camada de wrappers. Importe a função concreta da pasta à qual ela pertence.
- Uma constante usada por um único arquivo permanece nesse arquivo. Apenas dados compartilhados por vários arquivos vão para `src/data`.
