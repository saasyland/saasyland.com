## Routes

`src/routes/admin.users.tsx` is a layout with four link tabs; `/admin/users` redirects to `/admin/users/all`. All tabs use the `pages.admin.users` namespace.

| Route                      | Content                                                  |
| -------------------------- | -------------------------------------------------------- |
| `/admin/users/all`         | Live users table                                         |
| `/admin/users/invitations` | Demo rows (`ADMIN_INVITATION_ROWS`) with an email search |
| `/admin/users/roles`       | Demo rows (`ADMIN_ROLE_ROWS`)                            |
| `/admin/users/security`    | Empty state                                              |

## All users

```tsx
<DataTable columns={userColumns} options={{ query: getUsersPageQuery, selectable: true }} />
```

- `getUsersPageQuery` calls the `getUsers` server function (`src/modules/user/use-cases/get-users.ts`, permission `user: ["list"]`). Pagination and sorting run on the server over name, role, status, email verification, 2FA, time zone and the created and updated dates.
- Status is not a column. `getUserStatus` (`user.utils.ts`) derives `banned`, `pending` or `active` from `banned` and `emailVerified`, and the server sorts by the same SQL `case` expression.
- `userColumns` lives in `src/presentation/components/custom/admin/users/user-columns.tsx`; dates render in each user's own time zone.

## Row actions

`UserRowActions` (`row-actions.tsx`) is the menu in the last column:

- **Reset password** opens `ResetPasswordDialog`, which calls `setUserPassword`.
- **Ban** or **Unban** calls `banUser` or `unbanUser`.
- **Delete** opens `DeleteUserDialog`, which calls `deleteUser`.

Every success invalidates `USER_QUERY_KEYS.ALL` and shows a toast; errors go through `useErrorMessage`. The **Edit** and **View profile** items and the **Add user** button have no action yet.

## Not wired

`createUser`, `getUser`, `updateUser`, `setUserRole`, `impersonateUser` and `stopImpersonatingUser` exist in `src/modules/user/use-cases` with permission middleware, but no screen calls them. There is no invitation table; the real roles are `admin` and `customer` in `auth.access.ts`.
