Маршрути API — це серверні обробники TanStack Start у `src/routes/api/`. Екранам застосунку вони ніколи не потрібні: ті викликають серверні функції. Додавайте маршрут API лише для клієнтів поза застосунком, як-от вебхуки, сторонні клієнти чи пошукові роботи.

## Наявні маршрути

| Файл                         | Шлях                                         | Призначення                                                                           |
| ---------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------- |
| `src/routes/api/auth.$.ts`   | `/api/auth/*`                                | Better Auth: вхід, callback OAuth, підтвердження пошти, портал і вебхуки Polar        |
| `src/routes/api/index.ts`    | `/api`                                       | Перевірка середовища виконання, що повертає `{ "runtime": "cloudflare-workers" }`     |
| `src/routes/api/cli.v1.*.ts` | <RepositoryFact name="cliApiBasePath" />`/*` | [API ліцензій для CLI](/docs/features/cli-licence-api), який викликає CLI `saasyland` |

Плагін Polar не додає маршруту оформлення замовлення; оформлення замовлення починається в серверних функціях `startCheckout` модулів замовлень і ліцензій, і обидві створюють його через `createCheckout`. Вебхуки Polar надходять на `/api/auth/polar/webhooks`; плагін Polar для Better Auth перевіряє їхній підпис через `POLAR_WEBHOOK_SECRET`, перш ніж `handlePolarEvent` (`src/integrations/polar/polar.webhooks.ts`) передасть кожну подію обробникам замовлень, підписок і ліцензій, перелічених у `POLAR_EVENT_HANDLERS`.

## Напишіть обробник

Оголосіть методи в `server.handlers`. Кожен обробник отримує вебовий `Request` і повертає вебовий `Response`:

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: {
    handlers: {
      GET: ({ request }) => auth.handler(request),
      POST: ({ request }) => auth.handler(request),
    },
  },
})
```

Усередині обробника:

- Валідуйте параметри запиту чи тіло схемою Zod і повертайте `HTTP_STATUS.BAD_REQUEST` (з `src/modules/_core/constants/api.ts`), якщо валідація не пройшла. Якщо обробнику потрібен новий статус, додайте його туди.
- Читайте сесію через `getRequestSession(request)` і перевіряйте її через `hasPermission`. Middleware функцій, як-от `authorized`, стосується серверних функцій, а не обробників.
- Обмежуйте кількість запитів до публічних ендпоінтів через `withinRateLimit({ key, limit, windowSeconds })` з `src/lib/rate-limit.ts` і `clientAddress(request.headers)` з `src/integrations/better-auth/auth.middleware.ts`.
- Перевіряйте підписи, перш ніж довіряти вмісту вебхука.
- Повертайте безпечні тіла помилок, а подробиці записуйте через `console.error`.

## Правила маршрутизації

- Шляхи `/api` ніколи не отримують мовного префікса, а Worker пропускає для них пошук статичних файлів і мовні перенаправлення.
- URL `/api` не містять мови, тож `getCurrentLocale()` повертає там типову мову. Локалізована відповідь бере мову із запиту, наприклад із параметра запиту `locale`.
- `/api` виключено з попереднього рендерингу.
