## クエリキャッシュ

`getRouter` はリクエストごとに新しい `QueryClient` を作成するため、サーバー上でユーザー間にデータが漏れることはありません。デフォルト値は次のとおりです。

| 設定                                 | 値                                                                                                                              |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| クエリの `staleTime`                 | <RepositoryFact name="queryStaleTimeMinutes" unit="minute" />                                                                   |
| クエリの `gcTime`                    | <RepositoryFact name="queryGcTimeMinutes" unit="minute" />                                                                      |
| ルーターの `defaultStaleTime`        | <RepositoryFact name="routerStaleTimeMinutes" unit="minute" />                                                                  |
| ルーターの `defaultPreloadStaleTime` | <RepositoryFact name="routerStaleTimeMinutes" unit="minute" />                                                                  |
| プリロード                           | インテント時。ページがアイドルになると[ヘッダーのページ](/docs/conventions/performance#the-headers-pages-load-before-a-click)も |

ローダーは `queryClient.query({ ...options, staleTime: "static" })` でキャッシュを埋め、コンポーネントは `useSuspenseQuery` で同じキーを読み取ります。例外はコースのページと管理画面のコースエディターです。`invalidateQueries` は `static` のクエリを再取得しないため、レッスンの完了後やエディターで変更を保存した後にカリキュラムを更新できるよう、これらのクエリは `staleTime: COURSE_STALE_MS`（1 分）を使います。`setupRouterSsrQueryIntegration` はサーバーのキャッシュを HTML にシリアライズし、ブラウザでハイドレートします。

- **翻訳メッセージ**は、ロケールと名前空間ごとに、`staleTime` と `gcTime` を無限に設定してキャッシュされます。
- **セッションクエリ**（`getCurrentSessionQuery`）の `staleTime` は 1 分です。ルートガードは実際のナビゲーション時にこれを再取得し、サインイン中のユーザーが変わると、`meta: { public: true }` が付いていないすべてのクエリを削除します。翻訳や、プリレンダリングされたページのレンダリングに使われたスター数などの公開クエリは、キャッシュに残ります。[公開クエリ](/docs/conventions/data-fetching#public-queries) を参照してください。
- **ミューテーション**は成功後、そのモジュールのクエリキー（例：`USER_QUERY_KEYS.ALL`）を無効化します。

## プリレンダリング

`bun run build` はリンクをクロールして公開ページをプリレンダリングします。対象は、すべてのロケールのランディング、法務、ブログ、ドキュメントの各ページです。`/admin`、`/app`、`/auth`、`/courses`、`/newsletter`、`/api` 配下のパス（ロケールプレフィックスの有無を問わない）と、クエリ文字列やハッシュを含むリンクは除外されます。コースのページは、視聴者ごとのロックと進捗を表示するため除外されます。ランディングページのコースブロックは、表示領域に近づいたときにブラウザが `getCourseShowcase` のデータで埋めるため、プリレンダリングされたランディングページは全員に同じ内容のままです（[コース](/docs/features/courses) を参照）。

Worker は、アプリケーションを読み込む前に、`ASSETS` バインディングからプリレンダリング済みの HTML を返します。プリレンダリングされたページにはユーザーデータが含まれないため、誰に返しても安全です。訪問者が地域別価格の対象になる場合、Worker は HTML を書き換え、レスポンスに `Cache-Control: private, no-cache` を設定します。

プリレンダリングは、すべてのページを含む Worker のビルドで実行されます。その後、デプロイ用の Worker は、コンパイル済みのドキュメントとブログのページと、ランディングと法務の各ページだけが使う翻訳を除いて再ビルドされます。どちらも Worker には必要ありません。ドキュメント、ブログ、ランディングページは、ビルドが `/assets/` に書き出すインデックスからコンテンツを読み、クライアント側のナビゲーションではそれをブラウザーで行います。ドキュメントの検索もブラウザーで静的なインデックスを検索します。そのため、クライアント側のナビゲーションと検索が Worker に届くことはありません（[パフォーマンス](/docs/conventions/performance#the-worker-holds-no-docs-or-blog-content) を参照）。[Cloudflare Workers](/docs/integrations/cloudflare-workers) を参照してください。

## KV と D1

- **KV（`CACHE`）** には、`src/lib/github.ts` 用の GitHub スター数を保存します。1 時間より古いスター数はそのまま即座に返され、`waitUntil` によってバックグラウンドで更新されます。
- **D1（`DB`）** にはセッションとレート制限のカウンターを保存します。サーバー関数のセッションチェックは Better Auth のクッキーキャッシュを経由せず、結果はリクエストの残りの処理の間メモ化されます。
- **Workers のキャッシュ** には、`serveMedia` が R2 から読み取った動画ファイルを、署名を除いた `/media/_/<videoId>/<file>` の下に保持します。そのため、同じエッジロケーションの視聴者は、キャッシュされた 1 つのコピーを共有します。[Cloudflare R2](/docs/integrations/cloudflare-r2) を参照してください。
- サーバー関数が、キャッシュされたデータをもとに権限を判断することはありません。
