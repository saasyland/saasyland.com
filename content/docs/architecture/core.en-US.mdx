---
title: "Core shared kernel"
description: "The error codes, HTTP constants, catalogues, Zod fields and use-case inputs in src/modules/_core that every module is built from."
---

`src/modules/_core` is the only module folder that does not own a table. It holds only the foundation that the modules' schemas, Zod schemas and use cases are built from, so no module redefines it: the error codes, the HTTP and environment constants, the locale, time zone, country and currency catalogues with the store currency, the shared Zod fields and localized text, and the pagination, ordering, search and time-range inputs.

## Constants

| File                    | Contents                                                                                                                                          |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `constants/errors.ts`   | `ERROR_CODES`, the `ErrorCode` type and the `AppError` class                                                                                      |
| `constants/api.ts`      | `HTTP_STATUS`, the `cf-ipcountry` and `cf-connecting-ip` header names, the security headers, allowed hosts per build mode                         |
| `constants/locale.ts`   | The `LOCALES` catalog, `LocaleCode`, `getLocaleName` and `getLocaleDirection`                                                                     |
| `constants/country.ts`  | The `COUNTRIES` catalog and `CountryCode`                                                                                                         |
| `constants/currency.ts` | The `CURRENCIES` catalog, `CurrencyCode`, and `toMinorUnits` and `fromMinorUnits`, which convert an amount to and from the currency's minor units |
| `constants/timezone.ts` | The `TIMEZONES` catalog and `TimezoneCode`                                                                                                        |
| `constants/pricing.ts`  | The store currency `DEFAULT_CURRENCY_CODE` and the currency formatting `CURRENCY_FORMAT`                                                          |
| `constants/ordering.ts` | `FIRST_POSITION`, the place of the first item in an ordered list                                                                                  |

The catalogues live here because the foundation is built from them: `countryCodeField` and `currencyCodeField`, the order, product and subscription schemas, the user constants and the default currency of a product. The locale catalog lists every known locale; the locales the application serves are `I18N.SUPPORTED_LOCALES` in `src/integrations/use-intl/i18n.config.ts`. Data that no schema or use case is built from goes to `src/data`, which holds only constants and literal lists, and generic helpers go to `src/lib`. A test in `src/__test__/module-tables.test.ts` fails when a file in `_core` is not described on this page, so a new one is a decision, not a habit.

## Utilities

- `utils/localized-text.ts`: `LocalizedText`, a text per locale stored as JSON, `localizedTextSchema`, which requires `en-US` and allows at most <RepositoryFact name="localizedTextMaxLength" /> characters per text, and `localize`, which falls back to `en-US`
- `utils/ordering.ts`: `nextPosition`, the highest `position` plus one, and `reorder`, which moves an item to a place among its siblings, keeps a place past either end at that end, numbers the list from `FIRST_POSITION` and returns only the items whose `position` changes; the course, chapter, lesson and material use cases keep `position` dense with them
- `utils/pagination.ts`: `paginationSchema` (`pageIndex`, `pageSize`) and `DEFAULT_PAGE_SIZE`
- `utils/search.ts`: `searchSchema` and `localizedSearchSchema`, the input of the admin search use cases, their length limits and the `SearchHit` they return
- `utils/time-series.ts`: `TIME_RANGES` and `timeRangeSchema`, the ranges of the admin's revenue and sign-up charts, `timeSeries`, the day or month buckets of a range, and `pointsOf`, which gives a bucket without a value zero
- `utils/zod-fields.ts`: reusable Zod fields such as `idField`, `localeField`, `positionField` (a whole number from `FIRST_POSITION`) and `slugField`

## Errors

There is one error class and one list of codes:

```ts
export const ERROR_CODES = {
  AUTH_API_ERROR: "AUTH_API_ERROR",
  CONFLICT: "CONFLICT",
  FORBIDDEN: "FORBIDDEN",
  INTERNAL_ERROR: "INTERNAL_ERROR",
  NOT_FOUND: "NOT_FOUND",
  TOO_MANY_REQUESTS: "TOO_MANY_REQUESTS",
  UNAUTHORIZED: "UNAUTHORIZED",
  VALIDATION: "VALIDATION",
} as const

export type ErrorCode = (typeof ERROR_CODES)[keyof typeof ERROR_CODES]

export class AppError extends Error {
  readonly code: ErrorCode

  constructor(code: ErrorCode, message: string = code) {
    super(message)
    this.name = "AppError"
    this.code = code
  }
}
```

Server functions throw `AppError`. The `withRequest` middleware normalizes everything else: Better Auth API errors become `AUTH_API_ERROR` with the Better Auth error key as the message, Zod errors become `VALIDATION`, and unknown errors are logged and become `INTERNAL_ERROR`. In the browser, `useErrorMessage()` from `src/hooks/use-error-message.ts` maps the message to `auth.errors.*` or `errors.codes.*` translations.
