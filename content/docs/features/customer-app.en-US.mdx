## Layout

`src/routes/app.tsx` validates the search params of every page in the area, guards it with `requireSignedIn` and preloads its namespaces:

```tsx
const NAMESPACES = ["auth.errors", "pages.app", "pages.license"] as const

export const Route = createFileRoute("/app")({
  validateSearch: appSearchSchema,
  beforeLoad: requireSignedIn,
  component: AppLayout,
  loader: ({ context }) => preloadNamespaces({ locale: getCurrentLocale(), namespaces: NAMESPACES, queryClient: context.queryClient }),
  pendingComponent: AppPending,
  staticData: { namespaces: NAMESPACES },
})
```

`AppLayout` renders `AppSidebar` and `AppHeader` from `src/presentation/components/custom/app` inside the shadcn `SidebarProvider`. The sidebar builds its links from `APP_NAVIGATION` in `src/data/app.ts`, reads the user from the route context (`getRouteApi("/app")`) and ends with `SignOutButton`. The header shows the current page and a link back to the website. Admins land on `/admin` after sign-in, everyone else on `/app`.

## Pages

| Route           | Content                                                                                                                                                                                      |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/app`          | `LicenseOffer` without an active licence, otherwise `LicenseStatusCard` (tier, status and a link to the licence page); links to the docs and to support by email.                            |
| `/app/license`  | `LicenseOffer` without an active licence, otherwise `LicenseCard` (key, install command, customer portal link, how to change tier) and, once Polar has issued the key, `LicenseActivations`. |
| `/app/settings` | `PreferencesCard`: the time zone of every date in the workspace, with a search and **Detect from this browser**. See [Settings](/docs/features/settings).                                    |

`LicenseOffer` (`src/presentation/components/custom/app/license-offer.tsx`) reuses the landing page's `PricingTiers` with a `CheckoutButton` for each tier, adds the purchase terms (`CheckoutAgreement`) and ends with `CourseUnlocks`: the published courses that have paid lessons, with the number of locked lessons in each, counted from D1 by `getCatalogue`. The block is left out while no course has a paid lesson. A refunded licence keeps its card and gets the offer next to it.

`appSearchSchema` (`src/data/app.ts`) accepts two optional params, both ignored when invalid:

| Param        | Value                  | Effect                                                                                                                                         |
| ------------ | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `tier`       | a `LICENSE_TIER` value | `ChosenTier` above the offer: the tier, its price and a **Continue to checkout** button.                                                       |
| `checkoutId` | a UUID from Polar      | `CheckoutActivation` instead of the offer until the licence is active, then a thank-you. See [Payments and licences](/docs/features/payments). |

The overview and licence loaders preload `currentLicenseQuery` and the course catalogue; `/app/license` also preloads `licenseActivationsQuery`. `/app/settings` loads only its page namespace, and the layout's `NAMESPACES` include `timezones` for the zone names. Checkout, webhooks and licence states are described in [Payments and licences](/docs/features/payments).

## Skeletons

`AppSettingsPending` (`app-pending.tsx`) draws the page header and `PreferencesCardPending`. `AppOverviewPending` and `AppLicensePending` mirror the state the page will show: they read the search params with `appSearchSchema` and the cached licence and catalogue from the query client, and draw the activation panel, the chosen tier, the tier grid with one row per course with paid lessons, or the licence cards.

There are no billing history or course screens in `/app`, and `/app/settings` has no profile, email or password forms yet.
