Un e-mail comporte trois parties : un modèle dans `src/presentation/emails/`, un espace de noms de messages dans `messages/<locale>/emails.<name>.json` et le cas d'usage qui charge les messages, affiche le modèle et l'envoie. Modèles : `verify-email`, `reset-password-email`, `change-email-confirmation-email`, `newsletter-confirmation-email` et `newsletter-notification-email`.

## Modèle

Un modèle ne contient que du balisage et exporte son espace de noms. Il traduit avec `createTranslator` de `use-intl`, car il s'affiche hors du contexte React. `src/presentation/emails/verify-email.tsx` :

```tsx
import type { JSX } from "react"

import { Body, Button, Container, Head, Heading, Html, Preview, Section, Tailwind, Text, pixelBasedPreset } from "react-email"
import { createTranslator } from "use-intl"

import type { SupportedLocale } from "~/src/integrations/use-intl/i18n.config"

import type emailMessages from "~/messages/en-US/emails.verify-email.json"

export const VERIFY_EMAIL_NAMESPACE = "emails.verify-email"

const TAILWIND_CONFIG = { presets: [pixelBasedPreset] }

interface VerifyEmailProps {
  readonly locale: SupportedLocale
  readonly messages: typeof emailMessages
  readonly name: string
  readonly verifyUrl: string
}

export const VerifyEmail = ({ messages, locale, name, verifyUrl }: Readonly<VerifyEmailProps>): JSX.Element => {
  const t = createTranslator({ locale, messages: { emails: { "verify-email": messages } }, namespace: "emails.verify-email" })

  return (
    <Html lang={locale}>
      <Tailwind config={TAILWIND_CONFIG}>
        <Head />
        <Body className="font-sans">
          <Preview>{t("preview")}</Preview>
          <Container className="mx-auto px-5 py-10">
            <Section>
              <Heading className="m-0 mb-4 text-2xl font-bold">{t("heading")}</Heading>
              <Text className="m-0 mb-6 text-base text-neutral-600">{t("body", { name })}</Text>
              <Button
                href={verifyUrl}
                className="box-border rounded-md bg-neutral-900 px-5 py-3 text-center text-base text-white no-underline"
              >
                {t("button")}
              </Button>
              <Text className="mt-6 text-sm text-neutral-500">{t("footer")}</Text>
            </Section>
          </Container>
        </Body>
      </Tailwind>
    </Html>
  )
}
```

## Messages

Créez `messages/<locale>/emails.<name>.json` dans les neuf langues. Incluez une clé `subject` ; le cas d'usage la traduit séparément du corps.

```json
{
  "subject": "Verify your email address",
  "preview": "Verify your email for SaaSy Land",
  "heading": "Verify your email",
  "body": "Hi {name}, thanks for signing up. Confirm your email address to finish setting up your account.",
  "button": "Verify email",
  "footer": "If you did not create an account, you can safely ignore this email."
}
```

Les routes ne préchargent jamais les espaces de noms d'e-mails ; le cas d'usage qui envoie le message les charge sur le serveur.

## Envoi

Le cas d'usage reçoit la langue, charge les messages, construit des liens absolus avec `localizePathname` et appelle `sendEmail`. `src/modules/verification/use-cases/send-verify-email.ts` :

```ts
export const sendVerifyEmail = async ({
  locale,
  token,
  user,
}: {
  locale: SupportedLocale
  token: string
  user: { email: string; name: string }
}): Promise<void> => {
  const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
  const verifyUrl = new URL(localizePathname({ locale, pathname: ROUTES.VERIFY_EMAIL }), getRequest().url)
  verifyUrl.searchParams.set("token", token)

  await sendEmail({
    idempotencyKey: `verify-email/${token}`,
    react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
    subject: createTranslator({ locale, messages })("subject"),
    to: user.email,
  })
}
```

`sendEmail` (`src/integrations/resend/resend.utils.ts`) envoie via Resend depuis `RESEND_EMAIL_FROM` sauf si `from` est fourni, transmet la clé d'idempotence pour qu'une nouvelle tentative n'envoie jamais deux fois, et lève une erreur lorsque Resend en renvoie une.

## Qui envoie quoi

- Les hooks Better Auth de `src/integrations/better-auth/auth.server.ts` appellent les cas d'usage : `sendVerifyEmail` pour `emailVerification.sendVerificationEmail` et les inscriptions répétées de comptes non vérifiés, `sendResetPasswordEmail` pour `emailAndPassword.sendResetPassword` et `sendChangeEmailConfirmationEmail` pour `user.changeEmail`.
- Les requêtes Better Auth arrivent sur `/api/auth` sans préfixe de langue : les hooks déterminent donc la langue de l'e-mail à partir du `callbackURL` du parcours, un chemin de page localisé, avec `extractLocaleFromCallbackURL` ou `extractLocaleFromPath` de `src/integrations/use-intl/i18n.paths.ts`. L'anglais sert de langue de repli.
- Les cas d'usage de la newsletter envoient eux-mêmes les e-mails de confirmation et de notification, par exemple `subscribeToNewsletter`.

## Ajouter un e-mail

1. Ajoutez le modèle dans `src/presentation/emails/<name>.tsx` avec son `<NAME>_NAMESPACE` exporté.
2. Ajoutez `messages/<locale>/emails.<name>.json` dans les neuf langues.
3. Envoyez-le depuis le cas d'usage propriétaire de l'action, avec une clé d'idempotence dérivée du jeton ou de l'enregistrement déclencheur.
4. Testez le modèle dans `src/presentation/emails/__test__/` et le cas d'usage avec `sendEmail` simulé.

Identifiants Resend : `RESEND_API_KEY` et `RESEND_EMAIL_FROM`. Les tests ne contactent jamais Resend.
