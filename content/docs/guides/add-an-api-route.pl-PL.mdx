Trasy API to handlery serwerowe TanStack Start w `src/routes/api/`. Ekrany aplikacji nigdy ich nie potrzebują, bo wywołują funkcje serwerowe. Dodawaj trasę API tylko dla wywołań spoza aplikacji, takich jak webhooki, klienci zewnętrzni czy roboty indeksujące.

## Istniejące trasy

| Plik                         | Ścieżka                                      | Przeznaczenie                                                                                  |
| ---------------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `src/routes/api/auth.$.ts`   | `/api/auth/*`                                | Better Auth: logowanie, wywołania zwrotne OAuth, weryfikacja e-maila, portal i webhooki Polara |
| `src/routes/api/index.ts`    | `/api`                                       | Sprawdzenie środowiska uruchomieniowego, które zwraca `{ "runtime": "cloudflare-workers" }`    |
| `src/routes/api/cli.v1.*.ts` | <RepositoryFact name="cliApiBasePath" />`/*` | [API licencji CLI](/docs/features/cli-licence-api), które wywołuje CLI `saasyland`             |

Wtyczka Polara nie dodaje endpointu płatności; płatności rozpoczynają funkcje serwerowe `startCheckout` w modułach zamówień i licencji, a obie tworzą je przez `createCheckout`. Webhooki Polara trafiają na `/api/auth/polar/webhooks`; wtyczka Polara dla Better Auth sprawdza ich podpis przez `POLAR_WEBHOOK_SECRET`, zanim `handlePolarEvent` (`src/integrations/polar/polar.webhooks.ts`) przekaże każde zdarzenie do obsługi zamówień, subskrypcji i licencji wymienionej w `POLAR_EVENT_HANDLERS`.

## Napisz handler

Zadeklaruj metody w `server.handlers`. Każdy handler otrzymuje webowy `Request` i zwraca webowy `Response`:

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: {
    handlers: {
      GET: ({ request }) => auth.handler(request),
      POST: ({ request }) => auth.handler(request),
    },
  },
})
```

Wewnątrz handlera:

- Waliduj parametry zapytania lub treść schematem Zod i zwracaj `HTTP_STATUS.BAD_REQUEST` (z `src/modules/_core/constants/api.ts`), gdy walidacja się nie powiedzie. Jeśli handler potrzebuje nowego statusu, dodaj go tam.
- Odczytuj sesję przez `getRequestSession(request)` i sprawdzaj ją przez `hasPermission`. Middleware funkcji, np. `authorized`, dotyczy funkcji serwerowych, a nie handlerów.
- Ogranicz liczbę żądań do publicznych endpointów przez `withinRateLimit({ key, limit, windowSeconds })` z `src/lib/rate-limit.ts` i `clientAddress(request.headers)` z `src/integrations/better-auth/auth.middleware.ts`.
- Weryfikuj podpisy, zanim zaufasz treści webhooka.
- W odpowiedzi z błędem nie ujawniaj szczegółów; zapisuj je przez `console.error`.

## Zasady routingu

- Ścieżki `/api` nigdy nie dostają prefiksu języka, a Worker pomija dla nich wyszukiwanie zasobów statycznych i przekierowania językowe.
- Adresy `/api` nie zawierają języka, więc `getCurrentLocale()` zwraca tam język domyślny. Zlokalizowana odpowiedź pobiera język z żądania, na przykład z parametru zapytania `locale`.
- `/api` jest wyłączone z prerenderingu.

## Test

Wywołuj handler przez opcje trasy, tak jak `src/routes/api/__test__/auth.test.ts` robi to z `Route.options.server.handlers`, i mockuj dostawcę, do którego przekazuje żądanie.
