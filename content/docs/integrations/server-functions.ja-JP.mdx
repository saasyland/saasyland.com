ビジネス操作は `src/modules/<table>/use-cases/<operation>.ts` に、1 ファイルにつき 1 操作ずつ置きます。各ファイルは、ミドルウェア、Zod によるバリデーション、ハンドラーを持つネイティブな `createServerFn` と、コンポーネントが使うクエリオプションまたはミューテーションオプションをエクスポートします。どのテーブルにも属さないサーバー関数は `src/lib` に置きます（例: `src/lib/github.ts` の `getStarCount`）。1 つのルートだけで使うサーバー関数は、そのルートファイル内で定義できます（`src/routes/blog.index.tsx` の `getBlogPosts`）。

```ts
export const createCategory = createServerFn({ method: "POST" })
  .middleware([authorized({ category: ["create"] })])
  .validator((input: zod.input<typeof categoryZodSchemas.createCategory>) => categoryZodSchemas.createCategory.parse(input))
  .handler(({ data }) =>
    db
      .insert(category)
      .values({
        description: data.description ?? "",
        icon: data.icon ?? "FolderOpen",
        id: v7(),
        kind: data.kind,
        name: data.name,
        visibility: data.visibility ?? "public",
      })
      .returning()
      .get(),
  )

export const createCategoryMutation = mutationOptions({
  mutationFn: (data: Parameters<typeof createCategory>[0]["data"]) => createCategory({ data }),
  mutationKey: CATEGORY_MUTATION_KEYS.CREATE,
})
```

## ルール

- ミドルウェアはバリデーションとハンドラーより前に実行されます。保護された操作には `authorized(permission?)` を、機密性の高い公開操作には `withRateLimit(kind, RATE_LIMITS.SENSITIVE)` または `RATE_LIMITS.TOKEN` を使います。詳しくは [Better Auth](/docs/integrations/better-auth) を参照してください。
- 入力はモジュールの Zod スキーマ（`<table>.zod.ts`）で検証します。
- データはそのまま返し、想定される失敗には `src/modules/_core/constants/errors.ts` の `AppError(ERROR_CODES.X)` をスローします。それ以外のエラーは `INTERNAL_ERROR` としてクライアントに届くため、プロバイダーの詳細はサーバー側にとどまります。
- クエリキーとミューテーションキーは、モジュールの `<table>.constants.ts` にある読み取り専用のタプルです。クエリキーには、結果を変えるすべての入力を含めます。
- 操作は 1 つの SQL 文または `db.batch` でアトミックに保ちます。D1 にはインタラクティブなトランザクションがありません。

## ユースケースの使い方

コンポーネントは、エクスポートされたオプションを `useQuery`、`useSuspenseQuery`、`useMutation` に展開し、`src/hooks/use-error-message.ts` の `useErrorMessage()` でエラーを翻訳します。ミューテーションが成功したら、モジュールのクエリキーを無効化します。

```tsx
const deleteUser = useMutation({
  ...deleteUserMutation,
  onError: (error) => {
    toast.error(errorMessage(error))
  },
  onSuccess: async () => {
    await queryClient.invalidateQueries({ queryKey: USER_QUERY_KEYS.ALL })
    toast.success(t("feedback.deleteSuccess"))
  },
})
```

ローダーは同じクエリオプションを `Promise.all` でプリロードするため、サーバーレンダリングとクライアントが 1 つのキャッシュエントリを共有します。
