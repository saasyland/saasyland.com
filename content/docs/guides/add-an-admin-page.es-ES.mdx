---
title: "Añadir una página de administración"
description: "Registra la ruta, la entrada en la barra lateral, los mensajes y los widgets de una nueva página de administración."
---

Las páginas de administración son archivos de ruta planos bajo el layout `/admin` (`src/routes/admin.tsx`), que ejecuta `requireAdmin` en `beforeLoad` y renderiza la barra lateral, las migas de pan y la paleta de comandos. Los pasos siguientes añaden una página en `/admin/reports`; `src/routes/admin.orders.index.tsx` es un ejemplo real completo.

## 1. Añade la ruta

Añade la ruta a `ROUTES.ADMIN` en `src/routes.ts`, en su lugar alfabético:

```ts
REPORTS: `${ADMIN}/reports`,
```

Cuando la página pertenece a una funcionalidad que un proyecto puede dejar fuera, añade también el nombre a los `names` de esa funcionalidad en `scripts/features.ts`, para que `bun run check:features` elimine la ruta y todas las entradas que la nombran junto con la funcionalidad.

## 2. Crea el archivo de ruta

Crea `src/routes/admin.reports.tsx`. La ruta define solo el componente de página, `NAMESPACE`, el loader, `head` y `pendingComponent`; el generador del router registra el archivo en `src/routeTree.gen.ts`.

```tsx
import type { JSX } from "react"

import { createFileRoute } from "@tanstack/react-router"
import { useTranslations } from "use-intl/react"

import { loadPageMetadata, preloadNamespaces } from "~/src/integrations/use-intl/i18n.messages"
import { getCurrentLocale } from "~/src/integrations/use-intl/i18n.utils"

import { pageHead } from "~/src/lib/seo"

import { AdminPageHeader } from "~/src/presentation/components/custom/admin/admin-page-header"
import { AdminReportsPending } from "~/src/presentation/components/custom/admin/reports-pending"
import { ReportStats } from "~/src/presentation/components/custom/admin/reports/report-stats"

import { ROUTES } from "~/src/routes"

const ReportsPage = (): JSX.Element => {
  const t = useTranslations("pages.admin.reports")

  return (
    <div className="flex w-full flex-col space-y-8">
      <AdminPageHeader description={t("metadata.description")} title={t("metadata.title")} />

      <ReportStats />
    </div>
  )
}

const NAMESPACE = "pages.admin.reports"

export const Route = createFileRoute("/admin/reports")({
  component: ReportsPage,
  loader: async ({ context }) => {
    const locale = getCurrentLocale()
    const [metadata] = await Promise.all([
      loadPageMetadata({ locale, namespace: NAMESPACE }),
      preloadNamespaces({ locale, namespaces: [NAMESPACE], queryClient: context.queryClient }),
    ])
    return { locale, metadata }
  },
  head: pageHead(ROUTES.ADMIN.REPORTS),
  pendingComponent: AdminReportsPending,
  staticData: { namespaces: [NAMESPACE] },
})
```

Las queries que necesita la primera parte de la respuesta de la página van en el mismo `Promise.all`, por ejemplo `context.queryClient.query({ ...getUsersQuery, staleTime: "static" })` en `src/routes/admin.users.all.tsx`; una sección que puede esperar, como una estadística o un panel, llega en cambio en streaming a su esqueleto ([Secciones en streaming](/docs/conventions/routes#streamed-sections)). `pageHead` construye el título, la descripción, la URL canónica y los enlaces a los demás idiomas a partir de `metadata` del loader. `AdminReportsPending` es el esqueleto propio de la página, que solo se muestra cuando una navegación tarda más de <RepositoryFact name="navigationPendingMs" unit="millisecond" />. Escríbelo en el archivo de esqueletos de su área, aquí un `custom/admin/reports-pending.tsx` nuevo, a partir de `AdminPageHeaderPending` de `admin-page-header.tsx` para la cabecera y los bloques de `pending-blocks.tsx`, de modo que reproduzca la estructura de la página. El esqueleto del layout de administración lo lee de la ruta, así que también se muestra cuando alguien entra en `/admin/reports` desde fuera del área de administración.

Consulta [Esqueletos de carga](/docs/architecture/delivery-layer#esqueletos-de-carga).

## 3. Añade la entrada de la barra lateral

Añade una entrada a los `items` de su grupo de la barra lateral en `ADMIN_NAVIGATION` (`src/data/navigation.ts`), donde deba aparecer: por ejemplo, detrás de Panel en el grupo de resumen. La entrada indica su icono de `lucide-react`, la clave completa de su etiqueta y su ruta:

```ts
{ icon: FileText, label: "navigation.reports.admin.reports", to: ROUTES.ADMIN.REPORTS },
```

Añade la etiqueta como `admin.reports` a `messages/<locale>/navigation.reports.json`, en todos los idiomas. Un grupo nuevo también necesita un valor en `ADMIN_NAVIGATION_GROUP`, un lugar entre los grupos de `ADMIN_NAVIGATION` y `groups.<group>` en `pages.admin.sidebar`. La barra lateral, las migas de pan y la paleta de comandos ⌘K leen `ADMIN_NAVIGATION` (`src/data/navigation.ts`), así que la página aparece en los tres sitios. La página de inicio la cuenta entre las secciones de administración, y el menú lateral de administración del vídeo `app-tour` de la página de inicio la incluye cuando el vídeo se vuelve a renderizar (consulta `remotion/README.md`). Un tercer segmento de la URL, como `/admin/reports/create`, muestra una miga de pan cuando el `breadcrumbs` de la entrada nombra una etiqueta para él, como `breadcrumbs: { create: "navigation.reports.breadcrumbs.create" }`, y ninguna tercera miga cuando no la nombra.

## 4. Añade los mensajes de la página

Crea `messages/<locale>/pages.admin.reports.json` en todos los idiomas. `metadata` es obligatorio porque el loader lo lee para la cabecera del documento:

```json
{
  "metadata": {
    "title": "Reports",
    "description": "Revenue and usage reports."
  }
}
```

## 5. Añade los widgets

Coloca cada widget, diálogo, formulario y conjunto de columnas de tabla en su propio archivo en `src/presentation/components/custom/admin/reports/`, por ejemplo `report-stats.tsx` o `report-columns.tsx`. Los widgets llaman a `useTranslations("pages.admin.reports")` y leen sus propios datos con `useSuspenseQuery`; la página no les pasa etiquetas ni datos. Las tablas usan el `DataGrid`; consulta [Añadir una cuadrícula de datos](/docs/guides/add-a-data-table).

## 6. Protege y prueba

- El guard del layout controla el acceso a la página. Cada función de servidor que llama la página sigue necesitando `authorized(permission)`; consulta [Roles y permisos](/docs/guides/roles-and-permissions).
- `/admin` queda fuera del prerenderizado.
- Añade los tests de ruta de la funcionalidad en `src/routes/__test__/admin-<feature>-routes.component.test.tsx` y `admin-<feature>-loaders.test.ts`, los tests de widgets en `src/presentation/components/custom/admin/__test__/` y la página en `e2e/data/<feature>.pages.ts`, y ejecuta después `bun run check:i18n`, `bun run test:coverage` y `bun run check:features`.
