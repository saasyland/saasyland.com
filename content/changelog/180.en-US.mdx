- CLI licence API: the Worker serves the template bundle of each release, which `saasyland init` needs to generate a project. `POST /api/cli/v1/activations/:activationId/bundles` checks the licence and that the activation belongs to the calling machine, then answers with an HTTPS URL to the release's archive in the licence area's new `BUNDLES` R2 bucket, the SHA-256 of the archive's JSON content (the digest the CLI pins for each release), the archive's size and when the URL expires, `API_LIMIT.BUNDLE_URL_TTL_SECONDS` after it was issued. A release without an archive answers `versionNotFound`, and a bucket that cannot be read `serviceUnavailable`. The licence area's Worker handler serves `/bundles/<expiry>.<signature>/<version>.json.gz` from R2 once the expiry and an HMAC check out, with a key that HKDF derives from `AUTH_SECRET` for bundles alone, so no S3 credentials are needed; the key derivation that video playback used moved to `src/lib/hmac.ts`, which both share. The CLI repository's release uploads each archive to the preview and the production bucket, and [Publishing bundles](/docs/features/cli-licence-api#publishing-bundles) gives the key, the content type and the buckets. The privacy policy says that a bundle request sends the release and the stack's answers, which the API does not keep.
