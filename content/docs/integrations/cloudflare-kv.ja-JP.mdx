どの環境も KV 名前空間を `CACHE` としてバインドします。エントリーは 1 つです。

## GitHub のスター数

サイトに表示する GitHub のスター数で、`src/lib/github.ts` に実装されています。

- `getStarCount` は `github:<owner>/<repo>:stars` エントリーを読み取ります。
- エントリーがない場合は、<RepositoryFact name="starCountFetchTimeoutSeconds" unit="second" />のタイムアウトで GitHub API からリポジトリを取得してスター数を返し、`waitUntil` で `count` と `fetchedAt` を KV に書き込みます。
- エントリーが <RepositoryFact name="starCountRefreshHours" unit="hour" />（`STAR_COUNT_REFRESH_AFTER_MS`）より古い場合は、キャッシュされたスター数を返し、バックグラウンドで更新します。
- `starCountQuery` も同じ時間だけ結果をクエリキャッシュに保持します。`STAR_COUNT_REFRESH_AFTER_MS` はその `gcTime` でもあり、テストビルド以外ではその `staleTime` でもあります。テスト用 Worker は GitHub API に固定のスター数で応答するため、テストビルドでは `starCountStaleTime` がスター数を古くならないようにし、`build:test` がプリレンダリングしたページは、ビルドからどれだけ時間が経ってもスター数を取得し直しません。

エントリーには KV の有効期限を設定しておらず、更新のタイミングは `fetchedAt` で判断します。GitHub へのリクエストは、GitHub OAuth アプリの認証情報 `AUTH_GITHUB_CLIENT_ID` と `AUTH_GITHUB_CLIENT_SECRET` で認証されます。

## 整合性とテスト

KV は結果整合性のストアです。セッション、レート制限、認可に使うものはすべて D1 に保存されます。

Vitest では、`cloudflare:workers` が `src/platform/testing/mocks/cloudflare.ts` に解決され、インメモリの `CACHE` が提供されます。Wrangler の `test` 環境は `.wrangler/test` 配下のローカル名前空間を使います。
