| Zadanie                                                                           | Polecenie                |
| --------------------------------------------------------------------------------- | ------------------------ |
| Uruchomienie serwera deweloperskiego                                              | `bun run dev`            |
| Sprawdzenie formatowania, lintera, typów i tłumaczeń                              | `bun run check`          |
| Uruchomienie wszystkich projektów Vitest                                          | `bun run test`           |
| Sprawdzenie progu pokrycia                                                        | `bun run test:coverage`  |
| Uruchomienie przeglądarkowego testu smoke                                         | `bun run test:e2e:smoke` |
| Uruchomienie wszystkich testów przeglądarkowych w Chromium                        | `bun run test:e2e:pr`    |
| Uruchomienie wszystkich testów przeglądarkowych w Chromium i WebKit, tak jak w CI | `bun run test:e2e`       |
| Wygenerowanie migracji                                                            | `bun run db:generate`    |
| Zbudowanie Workera preview                                                        | `bun run build`          |
| Serwowanie ostatniego buildu                                                      | `bun run start`          |
| Wdrożenie preview                                                                 | `bun run deploy:preview` |

Przed otwarciem pull requesta wykonaj kroki z [Współtworzenia](/docs/project/contributing) razem ze specyfikacjami, które obejmują Twoją zmianę:

```sh
bun run check
bun run test:coverage
bun run build:test
bunx playwright test e2e/specs/<spec>.spec.ts --project=chromium
```

Lokalnie Playwright odtwarza testową bazę danych poleceniem `db:reset:test`, buduje testowego Workera i uruchamia go pod adresem z `PLAYWRIGHT_BASE_URL` (`127.0.0.1:3000`, gdy zmienna nie jest ustawiona), chyba że odpowiada tam już serwer. Każdy worktree bierze własny port z zakresu, któremu ufa build testowy, a przebieg zatrzymuje się, gdy serwer na jego porcie należy do innego worktree: zobacz [Uruchamianie obok innych worktree](/docs/tooling/playwright#running-beside-other-worktrees).

Używaj `bun run test`, a nie `bun test`, aby Vitest działał z konfiguracją projektu. Skrypty kończące się nazwą środowiska, takie jak `db:migrate:preview` czy `deploy:production`, działają wyłącznie na tym środowisku.

Pełną listę znajdziesz na stronie [Skrypty projektu](/docs/tooling/scripts).
