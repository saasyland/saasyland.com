## リンクの請求

`/auth/forgot-password` は `ForgotPasswordForm` を表示します。フォームは `requestPasswordReset`（`src/modules/verification/use-cases/request-password-reset.ts`、`RATE_LIMITS.SENSITIVE` で制限）を、現在の言語の `/auth/reset-password` を指す `redirectTo` 付きで呼び出します。続いて Better Auth が `sendResetPasswordEmail` を呼び出し、`ResetPasswordEmail` テンプレートを送信します。リセットメールはアドレスごとに 1 時間あたり最大 <RepositoryFact name="recipientEmailsPerHour" /> 通までしか送信しません（`withinRecipientRateLimit`）。それ以降のリクエストでは何も送信せず、同じレスポンスを返します。リンクは `EMAIL_LINK_LIFETIME_HOURS`（`resetPasswordTokenExpiresIn`）の間有効で、メールにもそのことが記載されます。

## 新しいパスワードの設定

メールのリンクは `/auth/reset-password?token=…` を開きます。トークンがない場合や `?error=` がある場合、ページは無効なリンクのメッセージと `/auth/forgot-password` へ戻るリンクを表示します。トークンがあれば `ResetPasswordForm` が `resetPassword`（`RATE_LIMITS.TOKEN` で制限）を呼び出し、`/auth/sign-in` へ移動します。`revokeSessionsOnPasswordReset` が有効なため、そのユーザーの既存セッションはすべて終了します。続いて `onPasswordReset` が、リセットページの言語で `PasswordChangedEmail` をバックグラウンドで送信します。このメールは、パスワードが変更されてすべてのセッションが終了したことを伝え、サインインへのリンクを示し、変更した覚えのない人にはパスワードをリセットして `CONTACT_EMAIL` に連絡するよう案内します（OWASP の Forgot Password チートシート）。送信に失敗した場合はログに記録され、新しいパスワードはそのまま有効です。

## その他のパスワード変更

- サインイン済みのユーザーは **設定 → セキュリティ** でパスワードを変更します（[設定](/docs/features/settings)）。
- 管理者はユーザーテーブルから他のユーザーのパスワードを設定します（[ユーザー（管理）](/docs/features/users-admin)）。
