## Base de datos

**`no such table` en `bun run dev`.** La base de datos local de desarrollo no se ha migrado. Ejecuta `bun run db:migrate:local`, o `bun run db:reset:local` y `bun run db:seed:local` para tener una nueva y sembrada.

**`no such table` en Playwright.** Las pruebas de navegador usan su propia base de datos local. Ejecuta `bun run db:reset:test`, o deja que Playwright arranque la aplicación, que lo ejecuta.

**Las tablas de Vitest están desactualizadas.** Al arrancar, el mock de D1 aplica todos los archivos SQL de `src/integrations/drizzle-orm/migrations`. Después de cambiar el esquema, genera una migración con `bun run db:generate`.

## Servidor de desarrollo

**El servidor de desarrollo no arranca.** Escucha en `localhost:3000` con `strictPort`, así que falla cuando el puerto está ocupado. Detén el otro proceso.

**Falla el inicio de sesión o OAuth.** Comprueba `AUTH_SECRET` y las credenciales del cliente OAuth en el archivo de entorno, y que la URL de callback del proveedor apunte a <RepositoryFact name="oauthCallbackPath" /> en el host que estás usando. Better Auth solo acepta los hosts configurados para el modo de build: `localhost:3000` y `127.0.0.1:3000` en desarrollo.

**A los tipos del Worker les falta un binding o un secreto.** Ejecuta `bun run cf-typegen` después de cambiar `wrangler.jsonc`: tipa cada binding y cada secreto de `secrets.required`. Un valor que Wrangler no puede derivar, como una variable que solo define `test`, va en el `src/types/<feature>.d.ts` de la funcionalidad.

**Las clases personalizadas `text-*` desaparecen al combinarlas.** `cn` depende de tablas generadas a partir de `src/lib/cn.config.ts`. `bun run dev`, `bun run check` y los builds las regeneran; ejecuta `bun run generate:cn` si falta `.source/cn-tables.ts`.

## Traducciones

**`No messages/<locale>/<namespace>.json`.** Una ruta declara un namespace que no tiene archivo para ese locale. Crea el archivo en todos los locales.

**Se muestra la ruta de una clave en lugar de su texto, o `check:i18n` informa de que falta una clave.** La clave falta en algún locale, o el componente la lee fuera del ámbito de su llamada a `useTranslations`. Usa un único `useTranslations` por componente y ejecuta `bun run check:i18n`.

## Documentación

**Una página de la documentación devuelve 404.** El archivo debe llamarse `<page>.<locale>.mdx` y figurar en `pages` dentro del `meta.<locale>.json` de su carpeta. Ejecuta `bun run content` para regenerar `.source`.

**Falla `check-content.ts`.** Compara cada locale con en-US. `Changed code examples` significa que un bloque de código difiere del inglés; los bloques de código deben ser idénticos. `Untranslated English paragraph` significa que se ha copiado un párrafo sin traducirlo. `Missing <file>` significa que no existe el archivo de un locale. `leaves out … from the English page` y `adds …, which the English page does not have` significan que una traducción perdió o añadió código en línea, un componente o una de sus props, o un enlace a otra página; cópialo tal como lo tiene la página en inglés. `has … table rows where the English page has …` significa que una tabla perdió o ganó una fila. `links to … instead of …` significa que un enlace interno se redirigiría o nombra un locale; escribe la ruta que propone el mensaje.

**Falla `check-message-formats.ts`.** `changed the path or command …` significa que una traducción cambió una ruta de archivo o un comando del mensaje en inglés; déjalo como está o pásalo como argumento ICU desde `REPOSITORY_FACTS`. `unexpected Markdown code` significa que una traducción añadió comillas invertidas, que un mensaje muestra tal cual. `uses “Sie” where de-DE addresses the reader as “du”` significa que una traducción trata al lector de una forma que su idioma no usa; reescribe la frase con el [tratamiento](/docs/conventions/translations#one-form-of-address) del idioma. `check-content.ts` informa de lo mismo en una página de la documentación, una entrada del blog o una entrada del changelog.

## Pruebas y despliegue

**Falla `test:coverage`.** La cobertura debe ser del <RepositoryFact name="coverageThreshold" unit="percent" /> en líneas, sentencias, funciones y ramas. El informe de `coverage/` enumera las líneas sin cubrir.

**El despliegue se detiene en `verify-bindings.ts`.** Al entorno de destino en `wrangler.jsonc` le falta un binding que declara el entorno `development` (`DB`, `CACHE`, `MEDIA` o `BUNDLES`), todavía tiene IDs provisionales de D1 o KV o, en el caso de producción, comparte un recurso con preview. Crea los recursos en Cloudflare y sustituye los IDs.

**El despliegue se detiene en `prepare-deploy-secrets.ts`.** Una clave que figura en `secrets.required` del entorno falta en `.env.<environment>`, está vacía o es un marcador de posición. `Set …` indica las claves que faltan o están vacías, y `Replace the placeholders …` las claves que contienen un valor entre corchetes, como `[UPDATE]`, o una palabra como `TODO` o `changeme`; ninguno de los dos muestra un valor. [Scripts del proyecto](/docs/tooling/scripts) enumera todos los marcadores de posición que rechaza. Pon los valores reales en el archivo y vuelve a ejecutar el despliegue.

**El despliegue se detiene en `auth:verify`.** Un identificador de cliente OAuth de `.env.<environment>` no tiene el formato de su proveedor, así que el proveedor rechazaría el inicio de sesión. El error indica la variable, el archivo y el proveedor sin mostrar el valor, por ejemplo `AUTH_GOOGLE_CLIENT_ID in .env.production is not a Google OAuth client ID.` Copia el identificador de cliente de la consola del proveedor (para Google, consulta más abajo la entrada sobre `invalid_client`) y ejecuta `bun run auth:verify:<environment>` para volver a comprobarlo.

**El despliegue se detiene en `polar:verify`.** Polar no coincide con el código: falta una clave en `.env.<environment>` o indica el servicio de Polar equivocado, el token se rechaza o le falta un ámbito, o la localización del pago o el comportamiento fiscal de la organización, un producto, un precio, una clave de licencia o un webhook difiere de lo que espera el código. El error enumera cada problema; [Configuración de Polar](/docs/getting-started/polar-setup) explica cada mensaje. `bun run polar:verify:<environment>` vuelve a ejecutar la comprobación.

**El despliegue se detiene en `verify-deployment.ts`.** El Worker está desplegado, pero una de las rutas comprobadas no ha respondido `200` con el tipo de contenido esperado, o un inicio de sesión no ha llegado a su proveedor como debía. El error enumera cada petición y lo que ha fallado; abre la URL y lee los registros del Worker en Cloudflare. Una línea que termina en `client_id is not a Google OAuth client ID.` significa que el Worker no tiene un identificador de cliente real para ese proveedor; consulta la entrada siguiente. `bun scripts/verify-deployment.ts <preview|production>` vuelve a ejecutar la comprobación.

**Google responde `Error 401: invalid_client` y `The OAuth client was not found.`** El Worker ha enviado a Google un identificador de cliente que Google no conoce. `bun run deploy:<environment>` rechaza antes de la compilación un marcador de posición o un valor con otro formato en `AUTH_GOOGLE_CLIENT_ID` (consulta `prepare-deploy-secrets.ts` y `auth:verify` más arriba), así que un secreto del Worker que contiene uno se configuró de otra forma, por ejemplo con `wrangler secret put`. Un identificador de cliente con el formato de Google que Google no conoce pertenece a un cliente que se eliminó o que está en otro proyecto de Google Cloud. Para solucionarlo:

1. En la consola de Google Cloud, abre **Google Auth Platform → Clients** y crea un cliente de tipo **Web application**, o abre el que quieras usar. Su identificador de cliente termina en `.apps.googleusercontent.com`.
2. Añade `https://<host>` a **Authorized JavaScript origins** y <RepositoryFact name="googleCallbackUrl" /> a **Authorized redirect URIs** para cada host en el que despliegues; Google puede tardar unos minutos en aplicarlos.
3. En **Google Auth Platform → Audience**, selecciona **Publish app** para que pueda iniciar sesión cualquier cuenta de Google y no solo los usuarios de prueba.
4. Guarda el identificador y el secreto del cliente en `AUTH_GOOGLE_CLIENT_ID` y `AUTH_GOOGLE_CLIENT_SECRET` en `.env.<environment>` y ejecuta `bun run deploy:<environment>`, que comprueba el identificador de cliente antes de la compilación, sube los dos secretos del Worker y vuelve a comprobar el inicio de sesión.

**Falla un build con prerenderizado.** La salida del build indica la primera URL que ha fallado. Abre esa página con `bun run dev` para ver el error.
