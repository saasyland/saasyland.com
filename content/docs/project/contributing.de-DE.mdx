---
title: "Mitwirken"
description: "Wie Sie Änderungen an SaaSy Land vorschlagen."
---

1. Besprechen Sie größere Änderungen zuerst in einem Issue.
2. Erstellen Sie einen Branch von `main`.
3. Halten Sie sich an die [Architektur](/docs/architecture) und die [Konventionen](/docs/reference/conventions), und lesen Sie den passenden [Agent-Skill](/docs/tooling/agent-skills), bevor Sie eine Anbieter-Integration ändern.
4. Legen Sie Tests neben ihren Besitzer und halten Sie die Testabdeckung bei 100 %.
5. Führen Sie die folgenden Prüfungen aus.
6. Committen Sie mit einer Nachricht im Format der [Conventional Commits](/docs/tooling/conventional-commits) und öffnen Sie einen Pull Request mit einem konventionellen Titel.

```sh
bun run check
bun run test:coverage
bun run test:e2e:install
bun run test:e2e:smoke
```

Führen Sie die vollständige Browser-Suite (`bun run test:e2e`) für Änderungen aus, die mehrere Routen, die Authentifizierung oder das Browserverhalten betreffen. Prüfen Sie echte Anbieter-Integrationen separat, wenn Sie deren Konfiguration ändern.

Wenn sich Verhalten ändert, aktualisieren Sie `content/docs` in allen neun Sprachen; `bun run check:i18n` weist fehlende Übersetzungen, abweichende Codeblöcke und abweichende Navigation zurück. Beschreiben Sie im Pull Request das resultierende Verhalten, wie Sie es geprüft haben und welche Demo- oder unfertigen Abläufe zurückbleiben.
