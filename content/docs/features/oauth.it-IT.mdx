description: "Accesso con GitHub e Google tramite i provider social di Better Auth."
---

`auth.server.ts` registra due provider con credenziali prese dall’ambiente del Worker, con chiavi date dagli ID dei provider in `AUTH_PROVIDER` (`auth.constants.ts`):

```ts
socialProviders: {
  [AUTH_PROVIDER.GITHUB]: { clientId: env.AUTH_GITHUB_CLIENT_ID, clientSecret: env.AUTH_GITHUB_CLIENT_SECRET },
  [AUTH_PROVIDER.GOOGLE]: { clientId: env.AUTH_GOOGLE_CLIENT_ID, clientSecret: env.AUTH_GOOGLE_CLIENT_SECRET },
},
```

## Flusso

`OAuthButtons` (`src/presentation/components/custom/auth/oauth-buttons.tsx`) mostra un pulsante per provider nelle pagine di accesso e registrazione, con l’etichetta **Continua con Google** o **Continua con GitHub** (`auth.oauth.continueWith`) su entrambe. Chiama `signIn.social` di Better Auth con un `callbackURL` localizzato (`/auth/callback`) e un `errorCallbackURL` (`/auth/sign-in`). Al ritorno dal provider, `/auth/callback` reindirizza gli amministratori su `/admin` e i clienti su `/app`. Un tentativo fallito torna alla pagina di accesso con `?error=`, che mostra il messaggio tradotto di `auth.errors`.

`accountLinking` è attivo, quindi un accesso social si collega a un utente esistente con la stessa email. I token del provider sono salvati cifrati nella tabella `account`.

## Configurazione del provider

Registra gli URL di callback <RepositoryFact name="oauthCallbackPaths" /> per ogni host che usi: `localhost:3000` in locale, `preview.saasyland.com` e `saasyland.com` (vedi `DEPLOYED_HOSTS` in `src/modules/_core/constants/api.ts`). Inserisci ID e secret dei client nelle variabili d’ambiente indicate sopra.

Dopo un deploy, `scripts/verify-deployment.ts` avvia l'accesso con ogni provider sul dominio distribuito e fallisce quando l'URL di autorizzazione del provider non è sul suo host, contiene un `client_id` che non è nel formato di quel provider, come un segnaposto dimenticato in `.env.<environment>`, o un `redirect_uri` che non riporta allo stesso dominio ([Script del progetto](/docs/tooling/scripts)). [Risoluzione dei problemi](/docs/reference/troubleshooting) spiega come correggere l'errore `Error 401: invalid_client` di Google.

Le credenziali GitHub autenticano anche la richiesta del numero di stelle del repository in `src/lib/github.ts`.
