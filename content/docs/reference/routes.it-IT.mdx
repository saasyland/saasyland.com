Ogni percorso ha una costante in `ROUTES` (`src/routes.ts`). I link usano la costante, ad esempio `<Link to={ROUTES.SIGN_IN}>`, e il router aggiunge il prefisso del locale. Ogni pagina elencata qui sotto viene servita anche con ciascun prefisso di locale non predefinito, ad esempio `/pl-PL/terms`.

## Pagine pubbliche

Queste pagine usano il layout `_landing` (navigazione e footer), tranne blog e documentazione, che hanno layout propri. Sono tutte prerenderizzate, tranne le pagine della newsletter.

| ------------------------- | ------------------------ | ------------------------------------- |

## Autenticazione

Il layout `/auth` (`auth.tsx`) non ha una guard; le guard sono sulle singole pagine.

| Percorso                | Costante          | File di route              | Guard                                                          |
| ----------------------- | ----------------- | -------------------------- | -------------------------------------------------------------- |
| `/auth/sign-in`         | `SIGN_IN`         | `auth.sign-in.tsx`         | `redirectIfSignedIn`                                           |
| `/auth/sign-up`         | `SIGN_UP`         | `auth.sign-up.tsx`         | `redirectIfSignedIn`                                           |
| `/auth/forgot-password` | `FORGOT_PASSWORD` | `auth.forgot-password.tsx` | nessuna                                                        |
| `/auth/reset-password`  | `RESET_PASSWORD`  | `auth.reset-password.tsx`  | nessuna                                                        |
| `/auth/two-factor`      | `TWO_FACTOR`      | `auth.two-factor.tsx`      | nessuna                                                        |
| `/auth/verify-email`    | `VERIFY_EMAIL`    | `auth.verify-email.tsx`    | Reindirizza un `token` all'endpoint di verifica di Better Auth |
| `/auth/callback`        | `AUTH_CALLBACK`   | `auth.callback.tsx`        | `redirectAfterAuth`                                            |

## API

I percorsi API non vengono mai localizzati.

| Percorso      | Costante        | File di route   |
| ------------- | --------------- | --------------- |
| `/api`        | `API`           | `api/index.ts`  |
| `/api/auth/*` | `API_AUTH_BASE` | `api/auth.$.ts` |
| `/api/search` | nessuna         | `api/search.ts` |

`ROUTES.API_AUTH` elenca i percorsi degli endpoint di Better Auth relativi a `/api/auth`; `auth.server.ts` li usa per escludere alcuni endpoint dal rate limiting. `API_AUTH_CUSTOMER_PORTAL` e `API_AUTH_VERIFY_EMAIL` sono percorsi completi di endpoint di Better Auth. `AUTH` e `NEWSLETTER` non hanno una pagina propria; insieme ad `ADMIN`, `APP` e `API` identificano le aree che non vengono mai prerenderizzate.
