CLI `saasyland`、`create-saasyland`、`@saasyland/stack` は同じバージョン番号でまとめてリリースされ、以下のプレリリースは 0.1.0-beta.3 を除いてすべて npm の `beta` タグで公開されました。現在のリリースは [CLI ガイド](/docs/cli)で、このウェブサイトの変更点は[変更履歴](/docs/project/changelog)で説明しています。

## 0.1.0-beta.5

### saasyland

- **破壊的変更：** Lemon Squeezy がサービスを終了するため、`--billing lemonsqueezy` を削除しました。Lemon Squeezy は 2026年11月16日から新規登録を受け付けておらず、2027年3月31日に終了します。`--billing polar` と `--billing stripe` は `--billing` が認識する値として残りますが、生成されるプロジェクトにはまだ課金がないため、`init` は引き続きどちらもコード <RepositoryFact name="cliExitNotAvailable" /> で拒否します。`init --billing lemonsqueezy` は、`--billing` にないほかの値と同じく、コード <RepositoryFact name="cliExitUsage" /> で終了するようになりました。

### create-saasyland

- **破壊的変更：** `saasyland` と同じく `--billing lemonsqueezy` を削除しました。指定するとコード <RepositoryFact name="cliExitUsage" /> で終了します。

### @saasyland/stack

- **破壊的変更：** Lemon Squeezy がサービスを終了するため、`BILLING.LEMONSQUEEZY` と課金の選択肢 `lemonsqueezy` を削除しました。Polar（`BILLING.POLAR`）と Stripe（`BILLING.STRIPE`）はマトリクスの選択肢として残りますが、どのテンプレートもまだ課金を生成しないため、`TEMPLATE_SUPPORT` は引き続き課金として `none` だけを挙げます。

## 0.1.0-beta.4

このリリースには、公開されなかった 0.1.0-beta.3 のすべての変更も含まれています。

### saasyland

- `saasyland init` に新しい最初の質問として UI ライブラリ（`--library react`、`angular`、`vue`、`svelte`、`solid`）が加わり、これによって提示されるフレームワークが決まります。React では TanStack Start に加えて Next.js と React Router、Angular では Analog と Angular SSR、Vue では Nuxt、Svelte では SvelteKit、Solid では TanStack Start に加えて SolidStart です。セルフホストのプロジェクト向けに、`node` と `bun` に `--runtime deno` が加わりました。
- このリリースが生成するのは React と TanStack Start で、`--yes` はこれを回答として選びます。`--help` はほかのライブラリ、それらのフレームワーク、Deno をまだ利用できないものとして示し、`init` はそれらを終了コード <RepositoryFact name="cliExitNotAvailable" /> で拒否します。その際、フレームワークより先に、そのフレームワークが依存するライブラリを示します。

### create-saasyland

- `saasyland` と同じく、UI ライブラリの質問が加わりました。`--library` が最初に来てフレームワークを決め、生成されるのは React と TanStack Start だけです。

### @saasyland/stack

- **破壊的変更：** マトリクスの最初の質問は UI ライブラリになりました。`CHOICE.LIBRARY`、`STACK_FLAG.LIBRARY`（`--library`）、`LIBRARY`（`react`、`angular`、`vue`、`svelte`、`solid`）があり、`STACK_DEFAULTS` には `react` が入ります。`stackZodSchemas.answers` は `library` のない完全な回答セットを拒否します。
- `FRAMEWORK` に `analog`、`angular-ssr`、`nuxt`、`sveltekit`、`solid-start` が加わり、それぞれ対応するライブラリでのみ表示されます（`tanstack` は `react` と `solid`）。`RUNTIME` には、Cloudflare と Vercel では動かない `deno` が加わりました。`TEMPLATE_SUPPORT` は `library` として `react` だけを挙げるので、マトリクスをもとに作った構成ツールはそれらをすべて表示し、React と TanStack Start 以外をすべて無効にします。

## 0.1.0-beta.3

npm には公開されていません。承認される前に 0.1.0-beta.4 がこのバージョンに取って代わり、以下の変更はすべて 0.1.0-beta.4 で提供されました。

### saasyland

- `saasyland --help` と `saasyland init --help` は、すべての質問のすべての値を一覧表示し、このリリースで生成できない値と、まだ提供されていないコマンドを、まだ利用できないものとして示します。
- `init` はそのような値を、ライセンスを確認する前にすぐに拒否します。`--billing polar` はコード <RepositoryFact name="cliExitNotAvailable" /> で終了し、このリリースでは利用できないことを伝え、利用できる `--no-billing` を示します。`init` がコピー用に出力するコマンドには、このリリースが生成する回答しか含まれません。
- 課金のテンプレートが提供されるまで、`init` は課金なしでプロジェクトを生成します。`--yes` と、質問が提供されるまでのターミナルは、課金の質問に `--no-billing` で答えて `saasyland.json` にそれを記録し、ほかの質問にはこれまでどおりこのウェブサイト自身のスタックで答えます。

### create-saasyland

このリリースでの変更はありません。

### @saasyland/stack

- 新しいエントリポイント `@saasyland/stack/cli` を追加しました。`saasyland` CLI が使い、ドキュメントに記載している値です。終了コード（`EXIT_CODE`）、読み取る環境変数（`CLI_VARIABLE`）、ライセンスを保存する場所とその権限（`CREDENTIALS_STORE`）、このリリースのテンプレートが対応する回答（`TEMPLATE_SUPPORT`）、各テンプレートレイヤーの ID（`TEMPLATE_LAYER`）です。このエントリポイントには定数しかないため、ブラウザのバンドルにも適しています。
- このリリースのどのテンプレートもまだ課金を生成しないため、`TEMPLATE_SUPPORT` は課金として `none` だけを挙げます。以前は Polar を挙げていましたが、生成されたプロジェクトに Polar が含まれたことはありませんでした。
- `resolveAnswers` は、テンプレート一式が対応するオプションを省略可能な 2 番目の引数として受け取ります。その場合、未回答の各質問に、オプションに既定値が含まれていれば既定値で、含まれていなければオプションのうち最初の有効なもので答えます。`resolveAnswers(given, TEMPLATE_SUPPORT.choices)` は、`saasyland init --yes` と同じように回答を解決します。

## 0.1.0-beta.2

### saasyland

- `saasyland init` がプロジェクトを作成します。実行するたびに、この端末で有効化されたライセンス、<RepositoryFact name="cliLicenseKeyVariable" /> のキー、または求められたときに入力したキーを使って saasyland.com でライセンスを確認し、そのリリース自身のテンプレートをダウンロードします。
- サイズまたは SHA-256 が、saasyland.com が送ってきた値やこのリリースが固定したダイジェストと異なるテンプレートは拒否します。プロジェクトは新しいディレクトリか空のディレクトリに一度に書き出すので、Ctrl+C や書き込みの失敗があっても何も残りません。リリース、回答、すべてのファイルのダイジェストは `saasyland.json` に記録します。`--dry-run` は何も書き出さずに、書き出すはずのすべてのファイルを一覧表示し、`--cwd` は別のディレクトリで起動したかのように実行します。
- 終了コードが問題の内容を示します。<RepositoryFact name="cliExitTemporaryFailure" /> は後で再試行すべきとき、<RepositoryFact name="cliExitProtocol" /> はテンプレートが一致しないとき、<RepositoryFact name="cliExitNoPermission" /> はライセンスが拒否されたとき、<RepositoryFact name="cliExitNotAvailable" /> はこのリリースにテンプレートがない回答のとき、<RepositoryFact name="cliExitCancelled" /> は Ctrl+C の後です。
- 新しいプロジェクトにサインインが加わります。自分の D1 データベース上の Better Auth で、メールアドレスとパスワード、GitHub と Google、メールアドレスの確認、パスワードリセット、二要素認証、ロール、なりすまし、取り消し可能なセッションに対応し、サインインのページ、管理画面のダッシュボード・ユーザー・設定、設定付きの顧客ワークスペースを備えます。確認、パスワードリセット、メールアドレス変更のメールは Resend 経由で送る React Email のテンプレートで、プロジェクトの Playwright スイートは Chromium と WebKit でサインインとメールアドレスの確認を行います。`--no-auth` はサインインのないプロジェクトを生成します。サインインがこれらのメールを送るため、`--email none` はまだ利用できません。
- 新しいプロジェクトにドキュメントサイトとブログが加わります。ドキュメントは Fumadocs で動き、検索、入門のセクション、そしてプロジェクト自身のコードが従うコーディング規約である「規約」を備えます。ブログは MDX で、記事の書き方と公開の仕方を説明する最初の記事が付きます。どちらもプロジェクトが対応するすべての言語で用意され、ホームページからリンクされ、事前レンダリングされてサイトマップに載ります。ある言語でページや記事が欠けている場合や、翻訳がコード、リンク、表を変えている場合は、プロジェクトのチェックが失敗します。サインインのないプロジェクトにも含まれます。`--content none` はまだ利用できません。
- 新しいプロジェクトに README、コーディングエージェント向けの `AGENTS.md`、GitHub Actions の CI ワークフローが加わります。README と `AGENTS.md` は選んだスタックを説明するので、`--no-auth` で作ったプロジェクトにはサインインの説明がなく、そこに書かれたコマンドはすべてプロジェクト自身のスクリプトです。ワークフローは、すべてのプルリクエストと `main` へのすべてのプッシュで、チェックとカバレッジ付きのテストを実行し、続いてテストビルドに対してブラウザのスイートを実行します。最初にプッシュする前に、`bun install` と、README の Getting started に記載されたコマンドを実行し、`bun.lock` とそれらが書き出すファイルをコミットしてください。CI はそれらを読み取ります。
- 新しいプロジェクトのドキュメントは、最初のインストールから最初のデプロイまでを案内します。インストールのページでは、最初のコミットの前にロックファイルを書き出し、マイグレーション、ルートツリー、Worker の型を生成します。環境変数のページでは、認証のシークレット、GitHub と Google の OAuth アプリとそのコールバック URL、Resend の API キーとドメインを含め、すべての値の入手先を説明します。デプロイのページでは、D1 データベースを作成し、その ID を `wrangler.jsonc` に設定し、ホストに名前を付けて、プレビュー環境をデプロイします。各ページには選んだスタックの手順だけが、プロジェクトが対応するすべての言語で載っており、README がそれらをまとめています。
- `saasyland` は、以前のバージョンに含まれていた草案に代えて、このウェブサイトの[ライセンス条項](/licence)と一字一句同じ、承認済みのライセンスを `LICENSE.md` として同梱するようになりました。
- `latest` はまだどのコマンドも使えないプレースホルダーのリリースなので、npm の README は `beta` の dist-tag から CLI を実行します。また、何が動くのかも説明しています。`init` はプロジェクトを作成し、`activate`、`whoami`、`deactivate` はライセンスを管理します。
- 新しいプロジェクトには `.editorconfig` が含まれなくなりました。`vite.config.ts` のフォーマッターの設定と `.gitattributes` が、そこにあった値をすべてすでに設定しているため、同じ設定の 2 つ目の情報源になっていました。

### create-saasyland

- `create-saasyland` は、このウェブサイトの[ライセンス条項](/licence)と一字一句同じ、承認済みのライセンスを `LICENSE.md` として同梱するようになりました。
- `latest` はまだプレースホルダーのリリースなので、npm の README は `beta` の dist-tag からこれを実行します。

### @saasyland/stack

- npm のパッケージの説明から、saasyland.com がスタックのマトリクスを共有しているという記述がなくなりました。
- `latest` はまだ `@saasyland/stack/api` のないプレースホルダーのリリースなので、npm の README は `beta` の dist-tag からパッケージをインストールします。

## 0.1.0-beta.1

### saasyland

- `saasyland activate` はこの端末でライセンスキーを有効化します。キーは引数か <RepositoryFact name="cliLicenseKeyVariable" /> で渡すか、求められたときに入力します（入力中は表示されません）。`saasyland whoami` はプラン、使用中の枠、この端末の名前を表示し、`saasyland deactivate` はこの端末の枠を解放します。
- ライセンスは設定ディレクトリ内の、あなたのユーザーだけが読めるファイルに保存され、1 つの CI リポジトリのすべての実行が 1 つの有効化を共有し、返金または取り消されたライセンスは端末から削除されます。
- 3 つのコマンドはいずれも `--json` で結果を 1 つの JSON ドキュメントとして出力し、もともと適用されていなかった `--cwd` と `--dry-run` は受け付けなくなりました。

### create-saasyland

このリリースでの変更はありません。

### @saasyland/stack

- `@saasyland/stack/api` は CLI のバージョンとリリースを `API_LIMIT.VERSION_MAX_LENGTH` 文字までに制限します。それより長い値には、ライセンス API がほかの不正なフィールドと同じく `invalidRequest` を返します。

## 0.1.0-beta.0

### saasyland

- `saasyland` CLI の最初のプレビューです。`saasyland --help` はすべてのコマンドを、`saasyland init --help` は構成の選択肢をすべてフラグとして一覧表示します。
- フラグは何かを実行する前に検証されます。`--db postgres` なしの `--provider neon` のように、未知の値や成り立たない組み合わせは、理由と終了コード <RepositoryFact name="cliExitUsage" /> とともに拒否されます。
- 出力は英語、ドイツ語、スペイン語、フランス語、イタリア語、日本語、ポーランド語、ブラジルポルトガル語、ウクライナ語に対応し、`--locale` かシステムの言語で選ばれます。`--json` はスクリプトやコーディングエージェント向けに 1 つの JSON ドキュメントを出力します。
- プロジェクトの生成とライセンスの有効化は次のプレビューで提供予定です。それまでは、これらのコマンドはその旨を表示し、コード <RepositoryFact name="cliExitNotAvailable" /> で終了します。

### create-saasyland

- `create-saasyland` の最初のプレビューです。`npm create saasyland`、`bun create saasyland`、`pnpm create saasyland`、`yarn create saasyland` は、同じフラグで `saasyland init` を実行します。

### @saasyland/stack

- 新しいエントリポイント `@saasyland/stack/api` を追加しました。これは `saasyland` CLI が呼び出す saasyland.com のライセンス API の契約です。<RepositoryFact name="cliApiBasePath" /> 配下のルート、ヘッダー、リクエストとレスポンスのスキーマ、エラーコード、上限を定義し、すべてのリクエストとレスポンスの組み立てと読み取りを行います。`@saasyland/stack` だけをインポートした場合、これらは一切読み込まれません。
