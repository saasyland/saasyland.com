The tiers are priced in code and in Polar, as below. The admin has no pricing screen: managing products and prices from the admin is on the [roadmap](/docs/project/roadmap).

## Where prices come from

- **Landing page**: `TIER_PRICES` in `src/data/license.ts`: `core` <TierPrice tier="core" />, `complete` <TierPrice tier="complete" />, `agency` <TierPrice tier="agency" />. `Price` formats them in the page locale. The landing page description takes the Core price as `{price}`, and blog posts and docs pages print a tier's price with `<TierPrice tier="core" />`, so no copy types a price. The consulting card's hourly rate is `CONSULTING_HOURLY_RATE` in `src/data/marketing.ts`; the call is booked by email rather than sold through Polar, so it has no regional price.
- **Checkout**: the Polar products referenced by `POLAR_PRODUCT_ID_CORE`, `POLAR_PRODUCT_ID_COMPLETE` and `POLAR_PRODUCT_ID_AGENCY`. A regional or upgrade price goes to the checkout as a price of its own (see [Licences](/docs/features/licences#starting-the-checkout)).
- **Regional prices**: `PPP_TIERS` in `src/modules/license/license.pricing.ts`, a price multiplier per group of countries. `regionalPrice` multiplies a tier's price and rounds it down to whole dollars, for the tier cards and for checkout alike:

`bun run polar:verify:<environment>` compares the Polar product prices with `TIER_PRICES`, and the deploy scripts run it before every manual deploy. Regional prices need nothing in Polar. Change the code first, then Polar; see [Polar setup](/docs/getting-started/polar-setup).

## Currency and prices

- **Store currency**: `DEFAULT_CURRENCY_CODE` in `src/modules/_core/constants/pricing.ts`. To charge in another currency, change it there; it is defined nowhere else. It lives beside the pricing constants rather than in `currency.ts`, so the landing page does not load the `CURRENCIES` catalogue.
- **What it changes**: `CURRENCY_FORMAT`, and with it every price on the landing page, the tier cards, `<TierPrice>` in the blog and the consulting rate; and the default `currency` of new products (`product.schema.ts`, `createProduct`). The admin dashboard shows revenue in the currency each order was paid in, whatever the store currency. Prices are rounded to the currency's minor unit by `Intl.NumberFormat`, which knows each ISO 4217 currency's decimals; regional prices are whole units already, because `regionalPrice` rounds them down.
- **What it does not change**: Polar charges in the currency of the Polar product prices, so set the products to the same currency and the amounts in `TIER_PRICES`. `TIER_PRICES` mirrors the Polar prices until prices are managed from the admin and read from Polar. Affiliate payouts stay in `AFFILIATE_TERMS.PAYOUT_CURRENCY`, the US dollars Affonso pays out in.
