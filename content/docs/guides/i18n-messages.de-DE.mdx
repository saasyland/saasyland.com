Messages verwenden `use-intl` mit ICU-Syntax. Jeder Namespace ist eine JSON-Datei pro Locale in `messages/<locale>/<namespace>.json`, für die neun Locales `en-US` (Standard), `de-DE`, `es-ES`, `fr-FR`, `it-IT`, `ja-JP`, `pl-PL`, `pt-BR` und `uk-UA`. Der Dateiname ist der Namespace: `messages/en-US/pages.admin.users.json` ist `pages.admin.users`.

## Namespace-Typen

| Namespace                                  | Geladen von                                                         |
| ------------------------------------------ | ------------------------------------------------------------------- |
| `common`, `components.*`, `errors*`        | Dem `beforeLoad` der Root-Route, auf jeder Seite                    |
| `pages.*`                                  | Der Seiten-Route, die ihn deklariert                                |
| Layout-Namespaces, etwa `auth.validations` | Der Layout-Route (`src/routes/auth.tsx`, `admin.tsx`, `app.tsx`, …) |
| `emails.*`                                 | Dem Use Case, der die E-Mail versendet, nur auf dem Server          |

`TranslationsProvider` umschließt den Dokument-Body und führt die Root-Namespaces mit den Namespaces jeder passenden Route zusammen, sodass jeder Bildschirm, einschließlich der Fehlerbildschirme, übersetzt ist.

## Schlüssel hinzufügen

Den Schlüssel in allen neun Locales mit derselben Struktur zur selben Datei hinzufügen. `bun run check:i18n` schlägt fehl, wenn in einer Locale ein Schlüssel fehlt oder überzählig ist.

## Seiten-Namespace hinzufügen

1. `messages/<locale>/pages.<area>.<page>.json` in allen neun Locales anlegen. Jeder Seiten-Namespace hat `metadata.title` und `metadata.description`; `loadPageMetadata` liest sie für den Dokument-Head.
2. Den Namespace in der Route deklarieren und laden:

```tsx
const NAMESPACE = "pages.legal.terms"

export const Route = createFileRoute("/_landing/terms")({
  component: TermsPage,
  head: pageHead(ROUTES.TERMS),
  loader: async ({ context }) => {
    const locale = getCurrentLocale()
    const [metadata] = await Promise.all([
      loadPageMetadata({ locale, namespace: NAMESPACE }),
      preloadNamespaces({ locale, namespaces: [NAMESPACE], queryClient: context.queryClient }),
    ])
    return { locale, metadata }
  },
  pendingComponent: LegalPending,
  staticData: { namespaces: [NAMESPACE] },
})
```

Layout-Routen deklarieren `const NAMESPACES = [...] as const`, laden sie im Loader vor und führen sie in `staticData` auf. Ein deklarierter Namespace ohne Datei wirft `No messages/<locale>/<namespace>.json`.

## Messages in Komponenten verwenden

- `useTranslations` genau einmal pro Komponente aufrufen und den Translator `t` nennen. i18n-ally und `check:i18n` lösen jedes `t("key")` gegen den nächstgelegenen vorangehenden `useTranslations`-Scope auf.
- Benötigt eine Komponente Schlüssel aus zwei unabhängigen Namespaces, `t` auf deren gemeinsamen übergeordneten Namespace beschränken oder `useTranslations()` aufrufen und vollständige Schlüssel verwenden, wie es `sign-in-form.tsx` tut.
- Komponenten lesen ihre eigenen Messages; Elternkomponenten übergeben nie Beschriftungen als Props.
- Rich Text verwendet `t.rich("key", TAGS)` mit der Tag-Map als Konstante auf Modulebene, wie `LEGAL_TAGS` in `src/routes/auth.sign-up.tsx`.
- `getCurrentLocale()` gibt die Locale auf dem Server und im Browser zurück. `useDateFormatter` und `useCurrencyFormatter` formatieren Datumswerte und Beträge für sie.

## Prüfen

```sh
bun run check:i18n
```

Der Befehl prüft die Schlüsselparität zwischen den Locales, statische Schlüssel gegen ihren `useTranslations`-Scope, ICU-Nachrichtenformate und die Parität der Docs-Inhalte zwischen den Locales. `bun run check` führt ihn ebenfalls aus.

## Locales in URLs

Englische Seiten haben kein Präfix (`/docs`); die anderen Locales verwenden eines (`/pl-PL/docs`). Der Worker leitet kurze Präfixe wie `/pl` auf `/pl-PL` weiter und hält das Locale-Cookie mit der Seiten-URL synchron. URLs von Server-Funktionen und `/api` enthalten keine Locale, daher nehmen Server-Funktionen, die lokalisierte Inhalte zurückgeben, die Locale als Eingabe entgegen.
