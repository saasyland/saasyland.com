title: "HTTP-Handler in TanStack Start"
description: "Die HTTP-Endpunkte unter /api und wann du einen davon statt einer Server Function anlegst."
---

Die eigenen Operationen der Anwendung sind Server Functions. HTTP-Handler gibt es nur dort, wo etwas außerhalb des RPC-Clients der Anwendung eine URL aufruft: der Browser-Client von Better Auth, OAuth-Provider, Polar-Webhooks und die CLI `saasyland`. Die Suche der Dokumentation braucht keinen: Sie durchsucht einen statischen Index im Browser (siehe [Dokumentationsseite](/docs/features/docs-site#search)).

| Datei                        | Pfad                                         | Methoden          | Verarbeitet                                                                                                                                     |
| ---------------------------- | -------------------------------------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/routes/api/index.ts`    | `/api`                                       | GET               | Eine JSON-Statusantwort `{ runtime: "cloudflare-workers" }`                                                                                     |
| `src/routes/api/auth.$.ts`   | `/api/auth/*`                                | GET, POST         | Alle Better-Auth-Endpunkte, einschließlich OAuth-Callbacks, E-Mail-Verifizierung, des Polar-Kundenportals und `/api/auth/polar/webhooks`        |
| `src/routes/api/cli.v1.*.ts` | <RepositoryFact name="cliApiBasePath" />`/*` | GET, POST, DELETE | Die [CLI-Lizenz-API](/docs/features/cli-licence-api): die Lizenz, ihre Geräte und das Vorlagen-Bundle jedes Releases, über `licenseApiHandlers` |

Der Worker beantwortet außerdem `/media/<expiry>.<signature>/<videoId>/<file>` selbst. Das ist keine Route: `src/server.ts` leitet diese Requests noch vor der Locale-Middleware und TanStack Start an `serveMedia` (`src/modules/video/video.delivery.ts`) weiter, und `serveMedia` prüft die Signatur und liefert die Videodatei aus dem Workers-Cache oder aus dem Bucket `MEDIA` aus. Siehe [Cloudflare R2](/docs/integrations/cloudflare-r2). Ebenso beantwortet er <RepositoryFact name="cliBundleUrlPath" />: Der Handler des Lizenz-Features leitet diese Requests an `serveBundle` (`src/modules/license/license.delivery.ts`) weiter, das die Signatur prüft und das Vorlagen-Bundle der CLI aus dem Bucket `BUNDLES` streamt. Siehe [CLI-Lizenz-API](/docs/features/cli-licence-api#template-bundles). Unter `/media/` beantwortet er außerdem `/media/covers/<courseId>/<file>`, die öffentlichen Titelbilder der Kurse, mit `serveCover` (`src/modules/course/course.delivery.ts`) und `/media/downloads/<expiry>.<signature>/<attachmentId>/<fileName>`, die signierten Lektionsmaterialien, mit `serveAttachment` (`src/modules/lesson-attachment/lesson-attachment.delivery.ts`). `serveBusinessLogo` (`src/modules/business-profile/business-profile.delivery.ts`) beantwortet das Logo des Unternehmens unter `/media/logos/` und steht als Erster in der Liste, vor den `/media/`-Handlern der Kurse.

Ein Handler wird mit `server.handlers` in `createFileRoute` deklariert. Er erhält den Web-`Request` und gibt eine `Response` zurück:

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Regeln

- Lege keinen REST-Endpunkt für eine Operation an, die nur diese Anwendung aufruft. Schreibe stattdessen einen Use Case mit `createServerFn`; er bekommt typisierte Eingaben, Middleware und Query-Optionen.
- Ein Handler validiert seine Eingaben und prüft Berechtigungen selbst. Die Middleware der Server Functions (`authorized`, `withRateLimit`) läuft für Handler nicht. Die CLI-Lizenz-API zählt jeden Request und liest seine Lizenz in einem D1-Batch mit `rateLimitBatch` aus `src/lib/rate-limit.ts`, liest einen zugelassenen Request mit `readApiRequest` aus dem Vertrag und beantwortet jeden eigenen Fehler, etwa wenn D1 oder Polar fehlschlägt, mit `serviceUnavailable` aus dem Vertrag.
- Anbieterspezifische Prüfungen bleiben in der Integration. Die Signaturen von Polar-Webhooks prüft das Polar-Plugin in Better Auth, kein eigener Handler.
- `/api`- und `/media`-Pfade werden nie lokalisiert, nie vorgerendert und umgehen die Locale-Verarbeitung des Workers.
