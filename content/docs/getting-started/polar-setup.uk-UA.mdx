<LegalNotice />

Polar продає три плани за цінами, які надсилає оплата, видає для них ліцензійні ключі й стягує податок. Код розраховує на точно визначене налаштування Polar, а Polar не попереджає, коли його налаштування розходиться з кодом: продукт без бенефіту ліцензійного ключа все одно приймає оплату, але не видає ключа. `bun run polar:verify:<environment>` порівнює Polar із кодом, а скрипти розгортання запускають цю перевірку перед кожним ручним розгортанням.

## Продакшн і пісочниця

Polar має два окремі сервіси. Продакшн (`polar.sh`, API `api.polar.sh`) списує кошти з реальних карток; пісочниця, або sandbox (`sandbox.polar.sh`, API `sandbox-api.polar.sh`), приймає лише тестові картки. Спільного в них немає нічого: обліковий запис, організація, токен, продукт, знижка чи вебхук існують лише в одному сервісі, тож зареєструйтеся на `sandbox.polar.sh` окремо й налаштуйте кожен сервіс незалежно від іншого.

| Файл середовища    | `POLAR_SERVER` | Організація Polar |
| ------------------ | -------------- | ----------------- |
| `.env.development` | `sandbox`      | Пісочниця         |
| `.env.preview`     | `sandbox`      | Пісочниця         |
| `.env.production`  | `production`   | Продакшн          |

Розробка й preview можуть спільно використовувати одну організацію в пісочниці, але її вебхук досягає лише preview: він надсилає події на хост preview, який записує їх до бази даних D1 preview, тоді як `bun run dev` використовує власну локальну базу. Тож тестова покупка, зроблена під час розробки, не надає ліцензії локально; перевіряйте покупки від початку до кінця на preview.

Ніколи не вписуйте продакшн-токен, ID продакшн-організації чи ID продакшн-продукту в `.env.development` або `.env.preview`. API пісочниці відхиляє продакшн-токен, а з `POLAR_SERVER=production` тестова оплата списала б кошти з реальної картки й видала б ліцензію в локальній базі даних або в базі preview. `polar:verify` відхиляє `POLAR_SERVER=production` для розробки та preview і `POLAR_SERVER=sandbox` для продакшну.

## Організація й токен

Спершу в пісочниці, потім у продакшні:

1. Створіть організацію й скопіюйте її ID з налаштувань організації в `POLAR_ORGANIZATION_ID`. Задайте обом організаціям slug із `POLAR_ORGANIZATION_SLUG` (`src/integrations/polar/polar.constants.ts`) або змініть константу на їхній slug: [сповіщення й список в адмінпанелі для замовлень без облікового запису](/docs/features/licences#orders-that-match-no-account) посилаються на кожне замовлення в панелі керування Polar під цим slug.
2. У налаштуваннях організації створіть токен доступу організації з наведеними нижче областями доступу (scopes) і лише з ними та скопіюйте його в `POLAR_ACCESS_TOKEN`.

| Область доступу           | Кому потрібна                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `checkouts:write`         | `createCheckout`, який створює кожен сеанс оплати через SDK Polar (`polar.checkouts.create`)                                                                                                                                                                                                                                                                                           |
| `customer_sessions:write` | Посилання на портал клієнта, `/api/auth/customer/portal`                                                                                                                                                                                                                                                                                                                               |
| `license_keys:write`      | Читання ключа та його активацій, активація пристрою й видалення активації (`deactivateLicense` і [API ліцензій для CLI](/docs/features/cli-licence-api)), а для підвищення плану — збільшення ліміту активацій ключа й вимкнення ключа, який Polar видає для замовлення на підвищення                                                                                                  |
| `orders:read`             | Обробники вебхуків, які читають замовлення, з якого походить ліцензія, і поточного клієнта замовлення, подія якого не відповідає жодному обліковому запису, ціна підвищення плану, яка підсумовує, скільки клієнт заплатив за ліцензії, сторінка замовлення в адмінці, яка читає замовлення і його рахунок, і `orders:backfill`, який копіює знижку й країну оплати кожного замовлення |
| `organizations:read`      | `polar:verify`, який читає, чи ввімкнено локалізацію оплати, типовий режим оподаткування та хости, яким дозволено вбудовувати оплату                                                                                                                                                                                                                                                   |
| `products:read`           | `polar:verify`                                                                                                                                                                                                                                                                                                                                                                         |
| `webhooks:read`           | `polar:verify`                                                                                                                                                                                                                                                                                                                                                                         |

Область доступу на запис охоплює й читання, тож `license_keys:write` дозволяє також читати ключі. Токен організації і так діє від імені своєї організації. Проте `polar:verify`, як і отримання списку замовлень для підвищення плану, надсилає `POLAR_ORGANIZATION_ID` як параметр запиту `organization_id`, тож з ID іншої організації продукти виглядатимуть відсутніми.

## Продукти

Створіть по одному продукту для кожного плану: одноразову покупку, а не підписку, з фіксованою ціною в `DEFAULT_CURRENCY_CODE` (доларах США), що дорівнює `TIER_PRICES` у `src/data/license.ts`. Скопіюйте ID кожного продукту в його ключ.

| План     | Ключ                        | Ціна                          | Активацій на ключ                   |
| -------- | --------------------------- | ----------------------------- | ----------------------------------- |
| Core     | `POLAR_PRODUCT_ID_CORE`     | <TierPrice tier="core" />     | <ActivationLimit tier="core" />     |
| Complete | `POLAR_PRODUCT_ID_COMPLETE` | <TierPrice tier="complete" /> | <ActivationLimit tier="complete" /> |
| Agency   | `POLAR_PRODUCT_ID_AGENCY`   | <TierPrice tier="agency" />   | <ActivationLimit tier="agency" />   |

Polar зберігає ціну в дрібних одиницях валюти, для доларів США це центи, і `polar:verify` так само перераховує `TIER_PRICES`, перш ніж їх порівнювати. Архівовані ціни він ігнорує.

## Ліцензійні ключі

Створіть по одному бенефіту типу **License Keys** (ліцензійні ключі) для кожного плану й прикріпіть його лише до продукту цього плану:

- **Активації**: обмежені числом із таблиці вище, `LICENSE_ACTIVATION_LIMITS` у `src/modules/license/license.constants.ts`. Дозволяти клієнтам керувати своїми активаціями в Polar необов'язково, бо `/app/license` сам показує й видаляє їх.
- **Термін дії**: немає. Ключі ніколи не втрачають чинності, бо покупка — це одноразовий платіж.
- **Ліміт використань**: немає.
- **Префікс**: на ваш вибір; `polar:verify` його не перевіряє.

Кожен продукт повинен мати рівно один бенефіт ліцензійного ключа; інші бенефіти поруч із ним допустимі. Коли Polar надає бенефіт, вебхук `benefit_grant.created` зберігає ключ у ліцензії покупця.

## Прапорець згоди [#consent-checkbox]

Покупець дає згоду на негайне надання на сторінці оплати Polar, і це поле — єдине місце, де її запитують (див. [Ліцензії](/docs/features/licences#consent-to-immediate-supply)); Polar записує її в замовлення. Створіть в організації одне користувацьке поле й прикріпіть його до трьох продуктів:

- **Тип**: прапорець (checkbox).
- **Slug**: <RepositoryFact name="licenseWithdrawalConsentField" />, `LICENSE_CHECKOUT_FIELD.WITHDRAWAL_CONSENT` у `src/modules/license/license.constants.ts`. Замовлення зберігає відмічений прапорець під цим ключем у `custom_field_data`.
- **Підпис**: точно `WITHDRAWAL_CONSENT_FIELD.label` з `src/lib/polar.ts`, англійське речення, побудоване з `REFUND_TERMS.WITHDRAWAL_DAYS`, яке закінчується Markdown-посиланням на Правила повернення коштів на продакшн-сайті.
- **Назва**: на ваш вибір; `WITHDRAWAL_CONSENT_FIELD.name` — це назва, яку пропонує код, і `polar:verify` її не перевіряє.
- **Обов’язкове** для кожного з трьох продуктів. Інші поля, які запитують продукти, можуть залишитися.

`startCheckout` не надсилає значення цього поля, тож прапорець спершу порожній і відмічає його покупець; Polar не приймає оплату, поки обов’язковий прапорець порожній. Polar зберігає значення лише тих полів, які запитує продукт: поки поле не прикріплено, оплата все одно працює, але замовлення не містить згоди, а [підтвердження покупки](/docs/features/licences#purchase-confirmation) натомість повідомляє про передбачене законом право на відмову від договору.

Щоб створити поле й прикріпити його до продукту, потрібні області доступу `custom_fields:write` і `products:write`, яких токен вище не має. Створіть і прикріпіть поле в панелі керування Polar або через API з окремим токеном, який має ці області доступу. `polar:verify` читає прикріплені поля зі списку продуктів, тож інших областей доступу йому не потрібно.

## Мова оплати [#checkout-language]

Polar показує свою сторінку оплати мовою, яку просить `createCheckout`, лише поки для організації ввімкнено локалізацію оплати; інакше кожна оплата відкривається англійською. Увімкніть її в налаштуваннях організації. [Посібник із локалізації оплати](https://polar.sh/docs/features/checkout/localization) Polar називає її прапорцем функції, а API повертає її як `feature_settings.checkout_localization_enabled` в організації. `POLAR_CHECKOUT_LANGUAGES` у `src/integrations/polar/polar.constants.ts` перелічує мови, які просить код, а `polar:verify` завершується помилкою, поки локалізацію вимкнено.

## Режим оподаткування [#tax-behaviour]

Картки цін кажуть, що ціни вказано в доларах США, що в ЄС ПДВ уже враховано, а в США, Канаді та Індії податок із продажу додається під час оплати. Polar стягує податок саме так, коли типовий режим оподаткування організації — за місцезнаходженням, тож виберіть його в налаштуваннях організації. API повертає його як `default_tax_behavior` в організації, а `polar:verify` завершується помилкою, поки він не `location` (`POLAR_TAX_BEHAVIOR.LOCATION` у `src/lib/polar.ts`).

## Вбудовування [#embedding]

Кнопки купівлі відкривають оплату Polar поверх сайту в iframe ([Ліцензії](/docs/features/licences#the-checkout-over-the-page)), а Polar дозволяє вбудовувати свою оплату у фрейм лише хостам, які перелічує його організація. У **Settings > Embedding** перелічіть хости, які `appHostsForMode` обслуговує в кожному середовищі, без схеми та з портом, якщо він є:

| Середовище    | Організація | Хости                              |
| ------------- | ----------- | ---------------------------------- |
| `development` | Пісочниця   | `localhost:3000`, `127.0.0.1:3000` |
| `preview`     | Пісочниця   | `preview.saasyland.com`            |
| `production`  | Продакшн    | `saasyland.com`                    |

Запис `*.saasyland.com` охоплює `preview.saasyland.com`, але не `saasyland.com`. Перевірені домени організації Polar додає до списку сам. API повертає список як `embed_hosts` в організації, а `polar:verify` завершується помилкою, поки бракує якогось хоста середовища. Доки хост не додано, фрейм Polar на ньому лишається порожнім, і через <RepositoryFact name="checkoutOverlayGraceSeconds" unit="second" /> кнопка натомість відправляє покупця на сторінку оплати Polar, тож покупці все одно можуть заплатити, лише трохи пізніше.

## Регіональні ціни [#regional-prices]

Регіональні ціни нічого не потребують у Polar. Для покупця з країни в `PPP_TIERS` (`src/modules/license/license.pricing.ts`), рівні якого знімають <RegionalDiscounts />, `startCheckout` надсилає саму ціну: `regionalPrice` округлює ціну плану вниз до цілих доларів, тобто до суми, яку показують картки планів, а сеанс оплати передає її в `prices` як фіксовану ціну продукту плану, що діє лише для цього сеансу оплати, тож продукт зберігає свою ціну з `TIER_PRICES`. [Підвищення плану](/docs/features/licences#upgrades) надсилає свою ціну так само. Знижки, створені під час попереднього налаштування, більше не використовуються, і їх можна видалити.

## Вебхук

Створіть по одній кінцевій точці вебхука для кожного розгорнутого середовища в організації, яку це середовище використовує.

| Середовище   | Організація | URL                                                     |
| ------------ | ----------- | ------------------------------------------------------- |
| `preview`    | Пісочниця   | `https://preview.saasyland.com/api/auth/polar/webhooks` |
| `production` | Продакшн    | `https://saasyland.com/api/auth/polar/webhooks`         |

Хост береться з `DEPLOYED_HOSTS`, а шлях — з `ROUTES`. Виберіть формат Raw, залиште кінцеву точку ввімкненою й підпишіть її саме на події з `POLAR_EVENTS` (`src/integrations/polar/polar.webhooks.ts`), де зібрано події всіх обробників із `POLAR_EVENT_HANDLERS` (див. [Платежі](/docs/features/payments#webhooks)). Наразі код ліцензії обробляє події з `LICENSE_WEBHOOK_EVENTS` (`src/modules/license/license.constants.ts`), а копії замовлень і підписок — події з `ORDER_WEBHOOK_EVENTS` і `SUBSCRIPTION_WEBHOOK_EVENTS`:

| Подія                   | Розділ ліцензій                                                        | Розділ розрахунків       |
| ----------------------- | ---------------------------------------------------------------------- | ------------------------ |
| `benefit_grant.created` | Зберігає ліцензійний ключ                                              |                          |
| `benefit_grant.revoked` | Відкликає ліцензію                                                     |                          |
| `order.created`         |                                                                        | Копіює замовлення в D1   |
| `order.paid`            | Видає ліцензію                                                         | Оновлює копію замовлення |
| `order.refunded`        | Позначає ліцензію як повернену, щойно за замовлення повернуто всю суму | Оновлює копію замовлення |
| `order.updated`         |                                                                        | Оновлює копію замовлення |
| `subscription.created`  |                                                                        | Копіює підписку в D1     |
| `subscription.updated`  |                                                                        | Оновлює копію підписки   |

Коли розділ починає обробляти подію, додайте цю подію до кожної кінцевої точки, перш ніж розгортати цей код. Код, розгорнутий до того часу, відповідає 200 на подію, яку не обробляє жоден розділ, і нічого з нею не робить, тож додати подію заздалегідь безпечно, а `polar:verify` зупиняє розгортання, доки якась кінцева точка не надсилає всіх подій із `POLAR_EVENTS`.

Скопіюйте секрет підпису кінцевої точки в `POLAR_WEBHOOK_SECRET` у файлі того самого середовища. Для розробки кінцева точка не потрібна, бо Polar не може звернутися до `localhost`.

Ніколи не додавайте кінцеву точку preview до продакшн-організації, а продакшн-кінцеву точку — до пісочниці: справжні платежі потрапляли б у preview, а тестові покупки видавали б ліцензії в продакшні.

## Перевірка налаштування

```sh
bun run polar:verify:development
bun run polar:verify:preview
bun run polar:verify:production
```

Кожен скрипт зчитує ключі Polar з `.env.<environment>` і надсилає лише GET-запити до API, яке вказує `POLAR_SERVER`: він читає організацію, отримує списки її продуктів і кінцевих точок вебхуків і нічого не змінює. Він перевіряє, що:

- файл середовища задає кожен ключ Polar, з `POLAR_SERVER=sandbox` для розробки та preview і `POLAR_SERVER=production` для продакшну;
- для організації ввімкнено локалізацію оплати, її типовий режим оподаткування — за місцезнаходженням, і вона дозволяє кожному хосту середовища вбудовувати свою оплату;
- кожен `POLAR_PRODUCT_ID_*` указує на продукт організації, який не архівовано й не є підпискою, а його ціни фіксовані, у `DEFAULT_CURRENCY_CODE` і дорівнюють `TIER_PRICES`;
- кожен продукт має рівно один бенефіт ліцензійного ключа з лімітом плану з `LICENSE_ACTIVATION_LIMITS`, без терміну дії й без ліміту використань;
- кожен продукт вимагає поле-прапорець <RepositoryFact name="licenseWithdrawalConsentField" /> з підписом із `WITHDRAWAL_CONSENT_FIELD`;
- preview і продакшн мають за своєю URL-адресою вебхука ввімкнену кінцеву точку у форматі Raw із секретом підпису `POLAR_WEBHOOK_SECRET`, підписану саме на `POLAR_EVENTS`;
- жодна кінцева точка не надсилає події на хост середовища, яке використовує інший сервіс Polar.

`polar:verify` — це перевірка перед розгортанням розділу Polar, бо його скрипти називаються `polar:verify:<environment>`. Тому `deploy:preview` і `deploy:production` запускають його через `scripts/run-deploy-checks.ts`, після `scripts/verify-bindings.ts` і `scripts/prepare-deploy-secrets.ts` і перед збіркою. Розгортання з CI не запускають жодної перевірки перед розгортанням, зокрема й `polar:verify`: у `deploy-reusable.yml` немає кроку з `scripts/run-deploy-checks.ts`, середовища GitHub не містять токена Polar, а Worker зберігає секрети Polar, уже задані в Cloudflare. Після кожної зміни в Polar запускайте `polar:verify` самостійно.

## Коли перевірка не проходить

Скрипт завершується помилкою, яка перелічує всі знайдені проблеми, по одній на рядок:

```text
Polar production does not match the code for production:
The core product (POLAR_PRODUCT_ID_CORE) has 0 licence-key benefits; it needs exactly one.
A webhook endpoint posts to https://preview.saasyland.com/api/auth/polar/webhooks, the preview host, from this Polar production organisation; remove it.
```

Невдала перевірка зупиняє розгортання до того, як щось буде зібрано, мігровано чи завантажено. Скрипт ніколи не змінює Polar: виправте Polar, а потім запустіть його знову. Кожне повідомлення називає ключ, константу чи налаштування, яке треба виправити:

- **`Set … in .env.<environment>`**: ключ Polar відсутній чи порожній або `POLAR_SERVER` вказує не на той сервіс.
- **`rejects POLAR_ACCESS_TOKEN`**: токен недійсний, відкликаний або належить іншому сервісу, як-от продакшн-токен у `.env.preview`.
- **`lacks the … scope`**: створіть токен з наведеними вище областями доступу.
- **`names no product of the organisation`**: ID продукту чи `POLAR_ORGANIZATION_ID` хибний або належить іншому сервісу.
- **Ціна або ліцензійний ключ**: змініть їх у Polar відповідно до коду. Коли бізнес-значення змінюється навмисно, спершу змініть `TIER_PRICES` або `LICENSE_ACTIVATION_LIMITS`, а потім Polar.
- **`does not ask for the … checkout field`, `without requiring it`, `instead of a checkbox` або `label differs`**: створіть, прикріпіть або виправте [прапорець згоди](#consent-checkbox). Коли формулювання змінюється навмисно, спершу змініть `WITHDRAWAL_CONSENT_FIELD.label`, а потім підпис у Polar.
- **`Checkout localization is off`**: увімкніть [локалізацію оплати](#checkout-language) для організації.
- **`default tax behaviour is not location`**: установіть для організації [режим оподаткування](#tax-behaviour) за місцезнаходженням.
- **`does not let … embed its checkout`**: додайте хост, який називає повідомлення, у [Settings > Embedding](#embedding).
- **Кінцева точка вебхука**: виправте кінцеву точку, яку називає повідомлення, або видаліть кінцеву точку, що надсилає події на хост іншого середовища.
