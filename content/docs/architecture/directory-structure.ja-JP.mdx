## 配置のルール

- **ファイルとフォルダーにはケバブケースを使います。** テストは同じ階層の `__test__` フォルダーに置きます。
- **ルートは組み立てるだけ。** ルートファイルが定義するのは、ページまたはレイアウトのコンポーネント、`NAMESPACE` または `NAMESPACES`、ローダー、`head` です。ウィジェット、ダイアログ、カラム定義は置きません。
- **モジュールはデータベーステーブル。** `src/modules/<name>` は、実在するテーブルのためだけに作成します。テーブルを扱わないサーバー関数は `src/lib`（例：`src/lib/github.ts`）に置くか、1 つのルートだけが使う場合はそのルートファイルに置きます。
- **共有コンポーネントはフラットに。** 複数のエリアで使うコンポーネントは、`presentation/components/custom` 直下の単一ファイルにします。
- **エリアとページのフォルダー。** 1 つのエリアだけで使うコンポーネントは、`admin/`、`app/`、`auth/`、`blog/`、`courses/`、`landing-page/`、`settings/` のいずれかに置きます。`settings/` には、`/app/settings` と `/admin/settings` が共有するアカウントのカードを置きます。管理画面のページには、`admin/users/` のように専用のフォルダーを設けます。ランディングページは、`sections/`（ページのセクションごとに 1 ファイル）と `components/`（セクション間で共有する部品）に分かれます。
- **1 ファイルにつきウィジェット、ダイアログ、フォーム、カラムセットは 1 つ。** コンポーネントをラッパーと `-content` ファイルに分割しないでください。
- **ヘルパー用のフォルダーを入れ子にしない。** コンポーネントのフォルダーには `components/`、`constants/`、`hooks/`、`lib/`、`types/` のサブフォルダーを作らず、コンポーネントの隣に `.ts` のヘルパーファイルも置きません。1 つのコンポーネントだけが使う定数は、そのコンポーネントのファイル内に置きます。
- **共有データは `src/data` に置く。** 例：`MARKETING_SECTION_IDS`、CLI の選択肢。各エリアは、プラットフォームに追加するもの（Worker ハンドラー、Vite プラグイン）もここで宣言します（[エリアが追加するもの](/docs/architecture/platform-layer#what-the-areas-add)を参照）。
- **すべてのパスは `src/routes.ts` に置く。** このファイルはブラウザー、Worker、Bun のスクリプト、Playwright、`vite.config.ts`、Remotion プロジェクトのすべての実行環境が読み込みます。そのためパスを宣言するだけで、何もインポートしません（[パスとナビゲーション](/docs/conventions/routes#paths-and-navigation)を参照）。
- **すべてのメニューは `src/data/navigation.ts` に置く。** 7 つのメニューはここにリテラルのリストとして並び、このファイルがインポートするのは `lucide-react`、`~/src/routes`、`~/src/data/navigation.constants` だけです。Remotion プロジェクトは、Remotion 自身のパッケージだけがインストールされた状態で管理画面のメニューを読み込むからです。
- **公開サイトのチェックは `src/lib/deployment.ts` に置く。** `LIVE_SITE_CHECKS` として、それをリクエストする `verifyDeployment` の隣に置きます。
- **権限ステートメントは `src/integrations/better-auth/auth.access.ts` の `APP_STATEMENTS` に置く。** 有料レッスンを開けるユーザーを決める `src/modules/lesson/lesson.access.ts` や、Polar の各 Webhook イベントが届くコードを決める `src/integrations/polar/polar.webhooks.ts` と同じく、変更のたびに人がレビューします。
- **生成ファイルは手で編集しない。** ルータープラグインが `src/routeTree.gen.ts` を、`bun run cf-typegen` が `src/types/worker-configuration.d.ts` を、`bun run content` と `bun run generate:cn` が `.source/` を書き出します。
