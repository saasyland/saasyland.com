## Qu'est-ce que SaaSy Land ?

SaaSy Land est un kit de démarrage SaaS React commercial. Une CLI pose des questions de configuration et n'écrit que les modules correspondant à vos réponses : authentification sur votre propre base de données, facturation, e-mails transactionnels, console d'administration, internationalisation et éditeur visuel de pages. Il est livré avec <RepositoryFact name="testFiles" /> fichiers de tests et un seuil de couverture qui les impose déjà, de sorte que le code que vous recevez est vérifié, et pas seulement présent.

Le code source du site web public est sous licence MIT ; la CLI et les modèles privés, distincts, sont propriétaires. Achetez une licence, connectez-vous sur saasyland.com et obtenez la clé nécessaire pour installer et utiliser la CLI. La validation de licence en ligne s'applique à la CLI. Les applications générées peuvent être modifiées et déployées sous la licence commerciale et ne nécessitent aucune clé à l'exécution. La licence du site web n'accorde aucun droit sur la marque SaaSy Land.

## Choisissez votre stack, lancez une commande

La CLI n'est pas un modèle que vous téléchargez avant de devoir lutter contre lui. Elle demande ce que vous construisez et écrit exactement cela : le même outil génère aussi bien un projet personnel mono-tenant qu'un produit multi-tenant avec un merchant of record.

```bash
bunx saasyland@latest init my-app \
  --framework tanstack \
  --tenancy multi \
  --billing polar \
  --content mdx \
  --email resend
```

Quelques-uns des choix, avec des options volontairement banales pour que la commande supporte d'être collée dans un script plutôt que dans un prompt :

| Question         | Options                                           | Pourquoi c'est une question                                                                                                                                                                           |
| ---------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Framework        | `tanstack`, `next`, `react-router`                | Les trois sont pris en charge ; choisissez celui que votre équipe connaît déjà                                                                                                                        |
| Tenancy          | `single`, `multi`                                 | Ajouter les organisations après coup touche chaque requête que vous avez écrite                                                                                                                       |
| Authentification | `better-auth`, `--no-auth`                        | Better Auth sur votre propre base de données, ou aucun compte pour un outil qui n'en a pas besoin                                                                                                     |
| E-mail           | `resend`, `plunk`, `--no-email`                   | Des e-mails transactionnels intégrés aux flux d'authentification, ou aucun                                                                                                                            |
| Facturation      | `polar`, `stripe`, `lemonsqueezy`, `--no-billing` | Polar et Lemon Squeezy sont des merchants of record et prennent en charge pour vous la TVA européenne et la taxe de vente américaine. Stripe, non. Un fondateur tranche cette question une seule fois |
| Contenu          | `mdx`, `--no-content`                             | Un blog et une documentation, ou ni l'un ni l'autre                                                                                                                                                   |

Changez une réponse et la commande change avec elle. Relancez-la pour le projet suivant : les réponses changent, la CLI et les mises à jour à vie restent les mêmes.

### Pourquoi le seuil de couverture compte davantage aujourd'hui qu'au lancement

À la sortie de la 2.0, le chiffre de couverture était un argument de qualité. C'est depuis devenu un argument de débit, car une grande partie du code ajouté aux bases de code SaaS est désormais écrite par un agent.

Dans l'[enquête Stack Overflow 2025 auprès des développeurs](https://survey.stackoverflow.co/2025/ai), 84 % des développeurs déclaraient utiliser ou prévoir d'utiliser des outils d'IA, tandis que la frustration la plus citée, mentionnée par 45 % d'entre eux, était une production d'IA « presque juste, mais pas tout à fait ». Un seuil qui bloque la fusion est la réponse la moins coûteuse à ce problème : un agent ne peut pas ajouter de comportement sans ajouter de test, et tout ce qu'il casse apparaît dans la pull request plutôt que chez un client.

Nous l'avons expliqué en détail dans [pourquoi votre dépôt détermine la qualité du travail de l'agent](/blog/ai-coding-agents-repository-readiness) et dans [comment choisir une stack pour les agents de programmation IA](/blog/choosing-a-saas-stack-for-ai-coding-agents). En bref, ce dépôt obtient 17 sur 20 à notre propre grille d'évaluation de préparation, par construction plutôt qu'à force d'efforts.

La CLI pose des questions de configuration et n'écrit que ce que vous avez choisi : l'authentification, la facturation, les e-mails et le contenu peuvent chacun être omis avec `--no-auth`, `--no-billing`, `--no-email` ou `--no-content`. La base de données, l'administration, l'interface, l'internationalisation, les tests et l'outillage sont toujours écrits.

</Accordion>

<Accordion title={"SaaSy Land est-il open source ?"}>

Le code source du site web public est sous licence MIT ; la CLI et les modèles privés, distincts, sont propriétaires. Achetez une licence, connectez-vous sur saasyland.com et obtenez la clé nécessaire pour installer et utiliser la CLI. La validation de licence en ligne s'applique à la CLI. Les applications générées peuvent être modifiées et déployées sous la licence commerciale et ne nécessitent aucune clé à l'exécution. La licence du site web n'accorde aucun droit sur la marque SaaSy Land.

</Accordion>

<Accordion title={"Comment savoir si c'est bien ce que cette page annonce ?"}>

Vérifiez avant de payer. La documentation est publique, le rapport de couverture est généré par le dépôt lui-même plutôt que présenté en capture d'écran, et le workflow CI qui impose le seuil est un fichier de ce dépôt. Le tableau de vérification ci-dessus associe chaque affirmation à une commande ou à un chemin.

</Accordion>

<Accordion title={"Pourquoi ne pas simplement faire construire tout cela par un agent IA ?"}>

Il le fera, et le résultat aura l'air correct. Ce qu'il ne vous dira pas, c'est quels cas limites de l'authentification il a laissés de côté, quel webhook n'est pas idempotent, ou que le contrôle de parité des traductions qu'il n'a jamais écrit aurait détecté les clés manquantes. Le travail d'un agent n'est fiable que dans la mesure où le sont les vérifications qui l'ont relu, et sur un dépôt vide, il n'y en a aucune.

</Accordion>
