title: "Projektskripte"
description: "Die Befehle, die du täglich verwendest."
---

| Aufgabe                                               | Befehl                   |
| ----------------------------------------------------- | ------------------------ |
| Dev-Server starten                                    | `bun run dev`            |
| Formatierung, Linting, Typen und Übersetzungen prüfen | `bun run check`          |
| Alle Vitest-Projekte ausführen                        | `bun run test`           |
| Prüfung der Testabdeckung ausführen                   | `bun run test:coverage`  |
| Browser-Smoke-Test ausführen                          | `bun run test:e2e:smoke` |
| Chromium-Browser-Suite der CI ausführen               | `bun run test:e2e:pr`    |
| Migration erzeugen                                    | `bun run db:generate`    |
| Preview-Worker bauen                                  | `bun run build`          |
| Letzten Build ausliefern                              | `bun run start`          |
| Preview deployen                                      | `bun run deploy:preview` |

Führe vor dem Öffnen eines Pull Requests die Abfolge aus [Mitwirken](/docs/project/contributing) aus, mit den Specs, die deine Änderung abdecken:

```sh
bun run check
bun run test:coverage
bun run build:test
bunx playwright test e2e/specs/<spec>.spec.ts --project=chromium
```

Lokal erstellt Playwright die Testdatenbank mit `db:reset:test` neu, baut den Test-Worker und startet ihn unter der Adresse aus `PLAYWRIGHT_BASE_URL` (`127.0.0.1:3000`, wenn die Variable fehlt), sofern dort nicht bereits ein Server antwortet. Jeder Worktree nimmt einen eigenen Port aus dem Bereich, dem der Test-Build vertraut, und der Lauf bricht ab, wenn der Server auf seinem Port zu einem anderen Worktree gehört: siehe [Neben anderen Worktrees ausführen](/docs/tooling/playwright#running-beside-other-worktrees).

Verwende `bun run test`, nicht `bun test`, damit Vitest mit dem Projekt-Setup läuft. Skripte, die auf einen Umgebungsnamen enden, etwa `db:migrate:preview` oder `deploy:production`, wirken nur auf diese Umgebung.

Die vollständige Liste findest du unter [Projektskripte](/docs/tooling/scripts).
