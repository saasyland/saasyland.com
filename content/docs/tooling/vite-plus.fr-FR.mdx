Vite+ (`vite-plus`, commande `vp`) regroupe Vite, Vitest, oxlint et oxfmt derrière une seule CLI, et `vite.config.ts` les configure tous. `package.json` remplace `vite` par `@voidzero-dev/vite-plus-core` et fixe `vitest` à la version 5.1.0. `vite-plus` est lui aussi épinglé à une version exacte ; mettez les trois à jour ensemble avec `vp migrate`, et non avec `bun update`. Les scripts du paquet appellent `vp` ; en dehors de ceux-ci, utilisez la CLI Vite+ globale ou `bunx vp`.

| Commande          | Utilisée par                                      |
| ----------------- | ------------------------------------------------- |
| `vp dev`          | `dev`                                             |
| `vp build --mode` | `build:preview`, `build:production`, `build:test` |
| `vp preview`      | `start`, `start:test`                             |
| `vp test`         | `test` et les scripts Vitest `test:*`             |
| `vp lint`         | `lint`                                            |
| `vp fmt`          | `format`, `format:check`                          |
| `vp check`        | `check`, `check:fix`                              |
| `vp staged`       | `check:pre-commit`                                |
| `vp config`       | `prepare`, qui installe les hooks Git             |

## Configuration

`vite.config.ts` ne nomme lui-même aucun plugin : il charge à la demande les plugins que chaque zone déclare dans `src/data/<area>.vite.ts`, que `src/data/vite.entries.ts` réunit et que `vitePlugins` dans `src/data/vite.ts` range selon leur `order` (voir [Ce que les zones apportent](/docs/architecture/platform-layer#what-the-areas-add)). Sous Vitest, seules les entrées marquées `vitest` sont chargées, c'est-à-dire `repositoryFacts()` et `@vitejs/plugin-react` ; sinon, la pile est la suivante :

- `@cloudflare/vite-plugin` : exécute le Worker dans l'environnement SSR, conserve l'état local (dans `.wrangler/test` pour le mode `test`) et utilise des bindings distants pour `development`.
- `fumadocs-mdx` : compile les collections de la documentation et du blog.
- `saasyland:fumadocs-bundled` : garde `fumadocs-core` et `@fumadocs/base-ui` dans le bundle serveur (`resolve.noExternal`).
- `repositoryFacts` (`scripts/repository-facts.ts`) : sert le module `virtual:repository-facts` : les nombres, les versions et les réglages d'outils que la page d'accueil et la documentation affichent, lus dans le dépôt au moment du build ; voir [Traductions et contenu](/docs/conventions/translations).
- `unused-primitives` (`scripts/unused-primitives.ts`) : avant Tailwind, écarte les classes de chaque primitive shadcn qu'aucune source de l'application n'importe ; voir [Composants shadcn](/docs/ui/shadcn-components).
- `@tailwindcss/vite` : Tailwind CSS 4.
- `tanstackStart` : routage, découpage du code et prérendu des pages publiques.
- `@vitejs/plugin-react`.
- `deployedWorker` (`scripts/deployed-worker.ts`) : recompile le Worker après le prérendu sans le MDX rendu ni les traductions de la landing page et des pages légales ; voir [Cloudflare Workers](/docs/integrations/cloudflare-workers).
- `saasyland:polar-sdk-optional-peers` : marque comme externes les dépendances pairs optionnelles de `@polar-sh/sdk` qui ne sont pas installées (`build.rolldownOptions.external`) ; voir [Dépendances](/docs/conventions/dependencies).

Le serveur de développement écoute sur `localhost:3000` et échoue si le port est occupé. `resolve.tsconfigPaths` fournit l'alias d'import `~/`. Le même fichier contient les sections `fmt`, `lint`, `staged` et `test` ; voir [Lint et formatage](/docs/tooling/lint-format) et [Tests](/docs/tooling/testing).

`vp preview`, que lancent `start`, `start:test` et le prérendu, écoute sur `127.0.0.1:3000`, l'adresse `LOCAL_SERVER` de `src/data/local-server.ts`, et Playwright ouvre cette adresse ; le prérendu utilise la même adresse avec un port libre. Avec `localhost`, le serveur n'écouterait que sur la première adresse que Node obtient pour ce nom, `::1`, et chaque client essaierait `::1` puis `127.0.0.1` en laissant peu de temps à chacune pour répondre : sur une machine chargée, ce délai expire avant que le client voie la connexion, il abandonne `::1`, ne trouve rien sur `127.0.0.1` et le prérendu s'arrête sur `ETIMEDOUT ::1` et `ECONNREFUSED 127.0.0.1`.

`src/data/polar.vite.ts` ajoute un plugin dont le hook `config` liste dans `build.rolldownOptions.external` les dépendances peer optionnelles de `@polar-sh/sdk` (OpenTelemetry et `ioredis`). Elles ne sont pas installées, et le module qui les importe est éliminé du Worker par tree-shaking.

## Hooks Git

`bun install` exécute `prepare`, qui appelle `vp config --no-agent` pour installer le répartiteur de hooks de `.vite-hooks/`. `pre-commit` exécute `bun run check:pre-commit`, et `prepare-commit-msg` exécute `scripts/commit-msg.ts` (voir [Commits conventionnels](/docs/tooling/conventional-commits)). `vp hooks status` indique si les hooks sont actifs dans un clone.

Privilégiez les scripts du paquet ; appelez `vp` directement pour des exécutions ciblées, comme le formatage ou le lint de chemins précis.
