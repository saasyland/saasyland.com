- Corregido: un worktree de Git nuevo recibe sus hooks de commit. `git worktree add` instala el despachador de hooks del nuevo worktree mediante el hook `post-checkout`, así que un commit hecho antes de `bun install` falla en el hook `pre-commit` en lugar de saltárselo, y `bun install` falla cuando `core.hooksPath` no es `.vite-hooks/_` o cuando al despachador le falta un hook. Hasta ahora Git hacía commits sin hooks, y sin avisar, en todos los worktrees que no tenían despachador propio. Consulta [Git y pull requests](/docs/conventions/git-workflow#hooks-in-every-worktree).
- Corregido: [Git y pull requests](/docs/conventions/git-workflow#linear-history) ya no te dice que fusiones `main` en la rama de una pull request ni que no hagas nunca force-push. Describe el historial lineal que sigue el proyecto: ningún commit de merge, tampoco en la rama de una pull request, ramas puestas al día con rebase sobre `main`, una pull request que GitHub no puede rebasar integrada de nuevo como un solo commit y ramas reescritas subidas con `git push --force-with-lease`. `AGENTS.md`, `CONTRIBUTING.md` y la página [Contribuir](/docs/project/contributing) dicen lo mismo.
