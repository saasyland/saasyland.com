## モジュール

`src/modules/<table>` 配下のモジュールは、実在するデータベーステーブルのためだけに存在します。モジュールには次のファイルが含まれます。

- `<table>.schema.ts`：Drizzle のテーブル。`src/integrations/drizzle-orm/drizzle.schemas.ts` から再エクスポートされます
- `<table>.zod.ts`：入力スキーマ。フォームとサーバー関数の両方で使います
- `<table>.constants.ts`：クエリキー、ミューテーションキー、enum
- `<table>.types.ts` と `<table>.utils.ts`：テーブルが必要とする場合のみ
- `use-cases/<operation>.ts`：1 ファイルにつき 1 つの操作

現在のモジュールは、account、category、license、newsletter-subscriber、product、rate-limit、session、two-factor、user、verification です。共有の定数とヘルパーは [`_core`](/docs/architecture/core) にあります。テーブルを扱わないサーバー関数は、`src/lib` か、それを使う唯一のルートに置きます。

## ユースケース

ほとんどのユースケースは、ブラウザから呼び出されるサーバー関数です。各ファイルは、`createServerFn` と、そのクエリオプションまたはミューテーションオプションをエクスポートします。

```ts
import { mutationOptions } from "@tanstack/react-query"
import { createServerFn } from "@tanstack/react-start"
import { v7 } from "uuid"
import type * as zod from "zod"

import { authorized } from "~/src/integrations/better-auth/auth.middleware"
import { db } from "~/src/integrations/drizzle-orm/drizzle.database"

import { CATEGORY_MUTATION_KEYS } from "~/src/modules/category/category.constants"
import { category } from "~/src/modules/category/category.schema"
import { categoryZodSchemas } from "~/src/modules/category/category.zod"

export const createCategory = createServerFn({ method: "POST" })
  .middleware([authorized({ category: ["create"] })])
  .validator((input: zod.input<typeof categoryZodSchemas.createCategory>) => categoryZodSchemas.createCategory.parse(input))
  .handler(({ data }) =>
    db
      .insert(category)
      .values({
        description: data.description ?? "",
        icon: data.icon ?? "FolderOpen",
        id: v7(),
        kind: data.kind,
        name: data.name,
        visibility: data.visibility ?? "public",
      })
      .returning()
      .get(),
  )

export const createCategoryMutation = mutationOptions({
  mutationFn: (data: Parameters<typeof createCategory>[0]["data"]) => createCategory({ data }),
  mutationKey: CATEGORY_MUTATION_KEYS.CREATE,
})
```

- **ミドルウェア**は `src/integrations/better-auth/auth.middleware.ts` で提供されています。`authorized()` はセッションを必須とし、`authorized({ category: ["create"] })` はさらに権限もチェックします。`withRateLimit(kind, RATE_LIMITS.SENSITIVE)` は公開された操作の実行回数を制限します。
- **バリデーション**では、ハンドラーの実行前に、モジュールの Zod スキーマで入力をパースします。
- **所有権**はセッションから判断します。呼び出し元自身のデータに対する操作は `context.auth.user.id` で絞り込み、入力に含まれるユーザー ID を信用することはありません。
- **エラー**は `new AppError(ERROR_CODES.X)` としてスローします。それ以外のエラーはログに記録され、クライアントには `INTERNAL_ERROR` として届きます。
- **読み取り**では、代わりに `queryOptions` をエクスポートします。たとえば `getCategoriesPageQuery(input)` は、データテーブル用に `{ rows, total }` を返します。

一部のユースケースは、サーバー上でのみ実行され RPC エンドポイントを持たない、通常の async 関数です。`send-verify-email.ts` や `grant-license.ts` などがこれにあたり、Better Auth のフックや Polar の Webhook ハンドラーから呼び出されます。

## コンポーネントからユースケースを呼び出す

コンポーネントは、エクスポートされたオプションを `useMutation` に展開し、`useErrorMessage()` でエラーを翻訳して、成功時にモジュールのクエリキーを無効化します。

```tsx
const t = useTranslations("pages.admin.users.actions")
const queryClient = useQueryClient()
const errorMessage = useErrorMessage()

const deleteUser = useMutation({
  ...deleteUserMutation,
  onError: (error) => {
    toast.error(errorMessage(error))
  },
  onSuccess: async () => {
    await queryClient.invalidateQueries({ queryKey: USER_QUERY_KEYS.ALL })
    toast.success(t("feedback.deleteSuccess"))
  },
})
```
