## 実装済み

- **セッション**: D1 に保存される Better Auth のセッション、Cookie プレフィックス `saasyland`、ローカル以外のモードでのセキュア Cookie、モード別の許可ホスト、クライアントアドレスとしての `cf-connecting-ip`。クライアント側のセッションにトークンは含まれません。
- **アカウント**: 必須のメール確認、パスワードリセット時のセッション失効、バックアップコード付きの任意の TOTP、ハッシュ化して保存される確認用識別子、暗号化された OAuth トークン。
- **認可**: ルートでは `requireSignedIn` と `requireAdmin`、サーバー関数では `auth.access.ts` のロールを使う `authorized(permission)`。
- **レート制限**: Better Auth のリミッターと `withRateLimit` ミドルウェアが D1 の `rate_limit` テーブルを共有します。`RATE_LIMITS.SENSITIVE` はクライアントとアクションごとに 60 秒あたり 3 回、`RATE_LIMITS.TOKEN` は 5 回まで許可します。
- **エラー**: リクエストミドルウェアが失敗を `AppError` のコード（`src/modules/_core/constants/errors.ts`）に変換するため、クライアントがサーバーの生のメッセージを受け取ることはありません。コンポーネントは `useErrorMessage` で表示します。
- **Webhook とフォーム**: Polar の Webhook は `POLAR_WEBHOOK_SECRET` で検証されます。ニュースレターのリクエストは既知のホストから HTTPS で送られたものだけを受け付けます（`newsletterRequestOrigin`）。
- **ヘッダー**: すべてのレスポンスに `X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`、`X-Frame-Options: DENY`、`Cross-Origin-Opener-Policy: same-origin`、カメラ・マイク・位置情報・topics を無効にする `Permissions-Policy`、フレームへの埋め込み・`<base>` の変更・プラグインを禁止する Content Security Policy を付けます。HTTPS のレスポンスには `Strict-Transport-Security` も加えます。Worker が `src/server.ts` で設定し（レスポンスに独自の値がある場合はそれを優先）、`public/_headers` が静的ファイルに同じヘッダーを付けます。

## 未実装

- スクリプトとスタイルを制限する Content Security Policy。事前レンダリングしたページでは、ページごとにすべてのインラインスクリプトのハッシュが必要になります。
- 利用停止、削除、なりすましを含む監査ログ。
- 公開フォームのボット対策や CAPTCHA。
- なりすましの画面（[なりすまし](/docs/features/impersonation)）。
