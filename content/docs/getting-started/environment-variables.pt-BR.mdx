title: "Variáveis de ambiente"
description: "As chaves do .env.example e onde cada ambiente as lê."
---

Copie o template para o ambiente em que você trabalha. `.env.development`, `.env.preview` e `.env.production` são ignorados pelo Git; `.env.test` é versionado com valores fictícios para os testes e para o preview isolado.

```sh
cp .env.example .env.development
openssl rand -base64 48
```

Use o valor gerado como `AUTH_SECRET`, com um secret diferente para cada ambiente com deploy.

| Variáveis                                                                       | Finalidade                                                                                     |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `AUTH_SECRET`                                                                   | Secret de assinatura e criptografia do Better Auth                                             |
| `AUTH_GITHUB_CLIENT_ID`, `AUTH_GITHUB_CLIENT_SECRET`                            | App OAuth do GitHub; também autentica a requisição da contagem de estrelas do GitHub           |
| `AUTH_GOOGLE_CLIENT_ID`, `AUTH_GOOGLE_CLIENT_SECRET`                            | App OAuth do Google                                                                            |
| `RESEND_API_KEY`, `RESEND_EMAIL_FROM`                                           | Chave de API do Resend e o endereço de remetente padrão                                        |
| `POLAR_SERVER`                                                                  | `sandbox` para desenvolvimento e preview, `production` para produção                           |
| `POLAR_ACCESS_TOKEN`, `POLAR_ORGANIZATION_ID`                                   | Acesso à API da Polar e a organização usada para descontos e chaves de licença                 |
| `POLAR_WEBHOOK_SECRET`                                                          | Verifica os webhooks da Polar em `/api/auth/polar/webhooks`                                    |
| `POLAR_PRODUCT_ID_CORE`, `POLAR_PRODUCT_ID_COMPLETE`, `POLAR_PRODUCT_ID_AGENCY` | Produtos da Polar para os três planos do checkout                                              |
| `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID`, `CLOUDFLARE_ACCESS_TOKEN`    | Acesso à API HTTP do D1 para o Drizzle Studio e a introspecção; a aplicação usa o binding `DB` |

Os ambientes `development`, `preview` e `production` em `wrangler.jsonc` exigem todas as chaves acima como secrets (`secrets.required`). O código do servidor as lê com `import { env } from "cloudflare:workers"`. Nenhuma tem o prefixo `VITE_`, porque o Vite expõe esses valores ao navegador. `.env.example` lista as chaves em blocos, um por módulo, na mesma ordem de `secrets.required`, e `src/__test__/wrangler.test.ts` falha quando os dois diferem.

`.env.development` também pode definir `LOCAL_ADMIN_PASSWORD`, a senha que `bun run db:seed:local` dá ao administrador local; ela não é um secret do Worker e nunca sai da sua máquina. Veja [O seed local](/docs/tooling/database#the-local-seed).

`AFFONSO_PROGRAM_ID` não é um secret e não está em `.env.example`. É o ID público do programa no Affonso de que o rastreamento de indicações de afiliados precisa, então é uma variável do Worker em `vars` no `wrangler.jsonc`, definida apenas para o ambiente que recebe pagamentos reais; `production` define o ID de programa do SaaSy Land, e `test`, um ID fictício para os testes no navegador. O rastreamento só funciona quando o Worker tem o ID e o programa está aberto: hoje `AFFILIATE_PROGRAM` vale <RepositoryFact name="affiliateProgram" />. Veja [Abrir o programa](/docs/features/affiliates#opening-the-programme).

## Valores no código

Algumas configurações são código, e não variáveis de ambiente:

- `src/presentation/branding/index.ts`: o nome da aplicação, `APP_DOMAIN` (a URL canônica é `https://` mais esse domínio), o host de preview `APP_PREVIEW_DOMAIN`, os endereços de contato e o repositório do GitHub.
- `src/modules/_core/constants/api.ts`: os hosts de preview e de produção (`DEPLOYED_HOSTS`, lidos de `APP_PREVIEW_DOMAIN` e `APP_DOMAIN`), que o Better Auth e os links da newsletter aceitam (`appHostsForMode`) e que os scripts de deploy verificam depois de um deploy.
- `wrangler.jsonc`: os nomes dos Workers, os domínios personalizados, que `src/__test__/wrangler.test.ts` mantém iguais a `DEPLOYED_HOSTS`, os IDs do D1 e do KV e os nomes dos buckets do R2.

## Callbacks dos provedores

- GitHub e Google: <RepositoryFact name="oauthCallbackUrls" />.
- Webhooks da Polar: `https://<host>/api/auth/polar/webhooks`, assinados com `POLAR_WEBHOOK_SECRET`. [Configuração do Polar](/docs/getting-started/polar-setup) lista os eventos, os produtos, os descontos e os escopos do token, e `bun run polar:verify:<environment>` os verifica.
