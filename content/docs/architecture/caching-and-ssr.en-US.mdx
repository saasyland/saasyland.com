## Query cache

`getRouter` creates a new `QueryClient` for every request, so no data leaks between users on the server. Defaults:

| Setting                   | Value     |
| ------------------------- | --------- |
| Query `staleTime`         | 1 minute  |
| Query `gcTime`            | 5 minutes |
| Router `defaultStaleTime` | 1 minute  |
| Preloading                | On intent |

Loaders fill the cache with `queryClient.query({ ...options, staleTime: "static" })` and components read the same keys with `useSuspenseQuery`. Course pages and the admin course editor are the exception: their queries keep `staleTime: COURSE_STALE_MS` (one minute), because `invalidateQueries` never refetches a `static` query, and finishing a lesson or saving a change in the editor has to refresh the curriculum. `setupRouterSsrQueryIntegration` serializes the server cache into the HTML and hydrates it in the browser.

- **Translation messages** are cached per locale and namespace with an infinite `staleTime` and `gcTime`.
- **The session query** (`getCurrentSessionQuery`) has a one-minute `staleTime`. Route guards refetch it on real navigations and clear the whole cache when the signed-in user changes.
- **Mutations** invalidate their module's query keys, for example `USER_QUERY_KEYS.ALL`, after they succeed.

## Prerendering

`bun run build` prerenders the public pages by crawling links: landing, legal, blog and docs pages in all nine locales. Paths under `/admin`, `/app`, `/auth`, `/courses`, `/newsletter` and `/api` (with or without a locale prefix) and links with a query string or hash are excluded. The course pages are excluded because they show each viewer's locks and progress. The browser fills the landing page's course block from `getCourseShowcase` when it scrolls near, so the prerendered landing page stays the same for everyone (see [Courses](/docs/features/courses)).

The Worker serves prerendered HTML from the `ASSETS` binding before it loads the application. A prerendered page contains no user data, so it is safe to serve to everyone. When a visitor qualifies for regional pricing, the Worker rewrites the HTML and marks the response `Cache-Control: private, no-cache`.

## KV and D1

- **KV (`CACHE`)** stores the GitHub star count for `src/lib/github.ts` and the regional checkout discounts for `src/modules/license/license.ppp.ts`. A star count older than one hour is returned immediately and refreshed in the background with `waitUntil`; discounts older than five minutes are listed from Polar again.
- **D1 (`DB`)** stores sessions and rate-limit counters. Session checks for server functions bypass Better Auth's cookie cache and are memoized for the rest of the request.
- **The Workers cache** keeps the video files that `serveMedia` reads from R2 under `/media/_/<videoId>/<file>`, without the signature, so the viewers at one edge location share a single cached copy. See [Cloudflare R2](/docs/integrations/cloudflare-r2).
- Server functions never make a permission decision from cached data.
