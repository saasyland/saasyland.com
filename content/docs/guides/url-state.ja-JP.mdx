検索パラメーターには、再読み込みや共有リンクの後も維持されるべき状態を保持します。選択中のタブやビュー、認証ページ間で受け渡すメールアドレス、検証トークンなどです。それ以外はすべて React の state に置きます。`DataTable` は、ページネーション、ソート、選択、フィルターをコンポーネントの state に保持します。

## パラメーターを宣言する

`validateSearch` は、生のクエリを型付きのオブジェクトに変換します。未知の値や無効な値は、例外をスローせずにデフォルト値にフォールバックします。`src/routes/admin.blog.index.tsx` の例です。

```tsx
validateSearch: (search: SearchSchemaInput & { view?: unknown }): { view: "grid" | "table" } => ({
  view: search.view === "table" ? "table" : "grid",
}),
search: { middlewares: [stripSearchParams({ view: "grid" })] },
```

`stripSearchParams` は URL からデフォルト値を取り除くため、`/admin/blog` がグリッド表示の正規アドレスのまま保たれます。

## 読み取る

- ルートコンポーネント内：`const { view } = Route.useSearch()`。
- セレクターを使うと、選択した値が変わったときだけコンポーネントが再レンダリングされます：`Route.useSearch({ select: (search) => search.error !== "" })`。
- ルートファイル外のコンポーネント：`reset-password-form.tsx` のように `getRouteApi("/auth/reset-password").useSearch()` を使います。

## 変更する

- リンク：`<Link search={{ view: id }} to={ROUTES.ADMIN_BLOG}>`。
- `src/routes/admin.products.index.tsx` の `TabsTrigger` のように `href` を持つ React Aria コンポーネントは、`AriaProvider` が React Aria と TanStack Router を接続しているため、ルーターを通じて遷移します。
- コード：`router.navigate({ search: { email }, to: ROUTES.VERIFY_EMAIL })`。
- ガードとローダー：`throw redirect({ replace: true, search: { status: "success" }, to: ROUTES.NEWSLETTER_UNSUBSCRIBE })`。

## パラメーターからデータを読み込む

検索パラメーターに依存するローダーは、そのパラメーターを `loaderDeps` で宣言し、`deps` から読み取ります。ニュースレターの確認ルートはこの方法でトークンを消費し、`preload: false` を設定しています。そのため、リンクにカーソルを合わせただけでトークンが消費されることはありません。

```tsx
loaderDeps: ({ search: { token } }) => ({ token: token ?? "" }),
```

## ロケールと URL

- ルーターのリンク（`<Link to={ROUTES.X}>`）には、ルーターの `rewrite` によってロケールのプレフィックスが付きます。英語にはプレフィックスがなく（`/docs`）、他のロケールには付きます（`/pl-PL/docs`）。
- 生の URL は `localizePathname({ locale, pathname })` で組み立てます。対象は、Better Auth の `callbackURL` と `errorCallbackURL`、メール内のリンク、手動で組み立てた `<a href>` です。`/api` のパスと外部 URL は変更されません。
- ロケールスイッチャーは、別のロケールの同じパス名にリンクし、ページ全体を読み込み直します。クエリとハッシュは引き継がれません。
