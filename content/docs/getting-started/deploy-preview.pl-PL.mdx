Środowisko `preview` wdraża Workera `saasyland-preview` pod adresem `preview.saasyland.com`. Domyślnie `development` i `preview` współdzielą jedną bazę D1 i jedną przestrzeń nazw KV.

## Przygotowanie zasobów

```sh
bunx wrangler login
bunx wrangler d1 create saasyland_com_preview
bunx wrangler kv namespace create CACHE --env preview
```

W `wrangler.jsonc` zastąp `database_id`, `database_name` i `id` przestrzeni KV zarówno w bloku `development`, jak i `preview`. Zachowaj nazwy bindingów `DB` i `CACHE` oraz `migrations_dir`, a nazwy Workerów i trasy domen niestandardowych dostosuj do swojego konta. Dla produkcji utwórz osobne zasoby i zaktualizuj blok `production`. Ustaw `APP_DOMAIN` w `src/presentation/branding/index.ts`. `appHostsForMode` w `src/modules/_core/constants/api.ts` wyprowadza z tej stałej dozwolone hosty: `APP_DOMAIN` na produkcji, `preview.<APP_DOMAIN>` w preview oraz `localhost:3000` lub `127.0.0.1:3000` w trybie deweloperskim i testowym. `HOSTS_BY_MODE` w tym samym pliku edytuj tylko wtedy, gdy Twój host preview ma inną nazwę.

## Wdrożenie

Uzupełnij `.env.preview`, a następnie wykonaj migrację i wdróż aplikację:

```sh
bun run db:migrate:preview
bun run deploy:preview
```

`deploy:preview` uruchamia `scripts/verify-bindings.ts preview`, który odrzuca zastępcze identyfikatory, następnie `build:preview`, który prerenderuje strony publiczne i weryfikuje wynik, a na końcu `wrangler deploy --secrets-file .env.preview`, który przesyła również sekrety. Budowanie i wdrażanie nigdy nie stosują migracji; uruchom `db:migrate:preview` przed wdrożeniem kodu, który wymaga nowego schematu.

Zarejestruj adresy zwrotne OAuth i webhook Polar dla hosta preview zgodnie z listą w [Zmiennych środowiskowych](/docs/getting-started/environment-variables).

## Automatyczne wdrożenia

Po pomyślnym przejściu kontroli i testów przeglądarkowych CI wdraża każdy pull request z gałęzi w tym repozytorium do współdzielonego środowiska preview, a każdy push do `main` na produkcję. Wymagane sekrety GitHub opisuje strona [CI/CD](/docs/tooling/ci-cd).
