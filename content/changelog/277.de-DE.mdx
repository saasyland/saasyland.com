- Geändert: Pull Requests kommen über die Merge Queue von GitHub auf `main`. Sie testet jeden noch einmal auf `main` und den Pull Requests vor ihm und führt eine Gruppe zusammen, sobald jeder bestanden hat, sodass ein fertiger Pull Request nicht mehr auf einen Rebase wartet. `bun scripts/enqueue-pr.ts <number>` stellt einen Pull Request in die Queue und gibt seinem Titel das Emoji, das der Squash-Commit behält. Siehe [Git und Pull Requests](/docs/conventions/git-workflow#merging).
- Geändert: Ein Pull Request deployt die geteilte Preview nicht mehr. Die neue Prüfung `Worker upload` lädt seinen Preview-Worker als Version zu Cloudflare hoch, die keinen Traffic bedient. Das beweist den Upload, seine Größe und seine Bindings, ohne zu ersetzen, was `preview.saasyland.com` ausliefert, sodass sich fertige Pull Requests nicht mehr gegenseitig blockieren. `main` wird vor der Produktion auf die Preview deployt, und `preview.yml` deployt einen getesteten Branch von Hand dorthin. Siehe [CI/CD](/docs/tooling/ci-cd#merge-queue).
- Geändert: Ein Push auf `main`, den die Merge Queue schon getestet hat, wird deployt, ohne die Prüfungen erneut auszuführen, und die Changelog-Prüfung behandelt einen Branch der Merge Queue wie `main`.
- Geändert: Die Definition of Done führt lokal `check`, `test:coverage`, `build:test` und die Browser-Specs aus, die die Änderung berührt; CI führt die ganze Browser-Suite im Pull Request und noch einmal in der Merge Queue aus. Siehe [Konventionen](/docs/conventions#definition-of-done).
