---
title: "Handlers HTTP de TanStack Start"
description: "Los endpoints HTTP bajo /api y cuándo conviene añadir uno en lugar de una función de servidor."
---

Las operaciones propias de la aplicación son funciones de servidor. Los handlers HTTP existen solo donde algo ajeno al cliente RPC de la aplicación llama a una URL: el cliente de navegador de Better Auth, los proveedores OAuth, los webhooks de Polar y la CLI `saasyland`. La búsqueda de la documentación no necesita ninguno: busca en un índice estático dentro del navegador (consulta [Sitio de documentación](/docs/features/docs-site#search)).

| Archivo                      | Ruta                                         | Métodos           | Gestiona                                                                                                                                                                |
| ---------------------------- | -------------------------------------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/routes/api/index.ts`    | `/api`                                       | GET               | Una respuesta de estado en JSON `{ runtime: "cloudflare-workers" }`                                                                                                     |
| `src/routes/api/auth.$.ts`   | `/api/auth/*`                                | GET, POST         | Todos los endpoints de Better Auth, incluidos los callbacks de OAuth, la verificación de correo, el portal de clientes de Polar y `/api/auth/polar/webhooks`            |
| `src/routes/api/cli.v1.*.ts` | <RepositoryFact name="cliApiBasePath" />`/*` | GET, POST, DELETE | La [API de licencias de la CLI](/docs/features/cli-licence-api): la licencia, sus dispositivos y el bundle de plantillas de cada versión, mediante `licenseApiHandlers` |

El Worker también responde por sí mismo a `/media/<expiry>.<signature>/<videoId>/<file>`. No es una ruta: `src/server.ts` envía esas peticiones a `serveMedia` (`src/modules/video/video.delivery.ts`) antes del middleware de locale y de TanStack Start, y `serveMedia` comprueba la firma y sirve el archivo de vídeo desde la caché de Workers o desde el bucket `MEDIA`. Consulta [Cloudflare R2](/docs/integrations/cloudflare-r2). Responde del mismo modo a <RepositoryFact name="cliBundleUrlPath" />: el handler de la funcionalidad de licencias la envía a `serveBundle` (`src/modules/license/license.delivery.ts`), que comprueba la firma y sirve en streaming el bundle de plantillas de la CLI desde el bucket `BUNDLES`. Consulta [API de licencias de la CLI](/docs/features/cli-licence-api#template-bundles). Bajo `/media/` también responde a `/media/covers/<courseId>/<file>`, las portadas públicas de los cursos, con `serveCover` (`src/modules/course/course.delivery.ts`), y a `/media/downloads/<expiry>.<signature>/<attachmentId>/<fileName>`, los materiales firmados de las lecciones, con `serveAttachment` (`src/modules/lesson-attachment/lesson-attachment.delivery.ts`). `serveBusinessLogo` (`src/modules/business-profile/business-profile.delivery.ts`) responde con el logotipo de la empresa bajo `/media/logos/` y va primero, por delante de los handlers de `/media/` de los cursos.

Un handler se declara con `server.handlers` en `createFileRoute`. Recibe la `Request` estándar de la Web y devuelve una `Response`:

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Reglas

- No añadas un endpoint REST para una operación a la que solo llama esta aplicación. Escribe en su lugar un caso de uso con `createServerFn`, que obtiene entrada tipada, middleware y opciones de consulta.
- Un handler valida su entrada y comprueba los permisos por su cuenta. El middleware de las funciones de servidor (`authorized`, `withRateLimit`) no se ejecuta en los handlers. La API de licencias de la CLI contabiliza cada petición y lee su licencia en un único batch de D1 con `rateLimitBatch` de `src/lib/rate-limit.ts`, lee una petición admitida con `readApiRequest` del contrato y responde a cualquier fallo propio, como un fallo de D1 o de Polar, con `serviceUnavailable` del contrato.
- La verificación específica de cada proveedor se queda en su integración. Las firmas de los webhooks de Polar las verifica el plugin de Polar dentro de Better Auth, no un handler propio.
- Las rutas de `/api` y `/media` nunca se localizan, nunca se prerenderizan y quedan fuera de la gestión del locale que hace el Worker.
