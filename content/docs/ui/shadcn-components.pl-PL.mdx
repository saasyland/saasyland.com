Komponenty bazowe w `src/presentation/components/shadcn/` to komponenty shadcn/ui zbudowane na React Aria Components. `input-otp`, `carousel`, `resizable`, `chart`, `message-scroller` i `sonner` opakowują inne biblioteki, `drawer` korzysta z Base UI, a pozostałe opierają się na React Aria. `components.json` kieruje alias `ui` do tego folderu, a `utils` do `~/src/lib/cn`. Ekrany importują komponenty bazowe bezpośrednio; nie ma wokół nich komponentów opakowujących.

## Propsy React Aria

| Nawyk z DOM lub Radix     | Tutaj używaj                           |
| ------------------------- | -------------------------------------- |
| `onClick`                 | `onPress`                              |
| `disabled`                | `isDisabled`                           |
| `open` w oknie dialogowym | `isOpen` z `onOpenChange`              |
| `checked`                 | `isSelected`                           |
| `value` w zakładkach      | `selectedKey` lub `defaultSelectedKey` |
| `onSelect` w pozycji menu | `onAction`                             |

`Input` zachowuje natywne zdarzenie `onChange`. `Select` przyjmuje `fieldLabel`, który renderuje etykietę.

## Konwencje

- **Przyciski w stanie oczekiwania**: przekaż stan mutacji do `Button`: `<Button isPending={mutation.isPending} type="submit">`.
- **Linki**: `LinkButton` i `SidebarMenuLink` to linki TanStack Router, utworzone przez `createLink` z `Link` z React Aria: przyjmują `to` razem z `params` i `search`, które drzewo tras sprawdza na poziomie typów, i wstępnie ładują swoją stronę, gdy kursor na nich spocznie, tak jak `<Link>`. `AnchorButton`, `TabsTrigger` i `SidebarMenuButton` przyjmują `href` dla adresów spoza drzewa tras, takich jak pliki do pobrania, `mailto:` i inne witryny, a `AriaProvider` kieruje `href` prowadzący do tej samej witryny przez TanStack Router, z prefiksem języka. Aby nadać innym elementom wygląd przycisku, użyj `buttonVariants`.
- **Formularze**: `Field`, `FieldGroup`, `FieldLabel`, `Input` i `ValidationFieldError` z TanStack Form, jak w tym polu z `ResetPasswordDialog`:

```tsx
<Field data-invalid={isInvalid}>
  <FieldLabel htmlFor={passwordId}>{t("resetPasswordDialog.password")}</FieldLabel>
  <Input
    aria-invalid={isInvalid}
    autoComplete="new-password"
    id={passwordId}
    name={field.name}
    onBlur={field.handleBlur}
    onChange={(event) => {
      field.handleChange(event.target.value)
    }}
    type="password"
    value={field.state.value}
  />
  {isInvalid && (
    <ValidationFieldError
      message={fieldErrorMessage(field.state.meta.errors)}
      namespace="auth.validations"
      params={AUTH_VALIDATION_PARAMS}
    />
  )}
</Field>
```

- **Okna dialogowe**: `Dialog` i `AlertDialog` są sterowane przez `isOpen` i `onOpenChange`; każde okno ma własny plik, na przykład `admin/users/delete-user-dialog.tsx`.
- **Menu**: `DropdownMenuTrigger` otacza wyzwalający je `Button` i `DropdownMenu`; pozycje wykonują `onAction`, a dla niebezpiecznych akcji używają `variant="destructive"`.
- **Powiadomienia**: wywołuj `toast.success` lub `toast.error` z `sonner`; trasa główna renderuje `Toaster` wewnątrz `ThemeProvider`. Jego region powiadomień ma nazwę z `components.shadcn.sonner`, a po niej skrót klawiszowy Sonnera.
- **Obwódki fokusu**: stylizuj wyzwalacze React Aria wariantami `data-focus-visible:`, tak jak robią to `checkbox`, `select`, `switch` i `radio-group`.
- **Nazwy klas**: używaj `cn` z `~/src/lib/cn` ze składnią obiektową dla klas warunkowych.

## Rozmiar CSS

`globals.css` nie zawiera żadnej listy komponentów bazowych. Plugin Vite `unused-primitives` z `scripts/unused-primitives.ts` działa przed Tailwindem: zapisuje w `.source/unused-primitives.css` wiersz `@source not` dla każdego komponentu bazowego, którego żaden plik źródłowy aplikacji nie importuje, ani bezpośrednio, ani przez inny komponent bazowy (testy i `src/platform/testing` się nie liczą), i importuje ten plik do arkusza stylów, który przekazuje Tailwindowi. CSS projektu zawiera klasy komponentów bazowych używanych przez jego własne obszary i żadnych innych. Tailwind śledzi importowany plik, a plugin zapisuje go ponownie tylko wtedy, gdy lista się zmienia, więc gdy ekran zaczyna importować komponent bazowy, serwer deweloperski przebudowuje CSS z jego klasami bez restartu.
