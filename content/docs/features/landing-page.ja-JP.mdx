## ルート

`src/routes/_site._marketing.index.tsx` は `MotionProvider` の中で、`src/presentation/components/custom/landing-page/sections` のセクションを組み合わせます。Hero、Proof、Stack、Manifesto、CLI、Line、Quality、Rally、Manifest、Studio、Record、Cases、Compare、Pricing、FAQ、Notes、Gate です。文言は `pages.landing` 名前空間から取得します。ローダーは `blogNotes` で Notes セクションの記事も選びます。`FEATURED_BLOG_POSTS` の最初の記事をカバー画像付きのカードにし、その隣にほかの新しい記事を並べます（[ブログ](/docs/features/blog#source)を参照してください）。また、Proof セクション用に KV にキャッシュされた GitHub のスター数 `starCountQuery` を事前に読み込みます。続いて `TIER_PRICES` の Core の価格を整形してページの説明文に入れます。`pages.landing` のメッセージはそれを `{price}` として受け取ります。ページには組織の構造化データ `ORGANIZATION_STRUCTURED_DATA_HTML` も含まれます。[検索エンジンとソーシャルプレビュー](/docs/features/seo#structured-data)を参照してください。

ページ上のその他の数値は手入力ではなく計測された値です。`scripts/repository-facts.ts` の Vite プラグイン `virtual:repository-facts` が、ビルド時にテストファイル、Playwright スペック、Playwright が一覧にするブラウザーテスト、UI コンポーネントを数え、通貨、タイムゾーン、国の数を `CURRENCY_CODES`、`TIMEZONES`、`COUNTRIES` から取得し、React と TanStack Table のメジャーバージョンを読み取ります。`src/lib/repository-facts.ts` の `REPOSITORY_FACTS` が言語数、動作する管理画面のセクション数と、`@saasyland/stack` の `STACK_MODULES` と `STACK_EXTRAS` から CLI のモジュール数（`cliModules`）、回答で省けるモジュール数（`cliOptionalModules`）、追加機能の数（`cliExtras`）を加え、各セクションはそれを `{testFiles, number}` のような ICU 引数として `pages.landing` のメッセージに渡します。**すべての主張を検証してください** のリストも、引用するファイルとコマンドを同じ値から受け取るため、どの言語でも翻訳されません。`vite.config.ts` のカバレッジサマリーのパス、`playwright.config.ts` のスペックのディレクトリ、CI のワークフロー、メッセージのディレクトリ、認証の統合、[テストカバレッジ](/docs/tooling/test-coverage)のページ、そしてコマンド <RepositoryFact name="coverageCommand" />、<RepositoryFact name="flowCheckCommand" />、<RepositoryFact name="i18nCheckCommand" /> です。

このページの約束は、生成されたプロジェクトが AI エージェントが壊せない SaaS の土台になるということです。この約束を Hero、Manifesto から料金へのリンク、Gate セクションの冒頭に掲げ、アドバンテージは Manifesto の第 2 段落でその裏付けになります。アドバンテージは `headStartHours` で、`src/data/head-start.ts` の `HEAD_START_ROWS` から算出します。各行は、CLI のテンプレートが生成するデフォルトプロジェクトの一部、それを含むテンプレートレイヤー、そしてシニアエンジニアが手で書く場合の時間の下限と上限を示します。課金、組織、マルチテナント、サンプルのコマースは、テンプレートが生成するまで行がありません。行の合計は <RepositoryFact name="headStartLowHours" /> 〜 <RepositoryFact name="headStartHighHours" /> 時間で、うたう時間は下限の合計を `HEAD_START_ROUNDING_HOURS` 単位で切り捨て、`HEAD_START_CLAIM_MAX_HOURS` を上限とした値を使います。そのため表示は <RepositoryFact name="headStartHours" /> になり、行が減れば自動的に下がります。ブログは `<HeadStartTable />` で行を表示し、ラベルは `pages.blog.headStart` から取得します。

ページ全体のカバレッジの数値は、`vite.config.ts` から読み取る `coverageThreshold` で、ブラウザーテストの数は、Playwright が一覧にするテストの数である `e2eTests` です。ページはフローの割合を表示しません。Quality セクションは[テストカバレッジ](/docs/tooling/test-coverage)にリンクしており、そこにはすべてのフローが、それを証明するテスト、または不足しているものとともに載っています。計測ではなく宣言する値は 2 種類あり、どちらも `src/data/marketing.ts` で一度だけ宣言します。2 つのコースプラットフォームの情報（`REACTPROJECTS_FACTS` と `ANGULARPROJECTS_FACTS`。各プラットフォームの URL から取るホスト、ビルド数、アクセスの状態）と、価格の試算に使う例示の時給（`ILLUSTRATIVE_HOURLY_RATE`）です。`CORE_PRICE_IN_HOURS`（`src/data/license.ts`）はこの時給から、Core の価格が下回る時間数を整数で計算し、価格がそれを下回らなくなると `license.test.ts` が失敗します。

`adminSections` は `src/data/navigation.ts` の `ADMIN_NAVIGATION` のエントリを数えます。管理画面のエントリはすべて実データで動作する画面を開くため、すべてが数えられ、現在は <RepositoryFact name="adminSections" /> です。同じエントリは、マニフェストに並ぶセクション名にもなります。`useAdminSections` がメニューのラベルを読者の言語で列挙します。Proof グリッドは数を表示し、生成されるプロジェクトはダッシュボード、ユーザー、設定から始まると添えるだけなので、グリッドの注記はどれも 2〜3 行に収まります。Proof グリッドの **言語** は対応ロケールを表示し、テストの数値については、生成されたプロジェクトではなくこのサイト自体のソースで数えたものだと明記しています。

公開ページはすべて、パスなしの `_site` レイアウト（`src/routes/_site.tsx`）の中にあります。このレイアウトは、サイトヘッダーの `Navigation` と `BackToTop` を、すべての公開ページのために一度だけ表示します。その内側の `_marketing` レイアウト（`_site._marketing.tsx`）は、`/`、法務ページ、ニュースレターのページ、ブログ、コースを `PageFrame`、`main` ランドマーク、`Footer` で囲みます。このレイアウトは `staticData` に `dark: true` を設定しており、一致したルートのいずれかがこれを設定していると、`_site` はヘッダーを含むページ全体をダークテーマに切り替えます。ドキュメントは訪問者のテーマのままです。セクションのアンカーは `src/data/navigation.constants.ts` の `MARKETING_SECTION_IDS`（`foundation`、`cli`、`quality`、`toolkit`、`pricing`、`faq`）で、リンクは `<Link to={ROUTES.HOME} hash={MARKETING_SECTION_IDS.PRICING}>` の形で書きます。`Footer` は `LocaleSwitcher` の隣に GitHub リポジトリと Instagram のプロフィール（`APP_GITHUB_URL` と `APP_INSTAGRAM_URL`）へのリンクを置き、新しいタブで開きます。`Footer` は、ブランドのブロックと 2 つのリンクグループを折り返す 1 本の flex の行に並べ、どの要素も最も長い単語より狭くなりません。ラベルが収まる間はグループが横に並び、収まらなければ縦に積み重なるので、どの言語でもラベル同士が重なりません。スマートフォンではブランドのブロックが最初の行を使い、`md` 以上では 3 つが 1.5 : 1.3 : 1 の比率で 1 行を分け合います。

## ページが見つからない場合 [#not-found-page]

どのルートにも一致しないパスは `_site._marketing.$.tsx` に届き、そのローダーが `notFound()` を投げます。サーバーはステータス 404 で応答し、ページはほかのページと同じく `_marketing` レイアウトの中に、1 つだけのサイトヘッダーの下、フッターの上に、マーケティングのテーマで表示されます。存在しないブログ記事、コース、レッスンは自身のローダーから `notFound()` を投げ、同じ場所に同じ `DefaultNotFound`（`src/presentation/components/custom/default-not-found.tsx`）を表示します。存在しないドキュメントのページは、ドキュメントのレイアウトの中にそれを表示します。マッチが見つからないとき、これらのルートは `notFoundHead`（`src/lib/not-found.ts`）から head を受け取ります。`errors.not-found` の翻訳済みのタイトルと説明、そして `noindex` で、canonical リンクとソーシャルカードはありません。ページの操作は `BackHomeLink` ひとつで、ラベルは `common.backHome` から取ります。期限切れのニュースレターのリンクでも同じものを表示します。

## ナビゲーションとページトップへ戻るボタン [#navigation-and-back-to-top]

- ヘッダーのリンクは `src/data/navigation.ts` の `HEADER_NAVIGATION` で、リストに並んだ順に表示されます。**料金**（`hash` で `/` の `pricing` セクションへリンクします）、**講座**、**ブログ**、**ドキュメント**、**ログイン** で、それぞれのラベルは、`navigation.core.json` の `navigation.core.header.pricing` のように、その `label` が指すメッセージから付きます。`Navigation` はこれらを表示し、続けて料金セクションへの行動喚起ボタン **開発を始める** を表示します。`lg` ブレークポイント未満では、項目は `MobileMenu`（`src/presentation/components/custom/mobile-menu.tsx`）に移ります。これはウィンドウ全体を覆う React Aria の `Modal` と `Dialog` です。上端の行はロゴを繰り返し、メニューボタンがあった位置に閉じるボタンを置きます。その下に同じ項目が同じ順序で並び、最後に **開発を始める** が続きます。ヘッダー自体は `sm` 未満でこのボタンを隠します。フォーカスは閉じるボタンに移って Tab はメニューの中にとどまり、Escape と閉じるボタンはフォーカスをメニューボタンに戻し、背後のページは `inert` になってスクロールしません。`html` がスクロールバーの幅を確保しているので（[スクロールバー](/docs/ui/theme#scrollbars)）、メニューを開閉しても何も動きません。`HEADER_NAVIGATION` に追加した項目は、すべての公開ページのヘッダーとメニューに表示されます。
- ページの読み込みが終わってブラウザーがアイドルになると、`Navigation` はルーターを通じてヘッダーの各項目のページをコードとデータごとプリロードします。そのため、クリックでも、スマートフォンのメニューでのタップでも、キー操作でも、Worker を待たずにページが開きます。データセーバーを有効にした訪問者には何も読み込まず、ナビゲーションのたびにもう一度実行します。[パフォーマンス](/docs/conventions/performance#the-headers-pages-load-before-a-click)を参照してください。
- TanStack Router の `Link` は現在のセクションの項目に `aria-current="page"` を付け、ヘッダーはその項目を明るくして下に点を表示します。ブログの一覧とすべての記事では **ブログ**、ドキュメントのすべてのページでは **ドキュメント** です。`hash` を持つ項目が現在の項目になるのは自身のアドレス `/#pricing` だけなので、ホームページのそれ以外の場所ではどの項目も現在の項目になりません。フッターのホームページのセクションへのリンク（**基盤**、**料金**、**FAQ**）も、同じ理由で `activeOptions={{ includeHash: true }}` を渡します。**開発を始める** は `/#pricing` でも現在の項目になりません。場所ではなく操作なので、`Navigation` と `MobileMenu` は `useLinkProps` でこのリンクを組み立て、TanStack Router が現在のアドレスへのすべてのリンクに付ける `aria-current` を外します。
- ヘッダーの先頭には **本文へスキップ** リンクがあります。キーボードフォーカスを受けるまでは隠れており、ページの本文へ移動します。`_marketing` レイアウトでは id が `SITE_CONTENT_ID` の `main` ランドマーク、ドキュメントのページでは id が `DOCS_CONTENT_ID`、つまり Fumadocs の `nd-page` である記事です（どちらも `src/data/navigation.constants.ts`。[ドキュメントサイト](/docs/features/docs-site)を参照）。
- ヘッダーは固定表示で、スクロール位置にかかわらず同じ見た目です。背景はぼかされ、下端には線があり、ページをスクロールするとその上に進捗を示す線が伸びます。高さは `globals.css` のテーマトークン `--spacing-header`（`h-header`）で、内容の幅はすべての公開ページの内容と同じ `--container-site`（`max-w-site`）なので、ロゴと **開発を始める** はどのページでも同じ位置にあります。`main` ランドマーク（`_marketing` レイアウト）は `pt-header` ですべてのページをヘッダーの下から始めます。ただしランディングページは `staticData` に `underHeader: true` を設定し、ヒーローをヘッダーの下に描きます。ドキュメントのレイアウトは Fumadocs の `--fd-banner-height` をこの高さに設定して、サイドバーと目次がヘッダーの下に固定されるようにします。`html` は `scroll-padding-top` でこの高さを確保するため、アンカーで移動した先の見出しも、キーボードフォーカスを受けた要素もヘッダーの下に隠れません。
- ヘッダーのロゴは `HomeLink`（`src/presentation/components/custom/home-link.tsx`）です。`/` でクリックすると、表示中のページを再読み込みする代わりにページの先頭までスクロールし、`#pricing` のようなセクションのハッシュを、履歴エントリーを置き換えてアドレスから取り除きます。ほかのページでは通常のホームへのリンクで、修飾キーを押しながらクリックすれば新しいタブやウィンドウで開けます。スマートフォンのメニューでは、ロゴを選ぶとメニューも閉じます。
- `BackToTop`（`src/presentation/components/custom/back-to-top.tsx`）は右下に固定された React Aria のボタンで、ラベルは `components.custom.back-to-top` 名前空間から取得します。`IntersectionObserver` で監視する番兵要素が、最初の画面がビューから外れると表示し、先頭近くに戻ると再び隠すので、スクロールイベントでコードは実行されません。押すとページの先頭までスクロールし、フォーカスをページの `h1` に移します。`_site` レイアウトが、すべての公開ページのために一度だけ表示します。
- どちらも `scrollTo({ top: 0 })` を呼び、動きは `globals.css` に任せます。`html` は滑らかにスクロールし、`prefers-reduced-motion: reduce` のときは先頭へ即座に移動します。

## 実在のプロダクト [#real-products]

`CasesSection` は、お客様の声の代わりに SaaSy Land で作られたプロダクトを表示します。カードは `src/data/marketing.ts` の `PRODUCT_CASES` で、その順に並びます。各エントリには ID があり、種類・説明・モジュールは `pages.landing` の `cases.items.<id>` です。名前にはプロダクトのホストを使い、`PRODUCT_CASE_STATUS` のラベルは `cases.status.<status>` から取ります。サイトが公開済みでウェイトリストの登録を受け付けているプロダクトは `waitlist` で URL を持ち、名前は新しいタブでサイトを開くリンクになり、そのリンクはカード全体を覆います。コースプラットフォームの URL は `REACTPROJECTS_URL` と `ANGULARPROJECTS_URL` です。まだ公開されていないプロダクトは `launch` でリンクを持たないため、ページは応答するサイトにだけリンクします。カードは `lg` 未満では縦に並び、`lg` 以上では 3 列になり、ランディングページのほかのグリッドと同じホバー時のハイライトを使います。

## コースブロック [#course-block]

**ツールキット** セクションの最後はコースブロックです。講座ページの紹介動画に続いて、D1 にある公開済みのコースを表示し、各コースにはカバー画像、最初のいくつかのレッスンのタイトル（開ける、ロックされている、収録中のいずれか）、収録済みの量が付きます。プリレンダリングされたページにはプレースホルダーだけが含まれ、ブロックが表示領域に近づくとブラウザがコースを取得するため、管理画面での変更はデプロイなしで次のページ表示から反映されます。[コースの「ランディングページ」](/docs/features/courses#on-the-landing-page)を参照してください。

## 料金と地域別価格 [#pricing-and-regional-pricing]

`PricingSection` は `src/presentation/components/custom/pricing.tsx` の `PricingTiers` を表示します。これは[顧客アプリ](/docs/features/customer-app)がライセンスのないアカウントに表示するのと同じプランのカードです。各カードは `LICENSE_TIERS`（`src/modules/license/license.constants.ts`）のプランを、`TIER_PRICES` の金額と `components.custom.pricing` 名前空間の文言とともに表示し、ボタンは表示するページから受け取ります。ランディングページでは `/auth/sign-up?redirect=/app?tier=<tier>` へのリンクなので、選んだプランはサインアップ後も引き継がれます。グリッドは自身のコンテナの幅が 42rem 以上になると 3 列に切り替わる（`@container`）ため、幅の狭いアプリの列にも収まります。地域別価格はクライアント側の JavaScript なしで動くため、ページはプリレンダリングされたままです。

注目のプランである `FEATURED_TIER`（Complete）には **おすすめ** のラベルが付きます。1 列のときはカードのボタンが価格の下、機能の一覧より前に置かれるため、スマートフォンの訪問者は一覧をスクロールしなくてもボタンに届きます。3 列のときはボタンがカードの下端に移り（`order-last`）、各カードのボタンの位置がそろいます。カードの下では、`PricingTrust` が `trust` メッセージの `PRICING_TRUST_ITEMS` を列挙します。Merchant of Record としての Polar（領収書と付加価値税の請求書、法人向けの VAT 番号の入力欄）、米ドル建ての価格（EU では付加価値税込み、米国、カナダ、インドでは売上税を加算。Polar の[税の扱い](/docs/getting-started/polar-setup#tax-behaviour)をこれに合わせる必要があります）、プロジェクトを生成するか有料レッスンを開く前であれば <RepositoryFact name="refundWithdrawalDays" unit="day" />以内の全額返金（返金ポリシーへのリンク付き）、そしてすべてのリリースが含まれる CLI のベータ版です。Hero セクションは、ボタンの下の `hero.anchor` でオファーを繰り返します。`PRICE_TAGS` による Core の価格（該当する地域では地域価格）、生涯アップデート、`REFUND_TERMS.WITHDRAWAL_DAYS` による返金期間です。

カードの機能は `src/data/license.ts` の `TIER_FEATURES` から取得します。各エントリには ID（その文言は `tiers.<tier>.features.<id>`）と `FEATURE_STATUS` があり、カードはエントリを **提供中** と **提供予定**（`status.available` と `status.arriving`）に分けて表示します。そのため、現在動くものと提供予定のものの区分は一か所で宣言され、どの翻訳もステータスを書きません。提供中のグループの最後には、1 つのキーを同時に使える端末数が並びます。これは `LICENSE_ACTIVATION_LIMITS[tier]` を ICU の複数形である `machines` メッセージに渡したもので、Core は <ActivationLimit tier="core" />、Complete は <ActivationLimit tier="complete" />、Agency は <ActivationLimit tier="agency" /> です。`LicenseOfferPending` も `TIER_FEATURES` から同じグループを描画します。

Complete に含まれる 2 つのコースプラットフォームへの無料の生涯アクセスは、同じファイルの `REACTPROJECTS_ACCESS` と `ANGULARPROJECTS_ACCESS` からステータスを受け取ります。どちらも `CLI_GENERATION` と同じ `FEATURE_STATUS` の値です。現在の値は reactprojects.com が <RepositoryFact name="reactprojectsAccess" />、angularprojects.com が <RepositoryFact name="angularprojectsAccess" /> です。どちらもウェイトリストの登録を受け付けている段階で、まだ公開されていないためです。Complete についての FAQ の回答は `reactprojectsAccess` と `angularprojectsAccess` に対する ICU の `select` で、FAQ はこれらを各プラットフォームのホストとともに `COURSE_PLATFORM_VALUES` で受け取ります。そのため、プラットフォームのステータスを `FEATURE_STATUS.AVAILABLE` にすると、その機能は**提供中**に移り、すべての言語でその文が変わります。`src/data/__test__/course-platform-access.test.ts` は、すべての言語で両方のバリアントを描画します。Agency のコースと 2 つのプラットフォームのチーム席は `TEAM_SEATS_ACCESS` から状態を取り、現在は <RepositoryFact name="teamSeatsAccess" /> です。サブスクリプションについての FAQ の回答は `teamSeatsAccess` に対する ICU の `select` で、`feature-status-copy.test.ts` が両方のバリアントをすべての言語で描画します。ブログ記事はアクセスを文章で説明しており、プラットフォームの公開時に書き換えます。

地域別価格は次のようにページに反映されます。

1. `Price` は通常価格をテキストとして表示します。地域の倍率（`PPP_KEYS`）ごとの金額（チェックアウトの請求にも使う関数 `regionalPrice` でドル未満を切り捨てたもの）と、その横の取り消し線付きの通常価格は、CSS が描く `data-text` 属性（`.ppp-text::before`）に入っており、プランの下のオファーと各価格の下の割引額も同じです。クローラーのように CSS なしでページを読むと、通常価格だけが読まれ、オファーは読まれません。
2. Worker が `DOCUMENT_REWRITES` の要素としてすべての HTML ページに適用する `rewritePppOffer`（`src/modules/license/license.pricing.ts`）が `cf-ipcountry` を読み取ります。`PPP_TIERS` に含まれる国であれば、`HTMLRewriter` で `html` 要素に `data-ppp` と変数 `--ppp-region`、`--ppp-percent` を設定し、レスポンスを `private, no-cache` にします。
3. 地域割引のチェックボックスがオンの間、`globals.css` の CSS が該当する価格を表示します。
4. チェックを外すと Cookie に `regional_pricing=off` が保存され、Worker と `startCheckout` の両方がこれに従うため、カードの価格がそのままチェックアウトの価格になります。

Agency のカードは、`tiers.agency.whoFor` で誰のためのプランかを示します。同じガードレールで多くのクライアント案件を手がける制作会社です。プランの下では、`OtherOptions` が **その他の選択肢**（`otherOptions`）の見出しの下に、プランではない 2 つの選択肢を、高さのそろった破線枠のカード 2 枚として並べ、追加のプランに見えないようにしています。**無料** は MIT ライセンスで公開されているこのサイト自身のソースで $0、ボタンは `APP_GITHUB_URL` を開きます。**コンサルティング** は `src/data/marketing.ts` の `CONSULTING_HOURLY_RATE` を `CURRENCY_FORMAT` で整形して表示します。通話はメールで予約するもので Polar では販売しないため、地域別価格はなく、ボタンには **メールで相談を予約** と表示されます。相談の長さは `src/data/license.ts` の `TIER_SUPPORT.CALL_MINUTES`（<RepositoryFact name="callMinutes" unit="minute" />）、Complete の優先サポートが回答するまでの期間は `TIER_SUPPORT.RESPONSE_BUSINESS_DAYS`（<RepositoryFact name="supportResponseDays" /> 営業日）で、プランのカード、コンサルティングカード、FAQ、ブログ記事はどちらも `TIER_SUPPORT_VALUES` から表示します。

## CLI コンフィギュレーター [#cli-configurator]

`CliSection` は `CliConfigurator`（`landing-page/components/cli-configurator.tsx`）を含みます。`@saasyland/stack` の `STACK_CHOICES` と `STACK_EXTRAS` にある質問と追加機能、そして `src/data/cli.ts` のパッケージマネージャーからフラグ付きの <RepositoryFact name="scaffoldTarget" /> コマンドを組み立て、`CopyButton` でコピーできます。質問、オプション、追加機能のラベルと各質問の `note` は `stack` 名前空間にあり、ルートはこれを `pages.landing` と一緒に読み込み、ドキュメントのレイアウトは[ロードマップ](/docs/project/roadmap)の表のために読み込みます。CLI がすでにこのコマンドを実行できるかどうかは、後述の `CLI_GENERATION` が決めます。現在の CLI でできることは [CLI ガイド](/docs/cli)にあります。

このセクションの `stack` の文はリード文の後に続き、CLI が現在書き出すスタックを示します。`GeneratedStack` は `CLI_TEMPLATE_SUPPORT` のフレームワーク、UI ライブラリ、デプロイ先のオプションを読み取り、`stack` 名前空間のラベルを付け、各リストを `format.list` で選択肢として連結し、その他については[ロードマップ](/docs/project/roadmap)にリンクします。そのため、新しいフレームワークやホスティング先は、それを生成するリリースでこの文に加わります。

構成ツールでは、CLI のテンプレートが生成するものだけを選択できます。その元になるのは、CLI 自身も確認する `@saasyland/stack/cli` の `TEMPLATE_SUPPORT` で、`src/data/cli.ts` が `CLI_TEMPLATE_SUPPORT` としてエクスポートします。これは質問ごとにテンプレートが書き出すオプションを、`extras` にはテンプレートが書き出す追加機能を挙げます。それ以外のオプションと追加機能は位置を変えずに無効になり、ラベルの後ろに砂時計が付きます。`aria-describedby` はそれらを、質問の上でパッケージマネージャーのタブの横にある凡例 `coming` に関連付けます。構成ツールの下の `generates` の行は、プロジェクト生成が選択できるすべてのオプションを書き出すことを示します。テンプレートがあるオプションを生成するようになると、そのテンプレートを含む `@saasyland/stack` のリリースがそれを挙げ、パッケージを更新すれば有効になります。ほかに変更は要りません。質問、そのオプション、そのルールも同じパッケージから来るため、Web サイトはその写しを持ちません。

構成ツールは、`init --yes` がこの一覧から決める回答（スタックの `resolveAnswers` を呼び出す、`src/lib/cli.ts` の `resolveCliAnswers`）で開きます。質問ごとに順に、テンプレートが生成し、それより前の回答が許すなら CLI のデフォルト、そうでなければその条件を満たす最初のオプションです。訪問者が回答を変えると、その回答が除外する回答だけが同じ方法で決め直され、ほかの回答はそのまま残ります。リリース記事は同じ初期コマンドを `<ScaffoldCommand />` で表示し、そのフラグは `@saasyland/stack` の `stackArguments` がこの回答から書き出すため、記事にテンプレートが生成しないフラグが載ることはありません。`cli.test.ts` は、スタックのすべてのオプションと追加機能に `stack` のメッセージのラベルがあることを確認するため、`@saasyland/stack` の新しいリリースが加えたオプションは、翻訳されるまでテストを失敗させます。開いたときの回答を含め、構成ツールで選べるどの回答でも、テンプレートが生成しないフラグがコマンドに入ることはありません。

各質問はラジオグループで、shadcn の `ToggleGroup` に `selectionMode="single"` を指定し、行のラベルを名前にします。追加機能は `selectionMode="multiple"` の `ToggleGroup` 1つです。矢印キーで質問内を移動し、Space または Enter で回答し、Tab で次の質問へ進みます。すべてのオプションは位置を変えません。それより前の回答が `@saasyland/stack` の `unavailableWhen` または `visibleWhen` のルールによって除外したオプションは無効になって取り消し線が付き、オプションの下に表示される質問の `note` がその理由を示します。`aria-describedby` は同じ理由をスクリーンリーダーに伝え、オプションが提供予定でもある場合は凡例 `coming` の後に伝えます。回答によって除外された追加機能はコマンドから外れます。選択したオプションは色だけが変わり、押しても縮まず、構成ツールは浮き上がらずにフェードインするため、押す操作でポインターの下のコントロールが動くことはありません。`e2e/specs/cli-configurator.spec.ts` は利用可能なすべてのオプションを中央と両端で押し、どのオプションも動かないことを確認したうえで、提供予定のオプションを押してコマンドが変わらないことを確認します。

`@saasyland/stack` と同じく UI ライブラリが最初の質問なので、コマンドは `--framework` より前に `--library` を渡します。フレームワークの質問は、各フレームワークをそれが動作するライブラリの下に並べます。これは `@saasyland/stack` のフレームワークの `visibleWhen` ルールが宣言しています。React の下に TanStack Start、Next.js、React Router、Angular の下に Analog と Angular SSR、Vue の下に Nuxt、Svelte の下に SvelteKit、Solid の下に SolidStart です。TanStack Start は Solid でも動作するため、React の下に一度だけ表示し、Solid のグループでは SolidStart の後にその名前を挙げます。各ライブラリのフレームワークは、質問のラジオグループの中でライブラリ名を名前にした `role="group"` になるので、矢印キーは引き続き質問全体を移動します。選んだライブラリで動作しないフレームワークは無効になりますが、理由はグループがすでに示しているため取り消し線は付かず、`aria-describedby` は質問の `note` に関連付けます。`CLI_TEMPLATE_SUPPORT` が挙げるのは React と TanStack Start なので、ほかのライブラリとフレームワークにはすべて砂時計が付きます。ランタイムの質問が Cloudflare と Vercel で除外する Deno も同様です。

プロジェクト生成が提供されたかどうかは、`src/data/cli.ts` の `CLI_GENERATION`（`FEATURE_STATUS`）が決めます。これに依存するメッセージはすべて `generation` に対する ICU の `select` で、`available` のバリアントと提供予定のバリアント（`other`）を持ちます。コンポーネントは `CLI_GENERATION_VALUES`、つまりステータスとプロジェクトを作る npm コマンド <RepositoryFact name="cliInitCommand" /> を渡します。生成によって提供される Core の機能と Agency のクライアントプロジェクトは、`TIER_FEATURES` で同じ定数からステータスを受け取ります。そのため定数を変えるだけで、すべての言語でそれらの文が変わり、その機能は**提供中**に移ります。Core のカードの課金は、さらに `CLI_TEMPLATE_SUPPORT` が課金プロバイダーを挙げるまで待つため、テンプレートが課金を生成するまで**提供予定**に残ります。また、Hero セクションと締めくくりの行動喚起がプロジェクトに含まれるものとして課金を挙げるのは、`BILLING_GENERATION` が提供中になってからです。Manifest の **請求** の項目は、このサイトが Polar で販売していることと、`BILLING_GENERATION` に基づいて生成されるプロジェクトに課金がすでに含まれるかどうかを示します。`src/data/__test__/cli-generation.test.ts` はそれらのメッセージを列挙し、すべての言語で両方のバリアントを表示し、提供予定の文言が選択肢の外にあると失敗します。ブログ記事、このドキュメント、`public/llms.txt` は文章で書かれているため、生成を提供するリリースで更新します。

## ニュースレター

`Footer` は `NewsletterForm`（`src/presentation/components/custom/newsletter-form.tsx`）を表示します。

1. `subscribeToNewsletter`（レート制限あり）が保留中の `newsletter_subscriber` 行を保存し、`NewsletterConfirmationEmail` を送信します。すでに購読済みのアドレスには `alreadySubscribed` を返し、何も書き込みません。1 つのアドレスに 1 時間以内に <RepositoryFact name="recipientEmailsPerHour" /> 通の確認メールを送った後は、何も書き込まず何も送信せずに `confirmationSent` を返します。
2. `/newsletter/confirm?token=` は訪問者に確認を求めます。ボタンを押すと `confirmNewsletterSubscription` が呼ばれ、購読を確定して `CONTACT_EMAIL` へ `NewsletterNotificationEmail` を送信します。
3. `/newsletter/unsubscribe?token=` も同じように確認してから、`unsubscribeFromNewsletter` が購読を解除します。どちらのリンクも開いたりプリフェッチしたりするだけでは何も変わらないため、メールスキャナーが誰かを登録・解除することはできません。`/newsletter/unsubscribe` へリンクするメールはありません。`newsletter-subscriber.utils.ts` の `unsubscribeUrl` がリンクを作成しますが、それを呼び出すものはありません。

号を配信する処理はまだありません。`src/data/newsletter.ts` の `NEWSLETTER_SENDING` は <RepositoryFact name="newsletterSending" /> なので、フッター、確認ページ、確認メール、講座がまだない講座一覧は、開発日誌の最初の号が配信予定だと伝えます。値が `available` になると、次の号から開発日誌が届くと伝えます。確認ページと確認メールは、リンクの有効期間 `CONFIRMATION_WINDOW_IN_HOURS`（<RepositoryFact name="newsletterConfirmationHours" unit="hour" />）を `newsletter-subscriber.constants.ts` から表示します。
