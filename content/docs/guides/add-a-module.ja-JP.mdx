---
title: "モジュールを追加する"
description: "Drizzle スキーマ、Zod スキーマ、定数、型、ユースケースを備えたデータベーステーブルを追加します。"
---

モジュールは 1 つのデータベーステーブルに対応します。`src/modules/<table>/` は実在するテーブルのためだけに存在し、テーブルを所有しないサーバー関数は `src/lib` か、それを使うルートに置きます。最小の完全な例は `src/modules/category` です。

## ファイル

| ファイル                   | 内容                                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------------ |
| `<table>.schema.ts`        | Drizzle のテーブル、インデックス、リレーション、enum の値のリスト                                |
| `<table>.zod.ts`           | 操作ごとに 1 つの入力スキーマと `drizzle-zod` のスキーマ。`<table>ZodSchemas` としてエクスポート |
| `<table>.constants.ts`     | クエリキーとミューテーションキーのタプル、モジュールの上限値                                     |
| `<table>.types.ts`         | テーブルから推論される行の型                                                                     |
| `<table>.utils.ts`         | 任意の純粋なヘルパー                                                                             |
| `use-cases/<operation>.ts` | 1 ファイルにつき 1 つのサーバー関数と、そのクエリオプションまたはミューテーションオプション      |
| `__test__/`                | ソースファイル名に合わせたテスト。例：`category.schema.test.ts`、`category.zod.test.ts`          |

## 1. テーブルを定義する

```ts
import { sql } from "drizzle-orm"
import { index, integer, sqliteTable, text } from "drizzle-orm/sqlite-core"

export const CATEGORY_KINDS = ["category", "collection"] as const

export const category = sqliteTable(
  "category",
  {
    createdAt: integer("created_at", { mode: "timestamp_ms" })
      .default(sql`(unixepoch() * 1000)`)
      .notNull(),
    id: text("id").primaryKey(),
    kind: text("kind", { enum: CATEGORY_KINDS }).notNull().default("category"),
    name: text("name", { length: 255 }).notNull(),
    updatedAt: integer("updated_at", { mode: "timestamp_ms" })
      .default(sql`(unixepoch() * 1000)`)
      .$onUpdate(() => new Date())
      .notNull(),
  },
  (table) => [index("category_createdAt_idx").on(table.createdAt)],
)
```

- カラム名は snake_case、プロパティは camelCase にします。
- ID は `text` の主キーで、挿入を行うユースケースで `uuid` の `v7()` を使って値を設定します。
- 日付は `integer(..., { mode: "timestamp_ms" })`、真偽値は `integer(..., { mode: "boolean" })` です。
- 外部キーには `.references(() => user.id, { onDelete: "cascade" })` を使い、結合は `relations(...)` で宣言します（`session.schema.ts` を参照）。

## 2. スキーマを登録する

テーブルと、リレーションがあればそれも、`src/integrations/drizzle-orm/drizzle.schemas.ts` からエクスポートします。

```ts
export { category } from "~/src/modules/category/category.schema"
```

このファイルは、D1 クライアント（`drizzle(env.DB, { schema })`）、Better Auth の Drizzle アダプター、drizzle-kit に読み込まれます。ここに含まれていないテーブルには、マイグレーションが生成されません。

## 3. マイグレーションを生成する

```sh
bun run db:generate
bun run db:migrate:local
```

`src/integrations/drizzle-orm/migrations/` に生成された SQL を確認し、スキーマと一緒にコミットします。リモート環境については [データベースマイグレーション](/docs/guides/database-migrations) で説明しています。

## 4. Zod スキーマを追加する

操作ごとに専用の入力スキーマを用意します。バリデーションメッセージは翻訳キーで、`<table>.validations` 名前空間で解決されます。

```ts
import { createSchemaFactory } from "drizzle-zod"
import zod from "zod/v4"

import { MIN_FIELD_LENGTH, idField } from "~/src/modules/_core/utils/zod-fields"
import { CATEGORY_KINDS, category } from "~/src/modules/category/category.schema"

const { createInsertSchema, createSelectSchema, createUpdateSchema } = createSchemaFactory({ zodInstance: zod })

export const CATEGORY_NAME_MAX_LENGTH = 255

const createCategory = zod.object({
  kind: zod.enum(CATEGORY_KINDS),
  name: zod.string().min(MIN_FIELD_LENGTH, { message: "nameRequired" }).max(CATEGORY_NAME_MAX_LENGTH, { message: "nameMaxLength" }),
})

const deleteCategory = zod.object({ categoryId: idField })

export const categoryZodSchemas = {
  createCategory,
  deleteCategory,
  insert: createInsertSchema(category),
  select: createSelectSchema(category),
  update: createUpdateSchema(category),
}
```

9 つのロケールすべてに `messages/<locale>/<table>.validations.json` を追加し、スキーマが使うすべてのキーを含めます。

## 5. 定数と型を追加する

```ts
export const CATEGORY_QUERY_KEYS = {
  ALL: ["category"],
  LIST: ["category", "getCategories"],
} as const

export const CATEGORY_MUTATION_KEYS = {
  CREATE: ["category", "createCategory"],
  DELETE: ["category", "deleteCategory"],
  UPDATE: ["category", "updateCategory"],
} as const
```

```ts
import type { category } from "~/src/modules/category/category.schema"

export interface Category {
  select: typeof category.$inferSelect
  insert: typeof category.$inferInsert
}
```

すべてのキーはモジュール名で始まるため、`ALL` を無効化するとモジュールのすべてのクエリが再取得されます。

## 6. 権限とユースケースを追加する

- 操作に権限が必要な場合は、`src/integrations/better-auth/auth.access.ts` の `APP_STATEMENTS` にテーブルのアクションを追加します。[ロールと権限](/docs/guides/roles-and-permissions) を参照してください。
- `use-cases/` の下に、操作ごとに 1 つのファイルを追加します。[ユースケースを追加する](/docs/guides/add-a-use-case) を参照してください。

## 7. テストする

モジュールの隣に `__test__/<table>.schema.test.ts`、`<table>.zod.test.ts`、`<table>.types.test.ts` を追加し、すべての操作について `use-cases/__test__/<operation>.test.ts` を追加します。カバレッジゲートは 100% です。[テストを書く](/docs/guides/writing-tests) を参照してください。
