## Templates

Templates live in `src/presentation/emails`. Each file holds markup only and exports its namespace constant:

| Template                       | Namespace                                | Sent by                                               |
| ------------------------------ | ---------------------------------------- | ----------------------------------------------------- |
| `VerifyEmail`                  | `emails.verify-email`                    | `sendVerifyEmail` (Better Auth hook)                  |
| `ResetPasswordEmail`           | `emails.reset-password-email`            | `sendResetPasswordEmail` (Better Auth hook)           |
| `ChangeEmailConfirmationEmail` | `emails.change-email-confirmation-email` | `sendChangeEmailConfirmationEmail` (Better Auth hook) |
| `NewsletterConfirmationEmail`  | `emails.newsletter-confirmation-email`   | `subscribeToNewsletter`                               |
| `NewsletterNotificationEmail`  | `emails.newsletter-notification-email`   | `confirmNewsletterSubscription`, to `CONTACT_EMAIL`   |

A template receives `locale` and `messages` and translates with use-intl `createTranslator`:

```tsx
const t = createTranslator({ locale, messages: { emails: { "verify-email": messages } }, namespace: "emails.verify-email" })
```

## Sending

The use case takes the locale and the `redirect` from the callback URL Better Auth passes along, checks the per-recipient limit, loads the messages, renders the template and sends it (`src/modules/verification/use-cases/send-verify-email.ts`):

```ts
if (!(await withinRecipientRateLimit({ kind: "verify-email", recipient: user.email }))) {
  console.warn("[email] verification email not sent: the recipient reached the hourly limit")
  return
}
const callback = new URL(callbackURL, getRequest().url)
const locale = extractLocaleFromPath(callback.pathname) ?? I18N.DEFAULT_LOCALE
const verifyUrl = new URL(localizePathname({ locale, pathname: ROUTES.VERIFY_EMAIL }), getRequest().url)
verifyUrl.search = callback.search
verifyUrl.searchParams.set("token", token)

const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotency: { purpose: "verify-email", token },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```

`sendEmail` (`src/integrations/resend/resend.utils.ts`) sends through Resend from `RESEND_EMAIL_FROM` unless a `from` is given (the owner notification uses `NOTIFICATIONS_EMAIL`), passes the idempotency key and throws on failure.

Account emails use the locale of the page where the flow started, read from the `callbackURL` in the email link; for a repeated sign-up it comes from the `callbackURL` of the sign-up request. Newsletter emails use the locale submitted with the form; the owner notification is always in `en-US`.

`withinRecipientRateLimit` (`src/lib/rate-limit.ts`) allows at most three verification, three password reset and three newsletter confirmation emails per address per hour, counted in the `rate_limit` table under a SHA-256 hash of the address. Over the limit the email is skipped and the request still gets its normal answer. The change-email confirmation and the owner notification are not limited.
