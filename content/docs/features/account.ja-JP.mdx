title: "アカウント"

---

`src/modules/account` は Better Auth の `account` テーブル（`account.schema.ts`）を所有します。ユーザーに紐づく認証情報または OAuth プロバイダーごとに 1 行あり、その中の OAuth トークンは暗号化されています。

## ユースケース

| ユースケース                       | ミドルウェア               | 利用箇所                                                                      |
| ---------------------------------- | -------------------------- | ----------------------------------------------------------------------------- |
| `signUpWithPassword`               | レート制限                 | `SignUpForm`                                                                  |
| `signOutUser`                      | サインイン必須             | `useSignOut`                                                                  |
| `changePassword`                   | サインイン必須、レート制限 | `PasswordCard`                                                                |
| `setPassword`                      | サインイン必須、レート制限 | `PasswordCard`                                                                |
| `changeEmail`                      | サインイン必須、レート制限 | `ChangeEmailForm`                                                             |
| `listAccounts`                     | サインイン必須             | `PasswordCard`、`TwoFactorCard`、`ConnectedAccountsCard`、`DeleteAccountCard` |
| `unlinkAccount`                    | サインイン必須、レート制限 | `ConnectedAccountsCard`                                                       |
| `updateUser`                       | サインイン必須             | 画面からは未使用                                                              |
| `sendChangeEmailConfirmationEmail` | Better Auth のフック       | `auth.server.ts` の `user.changeEmail`                                        |

`sendChangeEmailConfirmationEmail` は、Better Auth が発行した確認リンクを含む `ChangeEmailConfirmationEmail` を現在のアドレスへ送信します。`changePassword` は、ほかのセッションを必ず失効させます。`setPassword` は、GitHub または Google だけでサインインするアカウントに、Better Auth のサーバー専用の `setPassword` を通じてパスワードを追加し、ほかのセッションを失効させて `PasswordChangedEmail` を送信します。`listAccounts` は各サインイン方法の行 ID、プロバイダー、作成日をトークンなしで返し、`unlinkAccount` は行 ID を Better Auth の `unlinkAccount` に渡します。Better Auth は最後の 1 つの連携解除を拒否します。

## アカウントの削除

削除するとユーザーが消えるため、そのユースケースは user モジュールにあります。`requestAccountDeletion`（サインイン必須、レート制限）は Better Auth の `deleteUser` にパスワードの確認と確認リンクのメール送信を依頼し、`confirmAccountDeletion`（サインイン必須、トークンとしてレート制限）はリンクのトークンでアカウントを削除します。`sendDeleteAccountEmail`（`src/modules/user/use-cases/send-delete-account-email.ts`）は `sendDeleteAccountVerification` フックです。[設定](/docs/features/settings#delete-account)を参照してください。

## 環境設定

ユーザーが[設定](/docs/features/settings)で選ぶタイムゾーンは `user` テーブルの列なので、そのユースケースは user モジュールにあります。`updatePreferences`（`src/modules/user/use-cases/update-preferences.ts`）はサインイン中のユーザーを必須とし、`userZodSchemas.updatePreferences` で入力を検証して、Better Auth の `updateUser` を通じて保存します。これは上記のプロフィール更新と同じ経路です。`PreferencesCard` は `/app/settings` と `/admin/settings` でこれを呼び出します。言語は URL 内のロケールであり、保存されません。

## サインアウト

`useSignOut`（`src/hooks/use-sign-out.ts`）は `signOutUserMutation` を実行し、クエリキャッシュからそのアカウントのデータを削除して `/auth/sign-in` へ移動し、トーストを表示します。管理画面のユーザーウィジェットと `/app` のサイドバーには、それぞれこのフックを使う `SignOutButton` があります。
