- Fixed: three more places where the server and the browser could print different text, and React would report error #418. The footer printed `new Date().getFullYear()`: prerendered pages keep the year they were built in, while a browser past New Year computes the next one, so from 1 January until the next deploy every page with the footer would have failed to hydrate. It now ends the copyright in `REPOSITORY_FACTS.buildYear`, the UTC year of the build, which the server and the browser read from the same bundle. `CheckoutActivation` timed out by comparing the server's `dataUpdatedAt` with the browser's `Date.now`, so a browser clock a minute or more behind the server hydrated the delayed panel over the activating one; a timer started after hydration now ends the wait after `ACTIVATION_TIMEOUT_MS`, whatever the clock reads. The shadcn chart tooltip formatted numbers with `toLocaleString`, in the browser's locale, and now uses `useFormatter`. A lint rule keeps this from coming back: `hydration/no-clock-or-locale-in-render`, from the repository's own oxlint plugin in `scripts/hydration-lint-plugin.ts`, fails render code in `src/hooks`, `src/presentation`, `src/providers` and `src/routes/*.tsx` that reads the clock or formats in the runtime's locale outside event handlers, query functions, effects and timers. Browser tests set the browser's clock to 1 January 2099 on Kiritimati, and five minutes behind the server, and check that the landing page and the activation panel hydrate without an error.
