## Les routes composent les pages

Un fichier de route définit son composant `<Name>Page` ou `<Name>Layout`, `NAMESPACE` ou `NAMESPACES`, le loader et `head`. La page ne fait que placer des widgets ; les widgets se trouvent dans `src/presentation/components/custom/<feature>/`. Un layout ressemble à ceci (`src/routes/app.tsx`) :

```tsx title="src/routes/app.tsx"
const AppLayout = (): JSX.Element => (
  <SidebarProvider className="h-svh overflow-hidden">
    <AppSidebar />
    <SidebarInset className="relative min-h-0 min-w-0 overflow-hidden">
      <Background className="z-[-1]" glow={false} />
      <ImpersonationBanner />
      <AppHeader />
      <div
        className="custom-scrollbar flex min-h-0 flex-1 flex-col overflow-y-auto px-4 pt-5 pb-6 md:px-6 md:pt-7 md:pb-8"
        data-page-scroller
      >
        <div className="mx-auto w-full max-w-5xl">
          <EmailVerificationBanner />
          <Outlet />
        </div>
      </div>
    </SidebarInset>
  </SidebarProvider>
)
```

La zone de contenu défile à la place de la fenêtre ; elle porte donc `data-page-scroller` (voir [Barres de défilement](/docs/ui/theme#scrollbars)).

Une fonction serveur utilisée par une seule route peut être définie dans ce fichier de route avec `createServerFn`.

## Un widget, une boîte de dialogue ou un formulaire par fichier

Chaque widget, boîte de dialogue, formulaire ou jeu de colonnes a son propre fichier : `admin/users/row-actions.tsx`, `delete-user-dialog.tsx`, `reset-password-dialog.tsx`, `user-columns.tsx`. Les dossiers de composants sont à plat : pas de sous-dossiers `components/`, `hooks/`, `constants/` ou `types/`, et pas de découpage en `x.tsx` plus `x-content.tsx`. Les composants partagés se trouvent directement dans `custom/`.

## Les composants lisent leurs propres données

Un composant récupère lui-même ses textes et ses données au lieu de les recevoir en props :

- les traductions avec `useTranslations` ;
- les données de requête avec `useSuspenseQuery`, déjà chargées par le loader de la route ;
- les données du loader, le contexte de route et les paramètres de recherche avec `getRouteApi("…")`.

```tsx title="src/presentation/components/custom/blog/post-meta.tsx"
const route = getRouteApi("/_site/_marketing/blog/$")

const timeTag =
  (value: Date) =>
  (chunks: ReactNode): JSX.Element => (
    <time className="tabular-nums" dateTime={value.toISOString()}>
      {chunks}
    </time>
  )

export const PostMeta = (): JSX.Element => {
  const { post } = route.useLoaderData()
  const t = useTranslations("pages.blog")
  const format = useFormatter()

  const published = new Date(post.date)
  const updated = new Date(post.updated ?? post.date)
  const dateOf = (value: Date): string => format.dateTime(value, "calendarDate", { month: "long" })
  const tags = post.tags.map((tag) => t(`tags.${tag}`)).join(", ")
  const details = [BLOG_AUTHORS[post.author].name, t("post.readingTime", { minutes: post.readingTimeMinutes }), tags].filter(
    (item) => item.trim().length > 0,
  )

  return (
    <div className="flex flex-wrap items-center gap-x-3 gap-y-2 py-1 text-body-sm text-muted-foreground tabular-nums">
      <span className="flex items-center gap-2.5">
        <span aria-hidden className="size-1.25 shrink-0 rounded-full bg-ring" />
        <span>{t.rich("post.published", { date: dateOf(published), time: timeTag(published) })}</span>
      </span>
      {updated.getTime() > published.getTime() && (
        <span className="flex items-center gap-3">
          <span aria-hidden className="text-border">
            &middot;
          </span>
          <span>{t.rich("post.updated", { date: dateOf(updated), time: timeTag(updated) })}</span>
        </span>
      )}
      {details.map((item) => (
        <span className="flex items-center gap-3" key={item}>
          <span aria-hidden className="text-border">
            &middot;
          </span>
          {item}
        </span>
      ))}
    </div>
  )
}
```

Les props transportent une identité ou un état que seul le parent connaît, comme le `user` d’une boîte de dialogue avec `isOpen` et `onOpenChange`, ou un `activationId`. Il n’y a ni props de texte ou de libellé, ni transmission de props en cascade, ni enveloppes qui ne font que renommer des props ou transmettre des enfants. Une constante utilisée par un seul fichier reste dans ce fichier ; les données partagées par plusieurs fichiers vont dans `src/data`.

## Texte enrichi

Les tables de balises pour `t.rich` sont des constantes de module, jamais des objets créés pendant le rendu :

```tsx
const REUSE_TAGS = { accent: (chunks: ReactNode) => <strong className="font-medium text-foreground">{chunks}</strong> }
```

## Classes conditionnelles

Utilisez `cn` de `~/src/lib/cn` avec la syntaxe objet :

```tsx
<p className={cn("font-medium", { "text-foreground": !banned, "text-muted-foreground line-through": banned })}>{name}</p>
```

Affichez les alternatives avec une paire de conditions `&&` ou un retour anticipé plutôt qu’avec un ternaire sur plusieurs lignes.

## Fournisseurs

Les fournisseurs qui changent après l’hydratation n’enveloppent que les widgets qui en ont besoin, jamais un `Outlet` de route : `ThemeProvider` enveloppe le `Toaster` et le `ThemeSwitch` de la documentation, et `MotionProvider` enveloppe les sections de la page d’accueil, la liste du blog, les pages d’archive du blog et les cartes d’offres de `LicenseOffer`. `AriaProvider` enveloppe l’outlet racine et `TranslationsProvider` le corps du document, car tous les écrans en ont besoin.
