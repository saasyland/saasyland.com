Playwright testuje zbudowaną aplikację w prawdziwych przeglądarkach. Zestaw testów działa w środowisku Wranglera `test`: lokalne D1 i KV w `.wrangler/test`, fikcyjne dane uwierzytelniające z `.env.test` i testowy punkt wejścia `src/platform/testing/worker.ts`, który przechwytuje żądania do Resend i Polar.

```sh
bun run test:e2e:install
bun run test:e2e
bun run test:e2e:smoke
bun run test:e2e:pr
bun run test:e2e:headed
bun run test:e2e:ui
```

| Skrypt             | Uruchamia                                                          |
| ------------------ | ------------------------------------------------------------------ |
| `test:e2e:install` | Instaluje Chromium i WebKit wraz z zależnościami systemowymi       |
| `test:e2e`         | Wszystkie specyfikacje w Chromium i WebKit                         |
| `test:e2e:smoke`   | `e2e/specs/smoke.spec.ts` w Chromium                               |
| `test:e2e:pr`      | Wszystkie specyfikacje w Chromium, tak jak w CI dla pull requestów |
| `test:e2e:headed`  | Wszystkie specyfikacje w widocznych przeglądarkach                 |
| `test:e2e:ui`      | Tryb UI Playwright                                                 |

## Konfiguracja

`playwright.config.ts` definiuje projekty `chromium` (Desktop Chrome) i `webkit` (Desktop Safari) i używa `PLAYWRIGHT_BASE_URL` lub `http://127.0.0.1:3000`. Lokalnie polecenie serwera WWW uruchamia `db:migrate:test`, `db:seed:test`, `build:test` i `start:test` oraz ponownie wykorzystuje serwer, który już odpowiada pod tym adresem, więc najpierw zatrzymaj inne serwery na porcie 3000. W CI build przygotowuje workflow, a Playwright jedynie uruchamia serwer.

| Ustawienie     | Lokalnie                 | CI                        |
| -------------- | ------------------------ | ------------------------- |
| Ponowienia     | 0                        | 2                         |
| Workery        | 1                        | 2                         |
| Ślady (traces) | Zachowywane przy błędzie | Przy pierwszym ponowieniu |
| Nagrania wideo | Wyłączone                | Zachowywane przy błędzie  |
| Reporter       | Lista i HTML             | GitHub i HTML             |

## Struktura

- `e2e/specs/`: specyfikacje testów smoke, strony głównej, nawigacji, języków, uwierzytelniania, obszarów roboczych, newslettera, treści, motywu i cen regionalnych.
- `e2e/pages/`: obiekty stron (page objects).
- `e2e/fixtures/`: rozszerzony fixture `test` i funkcje pomocnicze do obsługi przechwyconych e-maili.
- `e2e/data/accounts.ts`: wstępnie utworzone konta administratora i klienta oraz ich hasło.

Testowy Worker udostępnia `/__test/emails` do odczytu e-maili przechwyconych przez mock Resend oraz `/__test/newsletter` do odczytu stanu subskrybenta.
