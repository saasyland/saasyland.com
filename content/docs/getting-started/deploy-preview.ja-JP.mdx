---
title: "プレビューをデプロイする"
description: "Cloudflare のリソースを用意し、プレビュー用 Worker をデプロイします。"
---

`preview` 環境は、Worker `saasyland-preview` を `preview.saasyland.com` にデプロイします。デフォルトでは、`development` と `preview` が 1 つの D1 データベース、1 つの KV 名前空間、1 つの R2 バケットを共有します。

## リソースを用意する

```sh
bunx wrangler login
bunx wrangler d1 create saasyland_com_preview
bunx wrangler kv namespace create CACHE --env preview
bunx wrangler r2 bucket create saasyland-preview
```

`wrangler.jsonc` で、`development` と `preview` の両方にある `database_id`、`database_name`、KV の `id`、`MEDIA` の `bucket_name` を置き換えます。バインディング名の `DB`、`CACHE`、`MEDIA`、および `migrations_dir` はそのままにし、Worker 名とカスタムドメインのルートを自分のアカウントに合わせて更新します。本番用には `saasyland` バケットを含む別のリソースを作成し、`production` ブロックを更新してください。`src/presentation/branding/index.ts` で `APP_DOMAIN` を設定します。`src/modules/_core/constants/api.ts` の `DEPLOYED_HOSTS` は、この値からデプロイ先のホスト（本番では `APP_DOMAIN`、プレビューでは `preview.<APP_DOMAIN>`）を導き出します。コードの中でこれらのホストを指定しているのはここだけです。`appHostsForMode` は Better Auth とニュースレターのリンクが受け付けるホストとしてこれを読み取り、`scripts/verify-deployment.ts` はデプロイ後にこれらのホストへリクエストを送ります。ローカルでは、`appHostsForMode` は開発で `localhost:3000` または `127.0.0.1:3000` を、テストではそれらに加えて `localhost:3020` と `127.0.0.1:3020` を受け付けます。`DEPLOYED_HOSTS` を編集するのは、プレビューのホスト名が異なる場合だけです。`wrangler.jsonc` のカスタムドメインの `routes` と `.github/workflows/deploy-reusable.yml` の環境 URL も同じホストを指定しているため、これらも合わせて更新してください。

## デプロイする

`.env.preview` に値を記入し、[Polar の設定](/docs/getting-started/polar-setup)の説明に従って Polar のサンドボックスを設定してから、デプロイします。

```sh
bun run deploy:preview
```

`deploy:preview` は、まずバインディングの欠落とプレースホルダーの ID を拒否する `scripts/verify-bindings.ts preview` を実行し、次に `.env.preview` の Polar の組織をコードと比較する `polar:verify:preview` を、その後に公開ページをプリレンダリングして出力を検証する `build:preview` を実行します。続いて `scripts/prepare-deploy-secrets.ts preview` が、`wrangler.jsonc` が `preview` 向けに宣言しているシークレットを `.env.preview` から `.wrangler/secrets.preview.json` に書き出し、いずれかが空であれば失敗します。`wrangler deploy` がそれらのシークレットとともに `dist/server/wrangler.json` をアップロードする前に `db:migrate:preview` が新しいマイグレーションを適用し、最後に `scripts/verify-deployment.ts preview` が、`DEPLOYED_HOSTS` のプレビューのホスト（https://preview.saasyland.com）が応答することを確認します。R2 バケットは名前でバインドされるため、`verify-bindings.ts` はバケットが存在するかどうかをチェックしません。バケットが存在するまで、デプロイは失敗します。`bun run db:migrations:preview` は、プレビューのデータベースにまだ適用されていないマイグレーションを一覧表示します。

[環境変数](/docs/getting-started/environment-variables)に記載されているとおり、プレビューのホスト用に OAuth のコールバックを登録します。

## 自動デプロイ

チェックとブラウザーテストが成功すると、CI はこのリポジトリ内のブランチからのプルリクエストを共有プレビューに、`main` へのプッシュを本番にそれぞれデプロイします。必要な GitHub のシークレットについては [CI/CD](/docs/tooling/ci-cd) を参照してください。
