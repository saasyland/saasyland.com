## Ablageregeln

- **Dateien und Ordner verwenden kebab-case.** Tests liegen in einem benachbarten `__test__`-Ordner.
- **Routen setzen nur zusammen.** Eine Routendatei definiert die Seiten- oder Layout-Komponente, `NAMESPACE` oder `NAMESPACES`, den Loader und `head`. Sie enthält keine Widgets, Dialoge oder Spaltendefinitionen.
- **Module sind Datenbanktabellen.** Lege `src/modules/<name>` nur für eine echte Tabelle an. Eine Server Function, die nicht mit einer Tabelle arbeitet, gehört nach `src/lib` (zum Beispiel `src/lib/github.ts`) oder, wenn nur eine Route sie nutzt, in diese Routendatei.
- **Gemeinsame Komponenten liegen flach.** Eine Komponente, die in mehreren Bereichen genutzt wird, ist eine einzelne Datei direkt in `presentation/components/custom`.
- **Bereichs- und Seitenordner.** Komponenten, die nur ein Bereich nutzt, liegen in `admin/`, `app/`, `auth/`, `blog/` oder `landing-page/`. Admin-Seiten bekommen einen eigenen Ordner, etwa `admin/users/` oder `admin/settings/`. Die Landingpage ist aufgeteilt in `sections/` (eine Datei pro Seitenabschnitt) und `components/` (Bausteine, die sich die Abschnitte teilen).
- **Ein Widget, Dialog, Formular oder Spaltensatz pro Datei.** Teile eine Komponente nicht in einen Wrapper und eine `-content`-Datei auf.
- **Keine verschachtelten Hilfsordner.** Komponentenordner enthalten nie Unterordner wie `components/`, `constants/`, `hooks/`, `lib/` oder `types/`, und neben einer Komponente liegt keine `.ts`-Hilfsdatei. Eine Konstante, die nur eine Komponente nutzt, bleibt in deren Datei.
- **Gemeinsame Daten gehören nach `src/data`.** Beispiele: die Gruppen der Admin-Sidebar, `MARKETING_SECTION_IDS`, die App-Navigation, die CLI-Auswahloptionen und die Demo-Zeilen.
- **Generierte Dateien werden nicht von Hand bearbeitet.** Das Router-Plugin schreibt `src/routeTree.gen.ts`, `bun run cf-typegen` schreibt `src/types/worker-configuration.d.ts`, und `bun run content` sowie `bun run generate:cn` schreiben `.source/`.
