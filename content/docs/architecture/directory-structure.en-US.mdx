## Placement rules

- **Files and folders use kebab-case.** Tests live in a sibling `__test__` folder.
- **Routes only compose.** A route file defines the page or layout component, `NAMESPACE` or `NAMESPACES`, the loader and `head`. It does not hold widgets, dialogs or column definitions.
- **Modules are database tables.** Create `src/modules/<name>` only for a real table. A server function that does not work on a table goes in `src/lib` (for example `src/lib/github.ts`) or, if one route uses it, in that route file.
- **Shared components are flat.** A component used across areas is a single file directly in `presentation/components/custom`.
- **Area and page folders.** Components used by one area live in `admin/`, `app/`, `auth/`, `blog/` or `landing-page/`. Admin pages get their own folder, such as `admin/users/` or `admin/settings/`. The landing page splits into `sections/` (one file per page section) and `components/` (pieces the sections share).
- **One widget, dialog, form or column set per file.** Do not split a component into a wrapper and a `-content` file.
- **No nested helper folders.** Component folders never contain `components/`, `constants/`, `hooks/`, `lib/` or `types/` subfolders, and no `.ts` helper file sits next to a component. A constant used by one component stays in that component's file.
- **Shared data goes in `src/data`.** Examples: the admin sidebar groups, `MARKETING_SECTION_IDS`, the app navigation, the CLI choices and demo rows.
- **Generated files are not edited by hand.** The router plugin writes `src/routeTree.gen.ts`, `bun run cf-typegen` writes `src/types/worker-configuration.d.ts`, and `bun run content` and `bun run generate:cn` write `.source/`.
