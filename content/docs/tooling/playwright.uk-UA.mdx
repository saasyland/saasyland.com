Playwright тестує зібраний застосунок у справжніх браузерах. Набір тестів працює із середовищем Wrangler `test`: локальні D1, KV і R2 у `.wrangler/test`, фіктивні облікові дані з `.env.test` і тестова точка входу `src/platform/testing/worker.ts`, яка перехоплює запити до Resend і Polar.

```sh
bun run test:e2e:install
bun run test:e2e
bun run test:e2e:smoke
bun run test:e2e:pr
bun run test:e2e:headed
bun run test:e2e:ui
```

| Скрипт             | Що запускає                                                   |
| ------------------ | ------------------------------------------------------------- |
| `test:e2e:install` | Встановлює Chromium і WebKit разом із системними залежностями |
| `test:e2e`         | Усі специфікації в Chromium і WebKit                          |
| `test:e2e:smoke`   | `e2e/specs/smoke.spec.ts` у Chromium                          |
| `test:e2e:pr`      | Усі специфікації в Chromium, як у CI для pull request         |
| `test:e2e:headed`  | Усі специфікації у видимих браузерах                          |
| `test:e2e:ui`      | Режим UI Playwright                                           |

## Конфігурація

`playwright.config.ts` визначає проєкти `chromium` (Desktop Chrome) і `webkit` (Desktop Safari) та використовує `PLAYWRIGHT_BASE_URL` або `http://127.0.0.1:3000`. Локально команда вебсервера запускає `db:migrate:test`, `db:seed:test`, `build:test` і `start:test` та повторно використовує сервер, який уже відповідає за цією адресою, тож спершу зупиніть інші сервери на порту 3000. У CI збірку готує workflow, а Playwright лише запускає сервер.

| Параметр   | Локально              | CI                      |
| ---------- | --------------------- | ----------------------- |
| Повтори    | 0                     | 2                       |
| Воркери    | 1                     | 2                       |
| Трасування | Зберігаються при збої | Під час першого повтору |
| Відео      | Вимкнено              | Зберігаються при збої   |
| Звіт       | List і HTML           | GitHub і HTML           |

## Структура

- `e2e/specs/`: специфікації для smoke-перевірок, лендингу, навігації, локалей, автентифікації, робочих просторів, розсилки, контенту, теми, регіональних цін, відео, курсів, адміністрування курсів і доступності.
- `e2e/pages/`: об'єкти сторінок (page objects).
- `e2e/fixtures/`: розширена фікстура `test` і помічники для перехоплених листів.
- `e2e/data/accounts.ts`: засіяні облікові записи адміністратора й клієнта та їхній пароль.
- `e2e/data/videos.ts` і `e2e/data/courses.ts`: засіяне тестове відео, файли якого лежать у `e2e/fixtures/video/`, і засіяний курс: один розділ із безкоштовним переглядом, уроком для акаунтів і двома платними уроками, один з яких без відео.

Тестовий Worker відкриває `/__test/emails` для читання листів, перехоплених моком Resend, і `/__test/newsletter` для читання стану підписника.

## Доступність

`e2e/specs/accessibility.spec.ts` запускає [axe-core](https://github.com/dequelabs/axe-core) через `@axe-core/playwright` на публічних сторінках, у записі блогу, на сторінках курсів і в робочих просторах адміністратора й клієнта у світлій і темній темах. Сторінки адмінпанелі охоплюють `/admin/courses`, `/admin/courses/create` і редактор тестового курсу, які також відвідує `e2e/specs/workspaces.spec.ts`. Специфікація застосовує правила рівнів A та AA з WCAG 2.0, 2.1 і 2.2, а також найкращі практики axe, прокручує сторінку, щоб перевірити й розділи, що з'являються під час прокручування, чекає завершення скінченних анімацій і падає за будь-якого порушення, вказуючи правило, його вплив і відповідні селектори.
