## Wybierz środowisko

| Środowisko        | Polecenia                                                     | Dane                                              | Dostawcy                               |
| ----------------- | ------------------------------------------------------------- | ------------------------------------------------- | -------------------------------------- |
| Izolowany podgląd | `db:migrate:test`, `db:seed:test`, `build:test`, `start:test` | Lokalne D1 i KV w `.wrangler/test`, konta testowe | Przechwytywani; konta nie są potrzebne |
| Deweloperskie     | `db:migrate:development`, `dev`                               | Zdalne D1 i KV podglądu                           | Prawdziwi, z `.env.development`        |

```sh
bun run db:migrate:test
bun run db:seed:test
bun run build:test
bun run start:test
```

Izolowany podgląd serwuje build pod `http://127.0.0.1:3000`; aby zobaczyć zmiany w kodzie, zbuduj go ponownie. Zaloguj się jako `admin@saasyland.example.test` lub `customer@saasyland.example.test` hasłem z `e2e/data/accounts.ts`. E-maile są przechwytywane zamiast wysyłane: otwórz `/__test/emails?to=<address>`, aby je przeczytać, łącznie z linkami weryfikacyjnymi.

```sh
bunx wrangler login
cp .env.example .env.development
bun run db:migrate:development
bun run dev
```

Serwer deweloperski działa pod `http://localhost:3000` z przeładowaniem na gorąco. Jego bindingi `DB` i `CACHE` to zdalne zasoby podglądu, więc zapisy i migracje wpływają na współdzieloną bazę podglądu. Ustaw `POLAR_SERVER=sandbox`.

## Odczytuj błędy serwera

- Nieudana funkcja serwerowa zapisuje `Server function failed` z oryginalnym błędem w terminalu z `bun run dev` albo w Workers Logs w środowiskach wdrożonych. Przeglądarka otrzymuje tylko kod błędu.
- `Rate-limit storage unavailable` oznacza, że D1 było nieosiągalne podczas sprawdzania limitu żądań; żądanie zostało odrzucone.
- `No messages/<locale>/<namespace>.json` oznacza, że trasa deklaruje przestrzeń nazw bez pliku dla danego języka.

## Przeglądaj dane

- Drizzle Studio: `bun run db:studio:development` (a także `:preview` i `:production`). Wymaga zmiennych `CLOUDFLARE_*` w odpowiednim pliku środowiskowym.
- Lokalna baza testowa: `bunx wrangler d1 execute DB --env test --local --persist-to .wrangler/test --command "SELECT email, role FROM user"`.

## Napraw pliki generowane

- Nieaktualne typy bindingów Workera, tabele nazw klas lub treść dokumentacji: `bun run typegen`.
- Tłumaczenia się nie rozwiązują: `bun run check:i18n` wypisuje brakujące klucze dla każdego języka oraz klucze, które nie rozwiązują się w swoim zakresie `useTranslations`.
- `bun run clean` usuwa wynik builda, cache i `.wrangler`, łącznie z lokalną bazą testową; potem uruchom ponownie `db:migrate:test` i `db:seed:test`.

## Debuguj testy

- Uruchom jeden projekt lub tylko testy objęte zmianami: `bun run test:unit`, `bun run test:component`, `bun run test:changed`, `bun run test:watch`.
- Playwright: `bun run test:e2e:headed` pokazuje przeglądarkę, a `bun run test:e2e:ui` otwiera tryb UI. Lokalne uruchomienia zachowują ślady nieudanych testów i otwierają raport HTML w razie błędów.
- Przed `bun run test:e2e` zatrzymaj inne serwery na porcie 3000 albo ustaw `PLAYWRIGHT_BASE_URL`.
