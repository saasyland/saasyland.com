Playwright は、ビルドしたアプリケーションを実際のブラウザーでテストします。スイートは Wrangler の `test` 環境に対して実行されます。この環境では、`.wrangler/test` 内のローカル D1、KV、R2、`.env.test` のダミー認証情報、そして Resend と Polar へのリクエストを横取りするテスト用エントリー `src/platform/testing/worker.ts` を使います。

```sh
bun run test:e2e:install
bun run test:e2e
bun run test:e2e:smoke
bun run test:e2e:pr
bun run test:e2e:headed
bun run test:e2e:ui
```

| スクリプト         | 実行内容                                                               |
| ------------------ | ---------------------------------------------------------------------- |
| `test:e2e:install` | Chromium と WebKit をシステムの依存関係とともにインストールします      |
| `test:e2e`         | すべてのスペックを Chromium と WebKit で実行します                     |
| `test:e2e:smoke`   | `e2e/specs/smoke.spec.ts` を Chromium で実行します                     |
| `test:e2e:pr`      | プルリクエストの CI と同じく、すべてのスペックを Chromium で実行します |
| `test:e2e:headed`  | すべてのスペックを表示されるブラウザーで実行します                     |
| `test:e2e:ui`      | Playwright の UI モード                                                |

## 設定

`playwright.config.ts` は `chromium`（Desktop Chrome）と `webkit`（Desktop Safari）のプロジェクトを定義し、`PLAYWRIGHT_BASE_URL` または `http://127.0.0.1:3000` を使います。ローカルでは、Web サーバーのコマンドが `db:reset:test`、`build:test`、`start:test` を実行します。その URL ですでに応答しているサーバーがあれば再利用するため、先にポート 3000 で動いている他のサーバーを停止してください。CI ではワークフローがビルドを準備し、Playwright はサーバーを起動するだけです。

| 設定       | ローカル     | CI               |
| ---------- | ------------ | ---------------- |
| リトライ   | 0            | 2                |
| ワーカー   | 1            | 2                |
| トレース   | 失敗時に保持 | 最初のリトライ時 |
| ビデオ     | オフ         | 失敗時に保持     |
| レポーター | List と HTML | GitHub と HTML   |

## 構成

- `e2e/specs/`: スモークチェック、ランディングページ、ナビゲーション、ロケール、認証、ワークスペース、ニュースレター、コンテンツ、テーマ、地域別価格、購入ファネル、アフィリエイト、動画、コース、コース管理、アクセシビリティのスペック。
- `e2e/pages/`: ページオブジェクト。
- `e2e/fixtures/`: 拡張した `test` フィクスチャ、キャプチャしたメール用のヘルパー、署名付きの `order.paid` Webhook を送信してライセンスを付与する `polar.ts` の `deliverPaidOrder`、`accessibility.ts` の `accessibilityViolations` とライトとダークの `COLOR_SCHEMES`。
- `e2e/data/accounts.ts`: シードされた管理者アカウントと顧客アカウント、およびそのパスワード。
- `e2e/data/videos.ts` と `e2e/data/courses.ts`: シードされるテスト動画（ファイルは `e2e/fixtures/video/`）と、シードされるコース。コースは 1 つのチャプターに、無料プレビュー、アカウント用レッスン、有料レッスン 2 つ（うち 1 つは動画なし）を持ちます。

テスト用 Worker は、Resend のモックがキャプチャしたメールを読み取る `/__test/emails` と、購読者の状態を読み取る `/__test/newsletter` を公開します。

## アクセシビリティ

`e2e/specs/accessibility.spec.ts` は `@axe-core/playwright` を通じて [axe-core](https://github.com/dequelabs/axe-core) を実行し、公開ページ、コースのページ、ドキュメントのトップページ、規約のすべてのページと、それ以外の各ドキュメントセクションから 1 ページずつ、ブログ記事、管理者とカスタマーのワークスペースをライトテーマとダークテーマで検査します。管理画面のページには `/admin/courses`、`/admin/courses/create`、シード済みのコースのエディターが含まれ、これらは `e2e/specs/workspaces.spec.ts` でも巡回します。WCAG 2.0、2.1、2.2 の A と AA のルールに加えて axe のベストプラクティスを適用し、ページが成功ステータスで読み込まれなければ失敗とし、スクロールで表示されるセクションも検査できるようページ全体をスクロールし、有限のアニメーションが終わるのを待ってから検査します。違反が 1 件でもあれば、ルール、影響度、該当するセレクターを示して失敗します。
