Cloudflare D1 (SQLite) to baza danych aplikacji, dostępna przez binding `DB`. `src/integrations/drizzle-orm/` łączy ją z Drizzle:

| Plik                  | Przeznaczenie                                                                                                                       |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `drizzle.database.ts` | Serwerowy `db`, tworzony przez `drizzle(env.DB, { schema })`                                                                        |
| `drizzle.schemas.ts`  | Ponownie eksportuje schemat każdej tabeli i jej relacje                                                                             |
| `drizzle.config.ts`   | drizzle-kit: dialekt SQLite, sterownik `d1-http`, migracje z prefiksem znacznika czasu w `migrations/`                              |
| `drizzle.errors.ts`   | `rethrowAsConflict`, który zamienia błąd ograniczenia unikalności na `AppError(ERROR_CODES.CONFLICT)` i rzuca dalej każdy inny błąd |
| `drizzle.columns.ts`  | `timestamps()`, czyli kolumny `createdAt` i `updatedAt`, które każda tabela ze znacznikami czasu wstawia do swojego schematu        |

## Tabele

Każda tabela należy do modułu w `src/modules/<table>/` z plikiem `<table>.schema.ts` (`drizzle-orm/sqlite-core`), a także `.zod.ts`, `.constants.ts`, `.types.ts` i folderem `use-cases/`, gdy tabela ma operacje, oraz `.utils.ts`, gdy potrzebuje helperów. Moduły to `account`, `category`, `chapter`, `course`, `lesson`, `lesson-progress`, `license`, `newsletter-subscriber`, `product`, `rate-limit`, `session`, `two-factor`, `user`, `verification` i `video`. `rate-limit` zawiera tylko swój schemat, a `license` jest też właścicielem `revoked_license_order`. Kod, który nie jest właścicielem żadnej tabeli, nie dostaje modułu.

Schematy stosują wspólne konwencje:

- Identyfikatory to ciągi UUID v7.
- Daty to kolumny `integer` w trybie `timestamp_ms` z wartością domyślną `unixepoch() * 1000`. `...timestamps()` dodaje w tej postaci `createdAt` i `updatedAt`, a `updatedAt` jest odświeżany przy każdej aktualizacji.
- Wartości logiczne to kolumny `integer` w trybie `boolean`.
- Relacje, indeksy, ograniczenia unikalności i klucze obce są deklarowane w schemacie.

## Atomowe zapisy

D1 nie obsługuje interaktywnych transakcji. Zachowaj atomowość operacji za pomocą pojedynczej instrukcji, np. upsertu z `onConflictDoUpdate`, albo grupuj instrukcje za pomocą `db.batch`. Przypadki użycia list stronicowanych pobierają stronę i łączną liczbę wierszy w jednym batchu (`src/modules/category/use-cases/get-categories.ts`):

```ts
const filter = data.kind && eq(category.kind, data.kind)
const [rows, totals] = await db.batch([
  db
    .select()
    .from(category)
    .where(filter)
    .orderBy(desc(category.createdAt), desc(category.id))
    .limit(data.pageSize)
    .offset(data.pageIndex * data.pageSize),
  db.select({ total: count() }).from(category).where(filter),
])
return { rows, total: totals.reduce((sum, row) => sum + row.total, 0) }
```

Limiter żądań w `src/lib/rate-limit.ts` łączy czyszczenie, atomowy upsert i odczyt w jednym batchu, dzięki czemu instancje Workera współdzielą te same limity.

## Migracje

Migracje to pliki SQL w `src/integrations/drizzle-orm/migrations/`, generowane poleceniem `bun run db:generate` i stosowane przez Wranglera. Vitest uruchamia je na bazie SQLite w pamięci. Polecenia opisuje strona [Migracje bazy danych](/docs/tooling/database).
