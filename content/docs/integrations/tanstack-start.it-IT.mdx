L'applicazione è un'app TanStack Start. `src/router.tsx` crea il router con un QueryClient per ogni richiesta, l'integrazione SSR delle query, i componenti predefiniti per errore e pagina non trovata, il preloading su intento, uno stale time dei precaricamenti uguale al suo stale time e il `rewrite` del locale. Non esiste un componente di attesa predefinito: ogni route imposta il proprio scheletro (vedi [Scheletri di caricamento](/docs/architecture/delivery-layer#scheletri-di-caricamento)). `src/routes.ts` esporta `ROUTES`, le costanti dei percorsi usate da link, guard e tag dell'head.

Il repository applica patch di Bun a `@tanstack/router-core` 1.171.39 e `@tanstack/react-router` 1.170.46 e fissa `@tanstack/router-core`, `@tanstack/react-router` e `@tanstack/react-start` perché restino installate le versioni con patch. Il primo render del router dopo l'idratazione reimpostava la posizione di scorrimento della finestra, che il browser e lo script di ripristino inline del router avevano già impostato, quindi un visitatore che scorreva mentre la pagina si idratava tornava in cima; con la patch, l'idratazione lascia invariata la posizione di scorrimento. `lazyRouteComponent` ricarica la pagina quando un chunk di route non si carica, per recepire un nuovo deploy, e Safari e Firefox fanno fallire allo stesso modo i chunk di una pagina che il visitatore sta lasciando, quindi il ricaricamento sostituiva la navigazione del visitatore con la pagina che stava lasciando; con la patch, un chunk che fallisce dopo `beforeunload` attende e si ricarica se il visitatore resta. Il chunk del loader di una route non ha questo ricaricamento; dopo un deploy è il componente di errore predefinito del router a ricaricare la pagina (vedi [Route e delivery](/docs/architecture/delivery-layer#after-a-deploy)). Vedi [Dipendenze](/docs/conventions/dependencies).

## Route

`src/routes/` contiene route basate su file in una struttura piatta: `admin.users.all.tsx` serve `/admin/users/all`, `_site.tsx` è un layout senza percorso e `_site.docs.$.tsx` è una route splat. L'ID in `createFileRoute("…")` è una stringa letterale gestita dal generatore del router in `src/routeTree.gen.ts`; le cartelle `__test__` non vengono considerate route.

Un file di route si limita a comporre la propria pagina. Definisce il componente `<Name>Page` o `<Name>Layout`, `NAMESPACE` o `NAMESPACES`, un loader che esegue il caricamento di metadati, messaggi e dati in un unico `Promise.all`, `head: pageHead(ROUTES.X)` e, per le aree protette, un guard in `beforeLoad`. Widget, dialog, form e colonne delle tabelle si trovano in `src/presentation/components/custom/` e leggono autonomamente le proprie traduzioni e i propri dati. Vedi [use-intl](/docs/integrations/use-intl) per il loader e [Better Auth](/docs/integrations/better-auth) per i guard.

## Funzioni server

Le operazioni sono funzioni `createServerFn` native esportate dai casi d'uso dei moduli, quindi l'applicazione non espone alcun endpoint REST per esse. Vedi [Funzioni server e casi d'uso](/docs/integrations/server-functions).

## Handler HTTP

Queste route in `src/routes/api/` dichiarano `server.handlers`:

| Route                                        | Handler                                                                                     |
| -------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `/api`                                       | Restituisce il runtime in formato JSON                                                      |
| `/api/auth/$`                                | Better Auth, inclusi i callback OAuth e i webhook di Polar su `/api/auth/polar/webhooks`    |
| <RepositoryFact name="cliApiBasePath" />`/*` | L'API delle licenze della CLI, `licenseApiHandlers` in `src/modules/license/license.api.ts` |

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Prerendering

Il plugin di TanStack Start in `vite.config.ts` abilita il prerendering con la scansione dei link, e `shouldPrerender` (`src/lib/prerender.ts`) filtra i percorsi scansionati. `build:preview`, `build:production` e `build:test` prerenderizzano le pagine pubbliche (landing, pagine legali, blog e documentazione) in tutti i locale. Il filtro esclude `/admin`, `/api`, `/app`, `/auth`, `/courses` e `/newsletter`, con o senza prefisso del locale, oltre ai link che contengono `?` o `#`. Le pagine escluse vengono renderizzate dal Worker a ogni richiesta.
