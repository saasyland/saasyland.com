---
title: "Migrações de banco de dados"
description: "Altere um schema do Drizzle, gere a migração SQL e aplique-a em cada banco D1."
---

O Cloudflare D1 (SQLite) é o banco de dados da aplicação. Os schemas dos módulos usam `drizzle-orm/sqlite-core`, `src/integrations/drizzle-orm/drizzle.schemas.ts` os reúne e o drizzle-kit grava as migrações em `src/integrations/drizzle-orm/migrations/` com um prefixo de data e hora.

## Fluxo de trabalho

1. Altere `<table>.schema.ts`. Para uma tabela nova, exporte-a também em `drizzle.schemas.ts`.
2. Gere o SQL:

```sh
bun run db:generate
```

3. Revise o arquivo gerado e faça o commit junto com a mudança do schema.
4. Aplique-o no banco com que você trabalha e em cada banco remoto antes de publicar código que dependa dele.

## Comandos

| Comando                          | Banco de dados                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------------- |
| `bun run db:migrate:test`        | Banco de teste local em `.wrangler/test`, usado pelo Playwright e pela prévia isolada |
| `bun run db:migrate:local`       | Banco de desenvolvimento local; `bun run dev` continua usando os bindings remotos     |
| `bun run db:migrate:development` | Banco remoto do ambiente de desenvolvimento, compartilhado por padrão com a prévia    |
| `bun run db:migrate:preview`     | Banco remoto da prévia                                                                |
| `bun run db:migrate:production`  | Banco remoto de produção                                                              |

`bun run db:studio:development`, `db:studio:preview` e `db:studio:production` abrem o Drizzle Studio, e os scripts `db:introspect:*` inspecionam o D1 pela API HTTP dele. Ambos precisam de `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID` e `CLOUDFLARE_ACCESS_TOKEN` no arquivo de ambiente correspondente.

## Convenções do schema

- Datas são `integer(..., { mode: "timestamp_ms" })` com o padrão `(unixepoch() * 1000)`.
- Booleanos são `integer(..., { mode: "boolean" })`.
- Índices, restrições de unicidade, chaves estrangeiras e relações ficam no arquivo do schema.
- O D1 não tem transações interativas. Mantenha uma operação atômica com uma única instrução SQL ou com `db.batch([...])`, como fazem `getUsers` e o limitador de requisições.

## Testes

O binding D1 de teste aplica cada arquivo SQL da pasta de migrações a um banco SQLite em memória, então os testes que usam o D1 rodam sobre o schema migrado. `src/integrations/drizzle-orm/__test__/` verifica se o schema, seus índices e suas chaves estrangeiras são criados corretamente. Veja [Escrever testes](/docs/guides/writing-tests).

## Dados existentes do PostgreSQL

Estas migrações criam apenas o schema SQLite. Mover dados de uma instalação anterior em PostgreSQL exige uma exportação e uma importação separadas e revisadas.
