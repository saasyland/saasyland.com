ドイツ語はサイトで最も長くなる言語で、読み手は直訳された文にすぐ気づくドイツ語圏のエンジニアと購入者です。`messages/de-DE/` のドイツ語メッセージ、ドキュメントのページ、ブログ記事、変更履歴の項目はすべてこのページに従います。最後の用語集がドイツ語の用語の唯一の情報源で、このページは `src/data/german-glossary.ts` の `GERMAN_TERMS`、`GERMAN_NAMES`、`GERMAN_PHRASES` を表示します。用語集でまだ決まっていない用語は、それを使う pull request の中でまず用語集に追加します。

## 文ではなく意味を書く

英語を読んだら閉じて、同じことを同僚や顧客に伝えるためにドイツのシニアエンジニアが書く文を書きます。事実、数値、プレースホルダー、タグは残し、翻訳らしく聞こえるそれ以外の部分はすべて書き直します。

- 英語が名詞を積み重ねるところで、ドイツ語は動詞を働かせます。`Die Funktionalität der Projektgenerierung wird ausgeliefert` ではなく `Die Projektgenerierung kommt mit einer späteren Version` です。
- 意味の違う同形語は意味を変えてしまいます。`kontrollieren` は制御するではなく点検する、`eventuell` は最終的にではなくもしかすると、`realisieren` は気づくではなく実行するという意味です。`Schnittstelle` はシステム間のインターフェースで、ユーザーインターフェースは `Oberfläche` です。`Quelle` は主張の出典で、コードは `Quellcode` です。ソフトウェアエンジニアは `Ingenieur` ではなく `Entwickler` です。
- 英語の決め台詞には、同じ言葉ではなく同じことを言うドイツ語の文を当てます。`You just shouldn’t have to` は `Du solltest es nur nicht noch einmal bauen müssen` で、`Du solltest es einfach nicht müssen` ではありません。
- ドイツ語の単語は 9 つの言語の中で最も長いので、スローガン、見出し、ボタンでは意味ではなく単語を削ります。トップページや料金の変更は、デスクトップとスマートフォンの幅で改行を確認します。

## 呼びかけと文体

サイトはすべての読み手に du で語りかけ、Duden が勧めるとおり小文字で書きます。`du`、`dein`、`dich`、`dir` です。呼びかけの形には法的な効力がないので、アカウントのページ、メール、法務ページも同じです。[文体は 1 つ](/docs/conventions/translations#one-form-of-address)では、`Sie`、`Ihr`、`Ihnen`、そして文中で大文字にした `Du` や `Dein` を不合格にするチェックを説明しています。

- ボタン、リンク、メニュー項目は不定詞（`Core kaufen`、`Befehl kopieren`、`Preise ansehen`）、見出しと表のヘッダーは名詞（`Einstellungen`、`Lizenz`、`Bestellungen`）、完了の通知は過去分詞（`Kopiert`、`Gespeichert`、`Aktivierungsplatz freigegeben`）にします。
- 本文は du の命令形で読み手に語りかけます。`Kopiere den Befehl, sobald er zu deiner Architektur passt.`
- エラーは、謝らずに、何が失敗したかと次に何をすればよいかを伝えます。`Die Kurse konnten nicht geladen werden. Du findest sie alle auf der Kursseite.`
- 語調は率直で、自信があり、正確です。感嘆符も、事実が裏づけない最上級も、英語のマーケティングにしかない売り文句も使いません。

## 複合語とハイフン

ドイツ語は複合語を 1 語で書き、英語から借りた語もほかの語と同じように結合します。`Kundenbereich`、`Lizenzschlüssel`、`Adminbereich`、`Landingpage`、`Starterkit`、`Teamplatz` です。

- 構成要素のどれかが略語、数字、名前、コードの識別子であるとき、または結合すると読みにくくなるときは、ハイフンでつなぎます。`E-Mail-Adresse`、`CI-Lauf`、`D1-Datenbank`、`Polar-Checkout`、`Webhook-Ereignis` です。
- 2 つの名詞からなる英語の複合語は、空白ではなく必ずハイフンでつなぎます。`Pull-Request`、`Merge-Queue`、`Rate-Limit`、`Code-Review`、`Use-Case`、`Release-Notes` です。英語の形容詞とその名詞は、Duden が `Open Source` に認めているように離して書いてもかまいません。`Breaking Change`、`Magic Link` です。
- 複合語が複数の単語からなる用語を含むときは、すべての部分をハイフンでつなぎます（Durchkopplung）。`Pull-Request-Beschreibung`、`TanStack-Start-Serverfunktionen`、`SaaSy-Land-Codebasis`、`End-to-End-Test` です。`Pull Request-Beschreibung` や `TanStack Start Serverfunktionen` とは書きません。
- 製品名は、単独で使うときは所有者が決めた表記を保ちます。`Durable Objects`、`Server Components`、`Content Security Policy`、`React Email` です。

## 英語の専門用語

ドイツのエンジニアは一部の英語の用語をドイツ語の名詞として使い、サイトもそれに倣います。`Webhook`、`Deployment`、`Worker`、`Build`、`Commit`、`Branch`、`Merge`、`Release`、`Stack`、`Framework`、`Repository`、`Checkout`、`Dashboard`、`Badge`、`Passkey`、`Pull-Request` です。斜体や引用符を付けずに書き、ドイツ語の冠詞と大文字を取り、ドイツ語の動詞と分詞を作ります。`der Build`、`das Deployment`、`das Release`、`die Repositorys`、`deployen`、`deployt`、`committet`、`gemergt` で、`deployed` や `gemerged` とは書きません。`die CLI` は `die Schnittstelle` にならって女性名詞です。

一般的なドイツ語の言葉があるものはすべて訳します。`tier` は `Paket`、`seat` は `Platz`、`refund` は `Erstattung`、`tenant` は `Mandant`、`server function` は `Serverfunktion`、`AI` は `KI` です。次の 2 語は、ドイツ語ですでに別の意味で使われているので注意が必要です。

- `Bereitstellung` はデジタルコンテンツの提供を指す消費者法の用語で、撤回権の期間が始まるきっかけになります。そのためデプロイは `Deployment` で、`Bereitstellung` とは書きません。
- ドイツ語の `Rate` は分割払いの 1 回分なので、仕組みは `Rate-Limiting`、上限は `Rate-Limit` で、`Ratenbegrenzung` とは書きません。

## ジェンダーに配慮した表現

読み手は常に du なので、読み手を指す性のある名詞は必要ありません。本文で役割を表すときは総称の男性形（`der Käufer`、`Entwickler`、`Nutzer`、`der Gründer`）を使い、ジェンダースター、コロン、大文字の I は使いません。`Nutzer*innen`、`Nutzer:innen`、`NutzerInnen` とは書きません。管理ページや法務文書が、記録を表示している 1 人の購入者について書くときは、両方の形を挙げます。`die Käuferin oder der Käufer` です。もともと中立な名詞は歓迎です。`Lernende` です。

## 組版

- 引用符は „…“ を使い、その中では ‚…‘ を使います。コードと識別子は、インラインコードの中でそれぞれの引用符を保ちます。
- 文の区切りのダッシュは両側に空白を入れたエンダッシュ（`–`）で、ハイフンは使いません。範囲は空白なしのエンダッシュで書きます。`10–20` です。
- コロンの後の完全な文は大文字で始めます（`Er darf so schnell schreiben, wie er will: Fehlerhafter Code gelangt nicht nach main.`）。単語、列挙、断片は小文字のままです（`Ja, für den Anwendungscode: Anweisungen, Verzweigungen, Funktionen und Zeilen`）。
- 見出し、タイトル、ボタン、メニュー項目はドイツ語の大文字の規則に従い、名詞だけを大文字にします。`Das Stabile Fundament` ではなく `Das stabile Fundament` です。
- ドイツ語では、すべての従属節（`dass`、`weil`、`wenn`、`sobald`、関係代名詞）の前と、`um`、`ohne`、`statt` を伴う不定詞句の前にコンマを置き、列挙の `und` や `oder` の前にはコンマを置きません。
- 数値、日付、通貨、単位はフォーマッターが出力します。3 桁区切りはピリオド（`50.000`）、小数点はコンマ（`0,50 $`）、パーセント記号と通貨記号の前には空白（`100 %`）を入れ、日付は `17. November 2026` と書くので、手で入力しません。コードが定義する値は `<RepositoryFact>` で表示します。

## 用語集のチェック [#glossary-check]

`bun run check` は `check:glossary` を実行し、ドイツ語のテキストが下の「使わない語」の列にある語を使うと失敗します。対象は `messages/de-DE/` のメッセージ（メールを含む）、ドイツ語のドキュメントページ、ブログ記事、変更履歴の項目すべて（タイトル、説明、質問を含む）、`meta.de-DE.json` のナビゲーションのタイトル、`content/courses/saasy-land-courses.json` のドイツ語のテキストです。ファイル、行、見つかった語、用語集が勧める語を出力します。同じチェックが、ポーランド語のテキストを[ポーランド語の用語集](/docs/conventions/polish-style#glossary-check)と照らし合わせます。

- 語は活用形のどれでも、また複合語の最初の部分としても失敗します。`src/data/german-glossary.ts` では縦線が語尾の始まる位置を示すので、`Stufe|` は `Stufen` と `Stufenkarte` で失敗し、`Graustufen` では失敗しません。下の表は縦線を除いて語を表示します。縦線のない語は書かれたとおりの形でだけ失敗するので、`Workspace` は `Bun-Workspace` でも `Workspaces` でも失敗しません。
- コード、リンク、パス、„…“ と ‚…‘ の引用、`engl.` の後に括弧で示した英語の用語はドイツ語の本文ではないので、チェックはこれらを飛ばします。
- 大文字で始まる語はどこに現れても失敗し、これでドイツ語の名詞をカバーします。小文字の語は、文、見出し、リスト項目、表のセル、リンクのテキストの先頭でも失敗します。
- ほかの言語をチェックに加えるには、`src/data/` に専用の用語集を置き、`src/lib/glossary-terms.ts` の `GLOSSARIES` に、そのロケール、引用符、英語を表す略語を指定するエントリーを追加します。
