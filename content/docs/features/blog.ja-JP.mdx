## コンテンツ

記事は言語ごとに 1 ファイルずつ `content/blog/<slug>.<locale>.mdx` に置きます。`src/integrations/fumadocs/fumadocs.schema.ts` のフロントマタースキーマでは `title`、`authorName`、`date` が必須で、`description`、`authorImage`、`excerpt`、`faq`、`featured`、`image`、`published`（既定値 `true`）、`tags`、`updated` を指定できます。タグは `src/data/blog.ts` の `BLOG_TAGS` のいずれかで、スキーマはそれ以外の値を拒否します。`PostRow` と `PostMeta` は各タグを `pages.blog` の `tags` にあるラベルで表示するため、タグはページの言語で読めます。

## 日付 [#dates]

`date` は記事を最初に公開した日で、変わることはありません。`updated` は記事の事実や内容が最後に変わった日です。価格、リリースされた機能、成り立たなくなった比較などがこれに当たり、誤字、書式、翻訳の修正では動かしません。どちらも `YYYY-MM-DD` で書き、記事のすべての言語で同じ 2 つを持ちます。日付が示すのは記事そのものであり、翻訳ではないからです。ブログのインデックスはすべての記事についてこの 2 つを保持し、読み手と検索エンジンが目にする日付はすべて、この 2 つから決まります。

- `PostMeta` は公開日と、`updated` が `date` より後のときは更新日を、それぞれ `dateTime` を持つ独自の `<time>` 要素に入れ、ページの言語に合わせた `calendarDate` 形式で表示します。ラベルは `pages.blog` の ICU メッセージ `post.published` と `post.updated` で、書式を整えた日付を `{date}` として受け取ります。ブログ一覧とランディングページの Notes にある `PostRow` は公開日だけを表示します。一覧をコンパクトに保てるうえ、一覧の並び順もこの日付で決まるからです。
- `BlogPosting` の JSON-LD は、`date` を `datePublished` に、`updated`（ない場合は `date`）を `dateModified` にします。
- `buildPageHead` は同じ 2 つを `article:published_time` と `article:modified_time` として書き出し、`sitemap.xml` はすべての言語で記事の URL に、その `article:modified_time` を `<lastmod>` として付けます。[検索エンジンとソーシャルプレビュー](/docs/features/seo)を参照してください。

フロントマターのスキーマは、ほかの形式の日付と、`date` より前の `updated` を拒否します。そのため、そうした記事では `bun run dev` もビルドも止まります。また、翻訳の `date` または `updated` が英語の記事と異なると、`scripts/check-content.ts` が失敗します。

## コードから取る値

記事はコードが定義する値を手で書かずに表示します。件数、カバレッジのしきい値（`coverageThreshold`）、React のメジャーバージョン（`reactMajor`）、例示用の時給（`illustrativeHourlyRate`、`unit="currency"` 付き）、Core の価格に相当する時間（`corePriceInHours`、`unit="hour"` 付き）には `<RepositoryFact>` を、価格、端末数の上限、先行時間には `<TierPrice>`、`<ActivationLimit>`、`<HeadStartTable />` を使います。`title` と `faq` の質問と回答は ICU メッセージで、`src/lib/post-text.ts` の `formatPostText` が `REPOSITORY_FACTS` と各プランの `<tier>Price`、`<tier>Machines` で整形します。`formatPostText` は `src/data/cli.ts` の `CLI_GENERATION_VALUES` も渡すため、プロジェクト生成の提供開始で変わる文は `{generation, select, available {…} other {…}}` として一度だけ書き、`post-faq.test.ts` が両方の状態で表示を確認します。`billingGeneration`（`src/data/marketing.ts` の `BILLING_GENERATION`）、`src/data/affiliates.ts` の `affiliateProgram` と `affiliateHoldDays`、`refundWithdrawalDays`（`REFUND_TERMS.WITHDRAWAL_DAYS`）も渡し、同じテストが `billingGeneration` と `affiliateProgram` による分岐を両方のステータスで表示します。`toBlogPostSummary` がタイトルを整形し、`<PostFaq entries={frontmatter.faq} />` が FAQ を表示します。記事の FAQPage JSON-LD も同じ FAQ を読みます。`post-faq.test.ts` は各記事のタイトル、質問、回答をその言語で整形します。

## ソース

ビルドのたびに、記事は言語ごとのブログのインデックスになります（[Fumadocs](/docs/integrations/fumadocs#content-indexes) を参照）。インデックスには、`/blog` 配下の公開済みの記事が、ドキュメントと同じ i18n 設定で新しい順に入り、各記事はフロントマター、目次、その言語向けに `Intl.Segmenter` で数えた読了時間を持ちます。`loadBlogIndex(locale)` はある言語のインデックス（`/assets/` 配下のファイル）をインポートし、`fumadocs.blog.ts` の `toBlogPostSummary` は記事のタイトルを整形して URL をローカライズします。以下のローダーはクライアント側のナビゲーションではブラウザーでインデックスを読むため、ブログ内を移動しても Worker には届きません。

## ルート

- `/blog` レイアウト（`_site._marketing.blog.tsx`）は `_site` と `_marketing` のレイアウトの中にあり、この 2 つがサイトヘッダー、`PageFrame`、`Footer`、`BackToTop` でその周囲を囲みます（[ランディングページ](/docs/features/landing-page#navigation-and-back-to-top)を参照）。記事のタイポグラフィ用に `docs.css` を読み込みます。ヘッダーは、一覧とすべての記事で **ブログ** を現在のセクションとして示します。ローダーは `fumadocs` と `pages.blog` を事前に読み込みます。
- `/blog`（`_site._marketing.blog.index.tsx`）は、ブログのインデックスにある記事を `PostRow` で一覧表示します。
- `/blog/$`（`_site._marketing.blog.$.tsx`）はブログのインデックスから記事を 1 件探し（見つからないか未公開なら 404）、`blogContent` でコンパイル済みの MDX をプリロードし、`src/presentation/components/custom/blog` の `PostMeta`、`PostToc`（小さい画面では同じ見出しの `InlineTOC`）、`PostCta`、`PostShare` を組み合わせます。`buildBlogPostStructuredDataHtml` の JSON-LD と `buildPageHead` の記事メタデータを追加します。`article:section` には `pages.blog` のブログのタイトルが入り、記事ごとに専用のソーシャルカードが付きます。[検索エンジンとソーシャルプレビュー](/docs/features/seo)を参照してください。記事は MDX を Fumadocs の `RootProvider` で包み、検索とテーマの切り替えは無効、文言は `useFumadocsI18n` のものです。そのため、コードブロックと見出しのアンカーのコピーボタン、FAQ のアコーディオンの項目には記事の言語で名前が付きます。

ランディングページの Notes セクションには、ブログのインデックスから 3 記事が、おすすめ記事を先に、続いて新しい記事の順で表示されます。

## 管理画面のブログ（デモ）

`/admin/blog` と `/admin/blog/create` は、`src/data/admin-blog.ts` のデモ記事と統計、および静的なエディターを表示します。`content/blog` の読み書きは行いません。

## チェック

記事を追加したら `bun run content` を実行します。`bun scripts/check-content.ts` は、すべての言語のファイルがあること、タイトル・説明・抜粋が翻訳されていること、コードブロックが同一であること、記事のすべての言語で `date` と `updated` が同じであることを確認します。
