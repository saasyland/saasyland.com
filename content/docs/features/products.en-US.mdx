## Data

`src/modules/product/product.schema.ts` defines the `product` table: `name`, `description`, `priceCents`, `currency`, `type` (`one_time`, `subscription`, `course`), `status` (`draft`, `published`, `archived`), `billingCycle` and timestamps.

Use cases in `src/modules/product/use-cases`, each behind the matching `product` permission:

- `getProducts` — paginated, with optional `type` and `status` filters; exports `getProductsPageQuery` and `getProductsQuery`.
- `getProduct`, `createProduct`, `updateProduct`, `deleteProduct`.

## Admin screen

`/admin/products` keeps its tab in the `?tab=` search param: `all`, `onetime`, `subscriptions`, `categories`, `collections`, `drafts` and `courses`. Product tabs page through the server:

```tsx
<DataTable
  columns={productColumns}
  key={tab}
  options={{ query: ({ pageIndex, pageSize }) => getProductsPageQuery({ pageIndex, pageSize, ...FILTERS[tab] }) }}
/>
```

`categories` and `collections` render `categoryColumns` with `getCategoriesPageQuery` (see [Categories](/docs/features/categories)); `courses` shows an empty state. The dashboard counter reads `getProductsQuery` too.

## Demo parts

- `/admin/products/create` renders `ProductDetails` and `ProductSidebar` as a static form; **Save** and **Cancel** are not wired.
- The row action button (`RowActionsCell`) has no menu.
- `createProduct`, `updateProduct`, `deleteProduct` and `getProduct` are not called by any screen yet.

Checkout does not use this table: purchasable tiers are Polar products (see [Payments and licences](/docs/features/payments)).
