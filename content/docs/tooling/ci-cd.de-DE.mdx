Workflows liegen in `.github/workflows/`. Die Anwendungs-Workflows (`ci.yml`, `e2e-reusable.yml` und `deploy-reusable.yml`) richten die Toolchain mit der Composite Action `.github/actions/setup` ein: Bun 1.4.0, Vite+ mit Node 24, ein Bun-Cache, `bun install --frozen-lockfile --ignore-scripts` und `bun run typegen`. `remotion.yml` richtet stattdessen Node und npm ein.

| Workflow              | Auslöser                                                     | Jobs                                                                                     |
| --------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `ci.yml`              | Pull Requests und Pushes auf `main`                          | Prüfungen und Testabdeckung, E2E in Chromium, dann Deployment in Preview oder Produktion |
| `e2e-full.yml`        | Pushes auf `main`, wöchentlich montags um 03:15 UTC, manuell | WebKit bei Push; Chromium und WebKit bei geplanten und manuellen Läufen                  |
| `e2e-reusable.yml`    | Von den obigen Workflows aufgerufen                          | Testdatenbank, Test-Build und ein Playwright-Projekt                                     |
| `deploy-reusable.yml` | Von `ci.yml` aufgerufen                                      | Build, D1-Migrationen und `wrangler deploy`                                              |
| `remotion.yml`        | Änderungen an `remotion/` oder seinen gemeinsamen Konstanten | Prüft und bündelt das Videoprojekt der Landingpage mit npm                               |

## Prüfungen

Der Job `verify` in `ci.yml` führt `bun run check` (Klassennamen-Tabellen, i18n- und Inhaltsprüfungen, Formatierung, Linting und Typen) und `bun run test:coverage` aus und lädt anschließend den Abdeckungsbericht hoch. Der Job `e2e` führt `db:migrate:test`, `db:seed:test` und `build:test` aus, installiert den Browser und startet `bunx playwright test e2e/specs --project=chromium`. Bei fehlgeschlagenen E2E-Läufen wird der Playwright-Bericht hochgeladen.

## Deployments

Deployments laufen erst, nachdem `verify` und `e2e` erfolgreich waren:

| Ereignis                                           | Ziel         | GitHub-Umgebung | URL                           |
| -------------------------------------------------- | ------------ | --------------- | ----------------------------- |
| Pull Request von einem Branch in diesem Repository | `preview`    | `Preview`       | https://preview.saasyland.com |
| Push auf `main`                                    | `production` | `Production`    | https://saasyland.com         |

Pull Requests aus Forks und von Dependabot werden validiert, aber nicht deployt. Die Preview ist gemeinsam genutzt: Jedes Deployment ersetzt das vorherige und verwendet dieselbe Preview-D1-Datenbank und denselben KV-Namespace.

`deploy-reusable.yml` prüft, ob die Secrets `CLOUDFLARE_API_TOKEN` und `CLOUDFLARE_ACCOUNT_ID` vorhanden sind, führt `scripts/verify-bindings.ts` aus, baut mit den Platzhalterwerten aus `.env.test`, entfernt die erzeugte `dist/server/.dev.vars`, wendet `db:migrate:<target>` an und führt `bunx wrangler deploy` aus. Es wird keine Secrets-Datei hochgeladen: Der Worker behält die Laufzeit-Secrets, die bereits in Cloudflare gesetzt sind. Deployments auf dasselbe Ziel werden in eine Warteschlange gestellt, statt sich gegenseitig abzubrechen.

Dependabot aktualisiert die GitHub Actions wöchentlich.
