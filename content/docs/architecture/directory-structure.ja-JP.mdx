## 配置のルール

- **ファイルとフォルダーにはケバブケースを使います。** テストは同じ階層の `__test__` フォルダーに置きます。
- **ルートは組み立てるだけ。** ルートファイルが定義するのは、ページまたはレイアウトのコンポーネント、`NAMESPACE` または `NAMESPACES`、ローダー、`head` です。ウィジェット、ダイアログ、カラム定義は置きません。
- **モジュールはデータベーステーブル。** `src/modules/<name>` は、実在するテーブルのためだけに作成します。テーブルを扱わないサーバー関数は `src/lib`（例：`src/lib/github.ts`）に置くか、1 つのルートだけが使う場合はそのルートファイルに置きます。
- **共有コンポーネントはフラットに。** 複数のエリアで使うコンポーネントは、`presentation/components/custom` 直下の単一ファイルにします。
- **エリアとページのフォルダー。** 1 つのエリアだけで使うコンポーネントは、`admin/`、`app/`、`auth/`、`blog/`、`landing-page/` のいずれかに置きます。管理画面のページには、`admin/users/` や `admin/settings/` のように専用のフォルダーを設けます。ランディングページは、`sections/`（ページのセクションごとに 1 ファイル）と `components/`（セクション間で共有する部品）に分かれます。
- **1 ファイルにつきウィジェット、ダイアログ、フォーム、カラムセットは 1 つ。** コンポーネントをラッパーと `-content` ファイルに分割しないでください。
- **ヘルパー用のフォルダーを入れ子にしない。** コンポーネントのフォルダーには `components/`、`constants/`、`hooks/`、`lib/`、`types/` のサブフォルダーを作らず、コンポーネントの隣に `.ts` のヘルパーファイルも置きません。1 つのコンポーネントだけが使う定数は、そのコンポーネントのファイル内に置きます。
- **共有データは `src/data` に置く。** 例：管理画面サイドバーのグループ、`MARKETING_SECTION_IDS`、アプリのナビゲーション、CLI の選択肢、デモ用の行。
- **生成ファイルは手で編集しない。** ルータープラグインが `src/routeTree.gen.ts` を、`bun run cf-typegen` が `src/types/worker-configuration.d.ts` を、`bun run content` と `bun run generate:cn` が `.source/` を書き出します。
