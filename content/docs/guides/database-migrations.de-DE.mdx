---
title: "Datenbankmigrationen"
description: "Ein Drizzle-Schema ändern, die SQL-Migration generieren und auf jede D1-Datenbank anwenden."
---

Cloudflare D1 (SQLite) ist die Anwendungsdatenbank. Modulschemas verwenden `drizzle-orm/sqlite-core`, `src/integrations/drizzle-orm/drizzle.schemas.ts` sammelt sie, und drizzle-kit schreibt Migrationen mit Zeitstempel-Präfix nach `src/integrations/drizzle-orm/migrations/`.

## Ablauf

1. `<table>.schema.ts` ändern. Eine neue Tabelle zusätzlich aus `drizzle.schemas.ts` exportieren.
2. Das SQL generieren:

```sh
bun run db:generate
```

3. Die generierte Datei prüfen und zusammen mit der Schemaänderung committen.
4. Sie auf die Datenbank anwenden, mit der gearbeitet wird, und auf jede Remote-Datenbank, bevor Code deployt wird, der davon abhängt.

## Befehle

| Befehl                           | Datenbank                                                                                   |
| -------------------------------- | ------------------------------------------------------------------------------------------- |
| `bun run db:migrate:test`        | Lokale Testdatenbank in `.wrangler/test`, genutzt von Playwright und der isolierten Preview |
| `bun run db:migrate:local`       | Lokale Entwicklungsdatenbank; `bun run dev` verwendet weiterhin die Remote-Bindings         |
| `bun run db:migrate:development` | Remote-Datenbank der Entwicklungsumgebung, standardmäßig mit Preview geteilt                |
| `bun run db:migrate:preview`     | Remote-Preview-Datenbank                                                                    |
| `bun run db:migrate:production`  | Remote-Produktionsdatenbank                                                                 |

`bun run db:studio:development`, `db:studio:preview` und `db:studio:production` öffnen Drizzle Studio, und die `db:introspect:*`-Skripte introspektieren D1 über seine HTTP-API. Beide benötigen `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID` und `CLOUDFLARE_ACCESS_TOKEN` in der passenden Umgebungsdatei.

## Schema-Konventionen

- Datumswerte sind `integer(..., { mode: "timestamp_ms" })` mit dem Standardwert `(unixepoch() * 1000)`.
- Boolesche Werte sind `integer(..., { mode: "boolean" })`.
- Indizes, Unique-Constraints, Fremdschlüssel und Relationen bleiben in der Schemadatei.
- D1 kennt keine interaktiven Transaktionen. Eine Operation mit einer einzigen SQL-Anweisung oder `db.batch([...])` atomar halten, wie es `getUsers` und der Rate-Limiter tun.

## Tests

Das Test-D1-Binding wendet jede SQL-Datei im Migrationsordner auf eine In-Memory-SQLite-Datenbank an, sodass D1-gestützte Tests gegen das migrierte Schema laufen. `src/integrations/drizzle-orm/__test__/` prüft, dass das Schema, seine Indizes und seine Fremdschlüssel tatsächlich angelegt werden. Siehe [Tests schreiben](/docs/guides/writing-tests).

## Bestehende PostgreSQL-Daten

Diese Migrationen erzeugen nur das SQLite-Schema. Das Übertragen von Daten aus einer früheren PostgreSQL-Installation erfordert einen separaten, geprüften Export und Import.
