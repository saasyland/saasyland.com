Las operaciones de negocio se encuentran en `src/modules/<table>/use-cases/<operation>.ts`, una operación por archivo. Cada archivo exporta un `createServerFn` nativo con su middleware, su validación con Zod y su handler, además de las opciones de consulta o de mutación que usan los componentes. Una función de servidor que no pertenece a ninguna tabla va en `src/lib` (por ejemplo, `getStarCount` en `src/lib/github.ts`), y una que solo usa una ruta puede definirse en el archivo de esa ruta (`getBlogPosts` en `src/routes/blog.index.tsx`).

```ts
export const createCategory = createServerFn({ method: "POST" })
  .middleware([authorized({ category: ["create"] })])
  .validator((input: zod.input<typeof categoryZodSchemas.createCategory>) => categoryZodSchemas.createCategory.parse(input))
  .handler(({ data }) =>
    db
      .insert(category)
      .values({
        description: data.description ?? "",
        icon: data.icon ?? "FolderOpen",
        id: v7(),
        kind: data.kind,
        name: data.name,
        visibility: data.visibility ?? "public",
      })
      .returning()
      .get(),
  )

export const createCategoryMutation = mutationOptions({
  mutationFn: (data: Parameters<typeof createCategory>[0]["data"]) => createCategory({ data }),
  mutationKey: CATEGORY_MUTATION_KEYS.CREATE,
})
```

## Reglas

- El middleware se ejecuta antes de la validación y del handler. Use `authorized(permission?)` para las operaciones protegidas y `withRateLimit(kind, RATE_LIMITS.SENSITIVE)` o `RATE_LIMITS.TOKEN` para las operaciones públicas sensibles; consulte [Better Auth](/docs/integrations/better-auth).
- Valide la entrada con el esquema de Zod del módulo (`<table>.zod.ts`).
- Devuelva los datos directamente y lance `AppError(ERROR_CODES.X)` de `src/modules/_core/constants/errors.ts` para los fallos previstos. Los demás errores llegan al cliente como `INTERNAL_ERROR`, de modo que los detalles del proveedor se quedan en el servidor.
- Las claves de consulta y de mutación son tuplas de solo lectura en el `<table>.constants.ts` del módulo, y las claves de consulta incluyen todas las entradas que modifican el resultado.
- Mantenga las operaciones atómicas con una única sentencia SQL o con `db.batch`; D1 no tiene transacciones interactivas.

## Usar un caso de uso

Los componentes propagan las opciones exportadas en `useQuery`, `useSuspenseQuery` o `useMutation`, traducen los errores con `useErrorMessage()` de `src/hooks/use-error-message.ts` e invalidan las claves de consulta del módulo tras una mutación correcta:

```tsx
const deleteUser = useMutation({
  ...deleteUserMutation,
  onError: (error) => {
    toast.error(errorMessage(error))
  },
  onSuccess: async () => {
    await queryClient.invalidateQueries({ queryKey: USER_QUERY_KEYS.ALL })
    toast.success(t("feedback.deleteSuccess"))
  },
})
```

Los loaders precargan las mismas opciones de consulta en su `Promise.all`, de modo que el renderizado en el servidor y el cliente comparten una única entrada de caché.
