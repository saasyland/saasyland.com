## Wybierz środowisko

| Środowisko        | Polecenia                                   | Dane                                                                                 | Dostawcy                               |
| ----------------- | ------------------------------------------- | ------------------------------------------------------------------------------------ | -------------------------------------- |
| Izolowany podgląd | `db:reset:test`, `build:test`, `start:test` | Lokalne D1, KV i R2 w `.wrangler/test`, konta testowe                                | Przechwytywani; konta nie są potrzebne |
| Deweloperskie     | `db:reset:local`, `db:seed:local`, `dev`    | Lokalne D1, KV i R2 w `.wrangler/state`, administrator i kursy z danych początkowych | Prawdziwi, z `.env.development`        |

```sh
bun run db:reset:test
bun run build:test
bun run start:test
```

Izolowany podgląd serwuje build pod `http://127.0.0.1:3000`; aby zobaczyć zmiany w kodzie, zbuduj go ponownie. Zaloguj się na jedno z przygotowanych kont wymienionych na stronie [Pierwsze uruchomienie](/docs/getting-started/first-run) hasłem z `e2e/data/accounts.ts`. E-maile są przechwytywane zamiast wysyłane: otwórz `/__test/emails?to=<address>`, aby je przeczytać, łącznie z linkami weryfikacyjnymi.

```sh
cp .env.example .env.development
bun run db:reset:local
bun run db:seed:local
bun run dev
```

Serwer deweloperski działa pod `http://localhost:3000` z przeładowaniem na gorąco. Jego bindingi `DB`, `CACHE`, `MEDIA` i `BUNDLES` są lokalne, więc nic, co robisz, nie dociera do danych podglądu ani produkcji. Zaloguj się jako administrator z [lokalnych danych początkowych](/docs/tooling/database#the-local-seed). Ustaw `POLAR_SERVER=sandbox`.

## Odczytuj błędy serwera

- Nieudana funkcja serwerowa zapisuje `Server function failed` z oryginalnym błędem w terminalu z `bun run dev` albo w Workers Logs w środowiskach wdrożonych. Przeglądarka otrzymuje tylko kod błędu.
- `Rate-limit storage unavailable` oznacza, że D1 było nieosiągalne podczas sprawdzania limitu żądań; żądanie zostało odrzucone.
- `[license] <method> <path> failed` oznacza, że żądanie do API licencji CLI zakończyło się błędem na serwerze, na przykład z powodu awarii D1 albo Polar, a CLI otrzymało `serviceUnavailable`. Wpis zawiera błąd z przyczyną i stosem wywołań, a w miejscu klucza wywołującego `[licence key]`.
- `No messages/<locale>/<namespace>.json` oznacza, że trasa deklaruje przestrzeń nazw bez pliku dla danego języka.

## Przeglądaj dane

- Drizzle Studio: `bun run db:studio:local` dla lokalnej bazy danych; `:preview` i `:production` wymagają zmiennych `CLOUDFLARE_*` w odpowiednim pliku środowiskowym.
- Lokalna baza testowa: `bunx wrangler d1 execute DB --env test --local --persist-to .wrangler/test --command "SELECT email, role FROM user"`.

## Napraw pliki generowane

- Nieaktualne typy bindingów Workera, tabele nazw klas lub treść dokumentacji: `bun run typegen`.
- Tłumaczenia się nie rozwiązują: `bun run check:i18n` wypisuje brakujące klucze dla każdego języka oraz klucze, które nie rozwiązują się w swoim zakresie `useTranslations`.
- `bun run clean` usuwa wynik builda, cache i `.wrangler`, łącznie z lokalną bazą testową; potem uruchom `db:reset:test`.

## Debuguj testy

- Uruchom jeden projekt lub tylko testy objęte zmianami: `bun run test:unit`, `bun run test:component`, `bun run test:changed`, `bun run test:watch`.
- Playwright: `bun run test:e2e:headed` pokazuje przeglądarkę, a `bun run test:e2e:ui` otwiera tryb UI. Lokalne uruchomienia zachowują ślady nieudanych testów i otwierają raport HTML w razie błędów.
- Przed `bun run test:e2e` zatrzymaj inne serwery pod adresem `127.0.0.1:3000` albo uruchom testy na drugim porcie, któremu ufa build testowy: `PLAYWRIGHT_BASE_URL=http://127.0.0.1:3020`.
