`DataGrid` (`src/presentation/components/custom/data-grid.tsx`) — це компонент таблиці. Він будує екземпляр TanStack Table v9 з можливостей у `src/integrations/tanstack-table/table.features.ts` і рендерить його примітивами таблиці shadcn та елементами керування React Aria. Сторінка передає йому свої стовпці й або свої рядки, або запит; усе інше, від панелі інструментів до панелі пагінації, міститься всередині нього.

```tsx
<DataGrid
  columns={columns}
  empty={t("empty")}
  id={ORDER_GRID_ID}
  label={t("title")}
  query={(request) => getOrdersPageQuery(orderZodSchemas.getOrders.parse(request))}
  search={t("filters.search")}
  selectable
/>
```

## Пропси

| Проп               | Призначення                                                                                                                                               |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `columns`          | Набір стовпців з `<entity>-columns.tsx` сторінки. Кожен рядок потребує рядкового `id`, який слугує ID рядка                                               |
| `id`               | Дає сітці назву: ключ її збереженого макета в браузері й початок назви її CSV-файлу                                                                       |
| `label`            | Доступна назва таблиці, зазвичай заголовок сторінки                                                                                                       |
| `data`             | Рядки в пам’яті, для сітки, яка шукає, фільтрує, сортує й ділить на сторінки на клієнті                                                                   |
| `query`            | Серверний режим: функція від запиту сітки, яка повертає параметри запиту, що розв’язуються в `{ rows, total }`                                            |
| `search`           | Мітка й плейсхолдер поля пошуку; без неї сітка не має пошуку                                                                                              |
| `empty`            | Що каже сітка, поки в ній немає рядків і не задано ні пошуку, ні фільтра                                                                                  |
| `emptyDescription` | Речення під цим заголовком, яке пояснює, звідки з'явиться перший рядок                                                                                    |
| `selectable`       | Додає стовпець прапорців і панель вибору                                                                                                                  |
| `bulkActions`      | Функція від вибраних рядків, яка рендерить додаткові кнопки на панелі вибору                                                                              |
| `rowActions`       | Компонент, що отримує кожен `row` і завершує його меню ⋯, у стовпці, закріпленому праворуч                                                                |
| `onReorder`        | Додає ручку до кожного рядка; викликається з переміщеним рядком і кількістю місць, на яку його зсунуто, як описано в розділі [Порядок рядків](#row-order) |

## Стовпці

Набір стовпців — це хук у `custom/<area>/<entity>-columns.tsx`, наприклад `useOrderColumns`. Стовпець, який додає інший розділ, — це один елемент стовпців хука, що називає комірку цього розділу, як стовпець **Пристрої** ліцензії в `useCustomerColumns`, а список стовпців скелетона так само називає комірку-скелетон цього розділу, тож якщо пропустити розділ, зникають обидва. Хук читає свої переклади й дані, які пропонують його фільтри, і повертає мемоізовані стовпці, тож кожна мітка — це простий рядок, який сітка може використати у своїх меню, оголошеннях і заголовку CSV. Кожна клітинка — невеликий компонент у тому самому файлі, який сам читає свої переклади.

```tsx
columnHelper.accessor("status", {
  cell: StatusCell,
  header: t("pages.admin.orders.table.headers.status"),
  meta: {
    export: ({ status }) => t(`pages.admin.orders.status.${status}`),
    filter: {
      kind: DATA_GRID_FILTER.MULTI_SELECT,
      options: ORDER_STATUSES.map((value) => ({ label: t(`pages.admin.orders.status.${value}`), value })),
    },
  },
  size: ORDER_COLUMN_SIZES.status,
})
```

`meta` — це те, що сітка читає зі стовпця:

| Ключ     | Дія                                                                                                                        |
| -------- | -------------------------------------------------------------------------------------------------------------------------- |
| `filter` | Фільтр стовпця: його `kind`, а для вибору — `options` у вигляді `{ label, value }`                                         |
| `hidden` | Прихований, доки адміністратор не покаже його з меню Стовпці                                                               |
| `pinned` | Закріплений на `start` або на `end`, доки адміністратор його не відкріпить                                                 |
| `export` | Текст, який CSV отримує для рядка. Без нього CSV бере рядки й числа як є, дати як моменти ISO, а все інше залишає порожнім |
| `align`  | `end` вирівнює заголовок і клітинки праворуч із табличними цифрами, для сум і кількостей                                   |

`size` — початкова ширина стовпця в пікселях. Стовпець можна сортувати, якщо він не задає `enableSorting: false`; у серверному режимі сортуватися мають лише ті стовпці, за якими вміє сортувати схема Zod модуля.

## Фільтри [#filters]

Види фільтрів: <RepositoryFact name="dataGridFilterKinds" />. Кожен має власний редактор, який відкривається кнопкою Фільтр на панелі інструментів або з чипа фільтра:

| Вид           | Редактор                                                                                                              | Значення                    |
| ------------- | --------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| `text`        | Текстове поле, що застосовується, щойно введення призупиняється на <RepositoryFact name="dataGridTypingDelayMs" /> мс | Текст без пробілів на краях |
| `select`      | Список варіантів; повторний вибір вибраного варіанта знімає його                                                      | Одне `value`                |
| `multiSelect` | Список варіантів, кілька одночасно; довгий список отримує поле пошуку                                                 | Масив `value`               |
| `numberRange` | Два числові поля, щонайменше й щонайбільше, будь-яке з них можна залишити порожнім                                    | `{ min?, max? }`            |
| `dateRange`   | Останні 7 днів, останні 30 днів, останні 12 місяців або будь-які дні в календарі                                      | `{ from?, to? }` у мс       |

Дні перетворюються на моменти в часовому поясі адміністратора, від початку першого дня до останньої мілісекунди останнього, тож сервер порівнює прості моменти. Кожен активний фільтр показується як чип на панелі інструментів, поруч із кнопкою Фільтр, щойно його задано, тож чипи й результати змінюються, поки фільтр лишається відкритим. Чип має короткий підсумок, наприклад щонайменше 40, Оплачено або Повернено чи вибрано: 3; його × прибирає його, а Прибрати фільтри прибирає всі. Зміна пошуку, фільтра або сортування повертає до першої сторінки й очищує вибір.

## Серверний режим

З `query` сітка ділить на сторінки, сортує, шукає й фільтрує на сервері. Вона викликає `query` з:

```ts
interface DataGridRequest {
  readonly filters: Readonly<Record<string, unknown>>
  readonly pageIndex: number
  readonly pageSize: number
  readonly search: string
  readonly sorting: SortingState
}
```

`filters` містить id кожного відфільтрованого стовпця з його значенням. Маршрут перевіряє запит схемою Zod модуля, перш ніж той дійде до серверної функції, як це робить `/admin/orders` через `orderZodSchemas.getOrders.parse(request)`. Поки не надійде перша сторінка, сітка показує рядки-скелетони; поки завантажується наступна сторінка, вона залишає попередні рядки приглушеними, позначає таблицю як зайняту й вимикає перемикання сторінок. Помилки запиту доходять до error boundary маршруту.

## Макет

Адміністратор переставляє сітку, а браузер зберігає це під `id` сітки в `localStorage` (`src/hooks/use-data-grid-preferences.ts`): які стовпці показано, їхній порядок, які закріплено, їхні ширини, щільність рядків і розмір сторінки. Пошук, фільтри, сортування й вибір не зберігаються. Скинути макет повертає типові значення. Якщо браузер відмовляє в сховищі, макет живе лише до кінця візиту.

- **Меню Стовпці.** Показує й ховає кожен стовпець, який можна сховати.
- **Меню стовпця.** Кнопка ⋮ кожного заголовка сортує за зростанням або за спаданням, скасовує сортування, закріплює стовпець ліворуч або праворуч, відкріплює його, посуває його на одне місце ліворуч або праворуч у межах його боку й ховає його.
- **Перетягування.** Заголовок, перетягнутий на інший заголовок того самого боку, займає його місце.
- **Зміна ширини.** Край заголовка можна перетягнути, щоб змінити ширину; це також роздільник, який клавіші зі стрілками розширюють або звужують, а подвійне клацання повертає початкову ширину.
- **Сортування.** Натискання на заголовок сортує за ним; із Shift воно додає стовпець до сортування, до <RepositoryFact name="dataGridMaxSortedColumns" /> стовпців, пронумерованих у заголовку.
- **Щільність.** Просторі або щільні рядки.
- **Розмір сторінки.** <RepositoryFact name="dataGridPageSizes" /> рядків на сторінку.

Сітка — це одна картка: зверху панель інструментів, далі таблиця, а внизу пагінація, розділені тонкими лініями. Панель інструментів має два рядки: у першому пошук і елементи керування виглядом, у другому, під ними, кнопка «Фільтр» і чипи активних фільтрів. Усі елементи керування панелі інструментів і чипи фільтрів мають однакову висоту; заголовки пишуться з великої літери лише на початку, у розмірі spec на приглушеній смузі, клітинки — у розмірі body, а останній стовпець даних займає всю ширину, що лишилася, тоді як стовпець дій зберігає власну. У кожному списку сітки варіант під вказівником підсвічується так само, як той, на якому стоїть клавіатура. Поле пошуку займає вільну ширину панелі інструментів, тож його підказка ніколи не обрізається. Заголовок завжди лишається в одному рядку й ніколи не розривається посеред слова: початкова ширина кожного стовпця вміщує його заголовок разом зі стрілками сортування й меню стовпця в кожній локалі, а `e2e/specs/text-layout.spec.ts` падає, коли мітка заголовка виходить за межі клітинки в будь-якій сітці адмін-панелі. У сітці, вужчій за 64rem, кнопки колонок, експорту CSV і скидання розкладки показують лише значки, тож пошук зберігає своє місце.

Рядок заголовків лишається на виду, поки рядки прокручуються всередині сітки, а закріплені стовпці лишаються на виду, поки сітка прокручується вбік; так телефон показує широку таблицю. Тінь на тому боці, де ще є стовпці поза видом, і на краю закріплених стовпців, щойно інші проходять під ними, показує, що сітка прокручується (`.grid-scroller` у `globals.css`).

Стовпець дій рядка має ширину <RepositoryFact name="dataGridActionsSize" /> пікселів і містить одну кнопку ⋯, `RowMenu` (`src/presentation/components/custom/row-menu.tsx`), яка відкриває дії рядка як меню: спершу повсякденні, а після роздільника — деструктивні, які просять підтвердження в діалоговому вікні попередження. Кожна сітка адмін-панелі й кожен список, порядок якого можна змінювати, як-от програма курсу, завершує свої рядки цією кнопкою, а не рядом значків. Стовпець не має меню стовпця: він не сортується, не ховається, не переміщується, не змінює ширину й не потрапляє в CSV, і завжди лишається останнім праворуч.

## Порядок рядків [#row-order]

З `onReorder` сітка починається з вузького стовпця ручок, який стоїть після прапорців, якщо вони в сітці є. Ручка — це приглушений значок для перетягування:

- **Перетягування.** Рядок, перетягнутий за ручку, рухається між іншими, коли вказівник проходить над ними, а коли його відпустити, нове місце зберігається. Escape або відпускання поза рядками повертає його на місце.
- **Клавіатура.** Коли ручка у фокусі, стрілки вгору й униз переміщують рядок на одне місце. Переміщення за перший або останній рядок сторінки відкриває сторінку, на яку переходить рядок, і ставить фокус на його ручку там.
- **Збереження.** `onReorder` отримує рядок і кількість місць, на яку його зсунуто, від’ємну вгору, тож сервер зсуває його від того місця, яке він займає в збереженому порядку на ту мить, зокрема між сторінками, а рядок, який інший адміністратор тим часом додав чи видалив деінде, не змінює того, куди він потрапить. Новий порядок з’являється одразу й тримається, поки переміщення зберігаються одне за одним, аж до приходу оновлених рядків; коли Promise, який повертає `onReorder`, відхиляється, рядки повертаються назад. `/admin/courses` передає `moveCourse` через мутацію зі `scope`, тож переміщення зберігаються в тому порядку, в якому їх зроблено.
- **Коли вимкнено.** Поки рядки відсортовано, відфільтровано або звужено пошуком, місце рядка на екрані не збігається з його місцем у збереженому порядку, тому ручки вимкнені.

Кожне переміщення оголошується в live-області, наприклад «Переміщено на позицію 3 з 12.»

## Вибір і експорт

З `selectable` прапорець вибирає рядок, а прапорець у заголовку вибирає сторінку. Тоді внизу вікна з’являється плаваюча панель із кількістю, Експортувати вибрані, `bulkActions` сторінки й Скасувати вибір. Вибирати рядки можна в кожній сітці адмін-панелі, яка показує записи: курси, продукти, категорії й колекції, замовлення, клієнтів, користувачів, запрошення й замовлення без ліцензії; не можна лише в таблицях із лічильниками на панелі адміністратора. `/admin/courses` додає **Видалити** для вибраних курсів; інші сітки експортують вибране, бо їхні записи не мають дії, яку можна застосувати до кількох одразу.

Експортувати CSV завантажує кожен рядок, який знаходять пошук і фільтри, а не лише сторінку на екрані: на сервері експорт запитує сторінки по <RepositoryFact name="dataGridExportPageSize" /> рядків, доки не отримає всі. Файл містить видимі стовпці в їхньому порядку, починається з мітки порядку байтів, щоб електронні таблиці читали його як UTF-8, і ставить `'` перед кожною клітинкою, яка починала б формулу. Записує його `src/lib/csv.ts`.

## Доступність

- Таблиця має `label` як назву та `aria-rowcount`; кожен рядок — свій `aria-rowindex`, порахований наскрізно через сторінки.
- Заголовки, за якими можна сортувати, — це кнопки з `aria-sort`.
- Кожен елемент керування працює з клавіатури: меню й списки підтримують клавіші зі стрілками та пошук під час введення з React Aria, Escape їх закриває, зміна ширини використовує стрілки на роздільнику заголовка, а рядок переміщується стрілками вгору й униз на його ручці, яка називається «Перетягніть або скористайтеся стрілками, щоб змінити порядок».
- Переміщення стовпця чи рядка, закріплення, приховування, сортування з меню та скидання макета оголошуються у ввічливій live-області; кількість результатів і кількість вибраних рядків теж оголошуються наживо.
