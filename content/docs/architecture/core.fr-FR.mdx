`src/modules/_core` est le seul dossier de module qui ne possède pas de table. Il ne contient que le socle sur lequel reposent les schémas, les schémas Zod et les cas d'usage des modules, afin qu'aucun module ne le redéfinisse : les codes d'erreur, les constantes HTTP et d'environnement, les champs Zod et les textes localisés partagés, ainsi que les entrées de pagination, d'ordre et de recherche.

## Constantes

| Fichier                 | Contenu                                                                                                                                    |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `constants/errors.ts`   | `ERROR_CODES`, le type `ErrorCode` et la classe `AppError`                                                                                 |
| `constants/api.ts`      | `HTTP_STATUS`, les noms des en-têtes `cf-ipcountry` et `cf-connecting-ip`, les en-têtes de sécurité, les hôtes autorisés par mode de build |
| `constants/ordering.ts` | `MOVE_DIRECTION` (`up`, `down`), `MOVE_DIRECTIONS` et le type `MoveDirection`                                                              |

Les données et les utilitaires que les modules utilisent sans reposer dessus vivent hors de `_core` : les catalogues des pays, des devises, des locales et des fuseaux horaires dans `src/data/countries.ts`, `src/data/currencies.ts`, `src/data/locales.ts` et `src/data/timezones.ts`, la devise de la boutique et le format des prix dans `src/data/pricing.ts`, et les périodes et les intervalles des graphiques de l'administration dans `src/lib/time-series.ts`. Le catalogue des locales recense toutes les locales connues ; les locales que l'application sert sont définies par `I18N.SUPPORTED_LOCALES` dans `src/integrations/use-intl/i18n.config.ts`. Un test de `src/__test__/module-tables.test.ts` échoue quand un fichier de `_core` n'est pas décrit sur cette page : chaque nouveau fichier est donc une décision réfléchie.

## Utilitaires

- `utils/localized-text.ts` : `LocalizedText`, un texte par locale stocké en JSON, `localizedTextSchema`, qui exige `en-US` et accepte au plus <RepositoryFact name="localizedTextMaxLength" /> caractères par texte, et `localize`, qui se rabat sur `en-US`
- `utils/ordering.ts` : `nextPosition`, la `position` la plus haute plus un, et `reorder`, qui échange un élément avec son voisin et numérote la liste à partir de 1 ; les cas d'usage des cours, des chapitres et des leçons gardent ainsi `position` sans trou
- `utils/pagination.ts` : `paginationSchema` (`pageIndex`, `pageSize`) et `DEFAULT_PAGE_SIZE`
- `utils/search.ts` : `searchSchema` et `localizedSearchSchema`, l'entrée des cas d'usage de recherche de l'administration, leurs limites de longueur et le `SearchHit` qu'ils renvoient
- `utils/zod-fields.ts` : des champs Zod réutilisables tels que `idField`, `localeField` et `slugField`

## Erreurs

Il existe une seule classe d'erreur et une seule liste de codes :

```ts
export const ERROR_CODES = {
  AUTH_API_ERROR: "AUTH_API_ERROR",
  CONFLICT: "CONFLICT",
  FORBIDDEN: "FORBIDDEN",
  INTERNAL_ERROR: "INTERNAL_ERROR",
  NOT_FOUND: "NOT_FOUND",
  TOO_MANY_REQUESTS: "TOO_MANY_REQUESTS",
  UNAUTHORIZED: "UNAUTHORIZED",
  VALIDATION: "VALIDATION",
} as const

export type ErrorCode = (typeof ERROR_CODES)[keyof typeof ERROR_CODES]

export class AppError extends Error {
  readonly code: ErrorCode

  constructor(code: ErrorCode, message: string = code) {
    super(message)
    this.name = "AppError"
    this.code = code
  }
}
```

Les fonctions serveur lèvent des `AppError`. Le middleware `withRequest` normalise tout le reste : les erreurs de l'API Better Auth deviennent `AUTH_API_ERROR` avec la clé d'erreur Better Auth comme message, les erreurs Zod deviennent `VALIDATION`, et les erreurs inconnues sont journalisées puis deviennent `INTERNAL_ERROR`. Dans le navigateur, `useErrorMessage()` de `src/hooks/use-error-message.ts` fait correspondre le message aux traductions `auth.errors.*` ou `errors.codes.*`.
