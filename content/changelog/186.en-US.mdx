- Fixed: the CLI licence API reported its own failures as the wrong error. When D1 could not count a request, the rate limiter refused it, so the CLI said there were too many requests; when D1 could not read the licence, or Polar refused a request in a way the contract does not name, the Worker answered HTTP 500, which the CLI cannot read, so it told the user to update it. Every endpoint, the bundle endpoint included, now answers any failure of the site with `serviceUnavailable` and `retry-after`. `serve` in `license.api.ts` is the one place that catches it and logs `[license] <method> <path> failed` with the error, its cause and its stack, with `[licence key]` in place of the caller's key, which Drizzle's query errors and Polar's validation errors would otherwise carry into Workers Logs. The API counts requests with `countRequest`, which throws when its storage fails; sign-in, the server functions and the email limits keep `consumeRateLimit`, which still refuses a request it cannot count. See [CLI licence API](/docs/features/cli-licence-api).
