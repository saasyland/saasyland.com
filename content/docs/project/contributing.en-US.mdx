---
title: "Contributing"
description: "How to propose changes to SaaSy Land."
---

1. Discuss large changes in an issue first.
2. Branch from `main`.
3. Follow the [architecture](/docs/architecture) and the [conventions](/docs/reference/conventions), and read the matching [agent skill](/docs/tooling/agent-skills) before changing a vendor integration.
4. Keep tests beside their owner and hold the 100% coverage gate.
5. Run the checks below.
6. Commit with a [conventional commit](/docs/tooling/conventional-commits) message and open a pull request with a conventional title.

```sh
bun run check
bun run test:coverage
bun run test:e2e:install
bun run test:e2e:smoke
```

Run the full browser suite (`bun run test:e2e`) for changes that affect several routes, authentication or browser behaviour. Validate real provider integrations separately when you change their configuration.

When behaviour changes, update `content/docs` in all nine locales; `bun run check:i18n` rejects missing translations, differing code blocks and navigation. In the pull request, describe the resulting behaviour, how you verified it and any demo or unfinished workflow it leaves.
