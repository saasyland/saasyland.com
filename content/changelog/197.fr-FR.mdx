- Chaque page charge environ 21 Kio de JavaScript compressé avec gzip en moins. Le script d'entrée contenait la table qui associe chaque fichier de messages à son chunk, chaque namespace de chaque locale, en double, parce que `loadPageMetadata` avait sa propre table, alors que la première page lit ses messages dans le cache de queries que le serveur envoie et n'en avait jamais besoin. La table vit désormais dans `i18n.loaders.ts`, que `loadNamespace` importe la première fois qu'il charge un namespace, et `loadPageMetadata` lit `metadata` dans le namespace de la page ; la page d'accueil est passée de 462,9 Kio à 442,3 Kio. `scripts/verify-build.ts` fait échouer le build lorsque les imports statiques du script d'entrée contiennent le loader d'un namespace de page. Voir [Charger les messages quand une page en a besoin](/docs/conventions/performance#load-messages-when-a-page-needs-them).
