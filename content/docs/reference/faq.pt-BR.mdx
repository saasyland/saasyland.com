## Qual runtime a aplicação usa?

Cloudflare Workers. O Bun instala os pacotes e executa os scripts; o Vite+ (`vp`) faz o build, a formatação, o lint e os testes da aplicação.

## Os testes locais precisam de uma conta do Cloudflare?

Não. O Vitest usa um banco SQLite em memória e um KV em memória. O Playwright usa o ambiente Wrangler `test`, com D1 e KV locais em `.wrangler/test` e secrets fictícios de `.env.test`. Já o `bun run dev` precisa de acesso ao Cloudflare, porque o ambiente `development` usa os bindings remotos de preview.

## Onde fica uma nova operação?

Se ela trabalha com uma tabela do banco de dados, é um caso de uso no módulo dessa tabela: `src/modules/<table>/use-cases/<verb>-<noun>.ts`. Se apenas uma rota a usa e ela não mexe em nenhuma tabela, defina-a com `createServerFn` no arquivo dessa rota. Caso contrário, coloque-a em `src/lib`.

## Quando devo criar um novo módulo?

Apenas quando você adicionar uma nova tabela ao banco de dados. Um módulo sem tabela não é permitido.

## Onde fica um novo componente?

Um componente compartilhado entre áreas é um arquivo plano em `src/presentation/components/custom`. Um componente de uma única área vai para a pasta dessa área, por exemplo `custom/admin/users/`. Um widget, diálogo ou formulário por arquivo.

## Como os idiomas são organizados?

O en-US usa URLs sem prefixo; os outros oito locales usam a tag completa como prefixo, por exemplo `/de-DE` ou `/pl-PL`. Todos os locales têm os mesmos arquivos de namespace em `messages/<locale>`, e cada página da documentação existe como `<page>.<locale>.mdx`.

## Como passo texto para um componente?

Você não passa. O componente chama `useTranslations` com o próprio namespace e lê o texto sozinho.
