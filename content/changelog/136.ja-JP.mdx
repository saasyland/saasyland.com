- Polar: `bun run polar:verify:<environment>` は、その環境の Polar の組織を GET リクエストだけでコードと比較し、`deploy:preview` と `deploy:production` は `verify-bindings.ts` の後にこれを実行します。失敗するのは、プランの商品がない、アーカイブ済み、またはサブスクリプションである場合、価格が `DEFAULT_CURRENCY_CODE` 建てで固定された `TIER_PRICES` の額ではない場合、商品のライセンスキーの特典がちょうど 1 つでないか、その特典のアクティベーション数の上限がプランの値と異なるか、有効期限や使用回数の上限が設定されている場合、`PPP_TIERS` のいずれかの区分に、購入時にすべてのプランに適用される自動割引がない場合、そしてその環境のホスト用の Webhook がない、無効になっている、別のシークレットで署名されている、またはハンドラーが処理するものとは異なるイベントを購読している場合や、エンドポイントが別の環境のホストに送信している場合です。CI のデプロイは Polar のトークンを持たないため、これを実行しません。
- 各プランのアクティベーション数の上限はコードで定義するようになりました。`license.constants.ts` の `LICENSE_ACTIVATION_LIMITS` で、`licenseWebhookHandlers` が処理しなければならないイベントである `LICENSE_WEBHOOK_EVENTS` と並んでいます。購入処理と `polar:verify` は、`polar.discounts.ts` の `findRegionalDiscount` という 1 つの地域割引のルールを共有します。
- [Polar の設定](/docs/getting-started/polar-setup)では、本番とサンドボックス、トークンのスコープ、商品、ライセンスキー、地域割引、Webhook、`polar:verify` の実行方法、各失敗の意味を説明しています。MDX コンポーネント `ActivationLimit` と `RegionalDiscounts` は、上限と割引をコードから取得して表示します。
