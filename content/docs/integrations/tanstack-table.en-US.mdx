Every new table renders through `DataGrid` in `src/presentation/components/custom/data-grid.tsx` ([Data grid](/docs/ui/data-grid)). The TanStack Table v9 setup it builds on lives in `src/integrations/tanstack-table/`:

| File                | Holds                                                                                                                                                      |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `table.features.ts` | `dataGridFeatures`, the `tableFeatures` registry; the filter kinds and their filter functions; the density and pin values; the `ColumnMeta` the grid reads |
| `table.columns.ts`  | Column helpers: the default visibility and pinning from `meta`, the column label, the sticky offsets of pinned columns, reordering and the CSV value       |

## Features

`dataGridFeatures` registers column filtering, ordering, pinning, sizing, resizing and visibility, the global filter, pagination, row selection and sorting, with the filtered, sorted and paginated row models. A grid with `query` sets `manualFiltering`, `manualPagination` and `manualSorting`, so those row models only run for a grid with `data`.

## Filter functions

Each filter kind maps to one registered function in `DATA_GRID_FILTER_FNS`, which the grid gives every column that declares `meta.filter`:

| Kind          | Function         |
| ------------- | ---------------- |
| `text`        | `includesString` |
| `select`      | `equalsString`   |
| `multiSelect` | `arrHas`         |
| `numberRange` | `numberInRange`  |
| `dateRange`   | `dateInRange`    |

`numberInRange` and `dateInRange` are built with `constructFilterFn` for the `{ min?, max? }` and `{ from?, to? }` values the grid's editors write, and drop a range that has neither bound. The same shapes are `numberRangeField` and `dateRangeField` in `src/modules/_core/utils/zod-fields.ts`, which a module's Zod schema uses to read the grid's request.

## State

The grid controls every slice it uses. Pagination, sorting, column filters, the search and the selection live in component state and go back to the first page and an empty selection when the search, a filter, the sorting or the page changes. Column visibility, order, pinning and sizing, with the density and the page size, come from `useDataGridPreferences` (`src/hooks/use-data-grid-preferences.ts`), which reads and writes them in `localStorage` through `useSyncExternalStore` and renders the defaults on the server.
