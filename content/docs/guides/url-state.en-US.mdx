---
title: "URL state"
description: "Keep tabs, views and one-time tokens in validated search parameters."
---

Search parameters hold state that should survive a reload or a shared link: the selected tab or view, an email address handed between auth pages, a verification token. Everything else stays in React state. `DataTable` keeps its pagination, sorting, selection and filters in component state.

## Declare the parameters

`validateSearch` takes a zod object, so the route's search parameters are typed and validated in one place. Its fields come from `src/lib/search-params.ts`: `searchText()` and `searchFlag()` are `undefined` when the value is missing, empty or malformed, so absent values never appear in the URL; `searchChoice(choices, fallback)` falls back to a choice. `searchParam(schema)` applies the same rule to any zod schema; the newsletter routes read `token` with the module's own token schema. A malformed value never leads to an error page. From `src/routes/admin.blog.index.tsx`:

```tsx
validateSearch: zod.object({
  view: searchChoice([ADMIN_BLOG_VIEW.GRID, ADMIN_BLOG_VIEW.TABLE], ADMIN_BLOG_VIEW.GRID),
}),
search: { middlewares: [stripSearchParams({ view: ADMIN_BLOG_VIEW.GRID })] },
```

`stripSearchParams` removes the default value from the URL, so `/admin/blog` stays the canonical address of the grid view.

## Read them

- In the route component: `const { view } = Route.useSearch()`.
- With a selector, the component re-renders only when the selected value changes: `Route.useSearch({ select: (search) => search.error !== undefined })`.
- In a component outside the route file: `getRouteApi("/auth/reset-password").useSearch()`, as in `reset-password-form.tsx`.

## Change them

- Links: `<Link search={{ view: id }} to={ROUTES.ADMIN_BLOG}>`.
- React Aria components with an `href`, such as `TabsTrigger` in `src/routes/admin.products.index.tsx`, navigate through the router because `AriaProvider` connects React Aria to TanStack Router.
- Code: `router.navigate({ search: { email }, to: ROUTES.VERIFY_EMAIL })`.
- Guards and loaders: `throw redirect({ replace: true, to: ROUTES.AUTH_CALLBACK })`.

## Load data from them

A component reads search parameters with `Route.useSearch()`; a loader that depends on one declares it in `loaderDeps` and reads it from `deps`. Never spend a token from the URL in a loader, because preloading, crawlers and mail scanners all run loaders. The newsletter confirmation and unsubscribe pages read their token and act only when the visitor presses the button:

```tsx
const { status, token } = Route.useSearch()
```

## Locales and URLs

- Router links (`<Link to={ROUTES.X}>`) receive the locale prefix from the router `rewrite`. English has no prefix (`/docs`); other locales do (`/pl-PL/docs`).
- Build a raw URL in the current locale with `router.buildLocation({ search, to }).publicHref`, which localizes it and serializes its search params, as `useAuthRedirect` does for Better Auth `callbackURL` and `errorCallbackURL`. `localizePathname({ locale, pathname })` builds a URL for a given locale, such as links in emails; it leaves `/api` paths and external URLs unchanged.
- The locale switcher links to the same pathname in the other locale with a full page load; query and hash are not carried over.
