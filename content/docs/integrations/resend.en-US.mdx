`src/integrations/resend/resend.config.ts` exports `resendClient`, which creates the Resend client from `RESEND_API_KEY` each time an email is sent: the Resend SDK throws without a key, so a build, a prerendered page or a request that sends no email needs none. `resend.utils.ts` exports `sendEmail`, the only function that sends email. `from` defaults to `RESEND_EMAIL_FROM`, the required `idempotency` option names the email's purpose and the token that triggered it, and `sendEmail` turns them into the key `${purpose}/${sha256Hex(token)}`, which stops Resend from sending a retried request twice and stays within Resend's 256-character limit, and a Resend error is thrown. Both files are server-only. Each area that sends email names its purposes in `src/data/<area>.email-purposes.ts`, and `resend.constants.ts` joins them from `src/data/email-purposes.entries.ts` into `EMAIL_PURPOSE`, which `resend.constants.test.ts` checks for duplicates. The use cases pass the same name as the `kind` of the per-recipient limit.

## Templates and use cases

Templates in `src/presentation/emails/` are React Email components with markup only. Each exports a `*_NAMESPACE` constant, receives `locale` and `messages` as props and translates with use-intl `createTranslator`. The use case that sends an email receives the locale from its caller (the verification email reads it from the callback URL), loads the messages, renders the template and calls `sendEmail`:

```ts
const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotency: { purpose: EMAIL_PURPOSE.VERIFY_EMAIL, token },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```

| Template                              | Namespace                                | Sent by                                                                      |
| ------------------------------------- | ---------------------------------------- | ---------------------------------------------------------------------------- |
| `verify-email.tsx`                    | `emails.verify-email`                    | `modules/verification/use-cases/send-verify-email.ts`                        |
| `reset-password-email.tsx`            | `emails.reset-password-email`            | `modules/verification/use-cases/send-reset-password-email.ts`                |
| `change-email-confirmation-email.tsx` | `emails.change-email-confirmation-email` | `modules/account/use-cases/send-change-email-confirmation-email.ts`          |
| `newsletter-confirmation-email.tsx`   | `emails.newsletter-confirmation-email`   | `modules/newsletter-subscriber/use-cases/subscribe-to-newsletter.ts`         |
| `newsletter-notification-email.tsx`   | `emails.newsletter-notification-email`   | `modules/newsletter-subscriber/use-cases/confirm-newsletter-subscription.ts` |
| `purchase-confirmation-email.tsx`     | `emails.purchase-confirmation-email`     | `modules/license/use-cases/send-purchase-confirmation-email.ts`              |

Better Auth calls the first three use cases from its hooks in `auth.server.ts`, which Resend joins through `RESEND_AUTH_EMAILS` in `src/data/resend.auth-emails.ts`. The newsletter notification goes to the site owner in English after a subscription is confirmed. The licence area's `order.paid` handler sends the purchase confirmation in the language stored on the order. Links inside emails are built with `localizePathname`, so they open in the email's locale.

The verification, password reset and newsletter confirmation use cases first call `withinRecipientRateLimit` from `src/lib/rate-limit.ts`: at most <RepositoryFact name="recipientEmailsPerHour" /> emails of each kind per address per hour, keyed on a SHA-256 hash of the address. Over the limit they skip the email without an error.

## Testing

Vitest mocks provider calls. In the Playwright test Worker, requests to the Resend API are captured instead of sent, and `/__test/emails?to=<address>` returns the captured emails.
