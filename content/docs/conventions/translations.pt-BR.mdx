O SaaSy Land é distribuído em <RepositoryFact name="languages" /> locales, <RepositoryFact name="supportedLocales" />, listados uma única vez em `I18N.SUPPORTED_LOCALES` em `src/integrations/use-intl/i18n.config.ts`. O inglês é a fonte da verdade. Uma alteração que adiciona ou edita um texto o adiciona ou edita em todos os locales no mesmo commit, e `bun run check:i18n` falha quando isso não acontece.

## Namespaces

As mensagens ficam em `messages/<locale>/<namespace>.json`, um arquivo por namespace, e o nome do arquivo é o namespace.

| Namespace                                                       | Contém                                                                                                             | Carregado                                          |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------- |
| `common`, `errors`, `errors.global`                             | Textos de que qualquer tela pode precisar, incluindo `errors.codes.<CODE>`                                         | Em todas as rotas                                  |
| `components.custom.<file>`, `components.shadcn.<file>`          | Os textos de um componente compartilhado, como `components.custom.newsletter-form`                                 | Em todas as rotas                                  |
| `fumadocs`                                                      | Os textos dos controles do próprio Fumadocs na documentação e no blog, que `useFumadocsI18n` passa para o Fumadocs | Pelos layouts da documentação e do blog            |
| `pages.<area>`, `pages.<area>.<page>`                           | Um layout ou uma página, com `metadata.title` e `metadata.description`                                             | Pela rota, por meio de `NAMESPACE` ou `NAMESPACES` |
| `navigation.<area>`, `dashboard.<area>`                         | Os rótulos dos itens de menu, da trilha de navegação e das estatísticas do painel de uma área                      | Na raiz, com todas as páginas                      |
| `<table>.validations`                                           | As mensagens do Zod de um módulo, como `course.validations`                                                        | Pelo layout cujos formulários as usam              |
| `auth.errors`, `auth.validations` e os outros arquivos `auth.*` | Erros do Better Auth, validação e telas de autenticação                                                            | Pelos layouts que precisam deles                   |
| `emails.<template>`                                             | Um template de e-mail                                                                                              | No servidor, pelo caso de uso que o envia          |
| `countries`, `currencies`, `locales`, `timezones`               | Catálogos                                                                                                          | Pelos layouts que precisam deles                   |

Os namespaces raiz são encontrados pelo nome do arquivo (`common.json`, `components.*.json`, `errors*.json`) em `src/integrations/use-intl/i18n.messages.ts`. Os textos de um componente compartilhado ficam no seu próprio namespace `components.custom.<file>`, nunca dentro de um namespace de página, para que ele renderize o mesmo texto onde quer que apareça. Todo namespace que uma rota declara precisa existir como arquivo em todos os locales; `loadNamespace` lança um erro para um que não existe.

## Um tradutor por componente

Um componente chama `useTranslations` uma vez, com o seu namespace, e dá ao resultado o nome `t`:

```tsx
const t = useTranslations("pages.admin.courses.form")
```

`scripts/check-i18n.ts` resolve todo `t("key")` estático nos arquivos `.tsx` de `src` contra o namespace da chamada a `useTranslations` acima dele e falha para uma chave que não existe em inglês. Ele também falha para uma chave em inglês que nenhum arquivo do código-fonte renderiza, para que textos removidos não fiquem esquecidos nos arquivos de mensagens. Uma chave conta como renderizada quando uma chamada `t()` nomeia ela ou uma chave acima dela, quando um template como `kinds.${kind}` a monta com cada placeholder preenchido por uma string que `src` ou o contrato da CLI `@saasyland/stack` declara, ou, abaixo de uma chamada `t()` que recebe uma variável, quando uma dessas strings, ou uma string de namespace seguida de uma delas, forma o resto do caminho. Por isso falha uma chave que um placeholder só alcançaria por uma palavra usada em outro lugar, como `filters.status` abaixo dos cabeçalhos de uma tabela. `navigation.website.test.ts` também verifica que os arquivos `navigation.<area>.json` rotulam exatamente os itens de menu e as abas de usuários que as áreas declaram. Os catálogos `countries`, `currencies`, `locales` e `timezones` ficam isentos, e `catalogues.test.ts` verifica, em vez disso, que as chaves deles são iguais às constantes. Uma constante cujos valores são exibidos aos usuários tem os rótulos verificados em todos os locales por `enum-labels.test.ts`, que lê cada uma dessas constantes com as mensagens que a rotulam das listas que as áreas declaram em `src/integrations/use-intl/__test__/<area>.labels.ts`. Uma segunda chamada a `useTranslations` no mesmo componente mudaria silenciosamente o escopo de todos os `t()` depois dela, e é por isso que só existe uma. Um componente que precisa de chaves de dois namespaces chama `useTranslations()` sem namespace e usa as chaves completas, como faz `sign-in-form.tsx` com `t("pages.auth.sign-in.form.resetPassword")`.

## Mensagens

- As chaves são objetos JSON aninhados com nomes em camelCase, agrupados da mesma forma que a tela: `table.headers.course`, `delete.confirm`.
- Plurais, números e datas usam a sintaxe ICU dentro da mensagem, nunca concatenação de strings no código: `"{e2eSpecs, plural, one {# Playwright suite} other {# Playwright suites}}"`.
- `scripts/check-message-formats.ts` exige em todos os locales os mesmos argumentos e tags ICU, e cada caminho de arquivo e cada comando `bun run`, `bunx`, `npx` ou `vp` da mensagem em inglês sem alterações. Ele rejeita texto em inglês deixado em outro locale, crases do Markdown, que as mensagens não renderizam, e uma [forma de tratamento](#one-form-of-address) que o locale não usa.
- Formate números, datas e moedas para o locale do leitor com `useFormatter` do use-intl, nunca à mão. As datas usam um formato nomeado de `I18N.FORMATS` (`date`, `time`, `calendarDate`), para que o fuso horário e a indicação do fuso fiquem consistentes. Um formato nomeado contém uma data ou um horário, nunca os dois: cada motor junta os dois de um jeito, e o Safari escreve “Jan 1, 2025 at 7:00 AM” onde o servidor escreve “Jan 1, 2025, 7:00 AM”, por isso uma data com horário é a mensagem `common.dateTime`, como em `t("common.dateTime", { value })`. Um tempo relativo conta a partir de quando os dados foram lidos, o `dataUpdatedAt` da sua query, como em `format.relativeTime(session.updatedAt, dataUpdatedAt)`, nunca a partir de `new Date()`, que o servidor e o navegador leem em momentos diferentes. `useCurrencyFormatter` formata um valor em uma moeda específica.
- As mensagens do Zod nos schemas de um módulo são chaves do seu namespace `<table>.validations` (`"slugInvalid"`), e os números que elas mencionam vêm de `<MODULE>_VALIDATION_PARAMS`. Veja [Formulários e tabelas](/docs/conventions/forms-and-tables).
- Um texto guardado no banco de dados que os visitantes leem em vários idiomas é uma coluna `LocalizedText`. O inglês é obrigatório e é o fallback que `localize(text, locale)` retorna quando falta uma tradução.

## Uma só forma de tratamento [#one-form-of-address]

Cada locale se dirige ao leitor de um só jeito, em cada mensagem, e-mail, página jurídica, página da documentação, post do blog e entrada do changelog: a forma que as ferramentas para desenvolvedores usam nesse idioma. `FORMS_OF_ADDRESS` em `src/lib/forms-of-address.ts` define a forma de cada locale e lista as formas que a contradizem, e `scripts/check-message-formats.ts` e `scripts/check-content.ts` falham quando uma tradução usa alguma delas fora do código, dos destinos dos links e das citações japonesas entre 「」.

- Uma palavra em **Nunca** falha onde quer que esteja, também com maiúscula no início de uma frase.
- Uma palavra em **Nunca dentro de uma frase** falha depois de uma palavra, um número ou uma vírgula na mesma linha. No início de uma frase, a mesma palavra costuma ser a terceira pessoa, como em `Sie laufen im Worker` (“eles rodam no Worker”), então a verificação a deixa ali para a revisão.
- Uma forma em **Nunca no fim de uma frase** falha antes de um ponto final japonês.
- Uma palavra em **Nunca no início de uma oração** falha no início de uma linha, de um título, de um item de lista ou de uma frase, depois de dois-pontos ou de ponto e vírgula e depois de uma das **Palavras que abrem uma oração** do locale. Uma oração que começa ali é uma oração principal, em que a forma só pode ser um imperativo, como em `Ejecute la suite` no lugar de `Ejecuta la suite`.

O alemão trata o leitor por du, em minúscula como o Duden recomenda, inclusive nas páginas jurídicas: a forma de tratamento não tem efeito jurídico. O polonês escreve Ty e Twój com maiúscula por cortesia. O japonês termina as frases em です・ます, enquanto títulos, itens de lista, células de tabela e slogans podem terminar em um substantivo ou em um verbo na forma simples, nunca na cópula simples. A verificação encontra os pronomes, as terminações e os imperativos sem ambiguidade; uma forma verbal que só o sentido da frase distingue fica para a revisão, como o espanhol `ejecute` em `espera a que arranque y ejecute la suite`, um subjuntivo quando o servidor executa a suíte e um imperativo formal quando quem a executa é o leitor.

## Números são medidos, não digitados

Uma contagem de algo no repositório, como arquivos de teste, suítes do Playwright, componentes de UI, países ou moedas, nunca é digitada no texto. `scripts/repository-facts.ts` as mede durante o build e as serve como o módulo `virtual:repository-facts`; `src/data/repository-facts.ts` as exporta como `REPOSITORY_FACTS`. O tamanho de um catálogo vem da sua constante (`COUNTRIES`, `CURRENCY_CODES`, `TIMEZONES`, `ADMIN_NAVIGATION`), nunca do arquivo de mensagens que o traduz. Os textos da landing page as interpolam, como em `t("body", REPOSITORY_FACTS)` com `"{testFiles, number} test files"` na mensagem, e o MDX renderiza uma delas com `<RepositoryFact name="testFiles" />`. Para mencionar um número novo, meça-o primeiro nesse plugin. Um número que o negócio define em vez de medir, como a comissão de afiliados, é declarado uma única vez em `src/data` (`AFFILIATE_TERMS` em `src/data/affiliates.ts`) e interpolado da mesma forma. Os preços seguem a mesma regra: `TIER_PRICES` e `CONSULTING_HOURLY_RATE` em `src/data/marketing.ts` chegam às mensagens como `{price}` e ao MDX como `<TierPrice tier="core" />`, e o endereço de contato chega às mensagens a partir de `CONTACT_EMAIL`, em `src/presentation/branding/index.ts`, como `{email}`. Os limites de dispositivos de `LICENSE_ACTIVATION_LIMITS` chegam à mensagem `machines` dos cards de planos como `{limit}` e ao MDX como `<ActivationLimit tier="core" />`. Componentes leem `REPOSITORY_FACTS` diretamente: a execução de testes da seção de qualidade imprime `Test Files` com `REPOSITORY_FACTS.testFiles`, o número de arquivos que os padrões `include` do Vitest encontram. Um número que só uma execução da suíte produz, como a contagem de testes individuais, não é exibido.

Caminhos de arquivo e comandos citados em um texto também são fatos do repositório, para que nenhum locale possa traduzi-los. `RecordSection`, na landing page, passa `{coverageSummaryPath}`, `{coverageCommand}`, `{ciWorkflowPath}`, `{e2eSpecsPath}`, `{messagesPath}`, `{i18nCheckCommand}` e `{authIntegrationPath}` a partir de `REPOSITORY_FACTS`: o diretório do resumo é `reportsDirectory` em `vite.config.ts`, o das specs é `testDir` em `playwright.config.ts`, e `repository-facts.test.ts` verifica que cada caminho existe e que cada comando é um script do `package.json`.

As páginas da documentação também não digitam os valores que o código define. `<RepositoryFact name="…" />` em `src/presentation/components/custom/repository-fact.tsx` mostra uma contagem medida, uma configuração que `repositoryFacts` lê de `vite.config.ts`, `playwright.config.ts`, `.nvmrc`, `package.json` ou de um workflow, ou uma constante importada do código, como `RATE_LIMITS` ou `PLAYBACK_TTL_SECONDS`. Ele formata um número para o locale da página, com `unit="second"`, `"minute"`, `"hour"`, `"day"` ou `"percent"` quando o valor tem uma unidade, e mostra um texto como código e uma lista como uma lista de código. `<RepositoryTable name="…" columns={["…", "…"]} />` mostra uma tabela montada a partir do código, como as declarações de permissão, os tipos de commit ou os multiplicadores de preço regionais, sob nomes de coluna que a página traduz. Os tempos de cache do roteador e o limite de e-mails por destinatário são declarados em `src/integrations/tanstack-query/query.cache.ts` e `src/modules/rate-limit/rate-limit.constants.ts`, e não em `src/router.tsx` e `src/lib/rate-limit.ts`, que roda só no servidor, módulos que a documentação não pode importar; o teste do componente compara os valores que ele mostra com o roteador e com o limitador. Já um valor que precisa ficar em um bloco de código ou no frontmatter é verificado por `scripts/check-content.ts`.

## Documentação e blog

Toda página em `content/docs`, todo post em `content/blog` e toda entrada do changelog em `content/changelog` existem como `<slug>.<locale>.mdx` em todos os locales, e a navegação de toda pasta como `meta.<locale>.json`. `scripts/check-content.ts`, executado por `bun run check:i18n`, falha quando:

- falta o arquivo de um locale;
- um bloco de código difere do bloco em inglês (os blocos de código são copiados byte a byte);
- um `meta.<locale>.json` lista slugs diferentes dos do inglês;
- um título, uma descrição ou um parágrafo ainda está em inglês;
- a tradução de um post do blog tem um `date` ou `updated` diferente do post em inglês;
- sobra no texto uma marca de tradução automática;
- uma tradução se dirige ao leitor de uma forma que o locale dela não usa (veja [Uma só forma de tratamento](#one-form-of-address));
- uma URL solta encosta sem espaço no texto seguinte, como acontece em japonês antes de um parêntese ou de um ponto de largura total, então o link dela levaria esse texto junto;
- um bloco de código com um caminho do repositório como título, como `title="src/integrations/better-auth/auth.access.ts"`, não é um trecho desse arquivo;
- uma página da documentação cita um host local ou um subdomínio de `APP_DOMAIN` que `appHostsForMode` não permite em nenhum modo de build;
- uma entrada do changelog não leva o número de um pull request nem o hash completo de um commit, ou a execução de CI de um pull request não encontra `content/changelog/<number>.en-US.mdx` com o número dele;
- a referência de rotas, a página de scripts ou uma tabela de variáveis de ambiente deixa de fora uma constante de `ROUTES`, um script do `package.json` ou um secret do `wrangler.jsonc`, ou dá a um deles o valor errado;
- um link interno termina em barra, `/index` ou `.html`, ou começa com um locale ou um alias de idioma como `/pl/`: o site redireciona esse caminho, e `localizeHref` adiciona o locale da página a todo link interno;
- uma tradução omite ou acrescenta código inline, um componente, uma prop de componente diferente de `title`, `description`, `excerpt` e `unreleased` ou um link para outra página, ou tem um número de linhas de tabela diferente do da página em inglês.

Escreva as traduções como um falante nativo escreveria, com a terminologia que o locale já usa em `messages/<locale>/` (o polonês, por exemplo, chama os planos de Podstawa, Komplet e Agencja e um desconto de rabat). Identificadores de código, caminhos de arquivo, comandos e nomes de produtos continuam como estão, e os links mantêm os seus caminhos `/docs/...` sem prefixo de locale, que o site adiciona ao renderizá-los. O polonês segue o [guia de estilo do polonês](/docs/conventions/polish-style), cujo glossário define cada termo polonês.
