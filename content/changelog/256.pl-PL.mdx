- Naprawiono: nowy worktree Gita dostaje swoje hooki commitów. `git worktree add` instaluje dyspozytor hooków nowego worktree przez hook `post-checkout`, więc commit utworzony przed `bun install` kończy się błędem w hooku `pre-commit`, zamiast go pominąć, a `bun install` kończy się błędem, gdy `core.hooksPath` ma inną wartość niż `.vite-hooks/_` albo gdy w dyspozytorze brakuje hooka. Do tej pory Git tworzył commity bez hooków, i to bez ostrzeżenia, w każdym worktree, który nie miał własnego dyspozytora. Zobacz [Git i pull requesty](/docs/conventions/git-workflow#hooks-in-every-worktree).
- Naprawiono: strona [Git i pull requesty](/docs/conventions/git-workflow#linear-history) nie każe już scalać `main` do gałęzi pull requesta i nigdy nie robić force-pusha. Opisuje liniową historię, której trzyma się projekt: żadnych commitów scalających, także na gałęzi pull requesta, gałęzie aktualizowane przez rebase na `main`, pull request, dla którego GitHub nie może zrobić rebase’u, wprowadzany ponownie jako jeden commit, i przepisane gałęzie wypychane poleceniem `git push --force-with-lease`. `AGENTS.md`, `CONTRIBUTING.md` i strona [Współtworzenie](/docs/project/contributing) mówią to samo.
