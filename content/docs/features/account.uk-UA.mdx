`src/modules/account` володіє таблицею `account` з Better Auth (`account.schema.ts`): один рядок на кожні облікові дані або провайдера OAuth, пов’язаного з користувачем. Токени OAuth у ній зашифровані.

## Сценарії використання

| Сценарій                           | Middleware             | Використовує                                                                  |
| ---------------------------------- | ---------------------- | ----------------------------------------------------------------------------- |
| `signUpWithPassword`               | з обмеженням           | `SignUpForm`                                                                  |
| `signOutUser`                      | з сесією               | `useSignOut`                                                                  |
| `changePassword`                   | з сесією, з обмеженням | `PasswordCard`                                                                |
| `setPassword`                      | з сесією, з обмеженням | `PasswordCard`                                                                |
| `changeEmail`                      | з сесією, з обмеженням | `ChangeEmailForm`                                                             |
| `listAccounts`                     | з сесією               | `PasswordCard`, `TwoFactorCard`, `ConnectedAccountsCard`, `DeleteAccountCard` |
| `unlinkAccount`                    | з сесією, з обмеженням | `ConnectedAccountsCard`                                                       |
| `updateUser`                       | з сесією               | жоден екран                                                                   |
| `sendChangeEmailConfirmationEmail` | хук Better Auth        | `user.changeEmail` в `auth.server.ts`                                         |

`sendChangeEmailConfirmationEmail` надсилає `ChangeEmailConfirmationEmail` на поточну адресу з посиланням для підтвердження від Better Auth. `changePassword` завжди відкликає інші сесії. `setPassword` додає пароль обліковому запису, що входить лише через GitHub або Google, за допомогою серверного `setPassword` з Better Auth, відкликає інші сесії й надсилає `PasswordChangedEmail`. `listAccounts` повертає для кожного способу входу ID рядка, провайдера й дату створення, без токенів, а `unlinkAccount` передає ID рядка в `unlinkAccount` з Better Auth, який відмовляється від’єднати останній.

## Видалення облікового запису

Видалення прибирає користувача, тому його сценарії розташовано в модулі користувача: `requestAccountDeletion` (з сесією, з обмеженням) просить `deleteUser` з Better Auth перевірити пароль і надіслати електронною поштою посилання для підтвердження, а `confirmAccountDeletion` (з сесією, з обмеженням як для токена) видаляє обліковий запис за токеном із посилання. `sendDeleteAccountEmail` (`src/modules/user/use-cases/send-delete-account-email.ts`) — це хук `sendDeleteAccountVerification`. Див. [Налаштування](/docs/features/settings#delete-account).

## Параметри

Часовий пояс, який користувач вибирає на екрані [Налаштування](/docs/features/settings), — це стовпець таблиці `user`, тому його сценарій використання розташовано в модулі користувача: `updatePreferences` (`src/modules/user/use-cases/update-preferences.ts`) вимагає користувача, який увійшов, перевіряє вхідні дані за допомогою `userZodSchemas.updatePreferences` і зберігає їх через `updateUser` з Better Auth — тим самим шляхом, що й оновлення профілю вище. `PreferencesCard` викликає його на `/app/settings` і `/admin/settings`. Мова — це локаль в URL, і вона не зберігається.

## Вихід

`useSignOut` (`src/hooks/use-sign-out.ts`) запускає `signOutUserMutation`, видаляє дані облікового запису з кешу запитів, переходить на `/auth/sign-in` і показує сповіщення. Віджет користувача в адмінпанелі та бічна панель `/app` мають власний `SignOutButton`, що його використовує.
