description: "ルート、サーバー関数、データ、シークレットに関わる変更をマージする前に確認すること。"
---

ページ、操作、エンドポイント、シークレットを追加するすべての変更について、このリストを確認してください。

## アクセス

- [ ] 非公開のページは、ガード付きのレイアウトの下にあります：`beforeLoad` で `requireAdmin`（`/admin`）または `requireSignedIn`（`/app`）。
- [ ] 保護されたすべてのサーバー関数に、`authorized(permission)` または `authorized()` があります。ルートガードは RPC 呼び出しを保護しません。
- [ ] 呼び出し元自身のデータに対する操作は、ユーザーを入力からではなく、`context.auth.user.id` から取得しています。
- [ ] 新しい権限は `APP_STATEMENTS` にあり、それを必要とするロールにだけ付与されています。
- [ ] テストで `UNAUTHORIZED` と `FORBIDDEN` をカバーしています。

## 入力

- [ ] すべてのサーバー関数に、モジュールの Zod スキーマでパースする `.validator` があります。
- [ ] API ハンドラーは、クエリとボディを使う前に検証しています。
- [ ] リダイレクト先は内部パスです。`auth.zod.ts` の `callbackPathSchema` は単一の `/` で始まるパスだけを受け付けます（`//` や `/\` は不可）。認証ページの `redirect` 検索パラメーター、サインアップ、メールアドレス変更がこれを使います。
- [ ] フォームのルールは Better Auth のエンドポイントでも守られています。パスワード、名前、メール、画像を受け付けるエンドポイントごとに、`auth.hooks.ts` の `INPUT_POLICY` にスキーマを追加します。

## 悪用への対策

- [ ] メールを送信する、コードを確認する、またはトークンを消費する公開操作は、`RATE_LIMITS.SENSITIVE` または `RATE_LIMITS.TOKEN` を指定した `withRateLimit` を使っています。
- [ ] アカウントなしで訪問者が送信させられるメール（確認、パスワードリセット、ニュースレターの確認）は、送信前に `withinRecipientRateLimit` を確認します。上限は種類ごと、アドレスごとに 1 時間あたり 3 通で、アドレスのハッシュで数えます。上限を超えた場合も通常どおり応答し、メールは送信しません。
- [ ] レートリミッターは、操作とクライアント IP（`cf-connecting-ip`）ごとのカウンターを D1 に保存し、ストレージが利用できない場合はリクエストを拒否します。Better Auth 自身のエンドポイントも同じストレージを使います。
- [ ] メールは、べき等性キー付きで送信されています。

## エラー

- [ ] 想定される失敗では、`ERROR_CODES` のコードを指定した `AppError` をスローしています。
- [ ] それ以外のものはクライアントに届きません。`withRequest` が未知のエラーをログに記録し、`INTERNAL_ERROR` に置き換えます。
- [ ] コンポーネントは、生の `error.message` ではなく、`useErrorMessage` を通してエラーを表示しています。

## シークレットとサーバー専用のコード

- [ ] シークレットは `cloudflare:workers` の `env` から、サーバーコード、つまりサーバー専用モジュール、サーバー関数のハンドラー、およびそれらだけがインポートするヘルパーでのみ読み取っています。クライアントアセットが `cloudflare:workers` をインポートしている場合、`scripts/verify-build.ts` がビルドを失敗させます。
- [ ] 非公開の値に `VITE_` プレフィックスが付いていません。付いているとブラウザに公開されてしまいます。
- [ ] クライアントに送るセッションデータは、セッショントークンを取り除く `getCurrentSession` から取得しています。

## セッションと Cookie

これらは `auth.server.ts` で設定されています。設定を変更する際も、維持してください。

- [ ] `requireEmailVerification: true` と `revokeSessionsOnPasswordReset: true`。
- [ ] ローカルモード以外での `useSecureCookies` と、環境のホストに限定された `baseURL.allowedHosts`。
- [ ] `encryptOAuthTokens: true` と `verification.storeIdentifier: "hashed"`。
- [ ] サインインとサインアウトでクエリキャッシュがクリアされ、ユーザーが変わったときにはガードがクリアします。

## Webhook と出力

- [ ] Webhook は、ペイロードを処理する前に署名を検証しています。Polar は `POLAR_WEBHOOK_SECRET` を使います。
- [ ] 非公開のページとトークンを消費するページは、プリレンダリングの対象外です。`/admin`、`/app`、`/auth`、`/courses`、`/newsletter`、`/api` は除外されています。
- [ ] トークン付きリンクはローダーではなく、明示的な操作があったときにだけ処理します。ニュースレターの確認ページと配信停止ページは、処理の前に確認を求めます。
- [ ] R2 バケットは非公開のままで、パブリックアクセスも `r2.dev` の URL もありません。動画ファイルは、署名済みの `/media/` パスを通じてのみブラウザーに届きます。
- [ ] レスポンスがセキュリティヘッダーを維持しています。`src/server.ts` は Worker のすべてのレスポンスに `SECURITY_HEADERS` と、HTTPS では `HTTPS_SECURITY_HEADERS` を設定し、`public/_headers` の `/*` ルールは、Worker を経由せずに配信されるファイルに同じヘッダーを付けます。ヘッダーを変更するときは、`src/modules/_core/constants/api.ts` とそのルールを一緒に変更してください。両者が異なると `server.test.ts` が失敗します。
