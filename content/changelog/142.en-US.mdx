- Fixed: the WebKit browser suite failed or flaked on `main` because specs acted on pages, or left them, before the app had rendered them. `waitForAppReady()` now returns once TanStack Router has rendered the current URL, which the new automatic `recordRenders` fixture records from the router's `onRendered` event, instead of once the router's data had hydrated, and specs call it after client-side navigations and before leaving a page. A form is no longer filled on the page being left, a scroll is no longer undone by the router's first render, and a page is no longer left while WebKit loads its imports, which made TanStack Router reload it. The new `waitForHydration(element)` waits until React has hydrated an element and everything in it: the slow-activation test moves the clock on only after the activation panel has hydrated, and `LandingPage.goto()` returns only after the landing page's `main` has, because a header link pressed earlier made React report a hydration mismatch. `auth-routing.spec.ts` opens each direct visit in its own tab. See [Testing](/docs/conventions/testing).
