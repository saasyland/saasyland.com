- API de licenças da CLI: o Worker serve o pacote de templates de cada versão, de que `saasyland init` precisa para gerar um projeto. `POST /api/cli/v1/activations/:activationId/bundles` verifica a licença e se a ativação pertence ao dispositivo que faz a chamada e, em seguida, responde com uma URL HTTPS para o arquivo compactado da versão no novo bucket R2 `BUNDLES` da área de licenças, o SHA-256 do conteúdo JSON do arquivo compactado (o digest que a CLI fixa para cada versão), o tamanho do arquivo compactado e quando a URL expira, `API_LIMIT.BUNDLE_URL_TTL_SECONDS` depois de emitida. Uma versão sem arquivo compactado responde `versionNotFound`, e um bucket que não pode ser lido, `serviceUnavailable`. O handler do Worker da área de licenças serve `/bundles/<expiry>.<signature>/<version>.json.gz` a partir do R2 assim que a expiração e um HMAC são validados, com uma chave que o HKDF deriva de `AUTH_SECRET` apenas para os pacotes, então nenhuma credencial S3 é necessária; a derivação de chave que a reprodução de vídeo usava foi para `src/lib/hmac.ts`, que as duas compartilham. A release do repositório da CLI envia cada arquivo compactado para o bucket de preview e para o de produção, e [Publicação dos pacotes](/docs/features/cli-licence-api#publishing-bundles) informa a chave, o tipo de conteúdo e os buckets. A política de privacidade diz que uma requisição de pacote envia a versão e as respostas da stack, que a API não guarda.
