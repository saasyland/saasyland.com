---
title: "Security checklist"
description: "What to verify before merging a change that touches routes, server functions, data or secrets."
---

Go through the list for every change that adds a page, an operation, an endpoint or a secret.

## Access

- [ ] Private pages sit under a guarded layout: `requireAdmin` (`/admin`) or `requireSignedIn` (`/app`) in `beforeLoad`.
- [ ] Every protected server function has `authorized(permission)` or `authorized()`. The route guard does not protect the RPC call.
- [ ] Operations on the caller's own data take the user from `context.auth.user.id`, never from the input.
- [ ] New permissions are in `APP_STATEMENTS` and granted only to the roles that need them.
- [ ] Tests cover `UNAUTHORIZED` and `FORBIDDEN`.

## Input

- [ ] Every server function has a `.validator` that parses the module's Zod schema.
- [ ] API handlers validate their query and body before using them.
- [ ] Redirect targets are internal paths: `callbackPathSchema` in `auth.zod.ts` accepts only paths that start with a single `/` (not `//` or `/\`). The auth pages' `redirect` search parameter, sign-up and email change use it.
- [ ] Rules the forms enforce also hold on Better Auth's own endpoints: add a schema to `INPUT_POLICY` in `auth.hooks.ts` for every endpoint that accepts a password, name, email or image.

## Abuse

- [ ] Public operations that send email, check a code or consume a token use `withRateLimit` with `RATE_LIMITS.SENSITIVE` or `RATE_LIMITS.TOKEN`.
- [ ] Emails a visitor can trigger without an account (verification, password reset, newsletter confirmation) check `withinRecipientRateLimit` before sending: at most three of a kind per address per hour, counted under a hash of the address. Over the limit the request gets its normal answer and nothing is sent.
- [ ] The rate limiter stores counters in D1 per operation and client IP (`cf-connecting-ip`) and rejects the request when its storage is unavailable. Better Auth's own endpoints use the same storage.
- [ ] Emails are sent with an idempotency key.

## Errors

- [ ] Expected failures throw `AppError` with an `ERROR_CODES` code.
- [ ] Nothing else reaches the client: `withRequest` logs unknown errors and replaces them with `INTERNAL_ERROR`.
- [ ] Components show errors through `useErrorMessage`, never raw `error.message`.

## Secrets and server-only code

- [ ] Secrets are read from `env` in `cloudflare:workers` only by server code: server-only modules, server function handlers and helpers that only they import. `scripts/verify-build.ts` fails the build when a client asset imports `cloudflare:workers`.
- [ ] No private value has a `VITE_` prefix, which would expose it to the browser.
- [ ] Session data sent to the client comes from `getCurrentSession`, which removes the session token.

## Sessions and cookies

These are set in `auth.server.ts`; keep them when you change the configuration:

- [ ] `requireEmailVerification: true` and `revokeSessionsOnPasswordReset: true`.
- [ ] `useSecureCookies` outside local modes and `baseURL.allowedHosts` limited to the environment's hosts.
- [ ] `encryptOAuthTokens: true` and `verification.storeIdentifier: "hashed"`.
- [ ] Sign-in and sign-out clear the query cache, and the guards clear it when the user changes.

## Webhooks and output

- [ ] Webhooks verify their signature before handling the payload; Polar uses `POLAR_WEBHOOK_SECRET`.
- [ ] Private and token-consuming pages stay out of prerendering: `/admin`, `/app`, `/auth`, `/newsletter` and `/api` are excluded.
- [ ] Token links act only on an explicit action, never in a loader: the newsletter confirmation and unsubscribe pages ask before they act.
- [ ] R2 buckets stay private, with no public access or `r2.dev` URL; video files reach the browser only through signed `/media/` paths.
- [ ] Responses keep the security headers: `src/server.ts` adds `SECURITY_HEADERS`, and `Strict-Transport-Security` over HTTPS, unless the response sets its own, and `public/_headers` covers the files served without the Worker. A route that sets one of these headers itself must not weaken it.
