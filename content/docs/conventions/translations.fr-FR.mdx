SaaSy Land est livré dans <RepositoryFact name="languages" /> locales : <RepositoryFact name="supportedLocales" />, listées une seule fois dans `I18N.SUPPORTED_LOCALES` de `src/integrations/use-intl/i18n.config.ts`. L'anglais fait foi. Une modification qui ajoute ou modifie du texte l'ajoute ou le modifie dans toutes les locales dans le même commit, et `bun run check:i18n` échoue dans le cas contraire.

## Espaces de noms

Les messages se trouvent dans `messages/<locale>/<namespace>.json`, un fichier par espace de noms, et le nom du fichier est l'espace de noms.

| Espace de noms                                                    | Contenu                                                                                                                 | Chargement                                       |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| `common`, `errors`, `errors.global`                               | Les textes dont tout écran peut avoir besoin, y compris `errors.codes.<CODE>`                                           | Pour chaque route                                |
| `components.custom.<file>`, `components.shadcn.<file>`            | Les textes d'un composant partagé, comme `components.custom.newsletter-form`                                            | Pour chaque route                                |
| `fumadocs`                                                        | Les textes des contrôles propres à Fumadocs dans la documentation et le blog, que `useFumadocsI18n` transmet à Fumadocs | Par les layouts de la documentation et du blog   |
| `pages.<area>`, `pages.<area>.<page>`                             | Un layout ou une page, avec `metadata.title` et `metadata.description`                                                  | Par la route, via `NAMESPACE` ou `NAMESPACES`    |
| `navigation.<area>`, `dashboard.<area>`                           | Les libellés des entrées de menu, du fil d'Ariane et des statistiques du tableau de bord d'une zone                     | À la racine, avec chaque page                    |
| `<table>.validations`                                             | Les messages Zod d'un module, comme `course.validations`                                                                | Par le layout dont les formulaires les utilisent |
| `auth.errors`, `auth.validations` et les autres fichiers `auth.*` | Les erreurs de Better Auth, la validation et les écrans d'authentification                                              | Par les layouts qui en ont besoin                |
| `emails.<template>`                                               | Un modèle d'e-mail                                                                                                      | Sur le serveur, par le cas d'usage qui l'envoie  |
| `countries`, `currencies`, `locales`, `timezones`                 | Des catalogues                                                                                                          | Par les layouts qui en ont besoin                |

Les espaces de noms racines sont repérés par nom de fichier (`common.json`, `components.*.json`, `errors*.json`) dans `src/integrations/use-intl/i18n.messages.ts`. Les textes d'un composant partagé se trouvent dans son propre espace de noms `components.custom.<file>`, jamais dans l'espace de noms d'une page : il affiche ainsi le même texte partout où il apparaît. Chaque espace de noms qu'une route déclare doit exister sous forme de fichier dans chaque locale ; `loadNamespace` lève une erreur pour un espace de noms qui n'existe pas.

## Un traducteur par composant

Un composant appelle `useTranslations` une seule fois, avec son espace de noms, et nomme le résultat `t` :

```tsx
const t = useTranslations("pages.admin.courses.form")
```

`scripts/check-i18n.ts` résout chaque `t("key")` statique des fichiers `.tsx` de `src` dans l'espace de noms de l'appel à `useTranslations` situé au-dessus, et échoue sur une clé qui n'existe pas en anglais. Il échoue aussi sur une clé anglaise qu'aucun fichier source n'affiche, afin que les textes supprimés ne s'attardent pas dans les fichiers de messages. Une clé compte comme affichée lorsqu'un appel `t()` la nomme, lorsqu'une clé construite par un littéral de gabarit, comme `kinds.${kind}`, lui correspond, ou, sous un appel `t()` qui reçoit une variable, lorsque son chemin apparaît sous forme de chaîne dans `src`. Les catalogues `countries`, `currencies`, `locales` et `timezones` en sont exemptés, et `catalogues.test.ts` vérifie à la place que leurs clés correspondent aux constantes. Une constante dont les valeurs sont montrées aux utilisateurs voit ses libellés vérifiés dans chaque locale par `enum-labels.test.ts`, qui lit chacune de ces constantes avec les messages qui fournissent ses libellés dans les listes que les zones déclarent dans `src/integrations/use-intl/__test__/<area>.labels.ts`. Un second appel à `useTranslations` dans le même composant changerait silencieusement la portée de chaque `t()` qui le suit : c'est pourquoi il n'y en a qu'un. Un composant qui a besoin de clés de deux espaces de noms appelle `useTranslations()` sans argument et utilise des clés complètes, comme le fait `sign-in-form.tsx` avec `t("errors.codes.INTERNAL_ERROR")`.

## Messages

- Les clés sont des objets JSON imbriqués aux noms en camelCase, regroupés comme l'est l'écran : `table.headers.course`, `delete.confirm`.
- Les pluriels, les nombres et les dates utilisent la syntaxe ICU dans le message, jamais une concaténation de chaînes dans le code : `"{e2eSpecs, plural, one {# Playwright suite} other {# Playwright suites}}"`.
- `scripts/check-message-formats.ts` exige dans chaque locale les mêmes arguments et balises ICU, ainsi que chaque chemin de fichier et chaque commande `bun run`, `bunx`, `npx` ou `vp` du message anglais à l’identique. Il rejette le texte anglais laissé dans une autre locale, les accents graves Markdown, que les messages n’affichent pas, et une [forme d’adresse](#one-form-of-address) que la locale n’utilise pas.
- Formatez les nombres, les dates et les devises pour la locale du lecteur avec `useFormatter` de use-intl, jamais à la main. Les dates utilisent un format nommé de `I18N.FORMATS` (`date`, `time`, `calendarDate`), afin que le fuseau horaire et son libellé restent cohérents. Un format nommé contient une date ou une heure, jamais les deux : chaque moteur les relie à sa façon, et Safari écrit « Jan 1, 2025 at 7:00 AM » là où le serveur écrit « Jan 1, 2025, 7:00 AM », donc une date avec son heure passe par le message `common.dateTime`, comme dans `t("common.dateTime", { value })`. Un temps relatif se compte à partir de la lecture de ses données, le `dataUpdatedAt` de sa requête, comme dans `format.relativeTime(session.updatedAt, dataUpdatedAt)`, jamais à partir de `new Date()`, que le serveur et le navigateur lisent à des moments différents. `useCurrencyFormatter` formate un montant dans une devise donnée.
- Les messages Zod des schémas d'un module sont des clés de son espace de noms `<table>.validations` (`"slugInvalid"`), et les nombres qu'ils mentionnent proviennent de `<MODULE>_VALIDATION_PARAMS`. Voir [Formulaires et tableaux](/docs/conventions/forms-and-tables).
- Le texte stocké dans la base de données que les visiteurs lisent en plusieurs langues est une colonne `LocalizedText`. L'anglais est obligatoire et sert de repli que `localize(text, locale)` renvoie pour une traduction manquante.

## Une seule forme d’adresse [#one-form-of-address]

Chaque locale s’adresse au lecteur d’une seule façon, dans chaque message, e-mail, page juridique, page de documentation, article de blog et entrée du changelog : la forme qu’emploient les outils de développement dans cette langue. `FORMS_OF_ADDRESS` dans `src/lib/forms-of-address.ts` nomme la forme de chaque locale et liste les formes qui la contredisent, et `scripts/check-message-formats.ts` et `scripts/check-content.ts` échouent lorsqu’une traduction en emploie une en dehors du code, des cibles de liens et des citations japonaises entre 「」.

- Un mot sous **Jamais** échoue où qu’il se trouve, y compris avec une majuscule en début de phrase.
- Un mot sous **Jamais dans une phrase** échoue après un mot, un nombre ou une virgule sur la même ligne. En début de phrase, le même mot est souvent une troisième personne, comme dans `Sie laufen im Worker` (« ils s’exécutent dans le Worker »), si bien que la vérification l’y laisse et s’en remet à la relecture.
- Une forme sous **Jamais en fin de phrase** échoue devant un point japonais.
- Un mot sous **Jamais en début de proposition** échoue en début de ligne, de titre, d’élément de liste ou de phrase, après un deux-points ou un point-virgule, et après l’un des **Mots qui ouvrent une proposition** de la locale. Une proposition qui commence là est une principale, où la forme ne peut être qu’un impératif, comme dans `Ejecute la suite` pour `Ejecuta la suite`.

L’allemand tutoie avec du, en minuscule comme le recommande le Duden, y compris dans les pages juridiques : la forme d’adresse n’a aucun effet juridique. Le polonais écrit Ty et Twój avec une majuscule par courtoisie. Le japonais termine ses phrases en です・ます, tandis que les titres, les éléments de liste, les cellules de tableau et les slogans peuvent se terminer par un nom ou un verbe à la forme simple, jamais par la copule simple. La vérification trouve les pronoms, les terminaisons et les impératifs sans ambiguïté ; une forme verbale que seul le sens de la phrase distingue relève de la relecture, comme l’espagnol `ejecute` dans `espera a que arranque y ejecute la suite`, un subjonctif quand le serveur lance la suite et un impératif de politesse quand c’est le lecteur qui la lance.

## Les nombres sont mesurés, pas saisis

Un décompte d'éléments du dépôt, comme les fichiers de test, les suites Playwright, les composants d'interface, les pays ou les devises, n'est jamais saisi à la main dans les textes. `scripts/repository-facts.ts` les mesure au moment du build et les sert sous la forme du module `virtual:repository-facts` ; `src/data/repository-facts.ts` les exporte sous le nom `REPOSITORY_FACTS`. La taille d'un catalogue provient de sa constante (`COUNTRIES`, `CURRENCY_CODES`, `TIMEZONES`, `ADMIN_NAVIGATION`), jamais du fichier de messages qui le traduit. Les textes de la page d'accueil les interpolent, comme dans `t("body", REPOSITORY_FACTS)` avec `"{testFiles, number} test files"` dans le message, et le MDX en affiche un avec `<RepositoryFact name="testFiles" />`. Pour mentionner un nouveau nombre, mesurez-le d'abord dans ce plugin. Un nombre que l'entreprise fixe au lieu de le mesurer, comme la commission d'affiliation, est déclaré une seule fois dans `src/data` (`AFFILIATE_TERMS` dans `src/data/affiliates.ts`) et interpolé de la même façon. Les prix suivent la même règle : `TIER_PRICES` et `CONSULTING_HOURLY_RATE` dans `src/data/marketing.ts` arrivent dans les messages comme `{price}` et dans le MDX comme `<TierPrice tier="core" />`, et l'adresse de contact arrive dans les messages depuis `CONTACT_EMAIL` comme `{email}`. Les limites d'appareils de `LICENSE_ACTIVATION_LIMITS` arrivent dans le message `machines` des cartes d'offres comme `{limit}` et dans le MDX comme `<ActivationLimit tier="core" />`. Les composants lisent `REPOSITORY_FACTS` directement : l'exécution des tests de la section qualité affiche `Test Files` avec `REPOSITORY_FACTS.testFiles`, le nombre de fichiers que reconnaissent les motifs `include` de Vitest. Un nombre que seule une exécution de la suite produit, comme le nombre de tests individuels, n'est pas affiché.

Les chemins de fichiers et les commandes que cite un texte sont eux aussi des faits du dépôt, afin qu’aucune locale ne puisse les traduire. `RecordSection`, sur la page d’accueil, passe `{coverageSummaryPath}`, `{coverageCommand}`, `{ciWorkflowPath}`, `{e2eSpecsPath}`, `{messagesPath}`, `{i18nCheckCommand}` et `{authIntegrationPath}` depuis `REPOSITORY_FACTS` : le répertoire du résumé est `reportsDirectory` dans `vite.config.ts`, celui des specs est `testDir` dans `playwright.config.ts`, et `repository-facts.test.ts` vérifie que chaque chemin existe et que chaque commande est un script de `package.json`.

Les pages de documentation ne saisissent pas non plus à la main les valeurs que le code définit. `<RepositoryFact name="…" />` dans `src/presentation/components/custom/repository-fact.tsx` affiche un décompte mesuré, un réglage que `repositoryFacts` lit dans `vite.config.ts`, `playwright.config.ts`, `.nvmrc`, `package.json` ou un workflow, ou une constante importée du code, comme `RATE_LIMITS` ou `PLAYBACK_TTL_SECONDS`. Il formate un nombre selon la locale de la page, avec `unit="second"`, `"minute"`, `"hour"`, `"day"` ou `"percent"` quand la valeur a une unité, et affiche un texte sous forme de code et une liste sous forme de liste de code. `<RepositoryTable name="…" columns={["…", "…"]} />` affiche un tableau construit à partir du code, comme les déclarations de permissions, les types de commit ou les multiplicateurs de prix régionaux, sous des noms de colonnes que la page traduit. Les durées de cache du routeur et la limite d'e-mails par destinataire sont déclarées dans `src/integrations/tanstack-query/query.cache.ts` et `src/modules/rate-limit/rate-limit.constants.ts`, et non dans `src/router.tsx` et `src/lib/rate-limit.ts`, réservé au serveur, que la documentation ne peut pas importer ; le test du composant compare les valeurs qu'il affiche avec le routeur et le limiteur. Une valeur qui doit rester dans un bloc de code ou dans le frontmatter est vérifiée à la place par `scripts/check-content.ts`.

## Documentation et blog

Chaque page sous `content/docs`, chaque article sous `content/blog` et chaque entrée du journal des modifications sous `content/changelog` existe sous la forme `<slug>.<locale>.mdx` dans toutes les locales, et la navigation de chaque dossier sous la forme `meta.<locale>.json`. `scripts/check-content.ts`, exécuté par `bun run check:i18n`, échoue lorsque :

- un fichier de locale manque ;
- un bloc de code diffère du bloc anglais (les blocs de code sont copiés octet pour octet) ;
- un `meta.<locale>.json` liste d'autres slugs que l'anglais ;
- un titre, une description ou un paragraphe est encore en anglais ;
- la traduction d’un article de blog a un `date` ou un `updated` différent de celui de l’article anglais ;
- un marqueur de traduction automatique reste dans le texte ;
- une traduction s’adresse au lecteur dans une forme que sa locale n’utilise pas (voir [Une seule forme d’adresse](#one-form-of-address)) ;
- une URL nue se colle sans espace au texte qui la suit, comme devant une parenthèse ou un point pleine chasse en japonais, si bien que son lien engloberait aussi ce texte ;
- un bloc de code dont le titre est un chemin du dépôt, comme `title="src/integrations/better-auth/auth.access.ts"`, n'est pas un extrait de ce fichier ;
- une page de documentation nomme un hôte local ou un sous-domaine de `APP_DOMAIN` que `appHostsForMode` n'autorise dans aucun mode de build ;
- une entrée du journal des modifications n'est nommée ni d'après un numéro de pull request ni d'après un hash de commit complet, ou l'exécution de CI d'une pull request ne trouve pas de `content/changelog/<number>.en-US.mdx` à son numéro ;
- la référence des routes, la page des scripts ou un tableau des variables d'environnement omet une constante `ROUTES`, un script de `package.json` ou un secret de `wrangler.jsonc`, ou lui donne une valeur erronée ;
- un lien interne se termine par une barre oblique, `/index` ou `.html`, ou commence par une locale ou un alias de langue comme `/pl/` : le site redirige un tel chemin, et `localizeHref` ajoute la locale de la page à chaque lien interne ;
- une traduction omet ou ajoute du code en ligne, un composant, une prop de composant autre que `title`, `description`, `excerpt` et `unreleased`, ou un lien vers une autre page, ou n’a pas le même nombre de lignes de tableau que la page anglaise.

Rédigez les traductions comme le ferait un locuteur natif, avec la terminologie que la locale utilise déjà dans `messages/<locale>/` (le polonais, par exemple, nomme les offres Podstawa, Komplet et Agencja et appelle une remise « rabat »). Les identifiants de code, les chemins de fichiers, les commandes et les noms de produits restent tels quels, et les liens conservent leurs chemins `/docs/...` sans préfixe de locale, que le site ajoute au moment du rendu.
