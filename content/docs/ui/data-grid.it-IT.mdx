`DataGrid` (`src/presentation/components/custom/data-grid.tsx`) è il componente tabella. Costruisce un’istanza di TanStack Table v9 dalle funzionalità di `src/integrations/tanstack-table/table.features.ts` e la mostra con le primitive tabella di shadcn e i controlli di React Aria. Una pagina gli passa le sue colonne e, in alternativa, le sue righe o una query; tutto il resto, dalla barra degli strumenti alla barra di paginazione, sta al suo interno.

```tsx
<DataGrid
  columns={columns}
  empty={t("empty")}
  id={ORDER_GRID_ID}
  label={t("title")}
  query={(request) => getOrdersPageQuery(orderZodSchemas.getOrders.parse(request))}
  search={t("filters.search")}
  selectable
/>
```

## Props

| Prop               | Scopo                                                                                                                                    |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `columns`          | L’insieme di colonne del `<entity>-columns.tsx` della pagina. Ogni riga ha bisogno di un `id` stringa, usato come ID della riga          |
| `id`               | Dà un nome alla griglia: la chiave del suo layout salvato nel browser e l’inizio del nome del suo file CSV                               |
| `label`            | Il nome accessibile della tabella, di solito il titolo della pagina                                                                      |
| `data`             | Righe in memoria, per una griglia che cerca, filtra, ordina e pagina sul client                                                          |
| `query`            | Modalità server: una funzione della richiesta della griglia che restituisce opzioni di query risolte in `{ rows, total }`                |
| `search`           | L’etichetta e il segnaposto della casella di ricerca; senza, la griglia non ha ricerca                                                   |
| `empty`            | Cosa dice la griglia finché non ha righe e non è impostata nessuna ricerca né filtro                                                     |
| `emptyDescription` | Una frase sotto quel titolo che dice come arriva la prima riga                                                                           |
| `selectable`       | Aggiunge una colonna di caselle di controllo e la barra di selezione                                                                     |
| `bulkActions`      | Una funzione delle righe selezionate che mostra altri pulsanti nella barra di selezione                                                  |
| `rowActions`       | Un componente che riceve ogni `row` e la chiude con il suo menu ⋯, in una colonna fissata a destra                                       |
| `onReorder`        | Aggiunge una maniglia a ogni riga; riceve la riga spostata e di quante posizioni si è spostata, come in [Ordine delle righe](#row-order) |

## Colonne

Un insieme di colonne è un hook in `custom/<feature>/<entity>-columns.tsx`, come `useOrderColumns`. Una colonna che aggiunge un’altra area è un elemento delle colonne dell’hook che indica la cella di quell’area, come la colonna **Dispositivi** della licenza in `useCustomerColumns`, e l’elenco delle colonne dello scheletro indica allo stesso modo la cella scheletro di quell’area, così escludere l’area le rimuove entrambe. L’hook legge le sue traduzioni e i dati che offrono i suoi filtri, e restituisce le colonne memoizzate, così ogni etichetta è una semplice stringa che la griglia può usare nei suoi menu, nei suoi annunci e nell’intestazione del CSV. Ogni cella è un piccolo componente nello stesso file che legge le proprie traduzioni.

```tsx
columnHelper.accessor("status", {
  cell: StatusCell,
  header: t("pages.admin.orders.table.headers.status"),
  meta: {
    export: ({ status }) => t(`pages.admin.orders.status.${status}`),
    filter: {
      kind: DATA_GRID_FILTER.MULTI_SELECT,
      options: ORDER_STATUSES.map((value) => ({ label: t(`pages.admin.orders.status.${value}`), value })),
    },
  },
  size: ORDER_COLUMN_SIZES.status,
})
```

`meta` è ciò che la griglia legge da una colonna:

| Chiave   | Effetto                                                                                                                                                 |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `filter` | Il filtro della colonna: il suo `kind` e, per una scelta, le `options` come `{ label, value }`                                                          |
| `hidden` | Nascosta finché l’amministratore non la mostra dal menu Colonne                                                                                         |
| `pinned` | Fissata a `start` o a `end` finché l’amministratore non la sblocca                                                                                      |
| `export` | Il testo che il CSV riceve per una riga. Senza, il CSV prende stringhe e numeri così come sono, le date come istanti ISO, e lascia vuoto tutto il resto |
| `align`  | `end` allinea a destra l’intestazione e le celle con cifre tabulari, per importi e conteggi                                                             |

`size` è la larghezza iniziale della colonna in pixel. Una colonna è ordinabile a meno che non imposti `enableSorting: false`; in modalità server dovrebbero essere ordinabili solo le colonne per cui lo schema Zod del modulo può ordinare.

## Filtri [#filters]

I tipi di filtro sono <RepositoryFact name="dataGridFilterKinds" />. Ognuno ha il proprio editor, che si apre dal pulsante Filtra della barra degli strumenti o dal chip del filtro:

| Tipo          | Editor                                                                                                             | Valore                                 |
| ------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------- |
| `text`        | Un campo di testo, applicato quando la digitazione si ferma per <RepositoryFact name="dataGridTypingDelayMs" /> ms | Il testo senza spazi iniziali e finali |
| `select`      | Un elenco di opzioni; scegliere di nuovo quella scelta la rimuove                                                  | Un `value`                             |
| `multiSelect` | Un elenco di opzioni, più d’una alla volta; un elenco lungo riceve un campo di ricerca                             | Un array di `value`                    |
| `numberRange` | Due campi numerici, almeno e al massimo, ciascuno può restare vuoto                                                | `{ min?, max? }`                       |
| `dateRange`   | Qualsiasi giorno su un calendario o un preset: <RepositoryFact name="dataGridDatePresets" />                       | `{ from?, to? }` in ms                 |

I giorni vengono trasformati in istanti nel fuso orario dell’amministratore, dall’inizio del primo giorno all’ultimo millisecondo dell’ultimo, così il server confronta semplici istanti. Ogni filtro attivo compare come un chip nella barra degli strumenti, accanto al pulsante Filtra, non appena viene impostato, così i chip e i risultati cambiano mentre il filtro resta aperto. Un chip riporta un breve riepilogo, come almeno 40, Pagato o Rimborsato, oppure 3 selezionate; la sua × lo rimuove e Rimuovi filtri li rimuove tutti. Cambiare la ricerca, un filtro o l’ordinamento torna alla prima pagina e svuota la selezione.

## Modalità server

Con `query`, la griglia pagina, ordina, cerca e filtra sul server. Chiama `query` con:

```ts
interface DataGridRequest {
  readonly filters: Readonly<Record<string, unknown>>
  readonly pageIndex: number
  readonly pageSize: number
  readonly search: string
  readonly sorting: SortingState
}
```

`filters` contiene l’id di ogni colonna filtrata con il suo valore. La route valida la richiesta con lo schema Zod del modulo prima che arrivi alla funzione server, come fa `/admin/orders` con `orderZodSchemas.getOrders.parse(request)`. Finché non arriva la prima pagina la griglia mostra righe scheletro; mentre si carica una pagina successiva mantiene attenuate le righe precedenti, segna la tabella come occupata e disattiva la paginazione. Gli errori della query arrivano all’error boundary della route.

## Layout

L’amministratore riorganizza la griglia e il browser la conserva sotto l’`id` della griglia in `localStorage` (`src/hooks/use-data-grid-preferences.ts`): quali colonne sono visibili, il loro ordine, quali sono fissate, le loro larghezze, la densità delle righe e la dimensione della pagina. Ricerca, filtri, ordinamento e selezione non vengono conservati. Ripristina layout rimette i valori predefiniti. Quando il browser rifiuta l’archiviazione, il layout resta solo per la durata della visita.

- **Menu Colonne.** Mostra e nasconde ogni colonna che si può nascondere.
- **Menu della colonna.** Il pulsante ⋮ di ogni intestazione ordina in modo crescente o decrescente, toglie l’ordinamento, fissa la colonna a sinistra o a destra, la sblocca, la sposta di un posto a sinistra o a destra all’interno del suo lato e la nasconde.
- **Trascinamento.** Un’intestazione trascinata su un’altra intestazione dello stesso lato ne prende il posto.
- **Ridimensionamento.** Il bordo di un’intestazione si trascina per ridimensionare; è anche un separatore che i tasti freccia allargano o restringono, e un doppio clic rimette la larghezza iniziale.
- **Ordinamento.** Premere un’intestazione ordina per quella colonna; con Maiusc aggiunge la colonna all’ordinamento, fino a <RepositoryFact name="dataGridMaxSortedColumns" /> colonne, numerate nell’intestazione.
- **Densità.** Righe ariose o compatte.
- **Dimensione della pagina.** <RepositoryFact name="dataGridPageSizes" /> righe per pagina. Una griglia parte da `defaultPageSize`, <RepositoryFact name="defaultPageSize" /> se non ne passa un altro, come gli utenti più recenti della dashboard, finché l’admin non sceglie una dimensione, che la griglia ricorda.

La griglia è un’unica scheda: la barra degli strumenti in alto, la tabella e la paginazione in basso, divise da linee sottili. La barra degli strumenti ha due righe: nella prima la ricerca e i controlli della vista, nella seconda, sotto, il pulsante Filtra e i chip dei filtri attivi. Ogni controllo della barra degli strumenti e ogni chip di filtro hanno la stessa altezza; le intestazioni hanno solo l’iniziale maiuscola, nella dimensione spec su una fascia attenuata, le celle nella dimensione body, e l’ultima colonna di dati occupa tutta la larghezza rimasta mentre la colonna delle azioni mantiene la propria. In ogni elenco della griglia, l’opzione sotto il puntatore è evidenziata come quella su cui si trova la tastiera. Il campo di ricerca occupa la larghezza libera della barra degli strumenti, così il testo segnaposto non viene mai tagliato. Un’intestazione resta su una sola riga e non va mai a capo a metà di una parola: la larghezza iniziale di ogni colonna contiene la sua intestazione, con le frecce di ordinamento e il menu della colonna, in ogni locale, e `e2e/specs/text-layout.spec.ts` fallisce quando l’etichetta di un’intestazione esce dalla sua cella in una qualsiasi griglia dell’amministrazione. In una griglia più stretta di 64rem, Colonne, Esporta CSV e Ripristina layout mostrano solo l'icona, così la ricerca conserva il suo spazio.

La riga di intestazione resta in vista mentre le righe scorrono dentro la griglia, e le colonne fissate restano in vista mentre la griglia scorre in orizzontale: è così che uno smartphone mostra una tabella larga. Un’ombra sul lato che ha altre colonne fuori vista, e sul bordo delle colonne fissate quando altre passano sotto di esse, mostra che la griglia scorre (`.grid-scroller` in `globals.css`).

La colonna delle azioni di riga è larga <RepositoryFact name="dataGridActionsSize" /> pixel e contiene un solo pulsante ⋯, `RowMenu` (`src/presentation/components/custom/row-menu.tsx`), che apre le azioni della riga come menu: prima quelle di uso quotidiano, poi, dopo un separatore, quelle distruttive, che chiedono conferma in una finestra di dialogo di avviso. Ogni griglia dell’amministrazione e ogni elenco riordinabile, come il programma, chiude le sue righe con questo pulsante, mai con una fila di icone. La colonna non ha menu della colonna: non si ordina, non si nasconde, non si sposta, non si ridimensiona e non compare nel CSV, e resta l’ultima a destra.

## Ordine delle righe [#row-order]

Con `onReorder`, la griglia inizia con una stretta colonna di maniglie, dopo le caselle di controllo quando la griglia le ha. Una maniglia è un’icona di presa attenuata:

- **Trascinamento.** Una riga trascinata dalla sua maniglia si fa strada tra le altre man mano che il puntatore ci passa sopra, e rilasciarla salva la sua nuova posizione. Esc, o un rilascio fuori dalle righe, la rimette al suo posto.
- **Tastiera.** Con il focus su una maniglia, le frecce su e giù spostano la riga di una posizione. Uno spostamento oltre la prima o l’ultima riga della pagina apre la pagina su cui passa la riga e porta lì il focus sulla sua maniglia.
- **Salvataggio.** `onReorder` riceve la riga e di quante posizioni si è spostata, in negativo verso l’alto, così il server la sposta dalla posizione che ha in quel momento nell’ordine salvato, anche attraverso le pagine, e una riga che un altro amministratore ha aggiunto o eliminato altrove nel frattempo non cambia dove arriva. Il nuovo ordine compare subito e resta mentre gli spostamenti vengono salvati, uno dopo l’altro, finché non arrivano le righe aggiornate; quando la promise restituita da `onReorder` viene rifiutata, le righe tornano indietro. `/admin/courses` passa `moveCourse` con uno `scope` di mutazione, così gli spostamenti vengono salvati nell’ordine in cui sono stati fatti.
- **Disattivazione.** Mentre le righe sono ordinate, filtrate o ristrette da una ricerca, la posizione di una riga sullo schermo non è la sua posizione nell’ordine salvato, quindi le maniglie sono disattivate.

Ogni spostamento viene annunciato nella live region, per esempio: «Riga spostata in posizione 3 di 12».

## Selezione ed esportazione

Con `selectable`, una casella di controllo seleziona una riga e quella dell’intestazione seleziona la pagina. Allora una barra fluttua in fondo alla finestra con il conteggio, Esporta selezione, le `bulkActions` della pagina e Annulla selezione. Ogni griglia dell’amministrazione che elenca dei record è selezionabile: corsi, prodotti di Polar, ordini, clienti, utenti, inviti, iscritti alla newsletter e gli ordini senza licenza; solo le tabelle di conteggi della dashboard e i numeri della newsletter non lo sono. `/admin/courses` aggiunge **Elimina** per i corsi selezionati; le altre griglie esportano la selezione, perché i loro record non hanno un’azione che si applichi a più di uno alla volta.

Esporta CSV scarica ogni riga che trovano la ricerca e i filtri, non solo la pagina sullo schermo: sul server chiede pagine da <RepositoryFact name="dataGridExportPageSize" /> righe finché non le ha tutte. Il file ha le colonne visibili nel loro ordine, comincia con un byte order mark perché i fogli di calcolo lo leggano come UTF-8 e mette un `'` davanti a ogni cella che inizierebbe una formula. `src/lib/csv.ts` lo scrive.

## Accessibilità

- La tabella porta `label` come nome e `aria-rowcount`; ogni riga il suo `aria-rowindex`, contato attraverso le pagine.
- Le intestazioni ordinabili sono pulsanti e portano `aria-sort`.
- Ogni controllo funziona da tastiera: i menu e gli elenchi seguono i tasti freccia e la ricerca durante la digitazione di React Aria, Esc li chiude, il ridimensionamento usa i tasti freccia sul separatore dell’intestazione, e una riga si sposta con le frecce su e giù sulla sua maniglia, il cui nome è «Trascina o usa le frecce per riordinare».
- Spostare una colonna o una riga, fissare, nascondere, ordinare da un menu e ripristinare il layout vengono annunciati in una live region cortese; anche il conteggio dei risultati e quello della selezione sono live.

## Traduzioni

I testi propri della griglia sono in `messages/<locale>/components.custom.data-grid.json`. Una pagina le passa solo le etichette delle colonne, le opzioni dei filtri, l’etichetta della ricerca e il messaggio vuoto.
