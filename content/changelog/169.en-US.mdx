- Code stays code in every language. The landing page's “Check every claim” list takes the files and commands it cites, such as `coverage/coverage-summary.json` and `bun run test:coverage`, from `REPOSITORY_FACTS` as ICU arguments, so the German, French, Italian, Japanese and Brazilian Portuguese pages no longer show translated paths or a command that does not exist; the summary's path comes from `vite.config.ts` and the specs directory from `playwright.config.ts`. `check-message-formats.ts` now fails when a translation changes a file path or a command of the English message or adds Markdown backticks, and `check-content.ts` when a translated page leaves out or adds inline code, a component, a component prop other than a title, or a link to another page, or has a different number of table rows. The new checks found the Polish and Brazilian Portuguese HTTP handlers pages without the CLI licence API row and a few changed code spans, all fixed. The German privacy policy names the newsletter's confirmation and unsubscribe tokens, as the other languages do, and the demo prices, saving and revenue on `/admin/pricing-models` are numbers in the store currency, `DEFAULT_CURRENCY_CODE`, formatted for the page's language, instead of amounts typed in dollars, euros, złoty or reais.
