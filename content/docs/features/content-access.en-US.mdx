---
title: "Content access"
description: "What controls access: route guards, permissions, the licence record and the access level of each course lesson."
---

Access is controlled by:

- **Route guards**: `/app` requires a session (`requireSignedIn`); `/admin` requires the `admin: ["access"]` permission (`requireAdmin`).
- **Server functions**: `authorized(permission)` checks the role permissions from `auth.access.ts`.
- **Licence**: the `license` table holds at most one licence per user with a `tier` (`core`, `complete`, `agency`) and a `status` (`active`, `revoked`), written by Polar webhooks. `/app` and `/app/license` read it through `currentLicenseQuery` to show either the tier cards or the licence key, and `startCheckout` refuses a new checkout while it is `active`.
- **Lessons**: each course lesson is `preview` (everyone), `account` (signed-in users) or `paid` (an `active` licence of tier `complete` or `agency`), and roles with `course: ["read"]` see every lesson. `getCourse` marks the lessons a viewer cannot watch as locked, and `getLessonPlayback` and `saveLessonProgress` refuse them, so the check does not depend on the page. See [Courses](/docs/features/courses).

The lessons are the only gated content. `/premium` (`src/routes/_landing.premium.tsx`) is a placeholder page that renders only its title from `pages.premium`.

To gate something else by purchase, read the licence on the server with `getLicense(userId)` from `src/modules/license/use-cases/get-license.ts` and check `status` and `tier`, as `resolveViewer` in `src/modules/lesson/lesson.viewer.ts` does.
