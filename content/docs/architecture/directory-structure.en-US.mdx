## Placement rules

- **Files and folders use kebab-case.** Tests live in a sibling `__test__` folder.
- **Routes only compose.** A route file defines the page or layout component, `NAMESPACE` or `NAMESPACES`, the loader and `head`. It does not hold widgets, dialogs or column definitions.
- **Modules are database tables.** Create `src/modules/<name>` only for a real table. A server function that does not work on a table goes in `src/lib` (for example `src/lib/github.ts`) or, if one route uses it, in that route file.
- **Shared components are flat.** A component used across areas is a single file directly in `presentation/components/custom`.
- **Area and page folders.** Components used by one area live in `admin/`, `app/`, `auth/`, `blog/`, `courses/`, `landing-page/` or `settings/`, which holds the account cards that `/app/settings` and `/admin/settings` share. Admin pages get their own folder, such as `admin/users/`. The landing page splits into `sections/` (one file per page section) and `components/` (pieces the sections share).
- **One widget, dialog, form or column set per file.** Do not split a component into a wrapper and a `-content` file.
- **No nested helper folders.** Component folders never contain `components/`, `constants/`, `hooks/`, `lib/` or `types/` subfolders, and no `.ts` helper file sits next to a component. A constant used by one component stays in that component's file.
- **Shared data goes in `src/data`.** Examples: `MARKETING_SECTION_IDS` and the CLI choices. Each area also declares its dashboard statistics there, in `<area>.dashboard.ts`, which the `*.entries.ts` barrels join (see [Paths and navigation](/docs/conventions/routes#paths-and-navigation)). The areas also declare there what they add to the platform: Worker handlers and Vite plugins (see [What the areas add](/docs/architecture/platform-layer#what-the-areas-add)).
- **Each area's paths go in `src/areas/<area>.shared.ts`.** Every runtime loads that file: the browser, the Worker, Bun scripts, Playwright and `vite.config.ts`. It therefore holds only constants and imports by relative path, and `src/routes.ts` joins the paths of every area (see [Paths and navigation](/docs/conventions/routes#paths-and-navigation)). Live site checks are a file kind of their own, `src/areas/<area>.live.ts`, because only deploy verification and the docs load them. What an area adds to the pages, such as its layout namespaces, its time zone and its root components, goes in its browser file, `src/areas/<area>.ts`, one `<AREA>_BROWSER` object that only the browser and the server rendering load. Menu entries are a pure kind of their own as well, `src/areas/<area>.navigation.ts`, joined by `src/areas/navigation.entries.ts` and read by `src/data/navigation.ts`, because the Remotion project reads the admin menu and its CI job installs only Remotion's own packages, so it cannot load an area's browser file, `src/areas/<area>.ts`, which imports router, query and server-function code. Its permission statements go in a file of their own, `src/areas/<area>.access.ts`, so that every change to them is reviewed by a person.
- **Generated files are not edited by hand.** The router plugin writes `src/routeTree.gen.ts`, `bun run cf-typegen` writes `src/types/worker-configuration.d.ts`, and `bun run content` and `bun run generate:cn` write `.source/`.
