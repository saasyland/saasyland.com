---
title: "API-Route hinzufügen"
description: "Einen HTTP-Handler unter /api für Webhooks und andere externe Aufrufer hinzufügen."
---

API-Routen sind Server-Handler von TanStack Start in `src/routes/api/`. Die eigenen Bildschirme der Anwendung benötigen nie eine, denn sie rufen Server-Funktionen auf. Eine API-Route nur für Aufrufer außerhalb der App hinzufügen, etwa Webhooks, Clients von Drittanbietern oder Crawler.

## Bestehende Routen

| Datei                        | Pfad                                         | Zweck                                                                                                  |
| ---------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `src/routes/api/auth.$.ts`   | `/api/auth/*`                                | Better Auth: Anmeldung, OAuth-Callbacks, E-Mail-Verifizierung, das Kundenportal von Polar und Webhooks |
| `src/routes/api/index.ts`    | `/api`                                       | Laufzeitprüfung, die `{ "runtime": "cloudflare-workers" }` zurückgibt                                  |
| `src/routes/api/cli.v1.*.ts` | <RepositoryFact name="cliApiBasePath" />`/*` | Die [CLI-Lizenz-API](/docs/features/cli-licence-api), die die CLI `saasyland` aufruft                  |

Das Polar-Plugin fügt keinen Checkout-Endpunkt hinzu; Checkouts starten in den Server-Funktionen `startCheckout` des Bestell- und des Lizenzmoduls, die sie beide mit `createCheckout` anlegen. Polar-Webhooks kommen unter `/api/auth/polar/webhooks` an; das Polar-Plugin von Better Auth prüft ihre Signatur mit `POLAR_WEBHOOK_SECRET`, bevor `handlePolarEvent` (`src/integrations/polar/polar.webhooks.ts`) jedes Ereignis an die in `POLAR_EVENT_HANDLERS` aufgeführten Handler für Bestellungen, Abonnements und Lizenzen weitergibt.

## Handler schreiben

Die Methoden in `server.handlers` deklarieren. Jeder Handler erhält den Web-`Request` und gibt eine Web-`Response` zurück:

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: {
    handlers: {
      GET: ({ request }) => auth.handler(request),
      POST: ({ request }) => auth.handler(request),
    },
  },
})
```

Innerhalb eines Handlers:

- Query-Parameter oder Body mit einem Zod-Schema validieren und bei einem Fehlschlag `HTTP_STATUS.BAD_REQUEST` (aus `src/modules/_core/constants/api.ts`) zurückgeben. Dort einen Status ergänzen, wenn der Handler einen neuen benötigt.
- Die Session mit `getRequestSession(request)` lesen und mit `hasPermission` prüfen. Funktions-Middleware wie `authorized` gilt für Server-Funktionen, nicht für Handler.
- Öffentliche Endpunkte mit `withinRateLimit({ key, limit, windowSeconds })` aus `src/lib/rate-limit.ts` und `clientAddress(request.headers)` aus `src/integrations/better-auth/auth.middleware.ts` begrenzen.
- Signaturen prüfen, bevor einem Webhook-Payload vertraut wird.
- Sichere Fehler-Bodys zurückgeben; Details mit `console.error` protokollieren.

## Routing-Regeln

- `/api`-Pfade erhalten nie ein Locale-Präfix, und der Worker überspringt für sie die Suche nach statischen Assets und die Locale-Weiterleitungen.
- `/api`-URLs enthalten keine Locale, daher liefert `getCurrentLocale()` dort die Standard-Locale. Eine lokalisierte Antwort entnimmt die Locale dem Request, etwa einem Query-Parameter `locale`.
- `/api` ist vom Prerendering ausgeschlossen.
