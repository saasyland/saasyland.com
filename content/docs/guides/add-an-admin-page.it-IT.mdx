---
title: "Aggiungere una pagina di amministrazione"
description: "Registra la route, la voce della barra laterale, i messaggi e i widget di una nuova pagina di amministrazione."
---

Le pagine di amministrazione sono file di route piatti sotto il layout `/admin` (`src/routes/admin.tsx`), che esegue `requireAdmin` in `beforeLoad` e mostra la barra laterale, le breadcrumb e la palette dei comandi. I passaggi seguenti aggiungono una pagina in `/admin/reports`; `src/routes/admin.orders.index.tsx` è un esempio reale completo.

## 1. Aggiungi il percorso

Aggiungi il percorso a `ROUTES.ADMIN` in `src/routes.ts`, al suo posto in ordine alfabetico:

```ts
REPORTS: `${ADMIN}/reports`,
```

Quando la pagina appartiene a una funzionalità che un progetto può escludere, aggiungi anche il nome ai `names` di quella funzionalità in `scripts/features.ts`, così che `bun run check:features` rimuova il percorso e ogni voce che lo nomina insieme alla funzionalità.

## 2. Crea il file della route

Crea `src/routes/admin.reports.tsx`. La route definisce solo il componente della pagina, `NAMESPACE`, il loader, `head` e `pendingComponent`; il generatore del router registra il file in `src/routeTree.gen.ts`.

```tsx
import type { JSX } from "react"

import { createFileRoute } from "@tanstack/react-router"
import { useTranslations } from "use-intl/react"

import { loadPageMetadata, preloadNamespaces } from "~/src/integrations/use-intl/i18n.messages"
import { getCurrentLocale } from "~/src/integrations/use-intl/i18n.utils"

import { pageHead } from "~/src/lib/seo"

import { AdminPageHeader } from "~/src/presentation/components/custom/admin/admin-page-header"
import { AdminReportsPending } from "~/src/presentation/components/custom/admin/reports-pending"
import { ReportStats } from "~/src/presentation/components/custom/admin/reports/report-stats"

import { ROUTES } from "~/src/routes"

const ReportsPage = (): JSX.Element => {
  const t = useTranslations("pages.admin.reports")

  return (
    <div className="flex w-full flex-col space-y-8">
      <AdminPageHeader description={t("metadata.description")} title={t("metadata.title")} />

      <ReportStats />
    </div>
  )
}

const NAMESPACE = "pages.admin.reports"

export const Route = createFileRoute("/admin/reports")({
  component: ReportsPage,
  loader: async ({ context }) => {
    const locale = getCurrentLocale()
    const [metadata] = await Promise.all([
      loadPageMetadata({ locale, namespace: NAMESPACE }),
      preloadNamespaces({ locale, namespaces: [NAMESPACE], queryClient: context.queryClient }),
    ])
    return { locale, metadata }
  },
  head: pageHead(ROUTES.ADMIN.REPORTS),
  pendingComponent: AdminReportsPending,
  staticData: { namespaces: [NAMESPACE] },
})
```

Le query necessarie alla pagina vanno nello stesso `Promise.all`, ad esempio `context.queryClient.query({ ...getUsersQuery, staleTime: "static" })` in `src/routes/admin.users.all.tsx`. `pageHead` costruisce titolo, descrizione, URL canonico e link alle altre lingue a partire da `metadata` del loader. `AdminReportsPending` è lo scheletro proprio della pagina, mostrato solo quando una navigazione richiede più di <RepositoryFact name="navigationPendingMs" unit="millisecond" />. Scrivilo nel file degli scheletri della sua area, qui un nuovo `custom/admin/reports-pending.tsx`, usando `AdminPageHeaderPending` di `admin-page-header.tsx` per l'intestazione e i blocchi di `pending-blocks.tsx`, così che riproduca la struttura della pagina. Lo scheletro del layout di amministrazione lo legge dalla route, quindi viene mostrato anche quando qualcuno entra in `/admin/reports` da fuori dell'area di amministrazione.

Vedi [Scheletri di caricamento](/docs/architecture/delivery-layer#scheletri-di-caricamento).

## 3. Aggiungi la voce della barra laterale

Aggiungi una voce agli `items` del suo gruppo della barra laterale in `ADMIN_NAVIGATION` (`src/data/navigation.ts`), nel punto in cui deve comparire: ad esempio dopo Dashboard nel gruppo della panoramica. La voce indica la sua icona di `lucide-react`, la chiave completa della sua etichetta e il suo percorso:

```ts
{ icon: FileText, label: "navigation.reports.admin.reports", to: ROUTES.ADMIN.REPORTS },
```

Aggiungi l'etichetta come `admin.reports` a `messages/<locale>/navigation.reports.json`, in tutte le lingue. Un nuovo gruppo richiede anche un valore in `ADMIN_NAVIGATION_GROUP`, un posto tra i gruppi di `ADMIN_NAVIGATION` e `groups.<group>` in `pages.admin.sidebar`. La barra laterale, le breadcrumb e la palette dei comandi ⌘K leggono tutte `ADMIN_NAVIGATION` (`src/data/navigation.ts`), quindi la pagina compare in tutti e tre i punti. La landing page la conta tra le sezioni dell'admin, e il menu laterale dell'admin nel video `app-tour` della landing page la elenca dopo che il video è stato renderizzato di nuovo (vedi `remotion/README.md`). Un terzo segmento dell'URL, come `/admin/reports/create`, mostra una breadcrumb quando il `breadcrumbs` della voce indica un'etichetta per esso, come `breadcrumbs: { create: "navigation.reports.breadcrumbs.create" }`, e nessun terzo elemento quando non la indica.

## 4. Aggiungi i messaggi della pagina

Crea `messages/<locale>/pages.admin.reports.json` in tutte le lingue. `metadata` è obbligatorio perché il loader lo legge per l'intestazione del documento:

```json
{
  "metadata": {
    "title": "Reports",
    "description": "Revenue and usage reports."
  }
}
```

## 5. Aggiungi i widget

Metti ogni widget, finestra di dialogo, modulo e insieme di colonne di tabella in un file a sé in `src/presentation/components/custom/admin/reports/`, ad esempio `report-stats.tsx` o `report-columns.tsx`. I widget chiamano `useTranslations("pages.admin.reports")` e leggono i propri dati con `useSuspenseQuery`; la pagina non passa loro né etichette né dati. Le tabelle usano il `DataGrid`; vedi [Aggiungere una griglia dati](/docs/guides/add-a-data-table).

## 6. Proteggi e testa

- La guardia del layout controlla l'accesso alla pagina. Ogni funzione server chiamata dalla pagina richiede comunque `authorized(permission)`; vedi [Ruoli e permessi](/docs/guides/roles-and-permissions).
- `/admin` è escluso dal prerendering.
- Aggiungi i test delle route della funzionalità in `src/routes/__test__/admin-<feature>-routes.component.test.tsx` e `admin-<feature>-loaders.test.ts`, i test dei widget in `src/presentation/components/custom/admin/__test__/` e la pagina in `e2e/data/<feature>.pages.ts`, poi esegui `bun run check:i18n`, `bun run test:coverage` e `bun run check:features`.
