## Templates

Os templates ficam em `src/presentation/emails`. Cada arquivo contém apenas marcação e exporta a constante do seu namespace:

| Template                         | Namespace                                 | Enviado por                                                                                                   |
| -------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `VerifyEmail`                    | `emails.verify-email`                     | `sendVerifyEmail` (hook do Better Auth)                                                                       |
| `ResetPasswordEmail`             | `emails.reset-password-email`             | `sendResetPasswordEmail` (hook do Better Auth)                                                                |
| `ChangeEmailConfirmationEmail`   | `emails.change-email-confirmation-email`  | `sendChangeEmailConfirmationEmail` (hook do Better Auth)                                                      |
| `ExistingAccountEmail`           | `emails.existing-account-email`           | `sendExistingAccountEmail` (`onExistingUserSignUp` do Better Auth)                                            |
| `PasswordChangedEmail`           | `emails.password-changed-email`           | `sendPasswordChangedEmail` (`onPasswordReset` do Better Auth, o hook `password-change-notice`, `setPassword`) |
| `DeleteAccountEmail`             | `emails.delete-account-email`             | `sendDeleteAccountEmail` (`sendDeleteAccountVerification` do Better Auth)                                     |
| `InvitationEmail`                | `emails.invitation-email`                 | `sendInvitationEmail` (`createInvitation`, `resendInvitation`)                                                |
| `NewsletterConfirmationEmail`    | `emails.newsletter-confirmation-email`    | `subscribeToNewsletter`                                                                                       |
| `NewsletterNotificationEmail`    | `emails.newsletter-notification-email`    | `confirmNewsletterSubscription`, para `CONTACT_EMAIL`                                                         |
| `NewsletterIssueEmail`           | `emails.newsletter-issue-email`           | `sendNewsletterIssue`, por meio de `sendBatchEmails`, para os assinantes confirmados                          |
| `PurchaseConfirmationEmail`      | `emails.purchase-confirmation-email`      | `sendPurchaseConfirmationEmail` (`order.paid` da Polar)                                                       |
| `UnmatchedOrderAlertEmail`       | `emails.unmatched-order-alert-email`      | `sendUnmatchedOrderAlert` (`order.paid` da Polar), para `CONTACT_EMAIL`                                       |
| `WithdrawalAcknowledgementEmail` | `emails.withdrawal-acknowledgement-email` | `sendWithdrawalAcknowledgement` (`submitWithdrawal`)                                                          |
| `WithdrawalNotificationEmail`    | `emails.withdrawal-notification-email`    | `sendWithdrawalNotification` (`submitWithdrawal`), para `CONTACT_EMAIL`                                       |

Um template recebe `locale` e `messages` e traduz com `createTranslator` do use-intl:

```tsx
const t = createTranslator({ locale, messages: { emails: { "verify-email": messages } }, namespace: "emails.verify-email" })
```

Os e-mails de conta começam com `EmailBrandHeader`, o nome da aplicação, e colocam `EmailFallbackLink` abaixo do botão: o mesmo link em texto simples, para os clientes que ocultam botões. Os e-mails de verificação, de redefinição de senha, de troca de e-mail e de exclusão da conta informam por quanto tempo o link deles funciona, a partir de `EMAIL_LINK_LIFETIME_HOURS`, o valor com que o Better Auth está configurado.

## Envio

O caso de uso obtém o idioma e o `redirect` da URL de callback que o Better Auth repassa, verifica o limite por destinatário, carrega as mensagens, renderiza o template e o envia (`src/modules/verification/use-cases/send-verify-email.ts`):

```ts
if (!(await withinRecipientRateLimit({ kind: VERIFICATION_EMAIL_PURPOSE.VERIFY_EMAIL, recipient: user.email }))) {
  console.warn("[email] verification email not sent: the recipient reached the hourly limit")
  return
}
const callback = new URL(callbackURL, getRequest().url)
const locale = extractLocaleFromPath(callback.pathname) ?? I18N.DEFAULT_LOCALE
const verifyUrl = new URL(localizePathname({ locale, pathname: ROUTES.VERIFY_EMAIL }), getRequest().url)
verifyUrl.search = callback.search
verifyUrl.searchParams.set("token", token)

const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotency: { purpose: VERIFICATION_EMAIL_PURPOSE.VERIFY_EMAIL, token: crypto.randomUUID() },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```

`sendEmail` (`src/integrations/resend/resend.utils.ts`) envia pelo Resend a partir de `RESEND_EMAIL_FROM`, a menos que um `from` seja informado (a notificação ao proprietário, o alerta de pedido sem conta correspondente e a notificação de desistência usam `NOTIFICATIONS_EMAIL`), repassa a chave de idempotência e lança um erro em caso de falha. `sendBatchEmails` envia até <RepositoryFact name="newsletterBatchSize" /> e-mails, cada um com os próprios cabeçalhos, em uma única requisição sob uma única chave de idempotência, registra no log os que o Resend recusa e devolve os IDs dos demais; só as edições da newsletter a usam ([Newsletter](/docs/features/newsletter#sending)).

Os e-mails de conta usam o idioma da página em que o fluxo começou, lido do `callbackURL` no link do e-mail; em um cadastro repetido, ele vem do `callbackURL` da requisição de cadastro. Um fluxo que não informa nenhum callback, um login em uma conta não verificada ou uma redefinição de senha, obtém o idioma e o `redirect` da página que enviou a requisição (o `Referer` dela, quando está neste site). A confirmação da newsletter usa o idioma enviado com o formulário, e cada edição o idioma salvo com a inscrição, ou inglês quando a edição não tem uma versão completa nele; a notificação ao proprietário é sempre em `en-US`. A confirmação da compra usa o idioma que `createCheckout` guardou nos metadados do pedido, e inglês quando não há nenhum; ela confirma em um suporte duradouro o consentimento do comprador ao fornecimento imediato, veja [Licenças](/docs/features/licences#purchase-confirmation). O alerta de pedido sem conta correspondente, que avisa o site sobre um pedido de licença pago cujo cliente não corresponde a nenhuma conta, é enviado em `I18N.DEFAULT_LOCALE`, veja [Licenças](/docs/features/licences#orders-that-match-no-account). O aviso de recebimento de uma desistência usa o idioma da página em que a declaração foi enviada, e a notificação de desistência ao site é enviada em `I18N.DEFAULT_LOCALE`, veja [Licenças](/docs/features/licences#withdrawal-function). O e-mail de convite usa o idioma que o admin escolheu para ele, salvo no `locale` do convite.

`withinRecipientRateLimit` (`src/lib/rate-limit.ts`) permite no máximo <RepositoryFact name="recipientEmailsPerHour" /> e-mails de cada tipo (verificação, redefinição de senha, conta existente, exclusão da conta, confirmação da newsletter e aviso de recebimento de desistência) por endereço por hora, contados na tabela `rate_limit` sob um hash SHA-256 do endereço. Acima do limite, o e-mail é descartado e a requisição ainda recebe a resposta normal. A confirmação de troca de e-mail, o aviso de troca de senha, a notificação ao proprietário, as edições da newsletter, a confirmação da compra, o alerta de pedido sem conta correspondente e a notificação de desistência não têm limite; uma troca de senha exige um token de redefinição ou a senha atual, quem dispara a confirmação da compra e o alerta de pedido sem conta correspondente é o webhook da Polar, não um visitante, uma vez por pedido, uma edição chega a cada assinante confirmado uma única vez e só um admin a envia, e a notificação de desistência vai apenas para o site, no máximo <RepositoryFact name="sensitiveRateLimit" /> por cliente por minuto. O e-mail de convite conta para o mesmo limite, mas acima dele `sendInvitationEmail` falha com `TOO_MANY_REQUESTS` em vez de pular o e-mail.
