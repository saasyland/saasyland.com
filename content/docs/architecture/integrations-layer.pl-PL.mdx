## Co nie jest integracją

- Liczba gwiazdek na GitHubie to funkcja serwerowa w `src/lib/github.ts`, przechowywana w cache KV.
- Ograniczanie liczby żądań to `src/lib/rate-limit.ts`, oparty na tabeli `rate_limit`.
- Bindingi Cloudflare nie potrzebują adaptera. Kod serwerowy odczytuje je z `env` w `cloudflare:workers`.

## Logika biznesowa zostaje w modułach

Integracja konfiguruje dostawcę. Decyzje dotyczące danych aplikacji należą do modułu odpowiedzialnego za tabelę:

- Wtyczka Polara, którą obszar polar dodaje do Better Auth w `src/data/polar.auth-plugins.ts`, weryfikuje podpisy webhooków za pomocą `POLAR_WEBHOOK_SECRET` i przekazuje każde zdarzenie do `handlePolarEvent` w `src/data/polar-events.ts`. Ta funkcja przekazuje je każdemu obszarowi, który wymienia to zdarzenie w swoim `<area>.polar-events.ts`; `src/data/license.polar-events.ts` obszaru licencji wywołuje `licenseWebhookHandlers` w `src/modules/license/license.webhooks.ts`, które wywołują przypadki użycia licencji. Identyfikatory produktów pakietów licencji, `POLAR_PRODUCT_IDS`, również należą do obszaru licencji i znajdują się w `src/modules/license/license.utils.ts`.
- Hooki e-mailowe Better Auth wywołują bezpośrednio `sendVerifyEmail`, `sendExistingAccountEmail`, `sendResetPasswordEmail`, `sendPasswordChangedEmail`, `sendDeleteAccountEmail` i `sendChangeEmailConfirmationEmail` z modułów weryfikacji, kont i użytkowników.
- Przypadek użycia wysyła e-mail w języku, który przekazuje wywołujący (e-mail weryfikacyjny odczytuje go z adresu zwrotnego): ładuje przestrzeń nazw szablonu, renderuje szablon i wywołuje `sendEmail`:

```ts
const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotency: { purpose: VERIFICATION_EMAIL_PURPOSE.VERIFY_EMAIL, token: crypto.randomUUID() },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```
