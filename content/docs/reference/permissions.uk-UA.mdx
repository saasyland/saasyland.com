`src/integrations/better-auth/auth.access.ts` оголошує декларації дозволів в `APP_STATEMENTS`, надає їх ролям і будує з них контроль доступу Better Auth (див. [Ролі та дозволи](/docs/guides/roles-and-permissions)). Ті самі визначення використовують і сервер (`authorized`, guard-функції маршрутів), і клієнт Better Auth.

## Ролі

| Роль          | Код        | Дозволи                                                                                                          |
| ------------- | ---------- | ---------------------------------------------------------------------------------------------------------------- |
| Адміністратор | `admin`    | Усі декларації застосунку, наведені нижче, а також адміністративні декларації Better Auth для `user` і `session` |
| Клієнт        | `customer` | Немає. Клієнти можуть викликати серверні функції, які вимагають лише сесії.                                      |

Нові користувачі отримують роль `customer` (`DEFAULT_ROLE_CODE` в `auth.roles.ts`).

## Де перевіряються дозволи

Кожен сценарій використання з `src/modules/*/use-cases/` за викликом `authorized`, який він виконує; `authorized()` вимагає сесії й жодного дозволу:

<RepositoryTable name="permissionChecks" columns={["Middleware", "Сценарії використання"]} />

Серверні функції без `authorized` виконують `withRequest` або `withRateLimit` і не потребують сесії: <RepositoryFact name="publicUseCases" />. Поза сценаріями використання `requireAdmin` у layout-і `/admin` і перенаправлення після входу перевіряють `admin: ["access"]` через `hasPermission`, а `resolveViewer` (`lesson.viewer.ts`) дозволяє власникам `course: ["read"]` дивитися кожен урок і завантажувати його матеріали незалежно від рівня доступу уроку.

## Перевірка дозволу

Серверні функції використовують middleware, наприклад `authorized({ category: ["read"] })`. Інший код викликає `hasPermission`, як це роблять guard-функції маршрутів:

```ts
const isAdmin = (role: string | null | undefined): boolean => hasPermission({ permission: { admin: ["access"] }, role })

export const requireAdmin = async (context: ProtectedRouteContext) => {
  const result = await requireSignedIn(context)
  if (!isAdmin(result.session.user.role)) {
    throw redirect({ replace: true, to: ROUTES.APP.INDEX })
  }
  return result
}
```
