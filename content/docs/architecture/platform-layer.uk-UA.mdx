## Worker і прив'язки

`wrangler.jsonc` задає `src/server.ts` як точку входу Worker. Worker отримує чотири прив'язки:

| Прив'язка | Тип              | Для чого                                                           |
| --------- | ---------------- | ------------------------------------------------------------------ |
| `DB`      | База даних D1    | Усі таблиці, зокрема сесії та лічильники обмеження частоти запитів |
| `CACHE`   | Простір імен KV  | Кількість зірок на GitHub і регіональні знижки під час оплати      |
| `MEDIA`   | Бакет R2         | Відеофайли, які `serveMedia` віддає під `/media/`                  |
| `ASSETS`  | Статичні ресурси | Попередньо відрендерені сторінки та файли з `public`               |

Запити до `/assets/*`, `/fonts/*`, `/robots.txt` і `/llms.txt` обслуговуються зі статичних ресурсів без запуску Worker. Серверний код читає прив'язки, секрети та `waitUntil` з `cloudflare:workers`. `src/server.ts` додає заголовки безпеки до кожної відповіді, яку повертає; файли, що віддаються без Worker, отримують підмножину з `public/_headers` ([Безпека та посилення захисту](/docs/features/security)).

## Середовища

`wrangler.jsonc` визначає чотири середовища. `CLOUDFLARE_ENV` обирає одне з них для `vp dev` і `vp build`.

| Середовище    | Прив'язки                                | Хто використовує                                |
| ------------- | ---------------------------------------- | ----------------------------------------------- |
| `development` | Віддалені D1, KV і R2 середовища preview | `bun run dev`                                   |
| `preview`     | D1, KV і R2 середовища preview           | `bun run build:preview`, `deploy:preview`       |
| `production`  | D1, KV і R2 середовища production        | `bun run build:production`, `deploy:production` |
| `test`        | Локальні D1, KV і R2 у `.wrangler/test`  | `bun run build:test`, Playwright                |

Кожне середовище перелічує свої обов'язкові секрети в `secrets.required`. Значення беруться з відповідного файлу `.env.<environment>`; скрипти розгортання записують оголошені ключі в `.wrangler/secrets.<environment>.json` і передають цей файл у Wrangler через `--secrets-file`. Середовище `test` використовує `src/platform/testing/worker.ts` як точку входу та фіктивні значення з `.env.test`, що зберігаються в репозиторії. `AFFONSO_PROGRAM_ID` публічний, тому це звичайна змінна Worker у `vars`, а не секрет; її задає лише `test`.

## Типи

- `src/types/bindings.d.ts` оголошує `Cloudflare.Env`: прив'язки, усі секрети, які читає Worker, і необов'язкову змінну `AFFONSO_PROGRAM_ID`. Три секрети `CLOUDFLARE_*` не оголошено, бо їх читає лише drizzle-kit, з `process.env`.
- `src/types/worker-configuration.d.ts` генерує `bun run cf-typegen`.
- `src/types/router.d.ts` реєструє тип роутера та опцію маршруту `staticData.namespaces`.

## Тестова інфраструктура

`src/platform/testing` містить лише те, що не може належати окремій функціональності:

- `setup.ts`: матчери jest-dom, скидання прив'язок перед кожним тестом і заміна `createServerFn`, яка виконує серверні функції в тому самому процесі
- `mocks/cloudflare.ts`: D1 на SQLite у пам'яті, який застосовує збережені в репозиторії міграції, KV у пам'яті, бакет `MEDIA` у пам'яті та `waitUntil`, відкладені завдання якого тести можуть примусово виконати
- `mocks/cache.ts`: `createEdgeCache`, заглушка кешу Workers для тестів доставки медіафайлів
- `mocks/resend.ts` і `mocks/polar.ts`: строгі дублери API Resend і Polar, а також `mocks/providers.ts`, який спрямовує до них `fetch` у кожному тесті й у тестовому Worker для браузерних тестів
- `mocks/wrksz-themes.ts`: заміна бібліотеки тем
- `lib/`: RPC-міст для серверних функцій, допоміжні функції рендерингу, допоміжні функції для URL-адрес запитів, засоби виконання запитів, а також моделі Polar із підписаними вебхуками
- `worker.ts`: точка входу Worker для браузерних тестів, яка встановлює дублери провайдерів і відкриває доступ до доставлених листів

Як набори тестів це використовують, описано на сторінці [Тестування та CI](/docs/architecture/testing-architecture).
