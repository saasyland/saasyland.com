---

メールは 3 つの部分で構成されます。`src/presentation/emails/` にあるテンプレート、`messages/<locale>/emails.<name>.json` にあるメッセージの名前空間、そしてメッセージを読み込み、テンプレートをレンダリングして送信するユースケースです。すべてのテンプレートと、それを送信するユースケースは [Resend](/docs/integrations/resend) のページにまとめています。

## テンプレート

テンプレートはマークアップだけを含み、自分の名前空間をエクスポートします。React のコンテキストの外でレンダリングされるため、`use-intl` の `createTranslator` で翻訳します。どのテンプレートも `src/presentation/emails/email-layout.tsx` の `EmailLayout` の中でレンダリングされます。言語、プレビューテキスト、Tailwind、中央寄せのコンテナーは、ここで全テンプレート分を一度だけ設定します。`src/presentation/emails/verify-email.tsx`：

```tsx title="src/presentation/emails/verify-email.tsx"
import type { JSX } from "react"

import { Button, Heading, Section, Text } from "react-email"
import { createTranslator } from "use-intl"

import { EMAIL_LINK_LIFETIME_HOURS } from "~/src/integrations/better-auth/auth.constants"
import type { SupportedLocale } from "~/src/integrations/use-intl/i18n.config"

import type emailMessages from "~/messages/en-US/emails.verify-email.json"
import { APP_NAME } from "~/src/presentation/branding"
import { EmailBrandHeader } from "~/src/presentation/emails/email-brand-header"
import { EmailFallbackLink } from "~/src/presentation/emails/email-fallback-link"
import { EmailLayout } from "~/src/presentation/emails/email-layout"

export const VERIFY_EMAIL_NAMESPACE = "emails.verify-email"

interface VerifyEmailProps {
  readonly locale: SupportedLocale
  readonly messages: typeof emailMessages
  readonly name: string
  readonly verifyUrl: string
}

export const VerifyEmail = ({ messages, locale, name, verifyUrl }: Readonly<VerifyEmailProps>): JSX.Element => {
  const t = createTranslator({ locale, messages: { emails: { "verify-email": messages } }, namespace: "emails.verify-email" })

  return (
    <EmailLayout lang={locale} preview={t("preview", { appName: APP_NAME })}>
      <EmailBrandHeader />
      <Section>
        <Heading className="m-0 mb-4 text-2xl font-bold">{t("heading")}</Heading>
        <Text className="m-0 mb-6 text-base text-neutral-600">{t("body", { name })}</Text>
        <Button href={verifyUrl} className="box-border rounded-md bg-neutral-900 px-5 py-3 text-center text-base text-white no-underline">
          {t("button")}
        </Button>
        <Text className="mt-6 mb-0 text-base text-neutral-600">{t("expiry", { hours: EMAIL_LINK_LIFETIME_HOURS })}</Text>
        <EmailFallbackLink label={t("fallback")} url={verifyUrl} />
        <Text className="mt-6 text-sm text-neutral-500">{t("footer")}</Text>
      </Section>
    </EmailLayout>
  )
}
```

## メッセージ

すべてのロケールに `messages/<locale>/emails.<name>.json` を作成します。`subject` キーを含めてください。ユースケースは、これを本文とは別に翻訳します。

```json title="messages/en-US/emails.verify-email.json"
{
  "subject": "Verify your email address",
  "preview": "Verify your email for {appName}",
  "heading": "Verify your email",
  "body": "Hi {name}, thanks for signing up. Confirm your email address to finish setting up your account.",
  "button": "Verify email",
  "expiry": "The link works for {hours, plural, one {# hour} other {# hours}}.",
  "fallback": "If the button does not work, copy this link into your browser:",
  "footer": "If you did not create an account, you can safely ignore this email."
}
```

メールの名前空間がルートでプリロードされることはありません。送信するユースケースがサーバー上で読み込みます。

## 送信

ユースケースは受け取ったコールバック URL からロケールを取り出し、受信者ごとの上限を確認し、メッセージを読み込み、`localizePathname` で絶対リンクを組み立て、`sendEmail` を呼び出します。`src/modules/verification/use-cases/send-verify-email.ts`：

```ts title="src/modules/verification/use-cases/send-verify-email.ts"
export const sendVerifyEmail = async ({
  callbackURL,
  token,
  user,
}: {
  callbackURL: string
  token: string
  user: { email: string; name: string }
}): Promise<void> => {
  if (!(await withinRecipientRateLimit({ kind: EMAIL_PURPOSE.VERIFY_EMAIL, recipient: user.email }))) {
    console.warn("[email] verification email not sent: the recipient reached the hourly limit")
    return
  }

  const callback = new URL(callbackURL, getRequest().url)
  const locale = extractLocaleFromPath(callback.pathname) ?? I18N.DEFAULT_LOCALE
  const verifyUrl = new URL(localizePathname({ locale, pathname: ROUTES.VERIFY_EMAIL }), getRequest().url)
  verifyUrl.search = callback.search
  verifyUrl.searchParams.set("token", token)

  const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })

  await sendEmail({
    idempotency: { purpose: EMAIL_PURPOSE.VERIFY_EMAIL, token: crypto.randomUUID() },
    react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
    subject: createTranslator({ locale, messages })("subject"),
    to: user.email,
  })
}
```

`sendEmail`（`src/integrations/resend/resend.utils.ts`）は、`from` が指定されていなければ `RESEND_EMAIL_FROM` を送信元として Resend 経由で送信します。べき等性キーを渡すため、リトライしても二重に送信されることはありません。Resend がエラーを返した場合は例外をスローします。

確認メールは、既存アカウントのメールやパスワード変更のメールと同じく、送信ごとに `crypto.randomUUID()` で新しいキーを使います。Better Auth は確認トークンに秒単位のタイムスタンプで署名するため、同じ秒に行われた登録とログインは同じトークンになり、Resend は 2 通目を 1 通目の再試行として扱ってしまいます。

## 誰が何を送るか

- `src/integrations/better-auth/auth.server.ts` の Better Auth のフックが、`RESEND_AUTH_EMAILS`（`src/data/resend.auth-emails.ts`）を通じてユースケースを呼び出します。`emailVerification.sendVerificationEmail` と、未認証アカウントでの再度のサインアップには `sendVerifyEmail`、認証済みアカウントでの再度のサインアップには `sendExistingAccountEmail`、`emailAndPassword.sendResetPassword` には `sendResetPasswordEmail`、`emailAndPassword.onPasswordReset` には `sendPasswordChangedEmail`、`user.changeEmail` には `sendChangeEmailConfirmationEmail`、`user.deleteUser.sendDeleteAccountVerification` には `sendDeleteAccountEmail` を使います。
- Better Auth へのリクエストはロケールのプレフィックスなしで `/api/auth` に届くため、フックはフローの `callbackURL`（ローカライズされたページのパス）から、`src/integrations/use-intl/i18n.paths.ts` の `extractLocaleFromCallbackURL` または `extractLocaleFromPath` を使ってメールのロケールを決めます。フォールバックは英語です。
- ニュースレターのユースケースは、ニュースレターの確認メールと通知メールを自ら送信します。例えば `subscribeToNewsletter` です。
- ライセンスのエリアの Webhook ハンドラー `onOrderPaid` は、ライセンスを付与した後に `sendPurchaseConfirmationEmail` を呼び出します。このメールは、言語を注文の `metadata.locale` から、リンクを Webhook を受け取ったホストから、冪等性トークンを Polar の注文 ID から得ます。送信に失敗するとハンドラーも失敗し、Polar が再送します。
- 支払い済みのライセンスの注文がどのアカウントにも対応しない場合、`onOrderPaid` は何も付与せずに `sendUnmatchedOrderAlert` を呼び出し、サイトのオーナーに英語で知らせます。
- `submitWithdrawal` が呼び出す `recordWithdrawal` は、撤回の意思表示の受領確認を送信元のページの言語で送り、撤回の通知をサイトのオーナーに英語で送ります。送信に失敗してもログに記録するだけで、意思表示の受け付けは失敗しません。
- `createInvitation` と `resendInvitation` は、管理者が選んで招待に保存された言語で `sendInvitationEmail` を呼び出します。冪等性トークンはリンクのトークンなので、新しいリンクごとに新しいメールになります。受信者ごとの上限を超えると、メールを省略せずに `TOO_MANY_REQUESTS` で失敗します。
- `sendVerifyEmail`、`sendResetPasswordEmail`、`sendExistingAccountEmail`、`subscribeToNewsletter` は、送信前に `withinRecipientRateLimit`（`src/lib/rate-limit.ts`）を呼び出します。アドレスの SHA-256 ハッシュをキーとして、1 種類のメールにつきアドレスごとに 1 時間あたり最大 <RepositoryFact name="recipientEmailsPerHour" /> 通までです。上限を超えると警告をログに記録し、何も送信しません。アカウントなしで訪問者が送信をトリガーできるメールには、同じチェックを追加してください。

## メールを追加する

1. エクスポートした `<NAME>_NAMESPACE` とともに、テンプレートを `src/presentation/emails/<name>.tsx` に追加します。
2. すべてのロケールに `messages/<locale>/emails.<name>.json` を追加します。
3. エリアの `src/data/<area>.email-purposes.ts` に目的の名前を追加し（`src/data/email-purposes.entries.ts` がそれを `EMAIL_PURPOSE` にまとめます）、そのアクションを担うユースケースから、きっかけとなったトークンまたはレコード ID を `idempotency: { purpose, token }` に渡して送信します。
4. テンプレートは `src/presentation/emails/__test__/` でテストし、ユースケースは `sendEmail` をモックしてテストします。

Resend の認証情報は `RESEND_API_KEY` と `RESEND_EMAIL_FROM` です。テストが Resend に接続することはありません。
