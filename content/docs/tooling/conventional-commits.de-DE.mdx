---
title: "Conventional Commits"
description: "Format der Commit-Nachrichten und der Emoji-Hook."
---

Commit-Betreffzeilen folgen dem Muster `<type>(<scope>): <description>`. Der Scope ist optional, und `!` kennzeichnet eine inkompatible Änderung. Schreibe die Betreffzeile ohne Emoji:

```sh
git commit -m "fix(auth): keep the locale in verification links"
```

Der Hook `prepare-commit-msg` in `.vite-hooks/` führt `bun scripts/commit-msg.ts` aus, das die Betreffzeile validiert und das Emoji für ihren Typ voranstellt; aus dem obigen Commit wird so `🐛 fix(auth): keep the locale in verification links`.

<RepositoryTable name="commitTypes" columns={["Typ", "Emoji"]} />

Jeder andere Typ oder eine Betreffzeile ohne das konventionelle Format bricht den Commit mit der Liste der erlaubten Typen ab. Der Hook lässt Betreffzeilen unverändert, die bereits mit einem Emoji beginnen oder von Git erzeugt wurden (`Merge`, `Revert "`, `fixup!`, `squash!`), sowie Merge-, Squash- und Vorlagennachrichten.

Vor dem Nachrichten-Hook führt der Hook `pre-commit` den Befehl `bun run check:pre-commit` aus. Nach ihm führt der Hook `commit-msg` den Befehl `bun scripts/verify-commit-msg.ts` auf der Nachricht aus, die Git gleich aufzeichnen wird, und bricht einen Commit ab, der ein KI-Werkzeug als Urheber ausweist: einen `Co-Authored-By`-, `Signed-off-by`- oder anderen `-by:`-Trailer, der eines der Werkzeuge in `AI_TOOLS` nennt, oder eine Zeile, die mit "Generated with" beginnt. Er überspringt die Zeilen, die Git entfernt, also Kommentare und den Diff unterhalb der Scherenlinie von `git commit -v`, und nennt jede Zeile, die zu entfernen ist. Umgehe die Hooks nicht.
