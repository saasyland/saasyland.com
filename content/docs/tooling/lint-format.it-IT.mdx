---
title: "Lint e formattazione"
description: "oxlint e oxfmt tramite Vite+ e gli script di controllo."
---

Vite+ esegue oxfmt per la formattazione e oxlint per il linting, entrambi configurati nelle sezioni `fmt` e `lint` di `vite.config.ts`. `bun run check` è il controllo che esegue la CI:

```sh
bun run check
```

Esegue `generate:cn`, `check:i18n` e `vp check`, che verifica la formattazione, applica le regole di lint e controlla i tipi del progetto. Usa `bun run lint`, `bun run format` e `bun run format:check` per usare un solo strumento alla volta.

## Formattazione

- Niente punti e virgola, virgolette doppie, virgole finali, indentazione di due spazi, larghezza di riga di 140 caratteri e fine riga LF.
- Gli import sono ordinati in gruppi fissi: solo server, `cloudflare:workers`, React, pacchetti esterni, poi le aree di `~/src` (platform, providers, integrations, modules, routes, hooks, dati e tema, types, lib, branding, componenti shadcn, componenti custom, styles), infine gli import relativi.
- Le classi Tailwind vengono ordinate in `className` e all'interno delle chiamate a `cn`, `cva`, `clsx` e `tw`.

## Linting

- Le categorie `correctness`, `nursery`, `pedantic`, `perf`, `style` e `suspicious` sono errori.
- Le regole basate sui tipi e il controllo dei tipi sono abilitati (`typeAware` e `typeCheck`).
- Limiti degni di nota: 800 righe per file, 150 righe per funzione, 20 istruzioni per funzione, nessun numero magico diverso da `0` e identificatori di almeno due caratteri, tranne `_`, `m` e `t`.
- Alcuni override rilassano qualche regola per i test, il codice di presentazione e gli hook, i mock dei test e i file delle route.

Entrambi gli strumenti ignorano i file generati ed esterni: file di dichiarazione, `src/routeTree.gen.ts`, migrazioni, `.source`, `dist`, `coverage`, `e2e`, `remotion`, le cartelle degli agenti e l'output di Playwright. `scripts/` viene formattato e analizzato come `src/`.

Correggi la causa di un errore di lint. Non aggiungere commenti di disattivazione, `@ts-expect-error` o cast con `as` per soddisfare una regola.

## Correzioni

L'hook di pre-commit esegue `bun run check:pre-commit`; il suo passaggio `vp staged` esegue `vp check --fix` solo sui file in stage. `bun run check:fix` applica le correzioni all'intero repository e può riscrivere file che non hai toccato, quindi rivedi il suo diff prima del commit. Per correggere solo le tue modifiche, passa i loro percorsi a `vp` (la CLI globale di Vite+, oppure `bunx vp`):

```sh
vp fmt src/routes/admin.users.all.tsx
vp lint --fix src/routes/admin.users.all.tsx
```
