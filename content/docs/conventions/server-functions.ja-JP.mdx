ブラウザーから呼び出せる操作はすべて、`createServerFn` で作成した TanStack Start のサーバー関数です。サーバー関数は公開インターネット上のエンドポイントなので、認可とバリデーションを自ら行います。ルートのガードが決めるのは、訪問者に何を表示するかだけです。

## 形

`src/modules/course/use-cases/update-course.ts` の例です。

```ts
export const updateCourse = createServerFn({ method: "POST" })
  .middleware([authorized({ course: ["update"] })])
  .validator((input: Course["updateCourse"]) => courseZodSchemas.updateCourse.parse(input))
  .handler(async ({ data }) => {
    const { courseId, ...fields } = data
    const [row] = await db.update(course).set(fields).where(eq(course.id, courseId)).returning({ id: course.id }).catch(rethrowAsConflict)

    if (row === undefined) {
      throw new AppError(ERROR_CODES.NOT_FOUND)
    }

    return row
  })

export const updateCourseMutation = mutationOptions({
  mutationFn: (data: Course["updateCourse"]) => updateCourse({ data }),
  mutationKey: COURSE_MUTATION_KEYS.UPDATE,
})
```

チェーンは常に次の順序です。

1. 読み取りには `createServerFn({ method: "GET" })` を、書き込みを伴うものには `{ method: "POST" }` を使います。
2. `.middleware([...])` には、操作に必要なミドルウェアを指定します（後述）。
3. 関数が入力を受け取る場合は `.validator((input: Module["operation"]) => moduleZodSchemas.operation.parse(input))` を指定します。引数は[モジュールのインターフェース](/docs/conventions/modules)を通して型付けし、スキーマはフォームの検証に使うものと同じです。
4. `.handler(async ({ context, data }) => ...)`。

同じファイルが、呼び出し側が使うオプションもエクスポートします。`mutationOptions` で作る `<name>Mutation`、または `queryOptions` で作るクエリです（[データの取得とキャッシュ](/docs/conventions/data-fetching)を参照）。コンポーネント、ローダー、テストはこれらのオプションをインポートし、サーバー関数そのものはインポートしません。

## ミドルウェア

3 つとも `src/integrations/better-auth/auth.middleware.ts` で提供されています。

| ミドルウェア                                 | 用途                                                             | `context` に追加されるもの |
| -------------------------------------------- | ---------------------------------------------------------------- | -------------------------- |
| `withRequest`                                | `getCatalogue` や `getCourse` などの公開の読み取り               | `requestHeaders`           |
| `authorized()`                               | サインイン済みのユーザーが必要なもの                             | `requestHeaders` と `auth` |
| `authorized({ course: ["update"] })`         | 権限が必要なもの                                                 | `requestHeaders` と `auth` |
| `withRateLimit(kind, RATE_LIMITS.SENSITIVE)` | サインアップなど、メールを送信したり認証情報を変更したりする操作 | `requestHeaders`           |
| `withRateLimit(kind, RATE_LIMITS.TOKEN)`     | リンクに含まれるトークンを使う公開の操作                         | `requestHeaders`           |

サインイン済みユーザーの機密性の高い操作では、両方を組み合わせます。`change-password.ts` は `[withRateLimit("change-password", RATE_LIMITS.SENSITIVE), authorized()]` を使います。`kind` は操作をケバブケースで表した名前で、そのカウンターのキーになります。

`authorized` と `withRateLimit` は最初に `withRequest` を実行するため、すべてのサーバー関数で同じエラー処理が行われます。

## 権限

権限ステートメントは、`src/integrations/better-auth/auth.access.ts` の `APP_STATEMENTS` で一度だけ宣言します。

```ts
const APP_STATEMENTS = {
  admin: ["access"],
  category: ["create", "read", "update", "delete"],
  course: ["create", "read", "update", "delete"],
  order: ["read", "update", "refund"],
  product: ["create", "read", "update", "delete", "publish"],
  settings: ["manage"],
  video: ["read", "delete"],
} as const
```

- 新しいリソースはここにステートメントを追加し、管理者ロールは `ac.newRole({ ...APP_STATEMENTS, ...adminAc.statements })` を通してそれを受け取ります。
- サーバー関数はステートメントを `authorized` に渡します。その他のサーバーコードは、`lesson.viewer.ts` の `resolveViewer` がスタッフのアクセスに対して行っているように、`hasPermission({ permission, role })` をその場でチェックします。`canEditCourses()` のようなラッパーはありません。
- サーバー関数がチェックする権限は[権限マトリクス](/docs/reference/permissions)に記載されています。

## 所有権

呼び出し元自身のデータに対する操作は、ユーザーを入力からではなくセッションから読み取ります。`save-lesson-progress.ts` は `userId: context.auth.user.id` を書き込み、`get-current-license.ts` は `getLicense(context.auth.user.id)` を読み取ります。入力にユーザー ID を含む操作は管理者向けの操作であり、権限をチェックします。

## エラー

サーバーのコードは、`src/modules/_core/constants/errors.ts` の `ERROR_CODES` のコードを付けて `AppError` をスローします。

| コード                   | 発生する場面                                                   |
| ------------------------ | -------------------------------------------------------------- |
| `NOT_FOUND`              | 行が存在しない。何にも一致しなかった更新や削除を含む           |
| `CONFLICT`               | 一意制約に違反した                                             |
| `UNAUTHORIZED`           | セッションがない（`authorized` がスローする）                  |
| `FORBIDDEN`              | 権限またはアクセス権がない                                     |
| `VALIDATION`             | 入力がスキーマの検証に失敗した（`ZodError` から変換）          |
| `TOO_MANY_REQUESTS`      | レート制限に達した                                             |
| `LICENSE_ALREADY_ACTIVE` | すでに有効なライセンスを持つアカウントに対する `startCheckout` |
| `AUTH_API_ERROR`         | Better Auth が呼び出しを拒否した。エラーのメッセージキーを伴う |
| `INTERNAL_ERROR`         | それ以外すべて。原因はログに記録し、送信しない                 |

- 訪問者が理解する必要のある拒否には、`LICENSE_ALREADY_ACTIVE` のように、`ERROR_CODES` に専用のコードを用意し、すべてのロケールの `errors.codes` の下にメッセージを用意します。ブラウザーが受け取るのはコードだけです。
- 行がないことは、2 回目のクエリではなく結果から検出します（`const [row] = await ... .returning(...)` の後に `if (row === undefined)`）。
- 一意制約違反は、`create-course.ts` や `update-course.ts` と同じように、`src/integrations/drizzle-orm/drizzle.errors.ts` の関数を使う `.catch(rethrowAsConflict)` で `CONFLICT` に変換します。
- `withRequest` は `AppError` をそのコードだけを付けて再スローし、Better Auth と Zod のエラーを変換し、それ以外はすべてログに記録してから `INTERNAL_ERROR` を返します。そのため、スタックトレースや SQL がブラウザーに届くことはありません。
- ブラウザーでは、`src/hooks/use-error-message.ts` の `useErrorMessage()` があらゆるエラーを、翻訳された `errors.codes.<CODE>` または `auth.errors.<key>` のテキストに変換します。フォームはそれを `toast.error(errorMessage(error))` で表示します。
- ルートのローダーでは、`src/lib/not-found.ts` の関数を使う `.catch(rethrowAsNotFound)` が、`NOT_FOUND` をルーターの not-found ページに変換します。

## 戻り値

- 呼び出し側が使うものを返します。ミューテーションは操作した ID を返し（`returning({ id: course.id })`）、ページ分割された読み取りは `{ rows, total }` を返します。存在しない可能性のあるレコードは `{ license }` のようにオブジェクトで包み、クエリのデータが決して `undefined` にならないようにします。
- 複数のステートメントは `db.batch([...])` で 1 回のラウンドトリップにまとめて送ります。D1 はバッチを 1 つのトランザクションとして実行します。これにより、`moveCourse` はすべての位置を一度に番号付けし直し、`getCourses` はページとその合計件数を一緒に読み取ります。
- データの形がローカライズされる場合は、表示言語をサーバーで解決します。`getCourse` は、すでに `localize(text, locale)` を通したタイトルを返します。

## サーバー関数の置き場所

| サーバー関数                                 | 置き場所                                                           |
| -------------------------------------------- | ------------------------------------------------------------------ |
| テーブルを読み書きする                       | `src/modules/<table>/use-cases/<verb>-<noun>.ts`                   |
| 1 つのルートだけで使い、テーブルを所有しない | そのルートファイル（`src/routes/blog.index.tsx` など）             |
| 外部サービスやコンテンツを読み、共有される   | `src/lib/<topic>.ts`（`src/lib/github.ts` の `getStarCount` など） |
| サーバー専用で、ブラウザーから呼び出されない | `server-only` を指定したファイル内の通常の `async` 関数            |

コンポーネントは `db`、`cloudflare:workers` の `env`、プロバイダーのクライアントを決してインポートしません。サーバー関数は、クエリオプションとミューテーションオプションを通して呼び出します。
