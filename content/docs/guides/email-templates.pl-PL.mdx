E-mail składa się z trzech części: szablonu w `src/presentation/emails/`, przestrzeni nazw komunikatów w `messages/<locale>/emails.<name>.json` oraz przypadku użycia, który wczytuje komunikaty, renderuje szablon i go wysyła. Szablony: `verify-email`, `reset-password-email`, `change-email-confirmation-email`, `newsletter-confirmation-email` i `newsletter-notification-email`.

## Szablon

Szablon zawiera wyłącznie znaczniki i eksportuje swoją przestrzeń nazw. Tłumaczy przez `createTranslator` z `use-intl`, ponieważ renderuje się poza kontekstem Reacta. `src/presentation/emails/verify-email.tsx`:

```tsx
import type { JSX } from "react"

import { Body, Button, Container, Head, Heading, Html, Preview, Section, Tailwind, Text, pixelBasedPreset } from "react-email"
import { createTranslator } from "use-intl"

import type { SupportedLocale } from "~/src/integrations/use-intl/i18n.config"

import type emailMessages from "~/messages/en-US/emails.verify-email.json"

export const VERIFY_EMAIL_NAMESPACE = "emails.verify-email"

const TAILWIND_CONFIG = { presets: [pixelBasedPreset] }

interface VerifyEmailProps {
  readonly locale: SupportedLocale
  readonly messages: typeof emailMessages
  readonly name: string
  readonly verifyUrl: string
}

export const VerifyEmail = ({ messages, locale, name, verifyUrl }: Readonly<VerifyEmailProps>): JSX.Element => {
  const t = createTranslator({ locale, messages: { emails: { "verify-email": messages } }, namespace: "emails.verify-email" })

  return (
    <Html lang={locale}>
      <Tailwind config={TAILWIND_CONFIG}>
        <Head />
        <Body className="font-sans">
          <Preview>{t("preview")}</Preview>
          <Container className="mx-auto px-5 py-10">
            <Section>
              <Heading className="m-0 mb-4 text-2xl font-bold">{t("heading")}</Heading>
              <Text className="m-0 mb-6 text-base text-neutral-600">{t("body", { name })}</Text>
              <Button
                href={verifyUrl}
                className="box-border rounded-md bg-neutral-900 px-5 py-3 text-center text-base text-white no-underline"
              >
                {t("button")}
              </Button>
              <Text className="mt-6 text-sm text-neutral-500">{t("footer")}</Text>
            </Section>
          </Container>
        </Body>
      </Tailwind>
    </Html>
  )
}
```

## Komunikaty

Utwórz `messages/<locale>/emails.<name>.json` we wszystkich dziewięciu językach. Dodaj klucz `subject`; przypadek użycia tłumaczy go niezależnie od treści.

```json
{
  "subject": "Verify your email address",
  "preview": "Verify your email for SaaSy Land",
  "heading": "Verify your email",
  "body": "Hi {name}, thanks for signing up. Confirm your email address to finish setting up your account.",
  "button": "Verify email",
  "footer": "If you did not create an account, you can safely ignore this email."
}
```

Przestrzenie nazw e-maili nigdy nie są wczytywane przez trasy; wczytuje je na serwerze przypadek użycia, który wysyła wiadomość.

## Wysyłka

Przypadek użycia otrzymuje język, wczytuje komunikaty, buduje bezwzględne linki przez `localizePathname` i wywołuje `sendEmail`. `src/modules/verification/use-cases/send-verify-email.ts`:

```ts
export const sendVerifyEmail = async ({
  locale,
  token,
  user,
}: {
  locale: SupportedLocale
  token: string
  user: { email: string; name: string }
}): Promise<void> => {
  const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
  const verifyUrl = new URL(localizePathname({ locale, pathname: ROUTES.VERIFY_EMAIL }), getRequest().url)
  verifyUrl.searchParams.set("token", token)

  await sendEmail({
    idempotencyKey: `verify-email/${token}`,
    react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
    subject: createTranslator({ locale, messages })("subject"),
    to: user.email,
  })
}
```

`sendEmail` (`src/integrations/resend/resend.utils.ts`) wysyła przez Resend z adresu `RESEND_EMAIL_FROM`, chyba że podano `from`, przekazuje klucz idempotencji, dzięki czemu ponowienie nigdy nie wyśle wiadomości dwa razy, i rzuca błąd, gdy Resend go zwróci.

## Kto co wysyła

- Hooki Better Auth w `src/integrations/better-auth/auth.server.ts` wywołują przypadki użycia: `sendVerifyEmail` dla `emailVerification.sendVerificationEmail` i ponownych rejestracji niezweryfikowanych kont, `sendResetPasswordEmail` dla `emailAndPassword.sendResetPassword` oraz `sendChangeEmailConfirmationEmail` dla `user.changeEmail`.
- Żądania Better Auth trafiają na `/api/auth` bez prefiksu języka, więc hooki ustalają język e-maila na podstawie `callbackURL` przepływu, czyli zlokalizowanej ścieżki strony, za pomocą `extractLocaleFromCallbackURL` lub `extractLocaleFromPath` z `src/integrations/use-intl/i18n.paths.ts`. Językiem zapasowym jest angielski.
- Przypadki użycia newslettera same wysyłają e-maile z potwierdzeniem i powiadomieniem, np. `subscribeToNewsletter`.

## Dodaj e-mail

1. Dodaj szablon w `src/presentation/emails/<name>.tsx` z wyeksportowaną stałą `<NAME>_NAMESPACE`.
2. Dodaj `messages/<locale>/emails.<name>.json` we wszystkich dziewięciu językach.
3. Wysyłaj go z przypadku użycia, do którego należy dana akcja, z kluczem idempotencji wyprowadzonym z wywołującego tokenu lub rekordu.
4. Przetestuj szablon w `src/presentation/emails/__test__/`, a przypadek użycia z zamockowanym `sendEmail`.

Dane dostępowe Resend to `RESEND_API_KEY` i `RESEND_EMAIL_FROM`. Testy nigdy nie łączą się z Resend.
