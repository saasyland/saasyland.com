## レイアウト

`src/routes/app.tsx` は認証のエリアに属します。`requireSignedIn` でワークスペースを保護し、自分の名前空間を、ほかのエリアが追加する名前空間（`layoutNamespaces("/app")`。ライセンスのエリアは `pages.license` を追加します）とあわせてプリロードします。

```tsx
const NAMESPACES = ["auth.errors", "pages.app.sidebar", "timezones", ...layoutNamespaces("/app")] as const

export const Route = createFileRoute("/app")({
  beforeLoad: requireSignedIn,
  component: AppLayout,
  loader: ({ context }) => preloadNamespaces({ locale: getCurrentLocale(), namespaces: NAMESPACES, queryClient: context.queryClient }),
  pendingComponent: AppPending,
  staticData: { namespaces: NAMESPACES },
})
```

`AppLayout` は shadcn の `SidebarProvider` の中に、`src/presentation/components/custom/app` の `AppSidebar` と `AppHeader` を表示します。サイドバーは `src/data/navigation.ts` の `APP_NAVIGATION`（概要と設定は `auth.navigation.ts`、ライセンスは `license.navigation.ts` から、ラベルは `navigation.auth.json` と `navigation.license.json` から）でリンクを作り、`APP_RESOURCE_NAVIGATION`（ドキュメントは `content.navigation.ts` から）でリソース欄を作ってサポートの連絡先を続け、ルートコンテキスト（`getRouteApi("/app")`）からユーザーを読み取り、最後に `SignOutButton` を置きます。ヘッダーは現在のページとサイトへ戻るリンクを表示します。サインイン後、管理者は `/admin` に、それ以外のユーザーは `/app` に移動します。

コースのエリアはサイドバーに **コース** を追加し（`courses.navigation.ts`。ラベルは `navigation.courses.json`）、`courses.app-badges.ts` でそのバッジを追加します。バッジは `CourseProgressBadge`（`custom/courses/course-progress-badge.tsx`）で、公開済みのすべてのレッスンのうち顧客が完了したレッスンの数を `completedLessonsQuery`（`src/modules/lesson-progress/use-cases/get-completed-lessons.ts`）から示します。サイドバーは、エリアが項目のパスに追加したバッジ（`src/data/app-badges.ts` の `appBadge`）を、リンクの横の `SidebarMenuBadge` に描きます。

## ページ

| ルート          | 内容                                                                                                                                                                                                                                                                                                                    |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/app`          | 有効なライセンスがなければ `LicenseOffer`、あれば `LicenseStatusCard`（プラン、ステータス、ライセンスページへのリンク）と、最初のプロジェクトまでのステップである `GetStarted`。[CLI ガイド](/docs/cli)（`ROUTES.DOCS_CLI`）とメールサポートへのリンク。                                                                |
| `/app/license`  | 有効なライセンスがなければ `LicenseOffer`、あれば `LicenseCard`（コピーできるキーと CLI コマンド、カスタマーポータルへのリンク、上位の各プランへのアップグレードのリンク）と、Polar がキーを発行した後は `LicenseActivations`。返金済みまたは取り消されたライセンスには、キーを表示せずにその旨を示すカードが残ります。 |
| `/app/settings` | `PreferencesCard`: ワークスペース内のすべての日付に使うタイムゾーン。検索と **このブラウザから検出** を備えます。[設定](/docs/features/settings)を参照してください。                                                                                                                                                    |

`LicenseOffer`（`src/presentation/components/custom/app/license-offer.tsx`）は、ランディングページの `PricingTiers` を再利用してプランごとに `CheckoutButton` を置きます。`CheckoutButton` は押されるとすぐに Polar のチェックアウトをページの上に開き、カードの下には `CheckoutNotice` を表示します（[ライセンス](/docs/features/licences#consent-to-immediate-supply)を参照）。`LicenseOffer` は最後に、ほかのエリアが追加するセクション（`src/data/license-offer.ts` の `LICENSE_OFFER_SECTIONS`）を、それぞれのスケルトンとページが読み込むデータとともに表示します。コースのエリアは `CourseUnlocks`（`src/data/courses.license-offer.ts`）を追加します。`CourseUnlocks` は有料レッスンのある公開済みコースを、それぞれのロックされたレッスン数とともに示します。この数は `getCatalogue` が D1 から数えます。有料レッスンのあるコースが 1 つもない間、このブロックは表示されません。`tier` を選んでいる場合、カードは `ChosenTier` の下にある **パッケージを比較** の折りたたみ表示にまとめられます。返金されたライセンスはカードがそのまま残り、その横に購入案内が表示されます。

`src/routes/app.index.tsx` は認証のエリアに属し、ほかのエリアは `src/data/<area>.app-overview.ts` で概要ページに追加します。`src/data/app-overview.entries.ts` がそれらをまとめます。追加するのは、読み取る検索パラメーター（`appOverviewSearchSchema`（`src/data/app-overview.ts`）が検証します）と、セクションです。各セクションはスケルトンと、ページが読み込むデータを持ちます。ライセンスのエリアは `LicenseOverview`（有効化のパネル、選択されたプラン、`LicenseStatusCard`、またはプランの案内）と、`licenseSearchSchema`（`src/data/license.ts`）の 2 つのパラメーターを追加します。`/app/license` も同じスキーマで検証します。どちらのパラメーターも省略可能で、無効な値は無視されます。

| パラメーター | 値                  | 効果                                                                                                                                                                                                                                                                                                  |
| ------------ | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tier`       | `LICENSE_TIER` の値 | 有効なライセンスがなければ、購入案内の上に `ChosenTier` を表示します。プラン、その価格、**決済に進む** ボタンが含まれます。より下位のプランの有効なライセンスがあれば、`UpgradeOffer` で[アップグレード](/docs/features/licences#upgrades)の価格を表示します。                                        |
| `checkoutId` | Polar の UUID       | ライセンスが有効になるまで購入案内の代わりに `CheckoutActivation` を表示し、有効になるとお礼を表示します。`tier`（チェックアウトで購入したプラン）があるときはライセンスがそのプランになるまで待ち、ページは `UpgradeOffer` を表示しません。[ライセンス](/docs/features/licences)を参照してください。 |

概要ページのローダーは各セクションの読み込みを実行するので、ライセンスのエリアがそこで `currentLicenseQuery` とコースのカタログをプリロードします。`/app/license` はその両方に加えて、ライセンスにキーがあればそのキーとプランの `licenseActivationsQuery` もプリロードします。そのため、ポーリングで届いたキーやアップグレードでは、マシン数の上限をあらためて読み込みます。`/app/settings` は自身のページの名前空間だけを読み込み、レイアウトの `NAMESPACES` にはタイムゾーン名のための `timezones` が含まれます。購入、Webhook、ライセンスの状態は[ライセンス](/docs/features/licences)で説明しています。

## CLI の手順 [#cli-instructions]

`LicenseCard` は、`CLI_KEY_LINES` のコマンド <RepositoryFact name="cliLicenseCommands" /> をそれぞれの働きとコピーボタンとともに一覧表示し、CI がキーを <RepositoryFact name="cliLicenseKeyVariable" /> から読み取ることを示します。コマンドの情報源は `src/data/cli.ts` で、ランディングページの <RepositoryFact name="scaffoldTarget" /> もここで組み立てます。変数は、CLI 自身が読む名前である `@saasyland/stack/cli` の `CLI_VARIABLE` から来ます。`CLI_RELEASE_CHANNEL` は CLI を実行する npm のタグを表します。CLI と `@saasyland/stack` は同じバージョンでまとめてリリースされるため、このタグがインストール済みの `@saasyland/stack` の公開時のタグ（プレリリース `x.y.z-beta.n` なら `beta`、安定版なら npm のデフォルトのタグ）でなければ `cli.test.ts` が失敗します。そのため、`@saasyland/stack` を安定版に更新すると、`CLI_RELEASE_CHANNEL` がデフォルトのタグを指すまでテストが失敗し、ライセンスページ、ランディングページ、ドキュメント、[ジャーニースイート](/docs/tooling/playwright#journey-suite)はその値に従います。`@saasyland/stack/package.json` をインポートするとファイル全体が Worker とすべてのページのバンドルに入るため、定数にしています。

## スケルトン

`AppOverviewPending` と `AppSettingsPending`（`app/auth-pending.tsx`。認証のエリアが `src/data/auth.skeletons.ts` で宣言します）は、`app/pending-blocks.tsx` のページヘッダーを描画します。続けて概要ページは各エリアが追加したセクションのスケルトンと、ドキュメントとサポートの案内を、設定ページは `PreferencesCardPending` を描画します。ライセンスのセクションのスケルトンである `LicenseOverviewPending` と、`AppLicensePending`（`app/license-pending.tsx`。ライセンスのエリアが `AppLicensePending` を `src/data/license.skeletons.ts` で宣言します）は、ページが表示することになる状態をそのまま再現します。`licenseSearchSchema` で検索パラメーターを読み取り、クエリクライアントからキャッシュ済みのライセンスとカタログを読み取って、有効化のパネル、選択されたプランかアップグレード、有料レッスンのあるコースごとに 1 行を添えたプランのグリッド（プランが選ばれている場合は **パッケージを比較** の行）、ライセンスのカードのいずれかを描画します。ライセンスが有効になると最初のステップも描き、ライセンスのカードのスケルトンはライセンスのステータスに合わせます。

`/app` には請求履歴とコースの画面はありません。また、`/app/settings` にはまだプロフィール、メールアドレス、パスワードのフォームはありません。
