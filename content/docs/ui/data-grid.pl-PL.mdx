`DataGrid` (`src/presentation/components/custom/data-grid.tsx`) to komponent tabeli. Buduje instancję TanStack Table v9 z funkcji w `src/integrations/tanstack-table/table.features.ts` i renderuje ją komponentami tabeli shadcn oraz kontrolkami React Aria. Strona przekazuje mu swoje kolumny oraz albo swoje wiersze, albo zapytanie; cała reszta, od paska narzędzi po pasek paginacji, znajduje się w nim.

```tsx
<DataGrid
  columns={columns}
  empty={t("empty")}
  id={ORDER_GRID_ID}
  label={t("title")}
  query={(request) => getOrdersPageQuery(orderZodSchemas.getOrders.parse(request))}
  search={t("filters.search")}
  selectable
/>
```

## Propsy

| Prop               | Przeznaczenie                                                                                                                                                                     |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `columns`          | Zestaw kolumn z `<entity>-columns.tsx` strony. Każdy wiersz potrzebuje tekstowego `id`, używanego jako ID wiersza                                                                 |
| `id`               | Nazwa siatki: klucz jej zapisanego układu w przeglądarce i początek nazwy jej pliku CSV                                                                                           |
| `label`            | Nazwa dostępna tabeli, zwykle tytuł strony                                                                                                                                        |
| `data`             | Wiersze w pamięci, dla siatki, która wyszukuje, filtruje, sortuje i stronicuje po stronie klienta                                                                                 |
| `query`            | Tryb serwerowy: funkcja, która z żądania siatki tworzy opcje zapytania zwracającego `{ rows, total }`                                                                             |
| `search`           | Etykieta i tekst zastępczy pola wyszukiwania; bez nich siatka nie ma wyszukiwania                                                                                                 |
| `empty`            | Komunikat siatki, gdy nie ma wierszy, a wyszukiwanie i filtry nie są ustawione                                                                                                    |
| `emptyDescription` | Zdanie pod tym tytułem, które mówi, skąd weźmie się pierwszy wiersz                                                                                                               |
| `selectable`       | Dodaje kolumnę pól wyboru i pasek zaznaczenia                                                                                                                                     |
| `bulkActions`      | Funkcja, która dla zaznaczonych wierszy renderuje dodatkowe przyciski na pasku zaznaczenia                                                                                        |
| `rowActions`       | Komponent z menu ⋯ na końcu każdego wiersza, w kolumnie przypiętej do prawej; dostaje `row`                                                                                       |
| `onReorder`        | Dodaje uchwyt do każdego wiersza; siatka wywołuje tę funkcję z przeniesionym wierszem i liczbą miejsc, o którą go przesunięto, jak opisuje sekcja [Kolejność wierszy](#row-order) |

## Kolumny

Zestaw kolumn to hook w `custom/<feature>/<entity>-columns.tsx`, na przykład `useOrderColumns`. Kolumna, którą dodaje inny obszar, to jeden element kolumn hooka wskazujący komórkę tego obszaru, tak jak kolumna **Urządzenia** z obszaru licencji w `useCustomerColumns`, a lista kolumn szkieletu w ten sam sposób wskazuje komórkę szkieletu tego obszaru, więc pominięcie obszaru usuwa obie. Hook odczytuje swoje tłumaczenia i dane, które oferują jego filtry, i zwraca zmemoizowane kolumny, dzięki czemu każda etykieta jest zwykłym tekstem, którego siatka może użyć w swoich menu, komunikatach dla czytników ekranu i nagłówku CSV. Każda komórka to mały komponent w tym samym pliku, który sam odczytuje swoje tłumaczenia.

```tsx
columnHelper.accessor("status", {
  cell: StatusCell,
  header: t("pages.admin.orders.table.headers.status"),
  meta: {
    export: ({ status }) => t(`pages.admin.orders.status.${status}`),
    filter: {
      kind: DATA_GRID_FILTER.MULTI_SELECT,
      options: ORDER_STATUSES.map((value) => ({ label: t(`pages.admin.orders.status.${value}`), value })),
    },
  },
  size: ORDER_COLUMN_SIZES.status,
})
```

Z kolumny siatka odczytuje `meta`:

| Klucz    | Działanie                                                                                                                                           |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `filter` | Filtr kolumny: jego `kind`, a dla wyboru `options` w postaci `{ label, value }`                                                                     |
| `hidden` | Ukryta, dopóki administrator nie pokaże jej z menu Kolumny                                                                                          |
| `pinned` | Przypięta do `start` albo do `end`, dopóki administrator jej nie odepnie                                                                            |
| `export` | Tekst, który CSV dostaje dla wiersza. Bez niego CSV bierze teksty i liczby bez zmian, daty jako znaczniki czasu ISO, a wszystko inne zostawia puste |
| `align`  | `end` wyrównuje nagłówek i komórki do prawej i używa cyfr tabelarycznych; do kolumn z kwotami i liczbami                                            |

`size` to początkowa szerokość kolumny w pikselach. Kolumnę można sortować, chyba że ustawia `enableSorting: false`; w trybie serwerowym sortować powinny się tylko kolumny, po których może sortować schemat Zod modułu.

## Filtry [#filters]

Rodzaje filtrów to <RepositoryFact name="dataGridFilterKinds" />. Każdy ma własny edytor, otwierany przyciskiem Filtruj na pasku narzędzi albo z chipa filtra:

| Rodzaj        | Edytor                                                                                                 | Wartość                     |
| ------------- | ------------------------------------------------------------------------------------------------------ | --------------------------- |
| `text`        | Pole tekstowe; filtr działa, gdy pisanie ustanie na <RepositoryFact name="dataGridTypingDelayMs" /> ms | Tekst bez spacji na końcach |
| `select`      | Lista opcji; ponowne wybranie zaznaczonej opcji czyści filtr                                           | Jedna `value`               |
| `multiSelect` | Lista opcji, kilka naraz; długa lista dostaje pole wyszukiwania                                        | Tablica `value`             |
| `numberRange` | Dwa pola liczbowe, co najmniej i co najwyżej, każde może zostać puste                                  | `{ min?, max? }`            |
| `dateRange`   | Ostatnie 7 dni, ostatnie 30 dni, ostatnie 12 miesięcy albo dowolne dni w kalendarzu                    | `{ from?, to? }` w ms       |

Dni są zamieniane na znaczniki czasu w strefie czasowej administratora, od początku pierwszego dnia do ostatniej milisekundy ostatniego, więc serwer porównuje zwykłe znaczniki czasu. Każdy aktywny filtr pojawia się jako chip na pasku narzędzi, obok przycisku Filtruj, gdy tylko zostanie ustawiony, więc chipy i wyniki zmieniają się, a edytor filtra pozostaje otwarty. Chip pokazuje krótkie podsumowanie, na przykład co najmniej 40, Opłacone lub Zwrócone albo wybrano: 3; jego × go usuwa, a Wyczyść filtry usuwa wszystkie. Zmiana wyszukiwania, filtra lub sortowania przenosi na pierwszą stronę i czyści zaznaczenie.

## Tryb serwerowy

Z `query` siatka stronicuje, sortuje, wyszukuje i filtruje na serwerze. Wywołuje `query` z:

```ts
interface DataGridRequest {
  readonly filters: Readonly<Record<string, unknown>>
  readonly pageIndex: number
  readonly pageSize: number
  readonly search: string
  readonly sorting: SortingState
}
```

`filters` zawiera id każdej filtrowanej kolumny z jej wartością. Trasa sprawdza żądanie schematem Zod modułu, zanim dotrze ono do funkcji serwerowej, tak jak `/admin/orders` robi to przez `orderZodSchemas.getOrders.parse(request)`. Dopóki nie dotrze pierwsza strona, siatka pokazuje szkielety wierszy; gdy ładuje się kolejna strona, zostawia poprzednie wiersze przygaszone, oznacza tabelę jako zajętą i wyłącza przechodzenie między stronami. Błędy zapytania trafiają do error boundary trasy.

## Układ

Administrator zmienia układ siatki, a przeglądarka zapisuje go pod `id` siatki w `localStorage` (`src/hooks/use-data-grid-preferences.ts`): które kolumny są widoczne, ich kolejność, które są przypięte, ich szerokości, gęstość wierszy i rozmiar strony. Wyszukiwanie, filtry, sortowanie i zaznaczenie nie są zapisywane. Przywróć układ przywraca wartości domyślne. Gdy przeglądarka odmawia dostępu do pamięci, układ zostaje zachowany tylko do końca wizyty.

- **Menu Kolumny.** Pokazuje i ukrywa każdą kolumnę, którą można ukryć.
- **Menu kolumny.** Przycisk ⋮ każdego nagłówka sortuje rosnąco lub malejąco, czyści sortowanie, przypina kolumnę do lewej lub prawej, odpina ją, przesuwa ją o jedno miejsce w lewo lub w prawo w obrębie jej strony i ją ukrywa.
- **Przeciąganie.** Nagłówek przeciągnięty na inny nagłówek po tej samej stronie zajmuje jego miejsce.
- **Zmiana szerokości.** Krawędź nagłówka można przeciągnąć, aby zmienić szerokość; jest to też separator, który klawisze strzałek poszerzają lub zwężają, a dwuklik przywraca początkową szerokość.
- **Sortowanie.** Naciśnięcie nagłówka sortuje według niego; z Shiftem dodaje kolumnę do sortowania, maksymalnie <RepositoryFact name="dataGridMaxSortedColumns" /> kolumn, ponumerowanych w nagłówku.
- **Gęstość.** Przestronne lub zwarte wiersze.
- **Rozmiar strony.** <RepositoryFact name="dataGridPageSizes" /> wierszy na stronę.

Siatka to jedna karta: na górze pasek narzędzi, pod nim tabela, a na dole pasek paginacji, oddzielone cienkimi liniami. Pasek narzędzi ma dwa wiersze: w pierwszym wyszukiwanie i ustawienia widoku, w drugim, pod nimi, przycisk Filtruj i chipy aktywnych filtrów. Wszystkie kontrolki paska narzędzi i chipy filtrów mają tę samą wysokość. Nagłówki zaczynają się wielką literą tylko w pierwszym słowie, mają rozmiar metadanych i przygaszone tło, komórki mają rozmiar zwykłego tekstu, a ostatnia kolumna z danymi zajmuje całą pozostałą szerokość, podczas gdy kolumna akcji zachowuje własną. Na każdej liście w siatce opcja pod kursorem jest podświetlona tak samo jak ta, na której jest fokus klawiatury. Pole wyszukiwania zajmuje wolne miejsce na pasku narzędzi, więc jego tekst zastępczy nigdy nie jest ucięty. Nagłówek mieści się w jednej linii i nigdy nie dzieli słowa: początkowa szerokość każdej kolumny mieści jej nagłówek razem ze strzałkami sortowania i menu kolumny w każdym języku, a `e2e/specs/text-layout.spec.ts` nie przechodzi, gdy etykieta nagłówka wychodzi poza komórkę w którejkolwiek siatce panelu administracyjnego. W siatce węższej niż 64rem przyciski Kolumny, Eksportuj CSV i Przywróć układ pokazują tylko ikony, dzięki czemu wyszukiwanie ma więcej miejsca.

Wiersz nagłówka pozostaje widoczny, gdy wiersze przewijają się wewnątrz siatki, a przypięte kolumny pozostają widoczne, gdy siatka przewija się w poziomie; tak telefon pokazuje szeroką tabelę. Cień po stronie, po której część kolumn jest jeszcze poza widokiem, oraz na krawędzi przypiętych kolumn, gdy inne przesuwają się pod nimi, pokazuje, że siatkę można przewijać (`.grid-scroller` w `globals.css`).

Kolumna akcji wiersza ma <RepositoryFact name="dataGridActionsSize" /> pikseli szerokości i mieści jeden przycisk ⋯, `RowMenu` (`src/presentation/components/custom/row-menu.tsx`), który otwiera akcje wiersza w menu: najpierw te używane na co dzień, a po separatorze destrukcyjne, które proszą o potwierdzenie w oknie dialogowym. Tym przyciskiem kończą się wiersze każdej siatki w panelu administracyjnym i każdej listy, w której można zmieniać kolejność, na przykład programu kursu – nigdy rzędem ikon. Kolumna nie ma menu w nagłówku: nie można jej sortować, ukryć, przesunąć ani zmienić jej szerokości, nie trafia do pliku CSV i zawsze zostaje ostatnia po prawej.

## Kolejność wierszy [#row-order]

Z `onReorder` siatka zaczyna się od wąskiej kolumny uchwytów, a jeśli ma pola wyboru, stoi ona zaraz za nimi. Uchwyt jest przygaszony i działa tak:

- **Przeciąganie.** Wiersz przeciągany za uchwyt przesuwa się między pozostałymi, gdy kursor nad nimi przechodzi, a upuszczenie zapisuje jego nowe miejsce. Escape albo upuszczenie poza wierszami przywraca go na poprzednie miejsce.
- **Klawiatura.** Gdy uchwyt ma fokus, strzałki w górę i w dół przesuwają wiersz o jedno miejsce. Przesunięcie poza pierwszy albo ostatni wiersz strony otwiera stronę, na którą trafia wiersz, i ustawia fokus na jego uchwycie.
- **Zapisywanie.** `onReorder` dostaje wiersz i liczbę miejsc, o którą go przesunięto, ujemną w górę, więc serwer przesuwa go od miejsca, które zajmuje w tej chwili w zapisanej kolejności, także między stronami, a wiersz, który inny administrator w międzyczasie dodał lub usunął gdzie indziej, nie zmienia tego, gdzie trafi. Nowa kolejność pojawia się od razu i zostaje na ekranie, gdy przesunięcia są zapisywane jedno po drugim, aż dotrą odświeżone wiersze; gdy obietnica zwrócona przez `onReorder` zostanie odrzucona, wiersze wracają na poprzednie miejsca. `/admin/courses` przekazuje `moveCourse` przez mutację z `scope`, więc przesunięcia są zapisywane w kolejności, w jakiej je wykonano.
- **Kiedy nie działa.** Gdy wiersze są posortowane, przefiltrowane albo zawężone wyszukiwaniem, miejsce wiersza na ekranie nie jest jego miejscem w zapisanej kolejności, więc uchwyty są wyłączone.

Każde przesunięcie jest ogłaszane w regionie live, na przykład „Przeniesiono na pozycję 3 z 12.”

## Zaznaczanie i eksport

Z `selectable` pole wyboru zaznacza wiersz, a pole wyboru w nagłówku zaznacza stronę. Wtedy u dołu okna pojawia się pływający pasek z liczbą, Eksportuj zaznaczone, `bulkActions` strony i Wyczyść zaznaczenie. Pola wyboru ma każda siatka panelu administracyjnego, która wyświetla rekordy: kursy, produkty, kategorie i kolekcje, zamówienia, klientów, użytkowników, zaproszenia i zamówienia bez licencji; nie mają ich tylko tabele z liczbami na pulpicie. `/admin/courses` dodaje **Usuń** dla zaznaczonych kursów; pozostałe siatki eksportują zaznaczenie, bo ich rekordy nie mają akcji, którą można wykonać na kilku naraz.

Eksportuj CSV pobiera każdy wiersz, który znajdują wyszukiwanie i filtry, nie tylko stronę na ekranie: na serwerze prosi o strony po <RepositoryFact name="dataGridExportPageSize" /> wierszy, aż ma je wszystkie. Plik zawiera widoczne kolumny w ich kolejności, zaczyna się od znacznika kolejności bajtów, żeby arkusze kalkulacyjne czytały go jako UTF-8, i wstawia `'` przed każdą komórką, która zaczynałaby formułę. Zapisuje go `src/lib/csv.ts`.

## Dostępność

- Tabela ma `label` jako nazwę oraz `aria-rowcount`; każdy wiersz ma swój `aria-rowindex`, liczony przez wszystkie strony.
- Sortowalne nagłówki są przyciskami i mają `aria-sort`.
- Każda kontrolka działa z klawiatury: menu i listy obsługują strzałki i wyszukiwanie przez pisanie z React Aria, Escape je zamyka, zmiana szerokości używa strzałek na separatorze nagłówka, a wiersz przesuwa się strzałkami w górę i w dół na jego uchwycie o nazwie „Przeciągnij albo użyj strzałek, aby zmienić kolejność”.
- Przesuwanie kolumny lub wiersza, przypinanie, ukrywanie, sortowanie z menu i przywracanie układu są ogłaszane w regionie live z priorytetem „polite”; liczba wyników i liczba zaznaczonych wierszy też są ogłaszane na bieżąco.

## Tłumaczenia

Własne teksty siatki są w `messages/<locale>/components.custom.data-grid.json`. Strona przekazuje jej tylko etykiety kolumn, opcje filtrów, etykietę wyszukiwania i komunikat o braku danych.
