## Projets Vitest

`vp test` exécute Vitest via Vite+ avec trois projets définis dans `vite.config.ts`. Les tests se trouvent dans un dossier `__test__` à côté du code qu'ils couvrent et importent les API de test depuis `vite-plus/test`.

| Projet        | Environnement | Motif de fichier        |
| ------------- | ------------- | ----------------------- |
| `node`        | Node          | `*.test.ts`             |
| `integration` | Node          | `*.integration.test.ts` |
| `component`   | jsdom         | `*.component.test.tsx`  |

Aucun test ne contacte un vrai compte Cloudflare ni un vrai fournisseur :

- D1 est une base SQLite en mémoire qui exécute les migrations versionnées, et KV est une map en mémoire. KV et les compteurs de limitation de débit sont réinitialisés avant chaque test.
- `createServerFn` est remplacé afin qu'une fonction serveur s'exécute dans le processus en passant par ses vrais middlewares et son vrai validateur.
- Les tests de composants effectuent le rendu avec un vrai `QueryClient` et un vrai routeur.
- Les requêtes d'e-mail, d'OAuth et de paiement sont simulées.

## Couverture

`bun run test:coverage` impose une couverture de 100 % des lignes, des instructions, des fonctions et des branches dans tout `src`. Les primitives shadcn, `src/platform/testing`, les fichiers générés et les déclarations de types sont exclus. Couvrez le comportement réel, et supprimez les branches qui ne peuvent jamais s'exécuter plutôt que de simuler des globales pour les atteindre.

## Tests navigateur

Les specs Playwright se trouvent dans `e2e/specs`, avec les page objects dans `e2e/pages` et les fixtures dans `e2e/fixtures`. Elles s'exécutent sur un build proche de la production qui utilise l'environnement Wrangler `test` : D1 et KV locaux dans `.wrangler/test`, secrets factices issus de `.env.test`, et un Worker de test qui capture les e-mails sortants afin qu'une spec puisse suivre un vrai lien de vérification. En local, Playwright applique lui-même les migrations, peuple la base, compile puis démarre l'application. La suite s'exécute dans Chromium et WebKit.

## CI

`.github/workflows/ci.yml` s'exécute sur les pull requests et sur les pushs vers `main` :

1. `bun run check` : formatage, lint, vérification des types et `check:i18n`
2. `bun run test:coverage`
3. Un build de test et la suite Playwright dans Chromium
4. Un déploiement de preview pour les pull requests, ou un déploiement de production pour `main`
