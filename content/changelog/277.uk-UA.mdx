- Змінено: pull request потрапляють у `main` через чергу злиття GitHub, яка ще раз тестує кожен поверх `main` і pull request перед ним і зливає групу разом, коли кожен пройшов, тож готовий pull request більше не чекає на rebase. `bun scripts/enqueue-pr.ts <number>` ставить pull request у чергу й дає його заголовку емодзі, яке зберігає squash-коміт. Див. [Git і pull request](/docs/conventions/git-workflow#merging).
- Змінено: pull request більше не розгортає спільний preview. Нова перевірка `Worker upload` завантажує його preview-Worker у Cloudflare як версію, що не обслуговує трафік, і це доводить завантаження, його розмір і bindings, не замінюючи того, що віддає `preview.saasyland.com`, тож готові pull request більше не блокують один одного. `main` розгортається на preview перед продакшеном, а `preview.yml` вручну розгортає там протестовану гілку. Див. [CI/CD](/docs/tooling/ci-cd#merge-queue).
- Змінено: push у `main`, який черга злиття вже протестувала, розгортається без повторного запуску перевірок, а перевірка changelog розглядає гілку черги злиття як `main`.
- Змінено: визначення готовності запускає локально `check`, `test:coverage`, `build:test` і браузерні специфікації, яких стосується зміна; CI запускає весь браузерний набір тестів у pull request і ще раз у черзі злиття. Див. [Конвенції](/docs/conventions#definition-of-done).
