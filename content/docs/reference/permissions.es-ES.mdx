Cada área define sus declaraciones de permisos y los roles a los que las concede en `src/data/<area>.access.ts`, y `src/integrations/better-auth/auth.access.ts` construye a partir de ellas el control de acceso de Better Auth y los roles (consulta [Roles y permisos](/docs/guides/roles-and-permissions)). Las mismas definiciones las usan el servidor (`authorized`, los guards de ruta) y el cliente de Better Auth.

## Roles

| Rol           | Código     | Permisos                                                                                                                                                                                 |
| ------------- | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Administrador | `admin`    | Todas las declaraciones de la aplicación que aparecen abajo, que cada área concede a los administradores, más las declaraciones de administración de Better Auth para `user` y `session` |
| Cliente       | `customer` | Ninguno. Los clientes pueden llamar a las funciones de servidor que solo exigen una sesión.                                                                                              |

Los usuarios nuevos reciben `customer` (`DEFAULT_ROLE_CODE` en `auth.roles.ts`).

## Dónde se comprueban los permisos

| Permiso                 | Lo comprueba                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `admin: ["access"]`     | `requireAdmin` en el layout de `/admin` y la redirección tras el inicio de sesión                                                                                                                                                                                                                                                                                                                                                                                          |
| Acciones de `category`  | Los casos de uso de categorías: `read`, `create`, `update`, `delete`                                                                                                                                                                                                                                                                                                                                                                                                       |
| `course: ["read"]`      | `get-courses` y `get-course-editor`; también `resolveViewer` (`lesson.viewer.ts`): quien lo tiene ve todas las lecciones y descarga sus materiales en `get-course`, `get-lesson`, `get-lesson-playback` y `save-lesson-progress`, sea cual sea su nivel de acceso                                                                                                                                                                                                          |
| `course: ["create"]`    | `create-course`                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `course: ["update"]`    | `update-course`, `move-course` y las escrituras de capítulos, lecciones y materiales: `create-chapter`, `update-chapter`, `delete-chapter`, `move-chapter`, `create-lesson`, `update-lesson`, `replace-lesson-video`, `delete-lesson`, `move-lesson`, `create-lesson-attachment`, `upload-lesson-attachment`, `update-lesson-attachment`, `move-lesson-attachment`, `delete-lesson-attachment`; también `set-video-placeholder`, que decide si las lecciones se reproducen |
| `course: ["delete"]`    | `delete-course`                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Acciones de `product`   | Los casos de uso de productos: `read`, `create`, `update`, `delete`                                                                                                                                                                                                                                                                                                                                                                                                        |
| `order: ["read"]`       | `get-unlicensed-orders`, del área de licencias: la lista del panel de administración con los pedidos de licencia pagados sin licencia                                                                                                                                                                                                                                                                                                                                      |
| Acciones de `video`     | `get-videos` y `get-video-playback` (`read`), `delete-video` (`delete`)                                                                                                                                                                                                                                                                                                                                                                                                    |
| Acciones de `user`      | Los casos de uso de usuarios, una acción cada uno; `ban` cubre tanto `ban-user` como `unban-user`, y `get` también el `get-user-license` del área de licencias                                                                                                                                                                                                                                                                                                             |
| Acciones de `session`   | `list-user-sessions` (`list`), `revoke-user-session` y `revoke-user-sessions` (`revoke`)                                                                                                                                                                                                                                                                                                                                                                                   |
| Una sesión, sin permiso | Los casos de uso de cuenta, licencia, dos factores, preferencias de la newsletter y sesiones propias, `stop-impersonating-user` y `save-lesson-progress`                                                                                                                                                                                                                                                                                                                   |

`order: ["update"]`, `order: ["refund"]`, `product: ["publish"]` y `settings` están declarados, pero todavía no los comprueba ninguna función de servidor.

## Comprobar un permiso

Las funciones de servidor usan el middleware, por ejemplo `authorized({ category: ["read"] })`. El resto del código llama a `hasPermission`, como hacen los guards de ruta:

```ts
const isAdmin = (role: string | null | undefined): boolean => hasPermission({ permission: { admin: ["access"] }, role })

export const requireAdmin = async (context: ProtectedRouteContext) => {
  const result = await requireSignedIn(context)
  if (!isAdmin(result.session.user.role)) {
    throw redirect({ replace: true, to: ROUTES.APP })
  }
  return result
}
```
