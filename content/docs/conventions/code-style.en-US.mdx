`bun run check` runs `bun run generate:cn`, `bun run check:comments`, `bun run check:i18n` and `bun run check:flows`, and then `vp check`, which formats with oxfmt, lints with oxlint and type-checks with TypeScript in one pass, with the configuration in `vite.config.ts` and `tsconfig.json`. CI runs the same command. Nothing here is a matter of taste: if the tools accept code that breaks a rule on this page, review rejects it.

## What the tools enforce

oxlint runs the `correctness`, `nursery`, `pedantic`, `perf`, `style` and `suspicious` categories as errors, with type-aware rules and type checking switched on. The limits that shape code most:

| Rule                                    | Setting                                                       | Effect                                                                 |
| --------------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `max-lines`                             | <RepositoryFact name="maxLines" />                            | Split a file by responsibility before it grows                         |
| `max-lines-per-function`                | <RepositoryFact name="maxLinesPerFunction" />                 | Components and handlers stay small                                     |
| `max-statements`                        | <RepositoryFact name="maxStatements" />                       | Extract named helpers instead of long bodies                           |
| `no-magic-numbers`                      | `0` and `1` allowed, plus array indexes and default values    | Every other number is a named constant                                 |
| `id-length`                             | at least two characters, except `_`, `m` and `t`              | Identifiers are words; `t` is the translator                           |
| `one-var`                               | `never`                                                       | One declaration per statement                                          |
| `unicorn/no-null`                       | on outside tests and `src/platform/testing`                   | Absent values are `undefined`                                          |
| `typescript/no-explicit-any`            | `error`                                                       | No value is typed `any`                                                |
| `typescript/ban-ts-comment`             | `true` for `@ts-expect-error`, `@ts-ignore` and `@ts-nocheck` | No compiler error is suppressed, with or without a reason              |
| `typescript/consistent-type-assertions` | `assertionStyle: "never"`                                     | No `as` cast; `as const` and `satisfies` remain                        |
| `code-style/no-comments`                | `error`                                                       | No comment, directive comments included                                |
| `code-style/no-multiline-ternary`       | `error`                                                       | A ternary fits on one line                                             |
| `code-style/no-undefined-branch`        | `error`                                                       | No ternary with an `undefined` or `null` branch, no `return undefined` |
| `code-style/no-undefined-fallback`      | `error`                                                       | No `?? undefined`                                                      |
| `code-style/zod-namespace-import`       | `error`                                                       | Zod is imported as `* as zod` from `zod`                               |
| `radius/no-off-scale`                   | `error`                                                       | Every corner takes a radius from the scale                             |
| `type/no-off-scale`                     | `error`                                                       | Every text size is a step of the type scale                            |
| `type/mono-for-code`                    | `error`                                                       | The monospaced face is only for code                                   |

The overrides are narrow and file-scoped: tests and the shared test helpers in `src/platform/testing` relax `no-magic-numbers`, `no-await-in-loop`, `unicorn/no-null`, `hydration/no-clock-or-locale-in-render` and `admin-data/no-literal-data`; `src/presentation` and `src/hooks` relax `typescript/consistent-return`; test mocks relax `require-await`; `src/routes` turns off `sort-keys`, because route options follow their own order (see [Route files](/docs/conventions/routes)); and the admin's routes, components and data files turn on `admin-data/no-literal-data` (see [Admin dashboard](/docs/features/admin-dashboard#real-data-only)). All of `src` turns on `radius/no-off-scale`, `type/no-off-scale` and `type/mono-for-code`, which tests and `src/platform/testing` turn off again, and `src/presentation/social-card.tsx` turns off `type/no-off-scale`, because Takumi renders the social card as an image of a fixed size whose text sizes are set in inline styles rather than on the page's type scale (see [Theme](/docs/ui/theme#type-scale)).

`tsconfig.json` adds the strict flags that change how code is written: `strict`, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, `noPropertyAccessFromIndexSignature`, `noImplicitReturns`, `noFallthroughCasesInSwitch`, `noUnusedLocals` and `noUnusedParameters`. An indexed read is possibly `undefined`, an optional property cannot be set to `undefined` explicitly, and an index signature is read as `record["key"]`.

The formatter prints without semicolons, with double quotes, trailing commas and a width of <RepositoryFact name="printWidth" />. It also sorts imports into fixed groups, Tailwind classes in `className` and `cn` calls, and the `package.json` scripts by name (`sortPackageJson: { sortScripts: true }`), so never order any of them by hand: `vp check` fails when one is out of order. See [Lint and format](/docs/tooling/lint-format) for the commands.

## Render what the server rendered

A page renders twice: on the server, and again in the browser when React hydrates the HTML. Both renders must print the same text, or React reports a hydration mismatch (error #418) and renders the page again. So render code never reads the clock or the runtime's locale, which differ between the two: no `new Date()` without an argument, no `Date.now`, and no `toLocaleString`, `toLocaleDateString` or `toLocaleTimeString`. Use a value both sides share:

- a relative time counts from the `dataUpdatedAt` of the query that read its data, as [Internationalization and locales](/docs/features/internationalization) shows;
- a year the site prints comes from the build: the footer ends its copyright in `REPOSITORY_FACTS.buildYear`, the UTC year the site was built in;
- numbers and dates go through `useFormatter` from use-intl, in the page's locale and the user's time zone;
- a wait in the browser, such as the activation timeout of `CheckoutActivation`, is a timer started in `useEffect`, so the first render is the server's.

`hydration/no-clock-or-locale-in-render`, the rule of the repository's own oxlint plugin in `scripts/hydration-lint-plugin.ts`, enforces this in `src/hooks`, `src/presentation`, `src/providers` and `src/routes/*.tsx`. Everything there counts as render code except a function that runs later: an `on…` event handler, as a JSX prop, an object property or a variable; a `queryFn` or a `mutationFn`; and a callback passed to `useEffect`, `useLayoutEffect`, `useCallback`, `setTimeout`, `setInterval`, `requestAnimationFrame` or `addEventListener`. Those lists in the plugin are the allow-list: another kind of deferred callback is added there, with a case in `src/__test__/hydration-lint-plugin.test.ts`, never with a disable comment.

## No comments

Write no comments: not in TypeScript, TSX, tests, scripts, configuration or CSS, and not even to explain a non-obvious constraint. A name carries the meaning instead, and the reasoning goes into the commit message, the pull request or these docs.

```ts
const INCLUSIVE_END = 1
const FIRST_SEQUENCE = 1
const UNINSTALLED_POLAR_SDK_OPTIONAL_PEERS = [/^@opentelemetry\//u, "ioredis"]
```

The first two come from `video.delivery.ts` and `release.ts`, the third from `src/integrations/polar/polar.vite.ts`: each would otherwise need a comment.

Two checks enforce the rule, and both name the file, the line and the fix:

- `code-style/no-comments`, a rule of the repository's oxlint plugin in `scripts/code-style-lint-plugin.ts`, reports every comment in the files the linter reads, in the editor and in `vp check`.
- `bun run check:comments` runs `scripts/check-comments.ts` before the linter, in `bun run check` and in the pre-commit hook. It parses every TypeScript, JavaScript and CSS file that Git tracks or would add, with oxc for code and PostCSS for styles, so a `//` in a URL or a regular expression and a `/*` in a CSS glob are not comments. It reads what the linter cannot: `e2e`, `remotion`, declaration files, the stylesheets, and a `/* oxlint-disable */` comment, which the linter obeys before any rule sees it.

The exemptions are the files that `.gitattributes` marks `linguist-generated`, of which `src/routeTree.gen.ts` and `src/types/worker-configuration.d.ts` are code, and the `#!` line of a script, which JavaScript's grammar does not count as a comment. A type the compiler needs everywhere goes into `types` in `tsconfig.json`, as the Vitest globals do, never into a `/// <reference>` comment.

## No escape hatches

Never write `oxlint-disable`, `eslint-disable`, `@ts-expect-error`, `@ts-ignore`, `@ts-nocheck`, an `as` cast or `any` to make a rule pass. A rule that fires is pointing at a design problem; change the design. The checks reject each of them: `typescript/ban-ts-comment` the three compiler directives even with a description, `typescript/consistent-type-assertions` every assertion but `as const`, `typescript/no-explicit-any` the `any`, and `code-style/no-comments` and `bun run check:comments` every disable comment. An `eslint-disable` comment switches nothing off in the first place (`respectEslintDisableDirectives: false`).

- **Validate instead of asserting.** Data from storage, the network or a request is parsed with Zod: `src/lib/github.ts` reads the cached star count with `cachedStarCountSchema.safeParse(await env.CACHE.get(CACHE_KEY, "json")).data`, which is a number or `undefined`, never a guess.
- **Narrow with a type guard.** `isRole` in `src/integrations/better-auth/auth.roles.ts` and `isSupportedLocale` in `src/integrations/use-intl/i18n.paths.ts` turn a `string` into a union with a real check.
- **Annotate, do not assert.** Give a value the type it needs where it is declared: the shadcn sidebar declares `SIDEBAR_MOBILE_STYLE: StyleWithCssVars`, the CSS properties plus its `--sidebar-width` custom property, instead of casting the object literal.
- **Check, do not convert.** `as const` and `satisfies` are allowed because they never change a type: `POLAR_ORDER_STATUS` ends in `as const satisfies Record<string, models.OrderStatus>`, so a misspelled Polar status fails to compile.
- **Restructure when a library contract fights you.** Wrap a value in an object, split a function, or read from a typed source rather than casting.

## Null and undefined

Outside tests and `src/platform/testing`, an absent value is `undefined`, and `null` is never written as a value. The linter allows it where an API defines it: in a comparison with a value that can be `null`, such as a nullable column (`entry.completedAt !== null` in `course.outline.ts`), and in a React DOM ref, which starts as `useRef<HTMLElement>(null)` because React types `ref` as `RefObject<T | null>` and sets it back to `null` on unmount (`course-showcase.tsx`). Never bridge an API that returns `null` with `?? undefined`; `code-style/no-undefined-fallback` fails it. Validate the input first, so the call cannot fail, or use a parser that already returns `undefined`. Search params are the common case, and `searchParam(schema)` in `src/lib/search-params.ts` returns `undefined` for a missing or malformed value:

```ts
export const authSearchSchema = zod.object({
  redirect: searchParam(callbackPathSchema),
})
```

## Ternaries and early returns

A ternary fits on one line, such as `{t(course === undefined ? "create" : "save")}` in `course-form.tsx`. Anything longer, and every choice between two pieces of JSX, becomes an early return, a pair of `&&` conditions or a small component; a conditional class becomes `cn("base", { "classes": condition })`. `code-style/no-multiline-ternary` fails every ternary that spans lines, including one the formatter broke because it grew past the print width. `src/routes/auth.reset-password.tsx` renders its two states with two conditions:

```tsx
{hasValidToken && <ResetPasswordForm token={token} />}
{!hasValidToken && (
  <>
    <p className="text-body text-pretty text-destructive">{t("form.invalidToken")}</p>
```

Functions return early for the special cases and keep the main path unindented, as `hasLessonAccess` in `src/modules/lesson/lesson.access.ts` does:

```ts
export const hasLessonAccess = (access: Lesson["select"]["access"], viewer: Viewer): boolean => {
  if (access === LESSON_ACCESS.PREVIEW || viewer.isStaff) {
    return true
  }

  if (access === LESSON_ACCESS.ACCOUNT) {
    return viewer.userId !== undefined
  }

  return viewer.entitled
}
```

No branch spells out the absent value either: `code-style/no-undefined-branch` fails a ternary with an `undefined` or `null` branch and every `return undefined`. Write what the code does instead: return early from a guard clause, read a value that may be missing with `?.` or with `??` and a real default, return what a lookup or `find` matches, render JSX with `&&`, and give a Vite plugin hook a filter that names the ids it handles, so Rolldown never calls it for any other id. `scripts/repository-facts.ts` serves its virtual module that way:

```ts title="scripts/repository-facts.ts"
    load: { filter: { id: exactRegex(RESOLVED_MODULE_ID) }, handler: () => moduleSource },
    name: "saasyland:repository-facts",
    resolveId: { filter: { id: exactRegex(MODULE_ID) }, handler: () => RESOLVED_MODULE_ID },
```

## Named constants

Numbers other than `0` and `1` are named (`COURSE_STALE_MS = 60_000`, `SAVE_INTERVAL_MS = 15_000`). `0` and `1` are written as literals, as in `.limit(1)`, `index + 1` and `toHaveBeenCalledTimes(1)`, unless they carry a meaning of their own: a process exit code is `FAILURE_EXIT_CODE`, and the inclusive end of an HTTP byte range is `INCLUSIVE_END`. Values that belong to the domain, such as statuses, kinds, access levels, tiers, roles and provider event values, are declared once as an `as const` object and referenced by name everywhere, including tests and fixtures:

```ts
export const COURSE_STATUS = {
  DRAFT: "draft",
  PUBLISHED: "published",
} as const
```

The tuple a column or an enum schema needs is built from the object, not retyped, and sits beside it in the module's constants, which import nothing from Drizzle: `course.constants.ts` declares `COURSE_STATUSES = [COURSE_STATUS.DRAFT, COURSE_STATUS.PUBLISHED] as const`, which feeds both `text("status", { enum: COURSE_STATUSES })` in `course.schema.ts` and `zod.enum(COURSE_STATUSES)` in `course.zod.ts`. Browser code reads the tuples from there too: the pricing table iterates `LICENSE_TIERS` from `license.constants.ts`.

- A module's constants live in its `<module>.constants.ts` (`LESSON_ACCESS`, `LICENSE_TIER`); a provider's values live in the integration's `*.constants.ts` (`POLAR_ORDER_STATUS` in `polar.constants.ts`, `AUTH_PROVIDER` in `auth.constants.ts`).
- Column and input lengths are named once, in the module's constants, and read by both the Drizzle schema and the Zod schema: `PRODUCT_NAME_MAX_LENGTH` in `product.constants.ts`.
- One concept has one map in one casing: `ERROR_CODES` for server errors, `AUTH_ERRORS` for Better Auth error keys, `ROLE_CODES` for roles.
- Environment names and HTTP status codes are declared once, in `src/modules/_core/constants/api.ts`: `ENVIRONMENT.PRODUCTION` in `__root.tsx` and the deploy scripts, `HTTP_STATUS.PARTIAL_CONTENT` in the Worker's media handler. No file declares its own map of either. The one exception is the Vite plugin files such as `src/data/cloudflare.vite.ts`, which compare `mode` with the plain names: Vite loads them before the `~` alias resolves, so they cannot import `api.ts`.
- A constant used by one file stays in that file, below the imports. A constant used by several files goes to its module, to `src/data` (see [Files and naming](/docs/conventions/files-and-naming)) or to `src/modules/_core/constants`. Never give one constant a file of its own.
- Typed API field names such as `license_key_id` are properties, not values, and stay as property access.

## Hooks in components

Single-value hook calls come first, then a blank line, then each destructured hook result, so the values a component pulls apart read as their own group. `src/presentation/components/custom/auth/sign-in-form.tsx`:

```tsx
const t = useTranslations()
const router = useRouter()

const { finishSignIn, redirect } = useAuthRedirect()
```

A component calls `useTranslations` once and names the result `t`; see [Translations and content](/docs/conventions/translations) for why.

## Names and imports

- Files and folders are kebab-case; components are PascalCase; constants are SCREAMING_SNAKE_CASE; functions start with a verb (`resolveViewer`, `rethrowAsConflict`); booleans read as questions (`isPending`, `hasLessonAccess`).
- Imports use the `~/src/...` alias and come from the file that defines the symbol; the paths are the one exception, which every file imports as one namespace, `import * as ROUTES from "~/src/routes"`. There are no barrel files that re-export a folder. The re-export files are the join points, which hold one `export { … } from` line per area, such as `src/routes.ts` and the `*.entries.ts` barrels (see [Paths and navigation](/docs/conventions/routes#paths-and-navigation)), and `src/integrations/drizzle-orm/drizzle.schemas.ts`, because Drizzle needs every table in one schema object.
- Zod comes in one way, `import * as zod from "zod"` (or `import type * as zod from "zod"` for types only), the form Zod 4's documentation shows; `code-style/zod-namespace-import` fails a default import, a named import and a subpath such as `zod/v4`.
- Stepping an index by one uses the literal: `lessons[index + 1]` in `course.utils.ts`. Any other offset, `-1` included, gets a name: `groups.at(LAST_GROUP_INDEX)` in `robots.ts`, never `slice(index, -5)`.
