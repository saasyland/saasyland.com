- Виправлено: нове робоче дерево Git отримує свої хуки комітів. `git worktree add` встановлює диспетчер хуків нового робочого дерева через хук `post-checkout`, тож коміт, зроблений до `bun install`, завершується помилкою в хуку `pre-commit`, а не пропускає його, а `bun install` завершується помилкою, коли `core.hooksPath` не дорівнює `.vite-hooks/_` або коли в диспетчері бракує хука. Досі Git робив коміти без хуків, і без попередження, у кожному робочому дереві, яке не мало власного диспетчера. Див. [Git і pull request](/docs/conventions/git-workflow#hooks-in-every-worktree).
- Виправлено: сторінка [Git і pull request](/docs/conventions/git-workflow#linear-history) більше не радить зливати `main` у гілку pull request і ніколи не робити force-push. Вона описує лінійну історію, якої дотримується проєкт: жодних комітів злиття, навіть у гілці pull request, гілки, які оновлюють через rebase на `main`, pull request, для якого GitHub не може зробити rebase, внесений знову одним комітом, і переписані гілки, надіслані командою `git push --force-with-lease`. `AGENTS.md`, `CONTRIBUTING.md` і сторінка [Участь у розробці](/docs/project/contributing) кажуть те саме.
