---

`wrangler.jsonc` defines four environments. `CLOUDFLARE_ENV` selects one for the dev server and builds, and each reads secrets from its own environment file:

| Environment   | Selected by                                 | Bindings                                 | Secrets from       |
| ------------- | ------------------------------------------- | ---------------------------------------- | ------------------ |
| `development` | `bun run dev`                               | Local D1, KV and R2 in `.wrangler/state` | `.env.development` |
| `preview`     | `build:preview`, `deploy:preview`           | Preview D1, KV and R2                    | `.env.preview`     |
| `production`  | `build:production`, `deploy:production`     | Production D1, KV and R2                 | `.env.production`  |
| `test`        | `build:test`, `start:test`, `db:reset:test` | Local D1, KV and R2 in `.wrangler/test`  | `.env.test`        |

`.env.development`, `.env.preview` and `.env.production` are ignored by Git; `.env.example` lists their keys. `.env.test` is committed and contains dummy values only. The deploy scripts upload only the keys listed in the environment's `secrets.required`, read from the matching file.

## Secrets

Each environment lists its secrets in `secrets.required`: the Better Auth, OAuth, Resend and Polar keys, plus `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID` and `CLOUDFLARE_ACCESS_TOKEN` for Drizzle tooling (the `test` environment omits those three). See [Environment variables](/docs/getting-started/environment-variables) for each key.

`AFFONSO_PROGRAM_ID`, the public Affonso program ID that affiliate referral tracking needs, is a Worker variable under `vars`, not a secret, so it is not in `.env.example` or `secrets.required`. Set it only for the environment that takes real payments; `production` sets SaaSy Land's programme ID and `test` a dummy ID for the browser tests. Tracking runs only when the Worker has the ID and the programme is open: `AFFILIATE_PROGRAM` is <RepositoryFact name="affiliateProgram" /> today ([Opening the programme](/docs/features/affiliates#opening-the-programme)).

Server code reads secrets with `import { env } from "cloudflare:workers"`. Nothing uses a `VITE_` variable, and none may hold a secret, because Vite exposes those to the browser. `scripts/verify-build.ts` fails the build when a client asset imports `cloudflare:workers`. The canonical domain comes from `APP_DOMAIN` in `src/presentation/branding/index.ts`, not from an environment variable.

## Bindings

| Binding   | Type          | Use                                                    |
| --------- | ------------- | ------------------------------------------------------ |
| `DB`      | D1            | Application database, sessions and rate limits         |
| `CACHE`   | KV            | GitHub star count and regional checkout discounts      |
| `MEDIA`   | R2            | Video files, served through `/media/`                  |
| `BUNDLES` | R2            | The CLI's template bundles, served through `/bundles/` |
| `ASSETS`  | Static assets | Prerendered pages, fonts and public files              |

Development uses local bindings only, so `bun run dev` never touches the preview or production data; [Database](/docs/tooling/database#three-databases) explains why each binding is local. Run `bun run cf-typegen` after changing bindings to regenerate `src/types/worker-configuration.d.ts`.

## Tests

Vitest loads `.env.test` through `test.env` and resolves `cloudflare:workers` to `src/platform/testing/mocks/cloudflare.ts`, which provides an in-memory D1, KV and a bucket for each R2 binding; `src/platform/testing/mocks/cache.ts` stubs the Workers cache. Playwright uses the `test` environment and its entry `src/platform/testing/worker.ts`. Neither needs real credentials.
