## Implemented

- **Sessions**: Better Auth sessions in D1, cookie prefix `saasyland`, secure cookies outside local modes, allowed hosts per mode, and `cf-connecting-ip` as the client address. The client session never contains the token.
- **Accounts**: required email verification, sessions revoked on password reset, optional TOTP with backup codes, verification identifiers stored hashed and OAuth tokens encrypted.
- **Authorization**: `requireSignedIn` and `requireAdmin` on routes; `authorized(permission)` on server functions with the roles from `auth.access.ts`.
- **Rate limits**: the Better Auth limiter and the `withRateLimit` middleware share the D1 `rate_limit` table. `RATE_LIMITS.SENSITIVE` allows <RepositoryFact name="sensitiveRateLimit" /> calls and `RATE_LIMITS.TOKEN` <RepositoryFact name="tokenRateLimit" /> calls per <RepositoryFact name="rateLimitWindowSeconds" unit="second" /> per client and action. Verification, password reset and newsletter confirmation emails are also limited to <RepositoryFact name="recipientEmailsPerHour" /> of each kind per address per hour (`withinRecipientRateLimit`, keyed on a SHA-256 hash of the address); over the limit the email is skipped silently.
- **Errors**: the request middleware turns failures into `AppError` codes (`src/modules/_core/constants/errors.ts`), so clients never receive raw server messages; components show them with `useErrorMessage`.
- **Webhooks and forms**: Polar webhooks are verified with `POLAR_WEBHOOK_SECRET`; a newsletter subscription (`subscribeToNewsletter`) is accepted only on the build mode's hosts from `appHostsForMode`, over HTTPS or, in development and test, HTTP (`newsletterRequestOrigin`).
- **Better Auth input**: `enforceInputPolicy` in `auth.hooks.ts` applies the form schemas to every Better Auth endpoint that accepts a password, name, email or image, so requests sent straight to `/api/auth` meet the same rules; a failing request gets `400` with `VALIDATION_ERROR`.
- **Media**: video files stay in a private R2 bucket. The Worker serves them only under `/media/` paths signed with an HMAC key derived from `AUTH_SECRET` and valid for at least <RepositoryFact name="signedMediaHours" unit="hour" />. `getVideoPlayback` issues them to callers with `video: ["read"]`; `getLessonPlayback` issues them for a published lesson once `hasLessonAccess` allows the viewer, so guests receive them for free previews, signed-in users for account lessons, Complete or Agency licence holders for paid lessons and admins for every lesson; a wrong or expired signature gets `403`.
- **Headers**: every response from the Worker carries `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`, `Cross-Origin-Opener-Policy: same-origin`, a `Permissions-Policy` that turns off camera, microphone, geolocation and topics, and a Content Security Policy that blocks framing, `<base>` changes and plugins. HTTPS responses add `Strict-Transport-Security`. They are defined once, as `SECURITY_HEADERS` and `HTTPS_SECURITY_HEADERS` in `src/modules/_core/constants/api.ts`, and `src/server.ts` sets them on every Worker response, replacing any value the response or a `public/_headers` rule already set. Files served without the Worker (`/assets/*`, `/fonts/*`, `/robots.txt`, `/llms.txt`) get the same headers from the `/*` rule in `public/_headers`, a static file the platform reads before any code runs; `src/__test__/server.test.ts` fails when that rule and the constants differ.

## Not implemented

- A Content Security Policy that restricts scripts and styles: prerendered pages would need a hash for every inline script on every page.
- An audit log, including for bans, deletions and impersonation.
- Bot protection or CAPTCHA on public forms.
- An impersonation screen ([Impersonation](/docs/features/impersonation)).
