---
title: "モジュールを追加する"
description: "Drizzle スキーマ、Zod スキーマ、定数、型、ユースケースを備えたデータベーステーブルを追加します。"
---

モジュールは 1 つのデータベーステーブルに対応します。`src/modules/<table>/` は実在するテーブルのためだけに存在し、テーブルを所有しないサーバー関数は `src/lib` か、それを使うルートに置きます。最小の完全な例は `src/modules/category` です。

## ファイル

| ファイル                   | 内容                                                                                                                                   |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `<table>.schema.ts`        | Drizzle のテーブル、インデックス、リレーション、定数から組み立てた enum のタプル                                                       |
| `<table>.zod.ts`           | 操作ごとに 1 つの入力スキーマと `drizzle-zod` のスキーマ。`<table>ZodSchemas` としてエクスポート                                       |
| `<table>.constants.ts`     | `CATEGORY_KIND` のような名前付きのドメイン値、カラムの上限値、クエリキーとミューテーションキーのタプル                                 |
| `<table>.types.ts`         | 行の型と各操作の入力型をまとめた 1 つのインターフェース                                                                                |
| `<table>.utils.ts`         | 任意のヘルパー。`license.utils.ts` は Worker の環境を読み取るため、サーバー専用です                                                    |
| `<table>.<concern>.ts`     | 1 つの操作に当たらない任意のコード。`license.webhooks.ts` や `video.playback.ts` など（[モジュールカタログ](/docs/reference/modules)） |
| `use-cases/<operation>.ts` | 1 ファイルにつき 1 つのサーバー関数と、そのクエリオプションまたはミューテーションオプション                                            |
| `__test__/`                | ソースファイル名に合わせたテスト。例：`category.schema.test.ts`、`category.zod.test.ts`                                                |

## 1. テーブルを定義する

テーブルの値には `category.constants.ts` で一度だけ名前を付けます。スキーマ、Zod スキーマ、ユースケース、コンポーネント、テスト、e2e のデータはここからインポートし、`"collection"` のような文字列を繰り返し書きません。

```ts
export const CATEGORY_NAME_MAX_LENGTH = 255

export const CATEGORY_KIND = {
  CATEGORY: "category",
  COLLECTION: "collection",
} as const
```

その名前を使ってテーブルを組み立てます。

```ts
import { index, sqliteTable, text } from "drizzle-orm/sqlite-core"

import { timestamps } from "~/src/integrations/drizzle-orm/drizzle.columns"

import { CATEGORY_KIND, CATEGORY_NAME_MAX_LENGTH } from "~/src/modules/category/category.constants"

export const CATEGORY_KINDS = [CATEGORY_KIND.CATEGORY, CATEGORY_KIND.COLLECTION] as const

export const category = sqliteTable(
  "category",
  {
    id: text("id").primaryKey(),
    kind: text("kind", { enum: CATEGORY_KINDS }).notNull().default(CATEGORY_KIND.CATEGORY),
    name: text("name", { length: CATEGORY_NAME_MAX_LENGTH }).notNull(),
    ...timestamps(),
  },
  (table) => [index("category_createdAt_idx").on(table.createdAt)],
)
```

- カラム名は snake_case、プロパティは camelCase にします。
- ID は `text` の主キーで、挿入を行うユースケースで `uuid` の `v7()` を使って値を設定します。
- `src/integrations/drizzle-orm/drizzle.columns.ts` の `...timestamps()` が `createdAt` と `updatedAt` を追加します。どちらも挿入時刻を既定値とするミリ秒のタイムスタンプで、`updatedAt` は更新のたびに打ち直されます。その他の日付は `integer(..., { mode: "timestamp_ms" })`、真偽値は `integer(..., { mode: "boolean" })` です。
- enum のカラムには定数オブジェクトから組み立てたタプルを渡し、既定値には文字列リテラルではなく `CATEGORY_KIND.CATEGORY` のような定数を使います。
- 外部キーには `.references(() => user.id, { onDelete: "cascade" })` を使い、結合は `relations(...)` で宣言します（`session.schema.ts` を参照）。

## 2. スキーマを登録する

テーブルと、リレーションがあればそれも、`src/integrations/drizzle-orm/drizzle.schemas.ts` からエクスポートします。

```ts
export { category } from "~/src/modules/category/category.schema"
```

このファイルは、D1 クライアント（`drizzle(env.DB, { schema })`）、Better Auth の Drizzle アダプター、drizzle-kit に読み込まれます。ここに含まれていないテーブルには、マイグレーションが生成されません。

## 3. マイグレーションを生成する

```sh
bun run db:generate
bun run db:migrate:local
```

`src/integrations/drizzle-orm/migrations/` に生成された SQL を確認し、スキーマと一緒にコミットします。リモート環境については [データベースマイグレーション](/docs/guides/database-migrations) で説明しています。

## 4. Zod スキーマを追加する

操作ごとに専用の入力スキーマを用意します。バリデーションメッセージは翻訳キーです。フォームは、`ValidationFieldError` に指定した名前空間でそれらを表示します。

```ts
import { createSchemaFactory } from "drizzle-zod"
import zod from "zod/v4"

import { MIN_FIELD_LENGTH, idField } from "~/src/modules/_core/utils/zod-fields"
import { CATEGORY_NAME_MAX_LENGTH } from "~/src/modules/category/category.constants"
import { CATEGORY_KINDS, category } from "~/src/modules/category/category.schema"

const { createInsertSchema, createSelectSchema, createUpdateSchema } = createSchemaFactory({ zodInstance: zod })

const createCategory = zod.object({
  kind: zod.enum(CATEGORY_KINDS),
  name: zod.string().min(MIN_FIELD_LENGTH, { message: "nameRequired" }).max(CATEGORY_NAME_MAX_LENGTH, { message: "nameMaxLength" }),
})

const deleteCategory = zod.object({ categoryId: idField })

export const categoryZodSchemas = {
  createCategory,
  deleteCategory,
  insert: createInsertSchema(category),
  select: createSelectSchema(category),
  update: createUpdateSchema(category),
}
```

すべてのロケールに `messages/<locale>/<table>.validations.json` を追加し、スキーマが使うすべてのキーを含めます。フォームがこれらのキーを表示するのは、そのルートが名前空間をプリロードし、それを `ValidationFieldError` に渡す場合だけです。管理画面のコースのフォームは `course.validations` を、それ以外のフォームは `auth.validations` を使います。

## 5. 定数と型を追加する

```ts
export const CATEGORY_QUERY_KEYS = {
  ALL: ["category"],
  LIST: ["category", "getCategories"],
} as const

export const CATEGORY_MUTATION_KEYS = {
  CREATE: ["category", "createCategory"],
  DELETE: ["category", "deleteCategory"],
  UPDATE: ["category", "updateCategory"],
} as const
```

```ts
import type * as zod from "zod"

import type { category } from "~/src/modules/category/category.schema"
import type { categoryZodSchemas } from "~/src/modules/category/category.zod"

export interface Category {
  select: typeof category.$inferSelect
  insert: typeof category.$inferInsert
  createCategory: zod.input<typeof categoryZodSchemas.createCategory>
  deleteCategory: zod.input<typeof categoryZodSchemas.deleteCategory>
}
```

すべてのキーはモジュール名で始まるため、`ALL` を無効化するとモジュールのすべてのクエリが再取得されます。

`Category` は操作のスキーマごとにキーを 1 つ持ちます。完全な `category` モジュールには、`getCategories`、`getCategory`、`updateCategory` もあります。サーバー関数はバリデーターの入力を `Category["createCategory"]` で型付けし、mutation や query のオプションも同じ型を使います。スキーマを追加したら、キーも追加してください。

## 6. 権限とユースケースを追加する

- 操作に権限が必要な場合は、`src/integrations/better-auth/auth.access.ts` の `APP_STATEMENTS` にテーブルのアクションを追加します。[ロールと権限](/docs/guides/roles-and-permissions) を参照してください。
- `use-cases/` の下に、操作ごとに 1 つのファイルを追加します。[ユースケースを追加する](/docs/guides/add-a-use-case) を参照してください。

## 7. テストする

モジュールの隣に `__test__/<table>.schema.test.ts`、`<table>.zod.test.ts`、`<table>.types.test.ts` を追加し、すべての操作について `use-cases/__test__/<operation>.test.ts` を追加します。カバレッジゲートは <RepositoryFact name="coverageThreshold" unit="percent" /> です。[テストを書く](/docs/guides/writing-tests) を参照してください。
