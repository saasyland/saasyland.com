---
title: "Conventional Commits"
description: "Format der Commit-Nachrichten und der Emoji-Hook."
---

Commit-Betreffzeilen folgen dem Muster `<type>(<scope>): <description>`. Der Scope ist optional, und `!` kennzeichnet eine inkompatible Änderung. Schreiben Sie die Betreffzeile ohne Emoji:

```sh
git commit -m "fix(auth): keep the locale in verification links"
```

Der Hook `prepare-commit-msg` in `.vite-hooks/` führt `bun scripts/commit-msg.ts` aus, das die Betreffzeile validiert und das Emoji für ihren Typ voranstellt; aus dem obigen Commit wird so `🐛 fix(auth): keep the locale in verification links`.

| Typ        | Emoji |
| ---------- | ----- |
| `build`    | 🛠️    |
| `chore`    | ♻️    |
| `ci`       | ⚙️    |
| `docs`     | 📚    |
| `feat`     | ✨    |
| `fix`      | 🐛    |
| `perf`     | 🚀    |
| `refactor` | 📦    |
| `revert`   | 🗑️    |
| `style`    | 💎    |
| `test`     | 🚨    |

Jeder andere Typ oder eine Betreffzeile ohne das konventionelle Format bricht den Commit mit der Liste der erlaubten Typen ab. Der Hook lässt Betreffzeilen unverändert, die bereits mit einem Emoji beginnen oder von Git erzeugt wurden (`Merge`, `Revert "`, `fixup!`, `squash!`), sowie Merge-, Squash- und Vorlagennachrichten.

Vor dem Nachrichten-Hook führt der Hook `pre-commit` den Befehl `bun run check:pre-commit` aus. Umgehen Sie die Hooks nicht.
