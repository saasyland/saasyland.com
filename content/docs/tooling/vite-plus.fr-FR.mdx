Vite+ (`vite-plus`, commande `vp`) regroupe Vite, Vitest, oxlint et oxfmt derrière une seule CLI, et `vite.config.ts` les configure tous. `package.json` remplace `vite` par `@voidzero-dev/vite-plus-core` et fixe `vitest` à la version 5.1.0. `vite-plus` est lui aussi épinglé à une version exacte ; mettez les trois à jour ensemble avec `vp migrate`, et non avec `bun update`. Les scripts du paquet appellent `vp` ; en dehors de ceux-ci, utilisez la CLI Vite+ globale ou `bunx vp`.

| Commande          | Utilisée par                                      |
| ----------------- | ------------------------------------------------- |
| `vp dev`          | `dev`                                             |
| `vp build --mode` | `build:preview`, `build:production`, `build:test` |
| `vp preview`      | `start`, `start:test`                             |
| `vp test`         | `test` et les scripts Vitest `test:*`             |
| `vp lint`         | `lint`                                            |
| `vp fmt`          | `format`, `format:check`                          |
| `vp check`        | `check`, `check:fix`                              |
| `vp staged`       | `check:pre-commit`                                |
| `vp config`       | `prepare`, qui installe les hooks Git             |

## Configuration

`vite.config.ts` charge ses plugins à la demande. Sous Vitest, seuls `repositoryFacts()` et `@vitejs/plugin-react` sont chargés ; sinon, la pile est la suivante :

- `@cloudflare/vite-plugin` : exécute le Worker dans l'environnement SSR, conserve l'état local (dans `.wrangler/test` pour le mode `test`) et utilise des bindings distants pour `development`.
- `fumadocs-mdx` : compile les collections de la documentation et du blog.
- `repositoryFacts` (`scripts/repository-facts.ts`) : sert le module `virtual:repository-facts`, les nombres et les versions mesurés dans le dépôt au moment du build ; voir [Page d'accueil](/docs/features/landing-page).
- `@tailwindcss/vite` : Tailwind CSS 4.
- `tanstackStart` : routage, découpage du code et prérendu des pages publiques.
- `@vitejs/plugin-react`.
- `deployedWorker` (`scripts/deployed-worker.ts`) : recompile le Worker après le prérendu sans le MDX rendu ni les traductions de la landing page et des pages légales ; voir [Cloudflare Workers](/docs/integrations/cloudflare-workers).

Le serveur de développement utilise le port 3000 et échoue si celui-ci est occupé. `resolve.tsconfigPaths` fournit l'alias d'import `~/`. Le même fichier contient les sections `fmt`, `lint`, `staged` et `test` ; voir [Lint et formatage](/docs/tooling/lint-format) et [Tests](/docs/tooling/testing).

`build.rolldownOptions.external` liste les dépendances peer optionnelles de `@polar-sh/sdk` (OpenTelemetry et `ioredis`). Elles ne sont pas installées, et le module qui les importe est éliminé du Worker par tree-shaking.

## Hooks Git

`bun install` exécute `prepare`, qui appelle `vp config --no-agent` pour installer le répartiteur de hooks de `.vite-hooks/`. `pre-commit` exécute `bun run check:pre-commit`, et `prepare-commit-msg` exécute `scripts/commit-msg.ts` (voir [Commits conventionnels](/docs/tooling/conventional-commits)). `vp hooks status` indique si les hooks sont actifs dans un clone.

Privilégiez les scripts du paquet ; appelez `vp` directement pour des exécutions ciblées, comme le formatage ou le lint de chemins précis.
