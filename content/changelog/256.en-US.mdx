- Fixed: a new Git worktree gets its commit hooks. `git worktree add` installs the hook dispatcher of the new worktree through the `post-checkout` hook, so a commit made before `bun install` fails in the `pre-commit` hook instead of skipping it, and `bun install` fails when `core.hooksPath` is not `.vite-hooks/_` or when the dispatcher lacks a hook. Until now Git committed without hooks, and without a warning, in every worktree that had no dispatcher of its own. See [Git and pull requests](/docs/conventions/git-workflow#hooks-in-every-worktree).
- Fixed: [Git and pull requests](/docs/conventions/git-workflow#linear-history) no longer tells you to merge `main` into a pull request branch and never to force-push it. It describes the linear history the project follows: no merge commits, not even on a pull request branch, branches brought up to date by rebasing onto `main`, a pull request that GitHub cannot rebase landed again as one commit, and rewritten branches pushed with `git push --force-with-lease`. `AGENTS.md`, `CONTRIBUTING.md` and the [contributing guide](/docs/project/contributing) say the same.
