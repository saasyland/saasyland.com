## Data

`src/modules/category/category.schema.ts` defines the `category` table: `name`, `description`, `kind` (`category` or `collection`), `visibility` (`public` or `hidden`), `icon` (`Archive`, `FolderOpen` or `Puzzle`) and timestamps.

Use cases in `src/modules/category/use-cases`, each behind the matching `category` permission: `getCategories` (paginated, optional `kind`), `getCategory`, `createCategory`, `updateCategory` and `deleteCategory`. No route, component or other use case calls them: only `drizzle.schemas.ts`, which gives Drizzle every table, and a test fixture import the module. It is not a pattern to copy; a use case to copy is one of a module a screen uses, such as `src/modules/course`.

Error messages live in the `category.errors` namespace. No form edits categories yet, so their Zod messages get a `category.validations` namespace with the first form that shows them.

## Admin screen

No screen lists, creates, edits or deletes categories, and products have no category relation. `/admin/products` lists the Polar catalogue (see [Products](/docs/features/products)).
