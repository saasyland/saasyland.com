title: "Noyau partagé"
description: "Les codes d'erreur, les constantes HTTP, les catalogues, les champs Zod et les entrées des cas d'usage de src/modules/_core sur lesquels chaque module est construit."
---

`src/modules/_core` est le seul dossier de module qui ne possède pas de table. Il ne contient que le socle sur lequel reposent les schémas, les schémas Zod et les cas d'usage des modules, afin qu'aucun module ne le redéfinisse : les codes d'erreur, les constantes HTTP et d'environnement, les catalogues des locales, des fuseaux horaires, des pays et des devises avec la devise de la boutique, les champs Zod et les textes localisés partagés, ainsi que les entrées de pagination, d'ordre, de recherche et de période.

## Constantes

| Fichier                 | Contenu                                                                                                                                                                     |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `constants/errors.ts`   | `ERROR_CODES`, le type `ErrorCode` et la classe `AppError`                                                                                                                  |
| `constants/api.ts`      | `HTTP_STATUS`, les noms des en-têtes `cf-ipcountry` et `cf-connecting-ip`, les en-têtes de sécurité, les hôtes autorisés par mode de build                                  |
| `constants/locale.ts`   | Le catalogue `LOCALES`, `LocaleCode`, `getLocaleName` et `getLocaleDirection`                                                                                               |
| `constants/country.ts`  | Le catalogue `COUNTRIES` et `CountryCode`                                                                                                                                   |
| `constants/currency.ts` | Le catalogue `CURRENCIES`, `CurrencyCode`, ainsi que `toMinorUnits` et `fromMinorUnits`, qui convertissent un montant vers la plus petite unité de la devise et inversement |
| `constants/timezone.ts` | Le catalogue `TIMEZONES` et `TimezoneCode`                                                                                                                                  |
| `constants/pricing.ts`  | La devise de la boutique `DEFAULT_CURRENCY_CODE` et le formatage des devises `CURRENCY_FORMAT`                                                                              |
| `constants/ordering.ts` | `FIRST_POSITION`, la place du premier élément d'une liste ordonnée                                                                                                          |

Les catalogues vivent ici parce que le socle repose sur eux : `countryCodeField` et `currencyCodeField`, les schémas des commandes, des produits et des abonnements, les constantes de l'utilisateur et la devise par défaut d'un produit. Le catalogue des locales recense toutes les locales connues ; les locales que l'application sert sont définies par `I18N.SUPPORTED_LOCALES` dans `src/integrations/use-intl/i18n.config.ts`. Les données sur lesquelles ne repose aucun schéma ni aucun cas d'usage vont dans `src/data`, qui ne contient que des constantes et des listes littérales, et les utilitaires génériques dans `src/lib`. Un test de `src/__test__/module-tables.test.ts` échoue quand un fichier de `_core` n'est pas décrit sur cette page : chaque nouveau fichier est donc une décision réfléchie.

## Utilitaires

- `utils/localized-text.ts` : `LocalizedText`, un texte par locale stocké en JSON, `localizedTextSchema`, qui exige `en-US` et accepte au plus <RepositoryFact name="localizedTextMaxLength" /> caractères par texte, et `localize`, qui se rabat sur `en-US`
- `utils/ordering.ts` : `nextPosition`, la `position` la plus haute plus un, et `reorder`, qui déplace un élément vers une place parmi ses voisins, ramène à l'extrémité correspondante une place située au-delà de l'une ou l'autre, numérote la liste à partir de `FIRST_POSITION` et ne renvoie que les éléments dont la `position` change ; les cas d'usage des cours, des chapitres, des leçons et des ressources gardent ainsi `position` sans trou
- `utils/pagination.ts` : `paginationSchema` (`pageIndex`, `pageSize`) et `DEFAULT_PAGE_SIZE`
- `utils/search.ts` : `searchSchema` et `localizedSearchSchema`, l'entrée des cas d'usage de recherche de l'administration, leurs limites de longueur et le `SearchHit` qu'ils renvoient
- `utils/time-series.ts` : `TIME_RANGES` et `timeRangeSchema`, les périodes des graphiques de revenus et d'inscriptions de l'admin, `timeSeries`, les tranches par jour ou par mois d'une période, et `pointsOf`, qui donne zéro à une tranche sans valeur
- `utils/zod-fields.ts` : des champs Zod réutilisables tels que `idField`, `localeField`, `positionField` (un nombre entier à partir de `FIRST_POSITION`) et `slugField`

## Erreurs

Il existe une seule classe d'erreur et une seule liste de codes :

```ts
export const ERROR_CODES = {
  AUTH_API_ERROR: "AUTH_API_ERROR",
  CONFLICT: "CONFLICT",
  FORBIDDEN: "FORBIDDEN",
  INTERNAL_ERROR: "INTERNAL_ERROR",
  NOT_FOUND: "NOT_FOUND",
  TOO_MANY_REQUESTS: "TOO_MANY_REQUESTS",
  UNAUTHORIZED: "UNAUTHORIZED",
  VALIDATION: "VALIDATION",
} as const

export type ErrorCode = (typeof ERROR_CODES)[keyof typeof ERROR_CODES]

export class AppError extends Error {
  readonly code: ErrorCode

  constructor(code: ErrorCode, message: string = code) {
    super(message)
    this.name = "AppError"
    this.code = code
  }
}
```

Les fonctions serveur lèvent des `AppError`. Le middleware `withRequest` normalise tout le reste : les erreurs de l'API Better Auth deviennent `AUTH_API_ERROR` avec la clé d'erreur Better Auth comme message, les erreurs Zod deviennent `VALIDATION`, et les erreurs inconnues sont journalisées puis deviennent `INTERNAL_ERROR`. Dans le navigateur, `useErrorMessage()` de `src/hooks/use-error-message.ts` fait correspondre le message aux traductions `auth.errors.*` ou `errors.codes.*`.
