## Cache de queries

`getRouter` crée un nouveau `QueryClient` pour chaque requête, si bien qu'aucune donnée ne fuit d'un utilisateur à l'autre côté serveur. Valeurs par défaut :

| Paramètre                     | Valeur        |
| ----------------------------- | ------------- |
| `staleTime` des queries       | 1 minute      |
| `gcTime` des queries          | 5 minutes     |
| `defaultStaleTime` du routeur | 1 minute      |
| Préchargement                 | Sur intention |

Les loaders remplissent le cache avec `queryClient.query({ ...options, staleTime: "static" })` et les composants lisent les mêmes clés avec `useSuspenseQuery`. Les pages de cours et l'éditeur de cours de l'administration font exception : leurs requêtes gardent `staleTime: COURSE_STALE_MS` (une minute), car `invalidateQueries` ne recharge jamais une requête `static`, et terminer une leçon ou enregistrer une modification dans l'éditeur doit rafraîchir le programme. `setupRouterSsrQueryIntegration` sérialise le cache du serveur dans le HTML et l'hydrate dans le navigateur.

- **Les messages de traduction** sont mis en cache par locale et par namespace, avec un `staleTime` et un `gcTime` infinis.
- **La query de session** (`getCurrentSessionQuery`) a un `staleTime` d'une minute. Les guards de route la récupèrent à nouveau lors des vraies navigations et vident tout le cache quand l'utilisateur connecté change.
- **Les mutations** invalident les clés de query de leur module, par exemple `USER_QUERY_KEYS.ALL`, une fois qu'elles ont réussi.

## Prérendu

`bun run build` prérend les pages publiques en parcourant les liens : landing page, pages légales, blog et documentation dans les neuf locales. Les chemins sous `/admin`, `/app`, `/auth`, `/courses`, `/newsletter` et `/api` (avec ou sans préfixe de locale) ainsi que les liens comportant une chaîne de requête ou un fragment sont exclus. Les pages de cours sont exclues parce qu'elles affichent les verrous et la progression de chaque spectateur. Le navigateur remplit le bloc des cours de la page d’accueil avec `getCourseShowcase` quand il approche de la zone visible ; la page d’accueil prérendue reste donc la même pour tous (voir [Cours](/docs/features/courses)).

Le Worker sert le HTML prérendu depuis le binding `ASSETS` avant de charger l'application. Une page prérendue ne contient aucune donnée utilisateur : elle peut donc être servie à tout le monde sans risque. Quand un visiteur a droit à la tarification régionale, le Worker réécrit le HTML et marque la réponse `Cache-Control: private, no-cache`.

## KV et D1

- **KV (`CACHE`)** stocke le nombre d'étoiles GitHub pour `src/lib/github.ts` et les remises régionales du paiement pour `src/modules/license/license.ppp.ts`. Un nombre d'étoiles de plus d'une heure est renvoyé immédiatement, puis rafraîchi en arrière-plan avec `waitUntil` ; les remises de plus de cinq minutes sont de nouveau listées depuis Polar.
- **D1 (`DB`)** stocke les sessions et les compteurs de limitation de débit. Les vérifications de session des fonctions serveur contournent le cache de cookies de Better Auth et sont mémoïsées pour le reste de la requête.
- **Le cache des Workers** conserve les fichiers vidéo que `serveMedia` lit depuis R2 sous `/media/_/<videoId>/<file>`, sans la signature, de sorte que les spectateurs d'un même point de présence partagent une seule copie en cache. Voir [Cloudflare R2](/docs/integrations/cloudflare-r2).
- Les fonctions serveur ne prennent jamais de décision de permission à partir de données en cache.
