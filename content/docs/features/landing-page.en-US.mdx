## Route

`src/routes/_landing.index.tsx` composes seventeen sections from `src/presentation/components/custom/landing-page/sections` inside `MotionProvider`: Hero, Proof, Stack, Manifesto, CLI, Line, Quality, Rally, Manifest, Studio, Record, Cases, Compare, Pricing, FAQ, Notes and Gate. Copy comes from the `pages.landing` namespace. The loader also fetches the three latest blog posts (featured first) for the Notes section and warms `starCountQuery`, the GitHub star count cached in KV for the Proof section.

Every other count on the page is measured, not typed: the `virtual:repository-facts` Vite plugin in `scripts/repository-facts.ts` counts the test files, Playwright specs, UI components, admin sections, currencies, timezones and countries, and reads the React and TanStack Table majors, when the site is built. `REPOSITORY_FACTS` in `src/data/repository-facts.ts` adds the languages and CLI questions, and the sections pass it to `pages.landing` messages as ICU arguments such as `{testFiles, number}`.

The `_landing` layout wraps `/`, the legal pages, `/premium` and the newsletter pages with `Navigation`, `PageFrame`, `Footer` and `BackToTop`, always in the dark theme. Section anchors are `MARKETING_SECTION_IDS` in `src/data/marketing.ts` (`foundation`, `cli`, `quality`, `toolkit`, `pricing`, `faq`); links use `<Link to={ROUTES.HOME} hash={MARKETING_SECTION_IDS.PRICING}>`.

## Navigation and back to top

- The logo in the landing, blog and course headers is `HomeLink` (`src/presentation/components/custom/home-link.tsx`). On `/` a click scrolls back to the top and removes a section hash such as `#pricing` from the address, replacing the history entry, instead of reloading the page the visitor is already on. On any other page it is an ordinary link home, and a click with a modifier key still opens a new tab or window.
- `BackToTop` (`src/presentation/components/custom/back-to-top.tsx`) is a React Aria button fixed to the bottom-right corner, labelled from the `components.custom.back-to-top` namespace. An `IntersectionObserver` sentinel shows it once the first screen has scrolled out of view and hides it again near the top, so no code runs on scroll events. Pressing it scrolls to the top and moves focus to the page's `h1`. The landing, blog, course and docs layouts render it.
- Both call `scrollTo({ top: 0 })` and leave the motion to `globals.css`: `html` scrolls smoothly, and under `prefers-reduced-motion: reduce` it jumps straight to the top.

## Pricing and regional pricing

`PricingSection` renders `PricingTiers` from `src/presentation/components/custom/pricing.tsx`, the same tier cards the [customer app](/docs/features/customer-app) shows to accounts without a licence. Each card shows a tier from `TIERS` with its `TIER_PRICES` amount and copy from the `components.custom.pricing` namespace, and its button comes from the page: on the landing page a link to `/auth/sign-up?redirect=/app?tier=<tier>`, so the chosen tier survives sign-up. The grid switches to three columns when its own container is at least 42rem wide (`@container`), so it fits the narrower app column too. Regional pricing works without client JavaScript, so the page stays prerendered:

1. `Price` renders the amount once per regional multiplier (`PPP_KEYS`) plus the struck-through regular price.
2. The Worker (`src/server.ts`) reads `cf-ipcountry`. For a country in `PPP_TIERS` it uses `HTMLRewriter` to set `data-ppp` and the `--ppp-region` and `--ppp-percent` variables on the `html` element, and marks the response `private, no-cache`.
3. CSS in `globals.css` shows the matching price while the regional offer checkbox is checked.
4. Unchecking stores `regional_pricing=off` in a cookie; the Worker and `startCheckout` both respect it.

## CLI configurator

`CliSection` hosts `CliConfigurator` (`landing-page/components/cli-configurator.tsx`). Choices, extras and package managers from `src/data/cli.ts` build a `saasyland@latest init my-app` command with flags, which `CopyButton` copies.

## Newsletter

`Footer` renders `NewsletterForm` (`src/presentation/components/custom/newsletter-form.tsx`):

1. `subscribeToNewsletter` (rate limited) stores a pending `newsletter_subscriber` row and sends `NewsletterConfirmationEmail`. An address that is already subscribed gets `alreadySubscribed` and nothing is written. After three confirmation emails to one address within an hour, it returns `confirmationSent` without writing or sending anything.
2. `/newsletter/confirm?token=` asks the visitor to confirm. Pressing the button calls `confirmNewsletterSubscription`, which confirms the subscription and sends `NewsletterNotificationEmail` to `CONTACT_EMAIL`.
3. `/newsletter/unsubscribe?token=` asks the same way before `unsubscribeFromNewsletter` unsubscribes. Opening or prefetching either link changes nothing, so a mail scanner cannot subscribe or unsubscribe anyone. No email links to `/newsletter/unsubscribe`: `unsubscribeUrl` in `newsletter-subscriber.utils.ts` builds the link, but nothing calls it.

## Admin screen (demo)

`/admin/landing-page` is a static builder mock: a section list, a canvas and a properties panel built from constants. It does not change the landing page.
