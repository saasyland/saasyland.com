Płatności przechodzą przez Polar za pomocą wtyczki `@polar-sh/better-auth`, którą obszar Polar dodaje do Better Auth w `src/data/polar.auth-plugins.ts`:

```ts
export const POLAR_AUTH_PLUGINS = [
  {
    disabledPaths: [],
    plugin: polar({
      client: polarCore,
      use: [portal(), webhooks({ onPayload: handlePolarEvent, secret: env.POLAR_WEBHOOK_SECRET })],
    }),
    rateLimitExemptPaths: [ROUTES.API_AUTH_POLAR.WEBHOOKS],
  },
] as const satisfies readonly AuthPluginEntry[]
```

Wtyczka dodaje portal klienta i webhooki, wyłączone z limitera żądań Better Auth, ale nie sesję płatności: jej `checkout()` tworzyłby sesję płatności tylko z identyfikatorem konta, więc Polar ponownie pytałby zalogowanego kupującego o adres e-mail. Obszar, który sprzedaje, tworzy swoje sesje płatności za pomocą SDK Polar po własnych sprawdzeniach, tak jak robi to `startCheckout` obszaru licencji (zobacz [Licencje](/docs/features/licences)).

`src/integrations/polar/polar.config.ts` tworzy z `POLAR_ACCESS_TOKEN` i `POLAR_SERVER` klienta `polarCore`, którego używa wtyczka, oraz `polar`, czyli zbudowane na nim usługi sesji płatności, rabatów, kluczy licencyjnych i zamówień. `POLAR_ORGANIZATION_ID` zawęża do organizacji każde wywołanie Polar, które ją wskazuje; wymienia je strona [Środowisko i bindingi](/docs/reference/environment). `src/integrations/polar/polar.constants.ts` przechowuje własne wartości Polar, `POLAR_ORDER_STATUS`, `POLAR_LICENSE_KEY_STATUS`, `POLAR_WEBHOOK_EVENT` i `POLAR_CHECKOUT_ID_PLACEHOLDER`, każdą sprawdzaną względem typów SDK; nie odczytuje środowiska, więc importują go też przeglądarka i zestaw testów przeglądarkowych. Ścieżki obszaru Polar, `API_AUTH_POLAR` i `API_AUTH_CUSTOMER_PORTAL`, znajdują się w `src/data/polar.routes.ts`. [Konfiguracja Polar](/docs/getting-started/polar-setup) opisuje produkty, klucze licencyjne, rabaty, webhook i token, których ten kod oczekuje w Polar, a `bun run polar:verify:<environment>` je sprawdza.

## Webhooki [#webhooks]

Polar wysyła zdarzenia do `/api/auth/polar/webhooks`. Wtyczka weryfikuje podpis za pomocą `POLAR_WEBHOOK_SECRET` i przekazuje każde zdarzenie do `handlePolarEvent` w `src/data/polar-events.ts`. Obszar, który reaguje na zdarzenia Polar, deklaruje listę w `src/data/<area>.polar-events.ts` i dodaje ją do `src/data/polar-events.entries.ts`. Każdy wpis wskazuje zdarzenia, które obsługuje, i funkcję, która je obsługuje:

```ts
export interface PolarEventHandler {
  readonly events: readonly models.WebhookEventType[]
  readonly handle: (event: webhooks.WebhookPayload) => Promise<void>
}
```

- `handlePolarEvent` uruchamia jednocześnie `handle` każdego wpisu, który wymienia typ zdarzenia, i czeka na wszystkie.
- Gdy któryś z nich zostanie odrzucony, wtyczka odpowiada kodem 500, a Polar później dostarcza zdarzenie ponownie, więc każdy handler musi bezpiecznie obsłużyć to samo zdarzenie dwa razy. Polar wyłącza endpoint, który ciągle zawodzi, a `polar:verify` zgłasza wyłączony endpoint.
- Zdarzenie, którego nie wymienia żaden wpis, jest potwierdzane i nigdzie nie trafia.
- `POLAR_EVENTS` łączy zdarzenia wszystkich wpisów, posortowane i każde tylko raz. Endpoint webhooka w Polar musi wysyłać dokładnie te zdarzenia, a `polar:verify` je porównuje.
- Obszar Polar dodaje pustą listę w `src/data/polar.polar-events.ts`, więc zbiorczy eksport nigdy nie jest pusty. Obecnie zdarzenia obsługuje tylko obszar licencji, w `src/data/license.polar-events.ts`; zobacz [Licencje](/docs/features/licences#webhooks-and-licences).

`polar:verify` działa w Bun, poza Workerem, i odczytuje `POLAR_EVENTS`, więc ani `src/data/polar-events.ts`, ani żaden `<area>.polar-events.ts` nie importuje kodu serwerowego. `handle` obszaru ładuje jego handlery dopiero, gdy przychodzi zdarzenie:

```ts
const { licenseWebhookHandlers } = await import("~/src/modules/license/license.webhooks")
```

`src/data/__test__/polar-events.test.ts` importuje `src/data/polar-events.ts` w Bun i kończy się błędem, gdy ten import sięga do środowiska uruchomieniowego Workera.

## Portal klienta

`ROUTES.API_AUTH_CUSTOMER_PORTAL` (`/api/auth/customer/portal`) otwiera portal klienta Polar zalogowanego konta. Prowadzi do niego karta licencji na `/app/license`.

## Ekran administracyjny (demonstracyjny)

`/admin/payments` wyświetla `RefundStats` i `DataTable` zwrotów z danymi `ADMIN_PAYMENT_ROWS` z `src/data/admin-payments.ts`; jego przyciski nie są podłączone. Obszar płatności deklaruje uprawnienia `order` (`read`, `update`, `refund`) w `src/data/payments.access.ts`, ale żaden przypadek użycia nie odczytuje zamówień ani zwrotów.
