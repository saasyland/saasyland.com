description: "絞り込み、非表示と固定のカラム、CSV の値を持つカラムのフックを書き、クライアントサイドの行かサーバーのクエリから DataGrid でレンダリングします。"
---

新しいテーブルはすべて、`src/presentation/components/custom/data-grid.tsx` の `DataGrid` でレンダリングします（[データグリッド](/docs/ui/data-grid)）。検索、絞り込み、並べ替え、管理者ごとに並べ替えて保持できるレイアウト、選択、CSV の書き出し、スケルトン行、空の状態がすべて含まれています。テーブルに必要なのは、カラムのフックと 1 つの `<DataGrid />` だけです。完全な例は `/admin/orders` で、`src/presentation/components/custom/admin/payments/order-columns.tsx` と `src/routes/admin.orders.index.tsx` です。

## 1. カラムのフックを書く

ページの他のウィジェットの隣に `<entity>-columns.tsx` を作成します。翻訳と、絞り込みが選択肢として示すデータを読み込み、カラムをメモ化して返すフックをエクスポートします。セルは同じファイル内の小さなコンポーネントで、自分の翻訳を自ら読み込みます。`order-columns.tsx` を簡略化した例です。

```tsx
const columnHelper = createColumnHelper<DataGridFeatures, OrderRow>()

export const useOrderColumns = (): DataGridColumn<OrderRow>[] => {
  const t = useTranslations()

  const { products } = useSuspenseQuery(orderFiltersQuery).data

  return useMemo(
    () =>
      columnHelper.columns([
        columnHelper.accessor("placedAt", {
          cell: PlacedCell,
          header: t("pages.admin.orders.table.headers.placedAt"),
          meta: { filter: { kind: DATA_GRID_FILTER.DATE_RANGE }, pinned: DATA_GRID_PIN.START },
          size: ORDER_COLUMN_SIZES.placedAt,
        }),
        columnHelper.accessor("description", {
          cell: ProductCell,
          enableSorting: false,
          header: t("pages.admin.orders.table.headers.product"),
          id: "product",
          meta: { filter: { kind: DATA_GRID_FILTER.MULTI_SELECT, options: products.map(({ id, name }) => ({ label: name, value: id })) } },
          size: ORDER_COLUMN_SIZES.product,
        }),
        columnHelper.accessor("refunded", {
          cell: RefundedCell,
          header: t("pages.admin.orders.table.headers.refundedAmount"),
          id: "refundedAmount",
          meta: { export: ({ refunded }) => exportedMoney(refunded), hidden: true },
          size: ORDER_COLUMN_SIZES.refundedAmount,
        }),
      ]),
    [products, t],
  )
}
```

- 行には文字列の `id` が必要です。これが選択に使う行 ID になります。
- `header` は翻訳済みのラベルの文字列です。グリッドはこれをヘッダー、メニュー、絞り込みのチップ、読み上げ、CSV に使います。
- `meta.filter` はカラムに 1 種類の絞り込みを与えます。種類は <RepositoryFact name="dataGridFilterKinds" /> です。選択式の場合は `options` を `{ label, value }` 形式で列挙します。
- `meta.hidden` は管理者が表示するまでカラムを非表示にし、`meta.pinned` はカラムを `start` または `end` に固定し、`meta.export` は行ごとのカラムの CSV テキストを書きます。
- `size` はピクセル単位の初期幅です。サイズは `src/data/<feature>.ts` の 1 つの定数にまとめます。`payments.ts` の `ORDER_COLUMN_SIZES` がその例で、ルートのスケルトンでも使えるようにするためです。
- サーバーが並べ替えに対応していないカラムには `enableSorting: false` を指定します。

## 2. レンダリングする

カラム、一意の `id`、テーブルの `label`、そして `data` か `query` のどちらかを渡します。

```tsx
const OrdersPage = (): JSX.Element => {
  const t = useTranslations("pages.admin.orders")
  const columns = useOrderColumns()

  return (
    <DataGrid
      columns={columns}
      empty={t("empty")}
      id={ORDER_GRID_ID}
      label={t("title")}
      query={(request) => getOrdersPageQuery(orderZodSchemas.getOrders.parse(request))}
      search={t("filters.search")}
      selectable
    />
  )
}
```

`data` を渡すと、グリッドはブラウザで行の検索、絞り込み、並べ替え、ページ分割を行います。`query` を渡すと `{ filters, pageIndex, pageSize, search, sorting }` を送信し、そのすべてをサーバーが行います。

## 3. サーバーでリクエストを読み取る

モジュールの Zod スキーマは、リクエストをそのまま受け取ります。`filters` には、絞り込んだカラムが id ごとに、[データグリッド](/docs/ui/data-grid#filters) で説明している値とともに入っています。そのため、スキーマは共有のフィールドを再利用します。`src/modules/order/order.zod.ts` の例です。

```ts
const orderFilters = zod.object({
  country: zod.array(countryCodeField).max(COUNTRY_CODES.length).optional(),
  customer: searchField.optional(),
  discount: idField.optional(),
  placedAt: dateRangeField.optional(),
  product: zod.array(idField).max(MAX_FILTER_VALUES).optional(),
  status: zod.array(choiceOf(ORDER_STATUSES)).max(ORDER_STATUSES.length).optional(),
  totalAmount: numberRangeField.optional(),
})

const getOrders = paginationSchema.extend({
  filters: orderFilters.default({}),
  search: searchField.default(""),
  sorting: sortingOf(ORDER_SORT_COLUMNS),
})
```

`numberRangeField`、`dateRangeField`、そして上限の `SEARCH_MAX_LENGTH`、`MAX_SORTED_COLUMNS`、`MAX_FILTER_VALUES` は `src/modules/_core/utils/` にあり、グリッドが使うのと同じ値です。そのため、検索ボックスには <RepositoryFact name="dataGridSearchMaxLength" /> 文字まで入力でき、グリッドは最大 <RepositoryFact name="dataGridMaxSortedColumns" /> カラムで並べ替えます。`getOrders` は各絞り込みを SQL に変換します。金額の範囲は、`inMinorUnits` を使って各注文をその注文自身の通貨で比較します。

ルートのローダーで `context.queryClient.query({ ...getOrdersQuery, staleTime: "static" })` を使い、最初のページをプリフェッチします。グリッドの最初のリクエストはパースすると同じクエリキーになります。

## 4. スケルトンに反映する

ルートの `pendingComponent` は、`data-grid-pending.tsx` の `DataGridPending` を、表示するカラムごとに 1 つのセルのスケルトンと幅を指定してレンダリングします。`payments-pending.tsx` の `AdminOrdersPending` がその例です。

## 5. メッセージ

グリッドのツールバー、絞り込み、メニュー、ページネーション、選択、空の状態の文言は、すべてのページで読み込まれる `components.custom.data-grid` から取得されます。カラムのラベル、絞り込みの選択肢、空のときのメッセージは、`pages.admin.orders` のようにページの名前空間に置きます。

ミューテーションによって行が変わったら、モジュールのクエリキーを無効化します。グリッドは現在のページを再取得します。[ユースケースを追加する](/docs/guides/add-a-use-case)を参照してください。
