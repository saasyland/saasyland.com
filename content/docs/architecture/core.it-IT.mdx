---

`src/modules/_core` è l'unica cartella di modulo che non possiede una tabella. Contiene solo le fondamenta su cui si costruiscono gli schemi, gli schemi Zod e i casi d'uso dei moduli, così nessun modulo deve ridefinirle: i codici di errore, le costanti HTTP e di ambiente, i campi Zod e i testi localizzati condivisi, e gli input di paginazione, ordinamento e ricerca.

## Costanti

| File                    | Contenuto                                                                                                                                       |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `constants/errors.ts`   | `ERROR_CODES`, il tipo `ErrorCode` e la classe `AppError`                                                                                       |
| `constants/api.ts`      | `HTTP_STATUS`, i nomi degli header `cf-ipcountry` e `cf-connecting-ip`, gli header di sicurezza, gli host consentiti per ogni modalità di build |
| `constants/ordering.ts` | `FIRST_POSITION`, la posizione del primo elemento di un elenco ordinato                                                                         |

I dati e gli helper che i moduli usano senza costruirci sopra stanno fuori da `_core`: i cataloghi di paesi, valute, locale e fusi orari in `src/data/countries.ts`, `src/data/currencies.ts`, `src/data/locales.ts` e `src/data/timezones.ts`, la valuta del negozio e il formato dei prezzi in `src/data/pricing.ts`, e i periodi e gli intervalli dei grafici dell'amministrazione in `src/lib/time-series.ts`. Il catalogo dei locale elenca tutti i locale conosciuti; i locale serviti dall'applicazione sono definiti da `I18N.SUPPORTED_LOCALES` in `src/integrations/use-intl/i18n.config.ts`. Un test in `src/__test__/module-tables.test.ts` fallisce quando un file di `_core` non è descritto in questa pagina, così ogni nuovo file è una scelta consapevole.

## Utility

- `utils/localized-text.ts`: `LocalizedText`, un testo per locale salvato come JSON, `localizedTextSchema`, che richiede `en-US` e ammette al massimo <RepositoryFact name="localizedTextMaxLength" /> caratteri per testo, e `localize`, che ripiega su `en-US`
- `utils/ordering.ts`: `nextPosition`, la `position` più alta più uno, e `reorder`, che sposta un elemento in una posizione tra i suoi fratelli, riporta all'estremità corrispondente una posizione oltre l'una o l'altra, numera l'elenco a partire da `FIRST_POSITION` e restituisce solo gli elementi la cui `position` cambia; i casi d'uso di corsi, capitoli, lezioni e materiali li usano per mantenere `position` senza buchi
- `utils/pagination.ts`: `paginationSchema` (`pageIndex`, `pageSize`) e `DEFAULT_PAGE_SIZE`
- `utils/search.ts`: `searchSchema` e `localizedSearchSchema`, l'input dei casi d'uso di ricerca dell'amministrazione, i loro limiti di lunghezza e il `SearchHit` che restituiscono
- `utils/zod-fields.ts`: campi Zod riutilizzabili come `idField`, `localeField`, `positionField` (un numero intero a partire da `FIRST_POSITION`) e `slugField`

## Errori

Esistono una sola classe di errore e un solo elenco di codici:

```ts
export const ERROR_CODES = {
  AUTH_API_ERROR: "AUTH_API_ERROR",
  CONFLICT: "CONFLICT",
  FORBIDDEN: "FORBIDDEN",
  INTERNAL_ERROR: "INTERNAL_ERROR",
  NOT_FOUND: "NOT_FOUND",
  TOO_MANY_REQUESTS: "TOO_MANY_REQUESTS",
  UNAUTHORIZED: "UNAUTHORIZED",
  VALIDATION: "VALIDATION",
} as const

export type ErrorCode = (typeof ERROR_CODES)[keyof typeof ERROR_CODES]

export class AppError extends Error {
  readonly code: ErrorCode

  constructor(code: ErrorCode, message: string = code) {
    super(message)
    this.name = "AppError"
    this.code = code
  }
}
```

Le server function lanciano `AppError`. Il middleware `withRequest` normalizza tutto il resto: gli errori delle API di Better Auth diventano `AUTH_API_ERROR` con la chiave di errore di Better Auth come messaggio, gli errori Zod diventano `VALIDATION` e gli errori sconosciuti vengono registrati nei log e diventano `INTERNAL_ERROR`. Nel browser, `useErrorMessage()` di `src/hooks/use-error-message.ts` associa il messaggio alle traduzioni `auth.errors.*` o `errors.codes.*`.
