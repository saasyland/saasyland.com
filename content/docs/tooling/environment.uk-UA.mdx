`wrangler.jsonc` визначає чотири середовища. `CLOUDFLARE_ENV` вибирає одне з них для dev-сервера та збірок, і кожне зчитує секрети з власного файлу середовища:

| Середовище    | Вибирається через                             | Прив'язки                           | Секрети з          |
| ------------- | --------------------------------------------- | ----------------------------------- | ------------------ |
| `development` | `bun run dev`                                 | Віддалені D1 і KV preview           | `.env.development` |
| `preview`     | `build:preview`, `deploy:preview`             | D1 і KV preview                     | `.env.preview`     |
| `production`  | `build:production`, `deploy:production`       | Продакшн D1 і KV                    | `.env.production`  |
| `test`        | `build:test`, `start:test`, `db:migrate:test` | Локальні D1 і KV у `.wrangler/test` | `.env.test`        |

`.env.development`, `.env.preview` і `.env.production` ігноруються Git; `.env.example` перелічує їхні ключі. `.env.test` закомічено, і він містить лише фіктивні значення. Скрипти розгортання завантажують відповідний файл через `wrangler deploy --secrets-file`.

## Секрети

Кожне середовище перелічує свої секрети в `secrets.required`: ключі Better Auth, OAuth, Resend і Polar, а також `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID` і `CLOUDFLARE_ACCESS_TOKEN` для інструментів Drizzle (середовище `test` ці три не містить). Опис кожного ключа див. у розділі [Змінні середовища](/docs/getting-started/environment-variables).

Серверний код зчитує секрети через `import { env } from "cloudflare:workers"`. Жоден код не використовує змінних `VITE_`, і жодна з них не може містити секрет, бо Vite відкриває їх браузеру. `scripts/verify-build.ts` зупиняє збірку, коли клієнтський ресурс імпортує `cloudflare:workers`. Канонічний домен береться з `APP_DOMAIN` у `src/presentation/branding/index.ts`, а не зі змінної середовища.

## Прив'язки

| Прив'язка | Тип              | Використання                                               |
| --------- | ---------------- | ---------------------------------------------------------- |
| `DB`      | D1               | База даних застосунку, сесії та ліміти частоти запитів     |
| `CACHE`   | KV               | Кількість зірок на GitHub                                  |
| `ASSETS`  | Статичні ресурси | Попередньо відрендерені сторінки, шрифти та публічні файли |

Під час розробки використовуються віддалені прив'язки Cloudflare, тож `bun run dev` читає та записує базу даних preview. Після зміни прив'язок запустіть `bun run cf-typegen`, щоб перегенерувати `src/types/worker-configuration.d.ts`.

## Тести

Vitest завантажує `.env.test` через `test.env` і розв'язує `cloudflare:workers` у `src/platform/testing/mocks/cloudflare.ts`, який надає D1 і KV у пам'яті. Playwright використовує середовище `test` і його точку входу `src/platform/testing/worker.ts`. Жодному з них не потрібні справжні облікові дані.
