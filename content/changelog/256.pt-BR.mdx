- Corrigido: uma worktree nova do Git recebe os hooks de commit. `git worktree add` instala o dispatcher de hooks da nova worktree pelo hook `post-checkout`, então um commit feito antes de `bun install` falha no hook `pre-commit` em vez de pulá-lo, e `bun install` falha quando `core.hooksPath` não é `.vite-hooks/_` ou quando falta um hook ao dispatcher. Até agora o Git fazia commits sem hooks, e sem aviso, em toda worktree que não tinha o próprio dispatcher. Veja [Git e pull requests](/docs/conventions/git-workflow#hooks-in-every-worktree).

A página descreve o histórico linear que o projeto segue: nenhum commit de merge, nem na branch de um pull request, branches atualizadas com rebase sobre `main`, um pull request que o GitHub não consegue rebasear integrado de novo como um único commit e branches reescritas enviadas com `git push --force-with-lease`. `AGENTS.md`, `CONTRIBUTING.md` e a página [Como contribuir](/docs/project/contributing) dizem o mesmo.
