## Seiten-Request

1. **Kanonisierung der Locale.** `src/server.ts` ruft `resolveLocale` für `GET`- und `HEAD`-Dokument-Requests außerhalb von `/api` und `/_serverFn` auf. Ein reines Sprachpräfix oder ein Präfix der Standard-Locale (`/pl/docs`, `/en-US/docs`) wird mit `308` auf seine kanonische Form (`/pl-PL/docs`, `/docs`) umgeleitet. Weicht die Locale der URL vom Locale-Cookie ab, wird das Cookie in der Antwort aktualisiert.
2. **Statische Assets zuerst.** Der Worker fragt das Binding `ASSETS` nach dem Pfad. Statische Dateien werden unverändert zurückgegeben, und eine vorgerenderte Seite wird durch `withNonce` gestreamt, das eine für diese Antwort erzeugte Nonce auf ihre Skripte setzt. Erst bei einem `404` lädt er den TanStack-Start-Handler per dynamischem `import()`.
3. **Routing.** `getRouter` erstellt einen neuen Router und einen neuen `QueryClient`. Das `rewrite` des Routers entfernt das Locale-Präfix, sodass `/pl-PL/docs` auf die `/docs`-Routen passt.
4. **Root-`beforeLoad`** lädt die Root-Übersetzungs-Namespaces vor (`common`, `components.*`, `errors*`).
5. **Guards.** `beforeLoad`-Funktionen von Layouts wie `requireAdmin` laden die Session-Query und leiten um, wenn der Zugriff nicht erlaubt ist.
6. **Loader** laufen parallel. Jeder lädt seine Namespaces, Seitenmetadaten und Queries in den `QueryClient` des Requests vor.
7. **Rendering.** Die Root-Shell rendert `<html lang dir>` und umschließt den Body mit `TranslationsProvider`. Der Query-Cache wird ins HTML serialisiert, damit der Browser dieselben Daten nicht erneut abruft.
8. **Response-Header.** Bei HTML-Antworten fügt der Worker einen `Link`-Preload-Header für die Schriften der Locale hinzu, setzt bei Bedarf das Locale-Cookie und wendet die Attribute für regionale Preise an, wenn der Header `cf-ipcountry` für einen Rabatt qualifiziert. Danach erhält jede Antwort, die der Worker zurückgibt, die Sicherheits-Header (`SECURITY_HEADERS`, dazu `HTTPS_SECURITY_HEADERS` über HTTPS, aus `src/modules/_core/constants/api.ts`), die jeden bereits gesetzten Wert ersetzen. Eine HTML-Antwort erhält stattdessen `documentPolicy` als Content Security Policy, mit der Nonce, die `src/server.ts` für sie erzeugt hat, und ist `private, no-cache` ohne `ETag` oder `Last-Modified`, sodass ein Browser sie nie mit der Nonce einer anderen Antwort wiederverwendet.
9. **Hydration.** Der Browser hydratisiert mit dem serialisierten Cache. Spätere Navigationen führen Guards und Loader im Browser aus und holen Daten über Server Functions.

## Aufruf einer Server Function

1. Der Browser ruft die Server Function auf, die der Build durch einen RPC-Request an `/_serverFn/…` ersetzt hat. Der Worker überspringt für diesen Pfad die Locale-Verarbeitung. Die URL hat kein Locale-Präfix, daher gibt `getCurrentLocale()` auf dem Server `en-US` zurück; eine Server Function, die die Locale braucht, erhält sie als Eingabe.
2. Die Middleware läuft in der deklarierten Reihenfolge. `withRequest` erfasst die Request-Header und normalisiert Fehler, `withRateLimit` zählt den Versuch in D1, und `authorized` lädt die Session und prüft die Berechtigung.
3. Der Validator parst die Eingabe mit dem Zod-Schema des Moduls.
4. Der Handler fragt D1 ab oder ruft einen Provider auf und gibt einfache Daten zurück.
5. Die Komponente erhält die Daten oder einen `AppError`-Code. Bei Erfolg invalidiert sie die Query-Keys des Moduls; bei einem Fehler zeigt sie `useErrorMessage()(error)` an.

```text
GET /pl-PL/admin/users/all
  src/server.ts        resolveLocale, ASSETS lookup, TanStack Start handler
  router rewrite       /admin/users/all
  __root beforeLoad    root namespaces
  /admin beforeLoad    requireAdmin
  loaders              metadata, namespaces, queries
  SSR                  HTML with serialized query cache
  src/server.ts        Link header, locale cookie, regional pricing, security headers

POST /_serverFn/…
  withRequest → withRateLimit → authorized → validator → handler → data or AppError
```

## Medien-Request

`src/server.ts` prüft den Pfad vor allem anderen: Ein Pfad, den der Request-Handler eines Bereichs beansprucht, geht an diesen Handler und überspringt die Locale-Verarbeitung, die Abfrage von `ASSETS` und TanStack Start. Der Kursbereich beansprucht `/media/`, und sein Handler lädt, jeweils per dynamischem `import()`, `serveCover` (`src/modules/course/course.delivery.ts`) für `/media/covers/`, `serveAttachment` für `/media/downloads/` und `serveMedia` (`src/modules/video/video.delivery.ts`) für jeden anderen Pfad. Titelbilder tragen keine Signatur, und `serveCover` antwortet aus dem Workers-Cache oder aus R2; `serveAttachment` prüft die Signatur eines Downloads und liest ihn aus R2. `serveMedia` prüft Signatur und Ablaufzeit im Pfad und antwortet dann aus dem Workers-Cache oder aus R2, auch auf `Range`-Requests. Der Kursbereich beansprucht außerdem `/sitemap-courses.xml`, dessen Handler `serveCourseSitemap` aus derselben Datei lädt und die Kurs-Sitemap aus D1 schreibt (siehe [Kurs-Sitemap](/docs/features/seo#course-sitemap)). Der Lizenzbereich beansprucht auf dieselbe Weise `/bundles/`, und sein Handler lädt `serveBundle` (`src/modules/license/license.delivery.ts`), das Signatur und Ablaufzeit prüft und das Vorlagen-Bundle der CLI aus R2 streamt. Die Antwort erhält dieselben Sicherheits-Header wie jede andere. Siehe [Cloudflare R2](/docs/integrations/cloudflare-r2).
