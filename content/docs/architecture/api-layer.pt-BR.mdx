---
title: "Handlers HTTP do TanStack Start"
description: "Os endpoints HTTP em /api e quando criar um deles em vez de uma server function."
---

As operações da própria aplicação são server functions. Handlers HTTP existem apenas quando algo fora do cliente RPC da aplicação chama uma URL: o cliente de navegador do Better Auth, os provedores OAuth, os webhooks do Polar e a caixa de busca da documentação.

| Arquivo                    | Caminho       | Métodos   | Responsável por                                                                                                                                     |
| -------------------------- | ------------- | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/routes/api/index.ts`  | `/api`        | GET       | Uma resposta de status em JSON `{ runtime: "cloudflare-workers" }`                                                                                  |
| `src/routes/api/auth.$.ts` | `/api/auth/*` | GET, POST | Todos os endpoints do Better Auth, incluindo os callbacks OAuth, a verificação de e-mail, o portal do cliente do Polar e `/api/auth/polar/webhooks` |
| `src/routes/api/search.ts` | `/api/search` | GET       | A busca do Fumadocs na documentação                                                                                                                 |

Um handler é declarado com `server.handlers` em `createFileRoute`. Ele recebe o `Request` da Web e retorna uma `Response`:

```ts
import { createFileRoute } from "@tanstack/react-router"

import { auth } from "~/src/integrations/better-auth/auth.server"

export const Route = createFileRoute("/api/auth/$")({
  server: { handlers: { GET: ({ request }) => auth.handler(request), POST: ({ request }) => auth.handler(request) } },
})
```

## Regras

- Não adicione um endpoint REST para uma operação que só esta aplicação chama. Escreva um caso de uso com `createServerFn`; ele ganha entrada tipada, middleware e query options.
- Um handler valida a própria entrada e verifica as permissões por conta própria. O middleware das server functions (`authorized`, `withRateLimit`) não roda para handlers.
- Mantenha a verificação específica de cada fornecedor na integração. As assinaturas dos webhooks do Polar são verificadas pelo plugin do Polar dentro do Better Auth, não por um handler próprio.
- Caminhos em `/api` nunca são localizados, nunca são pré-renderizados e ficam de fora do tratamento de locale do Worker.
