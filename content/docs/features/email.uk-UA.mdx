## Шаблони

Шаблони розташовані в `src/presentation/emails`. Кожен файл містить лише розмітку та експортує константу свого простору імен:

| Шаблон                           | Простір імен                              | Надсилає                                                                                                  |
| -------------------------------- | ----------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `VerifyEmail`                    | `emails.verify-email`                     | `sendVerifyEmail` (хук Better Auth)                                                                       |
| `ResetPasswordEmail`             | `emails.reset-password-email`             | `sendResetPasswordEmail` (хук Better Auth)                                                                |
| `ChangeEmailConfirmationEmail`   | `emails.change-email-confirmation-email`  | `sendChangeEmailConfirmationEmail` (хук Better Auth)                                                      |
| `ExistingAccountEmail`           | `emails.existing-account-email`           | `sendExistingAccountEmail` (`onExistingUserSignUp` з Better Auth)                                         |
| `PasswordChangedEmail`           | `emails.password-changed-email`           | `sendPasswordChangedEmail` (`onPasswordReset` з Better Auth, хук `password-change-notice`, `setPassword`) |
| `DeleteAccountEmail`             | `emails.delete-account-email`             | `sendDeleteAccountEmail` (`sendDeleteAccountVerification` з Better Auth)                                  |
| `InvitationEmail`                | `emails.invitation-email`                 | `sendInvitationEmail` (`createInvitation`, `resendInvitation`)                                            |
| `NewsletterConfirmationEmail`    | `emails.newsletter-confirmation-email`    | `subscribeToNewsletter`                                                                                   |
| `NewsletterNotificationEmail`    | `emails.newsletter-notification-email`    | `confirmNewsletterSubscription`, на `CONTACT_EMAIL`                                                       |
| `PurchaseConfirmationEmail`      | `emails.purchase-confirmation-email`      | `sendPurchaseConfirmationEmail` (`order.paid` від Polar)                                                  |
| `UnmatchedOrderAlertEmail`       | `emails.unmatched-order-alert-email`      | `sendUnmatchedOrderAlert` (`order.paid` від Polar), на `CONTACT_EMAIL`                                    |
| `WithdrawalAcknowledgementEmail` | `emails.withdrawal-acknowledgement-email` | `sendWithdrawalAcknowledgement` (`submitWithdrawal`)                                                      |
| `WithdrawalNotificationEmail`    | `emails.withdrawal-notification-email`    | `sendWithdrawalNotification` (`submitWithdrawal`), на `CONTACT_EMAIL`                                     |

Шаблон отримує `locale` і `messages` та перекладає через `createTranslator` з use-intl:

```tsx
const t = createTranslator({ locale, messages: { emails: { "verify-email": messages } }, namespace: "emails.verify-email" })
```

Листи облікового запису починаються з `EmailBrandHeader`, назви застосунку, а під кнопкою містять `EmailFallbackLink`: те саме посилання звичайним текстом для поштових клієнтів, які приховують кнопки. Листи підтвердження адреси, скидання пароля, зміни пошти й видалення облікового запису вказують, скільки діє їхнє посилання, з `EMAIL_LINK_LIFETIME_HOURS` — значення, з яким налаштовано Better Auth.

## Надсилання

Сценарій використання бере мову й `redirect` з callback-URL, який передає Better Auth, перевіряє ліміт на одержувача, завантажує повідомлення, рендерить шаблон і надсилає його (`src/modules/verification/use-cases/send-verify-email.ts`):

```ts
if (!(await withinRecipientRateLimit({ kind: EMAIL_PURPOSE.VERIFY_EMAIL, recipient: user.email }))) {
  console.warn("[email] verification email not sent: the recipient reached the hourly limit")
  return
}
const callback = new URL(callbackURL, getRequest().url)
const locale = extractLocaleFromPath(callback.pathname) ?? I18N.DEFAULT_LOCALE
const verifyUrl = new URL(localizePathname({ locale, pathname: ROUTES.VERIFY_EMAIL }), getRequest().url)
verifyUrl.search = callback.search
verifyUrl.searchParams.set("token", token)

const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotency: { purpose: EMAIL_PURPOSE.VERIFY_EMAIL, token: crypto.randomUUID() },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```

`sendEmail` (`src/integrations/resend/resend.utils.ts`) надсилає через Resend з адреси `RESEND_EMAIL_FROM`, якщо не вказано `from` (сповіщення власнику, сповіщення про замовлення без облікового запису та сповіщення про відмову від договору використовують `NOTIFICATIONS_EMAIL`), передає ключ ідемпотентності й кидає помилку в разі невдачі.

Листи облікового запису використовують мову сторінки, на якій почався сценарій, прочитану з `callbackURL` у посиланні листа; для повторної реєстрації вона береться з `callbackURL` запиту реєстрації. Сценарій, у якому немає callback-адреси, тобто вхід у непідтверджений обліковий запис або скидання пароля, бере мову й `redirect` зі сторінки, що надіслала запит (з її `Referer`, якщо вона на цьому сайті). Листи розсилки використовують мову, передану з формою; сповіщення власнику завжди надсилається мовою `en-US`. Підтвердження покупки використовує мову, яку `startCheckout` зберіг у метаданих замовлення, а якщо її немає — англійську; воно підтверджує згоду покупця на негайне надання на довговічному носії, див. [Ліцензії](/docs/features/licences#purchase-confirmation). Сповіщення про замовлення без облікового запису, яке повідомляє сайт про оплачене замовлення ліцензії, клієнт якого не відповідає жодному обліковому запису, надсилається мовою `I18N.DEFAULT_LOCALE`, див. [Ліцензії](/docs/features/licences#orders-that-match-no-account). Підтвердження отримання відмови від договору використовує мову сторінки, з якої подано заяву, а сповіщення сайту про відмову від договору надсилається мовою `I18N.DEFAULT_LOCALE`, див. [Ліцензії](/docs/features/licences#withdrawal-function). Лист із запрошенням використовує мову, яку для нього вибрав адміністратор і яку збережено в `locale` запрошення.

`withinRecipientRateLimit` (`src/lib/rate-limit.ts`) обмежує кількість листів кожного виду (підтвердження адреси, скидання пароля, наявний обліковий запис, видалення облікового запису, підтвердження розсилки й підтвердження отримання відмови від договору) на адресу за годину до <RepositoryFact name="recipientEmailsPerHour" />, з підрахунком у таблиці `rate_limit` за хешем SHA-256 адреси. Понад ліміт лист пропускається, а запит усе одно отримує звичайну відповідь. Підтвердження зміни пошти, повідомлення про зміну пароля, сповіщення власнику, підтвердження покупки, сповіщення про замовлення без облікового запису й сповіщення про відмову від договору не обмежено; для зміни пароля потрібен токен скидання або поточний пароль, підтвердження покупки й сповіщення про замовлення без облікового запису запускає вебхук Polar, а не відвідувач, один раз на замовлення, а сповіщення про відмову від договору надходить лише сайту, не більше <RepositoryFact name="sensitiveRateLimit" /> на клієнта за хвилину. Лист із запрошенням підпадає під те саме обмеження, але після його перевищення `sendInvitationEmail` завершується помилкою `TOO_MANY_REQUESTS`, а не пропускає лист.
