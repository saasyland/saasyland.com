---
title: "Contribuir"
description: "Cómo proponer cambios en SaaSy Land."
---

1. Comente primero los cambios importantes en un issue, abierto desde el formulario de informe de error o de solicitud de funcionalidad.
2. Cree una rama a partir de `main`.
3. Siga las [convenciones](/docs/conventions) y la [arquitectura](/docs/architecture), y lea la [skill para agentes](/docs/tooling/agent-skills) correspondiente antes de modificar una integración con un proveedor. Los agentes de programación parten de `AGENTS.md`, en la raíz del repositorio.
4. Mantenga las pruebas junto a su propietario y respete el umbral de cobertura del <RepositoryFact name="coverageThreshold" unit="percent" />.
5. Ejecute las comprobaciones siguientes.
6. Haga commit con un mensaje de [commit convencional](/docs/tooling/conventional-commits), abra una pull request con un título convencional y rellene su plantilla.

```sh
bun run check
bun run test:coverage
bun run build:test
bun run test:e2e:install
bun run test:e2e:pr
```

`build:test` ejecuta el build completo de Cloudflare, que `check` y las pruebas unitarias no ejercitan. `test:e2e:pr` compila y sirve el Worker de pruebas cuando no hay ningún servidor en marcha y ejecuta todas las specs en Chromium, como hace la CI de las pull requests. Ejecute también la suite completa de pruebas en el navegador (`bun run test:e2e`) para los cambios que puedan comportarse de forma distinta en WebKit. Valide por separado las integraciones con proveedores reales cuando cambie su configuración.

Cuando cambie el comportamiento, actualice `content/docs` en todos los idiomas; `bun run check:i18n` rechaza las traducciones que faltan y los bloques de código y la navegación que difieren. La plantilla de la pull request incluye un resumen, un plan de pruebas con las comprobaciones anteriores y una lista de la documentación actualizada; describa en ella el comportamiento resultante, cómo lo ha verificado y cualquier flujo de demostración o sin terminar que quede.

`CONTRIBUTING.md`, en la raíz del repositorio, es la versión breve de esta página, y `SUPPORT.md` indica dónde obtener ayuda. Todas las personas que participan siguen `CODE_OF_CONDUCT.md`, el Contributor Covenant 2.1. Informe de las vulnerabilidades de seguridad de forma privada, como describe `SECURITY.md`, nunca en un issue público.
