---
title: "Add a module"
description: "Create a domain folder under src/modules with use-cases and validations."
---

## Steps

1. Create `src/modules/<name>/` with `use-cases/`, optional `schemas/`, `validations/`, `utils/`
2. Put shared domain errors in `modules/_core` only when truly cross-cutting
3. Export use-cases that accept typed inputs and return DTO-safe results
4. Wire permissions via next-safe-action clients
5. Call from RSC pages / actions — never from presentation primitives
6. Add Vitest coverage next to the use-case
7. Document under Features

## Anti-patterns

- Importing UI from modules
- Putting Drizzle queries in `app/` pages
- Sharing mutable request state at module scope
