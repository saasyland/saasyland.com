Przypadek użycia to jedna operacja na jednej tabeli. Znajduje się w `src/modules/<table>/use-cases/<operation>.ts` i eksportuje funkcję serwerową razem z opcjami, których używają komponenty. Elementy składowe opisuje poradnik [Funkcje serwerowe](/docs/guides/server-functions).

## Napisz mutację

`src/modules/category/use-cases/create-category.ts`:

```ts
import { mutationOptions } from "@tanstack/react-query"
import { createServerFn } from "@tanstack/react-start"
import { v7 } from "uuid"
import type * as zod from "zod"

import { authorized } from "~/src/integrations/better-auth/auth.middleware"
import { db } from "~/src/integrations/drizzle-orm/drizzle.database"

import { CATEGORY_MUTATION_KEYS } from "~/src/modules/category/category.constants"
import { category } from "~/src/modules/category/category.schema"
import { categoryZodSchemas } from "~/src/modules/category/category.zod"

export const createCategory = createServerFn({ method: "POST" })
  .middleware([authorized({ category: ["create"] })])
  .validator((input: zod.input<typeof categoryZodSchemas.createCategory>) => categoryZodSchemas.createCategory.parse(input))
  .handler(({ data }) =>
    db
      .insert(category)
      .values({
        description: data.description ?? "",
        icon: data.icon ?? "FolderOpen",
        id: v7(),
        kind: data.kind,
        name: data.name,
        visibility: data.visibility ?? "public",
      })
      .returning()
      .get(),
  )

export const createCategoryMutation = mutationOptions({
  mutationFn: (data: Parameters<typeof createCategory>[0]["data"]) => createCategory({ data }),
  mutationKey: CATEGORY_MUTATION_KEYS.CREATE,
})
```

- Zapisy używają `method: "POST"`, odczyty `method: "GET"`.
- Middleware zabezpiecza wywołanie: `authorized(permission)` dla zalogowanych użytkowników z uprawnieniem, `authorized()` dla dowolnego zalogowanego użytkownika, `withRateLimit(kind, RATE_LIMITS.SENSITIVE)` dla operacji publicznych.
- Walidator parsuje schemat modułu, a handler otrzymuje sparsowane `data`.
- Handler zwraca wynik bezpośrednio. Operacje na danych wywołującego odczytują użytkownika z `context.auth.user.id`, nigdy z danych wejściowych.

## Napisz zapytanie

Zapytania eksportują opcje zapytania, których klucz zawiera sparsowane dane wejściowe, więc każda strona i każdy filtr mają osobny wpis w cache (`src/modules/category/use-cases/get-categories.ts`):

```ts
export const getCategoriesPageQuery = (input: zod.input<typeof listCategoriesSchema> = {}) =>
  queryOptions<Awaited<ReturnType<typeof getCategories>>>({
    queryFn: () => getCategories({ data: input }),
    queryKey: [...CATEGORY_QUERY_KEYS.LIST, listCategoriesSchema.parse(input)],
  })

export const getCategoriesQuery = getCategoriesPageQuery()
```

Wczytaj zapytanie z wyprzedzeniem w `Promise.all` loadera trasy za pomocą `context.queryClient.query({ ...getCategoriesQuery, staleTime: "static" })`, a w komponencie odczytaj je przez `useSuspenseQuery(getCategoriesQuery)`.

## Obsłuż błędy

Przy spodziewanych błędach rzucaj `AppError` z kodem z `src/modules/_core/constants/errors.ts`:

```ts
if (row === undefined) {
  throw new AppError(ERROR_CODES.NOT_FOUND)
}
```

Dostępne kody to `AUTH_API_ERROR`, `CONFLICT`, `FORBIDDEN`, `INTERNAL_ERROR`, `NOT_FOUND`, `TOO_MANY_REQUESTS`, `UNAUTHORIZED` i `VALIDATION`. Middleware `withRequest`, zawarte w `authorized` i `withRateLimit`, przekazuje dalej tylko kod `AppError`, zamienia błędy API Better Auth na `AUTH_API_ERROR` z kluczem błędu uwierzytelniania, błędy Zod na `VALIDATION`, a każdy inny błąd zapisuje w logach i zastępuje przez `INTERNAL_ERROR`.

## Użyj go w komponencie

Rozwiń wyeksportowane opcje w `useMutation`, tłumacz błędy przez `useErrorMessage` i po sukcesie unieważnij zapytania modułu (`src/presentation/components/custom/admin/users/delete-user-dialog.tsx`):

```tsx
const queryClient = useQueryClient()
const errorMessage = useErrorMessage()

const deleteUser = useMutation({
  ...deleteUserMutation,
  onError: (error) => {
    toast.error(errorMessage(error))
  },
  onSuccess: async () => {
    await queryClient.invalidateQueries({ queryKey: USER_QUERY_KEYS.ALL })
    toast.success(t("feedback.deleteSuccess"))
  },
})
```

`useErrorMessage` mapuje klucze błędów uwierzytelniania na `auth.errors.<key>`, kody błędów na `errors.codes.<CODE>`, a wszystko nieznane na `errors.codes.INTERNAL_ERROR`. Unieważniaj tylko moduły, których dane zmienia mutacja.
