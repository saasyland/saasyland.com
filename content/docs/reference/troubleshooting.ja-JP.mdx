## データベース

**`bun run dev` で `no such table` が発生する。** `development` 環境は、リモートのプレビュー用 D1 データベースを使います。`bun run db:migrate:development` で、そのデータベースにマイグレーションを適用してください。`bun run db:migrate:local` がマイグレーションするのは、`bun run dev` が使わないローカルのデータベースだけです。

**Playwright で `no such table` が発生する。** ブラウザテストは専用のローカルデータベースを使います。`bun run db:reset:test` を実行するか、Playwright にアプリを起動させてください。後者の場合はこのコマンドが自動で実行されます。

**Vitest のテーブルが古い。** D1 のモックは、起動時に `src/integrations/drizzle-orm/migrations` 内のすべての SQL ファイルを適用します。スキーマを変更したら、`bun run db:generate` でマイグレーションを生成してください。

## 開発サーバー

**開発サーバーが起動しない。** 開発サーバーは `strictPort` を指定してポート 3000 を使うため、ポートが使用中だと起動に失敗します。そのポートを使っている他のプロセスを停止してください。

**サインインや OAuth が失敗する。** 環境ファイルの `AUTH_SECRET` と OAuth クライアントの認証情報を確認してください。また、プロバイダーのコールバック URL が、使用しているホストの `/api/auth/callback/<provider>` を指していることも確認します。Better Auth は、ビルドモードごとに設定されたホストだけを受け付けます。development では `localhost:3000` と `127.0.0.1:3000` です。

**Worker の型にバインディングやシークレットが含まれていない。** `wrangler.jsonc` を変更した後に `bun run cf-typegen` を実行し、変数を `src/types/bindings.d.ts` に追加してください。

**カスタムの `text-*` クラスがマージ時に消える。** `cn` は、`src/lib/cn.config.ts` から生成されたテーブルに依存しています。このテーブルは `bun run dev`、`bun run check`、各ビルドで再生成されます。`.source/cn-tables.ts` が存在しない場合は、`bun run generate:cn` を実行してください。

## 翻訳

**`No messages/<locale>/<namespace>.json` と表示される。** ルートが、そのロケールにファイルが存在しない名前空間を宣言しています。すべてのロケールでファイルを作成してください。

**キーがパスのまま表示される、または `check:i18n` がキーの欠落を報告する。** そのキーがいずれかのロケールで欠けているか、コンポーネントが `useTranslations` 呼び出しのスコープ外でキーを読み取っています。コンポーネントごとに `useTranslations` を 1 回だけ使い、`bun run check:i18n` を実行してください。

## ドキュメント

**ドキュメントページが 404 を返す。** ファイル名を `<page>.<locale>.mdx` にし、フォルダーの `meta.<locale>.json` の `pages` に列挙する必要があります。`bun run content` を実行して `.source` を再生成してください。

**`check-content.ts` が失敗する。** このスクリプトは、すべてのロケールを en-US と比較します。`Changed code examples` は、コードブロックが英語版と異なることを意味します。コードブロックは同一でなければなりません。`Untranslated English paragraph` は、段落が翻訳されずにコピーされたことを意味します。`Missing <file>` は、ロケールのファイルが存在しないことを意味します。

## テストとデプロイ

**`test:coverage` が失敗する。** カバレッジは、行、ステートメント、関数、分岐のすべてで 100% である必要があります。カバーされていない行は、`coverage/` のレポートで確認できます。

**デプロイが `verify-bindings.ts` で止まる。** `wrangler.jsonc` の対象環境に `DB`、`CACHE`、`MEDIA` のいずれかのバインディングがないか、D1 や KV のプレースホルダー ID が残っているか、本番の場合はプレビューとリソースを共有しています。Cloudflare でリソースを作成し、ID を置き換えてください。

**デプロイが `polar:verify` で止まる。** Polar がコードと一致していません。`.env.<environment>` のキーがないか誤った Polar サービスを指している、トークンが拒否されたかスコープが足りない、あるいは商品、価格、ライセンスキー、地域割引、Webhook のいずれかがコードの前提と異なっています。エラーには各問題が列挙され、各メッセージの意味は [Polar の設定](/docs/getting-started/polar-setup)で説明しています。`bun run polar:verify:<environment>` でチェックを再実行できます。

**デプロイが `prepare-deploy-secrets.ts` で止まる。** 環境の `secrets.required` に列挙されたキーが、`.env.<environment>` にないか空になっています。エラーにそのキーが表示されます。

**デプロイが `verify-deployment.ts` で止まる。** Worker はデプロイされましたが、確認対象のパスが、期待されるコンテンツタイプで `200` を返しませんでした。エラーには各 URL とその応答が表示されます。その URL を開き、Cloudflare で Worker のログを確認してください。`bun scripts/verify-deployment.ts <preview|production>` で確認をもう一度実行できます。

**プリレンダリングのビルドが失敗する。** ビルドの出力に、最初に失敗した URL が表示されます。`bun run dev` でそのページを開き、エラーを確認してください。
