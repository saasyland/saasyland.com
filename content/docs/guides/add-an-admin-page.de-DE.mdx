---
title: "Admin-Seite hinzufügen"
description: "Route, Sidebar-Eintrag, Messages und Widgets einer neuen Admin-Seite registrieren."
---

Admin-Seiten sind flache Route-Dateien unter dem `/admin`-Layout (`src/routes/admin.tsx`), das in `beforeLoad` `requireAdmin` ausführt und Sidebar, Breadcrumbs und Befehlspalette rendert. Die folgenden Schritte fügen eine Seite unter `/admin/reports` hinzu; `src/routes/admin.orders.index.tsx` ist ein vollständiges reales Beispiel.

## 1. Pfad hinzufügen

Den Pfad in `src/routes.ts` an seiner alphabetischen Stelle deklarieren. Danach enthält `ROUTES` ihn:

```ts
export const ADMIN_REPORTS = "/admin/reports"
```

Gehört die Seite zu einem Bereich, den ein Projekt weglassen kann, den Namen außerdem in die `names` dieses Bereichs in `scripts/areas.ts` eintragen, damit `bun run check:areas` den Pfad und jeden Eintrag, der ihn nennt, zusammen mit dem Bereich entfernt.

## 2. Route-Datei anlegen

`src/routes/admin.reports.tsx` anlegen. Die Route definiert nur die Seitenkomponente, `NAMESPACE`, den Loader, `head` und `pendingComponent`; der Router-Generator registriert die Datei in `src/routeTree.gen.ts`.

```tsx
import type { JSX } from "react"

import { createFileRoute } from "@tanstack/react-router"
import { useTranslations } from "use-intl/react"

import { loadPageMetadata, preloadNamespaces } from "~/src/integrations/use-intl/i18n.messages"
import { getCurrentLocale } from "~/src/integrations/use-intl/i18n.utils"

import { pageHead } from "~/src/lib/seo"

import { AdminPageHeader } from "~/src/presentation/components/custom/admin/admin-page-header"
import { AdminReportsPending } from "~/src/presentation/components/custom/admin/reports-pending"
import { ReportStats } from "~/src/presentation/components/custom/admin/reports/report-stats"

import * as ROUTES from "~/src/routes"

const ReportsPage = (): JSX.Element => {
  const t = useTranslations("pages.admin.reports")

  return (
    <div className="flex w-full flex-col space-y-8">
      <AdminPageHeader description={t("metadata.description")} title={t("metadata.title")} />

      <ReportStats />
    </div>
  )
}

const NAMESPACE = "pages.admin.reports"

export const Route = createFileRoute("/admin/reports")({
  component: ReportsPage,
  head: pageHead(ROUTES.ADMIN_REPORTS),
  loader: async ({ context }) => {
    const locale = getCurrentLocale()
    const [metadata] = await Promise.all([
      loadPageMetadata({ locale, namespace: NAMESPACE }),
      preloadNamespaces({ locale, namespaces: [NAMESPACE], queryClient: context.queryClient }),
    ])
    return { locale, metadata }
  },
  pendingComponent: AdminReportsPending,
  staticData: { namespaces: [NAMESPACE] },
})
```

Queries, die die Seite benötigt, kommen in dasselbe `Promise.all`, zum Beispiel `context.queryClient.query({ ...getUsersQuery, staleTime: "static" })` in `src/routes/admin.users.all.tsx`. `pageHead` erzeugt Titel, Beschreibung, kanonische URL und Links zu den anderen Locales aus den `metadata` des Loaders. `AdminReportsPending` ist das eigene Skeleton der Seite und erscheint nur, wenn eine Navigation länger als <RepositoryFact name="navigationPendingMs" unit="millisecond" /> dauert. Das Skeleton in der Skeleton-Datei seines Bereichs, hier einer neuen `custom/admin/reports-pending.tsx`, aus `AdminPageHeaderPending` in `admin-page-header.tsx` für den Kopfbereich und den Bausteinen in `pending-blocks.tsx` aufbauen, sodass es das Layout der Seite nachbildet. Das Skeleton des Admin-Layouts liest es aus der Route und zeigt es daher auch, wenn jemand `/admin/reports` von außerhalb des Admin-Bereichs aufruft.

Siehe [Lade-Skeletons](/docs/architecture/delivery-layer#lade-skeletons).

## 3. Sidebar-Eintrag hinzufügen

Einen Eintrag zu den `items` seiner Sidebar-Gruppe in `ADMIN_NAVIGATION` (`src/data/navigation.ts`) hinzufügen, an der Stelle, an der er erscheinen soll, etwa hinter Dashboard in der Gruppe Überblick. Der Eintrag nennt sein `lucide-react`-Icon, den vollständigen Schlüssel seiner Beschriftung und seinen Pfad:

```ts
{ icon: FileText, label: "navigation.reports.admin.reports", to: ROUTES.ADMIN_REPORTS },
```

Die Beschriftung in jeder Locale als `admin.reports` in `messages/<locale>/navigation.reports.json` eintragen. Eine neue Gruppe benötigt zusätzlich einen Wert in `ADMIN_NAVIGATION_GROUP`, einen Platz unter den Gruppen von `ADMIN_NAVIGATION` und `groups.<group>` in `pages.admin.sidebar`. Sidebar, Breadcrumbs und die ⌘K-Befehlspalette lesen alle `ADMIN_NAVIGATION` (`src/data/navigation.ts`), sodass die Seite an allen drei Stellen erscheint. Die Landingpage zählt sie zu den Admin-Bereichen, und die Admin-Leiste des Landingpage-Videos `app-tour` führt sie auf, sobald das Video neu gerendert wurde (siehe `remotion/README.md`). Ein drittes URL-Segment wie `/admin/reports/create` zeigt einen Breadcrumb, wenn die `breadcrumbs` des Eintrags eine Beschriftung dafür nennen, etwa `breadcrumbs: { create: "navigation.reports.breadcrumbs.create" }`, und keinen dritten Breadcrumb, wenn nicht.

## 4. Seiten-Messages hinzufügen

`messages/<locale>/pages.admin.reports.json` in jeder Locale anlegen. `metadata` ist erforderlich, weil der Loader es für den Dokument-Head liest:

```json
{
  "metadata": {
    "title": "Reports",
    "description": "Revenue and usage reports."
  }
}
```

## 5. Widgets hinzufügen

Jedes Widget, jeden Dialog, jedes Formular und jeden Satz Tabellenspalten in eine eigene Datei unter `src/presentation/components/custom/admin/reports/` legen, zum Beispiel `report-stats.tsx` oder `report-columns.tsx`. Widgets rufen `useTranslations("pages.admin.reports")` auf und lesen ihre eigenen Daten mit `useSuspenseQuery`; die Seite übergibt ihnen weder Beschriftungen noch Daten. Tabellen verwenden das `DataGrid`; siehe [Datenraster hinzufügen](/docs/guides/add-a-data-table).

## 6. Schützen und testen

- Der Layout-Guard regelt den Seitenzugriff. Jede Server-Funktion, die die Seite aufruft, benötigt trotzdem `authorized(permission)`; siehe [Rollen und Berechtigungen](/docs/guides/roles-and-permissions).
- `/admin` ist vom Prerendering ausgeschlossen.
- Route-Tests des Bereichs in `src/routes/__test__/admin-<area>-routes.component.test.tsx` und `admin-<area>-loaders.test.ts`, Widget-Tests in `src/presentation/components/custom/admin/__test__/` und die Seite in `e2e/data/<area>.pages.ts` hinzufügen, danach `bun run check:i18n` und `bun run test:coverage` ausführen.
