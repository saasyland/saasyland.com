## Escolha um ambiente

| Ambiente        | Comandos                                    | Dados                                                                    | Provedores                              |
| --------------- | ------------------------------------------- | ------------------------------------------------------------------------ | --------------------------------------- |
| Prévia isolada  | `db:reset:test`, `build:test`, `start:test` | D1, KV e R2 locais em `.wrangler/test`, contas semeadas                  | Interceptados; nenhuma conta necessária |
| Desenvolvimento | `db:reset:local`, `db:seed:local`, `dev`    | D1, KV e R2 locais em `.wrangler/state`, administrador e cursos semeados | Reais, a partir de `.env.development`   |

```sh
bun run db:reset:test
bun run build:test
bun run start:test
```

A prévia isolada serve um build em `http://127.0.0.1:3000`; compile de novo para ver as mudanças no código. Entre com uma das contas do seed listadas em [Primeira execução](/docs/getting-started/first-run) e a senha de `e2e/data/accounts.ts`. Os e-mails são capturados em vez de enviados: abra `/__test/emails?to=<address>` para lê-los, inclusive os links de verificação.

```sh
cp .env.example .env.development
bun run db:reset:local
bun run db:seed:local
bun run dev
```

O servidor de desenvolvimento roda em `http://localhost:3000` com recarregamento automático. Os bindings `DB`, `CACHE`, `MEDIA` e `BUNDLES` dele são locais, então nada do que você faz chega aos dados da prévia ou de produção. Entre como o administrador semeado de [O seed local](/docs/tooling/database#the-local-seed). Use `POLAR_SERVER=sandbox`.

## Leia erros do servidor

- Uma função de servidor com falha registra `Server function failed` com o erro original no terminal em que roda `bun run dev`, ou no Workers Logs nos ambientes publicados. O navegador recebe apenas o código de erro.
- `Rate-limit storage unavailable` significa que o D1 estava inacessível durante uma verificação de limite de requisições; a requisição foi rejeitada.
- `[license] <method> <path> failed` significa que uma requisição à API de licenças da CLI falhou no servidor, por exemplo porque o D1 ou a Polar falhou, e a CLI recebeu `serviceUnavailable`. A entrada traz o erro com a causa e a stack, e `[licence key]` no lugar da chave de quem chamou.
- `No messages/<locale>/<namespace>.json` significa que uma rota declara um namespace sem arquivo para aquele idioma.

## Inspecione dados

- Drizzle Studio: `bun run db:studio:local` para o banco local; `:preview` e `:production` precisam das variáveis `CLOUDFLARE_*` no arquivo de ambiente correspondente.
- Banco de teste local: `bunx wrangler d1 execute DB --env test --local --persist-to .wrangler/test --command "SELECT email, role FROM user"`.

## Corrija arquivos gerados

- Tipos dos bindings do Worker, tabelas de nomes de classe ou conteúdo da documentação desatualizados: `bun run typegen`.
- Traduções não resolvem: `bun run check:i18n` lista as chaves ausentes por idioma e as que não resolvem no escopo de `useTranslations`.
- `bun run clean` remove a saída do build, os caches e `.wrangler`, inclusive o banco de teste local; depois execute `db:reset:test`.

## Depure testes

- Execute um único projeto ou apenas os testes afetados: `bun run test:unit`, `bun run test:component`, `bun run test:changed`, `bun run test:watch`.
- Playwright: `bun run test:e2e:headed` mostra o navegador e `bun run test:e2e:ui` abre o modo UI. Execuções locais mantêm os traces dos testes com falha e abrem o relatório HTML quando há falhas.
- Execute a suíte de navegador em uma porta livre do intervalo da build de teste quando outro servidor ocupa `127.0.0.1:3000` ou outro worktree roda a suíte dele: `PLAYWRIGHT_BASE_URL=http://127.0.0.1:3027 bun run test:e2e:pr`. [Playwright](/docs/tooling/playwright#running-beside-other-worktrees) explica como escolher a porta.
