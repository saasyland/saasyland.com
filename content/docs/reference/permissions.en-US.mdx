Each area declares its permission statements and the roles it grants them to in `src/data/<area>.access.ts`, and `src/integrations/better-auth/auth.access.ts` builds Better Auth's access control and the roles from them (see [Roles and permissions](/docs/guides/roles-and-permissions)). The same definitions are used by the server (`authorized`, route guards) and by the Better Auth client.

## Roles

| Role     | Code       | Permissions                                                                                                                       |
| -------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Admin    | `admin`    | Every application statement below, which each area grants to admins, plus Better Auth's admin statements for `user` and `session` |
| Customer | `customer` | None. Customers can call server functions that only require a session.                                                            |

New users get `customer` (`DEFAULT_ROLE_CODE` in `auth.roles.ts`).

## Where permissions are checked

| Permission               | Checked by                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `admin: ["access"]`      | `requireAdmin` on the `/admin` layout and the redirect after sign-in                                                                                                                                                                                                                                                                                                                                                                                   |
| `category` actions       | The category use cases: `read`, `create`, `update`, `delete`                                                                                                                                                                                                                                                                                                                                                                                           |
| `course: ["read"]`       | `get-courses` and `get-course-editor`; also `resolveViewer` (`lesson.viewer.ts`): its holders watch every lesson and download its materials in `get-course`, `get-lesson`, `get-lesson-playback` and `save-lesson-progress`, whatever the lesson's access level                                                                                                                                                                                        |
| `course: ["create"]`     | `create-course`                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `course: ["update"]`     | `update-course`, `move-course` and the chapter, lesson and material writes: `create-chapter`, `update-chapter`, `delete-chapter`, `move-chapter`, `create-lesson`, `update-lesson`, `replace-lesson-video`, `delete-lesson`, `move-lesson`, `create-lesson-attachment`, `upload-lesson-attachment`, `update-lesson-attachment`, `move-lesson-attachment`, `delete-lesson-attachment`; also `set-video-placeholder`, which decides whether lessons play |
| `course: ["delete"]`     | `delete-course`                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `product` actions        | The product use cases: `read`, `create`, `update`, `delete`                                                                                                                                                                                                                                                                                                                                                                                            |
| `order: ["read"]`        | The licence area's `get-unlicensed-orders`, the admin dashboard's list of paid licence orders without a licence                                                                                                                                                                                                                                                                                                                                        |
| `video` actions          | `get-videos` and `get-video-playback` (`read`), `delete-video` (`delete`)                                                                                                                                                                                                                                                                                                                                                                              |
| `user` actions           | The user use cases, one action each; `ban` covers both `ban-user` and `unban-user`, and `get` also the licence area's `get-user-license`                                                                                                                                                                                                                                                                                                               |
| `session` actions        | `list-user-sessions` (`list`), `revoke-user-session` and `revoke-user-sessions` (`revoke`)                                                                                                                                                                                                                                                                                                                                                             |
| A session, no permission | Account, licence, two-factor, newsletter preference and own-session use cases, `stop-impersonating-user` and `save-lesson-progress`                                                                                                                                                                                                                                                                                                                    |

`order: ["update"]`, `order: ["refund"]`, `product: ["publish"]` and `settings` are declared but not yet checked by any server function.

## Checking a permission

Server functions use the middleware, for example `authorized({ category: ["read"] })`. Other code calls `hasPermission`, as the route guards do:

```ts
const isAdmin = (role: string | null | undefined): boolean => hasPermission({ permission: { admin: ["access"] }, role })

export const requireAdmin = async (context: ProtectedRouteContext) => {
  const result = await requireSignedIn(context)
  if (!isAdmin(result.session.user.role)) {
    throw redirect({ replace: true, to: ROUTES.APP })
  }
  return result
}
```
