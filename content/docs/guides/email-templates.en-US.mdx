An email has three parts: a template in `src/presentation/emails/`, a message namespace in `messages/<locale>/emails.<name>.json`, and the use case that loads the messages, renders the template and sends it. The [Resend](/docs/integrations/resend) page lists every template with the use case that sends it.

## Template

A template contains markup only and exports its namespace. It translates with `createTranslator` from `use-intl` because it renders outside React context. Every template renders inside `EmailLayout` from `src/presentation/emails/email-layout.tsx`, which sets the language, the preview text, Tailwind and the centred container once for all of them. `src/presentation/emails/verify-email.tsx`:

```tsx title="src/presentation/emails/verify-email.tsx"
import type { JSX } from "react"

import { Button, Heading, Section, Text } from "react-email"
import { createTranslator } from "use-intl"

import { EMAIL_LINK_LIFETIME_HOURS } from "~/src/integrations/better-auth/auth.constants"
import type { SupportedLocale } from "~/src/integrations/use-intl/i18n.config"

import type emailMessages from "~/messages/en-US/emails.verify-email.json"
import { APP_NAME } from "~/src/presentation/branding"
import { EmailBrandHeader } from "~/src/presentation/emails/email-brand-header"
import { EmailFallbackLink } from "~/src/presentation/emails/email-fallback-link"
import { EmailLayout } from "~/src/presentation/emails/email-layout"

export const VERIFY_EMAIL_NAMESPACE = "emails.verify-email"

interface VerifyEmailProps {
  readonly locale: SupportedLocale
  readonly messages: typeof emailMessages
  readonly name: string
  readonly verifyUrl: string
}

export const VerifyEmail = ({ messages, locale, name, verifyUrl }: Readonly<VerifyEmailProps>): JSX.Element => {
  const t = createTranslator({ locale, messages: { emails: { "verify-email": messages } }, namespace: "emails.verify-email" })

  return (
    <EmailLayout lang={locale} preview={t("preview", { appName: APP_NAME })}>
      <EmailBrandHeader />
      <Section>
        <Heading className="m-0 mb-4 text-2xl font-bold">{t("heading")}</Heading>
        <Text className="m-0 mb-6 text-base text-neutral-600">{t("body", { name })}</Text>
        <Button href={verifyUrl} className="box-border rounded-md bg-neutral-900 px-5 py-3 text-center text-base text-white no-underline">
          {t("button")}
        </Button>
        <Text className="mt-6 mb-0 text-base text-neutral-600">{t("expiry", { hours: EMAIL_LINK_LIFETIME_HOURS })}</Text>
        <EmailFallbackLink label={t("fallback")} url={verifyUrl} />
        <Text className="mt-6 text-sm text-neutral-500">{t("footer")}</Text>
      </Section>
    </EmailLayout>
  )
}
```

## Messages

Create `messages/<locale>/emails.<name>.json` in every locale. Include a `subject` key; the use case translates it separately from the body.

```json title="messages/en-US/emails.verify-email.json"
{
  "subject": "Verify your email address",
  "preview": "Verify your email for {appName}",
  "heading": "Verify your email",
  "body": "Hi {name}, thanks for signing up. Confirm your email address to finish setting up your account.",
  "button": "Verify email",
  "expiry": "The link works for {hours, plural, one {# hour} other {# hours}}.",
  "fallback": "If the button does not work, copy this link into your browser:",
  "footer": "If you did not create an account, you can safely ignore this email."
}
```

Email namespaces are never preloaded by routes; the sending use case loads them on the server.

## Sending

The use case takes the locale from the callback URL it receives, checks the per-recipient limit, loads the messages, builds absolute links with `localizePathname` and calls `sendEmail`. `src/modules/verification/use-cases/send-verify-email.ts`:

```ts title="src/modules/verification/use-cases/send-verify-email.ts"
export const sendVerifyEmail = async ({
  callbackURL,
  token,
  user,
}: {
  callbackURL: string
  token: string
  user: { email: string; name: string }
}): Promise<void> => {
  if (!(await withinRecipientRateLimit({ kind: VERIFICATION_EMAIL_PURPOSE.VERIFY_EMAIL, recipient: user.email }))) {
    console.warn("[email] verification email not sent: the recipient reached the hourly limit")
    return
  }

  const callback = new URL(callbackURL, getRequest().url)
  const locale = extractLocaleFromPath(callback.pathname) ?? I18N.DEFAULT_LOCALE
  const verifyUrl = new URL(localizePathname({ locale, pathname: ROUTES.AUTH.VERIFY_EMAIL }), getRequest().url)
  verifyUrl.search = callback.search
  verifyUrl.searchParams.set("token", token)

  const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })

  await sendEmail({
    idempotency: { purpose: VERIFICATION_EMAIL_PURPOSE.VERIFY_EMAIL, token: crypto.randomUUID() },
    react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
    subject: createTranslator({ locale, messages })("subject"),
    to: user.email,
  })
}
```

`sendEmail` (`src/integrations/resend/resend.utils.ts`) sends through Resend from `RESEND_EMAIL_FROM` unless `from` is given, passes the idempotency key so a retry never sends twice, and throws when Resend returns an error.

The verification email keys each send with `crypto.randomUUID()`, as the existing-account and password-changed emails do: Better Auth signs its verification tokens with whole-second timestamps, so a sign-up and a sign-in in the same second carry the same token, and Resend would treat the second email as a retry of the first.

## Who sends what

- Better Auth hooks in `src/integrations/better-auth/auth.server.ts` call the use cases directly: `sendVerifyEmail` for `emailVerification.sendVerificationEmail` and repeated sign-ups of unverified accounts, `sendExistingAccountEmail` for repeated sign-ups of verified accounts, `sendResetPasswordEmail` for `emailAndPassword.sendResetPassword`, `sendPasswordChangedEmail` for `emailAndPassword.onPasswordReset`, `sendChangeEmailConfirmationEmail` for `user.changeEmail` and `sendDeleteAccountEmail` for `user.deleteUser.sendDeleteAccountVerification`.
- Better Auth requests arrive at `/api/auth` without a locale prefix, so the hooks take the email locale from the flow's `callbackURL`, a localized page path, with `extractLocaleFromCallbackURL` or `extractLocaleFromPath` from `src/integrations/use-intl/i18n.paths.ts`. English is the fallback.
- The newsletter use cases send the newsletter confirmation and notification emails themselves, for example `subscribeToNewsletter`.
- The licence feature's `onOrderPaid` webhook handler calls `sendPurchaseConfirmationEmail` after it grants the licence. The email takes its locale from the order's `metadata.locale`, its links from the host that received the webhook, and its idempotency token from the Polar order ID, and a failed send fails the handler so that Polar retries.
- When a paid licence order matches no account, `onOrderPaid` grants nothing and calls `sendUnmatchedOrderAlert`, which tells the site owner in English.
- `recordWithdrawal`, which `submitWithdrawal` calls, sends the acknowledgement of a withdrawal statement in the language of the page it was sent from, and the withdrawal notification to the site owner in English. A failed send is logged and does not fail the statement.
- `createInvitation` and `resendInvitation` call `sendInvitationEmail` with the language the admin chose, stored on the invitation. Its idempotency token is the link's token, so every new link is a new email, and over the per-recipient limit it fails with `TOO_MANY_REQUESTS` instead of skipping the email.
- `sendVerifyEmail`, `sendResetPasswordEmail`, `sendExistingAccountEmail` and `subscribeToNewsletter` call `withinRecipientRateLimit` (`src/lib/rate-limit.ts`) before sending: at most <RepositoryFact name="recipientEmailsPerHour" /> emails of a kind per address per hour, keyed on a SHA-256 hash of the address. Over the limit they log a warning and send nothing. Add the same check to any email a visitor can trigger without an account.

## Add an email

1. Add the template to `src/presentation/emails/<name>.tsx` with its exported `<NAME>_NAMESPACE`.
2. Add `messages/<locale>/emails.<name>.json` in every locale.
3. Name its purpose in the `<MODULE>_EMAIL_PURPOSE` object of the sending module's `<module>.constants.ts`, which `email-purposes.test.ts` checks against the purposes of every other module, and send it from the use case that owns the action, passing `idempotency: { purpose, token }` with the token or record id that triggered it.
4. Test the template in `src/presentation/emails/__test__/` and the use case with `sendEmail` mocked.

Resend credentials: `RESEND_API_KEY` and `RESEND_EMAIL_FROM`. Tests never contact Resend.
