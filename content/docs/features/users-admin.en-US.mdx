## Routes

`src/routes/admin.users.tsx` is a layout whose link tabs are `USER_TABS` in `src/data/user-tabs.ts`, which joins each area's `src/data/<area>.user-tabs.ts` by `order`. A tab names its path and its page skeleton, and its label in the area's `navigation.<area>.json` also names the page in the breadcrumbs. The auth area adds **All users** and **Security**, the team area **Invitations** and **Roles & Permissions**. `/admin/users` redirects to `/admin/users/all`. Every tab takes its page title from `pages.admin.users`; the team area's own copy is in `pages.admin.users.invitations` and `pages.admin.users.roles`, which it adds to the layout in `src/data/team.namespaces.ts`.

| Route                      | Content                                                  |
| -------------------------- | -------------------------------------------------------- |
| `/admin/users/all`         | Live users table                                         |
| `/admin/users/invitations` | Demo rows (`ADMIN_INVITATION_ROWS`) with an email search |
| `/admin/users/roles`       | Demo rows (`ADMIN_ROLE_ROWS`)                            |
| `/admin/users/security`    | Empty state                                              |

## All users

```tsx
<DataTable columns={userColumns} options={{ query: getUsersPageQuery, selectable: true }} />
```

- `getUsersPageQuery` calls the `getUsers` server function (`src/modules/user/use-cases/get-users.ts`, permission `user: ["list"]`). Pagination and sorting run on the server over name, role, status, email verification, 2FA, time zone and the created and updated dates.
- Status is not a column. `getUserStatus` (`user.utils.ts`) derives `banned`, `pending` or `active` from `banned` and `emailVerified`, and the server sorts by the same SQL `case` expression.
- `userColumns` lives in `src/presentation/components/custom/admin/users/user-columns.tsx`; the created and updated dates use the `common.dateTime` message, in the viewer's own time zone with its abbreviation, so both columns read and sort in one zone. Each user's zone has its own column.

## Row actions

`UserRowActions` (`row-actions.tsx`) is the menu in the last column:

- **Reset password** opens `ResetPasswordDialog`, which calls `setUserPassword`.
- **Ban** or **Unban** calls `banUser` or `unbanUser`.
- **Delete** opens `DeleteUserDialog`, which calls `deleteUser`.

Every success invalidates `USER_QUERY_KEYS.ALL` and shows a toast; errors go through `useErrorMessage`. The **Edit** and **View profile** items and the **Add user** button have no action yet.

## Not wired

`createUser`, `getUser`, `updateUser`, `setUserRole`, `impersonateUser` and `stopImpersonatingUser` exist in `src/modules/user/use-cases` with permission middleware, but no screen calls them. There is no invitation table; the real roles are `admin` and `customer` in `auth.roles.ts`. The invitations and roles tabs are the team area's demo screens: their rows live in `src/data/admin-team.ts` and their skeletons in `team-pending.tsx`, and a project without the team area keeps the auth area's two tabs.
