## Worker і прив'язки

`wrangler.jsonc` задає `src/server.ts` як точку входу Worker. Worker отримує три прив'язки:

| Прив'язка | Тип              | Для чого                                                           |
| --------- | ---------------- | ------------------------------------------------------------------ |
| `DB`      | База даних D1    | Усі таблиці, зокрема сесії та лічильники обмеження частоти запитів |
| `CACHE`   | Простір імен KV  | Кешована кількість зірок на GitHub                                 |
| `ASSETS`  | Статичні ресурси | Попередньо відрендерені сторінки та файли з `public`               |

Запити до `/assets/*`, `/fonts/*`, `/robots.txt` і `/llms.txt` обслуговуються зі статичних ресурсів без запуску Worker. Серверний код читає прив'язки, секрети та `waitUntil` з `cloudflare:workers`.

## Середовища

`wrangler.jsonc` визначає чотири середовища. `CLOUDFLARE_ENV` обирає одне з них для `vp dev` і `vp build`.

| Середовище    | Прив'язки                            | Хто використовує                                |
| ------------- | ------------------------------------ | ----------------------------------------------- |
| `development` | Віддалені D1 і KV середовища preview | `bun run dev`                                   |
| `preview`     | D1 і KV середовища preview           | `bun run build:preview`, `deploy:preview`       |
| `production`  | D1 і KV середовища production        | `bun run build:production`, `deploy:production` |
| `test`        | Локальні D1 і KV у `.wrangler/test`  | `bun run build:test`, Playwright                |

Кожне середовище перелічує свої обов'язкові секрети в `secrets.required`. Значення беруться з відповідного файлу `.env.<environment>`; скрипти розгортання передають його в Wrangler через `--secrets-file`. Середовище `test` використовує `src/platform/testing/worker.ts` як точку входу та фіктивні значення з `.env.test`, що зберігаються в репозиторії.

## Типи

- `src/types/bindings.d.ts` оголошує `Cloudflare.Env`: прив'язки та всі секрети.
- `src/types/worker-configuration.d.ts` генерує `bun run cf-typegen`.
- `src/types/router.d.ts` реєструє тип роутера та опцію маршруту `staticData.namespaces`.

## Тестова інфраструктура

`src/platform/testing` містить лише те, що не може належати окремій функціональності:

- `setup.ts`: матчери jest-dom, скидання прив'язок перед кожним тестом і заміна `createServerFn`, яка виконує серверні функції в тому самому процесі
- `mocks/cloudflare.ts`: D1 на SQLite у пам'яті, який застосовує збережені в репозиторії міграції, KV у пам'яті та `waitUntil`, відкладені завдання якого тести можуть примусово виконати
- `mocks/providers.ts`: перехоплення fetch для Resend і Polar у браузерних тестах, зокрема перехоплені листи
- `mocks/wrksz-themes.ts`: заміна бібліотеки тем
- `lib/`: RPC-міст для серверних функцій, допоміжні функції рендерингу, допоміжні функції для URL-адрес запитів і засоби виконання запитів
- `worker.ts`: точка входу Worker для браузерних тестів, яка перехоплює вихідні листи

Як набори тестів це використовують, описано на сторінці [Тестування та CI](/docs/architecture/testing-architecture).
