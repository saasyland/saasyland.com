Кількість локалей, з якими постачається SaaSy Land: <RepositoryFact name="languages" />. Це <RepositoryFact name="supportedLocales" />, перелічені один раз в `I18N.SUPPORTED_LOCALES` у `src/integrations/use-intl/i18n.config.ts`. Англійська — джерело істини. Зміна, яка додає чи редагує текст, додає чи редагує його в кожній локалі в тому самому коміті, а інакше `bun run check:i18n` завершується помилкою.

## Простори імен

Повідомлення лежать у `messages/<locale>/<namespace>.json`, по одному файлу на простір імен, і назва файлу є назвою простору імен.

| Простір імен                                                       | Містить                                                                                                         | Коли завантажується                                  |
| ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| `common`, `errors`, `errors.global`                                | Текст, який може знадобитися будь-якому екрану, зокрема `errors.codes.<CODE>`                                   | Для кожного маршруту                                 |
| `components.custom.<file>`, `components.shadcn.<file>`             | Тексти одного спільного компонента, як-от `components.custom.newsletter-form`                                   | Для кожного маршруту                                 |
| `fumadocs`                                                         | Тексти власних елементів керування Fumadocs у документації та блозі, які `useFumadocsI18n` передає у Fumadocs   | Макетами документації та блогу                       |
| `pages.<feature>`, `pages.<feature>.<page>`                        | Один макет або одна сторінка з `metadata.title` і `metadata.description`                                        | Маршрутом, через `NAMESPACE` або `NAMESPACES`        |
| `navigation.<feature>`, `dashboard.<feature>`                      | Підписи пунктів меню, хлібних крихт і статистики панелі однієї можливості, які пункт меню називає повним ключем | У корені, разом із кожною сторінкою                  |
| `<table>.validations`                                              | Повідомлення Zod одного модуля, як-от `course.validations`                                                      | Макетом, форми якого їх використовують               |
| `auth.errors`, `auth.validations` та інші файли `auth.*`           | Помилки Better Auth, валідація та екрани автентифікації                                                         | Макетами, яким вони потрібні                         |
| `emails.<template>`                                                | Один шаблон листа                                                                                               | На сервері, сценарієм використання, що його надсилає |
| `countries`, `currencies`, `flow-features`, `locales`, `timezones` | Каталоги                                                                                                        | Макетами, яким вони потрібні                         |
| `stack`                                                            | Підписи запитань, варіантів і доповнень CLI з `@saasyland/stack` разом із приміткою до кожного запитання        | Головною сторінкою й макетом документації            |

`src/integrations/use-intl/i18n.messages.ts` знаходить кореневі простори імен за назвою файлу (`common.json`, `components.*.json`, `errors*.json`). Тексти спільного компонента лежать у його власному просторі імен `components.custom.<file>`, а не в просторі імен сторінки, тож він рендерить той самий текст, де б не з’явився. Кожен простір імен, який оголошує маршрут, має існувати як файл у кожній локалі; для відсутнього `loadNamespace` викидає помилку.

## Одна функція перекладу на компонент

Компонент викликає `useTranslations` один раз зі своїм простором імен і називає результат `t`:

```tsx
const t = useTranslations("pages.admin.courses.form")
```

`scripts/check-i18n.ts` розбирає парсером oxc кожен файл застосунку в `src` і стежить за кожним перекладачем, якого повертає `useTranslations` або `createTranslator`, у просторі імен, який він отримав, або в тому, з якого `loadNamespace` завантажив його повідомлення. Перевірка не проходить для статичного ключа, якого немає в англійській версії, і для англійського ключа, якого не рендерить жоден файл джерельного коду, тож вилучений текст не залишається у файлах повідомлень. Ключ вважається відрендереним, коли:

- виклик записує його: рядком або шаблоном на кшталт `kinds.${kind}`, чиї заповнювачі через оголошення `const` та імпорти зводяться до рядків, які код може туди підставити. Лише `t.raw` рендерить і ключі під тим, який називає.
- заповнювач, який не вдається звести, або ключ у змінній заповнює оголошене ім'я: значення константи рівня модуля в `src`, `message` проблеми Zod, значення контракту CLI `@saasyland/stack` або рядок самого файлу, що робить виклик.
- ключ без статичного простору імен, як-от `${namespace}.${message}` у `use-error-message.ts` або `t(item.label)`, повністю записує одне оголошене ім'я, або він починається з простору імен, який файл, що робить виклик, називає сам або отримує як атрибут JSX, як-от `namespace="auth.validations"` у `ValidationFieldError`.

Тож слово, яке трапляється лише деінде, як-от термін із глосарію чи рядок в іншому компоненті, не доводить жодного ключа, а шаблон не доводить жодного з ключів під ним.

`navigation.website.test.ts` також перевіряє, що файли `navigation.<feature>.json` підписують саме ті пункти меню й вкладки користувачів, які оголошують можливості. Каталоги `countries`, `currencies`, `flow-features`, `locales` і `timezones` звільнено від цієї перевірки, натомість `catalogues.test.ts` перевіряє, що їхні ключі збігаються з константами, а для `flow-features` — з `FLOW_FEATURE` у `e2e/data/flows.ts`. Для константи, значення якої показують користувачам, `enum-labels.test.ts` перевіряє підписи в кожній локалі; він бере кожну таку константу разом із повідомленнями, що її підписують, зі списків, які можливості оголошують у `src/integrations/use-intl/__test__/<feature>.labels.ts`. Другий виклик `useTranslations` у тому самому компоненті непомітно змінив би область дії кожного `t()` після нього, тому він лише один. Компонент, якому потрібні ключі з двох просторів імен, викликає `useTranslations()` без простору імен і використовує повні ключі, як `sign-in-form.tsx` з `t("pages.auth.sign-in.form.resetPassword")`.

## Повідомлення

- Ключі — це вкладені JSON-об’єкти з назвами в camelCase, згруповані так, як влаштовано екран: `table.headers.course`, `delete.confirm`.
- Множина, числа й дати використовують синтаксис ICU всередині повідомлення, а не конкатенацію рядків у коді: `"{e2eSpecs, plural, one {# Playwright suite} other {# Playwright suites}}"`.
- `scripts/check-message-formats.ts` вимагає в кожній локалі однакових аргументів і тегів ICU, а також незмінних шляхів до файлів і команд `bun run`, `bunx`, `npx` чи `vp` з англійського повідомлення. Він відхиляє англійський текст, залишений в іншій локалі, зворотні апострофи Markdown, яких повідомлення не рендерять, і [форму звертання](#one-form-of-address), якої локаль не використовує.
- Форматуйте числа, дати й валюти для локалі читача через `useFormatter` з use-intl, а не вручну. Дати використовують іменований формат з `I18N.FORMATS` (`date`, `time`, `calendarDate`), тож часовий пояс і його позначення залишаються узгодженими. Іменований формат містить дату або час, ніколи обидва: рушії поєднують їх по-різному, і Safari пише «Jan 1, 2025 at 7:00 AM», де сервер пише «Jan 1, 2025, 7:00 AM», тому дата з часом — це повідомлення `common.dateTime`, як у `t("common.dateTime", { value })`. Відносний час відлічується від моменту, коли прочитали його дані, тобто від `dataUpdatedAt` його запиту, як у `format.relativeTime(session.updatedAt, dataUpdatedAt)`, і ніколи від `new Date()`, який сервер і браузер читають у різні моменти. Ціна теж є числом: `format.number(TIER_PRICES[tier], CURRENCY_FORMAT)` виводить її у валюті магазину, як це робить `TierPrice`.
- Повідомлення Zod у схемах модуля — це ключі його простору імен `<table>.validations` (`"slugInvalid"`), а числа, які вони згадують, беруться з `<MODULE>_VALIDATION_PARAMS`. Див. [Форми та таблиці](/docs/conventions/forms-and-tables).
- Текст у базі даних, який відвідувачі читають кількома мовами, — це стовпець `LocalizedText`. Англійська обов’язкова й слугує запасним варіантом, який `localize(text, locale)` повертає, коли перекладу бракує.

## Одна форма звертання [#one-form-of-address]

Кожна локаль звертається до читача в один спосіб, у кожному повідомленні, листі, юридичній сторінці, сторінці документації, дописі в блозі й записі в журналі змін: у формі, яку в цій мові використовують інструменти для розробників. `FORMS_OF_ADDRESS` у `src/lib/forms-of-address.ts` називає форму кожної локалі й перелічує форми, що їй суперечать, а `scripts/check-message-formats.ts` і `scripts/check-content.ts` завершуються помилкою, коли переклад використовує одну з них поза кодом, адресами посилань і японськими цитатами в 「」.

<RepositoryTable
  name="formsOfAddress"
  columns={[
    "Локаль",
    "Форма",
    "Ніколи",
    "Ніколи всередині речення",
    "Ніколи в кінці речення",
    "Ніколи на початку частини речення",
    "Слова, що відкривають частину речення",
  ]}
/>

- Слово з колонки **Ніколи** спричиняє помилку будь-де, зокрема з великої літери на початку речення.
- Слово з колонки **Ніколи всередині речення** спричиняє помилку після слова, числа чи коми в тому самому рядку. На початку речення те саме слово часто є третьою особою, як у `Sie laufen im Worker` («вони працюють у Worker»), тож перевірка залишає його там для рев’ю.
- Форма з колонки **Ніколи в кінці речення** спричиняє помилку перед японською крапкою.
- Слово з колонки **Ніколи на початку частини речення** спричиняє помилку на початку рядка, заголовка, пункту списку чи речення, після двокрапки чи крапки з комою і після одного зі слів з колонки **Слова, що відкривають частину речення**. Частина речення, що починається там, є головною, і форма в ній може бути лише наказовим способом, як у `Ejecute la suite` замість `Ejecuta la suite`.

Німецька звертається на du, з малої літери, як радить Duden, і на юридичних сторінках теж: форма звертання не має юридичної сили. Польська з ввічливості пише Ty і Twój з великої літери. Японська завершує речення на です・ます, а заголовки, пункти списків, клітинки таблиць і слогани можуть закінчуватися іменником або дієсловом у простій формі, але ніколи простою зв’язкою. Перевірка знаходить однозначні займенники, закінчення й форми наказового способу; форму дієслова, яку розрізняє лише зміст речення, перевіряє рев’ю, як іспанське `ejecute` у `espera a que arranque y ejecute la suite`: кон’юнктив, коли набір тестів запускає сервер, і ввічливий наказовий спосіб, коли його запускає читач.

## Числа вимірюються, а не вписуються

Кількість чогось у репозиторії, як-от тестових файлів, наборів Playwright, UI-компонентів, країн чи валют, ніколи не вписується в текст вручну. `scripts/repository-facts.ts` вимірює їх під час збірки й надає як модуль `virtual:repository-facts`; `src/lib/repository-facts.ts` експортує їх як `REPOSITORY_FACTS`. Розмір каталогу береться з його константи (`COUNTRIES`, `CURRENCY_CODES`, `TIMEZONES`, `ADMIN_NAVIGATION`) і ніколи — з файлу повідомлень, який його перекладає. Тексти лендингу підставляють їх, як у `t("body", REPOSITORY_FACTS)` з `"{testFiles, number} test files"` у повідомленні, а MDX рендерить одне з них через `<RepositoryFact name="testFiles" />`. Щоб згадати нове число, спершу виміряйте його в цьому плагіні. Число, яке бізнес встановлює, а не вимірює, як-от партнерська комісія, оголошують один раз у `src/data` (`AFFILIATE_TERMS` у `src/data/affiliates.ts`) і підставляють так само. Ціни підлягають тому самому правилу: `TIER_PRICES` (`src/data/license.ts`) і `CONSULTING_HOURLY_RATE` з `src/data/marketing.ts` потрапляють у повідомлення як `{price}`, а в MDX як `<TierPrice tier="core" />`, а контактна адреса потрапляє в повідомлення з `CONTACT_EMAIL` у `src/presentation/branding/index.ts` як `{email}`. Ліміти пристроїв із `LICENSE_ACTIVATION_LIMITS` потрапляють у повідомлення `machines` карток планів як `{limit}`, а в MDX як `<ActivationLimit tier="core" />`. Компоненти читають `REPOSITORY_FACTS` напряму: запуск тестів у розділі про якість виводить `Test Files` з `REPOSITORY_FACTS.testFiles`, тобто кількістю файлів, що відповідають шаблонам `include` у Vitest. Число, яке дає лише запуск набору, як-от кількість окремих тестів, не показують.

Шляхи до файлів і команди, які наводить текст, теж є фактами з репозиторію, щоб жодна локаль не могла їх перекласти. `RecordSection` на лендингу передає `{coverageSummaryPath}`, `{coverageCommand}`, `{ciWorkflowPath}`, `{e2eSpecsPath}`, `{messagesPath}`, `{i18nCheckCommand}` і `{authIntegrationPath}` з `REPOSITORY_FACTS`: каталог підсумку — це `reportsDirectory` у `vite.config.ts`, каталог specs — `testDir` у `playwright.config.ts`, а `repository-facts.test.ts` перевіряє, що кожен шлях існує і кожна команда є скриптом із `package.json`.

Сторінки документації теж не вписують значень, які визначає код. `<RepositoryFact name="…" />` у `src/presentation/components/custom/repository-fact.tsx` виводить виміряну кількість, параметр, який `repositoryFacts` читає з `vite.config.ts`, `playwright.config.ts`, `.nvmrc`, `package.json` або workflow-файлу, чи константу, імпортовану з коду, як-от `RATE_LIMITS` або `PLAYBACK_TTL_SECONDS`. Він форматує число для локалі сторінки, з `unit="second"`, `"minute"`, `"hour"`, `"day"` або `"percent"`, коли значення має одиницю виміру, а текст виводить як код, список — як список коду. `<RepositoryTable name="…" columns={["…", "…"]} />` виводить таблицю, побудовану з коду, як-от декларації дозволів, типи комітів чи регіональні множники цін, під назвами стовпців, які перекладає сторінка. Клітинка, що називає повідомлення його повним ключем, — `{ label: "components.custom.pricing.status.arriving" }` разом із `values`, коли повідомлення приймає аргументи, — виводить це повідомлення мовою сторінки, тож таблиці дорожньої карти з варіантами CLI й можливостями планів показують ті самі підписи, що й конфігуратор і картки цін, а таблиці сценаріїв показують підпис кожної можливості з `flow-features`. Клітинка `{ text: "…" }` виводить звичайний текст, як-от результат сценарію. Будь-яка інша текстова клітинка — це значення з коду, і вона виводиться як код: значення без пробілу ніколи не переноситься, а значення з кількох слів переноситься лише між ними. З `grouped` таблиця бере першу клітинку кожного рядка як заголовок окремої таблиці, тож дорожня карта показує сценарії, які ще треба протестувати або створити, в одній невеликій таблиці на кожну можливість. Час кешування роутера й ліміт листів на одного отримувача оголошено в `src/integrations/tanstack-query/query.cache.ts` і `src/modules/rate-limit/rate-limit.constants.ts`, а не в `src/router.tsx` і суто серверному `src/lib/rate-limit.ts`, які документація не може імпортувати; тест компонента порівнює значення, які він виводить, з роутером і обмежувачем. Значення, яке має залишатися в блоці коду чи у frontmatter, натомість перевіряє `scripts/check-content.ts`.

## Документація та блог

Кожна сторінка в `content/docs`, кожен допис у `content/blog` і кожен запис журналу змін у `content/changelog` існують як `<slug>.<locale>.mdx` у кожній локалі, а навігація кожної папки — як `meta.<locale>.json`. `scripts/check-content.ts`, який запускає `bun run check:content`, завершується помилкою, коли:

- бракує файлу локалі;
- блок коду відрізняється від англійського (блоки коду копіюються байт у байт);
- `meta.<locale>.json` перелічує інші slug-и, ніж англійський;
- заголовок, опис чи абзац усе ще англійською;
- переклад допису блогу має інший `date` чи `updated`, ніж англійський допис;
- у тексті залишився маркер машинного перекладу;
- переклад звертається до читача у формі, якої його локаль не використовує (див. [Одна форма звертання](#one-form-of-address));
- гола URL-адреса без пробілу зливається з текстом після неї, як перед японською дужкою чи крапкою повної ширини, тож її посилання захопило б і цей текст;
- блок коду із заголовком-шляхом у репозиторії, як-от `title="src/integrations/better-auth/auth.access.ts"`, не є фрагментом цього файлу;
- сторінка документації називає локальний хост або піддомен `APP_DOMAIN`, якого `appHostsForMode` не дозволяє в жодному режимі збірки;
- запис журналу змін названо ні номером pull request, ні повним хешем коміту або запуск CI для pull request не знаходить `content/changelog/<number>.en-US.mdx` з його номером;
- довідник маршрутів, сторінка скриптів або таблиця змінних середовища пропускає константу `ROUTES`, скрипт `package.json` чи секрет `wrangler.jsonc` або подає для нього неправильне значення;
- внутрішнє посилання закінчується скісною рискою, `/index` чи `.html` або починається з локалі чи мовного псевдоніма на кшталт `/pl/`: сайт перенаправляє такий шлях, а `localizeHref` додає локаль сторінки до кожного внутрішнього посилання;
- переклад пропускає чи додає вбудований код, компонент, prop компонента, крім `title`, `description`, `excerpt` і `unreleased`, або посилання на іншу сторінку чи має іншу кількість рядків таблиць, ніж англійська сторінка.

Пишіть переклади так, як писав би носій мови, з термінологією, яку локаль уже використовує в `messages/<locale>/` (польська, наприклад, називає тарифи Podstawa, Komplet і Agencja, а знижку — rabat). Ідентифікатори коду, шляхи до файлів, команди й назви продуктів залишаються без змін, а посилання зберігають свої шляхи `/docs/...` без префікса локалі, який сайт додає під час рендерингу. Німецька мова дотримується [посібника зі стилю німецької мови](/docs/conventions/german-style), а польська — [посібника зі стилю польської мови](/docs/conventions/polish-style), чиї глосарії визначають кожен німецький і польський термін.
