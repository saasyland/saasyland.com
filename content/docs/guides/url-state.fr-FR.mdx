---
title: "État dans l'URL"
description: "Conservez onglets, vues et jetons à usage unique dans des paramètres de recherche validés."
---

Les paramètres de recherche conservent l'état qui doit survivre à un rechargement ou à un lien partagé : l'onglet ou la vue sélectionnés, une adresse e-mail transmise entre les pages d'authentification, un jeton de vérification. Tout le reste reste dans l'état React. `DataTable` garde sa pagination, son tri, sa sélection et ses filtres dans l'état du composant.

## Déclarer les paramètres

`validateSearch` reçoit un objet zod : les paramètres de recherche de la route sont typés et validés au même endroit. Ses champs viennent de `src/lib/search-params.ts` : `searchText()` et `searchFlag()` valent `undefined` quand la valeur manque, est vide ou mal formée : une valeur absente n’apparaît donc jamais dans l’URL ; `searchChoice(choices, fallback)` revient à un choix. `searchParam(schema)` applique la même règle à n’importe quel schéma zod ; les routes de la newsletter lisent `token` avec le schéma de jeton du module. Une valeur mal formée ne mène jamais à une page d’erreur. Extrait de `src/routes/admin.blog.index.tsx` :

```tsx
validateSearch: zod.object({
  view: searchChoice([ADMIN_BLOG_VIEW.GRID, ADMIN_BLOG_VIEW.TABLE], ADMIN_BLOG_VIEW.GRID),
}),
search: { middlewares: [stripSearchParams({ view: ADMIN_BLOG_VIEW.GRID })] },
```

`stripSearchParams` retire la valeur par défaut de l'URL, si bien que `/admin/blog` reste l'adresse canonique de la vue en grille.

## Les lire

- Dans le composant de la route : `const { view } = Route.useSearch()`.
- Avec un sélecteur, le composant ne se réaffiche que si la valeur sélectionnée change : `Route.useSearch({ select: (search) => search.error !== undefined })`.
- Dans un composant hors du fichier de route : `getRouteApi("/auth/reset-password").useSearch()`, comme dans `reset-password-form.tsx`.

## Les modifier

- Liens : `<Link search={{ view: id }} to={ROUTES.ADMIN_BLOG}>`.
- Les composants React Aria dotés d'un `href`, comme `TabsTrigger` dans `src/routes/admin.products.index.tsx`, naviguent via le routeur, car `AriaProvider` relie React Aria à TanStack Router.
- Code : `router.navigate({ search: { email }, to: ROUTES.VERIFY_EMAIL })`.
- Gardes et loaders : `throw redirect({ replace: true, to: ROUTES.AUTH_CALLBACK })`.

## Charger des données à partir d'eux

Un composant lit les paramètres de recherche avec `Route.useSearch()` ; un loader qui dépend de l’un d’eux le déclare dans `loaderDeps` et le lit dans `deps`. Ne consommez jamais un jeton de l’URL dans un loader, car le préchargement, les robots d’indexation et les scanners de courriels exécutent les loaders. Les pages de confirmation et de désinscription de la newsletter lisent leur jeton et n’agissent que lorsque le visiteur appuie sur le bouton :

```tsx
const { status, token } = Route.useSearch()
```

## Langues et URL

- Les liens du routeur (`<Link to={ROUTES.X}>`) reçoivent le préfixe de langue du `rewrite` du routeur. L'anglais n'a pas de préfixe (`/docs`) ; les autres langues en ont un (`/pl-PL/docs`).
- Construisez une URL brute dans la langue courante avec `router.buildLocation({ search, to }).publicHref`, qui la localise et sérialise ses paramètres de recherche, comme le fait `useAuthRedirect` pour `callbackURL` et `errorCallbackURL` de Better Auth. `localizePathname({ locale, pathname })` construit une URL pour une langue donnée, comme les liens dans les e-mails ; les chemins `/api` et les URL externes restent inchangés.
- Le sélecteur de langue pointe vers le même chemin dans l'autre langue avec un rechargement complet de la page ; la query et le fragment ne sont pas conservés.
