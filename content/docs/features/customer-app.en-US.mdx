## Layout

`src/routes/app.tsx` belongs to the auth area. It guards the workspace with `requireSignedIn` and preloads its namespaces, with those other areas add to it (`layoutNamespaces("/app")`; the licence area adds `pages.license`):

```tsx
const NAMESPACES = ["auth.errors", "pages.app.sidebar", "timezones", ...layoutNamespaces("/app")] as const

export const Route = createFileRoute("/app")({
  beforeLoad: requireSignedIn,
  component: AppLayout,
  loader: ({ context }) => preloadNamespaces({ locale: getCurrentLocale(), namespaces: NAMESPACES, queryClient: context.queryClient }),
  pendingComponent: AppPending,
  staticData: { namespaces: NAMESPACES },
})
```

`AppLayout` renders `AppSidebar` and `AppHeader` from `src/presentation/components/custom/app` inside the shadcn `SidebarProvider`. The sidebar builds its links from `APP_NAVIGATION` in `src/data/navigation.ts` (Overview and Settings from `auth.navigation.ts`, Licence from `license.navigation.ts`, labelled from `navigation.auth.json` and `navigation.license.json`) and its resources from `APP_RESOURCE_NAVIGATION` (Documentation from `content.navigation.ts`), followed by the support address, reads the user from the route context (`getRouteApi("/app")`) and ends with `SignOutButton`. The header shows the current page and a link back to the website. Admins land on `/admin` after sign-in, everyone else on `/app`.

## Pages

| Route           | Content                                                                                                                                                                                   |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/app`          | `LicenseOffer` without an active licence, otherwise `LicenseStatusCard` (tier, status and a link to the licence page); links to the docs and to support by email.                         |
| `/app/license`  | `LicenseOffer` without an active licence, otherwise `LicenseCard` (key, CLI commands, customer portal link, how to change tier) and, once Polar has issued the key, `LicenseActivations`. |
| `/app/settings` | `PreferencesCard`: the time zone of every date in the workspace, with a search and **Detect from this browser**. See [Settings](/docs/features/settings).                                 |

`LicenseOffer` (`src/presentation/components/custom/app/license-offer.tsx`) reuses the landing page's `PricingTiers` with a `CheckoutButton` for each tier, adds the purchase terms (`CheckoutAgreement`) and ends with the sections that other areas add to it (`LICENSE_OFFER_SECTIONS` in `src/data/license-offer.ts`), each with its skeleton and the data its pages load. The courses area adds `CourseUnlocks` (`src/data/courses.license-offer.ts`): the published courses that have paid lessons, with the number of locked lessons in each, counted from D1 by `getCatalogue`. The block is left out while no course has a paid lesson. A refunded licence keeps its card and gets the offer next to it.

`src/routes/app.index.tsx` belongs to the auth area, and the other areas add to the overview in `src/data/<area>.app-overview.ts`, which `src/data/app-overview.entries.ts` joins: the search params they read, which `appOverviewSearchSchema` (`src/data/app-overview.ts`) validates, and their sections, each with its skeleton and the data the page loads. The licence area adds `LicenseOverview` (the activation panel, the chosen tier, `LicenseStatusCard` or the offer) and the two params of `licenseSearchSchema` (`src/data/license.ts`), which `/app/license` validates as well. Both are optional and ignored when invalid:

| Param        | Value                  | Effect                                                                                                                            |
| ------------ | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `tier`       | a `LICENSE_TIER` value | `ChosenTier` above the offer: the tier, its price and a **Continue to checkout** button.                                          |
| `checkoutId` | a UUID from Polar      | `CheckoutActivation` instead of the offer until the licence is active, then a thank-you. See [Licences](/docs/features/licences). |

The overview's loader runs the loads of its sections, so the licence area preloads `currentLicenseQuery` and the course catalogue there; `/app/license` preloads both and `licenseActivationsQuery`. `/app/settings` loads only its page namespace, and the layout's `NAMESPACES` include `timezones` for the zone names. Checkout, webhooks and licence states are described in [Licences](/docs/features/licences).

## CLI instructions

`LicenseCard` lists the commands that use the key on a machine, <RepositoryFact name="cliLicenseCommands" />, each with what it does, and says that CI reads the key from <RepositoryFact name="cliLicenseKeyVariable" />. `src/data/cli.ts` is their one source, and it also builds the landing page's <RepositoryFact name="scaffoldTarget" />. `CLI_RELEASE_CHANNEL` names the npm tag that the CLI runs from. The CLI and `@saasyland/stack` are released together under one version, so `cli.test.ts` fails unless the tag is the one that the installed `@saasyland/stack` was published on: `beta` for a prerelease `x.y.z-beta.n`, npm's default tag for a stable release. Upgrading `@saasyland/stack` to a stable release therefore fails the tests until `CLI_RELEASE_CHANNEL` names the default tag, and the licence page, the landing page, the docs and the [journey suite](/docs/tooling/playwright#journey-suite) follow it. It is a constant rather than an import of `@saasyland/stack/package.json`, which would put the whole file in the Worker and in every page's bundle.

## Skeletons

`AppOverviewPending` and `AppSettingsPending` (`app/auth-pending.tsx`, declared by the auth area in `src/data/auth.skeletons.ts`) draw the page header from `app/pending-blocks.tsx`. Below it, the overview draws the skeleton of each section the areas add, then the docs and support steps, and the settings page draws `PreferencesCardPending`. `LicenseOverviewPending`, the skeleton of the licence section, and `AppLicensePending` (`app/license-pending.tsx`; the licence area declares `AppLicensePending` in `src/data/license.skeletons.ts`) mirror the state the page will show: they read the search params with `licenseSearchSchema` and the cached licence and catalogue from the query client, and draw the activation panel, the chosen tier, the tier grid with one row per course with paid lessons, or the licence cards.

There are no billing history or course screens in `/app`, and `/app/settings` has no profile, email or password forms yet.
