The application runs as one Cloudflare Worker. `@cloudflare/vite-plugin` builds it, and `CLOUDFLARE_ENV` selects the Wrangler environment. `wrangler.jsonc` sets `main` to `./src/server.ts`, enables `nodejs_compat` and observability, and serves static files through the `ASSETS` binding. The Worker runs first for every path except `/assets/*`, `/fonts/*`, `/robots.txt` and `/llms.txt`. Source maps are not uploaded (`upload_source_maps` is `false`), because the Worker and its source maps together exceed the size Cloudflare accepts in one upload.

| Environment   | Worker                  | D1, KV and R2                        | Domain                  |
| ------------- | ----------------------- | ------------------------------------ | ----------------------- |
| `development` | `saasyland-development` | Local resources in `.wrangler/state` | `localhost:3000`        |
| `preview`     | `saasyland-preview`     | Preview resources                    | `preview.saasyland.com` |
| `production`  | `saasyland`             | Production resources                 | `saasyland.com`         |
| `test`        | `saasyland-test`        | Local resources in `.wrangler/test`  | `127.0.0.1:3000`        |

Every environment binds D1 as `DB`, KV as `CACHE` and R2 as `MEDIA` and `BUNDLES`, and lists its required secrets. `AFFONSO_PROGRAM_ID`, the program ID that affiliate referral tracking needs, is a plain variable under `vars`, set in `production` and, with a dummy ID, in `test`. Tracking runs only when the Worker has the ID and the programme is open: `AFFILIATE_PROGRAM` is <RepositoryFact name="affiliateProgram" /> today ([Opening the programme](/docs/features/affiliates#opening-the-programme)). The `test` environment uses `src/platform/testing/worker.ts` as its entry; it intercepts Resend and Polar requests and exposes test-only endpoints for Playwright.

## Request flow

`src/server.ts` handles every request:

1. A path that an area claims goes to that area's request handler before anything else. The courses area claims `/media/` and hands course covers to `serveCover`, lesson materials to `serveAttachment` and signed video files to `serveMedia`, which read them from R2, covers and videos through the Workers cache (see [Cloudflare R2](/docs/integrations/cloudflare-r2)), and the licence area claims `/bundles/` and hands it to `serveBundle`, which serves the CLI's signed template bundles from R2 (see [CLI licence API](/docs/features/cli-licence-api#template-bundles)). Of the steps below, only the security headers apply to them.
2. `resolveLocale` from `i18n.middleware.ts` inspects `GET` and `HEAD` document requests outside `/api` and `/_serverFn`. It redirects language aliases and non-canonical locale paths with status 308 and reports when the locale cookie differs from the URL locale.
3. `GET` and `HEAD` requests outside `/api` and `/_serverFn` are served from `ASSETS` first, which covers prerendered pages. A 404 falls through to the TanStack Start handler.
4. When the locale cookie needs an update, the Worker appends it to the response. HTML responses also receive a `Link` preload header for the locale's fonts, which Cloudflare sends as Early Hints (see Zone settings below).
5. HTML responses pass through the document handlers of the areas. The licence area's handler adds regional pricing: when the `cf-ipcountry` country qualifies for a purchasing-power discount, an `HTMLRewriter` adds the discount attributes to `<html>` and the response becomes `private, no-cache`.
6. Every response, including redirects, API calls and media files, gets the security headers from [Security and hardening](/docs/features/security), and every HTML response, rendered or prerendered, gets a script policy with a nonce of its own, which Cloudflare also gives to the scripts it injects. Files that skip the Worker get the same set from `public/_headers`.

`src/server.ts` names no area: each area declares its request and document handlers in `src/data/<area>.worker.ts`, and `src/data/worker.entries.ts` joins them (see [What the areas add](/docs/architecture/platform-layer#what-the-areas-add)).

## Zone settings

Two settings of the zone act on every page. Both are under **Speed** > **Settings** > **Content Optimization** in the Cloudflare dashboard:

- **Early Hints**: on. Cloudflare keeps the `Link` header of a page's last response and sends it as a `103 Early Hints` response while the Worker prepares the next response for the same URL, so the browser starts downloading the fonts earlier. The header names only the fonts, because Cloudflare also replays it after a deploy; see [Performance](/docs/conventions/performance).
- **Speed Brain**: off. It adds a `Speculation-Rules` header that asks Chromium to prefetch a link the visitor is about to open, but Cloudflare refuses to prefetch a URL that runs a Worker, and every page here does (`run_worker_first`), so each prefetch fails with `503` and `cf-speculation-refused: prefetch refused: disabled for worker requests`. Cloudflare also lists policies with `'strict-dynamic'` and nonces, such as this one, as unsupported. Turning it off costs nothing: TanStack Router already loads the code and data of a link under the pointer (`defaultPreload: "intent"`), and of every header link once a page is idle, and opens it without requesting a new document. Speed Brain is on by default on the Free plan.

## Deployment

`bun run deploy:preview` and `bun run deploy:production` run `scripts/verify-bindings.ts`, which rejects missing bindings and placeholder D1 and KV IDs, then `scripts/prepare-deploy-secrets.ts`, which rejects an empty or placeholder value among the secrets that `wrangler.jsonc` declares, then `scripts/run-deploy-checks.ts`, which runs the deploy check of every area, today `auth:verify:<environment>`, which checks the format of the OAuth client IDs, and `polar:verify:<environment>`, which compares the environment's Polar organisation with the code, then the matching build, the environment's D1 migrations, `wrangler deploy` of `dist/server/wrangler.json` with those secrets, and `scripts/verify-deployment.ts`, which checks the live site. The R2 buckets, `MEDIA` and `BUNDLES`, are bound by name and must exist before the first deploy; create them with `wrangler r2 bucket create`. Builds prerender public pages and run `scripts/verify-build.ts` and `scripts/optimize-prerendered-html.ts`. See [Deploy a preview](/docs/getting-started/deploy-preview), [Project scripts](/docs/tooling/scripts) and [CI/CD](/docs/tooling/ci-cd).

Each build compiles the Worker twice. The first Worker contains every page and prerenders the public ones. After prerendering, `scripts/deployed-worker.ts` rebuilds the Worker that is deployed without what only prerendering needs: every import of a compiled docs or blog page resolves to one module that throws, and the translations that only the landing and legal pages use are left out. Prerendered pages are served from `ASSETS`, and client navigations read the docs and blog indexes and render MDX from the browser chunks, so the deployed Worker never reads the content. `scripts/verify-build.ts` fails the build when a docs page or a published blog post was not prerendered, and when any file of the deployed Worker holds a docs or blog module.
