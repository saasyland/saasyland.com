- 追加: `bun run deploy:<environment>` は、何かをビルドする前に、プレースホルダーを含むシークレットを拒否します。`scripts/prepare-deploy-secrets.ts` は `scripts/verify-bindings.ts` の直後に実行されるようになり、`wrangler.jsonc` が宣言するシークレットが欠けているか空のとき、または本番環境に `AUTH_GOOGLE_CLIENT_ID` として届いていた `[UPDATE]` のような括弧で囲まれた値や、`TODO` や `changeme` のような単語を含むときに失敗します。エラーにはキーの名前が表示され、値は表示されません。[プロジェクトのスクリプト](/docs/tooling/scripts) を参照してください。
- 追加: 認証エリアのデプロイ前チェック `auth:verify` は、`.env.<environment>` の `AUTH_GOOGLE_CLIENT_ID` と `AUTH_GITHUB_CLIENT_ID` がそれぞれのプロバイダーの形式のクライアント ID を含んでいない限り、ビルドの前にデプロイを止めます。これはデプロイ後に公開サイトのサインインのチェックが使う形式と同じで、今は `src/data/auth.ts` の `OAUTH_CLIENTS` で一度だけ定義されています。`bun run auth:verify:preview` と `bun run auth:verify:production` で単独でも実行できます。[OAuth プロバイダー](/docs/features/oauth) と、Google の `Error 401: invalid_client` については [トラブルシューティング](/docs/reference/troubleshooting) を参照してください。
