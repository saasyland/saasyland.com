title: "機能を追加する"
description: "データベーステーブルからテスト済みのページまでを、詳細なガイドをつなぎながらたどるエンドツーエンドのウォークスルーです。"
---

機能は通常、すべてのレイヤーに関わります。テーブルのモジュール、そのユースケース、ルート、プレゼンテーションのコンポーネント、メッセージ、テストです。コースの実装が、この一連の流れをすべて示しています。`src/modules/course`、`src/routes/admin.courses.index.tsx`、`src/presentation/components/custom/admin/courses/course-columns.tsx` です。

## 1. データをモデル化する

機能が新しいデータを保存する場合は、そのテーブルのモジュールを追加し、マイグレーションを生成します。

- [モジュールを追加する](/docs/guides/add-a-module)
- [データベースマイグレーション](/docs/guides/database-migrations)

## 2. 誰が何をできるかを決める

`APP_STATEMENTS`（`src/integrations/better-auth/auth.access.ts`）にあるリソースのステートメントに新しいアクションを追加し、`ROLES` でロールに付与します。外せる機能は、新しいリソースを `scripts/features.ts` の自分の `names` に記載します。

- [ロールと権限](/docs/guides/roles-and-permissions)

## 3. 操作を実装する

操作ごとに 1 つのユースケースを追加し、そのミドルウェア、バリデーター、ハンドラー、クエリオプションまたはミューテーションオプションを定義します。

- [ユースケースを追加する](/docs/guides/add-a-use-case)
- [サーバー関数](/docs/guides/server-functions)

## 4. ルートを追加する

1. パスを `src/routes.ts` に、メニュー項目を `src/data/navigation.ts` のリストに、それぞれラベルの完全なキーとともに宣言し、オプションの機能のパスは `scripts/features.ts` のその機能の `names` に挙げます（[パスとナビゲーション](/docs/conventions/routes#paths-and-navigation)を参照）。
2. 領域に応じたフラットなルートファイルを作成します。管理画面のレイアウトの下なら `src/routes/admin.<feature>.tsx`、サインイン済みの顧客向けレイアウトの下なら `src/routes/app.<feature>.tsx`、公開ページなら `src/routes/_site._marketing.<page>.tsx` です。
3. ルートの規約に従います。`const NAMESPACE`、`staticData: { namespaces: [NAMESPACE] }`、`head: pageHead(ROUTES.X)`、メタデータ、メッセージ、レスポンスの最初の送信に必要なデータを 1 つの `Promise.all` で await し、残りをページのスケルトンへストリーミングするローダー、そしてページ専用のスケルトンを `pendingComponent` として用意します。別の場所からレイアウトに入ったときは、レイアウトスケルトンもこのスケルトンを表示します（[読み込み中のスケルトン](/docs/architecture/delivery-layer#loading-skeletons)を参照）。
4. レイアウトの `beforeLoad` ガード（`/admin` では `requireAdmin`、`/app` では `requireSignedIn`）がページを保護します。それでも、サーバー関数はすべての呼び出しを自ら認可します。

- [管理画面のページを追加する](/docs/guides/add-an-admin-page)
- [URL の状態](/docs/guides/url-state)

## 5. UI を構築する

ウィジェット、ダイアログ、フォーム、テーブルのカラムは、領域ごとのフラットなフォルダー `src/presentation/components/custom/<area>/`、管理画面の機能なら `src/presentation/components/custom/admin/<feature>/` に、1 ファイルに 1 つずつ置きます。各コンポーネントは自分の翻訳とデータを自ら読み込み、ルートはそれらを組み合わせるだけです。

- [データグリッドを追加する](/docs/guides/add-a-data-table)
- [フォームとバリデーション](/docs/guides/forms-and-validation)

## 6. メッセージを追加する

ページの名前空間と、必要であればバリデーション用の名前空間を、すべてのロケールに作成します。ページの名前空間には `metadata.title` と `metadata.description` が必要です。

- [国際化とロケール](/docs/guides/i18n-messages)
- [メールテンプレート](/docs/guides/email-templates)（機能がメールを送信する場合）

## 7. テストと検証

ユースケース、コンポーネント、ルートをテストでカバーしてから、ゲートとその機能のスペックを実行します。プルリクエストがマージされる前に、CI がブラウザーのスイート全体を実行します。

```sh
bun run check
bun run test:coverage
bun run build:test
bunx playwright test e2e/specs/<spec>.spec.ts --project=chromium
```

- [テストを書く](/docs/guides/writing-tests)
- [セキュリティチェックリスト](/docs/guides/security-checklist)
