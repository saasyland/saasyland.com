## Identité de la marque

`src/presentation/branding/index.ts` est la source unique de l'identité du produit : `APP_NAME`, `APP_DOMAIN`, `APP_URL` (dérivé sous la forme `https://${APP_DOMAIN}`), `CONTACT_EMAIL`, `NOTIFICATIONS_EMAIL`, `APP_FOUNDED_YEAR`, le propriétaire, le dépôt et les URL GitHub ainsi que le profil Instagram, `APP_INSTAGRAM_URL`. Les titres de page, les URL canoniques, le nom de l'application dans Better Auth, l'émetteur de la double authentification et les noms des cookies de thème et de langue en dérivent. Les messages qui nomment le produit le reçoivent en argument, jamais en texte : les métadonnées de page via `loadPageMetadata`, le texte d’inscription et les aperçus des e-mails reçoivent `{appName}`, et l’e-mail de confirmation de la newsletter `{appDomain}`, si bien que renommer l’application change chaque message.

Lors d'un changement de marque, mettez aussi à jour :

- `Wordmark` dans `src/presentation/components/custom/wordmark.tsx` : le logo SVG intégré à côté de `APP_NAME`.
- `public/favicon.ico` et les images de `public/images`.
- `APP_SLUG` dans `src/presentation/branding/index.ts`, le nom court qui préfixe les cookies d'authentification et le dossier temporaire du seed de test, et les hôtes autorisés par environnement dans `src/modules/_core/constants/api.ts`.
- `APP_GITHUB_OWNER`, `APP_GITHUB_REPO` et `APP_INSTAGRAM_URL` dans `src/presentation/branding/index.ts` : votre dépôt et vos profils, vers lesquels renvoie le pied de page et que citent les données structurées de la page d’accueil.

Recompilez après avoir changé la marque ; les fichiers d'environnement ne modifient pas l'URL canonique.

## Thème

`src/presentation/theme/index.ts` définit `THEME` : les thèmes `light`, `dark` et `system`, le thème par défaut `system` et le cookie qui mémorise le choix. `ThemeScript`, dans l'en-tête du document racine, applique le thème enregistré avant le premier affichage : les pages ne clignotent donc jamais avec le mauvais thème. `ThemeSwitch` (`src/presentation/components/custom/theme-switch.tsx`) le modifie. `ThemeProvider` (`src/providers/theme-provider.tsx`) n'enveloppe que les composants qui utilisent le thème, comme `<ThemeSwitch />` dans `src/routes/_site.docs.tsx` et le toaster de la route racine. Il n'enveloppe jamais un `Outlet` de route, car il se met à jour après l'hydratation et réafficherait toute la page.

## Tokens de couleur

`src/presentation/styles/globals.css` est l'unique point d'entrée de Tailwind. Il définit les tokens shadcn (`--background`, `--foreground`, `--primary`, `--muted`, `--border`, `--ring`, `--sidebar-*`, `--chart-*` et d'autres) dans `:root` pour le mode clair et dans `.dark` pour le mode sombre, puis les associe aux couleurs Tailwind dans `@theme inline`. Modifiez les valeurs à cet endroit ; les composants utilisent les classes sémantiques (`bg-background`, `text-muted-foreground`, `border-border`). Les accents d'état, comme l'ambre et le rose, font exception.

`docs.css` et `typeset.css`, dans le même dossier, sont du CSS simple chargé uniquement par les layouts de la documentation et du blog.

## Échelle typographique

L'échelle typographique est un ensemble de tokens `--text-*` dans `globals.css` : `display-hero`, `display-gate`, `display-blast`, `headline-peak`, `headline-support`, `price`, `title`, `statement`, `lead`, `body`, `body-sm`, `code`, `label` et `spec`. Chaque token définit la taille, l'interlignage et l'espacement des lettres, les plus grands aussi la graisse, et s'utilise comme classe : `text-body`, `text-title`, etc. Les petites tailles ont un plancher, et Geist Mono est réservée au code ; voir [Thème](/docs/ui/theme#type-scale).

Lorsque vous ajoutez un token `text-*`, ajoutez aussi son nom à `src/lib/cn.config.ts`. `cn` de `src/lib/cn.ts` utilise cette configuration pour traiter les tailles personnalisées comme des tailles de police lors de la fusion des classes ; sans elle, `cn` les supprime. `bun run generate:cn` régénère les tables de classes et s'exécute dans `dev`, `build` et `check`.

## Polices

Geist et Geist Mono sont auto-hébergées dans `public/fonts` et déclarées avec `@font-face` dans `src/presentation/styles/fonts.css`, un fichier par plage Unicode. `fontPreloads` dans `src/presentation/document-assets.ts` précharge le latin et le latin à chasse fixe sur toutes les pages, le latin étendu pour `pl-PL` et le cyrillique pour `uk-UA`. Pour changer de polices, remplacez les fichiers et les règles `@font-face`, puis mettez à jour la liste de préchargement en conséquence.
