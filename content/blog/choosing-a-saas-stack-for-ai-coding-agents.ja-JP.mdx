## 実際にAIコーディングエージェントのスタックは?

スタックはエージェントを正しくしません。 変更する **間違ったプログラムが何であるか**. . 各ライブラリの選択は、コンパイルするコードのスペースを縮小するか、それを拡張するかのいずれかです。 つまり、全機構であり、それが「エージェントフレンドリー」がバイブではなくテストできるプロパティである理由です。

2つのコードベースで同じ間違いを考慮する。 エージェントは、タイムスタンプであるときにデータベースの列を文字列としてコピーします。

型のクエリビルダーでは、間違いは明示できません。 コードがコンパイルされず、エージェントは自身の実行中にエラーが表示され、それを修正します。 再燃費:約2秒。

生のクエリで返す `any`, 間違いはコンパイルします, それが正しく読みますので、レビューを渡す, 請求メールに誤った日付を生成 6 週間後. 再燃費:事件。

同じモデル。 同じプロンプト。 同じ間違い。 スタックはコンパイルエラーやインシデントであったかどうかを決定しました。

## 通貨のギャップ、そしてなぜ普及した停止がプロキシである

ここでは、誰もが作る引数です: 一般的なライブラリは、トレーニングデータでより頻繁に表示されますので、モデルはそれらをより正確に書きます。 最初の半分は真です。 今の後半は、引数が無視する何かに完全に依存します。 **ライブラリが変化する速度**.

**通貨ギャップは、実際に出荷するモデルのAPIとAPIの間の距離です。** トレーニング・データ・ボリュームは、モデルがライブラリを記述する方法を教えてくれます。 通貨のギャップは、その自信が保証されているかどうかをあなたに伝えます。 彼らは異なる量であり、高速移動フレームワークのために、彼らは今、反対の方向に点在しています。

この研究は、非曖昧です。 測定された8つの広く使用されているライブラリの研究 **25%から38%の非推奨のAPI使用率** モデル生成されたコードで、パラメトリックの知識や API のライブビューの欠如を宣言するためにそれをアトリビュートします。[APILOT、arXiv(アルシブ)](https://arxiv.org/pdf/2409.16526))。 進化する API では、知識の衝突と同じ失敗をフレーム化します。モデルは推測しないので、もはや存在しないバージョンを思い起こさせます()。[LLMs が後ろにラグするとき、arXiv](https://arxiv.org/html/2604.09515v1)).

偽りのないランキングを生成します。 モデルのメモリの原因がどれだけトラブルでソートされるか:

### それについてどうするか

モデルのメモリを固定することはできませんが、そのエラーを安くすることができます。

- **競合するときに人気を上回る安定性を優先します。** 半会員の5年テーブル APIは、完全に偽りのない API を打ち破る。
- **コンパイラがバージョンのドリフトをキャッチしてみましょう。** 廃止された-API エラーは、未入力の境界線でのみ高価です。 これは、エンドツーエンドタイプの本当の引数で、通常のものよりも強いです。
- **エージェントが読み込まれるドキュメントをピンとベンダーします。** 次回のアドバイスはガイドを読むことです。 `node_modules`ウェブではなく。 ローカルのドキュメントは、インストールされたバージョンと一致します。 2024 からのブログ投稿はありません。
- **信頼できないように新しい依存関係を扱います。** これは、セキュリティ上の問題であり、是正だけであるため、以下にもっと。

## エージェントスタックテスト

依存症ごとの4つの質問は、8ポイントのための0、1または2をスコアしました。 これは、リストではなく、テストのポイントであるときに存在しなかったライブラリに適用されます。

### 1。 1。 制約: コンパイルに失敗する誤用はできますか?

- **0**: ライブラリの手裏 `any`, または config は、文字列キード, または実行時にのみエラー表面です。
- **1**: 型は存在しますが、アドバイザリーです。間違った呼び出しは、キャストの下にコンパイルされます。
- **2**: Misuse はタイプエラーです。 間違ったプログラムが明示的ではありません。

### 2。 一貫性:仕事を行うための明らかな方法はありますか?

エージェントは模造で動作します。そのため、6つの同等のAPIを持つライブラリは、既に使用している1つのコードベースの1つのインスタンスの1つのチャンスを与えます。

- **0**: 多くの等しいアプローチ, 野生とすべての訓練データで共通.
- **1**: 推奨方法、および広く使用されているレガシーの代替手段。
- **2**: 1つの方法、代替品は非推奨ではなく消えます。

### 3。 検証性: エージェントが機能するかどうかを証明できますか?

- **0**: 修正は、実行中のアプリを見ている人だけが観察できます。
- **1**: テスト可能だが、設定は、エージェントがそれを行わないという十分なマニュアルです。
- **2**: 既にエージェントがカバーしているコマンド。

### 4。 通貨:現在のモデルのメモリですか?

- **0**: 昨年のメジャーバージョンは、公開APIの名前を変更したり削除したりします。
- **1**: 最近のマイナーな変更、またはから学んだモデルのドキュメントは、現在間違っています。
- **2**: パブリック API は、コードがまだ実行されているか、ライブラリがインストールされたバージョンと一緒に機械で読みやすい docs を出荷するのに十分な十分に安定している。

**スコアを読みます。** 7〜8は、エージェントが監視されていないと信頼できる依存性です。 4〜6は、タイプ境界または周囲のテストで動作することを意味します。 3以下は、あなたが所有するインターフェイスでそれをラップするか、またはすべてのコールサイトを書き込みます。

テストは意図的にについて記述します _シェイプ_ その品質ではなく、依存性。 優れたライブラリは、ここがひどくスコアを上げます(通貨で最高のライブラリのミッドリライトスコア0)、そして注目すべきもののスコアはよくあります。 この対策剤は、メリットではなく、適合します。

## テスト、層を層によって適用する

以下は、私たちが出荷するスタックであり、それが何かを要する場所を含め、正直に評価されます。 あなたの答えは異なる場合があります。 推論は譲渡可能な部分です。

### 言語: TypeScript、厳密な、エスケープ無し

**スコア: 8/8.** これは、リストの他のすべての選択肢がに依存します。

厳格なモードは、目標ではなく、フロアです。 エージェントに関係するプロパティは、通常、オフになっているもの:暗黙なし `any`、チェックされていないインデックスアクセス、非nullアサーションはありません。 それぞれのフラグは、ランタイムのサプライズから、エージェントがそのターンを終える前に、エージェントが参照する赤色に、自信を持って、間違ったエージェントの出力のクラスを変換します。

バージョンは、設定よりも少ない問題です。 厳密に設定された古いものよりも、エージェントの作業のために、緩やかに構成された最近の TypeScript が悪いです。

### 実行時間とフレームワーク: Bun, Next.js, React

**スコア: 6/8.** 制約2、コンバージェンス1、汎用2、通貨1。

これは、正直な弱点であり、同じ Next.js が警告している。 React のコアは、モデルメモリが信頼性が高いほど安定している。 枠組みのレイヤーがなかったり、通貨のポイントはコストがかかる。

代替コストがもっと要するので、その費用は非適格に支払われます: Reactは、フロントエンドの仕事におけるトレーニングデータの最大の正しいと安定した体を持っており、私たちが使用するすべてのライブラリで生態系を仮定し、雇用プール。 緩和は、そのメモリではなく、インストールされたドキュメントでエージェントを指しているのがNext自体が推奨されるものです。 2行目のエントリーです。 `AGENTS.md`建築が変化しない。

Convergence は、サーバーコンポーネント、クライアントコンポーネント、ルートハンドラ、サーバーのアクションが、データを移動する4つの方法であり、すべての電流、トレーニングデータのすべて、およびリポジトリが各パターンの1つの例を正確に持っていない限り、エージェントはバイブによって選択されます。

### API レイヤー: Bun で Elysia をタイプし終端

**スコア: 7/8.**

重要なプロパティはフレームワークではなく、ハンドラの入力と出力タイプが呼び出し元に表示されていることです。 ルートの形状が変化すると、現在間違っているすべてのコールサイトがコンパイルに失敗します。

競合他社のアドバイスは、通常、特定の RPC ライブラリの名前です。 プロパティではなく、プロパティの1つの実装です。 エンドポイントを変更する任意のアプローチは、そのコールサイトでビルドを分割します。 修飾しないものは明白です `fetch` エージェントの誤った仮定がきれいにコンパイルし、出荷し、顧客によって発見される境界であるため、コールサイトの手でタイプされたJSONルートに。

**API バウンダリは、エージェントの間違いが生き残るために行く場所です。**

### データベース: Drizzle 以上 Neon Postgres

**スコア: 8/8.**

スキーマはTypeScriptなので、マイグレーションソースとタイプソースの両方で、ドリフトには2番目のアーティファクトはありません。 存在しない列を参照するクエリは、500ではなくコンパイルエラーです。

2つのプロパティは、明らかなタイピングを超えてフルスコアを獲得します。 まず、クエリビルダーは、モデルのSQL知識(非常に大きく、非常に安定した、10年)が直接転送するSQLに十分に近く読みます。 2 番目に、Postgres 自体は、スタック全体で最高通貨の依存性です。SQL は、2021 年に学んだモデルが今日も実行されます。

### バリデーション:すべての外部境界で Zod

**スコア: 8/8.** これは、レイヤーの最もスタックがスキップされ、最も速く支払うレイヤーです。

タイプはあなたが信じるものを記述します。 スキーマをチェックします。 各場所のデータがプロセス(HTTP ボディ、環境変数、webhook ペイロード、サードパーティの応答、データベース JSON 列)に入る場所は、システムが promise を誰も検証しないと信頼している場所です。

エージェントは、この問題は、人間の仕事よりも多く機能します。 統合を書いている人間は、彼らが燃えているので、ペイロードの疑わしい傾向があります。 エージェントは、そのトレーニングデータがほとんど含まれているものであるため、完全な自信を持つ幸せなパスを書いています。 フィールドを命名するメッセージで、キャッチされたエラーに最適化するエッジのスキーマ。

### Auth: Better Auth, あなたのリポジトリで

**スコア: 7/8.**

エージェント関連プロパティは、実装が不透明のホストされたコールではなく、所有するソースであるということです。 エージェントは、セッションが発行される方法を読み、検証されたトークンに従って、差分でレビューできる方法で拡張することができます。

## 依存性カウントは代理店の表面区域です

全ての依存性は API で、モデルが誤って記憶する可能性があります。 これは、通常の「too多くの依存関係」引数をリフレームし、バンドルサイズとサプライチェーンについて、正しい引数にもなります。

このコードベースは、フル SaaS のモデストである 48 のランタイム依存関係を実行します。 どのような問題はカウントではなく、形状: ほぼすべては、私たちが所有する境界線で終わるか、またはラップするタイプされた端です。そのため、それらについての間違った仮定は、生産に失敗するのではなく、コンパイルに失敗します。

注意すべき2つ目の理由がありますが、セキュリティの1つです。 2025年10月と2026年3月の間に発売されたフロンティアモデルは、パッケージ名を率いて測定した **4.62% および 6.10%** ([arXiv(アルシブ)](https://arxiv.org/pdf/2605.17062))。 攻撃者は、その発明された名前を公共のレジストリに登録し、待機し、名前を付けられた攻撃を登録します。 **スロップスquatting** ([メルド](https://www.mend.io/blog/the-hallucinated-package-attack-slopsquatting/)).

実用的なルール: **エージェントが追加された依存性は、見知らぬ人からの未見のプルリクエストです。** パッケージが存在していることを確認してください。その名前は、近傍ではなく、あなたが実際にそれを必要としていることです。 Lockfiles とレビュー手順 `package.json` 変化はゼロ努力に近い露出のほとんどをカバーします。

## エージェントが単独で所有すべきこと

SaaS の部分は 1 つのプロパティを共有します。 **間違ったバージョンが正しく見え、テストを通過し、正しくデモを行ない、テストスイートが再現されていない条件下でのみ失敗します。** その特性は、難しさではなく、それらを解権するために安全にするものです。

| サーフェス                     | 間違ったバージョンがレビューを通過する理由                                  |
| ------------------------------ | --------------------------------------------------------------------------- |
| セッションとトークンの取り扱い | 作業中のログインは、有効期限、回転、または再発について何も証明しません。    |
| 支払のwebhooks                 | 再試行が到着するまで、非重要ハンドラが正しい                                |
| データベースのマイグレーション | ロールバックまでリバーシビリティとデータの損失は見えない                    |
| テナントの分離                 | クエリは、テストのテナントと2番目の人のために間違っているのに適しています。 |
| 秘密を読んでいるもの           | トークンのログは、完全に機能する一線の変更です                              |

webhook は最も明確なケースです。Stripe は非 2xx で retries なので、最初の配信で正しく充電し、再試行で再び充電するハンドラは、エージェントが書いたすべてのテストを渡すので、テストを書くには既に失敗モードを把握する必要があるからです。 モデル機能の制限はありません。 エージェントが書いたテストスイートは、そのトレーニングデータに障害モードを反映しており、不測のバグは、実際のお金の費用がどのくらいの頻度に相対的に存在しているということです。

これらのパスをマークします。 `AGENTS.md` 人間のみとして、要求された査読者とそれを取り戻すと、信頼されるのではなく、インテントが強制されます。

## よくある質問

<Accordions>

<Accordion title={"2026年のAIコーディングエージェントに最適な技術スタックとは?"}>

エンドツーエンド TypeScript、タイプされたデータベースレイヤー、外部境界線でスキーマ検証、リポジトリに住んでいるauth、および型チェック、整列、テストの1つのコマンド。 特定のライブラリは、誤用がコンパイルに失敗するかどうかをはるかに少なくします。 制約、コンバージェンス、汎用性、通貨など、採用前に任意の候補をスコアします。

</Accordion>

<Accordion title={"一般的なフレームワークを選択すると、AI コーディングエージェントが役立ちますか?"}>

それよりも少なく、時には全く使用していません。 人気は、モデルをより多くのトレーニングデータを与えるが、訓練されたバージョンのみ。 モデルのリトレインが自信を持って、インフルエント、間違ったコードを生成するよりも速く変化する変化を出荷するフレームワーク。 ライブラリが素早く動くと、ボリューム以上の安定性が重要になります。

</Accordion>

<Accordion title={"エージェントが存在しないAPIを使用してコードを書くのはなぜですか?"}>

訓練されたバージョンをリコールするので。 研究は、広く使用されている8つのライブラリ全体で25%から38%の非推奨のAPI使用率を測定し、パラメトリックの知識を固定し、今日のAPIが何であるかのライブビューはありません。 あなたのタイプチェッカーは、このために最も安い補正です, これは、非タイプされた境界は、問題が生き残る場所である理由です.

</Accordion>

<Accordion title={"AIエージェントが自分の依存関係を選ぶようにすればいいですか?"}>

各パッケージが存在しているかどうかはチェックしません。 2025年10月と2026年3月の間にリリースされたフロンティアモデルは、4.62%と6.10%の間の速度でパッケージ名を幻覚し、攻撃者は、現在、公共の規制にそれらの発明された名前を登録します。 新しい依存症を扱い、エージェントは見知らぬ人のプルリクエストとして追加します。

</Accordion>

<Accordion title={"モノレポはAIコーディングのエージェントにとって優れているのでしょうか?"}>

読み出しではなく、ツールによって境界が強制される場合のみ。 パッケージ境界が交差したときにビルドに失敗したモノレポは、あなたのアーキテクチャを秒単位で教えます。 条約によって一緒に保持されるモノレポは、エージェントが間違ったパッケージに正しいコードを置くためにより多くの場所を与えます。

</Accordion>

<Accordion title={"SaaS のどの部分が、エージェントが単独で書くべきか?"}>

信じられないほどの間違いが高価でサイレント:セッションとトークンの処理、支払いのWebhooks、データベースの移行、テナントの分離、および秘密を読んで何か。 これらは、間違ったバージョンがテストやデモを正しく渡すことであり、あなたのテストスイートが再現されていない条件の下でのみ失敗するプロパティを共有します。

</Accordion>

<Accordion title={"エージェントフレンドリー API には tRPC や oRPC が必要ですか?"}>

ネットワーク境界を横断するタイプが必要です。特定のライブラリはセカンダリです。 クライアントが変更されたエンドポイントを呼び出すとコンパイルが失敗する任意のアプローチが行われます。 間違った仮定がきれいにコンパイルし、生産に到達する境界であるため、仕事が非定型JSONルートに明白なフェッチです。

</Accordion>

<Accordion title={"エージェント・アシスト・コードベースには、いくつの依存関係がいくつありますか?"}>

パッケージではなく表面をカウントします。 すべての依存性は API で、モデルは誤って記憶する可能性があるので、問題は、ロードベアリング、不慣れ、チェックされていないです。 厳密なタイプおよびテスト費用によって覆われる依存性は少しかかります。 あらゆる将来の変化に対して、未入力のデータをビジネスのロジックコストに返すもの。

</Accordion>

<Accordion title={"Tailwind は、AI のコーディングエージェントに実際に役立ちますか?"}>

はい、構造的な理由ではなく、スタイリスティックなもののために。 スタイルはスタイルはスタイル要素に座っているので、エージェントが開き、更新を記憶しなければならない2番目のファイルはありません。 同じ引数は、コロケーションテストとコロケーションされたタイプを支持し、エージェントが開いた理由がないファイルで1つの変更をミラーリングしなければならない任意のパターンに対して主張します。

</Accordion>

<Accordion title={"スタックを切り替えて、エージェントがうまく機能させる必要がありますか?"}>

ほとんど決してない。 移行コストは一定であり、ゲインがバインドされ、厳格なタイプ、境界検証、既存のスタックへの1つの検証コマンドを追加すると、すぐに適用されます。 とにかく変更するつもりでスタックを変更し、その理由ではなく、エージェントがティブレーカになるようにしましょう。

</Accordion>
