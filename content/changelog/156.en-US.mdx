- Admin skeletons follow the areas. Each area declares the skeletons of its admin pages in `src/data/<area>.skeletons.ts`, and `skeletons.entries.ts` joins them into `ADMIN_SKELETONS`, which the admin layout skeleton reads instead of a map of every admin path. The skeleton files are one per area (`custom/admin/<area>-pending.tsx`) instead of one per sidebar group, so the products skeletons no longer share a file with the pricing ones. The lists in `src/data/navigation.ts` are typed by `NavigationEntry`, so a placement no area fills, such as the dashboard actions without products, is an empty list that still type-checks, and every entry's path is checked against the route tree. The dashboard actions are the new `DashboardActions` widget, tested with a test-local action, and the auth middleware tests no longer read products or categories. A copy of the project without the products area type-checks and keeps 100% coverage. Nothing changes on screen. See [Paths and navigation](/docs/conventions/routes#paths-and-navigation).
