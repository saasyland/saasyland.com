`bun run check` は `bun run generate:cn`、`bun run check:comments`、`bun run check:i18n`, `bun run check:content`、`bun run check:flows`、`bun run check:skills` を実行してから `vp check` を実行します。`vp check` は `vite.config.ts` と `tsconfig.json` の設定に従い、oxfmt によるフォーマット、oxlint によるリント、TypeScript による型チェックを一度に行います。CI も同じコマンドを実行します。ここに好みの問題は何もありません。このページのルールに反するコードをツールが受け入れたとしても、レビューで却下されます。

## ツールが強制すること

oxlint は `correctness`、`nursery`、`pedantic`、`perf`、`style`、`suspicious` の各カテゴリーをエラーとして実行し、型情報を使うルールと型チェックも有効にしています。コードの形に最も大きく影響する制限は次のとおりです。

| ルール                                  | 設定                                                            | 効果                                                                         |
| --------------------------------------- | --------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `max-lines`                             | <RepositoryFact name="maxLines" />                              | 大きくなる前に、責務ごとにファイルを分割する                                 |
| `max-lines-per-function`                | <RepositoryFact name="maxLinesPerFunction" />                   | コンポーネントとハンドラーを小さく保つ                                       |
| `max-statements`                        | <RepositoryFact name="maxStatements" />                         | 長い本体を書かず、名前付きのヘルパーに切り出す                               |
| `no-magic-numbers`                      | `0` と `1` のみ許可。ほかに配列のインデックスとデフォルト値も可 | それ以外の数値はすべて名前付きの定数にする                                   |
| `id-length`                             | 2 文字以上。ただし `_`、`m`、`t` を除く                         | 識別子は単語にする。`t` は翻訳関数                                           |
| `one-var`                               | `never`                                                         | 1 つの文で宣言するのは 1 つだけ                                              |
| `unicorn/no-null`                       | テストと `src/platform/testing` 以外で有効                      | 値がないことは `undefined` で表す                                            |
| `typescript/no-explicit-any`            | `error`                                                         | どの値も `any` で型付けしない                                                |
| `typescript/ban-ts-comment`             | `@ts-expect-error`、`@ts-ignore`、`@ts-nocheck` に対して `true` | 理由の有無にかかわらず、コンパイラーのエラーを抑制しない                     |
| `typescript/consistent-type-assertions` | `assertionStyle: "never"`                                       | `as` によるキャストを使わない。`as const` と `satisfies` は使える            |
| `code-style/no-comments`                | `error`                                                         | 1 行のリンク以外のコメントを書かず、ディレクティブは決して書かない           |
| `code-style/no-multiline-ternary`       | `error`                                                         | 三項演算子は 1 行に収める                                                    |
| `code-style/no-undefined-branch`        | `error`                                                         | `undefined` や `null` の分岐を持つ三項演算子と `return undefined` を書かない |
| `code-style/no-undefined-fallback`      | `error`                                                         | `?? undefined` を書かない                                                    |
| `code-style/route-option-order`         | `src/routes` で `error`                                         | 型が通るルートオプションは TanStack Router の順に並べる                      |
| `code-style/zod-namespace-import`       | `error`                                                         | Zod は `zod` から `* as zod` としてインポートする                            |
| `radius/no-off-scale`                   | `error`                                                         | 角の半径はスケールから選ぶ                                                   |
| `type/no-off-scale`                     | `error`                                                         | 文字サイズはタイプスケールのいずれかの段階                                   |
| `type/mono-for-code`                    | `error`                                                         | 等幅フォントはコードにだけ使う                                               |

オーバーライドは限定的で、ファイル単位で適用されます。テストと `src/platform/testing` の共有テストヘルパーは `no-magic-numbers`、`no-await-in-loop`、`unicorn/no-null`、`hydration/no-clock-or-locale-in-render`、`admin-data/no-literal-data` を緩和し、`src/presentation` と `src/hooks` は `typescript/consistent-return` を、テスト用モックは `require-await` を緩和します。`src/routes` では `sort-keys` を無効にしています。ルートのオプションは独自の順序に従うためです（[ルートファイル](/docs/conventions/routes)を参照）。また、管理画面のルート、コンポーネント、データファイルでは `admin-data/no-literal-data` を有効にしています（[管理ダッシュボード](/docs/features/admin-dashboard#real-data-only)を参照）。`src` 全体では `radius/no-off-scale`、`type/no-off-scale`、`type/mono-for-code` を有効にし、テストと `src/platform/testing` ではそれらを再び無効にしています。`src/presentation/social-card.tsx` では `type/no-off-scale` を無効にしています。Takumi はソーシャルカードを固定サイズの画像として描画し、その文字サイズはページのタイプスケールではなくインラインスタイルで指定するためです（[テーマ](/docs/ui/theme#type-scale)を参照）。

`tsconfig.json` は、コードの書き方を左右する厳格なフラグを追加しています。`strict`、`exactOptionalPropertyTypes`、`noUncheckedIndexedAccess`、`noPropertyAccessFromIndexSignature`、`noImplicitReturns`、`noFallthroughCasesInSwitch`、`noUnusedLocals`、`noUnusedParameters` です。インデックスによる読み取りは `undefined` の可能性があり、省略可能なプロパティに明示的に `undefined` を設定することはできず、インデックスシグネチャは `record["key"]` の形で読み取ります。

フォーマッターは、セミコロンなし、ダブルクォート、末尾カンマあり、行幅 <RepositoryFact name="printWidth" /> で出力します。また、インポートを固定のグループに並べ替え、`className` と `cn` の呼び出し内の Tailwind のクラスも並べ替え、`package.json` のスクリプトを名前順に並べ替えます（`sortPackageJson: { sortScripts: true }`）。そのため、いずれも手作業で並べないでください。1 つでも順序が乱れていると `vp check` が失敗します。コマンドについては[リントとフォーマット](/docs/tooling/lint-format)を参照してください。

## サーバーと同じ内容をレンダリングする

ページは 2 回レンダリングされます。サーバーで 1 回、React が HTML をハイドレーションするときにブラウザでもう 1 回です。両方のレンダリングが同じテキストを出力しなければ、React はハイドレーションの不一致（エラー #418）を報告してページをレンダリングし直します。そのためレンダリングのコードは、両者で異なる時計や実行環境のロケールを読みません。引数なしの `new Date()`、`Date.now`、`toLocaleString`、`toLocaleDateString`、`toLocaleTimeString` は使わず、両方が共有する値を使います。

- 相対時間は、そのデータを読み込んだクエリの `dataUpdatedAt` から数えます（[国際化とロケール](/docs/features/internationalization)を参照）。
- サイトが出力する年はビルドから取ります。フッターの著作権表示は、サイトをビルドした UTC の年である `REPOSITORY_FACTS.buildYear` で終わります。
- 数値と日付は use-intl の `useFormatter` を通し、ページのロケールとユーザーのタイムゾーンでフォーマットします。
- `CheckoutActivation` の有効化タイムアウトのようなブラウザでの待ち時間は `useEffect` で開始するタイマーにするので、最初のレンダリングはサーバーと同じになります。

`hydration/no-clock-or-locale-in-render` は、リポジトリ独自の oxlint プラグイン `scripts/hydration-lint-plugin.ts` のルールで、これを `src/hooks`、`src/presentation`、`src/providers`、`src/routes/*.tsx` で強制します。そこではすべてがレンダリングのコードとみなされますが、後で実行される関数は例外です。JSX の prop、オブジェクトのプロパティ、変数としての `on…` イベントハンドラー、`queryFn` と `mutationFn`、そして `useEffect`、`useLayoutEffect`、`useCallback`、`setTimeout`、`setInterval`、`requestAnimationFrame`、`addEventListener` に渡すコールバックです。プラグインのこれらのリストが許可リストです。別の種類の遅延コールバックは `src/__test__/hydration-lint-plugin.test.ts` にケースを加えてそこへ追加し、無効化コメントは決して使いません。

## コメント [#comments]

原則としてコメントは書きません。TypeScript、TSX、テスト、スクリプト、設定、CSS、ワークフローのいずれでも同じです。代わりに名前で意味を伝え、理由はコミットメッセージ、プルリクエスト、またはこのドキュメントに書きます。

```ts
const INCLUSIVE_END = 1
const FIRST_SEQUENCE = 1
const UNINSTALLED_POLAR_SDK_OPTIONAL_PEERS = [/^@opentelemetry\//u, "ioredis"]
```

最初の 2 つは `video.delivery.ts` と `release.ts` から、3 つ目は `src/integrations/polar/polar.vite.ts` から取ったもので、どれも名前がなければコメントが必要になるところです。

コメントが意味を持つのは、コードを読む人が理由の在りかをどうしても知る必要があるときだけです。そのときも説明はせず、その場所を指し示します。チェックが受け入れる形は次の 2 つだけです。

- リンクのコメント: 理由が書かれた場所へのリンクを内容とする 1 行で、リンクの前に置ける語は <RepositoryFact name="linkCommentWords" /> 語までです。リンクは、ドキュメントのページ、GitHub 上の README やロードマップ、上流の issue やプルリクエストなどの `https://` の URL か、このサイトの `/docs/` で始まるドキュメントのパスです。たとえば `// https://github.com/TanStack/router/issues/8933` や `// See /docs/conventions/code-style#comments` です。ブロックコメントや JSX のコメントも同じ 1 行の形に限られ、その上下の行に別のコメントを置くことはできません。
- ワークフローのバージョンタグ: アクションを 40 文字のコミット SHA に固定する YAML の `uses:` の行は、そのコミットがリリースされたときのタグ、つまり `# v4` や `# v7.0.0` で終わります。YAML ファイルにはそれ以外のコメントを書けません。

それ以外はすべて失敗します。説明、区切りのバナー、`TODO`、コメントアウトしたコード、2 行目、リンクの後ろの文、そしてリンクで終わっていてもディレクティブのコメントです。

このルールは 2 つのチェックで強制され、どちらもファイル、行、修正方法を示します。

- `code-style/no-comments` は、`scripts/code-style-lint-plugin.ts` にあるリポジトリの oxlint プラグインのルールで、リンターが読むファイルにあるリンクのコメント以外のすべてのコメントを、エディターと `vp check` で報告します。
- `bun run check:comments` は、`bun run check` と pre-commit フックの中で、リンターより前に `scripts/check-comments.ts` を実行します。Git が追跡している、または追加しようとしているすべての TypeScript、JavaScript、CSS、YAML ファイルを、コードは oxc で、スタイルは PostCSS で、YAML は `yaml` パッケージでパースするので、URL や正規表現の中の `//`、CSS の glob の中の `/*`、YAML の文字列の中の `#` はコメントとみなされません。リンターが読めないものも読みます。`e2e`、`remotion`、宣言ファイル、スタイルシート、ワークフロー、そして `/* oxlint-disable */` コメントです。このコメントには、どのルールが見るよりも先にリンターが従ってしまいます。

対象外となるのは、`.gitattributes` が `linguist-generated` と指定しているファイル（そのうちコードは `src/routeTree.gen.ts` と `src/types/worker-configuration.d.ts`）と、JavaScript の文法がコメントとして数えないスクリプトの `#!` 行です。コンパイラーがどこでも必要とする型は、Vitest のグローバルと同じように `tsconfig.json` の `types` に入れ、`/// <reference>` コメントには決して書きません。

## 抜け道を使わない

ルールを通すために `oxlint-disable`、`eslint-disable`、`@ts-expect-error`、`@ts-ignore`、`@ts-nocheck`、`as` によるキャスト、`any` を書いてはいけません。ルールが反応するのは設計に問題があるということです。設計を変えてください。チェックはそのどれも拒否します。`typescript/ban-ts-comment` は 3 つのコンパイラーディレクティブを説明付きであっても、`typescript/consistent-type-assertions` は `as const` 以外のすべてのアサーションを、`typescript/no-explicit-any` は `any` を、`code-style/no-comments` と `bun run check:comments` はすべての無効化コメントを拒否します。そもそも `eslint-disable` コメントは何も無効にしません（`respectEslintDisableDirectives: false`）。

- **アサーションではなくバリデーションを使う。** ストレージ、ネットワーク、リクエストから来るデータは Zod でパースします。`src/lib/github.ts` は、キャッシュされたスター数を `cachedStarCountSchema.safeParse(await env.CACHE.get(CACHE_KEY, "json")).data` で読み取ります。結果は数値か `undefined` のどちらかで、推測ではありません。
- **型ガードで絞り込む。** `src/integrations/better-auth/auth.roles.ts` の `isRole` と `src/integrations/use-intl/i18n.paths.ts` の `isSupportedLocale` は、実際のチェックによって `string` をユニオン型に絞り込みます。
- **アサーションではなく型注釈を付ける。** 値には、宣言する場所で必要な型を与えます。shadcn のサイドバーは、オブジェクトリテラルをキャストせずに `SIDEBAR_MOBILE_STYLE: StyleWithCssVars` と宣言しています。この型は、CSS プロパティにサイドバーのカスタムプロパティ `--sidebar-width` を加えたものです。
- **変換せずにチェックする。** `as const` と `satisfies` は型を変えないため使用できます。`POLAR_ORDER_STATUS` の末尾は `as const satisfies Record<string, models.OrderStatus>` なので、Polar のステータスのスペルを間違えるとコンパイルに失敗します。
- **ライブラリの型の制約とぶつかったら構造を変える。** キャストするのではなく、値をオブジェクトで包む、関数を分割する、型付きのソースから読み取る、といった方法を取ります。

## null と undefined

テストと `src/platform/testing` 以外では、値がないことは `undefined` で表し、`null` を値として書くことはありません。リンターが `null` を許すのは、API がそれを決めている箇所だけです。1 つは `null` になりうる値との比較で、null 許容のカラム（`course.outline.ts` の `entry.completedAt !== null`）がその例です。もう 1 つは React の DOM ref で、React は `ref` を `RefObject<T | null>` として型付けし、アンマウント時に `null` に戻すため、`useRef<HTMLElement>(null)` から始めます（`course-showcase.tsx`）。`null` を返す API を `?? undefined` で橋渡ししてはいけません。`code-style/no-undefined-fallback` がそれを失敗させます。先に入力をバリデーションして呼び出しが失敗しないようにするか、最初から `undefined` を返すパーサーを使います。よくあるのは検索パラメーターで、`src/lib/search-params.ts` の `searchParam(schema)` は、値がない場合や不正な場合に `undefined` を返します。

```ts
export const authSearchSchema = zod.object({
  redirect: searchParam(callbackPathSchema),
})
```

## 三項演算子と早期リターン

三項演算子は、`course-form.tsx` の `{t(course === undefined ? "create" : "save")}` のように 1 行に収めます。それより長いものや、2 つの JSX のどちらかを選ぶ場合はすべて、早期リターン、`&&` 条件の組、または小さなコンポーネントにします。条件付きのクラスは `cn("base", { "classes": condition })` にします。`code-style/no-multiline-ternary` は、複数行にまたがるすべての三項演算子を失敗させます。行幅を超えて長くなったためにフォーマッターが改行したものも含みます。`src/routes/auth.reset-password.tsx` は、2 つの状態を 2 つの条件で描画しています。

```tsx
{hasValidToken && <ResetPasswordForm token={token} />}
{!hasValidToken && (
  <>
    <p className="text-body text-pretty text-destructive">{t("form.invalidToken")}</p>
```

関数は特殊なケースで早期にリターンし、メインの処理はインデントせずに書きます。`src/modules/lesson/lesson.access.ts` の `hasLessonAccess` がその例です。

```ts
export const hasLessonAccess = (access: Lesson["select"]["access"], viewer: Viewer): boolean => {
  if (access === LESSON_ACCESS.PREVIEW || viewer.isStaff) {
    return true
  }

  if (access === LESSON_ACCESS.ACCOUNT) {
    return viewer.userId !== undefined
  }

  return viewer.entitled
}
```

分岐で値がないことを書き出すこともしません。`code-style/no-undefined-branch` は、`undefined` または `null` の分岐を持つ三項演算子と、すべての `return undefined` を失敗させます。代わりに、コードがしていることを書きます。ガード節から早期にリターンし、欠けているかもしれない値は `?.` か、実際のデフォルト値を伴う `??` で読み、ルックアップや `find` が見つけたものを返し、JSX は `&&` で描画し、Vite プラグインのフックには扱う ID を指定するフィルターを渡して、Rolldown がほかの ID でフックを呼ばないようにします。`scripts/repository-facts.ts` はこの形で仮想モジュールを提供しています。

```ts title="scripts/repository-facts.ts"
    load: { filter: { id: exactRegex(RESOLVED_MODULE_ID) }, handler: () => moduleSource },
    name: "saasyland:repository-facts",
    resolveId: { filter: { id: exactRegex(MODULE_ID) }, handler: () => RESOLVED_MODULE_ID },
```

## 名前付きの定数

`0` と `1` 以外の数値には名前を付けます（`COURSE_STALE_MS = 60_000`、`LESSON_PROGRESS_SAVE_INTERVAL_MS = 15_000`）。`0` と `1` は `.limit(1)`、`index + 1`、`toHaveBeenCalledTimes(1)` のようにリテラルで書きます。ただし、それ自体に意味がある場合は名前を付けます。プロセスの終了コードは `FAILURE_EXIT_CODE`、HTTP のバイト範囲の終端を含めるための値は `INCLUSIVE_END` です。ステータス、種別、アクセスレベル、ティア、ロール、プロバイダーのイベント値など、ドメインに属する値は `as const` オブジェクトとして一度だけ宣言し、テストやフィクスチャを含むあらゆる場所で名前で参照します。

```ts
export const COURSE_STATUS = {
  DRAFT: "draft",
  PUBLISHED: "published",
} as const
```

カラムや enum スキーマが必要とするタプルは、値を打ち直さずにこのオブジェクトから組み立て、オブジェクトと並べてモジュールの定数ファイルに置きます。定数ファイルは Drizzle から何もインポートしません。`course.constants.ts` は `COURSE_STATUSES = [COURSE_STATUS.DRAFT, COURSE_STATUS.PUBLISHED] as const` を宣言し、これを `course.schema.ts` の `text("status", { enum: COURSE_STATUSES })` と `course.zod.ts` の `zod.enum(COURSE_STATUSES)` の両方に渡しています。ブラウザー側のコードもタプルをここから読みます。料金表は `license.constants.ts` の `LICENSE_TIERS` を順に処理します。

- モジュールの定数はそのモジュールの `<module>.constants.ts` に置き（`LESSON_ACCESS`、`LICENSE_TIER`）、プロバイダーの値は連携の `*.constants.ts` に置きます（`polar.constants.ts` の `POLAR_ORDER_STATUS`、`auth.constants.ts` の `AUTH_PROVIDER`）。
- カラムと入力の長さは、モジュールの定数で一度だけ名前を付け、Drizzle のスキーマと Zod スキーマの両方がそれを読み取ります（`video.constants.ts` の `VIDEO_TITLE_MAX_LENGTH`）。
- 1 つの概念には、表記を統一したマップを 1 つだけ用意します。サーバーのエラーには `ERROR_CODES`、Better Auth のエラーキーには `AUTH_ERRORS`、ロールには `ROLE_CODES` を使います。
- 環境名と HTTP ステータスコードは `src/modules/_core/constants/api.ts` で一度だけ宣言します。`__root.tsx` とデプロイ用スクリプトは `ENVIRONMENT.PRODUCTION` を、Worker のメディアハンドラーは `HTTP_STATUS.PARTIAL_CONTENT` を使います。どちらについても、ファイルごとに独自のマップを宣言することはありません。唯一の例外は `vite.config.ts` で、`mode` をそのままの名前と比較します。Vite は `~` エイリアスを解決する前にこれを読み込むため、`api.ts` をインポートできないからです。
- 1 つのファイルだけで使う定数は、そのファイルのインポートの下に置きます。複数のファイルで使う定数は、そのモジュール、`src/data`（[ファイルと命名](/docs/conventions/files-and-naming)を参照）、または `src/modules/_core/constants` に置きます。1 つの定数のためだけにファイルを作ってはいけません。
- `license_key_id` のような型付き API のフィールド名は値ではなくプロパティなので、プロパティアクセスのままにします。

## コンポーネント内のフック

単一の値を返すフックの呼び出しを先に書き、空行を挟んでから、分割代入するフックの結果をそれぞれ書きます。こうすると、コンポーネントが分解して取り出す値が独立したグループとして読めます。`src/presentation/components/custom/auth/sign-in-form.tsx` の例です。

```tsx
const t = useTranslations()
const router = useRouter()

const { finishSignIn, redirect } = useAuthRedirect()
```

コンポーネントは `useTranslations` を 1 回だけ呼び出し、その結果を `t` と名付けます。理由は[翻訳とコンテンツ](/docs/conventions/translations)を参照してください。

## 名前とインポート

- ファイルとフォルダーはケバブケース、コンポーネントはパスカルケース、定数は SCREAMING_SNAKE_CASE にします。関数は動詞で始め（`resolveViewer`、`rethrowAsConflict`）、真偽値は問いかけとして読める名前にします（`isPending`、`hasLessonAccess`）。
- インポートには `~/src/...` エイリアスを使い、パスも含めて、シンボルを定義しているファイルから直接インポートします（`import { ROUTES } from "~/src/routes"`）。バレルファイルはありません。フォルダーを再エクスポートするファイルも、複数のファイルのリストをまとめるファイルもなく、`src/routes.ts` はパスを自分で宣言します。`src/presentation/components/shadcn/` の shadcn プリミティブには、ラップしている部品を再エクスポートするものがあります。それ以外で再エクスポートするのは次のファイルだけです。Drizzle がすべてのテーブルを 1 つのスキーマオブジェクトにまとめる必要があるための `src/integrations/drizzle-orm/drizzle.schemas.ts`、ライセンスのコード向けに `orderCurrencySchema` と `polarOrderUrl` を再エクスポートする `src/modules/license/license.utils.ts`、`LazyMotion` が読み込む機能バンドルとして `domMax` を再エクスポートする `src/integrations/motion/motion.features.ts` です。
- Zod のインポートは、Zod 4 のドキュメントが示す `import * as zod from "zod"`（型だけなら `import type * as zod from "zod"`）の 1 つの形だけです。`code-style/zod-namespace-import` は、デフォルトインポート、名前付きインポート、`zod/v4` のようなサブパスを失敗させます。
- インデックスを 1 つ進めるときはリテラルを使い、`course.utils.ts` では `lessons[index + 1]` と書きます。それ以外のオフセットには `-1` も含めて名前を付けます。`robots.ts` の `groups.at(LAST_GROUP_INDEX)` のように書き、`slice(index, -5)` とは書きません。
