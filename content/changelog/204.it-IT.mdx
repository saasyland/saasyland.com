- Ogni pull request aggiunge la propria voce del changelog, `content/changelog/<number>.<locale>.mdx`, invece di modificare questa pagina, così le pull request aperte in parallelo non entrano più in conflitto nei nove file del changelog. Nessuna voce porta una data: la pagina e le note di rilascio ricavano il giorno di ogni voce, in UTC, dal commit squash il cui oggetto termina con `(#<number>)`, e mettono sotto **Non rilasciato** le voci non ancora arrivate su `main`. Le voci esistenti sono passate in file propri con i giorni registrati da Git: #160 passa al 2026-11-14, #104, #111 e #115 al 2026-11-12, e dodici voci dal 2026-11-15 al 2026-11-16; i vecchi punti di **Versioni precedenti** hanno la data 2026-09-24. In una pull request, `bun run check` fallisce finché manca la sua voce. Vedi [Voci del changelog](/docs/conventions/git-workflow#changelog-entries).
