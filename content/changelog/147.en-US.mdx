- Fixed: Safari joins a date and its time with “at”, as in “Jan 1, 2025 at 7:00 AM EST”, where the server writes “Jan 1, 2025, 7:00 AM EST”, so the licence activations and the admin user tables rendered different text in Safari than the server sent, and React reported a hydration mismatch. The `dateTime` format is replaced by `time`, and a date with its time is the new `common.dateTime` message, which joins the `date` and `time` formats as each locale writes them. Every engine prints each part the same, and the server's text is unchanged in every locale. `i18n.config.test.ts` fails when a named format mixes date and time fields, `preferences.spec.ts` checks that the licence page hydrates the server's date and time in every locale, and `check-message-formats.ts` counts only the words outside ICU arguments when it looks for untranslated English. See [Internationalization and locales](/docs/features/internationalization).
