Vite+ (`vite-plus`, polecenie `vp`) łączy Vite, Vitest, oxlint i oxfmt w jednym CLI, a `vite.config.ts` konfiguruje je wszystkie. `package.json` nadpisuje `vite` pakietem `@voidzero-dev/vite-plus-core` i przypina `vitest` do wersji 5.0.1. Skrypty pakietu wywołują `vp`; poza nimi używaj globalnego CLI Vite+ lub `bunx vp`.

| Polecenie         | Używane przez                                     |
| ----------------- | ------------------------------------------------- |
| `vp dev`          | `dev`                                             |
| `vp build --mode` | `build:preview`, `build:production`, `build:test` |
| `vp preview`      | `start`, `start:test`                             |
| `vp test`         | `test` i skrypty Vitest `test:*`                  |
| `vp lint`         | `lint`                                            |
| `vp fmt`          | `format`, `format:check`                          |
| `vp check`        | `check`, `check:fix`                              |
| `vp staged`       | `check:pre-commit`                                |
| `vp config`       | `prepare`, który instaluje hooki Git              |

## Konfiguracja

`vite.config.ts` ładuje swoje pluginy leniwie. Pod Vitest ładuje się tylko `@vitejs/plugin-react`; w pozostałych przypadkach zestaw pluginów wygląda następująco:

- `@cloudflare/vite-plugin`: uruchamia Workera w środowisku SSR, utrwala stan lokalny (w `.wrangler/test` dla trybu `test`) i używa zdalnych bindingów dla `development`.
- `fumadocs-mdx`: kompiluje kolekcje dokumentacji i bloga.
- `@tailwindcss/vite`: Tailwind CSS 4.
- `tanstackStart`: routing, dzielenie kodu i prerendering stron publicznych.
- `@vitejs/plugin-react`.

Serwer deweloperski używa portu 3000 i kończy się błędem, jeśli port jest zajęty. `resolve.tsconfigPaths` zapewnia alias importu `~/`. Ten sam plik zawiera sekcje `fmt`, `lint`, `staged` i `test`; zobacz [Lint i formatowanie](/docs/tooling/lint-format) oraz [Testy](/docs/tooling/testing).

## Hooki Git

`bun install` uruchamia `prepare`, który wywołuje `vp config --no-agent`, aby zainstalować dyspozytor hooków dla `.vite-hooks/`. `pre-commit` uruchamia `bun run check:pre-commit`, a `prepare-commit-msg` uruchamia `scripts/commit-msg.ts` (zobacz [Konwencjonalne commity](/docs/tooling/conventional-commits)). `vp hooks status` pokazuje, czy hooki są aktywne w danym klonie repozytorium.

Preferuj skrypty pakietu; `vp` wywołuj bezpośrednio przy uruchomieniach punktowych, np. przy formatowaniu lub lintowaniu konkretnych ścieżek.
