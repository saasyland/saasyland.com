title: "Variables d'environnement"
description: "Les clés de .env.example et l'endroit où chaque environnement les lit."
---

Copiez le modèle correspondant à l'environnement dans lequel vous travaillez. `.env.development`, `.env.preview` et `.env.production` sont ignorés par Git ; `.env.test` est versionné avec des valeurs factices pour les tests et la préversion isolée.

```sh
cp .env.example .env.development
openssl rand -base64 48
```

Utilisez la valeur générée comme `AUTH_SECRET`, avec un secret différent pour chaque environnement déployé.

| Variables                                                                       | Rôle                                                                                                    |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `AUTH_SECRET`                                                                   | Secret de signature et de chiffrement de Better Auth                                                    |
| `AUTH_GITHUB_CLIENT_ID`, `AUTH_GITHUB_CLIENT_SECRET`                            | Application OAuth GitHub ; authentifie aussi la requête du nombre d'étoiles GitHub                      |
| `AUTH_GOOGLE_CLIENT_ID`, `AUTH_GOOGLE_CLIENT_SECRET`                            | Application OAuth Google                                                                                |
| `RESEND_API_KEY`, `RESEND_EMAIL_FROM`                                           | Clé d'API Resend et adresse d'expéditeur par défaut                                                     |
| `POLAR_SERVER`                                                                  | `sandbox` pour le développement et la préversion, `production` pour la production                       |
| `POLAR_ACCESS_TOKEN`, `POLAR_ORGANIZATION_ID`                                   | Accès à l'API Polar et organisation pour les remises et les clés de licence                             |
| `POLAR_WEBHOOK_SECRET`                                                          | Vérifie les webhooks Polar sur `/api/auth/polar/webhooks`                                               |
| `POLAR_PRODUCT_ID_CORE`, `POLAR_PRODUCT_ID_COMPLETE`, `POLAR_PRODUCT_ID_AGENCY` | Produits Polar pour les trois offres de paiement                                                        |
| `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DATABASE_ID`, `CLOUDFLARE_ACCESS_TOKEN`    | Accès à l'API HTTP de D1 pour Drizzle Studio et l'introspection ; l'application utilise le binding `DB` |

Les environnements `development`, `preview` et `production` de `wrangler.jsonc` exigent toutes les clés ci-dessus en tant que secrets (`secrets.required`). Le code serveur les lit avec `import { env } from "cloudflare:workers"`. Aucune n'a de préfixe `VITE_`, car Vite expose ces valeurs au navigateur.

`AFFONSO_PROGRAM_ID` n'est pas un secret et ne figure pas dans `.env.example`. C'est l'identifiant public du programme Affonso qui active le suivi des recommandations d'affiliation ; c'est donc une variable de Worker sous `vars` dans `wrangler.jsonc`, définie uniquement pour l'environnement qui reçoit de vrais paiements. Pour l'instant, seul `test` en définit une, un identifiant factice pour les tests dans le navigateur. Voir [Programme d'affiliation](/docs/features/affiliates).

## Valeurs dans le code

Certains réglages relèvent du code et non des variables d'environnement :

- `src/presentation/branding/index.ts` : le nom de l'application, `APP_DOMAIN` (l'URL canonique est `https://` suivi de ce domaine), les adresses de contact et le dépôt GitHub.
- `src/modules/_core/constants/api.ts` : les hôtes de préversion et de production (`DEPLOYED_HOSTS`, déduits de `APP_DOMAIN`), qu'acceptent Better Auth et les liens de la newsletter (`appHostsForMode`) et que les scripts de déploiement vérifient après un déploiement.
- `wrangler.jsonc` : les noms des Workers, les domaines personnalisés, les identifiants D1 et KV et les noms des buckets R2.

## Callbacks des fournisseurs

- GitHub et Google : `https://<host>/api/auth/callback/github` et `https://<host>/api/auth/callback/google`.
- Webhooks Polar : `https://<host>/api/auth/polar/webhooks`, signés avec `POLAR_WEBHOOK_SECRET`. [Configurer Polar](/docs/getting-started/polar-setup) liste les événements, les produits, les remises et les scopes du jeton, et `bun run polar:verify:<environment>` les vérifie.
