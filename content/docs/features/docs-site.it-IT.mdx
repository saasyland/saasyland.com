## Contenuti

- Le pagine sono file `content/docs/<section>/<page>.<locale>.mdx` per tutte e nove le lingue.
- `meta.<locale>.json` in ogni cartella definisce il titolo della sezione, l’icona e l’ordine delle pagine.
- `src/integrations/fumadocs/fumadocs.i18n.ts` usa il parser `dot`, `en-US` come lingua predefinita e di riserva, e `hideLocale: "always"`, perché l’app gestisce da sé il prefisso della lingua.
- `bun run content` genera `.source` da `fumadocs.config.ts`.

## Rotte

- Layout `/docs` (`src/routes/docs.tsx`): una funzione server restituisce l’albero delle pagine per la lingua corrente; il layout mostra il `DocsLayout` di Fumadocs con il link a GitHub e, in fondo alla barra laterale, `LocaleSelect` e `ThemeSwitch` come campi di selezione dallo stile uniforme, carica `docs.css` e mostra `DocsPending` durante il caricamento.
- `/docs/` e `/docs/$` chiamano `loadDocsPage` (`fumadocs.docs.ts`), che risolve la pagina e precarica il suo MDX compilato (`docsContent`) prima del rendering.
- `/api/search` fornisce la ricerca di Fumadocs su tutte le lingue (`fumadocs.search.ts`).

Le pagine MDX possono usare `mdxComponents` da `src/presentation/components/custom/mdx.tsx`: i componenti predefiniti di Fumadocs, `Accordions`, `Steps` e `Tabs` di Fumadocs, e `Alert`, `Badge`, `Button`, le parti della card, `Separator` e le parti della tabella di shadcn. I link vengono localizzati automaticamente.

## Aggiungere una pagina

1. Scrivi `<page>.en-US.mdx` con `title` e `description`.
2. Aggiungi lo slug a `meta.en-US.json` e a ogni altro `meta.<locale>.json` nello stesso ordine.
3. Aggiungi le otto traduzioni con blocchi di codice identici byte per byte.
4. Esegui `bun scripts/check-content.ts` (incluso anche in `bun run check:i18n`) e `bun run content`.

`bun run build` prerenderizza ogni pagina della documentazione in tutte le lingue.
