## Szablony

Szablony leżą w `src/presentation/emails`. Każdy plik zawiera wyłącznie znaczniki i eksportuje stałą ze swoją przestrzenią nazw:

| Szablon                          | Przestrzeń nazw                           | Wysyła go                                                                                                  |
| -------------------------------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `VerifyEmail`                    | `emails.verify-email`                     | `sendVerifyEmail` (hook Better Auth)                                                                       |
| `ResetPasswordEmail`             | `emails.reset-password-email`             | `sendResetPasswordEmail` (hook Better Auth)                                                                |
| `ChangeEmailConfirmationEmail`   | `emails.change-email-confirmation-email`  | `sendChangeEmailConfirmationEmail` (hook Better Auth)                                                      |
| `ExistingAccountEmail`           | `emails.existing-account-email`           | `sendExistingAccountEmail` (`onExistingUserSignUp` z Better Auth)                                          |
| `PasswordChangedEmail`           | `emails.password-changed-email`           | `sendPasswordChangedEmail` (`onPasswordReset` z Better Auth, hook `password-change-notice`, `setPassword`) |
| `DeleteAccountEmail`             | `emails.delete-account-email`             | `sendDeleteAccountEmail` (`sendDeleteAccountVerification` z Better Auth)                                   |
| `InvitationEmail`                | `emails.invitation-email`                 | `sendInvitationEmail` (`createInvitation`, `resendInvitation`)                                             |
| `NewsletterConfirmationEmail`    | `emails.newsletter-confirmation-email`    | `subscribeToNewsletter`                                                                                    |
| `NewsletterNotificationEmail`    | `emails.newsletter-notification-email`    | `confirmNewsletterSubscription`, na `CONTACT_EMAIL`                                                        |
| `NewsletterIssueEmail`           | `emails.newsletter-issue-email`           | `sendNewsletterIssue`, przez `sendBatchEmails`, do potwierdzonych subskrybentów                            |
| `PurchaseConfirmationEmail`      | `emails.purchase-confirmation-email`      | `sendPurchaseConfirmationEmail` (`order.paid` z Polara)                                                    |
| `UnmatchedOrderAlertEmail`       | `emails.unmatched-order-alert-email`      | `sendUnmatchedOrderAlert` (`order.paid` z Polara), na `CONTACT_EMAIL`                                      |
| `WithdrawalAcknowledgementEmail` | `emails.withdrawal-acknowledgement-email` | `sendWithdrawalAcknowledgement` (`submitWithdrawal`)                                                       |
| `WithdrawalNotificationEmail`    | `emails.withdrawal-notification-email`    | `sendWithdrawalNotification` (`submitWithdrawal`), na `CONTACT_EMAIL`                                      |

Szablon dostaje `locale` i `messages`, a tłumaczy funkcją `createTranslator` z use-intl:

```tsx
const t = createTranslator({ locale, messages: { emails: { "verify-email": messages } }, namespace: "emails.verify-email" })
```

E-maile dotyczące konta zaczynają się od `EmailBrandHeader`, nazwy aplikacji, a pod przyciskiem umieszczają `EmailFallbackLink`: ten sam link jako zwykły tekst dla programów pocztowych, które ukrywają przyciski. E-maile weryfikacyjne, resetu hasła, zmiany adresu e-mail i usunięcia konta podają, jak długo działa link, według `EMAIL_LINK_LIFETIME_HOURS`, czyli wartości, z którą skonfigurowano Better Auth.

## Wysyłka

Przypadek użycia odczytuje język i `redirect` z adresu zwrotnego przekazanego przez Better Auth, sprawdza limit dla odbiorcy, ładuje komunikaty, renderuje szablon i wysyła wiadomość (`src/modules/verification/use-cases/send-verify-email.ts`):

```ts
if (!(await withinRecipientRateLimit({ kind: VERIFICATION_EMAIL_PURPOSE.VERIFY_EMAIL, recipient: user.email }))) {
  console.warn("[email] verification email not sent: the recipient reached the hourly limit")
  return
}
const callback = new URL(callbackURL, getRequest().url)
const locale = extractLocaleFromPath(callback.pathname) ?? I18N.DEFAULT_LOCALE
const verifyUrl = new URL(localizePathname({ locale, pathname: ROUTES.VERIFY_EMAIL }), getRequest().url)
verifyUrl.search = callback.search
verifyUrl.searchParams.set("token", token)

const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })
await sendEmail({
  idempotency: { purpose: VERIFICATION_EMAIL_PURPOSE.VERIFY_EMAIL, token: crypto.randomUUID() },
  react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
  subject: createTranslator({ locale, messages })("subject"),
  to: user.email,
})
```

`sendEmail` (`src/integrations/resend/resend.utils.ts`) wysyła przez Resend z adresu `RESEND_EMAIL_FROM`, chyba że podano `from` (powiadomienie dla właściciela, alert o nieprzypisanym zamówieniu i powiadomienie o odstąpieniu od umowy używają `NOTIFICATIONS_EMAIL`), przekazuje klucz idempotencji i rzuca wyjątek, gdy wysyłka się nie powiedzie. `sendBatchEmails` wysyła do <RepositoryFact name="newsletterBatchSize" /> e-maili, każdy z własnymi nagłówkami, w jednym żądaniu z jednym kluczem idempotencji, zapisuje w logach te, które Resend odrzuci, i zwraca identyfikatory pozostałych; korzystają z niej tylko numery newslettera ([Newsletter](/docs/features/newsletter#sending)).

E-maile dotyczące konta używają języka strony, od której zaczął się proces, odczytanego z `callbackURL` w linku z e-maila; przy ponownej rejestracji pochodzi on z `callbackURL` żądania rejestracji. Proces, który nie podaje adresu zwrotnego, czyli logowanie do niezweryfikowanego konta albo reset hasła, bierze język i `redirect` ze strony, która wysłała żądanie (z jej nagłówka `Referer`, jeśli ta strona należy do tej witryny). Potwierdzenie subskrypcji newslettera używa języka wysłanego razem z formularzem, a każdy numer języka zapisanego przy subskrypcji albo angielskiego, gdy numer nie ma w nim kompletnej wersji; powiadomienie dla właściciela jest zawsze w `en-US`. Potwierdzenie zakupu używa języka, który `createCheckout` zapisał w metadanych zamówienia, a gdy go tam nie ma, angielskiego; potwierdza ono na trwałym nośniku zgodę kupującego na natychmiastowe dostarczenie, zobacz [Licencje](/docs/features/licences#purchase-confirmation). Alert o nieprzypisanym zamówieniu, który informuje serwis o opłaconym zamówieniu licencji, którego klient nie pasuje do żadnego konta, jest w `I18N.DEFAULT_LOCALE`, zobacz [Licencje](/docs/features/licences#orders-that-match-no-account). Potwierdzenie otrzymania oświadczenia o odstąpieniu od umowy używa języka strony, na której je złożono, a powiadomienie dla serwisu o odstąpieniu od umowy jest w `I18N.DEFAULT_LOCALE`, zobacz [Licencje](/docs/features/licences#withdrawal-function). E-mail z zaproszeniem używa języka, który wybrał dla niego administrator, zapisanego w polu `locale` zaproszenia.

`withinRecipientRateLimit` (`src/lib/rate-limit.ts`) ogranicza liczbę e-maili każdego rodzaju (weryfikacyjnych, resetu hasła, o istniejącym koncie, o usunięciu konta, potwierdzających subskrypcję newslettera i potwierdzających otrzymanie oświadczenia o odstąpieniu od umowy) wysyłanych na jeden adres w ciągu godziny do <RepositoryFact name="recipientEmailsPerHour" />. Wysyłki są liczone w tabeli `rate_limit` pod skrótem SHA-256 adresu. Po przekroczeniu limitu e-mail nie wychodzi, a żądanie i tak dostaje zwykłą odpowiedź. Potwierdzenie zmiany adresu e-mail, powiadomienie o zmianie hasła, powiadomienie dla właściciela, numery newslettera, potwierdzenie zakupu, alert o nieprzypisanym zamówieniu i powiadomienie o odstąpieniu od umowy nie mają limitu; zmiana hasła wymaga tokenu resetu albo obecnego hasła, potwierdzenie zakupu i alert o nieprzypisanym zamówieniu wywołuje webhook Polara, a nie odwiedzający, i to raz na zamówienie, numer trafia do każdego potwierdzonego subskrybenta raz i wysyła go tylko administrator, a powiadomienie o odstąpieniu od umowy trafia tylko do serwisu, najwyżej <RepositoryFact name="sensitiveRateLimit" /> na klienta na minutę. E-mail z zaproszeniem wlicza się do tego samego limitu, ale po jego przekroczeniu `sendInvitationEmail` kończy się błędem `TOO_MANY_REQUESTS`, zamiast pominąć wiadomość.
