- Fixed: `/app/license` told buyers to run `npx saasyland@latest init` and enter the key when asked, but `latest` is the CLI's placeholder release and `init` takes no key. The page now shows the `activate`, `whoami` and `deactivate` commands with what each does, and that CI reads the key from `SAASYLAND_LICENSE_KEY`. `src/data/cli.ts` is their one source: `CLI_RELEASE_CHANNEL` names the npm tag (today `beta`), and a test fails unless it is the tag that the installed `@saasyland/stack` was published on, so upgrading the dependency to a stable release moves the landing page's command, the release post, the docs and the journey suite to npm's default tag in the same change. The machine list and the overview's documentation card no longer promise scaffolding and an installation guide that do not exist yet. See [CLI instructions](/docs/features/customer-app#cli-instructions).
- Fixed: the Polar checkout opened with an empty email field for a signed-in buyer, because the Better Auth Polar plugin creates a checkout with the account's ID alone. `startCheckout` now creates the checkout with the Polar SDK and fills in the account's email and name, and the strict Polar double requires both. The Polar plugin no longer adds its own checkout, which was closed to HTTP and no longer used, so `ROUTES.API_AUTH_POLAR` holds only the webhooks and `POLAR_CHECKOUT_PRODUCTS` is gone. See [Payments and licences](/docs/features/payments).
