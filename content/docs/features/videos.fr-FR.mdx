Les vidéos sont stockées dans votre propre bucket R2 et diffusées par votre propre Worker. Aucune plateforme vidéo ne s’intercale : Cloudflare ne facture pas la sortie de données depuis R2, la facture porte donc sur le stockage et les requêtes, pas sur les minutes visionnées.

## Ce qui existe

- **Vidéothèque** : `/admin/videos` (`src/routes/admin.videos.tsx`) liste chaque vidéo publiée avec sa durée, la résolution de la source, la taille stockée, les langues des sous-titres et la date de publication, de la plus récente à la plus ancienne. **Lire** ouvre la vidéo dans une boîte de dialogue ; **Supprimer** demande une confirmation, puis supprime la ligne et tous les fichiers situés sous le préfixe de la vidéo dans R2.
- **Publication** : `bun run video:publish:production <file> --title "…"` encode un enregistrement avec FFmpeg, le téléverse dans R2 et l’enregistre dans la table `video`, ce qui le fait apparaître dans la vidéothèque.
- **Diffusion** : `/media/<expiry>.<signature>/<videoId>/<file>` sert les fichiers au lecteur (voir [Cloudflare R2](/docs/integrations/cloudflare-r2)).
- **Lecteur** : `VideoPlayer` (`src/presentation/components/custom/video-player.tsx`) utilise Video.js 10 avec son propre moteur HLS. Il affiche les commandes de qualité, de vitesse, de sous-titres, d’image dans l’image et de plein écran, des aperçus pendant la recherche tirés du storyboard, et des libellés dans la langue de la page.

Les cours, les chapitres et les leçons ne font pas encore partie de cette fonctionnalité ; voir [Cours](/docs/features/courses).

## Contenu d’une vidéo publiée

L’encodeur planifie la sortie à partir de la source :

| Fichier                             | Contenu                                                                                                                                                                                        |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `master.m3u8`                       | Playlist HLS multivariante qui liste chaque rendu avec sa résolution, ses codecs et son débit de pointe.                                                                                       |
| `<height>p/`                        | Un rendu H.264 par palier : la hauteur de la source (jusqu’à 1440p), puis 1080p, 720p et 360p en dessous. Chacun contient `index.m3u8`, `init_<n>.mp4` et des segments `.m4s` de six secondes. |
| `audio/`                            | Une piste AAC (128 kb/s, 48 kHz stéréo) partagée par tous les rendus, de sorte que l’audio n’est stocké qu’une fois. Les enregistrements sans son n’en ont pas.                                |
| `poster.webp`, `poster-960.webp`    | Une image prise au dixième de la vidéo, ou celle passée avec `--poster`, en 1920 et 960 pixels de large. Le lecteur en choisit une avec `srcset`.                                              |
| `storyboard.webp`, `storyboard.vtt` | Des miniatures pour les aperçus pendant la recherche : une vignette toutes les deux secondes ou plus, 600 vignettes au maximum, avec une piste WebVTT qui pointe vers chaque vignette.         |
| `captions/<locale>.vtt`             | Les fichiers de sous-titres passés avec `--captions`, un par locale.                                                                                                                           |

Les segments sont au format CMAF (MP4 fragmenté) avec une image clé toutes les deux secondes, si bien que tous les rendus basculent aux mêmes points. Les débits sont à qualité constante (CRF 21) avec un plafond proportionnel à la taille de l’image : un enregistrement d’écran presque statique occupe donc bien moins de place que ce plafond.

## Publier un enregistrement

1. Installez FFmpeg, qui inclut `ffprobe` : `brew install ffmpeg` sur macOS. Définissez `FFMPEG` et `FFPROBE` pour utiliser d’autres binaires.
2. Connectez-vous à Cloudflare avec `bunx wrangler login`. Le script exécute Wrangler avec cette connexion, comme les scripts `db:migrate:*`, et ne lit aucun fichier `.env`.
3. Exécutez le script pour l’environnement :

```bash
bun run video:publish:production lesson-01.mp4 --title "Lesson 01" --poster cover.jpg --captions en-US=lesson-01.en.vtt --captions pl-PL=lesson-01.pl.vtt
```

`--poster` et `--captions` sont facultatifs. Utilisez `video:publish:preview` pour l’environnement de préversion.

`scripts/publish-video.ts` lit le nom du bucket dans le binding `MEDIA` de l’environnement dans `wrangler.jsonc`, encode dans un répertoire temporaire, téléverse les fichiers avec `wrangler r2 bulk put --remote`, 20 à la fois et regroupés par type de contenu, puis insère la ligne `video` avec `wrangler d1 execute DB --env <environment> --remote`. En cas d’échec, il supprime les objets téléversés avec `wrangler r2 object delete`. La planification (rendus, arguments FFmpeg, storyboard, noms de fichiers) se trouve dans `src/modules/video/video.encoding.ts` et `video.files.ts`, que le Worker utilise aussi.

## Coût

Avec le stockage R2 Standard à 0,015 $ par Go-mois et sans frais de sortie de données, une vidéothèque de 50 heures d’enregistrements d’écran, à environ 1,2 Go par heure tous rendus confondus, coûte moins de 1 $ par mois en stockage, quel que soit le nombre de visionnages. Chaque requête de segment exécute le Worker une fois et lit R2 au plus une fois par point de présence, car les fichiers servis sont conservés dans le cache des Workers. Vérifiez les prix en vigueur sur les pages de tarification de [R2](https://developers.cloudflare.com/r2/pricing/) et de [Workers](https://developers.cloudflare.com/workers/platform/pricing/).
