---
title: "Sessions"
description: "Better Auth sessions in D1, with self-service revocation in admin settings and revocation of any user's sessions from their admin profile."
---

Sessions live in the D1 `session` table (`src/modules/session/session.schema.ts`). `auth.session.ts` reads them with `getRequestSession`, memoized per request, and exposes `getCurrentSessionQuery` to routes and components. The client copy never includes the session token.

## Use cases

| Use case                                  | Middleware                   | Used by            |
| ----------------------------------------- | ---------------------------- | ------------------ |
| `getActiveSessions`                       | signed in                    | `SettingsSessions` |
| `revokeSession`                           | signed in; own sessions only | `SessionRow`       |
| `revokeOtherSessions`                     | signed in                    | `SettingsSessions` |
| `listUserSessions`                        | `session: ["list"]`          | `UserSessions`     |
| `revokeUserSession`, `revokeUserSessions` | `session: ["revoke"]`        | `UserSessions`     |

`getActiveSessions` returns the current user's unexpired sessions, newest first, and leaves out impersonation sessions. `listUserSessions` returns another user's unexpired sessions from Better Auth's `listUserSessions`, newest first and without their tokens, impersonation sessions included. `revokeUserSession` takes a session ID and looks its token up on the server, so no token reaches the browser.

## UI

**Settings → Security** in `/admin/settings` renders `SettingsSessions` (`src/presentation/components/custom/admin/settings/sessions.tsx`). Each `SessionRow` shows the device (user agent or IP address), the last activity and a badge on the current session, and can revoke that session. A header button revokes all other sessions. Changing the password also refreshes the session list.

A user's profile in `/admin/users` renders `UserSessions` (`src/presentation/components/custom/admin/users/user-sessions.tsx`): each session's device and when it signed in and was last active, a button that revokes it and, after a confirmation, a button that signs the user out everywhere. See [Users (admin)](/docs/features/users-admin).
