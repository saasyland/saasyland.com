description: "Escribe plantillas de React Email con mensajes traducidos y envíalas desde casos de uso a través de Resend."
---

Un correo tiene tres partes: una plantilla en `src/presentation/emails/`, un espacio de nombres de mensajes en `messages/<locale>/emails.<name>.json` y el caso de uso que carga los mensajes, renderiza la plantilla y la envía. La página [Resend](/docs/integrations/resend) enumera cada plantilla con el caso de uso que la envía.

## Plantilla

Una plantilla contiene solo marcado y exporta su espacio de nombres. Traduce con `createTranslator` de `use-intl` porque se renderiza fuera del contexto de React. Cada plantilla se renderiza dentro de `EmailLayout`, de `src/presentation/emails/email-layout.tsx`, que fija una sola vez para todas el idioma, el texto de vista previa, Tailwind y el contenedor centrado. `src/presentation/emails/verify-email.tsx`:

```tsx title="src/presentation/emails/verify-email.tsx"
import type { JSX } from "react"

import { Button, Heading, Section, Text } from "react-email"
import { createTranslator } from "use-intl"

import { EMAIL_LINK_LIFETIME_HOURS } from "~/src/integrations/better-auth/auth.constants"
import type { SupportedLocale } from "~/src/integrations/use-intl/i18n.config"

import type emailMessages from "~/messages/en-US/emails.verify-email.json"
import { APP_NAME } from "~/src/presentation/branding"
import { EmailBrandHeader } from "~/src/presentation/emails/email-brand-header"
import { EmailFallbackLink } from "~/src/presentation/emails/email-fallback-link"
import { EmailLayout } from "~/src/presentation/emails/email-layout"

export const VERIFY_EMAIL_NAMESPACE = "emails.verify-email"

interface VerifyEmailProps {
  readonly locale: SupportedLocale
  readonly messages: typeof emailMessages
  readonly name: string
  readonly verifyUrl: string
}

export const VerifyEmail = ({ messages, locale, name, verifyUrl }: Readonly<VerifyEmailProps>): JSX.Element => {
  const t = createTranslator({ locale, messages: { emails: { "verify-email": messages } }, namespace: "emails.verify-email" })

  return (
    <EmailLayout lang={locale} preview={t("preview", { appName: APP_NAME })}>
      <EmailBrandHeader />
      <Section>
        <Heading className="m-0 mb-4 text-2xl font-bold">{t("heading")}</Heading>
        <Text className="m-0 mb-6 text-base text-neutral-600">{t("body", { name })}</Text>
        <Button href={verifyUrl} className="box-border rounded-md bg-neutral-900 px-5 py-3 text-center text-base text-white no-underline">
          {t("button")}
        </Button>
        <Text className="mt-6 mb-0 text-base text-neutral-600">{t("expiry", { hours: EMAIL_LINK_LIFETIME_HOURS })}</Text>
        <EmailFallbackLink label={t("fallback")} url={verifyUrl} />
        <Text className="mt-6 text-sm text-neutral-500">{t("footer")}</Text>
      </Section>
    </EmailLayout>
  )
}
```

## Mensajes

Crea `messages/<locale>/emails.<name>.json` en todos los idiomas. Incluye una clave `subject`; el caso de uso la traduce aparte del cuerpo.

```json title="messages/en-US/emails.verify-email.json"
{
  "subject": "Verify your email address",
  "preview": "Verify your email for {appName}",
  "heading": "Verify your email",
  "body": "Hi {name}, thanks for signing up. Confirm your email address to finish setting up your account.",
  "button": "Verify email",
  "expiry": "The link works for {hours, plural, one {# hour} other {# hours}}.",
  "fallback": "If the button does not work, copy this link into your browser:",
  "footer": "If you did not create an account, you can safely ignore this email."
}
```

Las rutas nunca precargan los espacios de nombres de correo; los carga en el servidor el caso de uso que envía el mensaje.

## Envío

El caso de uso toma el idioma de la URL de callback que recibe, comprueba el límite por destinatario, carga los mensajes, construye enlaces absolutos con `localizePathname` y llama a `sendEmail`. `src/modules/verification/use-cases/send-verify-email.ts`:

```ts title="src/modules/verification/use-cases/send-verify-email.ts"
export const sendVerifyEmail = async ({
  callbackURL,
  token,
  user,
}: {
  callbackURL: string
  token: string
  user: { email: string; name: string }
}): Promise<void> => {
  if (!(await withinRecipientRateLimit({ kind: VERIFICATION_EMAIL_PURPOSE.VERIFY_EMAIL, recipient: user.email }))) {
    console.warn("[email] verification email not sent: the recipient reached the hourly limit")
    return
  }

  const callback = new URL(callbackURL, getRequest().url)
  const locale = extractLocaleFromPath(callback.pathname) ?? I18N.DEFAULT_LOCALE
  const verifyUrl = new URL(localizePathname({ locale, pathname: ROUTES.VERIFY_EMAIL }), getRequest().url)
  verifyUrl.search = callback.search
  verifyUrl.searchParams.set("token", token)

  const messages = await loadNamespace<typeof verifyEmailMessages>({ locale, namespace: VERIFY_EMAIL_NAMESPACE })

  await sendEmail({
    idempotency: { purpose: VERIFICATION_EMAIL_PURPOSE.VERIFY_EMAIL, token: crypto.randomUUID() },
    react: createElement(VerifyEmail, { locale, messages, name: user.name, verifyUrl: verifyUrl.toString() }),
    subject: createTranslator({ locale, messages })("subject"),
    to: user.email,
  })
}
```

`sendEmail` (`src/integrations/resend/resend.utils.ts`) envía a través de Resend desde `RESEND_EMAIL_FROM` salvo que se indique `from`, pasa la clave de idempotencia para que un reintento nunca envíe dos veces y lanza un error cuando Resend lo devuelve.

El correo de verificación usa una clave nueva en cada envío, `crypto.randomUUID()`, igual que los correos de cuenta existente y de contraseña cambiada: Better Auth firma sus tokens de verificación con marcas de tiempo de segundos enteros, así que un registro y un inicio de sesión en el mismo segundo llevan el mismo token, y Resend trataría el segundo correo como un reintento del primero.

## Quién envía qué

- Los hooks de Better Auth en `src/integrations/better-auth/auth.server.ts` llaman directamente a los casos de uso: `sendVerifyEmail` para `emailVerification.sendVerificationEmail` y para los registros repetidos de cuentas sin verificar, `sendExistingAccountEmail` para los registros repetidos de cuentas verificadas, `sendResetPasswordEmail` para `emailAndPassword.sendResetPassword`, `sendPasswordChangedEmail` para `emailAndPassword.onPasswordReset`, `sendChangeEmailConfirmationEmail` para `user.changeEmail` y `sendDeleteAccountEmail` para `user.deleteUser.sendDeleteAccountVerification`.
- Las peticiones de Better Auth llegan a `/api/auth` sin prefijo de idioma, así que los hooks toman el idioma del correo del `callbackURL` del flujo, una ruta de página localizada, con `extractLocaleFromCallbackURL` o `extractLocaleFromPath` de `src/integrations/use-intl/i18n.paths.ts`. El inglés es el idioma de reserva.
- Los casos de uso del boletín envían ellos mismos los correos de confirmación y de notificación, por ejemplo `subscribeToNewsletter`.
- El handler de webhook `onOrderPaid` del área de licencias llama a `sendPurchaseConfirmationEmail` después de conceder la licencia. El correo toma su idioma de `metadata.locale` del pedido, sus enlaces del host que recibió el webhook y su token de idempotencia del ID del pedido de Polar, y un envío fallido hace fallar el handler para que Polar lo reintente.
- Si un pedido de licencia pagado no corresponde a ninguna cuenta, `onOrderPaid` no concede nada y llama a `sendUnmatchedOrderAlert`, que avisa al propietario del sitio en inglés.
- `recordWithdrawal`, al que llama `submitWithdrawal`, envía el acuse de recibo de una declaración de desistimiento en el idioma de la página desde la que se envió, y la notificación del desistimiento al propietario del sitio en inglés. Un envío fallido queda registrado y no hace fallar la declaración.
- `createInvitation` y `resendInvitation` llaman a `sendInvitationEmail` con el idioma que eligió el administrador, guardado en la invitación. Su token de idempotencia es el token del enlace, de modo que cada enlace nuevo es un correo nuevo, y por encima del límite por destinatario falla con `TOO_MANY_REQUESTS` en lugar de omitir el correo.
- `sendVerifyEmail`, `sendResetPasswordEmail`, `sendExistingAccountEmail` y `subscribeToNewsletter` llaman a `withinRecipientRateLimit` (`src/lib/rate-limit.ts`) antes de enviar: como máximo <RepositoryFact name="recipientEmailsPerHour" /> correos de cada tipo por dirección y hora, con un hash SHA-256 de la dirección como clave. Por encima del límite registran un aviso y no envían nada. Añade la misma comprobación a cualquier correo que un visitante pueda provocar sin una cuenta.

## Añade un correo

1. Añade la plantilla en `src/presentation/emails/<name>.tsx` con su `<NAME>_NAMESPACE` exportado.
2. Añade `messages/<locale>/emails.<name>.json` en todos los idiomas.
3. Da nombre a su propósito en el objeto `<MODULE>_EMAIL_PURPOSE` del `<module>.constants.ts` del módulo remitente, que `email-purposes.test.ts` compara con los propósitos de todos los demás módulos, y envíalo desde el caso de uso al que pertenece la acción, pasando `idempotency: { purpose, token }` con el token o el id del registro que lo desencadena.
4. Prueba la plantilla en `src/presentation/emails/__test__/` y el caso de uso con `sendEmail` simulado.

Credenciales de Resend: `RESEND_API_KEY` y `RESEND_EMAIL_FROM`. Los tests nunca contactan con Resend.
