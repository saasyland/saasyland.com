---
title: "Gemeinsamer Kern"
description: "Die Fehlercodes, HTTP-Konstanten, Kataloge, Zod-Felder und Use-Case-Eingaben in src/modules/_core, auf denen jedes Modul aufbaut."
---

`src/modules/_core` ist der einzige Modulordner, der keine Tabelle besitzt. Er enthält nur das Fundament, auf dem die Schemas, Zod-Schemas und Use-Cases der Module aufbauen, damit kein Modul es neu definiert: die Fehlercodes, die HTTP- und Umgebungskonstanten, die Kataloge der Locales, Zeitzonen, Länder und Währungen samt Shop-Währung, die gemeinsamen Zod-Felder und lokalisierten Texte sowie die Eingaben für Paginierung, Reihenfolge, Suche und Zeitraum.

## Konstanten

| Datei                   | Inhalt                                                                                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `constants/errors.ts`   | `ERROR_CODES`, der Typ `ErrorCode` und die Klasse `AppError`                                                                                                  |
| `constants/api.ts`      | `HTTP_STATUS`, die Header-Namen `cf-ipcountry` und `cf-connecting-ip`, die Sicherheits-Header, erlaubte Hosts pro Build-Modus                                 |
| `constants/locale.ts`   | Der Katalog `LOCALES`, `LocaleCode`, `getLocaleName` und `getLocaleDirection`                                                                                 |
| `constants/country.ts`  | Der Katalog `COUNTRIES` und `CountryCode`                                                                                                                     |
| `constants/currency.ts` | Der Katalog `CURRENCIES`, `CurrencyCode` sowie `toMinorUnits` und `fromMinorUnits`, die einen Betrag in die kleinste Einheit der Währung und zurück umrechnen |
| `constants/timezone.ts` | Der Katalog `TIMEZONES` und `TimezoneCode`                                                                                                                    |
| `constants/pricing.ts`  | Die Shop-Währung `DEFAULT_CURRENCY_CODE` und die Währungsformatierung `CURRENCY_FORMAT`                                                                       |
| `constants/ordering.ts` | `FIRST_POSITION`, die Stelle des ersten Elements in einer geordneten Liste                                                                                    |

Die Kataloge liegen hier, weil das Fundament auf ihnen aufbaut: `countryCodeField` und `currencyCodeField`, die Schemas von Bestellung, Produkt und Abonnement, die Konstanten des Nutzers und die Standardwährung eines Produkts. Der Locale-Katalog führt jede bekannte Locale auf; die Locales, die die Anwendung ausliefert, stehen in `I18N.SUPPORTED_LOCALES` in `src/integrations/use-intl/i18n.config.ts`. Daten, auf denen kein Schema und kein Use-Case aufbaut, gehören nach `src/data`, das nur Konstanten und literale Listen enthält, und allgemeine Hilfsfunktionen nach `src/lib`. Ein Test in `src/__test__/module-tables.test.ts` schlägt fehl, wenn eine Datei in `_core` auf dieser Seite nicht beschrieben ist, sodass jede neue Datei eine bewusste Entscheidung ist.

## Hilfsfunktionen

- `utils/localized-text.ts`: `LocalizedText`, ein als JSON gespeicherter Text pro Locale, `localizedTextSchema`, das `en-US` verlangt und höchstens <RepositoryFact name="localizedTextMaxLength" /> Zeichen pro Text zulässt, und `localize`, das auf `en-US` zurückfällt
- `utils/ordering.ts`: `nextPosition`, die höchste `position` plus eins, und `reorder`, das ein Element an eine Stelle unter seinen Geschwistern verschiebt, eine Stelle über eines der beiden Enden hinaus auf dieses Ende begrenzt, die Liste ab `FIRST_POSITION` durchnummeriert und nur die Elemente zurückgibt, deren `position` sich ändert; die Use-Cases für Kurse, Kapitel, Lektionen und Materialien halten `position` damit lückenlos
- `utils/pagination.ts`: `paginationSchema` (`pageIndex`, `pageSize`) und `DEFAULT_PAGE_SIZE`
- `utils/search.ts`: `searchSchema` und `localizedSearchSchema`, die Eingabe der Such-Use-Cases im Adminbereich, ihre Längengrenzen und der `SearchHit`, den sie zurückgeben
- `utils/time-series.ts`: `TIME_RANGES` und `timeRangeSchema`, die Zeiträume der Umsatz- und Registrierungsdiagramme im Admin, `timeSeries`, die Tages- oder Monatsabschnitte eines Zeitraums, und `pointsOf`, das einem Abschnitt ohne Wert null gibt
- `utils/zod-fields.ts`: wiederverwendbare Zod-Felder wie `idField`, `localeField`, `positionField` (eine ganze Zahl ab `FIRST_POSITION`) und `slugField`

## Fehler

Es gibt eine einzige Fehlerklasse und eine einzige Liste von Codes:

```ts
export const ERROR_CODES = {
  AUTH_API_ERROR: "AUTH_API_ERROR",
  CONFLICT: "CONFLICT",
  FORBIDDEN: "FORBIDDEN",
  INTERNAL_ERROR: "INTERNAL_ERROR",
  NOT_FOUND: "NOT_FOUND",
  TOO_MANY_REQUESTS: "TOO_MANY_REQUESTS",
  UNAUTHORIZED: "UNAUTHORIZED",
  VALIDATION: "VALIDATION",
} as const

export type ErrorCode = (typeof ERROR_CODES)[keyof typeof ERROR_CODES]

export class AppError extends Error {
  readonly code: ErrorCode

  constructor(code: ErrorCode, message: string = code) {
    super(message)
    this.name = "AppError"
    this.code = code
  }
}
```

Serverfunktionen werfen `AppError`. Die Middleware `withRequest` normalisiert alles andere: Better-Auth-API-Fehler werden zu `AUTH_API_ERROR` mit dem Better-Auth-Fehlerschlüssel als Nachricht, Zod-Fehler werden zu `VALIDATION`, und unbekannte Fehler werden geloggt und zu `INTERNAL_ERROR`. Im Browser ordnet `useErrorMessage()` aus `src/hooks/use-error-message.ts` die Nachricht den Übersetzungen unter `auth.errors.*` oder `errors.codes.*` zu.
