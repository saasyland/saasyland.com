## いま取り組んでいること

- このリポジトリの構成の整理。すべてのファイルを、それを所有するモジュール、インテグレーション、ライブラリに移し、エリアごとのプラグインファイルの層をなくします。そうすれば、生成するプロジェクトから省略可能なモジュールのどれを外しても型チェックが通るようになり、CI がすべてのプルリクエストでそれを証明します。訪問者やお客様にとって変わることはありません。
- WebKit のブラウザースイートが `main` でのすべての実行で通るようにし、そのうえですべてのプルリクエストの必須チェックにします。
- 「いま修正していること」に挙げた修正。

## CLI：コンフィギュレーターのすべてのオプション

[コンフィギュレーター](/#cli)には、SaaSy Land が生成する予定のすべてのオプションと追加機能が表示されており、CLI はそのすべてを生成するようになります。オプションがコンフィギュレーターで有効になり、`init` に受け付けられるのは、そのオプションで生成したプロジェクトが、それに影響しうるすべての変更について、CI でインストール、型チェック、<RepositoryFact name="coverageThreshold" />% のカバレッジでのテスト合格、ビルド、起動まで通ったときだけです。それまでは、コンフィギュレーターでは無効として表示され、`init` はライセンスを確認する前に終了コード <RepositoryFact name="cliExitNotAvailable" /> で拒否します。

回答の中には、ほかの回答に左右されるものがあります。API の質問は分割 API とマイクロサービスのアーキテクチャにだけ関係し、ランタイムやプロバイダーの中には、Cloudflare Workers 上の Bun ランタイムのように、すべてのデプロイ先で動くわけではないものがあります。コンフィギュレーターは、デプロイ先で動かせない組み合わせを無効にします。

オプションは次の順で提供します。

1. Polar による課金と、生成される管理画面の注文と顧客。アプリケーションの汎用的な課金（次に取り組むこと）を待っています。
2. 追加機能のサブスクリプション型コースと、生成される管理画面のコース。課金が前提です。
3. Stripe による課金と、Plunk によるメール。
4. メールを外す回答と、コンテンツを外す回答。メールがない場合、サインインにはメールを送らないフローが必要です。コンテンツがない場合、生成されたプロジェクトのエージェント向け指示が参照するコーディング規約を、ドキュメントの外に置く必要があります。
5. Neon、Supabase、または自前のサーバー上の Postgres。Turso。ローカルの SQLite ファイル。Prisma。
6. Vercel または自前のサーバーへのデプロイ。Bun と Deno のランタイム。
7. Hono または Elysia の API を使う分割 API のアーキテクチャ、続いてマイクロサービス。
8. React 向けの Next.js と React Router。
9. Solid と SolidStart・TanStack Start、Vue と Nuxt、Svelte と SvelteKit、Angular と Analog・Angular SSR。
10. マルチテナント。アプリケーションに組織とロールが入ってからです。
11. サンプル商品付きストア、ビジュアルページビルダー、ビジュアル投稿エディター。いずれも、それぞれが生成する機能をアプリケーションがリリースした後です。

### コマンドとリリース

- ターミナルでの対話式の質問。現在のターミナルのセッションは、`--yes` と同じように、フラグで渡さなかった質問すべてに既定値で答えます。
- プロジェクトのリリース、回答、ライセンスを表示する `status`。
- 既存のプロジェクトに対して、別の回答で CLI をもう一度実行する `change`。まずモジュールを、プラットフォームの切り替えはその後に対応します。
- プロジェクトを 1 つのコマンドで新しいリリースに更新する `update`。3 方向マージで、自分で加えた編集を残します。update と change のシナリオは、最近のリリースをまたいで毎晩実行します。
- [CLI ガイド](/docs/cli)に載せる、すべてのコマンドとフラグの自動生成リファレンスと、CLI のアップグレード、ライセンスキーのローテーション、トラブルシューティング、プロジェクトの更新と変更の各ガイド。ガイドにあるすべてのコマンドは、テスト対象の CLI に対して CI で実行します。
- CLI 自身の README とリリース関連のドキュメントを修正する、次のベータ版。
- npm の既定タグでの安定版リリース。それまでは、CLI を <RepositoryFact name="cliPackageSpec" /> として実行してください。安定版をリリースするのは、課金と追加機能のサブスクリプション型コースが入り、夜間のジャーニースイートがパッケージマネージャーごとにプロジェクトを生成し、ビルドし、テストを実行し、ライセンスをエンドツーエンドで確認するようになったときです。そのうえで、サイトのコマンドを既定タグに切り替え、リリースノートとリリース記事を公開します。

## アプリケーション

1. 汎用的な課金。Polar のカスタマーポータルと、その上に載るライセンス。
2. サイト上の価格を Polar から読み込み、価格を 1 か所で変えられるようにします。
3. Polar を通じた、管理画面からの商品の作成、編集、削除。一回払いと定期払いの料金モデル。割引コード。
4. 注文ページからの返金（注文ページには、Polar に記録された返金がすでに表示されています）。ライセンスが返金または取り消されたときの購入者へのメール。そして注文ページでの支払いの異議申し立てと、その結果のライセンスへの反映。
5. ライセンスページからの下位プランへの変更。現在はサポートへのメールで対応しています。
6. 実データに基づくダッシュボードの指標。プライバシーに配慮した、サインアップとチェックアウトのファネル計測。ページビュー、訪問者、リテンション、チャーンを表示するアナリティクス画面。
7. ニュースレター。CSV エクスポート付きの購読者リスト、管理画面からの配信、顧客ワークスペースでのニュースレターのオン・オフ。
8. 権限。エディターのロール、権限で絞り込まれるメニュー、ロールエディター。
9. 組織とチーム、続いて Agency のチーム席。
10. 管理画面の設定でのワークスペースのプロフィール。名前、サポート用のメールアドレス、住所、ロゴ。
11. アカウント停止、削除、なりすましの監査ログ。
12. プルリクエストを通じて Git にコミットするビジュアルエディターでの、管理画面からのブログ編集。続いてドキュメントの編集。
13. セクションのレジストリから組み立てるランディングページ。続いてビジュアルなページデザイナー、料金ページ、セクションライブラリ、キャンペーンページ。
14. アフィリエイトプログラムの開始。
15. 埋め込みチェックアウトでの Apple Pay と Google Pay。埋め込みチェックアウトでこれらを使うには、Polar 側で有効にしてもらう必要があります。

その後：

- ストアフロントでの販売。追加機能のストアと marte-bizuteria.pl の事例が、これを待っています
- 高度なアナリティクスのパイプライン

## コース

- 収録。レッスンは収録しだい公開し、それまでは各レッスンに「収録中」と表示します。
- アップロード中のブラウザーでのエンコード。これにより、エンコードの工程を別に設けなくても、レッスンの動画がすぐに使えるようになります。
- 管理画面で、アップロードと一緒に字幕を追加できるようにします。
- コースとレッスンの Markdown の説明文と、動画ごとの詳細ページ。
- 生成するプロジェクト向けの、追加機能のサブスクリプション型コース（CLI）。

## コンテンツとドキュメント

- AI エンジニアリングのシリーズの続き。有料 CLI を安全にリリースする方法、ごまかさずに達成する 100% カバレッジ、実際の SaaS の AGENTS.md の注釈付き解説、そしてもう 1 本の記事。
- 記事に出てくる SaaSy Land に関するすべての数値をコードから出力します。Cloudflare の記事の計測値、サポートの応答時間、アーキテクチャ相談の長さも含みます。あわせて、タイトルのないコードの抜粋、「最終更新」の行、手入力のステータスを防ぐガードを設けます。
- ランディングページの機能の数を、このリポジトリの数と並べて、生成されるプロジェクトの中身から出力します。
- 細かな修正。リリース記事の古いパス、pre-commit フックの説明、依存関係のページにあるアップストリームへのリンク、自動コードレビューの説明、いくつかのメッセージの文言、そして古いフォルダ構成のままのコースの文章。
- 最新のスクリーンショットと、コードから生成するバッジを載せた、より短い README。
- 言語ごとのスタイルガイドと用語集を使った、すべての翻訳のネイティブ品質でのレビュー。ドイツ語から始めます。ポーランド語は完了しています。

## 品質とエンジニアリング

- WebKit のブラウザースイートを必須チェックにします。
- 夜間のジャーニースイートをプレビューサイトと Polar のサンドボックスに対して実行し、その後、CLI でプロジェクトを生成し、パッケージマネージャーごとにビルドしてテストを実行するところまで広げます。
- 下の表で未カバーとして挙げているすべてのフローのブラウザーテスト。まだ実装していないフローには、機能のリリースに合わせてテストを加えます。
- ライセンス、決済、アクセス制御のコードに対するミューテーションテストと、Playwright のスイートによるブラウザーのコードカバレッジ。
- カバレッジゲートの除外対象である shadcn のプリミティブとテストヘルパーを、テストカバレッジのページに明記します。
- 非 null アサーションと空の `catch` ブロックを禁じる lint ルールと、コーディングエージェント向けのガードレール。チェック付きのルールのレジストリ、規約から生成しドリフトを検出するリポジトリのスキル、そしてコミットされたフック。
- 生成されるプロジェクトで境界を守らせる lint ルールと、最新の依存関係で生成されるプロジェクトの毎晩のビルド。
- パフォーマンス。遅延読み込みされるセクションでクリックが失われないようにすること、modulepreload の除去の A/B テスト、Worker の Server-Timing、そしてライセンスの有効化をページにストリーミングすること。
- 依存関係を最新のリリースに保ち、修正がアップストリームでリリースされたパッチはそのつど外します。
- 以前の Next.js のコードベースの古い Issue を、説明を添えてクローズします。

現時点で部分的なもの：

- 生成されるプロジェクトの管理画面にあるのは、ダッシュボード、ユーザー、設定です。サインインを外すと、管理画面も外れます。
- 返金は注文ページに表示されますが、返金の手続きは Polar のダッシュボードで行います。
- 下位プランへの変更はメールで受け付けています。
- レッスンの動画は、アップロードの後に FFmpeg を備えたマシンでエンコードし、字幕はコマンドラインから追加します。
- ニュースレターは確認済みの購読者を保存していますが、まだ 1 号も配信していません。
- どのコースのレッスンにも「収録中」と表示されます。
- ライセンスが必要な CLI のコマンドは、どれもライセンスをオンラインで確認します。オフラインモードはありません。
- アフィリエイトプログラムはまだ始まっていません。アフィリエイトのページでは、参加を希望するパートナーに連絡を呼びかけています。
- 夜間のジャーニースイートは、まだ一度も実行を完了していません。
- WebKit のスイートは `main` で実行していますが、まだ必須チェックではありません。
- `updates.yml` は UTC のスケジュール <RepositoryFact name="updatesSchedule" /> で依存関係の更新を確認します。実行の合間には最新リリースより遅れるパッケージがいくつかあり、パッチを当てたパッケージは、その修正がアップストリームでリリースされるまで固定されたままです。
