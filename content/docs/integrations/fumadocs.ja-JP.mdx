title: "Fumadocs"

---

Fumadocs は `content/docs` と `content/blog` を、ローカライズされたページツリーに変換します。`bun run content` は `fumadocs-mdx` を実行して `.source/` を書き出します。`dev`、`typegen`、すべてのビルドスクリプトは、最初にこれを実行します。

| ファイル                | 目的                                                                                                                                                                                                     |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `fumadocs.config.ts`    | `docs` コレクション、フロントマターのスキーマを持つ `blog` コレクション、コードハイライトのテーマと色の置き換え                                                                                          |
| `fumadocs.i18n.ts`      | `I18N` のロケール、デフォルトかつフォールバックとしての `en-US`、`<slug>.<locale>.mdx` 用の `dot` パーサー、非表示のロケールプレフィックス                                                               |
| `fumadocs.source.ts`    | Lucide アイコンプラグイン付きで `/docs` に配置する `source`、`/blog` に配置する `blogSource`、読了時間付きの `getPublishedBlogPosts`                                                                     |
| `fumadocs.docs.ts`      | `docs.$` ルート用の `getDocsPage` サーバー関数、`loadDocsPage`、`docsHead`                                                                                                                               |
| `fumadocs.search.ts`    | `/api/search` から提供される検索インデックス                                                                                                                                                             |
| `fumadocs.changelog.ts` | `changelogEntries` プラグイン。変更履歴ページの `<ChangelogEntries unreleased="…" />` を、ページのロケールの `content/changelog` のエントリに置き換え、それぞれが `main` に入った UTC の日付ごとに並べる |

ロケールプレフィックスはルーターが付与するため、Fumadocs の URL では非表示になっています。ブログのフロントマターでは `title`、`authorName`、`date` が必須で、`description`、`excerpt`、`faq`、`featured`、`image`、`published`、`tags`、`updated`、`authorImage` も指定できます。

## コンポーネント

`src/presentation/components/custom/mdx.tsx` が MDX コンポーネントをマッピングします。Fumadocs のデフォルト（`Cards` と `Callout` を含む）、`Accordions`、`Steps`、`Tabs`、そして shadcn の `Alert`、`Badge`、`Button`、カードの各パーツ、`Separator`、`Table` です。さらに、ビルド時にリポジトリから計測した値やコードで定義された値を表示する `RepositoryFact`（例: `<RepositoryFact name="testFiles" />`）と、コードから組み立てた表を表示する `RepositoryTable`（例: `<RepositoryTable name="commitTypes" columns={["Type", "Emoji"]} />`）があります。`TierPrice` は `TIER_PRICES` からプランの定価をページの言語で表示します（例: `<TierPrice tier="core" />`）。そのため、どのページにも価格を手入力することはありません。`ActivationLimit` は `LICENSE_ACTIVATION_LIMITS` からプランのアクティベーション数の上限を表示し（例: `<ActivationLimit tier="core" />`）、`RegionalDiscounts` は `PPP_TIERS` から導き出した地域割引の割引率を一覧表示します。内部リンクは `localizePathname` でローカライズされ、タスクリストの項目はチェックボックスとテキストを `label` で囲みます。ページの描画は `docs-content.tsx` と `blog-content.tsx` が担当します。検索、**このページの内容**、コピーボタンなど、Fumadocs 自身のコントロールの文言は `fumadocs` 名前空間から取られます。`useFumadocsI18n` がページの言語と一緒に、ドキュメントとブログのレイアウトの `RootProvider` に渡します。

## コンテンツのルール

すべてのページは、ロケールごとに `<slug>.<locale>.mdx` として 1 つずつ存在します。各フォルダーには `meta.<locale>.json` があり、どのロケールでも同じ `pages` 配列を持ちます。meta ファイルの `icon` には Lucide のアイコン名を指定します。`bun run check:i18n` の一部である `scripts/check-content.ts` は、翻訳の欠落、コードブロック・インラインコード・コンポーネント・リンク・表・ナビゲーションの英語との差異、他のロケールに英語の段落が残っている場合に失敗します。
