## Макет

`src/routes/app.tsx` перевіряє параметри пошуку кожної сторінки зони, захищає її за допомогою `requireSignedIn` і попередньо завантажує її простори імен:

```tsx
const NAMESPACES = ["auth.errors", "pages.app", "pages.license"] as const

export const Route = createFileRoute("/app")({
  validateSearch: appSearchSchema,
  beforeLoad: requireSignedIn,
  component: AppLayout,
  loader: ({ context }) => preloadNamespaces({ locale: getCurrentLocale(), namespaces: NAMESPACES, queryClient: context.queryClient }),
  pendingComponent: AppPending,
  staticData: { namespaces: NAMESPACES },
})
```

`AppLayout` показує `AppSidebar` і `AppHeader` з `src/presentation/components/custom/app` усередині `SidebarProvider` з shadcn. Бічна панель будує посилання з `APP_NAVIGATION` у `src/data/app.ts`, читає користувача з контексту маршруту (`getRouteApi("/app")`) і закінчується кнопкою `SignOutButton`. Заголовок показує поточну сторінку та посилання назад на сайт. Після входу адміністратори потрапляють на `/admin`, а решта — на `/app`.

## Сторінки

| Маршрут         | Вміст                                                                                                                                                                                 |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/app`          | `LicenseOffer` без активної ліцензії, інакше `LicenseStatusCard` (план, статус і посилання на сторінку ліцензії); посилання на документацію та підтримку електронною поштою.          |
| `/app/license`  | `LicenseOffer` без активної ліцензії, інакше `LicenseCard` (ключ, команда встановлення, посилання на портал клієнта, як змінити план) і, коли Polar видав ключ, `LicenseActivations`. |
| `/app/settings` | `PreferencesCard`: часовий пояс усіх дат у робочому просторі, з пошуком і кнопкою **Визначити за цим браузером**. Див. [Налаштування](/docs/features/settings).                       |

`LicenseOffer` (`src/presentation/components/custom/app/license-offer.tsx`) повторно використовує `PricingTiers` з головної сторінки з `CheckoutButton` для кожного плану, додає умови купівлі (`CheckoutAgreement`) і закінчується блоком `CourseUnlocks`: опубліковані курси з платними уроками та кількістю заблокованих уроків у кожному, яку `getCatalogue` рахує з D1. Поки жоден курс не має платних уроків, блок не показується. Повернена ліцензія зберігає свою картку, а поруч із нею з’являється пропозиція купівлі.

`appSearchSchema` (`src/data/app.ts`) приймає два необов’язкові параметри й ігнорує кожен із них, якщо значення некоректне:

| Параметр     | Значення                | Дія                                                                                                                                                    |
| ------------ | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `tier`       | значення `LICENSE_TIER` | `ChosenTier` над пропозицією купівлі: план, його ціна й кнопка **Перейти до оплати**.                                                                  |
| `checkoutId` | UUID від Polar          | `CheckoutActivation` замість пропозиції купівлі, доки ліцензія не стане активною, а потім подяка. Див. [Платежі та ліцензії](/docs/features/payments). |

Loader-функції огляду та ліцензії попередньо завантажують `currentLicenseQuery` і каталог курсів; `/app/license` також завантажує `licenseActivationsQuery`. `/app/settings` завантажує лише простір імен своєї сторінки, а `NAMESPACES` макета містять `timezones` для назв поясів. Оплату, вебхуки та стани ліцензії описано на сторінці [Платежі та ліцензії](/docs/features/payments).

## Скелетони

`AppSettingsPending` (`app-pending.tsx`) малює заголовок сторінки та `PreferencesCardPending`. `AppOverviewPending` і `AppLicensePending` відтворюють стан, який покаже сторінка: вони читають параметри пошуку через `appSearchSchema`, а кешовані ліцензію й каталог — із клієнта запитів, і малюють панель активації, вибраний план, сітку планів із рядком для кожного курсу з платними уроками або картки ліцензії.

У `/app` немає історії рахунків чи екранів курсів, а `/app/settings` поки не має форм профілю, електронної пошти чи пароля.
