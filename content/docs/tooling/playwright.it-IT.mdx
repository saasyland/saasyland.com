Playwright testa l'applicazione compilata in browser reali. La suite viene eseguita sull'ambiente Wrangler `test`: D1, KV e R2 locali in `.wrangler/test`, credenziali fittizie da `.env.test` e l'entry point di test `src/platform/testing/worker.ts`, che intercetta le richieste a Resend e Polar.

```sh
bun run test:e2e:install
bun run test:e2e
bun run test:e2e:smoke
bun run test:e2e:pr
bun run test:e2e:headed
bun run test:e2e:ui
```

| Script             | Esegue                                                      |
| ------------------ | ----------------------------------------------------------- |
| `test:e2e:install` | Installa Chromium e WebKit con le dipendenze di sistema     |
| `test:e2e`         | Tutte le spec in Chromium e WebKit                          |
| `test:e2e:smoke`   | `e2e/specs/smoke.spec.ts` in Chromium                       |
| `test:e2e:pr`      | Tutte le spec in Chromium, come nella CI delle pull request |
| `test:e2e:headed`  | Tutte le spec in browser visibili                           |
| `test:e2e:ui`      | Modalità UI di Playwright                                   |

## Configurazione

`playwright.config.ts` definisce i progetti `chromium` (Desktop Chrome) e `webkit` (Desktop Safari) e usa `PLAYWRIGHT_BASE_URL` oppure `http://127.0.0.1:3000`. In locale il comando del web server esegue `db:reset:test`, `build:test` e `start:test`, e riutilizza un server che risponde già a quell'URL, quindi ferma prima gli altri server sulla porta 3000. In CI il workflow prepara la build e Playwright si limita ad avviare il server.

| Impostazione | Locale                       | CI                           |
| ------------ | ---------------------------- | ---------------------------- |
| Retry        | 0                            | 2                            |
| Worker       | 1                            | 2                            |
| Trace        | Conservate in caso di errore | Al primo retry               |
| Video        | Disattivati                  | Conservati in caso di errore |
| Reporter     | List e HTML                  | GitHub e HTML                |

## Struttura

- `e2e/specs/`: spec per smoke test, landing page, navigazione, locale, autenticazione, aree di lavoro, newsletter, contenuti, tema, prezzi regionali, video, corsi, amministrazione dei corsi e accessibilità.
- `e2e/pages/`: page object.
- `e2e/fixtures/`: la fixture `test` estesa e gli helper per le email intercettate.
- `e2e/data/accounts.ts`: gli account admin e cliente creati dal seed e la loro password.
- `e2e/data/videos.ts` e `e2e/data/courses.ts`: il video di test creato dal seed, i cui file sono in `e2e/fixtures/video/`, e il corso creato dal seed: un capitolo con un'anteprima gratuita, una lezione per chi ha un account e due lezioni a pagamento, una delle quali senza video.

Il Worker di test espone `/__test/emails` per leggere le email intercettate dal mock di Resend e `/__test/newsletter` per leggere lo stato di un iscritto.

## Accessibilità

`e2e/specs/accessibility.spec.ts` esegue [axe-core](https://github.com/dequelabs/axe-core) tramite `@axe-core/playwright` sulle pagine pubbliche, sulle pagine dei corsi, sulla home della documentazione, su ogni pagina di Convenzioni e su una pagina di ciascuna delle altre sezioni della documentazione, su un articolo del blog e sulle aree di lavoro di amministrazione e cliente, nei temi chiaro e scuro. Le pagine di amministrazione includono `/admin/courses`, `/admin/courses/create` e l'editor del corso di test, che visita anche `e2e/specs/workspaces.spec.ts`. Applica le regole A e AA di WCAG 2.0, 2.1 e 2.2 insieme alle best practice di axe, fallisce se una pagina non si carica con uno stato di successo, scorre la pagina perché vengano controllate anche le sezioni che compaiono durante lo scorrimento, attende la fine delle animazioni finite e fallisce a ogni violazione, riportando la regola, il suo impatto e i selettori coinvolti.
